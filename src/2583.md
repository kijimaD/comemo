## 変更の背景

Go言語のような並行処理を重視する言語において、ミューテックスやその他の同期プリミティブは、複数のゴルーチン（またはスレッド）が共有データに安全にアクセスするために不可欠です。これらの同期プリミティブの効率的かつ正確な動作は、基盤となるハードウェアが提供するアトミック操作に大きく依存します。

このコミットが行われた2009年当時、Go言語はまだ初期段階にあり、様々なアーキテクチャへの対応を進めていました。ARMアーキテクチャは、組み込みシステムやモバイルデバイスで広く利用されており、Goがこれらのプラットフォームで効率的に動作するためには、ARM固有のアトミック操作の実装が必要でした。

Compare-and-Swap (CAS) は、ロックフリーなデータ構造やミューテックスの実装において中心的な役割を果たすアトミック操作です。CASは、メモリ上の特定のアドレスの値が期待する値と一致する場合にのみ、そのアドレスの値を新しい値に更新することを保証します。この操作はアトミックであるため、複数のプロセッサやコアが同時にアクセスしても、競合状態（Race Condition）が発生することなく、一貫性を保つことができます。

このコミットは、ARMアーキテクチャ上でGoの`sync`パッケージが提供するミューテックスなどの同期プリミティブが、効率的かつ正しく機能するための低レベルな基盤を構築する初期段階として、`sys.cas`関数の定義を導入したものです。`TODO`コメントがあることから、この時点では関数のインターフェースと目的が明確にされ、実際のARMアセンブリによる実装は後続のコミットで追加される予定であったと考えられます。

## 前提知識の解説

### 1. ARMアーキテクチャ

ARM (Advanced RISC Machine) は、主にモバイルデバイス、組み込みシステム、最近ではサーバーやデスクトップPCにも採用されているRISC (Reduced Instruction Set Computer) ベースのプロセッサアーキテクチャです。低消費電力と高性能を両立させる設計が特徴です。ARMプロセッサは、特定の命令セット（例: ARMv7, ARMv8）を持ち、アセンブリ言語で直接プログラミングすることで、ハードウェアの機能を最大限に引き出すことができます。

### 2. アトミック操作 (Atomic Operations)

アトミック操作とは、複数のCPUコアやスレッドから同時にアクセスされた場合でも、その操作全体が一つの不可分な単位として実行されることを保証する操作です。つまり、操作の途中で他のスレッドによる割り込みや変更が入ることがなく、常に一貫性のある結果が得られます。並行プログラミングにおいて、共有データの整合性を保つために不可欠な概念です。

### 3. Compare-and-Swap (CAS)

CASは、アトミック操作の一種であり、ロックフリーなアルゴリズムを実装するための基本的な構成要素です。その動作は以下の通りです。

1.  メモリ上の特定のアドレス`A`にある現在の値`V`を読み取る。
2.  `V`が期待する値`E`と一致するかどうかを比較する。
3.  もし一致すれば、`A`の値を新しい値`N`に更新する。
4.  操作が成功したかどうか（値が更新されたかどうか）を示すブール値を返す。

この一連の「比較」と「交換」は、ハードウェアレベルでアトミックに実行されます。これにより、複数のスレッドが同時にCASを試みても、一度に成功するのは一つだけであり、他のスレッドは失敗を検知して再試行することができます。

### 4. ミューテックス (Mutex)

ミューテックス (Mutual Exclusion) は、共有リソースへのアクセスを制御するための同期プリミティブです。ミューテックスは、一度に一つのスレッド（またはゴルーチン）だけがクリティカルセクション（共有リソースにアクセスするコード部分）に入ることができるようにします。これにより、複数のスレッドが同時に共有データを変更することによる競合状態を防ぎ、データの整合性を保ちます。ミューテックスの内部実装には、通常、CASのようなアトミック操作が利用されます。

### 5. Goの`sync`パッケージ

Go言語の標準ライブラリである`sync`パッケージは、基本的な同期プリミティブ（ミューテックス、条件変数、WaitGroupなど）を提供します。これらのプリミティブは、Goの並行処理モデルにおいて、ゴルーチン間の安全なデータ共有と協調を可能にします。`sync`パッケージの多くの機能は、特定のアーキテクチャのアセンブリ言語で実装されたアトミック操作に依存しており、最高のパフォーマンスと正確性を実現しています。

### 6. Goのアセンブリ言語

Go言語は、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合に、アセンブリ言語を使用します。Goのアセンブリは、Plan 9アセンブラの構文に基づいており、一般的なx86やARMのアセンブリとは異なる独自の記法を持ちます。Goのランタイムや標準ライブラリの低レベルな部分（スケジューラ、ガベージコレクタ、アトミック操作など）は、このGoアセンブリで実装されています。

## 技術的詳細

このコミットは、ARMアーキテクチャにおけるGoの`sync`パッケージのための`cas`関数のインターフェースを定義しています。`cas`関数は、`*int32`型のポインタ`val`、`old`値、`new`値を受け取り、`bool`を返すというシグネチャを持っています。

ARMアーキテクチャにおけるアトミックなCompare-and-Swap操作は、通常、`LDREX` (Load-Exclusive) と `STREX` (Store-Exclusive) 命令のペアを使用して実装されます。

*   **`LDREX`**: メモリから値を読み込み、そのアドレスを排他モニターに登録します。
*   **`STREX`**: 排他モニターに登録されたアドレスが他のプロセッサによって変更されていない場合にのみ、新しい値をメモリに書き込みます。変更されていた場合は書き込みに失敗し、ステータスレジスタにその旨が示されます。

`cas`関数の実装では、まず`LDREX`で`*val`の値を読み込み、それが`old`と一致するかを比較します。一致した場合にのみ`STREX`で`new`値を`*val`に書き込もうとします。`STREX`が成功すれば`true`を返し、失敗するか、`LDREX`で読み込んだ値が`old`と一致しなかった場合は`false`を返します。この一連の処理をループで囲み、`STREX`が成功するまで再試行する形式が一般的です。

このコミットでは、具体的な`LDREX`/`STREX`命令を用いた実装は`TODO`として残されていますが、`sync`パッケージがARM上でアトミックなCAS操作を必要とすることを明確にし、そのための関数シグネチャとセマンティクスを確立しています。これは、Goランタイムが異なるアーキテクチャの特性を抽象化し、共通の`sync`プリミティブを提供するための重要なステップです。

## コアとなるコードの解説

このコードは、Goのアセンブリ言語で書かれています。

*   `// Copyright 2009 The Go Authors. All rights reserved.` から始まるコメントブロックは、Goプロジェクトの標準的なライセンス情報です。
*   `// func cas(val *int32, old, new int32) bool` から始まるコメントブロックは、このアセンブリ関数が実装するGo関数のシグネチャと、そのアトミックな動作を説明しています。これは、`*val`が`old`と等しい場合にのみ`*val`を`new`に更新し、成功した場合は`true`、そうでなければ`false`を返すという、典型的なCAS操作のセマンティクスを示しています。
*   `TEXT sync·cas+0(SB),0,$12` は、Goアセンブリにおける関数の定義です。
    *   `TEXT`: 関数を定義するためのディレクティブ。
    *   `sync·cas`: 定義される関数の名前。Goのアセンブリでは、パッケージ名と関数名を`·`（中点）で区切ります。これは`sync`パッケージの`cas`関数を意味します。
    *   `+0(SB)`: `SB` (Static Base) は、プログラムの開始アドレスを指す擬似レジスタです。`+0(SB)`は、この関数がプログラムの静的セグメントの先頭からオフセット0の位置にあることを示します。
    *   `0`: 関数のフラグ。ここでは0が指定されており、特別なフラグは設定されていません。
    *   `$12`: この関数が使用するスタックフレームのサイズ（バイト単位）。ここでは12バイトが割り当てられています。これは、引数やローカル変数、レジスタの保存などに使用される可能性があります。`int32`が4バイトなので、3つの`int32`引数（`val`, `old`, `new`）と戻り値`bool`（通常1バイトだが、アラインメントやレジスタ渡しを考慮すると12バイトは妥当なスタックサイズ）を考慮していると考えられます。
*   `TODO`: この行は、実際のCAS操作を実装するARMアセンブリコードがまだ書かれていないことを示しています。このコミットの時点では、関数のインターフェースと目的が定義されただけであり、具体的なアトミック操作のロジックは後続のコミットで追加される予定でした。

このコードは、GoランタイムがARMアーキテクチャ上でアトミックなCAS操作をどのように抽象化し、利用しようとしていたかを示す初期の証拠となります。
