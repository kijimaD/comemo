# [インデックス 2105] ファイルの概要

このコミットは、Go言語のコンパイラ（`gc`）において、`defer close(channel)`という構文が正しく解析され、実行できるようにするための文法的な修正を導入しています。具体的には、`defer`および`go`ステートメントの引数として、`close`組み込み関数呼び出しを許可するように、コンパイラの構文定義ファイル（`src/cmd/gc/go.y`）が更新されました。これにより、チャネルのクローズ処理を`defer`を用いて確実に実行できる、より堅牢なコード記述が可能になりました。

このコミットの目的は、「`defer close(chan)`」という構文を許可することです。これは「anton」によって発見されたバグの修正として行われました。

## 変更の背景

Go言語の`defer`ステートメントは、関数の終了時に必ず実行される処理を登録するために使用されます。これは、ファイルハンドルのクローズ、ロックの解放、データベース接続のクローズなど、リソースのクリーンアップ処理を確実に行うための非常に強力な機能です。

チャネルはGo言語におけるゴルーチン間の通信の主要な手段であり、チャネルの送信側がデータの送信を完了したことを受信側に通知するために`close`組み込み関数が使用されます。チャネルをクローズすることは、リソース管理の観点からも重要であり、特に送信側がチャネルのライフサイクルを管理する場合、関数の終了時にチャネルを確実にクローズしたいというニーズがあります。

しかし、このコミット以前のGoコンパイラでは、`defer close(channel_variable)`という構文が文法的に正しく解析されず、コンパイルエラーとなっていました。これは、`defer`ステートメントが受け入れる式の種類に関するコンパイラの制限、または`close`組み込み関数が`defer`の引数として適切に扱われていなかったことに起因する「バグ」でした。この制限は、チャネルのクローズを`defer`で管理したい開発者にとって不便であり、コードの堅牢性を損なう可能性がありました。

このコミットは、この文法的な制約を取り除き、`defer close(chan)`という自然で有用なパターンをGo言語で利用できるようにするために行われました。

## 前提知識の解説

### Go言語の`defer`ステートメント

`defer`ステートメントは、そのステートメントを含む関数がリターンする直前に、指定された関数呼び出しを遅延実行するGo言語の機能です。関数の正常終了、パニックによる終了のいずれの場合でも実行が保証されるため、リソースの解放処理（ファイルクローズ、ロック解除など）に非常に適しています。

例:
```go
func readFile(filename string) ([]byte, error) {
    f, err := os.Open(filename)
    if err != nil {
        return nil, err
    }
    defer f.Close() // 関数終了時にf.Close()が必ず実行される

    // ファイル読み込み処理
    data, err := ioutil.ReadAll(f)
    if err != nil {
        return nil, err
    }
    return data, nil
}
```

### Go言語のチャネルと`close`関数

チャネルは、Go言語のゴルーチン間で値を送受信するための型付きのコンジットです。チャネルは、同期と通信の両方を提供します。

`close`組み込み関数は、チャネルがこれ以上値を送信しないことを示します。
*   クローズされたチャネルから値を受信しようとすると、チャネルにバッファされた値があればそれらが返され、その後はゼロ値が無限に返されます。受信操作の2番目の戻り値（`ok`）は、チャネルがクローズされていて値が残っていない場合に`false`になります。
*   クローズされたチャネルに値を送信しようとすると、パニックが発生します。
*   既にクローズされているチャネルを再度クローズしようとすると、パニックが発生します。

`defer close(channel)`は、チャネルの送信側がそのチャネルのライフサイクルを管理し、関数が終了する際にチャネルを確実にクローズするための一般的なイディオムです。これにより、受信側はチャネルが閉じられたことを検出し、それ以上の値が来ないことを安全に知ることができます。

### Yacc/Bison (`go.y`) とGoコンパイラ (`gc`)

*   **Yacc (Yet Another Compiler Compiler) / Bison**: これらは、形式文法に基づいて構文解析器（パーサー）を生成するためのツールです。入力として文法規則の定義ファイル（通常は`.y`または`.yy`拡張子）を受け取り、その文法を解析するC言語のコードを生成します。
*   **`src/cmd/gc/go.y`**: Go言語の初期のコンパイラである`gc`（Go Compiler）の構文定義ファイルです。このファイルには、Go言語の文法規則がYacc形式で記述されており、Goのソースコードがどのように解析されるかを定義しています。
*   **抽象構文木 (AST)**: コンパイラはソースコードを解析する際に、その構造を表現する抽象構文木を構築します。`nod`関数は、このASTのノードを作成するために使用されるGoコンパイラ内部の関数です。
*   **ノードタイプ (`OCALL`, `ODEFER`, `OCLOSE`, `OPROC`)**: これらはASTの異なる種類の操作やステートメントを表す内部的な定数（オペレーションコード）です。
    *   `OCALL`: 関数呼び出しを表すノード。
    *   `ODEFER`: `defer`ステートメントを表すノード。
    *   `OCLOSE`: `close`組み込み関数呼び出しを表すノード。
    *   `OPROC`: `go`ステートメント（ゴルーチンの起動）を表すノード。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの構文定義ファイルである`src/cmd/gc/go.y`に`pseudocall`という新しい文法規則を導入し、既存の`defer`および`go`ステートメントの定義をこの新しい規則を使用するように変更した点にあります。

1.  **`pseudocall`文法規則の導入**:
    *   この新しい規則は、`defer`や`go`ステートメントの引数として使用できる「呼び出しのような」構文を抽象化するために作成されました。
    *   `pseudocall`は2つの形式を認識します。
        1.  `pexpr '(' oexpr_list ')'`: これは一般的な関数呼び出しの構文です。`unsafenmagic`という関数が呼び出され、特定の組み込み関数（例えば`len`, `cap`など）に対する特殊な処理を行う可能性があります。それ以外の場合は、通常の関数呼び出しを表す`OCALL`ノードが生成されます。
        2.  `LCLOSE '(' expr ')'`: これは`close`組み込み関数呼び出しの構文です。この形式が認識されると、`OCLOSE`ノードが生成されます。

2.  **`semi_stmt`規則の変更**:
    *   `semi_stmt`規則は、Go言語のセミコロンで区切られるステートメント（`go`ステートメントや`defer`ステートメントを含む）を定義します。
    *   変更前は、`LGO`（`go`キーワード）と`LDEFER`（`defer`キーワード）の後に直接`pexpr '(' oexpr_list ')'`という関数呼び出しの構文が続いていました。
    *   変更後は、これらのキーワードの後に新しく定義された`pseudocall`規則が続くように修正されました。これにより、`go`や`defer`の引数として、通常の関数呼び出しだけでなく、`close`組み込み関数呼び出しも文法的に許可されるようになりました。

3.  **`pexpr`規則の変更**:
    *   `pexpr`規則は、Go言語のプライマリ式（変数、リテラル、関数呼び出しなど）を定義します。
    *   変更前は、`pexpr '(' oexpr_list ')'`（通常の関数呼び出し）と`LCLOSE '(' expr ')'`（`close`呼び出し）が`pexpr`規則の一部として直接定義されていました。
    *   変更後は、これらの重複する定義が削除され、代わりに`pseudocall`規則が直接参照されるようになりました。これは、コードの重複を排除し、文法定義をより整理する効果もあります。

これらの変更により、コンパイラは`defer close(channel)`という構文を、`defer`ステートメントの引数として有効な`close`呼び出しとして正しく解析できるようになりました。これにより、Go言語の表現力が向上し、開発者はチャネルのクローズ処理をより安全かつ慣用的に記述できるようになりました。

## コアとなるコードの解説

上記のdiffは、Goコンパイラの構文定義ファイルである`src/cmd/gc/go.y`に対する変更を示しています。

1.  **`%type`宣言の変更**:
    ```diff
    -%type	<node>	exprsym3_list_r exprsym3
    +%type	<node>	exprsym3_list_r exprsym3 pseudocall
    ```
    これは、`pseudocall`という新しいシンボルが、抽象構文木（AST）のノードを生成する型（`<node>`）を持つことを宣言しています。これにより、パーサーが`pseudocall`を認識し、それに対応するASTノードを構築できるようになります。

2.  **`semi_stmt`規則の変更**:
    ```diff
    -|\tLGO pexpr \'(\' oexpr_list \')\'
    +|\tLGO pseudocall
    	{\n-\t\t$$ = nod(OCALL, $2, $4);\n-\t\t$$ = nod(OPROC, $$, N);\n+\t\t$$ = nod(OPROC, $2, N);\n \t}\n-|\tLDEFER pexpr \'(\' oexpr_list \')\'
    +|\tLDEFER pseudocall
    	{\n-\t\t$$ = nod(OCALL, $2, $4);\n-\t\t$$ = nod(ODEFER, $$, N);\n+\t\t$$ = nod(ODEFER, $2, N);\n \t}
    ```
    このセクションは、`go`ステートメント（`LGO`）と`defer`ステートメント（`LDEFER`）の文法規則を修正しています。
    *   変更前は、`LGO`や`LDEFER`の後に直接「式 `(` 引数リスト `)`」という形式の関数呼び出しが続くことを期待していました。そして、その関数呼び出しを表す`OCALL`ノードを生成し、それを`OPROC`（`go`ステートメント用）または`ODEFER`（`defer`ステートメント用）ノードの引数としていました。
    *   変更後は、`LGO`や`LDEFER`の後に新しく定義された`pseudocall`規則が続くように簡略化されています。これにより、`pseudocall`が生成するASTノード（通常の関数呼び出しまたは`close`呼び出し）が直接`OPROC`または`ODEFER`ノードの引数として渡されるようになります。この変更により、`defer`や`go`の対象として`close`呼び出しが文法的に許可されるようになりました。

3.  **`pseudocall`規則の新規追加**:
    ```diff
    +/*
    + * call-like statements that
    + * can be preceeded by 'defer' and 'go'
    + */
    +pseudocall:
    +\tpexpr \'(\' oexpr_list \')\'
    +\t{\n+\t\t$$ = unsafenmagic($1, $3);\n+\t\tif($$ == N)\n+\t\t\t$$ = nod(OCALL, $1, $3);\n+\t}\n+|\tLCLOSE \'(\' expr \')\'
    +\t{\n+\t\t$$ = nod(OCLOSE, $3, N);\n+\t}
    ```
    これがこのコミットの最も重要な追加部分です。
    *   `pseudocall`は、`defer`や`go`の引数として有効な「呼び出しのような」構文を定義します。
    *   最初の選択肢 `pexpr '(' oexpr_list ')'` は、通常の関数呼び出しを表します。`unsafenmagic`は、Goの組み込み関数（例: `len`, `cap`, `new`, `make`など）に対する特別な処理を行うための内部関数であると推測されます。もし`unsafenmagic`が特別な処理を行わない場合（`$$ == N`）、通常の関数呼び出しを表す`OCALL`ノードが生成されます。
    *   2番目の選択肢 `LCLOSE '(' expr ')'` は、`close`組み込み関数呼び出しを表します。この規則がマッチすると、`close`操作を表す`OCLOSE`ノードが生成されます。
    *   この`pseudocall`規則の導入により、`close(channel)`という構文が`defer`や`go`の引数として有効な「呼び出し」として認識されるようになりました。

4.  **`pexpr`規則の変更**:
    ```diff
    -|\tpexpr \'(\' oexpr_list \')\'
    -\t{\n-\t\t$$ = unsafenmagic($1, $3);\n-\t\tif($$ == N)\n-\t\t\t$$ = nod(OCALL, $1, $3);\n-\t}\n+|\tpseudocall
    ...
    -|\tLCLOSE \'(\' expr \')\'
    -\t{\n-\t\t$$ = nod(OCLOSE, $3, N);\n-\t}\n
    ```
    `pexpr`規則は、プライマリ式（最も基本的な式の構成要素）を定義します。変更前は、`pexpr`自身が通常の関数呼び出しと`close`呼び出しの規則を含んでいました。この変更では、これらの規則が`pseudocall`に移動されたため、`pexpr`は単に`pseudocall`を参照するように簡略化されました。これは、文法定義の重複を排除し、コードの再利用性を高めるためのリファクタリングです。

これらの変更の組み合わせにより、Goコンパイラは`defer close(channel)`という構文を正しく解析し、適切なASTノード（`ODEFER`ノードの子として`OCLOSE`ノード）を生成できるようになり、この有用なパターンがGo言語で利用可能になりました。
