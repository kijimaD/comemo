# [インデックス 26122] ファイルの概要

このコミットは、Goコンパイラの`cmd/go`ツールにおいて、`runtime`パッケージおよび`runtime/internal`配下のパッケージが、`runtime/internal/sys`パッケージに明示的に依存するように変更を加えるものです。これにより、`runtime/internal/sys`が生成する`zversion.go`ファイルが確実にこれらのパッケージに取り込まれるようになります。特に`runtime/internal/atomic`パッケージにおける潜在的な問題を解決することを目的としています。

## 変更の背景

Goのビルドシステムにおいて、`runtime`パッケージとその内部パッケージ（例: `runtime/internal/atomic`）は、Goのバージョン情報やビルドに関する特定のメタデータを含む`zversion.go`というファイルを必要とします。この`zversion.go`ファイルは、`runtime/internal/sys`パッケージによって生成されます。

しかし、Goのビルドツール（`cmd/go`）がパッケージの依存関係を解決する際、`runtime`や`runtime/internal`パッケージが`runtime/internal/sys`に直接的なコード上の依存関係を持たない場合、`cmd/go`は`runtime/internal/sys`をビルド対象に含めない可能性があります。その結果、`zversion.go`が生成されず、`runtime`関連パッケージのビルドが失敗したり、誤ったバージョン情報でビルドされたりする問題が発生していました。

この問題は特にIssue 13655で報告されており、`runtime/internal/atomic`のようなパッケージが`runtime/internal/sys`への依存を適切に認識しないことで、ビルドエラーや予期せぬ動作を引き起こす可能性がありました。このコミットは、この暗黙的な依存関係を`cmd/go`ツールに明示的に認識させることで、問題を解決することを目的としています。

## 前提知識の解説

*   **Goのビルドシステム (`cmd/go`)**: Go言語のソースコードをコンパイルし、実行可能なバイナリを生成するためのコマンドラインツールです。パッケージの依存関係を解析し、適切な順序でビルドを行います。
*   **`runtime`パッケージ**: Goプログラムの実行時環境（ランタイム）を構成する中核的なパッケージです。ガベージコレクション、スケジューラ、メモリ管理など、Go言語の並行処理やメモリ安全性を支える低レベルな機能を提供します。
*   **`runtime/internal`パッケージ**: `runtime`パッケージの内部実装に使われる補助的なパッケージ群です。外部からは直接利用されないことを想定しています。
*   **`runtime/internal/sys`パッケージ**: システム固有の定数や関数、そして`zversion.go`のようなビルド時に生成されるファイルを提供するためのパッケージです。
*   **`zversion.go`**: Goのバージョン情報やビルドに関するメタデータ（例: コンパイラのバージョン、ビルド日時など）を含むGoソースファイルです。Goのツールチェーンによってビルド時に生成され、`runtime`パッケージがこれらの情報にアクセスできるようにします。
*   **パッケージの依存関係**: あるパッケージが別のパッケージの機能を利用する場合、そのパッケージに依存していると言います。Goのビルドシステムは、この依存関係を解決して、すべての依存パッケージがビルドされることを保証します。

## 技術的詳細

このコミットの核心は、`cmd/go`ツールがパッケージの依存関係を処理する方法に介入することです。具体的には、`src/cmd/go/pkg.go`内の`Package`構造体の`load`メソッドにロジックが追加されています。

`load`メソッドは、Goのビルドシステムが個々のパッケージの情報をロードする際に呼び出されます。この変更では、ロード中のパッケージが以下の条件を満たす場合に、`runtime/internal/sys`への依存関係を強制的に追加します。

1.  `p.Standard`が`true`であること: これは、Go標準ライブラリの一部であるパッケージであることを意味します。
2.  `p.ImportPath`が`"runtime"`であるか、`"runtime/internal/"`で始まること: `runtime`パッケージ自体、または`runtime/internal`配下のいずれかのパッケージであることを指します。
3.  `p.ImportPath`が`"runtime/internal/sys"`ではないこと: `runtime/internal/sys`パッケージ自体に、自分自身への依存を追加するのを避けるためです。

これらの条件が満たされた場合、`importPaths`スライスに`"runtime/internal/sys"`が追加されます。これにより、`cmd/go`は`runtime`または`runtime/internal`パッケージをビルドする際に、必ず`runtime/internal/sys`もビルド対象に含めるようになります。結果として、`zversion.go`ファイルが適切に生成され、関連パッケージがその情報にアクセスできるようになります。

この変更は、Goのビルドシステムが持つ「暗黙的な依存関係」を明示的に扱う一例です。コード上では直接`import "runtime/internal/sys"`と書かれていなくても、ビルドの整合性を保つためにツール側で依存関係を注入する必要があるケースを示しています。

## コアとなるコードの解説

### `src/cmd/go/pkg.go` の変更

追加されたコードブロックは、`Package`構造体の`load`メソッド内にあります。このメソッドは、Goのビルドプロセス中に各パッケージのメタデータをロードする役割を担っています。

```go
	// Runtime and its internal packages depend on runtime/internal/sys,
	// so that they pick up the generated zversion.go file.
	// This can be an issue particularly for runtime/internal/atomic;
	// see issue 13655.
	if p.Standard && (p.ImportPath == "runtime" || strings.HasPrefix(p.ImportPath, "runtime/internal/")) && p.ImportPath != "runtime/internal/sys" {
		importPaths = append(importPaths, "runtime/internal/sys")
	}
```

*   **コメント**: この変更の目的を明確に説明しています。「`runtime`とその内部パッケージは`runtime/internal/sys`に依存しており、生成された`zversion.go`ファイルを取得するためである。これは特に`runtime/internal/atomic`で問題となる可能性があり、Issue 13655を参照のこと。」と記載されています。
*   **条件分岐 (`if`)**:
    *   `p.Standard`: 現在ロード中のパッケージがGoの標準ライブラリの一部であるかどうかをチェックします。
    *   `(p.ImportPath == "runtime" || strings.HasPrefix(p.ImportPath, "runtime/internal/"))`: ロード中のパッケージのインポートパスが`"runtime"`であるか、または`"runtime/internal/"`で始まるかをチェックします。これにより、`runtime`パッケージ自体と、`runtime/internal/`ディレクトリ配下のすべてのパッケージ（例: `runtime/internal/atomic`, `runtime/internal/sys`を除く）が対象となります。
    *   `p.ImportPath != "runtime/internal/sys"`: この条件は、`runtime/internal/sys`パッケージ自体が自分自身に依存関係を追加するのを防ぐために重要です。
*   **`importPaths = append(importPaths, "runtime/internal/sys")`**: 上記のすべての条件が真である場合、`importPaths`スライスに文字列`"runtime/internal/sys"`を追加します。`importPaths`は、そのパッケージが直接的または間接的に依存するすべてのパッケージのインポートパスを保持するスライスです。この行により、`cmd/go`は`runtime`または`runtime/internal`パッケージをビルドする際に、`runtime/internal/sys`も必ずビルド対象として含めるようになります。

### `src/cmd/go/go_test.go` の変更

`TestIssue13655`という新しいテスト関数が追加されました。

```go
func TestIssue13655(t *testing.T) {
	tg := testgo(t)
	defer tg.cleanup()
	for _, pkg := range []string{"runtime", "runtime/internal/atomic"} {
		tg.run("list", "-f", "{{.Deps}}", pkg)
		tg.grepStdout("runtime/internal/sys", "did not find required dependency of "+pkg+" on runtime/internal/sys")
	}
}
```

*   **`testgo(t)`**: テスト環境をセットアップするためのヘルパー関数です。
*   **`defer tg.cleanup()`**: テスト終了後にクリーンアップ処理が実行されるようにします。
*   **`for _, pkg := range []string{"runtime", "runtime/internal/atomic"}`**: `runtime`と`runtime/internal/atomic`の2つのパッケージに対してループ処理を行います。
*   **`tg.run("list", "-f", "{{.Deps}}", pkg)`**: `go list`コマンドを実行します。
    *   `-f "{{.Deps}}"`: このフラグは、指定されたパッケージが直接的または間接的に依存するすべてのパッケージのインポートパスのリストを出力するように`go list`に指示します。
*   **`tg.grepStdout("runtime/internal/sys", ...)`**: `go list`コマンドの標準出力に`"runtime/internal/sys"`という文字列が含まれていることを検証します。もし含まれていなければ、テストは失敗し、エラーメッセージ「`did not find required dependency of [pkg] on runtime/internal/sys`」が出力されます。

このテストは、`runtime`と`runtime/internal/atomic`が`runtime/internal/sys`に正しく依存していることを、`go list`コマンドの出力を使って確認することで、`pkg.go`の変更が意図通りに機能していることを保証します。
