## 元コミット内容

`[dev.cc] cmd/dist: show bootstrap build progress in real time`

このコミットは、`cmd/dist` ツールがブートストラップビルドの進行状況をリアルタイムで表示するように変更します。

## 変更の背景

Go言語のビルドプロセス、特にブートストラップビルド（Goコンパイラ自体をビルドするプロセス）は、時間がかかる場合があります。従来の `os/exec` パッケージの `CombinedOutput()` メソッドを使用すると、実行されるコマンドの標準出力と標準エラー出力は、コマンドが完全に終了するまでバッファリングされ、一度にまとめて表示されていました。

この挙動は、ユーザーがビルドの進行状況を把握する上で不便でした。特に、`go1.4 build -v bootstrap/...` のように詳細なログを出力するコマンドの場合、出力がバッファリングされると、ユーザーはビルドがフリーズしているのか、それとも単に時間がかかっているだけなのかを判断できませんでした。

この問題を解決し、ユーザーエクスペリエンスを向上させるために、ビルドの進行状況をリアルタイムで表示するよう変更が導入されました。これにより、ユーザーはビルドの各ステップが実行されるたびにその出力を確認できるようになります。

## 前提知識の解説

*   **`cmd/dist`**: Go言語のソースコードリポジトリに含まれるビルドツールの一つです。Goのツールチェイン（コンパイラ、リンカなど）をビルドするために使用されます。Goの自己ホスト型コンパイラ（Goで書かれたコンパイラがGo自身をコンパイルする）の特性上、初期のGoバージョン（Go 1.4など）を使って新しいGoバージョンをビルドする「ブートストラップ」プロセスにおいて重要な役割を果たします。
*   **ブートストラップビルド**: Go言語のコンパイラやツールチェインはGo言語自体で書かれています。そのため、新しいバージョンのGoをビルドする際には、既存のGoコンパイラ（通常は前の安定版）を使用して新しいコンパイラをビルドします。このプロセスをブートストラップビルドと呼びます。
*   **`os/exec` パッケージ**: Go言語で外部コマンドを実行するための標準ライブラリパッケージです。
    *   **`exec.Command().CombinedOutput()`**: 外部コマンドを実行し、その標準出力と標準エラー出力を結合して `[]byte` スライスとして返します。このメソッドは、コマンドが終了するまで出力をバッファリングします。
    *   **`exec.Command().Run()`**: 外部コマンドを実行し、コマンドが正常に終了したかどうかを示すエラーを返します。このメソッド自体は出力の処理を行いませんが、`Stdout` や `Stderr` フィールドに `io.Writer` を設定することで、出力を直接指定されたライターに書き込むことができます。
*   **`os.Stdout` / `os.Stderr`**: Go言語の `os` パッケージで提供される、標準出力および標準エラー出力への `io.Writer` インターフェースを実装したファイルディスクリプタです。これらに直接書き込むことで、リアルタイムでコンソールに出力を表示できます。
*   **`mode` フラグ**: `cmd/dist` の `run` 関数内で使用される内部的なフラグで、コマンドの実行方法（例：バックグラウンド実行、出力表示の有無、終了コードチェックの有無など）を制御します。このコミットでは `Background` と `ShowOutput` というフラグが特に重要です。

## 技術的詳細

このコミットの核心は、`src/cmd/dist/util.go` 内の `run` 関数における外部コマンドの出力処理方法の変更です。

以前の実装では、`run` 関数は常に `xcmd.CombinedOutput()` を使用して外部コマンドを実行していました。この方法は、コマンドの実行が完了するまでその出力をメモリにバッファリングし、その後まとめて呼び出し元に返します。これは、コマンドの出力が小さい場合や、コマンドの終了後にまとめて処理したい場合には適していますが、長時間実行されるコマンドや、リアルタイムのフィードバックが求められる場合には不向きです。

新しい実装では、`mode` 引数に渡されるフラグをチェックすることで、出力処理の挙動を条件分岐させています。具体的には、以下の条件が満たされた場合に出力をリアルタイムで表示するように変更されました。

1.  `mode` フラグに `ShowOutput` が設定されていること。
2.  `mode` フラグに `Background` が設定されていないこと。

この条件は `mode&(Background|ShowOutput) == ShowOutput` という式で表現されています。これは、コマンドがバックグラウンドで実行されるべきではなく（`Background` フラグが立っていない）、かつ出力が表示されるべきである（`ShowOutput` フラグが立っている）場合に真となります。

この条件が真の場合、`xcmd.Stdout` と `xcmd.Stderr` フィールドにそれぞれ `os.Stdout` と `os.Stderr` が直接割り当てられます。これにより、外部コマンドが標準出力や標準エラー出力に書き込むたびに、そのデータは直接Goプログラムの標準出力/標準エラー出力に転送され、ユーザーのコンソールにリアルタイムで表示されるようになります。その後、`xcmd.Run()` が呼び出され、コマンドが実行されます。

上記の条件が真でない場合（例えば、コマンドがバックグラウンドで実行される場合や、出力が表示されるべきでない場合）、以前と同様に `xcmd.CombinedOutput()` が使用され、出力はバッファリングされます。

この変更により、特にブートストラップビルドのような長時間実行されるプロセスにおいて、ユーザーはビルドの進行状況をより明確に把握できるようになり、ユーザーエクスペリエンスが大幅に向上しました。

## コアとなるコードの解説

変更の中心は、`os/exec.Command` の出力処理方法を切り替える条件分岐です。

1.  **`var data []byte` の追加**: 以前は `data, err := xcmd.CombinedOutput()` で `data` 変数が宣言されていましたが、条件分岐内で `data` を使用するために、先に宣言されています。
2.  **条件分岐 `if mode&(Background|ShowOutput) == ShowOutput`**:
    *   `Background` と `ShowOutput` は `cmd/dist` 内部で定義されたビットフラグです。
    *   `Background|ShowOutput` は、`Background` または `ShowOutput` のいずれかのフラグが立っている状態を表すビットマスクを作成します。
    *   `mode&(Background|ShowOutput)` は、現在の `mode` に `Background` または `ShowOutput` のどちらかのフラグが立っているかをチェックします。
    *   `== ShowOutput` は、この結果が `ShowOutput` フラグのみが立っている状態と等しいかを比較します。つまり、「`Background` フラグは立っておらず、かつ `ShowOutput` フラグは立っている」という条件を意味します。
    *   この条件が真の場合、コマンドはリアルタイムで出力を表示すべきと判断されます。
3.  **リアルタイム出力の設定**:
    *   `xcmd.Stdout = os.Stdout`
    *   `xcmd.Stderr = os.Stderr`
        これにより、実行される外部コマンドの標準出力と標準エラー出力が、Goプログラム自身の標準出力と標準エラー出力に直接リダイレクトされます。
    *   `err = xcmd.Run()`
        `Run()` メソッドが呼び出され、コマンドが実行されます。出力はバッファリングされずに直接コンソールに表示されます。
4.  **バッファリング出力の継続**:
    *   `else { data, err = xcmd.CombinedOutput() }`
        上記の条件が偽の場合（例：コマンドがバックグラウンドで実行される場合や、出力が不要な場合）、以前と同様に `CombinedOutput()` が使用され、出力はバッファリングされます。

この変更により、`cmd/dist` は、ユーザーがリアルタイムのフィードバックを必要とする場合にのみ、出力を直接ストリーミングするようになり、それ以外のケースでは既存のバッファリングメカニズムを維持することで、柔軟性と効率性を両立させています。
