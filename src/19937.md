## 変更の背景

このコミットは、Go 1.4リリースにおける重要な改善点の一つである、Windows上でのモノトニッククロックの実装をドキュメントに追加するものです。モノトニッククロックは、システム時刻の変更（例えば、NTPによる時刻同期や手動での時刻調整）に影響されずに単調に増加する時間を提供します。これは、パフォーマンス測定、タイムアウト処理、イベントの順序付けなど、時間の経過を正確に測定する必要がある多くのアプリケーションにとって不可欠です。

従来のシステムクロックは、時刻の調整によって前後にジャンプする可能性があり、これにより時間差の計算が不正確になる問題がありました。特に、長時間実行されるプロセスや、厳密な時間計測が求められる並行処理において、この問題は深刻でした。Windows環境でモノトニッククロックが利用可能になったことで、Goプログラムはより信頼性の高い時間計測を行うことができるようになり、クロスプラットフォームでの時間計測の一貫性が向上しました。

## 前提知識の解説

### モノトニッククロックとは

モノトニッククロック（Monotonic Clock）とは、システム時刻の変更（例：NTPサーバーによる時刻同期、サマータイムの開始・終了、ユーザーによる手動での時刻変更など）に影響されずに、常に単調に増加する時間を提供するクロックのことです。一度開始されると、その値は決して減少しません。

これに対し、一般的なシステムクロック（Wall Clock Time、またはReal-time Clock）は、現在の日付と時刻を表し、外部からの調整によって前後にジャンプする可能性があります。例えば、NTP（Network Time Protocol）によって時刻が同期されると、システム時刻はわずかに進んだり遅れたりすることがあります。また、サマータイムの切り替え時には1時間単位で時刻がジャンプします。

### モノトニッククロックの重要性

モノトニッククロックは、以下のようなシナリオで非常に重要です。

1.  **パフォーマンス測定**: ある処理の開始から終了までの正確な時間を測定する場合、システム時刻が途中で変更されると、測定結果が不正確になります。モノトニッククロックを使用することで、このような外部要因に影響されずに純粋な経過時間を測定できます。
2.  **タイムアウト処理**: 処理が特定の時間内に完了するかどうかを判断する際に、システム時刻が巻き戻ると、タイムアウトが意図せず延長される可能性があります。モノトニッククロックは、常に時間が進むため、信頼性の高いタイムアウト処理を保証します。
3.  **イベントの順序付け**: 複数のイベントの発生順序を正確に記録する場合、システム時刻のジャンプはイベントのタイムスタンプの順序を狂わせる可能性があります。モノトニッククロックは、イベント間の相対的な時間差を正確に保ちます。
4.  **並行処理と同期**: スレッドやゴルーチン間の同期メカニズムにおいて、時間ベースの待機やスリープを行う際に、モノトニッククロックはより堅牢な動作を保証します。

### Windowsにおける時間計測API

Windowsでは、時間計測のためにいくつかのAPIが提供されています。

*   **`GetSystemTime` / `GetLocalTime`**: 現在のシステム時刻（UTCまたはローカルタイム）を取得します。これらはウォールクロックタイムであり、時刻調整の影響を受けます。
*   **`GetTickCount` / `GetTickCount64`**: システム起動からの経過時間をミリ秒単位で返します。これはモノトニックな値ですが、精度が低く、オーバーフローする可能性があります（`GetTickCount`は32ビット値のため約49.7日でオーバーフロー）。
*   **`QueryPerformanceCounter` / `QueryPerformanceFrequency`**: 高分解能なパフォーマンスカウンタの値を取得します。`QueryPerformanceFrequency`でカウンタの周波数（1秒あたりのティック数）を取得し、`QueryPerformanceCounter`で現在のカウンタ値を取得することで、非常に高精度な経過時間を測定できます。これはWindowsにおけるモノトニッククロックの実装として最も一般的に使用されるAPIです。

Go言語がWindowsでモノトニッククロックを実装する際には、主に `QueryPerformanceCounter` を利用していると考えられます。

## 技術的詳細

Go言語のランタイムは、内部で時間計測を行う際に、可能な限りモノトニッククロックを利用するように設計されています。これは、`time` パッケージの `time.Now()` 関数が返す `time.Time` 型の内部表現にも影響を与えます。Go 1.9以降では、`time.Time` 型はウォールクロックタイムとモノトニッククロックタイムの両方を内部に保持するようになりましたが、Go 1.4の時点では、モノトニッククロックのサポートは主に内部的な時間計測の精度向上に寄与していました。

このコミットが指す「runtime: implement monotonic clocks on windows」は、GoランタイムがWindows上で `QueryPerformanceCounter` などのAPIを適切に利用し、内部的なタイマー、スケジューラ、プロファイラなどがより正確な時間情報に基づいて動作するように改善されたことを意味します。

具体的には、Goランタイムは以下のような処理でモノトニッククロックを利用します。

1.  **ゴルーチンスケジューラ**: ゴルーチンのタイムスライスや、`time.Sleep()` などの時間ベースの操作において、システム時刻の変動に影響されない正確な時間管理が可能になります。
2.  **タイマーとデッドライン**: ネットワークI/Oのタイムアウトや、`time.After()` などのタイマー処理において、より信頼性の高いデッドライン設定と検出が行われます。
3.  **プロファイリングとトレース**: CPUプロファイリングや実行トレースにおいて、イベント間の正確な時間差を記録し、パフォーマンス分析の精度を向上させます。
4.  **GC (Garbage Collection)**: ガベージコレクションの各フェーズの時間計測や、GCの実行頻度を決定する際のヒューリスティックにおいて、より安定した時間情報が利用されます。

Windows環境では、`QueryPerformanceCounter` はCPUのタイムスタンプカウンタ（TSC）や高分解能イベントタイマー（HPET）などのハードウェアカウンタを利用して実装されており、非常に高い精度と低いオーバーヘッドで時間情報を提供します。Goランタイムは、これらのOSレベルの機能と連携し、抽象化された形でモノトニッククロックの機能を提供します。
