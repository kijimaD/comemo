# [インデックス 25514] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）における「マーク完了」および「マーク終了」の処理を分散化することを目的としています。具体的には、これらのGCフェーズ間の遷移処理を、マーク完了を検出したゴルーチン自身が担当するように変更し、従来のGCコーディネーターやバックグラウンド完了バリアの利用を廃止する第一歩となります。これにより、GCの制御フローが簡素化され、特定のゴルーチンに依存しない、より柔軟なGCスケジューリングが可能になります。

## 変更の背景

Goのガベージコレクションは、複数のフェーズに分かれて実行されます。このコミット以前は、GCの「マークフェーズ」の完了や、GC全体の「終了フェーズ」への移行を調整するために、GCコーディネーターと呼ばれる特別なゴルーチンや、バックグラウンド完了バリアといったメカニズムが使用されていました。しかし、これらの集中管理的なアプローチは、GCのスケジューリングに複雑さをもたらし、特定の状況下でパフォーマンスのボトルネックとなる可能性がありました。

このコミットの背景には、GCの制御をより分散化し、GCの完了を検出した任意のゴルーチンが直接次のフェーズへの移行をトリガーできるようにすることで、GCのオーバーヘッドを削減し、全体的なスループットとレイテンシを改善するという目的があります。特に、GCコーディネーターへの「yield」を強制するようなワークアラウンドがコードベースに存在しており、これらを排除することでコードの複雑性を減らすことも意図されています。

また、この変更はIssue #11970に関連しており、GCのマークフェーズにおける並行処理の効率化と、フェーズ間のスムーズな移行を実現するための広範な取り組みの一環です。

## 前提知識の解説

このコミットを理解するためには、Goのガベージコレクションの基本的な仕組みと、いくつかの専門用語について知っておく必要があります。

1.  **Goのガベージコレクション (GC)**: Goは、並行マーク＆スイープ方式のGCを採用しています。これは、プログラムの実行と並行してGCの一部を実行することで、アプリケーションの一時停止時間（Stop-The-World, STW）を最小限に抑えることを目指しています。
    *   **マークフェーズ (Mark Phase)**: GCの主要なフェーズの一つで、到達可能なオブジェクト（プログラムがまだ参照しているオブジェクト）を特定し、マークします。GoのGCでは、このマークフェーズがさらに「マーク1」と「マーク2」に分けられることがあります。
        *   **マーク1 (Mark 1)**: 初期マークフェーズ。
        *   **マーク2 (Mark 2)**: マーク1で取りこぼしたオブジェクトや、マーク中に変更されたオブジェクトを再スキャンするフェーズ。
    *   **マーク終了フェーズ (Mark Termination Phase)**: マークフェーズが完了した後、GCが次のフェーズ（スイープフェーズなど）に移行する前に、最終的なクリーンアップや状態の更新を行うフェーズ。このフェーズは通常、STWを伴います。
    *   **Stop-The-World (STW)**: GCの特定の段階で、すべてのアプリケーションゴルーチンの実行を一時的に停止させる期間。GoのGCはSTW時間を極力短くするように設計されています。
    *   **GCコーディネーター (GC Coordinator)**: 以前のGo GC実装において、GCのフェーズ遷移やワーカーゴルーチンの調整を担当していた特別なゴルーチン。
    *   **バックグラウンド完了バリア (Background Completion Barriers)**: GCのバックグラウンド処理が完了したことを通知・同期するためのメカニズム。
    *   **マークワーカー (Mark Worker)**: マークフェーズ中に実際にオブジェクトをスキャンしてマークするゴルーチン。これらは通常、複数のP（プロセッサ）上で並行して実行されます。
    *   **プリエンプション (Preemption)**: Goランタイムが、実行中のゴルーチンを強制的に中断し、別のゴルーチンにCPUを割り当てる機能。これにより、長時間実行されるゴルーチンがシステムを独占するのを防ぎ、公平なスケジューリングを実現します。GCのSTWフェーズでは、すべてのゴルーチンが停止する必要があるため、プリエンプションが重要な役割を果たします。

## 技術的詳細

このコミットの核心は、GCのマークフェーズ完了からマーク終了フェーズへの移行ロジックを、集中管理型から分散型へと変更した点にあります。

以前のGCでは、マークフェーズの完了を検出したゴルーチンは、GCコーディネーターに処理を委譲するか、バックグラウンド完了バリアを通じて完了を通知していました。GCコーディネーターは、すべてのマークワーカーが完了したことを確認した後、マーク終了フェーズを開始する役割を担っていました。

このコミットでは、`gcMarkDone()` 関数がその役割を拡張し、マーク完了を検出した任意のゴルーチンが直接、マーク1からマーク2への遷移、またはマーク2からマーク終了フェーズへの遷移を実行するようになりました。

具体的な変更点は以下の通りです。

1.  **`gcMarkDone()` の役割の拡大**:
    *   `gcMarkDone()` は、`work.markDoneSema` という新しいセマフォによって保護されるようになりました。これにより、複数のゴルーチンが同時に遷移処理を開始しようとするのを防ぎます。
    *   マークフェーズが実際に完了しているか（`gcphase == _GCmark && work.nwait == work.nproc && !gcMarkWorkAvailable(nil)`）を再確認します。
    *   `gcBlackenPromptly` の状態に応じて、マーク1からマーク2への遷移、またはマーク2からマーク終了への遷移を直接実行します。
    *   **マーク1からマーク2への遷移**:
        *   新しいワーカーの開始を一時的に禁止します (`xaddint64(&gcController.dedicatedMarkWorkersNeeded, -0xffffffff)` など)。
        *   `gcMarkRootCheck()` を呼び出して、グローバルルートを再スキャンします。
        *   `gcBlackenPromptly = true` を設定し、マーク2フェーズに入ったことを示します。これにより、Pごとのワークバッファのキャッシュが無効になります。
        *   `forEachP` を使用して、すべてのPのワークバッファを破棄し、マーク1ワーカーがループを終了するのを待ちます。
        *   マーク2ワーカーの開始を許可します。
        *   `gcMarkDone()` を再帰的に呼び出すことで、マーク2の完了をチェックし、必要であればマーク終了フェーズへ移行します。
    *   **マーク2からマーク終了への遷移**:
        *   `work.tMarkTerm` と `work.pauseStart` を更新し、STWを開始します。
        *   `gcWakeAllAssists()` を呼び出し、GCアシストゴルーチンを再開します。
        *   `semrelease(&work.markDoneSema)` でセマフォを解放します。
        *   `gcController.endCycle()` を呼び出し、GCサイクルを終了します。
        *   `gcMarkTermination()` を呼び出して、マーク終了フェーズを実行します。

2.  **GCコーディネーターの廃止**:
    *   `src/runtime/mgc.go` 内の `startGCCoordinator()` 関数が `// TODO(austin): This function unused. Remove it and backgroundgc.` とコメントされ、将来的に削除されることが示唆されています。
    *   `gcStart()` 関数から `startGCCoordinator()` の呼び出しが削除されました。
    *   `gc(gcBackgroundMode)` の呼び出しが `gcMarkTermination()` に置き換えられ、バックグラウンドGCの処理が直接マーク終了フェーズに移行するようになりました。

3.  **マークワーカーのプリエンプション**:
    *   `gcBgMarkWorker` が `gcMarkDone()` を呼び出す際に、一時的にプリエンプション可能になるように変更されました。具体的には、`p.gcBgMarkWorker = nil` でPとの関連付けを解除し、`releasem(mp)` でM（マシン）を解放することで、プリエンプションを可能にします。`gcMarkDone()` の処理が完了した後、再度Pと関連付け (`casgp(&p.gcBgMarkWorker, nil, gp)`)、プリエンプションを無効にします。これにより、マークワーカーがSTWを開始し、GCの最終クリーンアップを実行できるようになります。

これらの変更により、GCのフェーズ遷移がより動的になり、GCの完了を検出したゴルーチンがその場で次のフェーズへの移行を主導できるようになります。これにより、GCコーディネーターのような集中管理ポイントが不要になり、GCの応答性と効率が向上することが期待されます。

## コアとなるコードの変更箇所

このコミットの主要な変更は `src/runtime/mgc.go` に集中しています。

1.  **`src/runtime/mgc.go`**:
    *   `work` 構造体に `markDoneSema uint32` が追加され、マーク完了遷移の排他制御に使用されます。
    *   `work.bgMark1` と `work.bgMark2` が `// TODO(austin): Unused. Remove.` とコメントされ、将来的に削除されることが示唆されています。
    *   `gcStart()` 関数内のGCフェーズ遷移ロジックが大幅に変更され、`startGCCoordinator()` の呼び出しが削除され、`gc(mode)` の代わりに `gcMarkTermination()` が直接呼び出されるようになりました。
    *   `gcMarkDone()` 関数が完全に書き直され、マーク1からマーク2、およびマーク2からマーク終了への遷移ロジックが組み込まれました。この関数は、`work.markDoneSema` を使用して排他制御を行い、GCフェーズの進行を管理します。
    *   `gc()` 関数が `gcMarkTermination()` にリネームされ、その役割がマーク終了フェーズの実行に特化されました。
    *   `gcBgMarkWorker()` 関数内で、`gcMarkDone()` を呼び出す際に、ワーカーゴルーチンが一時的にプリエンプション可能になるように変更されました。これは、`p.gcBgMarkWorker = nil` と `releasem(mp)` を使用して実現されます。

2.  **`src/runtime/malloc.go`**:
    *   `mallocgc` 関数内のGCスケジューリングに関する `TODO` コメントが更新され、以前のワークアラウンドが不要になったことが示されています。

3.  **`src/runtime/mgcmark.go`**:
    *   `gcMarkDone()` の呼び出し箇所が変更され、`Gosched()` の呼び出しが削除されました。これは、GCコーディネーターへの委譲が不要になったためです。

4.  **`src/runtime/proc.go`**:
    *   `forEachP` 関数に `//go:systemstack` ディレクティブが追加され、システムスタックで実行されることが明示されました。
    *   `findRunnableGCWorker` のロジックが簡素化され、`work.bgMark1.done` や `work.bgMark2.done` のチェックが削除されました。
    *   `schedule()` 関数内のアイドルタイムマーキングの条件が変更され、`work.bgMark1.done` や `work.bgMark2.done` のチェックが削除されました。

## コアとなるコードの解説

最も重要な変更は `src/runtime/mgc.go` の `gcMarkDone()` 関数です。

```go
func gcMarkDone() {
	semacquire(&work.markDoneSema, false)

	// Re-check transition condition under transition lock.
	if !(gcphase == _GCmark && work.nwait == work.nproc && !gcMarkWorkAvailable(nil)) {
		semrelease(&work.markDoneSema)
		return
	}

	// Disallow starting new workers so that any remaining workers
	// in the current mark phase will drain out.
	xaddint64(&gcController.dedicatedMarkWorkersNeeded, -0xffffffff)
	xaddint64(&gcController.fractionalMarkWorkersNeeded, -0xffffffff)

	if !gcBlackenPromptly {
		// Transition from mark 1 to mark 2.
		// ... (詳細なマーク1からマーク2への遷移ロジック) ...
		incnwait := xadd(&work.nwait, +1)
		if incnwait == work.nproc && !gcMarkWorkAvailable(nil) {
			// This recursion is safe because the call
			// can't take this same "if" branch.
			gcMarkDone()
		}
	} else {
		// Transition to mark termination.
		// ... (詳細なマーク2からマーク終了への遷移ロジック) ...
		gcMarkTermination()
	}
}
```

この `gcMarkDone()` 関数は、GCのマークフェーズが完了したことを検出したゴルーチンによって呼び出されます。

1.  **`semacquire(&work.markDoneSema, false)`**: まず、`work.markDoneSema` というセマフォを取得します。これは、複数のゴルーチンが同時にこの遷移ロジックを実行しようとするのを防ぐための排他制御です。
2.  **条件チェック**: `gcphase == _GCmark && work.nwait == work.nproc && !gcMarkWorkAvailable(nil)` という条件で、実際にマークフェーズが完了し、すべてのマークワーカーが作業を終えているかを確認します。このチェックはセマフォの下で行われるため、正確な状態を反映します。
3.  **ワーカーの停止**: 新しいマークワーカーの起動を一時的に禁止します。これは、現在のマークフェーズに残っているワーカーが作業を完了し、新しいフェーズの作業を開始しないようにするためです。
4.  **フェーズ遷移の分岐**:
    *   `!gcBlackenPromptly` の場合、これは「マーク1からマーク2への遷移」を意味します。ここでは、グローバルルートの再スキャン、Pごとのワークバッファの破棄、`gcBlackenPromptly` の設定（マーク2フェーズへの移行を示す）、そしてマーク2ワーカーの再開といった処理が行われます。最後に、`gcMarkDone()` を再帰的に呼び出すことで、マーク2の完了をチェックし、必要であればマーク終了フェーズへ移行します。
    *   `gcBlackenPromptly` の場合、これは「マーク2からマーク終了への遷移」を意味します。ここでは、STWの開始、GCアシストの再開、GCサイクルの終了、そして `gcMarkTermination()` の呼び出しによって、GCの最終クリーンアップと世界のリスタートが行われます。

この変更により、GCのフェーズ遷移がより自律的になり、GCの完了を検出したゴルーチンが直接次のステップに進むことができるようになりました。これにより、GCコーディネーターのような集中管理ポイントが不要になり、GCの応答性と効率が向上します。また、`gcBgMarkWorker` が `gcMarkDone()` を呼び出す際に一時的にプリエンプション可能になることで、STWを安全に実行し、GCの最終処理を完了させることが可能になります。
