# [インデックス 23516] ファイルの概要

このコミットは、Go言語の `net` パッケージにおける一連のネットワーク関連テスト、特に `TestLookup` シリーズおよび外部ネットワークに依存するテストの信頼性を向上させることを目的としています。Windows環境下での外部ネットワーク接続の有無がテスト結果に与える影響を考慮し、テストのスキップ条件をより厳密にすることで、不安定なテスト（flaky tests）の発生を防ぎます。

## コミット

`net: fix the series of TestLookup and external tests`

このコミットは、`net` パッケージ内の `TestLookup` シリーズおよび外部ネットワークに依存するテストを修正します。特にWindows環境において、テスト対象ノードが外部接続性を持っていることを確認する必要があるため、その条件をテストに組み込みました。

## 変更の背景

Go言語の `net` パッケージは、ネットワーク通信に関する低レベルおよび高レベルの機能を提供します。このパッケージのテストは、様々なネットワーク環境やオペレーティングシステムで正しく動作することを確認するために重要です。しかし、ネットワークテストは環境依存性が高く、特に外部ネットワークへの接続が必要な場合、テスト実行環境のネットワーク設定や状態によって結果が不安定になることがあります。

このコミットの背景には、Issue #10795 があります。このIssueでは、特にWindows環境において、外部ネットワーク接続がない場合に `net` パッケージの `Lookup` 関連API（`LookupSRV`, `LookupMX`, `LookupNS`, `LookupTXT`, `LookupAddr`, `LookupCNAME`, `LookupHost`, `LookupIP` など）が期待通りの結果を返さない、あるいはエラーを発生させるという問題が報告されていました。

WindowsのDNSリゾルバは、外部ネットワーク接続がない場合にIPv4やIPv6のアドレス解決に関するリソースレコードを返さないことがあります。これにより、外部接続を前提としたテストが、実際には接続がない環境で実行された場合に失敗し、テストの信頼性を損なっていました。このコミットは、このような環境依存のテスト失敗を回避し、テストがより堅牢になるように修正を加えています。具体的には、テストを実行する前に必要な外部接続性（IPv4およびIPv6）が利用可能であることを確認し、そうでない場合はテストをスキップするように変更されました。

## 前提知識の解説

### Go言語の `net` パッケージ

`net` パッケージは、IPアドレス、TCP/UDP接続、DNSルックアップなど、ネットワークプログラミングの基本的な機能を提供します。
- **`LookupSRV`**: サービスロケータレコード (SRVレコード) をルックアップします。
- **`LookupMX`**: メールエクスチェンジャレコード (MXレコード) をルックアップします。
- **`LookupNS`**: ネームサーバレコード (NSレコード) をルックアップします。
- **`LookupTXT`**: テキストレコード (TXTレコード) をルックアップします。
- **`LookupAddr`**: IPアドレスからホスト名をルックアップします (逆引きDNS)。
- **`LookupCNAME`**: 正規名 (CNAMEレコード) をルックアップします。
- **`LookupHost`**: ホスト名からIPアドレスをルックアップします。
- **`LookupIP`**: ホスト名からIPアドレスをルックアップします。

### DNS (Domain Name System)

インターネット上のドメイン名とIPアドレスを対応させるシステムです。`net` パッケージの `Lookup` 関数群は、このDNSを利用して情報を取得します。

### IPv4とIPv6

インターネットプロトコルには、現在主にIPv4とIPv6の2つのバージョンがあります。
- **IPv4**: 32ビットのアドレスを使用し、約43億個のアドレスを表現できます。
- **IPv6**: 128ビットのアドレスを使用し、IPv4では不足するアドレス空間を補完します。

ネットワークテストでは、どちらのプロトコルが利用可能か、またテスト環境で有効になっているかが重要になります。

### `testing` パッケージとテストフラグ

Goの標準テストフレームワークである `testing` パッケージは、テストの実行を制御するための様々な機能を提供します。
- **`testing.Short()`**: `-short` フラグが指定された場合に `true` を返します。これにより、時間のかかるテストや外部リソースに依存するテストをスキップできます。
- **`*testExternal`**: このコミットで言及されているように、外部ネットワークへの接続が必要なテストを制御するためのカスタムフラグ（`flag.Bool` で定義されることが多い）です。
- **`*testIPv4`, `*testIPv6`**: このコミットで導入された、IPv4/IPv6の外部接続性を明示的にテストで考慮するためのフラグです。

### WindowsのDNSリゾルバの特性

Windowsオペレーティングシステムでは、DNSリゾルバの動作が他のOS（LinuxやmacOSなど）と異なる場合があります。特に、ネットワークインターフェースが外部ネットワークに接続されていない場合、DNSルックアップAPIがIPv4やIPv6に関連するリソースレコードを返さないことがあります。これは、システムが「外部接続がない」と判断し、無効なレコードを返さないようにする挙動と考えられます。この特性が、外部接続を前提としたテストの不安定性の原因となっていました。

## 技術的詳細

このコミットの主要な変更点は以下の通りです。

1.  **外部テストのスキップ条件の厳格化**:
    `src/net/external_test.go` および `src/net/lookup_test.go` 内の外部ネットワークに依存するテストにおいて、スキップ条件がより厳しくなりました。以前は `!supportsIPv4 && !supportsIPv6` のように、どちらか一方でもサポートされていればテストが実行される可能性がありましたが、新しい条件では `!supportsIPv4 || !supportsIPv6 || !*testIPv4 || !*testIPv6` のように、IPv4とIPv6の両方がサポートされ、かつそれぞれのテストフラグが有効になっていることを要求します。これにより、テスト実行環境がIPv4とIPv6の両方の外部接続性を完全に満たさない限り、テストはスキップされるようになります。

2.  **データ駆動型テストへの移行**:
    `src/net/lookup_test.go` 内の多くの `Lookup` 関連テスト（`LookupSRV`, `LookupMX`, `LookupNS`, `LookupTXT`, `LookupAddr`, `LookupCNAME`, `LookupHost`, `LookupIP`）が、テストケースを構造体のスライスとして定義するデータ駆動型テストの形式にリファクタリングされました。これにより、テストケースの追加や管理が容易になり、コードの重複が削減されます。

3.  **ドメイン名マッチングの精度の向上**:
    `strings.Contains` を使用していたドメイン名やホスト名の検証が、`strings.HasSuffix` および `strings.HasSuffix(..., ".")` に変更されました。これは、部分文字列の一致ではなく、末尾の一致を厳密に確認することで、テストの精度を高めるためです。例えば、`google.com` と `sub.google.com` の違いを正確に区別できるようになります。また、FQDN (Fully Qualified Domain Name) の末尾に付くドット (`.`) の有無も考慮されるようになりました。

4.  **Windows環境での挙動に関するコメント追加**:
    `src/net/main_test.go` の `testIPv4` および `testIPv6` フラグの定義に、Windows環境における `Lookup` APIの挙動に関する注意書きが追加されました。これにより、開発者がこのフラグの重要性とWindows特有の問題を理解しやすくなります。

これらの変更により、テストの実行環境に起因する偽陽性（false positive）の失敗が減少し、テスト結果の信頼性が向上します。特にCI/CD環境など、多様なOSでテストが実行される場面でその効果を発揮します。

## コアとなるコードの解説

### `external_test.go` の変更

`TestResolveGoogle` と `TestDialGoogle` の両方で、テストをスキップする条件が `!supportsIPv4 && !supportsIPv6` から `!supportsIPv4 || !supportsIPv6 || !*testIPv4 || !*testIPv6` に変更されました。
- `supportsIPv4` / `supportsIPv6`: テスト実行環境がIPv4 / IPv6をサポートしているかどうかの内部的なチェック。
- `*testIPv4` / `*testIPv6`: コマンドライン引数で `-ipv4` / `-ipv6` フラグが指定されているかどうかのチェック。これらのフラグは、外部IPv4 / IPv6接続が存在すると仮定するかどうかを制御します。

この変更により、テストは以下のいずれかの条件が満たされた場合にスキップされます。
1.  IPv4がサポートされていない。
2.  IPv6がサポートされていない。
3.  `-ipv4=false` が指定されている（外部IPv4接続がないと仮定）。
4.  `-ipv6=false` が指定されている（外部IPv6接続がないと仮定）。

これにより、テストが実行されるのは、IPv4とIPv6の両方がサポートされ、かつ外部接続が期待される場合に限定され、Windows環境での不安定な挙動を回避します。また、以前の複雑な `switch` 文によるエラーハンドリングとスキップロジックが削除され、コードが簡潔になりました。

### `lookup_test.go` の変更

- **データ駆動型テスト**: 各 `Lookup` テスト関数内で、テスト対象の入力と期待される出力を含む構造体スライス（例: `lookupGoogleSRVTests`）が定義されています。テストはこれらのスライスをループ処理することで実行されます。これにより、テストケースの追加や変更が容易になり、テストコードの可読性と保守性が向上します。
- **IPv4接続性チェック**: 各 `Lookup` テストの冒頭に `if !supportsIPv4 || !*testIPv4 { t.Skip("IPv4 is required") }` という行が追加されました。これは、これらの `Lookup` テストがIPv4の外部接続性を必要とすることを明示し、条件を満たさない場合はテストをスキップします。これにより、Windows環境でIPv4接続がない場合に発生していたテスト失敗を防ぎます。
- **ドメイン名マッチングの改善**: `strings.Contains` から `strings.HasSuffix` への変更は、ドメイン名の検証においてより厳密な比較を行うためのものです。例えば、`google.com` を含む文字列を検索する場合、`strings.Contains` は `sub.google.com` も一致としますが、`strings.HasSuffix` は末尾が `google.com` であることを確認するため、より正確な検証が可能になります。また、FQDNの末尾のドット (`.`) の有無も考慮に入れることで、DNSの挙動に合わせた柔軟な検証が可能になっています。

### `main_test.go` の変更

`testIPv4` と `testIPv6` のフラグ定義に、Windows環境での `Lookup` APIの挙動に関するコメントが追加されました。このコメントは、Windowsでは外部IPv4/IPv6接続がない場合に `Lookup` APIが関連するリソースレコードを返さない可能性があることを明確に示しています。これは、このコミットの変更の根拠となる重要な情報であり、将来のGo開発者が同様の問題に遭遇した際に役立ちます。

## 変更の背景

Go言語の `net` パッケージは、ネットワーク通信に関する低レベルおよび高レベルの機能を提供します。このパッケージのテストは、様々なネットワーク環境やオペレーティングシステムで正しく動作することを確認するために重要です。しかし、ネットワークテストは環境依存性が高く、特に外部ネットワークへの接続が必要な場合、テスト実行環境のネットワーク設定や状態によって結果が不安定になることがあります。

このコミットの背景には、Issue #10795 があります。このIssueでは、特にWindows環境において、外部ネットワーク接続がない場合に `net` パッケージの `Lookup` 関連API（`LookupSRV`, `LookupMX`, `LookupNS`, `LookupTXT`, `LookupAddr`, `LookupCNAME`, `LookupHost`, `LookupIP` など）が期待通りの結果を返さない、あるいはエラーを発生させるという問題が報告されていました。

WindowsのDNSリゾルバは、外部ネットワーク接続がない場合にIPv4やIPv6のアドレス解決に関するリソースレコードを返さないことがあります。これは、システムが「外部接続がない」と判断し、無効なレコードを返さないようにする挙動と考えられます。この特性が、外部接続を前提としたテストの不安定性の原因となっていました。

このコミットは、このような環境依存のテスト失敗を回避し、テストがより堅牢になるように修正を加えています。具体的には、テストを実行する前に必要な外部接続性（IPv4およびIPv6）が利用可能であることを確認し、そうでない場合はテストをスキップするように変更されました。

## 前提知識の解説

### Go言語の `net` パッケージ

`net` パッケージは、IPアドレス、TCP/UDP接続、DNSルックアップなど、ネットワークプログラミングの基本的な機能を提供します。
- **`LookupSRV`**: サービスロケータレコード (SRVレコード) をルックアップします。
- **`LookupMX`**: メールエクスチェンジャレコード (MXレコード) をルックアップします。
- **`LookupNS`**: ネームサーバレコード (NSレコード) をルックアップします。
- **`LookupTXT`**: テキストレコード (TXTレコード) をルックアップします。
- **`LookupAddr`**: IPアドレスからホスト名をルックアップします (逆引きDNS)。
- **`LookupCNAME`**: 正規名 (CNAMEレコード) をルックアップします。
- **`LookupHost`**: ホスト名からIPアドレスをルックアップします。
- **`LookupIP`**: ホスト名からIPアドレスをルックアップします。

### DNS (Domain Name System)

インターネット上のドメイン名とIPアドレスを対応させるシステムです。`net` パッケージの `Lookup` 関数群は、このDNSを利用して情報を取得します。

### IPv4とIPv6

インターネットプロトコルには、現在主にIPv4とIPv6の2つのバージョンがあります。
- **IPv4**: 32ビットのアドレスを使用し、約43億個のアドレスを表現できます。
- **IPv6**: 128ビットのアドレスを使用し、IPv4では不足するアドレス空間を補完します。

ネットワークテストでは、どちらのプロトコルが利用可能か、またテスト環境で有効になっているかが重要になります。

### `testing` パッケージとテストフラグ

Goの標準テストフレームワークである `testing` パッケージは、テストの実行を制御するための様々な機能を提供します。
- **`testing.Short()`**: `-short` フラグが指定された場合に `true` を返します。これにより、時間のかかるテストや外部リソースに依存するテストをスキップできます。
- **`*testExternal`**: このコミットで言及されているように、外部ネットワークへの接続が必要なテストを制御するためのカスタムフラグ（`flag.Bool` で定義されることが多い）です。
- **`*testIPv4`, `*testIPv6`**: このコミットで導入された、IPv4/IPv6の外部接続性を明示的にテストで考慮するためのフラグです。

### WindowsのDNSリゾルバの特性

Windowsオペレーティングシステムでは、DNSリゾルバの動作が他のOS（LinuxやmacOSなど）と異なる場合があります。特に、ネットワークインターフェースが外部ネットワークに接続されていない場合、DNSルックアップAPIがIPv4やIPv6に関連するリソースレコードを返さないことがあります。これは、システムが「外部接続がない」と判断し、無効なレコードを返さないようにする挙動と考えられます。この特性が、外部接続を前提としたテストの不安定性の原因となっていました。

## 技術的詳細

このコミットの主要な変更点は以下の通りです。

1.  **外部テストのスキップ条件の厳格化**:
    `src/net/external_test.go` および `src/net/lookup_test.go` 内の外部ネットワークに依存するテストにおいて、スキップ条件がより厳しくなりました。以前は `!supportsIPv4 && !supportsIPv6` のように、どちらか一方でもサポートされていればテストが実行される可能性がありましたが、新しい条件では `!supportsIPv4 || !supportsIPv6 || !*testIPv4 || !*testIPv6` のように、IPv4とIPv6の両方がサポートされ、かつそれぞれのテストフラグが有効になっていることを要求します。これにより、テスト実行環境がIPv4とIPv6の両方の外部接続性を完全に満たさない限り、テストはスキップされるようになります。

2.  **データ駆動型テストへの移行**:
    `src/net/lookup_test.go` 内の多くの `Lookup` 関連テスト（`LookupSRV`, `LookupMX`, `LookupNS`, `LookupTXT`, `LookupAddr`, `LookupCNAME`, `LookupHost`, `LookupIP`）が、テストケースを構造体のスライスとして定義するデータ駆動型テストの形式にリファクタリングされました。これにより、テストケースの追加や管理が容易になり、コードの重複が削減されます。

3.  **ドメイン名マッチングの精度の向上**:
    `strings.Contains` を使用していたドメイン名やホスト名の検証が、`strings.HasSuffix` および `strings.HasSuffix(..., ".")` に変更されました。これは、部分文字列の一致ではなく、末尾の一致を厳密に確認することで、テストの精度を高めるためです。例えば、`google.com` と `sub.google.com` の違いを正確に区別できるようになります。また、FQDN (Fully Qualified Domain Name) の末尾に付くドット (`.`) の有無も考慮されるようになりました。

4.  **Windows環境での挙動に関するコメント追加**:
    `src/net/main_test.go` の `testIPv4` および `testIPv6` フラグの定義に、Windows環境における `Lookup` APIの挙動に関する注意書きが追加されました。これにより、開発者がこのフラグの重要性とWindows特有の問題を理解しやすくなります。

これらの変更により、テストの実行環境に起因する偽陽性（false positive）の失敗が減少し、テスト結果の信頼性が向上します。特にCI/CD環境など、多様なOSでテストが実行される場面でその効果を発揮します。

## コアとなるコードの解説

### `external_test.go` の変更

`TestResolveGoogle` と `TestDialGoogle` の両方で、テストをスキップする条件が `!supportsIPv4 && !supportsIPv6` から `!supportsIPv4 || !supportsIPv6 || !*testIPv4 || !*testIPv6` に変更されました。
- `supportsIPv4` / `supportsIPv6`: テスト実行環境がIPv4 / IPv6をサポートしているかどうかの内部的なチェック。
- `*testIPv4` / `*testIPv6`: コマンドライン引数で `-ipv4` / `-ipv6` フラグが指定されているかどうかのチェック。これらのフラグは、外部IPv4 / IPv6接続が存在すると仮定するかどうかを制御します。

この変更により、テストは以下のいずれかの条件が満たされた場合にスキップされます。
1.  IPv4がサポートされていない。
2.  IPv6がサポートされていない。
3.  `-ipv4=false` が指定されている（外部IPv4接続がないと仮定）。
4.  `-ipv6=false` が指定されている（外部IPv6接続がないと仮定）。

これにより、テストが実行されるのは、IPv4とIPv6の両方がサポートされ、かつ外部接続が期待される場合に限定され、Windows環境での不安定な挙動を回避します。また、以前の複雑な `switch` 文によるエラーハンドリングとスキップロジックが削除され、コードが簡潔になりました。

### `lookup_test.go` の変更

- **データ駆動型テスト**: 各 `Lookup` テスト関数内で、テスト対象の入力と期待される出力を含む構造体スライス（例: `lookupGoogleSRVTests`）が定義されています。テストはこれらのスライスをループ処理することで実行されます。これにより、テストケースの追加や変更が容易になり、テストコードの可読性と保守性が向上します。
- **IPv4接続性チェック**: 各 `Lookup` テストの冒頭に `if !supportsIPv4 || !*testIPv4 { t.Skip("IPv4 is required") }` という行が追加されました。これは、これらの `Lookup` テストがIPv4の外部接続性を必要とすることを明示し、条件を満たさない場合はテストをスキップします。これにより、Windows環境でIPv4接続がない場合に発生していたテスト失敗を防ぎます。
- **ドメイン名マッチングの改善**: `strings.Contains` から `strings.HasSuffix` への変更は、ドメイン名の検証においてより厳密な比較を行うためのものです。例えば、`google.com` を含む文字列を検索する場合、`strings.Contains` は `sub.google.com` も一致としますが、`strings.HasSuffix` は末尾が `google.com` であることを確認するため、より正確な検証が可能になります。また、FQDNの末尾のドット (`.`) の有無も考慮に入れることで、DNSの挙動に合わせた柔軟な検証が可能になっています。

### `main_test.go` の変更

`testIPv4` と `testIPv6` のフラグ定義に、Windows環境での `Lookup` APIの挙動に関するコメントが追加されました。このコメントは、Windowsでは外部IPv4/IPv6接続がない場合に `Lookup` APIが関連するリソースレコードを返さない可能性があることを明確に示しています。これは、このコミットの変更の根拠となる重要な情報であり、将来のGo開発者が同様の問題に遭遇した際に役立ちます。
