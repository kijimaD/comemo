# [インデックス 28211] ファイルの概要

このコミットは、Goランタイムが予期せぬシグナルによってパニックに陥った際に表示されるエラーメッセージの可読性を向上させるためのものです。具体的には、シグナル番号の16進数表記だけでなく、そのシグナルの人間が読める名前（例: `SIGSEGV`）も出力するように変更されました。これにより、開発者はパニックの原因をより迅速に特定できるようになります。

## 変更の背景

Goプログラムが予期せぬシグナル（例えば、セグメンテーション違反を示す`SIGSEGV`）を受け取ってパニックに陥った際、以前のGoランタイムは、そのシグナルを16進数の数値としてのみ出力していました。例えば、`SIGSEGV`はUnix系システムでは通常`11`という番号に対応しますが、パニックメッセージには`[signal 0xb ...]`のように表示されていました。

この数値だけの表示では、特にシグナルに関する知識が浅い開発者にとって、何が問題なのかを直感的に理解するのが困難でした。シグナル番号とそれが意味する内容を関連付けるためには、別途ドキュメントを参照したり、経験則に頼ったりする必要がありました。

この問題は、GitHub issue #13969 で報告されており、より分かりやすいシグナル名（例: `SIGSEGV: segmentation violation`）をパニックメッセージに含めることが求められていました。このコミットは、この要望に応え、デバッグ時の情報提供を改善することを目的としています。

## 前提知識の解説

### Goランタイムとパニック

Goプログラムは、実行中に回復不能なエラー（例: nilポインタ参照、配列の範囲外アクセス）が発生した場合に「パニック」を起こします。パニックは、通常の制御フローを中断し、スタックをアンワインドしながら`defer`関数を実行し、最終的にプログラムを終了させます。Goランタイムは、OSから受け取ったシグナルによってもパニックを引き起こすことがあります。

### シグナル（Unix系システム）

Unix系オペレーティングシステム（Linux, macOSなど）では、シグナルはプロセスに対して非同期に通知されるイベントです。これらは、特定の条件（例: 割り込み、不正なメモリアクセス、子プロセスの終了）が発生したことをプロセスに知らせるために使用されます。主要なシグナルには以下のようなものがあります。

*   **SIGINT (2)**: 割り込み（Ctrl+Cなど）
*   **SIGTERM (15)**: プロセス終了要求
*   **SIGKILL (9)**: 強制終了（捕捉・無視・ブロック不可）
*   **SIGSEGV (11)**: セグメンテーション違反（不正なメモリアクセス）
*   **SIGFPE (8)**: 浮動小数点例外
*   **SIGBUS (7)**: バスエラー（不正なメモリアクセス、通常はアラインメント違反）

Goランタイムは、これらのシグナルの一部を捕捉し、プログラムの異常終了を処理します。特に`SIGSEGV`のような致命的なシグナルは、Goプログラムのパニックを引き起こす主な原因の一つです。

### `sigtable`

Goランタイム内部では、各オペレーティングシステム（特にUnix系）において、シグナル番号とその人間が読める名前（例: `SIGSEGV`）および説明文をマッピングするテーブルが存在します。このテーブルは、シグナルハンドリングの際にシグナル情報を処理するために利用されます。このコミットでは、この`sigtable`を利用してシグナル名を取得する新しい関数が導入されています。

### `dopanic_m`関数

`src/runtime/panic.go`に存在する`dopanic_m`関数は、Goランタイム内でパニックが発生した際に呼び出される主要な関数の一つです。この関数は、パニックの原因がシグナルである場合に、そのシグナルに関する情報を出力する役割を担っています。以前は、ここでシグナル番号の16進数表記が出力されていました。

## 技術的詳細

このコミットの主要な変更点は、シグナル番号からシグナル名を取得する`signame`関数の導入と、`dopanic_m`関数でのその利用です。

1.  **`signame`関数の導入**:
    *   `src/runtime/os1_nacl.go`, `src/runtime/os1_plan9.go`, `src/runtime/signal_unix.go`の各ファイルに、`signame(sig uint32) string`という新しい関数が追加されました。
    *   これらの実装では、引数として渡されたシグナル番号`sig`が、内部で定義されている`sigtable`の範囲内にあるかを確認します。
    *   範囲内であれば、`sigtable[sig].name`から対応するシグナル名（例: "SIGSEGV"）を返します。
    *   範囲外の場合、または`sigtable`が存在しない場合は空文字列を返します。
    *   `src/runtime/signal_windows.go`にも`signame`関数が追加されましたが、WindowsにはUnix系のような`sigtable`が存在しないため、この関数は常に空文字列を返します。これにより、Windows環境では以前と同様にシグナル番号の16進数表記が出力されることになります。

2.  **`dopanic_m`関数の変更**:
    *   `src/runtime/panic.go`内の`dopanic_m`関数が修正されました。
    *   シグナルによってパニックが発生した場合（`gp.sig != 0`）、まず新しく導入された`signame(gp.sig)`を呼び出してシグナル名を取得します。
    *   `signame`が空文字列でない（つまり、シグナル名が判明した）場合、`"[signal SIGSEGV"`のようにシグナル名を出力します。
    *   `signame`が空文字列の場合（Windows環境や未知のシグナル番号の場合）、以前と同様に`"[signal 0xb"`のようにシグナル番号の16進数表記を出力するフォールバックロジックが実装されています。
    *   その後、`code`, `addr`, `pc`などの追加情報が引き続き出力されます。

この変更により、Goランタイムは、シグナルによって引き起こされたパニックメッセージにおいて、より人間が理解しやすい情報を提供するようになりました。

## コアとなるコードの解説

### `signame`関数の実装例 (`src/runtime/signal_unix.go`より)

```go
func signame(sig uint32) string {
	if sig >= uint32(len(sigtable)) {
		return ""
	}
	return sigtable[sig].name
}
```
この`signame`関数は、`uint32`型のシグナル番号`sig`を受け取ります。
まず、`sig`が`sigtable`のインデックスとして有効な範囲内にあるかを確認します。`sigtable`はシグナル番号とシグナル名のマッピングを保持する配列またはスライスであると推測されます。
もし`sig`が有効な範囲外であれば、空文字列を返します。これは、未知のシグナル番号や、`sigtable`が存在しない環境（例: Windows）でのフォールバックを意味します。
有効な範囲内であれば、`sigtable[sig].name`から対応するシグナル名（例: "SIGSEGV"）を文字列として返します。

### `dopanic_m`関数の変更 (`src/runtime/panic.go`より)

```go
func dopanic_m(gp *g, pc, sp uintptr) {
	if gp.sig != 0 {
		signame := signame(gp.sig) // 新しく追加されたsigname関数を呼び出す
		if signame != "" {         // シグナル名が取得できた場合
			print("[signal ", signame)
		} else {                    // シグナル名が取得できなかった場合（以前の挙動）
			print("[signal ", hex(gp.sig))
		}
		print(" code=", hex(gp.sigcode0), " addr=", hex(gp.sigcode1), " pc=", hex(gp.sigpc), "]\\n")
	}

	// ... (後続のパニック処理)
}
```
`dopanic_m`関数は、`gp.sig`（現在のgoroutineが受け取ったシグナル番号）が0でない場合、つまりシグナルによってパニックが引き起こされた場合にこのブロックに入ります。
変更前は、`print("[signal ", hex(gp.sig), ...)`のように、シグナル番号を直接16進数で出力していました。
変更後は、まず`signame(gp.sig)`を呼び出してシグナル名を取得しようとします。
取得した`signame`が空文字列でなければ、そのシグナル名（例: "SIGSEGV"）を`print`関数で出力します。
もし`signame`が空文字列であれば、以前の挙動に戻り、`hex(gp.sig)`を使ってシグナル番号の16進数表記を出力します。
これにより、シグナル名が利用可能な場合はより分かりやすいメッセージが表示され、そうでない場合でも情報が失われることはありません。
