# [インデックス 15671] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/ld`) におけるDarwin (macOS) 環境でのホストリンキング（host linking）のサポートを追加するものです。具体的には、Mach-O形式の実行可能ファイルやオブジェクトファイル生成時のリロケーション処理と、Cgoにおける`cgo_export_static`シンボルの扱いが改善されています。

## 元コミット内容

`cmd/ld: darwin support for host linking`

このコミットは、GoリンカがDarwin（macOS）上でホストリンキングをサポートするための変更です。

## 変更の背景

Go言語は、クロスコンパイルに非常に優れていますが、Cgo（GoとC/C++コードを連携させる機能）を使用する場合、ターゲットOSのCコンパイラとリンカが必要になります。特にmacOS (Darwin) 環境では、実行可能ファイルのフォーマットとしてMach-Oが採用されており、リロケーション（再配置）の仕組みが他のOS（LinuxのELFなど）とは異なります。

以前のGoリンカは、Darwin環境でのホストリンキング、特に外部のC/C++ライブラリとの連携において、リロケーション処理が不完全であったり、`cgo_export_static`のようなCgo特有のシンボルが正しく扱われない問題がありました。これにより、Cgoを用いたGoプログラムをmacOS上でビルドする際に、リンカエラーや実行時エラーが発生する可能性がありました。

このコミットは、これらの問題を解決し、GoプログラムがmacOS上でCgoを介して外部ライブラリとよりシームレスに連携できるようにすることを目的としています。特に、`go test -ldflags '-w -hostobj'`のようなコマンドで、ホストリンキングを伴うテストが正しく実行できるようになることが期待されます。

## 前提知識の解説

*   **リンカ (Linker)**: コンパイラによって生成されたオブジェクトファイル（機械語コードとデータを含むファイル）を結合し、実行可能なプログラムやライブラリを生成するツールです。リンカは、異なるオブジェクトファイル間の参照（関数呼び出しや変数アクセスなど）を解決し、最終的なアドレスを決定します。
*   **リロケーション (Relocation)**: オブジェクトファイル内のコードやデータが、最終的な実行可能ファイル内でどのメモリアドレスに配置されるかによって、その参照先のアドレスを調整するプロセスです。リンカの重要な機能の一つで、特に共有ライブラリを使用する場合や、プログラムがロードされるアドレスが実行時に決定される場合に必要となります。
*   **Mach-O (Mach Object)**: AppleのmacOS、iOS、watchOS、tvOSで使用される実行可能ファイル、オブジェクトコード、共有ライブラリ、ダイナミックロード可能コード、コアダンプのファイルフォーマットです。ELF (Executable and Linkable Format) やPE (Portable Executable) とは異なる構造を持っています。
*   **Cgo**: Go言語の機能の一つで、GoプログラムからC言語の関数を呼び出したり、C言語のコードをGoプログラムに組み込んだりすることを可能にします。Cgoを使用すると、既存のC/C++ライブラリをGoから利用できるようになります。
*   **ホストリンキング (Host Linking)**: Goのビルドプロセスにおいて、Goリンカが直接システムリンカ（この場合はmacOSの`ld`）を呼び出して、最終的な実行可能ファイルを生成する方式です。Cgoを使用する場合や、特定のシステムライブラリにリンクする必要がある場合に用いられます。Goリンカが独自に全てを処理する「内部リンキング」とは対照的です。
*   **`cgo_export_static`**: Cgoにおいて、Goの関数をC言語から呼び出せるようにエクスポートする際に使用されるシンボルです。静的リンクされるCgoプログラムで特に重要になります。
*   **`SHOSTOBJ` シンボルタイプ**: Goリンカ内部で、ホストリンカによって解決されるべき外部オブジェクトファイルからのシンボルを示すために使用されるタイプです。

## 技術的詳細

このコミットの主要な変更点は、GoリンカがMach-O形式のリロケーションをより正確に処理できるようにすることです。

1.  **`machoreloc1` 関数の導入と修正**:
    *   `src/cmd/6l/asm.c` (amd64アーキテクチャ用) と `src/cmd/8l/asm.c` (386アーキテクチャ用) に、`machoreloc1` 関数が追加または修正されています。この関数は、Mach-O形式のリロケーションエントリを生成する役割を担います。
    *   特に、`SHOSTOBJ` タイプのシンボル（ホストリンカが解決する外部シンボル）に対するリロケーション処理が強化されています。これらのシンボルは、Mach-Oのリロケーションエントリで「外部リロケーション」としてマークされ、`dynid`（ダイナミックシンボルテーブルのインデックス）が使用されます。
    *   リロケーションタイプ（`D_ADDR`、`D_PCREL`）とサイズ（1, 2, 4, 8バイト）に基づいて、適切なMach-Oリロケーションフラグ（`MACHO_X86_64_RELOC_UNSIGNED`, `MACHO_X86_64_RELOC_BRANCH`, `MACHO_GENERIC_RELOC_VANILLA`など）が設定されます。
2.  **`machoemitreloc` 関数の追加**:
    *   `src/cmd/ld/macho.c` に `machoemitreloc` 関数が追加され、`src/cmd/ld/macho.h` で宣言されています。この関数は、各セクション（テキスト、データなど）に対してリロケーションエントリを生成し、出力ファイルに書き込む役割を担います。
    *   `machorelocsect` 関数が導入され、個々のセクション内のシンボルに対するリロケーションを処理します。
3.  **リンカオプションの調整**:
    *   `src/cmd/6l/obj.c` と `src/cmd/8l/obj.c` の `main` 関数内で、`-hostobj` オプションがDarwin (`Hdarwin`) 環境でも使用できるようになっています。これにより、Goリンカが外部オブジェクトファイルを取り込む際に、Darwin固有の処理が適用されるようになります。
    *   `src/cmd/ld/lib.c` の `hostlink` 関数において、Darwin環境でのホストリンキング時に`-Wl,-no_pie,-pagezero_size,4000000`というリンカフラグが追加されています。
        *   `-no_pie`: Position Independent Executable (PIE) を無効にします。Goの実行ファイルは通常PIEではないため、互換性のために指定されることがあります。
        *   `-pagezero_size,4000000`: ゼロページ（アドレス0からの領域）のサイズを4MBに設定します。これは、NULLポインタ参照の検出などに利用されることがあります。
4.  **Mach-Oファイル構造の調整**:
    *   `src/cmd/ld/macho.c` の `machowrite` 関数で、出力ファイルがオブジェクトファイル (`isobj`) の場合はファイルタイプを `1` (Mach object) に、それ以外の場合は `2` (Mach executable) に設定するよう変更されています。
    *   `domacho` 関数内で、オブジェクトファイル (`isobj`) の場合は `.plt`, `.got`, `.linkedit.plt`, `.linkedit.got` といった動的リンク関連のシンボルやセグメントの初期化をスキップするようになっています。これは、オブジェクトファイルは実行可能ファイルとは異なり、これらの動的リンク情報を必要としないためです。
    *   `asmbmacho` 関数内で、オブジェクトファイルの場合と実行可能ファイルの場合で、Mach-Oセグメント（`__PAGEZERO`, `__TEXT`, `__DATA`, `__LINKEDIT`）の生成ロジックが条件分岐されています。特に、オブジェクトファイルの場合は単一のセグメントでファイル全体をカバーするようなシンプルな構造になります。
5.  **Cgoエクスポートシンボルの扱い**:
    *   `src/cmd/ld/go.c` において、`cgo_export_static` シンボルがDarwin環境で問題を引き起こしていたため、一時的にWindows環境でのみ無効化するよう変更されています。これは、Darwinでのホストリンキングサポートが改善されたことで、Darwinでの`cgo_export_static`の扱いが正常になったことを示唆しています。
    *   `src/cmd/ld/macho.c` の `machogenasmsym` および `machosymtab` 関数で、`SHOSTOBJ` タイプのシンボルも `SDYNIMPORT` と同様に外部シンボルとしてMach-Oシンボルテーブルに登録されるようになっています。これにより、ホストリンカがこれらのシンボルを正しく解決できるようになります。
6.  **リロケーション計算の修正**:
    *   `src/cmd/ld/data.c` の `relocsym` 関数で、`D_PCREL` (PC相対) リロケーションの計算ロジックがDarwin (`Hdarwin`) 環境向けに調整されています。特に、`SHOSTOBJ` ではないシンボルに対するリロケーションオフセットの計算が修正されています。

これらの変更により、GoリンカはDarwin環境で生成されるMach-Oファイルのリロケーション情報をより正確に生成し、外部のC/C++ライブラリとの連携（特にCgoを介したホストリンキング）がスムーズに行えるようになります。

## コアとなるコードの解説

### `src/cmd/6l/asm.c` および `src/cmd/8l/asm.c` の `machoreloc1` 関数

```c
int
machoreloc1(Reloc *r, vlong sectoff)
{
	uint32 v;
	Sym *rs;

	rs = r->xsym;

	if(rs->type == SHOSTOBJ) { // ホストリンカが解決する外部シンボル
		if(rs->dynid < 0) {
			diag("reloc %d to non-macho symbol %s type=%d", r->type, rs->name, rs->type);
			return -1;
		}
		v = rs->dynid;
		v |= 1<<27; // external relocation (外部リロケーションを示すフラグ)
	} else { // 内部シンボル
		v = rs->sect->extnum; // セクション番号
		if(v == 0) {
			diag("reloc %d to symbol %s in non-macho section %s type=%d", r->type, rs->name, rs->sect->name, rs->type);
			return -1;
		}
	}

	switch(r->type) { // リロケーションタイプに応じたフラグ設定
	default:
		return -1;
	case D_ADDR:
		v |= MACHO_X86_64_RELOC_UNSIGNED<<28; // または MACHO_GENERIC_RELOC_VANILLA
		break;
	case D_PCREL:
		v |= 1<<24; // pc-relative bit (PC相対リロケーションを示すフラグ)
		v |= MACHO_X86_64_RELOC_BRANCH<<28; // または MACHO_GENERIC_RELOC_VANILLA
		break;
	}

	switch(r->siz) { // リロケーションサイズに応じたフラグ設定
	default:
		return -1;
	case 1:
		v |= 0<<25;
		break;
	case 2:
		v |= 1<<25;
		break;
	case 4:
		v |= 2<<25;
		break;
	case 8:
		v |= 3<<25;
		break;
	}

	LPUT(sectoff); // リロケーション対象のオフセット
	LPUT(v);       // リロケーション情報（シンボルID、フラグなど）
	return 0;
}
```
この関数は、GoリンカがMach-O形式のリロケーションエントリを生成する際の中心的なロジックです。`Reloc`構造体からリロケーション対象のシンボル (`r->xsym`)、リロケーションタイプ (`r->type`)、サイズ (`r->siz`) を取得し、それらをMach-Oのリロケーションエントリのフォーマットに変換します。特に、`SHOSTOBJ`（ホストリンカが解決する外部シンボル）の場合には、`dynid`（ダイナミックシンボルテーブルのインデックス）と「外部リロケーション」フラグ (`1<<27`) を設定することで、システムリンカが正しく外部シンボルを解決できるようにしています。

### `src/cmd/ld/macho.c` の `machoemitreloc` および `machorelocsect` 関数

```c
void
machorelocsect(Section *sect, Sym *first)
{
	Sym *sym;
	int32 eaddr;
	Reloc *r;

	// If main section has no bits, nothing to relocate.
	if(sect->vaddr >= sect->seg->vaddr + sect->seg->filelen)
		return;
	
	sect->reloff = cpos(); // リロケーション情報の開始オフセットを記録
	for(sym = first; sym != nil; sym = sym->next) {
		if(!sym->reachable)
			continue;
		if(sym->value >= sect->vaddr) // 現在のセクション内のシンボルを探す
			break;
	}
	
	eaddr = sect->vaddr + sect->len; // セクションの終了アドレス
	for(; sym != nil; sym = sym->next) {
		if(!sym->reachable)
			continue;
		if(sym->value >= eaddr) // セクションの範囲を超えたら終了
			break;
		cursym = sym;
		
		for(r = sym->r; r < sym->r+sym->nr; r++) { // シンボル内の全てのリロケーションを処理
			if(r->done)
				continue;
			if(machoreloc1(r, sym->value+r->off - sect->vaddr) < 0) // machoreloc1を呼び出してリロケーションエントリを生成
				diag("unsupported obj reloc %d/%d to %s", r->type, r->siz, r->sym->name);
		}
	}
		
	sect->rellen = cpos() - sect->reloff; // リロケーション情報の長さを記録
}

void
machoemitreloc(void)
{
	Section *sect;

	while(cpos()&7) // 8バイトアラインメント
		cput(0);

	machorelocsect(segtext.sect, textp); // テキストセクションのリロケーションを処理
	for(sect=segtext.sect->next; sect!=nil; sect=sect->next)
		machorelocsect(sect, datap);	
	for(sect=segdata.sect; sect!=nil; sect=sect->next)
		machorelocsect(sect, datap);	// データセクションのリロケーションを処理
}
```
`machoemitreloc` は、Mach-Oファイルのリロケーションセクションを生成するエントリポイントです。この関数は、テキストセクションとデータセクション内のすべてのシンボルを走査し、それぞれのシンボルに付随するリロケーション情報を `machorelocsect` 関数を使って処理します。`machorelocsect` は、指定されたセクション内のシンボルを繰り返し処理し、各リロケーションに対して前述の `machoreloc1` を呼び出すことで、最終的なMach-Oリロケーションエントリをファイルに書き込みます。これにより、Goリンカが生成するMach-Oファイルが、システムリンカによって正しく再配置されるようになります。
