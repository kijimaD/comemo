## 変更の背景

Goの`context`パッケージは、API境界を越えてデッドライン、キャンセルシグナル、その他のリクエストスコープの値を伝播するためのメカニズムを提供します。`context.WithValue`関数は、コンテキストにキーと値のペアを格納するために使用されます。

このコミット以前は、`WithValue`に渡されるキーが比較可能であるという要件は、ドキュメントに明記されていませんでした。また、比較不可能な型（例: スライス、マップ、関数）がキーとして使用された場合、その場でエラーが発生するのではなく、後になってから予期せぬ、かつ理解しにくいランタイムエラー（例えば、内部のマップ操作でパニックが発生するなど）を引き起こす可能性がありました。

この変更の主な目的は以下の2点です。

1.  **ドキュメントの明確化**: `WithValue`のキーが比較可能でなければならないという重要な制約を明示的にドキュメントに追加することで、開発者が誤ったキーの型を使用するのを防ぎます。
2.  **早期エラー検出**: 比較不可能なキーが使用された場合に、`WithValue`の呼び出し時に即座にパニックを発生させるようにすることで、問題を早期に発見し、デバッグの労力を削減します。これにより、「後で不可解な失敗」が発生するのを防ぎます。

## 前提知識の解説

### Goの`context`パッケージ

`context`パッケージは、Goプログラムでリクエストスコープのデータを伝達し、デッドラインやキャンセルシグナルを伝播するための標準的な方法を提供します。特に、複数のGoroutineやAPI呼び出しにまたがる処理において、タイムアウトやキャンセルを協調的に処理するために不可欠です。

*   **`Context`インターフェース**: `Done()`, `Err()`, `Value(key interface{}) interface{}`, `Deadline()` の4つのメソッドを持つインターフェースです。
*   **`context.Background()`**: 最上位のコンテキストで、キャンセルも値もデッドラインも持ちません。通常、メイン関数、init関数、テストの初期化などで使用されます。
*   **`context.TODO()`**: `Background`と同様ですが、将来的にコンテキストを追加する予定があるが、現時点では不明な場合に使用されます。
*   **`context.WithCancel(parent Context)`**: 親コンテキストから派生し、キャンセル可能な新しいコンテキストを返します。
*   **`context.WithDeadline(parent Context, d time.Time)`**: 親コンテキストから派生し、指定された時刻にキャンセルされるコンテキストを返します。
*   **`context.WithTimeout(parent Context, timeout time.Duration)`**: `WithDeadline`の糖衣構文で、指定された期間後にキャンセルされるコンテキストを返します。
*   **`context.WithValue(parent Context, key, val interface{}) Context`**: 親コンテキストから派生し、キーと値のペアを格納する新しいコンテキストを返します。このキーと値は、`Value(key interface{})`メソッドで取得できます。

### Goにおける比較可能（Comparable）な型

Go言語では、特定の型の値は比較演算子`==`や`!=`を使って比較できます。これを「比較可能」な型と呼びます。

*   **比較可能な型**:
    *   ブール値
    *   数値型（整数、浮動小数点数、複素数）
    *   文字列
    *   ポインタ
    *   チャネル
    *   インターフェース（動的な型と値が両方とも比較可能である場合）
    *   構造体（すべてのフィールドが比較可能である場合）
    *   配列（要素の型が比較可能である場合）
*   **比較不可能な型**:
    *   スライス
    *   マップ
    *   関数

`context.WithValue`の内部実装では、キーを`map`のキーとして使用しています。Goの`map`のキーは比較可能でなければならないという制約があるため、`WithValue`のキーも必然的に比較可能である必要があります。比較不可能な型を`map`のキーとして使用しようとすると、コンパイルエラーになります。しかし、`WithValue`のキーは`interface{}`型として受け取られるため、コンパイル時には型チェックが行われず、ランタイムで問題が発生する可能性がありました。

### `reflect`パッケージ

`reflect`パッケージは、Goプログラムが実行時に自身の構造を検査（リフレクション）することを可能にします。これにより、変数の型、値、メソッドなどを動的に調べたり、操作したりできます。

*   **`reflect.TypeOf(i interface{}) Type`**: `interface{}`型の値`i`の動的な型を表す`reflect.Type`を返します。
*   **`reflect.Type.Comparable() bool`**: `reflect.Type`が比較可能であるかどうかを示すブール値を返します。

### `panic`と`recover`

Goでは、プログラムの異常終了を示すために`panic`を使用します。`panic`が発生すると、現在のGoroutineの実行が停止し、遅延関数（`defer`）が実行されながらスタックがアンワインドされます。`recover`関数は、`defer`関数内で呼び出された場合にのみ`panic`から回復し、パニックに陥った値を返すことができます。このコミットでは、不正なキーの使用を早期に`panic`させることで、プログラムの誤用を明確に示しています。

## 技術的詳細

このコミットの技術的詳細の中心は、`context.WithValue`関数に`reflect`パッケージを用いたランタイムチェックを追加した点です。

`WithValue`関数は、キーとして`interface{}`型を受け取ります。`interface{}`は任意の型を保持できるため、コンパイル時にはキーの比較可能性をチェックできません。しかし、`context`の内部実装では、このキーを`map`のキーとして利用しています。Goの仕様により、`map`のキーは比較可能でなければなりません。

このコミットでは、`WithValue`関数内で`reflect.TypeOf(key).Comparable()`を呼び出すことで、実行時にキーの動的な型が比較可能であるかをチェックします。

```go
if !reflect.TypeOf(key).Comparable() {
    panic("key is not comparable")
}
```

このチェックにより、もし比較不可能な型（例: `[]byte`、`map[string]string`、`func()`)がキーとして渡された場合、`WithValue`が呼び出されたその場で`panic`が発生します。これにより、以下のようなメリットがあります。

*   **即時性**: 問題がコードの実行フローの早い段階で顕在化するため、デバッグが容易になります。以前は、`context.Value`が後で呼び出された際に内部のマップ操作でパニックが発生するなど、原因の特定が難しいエラーにつながる可能性がありました。
*   **明確なエラーメッセージ**: `panic("key is not comparable")`というメッセージは、何が問題であるかを直接的に示します。これにより、開発者はすぐにキーの型が不適切であることを理解し、修正できます。
*   **堅牢性の向上**: `context`パッケージの契約を強制することで、不正な使用パターンからパッケージの内部状態を保護し、より堅牢なAPIを提供します。

また、`src/go/build/deps_test.go`の変更は、`context`パッケージが`reflect`パッケージに依存するようになったことをビルドシステムに伝えるためのものです。これは、Goのビルドシステムがパッケージ間の依存関係を追跡し、正しくコンパイルするために必要です。

## コアとなるコードの解説

### `src/context/context.go`の変更

1.  **`reflect`パッケージのインポート**: `reflect`パッケージが新しくインポートされました。これは、実行時にキーの型情報を取得し、その比較可能性をチェックするために必要です。
2.  **`WithValue`関数のドキュメント更新**: `WithValue`関数のコメントに「`The provided key must be comparable.`」という一文が追加されました。これにより、この関数の利用者がキーの型に関する制約を明確に理解できるようになります。
3.  **キーの比較可能性チェック**: `WithValue`関数の内部に以下のコードが追加されました。
    ```go
    if !reflect.TypeOf(key).Comparable() {
        panic("key is not comparable")
    }
    ```
    このコードは、`key`の動的な型を取得し（`reflect.TypeOf(key)`）、その型が比較可能であるか（`.Comparable()`）をチェックします。もし比較可能でなければ、`"key is not comparable"`というメッセージと共に`panic`を発生させ、プログラムの実行を停止させます。これにより、不正なキーの使用が即座に検出されます。

### `src/context/context_test.go`の変更

1.  **`TestWithValueChecksKey`テストケースの追加**:
    この新しいテストケースは、比較不可能な型（ここでは`[]byte`スライス）を`WithValue`のキーとして渡した場合に、期待通り`panic`が発生するかどうかを検証します。
    `WithValue(Background(), []byte("foo"), "bar")`という呼び出しは、`[]byte`が比較不可能な型であるため、`panic`を引き起こすはずです。
2.  **`recoveredValue`ヘルパー関数の追加**:
    `TestWithValueChecksKey`内で`panic`を捕捉するために使用されるヘルパー関数です。`defer`と`recover`を組み合わせて、引数として渡された関数が`panic`した場合にその値を捕捉し、テスト関数に返します。これにより、テスト内で`panic`の発生を検証できます。

### `src/go/build/deps_test.go`の変更

`context`パッケージの依存関係リストに`"reflect"`が追加されました。これは、`context`パッケージが`reflect`パッケージを使用するようになったため、Goのビルドシステムがこの新しい依存関係を認識し、正しくビルドできるようにするための設定変更です。
