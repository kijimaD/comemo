## 変更の背景

`net/http` パッケージの `http.Error` 関数は、HTTPレスポンスとして特定のエラーメッセージとステータスコードをクライアントに送信するための便利なヘルパー関数です。この関数は内部的に `Content-Type` ヘッダーを `text/plain; charset=utf-8` に設定し、提供されたエラー文字列をレスポンスボディとして書き込みます。

しかし、この関数の利用方法について、開発者間で誤解が生じる可能性がありました。特に、エラーメッセージとしてHTMLやJSONなどの構造化されたデータを渡してしまうケースが考えられます。`Content-Type` が `text/plain` に設定されているにもかかわらず、レスポンスボディがプレーンテキストではない場合、クライアント側で予期せぬ挙動を引き起こしたり、セキュリティ上の問題（例: クロスサイトスクリプティング (XSS) 脆弱性）につながる可能性がありました。

このコミットは、このような誤用を防ぎ、`http.Error` 関数が意図する「プレーンテキストのエラーメッセージ」という本来の目的を明確にするために、ドキュメントに明示的な注意書きを追加することを目的としています。これにより、開発者がより安全で予測可能なHTTPエラーレスポンスを生成できるようになります。

## 前提知識の解説

### Go言語の `net/http` パッケージ

`net/http` パッケージは、Go言語でHTTPクライアントおよびサーバーを実装するための標準ライブラリです。WebアプリケーションやAPIサーバーを構築する際に中心的な役割を果たします。

-   **`http.ResponseWriter`**: HTTPレスポンスを構築するために使用されるインターフェースです。ヘッダーの設定、ステータスコードの書き込み、レスポンスボディの書き込みなどを行います。
-   **`http.Request`**: 受信したHTTPリクエストに関する情報（URL、ヘッダー、ボディなど）をカプセル化した構造体です。
-   **`http.Handler` / `http.HandlerFunc`**: HTTPリクエストを処理するためのインターフェースおよび関数型です。`ServeHTTP(w http.ResponseWriter, r *http.Request)` メソッドを実装することで、特定のリクエストパスに対する処理を定義します。
-   **`http.Error` 関数**: `func Error(w ResponseWriter, error string, code int)` というシグネチャを持つヘルパー関数です。指定されたエラーメッセージ（`error`引数）とHTTPステータスコード（`code`引数）を使って、HTTPレスポンスをクライアントに送信します。この関数は、内部で `w.Header().Set("Content-Type", "text/plain; charset=utf-8")` を呼び出し、その後 `w.WriteHeader(code)` と `fmt.Fprintln(w, error)` を実行します。

### HTTP `Content-Type` ヘッダー

`Content-Type` ヘッダーは、HTTPレスポンスまたはリクエストのボディに含まれるデータのメディアタイプ（MIMEタイプ）を示すために使用されます。クライアント（ブラウザなど）は、このヘッダーを見て、受信したデータをどのように解釈し、表示すべきかを判断します。

-   **`text/plain`**: レスポンスボディがプレーンテキストであることを示します。ブラウザはこれをそのまま表示しようとします。
-   **`text/html`**: レスポンスボディがHTMLドキュメントであることを示します。ブラウザはこれをHTMLとしてレンダリングします。
-   **`application/json`**: レスポンスボディがJSON形式のデータであることを示します。
-   **`charset=utf-8`**: テキストデータの文字エンコーディングがUTF-8であることを示します。

### プレーンテキストと構造化データ

-   **プレーンテキスト**: フォーマット情報（フォント、色、レイアウトなど）を含まない、純粋なテキストデータです。改行やタブなどの基本的な制御文字は含まれますが、HTMLタグやJSONのキー・値の構造などは含まれません。
-   **構造化データ**: HTML、JSON、XMLなどのように、特定の構文規則に従って情報が整理されたデータです。これらのデータは、その構造を解釈するためのパーサーやレンダリングエンジンによって処理されることを前提としています。

`http.Error` が `Content-Type: text/plain` を設定するにもかかわらず、エラーメッセージとしてHTMLタグを含む文字列を渡した場合、ブラウザはそれをプレーンテキストとして表示しようとします。このとき、HTMLタグがそのまま画面に表示されてしまい、意図しない表示になったり、悪意のあるスクリプトが埋め込まれていた場合にXSS脆弱性につながる可能性があります。

## 技術的詳細

`http.Error` 関数は、Goの `net/http` パッケージにおいて、HTTPエラーレスポンスを生成するための標準的な方法を提供します。この関数の実装は非常にシンプルで、以下のステップを実行します。

1.  `w.Header().Set("Content-Type", "text/plain; charset=utf-8")` を呼び出し、レスポンスの `Content-Type` ヘッダーをプレーンテキストに設定します。
2.  `w.WriteHeader(code)` を呼び出し、指定されたHTTPステータスコード（例: 400 Bad Request, 404 Not Found, 500 Internal Server Errorなど）をレスポンスに書き込みます。
3.  `fmt.Fprintln(w, error)` を呼び出し、提供されたエラー文字列をレスポンスボディとして書き込みます。

このコミットが追加したドキュメントは、特にステップ3で書き込まれる `error` 引数の内容に焦点を当てています。`Content-Type` が `text/plain` である以上、レスポンスボディはプレーンテキストとして解釈されるべきです。もし `error` 引数にHTMLタグやJavaScriptコードなどの構造化されたコンテンツが含まれていた場合、クライアントはそれをプレーンテキストとして表示するため、タグがエスケープされずにそのまま表示されたり、ブラウザによってはXSSフィルターを回避してスクリプトが実行されてしまうリスクが生じます。

例えば、以下のようなコードがあったとします。

```go
http.Error(w, "<h1>エラーが発生しました</h1><script>alert('XSS');</script>", http.StatusInternalServerError)
```

この場合、`http.Error` は `Content-Type: text/plain` を設定するため、ブラウザは `<h1>エラーが発生しました</h1><script>alert('XSS');</script>` という文字列をそのまま表示しようとします。しかし、一部のブラウザや特定の状況下では、このHTMLが解釈されてしまい、`alert('XSS')` が実行される可能性があります。

このドキュメントの追加は、このような潜在的なセキュリティリスクや表示の不整合を防ぐための、ベストプラクティスを開発者に促すものです。`http.Error` を使用する際は、常にユーザーに表示するエラーメッセージが純粋なプレーンテキストであることを確認する必要があります。もしHTMLやJSONなどの構造化されたエラーレスポンスを返したい場合は、`http.Error` ではなく、`w.Header().Set("Content-Type", "text/html")` や `w.Header().Set("Content-Type", "application/json")` を適切に設定し、`w.Write()` や `json.NewEncoder(w).Encode()` などを用いて明示的にレスポンスボディを書き込む必要があります。

## コアとなるコードの解説

このコミットによって追加された行は、`http.Error` 関数のGoDocコメントの一部です。

```go
// Error replies to the request with the specified error message and HTTP code.
// The error message should be plain text.
func Error(w ResponseWriter, error string, code int) {
	w.Header().Set("Content-Type", "text/plain; charset=utf-8")
	w.WriteHeader(code)
	fmt.Fprintln(w, error)
}
```

追加されたコメント `// The error message should be plain text.` は、`http.Error` 関数の `error` 引数に渡される文字列の期待される形式を明確に指定しています。これは、この関数が内部的に `Content-Type: text/plain` ヘッダーを設定するため、レスポンスボディがプレーンテキストとして扱われるべきであることを開発者に強く示唆しています。

この変更はコードの動作自体には影響を与えませんが、関数の利用方法に関する重要なガイドラインを提供し、潜在的な誤用やセキュリティ上の問題を未然に防ぐためのドキュメンテーションの改善です。Go言語の標準ライブラリでは、このような詳細なドキュメンテーションを通じて、開発者が安全かつ意図通りにAPIを使用できるよう配慮されています。
