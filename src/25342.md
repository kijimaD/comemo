# [インデックス 25342] ファイルの概要

このコミットは、Go言語のランタイムにMemory Sanitizer (MSan) のサポートを追加するものです。具体的には、GoコードがC/C++のMemory Sanitizerと連携できるようにするためのランタイムサポート関数を導入しています。これにより、GoプログラムがC/C++コードと相互運用する際に、未初期化メモリの使用といったメモリ関連のバグを検出できるようになります。

## 変更の背景

Go言語は、Cgoを通じてC/C++コードと連携する機能を提供しています。C/C++の世界では、未初期化メモリの使用、境界外アクセス、ダブルフリーなどのメモリ関連のバグを検出するために、AddressSanitizer (ASan) やMemory Sanitizer (MSan) といった動的解析ツールが広く利用されています。

GoプログラムがC/C++ライブラリを呼び出す場合、Go側で確保したメモリをC/C++コードに渡し、C/C++側でそのメモリを操作することがあります。この際、C/C++コードが未初期化のGoメモリを読み取ったり、GoコードがC/C++コードによって部分的に初期化されたメモリを読み取ったりする状況が発生し得ます。このようなクロス言語のメモリ操作において、MSanがGoとC/C++の両方のメモリ状態を正しく追跡し、未初期化メモリの使用を検出できるようにすることが重要になります。

このコミットは、Goコンパイラが`-msan`オプション付きでビルドされた際に、メモリの読み書き操作に対してMSanのチェックを挿入するためのランタイムサポートを導入することで、この課題に対処しています。これにより、GoとC/C++が混在するアプリケーションにおいて、より堅牢なメモリ安全性の検証が可能になります。

## 前提知識の解説

### Memory Sanitizer (MSan)

Memory Sanitizer (MSan) は、LLVMプロジェクトの一部として開発された動的メモリエラー検出ツールです。主にC/C++プログラムにおける未初期化メモリの使用 (use-of-uninitialized-memory) を検出することを目的としています。

MSanは、プログラムのメモリ領域ごとに「シャドウメモリ」と呼ばれる追加のメモリ領域を割り当て、各バイトが初期化されているかどうかを追跡します。メモリが書き込まれると、対応するシャドウメモリのバイトは「初期化済み」としてマークされます。メモリが読み取られる際に、対応するシャドウメモリのバイトが「未初期化」とマークされていれば、MSanはエラーを報告します。

MSanはコンパイル時にコードを計測 (instrument) することで機能します。つまり、コンパイラがメモリ操作を行う命令の前後に追加のチェックコードを挿入します。

### GoのランタイムとCgo

*   **Goランタイム**: Goプログラムは、ガベージコレクタ、スケジューラ、メモリ管理などを含む独自のランタイムシステム上で動作します。GoのメモリモデルはC/C++とは異なり、ガベージコレクションによってメモリリークや解放後使用 (use-after-free) の問題が軽減されますが、Cgoを介してC/C++コードと連携する際には、両者のメモリ管理の境界で問題が発生する可能性があります。
*   **Cgo**: GoプログラムからC/C++コードを呼び出すためのメカニズムです。Cgoを使用すると、Goコード内でCの関数を直接呼び出したり、Cのデータ構造を使用したりできます。Cgoは、GoとCの間の呼び出し規約やデータ表現の違いを橋渡しする役割を担います。

### Goのビルドタグ (`+build msan`)

Goのソースファイルには、`+build`ディレクティブを使用してビルドタグを指定できます。これは、特定の環境やビルドオプションが有効な場合にのみ、そのファイルをコンパイルに含めるためのメカニズムです。
このコミットでは、`+build msan`タグが導入されており、Goコンパイラが`-msan`オプション付きで実行された場合にのみ、MSan関連のコードがビルドされるようになります。これにより、MSanを使用しない通常のビルドではオーバーヘッドが発生しないようになっています。

### Goの`unsafe.Pointer`と`uintptr`

*   **`unsafe.Pointer`**: Goの型システムを迂回して、任意の型のポインタを保持できる特殊なポインタ型です。C言語の`void*`に似ており、Goのメモリモデルの安全性を損なう可能性があるため、「unsafe」とされています。Cgoとの連携や低レベルのメモリ操作で必要になります。
*   **`uintptr`**: 整数型であり、ポインタの値を保持できます。`unsafe.Pointer`と相互変換が可能ですが、`uintptr`自体はポインタではないため、ガベージコレクタの対象外です。メモリサイズやオフセットの計算によく使用されます。

### Goの`go:noescape`と`go:cgo_import_static`

*   **`go:noescape`**: コンパイラヒントの一つで、関数が引数として受け取ったポインタが、その関数のスコープ外に「エスケープ」しないことを示します。これにより、コンパイラはスタック上にオブジェクトを割り当てることができ、ヒープ割り当てを避けることでパフォーマンスを向上させることができます。MSanのチェック関数は通常、メモリの状態をチェックするだけで、ポインタを保持し続けることはないため、このヒントが適切です。
*   **`go:cgo_import_static`**: Cgoのディレクティブで、Cgoを介してCの静的関数をGoのシンボルとしてインポートするために使用されます。これにより、Goのアセンブリコードから直接Cの関数を呼び出すことが可能になります。

### Goのg0スタック

Goランタイムは、各ゴルーチンに独自のスタックを割り当てます。しかし、システムコールやCgo呼び出しなど、Goランタイムの外部とやり取りする際には、特別な「g0スタック」または「mスタック」と呼ばれるスタックを使用することがあります。これは、Goのスタックが比較的小さく、動的に拡張されるのに対し、Cコードはより大きな固定サイズのスタックを期待する場合があるためです。Cgo呼び出しを行う際には、Goのスケジューラが現在のゴルーチンのスタックからg0スタックに切り替えることで、Cコードが安全に実行できる環境を提供します。

## 技術的詳細

このコミットは、Goプログラムが`-msan`ビルドタグ付きでコンパイルされた際に、Goのメモリ操作をMemory Sanitizerに報告するための複数の層にわたるメカニズムを導入しています。

1.  **コンパイラによる計測**:
    Goコンパイラは、`-msan`オプションが指定されている場合、Goコード内のメモリ読み書き操作に対して`runtime.msanread`および`runtime.msanwrite`関数への呼び出しを自動的に挿入します。これにより、Goのメモリ操作がMSanの監視下に置かれます。

2.  **Goランタイムのインターフェース (`src/runtime/msan.go`)**:
    このファイルは、GoランタイムがMSanと連携するためのGo側のインターフェースを定義しています。
    *   `MSanRead(addr unsafe.Pointer, len int)`と`MSanWrite(addr unsafe.Pointer, len int)`は、Goコードから直接呼び出される可能性のある公開APIです。これらは内部の`msanread`と`msanwrite`を呼び出します。
    *   `msanread`, `msanwrite`, `msanmalloc`, `msanfree`は、`go:noescape`ディレクティブを持つ内部関数です。これらはGoのアセンブリコードから呼び出されることを意図しており、Cgoを介してCのMSan関数に橋渡しされます。
    *   `go:cgo_import_static`ディレクティブにより、Cgoで定義された`__msan_read_go`、`__msan_write_go`、`__msan_malloc_go`、`__msan_free_go`というC関数がGoのシンボルとしてインポートされます。

3.  **CgoによるMSan APIのラッパー (`src/runtime/msan/msan.go`)**:
    このファイルは、Cgoを使用してC/C++のMSanライブラリ関数をGoから呼び出せるようにラップしています。
    *   `#cgo CFLAGS: -fsanitize=memory`と`#cgo LDFLAGS: -fsanitize=memory`は、CgoコンパイラとリンカにMSanを有効にするためのフラグを渡します。
    *   `#include <sanitizer/msan_interface.h>`により、MSanのAPIが利用可能になります。
    *   `__msan_read_go`は`__msan_check_mem_is_initialized`を呼び出し、指定されたメモリ範囲が初期化されているかを確認します。
    *   `__msan_write_go`と`__msan_malloc_go`は`__msan_unpoison`を呼び出し、指定されたメモリ範囲を「初期化済み」としてマークします。
    *   `__msan_free_go`は`__msan_poison`を呼び出し、解放されたメモリ範囲を「未初期化」としてマークします。これは、解放後使用 (use-after-free) の検出に役立ちます。

4.  **アセンブリによるC関数呼び出しの仲介 (`src/runtime/msan_amd64.s`)**:
    このアセンブリファイルは、`amd64`アーキテクチャ向けに、Goランタイムの`msanread`などの関数からCgoでインポートされたC関数を呼び出すための橋渡しをします。
    *   Goの関数呼び出し規約からCの関数呼び出し規約への引数のマッピングを行います（例: `MOVQ addr+0(FP), RARG0`）。
    *   `msancall<>`という共通のルーチンを介してC関数を呼び出します。このルーチンは、Goの現在のゴルーチンのスタックから`g0`スタック（または`m`スタック）に切り替える重要な役割を担います。これにより、CコードがGoのスタック管理に影響を与えることなく、安全に実行できるようになります。C関数が完了すると、元のGoスタックに戻ります。

5.  **MSan無効時のダミー実装 (`src/runtime/msan0.go`)**:
    `-msan`ビルドタグが有効でない場合（通常のビルド）、このファイルがコンパイルされます。
    *   `msanenabled`定数を`false`に設定します。
    *   `msanread`、`msanwrite`、`msanmalloc`、`msanfree`のダミー実装を提供します。これらの関数が誤って呼び出された場合、`throw("race")`または`throw("msan")`を呼び出してパニックを発生させます。これは、MSanが有効でないビルドでこれらの関数が呼び出されるべきではないことを保証するためです。

6.  **ビルドシステムへの統合 (`src/go/build/deps_test.go`)**:
    `pkgDeps`マップに`"runtime/msan": {"C"}`というエントリが追加され、`runtime/msan`パッケージがCgoに依存することが明示されます。これにより、ビルドシステムが`runtime/msan`を正しく処理できるようになります。

これらのメカニズムが連携することで、GoプログラムがC/C++のMSanとシームレスに連携し、クロス言語のメモリバグを効果的に検出できるようになります。

## コアとなるコードの解説

### `src/runtime/msan.go`

このファイルは、GoランタイムとMSanの間の主要なインターフェースを定義します。
*   `MSanRead`と`MSanWrite`は、Goコードがメモリの読み書きを行う際に、MSanにその操作を通知するための高レベルなラッパーです。
*   `msanread`, `msanwrite`, `msanmalloc`, `msanfree`は、`go:noescape`ディレクティブを持つ低レベルな関数シグネチャです。これらはコンパイラによって挿入されるか、他のランタイム関数から呼び出され、Goのアセンブリコードを介してCのMSan関数にディスパッチされます。`go:noescape`は、これらの関数が引数ポインタをヒープにエスケープさせないことをコンパイラに保証し、最適化を助けます。
*   `go:cgo_import_static`は、Cgoで定義されたC関数（`__msan_read_go`など）をGoのリンカが解決できるようにするための重要なディレクティブです。これにより、GoのアセンブリコードからこれらのC関数を直接参照し、呼び出すことが可能になります。

### `src/runtime/msan/msan.go`

このCgoファイルは、実際のMemory Sanitizerライブラリ (`sanitizer/msan_interface.h`) のAPIをGoから呼び出せるようにするためのC言語のラッパー関数を提供します。
*   `#cgo CFLAGS: -fsanitize=memory`と`#cgo LDFLAGS: -fsanitize=memory`は、このCコードをコンパイル・リンクする際にMSanを有効にするためのフラグです。これにより、Cgoが生成するCコード自体もMSanによって計測されます。
*   `__msan_read_go`は、Go側からのメモリ読み取り通知を受け取り、`__msan_check_mem_is_initialized`を呼び出して、そのメモリ領域が初期化されているかをMSanにチェックさせます。未初期化であればエラーが報告されます。
*   `__msan_write_go`と`__msan_malloc_go`は、Go側からのメモリ書き込みまたは割り当て通知を受け取り、`__msan_unpoison`を呼び出して、そのメモリ領域が「初期化済み」であることをMSanに伝えます。
*   `__msan_free_go`は、Go側からのメモリ解放通知を受け取り、`__msan_poison`を呼び出して、そのメモリ領域を「未初期化」としてマークします。これにより、解放されたメモリをGoコードが誤って使用した場合（use-after-free）にMSanが検出できるようになります。

### `src/runtime/msan_amd64.s`

このアセンブリファイルは、`amd64`アーキテクチャにおけるGoとCの間の呼び出し規約の橋渡しと、スタックの切り替えを行います。
*   `runtime·msanread`などのGo関数は、引数（`addr`と`size`）をGoのスタックフレームからCの呼び出し規約に従ってレジスタ（`RARG0`, `RARG1`など）に移動させます。
*   `MOVQ $__msan_read_go(SB), AX`は、CgoでインポートされたC関数`__msan_read_go`のアドレスを`AX`レジスタにロードします。
*   `JMP msancall<>(SB)`は、`msancall`ルーチンにジャンプします。このルーチンは、Goの現在のゴルーチンのスタック（`SP`）を一時的に保存し、`g0`スタック（GoランタイムがCgo呼び出しのために使用する特別なスタック）に切り替えます。
*   `CALL AX`命令で、`AX`レジスタに格納されたC関数（`__msan_read_go`など）が呼び出されます。これにより、CのMSanライブラリ関数が実行されます。
*   C関数が戻ると、`msancall`ルーチンは保存しておいたGoのスタックポインタを復元し、Goの実行フローに戻ります。
このスタック切り替えは、Goの動的に拡張されるスタックとCの固定スタックの間の互換性を確保し、Cgo呼び出しの安全性を高めるために不可欠です。
