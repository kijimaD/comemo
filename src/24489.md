# [インデックス 24489] ファイルの概要

このコミットは、Go言語の公式仕様書である `doc/go_spec.html` ファイルに対する更新です。具体的には、Goの式スイッチ（expression switch）文に関する既存の制限や振る舞いを明確にし、これまで仕様書に明記されていなかった点を追記することで、言語の定義をより厳密にすることを目的としています。

## コミット

このコミットは、Go言語の式スイッチ文に関するいくつかの未定義または不明瞭な側面をGo言語仕様書に明文化することを目的としています。これにより、コンパイラの挙動とユーザーの期待との間の不一致を解消し、言語の整合性を高めます。特に、スイッチ式の評価回数、型なし値の扱い、`nil`の使用制限、ケース式との比較規則、および重複する定数ケース式の許可に関する詳細が追加されました。

## 変更の背景

Go言語の仕様書は、言語の振る舞いを正確かつ網羅的に記述することを目的としています。しかし、このコミット以前の仕様書では、式スイッチ（expression switch）文のいくつかの重要な側面が明記されていませんでした。これにより、開発者がGoコードの挙動を予測する際に混乱が生じたり、コンパイラの実装間で微妙な差異が生じる可能性がありました。

具体的には、以下の点が不明瞭でした。

1.  **スイッチ式の評価回数**: スイッチ文の評価対象となる式が何回評価されるのかが明記されていませんでした。これは、副作用を持つ式の場合に特に重要となります。
2.  **型なし値の扱い**: スイッチ式が型なし（untyped）の定数に評価される場合、その値がどのように扱われるのかが不明瞭でした。Goには型なし定数という概念があり、文脈に応じて型が推論されます。
3.  **`nil`の使用**: 型なしの `nil` 値が式スイッチの式として使用できるかどうかが明確ではありませんでした。
4.  **ケース式との比較**: 各ケース式とスイッチ式の値との比較が、どのような規則に基づいて行われるのかが詳細に記述されていませんでした。特に、比較演算子 `==` の有効性が重要です。
5.  **重複する定数ケース式**: 同じ定数に評価される複数のケース式が許可されるかどうかが不明瞭でした。

これらの不明瞭さは、GoのIssueトラッカーで報告されたいくつかのバグや疑問（例: #4524, #6398, #11668）の原因となっていました。このコミットは、これらの問題を解決するために、既存のコンパイラの挙動に合わせて仕様書を更新し、言語の定義をより堅牢にすることを目的としています。

## 前提知識の解説

このコミットの理解には、Go言語の以下の概念に関する知識が不可欠です。

### 1. Go言語の `switch` 文

Go言語には2種類の `switch` 文があります。

*   **式スイッチ (Expression Switch)**: `switch` キーワードの後に式が続き、その式の値と各 `case` 節の式が比較されます。
    ```go
    switch x {
    case 1:
        // x == 1 の場合
    case 2, 3:
        // x == 2 または x == 3 の場合
    default:
        // どのケースにも一致しない場合
    }
    ```
*   **型スイッチ (Type Switch)**: インターフェースの動的な型を調べるために使用されます。`switch` キーワードの後に `.(type)` という特殊な構文が続きます。
    ```go
    switch v := i.(type) {
    case int:
        // i が int 型の場合
    case string:
        // i が string 型の場合
    default:
        // その他の型の場合
    }
    ```
    このコミットは主に式スイッチに関するものです。

### 2. 型なし定数 (Untyped Constants)

Go言語には、特定の型を持たない「型なし定数」という概念があります。これらは数値リテラル（例: `100`, `3.14`）やブーリアンリテラル（`true`, `false`）、文字列リテラル（`"hello"`）などです。型なし定数は、使用される文脈（代入先の変数や演算子のオペランドなど）に基づいて型が推論されます。

例:
```go
const c = 100 // c は型なし整数定数
var i int = c // c は int 型に変換される
var f float64 = c // c は float64 型に変換される
```

### 3. デフォルト型 (Default Type)

型なし定数が特定の型を必要とする文脈で使用されるが、明示的な型変換が行われない場合、Goは「デフォルト型」を適用します。
*   型なし整数定数のデフォルト型は `int` です。
*   型なし浮動小数点数定数のデフォルト型は `float64` です。
*   型なし複素数定数のデフォルト型は `complex128` です。
*   型なしルーン定数のデフォルト型は `rune` です。
*   型なしブーリアン定数のデフォルト型は `bool` です。
*   型なし文字列定数のデフォルト型は `string` です。

### 4. `nil` 値

Goにおける `nil` は、ポインタ、インターフェース、マップ、スライス、チャネルなどのゼロ値を表す特別な識別子です。`nil` はそれ自体では型を持たず、特定の型を持つ変数に代入されることでその型のゼロ値となります。例えば、`var p *int = nil` の場合、`p` は `*int` 型の `nil` ポインタです。

### 5. 比較演算子 `==`

Goの `==` 演算子は、2つの値が等しいかどうかを比較します。比較可能な型は限られており、例えば、整数、浮動小数点数、文字列、ブーリアン、ポインタ、チャネル、インターフェース、構造体、配列などが比較可能です。異なる型の値は、互いに比較可能である場合にのみ `==` で比較できます。例えば、`int` と `float64` は直接比較できませんが、型なし定数が関与する場合は型変換が行われることがあります。

## 技術的詳細

このコミットによってGo言語仕様書に追加された、式スイッチに関する具体的な技術的詳細と制限は以下の通りです。

1.  **スイッチ式の評価は厳密に1回**:
    *   仕様書に「The switch expression is evaluated exactly once in a switch statement.」という文が追加されました。
    *   これは、`switch` 文の冒頭で評価される式が、その `switch` 文の実行期間中に一度だけ評価されることを保証します。
    *   この保証は、スイッチ式が関数呼び出しやチャネル操作など、副作用を持つ可能性がある場合に非常に重要です。例えば、`switch f()` のように関数呼び出しがスイッチ式である場合、`f()` は一度だけ実行され、その戻り値がすべての `case` 節との比較に使用されます。

2.  **型なしスイッチ式のデフォルト型への変換**:
    *   「If the switch expression evaluates to an untyped constant, it is first converted to its default type; if it is an untyped boolean value, it is first converted to type `bool`.」と明記されました。
    *   これは、スイッチ式が型なし定数（例: `switch 100`）である場合、その定数はまず適切なデフォルト型（例: `int`）に変換されてから、`case` 節の式と比較されることを意味します。型なしブーリアン値（例: `true`）の場合は `bool` 型に変換されます。
    *   これにより、型なし定数と型付きの `case` 式との比較がどのように行われるかが明確になります。

3.  **型なし `nil` はスイッチ式として使用不可**:
    *   「The predeclared untyped value `nil` cannot be used as a switch expression.」と追記されました。
    *   これは、`switch nil` のような構文が許可されないことを明確にしています。`nil` は型なしの値ですが、式スイッチの評価対象としては使用できません。
    *   この制限は、`var` 宣言で明示的な型なしに `nil` を初期化できない規則（例: `var x = nil` はエラー）と対称的であり、Goコンパイラ（`gc`）の既存の挙動を反映しています。`nil` は常に特定の型を持つコンテキストで意味を持つため、型なしのままスイッチ式として使用することは曖昧さを生む可能性があります。

4.  **ケース式とスイッチ式の比較の有効性**:
    *   「For each (possibly converted) case expression `x` and the value `t` of the switch expression, `x == t` must be a valid comparison.」と記述されました。
    *   これは、各 `case` 節の式 `x` と、スイッチ式の評価結果 `t` との間で、`x == t` という比較がGoの比較規則に従って有効でなければならないことを意味します。
    *   つまり、`x` と `t` は互いに比較可能な型でなければなりません。必要に応じて、型なしの `case` 式 `x` はスイッチ式の型 `t` に変換されてから比較されます。
    *   この規則は、スイッチ文の背後にある論理が、一連の `if x == t || y == t || ...` のような比較として機能することを明確にしています。

5.  **重複する定数ケース式の制限 (実装上の制約)**:
    *   「Implementation restriction: A compiler may disallow multiple case expressions evaluating to the same constant. For instance, the current compilers disallow duplicate integer, floating point, or string constants in case expressions.」という実装上の制約が追加されました。
    *   これは、同じ定数に評価される複数の `case` 式（例: `case 1: ... case 1: ...`）が、コンパイラによっては許可されない場合があることを示しています。現在のGoコンパイラは、整数、浮動小数点数、文字列の重複する定数ケース式を禁止しています。
    *   これは言語仕様の厳密な要件ではなく、コンパイラの実装が選択できる制約ですが、Goの主要なコンパイラがこの制約を課しているため、実質的な言語の振る舞いとして認識されます。これにより、到達不能なコードや論理的な矛盾を防ぎます。

### 関連するIssueの明確化

このコミットは、以下のGo Issueを明確化または修正します。

*   **#4524: mult. equal int const switch case values should be illegal**: 複数の等しい整数定数ケース値が不正であるべきという問題。このコミットで、重複する定数ケース式が許可されないという実装上の制約が仕様書に追記され、この問題が仕様レベルで解決されました。
*   **#6398: switch w/ no value uses bool rather than untyped bool**: 値なしのスイッチが型なしブーリアンではなく `bool` を使用するという問題。このコミットで、型なしスイッチ式がデフォルト型（ブーリアンの場合は `bool`）に変換されることが明記され、この問題が仕様レベルで解決されました。
*   **#11668: use of untyped nil in switch**: スイッチ文での型なし `nil` の使用に関する問題。このコミットで、型なし `nil` がスイッチ式として許可されないことが明記され、これは `gc` コンパイラのバグではなく、仕様上の制限であることが明確になりました。

Issue #11578 (allows duplicate switch cases -> go/types bug) と #11667 (int overflow in switch expression -> go/types bug) は、このコミットの直接的な仕様変更ではなく、`go/types` パッケージのバグとして言及されています。これは、仕様の明確化がこれらのバグの根本原因ではないことを示唆しています。

具体的には、以下の変更が行われました。

    *   型なしスイッチ式がデフォルト型に変換されること。

*   既存のテキストの一部で、タブ文字や余分なスペースが修正されました。

## コアとなるコードの解説

`doc/go_spec.html` への変更は、主に `<p>` タグで囲まれた新しい段落の追加と、既存の段落の微修正によって行われています。

**追加された主要な段落:**

1.  **スイッチ式の評価回数に関する記述:**
    ```html
    <p>
    The switch expression is evaluated exactly once in a switch statement.
    </p>
    ```
    これは、`switch` 文の導入部分に追記され、スイッチ式が一度だけ評価されるという基本的な保証を明確にしています。

2.  **型なし値と `nil` の扱いに関する記述:**
    ```html
    <p>
    If the switch expression evaluates to an untyped constant, it is first
    <a href="#Conversions">converted</a> to its <a href="#Constants">default type</a>;
    if it is an untyped boolean value, it is first converted to type <code>bool</code>.
    The predeclared untyped value <code>nil</code> cannot be used as a switch expression.
    </p>
    ```
    この段落は、型なし定数がスイッチ式として使用された場合の型変換ルールと、型なし `nil` がスイッチ式として許可されないことを明確にしています。これにより、Goの型システムにおける型なし値の振る舞いが、スイッチ文の文脈でどのように適用されるかが詳細に記述されます。

3.  **ケース式との比較ルールに関する記述:**
    ```html
    <p>
    If a case expression is untyped, it is first <a href="#Conversions">converted</a>
    to the type of the switch expression.
    For each (possibly converted) case expression <code>x</code> and the value <code>t</code>
    of the switch expression, <code>x == t</code> must be a valid <a href="#Comparison_operators">comparison</a>.
    </p>

    <p>
    In other words, the switch expression is treated as if it were used to declare and
    initialize a temporary variable <code>t</code> without explicit type; it is that
    value of <code>t</code> against which each case expression <code>x</code> is tested
    for equality.
    </p>
    ```
    これらの段落は、`case` 式が型なしの場合の型変換ルールと、各 `case` 式 `x` とスイッチ式の値 `t` との間の比較が `x == t` という形式で有効でなければならないことを説明しています。特に、スイッチ式が暗黙的に一時変数 `t` として扱われるという説明は、その比較セマンティクスを理解する上で非常に重要です。

4.  **重複する定数ケース式に関する実装上の制約:**
    ```html
    <p>
    Implementation restriction: A compiler may disallow multiple case
    expressions evaluating to the same constant.
    For instance, the current compilers disallow duplicate integer,
    floating point, or string constants in case expressions.
    </p>
    ```
    この段落は、コンパイラが重複する定数ケース式を禁止する可能性があるという実装上の制約を明記しています。これは、Goの主要なコンパイラが既にこの挙動を示しているため、仕様書に追記することで、その振る舞いを公式に文書化するものです。

これらの変更は、Go言語の式スイッチ文のセマンティクスに関する曖昧さを解消し、開発者がより正確にコードの挙動を理解し、予測できるようにするために不可欠です。
