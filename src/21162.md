## 変更の背景

Go言語のランタイムは、初期にはC言語とアセンブリ言語で書かれた部分が多く存在しました。しかし、Go言語の設計思想の一つに「GoでGoを書く」というブートストラップの考え方があります。これは、コンパイラやランタイムといったGo言語の基盤部分をGo言語自身で記述することで、開発者体験の向上、コードベースの簡素化、そしてGo言語の機能（ガベージコレクション、並行処理など）をランタイム開発にも活用できるというメリットがあります。

このコミットは、Go 1.5以降で本格化したGoランタイムのC言語からGo言語への大規模な移行の一環として、特にPlan 9オペレーティングシステム向けのポートに焦点を当てています。Plan 9はGo言語の設計者であるケン・トンプソンやロブ・パイクが開発に携わったOSであり、Go言語の多くの設計思想に影響を与えています。そのため、Plan 9向けのランタイムはGo言語の進化において重要な位置を占めていました。

この変更の主な目的は、Plan 9固有のシステムコールや低レベルなOSインタラクションをC言語からGo言語に移植することで、コードの可読性、保守性、そしてGo言語開発者にとってのアクセシビリティを向上させることにありました。

## 前提知識の解説

### Plan 9オペレーティングシステム

Plan 9 from Bell Labsは、Unixの後継としてベル研究所で開発された分散オペレーティングシステムです。主な特徴は以下の通りです。

*   **「すべてがファイル」の哲学**: Unixのこの哲学をさらに推し進め、ネットワーク接続やユーザーインターフェースを含むすべてのシステムリソースをファイルとして表現します。
*   **9Pプロトコル**: ローカルおよびリモートのリソースアクセスに、シンプルでメッセージ指向のファイルシステムプロトコルである9Pを使用します。
*   **プロセスごとの名前空間**: 各プロセスは独自のシステムリソースビューを持ち、強力なプロセス分離を可能にします。
*   **ノート (Notes)**: Unixのシグナルに相当する概念で、文字列ベースの通知メカニズムです。プロセスは他のプロセスに文字列メッセージ（ノート）を送信できます。

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルなコンポーネントの集合体です。これには、ガベージコレクタ、スケジューラ（ゴルーチンの管理）、メモリ管理、システムコールインタフェース、シグナルハンドリングなどが含まれます。Goランタイムは、Goプログラムが異なるオペレーティングシステム上で一貫して動作するための抽象化レイヤーを提供します。

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGo言語のコードを呼び出したりするためのGo言語の機能です。GoランタイムのCからGoへの変換では、Cgoは一時的な手段として、あるいはOS固有の非常に低レベルな処理（アセンブリ言語が必要な場合など）のために使用されることがあります。しかし、パフォーマンスのオーバーヘッドがあるため、可能な限りGo言語で直接実装することが推奨されます。

## 技術的詳細

このコミットは、Plan 9向けのGoランタイムにおけるC言語コードをGo言語に変換するという、技術的に複雑な作業を伴います。主な技術的課題と解決策は以下の通りです。

1.  **メモリ管理の移植**:
    *   `src/runtime/mem_plan9.c` は、Plan 9におけるGoランタイムのメモリ割り当て（`sbrk`システムコールに相当する`brk`関数など）をC言語で実装していました。
    *   このコミットでは、`src/runtime/mem_plan9.go` が新設され、C言語の`brk`に相当する`sbrk`関数や、`sysAlloc`, `sysFree`などのメモリ管理関数がGo言語で再実装されています。Go言語の`unsafe`パッケージや`uintptr`型を駆使して、低レベルなポインタ操作やメモリ操作を行っています。
    *   `_PAGESIZE`のような定数もGo言語の`defs_plan9_386.go`や`defs_plan9_amd64.go`に定義され、メモリのアライメント処理に利用されています。

2.  **OSインタラクションの移植**:
    *   `src/runtime/os_plan9.c` は、プロセス管理（`rfork`）、ファイル操作（`open`, `read`, `write`, `close`）、時間管理（`nanotime`）、環境変数（`getenv`）など、Plan 9固有のシステムコールやOSインタラクションをC言語でラップしていました。
    *   これらの機能は、`src/runtime/os1_plan9.go`、`src/runtime/os2_plan9.go`、`src/runtime/os_plan9_386.go`、`src/runtime/os_plan9_amd64.go`といった複数のGoファイルに分割されて移植されています。
    *   `os1_plan9.go`には、`mpreinit`（Mの初期化）、`minit`（スレッドの初期化）、`getproccount`（CPU数の取得）、`getpid`（プロセスIDの取得）、`osinit`（OS固有の初期化）、`exit`（プログラム終了）などがGo言語で実装されています。
    *   `os2_plan9.go`には、Plan 9のシステムコールで使用される定数（`_OREAD`, `_OWRITE`, `_RFPROC`など）や、`tos`構造体（Thread-local OS state）の定義が含まれています。
    *   `os_plan9.go`には、`pread`, `pwrite`, `exits`, `brk_`, `sleep`, `rfork`, `plan9_semacquire`, `plan9_tsemacquire`, `plan9_semrelease`, `notify`, `noted`, `nsec`, `sigtramp`, `setfpmasks`, `tstart_plan9`, `errstr`といった、Go言語から直接呼び出されるPlan 9システムコールのGo言語ラッパー関数が定義されています。これらの関数には`//go:noescape`ディレクティブが付与されており、Goのスケジューラがこれらの関数がGoのスタックをエスケープしないことを認識し、最適化を可能にしています。

3.  **シグナルハンドリングの移植**:
    *   `src/runtime/signals_plan9.h` は、Plan 9の「ノート」に対応するシグナルハンドリングの定義をC言語のヘッダファイルとして持っていました。
    *   これが `src/runtime/signal_plan9.go` にGo言語の構造体と変数として移植されています。`sigTabT`構造体はシグナルのフラグと名前を定義し、`sigtable`変数に具体的なノート文字列とそれに対応するGoランタイムの挙動（パニック、終了、通知など）がマッピングされています。
    *   `sighandler`関数（`os_plan9_386.go`と`os_plan9_amd64.go`に実装）は、Plan 9カーネルから受け取ったノート文字列を解析し、`sigtable`に基づいて適切なGoランタイムの処理（パニックの発生、プログラムの終了、シグナル通知など）を実行します。

4.  **ネットワーキングスタブの移植**:
    *   `src/runtime/netpoll_stub.c` は、ネットワークポーリングのスタブ実装をC言語で提供していました。
    *   これが `src/runtime/netpoll_stub.go` にGo言語で移植されています。これは、Plan 9が統合されたネットワークポーラーをサポートしていないため、Goランタイムがネットワークイベントを処理するためのプレースホルダーとして機能します。

全体として、このコミットはGoランタイムのPlan 9ポートをC言語からGo言語へ移行させることで、Go言語のブートストラップ戦略を推進し、コードベースの統一性と保守性を大幅に向上させています。

## コアとなるコードの解説

このコミットの核心は、C言語で書かれていた低レベルなOSインタラクションやメモリ管理、シグナルハンドリングのロジックをGo言語に移植した点にあります。

### `mem_plan9.c` から `mem_plan9.go` への移行

**C言語 (`mem_plan9.c`) の抜粋**:
```c
static void*
brk(uintptr nbytes)
{
	uintptr bl;

	runtime·lock(&memlock);
	// Plan 9 sbrk from /sys/src/libc/9sys/sbrk.c
	bl = ((uintptr)bloc + Round) & ~Round;
	if(runtime·brk_((void*)(bl + nbytes)) < 0) {
		runtime·unlock(&memlock);
		return nil;
	}
	bloc = (byte*)bl + nbytes;
	runtime·unlock(&memlock);
	return (void*)bl;	
}
```

**Go言語 (`mem_plan9.go`) の抜粋**:
```go
func sbrk(n uintptr) unsafe.Pointer {
	lock(&memlock)
	// Plan 9 sbrk from /sys/src/libc/9sys/sbrk.c
	bl := (bloc + memRound) &^ memRound
	if brk_(unsafe.Pointer(bl+n)) < 0 {
		unlock(&memlock)
		return nil
	}
	bloc = bl + n
	unlock(&memlock)
	return unsafe.Pointer(bl)
}
```
この例では、C言語の`brk`関数がGo言語の`sbrk`関数に移植されています。基本的なロジックは変わっていませんが、C言語のポインタ操作や型キャストがGo言語の`unsafe.Pointer`や`uintptr`、そしてGoの構文（`&^`演算子など）に置き換えられています。`runtime·lock`や`runtime·brk_`といったC言語のランタイム関数呼び出しは、Go言語の`lock`や`brk_`といった対応する関数呼び出しに変わっています。これは、Goランタイムの内部関数がGo言語で実装されたことを示しています。

### `os_plan9.c` から `os1_plan9.go` / `os2_plan9.go` / `os_plan9.go` への移行

C言語の`os_plan9.c`は、Plan 9固有の多くのOSインタラクションを扱っていました。これがGo言語の複数のファイルに分割されています。

**`os_plan9.c` の `getproccount` 関数 (C言語)**:
```c
static int32
getproccount(void)
{
	int32 fd, i, n, ncpu;
	byte buf[2048];

	fd = runtime·open("/dev/sysstat", OREAD, 0);
	if(fd < 0)
		return 1;
	ncpu = 0;
	for(;;) {
		n = runtime·read(fd, buf, sizeof buf);
		if(n <= 0)
			break;
		for(i = 0; i < n; i++) {
			if(buf[i] == '\n')
				ncpu++;
		}
	}
	runtime·close(fd);
	return ncpu > 0 ? ncpu : 1;
}
```

**`os1_plan9.go` の `getproccount` 関数 (Go言語)**:
```go
func getproccount() int32 {
	var buf [2048]byte
	fd := open(&sysstat[0], _OREAD, 0)
	if fd < 0 {
		return 1
	}
	ncpu := int32(0)
	for {
		n := read(fd, unsafe.Pointer(&buf), int32(len(buf)))
		if n <= 0 {
			break
		}
		for i := int32(0); i < n; i++ {
			if buf[i] == '\n' {
				ncpu++
			}
		}
	}
	close(fd)
	if ncpu == 0 {
		ncpu = 1
	}
	return ncpu
}
```
ここでも、C言語の構文がGo言語の構文に置き換えられ、`runtime·open`や`runtime·read`といったC言語のランタイム関数がGo言語の`open`や`read`に変わっています。`_OREAD`のような定数は`os2_plan9.go`で定義されています。

### `signals_plan9.h` から `signal_plan9.go` への移行

**C言語 (`signals_plan9.h`) の抜粋**:
```c
#pragma dataflag NOPTR
SigTab runtime·sigtab[] = {
	// Traps that we cannot be recovered.
	T,	"sys: trap: debug exception",
	T,	"sys: trap: invalid opcode",
	// ...
};
```

**Go言語 (`signal_plan9.go`) の抜粋**:
```go
type sigTabT struct {
	flags int
	name  []byte
}

var sigtable = [...]sigTabT{
	// Traps that we cannot be recovered.
	{_SigThrow, []byte("sys: trap: debug exception")},
	{_SigThrow, []byte("sys: trap: invalid opcode")},
	// ...
}
```
C言語の構造体配列とマクロ定義が、Go言語の`struct`とスライス（または配列）に変換されています。これにより、シグナル（ノート）の定義がGo言語の型システムに統合され、より安全でGoらしい方法で扱えるようになりました。

これらの変更は、GoランタイムのPlan 9ポートが、C言語のコードからGo言語のコードへと完全に移行したことを明確に示しています。これにより、Go言語のブートストラップ目標がさらに一歩前進し、Goランタイムの全体的な保守性と開発効率が向上しました。
