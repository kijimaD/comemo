## 元コミット内容

このコミットは、Goのランタイムおよび`syscall`パッケージにおけるSolaris環境での`exec`関連のテストを修正し、同時に`fork`/`exec`パスに長らく存在していた問題を解決します。具体的には、`setpgid`システムコールのインポート定義の修正、Solaris固有の`exec`テストの追加、そしてUnix系システムにおける`ioctl`システムコール呼び出しのテストヘルパーの導入が含まれます。

## 変更の背景

GoプログラムがUnix系システム、特にSolaris上で外部プログラムを実行する際に、`fork`と`exec`システムコールが利用されます。しかし、Goのランタイムはマルチスレッド環境であり、単独の`fork`呼び出しは子プロセスでGoランタイムを不安定な状態にする可能性があります。このため、Goでは通常、`fork`の直後に`exec`を呼び出して子プロセスのイメージを新しいプログラムに置き換える`fork-exec`パターンが安全な方法とされています。

このコミットの背景には、以下の問題が考えられます。

1.  **Solarisにおける`exec`テストの不備**: 既存のテストスイートがSolaris環境での`exec`の挙動、特にプロセスグループや端末制御の側面を十分にカバーしていなかった可能性があります。これにより、Solaris固有のバグが見過ごされていた可能性があります。
2.  **`fork`/`exec`パスにおける長期的な問題**: Goの`fork`/`exec`実装において、プロセスグループの管理や端末とのインタラクションに関する潜在的なバグが存在していたと考えられます。これは、特にフォアグラウンド/バックグラウンドプロセスの切り替えや、子プロセスが正しく端末を制御できるかどうかに影響を与えます。
3.  **`setpgid`の誤ったリンケージ**: `src/runtime/syscall2_solaris.go`の変更が示唆するように、Solaris環境で`setpgid`システムコールを呼び出す際に、誤って`setsid`関数がリンクされていた可能性があります。`setpgid`は既存のプロセスグループを変更するのに対し、`setsid`は新しいセッションとプロセスグループを作成するため、これはプロセスグループ管理において重大な誤りとなります。
4.  **`ioctl`呼び出しのテストの複雑さ**: `ioctl`はデバイス固有の操作を行うための汎用的なシステムコールであり、端末制御（例: `TIOCGPGRP`, `TIOCSPGRP`）にも使用されます。テストコード内で直接`syscall.Syscall`を使って`ioctl`を呼び出すのは冗長であり、可読性や保守性の観点から改善の余地がありました。

これらの問題に対処するため、このコミットではSolaris固有のテストを追加し、`setpgid`のリンケージを修正し、`ioctl`呼び出しを抽象化するヘルパー関数を導入することで、`fork`/`exec`パスの堅牢性と正確性を向上させています。

## 前提知識の解説

### Goの`syscall`パッケージ

Goの`syscall`パッケージは、オペレーティングシステムの低レベルなシステムコールへのアクセスを提供します。これにより、ファイル操作、プロセス管理、ネットワーク通信など、OSカーネルが提供する機能と直接やり取りできます。

*   **`syscall.Syscall`**: 汎用的なシステムコール呼び出し関数です。引数としてシステムコール番号と最大3つの`uintptr`型の引数を取ります。
*   **`syscall.RawSyscall`**: `Syscall`と同様ですが、Goランタイムのスケジューラをブロックしないため、より低レベルな操作に適しています。ただし、Solarisでは直接の`RawSyscall`はサポートされておらず、`libc`経由でシステムコールを呼び出すのが一般的です。
*   **`ioctl`**: "Input/Output Control"の略で、デバイスドライバに直接コマンドを送信するための汎用的なシステムコールです。端末のフォアグラウンドプロセスグループの設定/取得など、様々なデバイス固有の操作に使用されます。

### `fork`/`exec`システムコール

Unix系OSにおける新しいプロセスの作成は、通常`fork`と`exec`の組み合わせで行われます。

*   **`fork()`**: 呼び出し元のプロセス（親プロセス）のほぼ完全なコピーである新しいプロセス（子プロセス）を作成します。子プロセスは親プロセスのメモリ空間、ファイルディスクリプタ、シグナルハンドラなどを継承します。
*   **`exec()`ファミリー**: 現在のプロセスイメージを、指定された新しいプログラムのイメージで置き換えます。`exec`が成功すると、現在のプロセスは終了せず、新しいプログラムが現在のプロセスのPIDを引き継いで実行されます。

Goのマルチスレッドランタイムでは、`fork`単独での使用は問題を引き起こす可能性があります。`fork`は呼び出し元のスレッドのみを子プロセスにコピーするため、子プロセスではGoランタイムの他のスレッドや内部状態が不整合になる可能性があります。このため、Goでは`syscall.ForkExec`のような関数が提供され、`fork`の直後に`exec`を実行することで、この問題を回避します。

### プロセスグループとセッション

Unix系OSでは、プロセスは階層的に組織化されます。

*   **プロセスグループ**: 1つ以上の関連するプロセスの集まりです。プロセスグループ内のプロセスは、シグナルをまとめて受け取ることができます。各プロセスグループには、プロセスグループリーダーと呼ばれるプロセスがあり、そのPIDがプロセスグループID (PGID) となります。
*   **セッション**: 1つ以上のプロセスグループの集まりです。各セッションには、セッションリーダーと呼ばれるプロセスがあり、そのPIDがセッションID (SID) となります。セッションは通常、ログインシェルや端末セッションに関連付けられます。
*   **`setpgid()`**: 指定されたプロセスのプロセスグループIDを設定します。
*   **`getpgid()`**: 指定されたプロセスのプロセスグループIDを取得します。
*   **`getpgrp()`**: 呼び出し元のプロセスのプロセスグループIDを取得します。
*   **`setsid()`**: 新しいセッションを作成し、呼び出し元のプロセスをそのセッションリーダーにします。同時に、新しいプロセスグループも作成し、呼び出し元のプロセスをそのプロセスグループリーダーにします。

### 端末制御と`ioctl`

端末（TTY）は、フォアグラウンドプロセスグループとバックグラウンドプロセスグループを管理します。

*   **フォアグラウンドプロセスグループ**: 端末からの入力（キーボード入力など）を受け取り、端末への出力（画面表示など）を行う権限を持つプロセスグループです。
*   **バックグラウンドプロセスグループ**: 端末からの入力は受け取らず、端末への出力も制限されるプロセスグループです。
*   **`TIOCGPGRP`**: `ioctl`コマンドの一つで、端末のフォアグラウンドプロセスグループIDを取得するために使用されます。
*   **`TIOCSPGRP`**: `ioctl`コマンドの一つで、端末のフォアグラウンドプロセスグループIDを設定するために使用されます。

これらの`ioctl`コマンドは、シェルがジョブコントロール（フォアグラウンド/バックグラウンドジョブの切り替え）を実装するために不可欠です。

### Solaris特有の考慮事項

Solarisは、他のUnix系OS（Linuxなど）とは異なるシステムコールインターフェースを持つことがあります。特に、GoプログラムがSolaris上でシステムコールを直接呼び出すのではなく、C標準ライブラリ（`libc`）を介して呼び出すことが一般的です。これは、Solarisが安定した直接のシステムコールインターフェースを提供しないためです。このため、Goのランタイムは`//go:cgo_import_dynamic`ディレクティブを使用して、`libc.so`から特定のC関数を動的にインポートします。

## 技術的詳細

このコミットは、以下の主要な技術的変更を含んでいます。

1.  **`setpgid`のリンケージ修正**:
    `src/runtime/syscall2_solaris.go`において、`libc_setpgid`の動的インポートが`setsid`ではなく`setpgid`を指すように修正されました。
    変更前: `//go:cgo_import_dynamic libc_setpgid setsid "libc.so"`
    変更後: `//go:cgo_import_dynamic libc_setpgid setpgid "libc.so"`
    この修正は非常に重要です。`setsid`は新しいセッションとプロセスグループを作成するのに対し、`setpgid`は既存のプロセスを特定のプロセスグループに所属させます。`exec`のコンテキストでは、子プロセスが親プロセスと同じセッションに留まりつつ、特定のプロセスグループに所属する必要がある場合が多いため、`setpgid`が正しい動作を提供します。誤って`setsid`が呼ばれると、予期せぬセッション分離が発生し、端末制御の問題やジョブコントロールの不具合につながる可能性があります。

2.  **Solaris固有の`exec`テストの追加**:
    `src/syscall/exec_solaris_test.go`という新しいファイルが追加されました。このファイルはSolaris環境でのみビルドされる（`+build solaris`）テストを含んでいます。このテストファイルには、`getpgid`と`getpgrp`というCライブラリ関数を呼び出すためのGoラッパー関数（`Getpgid`と`Getpgrp`）が定義されています。これらの関数は、`exec`されたプロセスのプロセスグループIDを正確に取得し、テスト内で検証するために使用されます。これにより、Solaris環境での`exec`後のプロセスグループの挙動が正しく行われているかを確認できるようになります。

3.  **`ioctl`テストヘルパーの導入**:
    `src/syscall/export_unix_test.go`という新しいファイルが追加されました。このファイルは、Unix系システム（Darwin, DragonFly, FreeBSD, Linux, NetBSD, OpenBSD）でビルドされる（`+build darwin dragonfly freebsd linux netbsd openbsd`）テスト用の`Ioctl`ヘルパー関数を定義しています。
    `func Ioctl(fd, req, arg uintptr) (err Errno) { _, _, err = Syscall(SYS_IOCTL, fd, req, arg); return err }`
    このヘルパー関数は、`syscall.Syscall`を直接呼び出す代わりに、`ioctl`システムコールをより簡潔に呼び出すためのラッパーを提供します。

4.  **`exec_unix_test.go`における`ioctl`呼び出しの変更**:
    `src/syscall/exec_unix_test.go`の`TestForeground`関数内で、端末のフォアグラウンドプロセスグループを取得・設定する`ioctl`呼び出しが、直接`syscall.Syscall(syscall.SYS_IOCTL, ...)`を使用する形式から、新しく導入された`syscall.Ioctl(...)`ヘルパー関数を使用する形式に変更されました。
    変更前: `_, _, errno := syscall.Syscall(syscall.SYS_IOCTL, tty.Fd(), syscall.TIOCGPGRP, uintptr(unsafe.Pointer(&fpgrp)))`
    変更後: `errno := syscall.Ioctl(tty.Fd(), syscall.TIOCGPGRP, uintptr(unsafe.Pointer(&fpgrp)))`
    この変更により、テストコードの可読性が向上し、`ioctl`呼び出しのパターンが統一されます。また、`export_unix_test.go`で定義された`Ioctl`関数が、`SYS_IOCTL`が定義されていない環境でも適切に動作するように抽象化されている可能性があります。

これらの変更は、Goが異なるUnix系OS、特にSolarisのような特定の挙動を持つ環境で、`fork`/`exec`およびプロセスグループ管理をより堅牢かつ正確に処理できるようにするためのものです。特に、`setpgid`のリンケージ修正は、プロセスグループの意図しない分離を防ぎ、ジョブコントロールが正しく機能するために不可欠です。

1.  **`src/runtime/syscall2_solaris.go`の修正**:
    この変更は、Solaris環境でGoランタイムがCライブラリの`setpgid`関数を正しく参照するようにします。以前は誤って`setsid`関数が参照されていたため、プロセスグループを設定しようとした際に、意図せず新しいセッションが作成されてしまう可能性がありました。この修正により、`exec`されたプロセスが既存のセッションとプロセスグループのコンテキスト内で正しく動作し、特に端末制御（フォアグラウンド/バックグラウンドプロセス管理）が期待通りに行われるようになります。これは、`fork`/`exec`パスにおける「長らく存在していた問題」の核心部分の一つと考えられます。

2.  **`src/syscall/exec_solaris_test.go`の追加**:
    この新しいテストファイルは、Solaris環境における`exec`の挙動、特にプロセスグループの管理が正しく行われているかを検証するために不可欠です。`Getpgid`と`Getpgrp`関数は、テスト内で子プロセスのプロセスグループIDを取得し、それが期待される値であるかを確認するために使用されます。これにより、Solaris固有のシステムコールや`libc`の挙動に起因する問題を早期に発見し、修正できるようになります。このテストの追加は、プラットフォーム固有の`exec`の堅牢性を高める上で重要な役割を果たします。

3.  **`src/syscall/exec_unix_test.go`と`src/syscall/export_unix_test.go`の変更**:
    `export_unix_test.go`で定義された`Ioctl`ヘルパー関数は、`exec_unix_test.go`内の`TestForeground`関数における`ioctl`システムコール呼び出しを抽象化します。これにより、テストコードがよりクリーンになり、`syscall.Syscall`の低レベルな詳細から解放されます。`Ioctl`関数は、`fd`（ファイルディスクリプタ）、`req`（`ioctl`リクエストコード、例: `TIOCGPGRP`）、`arg`（引数）を受け取り、`ioctl`呼び出しを実行します。この抽象化は、テストの可読性と保守性を向上させるだけでなく、将来的に`ioctl`の呼び出し方法が変更された場合でも、一箇所を修正するだけで済むという利点があります。`TestForeground`は、端末のフォアグラウンドプロセスグループを操作することで、Goプログラムが外部プロセスをフォアグラウンドで実行し、そのプロセスが端末を正しく制御できることを検証する重要なテストです。この変更は、そのテストの信頼性と明確性を高めます。

これらの変更は全体として、GoがUnix系システム、特にSolaris上で外部プログラムを起動する際の堅牢性と正確性を大幅に向上させるものです。プロセスグループの正しい管理は、シェルや他のプロセス管理ツールとの連携において極めて重要であり、このコミットはその基盤を強化しています。
