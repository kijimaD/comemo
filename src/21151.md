# [インデックス 21151] ファイルの概要

このコミットは、Goランタイムのレース検出器（ThreadSanitizer、TSan）がヒープ外のアドレス（データセグメントやBSSセグメントなど）に対するアトミック操作を正しく処理できない問題を修正します。具体的には、以前の変更で削除されたアドレスチェックを復元し、TSanがこれらのアドレスでのアトミック操作を適切に無視するように `__tsan_go_ignore_sync_start` および `__tsan_go_ignore_sync_end` 関数を使用するように変更します。これにより、レース検出器がクラッシュしたり、誤ったレポートを生成したりするのを防ぎます。

## 変更の背景

このコミットは、Goのレース検出器が特定のメモリ領域、特にヒープではないアドレス（グローバル変数や静的変数などが配置されるデータセグメントやBSSセグメント）に対するアトミック操作を処理する際に発生する問題を解決するために導入されました。

問題の根本原因は、以前のコミット `https://golang.org/cl/111310044` で、アトミック操作に対するアドレスチェックが削除されたことにあります。レース検出器（ThreadSanitizer）は、監視対象のメモリ領域を `__tsan_map_shadow` を通じて認識する必要があります。ヒープ外のアドレスがこのシャドウメモリマップに適切に登録されていない場合、それらのアドレスに対するアトミック操作がレース検出器によって監視されると、検出器がクラッシュしたり、誤ったデータ競合を報告したりする可能性がありました。

このコミットは、`#9136` として追跡されていた問題を修正します。この問題は、Goの内部的な問題追跡システムで管理されていた可能性があります。

## 前提知識の解説

*   **Goのレース検出器 (Race Detector)**: Go言語に組み込まれているツールで、並行処理におけるデータ競合（data race）を検出します。データ競合とは、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが同期メカニズムによって保護されていない場合に発生するバグです。Goのレース検出器は、GoogleのThreadSanitizer (TSan) をベースにしています。
*   **ThreadSanitizer (TSan)**: LLVMプロジェクトの一部として開発された動的データ競合検出ツールです。プログラムの実行中にメモリアクセスを監視し、データ競合のパターンを検出します。TSanは、各メモリワードに対して「シャドウメモリ」と呼ばれる追加のメタデータを維持し、アクセス履歴を記録します。
*   **ヒープ (Heap)**: プログラムが実行時に動的にメモリを割り当てる領域です。Goでは、`make` や `new` などで割り当てられるメモリがこれに該当します。
*   **非ヒープアドレス (Non-heap addresses)**: ヒープ以外のメモリ領域を指します。これには主に以下のものが含まれます。
    *   **データセグメント (Data Segment)**: 初期化されたグローバル変数や静的変数が格納される領域。
    *   **BSSセグメント (BSS Segment)**: 初期化されていないグローバル変数や静的変数が格納される領域。
    *   **スタック (Stack)**: 関数呼び出しやローカル変数が一時的に格納される領域。
*   **アトミック操作 (Atomic Operations)**: 複数のスレッド（またはゴルーチン）から同時にアクセスされても、その操作が中断されずに完全に実行されることが保証される操作です。これにより、データ競合を防ぎ、並行処理の安全性を確保します。Goでは `sync/atomic` パッケージで提供されます。
*   **`__tsan_map_shadow`**: ThreadSanitizerの内部関数で、特定のメモリ領域をTSanのシャドウメモリマップに登録するために使用されます。これにより、TSanはその領域のメモリアクセスを監視できるようになります。
*   **`__tsan_go_ignore_sync_start` / `__tsan_go_ignore_sync_end`**: ThreadSanitizerの内部関数で、これらの関数の呼び出しで囲まれたコードブロック内では、TSanが同期イベントの監視を一時的に無視するように指示します。これは、Goランタイムの内部的な操作など、本来安全であるにもかかわらずTSanが誤ってデータ競合を報告する可能性のある箇所で使用されます。

## 技術的詳細

Goのレース検出器は、プログラムのメモリアクセスを監視し、データ競合の可能性を検出します。この監視は、TSanが管理するシャドウメモリを通じて行われます。TSanは、監視対象のメモリ領域がどこにあるかを `__tsan_map_shadow` を通じて知る必要があります。

以前のコミット `https://golang.org/cl/111310044` では、アトミック操作が実行される際のアドレスチェックが削除されました。このチェックは、アトミック操作の対象アドレスがTSanが認識しているメモリ領域（ヒープ、データ、BSS）内にあることを確認するためのものでした。このチェックがなくなったことで、TSanが認識していない、または適切にマッピングされていない非ヒープアドレスに対するアトミック操作が行われた場合に問題が発生しました。TSanは、そのようなアドレスに対する操作を予期せず、クラッシュしたり、誤った競合を報告したりする可能性がありました。

このコミットの修正は、この問題を二段階で解決します。

1.  **アドレスチェックの復元と改善**: `isvalidaddr` 関数において、以前削除されたデータ、BSS、ヒープ領域のアドレスチェックを復元します。ただし、以前のように個々のセグメント（`noptrdata`, `data`, `bss`, `noptrbss`）を個別にチェックするのではなく、`runtime·racedatastart` と `runtime·racedataend` という新しいグローバル変数を用いて、データ+BSSセグメント全体を一つの範囲としてチェックするように変更します。これにより、コードが簡潔になり、管理が容易になります。これらの変数は `runtime·raceinit` で初期化され、`__tsan_map_shadow` を呼び出す際に使用される範囲と一致させます。
2.  **アトミック操作のTSan無視メカニズム**: アトミック操作自体は、TSanが内部的に処理を行う場合があります。単にレース検出器を呼び出さないだけでは、アトミック操作自体がスキップされてしまう可能性があります。そこで、このコミットでは、アトミック操作の前後で `__tsan_go_ignore_sync_start` と `__tsan_go_ignore_sync_end` を呼び出すように変更します。これにより、TSanはアトミック操作自体は実行しつつ、その操作に関連する同期イベントの監視を一時的に停止します。これにより、TSanがヒープ外のアドレスに対するアトミック操作で誤動作するのを防ぎつつ、アトミック操作の完全性を保証します。

新しいテストケース `TestNonGoMemory` は、`syscall.Mmap` を使用してGoランタイムが管理しないメモリを割り当て、そのメモリに対してアトミック操作を実行することで、この修正が正しく機能することを確認します。これは、まさに「非ヒープアドレス」に対する操作をシミュレートするものです。

## コアとなるコードの変更箇所

このコミットでは、主に以下の3つのファイルが変更されています。

1.  **`src/runtime/race.c`**:
    *   `runtime·racedatastart` と `runtime·racedataend` という新しいグローバル変数が追加され、データ+BSSセグメントの開始アドレスと終了アドレスを保持します。
    *   `isvalidaddr` 関数が変更され、個別のデータ/BSSセグメントのチェックが削除され、`runtime·racedatastart` と `runtime·racedataend` を使用した単一の範囲チェックに置き換えられました。
    *   `runtime·raceinit` 関数で、`runtime·racedatastart` と `runtime·racedataend` が初期化されます。
2.  **`src/runtime/race/race_unix_test.go`**:
    *   `TestNonGoMemory` という新しいテスト関数が追加されました。このテストは、`syscall.Mmap` を使用してGoランタイムが管理しないメモリを割り当て、そのメモリに対して `atomic.AddUint32` や直接的なポインタ操作を行い、レース検出器がクラッシュしないことを確認します。
3.  **`src/runtime/race_amd64.s`**:
    *   `racecalladdr` および `racecallatomic` というアセンブリ関数が変更されました。
    *   `racecalladdr` では、アドレスチェックのロジックが `runtime·racedatastart` と `runtime·racedataend` を使用するように更新されました。
    *   `racecallatomic` では、アトミック操作の対象アドレスが有効な範囲外である場合に、`__tsan_go_ignore_sync_begin` と `__tsan_go_ignore_sync_end` を呼び出すロジックが追加されました。これにより、TSanがアトミック操作を一時的に無視するようになります。

## コアとなるコードの解説

### `src/runtime/race.c` の変更

```c
// start/end of global data (data+bss).
uintptr runtime·racedatastart;
uintptr runtime·racedataend;

// ...

isvalidaddr(uintptr addr)
{
 	if(addr >= runtime·racearenastart && addr < runtime·racearenaend)
 		return true;
-	if(addr >= (uintptr)runtime·noptrdata && addr < (uintptr)runtime·enoptrdata)
-		return true;
-	if(addr >= (uintptr)runtime·data && addr < (uintptr)runtime·edata)
-		return true;
-	if(addr >= (uintptr)runtime·bss && addr < (uintptr)runtime·ebss)
-		return true;
-	if(addr >= (uintptr)runtime·noptrbss && addr < (uintptr)runtime·enoptrbss)
+	if(addr >= runtime·racedatastart && addr < runtime·racedataend)
 		return true;
 	return false;
}

// ...

runtime·raceinit(void)
{
 	// ...
 	start = start & ~(PageSize-1);
 	size = ROUND(end - start, PageSize);
 	runtime·racecall(__tsan_map_shadow, start, size);
+	runtime·racedatastart = start;
+	runtime·racedataend = start + size;
 	return racectx;
}
```
`runtime·racedatastart` と `runtime·racedataend` は、Goプログラムのグローバルデータ（初期化済みおよび未初期化）が配置されるメモリ範囲を定義します。`runtime·raceinit` でこれらの変数が初期化される際に、`__tsan_map_shadow` が呼び出され、TSanにこのメモリ範囲を監視対象として登録します。`isvalidaddr` 関数は、与えられたアドレスがレース検出器が監視すべき有効なメモリ領域（ヒープまたはグローバルデータ）内にあるかどうかを効率的にチェックするようになりました。

### `src/runtime/race/race_unix_test.go` の変更

```go
// Test that race detector does not crash when accessing non-Go allocated memory (issue 9136).
func TestNonGoMemory(t *testing.T) {
	data, err := syscall.Mmap(-1, 0, 4096, syscall.PROT_READ|syscall.PROT_WRITE, syscall.MAP_ANON|syscall.MAP_PRIVATE)
	if err != nil {
		t.Fatalf("failed to mmap memory: %v", err)
	}
	p := (*uint32)(unsafe.Pointer(&data[0]))
	atomic.AddUint32(p, 1)
	(*p)++
	if *p != 2 {
		t.Fatalf("data[0] = %v, expect 2", *p)
	}
	syscall.Munmap(data)
}
```
このテストは、Goランタイムのメモリ管理外で `syscall.Mmap` を使ってメモリを確保し、そのメモリに対して `atomic.AddUint32` や直接的なポインタ操作を行います。これにより、レース検出器がヒープ外のアドレスに対するアトミック操作を正しく処理し、クラッシュしないことを検証します。これは、このコミットが修正しようとしている問題の直接的なテストケースです。

### `src/runtime/race_amd64.s` の変更

```assembly
TEXT	racecallatomic<>(SB), NOSPLIT, $0-0
 	// Trigger SIGSEGV early.
 	MOVQ	16(SP), R12
-	MOVL	(R12), R12
+	MOVL	(R12), R13
+	// Check that addr is within [arenastart, arenaend) or within [racedatastart, racedataend).
+	CMPQ	R12, runtime·racearenastart(SB)
+	JB	racecallatomic_data
+	CMPQ	R12, runtime·racearenaend(SB)
+	JB	racecallatomic_ok
+racecallatomic_data:
+	CMPQ	R12, runtime·racedatastart(SB)
+	JB	racecallatomic_ignore
+	CMPQ	R12, runtime·racedataend(SB)
+	JAE	racecallatomic_ignore
+racecallatomic_ok:
+	// Addr is within the good range, call the atomic function.
 	get_tls(R12)
 	MOVQ	g(R12), R14
 	MOVQ	g_racectx(R14), RARG0	// goroutine context
 	MOVQ	8(SP), RARG1	// caller pc
 	MOVQ	(SP), RARG2	// pc
 	LEAQ	16(SP), RARG3	// arguments
+	JMP	racecall<>(SB)	// does not return
+racecallatomic_ignore:
+	// Addr is outside the good range.
+	// Call __tsan_go_ignore_sync_begin to ignore synchronization during the atomic op.
+	// An attempt to synchronize on the address would cause crash.
+	MOVQ	AX, R15	// remember the original function
+	MOVQ	$__tsan_go_ignore_sync_begin(SB), AX
+	MOVQ	g(R12), R14
+	MOVQ	g_racectx(R14), RARG0	// goroutine context
+	CALL	racecall<>(SB)
+	MOVQ	R15, AX	// restore the original function
+	// Call the atomic function.
+	MOVQ	g_racectx(R14), RARG0	// goroutine context
+	MOVQ	8(SP), RARG1	// caller pc
+	MOVQ	(SP), RARG2	// pc
+	LEAQ	16(SP), RARG3	// arguments
+	CALL	racecall<>(SB)
+	// Call __tsan_go_ignore_sync_end.
+	MOVQ	$__tsan_go_ignore_sync_end(SB), AX
+	MOVQ	g_racectx(R14), RARG0	// goroutine context
 	JMP	racecall<>(SB)
```
`racecallatomic` は、アトミック操作を呼び出すためのアセンブリルーチンです。この変更の核心は、アトミック操作の対象アドレスがヒープまたはグローバルデータセグメントの有効な範囲内にあるかどうかをチェックするロジックです。もしアドレスが有効な範囲外であれば、`racecallatomic_ignore` ラベルにジャンプします。

`racecallatomic_ignore` ブロックでは、`__tsan_go_ignore_sync_begin` を呼び出してTSanに同期イベントの監視を一時的に停止させます。その後、実際のアトミック操作を実行し、最後に `__tsan_go_ignore_sync_end` を呼び出してTSanの監視を再開させます。このメカニズムにより、TSanはヒープ外のアドレスに対するアトミック操作を安全に処理できるようになります。
