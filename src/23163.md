## 変更の背景

Go 1.5 は、Go言語にとって非常に重要なリリースでした。このバージョンでは、GoコンパイラとランタイムがGo自身で記述される「セルフホスティング」が達成され、ガベージコレクタの改善、並行処理モデルの進化など、多くの根本的な変更が加えられました。

このコミットは、Go 1.5 のリリースノートである `doc/go1.5.txt` に、特にセキュリティとネットワーク通信の基盤となる `crypto` パッケージ群における最近の重要な変更点を反映させることを目的としています。暗号技術は常に進化しており、新たな脅威やより堅牢な実装が求められます。Go言語が提供する暗号ライブラリは、その利用者が安全なアプリケーションを構築するために不可欠であり、これらの変更点を明確に文書化することは、開発者が最新のセキュリティプラクティスに準拠したコードを書く上で極めて重要です。

具体的には、楕円曲線暗号の安全性向上、TLS通信における透明性の確保と効率化、そしてX.509証明書の検証ロジックの改善といった、多岐にわたるセキュリティ関連の強化がGo 1.5で導入されており、本コミットはそれらを公式ドキュメントに記載することで、ユーザーへの情報提供を徹底しています。

## 前提知識の解説

このコミットの技術的詳細を理解するためには、以下の概念について基本的な知識があると役立ちます。

*   **Go 1.5**: Go言語の歴史において画期的なリリースであり、コンパイラとランタイムがGo自身で記述されるようになった最初のバージョンです。これにより、Goの開発サイクルが加速し、より高度な最適化が可能になりました。
*   **Goの `crypto` パッケージ群**: Go標準ライブラリには、暗号化、ハッシュ、デジタル署名、TLS/SSL通信など、様々な暗号関連機能を提供するパッケージ群（例: `crypto/tls`, `crypto/x509`, `crypto/elliptic` など）が含まれています。これらは、安全なネットワーク通信やデータ保護の基盤となります。
*   **TLS (Transport Layer Security)**: インターネット上で安全な通信を行うためのプロトコルです。ウェブサイトのHTTPS通信などで広く利用されており、データの暗号化、認証、完全性保証を提供します。
*   **X.509 証明書**: 公開鍵証明書の標準フォーマットであり、TLS通信においてサーバーやクライアントの身元を証明するために使用されます。認証局 (CA) によって発行され、公開鍵と所有者の情報を関連付けます。
*   **楕円曲線暗号 (Elliptic Curve Cryptography, ECC)**: 公開鍵暗号の一種で、従来のRSA暗号に比べて短い鍵長で同等のセキュリティ強度を実現できるため、モバイルデバイスなどリソースが限られた環境での利用に適しています。
*   **Certificate Transparency (CT)**: 証明書の透明性。認証局が発行したすべてのTLS証明書を公開ログに記録することを義務付けるオープンなフレームワークです。これにより、不正な証明書の発行を検出し、ウェブのセキュリティを向上させることを目的としています。SCT (Signed Certificate Timestamp) は、証明書がCTログに記録されたことを証明するタイムスタンプです。
*   **TLS セッションチケット (Session Tickets)**: TLSハンドシェイクの高速化を目的としたメカニズムです。クライアントとサーバーが以前のセッション情報を暗号化されたチケットとして共有することで、完全なハンドシェイクを省略し、その後の接続確立を迅速に行うことができます。

## 技術的詳細

このコミットによって `doc/go1.5.txt` に追加された各行は、Go 1.5 における `crypto` パッケージ群の具体的な改善点を示しています。それぞれの変更について、その技術的な意味合いを詳しく解説します。

1.  **`crypto/elliptic: Unmarshaling points now automatically checks that the point is on the curve (https://golang.org/cl/2421)`**
    *   **背景**: 楕円曲線暗号において、曲線上の点を表現する際に、与えられた座標が実際にその楕円曲線上にある点であるかを検証することは非常に重要です。悪意のある入力が曲線上にない点を提示した場合、特定の攻撃（例: 無効な点攻撃）によって秘密鍵が漏洩する可能性があります。
    *   **変更内容**: 以前は、楕円曲線上の点をアンマーシャリング（バイト列から構造体へ変換）する際に、その点が実際に曲線上に存在するかどうかの検証が自動的に行われていませんでした。この変更 (CL 2421) により、`crypto/elliptic` パッケージのアンマーシャリング処理において、入力された点が自動的に曲線上の点であるかどうかが検証されるようになりました。
    *   **技術的影響**: これにより、Goの楕円曲線暗号の実装の堅牢性が向上し、無効な点攻撃に対する耐性が強化されました。開発者が明示的に検証コードを記述する必要がなくなり、より安全なAPI利用が促進されます。

2.  **`crypto/tls: including Certificate Transparency SCTs in the handshake is now supported (https://golang.org/cl/8988)`**
    *   **背景**: Certificate Transparency (CT) は、認証局による証明書の不正発行を防ぐための重要な仕組みです。クライアントがTLSハンドシェイク中にSCT (Signed Certificate Timestamp) を受け取ることで、その証明書が公開されたCTログに記録されていることを検証できます。
    *   **変更内容**: この変更 (CL 8988) により、Goの `crypto/tls` パッケージは、TLSハンドシェイク中にSCTを含めることをサポートするようになりました。これにより、Goで実装されたTLSクライアントは、サーバーから提供される証明書がCTログに適切に記録されていることを検証できるようになります。
    *   **技術的影響**: GoアプリケーションがCTをより容易に利用できるようになり、ウェブの信頼性向上に貢献します。クライアント側でのSCT検証は、証明書の透明性を確保し、フィッシングや中間者攻撃のリスクを低減する上で重要な役割を果たします。

3.  **`crypto/tls: session ticket keys can now be rotated at runtime (https://golang.org/cl/9072)`**
    *   **背景**: TLSセッションチケットは、ハンドシェイクを高速化するために使用されますが、その暗号化に使用される鍵が長期間固定されていると、前方秘匿性 (Forward Secrecy) が損なわれる可能性があります。鍵が漏洩した場合、過去のセッションも復号されてしまうリスクがあります。
    *   **変更内容**: この変更 (CL 9072) は、`crypto/tls` パッケージに `Config.SetSessionTicketKeys` 関数を導入しました。これにより、TLSサーバーは実行時にセッションチケットの暗号化/復号に使用する鍵を動的にローテーションできるようになりました。複数の鍵を設定でき、新しいチケットはリストの最初の鍵で暗号化され、既存のチケットはリスト内のいずれかの鍵で復号されます。
    *   **技術的影響**: サーバー管理者は、セッションチケット鍵を定期的に更新することで、前方秘匿性を維持し、セキュリティを向上させることができます。これにより、鍵の漏洩が発生した場合でも、影響を受けるセッションの範囲を限定することが可能になります。

4.  **`crypto/tls: servers will now always call GetCertificate to pick a certificate for a connection when Certificates is empty (https://golang.org/cl/8792)`**
    *   **背景**: 従来のGoの `crypto/tls` サーバーでは、`tls.Config` の `Certificates` フィールドが空の場合、かつクライアントがSNI (Server Name Indication) を送信しない場合、`GetCertificate` コールバック関数が呼び出されず、証明書を提供できないためにハンドシェイクが失敗することがありました。これは、動的に証明書をロードするサーバーの実装を複雑にしていました。
    *   **変更内容**: この変更 (CL 8792) により、`tls.Config.Certificates` が空である場合、クライアントがSNIを送信したかどうかにかかわらず、`GetCertificate` コールバックが常に呼び出されるようになりました。
    *   **技術的影響**: これにより、GoのTLSサーバーは、SNIをサポートしない古いクライアントに対しても、完全に動的な証明書選択ロジックを適用できるようになりました。例えば、証明書をデータベースや外部サービスからオンデマンドで取得するような、より柔軟なサーバー構成が可能になります。

5.  **`crypto/x509: unknown critical extensions now cause errors in Verify, not when parsing (https://golang.org/cl/9390)`**
    *   **背景**: X.509証明書には、標準で定義されていない「拡張」を含めることができます。これらの拡張には「critical (クリティカル)」とマークされたものがあり、これはその拡張を理解できない場合、証明書を無効と見なすべきであることを示します。以前のGoの実装では、`ParseCertificate` 関数が未知のクリティカル拡張に遭遇すると、その時点でエラーを返していました。
    *   **変更内容**: この変更 (CL 9390) により、`ParseCertificate` は未知のクリティカル拡張があってもエラーを返さず、その拡張のOID (Object Identifier) を `Certificate` 構造体の新しいフィールド `UnknownCriticalExtensions` に記録するようになりました。そして、証明書の検証を行う `Verify` 関数が、この `UnknownCriticalExtensions` フィールドが空でない場合にエラーを返すようになりました。
    *   **技術的影響**: この変更は、証明書のパースと検証の役割を明確に分離します。パース段階では、未知のクリティカル拡張があっても証明書の基本的な構造を読み取れるようになり、例えばSNIなどの情報を抽出できるようになります。セキュリティ上の判断（クリティカル拡張の理解）は、より厳密な検証段階に委ねられるため、柔軟性とセキュリティのバランスが改善されました。

## コアとなるコードの解説

追加された各行は、Go 1.5 で導入された `crypto` パッケージ群の重要な改善点を簡潔に説明しています。これらは、Goのリリースノートの一部として、開発者がGo 1.5にアップグレードする際に知っておくべき主要な変更点、特にセキュリティと関連する機能強化を強調しています。

*   **`crypto/elliptic: Unmarshaling points now automatically checks that the point is on the curve`**: 楕円曲線暗号のセキュリティを向上させるための重要な変更であり、開発者が手動で検証を行う手間を省き、より安全なコードを書きやすくします。
*   **`crypto/tls: including Certificate Transparency SCTs in the handshake is now supported`**: ウェブの信頼性向上に貢献するCertificate TransparencyのサポートがGoのTLS実装に組み込まれたことを示します。これにより、Goアプリケーションはよりセキュアな通信を行うための基盤を得ます。
*   **`crypto/tls: session ticket keys can now be rotated at runtime`**: TLSセッションのセキュリティ（特に前方秘匿性）を強化するための機能追加です。サーバー運用者が鍵管理をより柔軟に行えるようになり、セキュリティリスクを低減できます。
*   **`crypto/tls: servers will now always call GetCertificate to pick a certificate for a connection when Certificates is empty`**: TLSサーバーにおける証明書選択の柔軟性を大幅に向上させる変更です。動的な証明書プロビジョニングをより容易にし、様々なデプロイメントシナリオに対応できるようになります。
*   **`crypto/x509: unknown critical extensions now cause errors in Verify, not when parsing`**: X.509証明書の処理における堅牢性と柔軟性のバランスを改善する変更です。証明書のパースと検証の役割を明確にすることで、開発者がより制御された方法で証明書を扱えるようになります。

これらの記述は、Go 1.5 が単なる機能追加だけでなく、基盤となるセキュリティコンポーネントの強化にも注力していることを示しており、Go言語が安全なシステム構築のための信頼できる選択肢であることを再確認させます。
