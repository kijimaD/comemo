## 元コミット内容

Goランタイムの`memmove`関数は、PowerPC 64ビット (ppc64) およびPowerPC 64ビット Little Endian (ppc64le) アーキテクチャにおいて、特に32バイト以上のメモリ移動のパフォーマンスを向上させます。さらに、ソースとデスティネーションが異なる種類のストレージにある場合に、非効率な後方移動を避けるための検出ロジックが強化されました。これにより、ベンチマークテストで最大3倍以上の性能向上が確認されています。

## 変更の背景

`memmove`は、メモリブロックをコピーするための基本的な操作であり、Goランタイムの様々な部分で頻繁に使用されます。特に、ガベージコレクション、スライス操作、チャネル通信など、メモリを大量に扱う処理において、`memmove`の効率は全体のパフォーマンスに大きく影響します。

PowerPC 64ビットアーキテクチャは、その設計上、特定のメモリ操作において最適化の余地がありました。特に、大きなメモリブロックを効率的に移動させるためには、プロセッサのキャッシュラインサイズやデータプリフェッチ機構を考慮したアセンブリコードレベルでの最適化が不可欠です。

このコミットの背景には、Go issue #14507 があります。このissueでは、ppc64le環境での`memmove`のパフォーマンスが他のアーキテクチャと比較して劣っていることが報告されており、特に大きなサイズのコピーで顕著でした。また、メモリのオーバーラップがある場合に、`memmove`はコピー元とコピー先の領域が重なっていても正しく動作するように設計されていますが、その実装方法によってはパフォーマンスが低下する可能性があります。特に、異なるストレージタイプ（例：スタックと静的領域）間で移動する際に、不必要な後方移動が発生することが問題視されていました。

このコミットは、これらの課題に対処し、GoプログラムがPowerPC 64ビット環境でより高速に動作するようにすることを目的としています。

## 前提知識の解説

*   **`memmove`関数**: C言語の標準ライブラリ関数の一つで、指定されたバイト数のメモリブロックをコピー元からコピー先へ移動させます。`memcpy`と異なり、コピー元とコピー先のメモリ領域が重なっていても正しく動作することが保証されています。これは、オーバーラップがある場合に、データが破壊されないようにコピーの方向（前方または後方）を適切に選択することで実現されます。
*   **PowerPC 64ビット (PPC64/PPC64LE) アーキテクチャ**: IBMが開発したRISCプロセッサアーキテクチャです。64ビットのレジスタとアドレス空間を持ち、高性能コンピューティングやエンタープライズシステムで利用されます。PPC64LEはLittle Endian版であり、Go言語は様々なアーキテクチャをサポートするため、それぞれのアーキテクチャに最適化されたランタイムコードを持っています。
*   **アセンブリ言語 (Assembly Language)**: プロセッサが直接実行できる機械語命令を人間が読める形式で記述した低レベル言語です。Goランタイムのようなパフォーマンスが重視される部分では、C言語やGo言語では実現できないような細かな最適化を行うためにアセンブリ言語が使用されます。
*   **キャッシュライン**: CPUがメモリからデータを読み込む際の最小単位です。通常、32バイトや64バイトといった固定サイズで、キャッシュライン単位でデータを扱うことでメモリ転送の効率が向上します。
*   **データプリフェッチ (Data Prefetching)**: CPUが将来必要になるであろうデータを予測し、事前にキャッシュに読み込んでおく技術です。これにより、CPUがデータが必要になったときにすぐに利用できるようになり、メモリレイテンシを隠蔽してパフォーマンスを向上させます。
*   **後方移動 (Backward Move)**: `memmove`において、コピー元とコピー先のメモリ領域がオーバーラップしており、かつコピー先アドレスがコピー元アドレスよりも小さい場合に、データの破壊を防ぐためにメモリブロックの末尾から先頭に向かってコピーを行う方式です。
*   **前方移動 (Forward Move)**: `memmove`において、コピー元とコピー先のメモリ領域がオーバーラップしていない場合、またはコピー先アドレスがコピー元アドレスよりも大きい場合に、メモリブロックの先頭から末尾に向かってコピーを行う方式です。

## 技術的詳細

このコミットは、`src/runtime/memmove_ppc64x.s`ファイル、すなわちPowerPC 64ビットアーキテクチャ向けのアセンブリ実装に焦点を当てています。主な変更点は以下の通りです。

1.  **32バイト単位の高速コピーパスの導入**:
    *   以前の実装では、主に8バイト（ダブルワード）単位でのコピーが中心でした。この変更では、32バイト単位でデータをロード・ストアする新しいパスが導入されています。
    *   `forward32setup`および`forward32`ラベルで示されるコードブロックがこれに該当します。ここでは、`MOVD`命令を連続して使用し、一度に4つのダブルワード（合計32バイト）をレジスタにロードし、その後、別の4つの`MOVD`命令でストアしています。
    *   これにより、ループのオーバーヘッドを削減し、より多くのデータを一度に処理することで、特に大きなメモリブロックのコピーにおいてスループットが向上します。
    *   `DCBTST (R3)`と`DCBT (R4)`命令が追加されており、これはデータキャッシュのプリフェッチを示唆しています。`DCBTST`はデータキャッシュブロックタッチ命令で、指定されたアドレスのデータがキャッシュに存在するかどうかをテストし、存在しない場合はプリフェッチを促すことがあります。`DCBT`はデータキャッシュブロックタッチ命令で、指定されたアドレスのデータブロックをキャッシュにプリフェッチするようプロセッサにヒントを与えます。これにより、メモリコピーに必要なデータが事前にキャッシュにロードされ、メモリアクセスの遅延が減少します。

2.  **後方移動検出ロジックの強化**:
    *   以前の`memmove`実装では、コピー元とコピー先のアドレスを比較するだけでオーバーラップを検出し、後方移動が必要かどうかを判断していました。しかし、ソースとデスティネーションが異なる種類のストレージ（例：スタックとヒープ、または異なるメモリ領域）にある場合、アドレスの単純な比較だけでは不適切な後方移動が選択される可能性がありました。
    *   新しいロジックでは、`SUB R4, R3, R8` (dest - src) と `CMPU R8, R5, CR2` (dest - src < len?) を使用してオーバーラップをより厳密に判定しています。`CMPU`は符号なし比較を行うため、アドレスの差分とコピーサイズを比較することで、実際のオーバーラップ状況を正確に把握できます。
    *   これにより、不必要な後方移動（特に異なるストレージタイプ間でオーバーラップがないにも関わらず後方移動が選択されるケース）を回避し、常に効率的な前方移動を選択できるようになります。後方移動は通常、前方移動よりも複雑なロジックを必要とし、パフォーマンスが低下する可能性があるため、これを避けることは重要です。

3.  **アセンブリコードの簡素化と効率化**:
    *   全体的に、レジスタの使用方法やループ構造が見直され、より効率的な命令シーケンスが採用されています。例えば、`MOVDU`（更新付きロード/ストア）命令の使用が減り、`ADD`命令でポインタを明示的に更新する形式が増えています。これは、特定のPowerPCプロセッサのマイクロアーキテクチャにおいて、更新付き命令よりも独立したロード/ストアとアドレス更新の方が効率的である場合があるためと考えられます。
    *   `RLDCLCC`命令（Rotate Left Doubleword then Clear Left and Compare）が導入され、残りのダブルワード数を効率的に計算しています。

これらの変更により、特に大きなメモリブロックのコピーにおいて、CPUのデータパスをより効率的に利用し、キャッシュミスを減らし、命令実行の並列性を高めることで、大幅なパフォーマンス向上が実現されています。

## コアとなるコードの解説

このアセンブリコードは、`runtime·memmove`関数のPowerPC 64ビット版の実装です。

1.  **初期設定とサイズ計算**:
    *   `MOVD to+0(FP), R3`, `MOVD from+8(FP), R4`, `MOVD n+16(FP), R5`：関数引数である`to`（コピー先アドレス）、`from`（コピー元アドレス）、`n`（コピーバイト数）をそれぞれレジスタ`R3`, `R4`, `R5`にロードします。
    *   `ANDCC $7, R5, R7`：コピーバイト数`R5`を8で割った余り（0-7バイト）を`R7`に格納します。これは、8バイト単位で処理できない残りのバイト数です。
    *   `SRAD $3, R5, R6`：コピーバイト数`R5`を8で割った商（ダブルワード数）を`R6`に格納します。
    *   `CMP R6, $0, CR1`：ダブルワード数`R6`が0かどうかを比較し、結果を条件レジスタ`CR1`に設定します。

2.  **オーバーラップ検出の強化**:
    *   `SUB R4, R3, R8`：コピー元アドレス`R4`からコピー先アドレス`R3`を引いた差分を`R8`に格納します（`dest - src`）。
    *   `CMPU R8, R5, CR2`：`R8`（アドレス差分）と`R5`（コピーバイト数）を符号なしで比較し、結果を`CR2`に設定します。`dest - src < len`の場合、オーバーラップがあり、後方移動が必要になる可能性があります。
    *   `BC 12, 8, backward`：`CR2`の比較結果に基づき、オーバーラップが検出された場合は`backward`ラベルに分岐します。これにより、異なるストレージタイプ間の不必要な後方移動が回避されます。

3.  **前方移動 (Forward Move) の最適化**:
    *   `BC 12, 6, noforwardlarge`：ダブルワード数`R6`が0の場合（`CR1`のEQビットがセットされている場合）、`noforwardlarge`に分岐し、バイト単位のコピーに進みます。
    *   `MOVD R6,CTR`：ダブルワード数`R6`をカウンタレジスタ`CTR`にロードします。
    *   `SRADCC $2,R6,R8`：`R6`を4で割った商（32バイトチャンク数）を`R8`に格納し、結果が0でなければ`forward32setup`に分岐します。これは、32バイト単位のコピーパスを使用するかどうかを決定します。
    *   **`forward32setup`**:
        *   `DCBTST (R3)`、`DCBT (R4)`：コピー先とコピー元のアドレスに対してデータキャッシュプリフェッチ命令を実行し、キャッシュミスを減らします。
        *   `MOVD R8, CTR`：32バイトチャンク数`R8`をカウンタレジスタ`CTR`にロードします。
    *   **`forward32`ループ**:
        *   `MOVD 0(R4), R8` ... `MOVD 24(R4), R15`：コピー元から32バイト（4つのダブルワード）を`R8`、`R9`、`R14`、`R15`レジスタにロードします。
        *   `ADD $32,R4`：コピー元ポインタ`R4`を32バイト進めます。
        *   `MOVD R8, 0(R3)` ... `MOVD R15, 24(R3)`：ロードした32バイトをコピー先にストアします。
        *   `ADD $32,R3`：コピー先ポインタ`R3`を32バイト進めます。
        *   `BC 16, 0, forward32`：`CTR`が0になるまでループを続けます。
    *   `RLDCLCC $61,R5,$3,R6`：残りのダブルワード数を計算し、`R6`に格納します。
    *   `BEQ noforwardlarge`：残りのダブルワードがなければ`noforwardlarge`に分岐します。
    *   `MOVD R6,CTR`、`BR forward8`：残りのダブルワードを8バイト単位でコピーするために`forward8`に分岐します。
    *   **`forward8`ループ**: 8バイト（ダブルワード）単位でメモリをコピーします。
    *   **`forwardtail`ループ**: 1バイト単位で残りのバイトをコピーします。

4.  **後方移動 (Backward Move) の処理**:
    *   `ADD R5, R4, R4`、`ADD R3, R5, R3`：コピー元とコピー先のポインタをブロックの末尾に移動させます。
    *   `backwardtailloop`：1バイト単位で末尾から先頭に向かってコピーします。
    *   `backwardlargeloop`：8バイト（ダブルワード）単位で末尾から先頭に向かってコピーします。

このコードは、PowerPCの命令セットを最大限に活用し、特に大きなメモリブロックのコピーにおいて、キャッシュ効率と命令のスループットを向上させるように設計されています。32バイト単位のコピーパスは、現代のプロセッサのキャッシュラインサイズに合わせた最適化であり、`DCBTST`/`DCBT`命令はデータプリフェッチを促すことで、メモリレイテンシを隠蔽します。
