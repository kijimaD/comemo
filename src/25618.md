# [インデックス 25618] ファイルの概要

このコミットは、Goプロジェクトの`AUTHORS`ファイルと`CONTRIBUTORS`ファイルにおける、貢献者のメールアドレスの記述方法に関する説明を明確化し、書式を統一することを目的としています。特に、複数のメールアドレスを扱う場合の記述方法を詳細に定義し、コードレビューシステムがRietveldからGerritへ移行したことを反映する変更が含まれています。

## コミット

Goプロジェクトの`AUTHORS`および`CONTRIBUTORS`ファイルにおけるメールアドレスの記述に関する説明を修正し、複数のメールアドレスの形式を明示的に列挙しました。`AUTHORS`ファイルでは、複数のメールアドレスの定義について`CONTRIBUTORS`ファイルを参照するように変更し、インデントをタブから4スペースに統一しました。また、`CONTRIBUTORS`ファイル内の「Rietveld」への言及を「Gerrit」に更新しました。さらに、`AUTHORS`ファイル内のSebastien Binet氏のエントリにおけるタブ区切りをスペース区切りに修正しました。

## 変更の背景

このコミットは、主に以下の2つの背景に基づいています。

1.  **貢献者情報の明確化と統一**: オープンソースプロジェクトにおいて、貢献者のリスト（`AUTHORS`および`CONTRIBUTORS`ファイル）は、プロジェクトへの貢献を記録し、著作権帰属を明確にする上で重要な役割を果たします。しかし、複数のメールアドレスを持つ貢献者や、組織としての貢献など、多様なケースに対応するためには、その記述形式を明確に定義し、統一する必要があります。このコミットは、特に複数のメールアドレスの扱いについて、より詳細な説明を導入することで、この点の曖昧さを解消しようとしています。
2.  **コードレビューシステムの移行**: Goプロジェクトは、かつてRietveldというコードレビューシステムを使用していましたが、このコミットが作成された2015年頃には、より新しいGerritというシステムへの移行が進んでいました。`CONTRIBUTORS`ファイル内のRietveldへの言及をGerritに更新することは、プロジェクトのインフラストラクチャの変更をドキュメントに反映させ、最新の状態に保つための重要な更新でした。
3.  **書式の一貫性**: `AUTHORS`ファイルと`CONTRIBUTORS`ファイルの間でインデントのスタイル（タブとスペース）が異なっていたこと、および特定の貢献者のエントリで不適切なタブが使用されていたことは、ドキュメント全体の品質と一貫性を損なうものでした。このコミットは、これらの書式上の不整合を修正し、プロジェクト全体のコーディングスタイルガイドラインへの準拠を強化しています。

## 前提知識の解説

### `AUTHORS`ファイルと`CONTRIBUTORS`ファイル

オープンソースプロジェクトでは、プロジェクトに貢献した人々や組織を記録するために、慣習的に`AUTHORS`ファイルと`CONTRIBUTORS`ファイルが使用されます。

*   **`AUTHORS`ファイル**: 主にプロジェクトの主要な作者や著作権保持者をリストアップするために用いられます。プロジェクトのライセンスが「The [Project Name] Authors」のような形で著作権者を指す場合、このファイルがその参照先となることがあります。
*   **`CONTRIBUTORS`ファイル**: プロジェクトに何らかの形で貢献したすべての個人や組織をリストアップするために用いられます。これには、コードの寄稿者だけでなく、ドキュメントの作成者、バグ報告者、テスターなども含まれることがあります。

Goプロジェクトでは、このコミットが作成された時点ではこれらのファイルが積極的に維持されていましたが、2022年以降、Goプロジェクトは`git log`が著作権および作者情報の正式な情報源であると判断し、これらのファイルを削除しています。しかし、このコミットの時点では、これらのファイルは重要な役割を担っていました。

### RietveldとGerrit

これらは、コードレビューを支援するためのウェブベースのツールです。

*   **Rietveld**: GoogleのGuido van Rossumによって作成された、Subversion用のオープンソースのコードレビューツールです。Googleの内部ツールであるMondrianに基づいており、Google App Engine上で動作していました。GoプロジェクトもかつてはRietveldを使用してコードレビューを行っていました。Rietveldは主にレビューを助言するものであり、提出前のピアレビューを強制するものではありませんでした。
*   **Gerrit**: Rietveldから派生した、Git用のウェブベースのコードレビューシステムです。RietveldがPythonベースであったのに対し、GerritはJavaで完全に書き直され、J2EEサーブレットコンテナとSQLデータベース上で動作します。Gerritは、Goプロジェクトを含む多くのプロジェクトで広く採用されており、サイドバイサイドの差分表示、インラインコメント、`Code-Review+2`のようなラベルによる承認プロセス、`Change-Id`による変更追跡など、より構造化されたレビュープロセスを強制します。GoプロジェクトはRietveldからGerritへ移行し、現在ではGerritがGoのコードレビューの標準ツールとなっています。

### 複数のメールアドレスの扱い

オープンソースの貢献者の中には、複数のメールアドレス（例：個人のメールアドレスと職場のメールアドレス、あるいは異なるオンラインアイデンティティに関連するメールアドレス）を持つ人がいます。プロジェクトがこれらの異なるアドレスを同じ人物として認識し、適切にクレジットを付与するためには、これらのアドレスをどのように記録し、関連付けるかを明確にする必要があります。特に、コードレビューシステム（RietveldやGerrit）が、コミットログの作者情報と、レビューシステム上のユーザーアカウントを紐付ける際に、この情報が重要になります。

## 技術的詳細

このコミットの技術的詳細は、主にドキュメントの正確性、一貫性、およびプロジェクトのインフラストラクチャの変更への対応に焦点を当てています。

1.  **メールアドレス記述の明確化**:
    *   `AUTHORS`ファイルでは、貢献者のエントリ形式として「Organization's name」、「Individual's name <submission email address>」、「Individual's name <submission email address> <email2> <emailN>」の3つの形式を明示的に列挙しました。これにより、単一のメールアドレスだけでなく、複数のメールアドレスを持つ貢献者も適切に記述できるようになりました。
    *   `AUTHORS`ファイルは、複数のメールアドレスの意味について`CONTRIBUTORS`ファイルを参照するように変更されました。これは、情報の重複を避け、一貫した定義を維持するための良いプラクティスです。
    *   `CONTRIBUTORS`ファイルでは、「An entry with two email addresses specifies that the first address should be used in the submit logs and that the second address should be recognized as the same person when interacting with Rietveld.」という記述が、「An entry with multiple email addresses specifies that the first address should be used in the submit logs and that the other addresses should be recognized as the same person when interacting with Gerrit.」に変更されました。これにより、複数のメールアドレスの目的がより一般化され、かつコードレビューシステムがRietveldからGerritへ移行したことが反映されました。

2.  **インデントの統一**:
    *   `AUTHORS`ファイル内のインデントが、タブから4スペースに変更されました。これは、`CONTRIBUTORS`ファイルが既に4スペースを使用していたため、両ファイル間の書式の一貫性を確保するための変更です。オープンソースプロジェクトでは、タブとスペースのどちらを使用するか、またその数について厳格なコーディングスタイルガイドラインを持つことが一般的であり、この変更はそのようなガイドラインへの準拠を強化するものです。
    *   Sebastien Binet氏のエントリにおける名前とメールアドレス間の区切り文字が、タブからスペースに変更されました。これは、特定の行における書式上の不整合を修正し、ファイル全体の統一された書式を維持するための細かな修正です。

3.  **RietveldからGerritへの移行の反映**:
    *   `CONTRIBUTORS`ファイル内のコードレビューシステムへの言及が「Rietveld」から「Gerrit」に変更されました。これは、GoプロジェクトがコードレビューにRietveldではなくGerritを使用するようになったという、プロジェクトのインフラストラクチャにおける重要な変更を反映するものです。この変更は、ドキュメントがプロジェクトの現在の技術スタックと一致していることを保証するために不可欠です。

これらの変更は、Goプロジェクトのドキュメントの正確性、保守性、および貢献者体験の向上に貢献します。

## コアとなるコードの解説

### `AUTHORS`ファイルへの変更

*   **メールアドレス記述の明確化**:
    *   変更前:
        ```
        # Names should be added to this file as
        #	Name or Organization <email address>
        # The email address is not required for organizations.
        ```
        この記述では、単一のメールアドレス形式しか示されておらず、インデントもタブ（`\t`）が使用されていました。
    *   変更後:
        ```
        # Names should be added to this file as one of
        #     Organization's name
        #     Individual's name <submission email address>
        #     Individual's name <submission email address> <email2> <emailN>
        # See CONTRIBUTORS for the meaning of multiple email addresses.
        ```
        新しい記述では、組織名のみ、単一のメールアドレス、そして複数のメールアドレスを持つ個人の3つの形式が明示的に列挙されています。これにより、貢献者の多様な状況に対応できるようになりました。また、インデントが4スペースに統一され、書式の一貫性が向上しています。さらに、複数のメールアドレスの意味については`CONTRIBUTORS`ファイルを参照するように指示することで、情報の重複を避け、一元的な定義を促しています。

*   **Sebastien Binet氏のエントリの修正**:
    *   変更前: `Sebastien Binet	<seb.binet@gmail.com>`
    *   変更後: `Sebastien Binet <seb.binet@gmail.com>`
    名前とメールアドレスの間の区切り文字がタブからスペースに変更されました。これは、ファイル全体の書式規則に合わせるための修正であり、視覚的な一貫性を保つ上で重要です。

### `CONTRIBUTORS`ファイルへの変更

*   **メールアドレス記述の明確化とGerritへの言及**:
    *   変更前:
        ```
        # Names should be added to this file like so:
        #     Name <email address>
        #
        # An entry with two email addresses specifies that the
        # first address should be used in the submit logs and
        # that the second address should be recognized as the
        # same person when interacting with Rietveld.
        ```
        この記述では、単一のメールアドレス形式しか示されておらず、複数のメールアドレスの例は2つに限定され、コードレビューシステムとしてRietveldが言及されていました。
    *   変更後:
        ```
        # Names should be added to this file like so:
        #     Individual's name <submission email address>
        #     Individual's name <submission email address> <email2> <emailN>
        #
        # An entry with multiple email addresses specifies that the
        # first address should be used in the submit logs and
        # that the other addresses should be recognized as the
        # same person when interacting with Gerrit.
        ```
        新しい記述では、単一のメールアドレスと複数のメールアドレスの形式が明確に示されています。特に、「<email2> <emailN>」という表記により、2つ以上のメールアドレスを記述できることが示唆されています。最も重要な変更点は、コードレビューシステムへの言及が「Rietveld」から「Gerrit」に更新されたことです。これは、GoプロジェクトがRietveldからGerritへ移行したというインフラストラクチャの変更をドキュメントに反映させたものであり、ドキュメントの正確性を保つ上で不可欠な修正です。また、「two email addresses」が「multiple email addresses」に変更されたことで、より一般的なケースに対応できるようになりました。

これらの変更は、Goプロジェクトの貢献者ドキュメントの品質を向上させ、プロジェクトの進化に合わせて情報を最新の状態に保つための細心の注意を払ったものです。
