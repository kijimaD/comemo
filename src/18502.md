# [インデックス 18502] ファイルの概要

このコミットは、Go言語のランタイムがPlan 9オペレーティングシステム上で動作するための`lib9`ライブラリのサポートを有効にするためのものです。具体的には、Plan 9固有のヘッダーファイルの追加、ビルドプロセスの調整、そして既存の`lib9`ソースコードに対するGoのビルドタグの適用を通じて、GoがPlan 9のネイティブ環境により適合するように変更を加えています。

## 変更の背景

Go言語は、その設計思想の一部にPlan 9オペレーティングシステムの影響を強く受けています。Plan 9は、ベル研究所で開発された分散オペレーティングシステムであり、Go言語の共同開発者であるRob PikeやKen Thompsonもその開発に携わっていました。Go言語が初期から様々なプラットフォームをサポートする中で、Plan 9上でのネイティブな動作サポートは自然な流れでした。

このコミットの背景には、Goの標準ライブラリやランタイムがPlan 9のシステムコールやAPIと適切に連携できるようにするための継続的な取り組みがあります。特に、`lib9`はPlan 9のCライブラリのAPIを他のシステム（例えばUnix系OS上のPlan 9 Port）でエミュレートするために使われていましたが、この変更はGoが**実際のPlan 9環境**でビルドされる際に、そのネイティブな`libc`（C標準ライブラリ）と適切に連携し、不要なエミュレーションコードを排除することを目的としています。

コミットメッセージにある「This change depends on CL 57170052」は、この変更が先行する別の変更リスト（Change List）に依存していることを示しています。CL 57170052は、GoのビルドシステムにおけるPlan 9のサポートを改善し、特に`src/cmd/dist/build.c`におけるPlan 9固有のビルドロジックを調整するものでした。この依存関係により、本コミットはよりスムーズにPlan 9上での`lib9`の有効化を進めることができました。

## 前提知識の解説

*   **Plan 9 from Bell Labs**: ベル研究所で開発された分散オペレーティングシステム。ファイルシステム中心の設計、UTF-8の採用、独自のCコンパイラツールチェイン（8c/6c/5cなど）と標準ライブラリ（`libc`）が特徴です。Go言語の設計思想に大きな影響を与えました。
*   **Plan 9 Port (Plan 9 from User Space)**: Plan 9のツールやライブラリをUnix系オペレーティングシステム上で利用できるようにするプロジェクト。`lib9`は、このプロジェクトの一部として、Plan 9のAPIをUnix環境で提供するために使われることが多かったです。
*   **`lib9`**: Go言語のソースツリー内にあるC言語のライブラリ群。Plan 9のシステムコールやユーティリティ関数をGoのランタイムやツールが利用できるようにするためのラッパーや実装を含んでいます。GoがPlan 9以外のOSで動作する際に、Plan 9のセマンティクスをエミュレートするためにも使われます。
*   **Go Build Tags (`// +build`)**: Goのソースファイルに記述される特殊なコメント行で、ファイルのコンパイル条件を指定します。例えば、`// +build linux`はLinuxでのみコンパイルされ、`// +build !windows`はWindows以外でコンパイルされることを意味します。これにより、OSやアーキテクチャに応じた条件付きコンパイルが可能です。
*   **`pragma varargck`**: Plan 9のCコンパイラ（8c/6c/5c）が提供する`pragma`ディレクティブの一つ。可変引数関数（`printf`のような関数）の引数の型チェックを強化するために使用されます。これにより、コンパイル時に型ミスマッチなどの潜在的なバグを検出できます。
*   **`rc`スクリプト**: Plan 9の標準シェルである`rc`で記述されたスクリプト。Unixのシェルスクリプトに似ていますが、構文や機能に違いがあります。

## 技術的詳細

このコミットの主要な目的は、Goの`lib9`がPlan 9上でネイティブに動作するように適応させることです。これまでの`lib9`は、主にPlan 9以外のシステムでPlan 9のAPIをエミュレートするために使われていましたが、この変更により、GoがPlan 9自体でビルドされる際に、Plan 9のネイティブなCライブラリと共存し、またはその機能を利用するように調整されます。

具体的な変更点は以下の通りです。

1.  **Plan 9固有のヘッダーファイルの導入と調整**:
    *   `include/plan9/errno.h`、`include/plan9/fmt.h`、`include/plan9/stdarg.h`、`include/plan9/utf.h`といった新しいヘッダーファイルが`include/plan9/`ディレクトリに追加されています。これらはPlan 9のCライブラリの対応するヘッダーから必要な定義をGoのビルドシステムに取り込むためのものです。
    *   特に`fmt.h`には、Plan 9のCコンパイラが可変引数関数の型チェックを行うための`#pragma varargck`ディレクティブが多数含まれています。これは、GoのランタイムがC言語で書かれた部分で、Plan 9のコンパイラによる厳密な型チェックの恩恵を受けることを可能にします。
    *   `include/plan9/libc.h`が修正され、新しく追加された`fmt.h`と`utf.h`、そして後述する`libc_plan9.h`をインクルードするようになりました。また、`HUGE_VAL`のような数学定数も定義されています。

2.  **`libc_plan9.h`の生成**:
    *   `include/plan9/mklibc.rc`という新しい`rc`スクリプトが追加されました。このスクリプトは`sed`コマンドを使用して、Plan 9システムの標準Cライブラリヘッダーである`/sys/include/libc.h`から特定の定義（`umuldiv`, `UTFmax`, `Runesync`など）を削除し、その結果を`include/plan9/libc_plan9.h`として出力します。
    *   この生成プロセスは、`src/make.rc`（Goのビルドスクリプト）に組み込まれました。これにより、Goのビルド時にPlan 9のネイティブ`libc.h`からGoのビルドに適した形式のヘッダーが自動的に生成されるようになります。これは、GoのCコードがPlan 9の`libc`と互換性を持つようにするための重要なステップです。

3.  **Goビルドタグによる条件付きコンパイルの導入**:
    *   `src/lib9/`ディレクトリ内のほとんどのCソースファイル（例: `_exits.c`, `atoi.c`, `create.c`など）に`// +build !plan9`というビルドタグが追加されました。これは、これらのファイルがPlan 9以外のOSでGoをビルドする際にのみコンパイルされることを意味します。
    *   一方で、`src/lib9/run_plan9.c`と`src/lib9/tempdir_plan9.c`には`// +build plan9`タグが追加されました。これは、これらのファイルがPlan 9上でGoをビルドする際にのみコンパイルされることを意味します。
    *   この変更により、Goのビルドシステムは、ターゲットがPlan 9であるかどうかに応じて、`lib9`の実装を動的に切り替えることができるようになりました。Plan 9以外のシステムではPlan 9のAPIをエミュレートする`lib9`のコードが使われ、Plan 9上ではネイティブなPlan 9の機能を利用する（またはPlan 9固有の）コードが使われるようになります。

4.  **ビルドプロセスの調整 (`src/cmd/dist/build.c`)**:
    *   `src/cmd/dist/build.c`内の`install`関数において、`lib9`ディレクトリに対する`-DPLAN9PORT`コンパイルフラグの追加ロジックが移動されました。これにより、`PLAN9PORT`マクロの定義がより適切に制御されるようになります。
    *   最も重要な変更は、`shouldbuild`関数からPlan 9固有の`lib9`ビルドロジックが削除されたことです。以前は、Plan 9上では`lib9`の特定のファイル（`goos.c`, `flag.c`など）のみをビルドし、それ以外のファイルはシステムに既に存在すると仮定してスキップしていました。このロジックが削除されたことで、Goのビルドシステムは、前述のビルドタグに基づいて、Plan 9上でも`lib9`のソースファイルをより細かく制御してコンパイルするようになりました。これは、GoがPlan 9のシステムライブラリへの依存を減らし、より自己完結的にビルドされる方向への一歩です。

5.  **`src/libbio/bprint.c`の変更**:
    *   `Bvprint`関数内の`fmtlocaleinit`呼び出しを囲んでいた`#ifndef PLAN9`プリプロセッサディレクティブが削除されました。これは、`fmtlocaleinit`がPlan 9上でも問題なく動作するか、またはその機能がPlan 9ビルドにおいて常に必要とされるようになったことを示唆しています。

これらの変更は、GoがPlan 9上でより堅牢かつ効率的に動作するための基盤を築くものです。

## コアとなるコードの解説

### `include/plan9/fmt.h` (新規追加)

```c
// Copyright 2014 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

#include "../fmt.h"

#pragma	varargck	argpos	fmtprint	2
#pragma	varargck	argpos	fprint		2
// ... (他の可変引数関数に対する #pragma varargck ディレクティブ)
#pragma	varargck	type	"lld"	vlong
// ... (他の型に対する #pragma varargck type ディレクティブ)
#pragma	varargck	flag	','
#pragma	varargck	flag	' '
#pragma	varargck	flag	'h'
#pragma	varargck	type	"<"	void*
#pragma	varargck	type	"["	void*
#pragma	varargck	type	"H"	void*
#pragma	varargck	type	"lH"	void*
```
このファイルは、Plan 9のCコンパイラがGoのランタイム内で使用される`fmt`（フォーマット）関連の関数（`print`, `fprint`など）の引数を厳密に型チェックするための`#pragma varargck`ディレクティブを含んでいます。これにより、コンパイル時にフォーマット文字列と引数の不一致といった一般的なバグを早期に発見できます。これはPlan 9のC開発環境の慣習に合わせたもので、GoのCコードの品質と堅牢性を高めます。

### `include/plan9/mklibc.rc` (新規追加)

```rc
#!/bin/rc

pattern='/umuldiv/d
	/UTFmax/d
	/Runesync/d
	/Runeself/d
	/Runeerror/d
	/Runemax/d
	/rune routines/,/^\\/\\*/d
	/print routines/,/^\\/\\*/d
	/error string for/,/^\\/\\*/d'

sed -e $pattern /sys/include/libc.h
```
この`rc`スクリプトは、Plan 9のシステムヘッダー`/sys/include/libc.h`を`sed`コマンドで処理し、特定の行（`umuldiv`、`UTFmax`などの定義や、コメントブロック）を削除します。この処理の目的は、Goのビルドシステムが利用する`libc_plan9.h`を生成することです。GoのCコードがPlan 9のネイティブ`libc`と連携する際に、Goのビルドプロセスと競合したり、不要な定義を含んだりしないように調整するために使われます。
