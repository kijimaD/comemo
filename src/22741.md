## 元コミット内容

このコミットの目的は、GoのCgo機能において、Windows環境での共有ライブラリ（DLL）からのグローバル変数のエクスポートとインポートに関する既知の問題（Issue 4339）が修正されたことを検証するためのテストを追加することです。

## 変更の背景

Go言語のCgoは、GoプログラムからC言語のコードを呼び出したり、その逆を行ったりするためのメカニズムを提供します。特にWindows環境では、共有ライブラリ（DLL）を介してCコードとGoコードが連携する際に、グローバル変数の可視性やリンケージに関する特有の問題が発生することがあります。

コミットメッセージに記載されている「issue 4339」の具体的な内容は、一般的なWeb検索では見つかりませんでしたが、コミットに含まれるコード変更から、この問題がCgoとWindows DLLにおけるグローバル変数のエクスポート/インポートの不具合に関連していると推測されます。WindowsのDLLでは、変数をエクスポートする側（DLLをビルドする側）は`__declspec(dllexport)`を、インポートする側（DLLを使用する側）は`__declspec(dllimport)`を使用する必要があります。このコミットは、これらのメカニズムがCgoを介して正しく機能することを確認するためのテストを追加しています。

## 前提知識の解説

*   **Cgo**: Go言語とC言語の相互運用を可能にするGoの機能です。GoプログラムからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。
*   **共有ライブラリ（DLL/Shared Object）**: 複数のプログラムから共有して利用できるライブラリです。WindowsではDLL（Dynamic Link Library）、LinuxではShared Object（.so）、macOSではDynamic Library（.dylib）と呼ばれます。
*   **`__declspec(dllexport)`と`__declspec(dllimport)`**: Microsoft Visual C++などのコンパイラで使用されるキーワードで、Windows DLLにおいて関数や変数をエクスポート（外部に公開）またはインポート（外部から利用）するために使用されます。
    *   `__declspec(dllexport)`: DLLからシンボル（関数や変数）をエクスポートすることをコンパイラに指示します。
    *   `__declspec(dllimport)`: 別のDLLからシンボルをインポートすることをコンパイラに指示します。これにより、リンカはシンボルがDLL内に存在することを知り、適切なコードを生成します。
*   **グローバル変数**: プログラムのどこからでもアクセスできる変数です。共有ライブラリを介してグローバル変数を共有する場合、その可視性とリンケージは特に重要になります。
*   **`#cgo` ディレクティブ**: Goのソースファイル内でCgoにCコンパイラやリンカへのオプションを渡すために使用されます。例えば、`-D`オプションでプリプロセッサマクロを定義したり、`-L`や`-l`でライブラリのパスや名前を指定したりします。

## 技術的詳細

このコミットは、Cgoテストスイートに新しいテストケースを追加することで、Windows環境でのDLLからのグローバル変数アクセスが正しく行われることを検証しています。

主な変更点は以下の通りです。

1.  **`cgoso_c.h` の追加**:
    *   この新しいヘッダーファイルは、Windows環境でのDLLのエクスポート/インポートメカニズムを抽象化するためのマクロ`VAR`を定義しています。
    *   `EXPORT_DLL`が定義されている場合は`__declspec(dllexport)`に、`IMPORT_DLL`が定義されている場合は`__declspec(dllimport)`に展開されます。
    *   これにより、Cコードで定義されるグローバル変数`exported_var`が、DLLとしてビルドされる際にはエクスポートされ、DLLを使用する側からはインポートされるように宣言されます。
2.  **`cgoso_c.c` の変更**:
    *   `cgoso_c.h`をインクルードし、`const char *exported_var = "Hello world";`というグローバル変数を定義しています。この変数は`VAR`マクロによって適切にエクスポートされるようになります。
3.  **`cgoso.c` の変更**:
    *   `cgoso_c.h`をインクルードし、`getVar()`というC関数を追加しています。この関数は、`exported_var`の値を返します。
4.  **`cgoso.go` の変更**:
    *   `#cgo windows CFLAGS: -DIMPORT_DLL` を追加し、GoコードがDLLをインポートする際に`IMPORT_DLL`マクロが定義されるようにしています。
    *   `const char* getVar(void);` をCgoのインポート宣言に追加し、Cの`getVar`関数をGoから呼び出せるようにしています。
    *   `testExportedVar()`という新しいGo関数を追加しています。この関数は、Cの`getVar()`関数を呼び出して`exported_var`の値を取得し、期待される値（"Hello world"）と比較することで、グローバル変数のアクセスが正しく行われることを検証します。また、`C.exported_var`として直接GoからCのグローバル変数にアクセスできることも検証しています。
5.  **`test.bat` の変更**:
    *   `gcc -c cgoso_c.c -DEXPORT_DLL` に変更され、`cgoso_c.c`をコンパイルする際に`EXPORT_DLL`マクロが定義されるようにしています。これにより、`exported_var`がDLLからエクスポートされるようになります。

これらの変更により、Windows環境でCgoを使用してDLLを介してグローバル変数を共有する際の、エクスポートとインポートのメカニズムが正しく機能するかどうかが自動テストで検証されるようになります。

## コアとなるコードの解説

このコミットの核となるのは、Windows DLLにおけるグローバル変数のエクスポートとインポートのメカニズムをCgoテストスイートに組み込むことです。

*   **`cgoso_c.h`**: このヘッダーファイルは、Windows特有の`__declspec(dllexport)`と`__declspec(dllimport)`を抽象化する`VAR`マクロを導入しています。これにより、Cコード側で`VAR const char *exported_var;`と宣言するだけで、コンパイル時に`EXPORT_DLL`が定義されていればエクスポート、`IMPORT_DLL`が定義されていればインポートとして扱われるようになります。これはクロスプラットフォーム対応やコードの簡潔化に寄与します。
*   **`cgoso_c.c`**: ここで実際にグローバル変数`exported_var`が定義され、初期化されます。`cgoso_c.h`をインクルードすることで、`VAR`マクロが適用され、この変数がDLLからエクスポートされる準備が整います。
*   **`cgoso.c`**: `getVar()`関数が追加され、エクスポートされた`exported_var`の値を返すシンプルなCのラッパー関数として機能します。これは、GoからCのグローバル変数にアクセスする際の一つの方法を提供します。
*   **`cgoso.go`**:
    *   `#cgo windows CFLAGS: -DIMPORT_DLL`は非常に重要です。GoプログラムがCgoを介してDLLをコンパイルする際に、`IMPORT_DLL`マクロを定義するように指示します。これにより、Go側からCのグローバル変数や関数を参照する際に、`__declspec(dllimport)`が適用され、正しくシンボルが解決されるようになります。
    *   `testExportedVar()`関数は、GoからCのグローバル変数にアクセスする2つの方法をテストしています。
        1.  `C.GoString(C.getVar())`: Cのラッパー関数`getVar()`を介してグローバル変数の値を取得します。
        2.  `C.GoString(C.exported_var)`: GoからCのグローバル変数`exported_var`に直接アクセスします。
        これらのテストは、どちらの方法でも期待される値（"Hello world"）が取得できることを検証し、CgoがWindows DLLのグローバル変数アクセスを正しく処理できることを確認します。
*   **`test.bat`**: `gcc -c cgoso_c.c -DEXPORT_DLL`の変更は、`cgoso_c.c`をコンパイルする際に`EXPORT_DLL`マクロを定義し、`exported_var`がDLLからエクスポートされるようにするためのものです。これにより、DLLが正しくビルドされ、Goプログラムから利用できるようになります。

これらの変更は、GoのCgoがWindows環境でDLLを扱う際の堅牢性を高め、特にグローバル変数の共有に関する潜在的な問題を解決するための重要なステップです。
