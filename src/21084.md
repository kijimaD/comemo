# [インデックス 21084] ファイルの概要

このコミットは、Go言語の初期のコンパイラである`9g`（PowerPC 64-bitアーキテクチャ向け）における`proginfo`関数の修正に関するものです。特に、レジスタの使用状況の追跡と、`DUFFZERO`および`DUFFCOPY`といった最適化されたメモリ操作ルーチンに関する情報伝達の改善に焦点を当てています。

## 変更の背景

このコミットは、Go言語の初期のコンパイラである`9g`（PowerPC 64-bitアーキテクチャ向け）の`proginfo`関数におけるレジスタ使用情報の追跡の正確性を向上させることを目的としています。

主な背景は以下の2点です。

1.  **`D_OREG`アドレスのレジスタ情報の誤った分類**: 以前の`proginfo`関数では、`D_OREG`（オフセットレジスタ）タイプのアドレス指定で使用されるレジスタを、汎用的なレジスタ使用情報（`reguse`）として記録していました。しかし、これらのレジスタはアドレス計算の一部として使用されるため、より適切にはアドレス指定に関連するレジスタインデックス（`regindex`）として扱われるべきでした。この誤った分類は、コンパイラのレジスタ割り当てや最適化の判断に影響を与える可能性がありました。
2.  **`DUFFZERO`/`DUFFCOPY`のレジスタ使用情報の欠落**: `DUFFZERO`と`DUFFCOPY`は、Goランタイムにおいてメモリのゼロクリアやコピーを高速に行うための特殊なアセンブリルーチンです。これらはDuff's Deviceに似た手法を用いてループアンローリングを効率的に行いますが、その実装では特定のレジスタ（R0, R2, R3など）を暗黙的に使用・設定します。しかし、`proginfo`関数ではこれらの暗黙的なレジスタの使用・設定が適切に記録されていませんでした。これにより、コンパイラがこれらのルーチンを呼び出す際に、レジスタの衝突や誤った最適化が発生するリスクがありました。

このコミットは、これらの問題を修正し、コンパイラがより正確なレジスタ使用情報を持ち、結果としてより効率的で正しいコードを生成できるようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **Goコンパイラ (9g)**:
    *   Go言語の初期のコンパイラ群は、ターゲットアーキテクチャに応じて`6g` (amd64), `8g` (386), `9g` (PowerPC 64-bit) などと呼ばれていました。これらはC言語で書かれていました。
    *   Go 1.5以降、Goコンパイラ自体がGo言語で書かれるようになり（ブートストラッピング）、現在の公式コンパイラは一般的に`gc`と呼ばれます。
    *   `9g`は、PowerPC 64-bitアーキテクチャ向けのGoコンパイラであり、このコミットが作成された2014年時点ではまだC言語で実装されていました。
2.  **`proginfo`関数**:
    *   コンパイラのバックエンドにおいて、個々のアセンブリ命令（`Prog`）に関する詳細な情報を収集する役割を持つ関数です。
    *   この情報は、レジスタ割り当て、データフロー解析、最適化など、コンパイラの様々な段階で利用されます。
    *   `ProgInfo`構造体には、命令がレジスタを読み込むか（`reguse`）、書き込むか（`regset`）、アドレス指定にレジスタを使用するか（`regindex`）などのフラグが含まれます。
3.  **`D_OREG` (Offset Register Addressing)**:
    *   アセンブリ言語におけるメモリアクセスモードの一つで、ベースレジスタの値にオフセットを加算してメモリアドレスを計算する方式です。
    *   例: `(R1 + 16)` は、レジスタR1の値に16を加えたアドレスを指します。この場合、R1がアドレス指定に使用されるレジスタです。
4.  **`DUFFZERO`と`DUFFCOPY` (Duff's Device)**:
    *   **Duff's Device**: 1983年にTom Duffによって考案されたC言語のプログラミングテクニックで、`switch`文と`do-while`ループを組み合わせて、ループのオーバーヘッドを削減し、効率的なループアンローリングを実現します。主にメモリのコピーや初期化などの操作で使われます。
    *   **GoランタイムにおけるDuff's Device**: Go言語のランタイムでは、`runtime.duffzero`（メモリのゼロクリア）や`runtime.duffcopy`（メモリのコピー）といった関数が、Duff's Deviceに似たアセンブリレベルの最適化として実装されています。これらは非常に高速なメモリ操作を実現するために、特定のレジスタを効率的に利用します。
    *   これらのルーチンは、コンパイラが生成するコードから呼び出され、大量のメモリ操作を効率的に処理します。

## 技術的詳細

このコミットは、`src/cmd/9g/prog.c`ファイル内の`proginfo`関数を修正しています。`proginfo`関数は、各アセンブリ命令（`Prog`構造体で表現される）がレジスタをどのように使用するか（読み込み、書き込み、アドレス指定など）を解析し、その情報を`ProgInfo`構造体に格納します。

修正のポイントは以下の通りです。

1.  **`D_OREG`アドレスのレジスタ情報の修正**:
    *   以前は、`D_OREG`タイプのアドレス指定（例: `p->from.type == D_OREG`）で使用されるレジスタ（`p->from.reg`や`p->to.reg`）が`info->reguse`（レジスタ読み込み）フラグに設定されていました。
    *   このコミットでは、これを`info->regindex`フラグに変更しています。`regindex`は、レジスタがアドレス計算の一部として使用されることを示すためのフラグです。これにより、コンパイラはアドレス指定に使用されるレジスタと、データ操作のために読み書きされるレジスタを区別できるようになります。
    *   また、`D_CONST`タイプのアドレス指定も`regindex`の対象に追加されています。これは、定数オフセットを持つアドレス指定も同様にアドレス計算の一部と見なされるためです。
    *   `PostInc`（ポストインクリメント）フラグが設定されている場合、アドレス指定に使用されたレジスタがインクリメントされるため、そのレジスタは`regset`（レジスタ書き込み）フラグにも設定されます。これは、レジスタの値が変更されることを正確に反映するためです。
2.  **`DUFFZERO`/`DUFFCOPY`のレジスタ使用情報の追加**:
    *   `ADUFFZERO`命令の場合、`proginfo`はレジスタR0とR2が読み込まれ（`info->reguse |= RtoB(0) | RtoB(2)`）、R2が書き込まれる（`info->regset |= RtoB(2)`）ことを明示的に設定します。
    *   `ADUFFCOPY`命令の場合、`proginfo`はレジスタR0, R2, R3が読み込まれ（`info->reguse |= RtoB(0) | RtoB(2) | RtoB(3)`）、R2とR3が書き込まれる（`info->regset |= RtoB(2) | RtoB(3)`）ことを明示的に設定します。
    *   これらのレジスタは、Duff's Deviceに似たアセンブリルーチンが内部的に使用するものであり、コンパイラがこれらの命令を扱う際に、これらのレジスタが暗黙的に使用されることを認識できるようにします。これにより、レジスタ割り当ての競合を防ぎ、正しいコード生成を保証します。
    *   以前のコードにあった、これらのレジスタ使用に関するTODOコメントは削除されています。これは、このコミットによって問題が解決されたことを示唆しています。

これらの変更により、`9g`コンパイラは、より正確なレジスタ使用情報を持ち、特にメモリ操作の最適化において、より堅牢なコード生成が可能になります。

## コアとなるコードの解説

1.  **`progtable`からのTODOコメント削除**:
    *   `progtable`は、各アセンブリ命令の基本的な情報（例: `Cjmp`はジャンプ命令、`Call`は呼び出し命令）を定義するテーブルです。
    *   `ADUFFZERO`と`ADUFFCOPY`のエントリの下にあった、レジスタ使用に関するTODOコメントが削除されました。これは、これらのレジスタ使用情報が`proginfo`関数内で適切に処理されるようになったため、もはやTODOとして残す必要がなくなったことを意味します。

2.  **`D_OREG`および`D_CONST`アドレスのレジスタ処理の変更**:
    *   変更前:
        ```c
        if(p->from.type == D_OREG && p->from.reg != NREG) {
            info->reguse |= RtoB(p->from.reg);
        }
        // ...
        if(p->to.type == D_OREG && p->to.reg != NREG) {
            info->reguse |= RtoB(p->to.reg);
        }
        ```
        `D_OREG`タイプのアドレス指定で使用されるレジスタは、`reguse`（レジスタ読み込み）としてマークされていました。
    *   変更後:
        ```c
        if((p->from.type == D_OREG || p->from.type == D_CONST) && p->from.reg != NREG) {
            info->regindex |= RtoB(p->from.reg);
            if(info->flags & PostInc) {
                info->regset |= RtoB(p->from.reg);
            }
        }
        // ...
        if((p->to.type == D_OREG || p->to.type == D_CONST) && p->to.reg != NREG) {
            info->regindex |= RtoB(p->to.reg);
            if(info->flags & PostInc) {
                info->regset |= RtoB(p->to.reg);
            }
        }
        ```
        `D_OREG`または`D_CONST`タイプのアドレス指定で使用されるレジスタは、`regindex`（アドレス指定に使用されるレジスタ）としてマークされるようになりました。これにより、レジスタの役割がより正確に区別されます。
        また、`PostInc`フラグが設定されている場合（例: `*R1++`のようなポストインクリメントアドレス指定）、そのレジスタは`regset`（レジスタ書き込み）としてもマークされ、レジスタの値が変更されることを正確に反映します。

3.  **`ADUFFZERO`および`ADUFFCOPY`のレジスタ使用情報の追加**:
    *   変更後:
        ```c
        if(p->as == ADUFFZERO) {
            info->reguse |= RtoB(0) | RtoB(2);
            info->regset |= RtoB(2);
        }
        if(p->as == ADUFFCOPY) {
            info->reguse |= RtoB(0) | RtoB(2) | RtoB(3);
            info->regset |= RtoB(2) | RtoB(3);
        }
        ```
        `ADUFFZERO`命令の場合、レジスタR0とR2が読み込まれ、R2が書き込まれることが明示的に`info->reguse`と`info->regset`に設定されます。
        `ADUFFCOPY`命令の場合、レジスタR0, R2, R3が読み込まれ、R2とR3が書き込まれることが明示的に設定されます。
        これらの追加により、コンパイラはこれらの特殊なメモリ操作ルーチンが内部的に使用するレジスタを正確に把握し、レジスタ割り当ての際に考慮に入れることができるようになります。

これらの変更は、コンパイラのレジスタ割り当てアルゴリズムとデータフロー解析の精度を向上させ、結果として生成される機械語コードの品質と正確性を高めることに貢献します。
