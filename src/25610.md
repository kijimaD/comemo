# [インデックス 25610] ファイルの概要

このコミットは、Go言語の `net/http` パッケージにおける `TestLinuxSendfile` テストが `mips64` および `mips64le` アーキテクチャで失敗する問題を修正するものです。具体的には、`strace` コマンドが `sendfile64` システムコールを正しくトレースできないという `mips64` 環境特有の制約に対応するため、これらのアーキテクチャでは `strace` が `sendfile` のみをトレースするように変更されています。

## 元コミット内容

`net/http`: `mips64` 用の `TestLinuxSendfile` を修正しました。

`mips64` の `strace` は `sendfile64` をサポートしておらず、`-e trace=` でそれを指定するとエラーになります。そのため、ここでは `mips64` 用に `sendfile` を使用します。

## 変更の背景

この変更は、Go言語の `net/http` パッケージに含まれる `TestLinuxSendfile` というテストが、`mips64` および `mips64le` (MIPS 64-bit Little Endian) アーキテクチャ上で失敗するという問題に対応するために行われました。

`TestLinuxSendfile` は、Linuxカーネルの `sendfile` システムコールが正しく機能するかどうかを検証するためのテストです。このテストでは、`strace` というツールを使用して、テスト対象のプロセスが `sendfile` または `sendfile64` システムコールを呼び出していることを確認します。

問題は、特定の `mips64` 環境における `strace` の挙動にありました。`mips64` アーキテクチャの `strace` は、`sendfile64` システムコールをトレース対象として指定すると、内部的にエラーを発生させてしまうという制約がありました。これは、`strace` が `ptrace` システムコールを通じてプロセスのシステムコールを監視する際に、`mips64` 環境での `sendfile64` のシステムコール番号の解釈や、関連するABI (Application Binary Interface) の違いに起因する可能性が考えられます。

この `strace` の問題により、`TestLinuxSendfile` は `mips64` 環境で常に失敗していました。テストの目的は `sendfile` の機能検証であり、`strace` の挙動を検証することではないため、`mips64` 環境の特殊性を考慮して `strace` のトレース対象を調整する必要がありました。

## 前提知識の解説

### `sendfile` および `sendfile64` システムコール

`sendfile` は、Linuxカーネルが提供するシステムコールの一つで、ファイルディスクリプタ間でデータを直接転送するために使用されます。このシステムコールの主な利点は「ゼロコピー」転送を実現することです。通常、ファイルからネットワークソケットへデータを送信する場合、データはカーネル空間からユーザー空間へ、そして再びカーネル空間へと複数回コピーされます。しかし、`sendfile` を使用すると、データはカーネル空間内で直接転送されるため、CPUオーバーヘッドとメモリコピーの回数が大幅に削減され、特に大規模なファイル転送や高負荷なWebサーバーにおいてパフォーマンスが向上します。

`sendfile64` は `sendfile` の64ビット版であり、2GBを超えるような非常に大きなファイルを扱う際に使用されます。ファイルオフセットやサイズを64ビットで指定できるため、大容量ファイルの効率的な転送が可能です。

### `strace` コマンド

`strace` は、Linuxシステムで実行中のプロセスが発行するシステムコールとそのシグナルを監視・記録するための強力な診断ツールです。プログラムがどのようなシステムコールをどのような引数で呼び出し、どのような結果を受け取ったかを詳細に表示することで、プログラムのデバッグや動作解析に役立ちます。

`strace` の `-e trace=` オプションは、トレース対象とするシステムコールをフィルタリングするために使用されます。例えば、`-e trace=sendfile,sendfile64` と指定すると、`sendfile` と `sendfile64` のシステムコールのみがトレース対象となります。

### `mips64` アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。`mips64` はその64ビット版であり、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで広く利用されてきました。異なるアーキテクチャは、システムコールの呼び出し規約、レジスタの使用方法、メモリ配置など、ABIに違いを持つことがあります。これらの違いは、`strace` のような低レベルのツールがシステムコールを正しく解釈する上で課題となることがあります。

### Go言語の `net/http` パッケージ

Go言語の標準ライブラリである `net/http` パッケージは、HTTPクライアントおよびサーバーの実装を提供します。Webサーバー機能では、静的ファイルの配信などにおいて、可能であれば `sendfile` のような効率的なシステムコールを利用してパフォーマンスを最適化しようとします。

### Go言語の `runtime.GOARCH`

`runtime.GOARCH` は、Goプログラムが実行されているターゲットアーキテクチャを示す文字列定数です。例えば、`amd64`、`arm64`、`mips64`、`mips64le` などがあります。この定数を利用することで、特定のアーキテクチャに依存するコードパスを条件分岐させることができます。

## 技術的詳細

このコミットの技術的な核心は、`mips64` および `mips64le` アーキテクチャにおける `strace` の `sendfile64` システムコールトレースに関する既知の制約を回避することにあります。

`TestLinuxSendfile` テストは、`strace` を用いて `sendfile` または `sendfile64` のシステムコールが実際に呼び出されたことを確認することで、`net/http` パッケージがゼロコピー転送を正しく利用しているかを検証します。しかし、`mips64` 環境の `strace` は、`sendfile64` をトレース対象に含めるとエラーを発生させ、テストが失敗してしまいます。これは、`strace` が `ptrace` を介してシステムコールを監視する際に、`mips64` の `sendfile64` のシステムコール番号や引数の解釈に問題があったためと考えられます。

この問題を解決するため、コミットでは `runtime.GOARCH` を利用した条件分岐が導入されました。具体的には、Goプログラムが `mips64` または `mips64le` アーキテクチャで実行されている場合、`strace` コマンドに渡すシステムコールトレースの引数から `sendfile64` を除外し、`sendfile` のみを使用するように変更しています。これにより、`mips64` 環境でも `strace` がエラーを発生させることなく、`sendfile` システムコールのトレースが可能となり、テストが正常に完了するようになります。

このアプローチは、`mips64` 環境の `strace` の特定のバグや制限に直接対処しつつ、他のアーキテクチャでは引き続き `sendfile64` のトレースを試みることで、より広範なテストカバレッジを維持するというバランスの取れた解決策です。

## コアとなるコードの解説

変更は `src/net/http/fs_test.go` ファイル内の `TestLinuxSendfile` 関数に集中しています。

1.  **`syscalls` 変数の導入**:
    ```go
    	syscalls := "sendfile,sendfile64"
    ```
    まず、`strace` に渡すシステムコールリストを保持するための `syscalls` という文字列変数が導入されます。デフォルトでは、`sendfile` と `sendfile64` の両方をトレースするように初期化されます。

2.  **アーキテクチャによる条件分岐**:
    ```go
    	switch runtime.GOARCH {
    	case "mips64", "mips64le":
    		// mips64 strace doesn't support sendfile64 and will error out
    		// if we specify that with `-e trace='.
    		syscalls = "sendfile"
    	}
    ```
    ここで、`runtime.GOARCH` の値に基づいて条件分岐が行われます。
    *   もし現在の実行アーキテクチャが `mips64` または `mips64le` であれば、`syscalls` 変数の値は `"sendfile"` に上書きされます。これにより、`strace` は `sendfile` システムコールのみをトレースするようになります。
    *   それ以外のアーキテクチャ（例: `amd64`, `arm64` など）では、`syscalls` の値は初期値の `"sendfile,sendfile64"` のまま維持されます。

3.  **`strace` コマンドの引数変更**:
    ```go
    -	child := exec.Command("strace", "-f", "-q", "-e", "trace=sendfile,sendfile64", os.Args[0], "-test.run=TestLinuxSendfileChild")
    +	child := exec.Command("strace", "-f", "-q", "-e", "trace="+syscalls, os.Args[0], "-test.run=TestLinuxSendfileChild")
    ```
    `exec.Command` を使用して `strace` プロセスを起動する部分が変更されています。以前は `trace=sendfile,sendfile64` とハードコードされていましたが、変更後は `trace=` の後に動的に決定された `syscalls` 変数の値が連結されるようになりました。

この変更により、`mips64` および `mips64le` 環境では `strace` が `sendfile` のみをトレースし、他の環境では引き続き `sendfile` と `sendfile64` の両方をトレースすることで、テストの安定性と正確性が向上しました。
