# [インデックス 26152] ファイルの概要

このコミットは、GoランタイムにおけるDarwin (macOS) 環境でのシグナルハンドリングの正確性を向上させるためのものです。具体的には、`sigaction`システムコールの引数型がDarwin上で他のUnix系システムと異なるという問題に対処し、シグナルハンドラが代替スタック (`sigaltstack`) 上で実行されるようにする`setsigstack`関数の実装を追加しています。また、不要なメモリクリア処理の削除も行われています。

## 変更の背景

このコミットの主な背景は、Darwin (macOS) オペレーティングシステムにおける`sigaction`システムコールの特殊な挙動にあります。`sigaction`は、特定のシグナルに対するアクション（シグナルハンドラ）を設定または取得するためのPOSIX標準のAPIですが、Darwinの実装では、その引数に渡される構造体の型が、設定時と取得時で微妙に異なるという問題がありました。

具体的には、`sigaction`の第2引数（新しいシグナルハンドラを設定する場合）と第3引数（現在のシグナルハンドラを取得する場合）で、期待される`sigaction`構造体の内部表現が異なっていました。特に、Goランタイムがシグナルハンドラを設定する際に使用する内部的な`sigaction`構造体には、シグナルハンドラの「トランポリン」（`sa_tramp`フィールド）へのポインタが含まれていましたが、Darwinのユーザー空間から見える`sigaction`構造体にはこの`sa_tramp`フィールドが存在しませんでした。

この不一致は、Goランタイムがシグナルハンドラを設定した後、その設定を`sigaction`を使って読み戻そうとした際に問題を引き起こす可能性がありました。Goランタイムは、シグナルハンドラを代替スタック（シグナルスタック）上で実行するために`_SA_ONSTACK`フラグを使用しますが、この設定が正しく読み取れないと、シグナルハンドラが安全でないスタック上で実行され、クラッシュなどの不安定な挙動につながる恐れがありました。

また、Goランタイムはシグナルハンドラを代替スタック上で実行するために`sigaltstack`（または`sigsetstack`）を適切に設定する必要があります。このコミット以前は、Darwin環境で`setsigstack`関数が実装されておらず、シグナルスタックの管理が不十分でした。

さらに、`setsig`関数内にC言語のコードからの遺物である不要な`memclr`呼び出しが存在しており、これもクリーンアップの対象となりました。

これらの問題を解決し、Darwin上でのGoランタイムのシグナルハンドリングの堅牢性と正確性を向上させることが、このコミットの目的です。

## 前提知識の解説

### 1. `sigaction`システムコール

`sigaction`は、Unix系システムでシグナル（プロセスに送信される非同期イベント）の処理方法を定義するためのシステムコールです。古い`signal()`関数よりも柔軟で信頼性の高いシグナルハンドリングを提供します。
主な機能は以下の通りです。
*   **シグナルハンドラの設定**: 特定のシグナルが発生したときに実行される関数（シグナルハンドラ）を指定します。
*   **シグナルマスクの制御**: シグナルハンドラ実行中にブロックするシグナルを指定できます。
*   **フラグの設定**: シグナルハンドラの挙動を制御する様々なフラグ（例: `SA_RESTART`, `SA_SIGINFO`, `SA_ONSTACK`）を設定できます。

### 2. `sigaltstack`と`_SA_ONSTACK` (シグナルスタック)

*   **`sigaltstack`**: プロセスがシグナルハンドラを実行するための代替スタック（シグナルスタック）を登録するためのシステムコールです。通常のプログラムスタックが破損している場合や、スタックオーバーフローの危険がある場合に、シグナルハンドラを安全に実行するために使用されます。
*   **`_SA_ONSTACK` (または `SA_ONSTACK`)**: `sigaction`システムコールでシグナルハンドラを設定する際に使用されるフラグの一つです。このフラグが設定されている場合、オペレーティングシステムは、シグナルハンドラを通常のプログラムスタックではなく、`sigaltstack`で登録された代替スタック上で実行します。Goランタイムでは、ゴルーチンのスタックが小さく、シグナルハンドラが安全に実行される保証がないため、このシグナルスタックを積極的に利用します。

### 3. `sa_tramp`フィールド (シグナルトランポリン)

`sa_tramp`は、`sigaction`構造体の一部として、シグナルハンドラが呼び出される前に実行される低レベルのコード（シグナルトランポリン）へのポインタを指します。これは、OSやCライブラリがシグナルハンドラの実行環境をセットアップするために内部的に使用するメカニズムです。
Darwin (macOS) では、この`sa_tramp`フィールドの扱いが特殊です。Goランタイムのようなカスタムランタイムが独自のシグナルトランポリン（`runtime.sigtramp`）をインストールしても、Darwinの`sigaction`は、設定はできるものの、そのトランポリンを信頼性高く取得することができません。これにより、Goランタイムが設定したシグナルハンドラの状態を正確に把握したり、CGoコードとの相互作用でシグナル設定が上書きされたりする際に問題が生じることがありました。

### 4. Goランタイムのシグナルハンドリング

Goランタイムは、Unix系システム上で独自のシグナルハンドリングメカニズムを持っています。
*   **`os/signal`パッケージ**: Goプログラムがユーザーレベルでシグナルを扱うための高レベルなAPIを提供します。`signal.Notify`を使って、特定のシグナルを受信するチャネルを登録できます。
*   **ランタイムの低レベル処理**: Goランタイムは、プログラム起動時に`sigaction`システムコールを使って自身のシグナルハンドラをインストールします。これらのハンドラはOSからシグナルを受け取り、Goの並行処理モデル（チャネルなど）に統合します。特に、各OSスレッド（GoのM）には専用のシグナルスタック（gsignalスタック）が割り当てられ、シグナルハンドラはこのスタック上で実行されます。

### 5. `memclr`と`memset`

*   **`memclr`**: C言語の標準ライブラリには存在しない関数ですが、その名前が示す通り、メモリブロックをゼロでクリアする（すべてのバイトを0に設定する）ことを意図したものです。
*   **`memset`**: C言語の標準ライブラリ関数（`<string.h>`で定義）で、指定されたメモリブロックを特定の値で埋めるために使用されます。`memset(ptr, 0, size)`とすることで、`memclr`と同様にメモリブロックをゼロクリアできます。`memset`は通常、アセンブリ言語で最適化されており、効率的に動作します。このコミットで`memclr`が「無駄」とされたのは、GoランタイムのコードベースがC言語からGo言語への移行期にあり、C言語時代の遺物が残っていたためと考えられます。

### 6. `funcPC`と`sigtramp` (Goランタイム内部)

*   **`sigtramp`**: Goランタイム内部の低レベルなアセンブリまたはC関数で、OSからシグナルが配送された際の最初の入り口となります。OSのC ABIからGo ABIへの移行、実行コンテキストの保存、スタックのセットアップなどを行い、最終的にGo言語で書かれたシグナルハンドラ（`runtime.sigtrampgo`など）を呼び出します。
*   **`funcPC`**: Goランタイム内部の機能で、特定の関数のエントリポイント（プログラムカウンタ、つまりメモリ上のアドレス）を取得するために使用されます。これは、非同期プリエンプションなどの高度なランタイム機能で、シグナルハンドラから中断されたゴルーチンの実行フローを別の関数にリダイレクトする際に利用されます。

## 技術的詳細

このコミットは、主にDarwin環境における`sigaction`システムコールの挙動の差異と、シグナルスタックの適切な管理に焦点を当てています。

### 1. `sigaction`引数型の不一致への対応

Darwinでは、`sigaction`システムコールが内部的に使用する`struct __sigaction`と、ユーザーが通常扱う`struct sigaction`という、2つの異なる`sigaction`構造体が存在します。Goランタイムがシグナルハンドラを設定する際には、`sa_tramp`フィールドを含む内部的な`struct __sigaction`に相当する型を使用しますが、既存のシグナルハンドラを問い合わせる際には、`sa_tramp`フィールドを持たないユーザー向けの`struct sigaction`に相当する型を使用する必要があります。

このコミットでは、この差異を吸収するために新しい型`Usigaction`が導入されました。
*   `src/runtime/defs_darwin.go`に`type Usigaction C.struct_sigaction`が追加されました。これは、`sigaction`の第2引数（`old`引数）として使用される、ユーザー空間から見える`sigaction`構造体を表現します。
*   各アーキテクチャ固有の定義ファイル（`defs_darwin_386.go`, `defs_darwin_amd64.go`, `defs_darwin_arm.go`, `defs_darwin_arm64.go`）には、`usigactiont`という構造体が追加されました。この構造体は、`__sigaction_u`（シグナルハンドラへのポインタを格納する共用体）、`sa_mask`（シグナルマスク）、`sa_flags`（フラグ）を含み、`sa_tramp`フィールドを持たない`struct sigaction`のGo言語での表現となります。

これにより、`sigaction`システムコールを呼び出す際に、設定用と取得用で適切な構造体型を使い分けることが可能になり、DarwinのAPIのセマンティクスに正確に合致するようになりました。

### 2. `setsigstack`関数の実装

以前は`setsigstack`関数が`throw("setsigstack")`というパニックを発生させていましたが、このコミットでDarwin向けに適切に実装されました。
`setsigstack`の目的は、特定のシグナルに対して`_SA_ONSTACK`フラグを設定し、シグナルハンドラが代替スタック上で実行されるようにすることです。

実装のロジックは以下の通りです。
1.  **既存のハンドラ情報の取得**: まず、`sigaction`システムコールを呼び出し、現在のシグナルハンドラの設定を`osa`（`usigactiont`型）に取得します。この際、`new`引数には`nil`を渡し、既存の情報を問い合わせます。
2.  **シグナルスタック設定の要否判定**: 取得した`osa`の`handler`（シグナルハンドラへのポインタ）が`0`（未設定）、`_SIG_DFL`（デフォルト動作）、`_SIG_IGN`（シグナル無視）のいずれかである場合、または既に`_SA_ONSTACK`フラグが設定されている場合は、特に変更の必要がないため、関数を終了します。
3.  **新しいハンドラ設定の準備**: `sa`（`sigactiont`型）という新しい構造体を準備します。
    *   `sa.__sigaction_u`には、既存のハンドラ`handler`をコピーします。
    *   `sa.sa_tramp`には、Goランタイムのシグナルトランポリンである`sigtramp`のアドレスを設定します。これは`funcPC(sigtramp)`で取得されます。
    *   `sa.sa_mask`には、既存のシグナルマスク`osa.sa_mask`をコピーします。
    *   `sa.sa_flags`には、既存のフラグ`osa.sa_flags`に加えて、`_SA_ONSTACK`フラグを設定します。
4.  **シグナルハンドラの設定**: 最後に、`sigaction`システムコールを呼び出し、準備した`sa`構造体を使ってシグナルハンドラを更新します。この際、`old`引数には`nil`を渡し、以前の情報を破棄します。

この実装により、GoランタイムはDarwin上でシグナルハンドラを安全な代替スタック上で実行できるようになり、スタックオーバーフローなどのリスクを軽減します。

### 3. `memclr`の削除

`src/runtime/os1_darwin.go`の`setsig`関数から、`memclr(unsafe.Pointer(&sa), unsafe.Sizeof(sa))`という行が削除されました。
これは、C言語のコードベースからGo言語への移行の際に残された遺物であり、Go言語では構造体のゼロ値がデフォルトでゼロ初期化されるため、明示的な`memclr`呼び出しは不要かつ無駄でした。この削除により、コードがよりクリーンになり、Goのイディオムに沿ったものになりました。

### 4. `getsig`関数の変更

`src/runtime/os1_darwin.go`の`getsig`関数も、`sigaction`から情報を取得する際に`usigactiont`型を使用するように変更されました。これにより、DarwinのAPIに正確に準拠し、`sa_tramp`フィールドの有無による型の不一致の問題を回避しています。

### 5. `sigaction`関数のシグネチャ変更

`src/runtime/os_darwin.go`では、`sigaction`関数のGo言語での宣言が変更されました。
変更前: `func sigaction(mode uint32, new, old *sigactiont)`
変更後: `func sigaction(mode uint32, new *sigactiont, old *usigactiont)`
この変更は、`sigaction`システムコールの`old`引数に`usigactiont`型（`sa_tramp`フィールドを持たないユーザー向け構造体）を渡す必要があるというDarwinの仕様を反映したものです。

## コアとなるコードの解説

### `src/runtime/defs_darwin.go` および `defs_darwin_*.go` の変更

*   **`Usigaction` 型の導入**: `src/runtime/defs_darwin.go` に `type Usigaction C.struct_sigaction` が追加されました。これは、Darwinの`sigaction`システムコールの第2引数（`old`引数）として使用される、`sa_tramp`フィールドを持たないユーザー向けの`sigaction`構造体をGo言語で表現するためのものです。
*   **`usigactiont` 構造体の定義**: 各アーキテクチャ固有の`defs_darwin_*.go`ファイルに`usigactiont`構造体が定義されました。この構造体は、`__sigaction_u`（シグナルハンドラへのポインタを格納する共用体）、`sa_mask`、`sa_flags`を含み、`sa_tramp`フィールドを持たない`struct sigaction`のGo言語での表現です。これにより、GoランタイムはDarwinのAPIのセマンティクスに正確に合致する形で、シグナルハンドラの設定を問い合わせることができるようになりました。

### `src/runtime/os1_darwin.go` の変更

*   **`setsig` から `memclr` の削除**: `setsig`関数内の`memclr(unsafe.Pointer(&sa), unsafe.Sizeof(sa))`という行が削除されました。Go言語では構造体はデフォルトでゼロ初期化されるため、この明示的なメモリクリアは不要であり、C言語からの遺物でした。この削除により、コードが簡潔になり、Goのイディオムに沿ったものになりました。
*   **`setsigstack` 関数の実装**:
    *   `var osa usigactiont; sigaction(uint32(i), nil, &osa)`: まず、対象のシグナル`i`に対する現在のシグナルハンドラの設定を`usigactiont`型の`osa`に取得します。`new`引数に`nil`を渡すことで、設定を変更せずに現在の情報を取得します。
    *   `handler := *(*uintptr)(unsafe.Pointer(&osa.__sigaction_u))`: 取得した`osa`からシグナルハンドラのアドレスを抽出します。
    *   `if handler == 0 || handler == _SIG_DFL || handler == _SIG_IGN || osa.sa_flags&_SA_ONSTACK != 0 { return }`: 既存のハンドラが未設定、デフォルト動作、シグナル無視の場合、または既に`_SA_ONSTACK`フラグが設定されている場合は、シグナルスタックを設定する必要がないため、関数を早期に終了します。
    *   `var sa sigactiont; *(*uintptr)(unsafe.Pointer(&sa.__sigaction_u)) = handler`: 新しい設定用の`sigactiont`構造体`sa`を準備し、既存のハンドラアドレスをコピーします。
    *   `sa.sa_tramp = unsafe.Pointer(funcPC(sigtramp))`: Goランタイムのシグナルトランポリン`sigtramp`のアドレスを`sa.sa_tramp`に設定します。これにより、シグナル発生時にGoランタイムが制御を奪い、適切な初期化を行うことができます。
    *   `sa.sa_mask = osa.sa_mask; sa.sa_flags = osa.sa_flags | _SA_ONSTACK`: 既存のシグナルマスクをコピーし、`_SA_ONSTACK`フラグを追加して設定します。これにより、シグナルハンドラが代替スタック上で実行されるようになります。
    *   `sigaction(uint32(i), &sa, nil)`: 最後に、更新された`sa`構造体を使ってシグナルハンドラを再設定します。
*   **`getsig` 関数の変更**: `getsig`関数も、`sigaction`から情報を取得する際に`usigactiont`型を使用するように変更されました。これにより、DarwinのAPIに正確に準拠し、`sa_tramp`フィールドの有無による型の不一致の問題を回避しています。

### `src/runtime/os_darwin.go` の変更

*   **`sigaction` 関数のシグネチャ変更**: Go言語での`sigaction`関数の宣言が `func sigaction(mode uint32, new *sigactiont, old *usigactiont)` に変更されました。これは、`sigaction`システムコールの`old`引数に`usigactiont`型（`sa_tramp`フィールドを持たないユーザー向け構造体）を渡す必要があるというDarwinの仕様を反映したものです。この変更により、GoランタイムはDarwinの`sigaction` APIをより正確かつ安全に利用できるようになりました。

これらの変更により、GoランタイムはDarwin環境でのシグナルハンドリングの堅牢性を大幅に向上させ、特にシグナルスタックの利用を正確に行うことで、プログラムの安定性を高めています。
