## 変更の背景

このコミットの背景には、Goのビルドシステムにおける `-a` フラグの挙動変更があります。元々、`go build -a` (または `go test -a`) コマンドは、たとえパッケージが最新の状態であっても、強制的に再ビルドを行うためのフラグです。しかし、過去にはこのフラグが標準ライブラリのパッケージには適用されないという特殊な挙動がありました。

コミットメッセージにある `https://golang.org/cl/10761` は、この挙動が変更されたコードレビュー（Change List）を指しています。このCL（コミット `3ab9ff1` に関連）では、コンパイル時のオブジェクトファイルの不一致をより適切に処理するための改善が行われました。この改善の一環として、`-a` フラグが標準ライブラリにも適用されるように内部的な変更が加えられたと考えられます。

`Update #12203` は、この変更に関連するGoのIssueトラッカー上の課題を指しています。Issue #12203は、おそらく `-a` フラグの標準ライブラリへの適用に関する挙動の不整合や、そのドキュメントの更新の必要性について議論されたものと推測されます。このコミットは、実際の挙動が変更されたことに伴い、ユーザー向けのドキュメント（`go help build` と `go help test` の出力）を最新の状態に保つために行われました。

つまり、このコミットは、Goツールチェインの内部的な改善によって生じた挙動の変更を、ユーザーが参照するドキュメントに正確に反映させるための「ドキュメントの同期」が目的です。

## 前提知識の解説

### `go build -a` コマンド

`go build` コマンドはGo言語のソースコードをコンパイルして実行可能ファイルを生成するための主要なツールです。通常、`go build` はスマートに動作し、変更されていない依存関係や既にコンパイル済みのパッケージは再ビルドしません。これにより、ビルド時間を短縮します。

しかし、`-a` フラグを `go build` や `go test` に付与すると、この最適化を無効にし、すべてのパッケージ（依存関係を含む）を強制的に再ビルドします。これは、以下のような状況で役立ちます。

*   **クリーンなビルドの保証**: ビルドキャッシュが破損している可能性がある場合や、古いオブジェクトファイルが残っていることによる予期せぬ問題が発生している場合に、完全にクリーンな状態からビルドをやり直したいとき。
*   **ツールチェインの変更**: Goコンパイラやツールチェイン自体をアップグレードした場合に、すべてのパッケージが新しいツールチェインでコンパイルされることを保証したいとき。
*   **デバッグ**: 特定のビルド問題がキャッシュや古いビルド成果物に起因するかどうかを切り分けるとき。

### Goの標準ライブラリ

Goの標準ライブラリは、Go言語のインストールに同梱されている一連のパッケージ群です。`fmt`, `net/http`, `io`, `os` など、Goアプリケーション開発の基盤となる多くの機能を提供します。これらのパッケージはGoのリリース時にコンパイル済みバイナリとして提供されることが多く、通常はユーザーが明示的に再ビルドする必要はありません。

### Goのリリースプロセスとツールチェイン

Go言語は定期的に新しいバージョンがリリースされます。各リリースには、コンパイラ、リンカ、アセンブラなどのツールチェインが含まれています。これらのツールチェインは、Goプログラムをビルドするために使用されます。過去には、Goのリリース版では標準ライブラリが特別な扱いを受け、`-a` フラグによる強制再ビルドの対象外とされていました。これは、標準ライブラリが安定しており、通常は再ビルドの必要がないという前提に基づいていた可能性があります。しかし、ビルドシステムの堅牢性を高めるために、この挙動が変更されたのがこのコミットの背景にあります。

## 技術的詳細

このコミットの技術的な詳細は、`go build -a` フラグの挙動が変更されたことに伴う、ドキュメントの更新に集約されます。

以前のGoツールチェインでは、`go build -a` コマンドを実行しても、Goの標準ライブラリ（例: `fmt`, `net/http` など）は強制再ビルドの対象外でした。これは、標準ライブラリがGoのリリースバイナリの一部として提供され、通常は変更されないため、再ビルドの必要がないという最適化、あるいは設計上の判断があったためと考えられます。

しかし、`https://golang.org/cl/10761` で導入された変更により、この挙動が修正され、`-a` フラグは標準ライブラリを含むすべてのパッケージに適用されるようになりました。この変更は、ビルドシステムがオブジェクトファイルの不一致をより適切に処理するための改善の一環として行われたと推測されます。例えば、異なるバージョンのGoツールチェインでビルドされた標準ライブラリのオブジェクトファイルが混在するような稀なケースで、一貫性のあるビルドを保証するために、強制的な再ビルドが必要になる場合があります。

このコミットは、この内部的な挙動変更をユーザーに正しく伝えるため、`src/cmd/go/alldocs.go` と `src/cmd/go/build.go` の2つのファイルから、以下の記述を削除しています。

```
-		In Go releases, does not apply to the standard library.
```

この記述は、`go help build` および `go help test` コマンドの出力に含まれる `-a` フラグの説明の一部でした。この記述を削除することで、`-a` フラグが標準ライブラリにも適用されるようになったという新しい挙動が、ユーザーに正しく伝わるようになります。

この変更は、Goツールチェインの透明性と正確性を高める上で重要です。ユーザーは、コマンドのドキュメントが実際の挙動と一致することを期待するため、このようなドキュメントの同期は開発体験を向上させます。

## コアとなるコードの解説

上記の差分は、`src/cmd/go/alldocs.go` と `src/cmd/go/build.go` の両方から、特定の行が削除されたことを示しています。

*   `src/cmd/go/alldocs.go`: このファイルは、`go help` コマンドが提供する一般的なドキュメントのソースコードの一部です。`go help build` や `go help test` のようなサブコマンドのヘルプメッセージもここから生成されます。
*   `src/cmd/go/build.go`: このファイルは、`go build` コマンドのロジックと、そのコマンドライン引数に関するドキュメントを定義しています。

削除された行 `-\t\tIn Go releases, does not apply to the standard library.` は、`-a` フラグの説明の一部でした。この行が削除されたことにより、`go help build` や `go help test` を実行した際に表示される `-a` フラグの説明から、「Goのリリース版では、標準ライブラリには適用されない」という誤った情報が取り除かれます。

この変更は、コードの機能的な挙動を変更するものではなく、あくまでその挙動を説明するドキュメントを修正するものです。しかし、ユーザーがGoツールチェインを正しく理解し、効果的に使用するためには、ドキュメントが実際の挙動と一致していることが不可欠です。このコミットは、その整合性を保つための重要な修正と言えます。
