## 変更の背景

このコミットの背景には、Go言語の歴史における画期的な変更点であるGo 1.5のリリースがあります。Go 1.5では、GoコンパイラとランタイムがC言語とアセンブリ言語からGo言語自身へと完全に書き換えられ、Goが「セルフホスティング」されるようになりました。これは、GoのビルドにCコンパイラが不要になるという大きなメリットをもたらしましたが、同時に「ブートストラップ問題」という新たな課題も生じさせました。

ブートストラップ問題とは、Go言語で書かれたGoコンパイラをコンパイルするために、既に動作するGoコンパイラが必要になるという循環的な問題です。Go 1.5では、この問題を解決するために、Go 1.4（C言語ベースの最後のコンパイラ）をブートストラップツールチェインとして使用する方式が採用されました。つまり、Go 1.5をビルドするには、まずGo 1.4がインストールされている必要がありました。

しかし、`linux/ppc64`のような一部のアーキテクチャはGo 1.4では公式にサポートされていませんでした。このような環境でGo 1.5をビルドしようとすると、通常のブートストラップ手順では困難が生じます。このコミットは、このような特定の環境でGo 1.5をビルドするための具体的な手順とヒントをドキュメントに追加することで、ユーザーがGo 1.5への移行をスムーズに行えるようにすることを目的としています。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念を把握しておく必要があります。

*   **Goのブートストラップ (Bootstrapping Go)**:
    GoコンパイラはGo言語自体で書かれているため、新しいバージョンのGoをビルドするには、それ以前のバージョンのGoコンパイラが必要です。このプロセスを「ブートストラップ」と呼びます。Go 1.5以降、GoのビルドにはGo 1.4以降のGoコンパイラが必要となりました。Go 1.4はC言語で書かれた最後のGoコンパイラであり、Go 1.5以降のGoコンパイラをビルドするための「種」の役割を果たしました。

*   **Go 1.5のセルフホスティング (Self-hosting)**:
    Go 1.5の最も重要な変更点の一つは、Goコンパイラ、アセンブラ、リンカといったツールチェイン全体がGo言語で再実装されたことです。これにより、GoのビルドにCコンパイラ（GCCやClangなど）が不要となり、Goエコシステム内だけでGoをビルドできるようになりました。これは開発の簡素化、メンテナンス性の向上、そしてGo言語の進化を加速させる上で非常に重要な一歩でした。

*   **クロスコンパイル (Cross-compilation)**:
    あるコンピュータアーキテクチャ（ホスト）上で、別のコンピュータアーキテクチャ（ターゲット）向けの実行ファイルを生成するプロセスです。Go言語は、`GOOS`（ターゲットOS）と`GOARCH`（ターゲットアーキテクチャ）という環境変数を設定するだけで簡単にクロスコンパイルできることで知られています。

*   **`GOOS`と`GOARCH`**:
    Goのビルドシステムで使用される環境変数です。
    *   `GOOS`: ターゲットとなるオペレーティングシステム（例: `linux`, `windows`, `darwin`）。
    *   `GOARCH`: ターゲットとなるCPUアーキテクチャ（例: `amd64`, `arm`, `ppc64`）。
    これらの変数を設定することで、異なるプラットフォーム向けのバイナリを生成できます。

*   **`bootstrap.bash`**:
    Goのソースコードリポジトリに含まれるシェルスクリプトで、Goツールチェインをビルドするために使用されます。特にGo 1.5以降のセルフホスティング環境において、Go 1.4などの既存のGoインストールを使って新しいGoバージョンをビルドする際の初期段階で重要な役割を果たします。クロスコンパイル環境を構築する際にも利用されます。

*   **`gccgo`**:
    GCC (GNU Compiler Collection) のフロントエンドとしてGo言語をサポートするコンパイラです。Goの公式コンパイラである`gc`（Go Compiler）とは異なる実装であり、GCCの最適化技術を利用できるという特徴があります。`gc`がサポートしていない特定のアーキテクチャや、C/C++とのより密接な連携が必要な場合に選択肢となることがあります。Go 1.5のブートストラップ時には、`gc`が利用できない環境での代替手段として言及されることがあります。

## 技術的詳細

このコミットで追加されたドキュメントは、Go 1.5をGo 1.4がサポートしていないシステム（例: `linux/ppc64`）にインストールするための2つの主要なアプローチを提示しています。

1.  **`bootstrap.bash` を用いたクロスブートストラップ**:
    この方法は、Go 1.5を通常通りブートストラップできるシステム（ホストシステム）を利用して、ターゲットシステム向けのGoツールチェインを生成します。
    *   **手順**:
        ```bash
        $ GOOS=linux GOARCH=ppc64 ./bootstrap.bash
        ```
        このコマンドを実行すると、`bootstrap.bash`スクリプトは指定された`GOOS/GOARCH`（この例では`linux/ppc64`）の組み合わせに対応するGoツールチェインをクロスコンパイルします。
    *   **出力**:
        コンパイルされたツールチェインは、`../../go-${GOOS}-${GOARCH}-bootstrap`というディレクトリに生成されます。このディレクトリは、ターゲットシステムにコピーして使用するための、自己完結型のGoインストールとなります。
    *   **その後の利用**:
        ターゲットシステムにこの生成されたツールチェインをコピーした後、そのパスを`GOROOT_BOOTSTRAP`環境変数に設定することで、ターゲットシステム上でGo 1.5の完全なビルド（`./make.bash`など）を行うためのブートストラップツールとして利用できます。これにより、Go 1.4が直接サポートしていない環境でも、Go 1.5をビルドするための初期環境を確立できます。

2.  **`gccgo 5` を用いたブートストラップ**:
    `bootstrap.bash`によるクロスブートストラップが難しい場合や、`gccgo`が利用可能な環境での代替手段として提示されています。
    *   **背景**:
        `gccgo`はGCCの一部としてGo言語をサポートしており、Goの公式コンパイラ`gc`とは独立して開発が進められています。Go 1.5のリリース当時、`gccgo 5`はGo 1.4のユーザーライブラリを完全に実装しており、`gc`がサポートしていないアーキテクチャでも利用できる可能性がありました。
    *   **手順**:
        ドキュメントではUbuntu Vividを例に挙げています。
        ```bash
        $ sudo apt-get install gccgo-5
        $ sudo update-alternatives --set go /usr/bin/go-5
        $ GOROOT_BOOTSTRAP=/usr ./make.bash
        ```
        1.  `sudo apt-get install gccgo-5`: `gccgo 5`をインストールします。これにより、`gccgo`コンパイラと、それに対応する`go`コマンドがシステムに導入されます。
        2.  `sudo update-alternatives --set go /usr/bin/go-5`: システムのデフォルトの`go`コマンドを`gccgo 5`が提供する`go`コマンドに切り替えます。これは、`./make.bash`が`go`コマンドを呼び出す際に`gccgo`のバージョンを使用するようにするためです。
        3.  `GOROOT_BOOTSTRAP=/usr ./make.bash`: `GOROOT_BOOTSTRAP`環境変数を`/usr`に設定して`./make.bash`を実行します。これは、システムにインストールされた`gccgo`がGoのブートストラップツールとして機能することを`make.bash`に伝えます。`/usr`は通常、システム全体のGoインストール（`gccgo`を含む）のルートディレクトリとして機能します。

このドキュメントの追加は、Go 1.5のセルフホスティング化という大きな変更が、Goのビルドとデプロイメントに与える影響を軽減し、より広範なプラットフォームでのGoの採用を促進するための重要な一歩でした。

## コアとなるコードの解説

追加されたHTMLスニペットは、Go 1.5のインストールに関する重要な情報を提供しています。

1.  **最初の段落 (`<p>If you want to install Go 1.5...`)**:
    *   Go 1.4でサポートされていないシステム（具体例として`linux/ppc64`を挙げている）にGo 1.5をインストールしたい場合の選択肢を提示しています。
    *   選択肢は2つ：「Go 1.5を通常通りブートストラップできるシステムで`bootstrap.bash`を使用する」か、「`gccgo 5`でブートストラップする」です。
    *   `bootstrap.bash`へのリンク（`/src/bootstrap.bash`）も提供されており、ユーザーがスクリプトのソースコードを確認できるようにしています。

2.  **`bootstrap.bash` の使用例 (`<pre>$ GOOS=linux GOARCH=ppc64 ./bootstrap.bash</pre>`)**:
    *   `GOOS`と`GOARCH`環境変数を設定して`bootstrap.bash`を実行する具体的なコマンド例を示しています。これは、クロスコンパイルの基本的なパターンです。
    *   この例は、`linux`オペレーティングシステムと`ppc64`アーキテクチャ向けのGoツールチェインをビルドすることを示唆しています。

3.  **`bootstrap.bash` の結果の説明 (`<p><code>bootstrap.bash</code> cross-compiles...`)**:
    *   `bootstrap.bash`が指定された`GOOS/GOARCH`の組み合わせに対してクロスコンパイルを行い、結果として生成されるツールチェインが`../../go-${GOOS}-${GOARCH}-bootstrap`というディレクトリに配置されることを説明しています。
    *   この生成されたツリーは、ターゲットマシンにコピーされ、そのマシン上で`GOROOT_BOOTSTRAP`として使用することで、ローカルビルドをブートストラップできることを明確にしています。これは、Go 1.5の完全なビルドを行うための初期ステップとなります。

4.  **`gccgo` の使用に関する説明 (`<p>To use gccgo, you need to arrange...`)**:
    *   `gccgo`を使用する場合、`$GOROOT_BOOSTRAP/bin/go`が`gccgo 5`の一部として提供される`go`ツールを指すように設定する必要があることを説明しています。
    *   これは、Goのビルドシステムが`GOROOT_BOOTSTRAP`で指定されたパス内の`bin/go`ツールを探すため、`gccgo`の`go`コマンドを指すようにする必要があることを意味します。

5.  **`gccgo` の具体的なコマンド例 (`<pre>$ sudo apt-get install gccgo-5...</pre>`)**:
    *   Ubuntu Vividを例に、`gccgo`を使ったブートストラップの具体的な手順を示しています。
    *   `sudo apt-get install gccgo-5`: `gccgo 5`パッケージのインストール。
    *   `sudo update-alternatives --set go /usr/bin/go-5`: システムのデフォルトの`go`コマンドを`gccgo 5`が提供するバージョンに切り替えるコマンド。これにより、`./make.bash`が`gccgo`の`go`ツールを使用するようになります。
    *   `GOROOT_BOOTSTRAP=/usr ./make.bash`: `GOROOT_BOOTSTRAP`を`/usr`に設定して`./make.bash`を実行。これは、システムにインストールされた`gccgo`がブートストラップツールとして機能することを`make.bash`に伝えます。

これらの追加されたドキュメントは、Go 1.5のセルフホスティング化という大きな変更がもたらすビルドの複雑さに対し、実用的な解決策とガイダンスをユーザーに提供するものです。特に、Go 1.4がサポートしない新しいアーキテクチャへのGo 1.5の導入を容易にすることを目的としています。
