## 変更の背景

Go言語の`math/big`パッケージは、任意精度（arbitrary-precision）の浮動小数点数演算を提供します。このパッケージの`Float`型は、標準の`float32`や`float64`型では表現できない非常に大きな数や小さな数を扱うことができます。しかし、`Float`型で表現された数値を標準の`float64`型に変換する際、IEEE 754浮動小数点標準の特定の境界ケース、特に非正規化数（denormalized numbersまたはsubnormal numbers）の扱いにおいて、既存の実装に誤りがありました。

具体的には、非常に小さいがゼロではない数値が`float64`の表現範囲に収まるように丸められる際に、最小の非正規化数に正確に切り上げられるべきケースで、誤った結果が生成される可能性がありました。この問題は、`Float32`変換のロジックとは異なり、`Float64`変換のロジックがこの種のコーナーケースを適切に処理できていなかったことに起因します。

このコミットの目的は、`Float.Float64()`メソッドがIEEE 754標準に完全に準拠し、すべての境界ケース、特に非正規化数の丸め処理を正確に行うように修正することでした。これにより、`math/big`パッケージの信頼性と正確性が向上します。

## 前提知識の解説

### IEEE 754 浮動小数点標準

現代のコンピュータシステムで浮動小数点数を表現するための最も一般的な標準です。`float32`（単精度）と`float64`（倍精度）は、この標準に基づいて実装されています。

- **正規化数 (Normal Numbers)**: ほとんどの浮動小数点数は正規化数として表現されます。これらは、仮数部（mantissa）の最上位ビットが常に1であると暗黙的に仮定することで、精度を最大化します。
- **非正規化数 (Denormalized/Subnormal Numbers)**: 非常に小さいがゼロではない数値を表現するために使用されます。正規化数とは異なり、仮数部の最上位ビットが暗黙的に1であるとは仮定されません（つまり、先行ゼロを持つことができます）。これにより、ゼロに近い数値の精度が失われることなく、より広い範囲の小さな数値を表現できます。非正規化数は、アンダーフロー（underflow）が発生する際に、結果がゼロにフラッシュされるのを防ぐ「グラデーションアンダーフロー」を提供します。
- **指数部 (Exponent)**: 浮動小数点数の大きさを決定します。バイアス形式で格納され、実際の指数にオフセットが加算されます。
- **仮数部 (Mantissa/Significand)**: 浮動小数点数の精度を決定します。正規化数では暗黙の1ビットが存在しますが、非正規化数では明示的に表現されます。
- **`float64`の構造**:
    - 符号ビット (Sign bit): 1ビット
    - 指数部 (Exponent): 11ビット (バイアスは1023)
    - 仮数部 (Mantissa): 52ビット (暗黙の1ビットを含めると53ビットの精度)
    - `emin` (最小指数): -1022 (非正規化数の場合は-1022より小さい指数に対応)
    - `emax` (最大指数): 1023
    - `dmin` (非正規化数の最小指数): `emin - mbits` (ここで`mbits`は仮数部のビット数)

### `math/big.Float`

Go言語の`math/big`パッケージは、任意精度の数値型を提供します。`big.Float`は、任意の精度と指数範囲を持つ浮動小数点数を表現できます。これは、標準の`float32`や`float64`の精度や範囲では不十分な科学計算や金融計算などで利用されます。

`big.Float`は、内部的に符号、指数、および大きな整数の仮数部で構成されます。`Float64()`メソッドは、この任意精度の`big.Float`値を最も近い`float64`値に変換する役割を担います。この変換プロセスでは、精度が失われる可能性があり、丸め処理が重要になります。

## 技術的詳細

このコミットの技術的詳細の中心は、`big.Float`から`float64`への変換における非正規化数の丸め処理の正確性です。

以前の`Float64()`実装は、`Float32()`の実装とは異なり、非正規化数の境界ケース、特に「最小の非正規化数に切り上げられる数値」の処理に問題がありました。このコミットでは、`Float32()`で既に正しく機能していたアルゴリズムを`Float64()`にも適用することで、この問題を解決しています。

変更の主要なポイントは以下の通りです。

1.  **共通の変換ロジックの採用**: `Float32()`と`Float64()`で浮動小数点数への変換ロジックを共通化しました。これにより、`Float32()`で既に解決されていた非正規化数の丸め問題が`Float64()`にも適用されます。
2.  **精度（`p`）の動的な調整**:
    - `big.Float`の内部表現では、仮数`m`は`0.5 <= m < 1.0`の範囲にあり、指数`e`は`floatxx`（`float32`または`float64`）の仮数（`1.0 <= m < 2.0`）に対応する指数よりも1小さい値として計算されます (`e = x.exp - 1`)。
    - `float64`の正規化数の精度は`mbits + 1`（暗黙の1ビットを含む53ビット）です。
    - 指数`e`が`emin`（`float64`の最小正規化指数、-1022）よりも小さい場合、その数値は非正規化数になる可能性があります。この場合、利用可能な仮数ビット数が減るため、精度`p`を動的に調整する必要があります。
    - `p -= emin - int(e)`: この計算により、指数が`emin`からどれだけ離れているかに応じて精度`p`を減らします。これは、非正規化数が先行ゼロを持つため、有効なビット数が減少することを反映しています。
    - `if p < 1 { p = 1 }`: 精度が少なくとも1ビットであることを保証します。これは、「最小の非正規化数に切り上げられる数値」がゼロに丸められてしまうのを防ぐために重要です。
3.  **丸め処理の改善**:
    - `r.prec = uint32(p)`: 調整された精度`p`を使用して、`big.Float`の丸め処理を行います。`r.Set(x)`で`x`を`r`にコピーし、`r`の精度`r.prec`に基づいて丸めます。
    - 丸め後に`r`が無限大（`inf`）になった場合、オーバーフローとして処理するために指数`e`を`emax + 1`に設定します。
4.  **オーバーフロー/アンダーフローの正確な処理**:
    - `if e > emax`: 指数`e`が`emax`（`float64`の最大指数、1023）を超えた場合、オーバーフローとして`±Inf`を返します。
    - `if e < dmin`: 指数`e`が`dmin`（`float64`の最小非正規化指数、`emin - mbits`）よりも小さい場合、アンダーフローとして`±0`を返します。
5.  **`float64`ビット表現の構築**:
    - 符号ビット、バイアスされた指数、仮数ビットを正確に組み立てて、`math.Float64frombits()`関数を使用して最終的な`float64`値を生成します。
    - 非正規化数の場合、指数部`bexp`は0になります。仮数部`mant`は、`r.mant`から適切なビットをシフトして抽出されます。
    - 正規化数の場合、指数部`bexp`は`uint64(e+bias) << mbits`として計算され、仮数部`mant`は`high64(r.mant) >> ebits & (1<<mbits - 1)`として、暗黙の1ビットを除去して抽出されます。

この修正により、`Float64()`は`float64`の表現可能な範囲のすべての数値、特に非正規化数の領域において、IEEE 754標準に準拠した正確な変換と丸め処理を行うことができるようになりました。

## コアとなるコードの解説

変更された`Float64()`メソッドの主要なロジックは以下の通りです。

1.  **指数`e`と精度`p`の初期化**:
    - `e := x.exp - 1`: `big.Float`の指数`x.exp`は`0.5 <= m < 1.0`の仮数に対応するため、`1.0 <= m < 2.0`の`float64`仮数に対応する指数を得るために1を引きます。
    - `p := mbits + 1`: `float64`の正規化数のデフォルト精度（53ビット）を設定します。

2.  **非正規化数のための精度調整**:
    - `if e < emin`: 計算された指数`e`が`float64`の最小正規化指数`emin`（-1022）よりも小さい場合、その数値は非正規化数になる可能性があります。
    - `p -= emin - int(e)`: 非正規化数では、指数が小さくなるにつれて有効な仮数ビットが減少するため、精度`p`を調整します。例えば、`e`が`emin - 1`であれば、精度は1ビット減少します。
    - `if p < 1 { p = 1 }`: 精度が少なくとも1ビットであることを保証します。これは、非常に小さい数値がゼロに丸められるのを防ぎ、最小の非正規化数に正しく切り上げられるようにするために不可欠です。

3.  **`big.Float`の丸め**:
    - `var r Float; r.prec = uint32(p); r.Set(x)`: 調整された精度`p`を使用して、`big.Float`の丸め処理を行います。`r.Set(x)`は`x`を`r`にコピーし、`r`の精度`r.prec`に基づいて`r`を丸めます。このステップで、`big.Float`の内部表現が`float64`の精度に合うように調整されます。

4.  **オーバーフローチェック**:
    - `if r.form == inf { e = emax + 1 }`: 丸め処理の結果、`r`が無限大になった場合、後続のオーバーフローチェックで正しく処理されるように`e`を`emax + 1`に設定します。
    - `if e > emax`: 指数`e`が`float64`の最大指数`emax`（1023）を超えた場合、`math.Inf(±1)`を返してオーバーフローを処理します。

5.  **符号、バイアスされた指数、仮数の決定**:
    - `sign`: `x.neg`（負の数であるか）に基づいて符号ビットを設定します。
    - `bexp`, `mant`:
        - `if e < emin`: 非正規化数の場合。
            - `if e < dmin`: 指数`e`が`float64`の最小非正規化指数`dmin`よりも小さい場合、アンダーフローとして`±0`を返します。
            - それ以外の場合（非正規化数だがアンダーフローではない場合）、`bexp`は0（非正規化数の指数は0として表現される）となり、`mant`は`high64(r.mant) >> (fbits - r.prec)`によって、`r.mant`から適切なビットをシフトして抽出されます。
        - `else`: 正規化数の場合。
            - `bexp = uint64(e+bias) << mbits`: バイアスされた指数を計算し、`mbits`だけ左シフトして`float64`の指数部の位置に配置します。
            - `mant = high64(r.mant) >> ebits & (1<<mbits - 1)`: `r.mant`から仮数ビットを抽出し、暗黙の1ビットを除去します。

6.  **最終的な`float64`値の構築**:
    - `return math.Float64frombits(sign | bexp | mant), r.acc`: 決定された符号、バイアスされた指数、仮数ビットを結合し、`math.Float64frombits()`関数を使って最終的な`float64`値を生成して返します。`r.acc`は丸めの精度情報です。

この一連の変更により、`Float64()`メソッドは、`float64`の表現範囲におけるすべての数値、特に非正規化数の丸め処理において、IEEE 754標準に準拠した正確な動作を保証するようになりました。
