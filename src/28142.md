# [インデックス 28142] ファイルの概要

このコミットは、Go言語のMIPS64xアーキテクチャ向けアセンブラおよびオブジェクトファイル生成ツールにおけるレジスタエイリアスの定義に関する変更です。具体的には、`RSB` (Static Base Register) のエイリアスを導入し、`R28`レジスタにマッピングすることで、レジスタの意図しない上書き（clobbering）を防ぐことを目的としています。

## 変更の背景

Goコンパイラおよびアセンブラは、特定のアーキテクチャ（この場合はMIPS64x）において、Goランタイムが内部的に使用する特別なレジスタに対して特定の慣習を持っています。例えば、`g` (現在のゴルーチン構造体へのポインタ) はMIPS64xでは`R30`レジスタにマッピングされています。このような特別なレジスタは、アセンブリコード内で明示的に参照されることもあれば、コンパイラによって暗黙的に使用されることもあります。

このコミットの背景には、`REGSB` (Static Base Register) の扱いに関する問題があったと考えられます。`REGSB`は、静的データへのアクセスに使用されるベースレジスタであり、MIPS64xアーキテクチャでは通常`R28`がこれに割り当てられます。しかし、Goのアセンブラが`R28`を汎用レジスタとして扱ってしまうと、`REGSB`として期待される`R28`の内容が意図せず上書きされてしまう（clobbering）可能性があります。これは、Goランタイムの安定性や正確性に影響を与える重大な問題となり得ます。

この変更は、`g`レジスタ（`R30`）が意図せず上書きされるのを防ぐために`g`というエイリアスが導入されたのと同様に、`REGSB`（`R28`）も同様に保護する必要があるという認識から行われました。これにより、アセンブラが`R28`を特別な意味を持つレジスタとして認識し、その使用を適切に管理できるようになります。

## 前提知識の解説

*   **MIPS64xアーキテクチャ**: MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64xは64ビット版のMIPSアーキテクチャで、組み込みシステムやネットワーク機器などで広く利用されています。レジスタセットは32個の汎用レジスタ（R0-R31）と浮動小数点レジスタなどから構成されます。
*   **Goアセンブラ (`cmd/asm`)**: Go言語は、一部のパフォーマンスクリティカルな部分や、特定のハードウェア機能にアクセスするためにアセンブリ言語を使用します。Goのアセンブラは、一般的なアセンブラとは異なる独自の構文（Plan 9アセンブラ構文）を使用します。`cmd/asm`は、このGoアセンブリコードをオブジェクトファイルにコンパイルするツールです。
*   **Goオブジェクトファイル (`cmd/internal/obj/mips`)**: Goコンパイラは、各ソースファイルをオブジェクトファイルにコンパイルします。`cmd/internal/obj/mips`パッケージは、MIPSアーキテクチャ向けのオブジェクトファイル生成に関する定義やユーティリティを提供します。これには、レジスタの定義や命令セットの定義などが含まれます。
*   **レジスタエイリアス**: 特定のレジスタに、そのレジスタの役割や用途を示す別の名前（エイリアス）を付けることです。これにより、コードの可読性が向上し、またコンパイラやアセンブラがそのレジスタを特別に扱うべきであることを示すことができます。
*   **レジスタのClobbering**: プログラムの実行中に、あるレジスタに格納されている値が、意図せず別の操作によって上書きされてしまうことです。これはバグの原因となり、特にコンパイラやアセンブラがレジスタの使用を最適化する際に注意が必要です。
*   **Static Base Register (SB)**: 静的データセクションへのアクセスに使用されるベースレジスタ。MIPSアーキテクチャでは、通常`R28`がこの役割を担います。プログラムの静的変数やグローバル変数へのアクセスを効率化するために使用されます。
*   **Goroutine Pointer (g)**: Goランタイムにおいて、現在のゴルーチンに関する情報（スタックポインタ、スケジューラ情報など）を保持する`g`構造体へのポインタ。MIPS64xでは`R30`レジスタにマッピングされています。

## 技術的詳細

このコミットの技術的な核心は、MIPS64xアーキテクチャにおける`REGSB`レジスタの扱いを改善することにあります。

1.  **`REGSB`のレジスタ番号変更**:
    `src/cmd/internal/obj/mips/a.out.go`において、`REGSB`が`REG_R30`から`REG_R28`に変更されました。これは、MIPS64xのABI（Application Binary Interface）において、`R28`が静的データへのポインタ（GPレジスタ）として慣習的に使用されることに合わせた変更と考えられます。
    ```diff
    --- a/src/cmd/internal/obj/mips/a.out.go
    +++ b/src/cmd/internal/obj/mips/a.out.go
    @@ -187,7 +187,7 @@ const (
     
     	REGZERO  = REG_R0 /* set to zero */
     	REGSP    = REG_R29

    +	REGSB    = REG_R28
     	REGLINK  = REG_R31
     	REGRET   = REG_R1
     	REGARG   = -1      /* -1 disables passing the first argument in register */
    ```

2.  **アセンブラにおける`RSB`エイリアスの追加**:
    `src/cmd/asm/internal/arch/arch.go`において、MIPS64xアーキテクチャのアセンブラが認識するレジスタマップに`RSB`というエイリアスが追加され、`mips.REG_R28`（つまり`R28`）にマッピングされました。これにより、アセンブリコード内で`RSB`というシンボルを使用できるようになります。
    同時に、`R28`が汎用レジスタとして誤って扱われることを防ぐため、`delete(register, "R28")`が実行されています。これは、`g`レジスタ（`R30`）の保護と同様のアプローチです。

3.  **アセンブラの出力文字列変換の更新**:
    `src/cmd/internal/obj/mips/list0.go`において、レジスタ番号を文字列に変換する`Rconv`関数が更新され、`REGSB`（`R28`）が渡された場合に`"RSB"`という文字列を返すようになりました。これにより、デバッグ出力やアセンブリリストにおいて、`R28`が`RSB`として表示され、その役割が明確になります。

## コアとなるコードの解説

このコミットの主要な変更は、MIPS64xアーキテクチャにおける`REGSB`（Static Base Register）の定義と、それに関連するアセンブラの挙動の調整です。

1.  **`src/cmd/internal/obj/mips/a.out.go` の変更**:
    `REGSB`が`REG_R30`から`REG_R28`に変更されました。これは、MIPS64xの一般的なABIにおいて、`R28`がグローバルポインタ（GP）レジスタとして静的データへのアクセスに使用される慣習に合わせたものです。Goランタイムがこの慣習に従うことで、より標準的なMIPS64xコードとの互換性や、既存のツールチェーンとの連携がスムーズになる可能性があります。

2.  **`src/cmd/asm/internal/arch/arch.go` の変更**:
    `archMips64`関数は、MIPS64xアーキテクチャ向けのアセンブラのレジスタ定義を初期化します。ここで、`R28`が汎用レジスタとして扱われることを防ぐために`delete(register, "R28")`が呼び出され、その後に`register["RSB"] = mips.REG_R28`として`RSB`というエイリアスが`R28`に割り当てられています。
    このパターンは、既に`g`（ゴルーチンポインタ）が`R30`に割り当てられ、`R30`が汎用レジスタリストから削除されているのと同様です。これにより、アセンブラは`R28`を単なる汎用レジスタではなく、`RSB`という特別な意味を持つレジスタとして認識し、その使用を適切に管理できるようになります。これにより、`R28`が意図せず上書きされる「clobbering」を防ぎ、静的データへのアクセスが常に安定して行われることを保証します。

3.  **`src/cmd/internal/obj/mips/list0.go` の変更**:
    `Rconv`関数は、レジスタ番号を人間が読める文字列形式に変換するために使用されます。この変更により、`REGSB`（`R28`）が渡された場合に`"RSB"`という文字列が返されるようになりました。これは、アセンブリリストやデバッグ出力において、`R28`が`RSB`として表示されることを意味し、開発者がコードを理解しやすくなります。`g`レジスタが`"g"`と表示されるのと同様の目的です。

4.  **`src/cmd/asm/internal/asm/operand_test.go` の変更**:
    テストケースの更新は、上記のアセンブラの変更が正しく機能することを確認するためのものです。`R28`が汎用レジスタとして認識されなくなったため、そのテストケースは削除され、代わりに新しく導入された`RSB`エイリアスのテストケースが追加されました。これにより、アセンブラが`RSB`を正しくパースし、`R28`にマッピングできることが検証されます。

これらの変更は、MIPS64xアーキテクチャにおけるGoランタイムのレジスタ管理をより堅牢にし、静的データへのアクセスの一貫性と正確性を保証するために不可欠です。
