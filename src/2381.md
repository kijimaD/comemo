## 元コミット内容

このコミットは、Go言語の `syscall` パッケージに、Linux 386アーキテクチャ用の機械生成されたファイル群を追加します。これらのファイルは、LinuxカーネルのシステムコールインターフェースをGo言語から利用するための低レベルなバインディングを提供します。具体的には、システムコール番号、エラーコード、システムコール関数ラッパー、およびシステムコールで使用されるC言語のデータ構造に対応するGoの型定義が含まれています。

## 変更の背景

Go言語は、その設計思想の一つとして、異なるオペレーティングシステムやアーキテクチャ上での高い移植性を持っています。これを実現するためには、各プラットフォームの低レベルな機能（システムコール）にアクセスするための抽象化レイヤーが必要です。`syscall` パッケージは、この目的のために存在します。

このコミットが行われた時期はGo言語の初期開発段階であり、様々なOSとアーキテクチャへの対応を進めている最中でした。Linux 386は当時広く利用されていたアーキテクチャの一つであり、Goがこのプラットフォームで動作するためには、Linux 386固有のシステムコールインターフェースを定義する必要がありました。

手動でこれらの低レベルなバインディングを作成することは、膨大な作業量とエラーの可能性を伴います。そのため、LinuxカーネルのヘッダーファイルからGoのコードを自動生成するツール（`mksyscall`、`godefs`など）が開発され、このコミットはそのツールによって生成された結果をリポジトリに追加するものです。これにより、正確性と保守性が向上し、Go言語のクロスプラットフォーム対応が効率的に進められました。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下の概念に関する知識が役立ちます。

*   **システムコール (System Call)**:
    アプリケーションプログラムがオペレーティングシステムカーネルにサービスを要求するためのインターフェースです。ファイルI/O、プロセス管理、メモリ管理など、OSが提供するほとんどの機能はシステムコールを通じて利用されます。ユーザーモードのプログラムが直接ハードウェアにアクセスできないため、システムコールはOSの保護された機能への唯一のゲートウェイとなります。

*   **Go言語の `syscall` パッケージ**:
    Goの標準ライブラリの一部であり、オペレーティングシステムのプリミティブな関数（システムコール）への低レベルなアクセスを提供します。`os` や `net` といった高レベルなパッケージも、内部的にはこの `syscall` パッケージを利用してOSと対話しています。このパッケージは、OS固有の定数、データ構造、およびシステムコールを呼び出すための関数を提供します。

*   **Linuxカーネルのシステムコールインターフェース**:
    Linuxカーネルは、各アーキテクチャ（例: x86, x86-64, ARM）に対して異なるシステムコールインターフェースを持っています。これには、システムコール番号（各システムコールを一意に識別する整数値）、引数の渡し方、戻り値の処理などが含まれます。32ビットx86 (i386) アーキテクチャでは、通常 `int 0x80` 命令や `sysenter` 命令を使用してシステムコールが呼び出され、引数はレジスタを介して渡されます。

*   **エラー番号 (errno)**:
    システムコールが失敗した場合、その原因を示すために返される整数値です。Linuxでは、これらのエラー番号は `errno.h` などのヘッダーファイルで定義されており、`EACCES` (Permission denied) や `EINVAL` (Invalid argument) など、様々なエラー条件に対応する定数が存在します。

*   **Goの `unsafe` パッケージ**:
    Go言語は通常、厳格な型安全性を提供しますが、`unsafe` パッケージを使用すると、ポインタ演算や型変換など、低レベルなメモリ操作が可能になります。システムコールでは、Goのデータ構造をC言語の期待するメモリレイアウトに合わせたり、生ポインタをカーネルに渡したりする必要があるため、`unsafe` パッケージが不可欠となります。

*   **コード生成 (Code Generation)**:
    ソースコードを自動的に生成するプロセスです。このコミットのように、OSのヘッダーファイルからGoのシステムコールバインディングを生成することで、手動での記述ミスを防ぎ、OSの変更に追従しやすくする利点があります。

## 技術的詳細

このコミットによって追加された4つのファイルは、Goの `syscall` パッケージがLinux 386環境で機能するために不可欠な要素を構成しています。

1.  **`src/lib/syscall/zerrors_linux_386.go`**:
    *   このファイルは、Linux 386アーキテクチャにおける標準的なエラー定数をGoの `const` として定義しています。例えば、`EACCES = 0xd` (13) や `EINVAL = 0x16` (22) など、Linuxカーネルのエラー番号に直接対応する値が割り当てられています。
    *   さらに、これらの数値エラーコードを人間が読める文字列にマッピングする `errors` という名前の `[...]string` 型の配列も含まれています。これにより、`syscall` パッケージを利用するGoプログラムは、システムコールが失敗した際に具体的なエラーメッセージを取得できます。
    *   ファイルの冒頭にある `// mkerrors` および `// godefs -gsyscall _errors.c` というコメントは、このファイルが `mkerrors` および `godefs` というツールによって、C言語のソースファイル（おそらくLinuxカーネルのエラー定義を含むもの）から自動生成されたものであることを示しています。

2.  **`src/lib/syscall/zsyscall_linux_386.go`**:
    *   このファイルは、Linux 386の各システムコールに対応するGoのラッパー関数を定義しています。例えば、`Read`、`Write`、`Open`、`Close`、`Chmod`、`Getcwd` など、多数のシステムコールがGoの関数として提供されています。
    *   これらのラッパー関数は、Goの型（`int`、`string`、`[]byte`、`*Struct` など）を引数として受け取り、Goの型を戻り値として返します。内部的には、`Syscall` または `Syscall6` という低レベルな関数を呼び出しています。
    *   `Syscall` および `Syscall6` は、システムコール番号と最大3つまたは6つの `uintptr` 型の引数を受け取ります。Goの文字列やバイトスライスをシステムコールに渡す際には、`unsafe.Pointer` を用いてGoの型安全性を一時的に迂回し、C言語のポインタとして扱えるように変換しています（例: `uintptr(unsafe.Pointer(StringBytePtr(path)))`）。
    *   システムコールからの戻り値は、通常 `r0`, `r1`, `e1` の3つで、それぞれ主要な戻り値、補助的な戻り値（多くの場合未使用）、エラーコードを表します。これらの値はGoの適切な型に変換されて返されます。
    *   `// mksyscall syscall_linux.go syscall_linux_386.go` というコメントは、`mksyscall` ツールがこのファイルを生成したことを示しています。

3.  **`src/lib/syscall/zsysnum_linux_386.go`**:
    *   このファイルは、Linux 386アーキテクチャにおける各システムコールの一意な識別子であるシステムコール番号をGoの `const` として定義しています。例えば、`SYS_READ = 3`、`SYS_WRITE = 4`、`SYS_OPEN = 5` などです。
    *   これらの定数は、`zsyscall_linux_386.go` 内のラッパー関数が `Syscall` や `Syscall6` を呼び出す際に、どのカーネル関数を実行すべきかを指定するために使用されます。
    *   `// Generated by mklinux; DO NOT EDIT.` および `// mklinux /usr/include/asm/unistd_32.h` というコメントから、このファイルが `mklinux` ツールによって、Linuxカーネルの `unistd_32.h` ヘッダーファイル（32ビットx86のシステムコール番号が定義されている）から生成されたことがわかります。

4.  **`src/lib/syscall/ztypes_linux_386.go`**:
    *   このファイルは、Linux 386システムコールで使用されるC言語のデータ構造に対応するGoの `struct` 型を定義しています。例えば、`Timespec` (時間構造体)、`Timeval` (時間値構造体)、`Stat_t` (ファイル統計情報構造体)、`Rusage` (リソース使用量構造体)、`EpollEvent` (epollイベント構造体) などがあります。
    *   これらのGoの `struct` は、C言語の対応する構造体とメモリレイアウトが一致するように設計されており、システムコールとの間でデータを正しくやり取りするために不可欠です。
    *   また、ファイルモード (`O_RDONLY`, `O_CREAT`)、ファイルディスクリプタフラグ (`FD_CLOEXEC`)、ソケットオプション (`AF_INET`, `SOCK_STREAM`)、`epoll` イベント (`EPOLLIN`, `EPOLL_CTL_ADD`) など、システムコールに関連する様々な定数も定義されています。
    *   `// godefs -gsyscall -f-m32 types_linux.c types_linux_386.c` というコメントは、`godefs` ツールがC言語の型定義からこれらのGoの型を生成したことを示しています。`f-m32` フラグは、32ビットアーキテクチャ向けの型定義であることを意味します。

これらの機械生成されたファイル群は、Go言語がLinux 386上で動作するための低レベルなインターフェースを網羅的に提供し、GoプログラムがOSの機能にアクセスする際の基盤を形成しています。

## コアとなるコードの解説

`zsyscall_linux_386.go` の `Read` システムコールラッパー関数を例に、コアとなるコードの動作を解説します。

```go
func Read(fd int, p []byte) (n int, errno int) {
	var _p0 *byte;
	if len(p) > 0 { _p0 = &p[0]; } // バイトスライスpの先頭要素への生ポインタを取得
	
	// SYS_READ システムコールを呼び出す
	// 引数:
	//   1. SYS_READ: readシステムコールの番号 (zsysnum_linux_386.goで定義)
	//   2. uintptr(fd): ファイルディスクリプタ
	//   3. uintptr(unsafe.Pointer(_p0)): バッファのメモリアドレス (unsafe.Pointerで型安全性を迂回)
	//   4. uintptr(len(p)): バッファの長さ
	r0, r1, e1 := Syscall(SYS_READ, uintptr(fd), uintptr(unsafe.Pointer(_p0)), uintptr(len(p)));
	
	// システムコールからの戻り値をGoの型に変換
	n = int(r0);    // 読み込んだバイト数
	errno = int(e1); // エラーコード
	return;
}
```

1.  **`func Read(fd int, p []byte) (n int, errno int)`**:
    Go言語の `Read` 関数として定義されており、ファイルディスクリプタ `fd` と、読み込んだデータを格納するバイトスライス `p` を引数に取ります。戻り値は、実際に読み込んだバイト数 `n` と、システムコールが失敗した場合のエラーコード `errno` です。

2.  **`var _p0 *byte; if len(p) > 0 { _p0 = &p[0]; }`**:
    Goのバイトスライス `p` は、連続したメモリ領域を指しますが、システムコールはC言語スタイルの生ポインタ（メモリのアドレス）を期待します。この行では、`p` が空でない場合に、スライスの最初の要素のアドレスを `_p0` という `*byte` 型のポインタとして取得しています。

3.  **`r0, r1, e1 := Syscall(SYS_READ, uintptr(fd), uintptr(unsafe.Pointer(_p0)), uintptr(len(p)))`**:
    これが実際のシステムコール呼び出しです。
    *   `Syscall`: `syscall` パッケージが提供する低レベルな関数で、カーネルにシステムコールを要求します。
    *   `SYS_READ`: `zsysnum_linux_386.go` で定義されている `read` システムコールの数値IDです。Linux 386では `3` に対応します。
    *   `uintptr(fd)`: ファイルディスクリプタ `fd` を `uintptr` 型に変換して渡します。`uintptr` はポインタを保持できる整数型です。
    *   `uintptr(unsafe.Pointer(_p0))`: `_p0` はGoのポインタですが、これを `unsafe.Pointer` に変換し、さらに `uintptr` に変換することで、Goの型システムを迂回して生のメモリアドレスとしてカーネルに渡します。これにより、カーネルは指定されたメモリ領域にデータを書き込むことができます。
    *   `uintptr(len(p))`: 読み込む最大バイト数（バッファの長さ）を `uintptr` 型に変換して渡します。
    *   `r0`, `r1`, `e1`: `Syscall` 関数は、システムコールの結果として3つの値を返します。`r0` は通常、システムコールの主要な戻り値（この場合は読み込んだバイト数）、`r1` は補助的な戻り値（多くの場合未使用）、`e1` はエラーが発生した場合のエラーコードです。

4.  **`n = int(r0); errno = int(e1); return;`**:
    システムコールから返された `uintptr` 型の `r0` と `e1` を、Goの `int` 型に変換し、それぞれ `n` と `errno` に代入して関数から返します。

この一連の処理は、Goの型安全な世界と、OSカーネルが期待するC言語スタイルの低レベルなインターフェースとの間の橋渡しをしています。他のシステムコールラッパー関数も、同様のパターンで実装されています。
