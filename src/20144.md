# [インデックス 20144] ファイルの概要

このコミットは、Goランタイムの`amd64p32`アーキテクチャ向けに`atomicor8`という新しいアトミック操作を追加するものです。具体的には、`src/pkg/runtime/asm_amd64p32.s`ファイルに8バイトのビット単位OR操作をアトミックに実行するアセンブリコードが追加されています。

## コミット

このコミットは、Goランタイムが特定のアーキテクチャ（この場合は`amd64p32`）上で、共有メモリに対するビット単位のOR操作をスレッドセーフかつ効率的に実行できるようにするためのものです。アトミック操作は、複数のゴルーチン（またはスレッド）が同時に同じメモリ位置にアクセスしようとしたときに、データ競合を防ぎ、操作が不可分（中断されない）であることを保証するために不可欠です。

## 変更の背景

Goランタイムは、様々なアーキテクチャとオペレーティングシステムをサポートしています。それぞれのプラットフォームで最適なパフォーマンスと正確性を保証するためには、低レベルのアセンブリコードで特定のアトミック操作を実装する必要がある場合があります。

このコミットの背景には、`amd64p32`という特定のアーキテクチャにおけるアトミックなビット単位OR操作の必要性があります。`amd64p32`は、64ビットのx86-64命令セットを使用しながら、ポインタサイズが32ビットであるという特徴を持つ環境を指します。これは、例えば一部の組み込みシステムや、メモリ使用量を抑えたい特定のLinuxディストリビューションなどで見られる構成です。このような環境でGoプログラムが正しく動作し、特にガベージコレクションやスケジューラなどのランタイム内部処理がデータ競合なく実行されるためには、`atomicor8`のような基本的なアトミック操作が不可欠となります。

既存のGoランタイムには、他のアトミック操作（例: `atomicstore64`など）が既に存在していましたが、`amd64p32`環境での8ビット（バイト）のアトミックOR操作が欠けていたため、このコミットで追加されました。これにより、`amd64p32`環境におけるGoランタイムの堅牢性と互換性が向上します。

## 前提知識の解説

### 1. アトミック操作 (Atomic Operations)

アトミック操作とは、複数のスレッド（またはゴルーチン）から同時にアクセスされた場合でも、その操作全体が不可分（中断されない）であることを保証する操作です。つまり、操作の途中で他のスレッドが介入して状態を不正に読み取ったり変更したりすることがありません。これにより、並行処理におけるデータ競合（data race）を防ぎ、プログラムの正確性を保証します。

Go言語では、`sync/atomic`パッケージを通じて高レベルのアトミック操作が提供されていますが、その内部ではCPUの提供するアトミック命令（例: `LOCK`プレフィックス付きの命令）や、より低レベルなアセンブリコードが利用されています。

### 2. `amd64p32` アーキテクチャ

`amd64p32`は、x86-64（AMD64）命令セットを使用するが、ポインタのサイズが32ビットであるシステムを指します。通常のx86-64システムではポインタは64ビットですが、`amd64p32`はメモリ消費を抑える目的などで使用されることがあります。これは、Linuxのx32 ABI（Application Binary Interface）などに見られる特徴です。Goランタイムは、このような特定のABIやアーキテクチャのバリエーションにも対応するために、専用のアセンブリコードを持つことがあります。

### 3. Goのアセンブリ言語 (`.s`ファイル)

Go言語は、そのランタイムの一部や、特定のパフォーマンスが要求される箇所でアセンブリ言語を使用します。Goのアセンブリは、Plan 9アセンブリの文法に基づいており、一般的なIntelやAT&Tのアセンブリ文法とは異なります。

*   **`TEXT`**: 関数の開始を宣言します。
*   **`NOSPLIT`**: この関数がスタックを分割しないことを示します。つまり、関数呼び出し時にスタックの拡張チェックを行いません。これは、非常に短い関数や、スタックの拡張が不要な低レベルの関数で使われます。
*   **`SB` (Static Base)**: グローバルシンボルや静的データへの参照に使われる擬似レジスタです。
*   **`FP` (Frame Pointer)**: 関数の引数やローカル変数への参照に使われる擬似レジスタです。
*   **`MOVL`**: 32ビットの値を移動する命令です。
*   **`MOVB`**: 8ビット（バイト）の値を移動する命令です。
*   **`LOCK` プレフィックス**: x86アーキテクチャにおける重要なプレフィックスで、続く命令がアトミックに実行されることを保証します。これは、マルチプロセッサ環境でメモリ操作の不可分性を保証するために、バスロックやキャッシュコヒーレンシプロトコルを利用します。
*   **`ORB`**: ビット単位のOR操作を実行する命令です。オペランドはバイトサイズです。
*   **`RET`**: 関数からのリターン命令です。

## 技術的詳細

このコミットは、`amd64p32`アーキテクチャ向けに`runtime·atomicor8`というアトミック操作を実装しています。この関数は、指定されたメモリ位置のバイト値と、与えられたバイト値をビット単位でOR演算し、その結果をアトミックにメモリに書き戻します。

Goランタイムでは、ガベージコレクタのマークビット操作や、スケジューラの状態管理など、様々な場所でアトミック操作が必要とされます。特に、複数のゴルーチンが共有するフラグやカウンタを更新する際に、データ破損を防ぐためにアトミックな読み書きや変更が不可欠です。

`atomicor8`は、以下のようなシグネチャを持つC言語風の関数として定義されています（GoのアセンブリではC言語の規約に似た呼び出し規約が使われます）：

```c
// void runtime·atomicor8(byte volatile* ptr, byte val);
```

*   `ptr`: OR操作の対象となるバイトへのポインタ。`volatile`キーワードは、コンパイラがこのメモリ位置へのアクセスを最適化しないように指示し、常にメモリから読み書きすることを保証します。
*   `val`: OR演算で適用されるバイト値。

このアセンブリコードは、`LOCK`プレフィックスを使用することで、マルチコアプロセッサ環境下でもこのOR操作が不可分であることを保証しています。`LOCK`プレフィックスは、CPUがこの命令を実行する際に、他のCPUコアからのメモリアクセスを一時的にブロックするか、キャッシュコヒーレンシプロトコル（MESIプロトコルなど）を利用して、操作対象のメモリ領域に対する排他的なアクセス権を確保します。これにより、複数のCPUが同時に同じバイトを更新しようとしても、一つずつ順番に処理され、最終的な結果が正しくなります。

変更は`src/pkg/runtime/asm_amd64p32.s`ファイルに集中しており、以下の8行が追加されています。


## コアとなるコードの解説

追加されたアセンブリコードは、`runtime·atomicor8`関数の実装です。

1.  `TEXT runtime·atomicor8(SB), NOSPLIT, $0-8`:
    *   `TEXT runtime·atomicor8(SB)`: `runtime·atomicor8`という名前の関数を定義します。`SB`は静的ベースレジスタで、グローバルシンボルを参照するために使われます。
    *   `NOSPLIT`: この関数がスタックを拡張しないことを示します。これは、関数が非常に短く、スタックフレームのセットアップが不要な場合にパフォーマンスを向上させます。
    *   `$0-8`: この関数のスタックフレームサイズが0バイトであり、引数が合計8バイトであることを示します。Goのアセンブリでは、引数はスタック上に配置され、`FP`（フレームポインタ）からのオフセットでアクセスされます。

2.  `MOVL ptr+0(FP), BX`:
    *   `ptr+0(FP)`: 関数`atomicor8`の最初の引数である`ptr`（バイトポインタ）を指します。`FP`はフレームポインタで、`+0`は引数がスタックフレームの先頭から0バイトのオフセットにあることを意味します。
    *   `BX`: `ptr`の値を`BX`レジスタに移動します。`BX`は、OR操作の対象となるメモリアドレスを保持するために使用されます。`MOVL`は32ビット移動命令であり、`amd64p32`環境ではポインタが32ビットであるため、これで十分です。

3.  `MOVB val+4(FP), AX`:
    *   `val+4(FP)`: 関数`atomicor8`の2番目の引数である`val`（バイト値）を指します。`+4`は、最初の引数`ptr`が4バイト（32ビットポインタ）を占めるため、その次のオフセットに`val`があることを意味します。
    *   `AX`: `val`の値を`AX`レジスタに移動します。`AX`は、OR操作のソースオペランドとして使用されます。`MOVB`は8ビット移動命令であり、バイト値を扱うのに適しています。

4.  `LOCK`:
    *   このプレフィックスは、次の命令（`ORB`）がアトミックに実行されることを保証します。マルチプロセッサシステムにおいて、この命令が実行されている間、他のプロセッサが同じメモリ位置にアクセスするのを防ぎます。これは、バスロックやキャッシュコヒーレンシメカニズムを通じて実現されます。

5.  `ORB AX, 0(BX)`:
    *   `ORB`: ビット単位のOR操作を実行します。オペランドはバイトサイズです。
    *   `AX`: ソースオペランド。`val`の値が格納されています。
    *   `0(BX)`: デスティネーションオペランド。`BX`レジスタが指すメモリアドレス（`ptr`が指す場所）の0オフセットにあるバイトを指します。
    *   この命令は、`BX`が指すメモリ位置のバイト値と`AX`レジスタのバイト値のビット単位ORを計算し、その結果を`BX`が指すメモリ位置に書き戻します。`LOCK`プレフィックスにより、この読み取り-変更-書き込みサイクル全体がアトミックに実行されます。

6.  `RET`:
    *   関数から呼び出し元に戻ります。

このコードは、`amd64p32`環境において、Goランタイムが共有メモリ上のバイト値を安全かつ効率的に更新するための基本的なプリミティブを提供します。
