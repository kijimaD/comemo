# [インデックス 2804] ファイルの概要

このコミットは、Go言語の初期の評価（`eval`）パッケージにおいて、基本的な制御フロー文である`if`、`for`（`range`を除く）、`break`、`continue`、そしてインクリメント/デクリメント演算子（`++`、`--`）の実装を追加するものです。これにより、`eval`パッケージがより複雑なGoコードを解釈・実行できるようになるための基盤が強化されました。特に、スコープのネストを模倣し、`break`および`continue`のジャンプ先を追跡するための`blockCompiler`の構造が大幅に改善されています。

## 変更の背景

このコミットは、Go言語の初期段階における`eval`パッケージ（おそらくGoコードを動的に評価するための実験的なインタプリタまたはコンパイラコンポーネント）の機能拡張の一環として行われました。プログラミング言語において、`if`文による条件分岐、`for`文による繰り返し処理、そして`break`や`continue`によるループ制御は、プログラムのロジックを構築する上で不可欠な要素です。また、`++`や`--`といったインクリメント/デクリメント演算子も、数値操作の簡潔性を高めるために広く利用されます。

これらの基本的な制御フローと演算子を`eval`パッケージに実装することで、より複雑なGoコードスニペットの評価が可能になり、`eval`パッケージの有用性が大幅に向上します。特に、`blockCompiler`の改善は、これらの制御フロー文が持つスコープの概念と、`break`/`continue`がジャンプすべき正確な位置（プログラムカウンタ、PC）を正しく管理するために必要不可欠でした。これにより、言語のセマンティクスに沿った正確なコード実行が保証されます。

## 前提知識の解説

### Go言語のAST (Abstract Syntax Tree)

Goコンパイラやインタプリタは、ソースコードを直接扱うのではなく、まずその構造を抽象構文木（AST: Abstract Syntax Tree）というデータ構造に変換します。ASTは、ソースコードの構文構造を木構造で表現したもので、各ノードがプログラムの構成要素（式、文、宣言など）に対応します。このコミットで言及されている`ast.BlockStmt`、`ast.ExprStmt`、`ast.IncDecStmt`、`ast.BranchStmt`、`ast.IfStmt`、`ast.ForStmt`などは、`go/ast`パッケージで定義されているASTノードの型であり、それぞれGo言語のブロック、式文、インクリメント/デクリメント文、分岐文、if文、for文を表します。コンパイラやインタプリタは、このASTを走査してコードの解析や生成を行います。

### コンパイラ/インタプリタの基本

このコミットが対象としている`eval`パッケージは、Go言語のコードを評価するためのコンポーネントです。一般的に、コンパイラやインタプリタは以下の段階を経てコードを処理します。

1.  **字句解析 (Lexical Analysis)**: ソースコードをトークン（意味のある最小単位）のストリームに変換します。
2.  **構文解析 (Parsing)**: トークンのストリームからASTを構築します。
3.  **意味解析 (Semantic Analysis)**: ASTを走査し、型チェック、スコープ解決、名前解決などの意味的な正当性を検証します。
4.  **コード生成 (Code Generation)**: ASTまたは中間表現から、ターゲットマシン（この場合は仮想マシン）が実行できるコードを生成します。

このコミットは主に意味解析とコード生成の段階に関わっており、特に制御フロー文のコード生成ロジックを扱っています。

### スコープ (Scope)

スコープとは、プログラム内で変数が参照可能である範囲を定義するものです。Go言語では、ブロック（`{}`で囲まれた部分）ごとに新しいスコープが作成されます。このコミットでは、`blockCompiler`が`scope`を管理し、`enterChild()`や`exit()`といったメソッドを通じてスコープのネストを正確に追跡することで、変数の可視性とライフタイムを保証しています。

### プログラムカウンタ (PC)

プログラムカウンタ（PC）は、仮想マシンやインタプリタにおいて、次に実行すべき命令のアドレス（またはインデックス）を指し示すレジスタです。`break`や`continue`のような制御フロー文は、通常の逐次実行の流れを中断し、プログラムカウンタを特定の命令にジャンプさせることで動作します。このコミットでは、`blockCompiler`が`breakPC`と`continuePC`というフィールドを持つことで、現在のブロックにおける`break`や`continue`がジャンプすべき正確な位置を記憶し、制御フローを正しく誘導します。

### Go言語の制御フロー

*   **`if`文**: 条件式が真の場合にコードブロックを実行します。`else`節を持つこともできます。
*   **`for`文**: 条件式が真である間、または無限にコードブロックを繰り返し実行します。初期化文、条件式、後処理文を持つことができます。
*   **`break`文**: `for`、`switch`、`select`文などの最も内側のループまたは文を終了させます。
*   **`continue`文**: `for`ループの現在のイテレーションをスキップし、次のイテレーションに進みます。
*   **`++` (インクリメント)** / **`--` (デクリメント)**: 変数の値を1増やす/減らす単項演算子です。

### `bignum`パッケージ

`stmt.go`で`bignum`パッケージがインポートされています。これは、任意精度の整数を扱うためのパッケージです。Go言語の組み込み整数型は固定ビット幅ですが、コンパイラやインタプリタの内部処理、特に定数式評価や型推論において、より大きな数値を扱う必要がある場合に`bignum`のようなパッケージが利用されます。このコミットでは、インクリメント/デクリメント演算子の実装において、`IdealIntType`（理想的な整数型）の`1`を表現するために使用されています。

## 技術的詳細

このコミットの主要な技術的変更点は、`blockCompiler`の拡張と、それを利用した`if`、`for`、`break`、`continue`、`++`、`--`の実装です。

### `blockCompiler`の役割と拡張

`blockCompiler`は、Goコードのブロック（`{}`で囲まれた部分）をコンパイルする際のコンテキストを管理する構造体です。このコミットにより、以下のフィールドが追加され、その役割が大幅に強化されました。

*   `breakPC *uint`: 現在のブロック内で`break`文が実行された場合にジャンプすべきプログラムカウンタ（PC）を指します。`break`が許可されていないブロックでは`nil`になります。
*   `continuePC *uint`: 現在のブロック内で`continue`文が実行された場合にジャンプすべきPCを指します。`continue`が許可されていないブロックでは`nil`になります。
*   `parent *blockCompiler`: この`blockCompiler`を囲む親ブロックの`blockCompiler`へのポインタです。これにより、`blockCompiler`のツリー構造が形成され、スコープのネストが模倣されます。
*   `child *blockCompiler`: 現在コンパイル中のネストされた子ブロックの`blockCompiler`へのポインタです。

これらのフィールドにより、`blockCompiler`はスコープの階層構造を正確に表現し、`break`や`continue`がどのループやスイッチ文に属するかを判断できるようになります。

### `blockCompiler`の新しいメソッド

*   `func (a *blockCompiler) compileStmt(s ast.Stmt)`: 単一のASTステートメントをコンパイルします。
*   `func (a *blockCompiler) compileStmts(body *ast.BlockStmt)`: `ast.BlockStmt`内の複数のステートメントを順にコンパイルします。以前の`compileBlock`を置き換えるものです。
*   `func (a *blockCompiler) enterChild() *blockCompiler`: 新しい子`blockCompiler`を作成し、現在の`blockCompiler`の子として設定します。これにより、新しいスコープが作成され、仮想マシンのフレームスタックに新しいフレームがプッシュされます。
*   `func (a *blockCompiler) exit()`: 現在の`blockCompiler`を終了し、親`blockCompiler`に戻ります。仮想マシンのフレームスタックから現在のフレームをポップします。

これらのメソッドは、スコープの出入りと`blockCompiler`ツリーの管理をカプセル化し、制御フロー文の実装を簡潔にしています。

### `if`ステートメントの実装 (`DoIfStmt`)

`if`文のコンパイルは以下のステップで行われます。

1.  `bc.enterChild()`で新しい子ブロックに入り、`defer bc.exit()`で終了時に確実に抜けるようにします。これにより、`if`文内で宣言された変数のスコープが正しく管理されます。
2.  `s.Init`（初期化文）があればコンパイルします。
3.  `elsePC`と`endPC`という2つのプログラムカウンタのプレースホルダーを準備します。これらは、条件が偽の場合に`else`節にジャンプするため、または`if-else`ブロック全体をスキップするために使用されます。
4.  `s.Cond`（条件式）をコンパイルし、その結果がブーリアン型であることを確認します。
5.  条件式が偽の場合に`elsePC`にジャンプする命令を生成します。
6.  `if`の本体（`s.Body`）をコンパイルします。ここでも`enterChild()`と`exit()`を使ってスコープを管理します。
7.  `s.Else`（`else`節）があれば、`if`本体の実行後に`endPC`にジャンプする命令を生成し、その後に`else`節をコンパイルします。`elsePC`は`else`節の開始位置に設定されます。
8.  `endPC`は`if`文全体の終了位置に設定されます。

### `for`ステートメントの実装 (`DoForStmt`)

`for`文のコンパイルはより複雑で、以下のステップで行われます。

1.  `s.Init`（初期化文）があれば、新しい子ブロックに入ってコンパイルします。
2.  `bodyPC`、`checkPC`、`endPC`という3つのプログラムカウンタのプレースホルダーを準備します。
3.  まず`checkPC`にジャンプする命令を生成します。これは、`for`ループの条件チェックがループ本体の後に配置されるためです。
4.  `bodyPC`をループ本体の開始位置に設定し、ループ本体をコンパイルします。ここで重要なのは、ループ本体の`blockCompiler`の`breakPC`を`&endPC`に、`continuePC`を`&checkPC`に設定することです。これにより、ループ内の`break`はループ全体を終了させ、`continue`は条件チェックにジャンプするようになります。
5.  `s.Post`（後処理文）があればコンパイルします。
6.  `checkPC`を条件チェックの開始位置に設定し、`s.Cond`（条件式）をコンパイルします。条件式がなければ無限ループと見なされ、常に`bodyPC`にジャンプします。
7.  条件式が真の場合に`bodyPC`にジャンプする命令を生成します。
8.  `endPC`を`for`文全体の終了位置に設定します。

### `inc/dec`ステートメントの実装 (`DoIncDecStmt`)

インクリメント/デクリメント演算子（`++`、`--`）のコンパイルは以下のステップで行われます。

1.  対象となる式`s.X`をコンパイルし、それがアドレス指定可能（代入可能）であることを確認します。
2.  対象の型が整数または浮動小数点数であることを確認します。
3.  `bignum.Int(1)`を使用して、値`1`を表す式を作成します。これは`IdealIntType`として扱われます。
4.  `s.Tok`（`token.INC`または`token.DEC`）に応じて、`token.ADD`または`token.SUB`演算子を選択します。
5.  元の式と`1`に対して二項演算（加算または減算）を適用する式を作成します。
6.  この結果を元の式に代入するコンパイル済み関数を生成します。
7.  最終的に、仮想マシン上でこの代入を実行する命令をプッシュします。

### `break`/`continue`ステートメントの実装 (`DoBranchStmt`)

`break`と`continue`文のコンパイルは、`blockCompiler`のツリー構造を活用します。

1.  現在の`blockCompiler`から開始し、`parent`ポインタをたどって親ブロックを順に遡ります。
2.  `break`文の場合、`breakPC`が`nil`でない最初の`blockCompiler`を見つけます。見つかった場合、その`breakPC`にジャンプする命令を生成します。
3.  `continue`文の場合、`continuePC`が`nil`でない最初の`blockCompiler`を見つけます。見つかった場合、その`continuePC`にジャンプする命令を生成します。
4.  適切な`blockCompiler`が見つからなかった場合（例: ループの外で`break`が使用された場合）、エラーを報告します。

### `CompileStmt`から`CompileStmts`への変更

以前は単一のステートメントをコンパイルする`CompileStmt`関数がありましたが、このコミットにより、複数のステートメントのリストをコンパイルする`CompileStmts`関数が導入されました。これは、`blockCompiler`が複数のステートメントを効率的に処理できるようにするための変更であり、コンパイラの内部構造を簡素化します。

## コアとなるコードの解説

### `blockCompiler`の構造体変更 (`usr/austin/eval/compiler.go`)

```go
type blockCompiler struct {
	*funcCompiler;
	scope *Scope;
	returned bool;
	// The PC break statements should jump to, or nil if a break
	// statement is invalid.
	breakPC *uint;
	// The PC continue statements should jump to, or nil if a
	// continue statement is invalid.
	continuePC *uint;
	// The blockCompiler for the block enclosing this one, or nil
	// for a function-level block.
	parent *blockCompiler;
	// The blockCompiler for the nested block currently being
	// compiled, or nil if compilation is not in a nested block.
	child *blockCompiler;
}
```
`breakPC`と`continuePC`は、それぞれ`break`と`continue`がジャンプすべき命令のPCを保持します。ポインタ型であるため、ジャンプ先が未定の場合や無効な場合は`nil`を設定できます。`parent`と`child`は、`blockCompiler`インスタンスがツリー構造を形成し、スコープのネストを表現するために使用されます。これにより、`break`や`continue`がどの外側のループやスイッチ文に影響するかを正確に判断できるようになります。

### `blockCompiler`のスコープ管理メソッド (`usr/austin/eval/stmt.go`)

```go
func (a *blockCompiler) enterChild() *blockCompiler {
	if a.child != nil {
		log.Crash("Failed to exit child block before entering another child");
	}
	blockScope := a.scope.Fork(); // 新しいスコープを作成
	bc := &blockCompiler{
		funcCompiler: a.funcCompiler,
		scope: blockScope,
		returned: false,
		parent: a, // 親を設定
	};
	a.child = bc; // 現在のブロックの子として設定
	a.push(func(v *vm) {
		v.f = blockScope.NewFrame(v.f); // VMのフレームスタックに新しいフレームをプッシュ
	});
	return bc;
}

func (a *blockCompiler) exit() {
	if a.parent == nil {
		log.Crash("Cannot exit top-level block");
	}
	if a.parent.child != a {
		log.Crash("Double exit of block");
	}
	if a.child != nil {
		log.Crash("Exit of parent block without exit of child block");
	}
	a.push(func(v *vm) {
		v.f = v.f.Outer; // VMのフレームスタックから現在のフレームをポップ
	});
	a.parent.child = nil; // 親ブロックから子ブロックの参照を解除
}
```
`enterChild()`は、新しいブロック（例えば`if`文の本体や`for`ループの本体）に入る際に呼び出され、新しい`blockCompiler`インスタンスを作成し、スコープをフォーク（複製）して新しいVMフレームをプッシュします。`exit()`は、ブロックを抜ける際に呼び出され、VMフレームをポップし、親ブロックとの関係を解除します。これらのメソッドは、スコープのライフタイムとVMの実行コンテキストを正確に管理するために重要です。

### `DoIncDecStmt`の実装 (`usr/austin/eval/stmt.go`)

```go
func (a *stmtCompiler) DoIncDecStmt(s *ast.IncDecStmt) {
	l := a.compileExpr(a.scope, s.X, false);
	if l == nil { return; }

	if l.evalAddr == nil {
		l.diag("cannot assign to %s", l.desc);
		return;
	}
	if !(l.t.isInteger() || l.t.isFloat()) {
		l.diagOpType(s.Tok, l.t);
		return;
	}

	effect, l := l.extractEffect();

	one := l.copy();
	one.pos = s.Pos();
	one.t = IdealIntType;
	one.evalIdealInt = func() *bignum.Integer { return bignum.Int(1) }; // bignum.Int(1) を使用

	var op token.Token;
	switch s.Tok {
	case token.INC: op = token.ADD;
	case token.DEC: op = token.SUB;
	default: log.Crashf("Unexpected IncDec token %v", s.Tok);
	}

	binop := l.copy();
	binop.pos = s.Pos();
	binop.doBinaryExpr(op, l, one); // 二項演算として処理
	if binop.t == nil { return; }

	assign := a.compileAssign(s.Pos(), l.t, []*exprCompiler{binop}, "", "");
	if assign == nil { log.Crashf("compileAssign type check failed"); }

	lf := l.evalAddr;
	a.push(func(v *vm) {
		effect(v.f);
		assign(lf(v.f), v.f); // 結果を元の変数に代入
	});
	a.err = false;
}
```
このコードは、`++`や`--`演算子を、対象の変数に`1`を加算または減算し、その結果を再度変数に代入するという一連の操作としてコンパイルします。`bignum.Int(1)`を使用して、任意精度の整数`1`を表現している点が注目されます。これにより、`int`や`float`だけでなく、将来的に`bignum`で表現されるような大きな数値型に対してもインクリメント/デクリメントが正しく機能するよう設計されています。

### `DoBranchStmt`の実装 (`usr/austin/eval/stmt.go`)

```go
func (a *stmtCompiler) DoBranchStmt(s *ast.BranchStmt) {
	switch s.Tok {
	case token.BREAK:
		// ... (ラベル付きbreakは未実装)
		bc := a.blockCompiler;
		for ; bc != nil; bc = bc.parent { // 親ブロックを遡る
			if bc.breakPC != nil { // breakPCが設定されているブロックを見つける
				pc := bc.breakPC;
				a.push(func(v *vm) { v.pc = *pc }); // そのPCにジャンプする命令を生成
				a.err = false;
				return;
			}
		}
		a.diag("break outside for loop, switch, or select"); // 見つからなければエラー
	case token.CONTINUE:
		// ... (ラベル付きcontinueは未実装)
		bc := a.blockCompiler;
		for ; bc != nil; bc = bc.parent { // 親ブロックを遡る
			if bc.continuePC != nil { // continuePCが設定されているブロックを見つける
				pc := bc.continuePC;
				a.push(func(v *vm) { v.pc = *pc }); // そのPCにジャンプする命令を生成
				a.err = false;
				return;
			}
		}
		a.diag("continue outside for loop"); // 見つからなければエラー
	// ... (goto, fallthroughは未実装)
	}
}
```
`break`と`continue`の実装は、`blockCompiler`の`parent`ポインタをたどって、最も内側の適切な`breakPC`または`continuePC`を見つけることで行われます。これにより、ネストされたループやスイッチ文において、`break`や`continue`が意図したとおりの制御フローを実現します。

### `DoIfStmt`の実装 (`usr/austin/eval/stmt.go`)

```go
func (a *stmtCompiler) DoIfStmt(s *ast.IfStmt) {
	bc := a.blockCompiler;
	bc = bc.enterChild(); // if文のスコープに入る
	defer bc.exit();     // if文を抜ける際にスコープを終了

	if s.Init != nil {
		bc.compileStmt(s.Init); // 初期化文をコンパイル
	}

	var elsePC, endPC uint;

	bad := false;
	if s.Cond != nil {
		e := bc.compileExpr(bc.scope, s.Cond, false);
		// ... (条件式の型チェック)
		eval := e.asBool();
		a.push(func(v *vm) {
			if !eval(v.f) {
				v.pc = elsePC; // 条件が偽ならelsePCにジャンプ
			}
		});
	}

	body := bc.enterChild(); // if本体のスコープに入る
	body.compileStmts(s.Body); // if本体をコンパイル
	body.exit();             // if本体のスコープを終了

	if s.Else != nil {
		a.push(func(v *vm) {
			v.pc = endPC; // if本体が実行されたらendPCにジャンプしてelseをスキップ
		});
		elsePC = a.nextPC(); // else節の開始PCを設定
		bc.compileStmt(s.Else); // else節をコンパイル
	} else {
		elsePC = a.nextPC(); // else節がない場合、if本体の直後がelsePC
	}
	endPC = a.nextPC(); // if文全体の終了PCを設定

	if !bad { a.err = false; }
}
```
`if`文は、条件式の評価結果に基づいてプログラムカウンタを操作することで実装されます。条件が偽の場合には`elsePC`にジャンプし、`else`節が存在する場合はそのコードを実行します。`else`節がない場合や`if`本体が実行された場合は、`endPC`にジャンプして`if`文全体をスキップします。`enterChild()`と`exit()`を適切に利用して、`if`文の初期化文や本体、`else`節のスコープが正しく管理されています。

### `DoForStmt`の実装 (`usr/austin/eval/stmt.go`)

```go
func (a *stmtCompiler) DoForStmt(s *ast.ForStmt) {
	bc := a.blockCompiler;
	if s.Init != nil {
		bc = bc.enterChild(); // 初期化文のスコープに入る
		defer bc.exit();     // 終了時にスコープを終了
		bc.compileStmt(s.Init); // 初期化文をコンパイル
	}

	var bodyPC, checkPC, endPC uint;

	a.push(func(v *vm) { v.pc = checkPC }); // まず条件チェックにジャンプ

	bodyPC = a.nextPC(); // ループ本体の開始PC
	body := bc.enterChild(); // ループ本体のスコープに入る
	body.breakPC = &endPC;   // ループ本体内のbreakはendPCにジャンプ
	body.continuePC = &checkPC; // ループ本体内のcontinueは条件チェックにジャンプ
	body.compileStmts(s.Body); // ループ本体をコンパイル
	body.exit();             // ループ本体のスコープを終了

	if s.Post != nil {
		bc.compileStmt(s.Post); // 後処理文をコンパイル
	}

	bad := false;
	checkPC = a.nextPC(); // 条件チェックの開始PC
	if s.Cond == nil {
		a.push(func(v *vm) { v.pc = bodyPC }); // 条件なしなら常にループ本体にジャンプ
	} else {
		e := bc.compileExpr(bc.scope, s.Cond, false);
		// ... (条件式の型チェック)
		eval := e.asBool();
		a.push(func(v *vm) {
			if eval(v.f) {
				v.pc = bodyPC; // 条件が真ならループ本体にジャンプ
			}
		});
	}

	endPC = a.nextPC(); // for文全体の終了PC

	if !bad { a.err = false; }
}
```
`for`文は、初期化、条件チェック、後処理、本体の各部分を適切に配置し、プログラムカウンタを操作することでループを実現します。特に重要なのは、ループ本体の`blockCompiler`の`breakPC`と`continuePC`を、それぞれループの終了位置（`endPC`）と条件チェックの位置（`checkPC`）に設定している点です。これにより、ループ内の`break`と`continue`が正しく機能します。
