# [インデックス 21559] ファイルの概要

このコミットは、Go言語のAndroidテスト実行スクリプトである `src/androidtest.bash` におけるファイル転送メカニズムの修正に関するものです。具体的には、Androidデバイスへのテスト関連ファイルの同期において、シンボリックリンクの使用から実際のファイルコピーへと変更することで、`adb sync` コマンドがシンボリックリンクを辿らないという問題を解決しています。

## 変更の背景

Go言語のAndroidテスト環境では、テストを実行するためにGoのソースコードやテストデータなどのリソースをAndroidデバイスに転送する必要があります。この転送には `adb sync` コマンドが使用されていました。

以前の実装では、ホストマシン上の `GOROOT` ディレクトリ内の `src`, `test`, `lib` などのディレクトリを、Androidデバイスに同期するための仮のディレクトリ構造 (`FAKE_GOROOT`) 内にシンボリックリンクとして配置していました。これは、`adb sync` がホスト上の `/system` または `/data` ディレクトリとAndroidデバイス上の対応するディレクトリを同期するという特性を利用し、`GOROOT` の内容を `/data/local/tmp/goroot` のサブディレクトリとして「偽装」するためでした。

しかし、このアプローチには根本的な問題がありました。`adb sync` コマンドはシンボリックリンクを辿ってその実体を同期する機能を持っていません。そのため、`FAKE_GOROOT` 内に作成されたシンボリックリンクは、Androidデバイス上では単なるシンボリックリンクとして転送されるか、あるいは転送自体が失敗し、結果としてテストに必要なファイルがデバイス上に正しく配置されないという問題が発生していました。

このコミットは、このシンボリックリンクの問題を解決し、テストが正しく実行されるようにするために、シンボリックリンクの作成を止め、代わりに実際のファイルをAndroidデバイスにコピーするように変更しました。

## 前提知識の解説

### Go言語のAndroidテスト環境

Go言語は、Androidアプリケーション開発をサポートしており、GoコードをAndroidデバイス上で実行したり、テストしたりすることが可能です。これには、GoコンパイラがAndroid向けのバイナリを生成する機能や、`go mobile` などのツールチェーンが関与します。テストを実行する際には、テストバイナリだけでなく、テストが依存するソースファイルやリソースファイルもデバイス上に存在する必要があります。

### `adb` (Android Debug Bridge)

`adb` は、Androidデバイスとコンピュータ間で通信を行うための多機能なコマンドラインツールです。開発者は `adb` を使用して、デバイスのログの表示、ファイルの転送、シェルコマンドの実行、アプリケーションのインストールなど、様々な操作を行うことができます。

*   **`adb push <local> <remote>`**: ホストコンピュータからAndroidデバイスへファイルをコピーします。
*   **`adb pull <remote> <local>`**: Androidデバイスからホストコンピュータへファイルをコピーします。
*   **`adb sync <directory>`**: ホストコンピュータの指定されたディレクトリとAndroidデバイスの対応するディレクトリ間でファイルを同期します。これは、`push` と `pull` を組み合わせて、両者の内容を一致させるように動作します。

重要な点として、`adb push` や `adb sync` は、デフォルトではシンボリックリンクを辿りません。つまり、ホスト側にシンボリックリンクが存在する場合、そのリンク先の実体ではなく、シンボリックリンク自体がデバイスにコピーされるか、あるいはエラーとなることが多いです。これは、ファイルシステム構造の整合性を保つため、またはセキュリティ上の理由によるものと考えられます。

### シンボリックリンク (Symbolic Links)

シンボリックリンク（またはソフトリンク）は、ファイルシステム内の別のファイルやディレクトリへの参照（ポインタ）として機能する特殊な種類のファイルです。Windowsのショートカットに似ていますが、より低レベルでOSによって直接サポートされます。

*   **作成**: `ln -s <target> <link_name>` コマンドで作成されます。
*   **動作**: シンボリックリンクにアクセスすると、OSは自動的にそのリンクが指すターゲットにリダイレクトします。
*   **問題点**: しかし、一部のツールや操作（特にファイルシステムを跨ぐようなコピーや同期ツール）は、このリダイレクトを自動的に行わず、シンボリックリンク自体を「ファイル」として扱ってしまうことがあります。これが `adb sync` のケースで発生していた問題です。

## 技術的詳細

このコミットの技術的な核心は、`adb sync` のシンボリックリンク処理の限界を回避することにあります。

`src/androidtest.bash` スクリプトは、Androidデバイス上でGoのテストを実行するために、ホストの `GOROOT` から `src`, `test`, `lib` ディレクトリの内容をデバイスに転送する必要がありました。

**変更前:**
スクリプトは、`FAKE_GOROOT` という一時ディレクトリを作成し、その中に `GOROOT/src`, `GOROOT/test`, `GOROOT/lib` へのシンボリックリンクを作成していました。
```bash
mkdir -p $FAKE_GOROOT
ln -s $GOROOT/src $FAKE_GOROOT/src
ln -s $GOROOT/test $FAKE_GOROOT/test
ln -s $GOROOT/lib $FAKE_GOROOT/lib
```
その後、`adb sync data` コマンドを実行して、`FAKE_GOROOT` が配置されている `/tmp/androidtest-$$/data/local/tmp/goroot` の内容をAndroidデバイスの `/data` ディレクトリに同期しようとしていました。しかし、`adb sync` は `FAKE_GOROOT` 内のシンボリックリンクを辿らなかったため、デバイス側には必要なファイルが展開されず、テストが失敗していました。

**変更後:**
このコミットでは、シンボリックリンクを作成する代わりに、`cp -R --preserve=all` コマンドを使用して、`GOROOT` の実際のディレクトリ内容を `FAKE_GOROOT` に再帰的にコピーするように変更しました。
```bash
cp -R --preserve=all "${GOROOT}/src" "${FAKE_GOROOT}/"
cp -R --preserve=all "${GOROOT}/test" "${FAKE_GOROOT}/"
cp -R --preserve=all "${GOROOT}/lib" "${FAKE_GOROOT}/"
```
*   **`cp -R`**: ディレクトリの内容を再帰的にコピーします。これにより、シンボリックリンクではなく、そのリンクが指す実際のファイルやディレクトリがコピーされます。
*   **`--preserve=all`**: このオプションは非常に重要です。ファイルのパーミッション、所有者、タイムスタンプなどの属性を可能な限り保持したままコピーを行います。テスト環境では、ファイルの実行権限や更新日時などがテストの動作に影響を与える可能性があるため、これらの属性を保持することは重要です。

この変更により、`FAKE_GOROOT` はシンボリックリンクではなく、実際のファイルとディレクトリのコピーを含むようになり、`adb sync` が正しく動作して、必要なすべてのファイルがAndroidデバイスに転送されるようになりました。

## コアとなるコードの解説

変更は `src/androidtest.bash` スクリプトの以下の部分に集中しています。

1.  **コメントの変更**:
    ```diff
    -# on the host. So we fake one with symlinks to push the GOROOT
    -# into a subdirectory of /data.\
    +# on the host. We copy the files required for running tests under
    +# /data/local/tmp/goroot. The adb sync command does not follow
    +# symlinks so we have to copy.\
    ```
    このコメントの変更は、スクリプトの動作がシンボリックリンクから実際のコピーに変わったことを明確に示しています。特に「`adb sync` コマンドはシンボリックリンクを辿らないため、コピーする必要がある」という理由が追記されています。

2.  **シンボリックリンク作成コマンドの削除**:
    ```diff
    -ln -s $GOROOT/src $FAKE_GOROOT/src
    -ln -s $GOROOT/test $FAKE_GOROOT/test
    -ln -s $GOROOT/lib $FAKE_GOROOT/lib
    ```
    以前は `ln -s` コマンドを使って `GOROOT` 内の `src`, `test`, `lib` ディレクトリへのシンボリックリンクを `FAKE_GOROOT` 内に作成していました。これらの行が削除されました。

3.  **ファイルコピーコマンドの追加**:
    ```diff
    +cp -R --preserve=all "${GOROOT}/src" "${FAKE_GOROOT}/"
    +cp -R --preserve=all "${GOROOT}/test" "${FAKE_GOROOT}/"
    +cp -R --preserve=all "${GOROOT}/lib" "${FAKE_GOROOT}/"
    ```
    削除された `ln -s` の代わりに、`cp -R --preserve=all` コマンドが追加されました。
    *   `cp`: ファイルやディレクトリをコピーするコマンド。
    *   `-R` (または `--recursive`): ディレクトリの内容を再帰的にコピーします。これにより、`src`, `test`, `lib` ディレクトリとその中のすべてのファイルおよびサブディレクトリがコピーされます。
    *   `--preserve=all`: 元ファイルの属性（パーミッション、タイムスタンプ、所有者など）を可能な限り保持したままコピーします。これは、テストの実行環境においてファイルの属性が重要である場合に特に役立ちます。
    *   `"${GOROOT}/src"`: コピー元のディレクトリ。変数を引用符で囲むことで、パスにスペースが含まれていても正しく扱われます。
    *   `"${FAKE_GOROOT}/"`: コピー先のディレクトリ。末尾のスラッシュは、コピー元がディレクトリの場合に、コピー元ディレクトリの内容がコピー先ディレクトリの直下にコピーされることを明確にします。

この変更により、`adb sync` が実行される前に、テストに必要なすべてのファイルが `FAKE_GOROOT` 内に物理的に存在することになり、`adb sync` がそれらを正しくAndroidデバイスに転送できるようになりました。
