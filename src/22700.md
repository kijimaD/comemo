# [インデックス 22700] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net` パッケージ内のテストコード、特に `TestDialGoogle` と `TestResolveDialGoogle` の信頼性を向上させるための変更です。外部ネットワークへの接続テストにおいて、非スレッドセーフな `syscall.SocketDisableIPv6` 変数の使用を廃止し、より堅牢な `net/internal/socktest` パッケージに置き換えることで、テストの不安定性（flakiness）を解消しています。また、IPv4専用、IPv6専用、デュアルスタックカーネル上でのテストを制御するための `-ipv4` フラグが追加されました。

`net: deflake TestDialGoogle, TestResolveDialGoogle`

この変更は、到達不能な外部ネットワークをシミュレートするために、非スレッドセーフな `syscall.SocketDisableIPv6` 変数の代わりに `socktest` パッケージを使用します。

Fixes #7687.

## 変更の背景

Go言語のネットワークテスト、特に `net` パッケージ内の `TestDialGoogle` や `TestResolveDialGoogle` のような外部ネットワークに依存するテストは、環境要因によって不安定になる（flakyになる）ことがありました。これは、テストが外部ネットワークの可用性や設定に左右されるためです。

以前のテストでは、特定のネットワークプロトコル（例: IPv6）を無効にして到達不能な状態をシミュレートするために、`syscall.SocketDisableIPv6` というグローバル変数を使用していました。しかし、この変数は非スレッドセーフであり、並行して実行される他のテストやゴルーチンに予期せぬ影響を与える可能性がありました。これにより、テスト結果が不安定になったり、デバッグが困難になったりする問題が発生していました。

このコミットの目的は、この不安定性を解消し、より信頼性の高いテスト環境を構築することです。具体的には、`syscall.SocketDisableIPv6` のようなグローバルな状態に依存するのではなく、テストごとにネットワークの挙動を制御できるメカニズムを導入することで、テストの分離性と再現性を高めることを目指しています。また、IPv4とIPv6のそれぞれの環境でのテストをより細かく制御できるように、新しいテストフラグを追加することも目的とされています。

## 前提知識の解説

*   **Flaky Test（不安定なテスト）**: 実行するたびに成功したり失敗したりするテストのこと。外部要因（ネットワーク、時間、並行処理のタイミングなど）に依存することが多く、信頼性の低いテストと見なされます。
*   **`syscall.SocketDisableIPv6`**: Goの `syscall` パッケージに存在した（このコミットで置き換えられる）グローバル変数で、IPv6ソケットの作成を一時的に無効にするために使用されていました。これは、特定のテストシナリオでIPv6ネットワークが利用できない状況をシミュレートするために使われましたが、グローバルな状態を変更するため、並行テスト環境では問題を引き起こす可能性がありました。
*   **`net/internal/socktest` パッケージ**: Goの `net` パッケージの内部で使用されるテストユーティリティパッケージです。このパッケージは、ソケットの作成、接続、読み書きなどのシステムコールをインターセプトし、テスト目的でその挙動を制御することを可能にします。これにより、実際のネットワーク環境に依存せずに、特定のネットワークエラーや遅延をシミュレートしたり、ソケットの状態を検証したりすることができます。`internal` パッケージであるため、外部からの直接利用は想定されていません。
*   **IPv4とIPv6**: インターネットプロトコルのバージョン。IPv4は現在広く使われていますが、アドレス空間の枯渇が問題となっています。IPv6はより広いアドレス空間を持ち、次世代のインターネットプロトコルとして普及が進んでいます。
*   **デュアルスタックカーネル**: IPv4とIPv6の両方のプロトコルスタックを同時にサポートするオペレーティングシステムカーネルのこと。これにより、システムはIPv4とIPv6の両方のネットワークに接続できます。
*   **`go test` フラグ**: `go test` コマンドに渡すことができるオプションで、テストの実行方法を制御します。例えば、`-short` は短時間で終わるテストのみを実行し、`-v` は詳細なテスト結果を表示します。このコミットでは、`-ipv4` と `-ipv6` という新しいフラグが導入され、特定のIPバージョンでのテスト実行を制御します。

## 技術的詳細

このコミットの主要な技術的変更点は、テストにおけるネットワークの挙動シミュレーション方法の根本的な見直しです。

1.  **`syscall.SocketDisableIPv6` から `socktest` への移行**:
    *   従来の `syscall.SocketDisableIPv6` は、グローバルな状態を変更するため、並行テスト環境での競合状態や予測不能な挙動の原因となっていました。
    *   新しいアプローチでは、`net/internal/socktest` パッケージが導入されます。このパッケージは、ソケット関連のシステムコール（`connect` など）をフックし、テストコードがその挙動をプログラム的に制御できるようにします。
    *   具体的には、`socktest.FilterConnect` を使用して、特定のネットワークタイプ（例: `tcp6`）への接続試行をインターセプトし、`syscall.EHOSTUNREACH` のようなエラーを返すことで、そのネットワークが到達不能であるかのようにシミュレートします。これにより、テストは実際のネットワーク状態に依存せず、かつスレッドセーフな方法で特定のネットワーク条件を再現できます。
    *   `enableSocketConnect()` と `disableSocketConnect(network string)` 関数が導入され、テストのセットアップとティアダウンで `socktest` のフィルターを有効/無効にすることで、テストの分離性を確保しています。

2.  **IPv4/IPv6 テスト制御フラグの追加**:
    *   既存の `-ipv6` フラグに加えて、`-ipv4` フラグが追加されました。これにより、テスト実行時にIPv4またはIPv6の接続性を明示的に仮定できるようになります。
    *   これらのフラグは、テストが特定のIPバージョンでのみ実行されるべきか、あるいは特定のIPバージョンが利用できない場合にスキップされるべきかを判断するために使用されます。例えば、`-ipv4=false` と `-ipv6=false` の場合、デュアルスタック環境でのテストはスキップされ、IPv4またはIPv6のみのテストが実行されます。
    *   これにより、CI/CD環境や開発者のローカル環境で、特定のネットワーク設定（例: IPv6が利用できない環境）に合わせてテストを調整し、不要なテスト失敗を避けることができます。

3.  **テスト構造の改善**:
    *   `TestDialGoogle` テストは、`dialGoogleTests` という構造体のスライスを使用して、複数のテストシナリオをパラメータ化しています。これにより、異なる `Dial` 関数（例: `DualStack` を有効にしたものとそうでないもの）や、到達不能なネットワーク条件を簡単にテストできるようになりました。
    *   `googleLiteralAddrs()` 関数が導入され、`www.google.com` や `ipv6.google.com` のようなドメイン名だけでなく、実際のIPアドレス（IPv4およびIPv6）を動的に取得し、テストで使用するアドレスリストを生成します。これにより、DNS解決の不安定性に依存せず、より直接的なIPアドレスへの接続テストが可能になります。

これらの変更により、Goのネットワークテストはより堅牢で、再現性が高く、様々なネットワーク環境でのテストが容易になりました。

## コアとなるコードの解説

### `src/net/dialgoogle_test.go` の変更点

`TestDialGoogle` の新しい構造は、`dialGoogleTests` スライスによって定義されるテストケースのイテレーションに基づいています。

```go
var dialGoogleTests = []struct {
	dial               func(string, string) (Conn, error)
	unreachableNetwork string
	networks           []string
	addrs              []string
}{
	{
		dial:     (&Dialer{DualStack: true}).Dial,
		networks: []string{"tcp", "tcp4", "tcp6"},
		addrs:    []string{"www.google.com:http"},
	},
	{
		dial:               Dial,
		unreachableNetwork: "tcp6",
		networks:           []string{"tcp", "tcp4"},
	},
	{
		dial:               Dial,
		unreachableNetwork: "tcp4",
		networks:           []string{"tcp", "tcp6"},
	},
}
```
この構造体は、テスト対象の `Dial` 関数、シミュレートする到達不能なネットワークタイプ、テストするネットワークタイプ、および接続先のアドレスを定義します。これにより、テストのバリエーションを簡単に記述できるようになりました。

`TestDialGoogle` 内では、`googleLiteralAddrs()` を呼び出して、テストで使用する実際のIPアドレスリストを動的に取得します。

```go
	var err error
	dialGoogleTests[1].addrs, dialGoogleTests[2].addrs, err = googleLiteralAddrs()
	if err != nil {
		t.Error(err)
	}
```
これにより、テストがDNS解決に依存せず、特定のIPアドレスへの接続を直接テストできます。

そして、各テストケースに対してループを回し、`disableSocketConnect` で特定のネットワークを無効にし、`fetchGoogle` で接続を試行し、最後に `enableSocketConnect` でフィルターをリセットします。

```go
		for _, network := range tt.networks {
			// ... (スキップロジック) ...
			disableSocketConnect(tt.unreachableNetwork)
			for _, addr := range tt.addrs {
				if err := fetchGoogle(tt.dial, network, addr); err != nil {
					t.Error(err)
				}
			}
			enableSocketConnect()
		}
```

### `src/net/main_posix_test.go` (新規ファイル)

このファイルは、POSIX互換システム（Linux, macOSなど）での `socktest` の実装を提供します。

```go
// +build !plan9

package net

import (
	"net/internal/socktest"
	"strings"
	"syscall"
)

func enableSocketConnect() {
	sw.Set(socktest.FilterConnect, nil)
}

func disableSocketConnect(network string) {
	ss := strings.Split(network, ":")
	sw.Set(socktest.FilterConnect, func(so *socktest.Status) (socktest.AfterFilter, error) {
		switch ss[0] {
		case "tcp4", "udp4", "ip4":
			if so.Cookie.Family() == syscall.AF_INET {
				return nil, syscall.EHOSTUNREACH
			}
		case "tcp6", "udp6", "ip6":
			if so.Cookie.Family() == syscall.AF_INET6 {
				return nil, syscall.EHOSTUNREACH
			}
		}
		return nil, nil
	})
}
```
`disableSocketConnect` 関数は、`socktest.Set` を使用して `socktest.FilterConnect` にカスタムフィルター関数を設定します。このフィルター関数は、ソケットの接続試行をインターセプトし、指定されたネットワークファミリー（例: `syscall.AF_INET` for IPv4, `syscall.AF_INET6` for IPv6）に一致する場合に `syscall.EHOSTUNREACH` エラーを返します。これにより、特定のIPバージョンへの接続が失敗したかのようにシミュレートされます。

`enableSocketConnect` 関数は、フィルターを `nil` に設定することで、ソケット接続のインターセプトを無効にし、通常の挙動に戻します。

### `src/net/main_test.go` の変更点

新しいテストフラグ `-ipv4` が追加されました。

```go
	testIPv4 = flag.Bool("ipv4", true, "assume external IPv4 connectivity exists")
```
このフラグは、テストが外部IPv4接続の存在を仮定するかどうかを制御します。

これらの変更により、Goのネットワークテストは、より細かく制御可能で、再現性が高く、様々なネットワーク条件でのテストが容易になりました。
