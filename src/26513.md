## 変更の背景

この変更は、Goの`os.FindProcess`関数の挙動に関する一般的な誤解を解消するために行われました。特にUnix系システムにおいて、`os.FindProcess(pid)`は、指定されたプロセスID (PID) を持つプロセスが実際に実行中であるかどうかにかかわらず、常に`*os.Process`オブジェクトと`nil`エラーを返します。これは、Windowsなどの他のオペレーティングシステムでの挙動とは異なり、ユーザーがプロセスが存在しない場合にエラーを期待する可能性があるため、混乱を招くことがありました。

この問題は、Go issue #14146で報告され、`os.FindProcess`のドキュメンテーションがこのUnix特有の挙動を明確に説明する必要があるという結論に至りました。このコミットは、そのドキュメンテーションの不足を修正し、開発者が`os.FindProcess`を正しく理解し、使用できるようにすることを目的としています。

## 前提知識の解説

### プロセスID (PID)

プロセスID (PID) は、オペレーティングシステムが実行中の各プロセスに割り当てる一意の識別子です。これにより、システムは特定のプロセスを参照し、管理することができます。

### `os.FindProcess`関数

Go言語の`os`パッケージに含まれる`FindProcess`関数は、指定されたPIDに対応する`*os.Process`オブジェクトを返します。このオブジェクトは、プロセスのシグナル送信や待機などの操作に使用できます。

### Unix系システムとWindowsにおけるプロセスの扱い

*   **Unix系システム (Linux, macOSなど):** Unix系システムでは、PIDは単なる数値であり、カーネルは特定のPIDに対応するプロセスが存在するかどうかを`FindProcess`のような高レベルのAPI呼び出しで直接検証しません。`FindProcess`は、単にそのPIDを持つ`*os.Process`構造体を作成するだけであり、そのPIDが現在有効なプロセスに割り当てられているかどうかは確認しません。プロセスが存在するかどうかを確認するには、通常、`kill(pid, 0)`のようなシステムコール（Goでは`process.Signal(syscall.Signal(0))`に相当）を使用する必要があります。これは、シグナル0が実際のシグナルを送信せずに、シグナル送信の権限とプロセスの存在を確認するために使用されるためです。
*   **Windowsシステム:** Windowsでは、`FindProcess`に相当するAPIは、指定されたPIDのプロセスが存在しない場合、エラーを返すことが一般的です。この違いが、Goの`os.FindProcess`のクロスプラットフォームな挙動に関する混乱の原因となっていました。

## 技術的詳細

Unix系システムにおいて`os.FindProcess`が常に成功する理由は、その実装がOSの低レベルなプロセス管理メカニズムに起因します。Goの`os.FindProcess`は、内部的に`findProcess`というプラットフォーム固有の関数を呼び出します。Unixの実装では、この関数は単に与えられたPIDで`os.Process`構造体を初期化し、それを返します。この時点では、そのPIDが有効なプロセスに対応しているか、あるいはそのプロセスがまだ実行中であるかどうかのチェックは行われません。

これは、Unixの`kill(pid, 0)`システムコールと同様の哲学に基づいています。`kill(pid, 0)`は、指定されたPIDのプロセスにシグナルを送信する権限があるかどうか、およびそのPIDのプロセスが存在するかどうかをチェックしますが、実際にシグナルは送信しません。`os.FindProcess`が返す`*os.Process`オブジェクトに対して`Signal(syscall.Signal(0))`を呼び出すことで、初めてプロセスの存在とアクセス権を確実に確認できます。

この挙動は、PIDが再利用される可能性があるという事実と密接に関連しています。あるプロセスが終了した後、そのPIDは新しいプロセスに割り当てられる可能性があります。したがって、`FindProcess`が単にPIDに基づいて`*os.Process`を返すだけでは、それが意図したプロセスであるという保証はありません。ドキュメンテーションの追加は、この重要なニュアンスを明確にし、開発者が`os.Process`オブジェクトを扱う際に適切な検証ステップを踏むよう促します。

## コアとなるコードの解説

変更は`src/os/doc.go`ファイル内の`FindProcess`関数のドキュメンテーションコメントにあります。

*   **追加された行:**
    ```go
    //
    // On Unix systems, FindProcess always succeeds and returns a Process
    // for the given pid, regardless of whether the process exists.
    ```
    この3行が追加されました。特に重要なのは「On Unix systems, FindProcess always succeeds and returns a Process for the given pid, regardless of whether the process exists.」という文言です。これは、Unix系システムにおける`FindProcess`の挙動を明確に記述しており、指定されたPIDのプロセスが存在するかどうかにかかわらず、常に`*os.Process`オブジェクトが返され、エラーは発生しないことを強調しています。

*   **変更された関数シグネチャのコメント:**
    ```diff
    -func FindProcess(pid int) (p *Process, err error) {
    +func FindProcess(pid int) (*Process, error) {
    ```
    これは、関数の戻り値の命名を明示的に`p *Process, err error`から`*Process, error`に変更していますが、これはドキュメンテーションコメントの追加に伴うスタイルの一貫性のためであり、機能的な変更ではありません。Goの慣例として、戻り値が1つまたは2つの場合は名前を省略することがよくあります。

この変更は、`FindProcess`関数の実際のロジックには影響を与えませんが、その利用方法に関する重要な情報を提供することで、APIの誤用を防ぎ、開発者がより堅牢なコードを書く手助けとなります。プロセスが実際に存在するかどうかを確認するには、返された`*os.Process`オブジェクトに対して`Signal(syscall.Signal(0))`を呼び出し、その結果のエラーをチェックする必要があることを、このドキュメンテーションは暗に示唆しています。

## 参考にした情報源リンク

*   Go issue 14146, and subsequent discussions like issue 34396, address the behavior of `os.FindProcess` on Unix-like systems, where it always returns a `*os.Process` instance and a `nil` error, even if the process with the given PID does not exist.
*   To accurately determine if a process exists and is still running, the recommended approach is to send a \"signal 0\" to the `os.Process` object.
*   Signal 0 is a special Unix signal that performs error checking without actually sending a signal to the process.
*   Process IDs (PIDs) can be reused by the operating system, meaning a PID might refer to a different process than the one originally intended if the original process has terminated.
*   The Go documentation for `os.FindProcess` has been updated to include this clarification and the recommended method for checking process existence.
