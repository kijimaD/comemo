## 変更の背景

この変更は、Goランタイムのテストスイートの一部である `test/init1.go` ファイル内のエラーメッセージの正確性を向上させることを目的としています。元のコードでは、ガベージコレクションの回数 (`numGC`) の変化を示すメッセージにおいて、変更前の値と変更後の値の両方に同じ変数 `numGC` を使用していました。これにより、テストが失敗した際に表示される情報が誤解を招く可能性がありました。

このテストは、特定のメモリ割り当てとGCの挙動を検証するためのものであり、GC回数の変化を正確に報告することは、テストのデバッグや問題の特定において非常に重要です。したがって、このコミットは、エラーメッセージの出力ロジックの単純なバグを修正し、より正確な情報を提供するように改善しています。

## 前提知識の解説

*   **Go言語の `init()` 関数**: Goプログラムでは、`init()` 関数はパッケージがインポートされた際、またはプログラムが開始される際に、`main()` 関数が実行される前に自動的に実行されます。複数の `init()` 関数がある場合、それらは定義された順序で実行されます。このコミットの対象となる `init1.go` ファイルも、この `init()` 関数を利用して特定の初期化処理やテストロジックを実行しています。
*   **Go言語の `runtime.MemStats`**: `runtime` パッケージは、Goランタイムシステムとの対話のための関数を提供します。`runtime.MemStats` 構造体は、Goプログラムのメモリ割り当て、ガベージコレクション、ヒープ使用量などに関する詳細な統計情報を含んでいます。このコミットでは、`MemStats` の `NumGC` フィールド（ガベージコレクションが実行された回数）が使用されています。
*   **ガベージコレクション (GC)**: Go言語は自動メモリ管理（ガベージコレクション）を採用しています。GCは、プログラムがもはや参照しないメモリ領域を自動的に解放し、メモリリークを防ぎ、開発者が手動でメモリを管理する負担を軽減します。`NumGC` は、GCが何回実行されたかを示すカウンターです。
*   **テストファイル `test/init1.go`**: このファイルは、Goランタイムの特定の挙動、特にメモリ割り当てとGCの相互作用をテストするために書かれたものです。`init()` 関数内でメモリを大量に割り当て、GCの回数をチェックすることで、ランタイムの安定性や性能を検証しています。テストの目的は、`N*MB` (ここで `N` は1000) のメモリを割り当てた後に、`sys1-sys >= N*MB` (割り当てられたメモリが期待値以上であること) または `numGC1 == numGC` (GCが実行されなかったこと) のいずれかの条件が満たされた場合に `panic` を発生させることです。これは、メモリが適切に解放されなかったか、GCが期待通りに動作しなかったことを示します。

## 技術的詳細

このコミットの技術的な変更は非常にシンプルですが、その背景にあるテストの意図を理解することが重要です。

`test/init1.go` ファイルの `init()` 関数内では、以下の処理が行われています。

1.  `runtime.ReadMemStats(&memstats)` を呼び出して、現在のメモリ統計情報を取得します。
2.  `sys, numGC := memstats.Sys, memstats.NumGC` で、現在のシステムメモリ使用量 (`sys`) とGC回数 (`numGC`) を記録します。
3.  `make([]byte, MB)` を `N` 回繰り返して、大量のメモリを割り当てます。これにより、GCがトリガーされることが期待されます。
4.  再度 `runtime.ReadMemStats(&memstats)` を呼び出して、メモリ割り当て後のメモリ統計情報を取得します。
5.  `sys1, numGC1 := memstats.Sys, memstats.NumGC` で、メモリ割り当て後のシステムメモリ使用量 (`sys1`) とGC回数 (`numGC1`) を記録します。
6.  `if sys1-sys >= N*MB || numGC1 == numGC` という条件でテストの失敗を判定します。
    *   `sys1-sys >= N*MB`: 割り当てられたメモリが期待値以上である場合。これは、GCがメモリを適切に解放しなかったことを示唆します。
    *   `numGC1 == numGC`: GCが一度も実行されなかった場合。これは、大量のメモリが割り当てられたにもかかわらずGCがトリガーされなかったことを示唆します。
7.  上記の条件が真の場合、`panic("init1")` を呼び出してテストを失敗させます。この `panic` の直前に、デバッグ情報としてメモリ使用量とGC回数の変化を出力しています。

元のコードでは、このデバッグ出力の行が `println("numGC went", numGC, "to", numGC)` となっていました。これは、GC回数の変化を示す意図であるにもかかわらず、変更前のGC回数 (`numGC`) を2回出力していました。

今回のコミットでは、この行を `println("numGC went", numGC, "to", numGC1)` に修正しています。これにより、変更前のGC回数 (`numGC`) と変更後のGC回数 (`numGC1`) が正しく表示されるようになり、テストが失敗した際に、GCが実際に何回実行されたのか、または実行されなかったのかを正確に把握できるようになります。

## コアとなるコードの変更箇所

変更は `test/init1.go` ファイルの1箇所のみです。

```diff
--- a/test/init1.go
+++ b/test/init1.go
@@ -40,7 +40,7 @@ func init() {
 	sys1, numGC1 := memstats.Sys, memstats.NumGC
 	if sys1-sys >= N*MB || numGC1 == numGC {
 		println("allocated 1000 chunks of", MB, "and used ", sys1-sys, "memory")
-		println("numGC went", numGC, "to", numGC)
+		println("numGC went", numGC, "to", numGC1)
 		panic("init1")
 	}
 }
```

## コアとなるコードの解説

変更された行は、`init()` 関数内の `if` ブロックの中にあります。このブロックは、テストが失敗条件を満たした場合に実行されます。

*   **変更前**: `println("numGC went", numGC, "to", numGC)`
    *   `numGC` は、メモリ割り当て前のGC回数を格納する変数です。この行では、`numGC` の値が2回出力されていました。例えば、GCが0回から1回に増えた場合でも、「numGC went 0 to 0」と表示され、誤解を招く可能性がありました。
*   **変更後**: `println("numGC went", numGC, "to", numGC1)`
    *   `numGC` はメモリ割り当て前のGC回数、`numGC1` はメモリ割り当て後のGC回数を格納する変数です。この修正により、GC回数の変化が「numGC went [変更前] to [変更後]」という形式で正確に表示されるようになります。例えば、GCが0回から1回に増えた場合は、「numGC went 0 to 1」と表示され、テストの挙動がより明確になります。

この修正は、テストの出力の正確性を高め、デバッグ作業を容易にするための、小さくも重要な改善です。
