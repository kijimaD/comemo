# [インデックス 22997] ファイルの概要

このコミットは、Go言語の`net`パッケージにおけるCGOベースのネットワークルックアップ処理のクリーンアップとエラーハンドリングの改善を目的としています。具体的には、`getaddrinfo`や`getnameinfo`といったCライブラリ関数から返されるエラーをより適切に表現するための新しい型`addrinfoErrno`を導入し、CGO関連ファイルのタグ付けを明確化し、全体的なコードの整理を行っています。

## 元コミット内容

`net: clean up cgo`

この変更は、`getaddrinfo`、`getnameinfo`固有のエラーを表す`addrinfoErrno`型を追加し、CGOベースのルックアップ関数で使用します。

また、CGOファイルのタグ付けを明確化し、マイナーなクリーンアップを行います。

## 変更の背景

Go言語の`net`パッケージは、DNSルックアップやサービス名解決などのネットワーク関連機能を提供します。これらの機能の一部は、C言語の標準ライブラリ関数（特に`getaddrinfo`や`getnameinfo`）をCGOを介して呼び出すことで実装されています。

従来のGoのCGOベースのネットワークルックアップでは、Cライブラリ関数から返されるエラーコードのハンドリングが必ずしも最適ではありませんでした。特に、`getaddrinfo`や`getnameinfo`が返す特定のエラー（例: `EAI_AGAIN`、`EAI_SYSTEM`、`EAI_NONAME`）は、Goのエラーインターフェースに直接マッピングされておらず、エラーの種類に応じた適切な処理（例: 一時的なエラーかどうかの判断）が困難でした。

このコミットの主な背景は以下の点にあります。

1.  **エラーハンドリングの改善**: `getaddrinfo`や`getnameinfo`が返すエラーコードをGoのエラーシステムに統合し、より詳細で型安全なエラー情報を提供すること。これにより、呼び出し元がエラーの種類を正確に判断し、適切なリカバリ処理を行えるようにします。
2.  **コードの明確化と整理**: CGO関連のファイルに適切なビルドタグを追加することで、どのファイルがCGOを使用するビルドに含まれるかを明確にし、コードベースの可読性と保守性を向上させます。また、冗長なコードの削除や定数化による最適化も含まれます。
3.  **Windowsサポートの追加**: CGOベースのネットワークルックアップにおけるWindows固有の処理を分離し、プラットフォームごとのコードの整合性を高めます。

## 前提知識の解説

### CGO

CGOは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。Goの`import "C"`構文を使用することで、C言語の関数、型、変数をGoコードから直接利用できます。これにより、既存のCライブラリを活用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。ネットワーク関連のシステムコールはOSのCライブラリで提供されることが多いため、Goの`net`パッケージではCGOが利用されています。

### `getaddrinfo` / `getnameinfo`

これらはPOSIX標準で定義されているネットワークアドレス変換関数です。
*   **`getaddrinfo`**: ホスト名とサービス名（例: "www.example.com", "http"）を、ネットワークアドレス構造体（`sockaddr`構造体）のリストに変換します。DNSルックアップや`/etc/hosts`ファイルの参照などを行い、IPv4/IPv6の両方に対応しています。
*   **`getnameinfo`**: ネットワークアドレス構造体（`sockaddr`構造体）をホスト名とサービス名に変換します。

これらの関数は、成功時には0を返し、エラー時には非ゼロの値を返します。エラーコードは通常、`EAI_...`という形式のマクロで定義されます。

### `addrinfo`構造体

`getaddrinfo`関数は、`struct addrinfo`のリンクリストを返します。この構造体には、アドレスファミリー（`ai_family`）、ソケットタイプ（`ai_socktype`）、プロトコル（`ai_protocol`）、アドレスの長さ（`ai_addrlen`）、アドレス自体（`ai_addr`）、正規名（`ai_canonname`）などの情報が含まれます。

### `gai_strerror`

`gai_strerror`関数は、`getaddrinfo`や`getnameinfo`が返すエラーコード（`EAI_...`）を、人間が読めるエラーメッセージ文字列に変換します。

### `EAI_AGAIN`, `EAI_SYSTEM`, `EAI_NONAME`

これらは`getaddrinfo`が返す代表的なエラーコードです。
*   **`EAI_AGAIN`**: 一時的な失敗。名前解決サービスが一時的に利用できないか、リソース不足のため再試行が必要であることを示します。DNSサーバーが応答しない場合など。
*   **`EAI_SYSTEM`**: システムエラー。`getaddrinfo`の内部でシステムコールが失敗した場合に発生します。通常、`errno`変数に詳細なエラーコードが設定されます。
*   **`EAI_NONAME`**: ホスト名またはサービス名が見つからない。指定されたホスト名やサービス名が解決できない場合に発生します。

### Goの`net`パッケージ

Goの標準ライブラリである`net`パッケージは、TCP/IPネットワークプログラミングのための基本的なインターフェースを提供します。IPアドレスの解決、TCP/UDP接続の確立、HTTPクライアント/サーバーの実装など、幅広いネットワーク機能が含まれます。内部的には、OSのネットワーク機能を利用するためにCGOを使用する場合があります。

### ビルドタグ (`+build`)

Goのビルドタグは、ソースファイルの先頭にコメント形式で記述され、特定の条件が満たされた場合にのみそのファイルをコンパイル対象に含めるためのディレクティブです。例えば、`// +build linux`はLinuxシステムでのみコンパイルされることを意味します。`// +build cgo,!netgo`は、CGOが有効で、かつ`netgo`タグが指定されていない場合にコンパイルされることを意味します。`netgo`タグは、Goのネットワークスタックのみを使用し、CGOを使用しないビルドを強制するために使われます。

## 技術的詳細

このコミットの技術的な変更点は多岐にわたりますが、主要なものは以下の通りです。

1.  **`addrinfoErrno`型の導入**:
    *   `src/net/cgo_unix.go`および`src/net/cgo_windows.go`（新規追加）に`type addrinfoErrno int`が定義されました。
    *   この型はGoの`error`インターフェースを実装しています。
        *   `Error() string`: `C.gai_strerror(C.int(eai))`を呼び出し、Cライブラリのエラーコードに対応する文字列メッセージを返します。これにより、`getaddrinfo`や`getnameinfo`固有のエラーメッセージをGoのエラーとして取得できるようになります。
        *   `Temporary() bool`: `eai == C.EAI_AGAIN`の場合に`true`を返します。これにより、`EAI_AGAIN`が一時的なエラーであることをGoのエラーハンドリングで認識できるようになり、再試行などのロジックを実装しやすくなります。
        *   `Timeout() bool`: 常に`false`を返します。`getaddrinfo`のエラーは通常タイムアウトとは直接関連しないためです。
    *   この新しいエラー型を導入することで、CGO経由で発生した`getaddrinfo`や`getnameinfo`のエラーをGoの型システム内でより具体的に扱えるようになります。

2.  **`cgoAddrInfoFlags`の関数から定数への変更**:
    *   `src/net/cgo_android.go`, `src/net/cgo_bsd.go`, `src/net/cgo_linux.go`, `src/net/cgo_netbsd.go`, `src/net/cgo_openbsd.go`において、`func cgoAddrInfoFlags() C.int`として定義されていたものが、`const cgoAddrInfoFlags = ...`という定数定義に変更されました。
    *   これは、`cgoAddrInfoFlags`が実行時に変化しない値であるため、関数呼び出しのオーバーヘッドをなくし、コンパイル時に値を確定させることで、より効率的なコード生成を可能にするための最適化です。

3.  **`cgo_windows.go`の新規追加**:
    *   Windows環境におけるCGOベースのネットワークルックアップのエラーハンドリングを統一するために、`src/net/cgo_windows.go`が新しく追加されました。このファイルには、`addrinfoErrno`型の定義が含まれています。これにより、Windows固有のCGOネットワーク処理が他のUnix系システムと整合性のあるエラーハンドリングを持つようになります。

4.  **`cgo_unix.go`におけるエラーハンドリングの改善**:
    *   `cgoLookupPort`および`cgoLookupIPCNAME`関数内で、`C.getaddrinfo`の戻り値である`gerrno`（`getaddrinfo`のエラーコード）のハンドリングが強化されました。
    *   特に`C.EAI_SYSTEM`の場合に`err == nil`である可能性（Go issue #6232）を考慮し、`syscall.EMFILE`を割り当てるなどの対応が追加されています。
    *   その他の`gerrno`については、新しく導入された`addrinfoErrno(gerrno)`にキャストして返すことで、Goのエラーインターフェースを通じてCライブラリ固有のエラー情報を利用できるようにしています。

5.  **ビルドタグの明確化**:
    *   `src/net/cgo_bsd.go`と`src/net/cgo_unix.go`のビルドタグが`// +build !netgo`から`// +build cgo,!netgo`に変更されました。
    *   これは、これらのファイルがCGOを使用するビルドでのみコンパイルされることをより明示的に示すための変更です。`!netgo`はCGOを使用しないビルドを除外する意味ですが、`cgo,!netgo`とすることで、CGOが有効なビルドでのみ含まれることを強調します。

6.  **`error_test.go`における`addrinfoErrno`の追加**:
    *   `src/net/error_test.go`の`isTemporary`関数において、`addrinfoErrno`が一時的なエラーとして適切に扱われるように、`case addrinfoErrno:`が追加されました。これにより、新しいエラー型が既存のエラーテストフレームワークに統合されます。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に以下のファイルとコードスニペットに集約されます。

1.  **`src/net/cgo_unix.go`における`addrinfoErrno`型の定義と利用**:
    ```go
    // An addrinfoErrno represents a getaddrinfo, getnameinfo-specific
    // error number. It's a signed number and a zero value is a non-error
    // by convention.
    type addrinfoErrno int

    func (eai addrinfoErrno) Error() string   { return C.GoString(C.gai_strerror(C.int(eai))) }
    func (eai addrinfoErrno) Temporary() bool { return eai == C.EAI_AGAIN }
    func (eai addrinfoErrno) Timeout() bool   { return false }
    ```
    この定義により、C言語の`getaddrinfo`や`getnameinfo`が返すエラーコードをGoのエラーとしてラップし、そのエラーが一時的なものかどうかを判断する機能を提供します。

2.  **`src/net/cgo_unix.go`における`cgoLookupPort`および`cgoLookupIPCNAME`でのエラーハンドリングの変更**:
    `C.getaddrinfo`の呼び出し後、`gerrno`（C言語のエラーコード）をチェックし、`addrinfoErrno`型にキャストしてGoのエラーとして返しています。

    ```go
    // cgoLookupPort内の変更例
    	gerrno, err := C.getaddrinfo(nil, s, &hints, &res)
    	if gerrno != 0 {
    		switch gerrno {
    		case C.EAI_SYSTEM:
    			if err == nil { // see golang.org/issue/6232
    				err = syscall.EMFILE
    			}
    		default:
    			err = addrinfoErrno(gerrno)
    		}
    		return 0, err, true
    	}
    ```

3.  **`src/net/cgo_windows.go`の新規追加**:
    ```go
    // +build cgo,!netgo

    package net

    type addrinfoErrno int

    func (eai addrinfoErrno) Error() string   { return "<nil>" } // Windowsではgai_strerrorが利用できないため、ダミー実装
    func (eai addrinfoErrno) Temporary() bool { return false }
    func (eai addrinfoErrno) Timeout() bool   { return false }
    ```
    Windowsでは`gai_strerror`が利用できないため、`Error()`メソッドはダミー実装となっていますが、`addrinfoErrno`型自体は導入されています。

4.  **`cgoAddrInfoFlags`の関数から定数への変更**:
    例: `src/net/cgo_android.go`
    ```diff
    --- a/src/net/cgo_android.go
    +++ b/src/net/cgo_android.go
    @@ -9,6 +9,4 @@ package net
     //#include <netdb.h>\n import "C"\n     
    -func cgoAddrInfoFlags() C.int {
    -	return C.AI_CANONNAME
    -}
    +const cgoAddrInfoFlags = C.AI_CANONNAME
    ```
    これは複数の`cgo_*.go`ファイルで同様に変更されています。

## コアとなるコードの解説

### `addrinfoErrno`型の導入とエラーハンドリングの改善

このコミットの最も重要な変更は、`addrinfoErrno`という新しい整数型を導入し、これをGoの`error`インターフェースとして機能させることです。

*   **`type addrinfoErrno int`**: この型は、C言語の`getaddrinfo`や`getnameinfo`関数が返すエラーコード（整数値）をGoの型システムで表現するためのラッパーです。
*   **`func (eai addrinfoErrno) Error() string`**: このメソッドは、`addrinfoErrno`型の値がGoのエラーとして扱われた際に、そのエラーメッセージを返します。Unix系システムでは`C.gai_strerror(C.int(eai))`を呼び出すことで、Cライブラリが提供する人間が読めるエラー文字列を取得します。これにより、例えば`EAI_NONAME`が「Host not found」のような具体的なメッセージとしてGoのエラーとして伝播されるようになります。Windowsでは`gai_strerror`が利用できないため、暫定的に`"<nil>"`を返しています。
*   **`func (eai addrinfoErrno) Temporary() bool`**: このメソッドは、エラーが一時的なものであるかどうかを判断するために使用されます。`eai == C.EAI_AGAIN`の場合に`true`を返します。`EAI_AGAIN`は、DNSサーバーが一時的に応答しないなどの理由で、操作を再試行すれば成功する可能性があることを示します。この機能は、ネットワーク操作を行うGoアプリケーションが、一時的なネットワークの問題に対してより堅牢なリカバリロジックを実装するのに役立ちます。
*   **`func (eai addrinfoErrno) Timeout() bool`**: このメソッドは常に`false`を返します。`getaddrinfo`のエラーコードは、直接的なタイムアウトを示すものではないためです。

`cgoLookupPort`や`cgoLookupIPCNAME`といったCGOベースのルックアップ関数では、`C.getaddrinfo`の呼び出し結果として得られる`gerrno`（Cのエラーコード）を、この`addrinfoErrno`型にキャストしてGoのエラーとして返します。これにより、GoのコードはCライブラリの詳細なエラー情報を、Goのエラーインターフェースを通じて透過的に扱うことができるようになります。特に、`EAI_SYSTEM`の場合に`err == nil`となるLinux特有のバグ（Go issue #6232）に対するワークアラウンドも組み込まれており、堅牢性が向上しています。

### `cgoAddrInfoFlags`の定数化

以前は`func cgoAddrInfoFlags() C.int`という関数として定義されていた`getaddrinfo`に渡すフラグが、`const cgoAddrInfoFlags = ...`という定数に変更されました。
これは、`AI_CANONNAME`, `AI_V4MAPPED`, `AI_ALL`といったフラグの値がコンパイル時に固定されており、実行時に計算する必要がないためです。関数呼び出しのオーバーヘッドを排除し、コンパイル時に値を直接埋め込むことで、わずかながらパフォーマンスの向上とコードの簡素化が図られます。

### ビルドタグの明確化と`cgo_windows.go`の追加

`+build cgo,!netgo`というビルドタグは、そのファイルがCGOを有効にしたビルドでのみコンパイルされ、かつGoの純粋なネットワークスタックを使用する`netgo`ビルドタグが指定されていない場合にのみ含まれることを意味します。これにより、CGOに依存するネットワーク関連のコードが、意図したビルド環境でのみ使用されることが保証されます。

また、`cgo_windows.go`が新しく追加されたことで、Windows環境におけるCGOベースのネットワークルックアップのエラーハンドリングが他のUnix系システムと整合性を持つようになりました。これにより、クロスプラットフォームでのCGO利用におけるコードの整理と保守性が向上しています。

これらの変更は、GoのネットワークスタックがCGOを介してOSの機能を利用する際の堅牢性、エラー診断能力、およびコードの保守性を全体的に向上させるものです。
