# [インデックス 25527] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http` パッケージにおいて、HTTP/2のサポートを `DefaultTransport` でデフォルトで有効にする重要な変更を導入します。これにより、Goアプリケーションは特別な設定なしにHTTP/2の恩恵を受けられるようになります。

## 変更の背景

このコミットの主な背景は、Go言語の `net/http` パッケージにおけるHTTP/2サポートの成熟と、それをデフォルトで利用可能にすることです。HTTP/2は、HTTP/1.1に比べてパフォーマンスが大幅に向上する多くの機能（多重化、ヘッダー圧縮、サーバープッシュなど）を提供します。

以前は、GoのHTTP/2クライアントサポートは `GODEBUG=h2client=1` という環境変数を設定することで明示的に有効にする必要がありました。これは開発中の機能であり、安定性や互換性の問題が懸念されていたためです。しかし、このコミットの時点でHTTP/2の実装が十分に安定し、デフォルトで有効にしても問題ないと判断されました。

この変更により、Goアプリケーション開発者は、追加の設定なしにHTTP/2のパフォーマンス上の利点を享受できるようになります。ただし、互換性の問題や特定のデバッグシナリオのために、一時的にHTTP/2を無効にするオプション (`GODEBUG=h2client=0`) は残されました。これは、Go 1.6リリースに向けての最終調整段階での重要なステップでした。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **HTTP/2**:
    *   **多重化 (Multiplexing)**: 複数のリクエストとレスポンスを単一のTCP接続上で同時に送受信できる機能。HTTP/1.1では、通常、リクエストごとに新しい接続を確立するか、パイプライン処理（ヘッドオブラインブロッキングの問題がある）を使用していました。
    *   **ヘッダー圧縮 (HPACK)**: HTTPヘッダーは冗長になりがちですが、HTTP/2ではHPACKという圧縮アルゴリズムを使用してヘッダーサイズを削減し、帯域幅の利用効率を高めます。
    *   **サーバープッシュ (Server Push)**: クライアントがリクエストする前に、サーバーがクライアントが必要と予測するリソースをプッシュできる機能。これにより、ページのロード時間を短縮できます。
    *   **ストリーム優先度 (Stream Prioritization)**: クライアントは、どのリソースがより重要であるかをサーバーに伝えることができ、サーバーはそれに基づいてリソースの送信順序を最適化できます。
    *   **ALPN (Application-Layer Protocol Negotiation)**: TLSハンドシェイク中にクライアントとサーバーがどのアプリケーションプロトコル（例: HTTP/1.1, HTTP/2）を使用するかをネゴシエートする拡張機能。HTTP/2は通常、TLS上で動作し、ALPNを使用してプロトコルを決定します。

2.  **Goの `net/http` パッケージ**:
    *   **`http.Client`**: HTTPリクエストを送信するためのクライアント。
    *   **`http.Transport`**: `http.Client` の内部で実際にネットワーク接続を管理し、リクエストを送信し、レスポンスを受信するコンポーネント。`RoundTripper` インターフェースを実装します。
    *   **`RoundTripper` インターフェース**: `RoundTrip(*Request) (*Response, error)` メソッドを持つインターフェース。`http.Transport` はこのインターフェースの実装の一つです。
    *   **`DefaultTransport`**: `http.DefaultClient` が使用するデフォルトの `http.Transport` インスタンス。多くのGoアプリケーションで明示的に `http.Client` を設定しない場合、これが使用されます。
    *   **`TLSNextProto`**: `http.Transport` のフィールドで、TLS接続が確立された後にALPNによってネゴシエートされたプロトコルに基づいて、カスタムの `RoundTripper` を提供するために使用されます。例えば、"h2"（HTTP/2）がネゴシエートされた場合、HTTP/2用の `RoundTripper` を返す関数を設定できます。

3.  **`GODEBUG` 環境変数**:
    *   Goランタイムのデバッグや特定の機能の有効/無効を切り替えるために使用される環境変数。`key=value` の形式で複数の設定をカンマ区切りで指定できます。このコミットでは `h2client=0` でHTTP/2クライアントを無効にするために使用されます。

4.  **`h2_bundle.go`**:
    *   Goの `net/http` パッケージは、HTTP/2の複雑な実装を標準ライブラリに直接含めるのではなく、`golang.org/x/net/http2` パッケージのコードをバンドルして `h2_bundle.go` というファイルに含めることで、依存関係を管理しています。これにより、標準ライブラリのリリースサイクルと `x/net/http2` の開発サイクルを分離しつつ、HTTP/2機能を提供できます。

## 技術的詳細

このコミットの技術的な核心は、`net/http` パッケージの `init()` 関数と、HTTP/2トランスポートの接続管理ロジックの変更にあります。

1.  **`DefaultTransport` のHTTP/2有効化**:
    *   `src/net/http/transport.go` の `init()` 関数が変更されました。以前は `GODEBUG` 環境変数に `h2client=1` が含まれている場合にのみHTTP/2サポートが有効になっていましたが、このコミットでは `h2client=0` が含まれている場合を除き、デフォルトでHTTP/2が有効になります。
    *   具体的には、`DefaultTransport` に対して `https` スキームのプロトコルハンドラとして `noDialH2Transport` が登録され、`TLSClientConfig` に `NextProtos: []string{"h2"}` が設定されます。これにより、TLSハンドシェイク時にクライアントはHTTP/2をサポートすることをサーバーに通知します。
    *   `TLSNextProto` マップには、ALPNで `h2` がネゴシエートされた場合に呼び出される関数が設定されます。この関数は、確立されたTLS接続 (`*tls.Conn`) を `h2DefaultTransport` のアイドル接続プールに追加し、`h2DefaultTransport` を `RoundTripper` として返します。

2.  **HTTP/2接続管理の改善 (`h2_bundle.go`)**:
    *   `http2RoundTripOpt` という新しい構造体が導入され、`OnlyCachedConn` というフィールドを持ちます。これは、`http2Transport.RoundTripOpt` メソッドに渡され、新しいTCP接続を確立せずに、キャッシュされた既存の接続のみを使用するかどうかを制御します。
    *   `http2Transport.RoundTrip` メソッドは、内部的に `http2RoundTripOpt{}` を引数として `http2Transport.RoundTripOpt` を呼び出すように変更されました。
    *   `http2Transport.getClientConn` 関数に `onlyCached` という新しいブール型引数が追加されました。この引数が `true` で、かつキャッシュされた接続が見つからない場合、`http2ErrNoCachedConn` という新しいエラーを返します。これにより、呼び出し元は新しい接続を試みるか、別のプロトコルにフォールバックするかを決定できます。

3.  **`noDialH2Transport` の動作変更**:
    *   `noDialH2Transport` は、`http.Transport` が `https` リクエストを処理する際に、HTTP/2トランスポートに処理を委譲するためのラッパーです。
    *   このコミットでは、`noDialH2Transport.RoundTrip` メソッドが変更され、`t.rt.RoundTripOpt(req, http2RoundTripOpt{OnlyCachedConn: true})` を呼び出すようになりました。これは、`noDialH2Transport` が新しいHTTP/2接続を確立するのではなく、既存のアイドルなHTTP/2接続がある場合にのみHTTP/2でリクエストを処理しようとすることを意味します。
    *   もし `http2ErrNoCachedConn` が返された場合、`noDialH2Transport` は `ErrSkipAltProtocol` を返します。これは、`DefaultTransport` がこのリクエストをHTTP/1.1で再試行するように指示するシグナルです。このメカニズムにより、HTTP/2接続が利用できない場合でも、HTTP/1.1へのシームレスなフォールバックが可能になります。

これらの変更により、Goの `net/http` クライアントは、デフォルトでHTTP/2を優先しつつ、必要に応じてHTTP/1.1に適切にフォールバックする、より堅牢で高性能な動作を実現しています。

## コアとなるコードの変更箇所

### `src/net/http/h2_bundle.go`

```go
// 追加: キャッシュされた接続がない場合に返すエラー
var http2ErrNoCachedConn = errors.New("http2: no cached connection was available")

// 追加: RoundTripOpt メソッドのオプションを定義する構造体
type http2RoundTripOpt struct {
	// OnlyCachedConn controls whether RoundTripOpt may
	// create a new TCP connection. If set true and
	// no cached connection is available, RoundTripOpt
	// will return ErrNoCachedConn.
	OnlyCachedConn bool
}

// 変更: RoundTrip は RoundTripOpt を呼び出すように変更
func (t *http2Transport) RoundTrip(req *Request) (*Response, error) {
	return t.RoundTripOpt(req, http2RoundTripOpt{})
}

// 追加: オプションを受け取る RoundTrip メソッド
func (t *http2Transport) RoundTripOpt(req *Request, opt http2RoundTripOpt) (*Response, error) {
	// ... (既存のロジック) ...
	for {
		// 変更: getClientConn に opt.OnlyCachedConn を渡す
		cc, err := t.getClientConn(host, port, opt.OnlyCachedConn)
		if err != nil {
			return nil, err
		}
		// ... (既存のロジック) ...
	}
}

// 変更: getClientConn に onlyCached 引数を追加
func (t *http2Transport) getClientConn(host, port string, onlyCached bool) (*http2clientConn, error) {
	// ... (既存のロジック) ...
	// キャッシュされた接続が見つからず、onlyCached が true の場合、エラーを返す
	if onlyCached {
		return nil, http2ErrNoCachedConn
	}
	// ... (既存のロジック) ...
}
```

### `src/net/http/transport.go`

```go
// 変更: init 関数。HTTP/2をデフォルトで有効にするロジック
func init() {
	// GODEBUG=h2client=0 が設定されている場合のみHTTP/2を無効にする
	if strings.Contains(os.Getenv("GODEBUG"), "h2client=0") {
		return
	}

	t := DefaultTransport.(*Transport)

	// https スキームのプロトコルハンドラとして noDialH2Transport を登録
	t.RegisterProtocol("https", noDialH2Transport{h2DefaultTransport})
	// TLSClientConfig に NextProtos: "h2" を設定
	t.TLSClientConfig = &tls.Config{
		NextProtos: []string{"h2"},
	}
	// TLSNextProto ハンドラを設定。ALPNで "h2" がネゴシエートされた場合に呼び出される
	t.TLSNextProto = map[string]func(string, *tls.Conn) RoundTripper{
		"h2": func(authority string, c *tls.Conn) RoundTripper {
			// 確立されたTLS接続を h2DefaultTransport のアイドル接続プールに追加
			h2DefaultTransport.AddIdleConn(authority, c)
			return h2DefaultTransport
		},
	}
}

// 変更: noDialH2Transport の RoundTrip メソッド
func (t noDialH2Transport) RoundTrip(req *Request) (*Response, error) {
	// OnlyCachedConn: true を指定して RoundTripOpt を呼び出す
	res, err := t.rt.RoundTripOpt(req, http2RoundTripOpt{OnlyCachedConn: true})
	// キャッシュされた接続がない場合、ErrSkipAltProtocol を返してHTTP/1.1にフォールバックさせる
	if err == http2ErrNoCachedConn {
		return nil, ErrSkipAltProtocol
	}
	return res, err
}
```

## コアとなるコードの解説

### `src/net/http/transport.go` の `init()` 関数

この `init()` 関数は、プログラム起動時に一度だけ実行され、`DefaultTransport` にHTTP/2サポートを組み込みます。
*   `if strings.Contains(os.Getenv("GODEBUG"), "h2client=0") { return }` の行は、`GODEBUG` 環境変数に `h2client=0` が含まれている場合、HTTP/2の有効化をスキップします。これにより、ユーザーは必要に応じてHTTP/2を無効にできます。
*   `t.RegisterProtocol("https", noDialH2Transport{h2DefaultTransport})` は、`https` スキームのリクエストが来た際に、`noDialH2Transport` を使用して処理することを `DefaultTransport` に登録します。`noDialH2Transport` は、HTTP/2トランスポート (`h2DefaultTransport`) へのラッパーです。
*   `t.TLSClientConfig.NextProtos = []string{"h2"}` は、TLSハンドシェイク時にクライアントがALPN拡張を使用して、HTTP/2 (`h2`) をサポートすることをサーバーに通知するように設定します。
*   `t.TLSNextProto` の設定は、ALPNネゴシエーションの結果、サーバーがHTTP/2を選択した場合に実行されるコールバック関数を定義します。この関数は、確立されたTLS接続 (`c *tls.Conn`) を `h2DefaultTransport.AddIdleConn` を通じてHTTP/2トランスポートのアイドル接続プールに追加します。これにより、この接続は後続のHTTP/2リクエストで再利用できるようになります。そして、`h2DefaultTransport` 自体を `RoundTripper` として返し、以降のリクエスト処理をHTTP/2トランスポートに委譲します。

### `src/net/http/h2_bundle.go` の `http2RoundTripOpt` と `getClientConn`

*   `http2RoundTripOpt` 構造体と `OnlyCachedConn` フィールドは、HTTP/2トランスポートが新しい接続を確立するか、既存のキャッシュされた接続のみを使用するかを制御するための新しいメカニズムです。
*   `http2Transport.getClientConn` 関数は、`onlyCached` という新しい引数を受け取ります。この引数が `true` の場合、関数はキャッシュされた接続のみを探し、見つからない場合は `http2ErrNoCachedConn` を返します。これは、`noDialH2Transport` が新しい接続を確立せずに、既存のHTTP/2接続がある場合にのみHTTP/2を使用するという要件を満たすために重要です。

### `src/net/http/transport.go` の `noDialH2Transport.RoundTrip`

*   このメソッドは、`DefaultTransport` が `https` リクエストを処理する際に呼び出されます。
*   `t.rt.RoundTripOpt(req, http2RoundTripOpt{OnlyCachedConn: true})` の呼び出しは、基盤となるHTTP/2トランスポート (`h2DefaultTransport`) に対して、新しい接続を確立せずに、既存のキャッシュされたHTTP/2接続のみを使用してリクエストを処理するように指示します。
*   もし `http2ErrNoCachedConn` が返された場合（つまり、既存のHTTP/2接続が利用できない場合）、`noDialH2Transport` は `nil, ErrSkipAltProtocol` を返します。`ErrSkipAltProtocol` は `DefaultTransport` に対し、このリクエストをHTTP/1.1で再試行するように促す特別なエラーです。これにより、HTTP/2接続が確立されていない場合でも、リクエストがHTTP/1.1で正常に処理されることが保証され、HTTP/2への透過的なフォールバックが実現されます。

これらの変更は、Goの `net/http` クライアントがHTTP/2をデフォルトで利用しつつ、堅牢な接続管理とプロトコルフォールバックメカニズムを備えることを可能にしています。
