`doc/install-source.html: fix cd command, already in go dir.`

## 変更の背景

この変更は、Go言語のソースコードからビルドする際の手順を説明する公式ドキュメント `doc/install-source.html` に含まれていた誤りを修正するために行われました。以前のドキュメントでは、ユーザーがGoのルートディレクトリ（通常は `$GOROOT` に相当するディレクトリ）にいることを前提として、その中でさらに `go/src` ディレクトリに移動するよう指示していました。しかし、Goのソースコードリポジトリをクローンした場合、通常は既にGoのルートディレクトリにいるため、`go/src` ではなく単に `src` ディレクトリに移動するのが正しい手順でした。この誤った指示は、ユーザーがGoをソースからビルドしようとした際に混乱やエラーを引き起こす可能性があったため、修正されました。

## 前提知識の解説

このコミットの理解には、以下のGo言語に関する基本的な知識が役立ちます。

*   **Go言語のソースコード構造**: Go言語のソースコードは、通常、`go` という名前のルートディレクトリの下に配置されます。このルートディレクトリには、`src` (標準ライブラリのソースコード)、`bin` (コンパイルされたバイナリ)、`pkg` (コンパイルされたパッケージ) などのサブディレクトリが含まれます。
*   **`GOROOT`**: Goのインストールルートディレクトリを指す環境変数です。Goのツールチェーンや標準ライブラリが配置されている場所を示します。ソースからビルドする場合、ユーザーがクローンしたGoリポジトリのルートディレクトリがこれに相当します。
*   **`src` ディレクトリ**: Goの標準ライブラリやツール群のソースコードが格納されているディレクトリです。Goのビルドプロセスは、このディレクトリ内のコードをコンパイルすることから始まります。
*   **`all.bash` (または `all.bat` for Windows)**: GoのソースコードからGoツールチェーン全体をビルドするためのシェルスクリプトです。このスクリプトは、Goのコンパイラ、リンカ、標準ライブラリ、およびその他のツールをコンパイルし、インストールします。通常、`$GOROOT/src` ディレクトリ内で実行されます。

## 技術的詳細

このコミットの技術的な変更は非常にシンプルで、HTMLドキュメント内の1行のテキスト修正に過ぎません。しかし、その影響はGoのインストール手順の正確性に直結します。

変更前は、`doc/install-source.html` のビルド手順のセクションに以下のコマンドが記載されていました。

```html
<pre>
$ cd go/src
$ ./all.bash
</pre>
```

これは、ユーザーがGoのソースコードをクローンしたディレクトリ（例: `/home/user/go`）にいると仮定した場合、`cd go/src` とすることで `/home/user/go/go/src` という存在しないパスに移動しようとすることになります。

正しい手順は、ユーザーがGoのルートディレクトリ（例: `/home/user/go`）にいる場合、その直下にある `src` ディレクトリに移動することです。したがって、`cd src` が正しいコマンドとなります。

この修正により、ドキュメントはGoのソースコードからのビルド手順を正確に反映し、ユーザーが迷うことなくGoをインストールできるようになりました。これは、ユーザーエクスペリエンスの向上と、ドキュメントの信頼性維持に貢献する小さな、しかし重要な修正です。

## コアとなるコードの解説

上記のdiffは、`doc/install-source.html` ファイルの変更を示しています。

*   `- $ cd go/src`: これは変更前の行で、Goのソースコードをビルドする際に `go/src` ディレクトリに移動するよう指示していました。
*   `+ $ cd src`: これは変更後の行で、`go/src` から `src` に修正されています。

この変更は、Goのソースコードリポジトリをクローンした後、ユーザーが既にGoのルートディレクトリ（例: `~/go`）にいることを前提としています。この状況で `cd go/src` とすると、`~/go/go/src` という誤ったパスに移動しようとします。しかし、`cd src` とすることで、正しく `~/go/src` ディレクトリに移動し、その後の `./all.bash` コマンドが正常に実行できるようになります。

この修正は、Goのビルド手順の正確性を確保し、ユーザーがGoをソースからビルドする際の混乱を避けるために不可欠でした。
