## 元コミット内容

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドに、型アサーション (`ODOTTYPE` および `OAS2DOTTYPE`) のサポートを追加します。具体的には、インターフェース値の基底型をチェックし、その型に変換する処理をSSA形式で表現するためのコードが `src/cmd/compile/internal/gc/ssa.go` に追加されました。また、この機能のテストケースとして `src/cmd/compile/internal/gc/testdata/assert_ssa.go` が新規作成され、`src/cmd/compile/internal/gc/ssa_test.go` にテストの呼び出しが追加されています。

この変更は、Josh Bleecher Snyder氏による先行作業 (https://go-review.googlesource.com/#/c/14524/) を引き継ぎ、Keith Randall氏が完成させたものです。

## 変更の背景

Goコンパイラは、コードの最適化と効率的な機械語生成のために、中間表現としてSSA (Static Single Assignment) 形式を採用しています。SSAは、各変数が一度だけ代入されることを保証する形式であり、データフロー解析や最適化を容易にします。

Go言語には、インターフェース型から具体的な型への変換を行う「型アサーション」という機能があります。例えば、`v, ok := i.(T)` や `v := i.(T)` のような構文です。これまでのコンパイラバックエンドでは、これらの型アサーションはSSA形式に変換されずに処理されていた可能性があります。

このコミットの背景には、型アサーションの処理をSSAバックエンドに統合し、SSAの利点（より良い最適化、コード生成の簡素化、バグの減少など）を型アサーションにも適用するという目的があります。特に、`ODOTTYPE` (単一の型アサーション) と `OAS2DOTTYPE` (「カンマOK」イディオムを含む型アサーション) の両方をSSAで適切に表現し、処理できるようにすることが求められました。

## 前提知識の解説

### 1. Goコンパイラの構造

Goコンパイラ (`cmd/compile`) は、主に以下の段階で構成されます。
*   **字句解析 (Lexing)**: ソースコードをトークンに分解します。
*   **構文解析 (Parsing)**: トークンから抽象構文木 (AST: Abstract Syntax Tree) を構築します。
*   **型チェック (Type Checking)**: ASTの各ノードの型を検証します。
*   **中間表現 (IR: Intermediate Representation) への変換**: ASTを、より機械語に近い形式の中間表現に変換します。Goコンパイラでは、この中間表現として主に「Generic SSA (GSSA)」が使用されます。
*   **最適化 (Optimization)**: IRに対して様々な最適化を適用します。
*   **コード生成 (Code Generation)**: 最適化されたIRからターゲットアーキテクチャの機械語を生成します。

### 2. ASTノードの種類 (`ODOTTYPE`, `OAS2DOTTYPE`)

Goコンパイラのフロントエンドでは、ソースコードの各要素をASTノードとして表現します。
*   `ODOTTYPE`: `v := i.(T)` のような、単一の戻り値を持つ型アサーションを表すASTノードです。アサーションが失敗した場合、パニックが発生します。
*   `OAS2DOTTYPE`: `v, ok := i.(T)` のような、「カンマOK」イディオムを含む型アサーションを表すASTノードです。アサーションが成功したかどうかを示すブール値 (`ok`) を返します。失敗してもパニックは発生しません。

### 3. SSA (Static Single Assignment) 形式

SSAは、コンパイラ最適化で広く使われる中間表現です。SSA形式では、各変数はプログラム内で一度だけ代入されます。これにより、データフロー解析が大幅に簡素化され、デッドコード削除、共通部分式除去、レジスタ割り当てなどの最適化が容易になります。

GoコンパイラのSSAバックエンドは、ASTからSSA形式のグラフを構築し、そのグラフに対して最適化を適用し、最終的に機械語を生成します。

### 4. Goのインターフェースと型アサーション

Goのインターフェースは、メソッドのセットを定義する型です。任意の具象型がインターフェースのすべてのメソッドを実装していれば、その具象型の値はインターフェース型の変数に代入できます。

型アサーションは、インターフェース型の変数が保持している具象値の型を、特定の型であると主張し、その型に変換する操作です。
*   `value := interfaceValue.(ConcreteType)`: `interfaceValue` が `ConcreteType` の値を持っている場合、その値を `value` に代入します。持っていない場合、ランタイムパニックが発生します。
*   `value, ok := interfaceValue.(ConcreteType)`: `interfaceValue` が `ConcreteType` の値を持っている場合、その値を `value` に代入し、`ok` に `true` を代入します。持っていない場合、`value` には `ConcreteType` のゼロ値が代入され、`ok` には `false` が代入されます。パニックは発生しません。

インターフェース値は内部的に、具象値の型情報 (`_type` または `itab`) と、具象値自体へのポインタ (`data`) の2つのワードで構成されます。型アサーションは、この型情報をチェックし、一致すれば `data` 部分を取り出す操作です。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンド (`src/cmd/compile/internal/gc/ssa.go`) に、型アサーションをSSA形式で処理するためのロジックを追加します。

### 1. 新しいダミー変数の追加

`ssa.go` の冒頭で、SSA生成中に一時的に使用されるダミー変数 `typVar`, `idataVar`, `okVar` が追加されています。これらは、型アサーションの結果（型情報、データ、成功フラグ）をSSAグラフ内で一時的に保持するために使われます。

```go
var (
	// dummy node for the memory variable
	memvar = Node{Op: ONAME, Sym: &Sym{Name: "mem"}}

	// dummy nodes for temporary variables
	ptrvar   = Node{Op: ONAME, Sym: &Sym{Name: "ptr"}}
	capvar   = Node{Op: ONAME, Sym: &Sym{Name: "cap"}}
	typVar   = Node{Op: ONAME, Sym: &Sym{Name: "typ"}}   // 追加
	idataVar = Node{Op: ONAME, Sym: &Sym{Name: "idata"}} // 追加
	okVar    = Node{Op: ONAME, Sym: &Sym{Name: "ok"}}     // 追加
)
```

### 2. `stmt` メソッドでの `OAS2DOTTYPE` の処理

`stmt` メソッドは、ASTのステートメントノードをSSA形式に変換する役割を担います。`OAS2DOTTYPE` のケースが追加され、これは `dottype` ヘルパー関数を呼び出して型アサーションを処理します。

```go
	case OAS2DOTTYPE:
		res, resok := s.dottype(n.Rlist.N, true) // commaok=true で dottype を呼び出し
		s.assign(n.List.N, res, false)
		s.assign(n.List.Next.N, resok, false)
		return
```
ここで `n.Rlist.N` はアサーション対象のインターフェース式、`n.List.N` は結果の具象値、`n.List.Next.N` は `ok` 変数に対応します。

### 3. `expr` メソッドでの `ODOTTYPE` の処理

`expr` メソッドは、ASTの式ノードをSSA形式に変換します。`ODOTTYPE` のケースが追加され、これも `dottype` ヘルパー関数を呼び出します。

```go
	case ODOTTYPE:
		res, _ := s.dottype(n, false) // commaok=false で dottype を呼び出し
		return res
```
この場合、`commaok` は `false` なので、アサーション失敗時にはパニックが発生するロジックが `dottype` 内で生成されます。

### 4. `ifaceType` ヘルパー関数の追加

`ifaceType` 関数は、インターフェース値からその具象型の型情報（`_type` または `itab`）を抽出するSSAコードを生成します。
*   `isnilinter(n.Type)`: インターフェースが空インターフェース (`interface{}`) の場合、型情報はインターフェース値の最初のワードに直接格納されています。`ssa.OpITab` オペレーションを使ってこれを取り出します。
*   非空インターフェースの場合: 型情報は `itab` (interface table) の中に格納されています。`itab` 自体はインターフェース値の最初のワードです。`itab` が `nil` でないことをチェックし、`itab` の2番目のワード（`Widthptr` オフセット）から型情報をロードします。この処理には条件分岐 (`ssa.BlockIf`) が含まれます。

### 5. `dottype` ヘルパー関数の追加

`dottype` 関数は、型アサーションの主要なロジックを実装します。
1.  **インターフェース値とターゲット型の取得**: `n.Left` からアサーション対象のインターフェース値 (`iface`) を取得し、`n.Type` からアサーション先のターゲット型 (`target`) を取得します。
2.  **実際の型情報の取得**: `ifaceType` を呼び出して、`iface` が保持する実際の具象型の型情報 (`typ`) を取得します。
3.  **型の一致チェック**: `ssa.OpEqPtr` を使って、`typ` と `target` が一致するかどうかを比較し、条件 (`cond`) を生成します。
4.  **条件分岐**: `ssa.BlockIf` を使って、型の一致結果に基づいて `bOk` (成功ブロック) と `bFail` (失敗ブロック) に分岐します。
5.  **`commaok` が `false` の場合 (パニック)**:
    *   `bFail` ブロックでは、`panicdottype` ランタイム関数を呼び出すSSAコードを生成します。この関数は、型アサーション失敗時のパニック処理を行います。スタック上に、実際の型、ターゲット型、ソースの静的型を格納してから `panicdottype` を呼び出します。
    *   `bOk` ブロックでは、`ssa.OpIData` を使ってインターフェース値から具象データを取り出し、それを結果として返します。
6.  **`commaok` が `true` の場合 (カンマOKイディオム)**:
    *   `bOk` ブロックでは、`ssa.OpIData` で具象データを取り出し、`okVar` に `true` を設定します。
    *   `bFail` ブロックでは、`idataVar` に `nil` を設定し、`okVar` に `false` を設定します。
    *   両方のブロックは `bEnd` (マージポイント) に合流し、`idataVar` と `okVar` の最終的な値を結果として返します。

### 6. テストケースの追加

*   `src/cmd/compile/internal/gc/ssa_test.go`: `TestTypeAssertion` 関数が追加され、`assert_ssa.go` をテストデータとして実行するように設定されています。
*   `src/cmd/compile/internal/gc/testdata/assert_ssa.go`: 型アサーションの様々なシナリオをテストする新しいGoファイルが追加されました。これには、単一戻り値の型アサーション（成功/パニック）、カンマOKイディオムの型アサーション（成功/失敗）が含まれ、インターフェース型が `interface{}` の場合と、メソッドを持つインターフェースの場合の両方がテストされています。

## コアとなるコードの解説

このコミットの核心は、`dottype` 関数と `ifaceType` 関数にあります。

### `ifaceType` 関数

この関数は、与えられたインターフェース値 `v` (SSA値) とそのASTノード `n` から、そのインターフェースが現在保持している具象型の型情報 (`*ssa.Value`) を抽出します。

1.  **空インターフェース (`interface{}`) の場合**:
    *   `isnilinter(n.Type)` で判定されます。
    *   空インターフェースは、内部的に `[type, data]` の2ワード構造で、最初のワードが型情報です。
    *   `s.newValue1(ssa.OpITab, byteptr, v)` を使って、インターフェース値 `v` から直接型情報を取り出します。`ssa.OpITab` は、インターフェース値の型情報部分を抽出するSSAオペレーションです。

2.  **非空インターフェース (メソッドを持つインターフェース) の場合**:
    *   非空インターフェースは、内部的に `[itab, data]` の2ワード構造で、最初のワードが `itab` (interface table) へのポインタです。`itab` は、具象型とインターフェースのペアに関する情報（型情報、メソッドテーブルなど）を含みます。
    *   まず、`s.newValue1(ssa.OpITab, byteptr, v)` で `itab` ポインタ自体を取り出します。
    *   次に、`itab` が `nil` でないか (`ssa.OpNeqPtr`) をチェックする条件分岐 (`ssa.BlockIf`) を生成します。`itab` が `nil` の場合、そのインターフェースは `nil` 値を保持しており、型情報も `nil` となります。
    *   `itab` が `nil` でない場合、`itab` のオフセット `Widthptr` (ポインタのサイズ、通常は8バイト) の位置に実際の型情報が格納されているため、`s.newValue1I(ssa.OpOffPtr, ..., tab)` でオフセットを計算し、`s.newValue2(ssa.OpLoad, ..., off, s.mem())` でその位置から型情報をロードします。

### `dottype` 関数

この関数は、型アサーション `i.(T)` または `i.(T), ok` のSSAコードを生成します。

1.  **インターフェース値とターゲット型の取得**:
    *   `iface := s.expr(n.Left)`: アサーション対象のインターフェース式をSSA値に変換します。
    *   `typ := s.ifaceType(n.Left, iface)`: `ifaceType` を呼び出して、インターフェースが保持する実際の型情報を取得します。
    *   `target := s.expr(typename(n.Type))`: アサーション先のターゲット型をSSA値に変換します。

2.  **型の一致判定**:
    *   `cond := s.newValue2(ssa.OpEqPtr, Types[TBOOL], typ, target)`: 実際の型情報 `typ` とターゲット型 `target` が等しいかどうかを比較するSSAオペレーション (`ssa.OpEqPtr`) を生成し、結果をブール値 `cond` に格納します。

3.  **条件分岐**:
    *   `b.Kind = ssa.BlockIf; b.Control = cond`: `cond` の結果に基づいて、成功ブロック (`bOk`) と失敗ブロック (`bFail`) に分岐するSSAブロックを生成します。

4.  **パニックを伴う型アサーション (`commaok` が `false`)**:
    *   **失敗ブロック (`bFail`)**:
        *   `panicdottype` ランタイム関数を呼び出すための準備を行います。これは、スタック上に、アサーション対象のインターフェースの実際の型、アサーション先のターゲット型、そしてソースコード上の静的なインターフェース型を配置します。
        *   `s.newValue1A(ssa.OpStaticCall, ssa.TypeMem, syslook("panicdottype", 0).Sym, s.mem())` で `panicdottype` を呼び出すSSAオペレーションを生成します。
        *   `bFail.Kind = ssa.BlockExit`: このブロックがプログラムの実行を終了させることを示します。
    *   **成功ブロック (`bOk`)**:
        *   `s.newValue1(ssa.OpIData, n.Type, iface)`: インターフェース値 `iface` から具象データ部分を抽出する `ssa.OpIData` オペレーションを生成し、これをアサーションの結果として返します。

5.  **カンマOKイディオム (`commaok` が `true`)**:
    *   **成功ブロック (`bOk`)**:
        *   `s.vars[&idataVar] = s.newValue1(ssa.OpIData, n.Type, iface)`: 具象データを取り出し、一時変数 `idataVar` に格納します。
        *   `s.vars[&okVar] = s.constBool(true)`: `ok` 変数に対応する一時変数 `okVar` に `true` を設定します。
    *   **失敗ブロック (`bFail`)**:
        *   `s.vars[&idataVar] = s.entryNewValue0(ssa.OpConstNil, byteptr)`: 具象データは `nil` (またはゼロ値) となるため、`idataVar` に `nil` を設定します。
        *   `s.vars[&okVar] = s.constBool(false)`: `okVar` に `false` を設定します。
    *   **マージポイント (`bEnd`)**:
        *   `bOk` と `bFail` の両方から `bEnd` に合流します。
        *   `res = s.variable(&idataVar, byteptr)` と `resok = s.variable(&okVar, Types[TBOOL])` を使って、マージされた `idataVar` と `okVar` の値を最終的な結果として返します。

これらの変更により、Goコンパイラは型アサーションをSSA形式で表現し、その後の最適化パスでより効率的に処理できるようになります。特に、カンマOKイディオムの型アサーションにおける条件分岐と値のマージがSSAグラフとして明確に表現されることで、コンパイラはより高度な最適化を適用できるようになります。
