# [インデックス 22582] ファイルの概要

このコミットは、Go言語のNative Client (NaCl) テストスクリプトである `nacltest.bash` の改善に関するものです。具体的には、テスト実行時間の短縮を目的として、`fstest_nacl.go` ファイルのビルド方法を変更しています。これにより、完全な `make.bash` の実行を回避し、テストサイクルを効率化しています。

## 変更の背景

Go言語のプロジェクトでは、様々なプラットフォームやアーキテクチャ向けにビルドとテストが行われます。その中には、Google Chromeのサンドボックス環境で動作するNative Client (NaCl) も含まれます。`nacltest.bash` スクリプトは、GoのNaClポートのテストスイートを実行するために使用されます。

このスクリプトの以前のバージョンでは、テストの準備段階で `make.bash` を実行し、ホスト環境用のGoツールチェインを完全にビルドしていました。このツールチェインは、`syscall/fstest_nacl.go` というファイルを生成するために必要な `mkzip.go` ユーティリティを実行するために使われていました。しかし、`make.bash` の実行は時間がかかるプロセスであり、テスト全体の実行時間を不必要に長くしていました。

このコミットの目的は、この冗長な `make.bash` の実行を排除し、テスト時間を短縮することです。具体的には、`fstest_nacl.go` のビルドに、既存のブートストラップGoツールチェイン（通常は以前にビルドされた安定版のGoバージョン）を使用することで、この問題を解決しています。

## 前提知識の解説

### Go Native Client (NaCl)

Go Native Client (NaCl) は、GoプログラムをGoogle Chromeブラウザのサンドボックス環境で実行するための技術です。NaClは、Webアプリケーション内でC/C++コードなどのネイティブコードを安全かつ高性能に実行することを可能にする技術として開発されました。Go言語もこのNaClをターゲットプラットフォームの一つとしてサポートしており、GoプログラムをNaCl環境でコンパイル・実行するためのツールチェインとランタイムを提供していました。これにより、Goで記述された高性能なWebアプリケーションコンポーネントを開発することが可能でした。

### Goのビルドプロセスとブートストラップ (make.bash)

Go言語のコンパイラとツールチェインはGo自身で書かれています。そのため、Goの新しいバージョンをビルドする際には、既存のGoコンパイラ（ブートストラップコンパイラ）が必要です。このプロセスは「ブートストラップ」と呼ばれます。

*   **`make.bash`**: Goのソースコードリポジトリの `src` ディレクトリにあるシェルスクリプトで、Goツールチェイン全体をビルドするために使用されます。これには、コンパイラ、アセンブラ、リンカ、標準ライブラリなどが含まれます。
*   **`GOROOT_BOOTSTRAP`**: 環境変数で、ブートストラップに使用する既存のGoインストールのパスを指定します。`make.bash` は、このパスにあるGoツールチェインを使用して、新しいGoツールチェインをビルドします。通常、これは以前にインストールされた安定版のGoバージョン（例: Go 1.4）を指します。
*   **`GOBIN`**: Goの実行可能ファイルがインストールされるディレクトリを指定する環境変数です。

### `nacltest.bash`

`nacltest.bash` は、Goのソースツリー内の `src` ディレクトリに存在するシェルスクリプトで、GoのNative Client (NaCl) ポートのテストを実行するために設計されています。このスクリプトは、NaCl環境でGoプログラムが正しく動作するかどうかを検証するためのビルド、テスト、および関連するセットアップタスクを自動化します。

### `mkzip.go`

`mkzip.go` は、Goのソースツリー内の `misc/nacl` ディレクトリにあるユーティリティプログラムです。このプログラムは、Goの `syscall` パッケージがNaCl環境で必要とする、組み込みのファイルシステムデータを含むGoソースファイル（`fstest_nacl.go`）を生成するために使用されます。このファイルは、テスト中にNaCl環境内で仮想的なファイルシステムを提供するために利用されます。

## 技術的詳細

このコミットの核心は、`nacltest.bash` スクリプトが `fstest_nacl.go` を生成する際の依存関係を最適化することにあります。

**変更前:**

1.  `nacltest.bash` が実行される。
2.  `unset GOOS GOARCH` の後、`GOOS=$GOHOSTOS GOARCH=$GOHOSTARCH ./make.bash` が実行される。これは、ホスト環境（テストを実行しているマシン）向けのGoツールチェインを完全にビルドするステップです。このステップは、`mkzip.go` を実行するための `go` コマンドを提供するために必要でした。
3.  ビルドされたホストツールチェインの `go` コマンド（`$gobin/go`）を使用して、`../misc/nacl/mkzip.go` が実行され、`syscall/fstest_nacl.go` が生成される。
4.  その後、`GOOS=nacl GOARCH=$naclGOARCH ./all.bash --no-clean` が実行され、NaCl向けのGoツールチェインがビルドされ、テストが実行される。

このプロセスでは、`mkzip.go` の実行のためだけに、ホスト向けのGoツールチェインをフルビルドするという、時間のかかる冗長なステップが含まれていました。

**変更後:**

1.  `nacltest.bash` が実行される。
2.  `GOOS=$GOHOSTOS GOARCH=$GOHOSTARCH ./make.bash` の行が削除される。これにより、ホスト向けのGoツールチェインのフルビルドが不要になります。
3.  `fstest_nacl.go` の生成には、`GOROOT_BOOTSTRAP` 環境変数で指定された既存のブートストラップGoツールチェインが使用されます。
    *   `GOROOT_BOOTSTRAP` が設定されていない場合、デフォルトで `$HOME/go1.4` が使用されます。これは、Go 1.4がGo 1.5以降のブートストラップに使用される標準的なバージョンであったためです。
    *   `gobin` 変数は、このブートストラップGoの `bin` ディレクトリを指すように変更されます。
4.  `$gobin/go run ../misc/nacl/mkzip.go ...` コマンドが、ブートストラップGoの `go` コマンドを使用して実行され、`syscall/fstest_nacl.go` が生成されます。
5.  `GOOS=nacl GOARCH=$naclGOARCH ./all.bash` が実行される。以前の `--no-clean` オプションは削除されています。これは、`make.bash` が実行されなくなったため、クリーンアップの必要性が変わったか、または `all.bash` のデフォルト動作で十分になったためと考えられます。

この変更により、`mkzip.go` の実行に必要なGoツールチェインの準備が大幅に効率化され、テスト全体の実行時間が短縮されます。

## コアとなるコードの解説

### 削除された行

*   `-GOOS=$GOHOSTOS GOARCH=$GOHOSTARCH ./make.bash`
    *   この行は、ホスト環境向けのGoツールチェインを完全にビルドするコマンドでした。`mkzip.go` を実行するために必要でしたが、ブートストラップGoを使用する新しいアプローチにより不要になりました。これにより、テストのセットアップ時間が大幅に短縮されます。

### 追加・変更された行

*   `+echo "##### Building fake file system zip for nacl"`
    *   `fstest_nacl.go` のビルドが開始されることを示すための、単なる情報メッセージです。
*   `-gobin=${GOBIN:-$(pwd)/../bin}`
    *   以前は、`GOBIN` 環境変数が設定されていればそれを使用し、そうでなければ現在のGoルートの `bin` ディレクトリを `gobin` として設定していました。これは、`make.bash` でビルドされたツールチェインを指すことを意図していました。
*   `+GOROOT_BOOTSTRAP=${GOROOT_BOOTSTRAP:-$HOME/go1.4}`
    *   `GOROOT_BOOTSTRAP` 環境変数を設定します。もし既に設定されていなければ、デフォルト値として `$HOME/go1.4` を使用します。これは、Go 1.4がGoのブートストラップビルドで一般的に使用される安定版のGoのパスです。これにより、`mkzip.go` を実行するためのGoツールチェインの場所が明示的に指定されます。
*   `+gobin=$GOROOT_BOOTSTRAP/bin`
    *   `gobin` 変数を、新しく定義された `GOROOT_BOOTSTRAP` の `bin` ディレクトリを指すように変更します。これにより、`mkzip.go` はブートストラップGoツールチェインの `go` コマンドを使用して実行されるようになります。
*   `-GOOS=$GOHOSTOS GOARCH=$GOHOSTARCH $gobin/go run ../misc/nacl/mkzip.go -p syscall -r .. ../misc/nacl/testzip.proto syscall/fstest_nacl.go`
    *   `mkzip.go` を実行するコマンドです。以前は、ホスト環境のGoツールチェイン（`$gobin`）を使用していました。
*   `+GOROOT=$GOROOT_BOOTSTRAP $gobin/go run ../misc/nacl/mkzip.go -p syscall -r .. ../misc/nacl/testzip.proto syscall/fstest_nacl.go`
    *   `mkzip.go` を実行する新しいコマンドです。`GOROOT` を一時的に `GOROOT_BOOTSTRAP` に設定し、`$gobin`（ブートストラップGoの `bin` ディレクトリ）にある `go` コマンドを使用して `mkzip.go` を実行します。これにより、`mkzip.go` の実行が、フルビルドされたホストツールチェインに依存しなくなります。
*   `-GOOS=nacl GOARCH=$naclGOARCH ./all.bash --no-clean`
    *   NaCl向けのビルドとテストを実行するコマンドです。以前は `--no-clean` オプションが付いていました。
*   `+GOOS=nacl GOARCH=$naclGOARCH ./all.bash`
    *   `--no-clean` オプションが削除されました。これは、`make.bash` が実行されなくなったため、クリーンアップの動作が変更されたか、または `all.bash` のデフォルト動作で十分になったためと考えられます。通常、`--no-clean` は、ビルド成果物を削除せずにテストを実行し、デバッグを容易にするために使用されます。このオプションが削除されたということは、テストのたびにクリーンな状態からビルドが開始されることを意味する可能性があります。
