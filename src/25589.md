# [インデックス 25589] ファイルの概要

このコミットは、Go言語のツールチェインにおいて、MIPS64アーキテクチャ（`GOARCH=mips64` および `mips64le`）のサポートを追加するものです。具体的には、GoのアセンブラとリンカがMIPS64命令セットとレジスタセットを理解し、MIPS64バイナリを生成できるようにするための基盤を構築します。これには、MIPS64固有のレジスタ定義、命令セットの追加、リロケーション処理の導入、およびブランチ遅延スロットの扱いが含まれます。

## 変更の背景

Go言語は、その設計思想として多様なアーキテクチャへの対応を重視しています。このコミットは、GoがサポートするCPUアーキテクチャの範囲をMIPS64（ビッグエンディアンおよびリトルエンディアン）に拡張するためのものです。MIPS64は、組み込みシステムやネットワーク機器などで広く利用されている64ビットRISCアーキテクチャであり、Goがこれらのプラットフォームで動作できるようにすることは、Goの適用範囲を広げる上で重要です。

この変更により、GoコンパイラとリンカはMIPS64の命令セット、レジスタ、およびメモリモデルを正しく処理できるようになり、MIPS64ターゲット向けのGoプログラムのビルドが可能になります。特に、Goのツールチェインのバックエンドである`cmd/internal/obj`パッケージにMIPS64固有の定義とロジックを追加することが、このサポートの核心となります。

コミットメッセージには、ブランチ遅延スロットの扱いについても言及されており、初期段階ではNOP命令で埋めることで機能を実現し、将来的な最適化（命令スケジューリング）の余地を残していることが示されています。

## 前提知識の解説

### Goツールチェインの構造

Go言語のビルドプロセスは、複数のコンポーネントから構成されます。
*   **`cmd/compile`**: Goソースコードを中間表現（SSA）に変換し、最終的にターゲットアーキテクチャのアセンブリコードを生成します。
*   **`cmd/internal/obj`**: 各アーキテクチャ固有のアセンブリ命令、レジスタ、およびアセンブリコード生成ロジックを定義するバックエンドです。コンパイラとリンカの両方から利用されます。
*   **`cmd/link`**: 生成されたオブジェクトファイルをリンクし、実行可能なバイナリを生成します。この過程で、リロケーション処理が行われます。

### MIPS64アーキテクチャ

MIPS（Microprocessor without Interlocked Pipeline Stages）は、RISC（Reduced Instruction Set Computer）アーキテクチャの一種です。MIPS64は、その64ビット版であり、以下の特徴を持ちます。
*   **レジスタ**: 32個の64ビット汎用整数レジスタ（R0-R31）と、32個の64ビット浮動小数点レジスタ（F0-F31）を持ちます。
*   **命令セット**: 固定長（32ビット幅）の命令を持ち、通常1、2、3オペランド形式で記述されます。
*   **パイプライン処理**: MIPSはパイプライン処理を効率的に行うために設計されており、その特徴の一つに「ブランチ遅延スロット」があります。

### ブランチ遅延スロット (Branch Delay Slot)

多くの古いRISCアーキテクチャ（MIPSを含む）に見られる特徴です。分岐命令（`BEQ`, `JMP`など）が実行された直後の命令は、分岐が成立するかどうかにかかわらず、常に実行されます。この命令が配置される場所を「ブランチ遅延スロット」と呼びます。

これは、プロセッサのパイプライン処理の効率を向上させるために導入されました。分岐命令がフェッチされてから、実際に分岐先が決定されるまでの間に、パイプラインがストール（停止）するのを防ぐためです。コンパイラは、この遅延スロットに、プログラムのロジックに影響を与えない有用な命令（例えば、分岐先で必要となるロード命令など）を配置しようとします。もし有用な命令が見つからない場合は、`NOP`（No Operation）命令が挿入されます。

### リロケーション (Relocation)

プログラムがコンパイルされ、リンクされる際に、コード内のアドレス参照を修正するプロセスです。コンパイル時には、関数やデータの正確なメモリ上の位置は不明なため、相対アドレスやシンボル名で参照されます。リンカは、これらの参照を最終的な実行可能ファイル内の実際のアドレスに解決（リロケート）します。MIPS64のような特定のアーキテクチャでは、その命令セットの特性（例：アドレスを直接命令に埋め込む方法の制限）により、特定のリロケーションタイプが必要となります。

## 技術的詳細

このコミットは、GoツールチェインのMIPS64サポートの核心部分を実装しています。

1.  **MIPS64レジスタと命令セットの定義**:
    *   `src/cmd/internal/obj/mips/a.out.go`: MIPS64固有のレジスタ（`REG_R0`から`REG_R31`、`REG_F0`から`REG_F31`など）と、MIPS64命令（`AADD`, `AMOVV`, `ASLL`など）の定数を定義しています。以前はPPC64（PowerPC 64-bit）の定義が混在していた箇所がMIPS64用に修正されています。
    *   `src/cmd/internal/obj/mips/anames.go`: `a.out.go`で定義された命令の文字列名を生成するためのファイルです。
    *   `src/cmd/internal/obj/mips/anames0.go`: `a.out.go`で定義されたクラス名の文字列名を生成するためのファイルです。

2.  **MIPS64固有のリロケーションの追加**:
    *   `src/cmd/internal/obj/link.go`: Goリンカが使用するリロケーションタイプに、MIPS64固有のものが追加されています。
        *   `R_ADDRMIPS`: 32ビットの外部アドレスを解決し、`lui` (Load Upper Immediate) と `ori` (OR Immediate) の2つの命令でレジスタにアドレスをロードします。
        *   `R_CALLMIPS`: `JAL` (Jump And Link) 命令の非PC相対ターゲットアドレスを解決し、命令にアドレスをエンコードします。
        *   `R_JMPMIPS`: `JMP` 命令の非PC相対ターゲットアドレスを解決し、命令にアドレスをエンコードします。
    *   これらのリロケーションは、MIPS64の命令セットが持つアドレス指定の制約（例：命令に直接埋め込めるオフセットの範囲）に対応するために不可欠です。

3.  **アセンブリコード生成ロジックの更新**:
    *   `src/cmd/internal/obj/mips/asm0.go`: MIPS64命令のアセンブリコードを生成するための主要なロジックが含まれています。`Optab`構造体と`oplook`関数が、GoのアセンブラがMIPS64命令をどのように解釈し、機械語に変換するかを定義しています。このファイルでは、MIPS64のレジスタクラス（`C_REG`, `C_FREG`, `C_MREG`, `C_FCREG`など）や、定数タイプ（`C_ADDCON`, `C_LCON`など）が定義され、それらに対応する命令のエンコーディングルールが記述されています。
    *   特に、`aclass`関数は、オペランドのタイプ（レジスタ、定数、メモリ参照など）を分類し、`oplook`関数は、命令とオペランドの組み合わせに基づいて適切な命令エンコーディング（`Optab`エントリ）を検索します。
    *   ブランチ命令の処理において、非常に大きな条件分岐の場合に、中間的な`JMP`命令を挿入してジャンプ範囲を拡張するロジックが追加されています。
    *   ブランチ遅延スロットは、現時点では`NOP`命令で埋められます。これは、命令スケジューリングによる最適化がまだ実装されていないための一時的な措置です。

4.  **テストデータの再生成**:
    *   `src/cmd/newlink/testdata/`以下のバイナリファイル（`.6`拡張子）が多数変更されています。これは、MIPS64固有のリロケーションが追加されたことにより、リンカのテストデータがMIPS64の新しい仕様に合わせて再生成されたためです。

このコミットは、Goのクロスコンパイル能力をMIPS64アーキテクチャに拡張するための重要なステップであり、Goがより多様なハードウェアプラットフォームで利用可能になるための基盤を築いています。

*   **`src/cmd/internal/obj/mips/anames.go`**:

    *   `a.out.go`で定義された新しいMIPS64レジスタクラスに対応する文字列配列`cnames0`が更新されました。

    *   `aclass`関数がMIPS64のレジスタ（汎用、浮動小数点、コプロセッサ、HI/LOレジスタ）を正しく分類するように修正されました。
    *   `span0`関数（旧`span9`）内のブランチ命令処理ロジックがMIPS64のジャンプ範囲に合わせて調整され、必要に応じて中間`JMP`命令と`NOP`命令が挿入されるようになりました。
    *   `oplook`関数が、命令とオペランドの組み合わせから適切な`Optab`エントリを検索するロジックをMIPS64向けに更新しました。

## コアとなるコードの解説

このコミットの主要な目的は、GoのアセンブラとリンカがMIPS64アーキテクチャの命令とレジスタを正しく処理できるようにすることです。

*   **リロケーションの追加 (`src/cmd/internal/obj/link.go`)**:
    *   `R_ADDRMIPS`は、MIPS64で32ビットアドレスをレジスタにロードする際に使用されます。MIPS64の命令は32ビット固定長であり、直接64ビットアドレスを命令に埋め込むことはできません。そのため、`lui`（Load Upper Immediate）と`ori`（OR Immediate）の2つの命令を組み合わせて、64ビットアドレスの上位と下位をそれぞれレジスタにロードするシーケンスが必要になります。`R_ADDRMIPS`はこの2命令シーケンスを生成するためのリロケーションです。
    *   `R_CALLMIPS`と`R_JMPMIPS`は、`JAL`（Jump And Link）や`JMP`命令のターゲットアドレスを命令自体にエンコードする際に使用されます。MIPSのジャンプ命令は、ターゲットアドレスの一部を直接命令に含める形式を持つため、リンカがこの部分を正しく解決する必要があります。

*   **MIPS64命令とレジスタの定義 (`src/cmd/internal/obj/mips/a.out.go`)**:
    *   このファイルは、MIPS64アーキテクチャの「言語」をGoツールチェインに教えています。`REG_R0`から`REG_R31`、`REG_F0`から`REG_F31`といった定数は、GoのアセンブラがMIPS64の物理レジスタを抽象的に参照するための識別子です。
    *   `AADD`, `AMOVV`などの命令定数は、GoのアセンブラがMIPS64の各操作を認識するためのシンボルです。これらの定義により、GoのコンパイラはMIPS64のアセンブリコードを生成する際に、これらのシンボルを使用できるようになります。

*   **アセンブリコード生成ロジック (`src/cmd/internal/obj/mips/asm0.go`)**:
    *   `optab`は、MIPS64の各命令がどのようなオペランドの組み合わせを取り、それがどのように機械語にエンコードされるかを定義するテーブルです。例えば、`AADD`命令が2つのレジスタと1つのレジスタオペランドを取る場合、そのエンコーディング形式が`optab`に記述されています。
    *   `aclass`関数は、Goのアセンブラが与えられたオペランド（例えば、`R1`, `10(R2)`, `0x12345678`）をMIPS64のどのカテゴリ（汎用レジスタ、メモリ参照、即値定数など）に分類するかを決定します。この分類は、`oplook`関数が`optab`から適切な命令エンコーディングを見つけるために重要です。
    *   `span0`関数内のブランチ命令の拡張ロジックは、MIPS64の分岐命令が持つジャンプ範囲の制限に対処するためのものです。MIPS64の分岐命令は、通常、PC（プログラムカウンタ）からの相対オフセットでジャンプしますが、そのオフセットには限りがあります。もしターゲットがその範囲外にある場合、リンカは直接ジャンプできないため、まず無条件ジャンプ命令（`JMP`）を挿入し、その`JMP`命令のターゲットを実際のターゲットに設定することで、より広い範囲へのジャンプを可能にします。この際、ブランチ遅延スロットを埋めるために`NOP`命令が挿入されます。

これらの変更により、GoツールチェインはMIPS64アーキテクチャの特性を理解し、効率的かつ正確な機械語を生成できるようになります。
