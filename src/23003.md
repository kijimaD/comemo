# [インデックス 23003] ファイルの概要

このコミットは、Go言語の標準ライブラリ`net`パッケージにおける書き込み（Write）操作のエラー値の不整合を修正することを目的としています。具体的には、`Write`、`WriteTo`、`WriteMsg`などの様々な書き込み関連関数が返すエラーの形式を統一し、`*net.OpError`として一貫してラップされるように変更しています。これにより、Goアプリケーションがネットワーク操作のエラーをより予測可能かつ容易に処理できるようになります。

## 変更の背景

Go言語の`net`パッケージは、ネットワーク通信を行うための基本的な機能を提供します。しかし、このコミット以前は、様々な書き込み操作（TCP、UDP、Unixドメインソケットなど）において、エラーの返され方が一貫していませんでした。

具体的には、以下のような問題がありました。

1.  **エラーのラップの有無の不整合**: 一部の低レベルな書き込み関数（例: `fd_unix.go`や`fd_windows.go`内の`fd.Write`）は、発生したシステムコールエラーを`*net.OpError`でラップして返していました。一方で、他の高レベルな書き込み関数（例: `iprawsock_plan9.go`内の`WriteToIP`）は、`syscall.Err`のような生のシステムコールエラーを直接返していました。
2.  **エラー情報の欠落**: 生のエラーが返される場合、そのエラーがどのネットワーク操作（`read`、`write`など）で発生したのか、どのネットワークタイプ（`tcp`、`udp`など）やアドレスに関連するのかといった、`*net.OpError`が提供する付加的なコンテキスト情報が失われていました。
3.  **エラーハンドリングの複雑化**: アプリケーション開発者は、ネットワーク操作のエラーを処理する際に、返されるエラーが`*net.OpError`であるか、それとも生のエラーであるかを区別する必要がありました。これにより、エラーの型アサーションやエラーチェーンの解析が複雑になり、堅牢なエラーハンドリングの実装が困難になっていました。

この不整合は、特に異なるOSやネットワークプロトコル間でコードを移植する際に問題となり、Goの「エラーは値である」という哲学に反するものでした。このコミットは、これらの問題を解決し、`net`パッケージのエラーモデルをより堅牢で予測可能なものにすることを目指しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のネットワークプログラミングとエラーハンドリングに関する知識が必要です。

1.  **`net`パッケージ**: Go言語の標準ライブラリで、TCP/IP、UDP、UnixドメインソケットなどのネットワークI/O機能を提供します。`net.Conn`、`net.PacketConn`、`net.Listener`などのインターフェースを通じて、ネットワーク接続の確立、データの送受信、接続の終了などを行います。
2.  **`*net.OpError`**: `net`パッケージで定義されているエラー型の一つです。ネットワーク操作中に発生したエラーに関する詳細な情報を提供するために使用されます。
    *   `Op`: 発生した操作の種類（例: "read", "write", "dial"）。
    *   `Net`: ネットワークの種類（例: "tcp", "udp", "unix"）。
    *   `Source`: ローカルアドレス。
    *   `Addr`: リモートアドレス。
    *   `Err`: 根本的なエラー（通常は`os.SyscallError`やその他のシステムエラー）。
    この構造により、開発者はエラーの原因をより詳細に特定し、適切なエラーハンドリングを行うことができます。
3.  **`syscall`パッケージ**: オペレーティングシステムのシステムコールへの低レベルなインターフェースを提供します。ネットワーク操作の多くは、内部的にこのパッケージを通じてシステムコールを呼び出します。`syscall.Errno`は、システムコールが返すエラーコードを表します。
4.  **エラーのラップとアンラップ**: Go 1.13以降で導入されたエラーハンドリングの機能で、`fmt.Errorf`の`%w`動詞や`errors.Is`, `errors.As`関数を使って、エラーを別のエラーでラップしたり、ラップされたエラーから元のエラーを取り出したりすることができます。このコミットはGo 1.13以前のものですが、`*net.OpError`自体がエラーをラップする構造として機能していました。
5.  **`fd_unix.go`, `fd_windows.go`などのファイル**: `net`パッケージの内部実装で、Unix系OSやWindowsなどの特定のプラットフォームにおけるファイルディスクリプタ（またはソケットハンドル）の操作を抽象化しています。これらのファイルには、実際のシステムコールを呼び出す低レベルなI/O関数が含まれています。
6.  **`PrepareWrite()`**: ネットワーク操作を行う前に、ファイルディスクリプタが書き込み可能であるか、またはブロックしないかを準備するための内部関数。

## 技術的詳細

このコミットの技術的な核心は、`net`パッケージ内の様々な書き込み関数が返すエラーの「正規化」にあります。以前は、エラーが`*net.OpError`でラップされるタイミングや、そもそもラップされるかどうかが一貫していませんでした。この変更は、そのロジックを再構築し、以下の原則に基づいています。

1.  **低レベル関数からの生エラー返却**: `src/net/fd_unix.go`や`src/net/fd_windows.go`のようなプラットフォーム固有の低レベルなファイルディスクリプタ操作関数（例: `fd.Write`, `fd.writeTo`, `fd.writeMsg`）は、`syscall`パッケージから返されるエラーを**直接**返すように変更されました。これにより、これらの関数は純粋にシステムコール結果を反映するようになります。
    *   変更前: `return 0, &OpError{"write", fd.net, fd.raddr, err}`
    *   変更後: `return 0, err`
2.  **高レベル関数での`*net.OpError`による一貫したラップ**: `net.Conn`インターフェースを実装する`conn`型や、`net.PacketConn`インターフェースを実装する`UDPConn`, `IPConn`, `UnixConn`などの高レベルな型における`Write`、`WriteTo`、`WriteMsg`メソッドが、低レベル関数から返された生のエラーや、その他の特定の条件で発生するエラー（例: `syscall.EINVAL`, `ErrWriteToConnected`, `errMissingAddress`）を**必ず**`*net.OpError`でラップするように変更されました。
    *   変更前: `return 0, syscall.EPLAN9` (Plan 9の場合)
    *   変更後: `return 0, &OpError{Op: "write", Net: c.fd.net, Addr: addr, Err: syscall.EPLAN9}`
    *   `src/net/net.go`の`conn.Write`メソッドでは、`fd.Write`から返されたエラーを中央で`*net.OpError`にラップするロジックが追加されました。これにより、接続モードに応じて適切なアドレス（`raddr`または`laddr`）が`OpError`に設定されます。
3.  **テストによるエラーの一貫性検証**: `src/net/error_test.go`に`parseWriteError`という新しいヘルパー関数が追加されました。この関数は、与えられたエラーが`net`パッケージの書き込み関数から返されるべき期待される形式（`*net.OpError`でラップされ、その内部に`os.SyscallError`などが含まれる）に準拠しているかを検証します。これにより、将来的な回帰を防ぎ、エラーモデルの一貫性を保証します。`src/net/timeout_test.go`でもこの関数が利用され、テストの堅牢性が向上しています。

この変更により、Goの`net`パッケージを利用する開発者は、ネットワーク書き込み操作でエラーが発生した場合、常に`*net.OpError`を受け取ることが期待できるようになります。これにより、エラーの型アサーションやエラーチェーンの解析が簡素化され、より信頼性の高いエラーハンドリングロジックを記述できるようになります。

## コアとなるコードの解説

このコミットの核心は、エラーの「生成元」と「ラップ元」を分離し、高レベルなAPIが常に一貫したエラー型を返すようにすることです。

1.  **低レベルI/O関数の役割の明確化**:
    `src/net/fd_unix.go`や`src/net/fd_windows.go`にある`fd.Write`などの関数は、OSのシステムコール（`syscall.Sendto`, `syscall.WSASend`など）を直接呼び出します。これらの関数は、システムコールが返したエラーをそのまま（`*net.OpError`でラップせずに）返すように変更されました。これにより、これらの関数は純粋にシステムコール結果のラッパーとしての役割に徹し、エラーの「生成元」となります。

2.  **高レベルAPIでの`*net.OpError`の集中生成**:
    `src/net/net.go`の`conn.Write`や、`src/net/udpsock_posix.go`の`UDPConn.WriteToUDP`などの高レベルなAPIメソッドが、エラーの「ラップ元」としての役割を担うようになりました。
    *   これらのメソッドは、低レベルI/O関数から返された生のエラーを受け取ります。
    *   また、`syscall.EINVAL`（不正な引数）や`ErrWriteToConnected`（接続済みソケットで`WriteTo`を呼び出した場合）のような、ネットワーク操作のセマンティクスに関連する特定のエラーもここで捕捉されます。
    *   これらのエラーはすべて、`&net.OpError{Op: "write", Net: ..., Addr: ..., Err: underlyingErr}`の形式でラップされます。これにより、アプリケーション開発者は、どのネットワーク操作（`Op`）、どのネットワークタイプ（`Net`）、どのリモートアドレス（`Addr`）で、どのような根本的なエラー（`Err`）が発生したかを一貫して知ることができます。特に`conn.Write`では、接続モード（コネクション指向か、コネクションレスか）に応じて`raddr`または`laddr`を`OpError`の`Addr`フィールドに設定するロジックが追加され、より正確なコンテキストが提供されます。

3.  **エラー検証の強化**:
    `src/net/error_test.go`に追加された`parseWriteError`関数は、この新しいエラーモデルが正しく機能しているかを検証するための重要なツールです。この関数は、エラーが`*net.OpError`で始まり、その内部に期待されるエラー型（`os.SyscallError`など）が含まれているかをチェックします。これにより、`net`パッケージのテストスイートは、エラーの一貫性が維持されていることを自動的に確認できるようになりました。

この変更は、Goのエラーハンドリングのベストプラクティスに沿ったものです。つまり、エラーは発生した場所で詳細なコンテキストを持つべきであり、高レベルなAPIはユーザーにとって意味のある、予測可能なエラー型を返すことで、エラー処理の負担を軽減すべきであるという考え方です。
