## 変更の背景

Goランタイムは、プログラムのメモリ使用状況を詳細に追跡し、`runtime.MemStats` 構造体を通じてその統計情報を提供します。`MemStats.Mallocs` フィールドは、プログラムがこれまでに実行したメモリ確保（アロケーション）の総回数を表します。

Go 1.3以前のバージョンでは、非常に小さなサイズのメモリ確保（いわゆる「tiny allocations」）が `MemStats.Mallocs` のカウントに含まれていないという問題がありました。これは、ランタイムの内部的な最適化や、特定の小さなオブジェクトのアロケーションパスが、一般的なアロケーションカウントのロジックから外れていたためと考えられます。

このコミットの背景にあるのは、Goランタイムのメモリ統計の正確性を向上させるという目的です。特に、`MemStats.Mallocs` が提供する情報が、実際のメモリ確保操作の総数をより正確に反映するように修正されました。この修正は、メモリ使用量のプロファイリングや、`testing.AllocsPerRun` のようなツールを用いたパフォーマンス測定において、より信頼性の高いデータを提供するために不可欠でした。

## 前提知識の解説

### Goランタイムとメモリ管理

Go言語は、独自のランタイムシステムを持ち、その中でメモリ管理（アロケータとガベージコレクタ）を自律的に行います。Goプログラムがメモリを要求すると、ランタイムのアロケータがヒープからメモリを割り当てます。

### `runtime.MemStats`

`runtime` パッケージは、Goプログラムのランタイムシステムに関する情報を提供します。`runtime.MemStats` は、Goプログラムのメモリ使用状況に関する詳細な統計情報を含む構造体です。この構造体は、`runtime.ReadMemStats` 関数を呼び出すことで取得できます。

`MemStats` 構造体には、以下のようなフィールドが含まれます（関連する一部のみ抜粋）：

*   **`Alloc`**: 現在ヒープに割り当てられているオブジェクトによって使用されているバイト数。
*   **`TotalAlloc`**: プログラムの開始以降にヒープに割り当てられたオブジェクトの総バイト数。
*   **`Sys`**: ランタイムがOSから取得したメモリの総バイト数。
*   **`Mallocs`**: プログラムの開始以降に実行されたメモリ確保操作の総回数。
*   **`Frees`**: プログラムの開始以降に実行されたメモリ解放操作の総回数。
*   **`HeapObjects`**: 現在ヒープに存在するオブジェクトの総数。

### Tiny Allocations (小さなアロケーション)

Goランタイムのメモリ管理では、様々なサイズのアロケーションを効率的に処理するために、異なる戦略が用いられます。特に、非常に小さなオブジェクト（例えば、数バイトから数十バイト）のアロケーションは「tiny allocations」と呼ばれ、特別な最適化が施されることがあります。これは、小さなオブジェクトが頻繁にアロケート・デアロケートされる場合に、アロケータのオーバーヘッドを最小限に抑えるためです。

Goのメモリ管理は、通常、ページ（通常8KB）単位でOSからメモリを取得し、それをさらに小さなスパン（span）に分割してオブジェクトに割り当てます。小さなオブジェクトの場合、複数のオブジェクトが同じスパンにパックされることがあります。

### `testing.AllocsPerRun`

`testing` パッケージは、Goのテストフレームワークを提供します。`testing.AllocsPerRun` は、ベンチマークテストにおいて、指定された関数が実行される間に発生するメモリ確保の回数を測定するためのヘルパー関数です。これは、コードのパフォーマンス特性、特にメモリ割り当ての効率を評価する上で非常に有用です。

## 技術的詳細

この変更の技術的詳細の核心は、Goランタイムのメモリ確保パスにおける `MemStats.Mallocs` のインクリメントロジックの修正にあります。

Goのメモリ管理システムは、アロケーション要求のサイズに基づいて異なるパスを取ることがあります。
1.  **Tiny Objects (<= 16 bytes)**: 非常に小さなオブジェクトは、`mcache` (per-P cache) 内の `tiny` アロケータによって処理されることがあります。これは、ロックフリーで高速なアロケーションを提供します。
2.  **Small Objects (16 bytes < size <= 32KB)**: これらのオブジェクトは、`mcache` 内のサイズクラスに応じたスパンから割り当てられます。
3.  **Large Objects (> 32KB)**: これらのオブジェクトは、`mheap` (global heap) から直接割り当てられます。

Go 1.3以前では、特に `tiny` アロケータによって処理されるような非常に小さなアロケーションが、`MemStats.Mallocs` のカウントロジックから漏れていた可能性があります。これは、これらのアロケーションが、一般的な `malloc` 呼び出しとは異なる、より最適化された（そして、もしかしたら統計更新のロジックが省略された）パスを通っていたためと考えられます。

このコミットが参照している `CL 143150043` で行われた実際の変更は、ランタイムの内部アロケーション関数（例: `runtime.mallocgc` やその内部で呼び出される関数）において、すべてのメモリ確保操作、特に `tiny` アロケーションを含むすべてのサイズのアロケーションに対して、`MemStats.Mallocs` カウンタが適切にインクリメントされるように修正されたものと推測されます。

この修正により、`MemStats.Mallocs` は、Goプログラムが実行したすべてのメモリ確保操作の真の総数を反映するようになります。結果として、`runtime.ReadMemStats` や `testing.AllocsPerRun` を使用する既存のテストやプロファイリングツールは、Go 1.3と比較してより高い `Mallocs` カウントを報告する可能性があります。これは、以前のバージョンでは見過ごされていたアロケーションが、Go 1.4以降で正確にカウントされるようになったためです。

## コアとなるコードの解説

このコミット自体はドキュメントの変更であるため、直接的な「コアとなるコード」の変更はありません。しかし、このドキュメントの変更が指し示している `CL 143150043` におけるランタイムの変更は、Goのメモリ管理の正確性を向上させる上で非常に重要です。

`CL 143150043` で行われたであろう変更は、Goランタイムの内部的なメモリ確保関数（例: `runtime.mallocgc` や、`tiny` オブジェクトを扱うための低レベルなアロケーションルーチン）に、`MemStats.Mallocs` カウンタをインクリメントするロジックを追加または修正することであったと推測されます。

具体的には、Goのランタイムは、メモリを割り当てる際に `runtime.mstats.mallocs` というグローバルカウンタをインクリメントします。以前は、特定の最適化されたパス（特に非常に小さなアロケーションの場合）でこのカウンタのインクリメントがスキップされていた可能性があります。`CL 143150043` は、これらのスキップされていたアロケーションパスにも、このカウンタのインクリメントを確実に含めるように修正したと考えられます。

この修正により、`runtime.ReadMemStats` を通じて取得される `MemStats.Mallocs` の値は、Goプログラムが実行したすべてのメモリ確保操作を網羅するようになり、より正確なメモリプロファイリングやベンチマークが可能になります。ただし、これにより `testing.AllocsPerRun` を使用する既存のテストが、Go 1.3と比較して異なる（通常は高い）アロケーション数を報告する可能性があるため、テストの調整が必要になる場合があることがドキュメントに明記されています。
