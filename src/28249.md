# [インデックス 28249] ファイルの概要

このコミットは、Go言語のビルドシステムにおいて、`darwin/arm` および `darwin/arm64` プラットフォームで `c-archive` ビルドモードを使用する際のデフォルトのビルドオプションに `-shared` フラグを追加する変更です。これにより、これらのプラットフォームで生成されるアーカイブがPosition Independent Code (PIC) を含むようになり、特に `gomobile` のようなツールが標準ライブラリをPICサポート付きでインストールできるようになります。

## 元コミット内容

cmd/go: add -shared to darwin/arm{,64} default build mode

Buildmode c-archive now supports position independent code for
darwin/arm (in addition to darwin/arm64). Make PIC (-shared) the
default for both platforms in the default buildmode.

Without this change, gomobile will go install the standard library
into its separate package directory without PIC support.

Also add -shared to darwin/arm64 in buildmode c-archive, for
symmetry (darwin/arm64 always generates position independent code).

Fixes #15519
```

## 変更の背景

この変更の主な背景には、Go言語でiOSアプリケーションを開発する際に利用される `gomobile` ツールが関係しています。

以前は、`darwin/arm` (32ビットARMアーキテクチャ、主に古いiOSデバイス向け) で `c-archive` ビルドモードを使用してGoコードをアーカイブ化する際に、Position Independent Code (PIC) がデフォルトで生成されていませんでした。PICではないコードは、メモリ上の特定のアドレスにロードされることを前提としているため、共有ライブラリや動的にロードされるモジュールとしては不適切です。iOSのようなモダンなOSでは、セキュリティ上の理由（ASLR: Address Space Layout Randomization）やメモリ効率の観点から、共有ライブラリはPICである必要があります。

`gomobile` は、Goの標準ライブラリをiOSアプリケーションに組み込む際に、`c-archive` モードでビルドされたアーカイブを利用します。PICがデフォルトで有効になっていないと、`gomobile` が標準ライブラリをインストールする際に、PICをサポートしない形式でインストールされてしまい、結果としてiOSアプリケーションのビルドや実行に問題が生じる可能性がありました。

このコミットは、`darwin/arm` プラットフォームで `c-archive` ビルドモードがPICをサポートするようになったことを受け、その機能を活用してデフォルトでPICを生成するように変更することで、`gomobile` の利用体験を改善し、関連する問題を解決することを目的としています。また、`darwin/arm64` (64ビットARMアーキテクチャ) では既にPICが生成されていましたが、一貫性を持たせるために明示的に `-shared` フラグを追加しています。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念を把握しておく必要があります。

1.  **Goのビルドモード (`buildmode`)**:
    Goコンパイラは、様々な形式のバイナリを生成するための「ビルドモード」をサポートしています。`go build -buildmode=<mode>` の形式で指定します。
    *   **`c-archive`**: GoパッケージをCアーカイブライブラリ (`.a` ファイル) としてビルドします。これは、C/C++プロジェクトやObjective-Cプロジェクト（iOSアプリなど）にGoコードを組み込む際に使用されます。生成されたアーカイブは、Cリンカによって他のオブジェクトファイルとリンクされます。
    *   **`c-shared`**: GoパッケージをC共有ライブラリ (`.so` または `.dylib` ファイル) としてビルドします。これは、動的にロードされるライブラリとしてGoコードを使用する場合に利用されます。
    *   **`exe`**: 実行可能ファイルをビルドします（デフォルト）。
    *   **`pie` (Position Independent Executable)**: 位置独立実行可能ファイルをビルドします。

2.  **Position Independent Code (PIC)**:
    位置独立コードとは、メモリ上のどこにロードされても正しく実行できるコードのことです。これは、コード内の絶対アドレス参照を相対アドレス参照に置き換えることで実現されます。
    *   **なぜ重要か**:
        *   **共有ライブラリ**: 複数のプロセスで同じライブラリのコードセグメントを共有するために不可欠です。各プロセスはライブラリを異なる仮想アドレスにロードする可能性があるため、コードが位置独立である必要があります。
        *   **セキュリティ (ASLR)**: Address Space Layout Randomization (ASLR) は、セキュリティを向上させるために、実行可能ファイルやライブラリがメモリにロードされるアドレスをランダム化する技術です。PICはASLRと組み合わせて使用され、攻撃者が特定のコードやデータを予測可能なアドレスに配置することを困難にします。
    *   **`-shared` フラグ**: コンパイラやリンカにPICを生成するように指示する一般的なフラグです。Goのビルドシステムでは、内部的にこのフラグを適切なツールチェーンに渡します。

3.  **`darwin/arm` および `darwin/arm64`**:
    Go言語におけるターゲットプラットフォームの指定です。
    *   `darwin`: オペレーティングシステムがmacOSまたはiOSであることを示します。
    *   `arm`: 32ビットARMアーキテクチャを指します。主に古いiPhoneやiPadなどのiOSデバイスで使用されていました。
    *   `arm64`: 64ビットARMアーキテクチャを指します。現在のほとんどのiPhoneやiPad、Apple Silicon Macで使用されています。

4.  **`gomobile`**:
    Go言語でモバイルアプリケーション（AndroidおよびiOS）を開発するためのツールセットです。Goコードをモバイルプラットフォーム向けのライブラリとしてビルドし、ネイティブアプリケーションに組み込むことを可能にします。`gomobile` は内部的に `go build -buildmode=c-archive` を利用してGoコードをアーカイブ化します。

## 技術的詳細

このコミットは、Goのビルドコマンド (`cmd/go`) の内部ロジックと、`cgo` を使用したアーカイブのテストケースに影響を与えます。

主要な変更点は以下の通りです。

1.  **`src/cmd/go/build.go` の変更**:
    このファイルは `go build` コマンドのビルドロジックを定義しています。
    *   `buildModeInit` 関数内で、`c-archive` ビルドモードの際の `codegenArg` (コード生成引数) の設定ロジックが変更されています。
    *   以前は、`darwin/arm` プラットフォームでのみ `codegenArg = "-shared"` が設定されていました。
    *   変更後、`darwin/arm` に加えて `darwin/arm64` プラットフォームも `codegenArg = "-shared"` の対象に追加されました。これにより、`darwin/arm` および `darwin/arm64` の両方で、`c-archive` ビルド時にデフォルトでPICが生成されるようになります。
    *   また、`ldBuildmode` (リンカのビルドモード) を設定する別の `switch` ステートメントでも、`darwin/arm` と `darwin/arm64` に対して `codegenArg = "-shared"` が明示的に追加され、`fallthrough` を使用してデフォルトの `ldBuildmode = "exe"` に続くように変更されています。これは、`c-archive` モードで `-shared` を指定しつつ、リンカのビルドモードとしては実行可能ファイル（またはそれに準ずる形式）として扱うという意図を示唆しています。

2.  **`misc/cgo/testcarchive/carchive_test.go` の変更**:
    このファイルは `c-archive` ビルドモードの動作をテストするためのGoテストファイルです。
    *   `libgodir` 変数の設定ロジックが変更されています。この変数は、ビルドされたGoライブラリが配置されるディレクトリ名を決定するために使用されます。
    *   以前は、`GOOS == "darwin" && GOARCH == "arm"` の場合にのみ `libgodir` に `_shared` サフィックスが追加されていました。
    *   変更後、`GOOS == "darwin" && (GOARCH == "arm" || GOARCH == "arm64")` の場合に `_shared` サフィックスが追加されるようになりました。これは、`darwin/arm64` も共有ライブラリとして扱われるようになったことをテストコード側で反映しています。

これらの変更により、`go build -buildmode=c-archive` コマンドが `darwin/arm` および `darwin/arm64` ターゲットに対して、デフォルトでPICを生成するようになり、`gomobile` などのツールがより適切に機能するようになります。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更点

*   **`case "darwin/arm", "darwin/arm64": codegenArg = "-shared"`**:
    この部分では、`c-archive` ビルドモードが選択された際に、Goコンパイラに渡すコード生成引数 (`codegenArg`) を設定しています。以前は `darwin/arm` のみでしたが、`darwin/arm64` も追加されました。これにより、Goコンパイラはこれらのプラットフォーム向けにPICを生成するように指示されます。PICは、共有ライブラリとして機能するために不可欠な特性であり、特にiOS環境では必須です。

*   **`case "darwin/arm", "darwin/arm64": codegenArg = "-shared"; fallthrough`**:
    この別の `switch` ステートメントは、リンカのビルドモード (`ldBuildmode`) を設定する部分です。ここでも `darwin/arm` と `darwin/arm64` が追加され、`codegenArg = "-shared"` が設定されています。`fallthrough` キーワードは、この `case` の処理が完了した後、次の `default` `case` の処理も実行するように指示します。これにより、`ldBuildmode` は `exe` (実行可能ファイル) として扱われつつ、コード生成時には `-shared` フラグが適用されるという、`c-archive` モードにおける特定の挙動が実現されます。これは、Goの `c-archive` が最終的にネイティブの実行可能ファイルにリンクされることを考慮した設計です。

### `misc/cgo/testcarchive/carchive_test.go` の変更点

*   **`if GOOS == "darwin" && (GOARCH == "arm" || GOARCH == "arm64")`**:
    この変更は、テストスイートがビルドされたGoライブラリのディレクトリ名を決定する方法を更新しています。`c-archive` モードでビルドされた共有ライブラリは、通常、その特性を示すためにディレクトリ名に `_shared` サフィックスを持つことがあります。以前は `darwin/arm` の場合にのみこのサフィックスが追加されていましたが、このコミットにより `darwin/arm64` も同様に扱われるようになりました。これは、`darwin/arm64` もデフォルトでPICを生成するようになったという `build.go` の変更をテスト側で正しく反映するためのものです。これにより、テストが新しいビルド設定と一貫性を持つことが保証されます。

これらの変更は、Goのビルドシステムが `darwin/arm` および `darwin/arm64` プラットフォームで `c-archive` を使用する際に、よりモダンなOSの要件（PICの利用）に適合するように調整されたことを示しています。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更点

*   **`case "darwin/arm", "darwin/arm64": codegenArg = "-shared"`**:
    この部分では、`c-archive` ビルドモードが選択された際に、Goコンパイラに渡すコード生成引数 (`codegenArg`) を設定しています。以前は `darwin/arm` のみでしたが、`darwin/arm64` も追加されました。これにより、Goコンパイラはこれらのプラットフォーム向けにPICを生成するように指示されます。PICは、共有ライブラリとして機能するために不可欠な特性であり、特にiOS環境では必須です。

*   **`case "darwin/arm", "darwin/arm64": codegenArg = "-shared"; fallthrough`**:
    この別の `switch` ステートメントは、リンカのビルドモード (`ldBuildmode`) を設定する部分です。ここでも `darwin/arm` と `darwin/arm64` が追加され、`codegenArg = "-shared"` が設定されています。`fallthrough` キーワードは、この `case` の処理が完了した後、次の `default` `case` の処理も実行するように指示します。これにより、`ldBuildmode` は `exe` (実行可能ファイル) として扱われつつ、コード生成時には `-shared` フラグが適用されるという、`c-archive` モードにおける特定の挙動が実現されます。これは、Goの `c-archive` が最終的にネイティブの実行可能ファイルにリンクされることを考慮した設計です。

### `misc/cgo/testcarchive/carchive_test.go` の変更点

*   **`if GOOS == "darwin" && (GOARCH == "arm" || GOARCH == "arm64")`**:
    この変更は、テストスイートがビルドされたGoライブラリのディレクトリ名を決定する方法を更新しています。`c-archive` モードでビルドされた共有ライブラリは、通常、その特性を示すためにディレクトリ名に `_shared` サフィックスを持つことがあります。以前は `darwin/arm` の場合にのみこのサフィックスが追加されていましたが、このコミットにより `darwin/arm64` も同様に扱われるようになりました。これは、`darwin/arm64` もデフォルトでPICを生成するようになったという `build.go` の変更をテスト側で正しく反映するためのものです。これにより、テストが新しいビルド設定と一貫性を持つことが保証されます。

これらの変更は、Goのビルドシステムが `darwin/arm` および `darwin/arm64` プラットフォームで `c-archive` を使用する際に、よりモダンなOSの要件（PICの利用）に適合するように調整されたことを示しています。
