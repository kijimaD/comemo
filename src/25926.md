# [インデックス 25926] ファイルの概要

このコミットは、Go言語の`net`パッケージにおいて、Plan 9オペレーティングシステム上でのDNS名解決の挙動を修正するものです。具体的には、DNSルックアップによって返されるドメイン名が、他のオペレーティングシステムとの一貫性を保つために、末尾にルートを示すドット（`.`）が付加された「rooted DNS name」として返されるように変更されました。

## 変更の背景

この変更の背景には、Go言語の`net`パッケージがPlan 9環境でDNSルックアップを実行した際に、他の主要なオペレーティングシステム（Linux, macOS, Windowsなど）と異なる形式のドメイン名を返していたという問題があります。具体的には、Plan 9では完全修飾ドメイン名（FQDN）の末尾にルートを示すドット（`.`）が付加されない形式で返されることがありましたが、他のシステムでは通常、このドットが付加された「rooted DNS name」として返されます。

この不一致は、Goアプリケーションが異なるOS環境で動作する際に、DNSルックアップの結果に依存するロジックが予期せぬ挙動を示す可能性がありました。例えば、ドメイン名の正規化や比較を行う際に、末尾のドットの有無によって結果が変わってしまうといった問題が考えられます。この一貫性の欠如を解消し、クロスプラットフォームでの互換性と予測可能性を高めるために、Plan 9においてもrooted DNS nameを返すように修正する必要がありました。

この変更は、Issue #12193 に対応するものです。

## 前提知識の解説

### DNS (Domain Name System)

DNSは、インターネット上のコンピュータやサービスを識別するための階層的な分散型命名システムです。人間が覚えやすいドメイン名（例: `example.com`）を、コンピュータが理解できるIPアドレス（例: `192.0.2.1`）に変換（名前解決）する役割を担っています。

### ルート付きDNS名 (Rooted DNS Name / FQDN)

完全修飾ドメイン名（Fully Qualified Domain Name, FQDN）は、ドメイン名の階層構造において、ルートゾーン（`.`）まで含めて完全に指定されたドメイン名です。例えば、`www.example.com` のFQDNは `www.example.com.` となります。末尾のドットは、そのドメイン名がDNSツリーのルートに対して絶対的なパスであることを示します。

多くのDNSクライアントやライブラリは、ユーザーが末尾のドットを省略しても自動的に補完して処理しますが、内部的にはFQDNとして扱われることが一般的です。このコミットの文脈では、Goの`net`パッケージがDNSルックアップの結果として返すドメイン名が、この末尾のドットを含むべきかどうかが問題となりました。

### Plan 9

Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Unixの概念をさらに推し進め、すべてのリソース（ファイル、デバイス、ネットワーク接続など）をファイルシステムとして表現するという特徴を持っています。ネットワークプロトコルやDNS解決のメカニズムも、そのファイルシステム中心の設計思想に沿って実装されています。このため、他のOSとは異なるDNS解決の挙動を示すことがありました。

### Go言語の `net` パッケージ

Go言語の標準ライブラリに含まれる`net`パッケージは、ネットワークI/O機能を提供します。TCP/IP、UDP、Unixドメインソケットなどのネットワークプロトコルを扱うためのAPIが含まれており、DNSルックアップ機能もこのパッケージの一部として提供されています。`net.LookupHost`, `net.LookupIP`, `net.LookupCNAME`などの関数を通じて、ドメイン名からIPアドレス、CNAMEレコード、MXレコードなどを取得できます。

## 技術的詳細

このコミットの技術的詳細は、Plan 9環境におけるDNSルックアップの結果が、他のOSと異なり末尾のドットを持たない場合があるという問題に対処することにあります。

Goの`net`パッケージは、内部的に各OSのネイティブなDNS解決メカニズムを利用するか、あるいは独自のDNSクライアントを実装しています。Plan 9の場合、`src/net/lookup_plan9.go`ファイルがその役割を担っています。

問題は、`lookupSRV`、`lookupMX`、`lookupNS`、`lookupTXT`、`lookupAddr`といったDNSレコードを問い合わせる関数が、返されるドメイン名に対して一貫して末尾のドットを付加していなかった点です。これにより、例えば`example.com`というドメイン名が、他のOSでは`example.com.`として返されるのに対し、Plan 9では`example.com`のまま返される可能性がありました。

この不一致を解消するため、コミットでは以下の戦略が取られました。

1.  **ヘルパー関数の導入**: `ensureEndDot(name string) string` という新しいヘルパー関数が導入されました。この関数は、与えられたドメイン名が空文字列であれば単にドットを返し、既に末尾にドットがあればそのままの文字列を返し、そうでなければ末尾にドットを付加した文字列を返します。
2.  **既存ルックアップ関数への適用**: `lookupSRV`, `lookupMX`, `lookupNS`, `lookupTXT`, `lookupAddr` の各関数内で、DNSクエリの結果として得られるドメイン名フィールドに対して、この `ensureEndDot` 関数を適用するように変更されました。これにより、Plan 9環境でも常にrooted DNS nameが返されるようになります。

この変更により、Goアプリケーションは、実行されているOSがPlan 9であっても、DNSルックアップの結果として一貫した形式のドメイン名（rooted DNS name）を受け取ることが保証されます。これは、特にDNSSEC検証や、ドメイン名に基づくセキュリティポリシーを実装する際に重要となる可能性があります。

## コアとなるコードの解説

### `ensureEndDot` 関数

```go
// ensureEndDot adds '.' at the end of name unless it is already there.
func ensureEndDot(name string) string {
	if name == "" {
		return "."
	}
	if name[len(name)-1] == '.' {
		return name
	}
	return name + "."
}
```
この関数は、与えられた`name`文字列がrooted DNS nameである（末尾にドットがある）ことを保証するためのユーティリティです。
1.  `name`が空文字列の場合、ルートドメインを示すために単一のドット `.` を返します。
2.  `name`の最後の文字が既にドットである場合、変更せずに`name`をそのまま返します。
3.  上記以外の場合（`name`が空でなく、末尾にドットがない場合）、`name`の末尾にドットを追加して返します。

### 各ルックアップ関数への適用

`lookupSRV`, `lookupMX`, `lookupNS`, `lookupTXT`, `lookupAddr` の各関数は、DNSクエリの結果をパースし、ドメイン名を含むフィールドを抽出します。これらの抽出されたドメイン名に対して、`ensureEndDot`関数が適用されています。

例えば、`lookupSRV`関数では、SRVレコードのターゲットホスト名（`f[5]`）とCNAME（`f[0]`）に対して`ensureEndDot`が適用されています。

```go
// 変更前
// addrs = append(addrs, &SRV{f[5], uint16(port), uint16(priority), uint16(weight)})
// cname = f[0]

// 変更後
addrs = append(addrs, &SRV{ensureEndDot(f[5]), uint16(port), uint16(priority), uint16(weight)})
cname = ensureEndDot(f[0])
```

同様に、`lookupMX`ではMXレコードのメールエクスチェンジャーホスト名（`f[3]`）、`lookupNS`ではネームサーバーホスト名（`f[2]`）、`lookupTXT`ではTXTレコードのテキストデータ（`line[i+1:]`）、`lookupAddr`では逆引きルックアップの結果得られるホスト名（`f[2]`）に対して、それぞれ`ensureEndDot`が適用されています。

これにより、Plan 9環境でこれらのDNSルックアップ関数が呼び出された場合でも、返されるドメイン名が常に末尾にドットを持つrooted DNS nameとして統一され、他のOS環境との一貫性が保たれるようになります。
