# [インデックス 20095] ファイルの概要

このコミットでは、主にGo言語の`net`パッケージにおけるWindows環境でのDNSルックアップの挙動が修正されています。具体的には、CNAME（Canonical Name）レコードの解決に関する問題が対処され、関連するシステムコールやテストが追加されています。

変更されたファイルは以下の通りです。

-   `src/pkg/net/lookup_windows.go`: Windows環境でのDNSルックアップロジックの主要な変更が含まれています。特に`lookupCNAME`関数の修正と、`validRecs`、`resolveCNAME`といった補助関数の追加が行われました。
-   `src/pkg/net/lookup_windows_test.go`: このコミットで新規に追加されたテストファイルです。WindowsにおけるDNSルックアップの正確性を検証するためのテストケースが含まれています。`nslookup`コマンドを外部プロセスとして利用し、Goの`net`パッケージの挙動と比較しています。

-   `src/pkg/syscall/zsyscall_windows_amd64.go`: Windows AMD64アーキテクチャ向けのシステムコール実装ファイルです。こちらも`DnsNameCompare`システムコールの呼び出しに関するコードが自動生成によって追加されています。
-   `src/pkg/syscall/ztypes_windows.go`: Windowsシステムコールに関連する型定義ファイルです。DNS関連の新しい定数（`DNS_INFO_NO_RECORDS`や`DnsSection`関連のマスク）が追加されています。

## 変更の背景

このコミットは、Go言語の`net`パッケージがWindows環境でCNAMEレコードを適切に解決できないという問題（Issue #8492: "net: LookupNS does not resolve CNAME on windows"）を修正するために行われました。

従来のGoの`net`パッケージは、WindowsのDNS API (`DnsQuery`) を利用してDNSルックアップを行っていましたが、CNAMEレコードの解決に関していくつかの不完全な点がありました。具体的には、以下のような問題が挙げられます。

1.  **`DNS_INFO_NO_RECORDS`の不適切なハンドリング**: `DnsQuery`がCNAMEレコードを見つけられない場合に`DNS_INFO_NO_RECORDS`というエラーコードを返すことがありますが、Goのコードがこれを適切に処理せず、CNAMEが存在しない場合に誤った結果を返す可能性がありました。
2.  **CNAMEチェーンの未解決**: 複数のCNAMEレコードが連鎖している場合（例: `a.example.com` -> `b.example.com` -> `c.example.com`）、Goの既存のロジックでは最終的な正規名まで辿り着けないことがありました。
3.  **DNSレコードのフィルタリングの不備**: `DnsQuery`は様々な種類のDNSレコードを返すことがありますが、Goのルックアップ関数が特定のレコードタイプ（例: MX, SRV, NS, TXT, PTR）を検索する際に、関連性のないレコードやCNAMEによって解決されるべきレコードを適切にフィルタリングできていませんでした。これにより、不正確な結果が返される可能性がありました。

これらの問題は、特に`LookupNS`のような関数がCNAMEを適切に解決できないという形で顕在化し、Windows環境でのDNSルックアップの信頼性を低下させていました。このコミットは、これらの問題を解決し、WindowsにおけるDNSルックアップの正確性と堅牢性を向上させることを目的としています。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の前提知識が役立ちます。

-   **DNS (Domain Name System)**:
    インターネット上のコンピュータやサービスを識別するための階層的な分散型命名システムです。人間が覚えやすいドメイン名（例: `example.com`）を、コンピュータが理解できるIPアドレス（例: `192.0.2.1`）に変換する役割を担っています。

-   **CNAMEレコード (Canonical Name Record)**:
    DNSレコードの一種で、あるドメイン名が別のドメイン名の「エイリアス（別名）」であることを示します。例えば、`www.example.com`が`example.com`のCNAMEである場合、`www.example.com`への問い合わせは`example.com`への問い合わせとして扱われます。これにより、複数のサービスが同じIPアドレスを共有したり、サービス名を変更せずにバックエンドのホスト名を変更したりすることが可能になります。

-   **`nslookup`**:
    DNS情報を問い合わせるためのコマンドラインツールです。ドメイン名からIPアドレスを調べたり、特定の種類のDNSレコード（MX, NS, CNAMEなど）を問い合わせたりする際に使用されます。このコミットのテストコードでは、Goの`net`パッケージのルックアップ結果を`nslookup`の結果と比較することで、正確性を検証しています。

-   **Windows DNS API**:
    Windowsオペレーティングシステムが提供するDNSクライアント機能を利用するためのAPI群です。Goの`net`パッケージは、Windows環境ではこれらのAPIを呼び出してDNSルックアップを実行します。
    -   **`DnsQuery`**: DNSクエリを実行するための主要なAPIです。指定されたドメイン名とレコードタイプに基づいてDNSサーバーに問い合わせを行い、結果を`DNSRecord`構造体のリストとして返します。
    -   **`DNSRecord`**: `DnsQuery`の結果として返されるDNSレコードの情報を格納する構造体です。レコードのタイプ、名前、データなどが含まれます。
    -   **`DnsRecordListFree`**: `DnsQuery`によって割り当てられた`DNSRecord`リストのメモリを解放するためのAPIです。メモリリークを防ぐために、`DnsQuery`を使用した後は必ず呼び出す必要があります。
    -   **`DnsNameCompare`**: 2つのDNS名を比較するためのAPIです。DNS名は大文字・小文字を区別しないため、このAPIは適切な比較を行います。

-   **Goの`syscall`パッケージ**:
    Go言語の標準ライブラリの一部で、オペレーティングシステム固有のシステムコールを呼び出すための機能を提供します。Windows環境では、このパッケージを通じて上述のWindows DNS APIをGoのコードから直接呼び出すことができます。

-   **`unsafe.Pointer`**:
    Go言語の型安全性を一時的にバイパスし、任意の型へのポインタを扱うための特殊な型です。Windows APIはC言語のインターフェースを持つため、Goの構造体やデータとAPIの期待するメモリレイアウトとの間で変換を行う際に`unsafe.Pointer`が使用されることがあります。これにより、Goの型システムでは通常許されないポインタ演算や型変換が可能になります。

-   **`syscall.UTF16ToString`**:
    Windows APIは文字列をUTF-16エンコーディングで扱うことが多いため、Goの`syscall`パッケージにはUTF-16エンコードされたバイト列をGoのUTF-8文字列に変換するためのヘルパー関数が用意されています。

## 技術的詳細

このコミットの技術的な変更は、Windows環境におけるGoの`net`パッケージのDNSルックアップの正確性と堅牢性を大幅に向上させるものです。主な変更点は以下の通りです。

1.  **`lookupCNAME`関数の改善**:
    -   `syscall.DnsQuery`がCNAMEレコードを見つけられない場合に`syscall.DNS_INFO_NO_RECORDS`というエラーコードを返すようになりました。このコミットでは、このエラーを明示的にチェックし、その場合は入力された名前自体が正規名であると判断して返すように修正されました。これにより、CNAMEが存在しない場合の挙動がより正確になります。
    -   従来の`DNSRecord`リストを直接走査してCNAMEを探すロジックが削除され、新たに導入された`resolveCNAME`関数が使用されるようになりました。これにより、CNAMEチェーンの解決が適切に行われるようになります。

2.  **`validRecs`関数の導入**:
    -   この新しいヘルパー関数は、`DnsQuery`から返された`DNSRecord`のリストから、指定されたDNSタイプとクエリ名に合致する有効なレコードのみを抽出する役割を担います。
    -   `dnsSectionMask`と`syscall.DnsSectionAnswer`を使用して、DNS応答の「回答セクション」にあるレコードのみを対象とします。これにより、権威セクションや追加セクションにあるレコードが誤って処理されることを防ぎます。
    -   `syscall.DnsNameCompare`（後述）を使用して、レコードの名前とクエリ名を比較し、大文字・小文字を区別せずに正確なマッチングを行います。

3.  **`resolveCNAME`関数の導入**:
    -   この関数は、与えられたDNSレコードのリストの中からCNAMEチェーンを辿り、最終的な正規名（Canonical Name）を解決します。
    -   無限CNAMEループ（例: `a` -> `b` -> `a`）を防ぐために、CNAME解決の深さを10に制限するロジックが組み込まれています。これにより、悪意のある、または誤設定されたDNSレコードによってプログラムがハングアップするのを防ぎます。
    -   `validRecs`と同様に、`syscall.DnsNameCompare`を使用して名前の比較を行います。

4.  **`DnsNameCompare`システムコールの追加**:
    -   WindowsのDNS APIである`DnsNameCompare_W`をGoから呼び出せるように、`src/pkg/syscall/syscall_windows.go`にその宣言が追加されました。
    -   これに伴い、`zsyscall_windows_386.go`と`zsyscall_windows_amd64.go`という自動生成されるファイルにも、このシステムコールを呼び出すためのGoのラッパー関数が追加されました。これにより、GoのコードからWindowsのネイティブなDNS名比較機能を利用できるようになり、正確な名前マッチングが可能になります。

5.  **他のルックアップ関数の変更**:
    -   `lookupSRV`, `lookupMX`, `lookupNS`, `lookupTXT`, `lookupAddr`といった他のDNSルックアップ関数も、レコードのフィルタリングとCNAME解決のために新たに導入された`validRecs`関数を利用するように変更されました。これにより、これらの関数もCNAME解決の恩恵を受け、より正確な結果を返すようになります。

6.  **テストの追加**:
    -   `src/pkg/net/lookup_windows_test.go`という新しいテストファイルが追加されました。このファイルには、`LookupMX`, `LookupCNAME`, `LookupNS`, `LookupTXT`といった主要なDNSルックアップ関数に対するテストケースが含まれています。
    -   これらのテストは、Goの`net`パッケージのルックアップ結果を、Windowsの標準的なDNS問い合わせツールである`nslookup`コマンドの出力と比較することで、Goの実装がWindowsのネイティブなDNS解決と一致していることを検証します。これにより、変更の正確性が保証されます。

これらの変更により、Goの`net`パッケージはWindows環境において、より堅牢で正確なDNSルックアップ、特にCNAME解決を提供できるようになりました。

### `lookupCNAME`関数の変更

```go
	e := syscall.DnsQuery(name, syscall.DNS_TYPE_CNAME, 0, nil, &r, nil)
```

-   **`DNS_INFO_NO_RECORDS`のハンドリング**: `syscall.DnsQuery`が`DNS_INFO_NO_RECORDS`を返した場合（CNAMEレコードが見つからない場合）、エラーとして処理するのではなく、入力された`name`自体が正規名であると判断して返します。これにより、CNAMEが存在しない場合の挙動が明確になります。末尾にドットがない場合はFQDN（完全修飾ドメイン名）としてドットを追加します。
-   **`resolveCNAME`の導入**: 以前は`r.Type == syscall.DNS_TYPE_CNAME`という直接的なチェックでCNAMEを処理していましたが、この部分が削除され、新たに導入された`resolveCNAME`関数が呼び出されるようになりました。`resolveCNAME`はCNAMEチェーンを解決し、最終的な正規名を返します。これにより、複数のCNAMEが連鎖している場合でも正しく解決できるようになります。
-   **結果の変換**: `resolveCNAME`によって得られた`*uint16`（UTF-16エンコードされたポインタ）を`syscall.UTF16ToString`でGoの文字列に変換し、末尾にドットを追加して返します。

### `validRecs`関数の追加

```go
const dnsSectionMask = 0x0003

// returns only results applicable to name and resolves CNAME entries
func validRecs(r *syscall.DNSRecord, dnstype uint16, name string) []*syscall.DNSRecord {
	cname := syscall.StringToUTF16Ptr(name)
	if dnstype != syscall.DNS_TYPE_CNAME {
		cname = resolveCNAME(cname, r)
	}
	rec := make([]*syscall.DNSRecord, 0, 10)
	for p := r; p != nil; p = p.Next {
		if p.Dw&dnsSectionMask != syscall.DnsSectionAnswer {
			continue
		}
		if p.Type != dnstype {
			continue
		}
		if !syscall.DnsNameCompare(cname, p.Name) {
			continue
		}
		rec = append(rec, p)
	}
	return rec
}
```

-   **目的**: `DnsQuery`が返す`DNSRecord`のリストから、指定されたDNSタイプと名前に合致する有効なレコードのみをフィルタリングして返します。
-   **CNAME解決**: `dnstype`が`DNS_TYPE_CNAME`でない場合、入力された`name`を`resolveCNAME`で解決し、その正規名（`cname`）を基準にレコードをフィルタリングします。これにより、他のDNSレコードタイプ（MX, SRVなど）のルックアップ時にもCNAME解決が適用されます。
-   **セクションフィルタリング**: `p.Dw&dnsSectionMask != syscall.DnsSectionAnswer`のチェックにより、DNS応答の「回答セクション」にあるレコードのみを対象とします。これにより、権威セクションや追加セクションにあるレコードが誤って処理されることを防ぎます。
-   **タイプと名前の比較**: `p.Type != dnstype`でレコードタイプを、`!syscall.DnsNameCompare(cname, p.Name)`でレコード名を比較します。`DnsNameCompare`を使用することで、大文字・小文字を区別しない正確な名前比較が可能になります。

### `resolveCNAME`関数の追加

```go
// returns the last CNAME in chain
func resolveCNAME(name *uint16, r *syscall.DNSRecord) *uint16 {
	// limit cname resolving to 10 in case of a infinite CNAME loop
Cname:
	for cnameloop := 0; cnameloop < 10; cnameloop++ {
		for p := r; p != nil; p = p.Next {
			if p.Dw&dnsSectionMask != syscall.DnsSectionAnswer {
				continue
			}
			if p.Type != syscall.DNS_TYPE_CNAME {
				continue
			}
			if !syscall.DnsNameCompare(name, p.Name) {
				continue
			}
			name = (*syscall.DNSPTRData)(unsafe.Pointer(&r.Data[0])).Host
			continue Cname
		}
		break
	}
	return name
}
```

-   **目的**: `DNSRecord`のリストを走査し、CNAMEチェーンを解決して最終的な正規名を返します。
-   **無限ループ防止**: `cnameloop < 10`という条件により、CNAME解決の深さを最大10に制限しています。これにより、無限CNAMEループが発生した場合でもプログラムがハングアップするのを防ぎます。
-   **CNAMEの探索と解決**:
    -   `p.Dw&dnsSectionMask != syscall.DnsSectionAnswer`で回答セクションのレコードのみを対象とします。
    -   `p.Type != syscall.DNS_TYPE_CNAME`でCNAMEレコードのみを対象とします。
    -   `!syscall.DnsNameCompare(name, p.Name)`で現在のCNAMEとレコード名を比較し、一致した場合にそのCNAMEの指すホスト名（`(*syscall.DNSPTRData)(unsafe.Pointer(&r.Data[0])).Host`）を次の解決対象として`name`に設定し、`Cname`ラベルにジャンプして再度CNAMEチェーンを探索します。
-   **最終的な正規名**: ループが終了するか、CNAMEチェーンが途切れた場合、最後に解決された`name`（`*uint16`ポインタ）を返します。

### `syscall/syscall_windows.go`における`DnsNameCompare`の追加

```go
//sys	DnsNameCompare(name1 *uint16, name2 *uint16) (same bool) = dnsapi.DnsNameCompare_W
```

-   この行は、Goの`syscall`パッケージがWindowsの`dnsapi.dll`にある`DnsNameCompare_W`関数を呼び出すための宣言です。これにより、GoのコードからWindowsネイティブのDNS名比較APIを直接利用できるようになります。このAPIは、DNS名の大文字・小文字を区別しない比較を正確に行うために重要です。

### `src/pkg/net/lookup_windows_test.go`の新規追加

このテストファイルは、Goの`net`パッケージがWindows環境でDNSルックアップを正しく行えることを検証するために非常に重要です。

-   **`nslookup`との比較**: `nslookup`というヘルパー関数を通じて、Windowsの標準コマンドラインツールである`nslookup`を実行し、その出力をパースしてGoの`net`パッケージのルックアップ結果と比較します。これにより、Goの実装がWindowsのネイティブなDNS解決と一致していることを確認します。
-   **テスト対象**: `TestLookupMX`, `TestLookupCNAME`, `TestLookupNS`, `TestLookupTXT`といった関数が定義されており、それぞれのDNSレコードタイプに対するルックアップが正しく行われるかを検証します。
-   **外部ネットワークへの依存**: `*testExternal`フラグが設定されている場合にのみ外部ネットワークへの問い合わせを行うように制御されており、通常はテストをスキップできます。

これらの変更と追加されたテストにより、Goの`net`パッケージはWindows環境において、より正確で信頼性の高いDNSルックアップ機能を提供するようになりました。
