## 変更の背景

この変更は、Go言語のアセンブラ (`cmd/asm`) が特定の不正なアセンブリコードをパースする際に発生する無限ループのバグを修正するために行われました。具体的には、レジスタリスト（例: `[R0-R15]` のようにレジスタの範囲を指定する構文）を解析する内部ループにおいて、`lo <= hi` というループ条件が、`lo` と `hi` が符号なし16ビット整数 (`uint16`) であるために脆弱でした。

問題は、`[):[o-FP` のような不正なオペランドが入力された場合に顕在化しました。この入力によって、`hi` の値が `2^16-1` (つまり `uint16` の最大値) に計算されてしまう特定のコーナーケースが発生しました。`lo` が `0` で `hi` が `2^16-1` の場合、`lo <= hi` の条件は常に真となり、ループが無限に繰り返されることになります。

この無限ループは、非ARMアーキテクチャではアセンブラがハングアップする原因となり、ARMアーキテクチャでは約 `2^16` 個ものエラーが生成され、その後無視されるという非効率な挙動を引き起こしていました。この問題は [Issue 12469](https://github.com/golang/go/issues/12469) として報告されており、本コミットはその修正を目的としています。

## 前提知識の解説

### `cmd/asm` とは
`cmd/asm` は、Go言語のツールチェインに含まれるアセンブラです。Goプログラムは、Goソースコードから直接機械語にコンパイルされるだけでなく、一部のパフォーマンスクリティカルな部分や、特定のハードウェア機能を利用する部分ではアセンブリ言語が使用されることがあります。`cmd/asm` は、これらのGoアセンブリ言語のソースファイルをオブジェクトファイルに変換する役割を担っています。

### レジスタリストのパース
アセンブリ言語では、複数のレジスタをまとめて指定する「レジスタリスト」という構文が使われることがあります。例えば、`[R0-R15]` はレジスタR0からR15まで全てを指します。`cmd/asm` の内部では、このレジスタリストの文字列を解析し、どのレジスタが含まれているかを識別する処理が行われます。この解析処理には、指定された範囲（`lo` から `hi` まで）をイテレートするループが含まれます。

### 符号なし16ビット整数 (`uint16`)
`uint16` は、0から65535 (2^16 - 1) までの値を表現できる符号なしの16ビット整数型です。符号なし整数は負の値を表現できず、演算結果が表現可能な範囲を超えると、モジュロ演算のようにラップアラウンド（例: 65535 + 1 = 0）します。
今回のバグでは、`lo` と `hi` が `uint16` であったため、不正な入力によって `hi` が `uint16` の最大値 `65535` に設定されると、`lo` が `0` の場合、`lo <= hi` の条件は常に `0 <= 65535` となり、無限にループし続けることになりました。

### ARMアーキテクチャと非ARMアーキテクチャでの挙動の違い
コミットメッセージでは、非ARMアーキテクチャで無限ループ、ARMアーキテクチャで大量のエラー生成と説明されています。これは、各アーキテクチャのアセンブラがレジスタの命名規則やパースロジックに微妙な違いがあるためと考えられます。ARMアーキテクチャでは、不正なレジスタ名が検出された際にエラーを生成し、そのエラーがループの進行を妨げなかったものの、最終的に無視されるという挙動になったと推測されます。非ARMアーキテクチャでは、エラー生成ロジックが異なるか、あるいはエラーが生成されずに純粋な無限ループに陥ったと考えられます。

## 技術的詳細

このコミットは、`cmd/asm` のレジスタリストパースロジックにおける無限ループの脆弱性に対処するために、以下の3つの主要な改善を導入しています。

1.  **非`R`プレフィックスレジスタの早期終了**:
    `registerNumber` 関数は、レジスタ名を数値に変換する役割を担っています。本来、Goのアセンブリでは `R0` から `R15` のような形式でレジスタが指定されます。しかし、`[):[o-FP` のような不正な入力では、`o-FP` の `o` の部分が `registerNumber` に渡される可能性があります。以前のコードでは、`R` 以外のプレフィックスを持つレジスタ名が渡された場合、エラーを報告するものの、関数から早期にリターンしていませんでした。この修正により、`name[0] != 'R'` の場合にエラーを報告し、直ちに `0` を返して処理を中断するように変更されました。これにより、不正な入力が後続の脆弱なロジックに進むのを防ぎます。

2.  **レジスタインデックスが負にならないことの保証**:
    `registerNumber` 関数内で、レジスタの数値インデックスは `r - p.arch.Register["R0"]` のように計算されます。ここで `r` はパースされたレジスタの内部表現、`p.arch.Register["R0"]` はアーキテクチャ固有の `R0` レジスタの内部値です。特定のアーキテクチャにおいて、`R` プレフィックスを持つが `R0` よりも小さい内部値を持つレジスタが存在する場合、この減算結果が負になる可能性がありました。`uint16` にキャストされる前に負の値が生成されると、予期せぬ大きな符号なし整数値に変換され、これが無限ループのトリガーとなる可能性がありました。この修正では、`reg` が `0` 未満の場合にエラーを報告し、`0` を返して処理を中断することで、レジスタインデックスが常に非負であることを保証します。

3.  **イテレーション数の上限設定**:
    `registerList` 関数内の `for lo <= hi` ループは、レジスタ範囲をイテレートするコア部分です。このループが無限ループに陥る可能性があったため、防御的な措置としてイテレーション回数に上限が設けられました。具体的には、`const maxReg = 16` という定数が導入され、ループ条件が `for i := 0; lo <= hi && i < maxReg; i++` に変更されました。これにより、たとえ `lo <= hi` の条件が不正な入力によって常に真になったとしても、ループは最大 `maxReg` 回（この場合は16回）で強制的に終了するようになります。これは、Goのアセンブリにおけるレジスタの最大数（通常はR0-R15の16個）を考慮した現実的な上限であり、無限ループを防ぐための堅牢な対策となります。

これらの変更は、`cmd/asm` の堅牢性を高め、不正な入力に対する耐性を向上させるものです。

#### `registerList` 関数

```go
func (p *Parser) registerList(a *obj.Addr) {
	// One range per loop.
	const maxReg = 16 // 新しく追加された定数
	var bits uint16
ListLoop:
	for {
		// ... (既存のコード) ...

		// Check there are no duplicates in the register list.
		for i := 0; lo <= hi && i < maxReg; i++ { // ループ条件の変更
			if bits&(1<<lo) != 0 {
				p.errorf("register R%d already in list", lo)

			bits |= 1 << lo
			lo++
		}

	}

```
`registerList` 関数は、アセンブリコード内のレジスタリスト（例: `[R0-R15]`）をパースする主要なロジックを含んでいます。
*   `const maxReg = 16` の追加は、レジスタの最大数を明示的に定義し、防御的なプログラミングを導入しています。Goのアセンブリでは通常、R0からR15までの16個の汎用レジスタが使われるため、この値は妥当です。
*   最も重要な変更は、内部ループの条件が `for lo <= hi` から `for i := 0; lo <= hi && i < maxReg; i++` に変更された点です。
    *   `lo <= hi` は、レジスタ範囲の開始が終了以下である限りループを続けるという元の条件です。
    *   `i := 0; ...; i++` は、ループのイテレーション回数をカウントするための新しいカウンタです。
    *   `i < maxReg` は、ループが `maxReg` 回を超えて実行されないようにする新しい条件です。
この変更により、たとえ `lo <= hi` が不正な入力によって常に真になったとしても、ループは最大16回で強制的に終了し、無限ループに陥ることを防ぎます。これは、`uint16` のオーバーフローによる脆弱性に対する直接的な防御策となります。

#### `registerNumber` 関数

```go
func (p *Parser) registerNumber(name string) uint16 {
	// ... (既存のコード) ...

	if name[0] != 'R' {
		p.errorf("expected g or R0 through R15; found %s", name)
		return 0 // 早期リターンを追加
	}
	r, ok := p.registerReference(name)
	if !ok {
		return 0
	}
	reg := r - p.arch.Register["R0"] // reg変数を導入
	if reg < 0 { // 負のレジスタインデックスチェックを追加
		// Could happen for an architecture having other registers prefixed by R
		p.errorf("expected g or R0 through R15; found %s", name)
		return 0
	}
	return uint16(reg)
}
```
`registerNumber` 関数は、レジスタ名を数値インデックスに変換します。
*   `if name[0] != 'R'` のブロックに `return 0` が追加されました。これにより、レジスタ名が `R` で始まらない場合（例: `o-FP` の `o`）、エラーメッセージを出力した後に直ちに `0` を返して処理を中断します。これは、不正な入力が後続の処理で問題を引き起こすのを防ぐための早期終了メカニズムです。
*   `reg := r - p.arch.Register["R0"]` という行が追加され、レジスタインデックスの計算結果を一時変数 `reg` に格納するようになりました。
*   その直後に `if reg < 0` というチェックが追加されました。これは、計算されたレジスタインデックスが負の値になる可能性を検出するためのものです。もし負の値になった場合、それは予期せぬレジスタ名が渡されたことを意味するため、エラーを報告し `0` を返して処理を中断します。これにより、負の値が `uint16` にキャストされて巨大な符号なし整数になることによる潜在的なバグを防ぎます。

これらの変更は、レジスタリストのパース処理をより堅牢にし、不正な入力や予期せぬコーナーケースに対する耐性を大幅に向上させています。

今回のバグでは、`lo` と `hi` が `uint16` であったため、不正な入力によって `hi` が `uint16` の最大値 `65535` に設定されると、`lo` が `0` の場合、`lo <= hi` の条件は常に `0 <= 65535` となり、無限にループし続けることになりました。

### ARMアーキテクチャと非ARMアーキテクチャでの挙動の違い
コミットメッセージでは、非ARMアーキテクチャで無限ループ、ARMアーキテクチャで大量のエラー生成と説明されています。これは、各アーキテクチャのアセンブラがレジスタの命名規則やパースロジックに微妙な違いがあるためと考えられます。ARMアーキテクチャでは、不正なレジスタ名が検出された際にエラーを生成し、そのエラーがループの進行を妨げなかったものの、最終的に無視されるという挙動になったと推測されます。非ARMアーキテクチャでは、エラー生成ロジックが異なるか、あるいはエラーが生成されずに純粋な無限ループに陥ったと考えられます。

## 技術的詳細

このコミットは、`cmd/asm` のレジスタリストパースロジックにおける無限ループの脆弱性に対処するために、以下の3つの主要な改善を導入しています。

1.  **非`R`プレフィックスレジスタの早期終了**:
    `registerNumber` 関数は、レジスタ名を数値に変換する役割を担っています。本来、Goのアセンブリでは `R0` から `R15` のような形式でレジスタが指定されます。しかし、`[):[o-FP` のような不正な入力では、`o-FP` の `o` の部分が `registerNumber` に渡される可能性があります。以前のコードでは、`R` 以外のプレフィックスを持つレジスタ名が渡された場合、エラーを報告するものの、関数から早期にリターンしていませんでした。この修正により、`name[0] != 'R'` の場合にエラーを報告し、直ちに `0` を返して処理を中断するように変更されました。これにより、不正な入力が後続の脆弱なロジックに進むのを防ぎます。

2.  **レジスタインデックスが負にならないことの保証**:
    `registerNumber` 関数内で、レジスタの数値インデックスは `r - p.arch.Register["R0"]` のように計算されます。ここで `r` はパースされたレジスタの内部表現、`p.arch.Register["R0"]` はアーキテクチャ固有の `R0` レジスタの内部値です。特定のアーキテクチャにおいて、`R` プレフィックスを持つが `R0` よりも小さい内部値を持つレジスタが存在する場合、この減算結果が負になる可能性がありました。`uint16` にキャストされる前に負の値が生成されると、予期せぬ大きな符号なし整数値に変換され、これが無限ループのトリガーとなる可能性がありました。この修正では、`reg` が `0` 未満の場合にエラーを報告し、`0` を返して処理を中断することで、レジスタインデックスが常に非負であることを保証します。

3.  **イテレーション数の上限設定**:
    `registerList` 関数内の `for lo <= hi` ループは、レジスタ範囲をイテレートするコア部分です。このループが無限ループに陥る可能性があったため、防御的な措置としてイテレーション回数に上限が設けられました。具体的には、`const maxReg = 16` という定数が導入され、ループ条件が `for i := 0; lo <= hi && i < maxReg; i++` に変更されました。これにより、たとえ `lo <= hi` の条件が不正な入力によって常に真になったとしても、ループは最大 `maxReg` 回（この場合は16回）で強制的に終了するようになります。これは、Goのアセンブリにおけるレジスタの最大数（通常はR0-R15の16個）を考慮した現実的な上限であり、無限ループを防ぐための堅牢な対策となります。

これらの変更は、`cmd/asm` の堅牢性を高め、不正な入力に対する耐性を向上させるものです。

### `src/cmd/asm/internal/asm/parse.go` の変更

#### `registerList` 関数

```go
func (p *Parser) registerList(a *obj.Addr) {
	// One range per loop.
	const maxReg = 16 // 新しく追加された定数
	var bits uint16
ListLoop:
	for {
		// ... (既存のコード) ...

		// Check there are no duplicates in the register list.
		for i := 0; lo <= hi && i < maxReg; i++ { // ループ条件の変更
			if bits&(1<<lo) != 0 {
				p.errorf("register R%d already in list", lo)
			}
			bits |= 1 << lo
			lo++
		}
		// ... (既存のコード) ...
	}
}
```
`registerList` 関数は、アセンブリコード内のレジスタリスト（例: `[R0-R15]`）をパースする主要なロジックを含んでいます。
*   `const maxReg = 16` の追加は、レジスタの最大数を明示的に定義し、防御的なプログラミングを導入しています。Goのアセンブリでは通常、R0からR15までの16個の汎用レジスタが使われるため、この値は妥当です。
*   最も重要な変更は、内部ループの条件が `for lo <= hi` から `for i := 0; lo <= hi && i < maxReg; i++` に変更された点です。
    *   `lo <= hi` は、レジスタ範囲の開始が終了以下である限りループを続けるという元の条件です。
    *   `i := 0; ...; i++` は、ループのイテレーション回数をカウントするための新しいカウンタです。
    *   `i < maxReg` は、ループが `maxReg` 回を超えて実行されないようにする新しい条件です。
この変更により、たとえ `lo <= hi` が不正な入力によって常に真になったとしても、ループは最大16回で強制的に終了し、無限ループに陥ることを防ぎます。これは、`uint16` のオーバーフローによる脆弱性に対する直接的な防御策となります。

#### `registerNumber` 関数

```go
func (p *Parser) registerNumber(name string) uint16 {
	// ... (既存のコード) ...

	if name[0] != 'R' {
		p.errorf("expected g or R0 through R15; found %s", name)
		return 0 // 早期リターンを追加
	}
	r, ok := p.registerReference(name)
	if !ok {
		return 0
	}
	reg := r - p.arch.Register["R0"] // reg変数を導入
	if reg < 0 { // 負のレジスタインデックスチェックを追加
		// Could happen for an architecture having other registers prefixed by R
		p.errorf("expected g or R0 through R15; found %s", name)
		return 0
	}
	return uint16(reg)
}
```
`registerNumber` 関数は、レジスタ名を数値インデックスに変換します。
*   `if name[0] != 'R'` のブロックに `return 0` が追加されました。これにより、レジスタ名が `R` で始まらない場合（例: `o-FP` の `o`）、エラーメッセージを出力した後に直ちに `0` を返して処理を中断します。これは、不正な入力が後続の処理で問題を引き起こすのを防ぐための早期終了メカニズムです。
*   `reg := r - p.arch.Register["R0"]` という行が追加され、レジスタインデックスの計算結果を一時変数 `reg` に格納するようになりました。
*   その直後に `if reg < 0` というチェックが追加されました。これは、計算されたレジスタインデックスが負の値になる可能性を検出するためのものです。もし負の値になった場合、それは予期せぬレジスタ名が渡されたことを意味するため、エラーを報告し `0` を返して処理を中断します。これにより、負の値が `uint16` にキャストされて巨大な符号なし整数になることによる潜在的なバグを防ぎます。

これらの変更は、レジスタリストのパース処理をより堅牢にし、不正な入力や予期せぬコーナーケースに対する耐性を大幅に向上させています。
