# [インデックス 27413] ファイルの概要

このコミットは、Goコマンドラインツール（`cmd/go`）におけるビルド処理の改善に関するものです。具体的には、アーカイブファイルの`os.Stat`呼び出しが、実際にコマンドを実行する時のみに行われるように修正されています。これにより、ドライラン（`-n`オプション）時に不要なファイルシステム操作が行われなくなり、関連するエラーが回避されます。

## コミット

`cmd/go`において、アーカイブファイルの`os.Stat`呼び出しを、コマンド実行時のみに限定する変更です。

## 変更の背景

この変更は、Goのビルドコマンド（`go build`など）が`-n`オプション（ドライランモード）で実行された際に発生する問題を解決するために導入されました。ドライランモードでは、実際にビルドやファイル生成は行われず、実行されるであろうコマンドが標準出力に表示されるだけです。

しかし、以前の実装では、ビルドプロセスの一部として生成されるはずのアーカイブファイル（`.a`ファイル）に対して、`os.Stat`関数が呼び出されていました。ドライランモードではこのアーカイブファイルは実際に生成されないため、`os.Stat`は「そのようなファイルまたはディレクトリはありません」というエラーを返していました。このエラーは、ユーザーがドライランの結果を評価する際に混乱を招く可能性があり、また、本来エラーが発生すべきではない状況でエラーメッセージが表示されるのは不適切な挙動でした。

`Fixes #14944`という記述から、この問題がGoの公式イシュートラッカーで報告されていたことがわかります。このコミットは、この特定のバグを修正することを目的としています。

## 前提知識の解説

*   **`cmd/go`**: Go言語の公式ツールチェーンに含まれるコマンドラインツールです。`go build`, `go run`, `go test`など、Goプロジェクトの管理とビルドに関する様々な機能を提供します。
*   **`go build -n`**: `go build`コマンドに`-n`オプションを付けると、ドライランモードで実行されます。このモードでは、ビルドコマンドが実際に実行される代わりに、実行されるであろうコマンドが標準出力に表示されます。これは、ビルドプロセスがどのように進行するかを確認したり、デバッグしたりする際に役立ちます。
*   **`os.Stat`**: Go言語の標準ライブラリ`os`パッケージに含まれる関数で、指定されたパスのファイルまたはディレクトリの情報を取得します。ファイルが存在しない場合やアクセス権がない場合などにはエラーを返します。
*   **アーカイブファイル（`.a`ファイル）**: Goのビルドプロセスにおいて、コンパイルされたパッケージのオブジェクトコードが格納される静的ライブラリファイルです。リンカによって最終的な実行可能ファイルに結合されます。
*   **Cgo**: GoプログラムからC言語のコードを呼び出すためのメカニズムです。Cgoを使用するGoパッケージは、通常のGoパッケージとは異なるビルドプロセスを必要とすることがあります。

## 技術的詳細

変更の核心は、`cmd/go`のビルドロジック内で、生成されたアーカイブファイルが存在するかどうかを確認する`os.Stat`呼び出しの条件を修正することです。

元のコードでは、`gcToolchain.pack`関数内で、コンパイラによってアーカイブファイルが作成されたことを確認するために、無条件に`os.Stat(absAfile)`が呼び出されていました。

```go
// The archive file should have been created by the compiler.
// Since it used to not work that way, verify.
if _, err := os.Stat(absAfile); err != nil {
    fatalf("os.Stat of archive file failed: %v", err)
}
```

このコミットでは、この`os.Stat`呼び出しが`!buildN`という条件でラップされています。`buildN`は、`go build -n`のようにドライランモードが有効になっているかどうかを示すブール値です。

```go
if !buildN {
    if _, err := os.Stat(absAfile); err != nil {
        fatalf("os.Stat of archive file failed: %v", err)
    }
}
```

これにより、ドライランモード（`buildN`が`true`）の場合には`os.Stat`の呼び出しがスキップされ、実際にアーカイブファイルが生成されない状況でファイルが存在しないことによるエラーが発生しなくなります。

また、この変更を検証するために、`src/cmd/go/go_test.go`に新しいテストケース`TestBuildDryRunWithCgo`が追加されています。このテストは、Cgoを使用するGoプログラムを`-n`オプションでビルドし、標準エラー出力に「`os.Stat .* no such file or directory`」という文字列が含まれていないことを確認します。これは、修正が正しく機能し、ドライラン時に`os.Stat`関連のエラーが発生しないことを保証するためのものです。

## コアとなるコードの解説

### `src/cmd/go/build.go`の変更

`gcToolchain.pack`関数は、Goのビルドプロセスにおいて、コンパイルされたオブジェクトファイルをアーカイブファイルにまとめる役割を担っています。この関数内で、アーカイブファイルが正しく作成されたことを確認するために`os.Stat`が使用されていました。

変更前は、`os.Stat(absAfile)`が常に呼び出され、その結果がエラーであれば`fatalf`で処理を中断していました。
変更後は、`if !buildN`という条件が追加されました。`buildN`は、`go build -n`のようにドライランモードが有効な場合に`true`となるグローバル変数（またはそれに準ずるフラグ）です。
この条件により、ドライランモードではない（つまり、実際にビルドが実行される）場合にのみ`os.Stat`が呼び出されるようになります。これにより、ドライランモードでアーカイブファイルが存在しないことによるエラーが回避されます。

### `src/cmd/go/go_test.go`の追加テスト

`TestBuildDryRunWithCgo`という新しいテスト関数が追加されました。
1.  `if !canCgo { t.Skip(...) }`: このテストはCgoに依存するため、Cgoが有効でない環境ではスキップされます。
2.  `tg := testgo(t); defer tg.cleanup()`: テスト用の環境をセットアップし、テスト終了後にクリーンアップします。
3.  `tg.tempFile(...)`: Cgoを使用する簡単なGoプログラム（`foo.go`）を作成します。このプログラムはCのヘッダーファイル`<limits.h>`をインポートし、`C.INT_MAX`を出力します。Cgoを使用するプログラムは、通常のGoプログラムよりも複雑なビルドステップを伴うことがあり、この問題が顕在化しやすいシナリオです。
4.  `tg.run("build", "-n", tg.path("foo.go"))`: 作成した`foo.go`を`-n`オプション付きでビルドします。これにより、ドライランモードがシミュレートされます。
5.  `tg.grepStderrNot(`os.Stat .* no such file or directory`, "unexpected stat of archive file")`: この行がテストの核心です。`tg.grepStderrNot`は、直前の`tg.run`コマンドの標準エラー出力に、指定された正規表現（`os.Stat .* no such file or directory`）が含まれていないことを確認します。もしこの正規表現が見つかった場合、テストは失敗し、「unexpected stat of archive file」というメッセージが表示されます。これは、ドライラン時に`os.Stat`が不要なエラーを発生させていないことを検証します。

このテストの追加により、将来的に同様の回帰バグが発生するのを防ぐことができます。
