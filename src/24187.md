# [インデックス 24187] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto/x509` パッケージ内の `root_solaris.go` ファイルに対する変更です。具体的には、OmniOS環境において、システムが信頼するルート認証局（CA）証明書を検索するパスリストに `/etc/ssl/cacert.pem` を追加しています。これにより、OmniOS上で動作するGoアプリケーションが、TLS/SSL接続を行う際に正しく証明書を検証できるようになります。

## 元コミット内容

このコミットは、`src/crypto/x509/root_solaris.go` ファイルに以下の変更を加えています。

```diff
--- a/src/crypto/x509/root_solaris.go
+++ b/src/crypto/x509/root_solaris.go
@@ -8,4 +8,5 @@ package x509
 var certFiles = []string{
 	"/etc/certs/ca-certificates.crt",     // Solaris 11.2+
 	"/etc/ssl/certs/ca-certificates.crt", // Joyent SmartOS
+\t"/etc/ssl/cacert.pem",                // OmniOS
 }
```

具体的には、`certFiles` という文字列スライスに `/etc/ssl/cacert.pem` というパスが追加されています。このスライスは、Goの `crypto/x509` パッケージが信頼するルートCA証明書を検索する際に使用するファイルパスのリストです。

## 変更の背景

この変更の背景には、GoアプリケーションがTLS/SSL接続を確立する際に、システムが信頼するルートCA証明書を正しく見つけられないという問題がありました。特に、OmniOSというSolarisベースのオペレーティングシステム環境において、Goの `crypto/x509` パッケージがデフォルトで検索する証明書パスに、OmniOSが標準でルートCA証明書を配置するパスが含まれていなかったため、証明書検証エラーが発生していました。

この問題は、Go issue #9146 として報告されており、このコミットはその問題を解決するために行われました。GoアプリケーションがHTTPSリクエストを行う際や、TLSクライアント/サーバーとして動作する際に、相手の証明書が信頼できるCAによって署名されているかを検証する必要があります。この検証プロセスには、システムにインストールされている信頼されたルートCA証明書が必要不可欠です。OmniOSの特定のパスがGoの検索リストに含まれていなかったため、Goアプリケーションは信頼できるCA証明書を見つけられず、結果としてTLS接続が失敗していました。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

1.  **TLS/SSLと証明書:**
    *   **TLS (Transport Layer Security) / SSL (Secure Sockets Layer):** インターネット上でデータを安全にやり取りするためのプロトコルです。データの暗号化、完全性の保証、および通信相手の認証を提供します。
    *   **X.509証明書:** 公開鍵暗号基盤 (PKI) において、公開鍵の所有者を証明するために使用されるデジタル証明書の標準フォーマットです。ウェブサイトの身元確認や、安全な通信路の確立に不可欠です。
    *   **ルート認証局 (Root CA):** 信頼の階層の最上位に位置する認証局です。ルートCAの証明書は、オペレーティングシステムやブラウザに事前にインストールされており、「信頼できる」ものとして扱われます。中間CAやエンドエンティティ証明書は、このルートCAまたはその下の中間CAによって署名されます。
    *   **証明書チェーン:** エンドエンティティ証明書（例：ウェブサイトの証明書）から始まり、中間CA証明書を介してルートCA証明書に至るまでの証明書の連鎖です。クライアントは、このチェーンをたどって、最終的に信頼できるルートCAに到達することで、エンドエンティティ証明書が正当であることを検証します。

2.  **`crypto/x509` パッケージ:**
    *   Go言語の標準ライブラリの一部で、X.509証明書の解析、検証、生成などの機能を提供します。TLS接続を行う際に、相手から提示された証明書を検証するために内部的に利用されます。
    *   特に、`SystemCertPool` という機能を通じて、オペレーティングシステムが提供する信頼されたルートCA証明書のプールをロードしようとします。これにより、GoアプリケーションはOSレベルで設定された信頼ポリシーに従うことができます。

3.  **オペレーティングシステムにおけるCA証明書の管理:**
    *   LinuxやUnix系のシステムでは、信頼されたルートCA証明書は通常、特定のディレクトリ（例: `/etc/ssl/certs`, `/usr/share/ca-certificates/`) やファイル（例: `/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`）に保存されています。
    *   これらのパスはディストリビューションによって異なり、システム管理者が `update-ca-certificates` のようなツールを使って管理することが一般的です。
    *   **Solaris/OmniOS:** SolarisはOracleが開発したUnix系OSで、OmniOSはOpenSolarisをベースにしたディストリビューションです。これらのシステムも独自のパスでCA証明書を管理しています。

## 技術的詳細

Goの `crypto/x509` パッケージは、`SystemCertPool` をロードする際に、実行されているオペレーティングシステムに応じて、信頼されたルートCA証明書が格納されている可能性のある既知のパスを検索します。これは、GoアプリケーションがOSのセキュリティポリシーに準拠し、システム全体で信頼されているCA証明書を利用できるようにするためです。

`src/crypto/x509/root_solaris.go` ファイルは、Solaris系のシステム（Solaris、SmartOS、OmniOSなど）に特化した証明書検索パスを定義しています。このファイル内の `certFiles` 変数は、GoがルートCA証明書を探すファイルパスのリストを保持しています。

このコミット以前の `certFiles` リストは以下の通りでした。

*   `/etc/certs/ca-certificates.crt` (Solaris 11.2+)
*   `/etc/ssl/certs/ca-certificates.crt` (Joyent SmartOS)

しかし、OmniOS環境では、ルートCA証明書が `/etc/ssl/cacert.pem` という別のパスに配置されることが一般的でした。このため、OmniOS上でGoアプリケーションがTLS接続を試みると、信頼できるルートCA証明書を見つけられず、`x509: certificate signed by unknown authority` のようなエラーが発生していました。

このコミットは、`certFiles` リストに `/etc/ssl/cacert.pem` を追加することで、OmniOS環境におけるこの問題を解決します。Goアプリケーションは、この新しいパスも検索対象に含めることで、OmniOSが提供するルートCA証明書を正しくロードし、TLS接続の検証を成功させることができるようになります。

この変更は、Goのクロスプラットフォーム互換性を向上させ、特定のOS環境でのTLS/SSL関連の問題を解消するための重要な修正です。

## コアとなるコードの変更箇所

変更は `src/crypto/x509/root_solaris.go` ファイルの `certFiles` 変数定義にあります。

```go
// src/crypto/x509/root_solaris.go
package x509

var certFiles = []string{
	"/etc/certs/ca-certificates.crt",     // Solaris 11.2+
	"/etc/ssl/certs/ca-certificates.crt", // Joyent SmartOS
	"/etc/ssl/cacert.pem",                // OmniOS
}
```

追加された行は以下の通りです。

```
	"/etc/ssl/cacert.pem",                // OmniOS
```

## コアとなるコードの解説

`certFiles` は、Goの `crypto/x509` パッケージがSolaris系のシステムで信頼されたルートCA証明書を探す際に参照する文字列スライスです。このスライスに列挙されたパスは、`SystemCertPool` を構築する際に順番に試行され、最初に見つかった有効な証明書ファイルがロードされます。

このコミットによって `/etc/ssl/cacert.pem` が追加されたことで、GoアプリケーションはOmniOS環境でこのパスもチェックするようになります。これにより、OmniOSの標準的なCA証明書配置とGoの証明書検索ロジックが一致し、TLS接続時の証明書検証が正しく機能するようになります。

このアプローチは、各OSディストリビューションがCA証明書を配置する慣習の違いに対応するための一般的な方法です。Goは、主要なOSごとに異なるパスをハードコードすることで、システム全体の信頼ストアとの統合を図っています。
