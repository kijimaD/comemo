# [インデックス 21808] ファイルの概要

このコミットは、Goコンパイラのリンカ（`cmd/ld`）がWindowsのPE（Portable Executable）ヘッダに書き込むタイムスタンプの挙動を変更するものです。具体的には、ビルド時に現在時刻を記録する代わりに、常にタイムスタンプを`0`に設定するように変更しています。これにより、同一の入力に対して常に同一のバイナリ出力を生成できるようになり、再現可能なビルド（Reproducible Builds）の実現に貢献します。

## 元コミット内容

このコミットは、Goリンカ（`cmd/ld`）がWindowsのPEファイル（実行可能ファイルやDLL）のヘッダに書き込むタイムスタンプを、ビルド時の現在時刻ではなく、常に`0`に設定するように変更します。

変更前:
`fh.TimeDateStamp = time(0);`

変更後:
`fh.TimeDateStamp = 0;`

この変更は、Issue #9756 を修正するために行われました。また、`doc/go1.5.txt` にもこの変更がGo 1.5のリリースノートとして追記されています。

## 変更の背景

この変更の主な背景は、「再現可能なビルド（Reproducible Builds）」の実現です。

従来のビルドプロセスでは、WindowsのPEファイルヘッダに含まれるタイムスタンプフィールドに、ビルドが実行された正確な日時が記録されていました。これは一見すると有用な情報のように思えますが、同じソースコードとビルド環境であっても、ビルドを実行するたびにタイムスタンプが異なるため、生成されるバイナリファイルが毎回異なるという問題を引き起こしていました。

この「バイナリの非同一性」は、以下のような問題を引き起こします。

1.  **検証の困難さ**: ソフトウェアの配布元が提供するバイナリと、ユーザーが同じソースコードからビルドしたバイナリが一致しないため、ユーザーがバイナリの正当性（改ざんされていないこと）を検証することが困難になります。これはセキュリティ上の懸念となります。
2.  **キャッシュの非効率性**: ビルドシステムやCI/CDパイプラインにおいて、バイナリのハッシュ値に基づいてキャッシュを行う場合、タイムスタンプの違いによって常に新しいバイナリと認識され、キャッシュがヒットしなくなります。これにより、ビルド時間が長くなったり、ストレージの無駄が発生したりします。
3.  **デバッグの複雑化**: 特定のバイナリの問題を追跡する際に、ビルド日時が異なると、どのビルドがどのソースコードに対応しているのかを正確に特定するのが難しくなる場合があります。

このコミットは、これらの問題を解決するために、タイムスタンプを固定値（`0`）にすることで、同一のソースコードからは常に同一のバイナリが生成されるようにすることを目指しています。コミットメッセージのコメントにある「Being able to produce identical output for identical input is much more beneficial than having build timestamp in the header.」という一文が、この変更の意図を明確に示しています。

## 前提知識の解説

### 1. PE (Portable Executable) フォーマット

PEフォーマットは、Microsoft Windowsオペレーティングシステムで使用される実行可能ファイル、DLL（Dynamic Link Library）、オブジェクトコード、FON（フォント）ファイルなどのファイル形式です。PEファイルは、ヘッダ、セクションテーブル、および実際のコードとデータを含むセクションで構成されます。

PEヘッダには、ファイルの種類、CPUアーキテクチャ、エントリポイント、インポート/エクスポートテーブルなど、実行に必要なメタデータが含まれています。このヘッダの一部に、`TimeDateStamp`というフィールドが存在します。

### 2. `TimeDateStamp` フィールド

PEヘッダ内の`TimeDateStamp`フィールドは、通常、リンカがファイルを生成した日時をUnixエポックタイム（1970年1月1日00:00:00 UTCからの秒数）で記録するために使用されます。このフィールドは、デバッグ情報やバージョン管理の目的で利用されることがありますが、バイナリの同一性を保証する上では障害となります。

### 3. Reproducible Builds (再現可能なビルド)

再現可能なビルドとは、特定のソースコード、ビルドスクリプト、およびビルド環境が与えられた場合、常にビット単位で同一のバイナリ出力を生成できるビルドプロセスのことです。これは、ソフトウェアの信頼性、セキュリティ、および検証可能性を高める上で非常に重要です。

再現可能なビルドを実現するためには、ビルドプロセスにおける非決定的な要素（例: タイムスタンプ、ランダムなID、ファイルシステムの順序、環境変数など）を排除する必要があります。このコミットは、PEヘッダのタイムスタンプという非決定的な要素を排除する一環として行われました。

### 4. Goリンカ (`cmd/ld`)

`cmd/ld`は、Go言語のツールチェインの一部であるリンカです。Goのソースコードがコンパイルされた後、オブジェクトファイルが生成されます。このリンカは、これらのオブジェクトファイルを結合し、必要なライブラリとリンクして、最終的な実行可能バイナリを生成する役割を担っています。Windowsターゲットの場合、このリンカがPEフォーマットのバイナリを生成します。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/ld/pe.c`ファイル内の`asmbpe`関数における`fh.TimeDateStamp`フィールドへの値の割り当て方法の変更です。

*   **変更前**: `fh.TimeDateStamp = time(0);`
    *   `time(0)`はC標準ライブラリの関数で、現在のUnixエポックタイムを返します。これにより、ビルドが実行されるたびに異なるタイムスタンプがPEヘッダに書き込まれていました。

*   **変更後**: `fh.TimeDateStamp = 0;`
    *   `0`という固定値を設定することで、ビルド日時に関わらず、このフィールドの値は常に同じになります。これにより、PEヘッダのこの部分がバイナリの同一性を損なう要因から排除されます。

この変更は、WindowsのPEファイルに特化したものであり、他のOS（LinuxのELF、macOSのMach-Oなど）のバイナリフォーマットには直接影響しません。しかし、再現可能なビルドという概念は、クロスプラットフォームで重要であり、各OSのバイナリフォーマットにおける非決定的な要素を特定し、排除する努力が続けられています。

この変更は、Go 1.5のリリースノートにも記載されており、Go言語が再現可能なビルドの重要性を認識し、その実現に向けて取り組んでいることを示しています。

## コアとなるコードの解説

### `src/cmd/ld/pe.c`

このファイルは、Goリンカ（`cmd/ld`）がWindowsのPEフォーマットの実行可能ファイルを生成する際のロジックを含んでいます。

*   **`asmbpe(void)` 関数**:
    この関数は、PEファイルのヘッダやセクションを組み立てる主要な役割を担っています。`fh` は `IMAGE_FILE_HEADER` 構造体（またはそれに相当するGoの内部表現）のインスタンスであり、PEファイルの標準的なヘッダ情報を含んでいます。

*   **`fh.TimeDateStamp = time(0);` から `fh.TimeDateStamp = 0;` への変更**:
    この行が、PEヘッダのタイムスタンプを設定している箇所です。
    *   変更前は、`time(0)` 関数を呼び出して現在のシステム時刻（Unixエポックからの秒数）を取得し、それを`TimeDateStamp`フィールドに設定していました。これにより、ビルドごとに異なるタイムスタンプが埋め込まれ、結果としてバイナリのハッシュ値が変化していました。
    *   変更後は、`TimeDateStamp`フィールドに直接`0`という固定値を設定しています。これにより、ビルドがいつ実行されたかに関わらず、このフィールドの値は常に`0`となり、バイナリの同一性が保証されます。

*   **コメントの追加**:
    `// Being able to produce identical output for identical input is // much more beneficial than having build timestamp in the header.`
    このコメントは、なぜこの変更が行われたのかという理由を明確に説明しています。ビルドタイムスタンプをヘッダに含めることよりも、同一の入力から同一の出力を生成できること（再現可能なビルド）の方が、より大きなメリットがあるという開発チームの判断を示しています。これは、ソフトウェアの検証可能性と信頼性を高めるための重要な設計思想です。

### `doc/go1.5.txt`

このファイルは、Go 1.5のリリースノートのドラフトです。

*   **`cmd/ld: no longer record build timestamp in Windows PE file header (https://golang.org/cl/3740)` の追加**:
    この行は、Go 1.5で導入される変更点として、このコミットの内容が公式にアナウンスされることを示しています。`https://golang.org/cl/3740` は、この変更に対応するGerritのチェンジリストへのリンクです。これにより、ユーザーはGo 1.5以降のWindowsバイナリが再現可能なビルドの特性を持つことを認識できます。
