## 変更の背景

Go言語のランタイムには、プログラムの異常終了を処理するための `panic` および `recover` メカニズムが備わっています。これらの機能は、エラーハンドリングの重要な一部であり、特に回復不可能なエラーや予期せぬ状況に対応するために使用されます。

このコミットが行われる以前は、パニック処理に関するコードが `src/runtime/panic.go` と `src/runtime/panic1.go` の2つのファイルに分散していました。`panic1.go` には「TODO: Merge into panic.go.」というコメントが存在しており、これは将来的にこれらのファイルを統合する意図があったことを示しています。

コードが複数のファイルに分散していると、関連するロジックを追跡するのが難しくなり、保守性や理解度が低下する可能性があります。このコミットは、このTODOコメントに従い、パニック処理のコードベースを統合することで、ランタイムのコード構造を簡素化し、より一貫性のあるものにすることを目的としています。これにより、開発者がパニック処理の内部動作を理解しやすくなり、将来的な変更やデバッグが容易になります。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下のGoランタイムの概念とパニック/リカバリメカニズムに関する知識が必要です。

1.  **Goroutine (g)**: Goランタイムにおける軽量な実行スレッドです。すべてのGoプログラムは1つ以上のgoroutineで実行されます。ランタイムはgoroutineのスケジューリング、スタック管理、パニック処理などを担当します。
2.  **Machine (m)**: オペレーティングシステムのスレッドを表します。Goランタイムは、複数のgoroutineを少数のOSスレッド（M）上で多重化して実行します。
3.  **Panic**: Goプログラムが回復不可能なエラーに遭遇した際に発生するメカニズムです。`panic` が発生すると、現在のgoroutineの実行は中断され、遅延関数（`defer`）がスタックを巻き戻しながら実行されます。
4.  **Recover**: `panic` によって中断されたgoroutineの実行を再開し、パニックから回復するための組み込み関数です。`recover` は `defer` 関数内でのみ有効であり、パニック値を捕捉して、プログラムがクラッシュするのを防ぐことができます。
5.  **Defer**: 関数がリターンする直前、または `panic` が発生してスタックが巻き戻される際に実行される関数をスケジュールするためのキーワードです。`defer` はリソースの解放やログ記録、そして `recover` と組み合わせてパニックからの回復によく使用されます。
6.  **Goランタイムの内部構造**: Goランタイムは、メモリ管理、スケジューリング、ガベージコレクション、パニック処理など、Goプログラムの実行を支える低レベルのコードです。これらの機能はC言語やアセンブリ言語、そしてGo言語自体で記述されています。
7.  **`_g_` と `_m_`**: ランタイムコード内で現在のgoroutine (`g`) と現在のOSスレッド (`m`) を参照するための慣習的な変数名です。`getg()` 関数は現在のgoroutineのポインタを返します。
8.  **`mutex`**: 複数のgoroutineが共有リソースに同時にアクセスするのを防ぐための同期プリミティブです。パニック処理のようなクリティカルなセクションでは、競合状態を避けるためにミューテックスが使用されます。
9.  **`freezetheworld()`**: ガベージコレクションやパニック処理などの特定のランタイム操作中に、すべてのgoroutineの実行を一時停止させるランタイム関数です。これにより、ランタイムが整合性のある状態で操作を実行できます。
10. **`traceback`**: パニック発生時に、現在のgoroutineのスタックトレースを出力するランタイム関数です。これにより、パニックが発生した場所と、そこに至るまでの関数呼び出しのシーケンスを特定できます。

## 技術的詳細

このコミットは、`src/runtime/panic1.go` に定義されていた以下の主要な関数と関連するグローバル変数、定数を `src/runtime/panic.go` に移動させました。

移動された主な要素は以下の通りです。

*   **`paniclk` (mutex)**: パニック処理中にランタイムの内部状態を保護するためのミューテックス。複数のgoroutineが同時にパニック状態になった場合に、処理の競合を防ぎます。
*   **`hasLinkRegister` (const)**: 特定のアーキテクチャ（ARM, ARM64, PPC64, PPC64LE）がリンクレジスタを持つかどうかを示す定数。スタックアンワインドやレジスタの復元に関連する処理で利用されます。
*   **`recovery(gp *g)` 関数**: `defer` 関数内で `recover` が呼び出された際に、スタックを巻き戻し、通常の関数リターンとして実行を継続させるためのロジックを実装しています。これは、パニック状態から正常な実行フローに戻るための重要なメカニズムです。
    *   `gp.sigcode0` と `gp.sigcode1` を使用して、`defer` の引数やリターンアドレスなどの情報を取得します。
    *   `gcUnwindBarriers` を呼び出して、ガベージコレクションのバリアを調整します。
    *   `gp.sched.sp`, `gp.sched.pc`, `gp.sched.ret` を設定し、`gogo(&gp.sched)` を使ってスケジューラに制御を戻し、指定されたPCとSPで実行を再開させます。`gp.sched.ret = 1` は、`deferproc` が成功したことを示す戻り値です。
*   **`startpanic_m()` 関数**: パニック処理の開始時に、現在のM（OSスレッド）の状態を初期化し、パニック処理の準備を行う関数です。
    *   `mheap_.cachealloc.size == 0` のチェックにより、メモリヒープが初期化されていない非常に早い段階でのパニックを検出します。
    *   `_g_.m.mcache == nil` のチェックにより、シグナルハンドラや `throw` から呼び出された場合の `mcache` の割り当てを処理します。
    *   `_g_.m.dying` という状態変数を使って、パニック処理の多重度を管理します。
        *   `dying = 0`: 最初のパニック。`panicking` カウンタをインクリメントし、`paniclk` をロックし、`freezetheworld()` を呼び出して他のgoroutineを停止させます。
        *   `dying = 1`: パニック処理中に別のパニックが発生した場合（例: パニック引数の出力中にエラー）。スタックトレースを出力して終了します。
        *   `dying = 2`: 2度目のパニック処理中にさらに問題が発生した場合（例: スタックトレースの出力に失敗）。「stack trace unavailable」と出力して終了します。
        *   `dying = 3` 以降: 印刷すらできない致命的な状況。直接終了します。
*   **`didothers` (var)**: 他のgoroutineのスタックトレースが既に出力されたかどうかを追跡するフラグ。
*   **`deadlock` (mutex)**: 複数のMが同時にパニック処理を行おうとした場合に、デッドロックを回避するためのミューテックス。
*   **`dopanic_m(gp *g, pc, sp uintptr)` 関数**: パニック処理の主要なロジックを実行する関数です。スタックトレースの出力、他のgoroutineの処理、そして最終的なプログラムの終了を担当します。
    *   シグナルによるパニックの場合、シグナル情報を出力します。
    *   `gotraceback()` を呼び出して、スタックトレースの出力レベルを決定します。
    *   現在のgoroutine (`gp`) のスタックトレースを出力します。
    *   `tracebackothers(gp)` を呼び出して、他のgoroutineのスタックトレースも出力します。
    *   `paniclk` をアンロックし、`panicking` カウンタをデクリメントします。
    *   もし他のMもパニック処理中であれば、`deadlock` ミューテックスを使って待機します。
    *   `docrash` フラグが設定されていれば、`crash()` を呼び出してプログラムを強制終了させます。
    *   最終的に `exit(2)` を呼び出してプログラムを終了します。
*   **`canpanic(gp *g) bool` 関数**: 指定されたgoroutine `gp` がパニックを安全に処理できる状態にあるかどうかを判断する関数です。
    *   ランタイムコードの実行中、ロックを保持している、メモリ割り当て中、`throw` 処理中、プリエンプションが無効になっている、または `dying` 状態にあるM上ではパニック処理を安全に行えないため `false` を返します。
    *   `_Grunning` 状態でないgoroutineや、システムコール中にスタックポインタが設定されているgoroutineもパニック処理の対象外とします。
    *   Windows環境では、`libcallsp` が設定されている場合も `false` を返します。

これらの関数と変数を `panic.go` に統合することで、パニック処理に関するすべてのロジックが1つのファイルに集約され、Goランタイムの内部構造がより明確になりました。

//uint32 runtime·panicking;
var paniclk mutex

const hasLinkRegister = GOARCH == "arm" || GOARCH == "arm64" || GOARCH == "ppc64" || GOARCH == "ppc64le"

// Unwind the stack after a deferred function calls recover
// after a panic.  Then arrange to continue running as though
// the caller of the deferred function returned normally.
func recovery(gp *g) {
	// Info about defer passed in G struct.
	sp := gp.sigcode0
	pc := gp.sigcode1

	// d's arguments need to be in the stack.
	if sp != 0 && (sp < gp.stack.lo || gp.stack.hi < sp) {
		print("recover: ", hex(sp), " not in [", hex(gp.stack.lo), ", ", hex(gp.stack.hi), "]\\n")
		throw("bad recovery")
	}

	// Make the deferproc for this d return again,
	// this time returning 1.  The calling function will
	// jump to the standard return epilogue.
	gcUnwindBarriers(gp, sp)
	gp.sched.sp = sp
	gp.sched.pc = pc
	gp.sched.lr = 0
	gp.sched.ret = 1
	gogo(&gp.sched)
}

func startpanic_m() {
	_g_ := getg()
	if mheap_.cachealloc.size == 0 { // very early
		print("runtime: panic before malloc heap initialized\\n")
		_g_.m.mallocing = 1 // tell rest of panic not to try to malloc
	} else if _g_.m.mcache == nil { // can happen if called from signal handler or throw
		_g_.m.mcache = allocmcache()
	}

	switch _g_.m.dying {
	case 0:
		_g_.m.dying = 1
		if _g_ != nil {
			_g_.writebuf = nil
		}
		xadd(&panicking, 1)
		lock(&paniclk)
		if debug.schedtrace > 0 || debug.scheddetail > 0 {
			schedtrace(true)
		}
		freezetheworld()
		return
	case 1:
		// Something failed while panicing, probably the print of the
		// argument to panic().  Just print a stack trace and exit.
		_g_.m.dying = 2
		print("panic during panic\\n")
		dopanic(0)
		exit(3)
		fallthrough
	case 2:
		// This is a genuine bug in the runtime, we couldn't even
		// print the stack trace successfully.
		_g_.m.dying = 3
		print("stack trace unavailable\\n")
		exit(4)
		fallthrough
	default:
		// Can't even print!  Just exit.
		exit(5)
	}
}

var didothers bool
var deadlock mutex

func dopanic_m(gp *g, pc, sp uintptr) {
	if gp.sig != 0 {
		print("[signal ", hex(gp.sig), " code=", hex(gp.sigcode0), " addr=", hex(gp.sigcode1), " pc=", hex(gp.sigpc), "]\\n")
	}

	var docrash bool
	_g_ := getg()
	if t := gotraceback(&docrash); t > 0 {
		if gp != gp.m.g0 {
			print("\\n")
			goroutineheader(gp)
			traceback(pc, sp, 0, gp)
		} else if t >= 2 || _g_.m.throwing > 0 {
			print("\\nruntime stack:\\n")
			traceback(pc, sp, 0, gp)
		}
		if !didothers {
			didothers = true
			tracebackothers(gp)
		}
	}
	unlock(&paniclk)

	if xadd(&panicking, -1) != 0 {
		// Some other m is panicking too.
		// Let it print what it needs to print.
		// Wait forever without chewing up cpu.
		// It will exit when it's done.
		lock(&deadlock)
		lock(&deadlock)
	}

	if docrash {
		crash()
	}

	exit(2)
}

//go:nosplit
func canpanic(gp *g) bool {
	// Note that g is m->gsignal, different from gp.
	// Note also that g->m can change at preemption, so m can go stale
	// if this function ever makes a function call.
	_g_ := getg()
	_m_ := _g_.m

	// Is it okay for gp to panic instead of crashing the program?
	// Yes, as long as it is running Go code, not runtime code,
	// and not stuck in a system call.
	if gp == nil || gp != _m_.curg {
		return false
	}
	if _m_.locks-_m_.softfloat != 0 || _m_.mallocing != 0 || _m_.throwing != 0 || _m_.preemptoff != "" || _m_.dying != 0 {
		return false
	}
	status := readgstatus(gp)
	if status&^_Gscan != _Grunning || gp.syscallsp != 0 {
		return false
	}
	if GOOS == "windows" && _m_.libcallsp != 0 {
		return false
	}
	return true
}

## コアとなるコードの解説

このコミットで `panic.go` に追加されたコードは、Goランタイムにおける `panic` と `recover` のメカニズムの根幹をなす部分です。

*   **`recovery(gp *g)`**: この関数は、`defer` 関数内で `recover()` が呼び出されたときに、パニック状態から正常な実行フローに復帰させる役割を担います。`gp.sched.sp` (スタックポインタ) と `gp.sched.pc` (プログラムカウンタ) を、パニック発生前の `defer` が呼び出された時点のコンテキストに設定し、`gogo(&gp.sched)` を使ってそのコンテキストでgoroutineの実行を再開させます。これにより、`defer` を呼び出した関数が、パニックが発生しなかったかのように正常にリターンできるようになります。`gp.sched.ret = 1` は、`deferproc` が成功したことを示す特別な戻り値です。
*   **`startpanic_m()`**: この関数は、OSスレッド（M）レベルでパニック処理を開始する際の初期化と状態管理を行います。特に重要なのは、`_g_.m.dying` という状態変数による多重パニックのハンドリングです。
    *   `dying = 0` の場合、これは最初のパニックであり、`panicking` カウンタをインクリメントし、`paniclk` ミューテックスをロックして、`freezetheworld()` を呼び出すことで、他のすべてのgoroutineを一時停止させます。これは、パニック処理中にランタイムの整合性を保つために不可欠です。
    *   `dying` が1以上の場合、それはパニック処理中にさらにパニックが発生したことを意味します。この場合、ランタイムはより限定的なエラーメッセージを出力し、最終的にはプログラムを終了させます。これは、パニック処理自体が失敗するような深刻な状況に対応するためのフォールバックメカニズムです。
*   **`dopanic_m(gp *g, pc, sp uintptr)`**: この関数は、パニック発生時のスタックトレースの生成と出力、そしてプログラムの終了処理を担当します。
    *   シグナルによるパニックの場合、関連するシグナル情報を出力します。
    *   `gotraceback()` の結果に基づいて、現在のgoroutineおよび他のすべてのgoroutineのスタックトレースを詳細に出力します。これにより、開発者はパニックの原因を特定するための重要な情報を得ることができます。
    *   `paniclk` をアンロックし、`panicking` カウンタをデクリメントします。
    *   複数のMが同時にパニック処理を行っている可能性がある場合、`deadlock` ミューテックスを使用して、他のMが処理を完了するのを待ちます。
    *   `docrash` フラグが設定されている場合（通常は致命的なエラーの場合）、`crash()` を呼び出してプログラムを強制終了させます。
    *   最終的に `exit(2)` を呼び出してプログラムを終了させます。
*   **`canpanic(gp *g) bool`**: この関数は、特定のgoroutineが現在パニックを安全に処理できる状態にあるかどうかを判断します。Goランタイムは非常に低レベルで動作するため、特定の状況下（例: ランタイム内部のロックを保持している、メモリ割り当て中、システムコール中など）では、パニック処理を安全に実行できない場合があります。この関数は、そのような状況を検出し、プログラムのクラッシュを防ぐために `false` を返します。これにより、ランタイムの整合性が保たれ、予期せぬ動作を防ぎます。

これらのコードが `panic.go` に統合されたことで、Goランタイムのパニック処理に関するすべてのロジックが単一のファイルに集約され、Goのパニック/リカバリメカニズムの全体像をより容易に把握できるようになりました。

Go言語のランタイムには、プログラムの異常終了を処理するための `panic` および `recover` メカニズムが備わっています。これらの機能は、エラーハンドリングの重要な一部であり、特に回復不可能なエラーや予期せぬ状況に対応するために使用されます。

コードが複数のファイルに分散していると、関連するロジックを追跡するのが難しくなり、保守性や理解度が低下する可能性があります。このコミットは、このTODOコメントに従い、パニック処理のコードベースを統合することで、ランタイムのコード構造を簡素化し、より一貫性のあるものにすることを目的としています。これにより、開発者がパニック処理の内部動作を理解しやすくなり、将来的な変更やデバッグが容易になります。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下のGoランタイムの概念とパニック/リカバリメカニズムに関する知識が必要です。

1.  **Goroutine (g)**: Goランタイムにおける軽量な実行スレッドです。すべてのGoプログラムは1つ以上のgoroutineで実行されます。ランタイムはgoroutineのスケジューリング、スタック管理、パニック処理などを担当します。
2.  **Machine (m)**: オペレーティングシステムのスレッドを表します。Goランタイムは、複数のgoroutineを少数のOSスレッド（M）上で多重化して実行します。
3.  **Panic**: Goプログラムが回復不可能なエラーに遭遇した際に発生するメカニズムです。`panic` が発生すると、現在のgoroutineの実行は中断され、遅延関数（`defer`）がスタックを巻き戻しながら実行されます。
4.  **Recover**: `panic` によって中断されたgoroutineの実行を再開し、パニックから回復するための組み込み関数です。`recover` は `defer` 関数内でのみ有効であり、パニック値を捕捉して、プログラムがクラッシュするのを防ぐことができます。
5.  **Defer**: 関数がリターンする直前、または `panic` が発生してスタックが巻き戻される際に実行される関数をスケジュールするためのキーワードです。`defer` はリソースの解放やログ記録、そして `recover` と組み合わせてパニックからの回復によく使用されます。
6.  **Goランタイムの内部構造**: Goランタイムは、メモリ管理、スケジューリング、ガベージコレクション、パニック処理など、Goプログラムの実行を支える低レベルのコードです。これらの機能はC言語やアセンブリ言語、そしてGo言語自体で記述されています。
7.  **`_g_` と `_m_`**: ランタイムコード内で現在のgoroutine (`g`) と現在のOSスレッド (`m`) を参照するための慣習的な変数名です。`getg()` 関数は現在のgoroutineのポインタを返します。
8.  **`mutex`**: 複数のgoroutineが共有リソースに同時にアクセスするのを防ぐための同期プリミティブです。パニック処理のようなクリティカルなセクションでは、競合状態を避けるためにミューテックスが使用されます。
9.  **`freezetheworld()`**: ガベージコレクションやパニック処理などの特定のランタイム操作中に、すべてのgoroutineの実行を一時停止させるランタイム関数です。これにより、ランタイムが整合性のある状態で操作を実行できます。
10. **`traceback`**: パニック発生時に、現在のgoroutineのスタックトレースを出力するランタイム関数です。これにより、パニックが発生した場所と、そこに至るまでの関数呼び出しのシーケンスを特定できます。

## 技術的詳細

このコミットは、`src/runtime/panic1.go` に定義されていた以下の主要な関数と関連するグローバル変数、定数を `src/runtime/panic.go` に移動させました。

移動された主な要素は以下の通りです。

*   **`paniclk` (mutex)**: パニック処理中にランタイムの内部状態を保護するためのミューテックス。複数のgoroutineが同時にパニック状態になった場合に、処理の競合を防ぎます。
*   **`hasLinkRegister` (const)**: 特定のアーキテクチャ（ARM, ARM64, PPC64, PPC64LE）がリンクレジスタを持つかどうかを示す定数。スタックアンワインドやレジスタの復元に関連する処理で利用されます。
*   **`recovery(gp *g)` 関数**: `defer` 関数内で `recover` が呼び出された際に、スタックを巻き戻し、通常の関数リターンとして実行を継続させるためのロジックを実装しています。これは、パニック状態から正常な実行フローに戻るための重要なメカニズムです。
    *   `gp.sigcode0` と `gp.sigcode1` を使用して、`defer` の引数やリターンアドレスなどの情報を取得します。
    *   `gcUnwindBarriers` を呼び出して、ガベージコレクションのバリアを調整します。
    *   `gp.sched.sp`, `gp.sched.pc`, `gp.sched.ret` を設定し、`gogo(&gp.sched)` を使ってスケジューラに制御を戻し、指定されたPCとSPで実行を再開させます。`gp.sched.ret = 1` は、`deferproc` が成功したことを示す戻り値です。
*   **`startpanic_m()` 関数**: パニック処理の開始時に、現在のM（OSスレッド）の状態を初期化し、パニック処理の準備を行う関数です。
    *   `mheap_.cachealloc.size == 0` のチェックにより、メモリヒープが初期化されていない非常に早い段階でのパニックを検出します。
    *   `_g_.m.mcache == nil` のチェックにより、シグナルハンドラや `throw` から呼び出された場合の `mcache` の割り当てを処理します。
    *   `_g_.m.dying` という状態変数を使って、パニック処理の多重度を管理します。
        *   `dying = 0`: 最初のパニック。`panicking` カウンタをインクリメントし、`paniclk` をロックし、`freezetheworld()` を呼び出して他のgoroutineを停止させます。
        *   `dying = 1`: パニック処理中に別のパニックが発生した場合（例: パニック引数の出力中にエラー）。スタックトレースを出力して終了します。
        *   `dying = 2`: 2度目のパニック処理中にさらに問題が発生した場合（例: スタックトレースの出力に失敗）。「stack trace unavailable」と出力して終了します。
        *   `dying = 3` 以降: 印刷すらできない致命的な状況。直接終了します。
*   **`didothers` (var)**: 他のgoroutineのスタックトレースが既に出力されたかどうかを追跡するフラグ。
*   **`deadlock` (mutex)**: 複数のMが同時にパニック処理を行おうとした場合に、デッドロックを回避するためのミューテックス。
*   **`dopanic_m(gp *g, pc, sp uintptr)` 関数**: パニック処理の主要なロジックを実行する関数です。スタックトレースの出力、他のgoroutineの処理、そして最終的なプログラムの終了を担当します。
    *   シグナルによるパニックの場合、関連するシグナル情報を出力します。
    *   `gotraceback()` を呼び出して、スタックトレースの出力レベルを決定します。
    *   現在のgoroutine (`gp`) のスタックトレースを出力します。
    *   `tracebackothers(gp)` を呼び出して、他のgoroutineのスタックトレースも出力します。
    *   `paniclk` をアンロックし、`panicking` カウンタをデクリメントします。
    *   もし他のMもパニック処理中であれば、`deadlock` ミューテックスを使って待機します。
    *   `docrash` フラグが設定されていれば、`crash()` を呼び出してプログラムを強制終了させます。
    *   最終的に `exit(2)` を呼び出してプログラムを終了します。
*   **`canpanic(gp *g) bool` 関数**: 指定されたgoroutine `gp` がパニックを安全に処理できる状態にあるかどうかを判断する関数です。
    *   ランタイムコードの実行中、ロックを保持している、メモリ割り当て中、`throw` 処理中、プリエンプションが無効になっている、または `dying` 状態にあるM上ではパニック処理を安全に行えないため `false` を返します。
    *   `_Grunning` 状態でないgoroutineや、システムコール中にスタックポインタが設定されているgoroutineもパニック処理の対象外とします。
    *   Windows環境では、`libcallsp` が設定されている場合も `false` を返します。

これらの関数と変数を `panic.go` に統合することで、パニック処理に関するすべてのロジックが1つのファイルに集約され、Goランタイムの内部構造がより明確になりました。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、`src/runtime/panic1.go` の内容が完全に削除され、その内容が `src/runtime/panic.go` の末尾に追加された点です。

**`src/runtime/panic.go` への追加:**

```go
//uint32 runtime·panicking;
var paniclk mutex

const hasLinkRegister = GOARCH == "arm" || GOARCH == "arm64" || GOARCH == "ppc64" || GOARCH == "ppc64le"

// Unwind the stack after a deferred function calls recover
// after a panic.  Then arrange to continue running as though
// the caller of the deferred function returned normally.
func recovery(gp *g) {
	// Info about defer passed in G struct.
	sp := gp.sigcode0
	pc := gp.sigcode1

	// d's arguments need to be in the stack.
	if sp != 0 && (sp < gp.stack.lo || gp.stack.hi < sp) {
		print("recover: ", hex(sp), " not in [", hex(gp.stack.lo), ", ", hex(gp.stack.hi), "]\\n")
		throw("bad recovery")
	}

	// Make the deferproc for this d return again,
	// this time returning 1.  The calling function will
	// jump to the standard return epilogue.
	gcUnwindBarriers(gp, sp)
	gp.sched.sp = sp
	gp.sched.pc = pc
	gp.sched.lr = 0
	gp.sched.ret = 1
	gogo(&gp.sched)
}

func startpanic_m() {
	_g_ := getg()
	if mheap_.cachealloc.size == 0 { // very early
		print("runtime: panic before malloc heap initialized\\n")
		_g_.m.mallocing = 1 // tell rest of panic not to try to malloc
	} else if _g_.m.mcache == nil { // can happen if called from signal handler or throw
		_g_.m.mcache = allocmcache()
	}

	switch _g_.m.dying {
	case 0:
		_g_.m.dying = 1
		if _g_ != nil {
			_g_.writebuf = nil
		}
		xadd(&panicking, 1)
		lock(&paniclk)
		if debug.schedtrace > 0 || debug.scheddetail > 0 {
			schedtrace(true)
		}
		freezetheworld()
		return
	case 1:
		// Something failed while panicing, probably the print of the
		// argument to panic().  Just print a stack trace and exit.
		_g_.m.dying = 2
		print("panic during panic\\n")
		dopanic(0)
		exit(3)
		fallthrough
	case 2:
		// This is a genuine bug in the runtime, we couldn't even
		// print the stack trace successfully.
		_g_.m.dying = 3
		print("stack trace unavailable\\n")
		exit(4)
		fallthrough
	default:
		// Can't even print!  Just exit.
		exit(5)
	}
}

var didothers bool
var deadlock mutex

func dopanic_m(gp *g, pc, sp uintptr) {
	if gp.sig != 0 {
		print("[signal ", hex(gp.sig), " code=", hex(gp.sigcode0), " addr=", hex(gp.sigcode1), " pc=", hex(gp.sigpc), "]\\n")
	}

	var docrash bool
	_g_ := getg()
	if t := gotraceback(&docrash); t > 0 {
		if gp != gp.m.g0 {
			print("\\n")
			goroutineheader(gp)
			traceback(pc, sp, 0, gp)
		} else if t >= 2 || _g_.m.throwing > 0 {
			print("\\nruntime stack:\\n")
			traceback(pc, sp, 0, gp)
		}
		if !didothers {
			didothers = true
			tracebackothers(gp)
		}
	}
	unlock(&paniclk)

	if xadd(&panicking, -1) != 0 {
		// Some other m is panicking too.
		// Let it print what it needs to print.
		// Wait forever without chewing up cpu.
		// It will exit when it's done.
		lock(&deadlock)
		lock(&deadlock)
	}

	if docrash {
		crash()
	}

	exit(2)
}

//go:nosplit
func canpanic(gp *g) bool {
	// Note that g is m->gsignal, different from gp.
	// Note also that g->m can change at preemption, so m can go stale
	// if this function ever makes a function call.
	_g_ := getg()
	_m_ := _g_.m

	// Is it okay for gp to panic instead of crashing the program?
	// Yes, as long as it is running Go code, not runtime code,
	// and not stuck in a system call.
	if gp == nil || gp != _m_.curg {
		return false
	}
	if _m_.locks-_m_.softfloat != 0 || _m_.mallocing != 0 || _m_.throwing != 0 || _m_.preemptoff != "" || _m_.dying != 0 {
		return false
	}
	status := readgstatus(gp)
	if status&^_Gscan != _Grunning || gp.syscallsp != 0 {
		return false
	}
	if GOOS == "windows" && _m_.libcallsp != 0 {
		return false
	}
	return true
}

## コアとなるコードの解説

このコミットで `panic.go` に追加されたコードは、Goランタイムにおける `panic` と `recover` のメカニズムの根幹をなす部分です。

*   **`recovery(gp *g)`**: この関数は、`defer` 関数内で `recover()` が呼び出されたときに、パニック状態から正常な実行フローに復帰させる役割を担います。`gp.sched.sp` (スタックポインタ) と `gp.sched.pc` (プログラムカウンタ) を、パニック発生前の `defer` が呼び出された時点のコンテキストに設定し、`gogo(&gp.sched)` を使ってそのコンテキストでgoroutineの実行を再開させます。これにより、`defer` を呼び出した関数が、パニックが発生しなかったかのように正常にリターンできるようになります。`gp.sched.ret = 1` は、`deferproc` が成功したことを示す特別な戻り値です。
*   **`startpanic_m()`**: この関数は、OSスレッド（M）レベルでパニック処理を開始する際の初期化と状態管理を行います。特に重要なのは、`_g_.m.dying` という状態変数による多重パニックのハンドリングです。
    *   `dying = 0` の場合、これは最初のパニックであり、`panicking` カウンタをインクリメントし、`paniclk` ミューテックスをロックして、`freezetheworld()` を呼び出すことで、他のすべてのgoroutineを一時停止させます。これは、パニック処理中にランタイムの整合性を保つために不可欠です。
    *   `dying` が1以上の場合、それはパニック処理中にさらにパニックが発生したことを意味します。この場合、ランタイムはより限定的なエラーメッセージを出力し、最終的にはプログラムを終了させます。これは、パニック処理自体が失敗するような深刻な状況に対応するためのフォールバックメカニズムです。
*   **`dopanic_m(gp *g, pc, sp uintptr)`**: この関数は、パニック発生時のスタックトレースの生成と出力、そしてプログラムの終了処理を担当します。
    *   シグナルによるパニックの場合、関連するシグナル情報を出力します。
    *   `gotraceback()` の結果に基づいて、現在のgoroutineおよび他のすべてのgoroutineのスタックトレースを詳細に出力します。これにより、開発者はパニックの原因を特定するための重要な情報を得ることができます。
    *   `paniclk` をアンロックし、`panicking` カウンタをデクリメントします。
    *   複数のMが同時にパニック処理を行っている可能性がある場合、`deadlock` ミューテックスを使用して、他のMが処理を完了するのを待ちます。
    *   `docrash` フラグが設定されている場合（通常は致命的なエラーの場合）、`crash()` を呼び出してプログラムを強制終了させます。
    *   最終的に `exit(2)` を呼び出してプログラムを終了させます。
*   **`canpanic(gp *g) bool`**: この関数は、特定のgoroutineが現在パニックを安全に処理できる状態にあるかどうかを判断します。Goランタイムは非常に低レベルで動作するため、特定の状況下（例: ランタイム内部のロックを保持している、メモリ割り当て中、システムコール中など）では、パニック処理を安全に実行できない場合があります。この関数は、そのような状況を検出し、プログラムのクラッシュを防ぐために `false` を返します。これにより、ランタイムの整合性が保たれ、予期せぬ動作を防ぎます。

これらのコードが `panic.go` に統合されたことで、Goランタイムのパニック処理に関するすべてのロジックが単一のファイルに集約され、Goのパニック/リカバリメカニズムの全体像をより容易に把握できるようになりました。
