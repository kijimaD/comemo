# [インデックス 25895] ファイルの概要

このコミットは、Go言語の `net/mail` パッケージにおける `Address.String()` メソッドの挙動を修正し、メールアドレスの表示名（Name）に非ASCII文字や特定の記号が含まれる場合に、RFC 2047に準拠した適切なMIMEエンコード（Base64エンコード）を使用するように変更するものです。これにより、不正な文字を含む表示名が原因でメールクライアントがアドレスを正しく解釈できない問題を解決します。

## 元コミット内容

メールアドレスの表示名に非ASCII文字が含まれる場合、`Address.String()` は `mime.QEncoding` を使用してエンコードしていました。しかし、RFC 2047のセクション5.3で定義されているように、フレーズコンテキスト内のエンコードされた単語には特定の文字が禁止されており、`mime.QEncoding` はこれらの文字をエンコードしませんでした。このコミットでは、禁止されている文字もエンコードされるように、必要に応じて `mime.BEncoding` (Base64エンコーディング) を使用するように変更されました。これにより、Issue #11292 が修正されます。

## 変更の背景

電子メールのヘッダーフィールド、特に `From`, `To`, `Cc` などのアドレスフィールドには、通常、ASCII文字のみが使用されることが期待されます。しかし、世界中のユーザーが様々な言語を使用するため、表示名（例: "山田 太郎"）に非ASCII文字が含まれることは一般的です。このような場合、RFC 2047「MIME (Multipurpose Internet Mail Extensions) Part Three: Message Header Extensions for Non-ASCII Text」で定義されている「Encoded-Word」構文を使用して、非ASCII文字をASCII文字のシーケンスに変換する必要があります。

Goの `net/mail` パッケージの `Address.String()` メソッドは、これまで非ASCII文字を含む表示名に対して `mime.QEncoding` (Quoted-Printableエンコーディング) を使用していました。しかし、RFC 2047のセクション5.3「Use of Encoded-Words in Phrases」には、エンコードされた単語が「フレーズ」コンテキスト（例えば、表示名）で使用される場合、特定の文字（引用符、括弧、コロン、セミコロンなど）はエンコードされた単語内に直接含めることが禁止されていると明記されています。`mime.QEncoding` は、これらの禁止文字をエンコードしないため、表示名にこれらの文字が含まれていると、RFC 2047の要件に違反し、一部のメールクライアントでアドレスが正しく表示されない、またはパースエラーを引き起こす可能性がありました。

この問題は、GoのIssue #11292として報告され、このコミットによって解決されることになりました。具体的には、表示名にRFC 2047セクション5.3で禁止されている文字が含まれる場合、より包括的に文字をエンコードできる `mime.BEncoding` (Base64エンコーディング) を使用するように変更されました。

## 前提知識の解説

### RFC 2047: MIME Encoded-Words

RFC 2047は、MIMEヘッダーフィールド内で非ASCII文字を使用するための標準を定義しています。これは「Encoded-Word」と呼ばれる特別な構文を使用します。Encoded-Wordは `=?charset?encoding?encoded-text?=` の形式を取ります。

-   `charset`: 使用される文字セット（例: `utf-8`, `iso-2022-jp`）。
-   `encoding`: エンコード方式（`Q` は Quoted-Printable、`B` は Base64）。
-   `encoded-text`: 実際のエンコードされた文字列。

### Q-Encoding (Quoted-Printable)

`Q` エンコーディングは、主にテキストの可読性を維持しつつ、非ASCII文字をエンコードするために使用されます。ASCII文字の多くはそのまま残され、非ASCII文字や特定の記号は `=XX` の形式（XXは16進数）でエンコードされます。スペースは `_` にエンコードされることもあります。

### B-Encoding (Base64)

`B` エンコーディングは、すべてのバイトデータをBase64形式でエンコードします。これにより、元のテキストがどのような文字を含んでいても、完全にASCII文字のシーケンスに変換されます。Q-Encodingと比較して、可読性は失われますが、より広範な文字セットやバイナリデータを安全に転送できます。

### RFC 2047 セクション 5.3: フレーズコンテキストにおける禁止文字

RFC 2047のセクション5.3では、Encoded-Wordが「phrase」（例: `From: "表示名" <アドレス>` の「表示名」部分）内で使用される場合の制約が記述されています。このコンテキストでは、Encoded-Wordのデコードされた結果が、以下の文字を含んではならないとされています。

-   `(` `)` `<` `>` `@` `,` `;` `:` `\` `.` `"` `[` `]`
-   制御文字 (CTLs)
-   スペース (SP)

これらの文字は、メールヘッダーの構文解析において特別な意味を持つため、Encoded-Wordのデコード結果に直接現れると、パーサーが誤動作する可能性があります。`mime.QEncoding` はこれらの文字の一部をエンコードしないため、問題が発生することがありました。

### Go言語の `net/mail` および `mime` パッケージ

-   `net/mail`: 電子メールアドレスのパースとフォーマット、メッセージヘッダーの処理など、メール関連の機能を提供します。`Address` 構造体は、メールアドレスの表示名とアドレス部分を保持します。
-   `mime`: MIMEエンコード/デコード機能を提供します。`mime.QEncoding` と `mime.BEncoding` は、それぞれQuoted-PrintableとBase64のエンコーダー/デコーダーを提供します。

## 技術的詳細

このコミット以前の `net/mail.Address.String()` メソッドは、表示名 `a.Name` に非ASCII文字が含まれる場合、常に `mime.QEncoding` を使用してエンコードしていました。

```go
// 以前のコードの抜粋 (概念)
if containsNonASCII(a.Name) {
    return mime.QEncoding.Encode("utf-8", a.Name) + " " + s
}
```

このアプローチは、表示名が単純な非ASCII文字（例: "あいうえお"）のみを含む場合には問題ありませんでした。しかし、表示名に `"` や `(` などのRFC 2047セクション5.3で禁止されている文字が含まれている場合、`mime.QEncoding` はこれらの文字をエンコードせずにそのまま出力することがありました。例えば、`"Böb, Jacöb"` のような表示名の場合、`QEncoding` は `,` をエンコードしないため、結果として生成されるヘッダーはRFC 2047の要件に違反し、メールクライアントが正しく解釈できない可能性がありました。

このコミットでは、この問題を解決するために、`Address.String()` メソッドに以下のロジックが追加されました。

1.  まず、表示名 `a.Name` にRFC 2047セクション5.3で禁止されている文字のいずれかが含まれているかをチェックします。具体的には、`strings.ContainsAny(a.Name, "\"#$%&'(),.:;<>@[]^`{|}~")` を使用して、これらの文字のいずれかが存在するかを確認します。
2.  もしこれらの禁止文字が含まれている場合、`mime.BEncoding` (Base64エンコーディング) を使用して表示名をエンコードします。Base64エンコーディングは、すべてのバイトをASCII文字に変換するため、禁止文字も確実にエンコードされ、RFC 2047の要件を満たすことができます。
3.  禁止文字が含まれていない場合は、これまで通り `mime.QEncoding` を使用してエンコードします。これは、Q-Encodingの方が一般的に可読性が高いため、可能な限りQ-Encodingを使用するという意図があるためと考えられます。

この変更により、`Address.String()` は、表示名がRFC 2047のフレーズコンテキストの制約に違反する可能性のある文字を含む場合に、より堅牢なBase64エンコーディングを選択するようになり、メールの互換性が向上しました。

## コアとなるコードの解説

### `src/net/mail/message.go` の変更

`Address.String()` メソッド内に新しい条件分岐が追加されました。

```go
	// Text in an encoded-word in a display-name must not contain certain
	// characters like quotes or parentheses (see RFC 2047 section 5.3).
	// When this is the case encode the name using base64 encoding.
	if strings.ContainsAny(a.Name, "\"#$%&'(),.:;<>@[]^`{|}~") {
		return mime.BEncoding.Encode("utf-8", a.Name) + " " + s
	}
	return mime.QEncoding.Encode("utf-8", a.Name) + " " + s
```

-   `strings.ContainsAny(a.Name, "\"#$%&'(),.:;<>@[]^`{|}~")`: この行が変更の核心です。`a.Name` (表示名) に、RFC 2047セクション5.3でフレーズコンテキストにおいて禁止されている文字のいずれかが含まれているかをチェックします。具体的には、引用符 (`"`), シャープ (`#`), ドル (`$`), パーセント (`%`), アンパサンド (`&`), シングルクォート (`'`), 括弧 (`()`), カンマ (`,`), コロン (`:`), セミコロン (`;`), 小なり (`<`), 大なり (`>`), アットマーク (`@`), 角括弧 (`[]`), キャレット (`^`), バッククォート (`` ` ``), 波括弧 (`{}`), パイプ (`|`), チルダ (`~`) のいずれかが含まれているかを確認します。
-   `return mime.BEncoding.Encode("utf-8", a.Name) + " " + s`: もし禁止文字が含まれている場合、`mime.BEncoding` (Base64エンコーディング) を使用して `a.Name` をUTF-8でエンコードします。これにより、すべての文字がASCII表現に変換され、RFC 2047の制約が満たされます。エンコードされた表示名の後に、アドレス部分 `s` が続きます。
-   `return mime.QEncoding.Encode("utf-8", a.Name) + " " + s`: 禁止文字が含まれていない場合は、これまで通り `mime.QEncoding` (Quoted-Printableエンコーディング) を使用してエンコードします。

この変更により、`Address.String()` は、表示名がRFC 2047のフレーズコンテキストの制約に違反する可能性のある文字を含む場合に、より堅牢なBase64エンコーディングを選択するようになり、メールの互換性が向上しました。

### `src/net/mail/message_test.go` の変更

テストファイルには、新しいテストケースが追加されています。

1.  `TestAddressFormatting` に新しいテストケースが追加されました。
    ```go
    		{
    			&Address{Name: "Böb, Jacöb", Address: "bob@example.com"},
    			`=?utf-8?b?QsO2YiwgSmFjw7Zi?= <bob@example.com>`,
    		},
    ```
    このテストケースは、表示名に非ASCII文字とカンマ (`,`) が含まれる場合に、正しくBase64エンコードされることを確認します。カンマはRFC 2047セクション5.3で禁止されている文字の一つであり、この変更によってBase64エンコードが選択されるべきケースです。期待される出力は `=?utf-8?b?QsO2YiwgSmFjw7Zi?= <bob@example.com>` であり、`QsO2YiwgSmFjw7Zi` は "Böb, Jacöb" のBase64エンコードです。

2.  `TestAddressFormattingAndParsing` という新しいテスト関数が追加されました。
    このテスト関数は、様々な特殊文字や非ASCII文字を含む表示名を持つ `Address` オブジェクトのリストを定義しています。
    ```go
    	tests := []*Address{
    		&Address{Name: "@lïce", Address: "alice@example.com"},
    		&Address{Name: "Böb O'Connor", Address: "bob@example.com"},
    		&Address{Name: "???", Address: "bob@example.com"},
    		&Address{Name: "Böb ???", Address: "bob@example.com"},
    		&Address{Name: "Böb (Jacöb)", Address: "bob@example.com"},
    		&Address{Name: "à#$%&'(),.:;<>@[]^`{|}~'", Address: "bob@example.com"},
    		// https://golang.org/issue/11292
    		&Address{Name: "\"\\x1f,\"", Address: "0@0"},
    		// https://golang.org/issue/12782
    		&Address{Name: "naé, mée", Address: "test.mail@gmail.com"},
    	}
    ```
    これらのテストケースには、アットマーク (`@`), シングルクォート (`'`), 疑問符 (`?`), 括弧 (`()`), そしてRFC 2047セクション5.3で禁止されているほぼすべての文字を含む表示名が含まれています。特に、`"à#$%&'(),.:;<>@[]^`{|}~'"` のような表示名は、新しいロジックがBase64エンコーディングをトリガーすることを確認するためのものです。
    各テストケースに対して、`test.String()` を呼び出してアドレスを文字列にフォーマットし、その結果を `ParseAddress` で再度パースします。そして、パースされた `Name` と `Address` が元の値と一致するかどうかを検証しています。これにより、フォーマットとパースの両方のプロセスが正しく機能し、特にBase64エンコードされた表示名が正しく処理されることを保証します。

これらのテストケースは、変更が意図した通りに機能し、RFC 2047の要件を満たしていることを確認するための重要な検証です。
