# [インデックス 25139] ファイルの概要

このコミットは、Go言語のコードフォーマッタである `gofmt` および `go/format` パッケージが、空白のみの入力（例えば、空のファイルやスペース、タブ、改行のみを含むファイル）を正しく処理するように修正するものです。具体的には、フォーマット後の出力が空になる場合に、元の入力ソースコードを返すように変更されています。これにより、空白のみの入力が意図せず削除されてしまう問題を解決しています。

## 変更の背景

Go言語の公式フォーマッタである `gofmt` や、その基盤となる `go/format` パッケージは、Goのソースコードを標準的なスタイルに整形する役割を担っています。しかし、このコミット以前のバージョンでは、入力されたソースコードが実質的に空白文字（スペース、タブ、改行など）のみで構成されている場合、フォーマット処理後にその空白がすべて削除され、空の出力が生成されるという問題がありました。

これは、特に以下のようなシナリオで問題を引き起こす可能性がありました。

1.  **空のファイルの扱い**: 完全に空のファイルや、意図的に空白のみで構成されたファイルが `gofmt` によって処理されると、そのファイルの内容が失われ、空のファイルになってしまう。
2.  **差分ツールの挙動**: バージョン管理システム（Gitなど）で差分を比較する際、空白のみの変更が `gofmt` によって削除されると、意図しない変更として検出されたり、逆に意図した空白の保持ができなかったりする。
3.  **ツールの連携**: `gofmt` を他のツールやスクリプトと連携させる場合、空白のみの入力に対する予期せぬ挙動が、後続の処理に悪影響を及ぼす可能性があった。

この問題は、GoのIssueトラッカーで #11275 として報告され、このコミットによって解決されました。

## 前提知識の解説

*   **`gofmt`**: Go言語のソースコードを自動的に整形するツールです。Goの標準的なコーディングスタイルを強制し、コードの一貫性を保つのに役立ちます。通常、`gofmt -w file.go` のように実行され、ファイルを直接書き換えます。
*   **`go/format` パッケージ**: `gofmt` ツールが内部で使用しているGo標準ライブラリのパッケージです。Goの抽象構文木 (AST) を解析し、整形されたバイト列を生成する機能を提供します。
*   **抽象構文木 (AST)**: ソースコードの構造を木構造で表現したものです。コンパイラやリンタ、フォーマッタなどのツールは、ソースコードをASTに変換し、そのASTを操作することで様々な処理を行います。`go/format` パッケージは、このASTを基にコードを整形します。
*   **`sourceAdj` 関数**: `go/format` パッケージ内部で使用される関数で、整形されたコードのバイト列とインデント設定を受け取り、最終的な出力バイト列を調整する役割を担っています。特に、行頭のスペースやインデントの処理に関わります。
*   **Issue #11275**: このコミットが修正したGoのバグ報告番号です。具体的な内容は「`gofmt` が空白のみの入力を正しく扱わない」というものでした。

## 技術的詳細

`gofmt` および `go/format` パッケージの `format` 関数は、入力されたソースコードを解析し、整形されたバイト列を生成します。この処理の過程で、`sourceAdj` という内部関数が整形後のバイト列の調整を行います。

問題は、入力が空白のみの場合、`sourceAdj` が返す整形後のバイト列が空になることがあった点です。従来のコードでは、この空のバイト列がそのまま最終結果に追加されていました。その結果、元のソースコードが空白のみであっても、出力は完全に空になってしまっていました。

このコミットの修正は、この挙動を変更し、`sourceAdj` から返された出力が空である場合に、元の入力ソースコード（`src`）をそのまま返すようにしています。これにより、空白のみの入力が意図せず削除されることを防ぎます。

具体的には、以下のロジックが導入されました。

1.  `sourceAdj` 関数によって調整された出力 (`out`) を取得します。
2.  もし `out` の長さが0（つまり空）であれば、それは元のソースが空であるか、空白のみで構成されていたことを意味します。この場合、元の入力ソース (`src`) をそのまま返します。
3.  `out` が空でなければ、通常通り `res` に `out` を追加します。

この変更は、`src/cmd/gofmt/internal.go` と `src/go/format/internal.go` の両方に適用されています。これは、`gofmt` ツールと `go/format` パッケージが同じ内部ロジックを共有しているためです。

また、この修正を検証するために、`src/go/format/format_test.go` に新しいテストケースが追加されました。これらのテストケースは、空文字列、スペース、タブ、改行、それらの組み合わせなど、様々な空白のみの入力を `gofmt` が正しく処理し、元の入力を保持することを確認します。

## コアとなるコードの解説

変更された `format` 関数内のロジックは以下の通りです。

1.  `sourceAdj(buf.Bytes(), cfg.Indent)` を呼び出し、整形されたコードのバイト列 `out` を取得します。`buf.Bytes()` は、ASTから生成された整形済みコードのバイト列です。`cfg.Indent` はインデント設定です。
2.  `if len(out) == 0 { return src, nil }`
    *   ここで、`out` の長さが0であるかどうかがチェックされます。
    *   もし `out` が空であれば、これは元のソースコードが空であるか、Goの有効な構文要素を含まず、空白文字のみで構成されていたことを意味します。
    *   この場合、`src` (元の入力ソースコードのバイト列) をそのまま返し、エラーは発生しなかったことを示します (`nil`)。これにより、空白のみの入力が失われることを防ぎます。
3.  `res = append(res, out...)`
    *   `out` が空でなければ、通常通り `out` を結果のバイト列 `res` に追加します。これは、有効なGoコードが整形された場合に適用される通常の処理パスです。

この修正により、`gofmt` は空白のみの入力に対しても「何もしない」という期待される挙動を示すようになり、元の空白を保持するようになりました。これは、ツールの堅牢性とユーザーエクスペリエンスの向上に貢献します。
