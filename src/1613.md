## 変更の背景

Go言語の`flag`パッケージは、コマンドライン引数を解析するための基本的な機能を提供します。このコミットが作成された2009年2月は、Go言語がまだ初期開発段階にあり、多くの標準ライブラリが活発に設計・実装・改善されていた時期です。

このコミットの主な背景は以下の2点です。

1.  **`Usage`メッセージのバグ修正**: `flag`パッケージには、定義されたフラグのヘルプメッセージ（`Usage`メッセージ）を表示する機能があります。この機能は通常、フラグの名前、デフォルト値、および説明を表示します。しかし、バグにより、フラグに値が設定された後（例えば、コマンドラインで指定された値や、プログラム内で明示的に設定された値）に`Usage`メッセージを表示すると、本来表示されるべき「デフォルト値」ではなく、「現在の値」が表示されてしまう問題がありました。これはユーザーがフラグの本来のデフォルト設定を理解する上で混乱を招く可能性がありました。
2.  **コードのクリーンアップ**: 初期開発段階のコードベースでは、機能の追加と同時に、コードの構造や可読性を改善するためのリファクタリングが頻繁に行われます。このコミットも、`flag`パッケージ内の内部構造（`Flag`構造体）の改善や、関連関数の呼び出し順序の整理など、全体的なコード品質の向上を目指しています。

これらの変更は、`flag`パッケージの正確性、使いやすさ、および内部的な整合性を高めるために不可欠でした。

## 前提知識の解説

### Go言語の`flag`パッケージ

Go言語の`flag`パッケージは、コマンドライン引数を解析するための標準ライブラリです。プログラムが起動される際に渡される引数（例: `-port=8080`, `-debug`）を、Goプログラム内で簡単に扱えるようにします。

主要な機能は以下の通りです。

*   **フラグの定義**: `flag.Int()`, `flag.String()`, `flag.Bool()`などの関数を使って、整数、文字列、真偽値などの型のフラグを定義します。これらの関数は、フラグの名前、デフォルト値、およびヘルプメッセージを受け取ります。
*   **変数のバインド**: `flag.IntVar()`, `flag.StringVar()`, `flag.BoolVar()`などの関数を使って、既存の変数にフラグの値をバインドすることもできます。
*   **引数の解析**: `flag.Parse()`関数を呼び出すことで、コマンドライン引数が解析され、定義されたフラグに値が設定されます。
*   **ヘルプメッセージ**: `flag`パッケージは、`--help`や`-h`オプションが指定された場合、または解析エラーが発生した場合に、定義されたすべてのフラグとその説明、デフォルト値を自動的に表示する機能（`Usage`メッセージ）を提供します。

### コマンドライン引数とデフォルト値

コマンドライン引数は、プログラムの実行時に外部から設定を渡すための一般的な方法です。例えば、`myprogram -config /etc/myprogram.conf`のように使われます。

「デフォルト値」とは、ユーザーが特定のコマンドライン引数を指定しなかった場合に、プログラムが自動的に使用する値のことです。例えば、`-port`フラグのデフォルト値が`8080`であれば、ユーザーが`-port`を指定しなくても、プログラムはポート`8080`を使用します。このデフォルト値は、プログラムの使いやすさと柔軟性を高める上で非常に重要です。

### Go言語におけるエクスポートされた識別子と非エクスポートされた識別子

Go言語では、識別子（変数名、関数名、型名など）の最初の文字が大文字か小文字かによって、その可視性（スコープ）が決定されます。

*   **大文字で始まる識別子**: パッケージ外からアクセス可能です。これを「エクスポートされた識別子」と呼びます。例えば、`fmt.Println`の`Println`はエクスポートされているため、`fmt`パッケージをインポートすればどこからでも呼び出せます。
*   **小文字で始まる識別子**: その識別子が定義されているパッケージ内からのみアクセス可能です。これを「非エクスポートされた識別子」と呼びます。これは、パッケージの内部実装の詳細を隠蔽し、外部からの不適切なアクセスを防ぐためのカプセル化のメカニズムです。

このコミットでは、`ParseOne`関数が`parseOne`にリネームされており、これはこの関数がパッケージ内部でのみ使用されるべきであることを示しています。

## 技術的詳細

このコミットは、`src/lib/flag.go`ファイルに対して行われ、主に以下の技術的な変更を含んでいます。

1.  **`Flag`構造体の拡張**:
    *   `Flag`構造体は、個々のコマンドラインフラグのメタデータを保持します。
    *   以前は`name`, `usage`, `value`のフィールドを持っていましたが、このコミットで新たに`defvalue string`フィールドが追加されました。
    *   `defvalue`は、フラグの「デフォルト値」を文字列として記憶するためのものです。これにより、フラグの現在の値とは独立して、常に元のデフォルト値を参照できるようになります。
    *   既存のフィールドにもコメントが追加され、それぞれの役割が明確化されました。

2.  **`add`関数の変更**:
    *   `add`関数は、新しいフラグを`flag`パッケージの内部マップに登録する役割を担います。
    *   この関数内で、`f.defvalue = value.str()`という行が追加されました。これは、フラグが定義される際に、その初期値（デフォルト値）を文字列として`defvalue`フィールドに保存することを意味します。この値は、後で`Usage`メッセージを表示する際に使用されます。

3.  **`PrintDefaults`関数のバグ修正**:
    *   `PrintDefaults`関数は、すべての定義済みフラグのヘルプメッセージ（デフォルト値を含む）を出力します。
    *   以前の実装では、`f.value.str()`を使用してフラグの値を表示していました。`f.value`はフラグの「現在の値」を保持しているため、フラグがコマンドライン引数によって変更された場合、`PrintDefaults`はデフォルト値ではなく、変更後の現在の値を表示してしまっていました。
    *   このコミットでは、`f.value.str()`が`f.defvalue`に置き換えられました。これにより、`PrintDefaults`は常にフラグの定義時に設定されたデフォルト値を正確に表示するようになります。これがこのコミットの主要なバグ修正です。

4.  **フラグ定義関数のリファクタリング**:
    *   `Bool`, `Int`, `Int64`, `Uint`, `Uint64`, `String`といった、特定の型のフラグを定義する関数群の順序が変更されました。
    *   以前は、`Bool`の後に`BoolVar`が定義されていましたが、この変更により`BoolVar`が先に定義され、`Bool`関数が内部で`BoolVar`を呼び出す形になりました。
    *   これは、コードの重複を減らし、`Var`形式の関数（既存の変数にバインドする形式）を基本的な実装として、非`Var`形式の関数（新しいポインタを返す形式）がそれを再利用するという、よりクリーンな設計パターンへの移行を示しています。

5.  **`ParseOne`関数のリネーム**:
    *   `allFlags`構造体のメソッドである`ParseOne`が`parseOne`にリネームされました。
    *   Go言語の命名規則に従い、小文字で始まる関数はパッケージ内部でのみ使用されることを意味します。これにより、`ParseOne`が`flag`パッケージの外部から直接呼び出されることがなくなり、内部実装の詳細が隠蔽され、APIの整合性が向上します。

これらの変更は、`flag`パッケージの堅牢性、正確性、およびGo言語の設計原則への準拠を強化するものです。

## コアとなるコードの解説

### `Flag`構造体への`defvalue`フィールド追加

```go
type Flag struct {
	name	string;	// name as it appears on command line
	usage	string;	// help message
	value	_Value;	// value as set
	defvalue	string;	// default value (as text); for usage message
}
```

*   **変更点**: `Flag`構造体に`defvalue string`フィールドが追加されました。
*   **解説**: このフィールドは、フラグが定義された際の「初期のデフォルト値」を文字列として保持するために導入されました。以前は、`Flag`構造体にはフラグの「現在の値」を保持する`value`フィールドしかありませんでした。このため、フラグの値がコマンドライン引数などによって変更されると、元のデフォルト値を参照する方法がありませんでした。`defvalue`の追加により、`Usage`メッセージなどで常に正しいデフォルト値を表示できるようになります。また、既存のフィールドにもコメントが追加され、コードの可読性が向上しています。

### `add`関数での`defvalue`の初期化

```go
func add(name string, value _Value, usage string) {
	f.name = name;
	f.usage = usage;
	f.value = value;
	f.defvalue = value.str();	// Remember the default value as a string; it won't change.
	dummy, alreadythere := flags.formal[name];
	if alreadythere {
		print("flag redefined: ", name, "\n");
		panic("flag redefinition");	// Happens only if flags are declared with identical names
	}
	flags.formal[name] = f;
}
```

*   **変更点**: `f.defvalue = value.str();`という行が追加されました。
*   **解説**: `add`関数は、新しいフラグがシステムに登録される際に呼び出されます。この変更により、フラグが初期化される時点で、そのデフォルト値（`value.str()`で取得される初期値）が`Flag`構造体の`defvalue`フィールドに保存されます。この`defvalue`は、フラグのライフサイクルを通じて変更されることはなく、常にそのフラグの本来のデフォルト設定を反映します。これにより、後続の`PrintDefaults`関数が正確なデフォルト値を参照できるようになります。

### `PrintDefaults`関数での`defvalue`の使用

```go
func PrintDefaults() {
	for k, f := range flags.formal {
		print("  -", f.name, "=", f.defvalue, ": ", f.usage, "\n");
	}
}
```

*   **変更点**: `print`文の中で、`f.value.str()`が`f.defvalue`に置き換えられました。
*   **解説**: これが、`Usage`メッセージのバグを修正する核心的な変更です。以前は、`PrintDefaults`がフラグの「現在の値」を表示してしまっていたため、ユーザーがコマンドラインでフラグの値を変更した場合、ヘルプメッセージに表示される値も変更後の値になってしまい、混乱を招いていました。`f.defvalue`を使用することで、`PrintDefaults`は常にフラグが定義された際の「デフォルト値」を正確に表示するようになり、ユーザーはフラグの本来の挙動を正しく理解できるようになります。

### フラグ定義関数のリファクタリング

```go
// Before:
// func Bool(name string, value bool, usage string) *bool { ... }
// func BoolVar(p *bool, name string, value bool, usage string) { ... }

// After:
func BoolVar(p *bool, name string, value bool, usage string) {
	add(name, newBoolValue(value, p), usage);
}

func Bool(name string, value bool, usage string) *bool {
	p := new(bool);
	BoolVar(p, name, value, usage);
	return p;
}
// Similar changes for Int, Int64, Uint, Uint64, String
```

*   **変更点**: `BoolVar`のような`Var`形式の関数が先に定義され、`Bool`のような非`Var`形式の関数が内部で`Var`形式の関数を呼び出すように変更されました。
*   **解説**: この変更は、コードの重複を減らし、よりモジュール化された設計を促進するためのリファクタリングです。`Var`形式の関数は、既存の変数にフラグの値をバインドするという、より低レベルで汎用的な操作を行います。非`Var`形式の関数は、内部で新しいポインタを作成し、それを`Var`形式の関数に渡すことで、その機能を再利用しています。これにより、コードベース全体の保守性が向上し、将来的な機能追加や変更が容易になります。

### `ParseOne`から`parseOne`へのリネーム

```go
// Before:
// func (f *allFlags) ParseOne(index int) (ok bool, next int)

// After:
func (f *allFlags) parseOne(index int) (ok bool, next int)
```

*   **変更点**: `allFlags`構造体のメソッド`ParseOne`が`parseOne`にリネームされ、それに伴い`Parse`関数内の呼び出しも変更されました。
*   **解説**: Go言語の命名規則では、小文字で始まる識別子はパッケージ内部でのみアクセス可能です。このリネームは、`ParseOne`関数が`flag`パッケージの外部から直接呼び出されることを意図していない、内部的なヘルパー関数であることを明確に示しています。これにより、パッケージのAPIがより明確になり、外部からの不適切な使用を防ぐことができます。これは、Go言語の設計哲学である「カプセル化」と「明確なAPI境界」に沿った変更です。
