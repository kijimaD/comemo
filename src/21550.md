# [インデックス 21550] ファイルの概要

このコミットは、Goランタイムにおける`*bsd/amd64`ビルドの問題を修正するものです。具体的には、古いGoコンパイラである`6g`が定数スイッチ（`const switch`）に対してデッドコード排除（Dead Code Elimination: DCE）を適切に行わないために発生していたリンク時のエラーを解決します。`raiseproc()`という未定義の関数が、本来到達不能なコードパスに存在していたことが問題の原因でした。この修正により、`switch`文を`if`文に置き換えることで、`6g`コンパイラでもデッドコードが正しく排除されるようになり、ビルドが成功するようになります。

## 変更の背景

この変更の背景には、Go言語の古いコンパイラである`6g`の特定の最適化の限界がありました。`src/runtime/signal_amd64x.go`ファイル内の`sighandler`関数には、`docrash`が真の場合に特定のOS（`darwin`や`linux`）でのみ実行されるべきコードブロックが存在しました。このブロック内には、他のシステムでは未実装である`raiseproc()`という関数への呼び出しが含まれていました。

通常、コンパイラは到達不能なコード（デッドコード）を最終的なバイナリから削除する「デッドコード排除」という最適化を行います。しかし、`6g`コンパイラは、定数条件を持つ`if`文に対してはデッドコード排除を適切に行う一方で、定数条件を持つ`switch`文に対してはそれが不完全でした。

このため、`GOOS`が`darwin`や`linux`ではないビルド（例：`*bsd/amd64`）において、`switch GOOS`文の他の`case`ブロック（この場合はデフォルトのケース）が、たとえ実行時に到達不能であっても、コンパイル時に完全に排除されませんでした。結果として、そのブロック内に含まれる未定義の`raiseproc()`関数への参照が残り、リンク時に「未定義シンボル」エラー（`link-time failure`）を引き起こしていました。

このコミットは、この`6g`コンパイラの挙動の差異を回避し、`*bsd/amd64`環境でのビルドを成功させるために行われました。

## 前提知識の解説

1.  **Goコンパイラ (`6g`):**
    *   `6g`は、Go言語の初期のコンパイラツールチェーンの一部であり、`amd64`アーキテクチャ向けのGoコードをコンパイルするために使用されていました。Go言語の進化に伴い、現在ではより新しい`gc`（Go Compiler）が主流となっています。このコミットが作成された時点では、`6g`がまだ広く使われており、その特性を考慮する必要がありました。
2.  **デッドコード排除 (Dead Code Elimination: DCE):**
    *   コンパイラ最適化の一種で、プログラムの実行に影響を与えないコード（デッドコード）を識別し、最終的な実行可能ファイルから削除するプロセスです。これにより、バイナリサイズが削減され、実行効率が向上する可能性があります。
    *   デッドコードは、例えば、常に`false`と評価される条件文の内部にあるコードや、決して呼び出されない関数などが該当します。
    *   コンパイラは、コンパイル時に定数として評価できる式（例: `const x = 1; if x == 2 { ... }`）に基づいて、コードが到達可能かどうかを判断します。
3.  **定数条件 (Const Condition):**
    *   コンパイル時にその値が確定している定数（`const`キーワードで宣言された変数やリテラル）を用いた条件式のことです。例えば、`const GOOS = "linux"`のような場合、`GOOS == "darwin"`はコンパイル時に`false`と評価されます。
4.  **リンク時のエラー (Link-time Failure):**
    *   コンパイルされたオブジェクトファイル（`.o`ファイルなど）を結合して最終的な実行可能ファイルを生成する「リンク」の段階で発生するエラーです。
    *   最も一般的なリンクエラーの一つが「未定義シンボル（Undefined Symbol）」エラーです。これは、ある関数や変数がコード内で参照されているにもかかわらず、その定義がリンク対象のどのオブジェクトファイルやライブラリにも見つからない場合に発生します。
    *   このコミットのケースでは、`raiseproc()`関数が特定のOSでは未定義であるにもかかわらず、`6g`のデッドコード排除の不備により、その参照がバイナリに残ってしまったためにリンクエラーが発生しました。
5.  **`GOOS`環境変数:**
    *   Go言語のビルドシステムで使用される環境変数で、ターゲットとなるオペレーティングシステム（例: `linux`, `darwin`, `windows`, `freebsd`など）を指定します。Goのクロスコンパイルにおいて非常に重要です。
6.  **`raiseproc()`関数:**
    *   Goランタイム内部で使用される可能性のある関数で、特定のシグナル処理やクラッシュハンドリングに関連していると考えられます。このコミットの文脈では、一部のOSではまだ実装されていない関数として言及されています。

## 技術的詳細

この問題の核心は、`6g`コンパイラのデッドコード排除ロジックにおける`switch`文と`if`文の扱いの差異にありました。

*   **`if`文の場合:** `if`文の条件がコンパイル時に定数として評価され、その結果が`false`であれば、`if`ブロック内のコードは完全にデッドコードとして認識され、最終的なバイナリから削除されます。
*   **`switch`文の場合:** `6g`コンパイラは、`switch`文の式が定数である場合でも、すべての`case`ラベルを完全に評価し、到達不能な`case`ブロック内のコードを完全に排除する能力が不足していました。特に、`GOOS`のような定数に基づいて`switch`を行う場合、現在の`GOOS`に一致しない`case`ブロックは実行時に到達不能ですが、`6g`はこれらのブロック内の未定義関数への参照を削除しきれなかったのです。

この不備により、`src/runtime/signal_amd64x.go`内の`sighandler`関数において、`docrash`が真の場合に実行されるコードパスで問題が発生しました。このパスは、`GOOS`が`darwin`または`linux`の場合にのみ`crashing++`などの処理を行うように意図されていました。しかし、`switch GOOS`を使用していたため、`*bsd/amd64`のような他のOS向けのビルドでは、`raiseproc()`という未定義関数への参照が残ってしまい、リンクエラーを引き起こしていました。

この修正は、このコンパイラの特性を回避するために、`switch`文を同等の`if`文に置き換えるというシンプルなアプローチを取りました。`if GOOS == "darwin" || GOOS == "linux"`という形式にすることで、`6g`コンパイラがこの条件を定数として正しく評価し、条件が`false`となるOS（例: `freebsd`）では、`if`ブロック全体をデッドコードとして完全に排除できるようになります。これにより、`raiseproc()`への未定義参照がバイナリから削除され、リンクエラーが解消されました。

現代のGoコンパイラ（`gc`）では、定数条件を持つ`switch`文に対してもデッドコード排除が適切に行われるため、このような問題は発生しません。このコミットは、当時の`6g`コンパイラの特定の制限に対処するための実用的な解決策でした。

## コアとなるコードの変更箇所

変更は`src/runtime/signal_amd64x.go`ファイルの一箇所のみです。

```diff
--- a/src/runtime/signal_amd64x.go
+++ b/src/runtime/signal_amd64x.go
@@ -170,9 +170,8 @@ func sighandler(sig uint32, info *siginfo, ctxt unsafe.Pointer, gp *g) {\n \n \tif docrash {\n \t\t// TODO(rsc): Implement raiseproc on other systems\n-\t\t// and then add to this switch.\n-\t\tswitch GOOS {\n-\t\tcase "darwin", "linux":
+\t\t// and then add to this if condition.\n+\t\tif GOOS == "darwin" || GOOS == "linux" {
 \t\t\tcrashing++
 \t\t\tif crashing < sched.mcount {\n \t\t\t\t// There are other m\'s that need to dump their stacks.
```

具体的には、以下の行が変更されました。

*   `-		switch GOOS {`
*   `-		case "darwin", "linux":`
*   `+		if GOOS == "darwin" || GOOS == "linux" {`

コメントも`// and then add to this switch.`から`// and then add to this if condition.`に変更されています。

## コアとなるコードの解説

変更されたコードは、`sighandler`関数内のクラッシュ処理ロジックの一部です。

元のコードでは、`GOOS`（ビルドターゲットOSを示す定数）に基づいて`switch`文を使用していました。

```go
		switch GOOS {
		case "darwin", "linux":
			crashing++
			// ...
```

この`switch`文の意図は、`GOOS`が`darwin`または`linux`の場合にのみ、`crashing++`などの特定の処理を実行することでした。しかし、`6g`コンパイラは、`GOOS`が例えば`freebsd`である場合でも、`case "darwin", "linux":`以外のパス（暗黙のデフォルトパス）に存在する可能性のある未定義の`raiseproc()`関数への参照を完全に削除できませんでした。

修正後のコードでは、`switch`文が同等の`if`文に置き換えられました。

```go
		if GOOS == "darwin" || GOOS == "linux" {
			crashing++
			// ...
```

この変更により、`GOOS`が`darwin`でも`linux`でもない場合（例: `freebsd`）、`if`条件`GOOS == "darwin" || GOOS == "linux"`はコンパイル時に`false`と評価されます。`6g`コンパイラは、定数条件を持つ`if`文に対してはデッドコード排除を適切に行うため、この`if`ブロック全体（およびその内部に含まれる`raiseproc()`への参照）が最終的なバイナリから完全に削除されるようになりました。

結果として、`*bsd/amd64`のようなビルドターゲットにおいても、未定義の`raiseproc()`関数への参照がバイナリに残ることがなくなり、リンク時のエラーが解消され、ビルドが成功するようになりました。この修正は、コンパイラの特定の挙動を回避するための、シンプルかつ効果的なパッチです。
