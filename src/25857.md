# [インデックス 25857] ファイルの概要

このコミットは、Go言語の標準ライブラリである`crypto/x509`パッケージにおけるX.509証明書のシリアル番号の取り扱いに関する変更です。具体的には、負のシリアル番号を持つ証明書のパースを許可するように修正されています。

## コミット

`crypto/x509`パッケージにおいて、負のシリアル番号を持つ証明書のパースを許可する変更。これは、一部のバグのあるソフトウェアが生成する証明書が負のシリアル番号を持つ場合があるため、それらの証明書をGoで処理できるようにするための対応です。

## 元コミット内容

```
crypto/x509: permit serial numbers to be negative.

Some software that produces certificates doesn't encode integers
correctly and, about half the time, ends up producing certificates with
serial numbers that are actually negative.

This buggy software, sadly, appears to be common enough that we should
let these errors pass. This change allows a Certificate.SerialNumber to
be negative.

Fixes #8265.

Change-Id: Ief35dae23988fb6d5e2873e3c521366fb03c6af4
Reviewed-on: https://go-review.googlesource.com/17247
Reviewed-by: Brad Fitzpatrick <bradfitz@golang.org>
```

## 変更の背景

X.509証明書のシリアル番号は、RFC 5280の規定により正の整数であるべきとされています。しかし、現実世界では、一部の証明書発行ソフトウェア（特にASN.1エンコーディングの実装にバグがあるもの）が、誤って負のシリアル番号を持つ証明書を生成してしまうケースが確認されていました。

Goの`crypto/x509`パッケージは、以前はこのような負のシリアル番号を持つ証明書をパースする際にエラーを発生させていました。しかし、これらの「バグのある」証明書が広く流通しているという実情があり、Goアプリケーションがこれらの証明書を処理できないと、相互運用性の問題が生じます。

このコミットは、Goの`crypto/x509`パッケージが、RFC 5280の「証明書利用者は、そのような証明書（負またはゼロのシリアル番号を持つもの）を適切に処理する準備をすべきである」という勧告に従い、実用上の必要性から負のシリアル番号を持つ証明書のパースを許可するように変更されました。これにより、Goアプリケーションがより多くの種類の証明書を問題なく扱えるようになり、互換性が向上しました。

この変更は、GitHub Issue #8265で報告された問題に対応するものです。

## 前提知識の解説

### X.509証明書とシリアル番号

X.509証明書は、公開鍵暗号の公開鍵を所有者（サブジェクト）に紐付けるためのデジタル文書です。TLS/SSL通信などで広く利用されています。
証明書には様々な情報が含まれていますが、その一つに「シリアル番号 (Serial Number)」があります。シリアル番号は、認証局 (CA) が発行する各証明書を一意に識別するための番号です。RFC 5280では、シリアル番号はCAによって各証明書に割り当てられる「正の整数」でなければならないと規定されています。

### ASN.1エンコーディングと整数表現

X.509証明書は、ASN.1 (Abstract Syntax Notation One) という標準化されたデータ記述言語で定義され、DER (Distinguished Encoding Rules) などのエンコーディングルールに従ってバイナリ形式で符号化されます。
ASN.1では整数を表現する際に、その値が負であるか正であるかをビットで示すことがあります。バグのある実装では、この符号ビットの扱いを誤り、本来正であるべきシリアル番号が負の数としてエンコードされてしまうことがあります。

### Goの`math/big`パッケージ

Go言語の`math/big`パッケージは、任意精度の整数、有理数、浮動小数点数を扱うためのパッケージです。X.509証明書のシリアル番号は非常に大きな値になることがあるため、Goの`crypto/x509`パッケージでは`*big.Int`型を使用してシリアル番号を表現しています。
`big.Int`型には`Sign()`メソッドがあり、これは数値の符号を返します。
*   `x.Sign() == -1` なら `x < 0`
*   `x.Sign() == 0` なら `x == 0`
*   `x.Sign() == 1` なら `x > 0`

## 技術的詳細

このコミット以前の`crypto/x509`パッケージの`parseCertificate`関数では、証明書のパース処理中にシリアル番号が負であるかどうかをチェックし、負であればエラーを返していました。具体的には、`in.TBSCertificate.SerialNumber.Sign() < 0`という条件でシリアル番号の符号をチェックし、負の場合には`errors.New("x509: negative serial number")`というエラーを返していました。

この厳格なチェックはRFC 5280の「シリアル番号は正の整数でなければならない」という規定に準拠したものでしたが、前述の通り、一部のバグのあるソフトウェアが負のシリアル番号を持つ証明書を生成してしまうという現実的な問題がありました。

このコミットでは、このシリアル番号が負であることのチェックを削除することで、負のシリアル番号を持つ証明書もパースできるように変更されました。これにより、Goの`crypto/x509`パッケージは、RFC 5280の「証明書利用者は、そのような証明書を適切に処理する準備をすべきである」という勧告により強く従う形となりました。

ただし、この変更は証明書の「生成」には影響しません。`crypto/x509`パッケージは、新しい証明書を生成する際には引き続きRFC 5280に準拠し、正のシリアル番号のみを生成します。この変更はあくまで「パース」時の挙動に関するものです。

後のGoのバージョン（Go 1.23以降）では、デフォルトで負のシリアル番号を拒否するようになり、`GODEBUG=x509negativeserial=1`という環境変数でこの挙動をオーバーライドできるようになっています。これは、このコミットで導入された「負のシリアル番号を許可する」という挙動が、セキュリティ上の懸念や標準への厳密な準拠の観点から再検討された結果と考えられます。しかし、このコミットが作成された時点では、相互運用性の確保が最優先されていました。

## コアとなるコードの解説

### `src/crypto/x509/x509.go`の変更

`parseCertificate`関数から以下の4行が削除されました。

```go
	if in.TBSCertificate.SerialNumber.Sign() < 0 {
		return nil, errors.New("x509: negative serial number")
	}
```

このコードは、パース中の証明書のシリアル番号が負である場合にエラーを返す役割を担っていました。この削除により、`parseCertificate`関数は負のシリアル番号を持つ証明書に対してもエラーを返さなくなり、パース処理を続行するようになります。結果として、`Certificate.SerialNumber`フィールドに負の値が設定されることが許可されます。

### `src/crypto/x509/x509_test.go`の変更

`TestCreateSelfSignedCertificate`テスト関数内で、自己署名証明書を作成する際の`SerialNumber`が`big.NewInt(1)`から`big.NewInt(-1)`に変更されました。

```go
			// SerialNumber is negative to ensure that negative
			// values are parsed. This is due to the prevalence of
			// buggy code that produces certificates with negative
			// serial numbers.
			SerialNumber: big.NewInt(-1),
```

この変更は、負のシリアル番号を持つ証明書が正しくパースされることを確認するためのテストケースの追加です。コメントにも明記されている通り、これはバグのあるコードが負のシリアル番号を持つ証明書を生成する実情に対応するため、負の値がパース可能であることを保証するためのものです。このテストの追加により、将来的に同様のチェックが誤って再導入されることを防ぐ役割も果たします。
