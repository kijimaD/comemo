# [インデックス 21723] ファイルの概要

## コミット

このコミットは、Goツールチェインの `cmd/9a` (アセンブラ)、`cmd/9g` (コンパイラ)、`cmd/9l` (リンカ)、および `liblink` における `Prog` および `Addr` 型のポータビリティを向上させるための更新です。これは、Goツールチェインの内部表現をより汎用的で、将来の変更や異なるアーキテクチャへの対応を容易にするための重要なリファクタリングの一環です。

## 変更の背景

このコミットは、Goツールチェインの進化における重要な時期に行われました。Go 1.3では、ツールチェインをC言語からGo言語への移行を進め、リンカの責任の一部を `liblink` (後に `obj` に改名) という新しいライブラリに抽出するという大きな変更がありました。この変更により、コンパイラはより具体的な命令を出力するようになり、ビルドプロセス全体の高速化に貢献しました。

このコミットが行われた2015年1月は、Go 1.3のリリース後であり、Go 1.5でツールチェインが完全にGo言語化され、アーキテクチャ固有のコンパイラ (`6g`, `8g` など) やリンカ (`6l`, `8l` など) が単一の `compile` および `link` コマンドに統合される前の期間にあたります。

このような背景から、このコミットの目的は、Goツールチェインの内部表現である `Prog` (プログラム命令) と `Addr` (アドレス/オペランド) の型定義を、より汎用的でポータブルなものにリファクタリングすることにありました。これにより、将来的なツールチェインの統合、異なるアーキテクチャへの対応、および共有ライブラリのサポートなど、Go言語の進化に必要な基盤を強化することが目指されました。特に、プログラムカウンタ (PC) の値をモジュールのロードアドレスからの相対値として扱うことで、ポータビリティが向上し、メモリ内のモジュール配置に依存しない柔軟な設計が可能になります。

## 前提知識の解説

このコミットを理解するためには、以下の概念についての知識が役立ちます。

*   **Goツールチェイン**: Go言語のプログラムをビルドするためのツール群で、コンパイラ (`go tool compile`)、アセンブラ (`go tool asm`)、リンカ (`go tool link`) などが含まれます。歴史的には、`6g`/`8g`/`9g` (コンパイラ)、`6a`/`8a`/`9a` (アセンブラ)、`6l`/`8l`/`9l` (リンカ) のように、アーキテクチャごとに異なるツールが存在しました。このコミットで言及されている `9a`, `9g`, `9l` は、`amd64` アーキテクチャ向けのツールを指します。
*   **`Prog` (プログラム命令)**: Goツールチェインの内部表現において、個々の命令やプログラムの基本的な要素を表す構造体です。これは、コンパイラが生成し、リンカが最終的な機械語に変換する擬似命令のストリームと考えることができます。
*   **`Addr` (アドレス/オペランド)**: `Prog` 命令に関連付けられたオペランド（操作対象）を表す型です。メモリのアドレス、レジスタ、定数値、シンボル参照など、様々な種類の場所や値を指定できます。
*   **`cmd/internal/obj` パッケージ**: Goツールチェインの内部で使用される低レベルのオブジェクトファイル生成および操作のためのパッケージです。`Prog` や `Addr` の定義はここにあります。
*   **ポータビリティ**: ソフトウェアが異なる環境（オペレーティングシステム、アーキテクチャなど）で変更なしに、または最小限の変更で動作する能力を指します。この文脈では、プログラムのアドレス表現が、メモリ内のロード位置に依存しないようにすることを意味します。
*   **`NREG`**: 以前のGoツールチェインで、レジスタが指定されていないことを示すために使用されていた定数です。このコミットでは、より汎用的な `0` に置き換えられています。
*   **`D_CONST`, `D_REG`, `D_OREG` などの定数**: これらは、`Addr` 型が表すアドレスの種類（定数、レジスタ、オフセット付きレジスタなど）を示すために使用されていた列挙型またはマクロです。このコミットでは、より汎用的な `TYPE_CONST`, `TYPE_REG`, `TYPE_MEM` などに置き換えられています。これは、Goツールチェインの内部表現が、より抽象的で柔軟な設計に移行していることを示しています。

## 技術的詳細

このコミットの核心は、Goツールチェインの内部で命令 (`Prog`) とそのオペランド (`Addr`) を表現する方法の根本的な変更にあります。以前は、`Addr` 型の `type` フィールドが `D_CONST`, `D_REG`, `D_OREG` といった特定の定数を使用して、そのアドレスの種類を直接示していました。また、レジスタが指定されていないことを示すために `NREG` という定数が使用されていました。

この変更では、これらの特定の定数が、より汎用的な `TYPE_CONST`, `TYPE_REG`, `TYPE_MEM`, `TYPE_BRANCH`, `TYPE_SCONST` などに置き換えられています。これにより、`Addr` 型の `type` フィールドが、より抽象的な「型」を示すようになり、特定のアーキテクチャやレジスタセットに強く依存しない設計になっています。

具体的には、以下のような変更が行われています。

*   **`Addr` 型の `type` フィールドの抽象化**:
    *   `D_CONST` -> `TYPE_CONST`
    *   `D_REG` -> `TYPE_REG`
    *   `D_OREG` -> `TYPE_MEM` (メモリ参照)
    *   `D_BRANCH` -> `TYPE_BRANCH` (分岐先アドレス)
    *   `D_SPR`, `D_MSR`, `D_FPSCR`, `D_FREG`, `D_CREG` -> `TYPE_REG` (特殊レジスタ、浮動小数点レジスタ、条件レジスタも汎用レジスタ型として扱う)
    *   `D_SCONST` -> `TYPE_SCONST` (文字列定数)
    *   `D_AUTO`, `D_EXTERN`, `D_PARAM` -> `NAME_AUTO`, `NAME_EXTERN`, `NAME_PARAM` (シンボル名に関連する型)
*   **`NREG` の廃止と `0` への置き換え**: `outcode` 関数などの呼び出しにおいて、レジスタが指定されていないことを示す `NREG` が `0` に置き換えられています。これは、レジスタ番号が `0` から始まることを前提とした、より簡潔な表現への移行を示唆しています。
*   **レジスタ番号のオフセット**: `src/cmd/9a/lex.c` では、`R0` や `F0` などのレジスタ名が、`REG_R0` や `REG_F0` といったベース定数にオフセットを加える形で定義されています。これにより、レジスタの命名規則と内部表現がより一貫性を持つようになります。
*   **Yacc/Bison定義の更新**: `src/cmd/9a/a.y` および `src/cmd/9a/y.tab.c` では、`fpscrf` のような特定の浮動小数点ステータスレジスタの定義が削除され、より汎用的な `fpscr` に統合されています。また、`YYNTOKENS`, `YYNNTS`, `YYNRULES`, `YYNSTATES` といったYacc/Bisonの内部定数も、文法変更に伴い更新されています。

これらの変更は、Goツールチェインの内部表現を、特定のアーキテクチャのレジスタセットやアドレス指定モードから独立させ、より抽象的で汎用的なものにすることで、将来的な拡張性や異なるアーキテクチャへの対応を容易にすることを目的としています。これにより、Go言語のクロスコンパイル能力や、新しいハードウェアプラットフォームへの移植性が向上します。

## コアとなるコードの変更箇所

このコミットは、主に以下のファイル群に影響を与えています。

*   `src/cmd/9a/a.y`: アセンブラの文法定義ファイル。`Addr` 型のトークン定義や、命令の出力ロジック (`outcode`, `outgcode`) の引数が変更されています。
*   `src/cmd/9a/lex.c`: アセンブラの字句解析ファイル。レジスタ名や特殊レジスタ名に対応する内部定数 (`D_AUTO`, `D_EXTERN`, `D_LR` など) が、新しい汎用的な定数 (`NAME_AUTO`, `REG_LR` など) に置き換えられています。
*   `src/cmd/9a/y.tab.c`: `a.y` から生成されるYacc/Bisonのパーサーコード。文法変更に伴い、内部のテーブルが更新されています。
*   `src/cmd/9g/cgen.c`, `src/cmd/9g/galign.c`, `src/cmd/9g/ggen.c`, `src/cmd/9g/gobj.c`, `src/cmd/9g/gsubr.c`, `src/cmd/9g/peep.c`, `src/cmd/9g/prog.c`, `src/cmd/9g/reg.c`: コンパイラ (`9g`) のコード生成、アラインメント、オブジェクトファイル生成、サブルーチン処理、最適化、プログラム表現、レジスタ割り当てなどに関連するファイル。これらのファイルでは、`Prog` や `Addr` 型の操作、特に `type` フィールドやレジスタ番号の扱いが新しい定義に合わせて更新されています。
*   `src/liblink/9.out.h`, `src/liblink/asm9.c`, `src/liblink/list9.c`, `src/liblink/obj9.c`: リンカの共通ライブラリ (`liblink`) のファイル。オブジェクトファイルのフォーマット定義、アセンブリコード生成、リスト出力、オブジェクトファイル処理などに関連します。これらのファイルでも、`Prog` や `Addr` の内部表現の変更が反映されています。

変更の具体的な例としては、`src/cmd/9a/a.y` における `outcode` 関数の呼び出しで、`NREG` が `0` に置き換えられている箇所が多数見られます。また、`Addr` 構造体の `type` フィールドに代入される定数が、`D_CONST` から `TYPE_CONST` へ、`D_OREG` から `TYPE_MEM` へ、`D_BRANCH` から `TYPE_BRANCH` へと変更されています。

## コアとなるコードの解説

このコミットの主要な変更は、Goツールチェインの内部で命令のオペランド（`Addr` 型）の種類を識別するために使用される定数の体系的な置き換えです。

例えば、`src/cmd/9a/a.y` の以下の部分を見てみましょう。

```diff
--- a/src/cmd/9a/a.y
+++ b/src/cmd/9a/a.y
@@ -101,107 +101,103 @@ inst:
  */
 	LMOVW rreg ',' rreg
 	{
-		outcode($1, &$2, NREG, &$4);
+		outcode($1, &$2, 0, &$4);
 	}
```

ここでは、`outcode` 関数の第3引数 (`reg`) が `NREG` から `0` に変更されています。`NREG` は「レジスタなし」を意味する定数でしたが、この変更により、レジスタが指定されない場合は明示的に `0` を渡すようになりました。これは、レジスタ番号が `0` から始まるというGoツールチェインの内部規約に合わせた、より一貫性のある表現です。

また、`Addr` 型の `type` フィールドの変更は、`src/cmd/9a/a.y` の `rel` ルールや `rreg` ルールなどで顕著です。

```diff
--- a/src/cmd/9a/a.y
+++ b/src/cmd/9a/a.y
@@ -656,14 +652,14 @@ inst:
  */
 |	LRETRN	comma
 	{
-		outcode($1, &nullgen, NREG, &nullgen);
+		outcode($1, &nullgen, 0, &nullgen);
 	}
 
 rel:
 	con '(' LPC ')'
 	{
 		$$ = nullgen;
-		$$.type = D_BRANCH;
+		$$.type = TYPE_BRANCH;
 		$$.offset = $1 + pc;
 	}
```

ここでは、分岐アドレスのタイプを示す `D_BRANCH` が `TYPE_BRANCH` に変更されています。同様に、レジスタを示す `D_REG` は `TYPE_REG` に、メモリ参照を示す `D_OREG` は `TYPE_MEM` に、定数を示す `D_CONST` は `TYPE_CONST` に置き換えられています。

これらの変更は、Goツールチェインの内部で `Prog` と `Addr` がどのように解釈され、処理されるかという低レベルのメカニズムに影響を与えます。新しい型システムは、より抽象的で、特定のCPUアーキテクチャのレジスタやアドレッシングモードに直接マッピングされるのではなく、より汎用的な概念として扱われます。これにより、Goツールチェインは、異なるアーキテクチャや将来の命令セットの変更に対して、より柔軟に対応できるようになります。

`src/cmd/9a/lex.c` では、アセンブラが認識するレジスタ名や特殊なシンボルに対応する内部値が更新されています。例えば、`SP` (スタックポインタ) の型が `D_AUTO` から `NAME_AUTO` に変更されています。これは、アドレスの種類を示す定数と、シンボル名に関連する定数を区別し、より明確なセマンティクスを与えるための変更です。

これらの変更は、Goツールチェインの内部構造を整理し、より堅牢で保守しやすいコードベースを構築するための継続的な取り組みの一環です。
