# [インデックス 23384] ファイルの概要

このコミットは、Go言語の`fmt`パッケージにおけるメモリ割り当てテスト（`mallocTest`）が、Goの競合検出器（Race Detector）が有効な状態で実行された際に発生する問題を解決するためのものです。具体的には、競合検出器が有効な場合には、このメモリ割り当てテストをスキップするように変更が加えられています。これにより、テストの信頼性が向上し、競合検出器使用時の誤検出やテスト失敗を防ぎます。

## 変更の背景

Go言語の`fmt`パッケージには、特定の操作がどれくらいのメモリ割り当て（`malloc`）を行うかを計測する`TestCountMallocs`というテストが存在します。このテストは、`testing.AllocsPerRun`関数を使用して、関数の実行あたりの平均メモリ割り当て数を測定します。

しかし、Goの競合検出器（Race Detector）を有効にしてテストを実行すると、この`TestCountMallocs`が正しく機能しない、あるいは誤った結果を報告する問題が発生していました（`Fixes #10778`で示されている問題）。競合検出器は、データ競合を検出するためにプログラムのメモリアクセスを詳細に監視・計測します。この監視プロセス自体がメモリ割り当ての挙動に影響を与えたり、`testing.AllocsPerRun`の計測を妨げたりすることが考えられます。結果として、競合検出器が有効な環境では、メモリ割り当てテストが不安定になったり、誤った失敗を引き起こしたりする可能性がありました。

このコミットは、このような競合検出器とメモリ割り当てテストの間の非互換性を解消し、テストスイート全体の信頼性を高めることを目的としています。

## 前提知識の解説

### Go Race Detector (競合検出器)

Go Race Detectorは、Goプログラムにおけるデータ競合（data race）を検出するための強力なツールです。データ競合は、複数のゴルーチン（goroutine）が同時に同じメモリ位置にアクセスし、そのうち少なくとも1つが書き込み操作であり、かつそれらのアクセスが同期メカニズムによって適切に保護されていない場合に発生します。データ競合は、プログラムの予測不能な動作やクラッシュの原因となることがあり、デバッグが非常に困難です。

Go Race Detectorは、`go test -race`、`go run -race`、`go build -race`などのコマンドで`-race`フラグを付けて実行することで有効になります。有効にすると、実行時にメモリアクセスを監視し、データ競合の可能性を検出すると警告を出力します。この検出器は、プログラムの実行速度を低下させ、メモリ使用量を増加させるオーバーヘッドを伴います。

### `testing.AllocsPerRun`

`testing.AllocsPerRun`は、Goの`testing`パッケージに含まれる関数で、特定の関数が実行される際に発生する平均メモリ割り当て回数を計測するために使用されます。これは、特にパフォーマンスが重要なコードにおいて、メモリ割り当てを最小限に抑える（ゼロアロケーションを目指す）ための最適化作業で役立ちます。

この関数は、指定された回数だけ関数を実行し、その間に発生したメモリ割り当ての総数を計測し、平均値を返します。非常に正確な計測が求められるため、外部要因（例えば、競合検出器による追加の計測）が結果に影響を与えることは望ましくありません。

### Go Build Tags (ビルドタグ)

Goビルドタグは、Goソースファイルの先頭に記述される特別なコメントで、特定の条件に基づいてファイルのコンパイルを含めるか除外するかをGoツールチェインに指示します。これにより、異なる環境（OS、アーキテクチャ）やビルド設定（例: 競合検出器の有無）に応じて、異なるコードをコンパイルすることが可能になります。

構文は`// +build <expression>`（古い形式）または`//go:build <expression>`（Go 1.17以降の新しい形式）です。
*   `// +build race`: このタグを持つファイルは、`-race`フラグが指定された場合にのみコンパイルされます。
*   `// +build !race`: このタグを持つファイルは、`-race`フラグが指定されていない場合にのみコンパイルされます。

このメカニズムを利用することで、競合検出器が有効な場合とそうでない場合で、異なる定数や関数定義を提供できます。

## 技術的詳細

このコミットの技術的解決策は、Goビルドタグを利用して、競合検出器が有効かどうかを示す`raceenabled`というブール定数を導入することです。

1.  **`raceenabled`定数の導入**:
    *   `src/fmt/norace_test.go`という新しいファイルが作成され、`// +build !race`タグが付けられています。このファイルでは`const raceenabled = false`と定義されています。これは、競合検出器が有効でない場合にのみコンパイルされ、`raceenabled`が`false`となることを意味します。
    *   `src/fmt/race_test.go`という別の新しいファイルが作成され、`// +build race`タグが付けられています。このファイルでは`const raceenabled = true`と定義されています。これは、競合検出器が有効な場合にのみコンパイルされ、`raceenabled`が`true`となることを意味します。

2.  **`TestCountMallocs`での条件付きスキップ**:
    *   既存の`src/fmt/fmt_test.go`内の`TestCountMallocs`関数が変更され、`raceenabled`定数の値に基づいてテストをスキップする条件が追加されました。
    *   具体的には、`if raceenabled:`という条件が追加され、`raceenabled`が`true`（つまり競合検出器が有効）の場合には`t.Skip("skipping malloc count under race detector")`が呼び出され、テストがスキップされます。

このアプローチにより、競合検出器のオーバーヘッドや計測の干渉を気にすることなく、通常のテスト実行時にはメモリ割り当てテストが実行され、競合検出器を有効にしたテスト実行時には問題のあるテストが自動的にスキップされるようになります。

## コアとなるコードの解説

### `src/fmt/fmt_test.go` の変更

`TestCountMallocs`関数は、以前は`testing.Short()`と`runtime.GOMAXPROCS(0) > 1`の2つの条件でスキップされていました。このコミットでは、`switch`文を使用してこれらの条件を整理し、新たに`raceenabled`という条件を追加しています。

*   `case raceenabled:`: この行が追加された最も重要な変更点です。もし`raceenabled`定数が`true`であれば、`t.Skip("skipping malloc count under race detector")`が実行され、このテストは競合検出器が有効な環境では実行されなくなります。これにより、競合検出器の計測がメモリ割り当てテストに与える悪影響を回避します。

### `src/fmt/norace_test.go` と `src/fmt/race_test.go` の新規追加

これらのファイルは、Goビルドタグの仕組みを利用して、`raceenabled`定数を条件付きで定義するために導入されました。

*   **`src/fmt/norace_test.go`**:
    *   `// +build !race`: このビルドタグは、`go test`コマンドに`-race`フラグが指定されていない場合にのみ、このファイルをコンパイルするようにGoツールチェインに指示します。
    *   `const raceenabled = false`: したがって、競合検出器が有効でない通常のテスト実行時には、`raceenabled`は`false`として定義されます。

*   **`src/fmt/race_test.go`**:
    *   `// +build race`: このビルドタグは、`go test`コマンドに`-race`フラグが指定されている場合にのみ、このファイルをコンパイルするようにGoツールチェインに指示します。
    *   `const raceenabled = true`: したがって、競合検出器が有効なテスト実行時には、`raceenabled`は`true`として定義されます。

Goのビルドシステムは、ビルドタグに基づいて適切なファイルを選択的にコンパイルするため、常に`raceenabled`という定数が存在し、その値は競合検出器の有効/無効状態を正確に反映します。これにより、`TestCountMallocs`は競合検出器の有無に応じて適切に動作を調整できるようになります。
