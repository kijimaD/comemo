# [インデックス 21615] ファイルの概要

このコミットは、Goランタイムのメモリ管理とガベージコレクション（GC）のトリガーロジックに関連する変更です。具体的には、`src/runtime/malloc.go` ファイルが変更されています。このファイルは、Goプログラムのヒープメモリ割り当てと、ガベージコレクタの動作を制御する重要な部分を担っています。`malloc.go` 内の `shouldtriggergc()` 関数は、Goランタイムがいつ並行GCサイクルを開始すべきかを決定するためのヒューリスティックを実装しています。

## 元コミット内容

このコミットは、コミット `44529d939192c3034a04e2eff865d04ee51ae532` を元に戻す（revert）ものです。元に戻されたコミットのタイトルは「runtime: fix trigger for concurrent GC」であり、並行ガベージコレクションのトリガーメカニズムを修正することを目的としていました。この「修正」は、`triggerratio` という変数を導入し、GCトリガーの条件を `memstats.heap_alloc+memstats.heap_alloc/triggerratio >= memstats.next_gc` に変更することで、GCが開始されるタイミングを調整しようとしたものと推測されます。

## 変更の背景

このコミットが元のコミットをrevertしているという事実は、元の「修正」が意図しない問題を引き起こしたことを強く示唆しています。並行GCのトリガーロジックは、Goアプリケーションのパフォーマンスに直接影響を与える非常にデリケートな部分です。GCのトリガーが早すぎると、不必要なGCサイクルが頻繁に実行され、アプリケーションのスループットが低下する可能性があります。逆に、トリガーが遅すぎると、ヒープサイズが過度に大きくなり、GCの停止時間が長くなったり、メモリ使用量が増加したりする可能性があります。

元のコミットが導入した変更は、おそらくこれらのバランスを崩し、特定のワークロードやシナリオでパフォーマンスの回帰やメモリ使用量の問題を引き起こしたため、元の状態に戻すことが決定されたと考えられます。Goランタイムの開発では、このようなパフォーマンスの回帰は非常に厳しく評価され、問題が確認された場合は迅速にrevertされることが一般的です。

## 前提知識の解説

### Goのガベージコレクション (GC)

Goは、自動メモリ管理のためにトレース型ガベージコレクタを使用しています。Go 1.5以降、GoのGCは「並行（concurrent）」かつ「非世代別（non-generational）」のマーク＆スイープGCを採用しています。

*   **並行GC**: GCの大部分のフェーズ（マークフェーズの一部など）が、Goアプリケーションの通常の実行（ミューテータの実行）と並行して行われます。これにより、アプリケーションの停止時間（STW: Stop-The-World）を最小限に抑えることを目指しています。
*   **マーク＆スイープ**:
    *   **マークフェーズ**: GCは、到達可能なオブジェクト（プログラムがまだ参照しているオブジェクト）を特定し、マークします。
    *   **スイープフェーズ**: マークされなかったオブジェクト（到達不能なオブジェクト、つまり不要になったメモリ）を解放し、再利用可能な状態にします。

### GCトリガーのヒューリスティック

GoのGCは、ヒープの使用量に基づいてGCサイクルを開始するかどうかを決定するヒューリスティックを使用しています。これは、GCがいつ実行されるべきかを判断するための「経験則」です。

*   `memstats.heap_alloc`: 現在ヒープに割り当てられているメモリの総量（バイト単位）。これは、Goプログラムが現在使用しているメモリの量を示します。
*   `memstats.next_gc`: 次のGCサイクルがトリガーされるべきヒープ割り当ての目標値。この値は、前回のGCサイクルで解放されたメモリ量に基づいて動的に調整されます。GoのGCは、前回のGCで解放されたメモリの約2倍のメモリが割り当てられたときに次のGCを開始するように設計されています（これはあくまで一般的な目標であり、実際のヒューリスティックはより複雑です）。

GCトリガーの基本的な考え方は、「現在のヒープ割り当て量がある閾値を超えたらGCを開始する」というものです。この閾値は `memstats.next_gc` によって表されます。

### `atomicloaduint(&bggc.working)`

これは、並行GCが現在アクティブに動作しているかどうかを示すフラグをアトミックに読み取るものです。GCが既に動作している場合、新たなGCサイクルをトリガーする必要はありません。アトミック操作は、複数のゴルーチンが同時にこのフラグにアクセスしても、データの整合性が保たれるようにするために使用されます。

## 技術的詳細

このコミットの核心は、`src/runtime/malloc.go` 内の `shouldtriggergc()` 関数の変更です。この関数は、Goランタイムが新しい並行GCサイクルを開始すべきかどうかを決定します。

元のコミット（revertされたもの）は、GCトリガーの条件に `triggerratio` という新しい変数（デフォルト値は8）を導入しました。これにより、GCトリガーの条件は以下のようになりました。

`memstats.heap_alloc + memstats.heap_alloc / triggerratio >= memstats.next_gc`

この式は、`memstats.heap_alloc` に `memstats.heap_alloc / 8` を加えた値が `memstats.next_gc` を超えた場合にGCをトリガーするという意味です。これは、GCがより早くトリガーされる可能性を示唆しています。コメントには「1/triggerratio memory is available to allocate」とあり、これは「`triggerratio` 分の1のメモリが割り当て可能になったらGCをトリガーする」という意図を示しています。つまり、ヒープが `next_gc` に達する前に、より積極的にGCをトリガーしようとしたと考えられます。

しかし、このrevertコミットにより、GCトリガーの条件は元の状態に戻されました。元の条件は以下の通りです。

`memstats.heap_alloc + memstats.heap_alloc * 3 / 4 >= memstats.next_gc`

この式は、`memstats.heap_alloc` に `memstats.heap_alloc` の75%（3/4）を加えた値が `memstats.next_gc` を超えた場合にGCをトリガーするという意味です。これは、前回のGCサイクルによって利用可能になったスペースの約半分が使用されたときに、新しい並行GCを開始するというヒューリスティックを反映しています。

この変更は、GCのトリガータイミングをより保守的な、実績のあるヒューリスティックに戻すことを目的としています。`triggerratio` を使用したアプローチが、おそらく過剰なGCトリガーや、GCの効率低下といった問題を引き起こしたため、元の安定した動作に戻すことが優先されたと考えられます。

        *   この行は、revert後の新しい（元の）GCトリガー条件です。`memstats.heap_alloc` に `memstats.heap_alloc` の3/4（75%）を加算しています。
        *   `atomicloaduint(&bggc.working) == 0` の部分は変更されていません。これは、GCが現在動作中でないことを確認する条件であり、GCトリガーの基本的なロジックの一部です。

3.  **コメントの変更**:
    *   `// triggers the concurrent GC when 1/triggerratio memory is available to allocate.` などのコメントが削除され、代わりに以下のコメントが追加されています。
    *   `// Currently the primitive heuristic we use will start a new`
    *   `// concurrent GC when approximately half the available space`
    *   `// made available by the last GC cycle has been used.`
        *   この新しいコメントは、GCトリガーのヒューリスティックが、前回のGCサイクルで利用可能になったスペースの約半分が使用されたときに新しい並行GCを開始するという、より一般的な説明に戻ったことを示しています。これは、`memstats.heap_alloc * 3 / 4` という条件が、この「約半分」という目標を達成するための近似値であることを示唆しています。

この変更は、GCトリガーのロジックを、よりシンプルで実績のあるヒューリスティックに戻すことで、GCの安定性と予測可能性を向上させることを目的としています。
