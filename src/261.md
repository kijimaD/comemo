## 変更の背景

Go言語の初期バージョンでは、マップの初期化に関するセマンティクスがまだ完全に確立されていなかったか、あるいはユーザーが誤解しやすい挙動が存在していました。特に、`new`キーワードは型Tのゼロ値を指すポインタを返しますが、マップの場合、これは`nil`マップへのポインタを意味します。`nil`マップは読み取りは可能ですが、要素の追加や変更はランタイムパニックを引き起こします。

このコミットは、このような誤ったマップの使用パターン（`new(map[K]V)`でマップを作成し、すぐに要素にアクセスしようとする）が実際にクラッシュを引き起こすことを確認し、その挙動をテストスイートに組み込むことを目的としています。これにより、将来的にこの挙動が変更された場合や、コンパイラがより親切なエラーを出すようになった場合に、その変化を検出できるようになります。

## 前提知識の解説

### Go言語における`new`と`make`

Go言語には、メモリを割り当てて値を初期化するための2つの組み込み関数`new`と`make`があります。

*   **`new(T)`**:
    *   型`T`のゼロ値を格納するのに十分なメモリを割り当てます。
    *   割り当てられたメモリを指す`*T`型のポインタを返します。
    *   すべての型に対して機能します。
    *   例: `new(int)`は`*int`を返し、その値は`0`に初期化されます。`new(struct{})`は`*struct{}`を返します。
    *   マップの場合、`new(map[K]V)`は`*map[K]V`を返しますが、その`map[K]V`の値は`nil`です。つまり、`nil`マップへのポインタが返されます。

*   **`make(T, args)`**:
    *   スライス、マップ、チャネルの3つの組み込み参照型のみに使用されます。
    *   これらの型を初期化し、使用可能な状態にします。
    *   `new`とは異なり、ポインタではなく、初期化された型`T`の値を返します。
    *   例:
        *   `make([]int, 10, 20)`: 長さ10、容量20の`[]int`スライスを作成します。
        *   `make(map[string]int)`: 空の`map[string]int`を作成します。
        *   `make(chan int, 5)`: バッファサイズ5の`chan int`を作成します。

### `nil`マップの挙動

Goにおいて、マップのゼロ値は`nil`です。`nil`マップは以下の特性を持ちます。

*   要素の読み取りは可能で、存在しないキーに対しては値型のゼロ値を返します。
*   要素の追加や削除はできません。試みるとランタイムパニック（panic）が発生します。
*   `len(nilMap)`は0を返します。
*   `range nilMap`は何もイテレートしません。

このコミットの時点では、`new(map[int]int)`が`nil`マップへのポインタを返すため、そのポインタを介してマップ要素にアクセスしようとするとパニックが発生します。

## 技術的詳細

`test/bugs/bug060.go`のコードは、Go言語の初期のランタイムにおけるマップの挙動の特定の側面をテストしています。

1.  `m := new(map[int]int);`
    *   ここで`new`関数が使用されています。`new(map[int]int)`は`*map[int]int`型の値を返します。このポインタが指す`map[int]int`の値は`nil`です。つまり、`m`は`nil`マップへのポインタとなります。

2.  `m[0] = 0;`
    *   この行が問題の核心です。`m`は`*map[int]int`型であり、`m[0]`のように直接要素にアクセスしようとすると、Goのコンパイラは自動的にポインタをデリファレンスして`(*m)[0]`として扱います。
    *   しかし、`*m`は`nil`マップであるため、`nil`マップに対して要素の代入（書き込み）を行おうとすると、ランタイムパニックが発生します。これはGoの仕様であり、`nil`マップは書き込み操作をサポートしていません。

3.  `m[0]++;`
    *   この行も同様にパニックを引き起こします。`m[0]`の値を読み取ってインクリメントし、再度`m[0]`に代入しようとしますが、`nil`マップへの書き込み操作であるためパニックとなります。

4.  `if m[0] != 1 { ... }`
    *   この`if`文は、上記の行でパニックが発生するため、通常は実行されません。もしパニックが発生しなかった場合（例えば、将来的にGoのランタイムが`new(map)`の挙動を変更した場合）、この条件が評価され、マップのインクリメントが正しく行われたかを検証します。

`test/golden.out`に`BUG: crashes`と記述されていることから、このテストケースは意図的にクラッシュを引き起こすことを期待されており、そのクラッシュがGoのランタイムの正しい（当時の）挙動であることを確認するためのものです。

## コアとなるコードの解説

### `test/bugs/bug060.go`

このファイルは、Go言語のマップの初期化と使用に関する一般的な誤解を浮き彫りにする目的で作成されました。

```go
package main

import "sys" // 2008年当時のGoではsysパッケージが存在した

func main() {
	m := new(map[int]int); // ここでmはnilマップへのポインタとなる
	m[0] = 0;             // nilマップへの書き込み操作 -> ランタイムパニック
	m[0]++;               // 同上
	if m[0] != 1 {
		print "map does not increment";
		sys.exit(1)
	}
}
```

このテストの意図は、`new(map[int]int)`が`nil`マップを生成し、その`nil`マップに対して要素の代入（`m[0] = 0`や`m[0]++`）を行うと、ランタイムパニックが発生するという当時のGoの仕様を検証することです。もしこのテストがパニックせずに正常終了した場合、それはGoのマップの挙動が変更されたことを意味し、開発者はその変更を認識し、必要に応じて対応を検討することになります。
