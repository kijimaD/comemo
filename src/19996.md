## 変更の背景

このコミットは、Goの32ビットx86アーキテクチャ向けコンパイラである`cmd/8g`におけるビルドの問題を修正することを目的としています。具体的には、コンパイラのコード生成フェーズで、バイトレジスタの型チェックに関する誤ったロジックが存在し、これがビルドエラーや不適切なコード生成を引き起こしていたと考えられます。

コミットメッセージには「Fixes #8510」とありますが、現在の公開されているGoのIssueトラッカーにおける#8510は、`init`関数の実行に関する別の問題を示しています。これは、コミットが作成された2014年当時と現在でIssue番号の参照が異なるか、あるいは内部的なIssueトラッカーの番号を参照している可能性が高いです。したがって、このコミットの主要な目的は、`src/cmd/8g/peep.c`内のバイトレジスタに関する型チェックの不整合を解消することにあります。

## 前提知識の解説

### Goコンパイラ `cmd/8g`

`cmd/8g`は、Go言語の初期のツールチェインにおいて、32ビットx86アーキテクチャ（Intel/AMDプロセッサの32ビットモード）をターゲットとするコンパイラでした。Goのコンパイラは、ターゲットアーキテクチャごとに異なる名前が付けられており、例えば`6g`はamd64（64ビットx86）、`5g`はARMを指していました。これらのコンパイラは、Goのソースコード（`.go`ファイル）を読み込み、オブジェクトファイル（`.8`ファイルなど）を生成する役割を担っていました。

現代のGoツールチェインでは、これらの特定のコンパイラ名（`8g`など）を直接意識することはほとんどありません。代わりに、`go tool compile`コマンドが使用され、`GOOS`（オペレーティングシステム）と`GOARCH`（アーキテクチャ）環境変数によってターゲットが決定されます。`cmd/8g`は、Goコンパイラの進化の歴史における重要な一部であり、特に32ビットシステム向けの最適化やコード生成の課題に取り組んでいました。

`peep.c`ファイルは、コンパイラのバックエンド、特にコード生成の最終段階やpeephole最適化（局所的なコードパターンをより効率的なものに置き換える最適化）を担当する部分に関連しています。

### レジスタの種類 (D_AL, D_R15B, D_BL)

x86アーキテクチャでは、CPUがデータを一時的に保持するために使用するレジスタが多数存在します。これらのレジスタは、そのサイズ（ビット幅）によって異なる名前を持ちます。Goコンパイラの内部では、これらのレジスタを抽象化した定数や型が定義されています。

*   **`D_AL`**: `AL`レジスタを指します。`AL`は、汎用レジスタ`AX`の下位8ビット（バイト）部分です。
*   **`D_BL`**: `BL`レジスタを指します。`BL`は、汎用レジスタ`BX`の下位8ビット（バイト）部分です。
*   **`D_R15B`**: `R15`レジスタの下位8ビット（バイト）部分を指します。`R15`は、x86-64アーキテクチャ（64ビット拡張）で導入された汎用レジスタの一つです。32ビットx86アーキテクチャには存在しないレジスタです。

このコミットの変更点では、これらのレジスタ型を表す定数を使用して、あるレジスタがバイトレジスタの範囲内にあるかどうかをチェックしています。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/8g/peep.c`ファイル内の`copyas`関数におけるバイトレジスタの型チェックの修正です。

`copyas`関数は、Goコンパイラのコード生成フェーズで、アセンブリ命令のオペランド（アドレスやレジスタなど）を処理する際に使用されると考えられます。この関数は、引数として渡された`Adr`（アドレス記述子）構造体が、特定の種類のレジスタ、特にバイトレジスタであるかどうかを検証するロジックを含んでいます。

元のコードでは、バイトレジスタの範囲を`D_AL`から`D_R15B`までと定義していました。
`if(D_AL <= a->type && a->type <= D_R15B)`

しかし、`cmd/8g`は32ビットx86アーキテクチャ向けのコンパイラです。`D_R15B`は、64ビットx86アーキテクチャで導入された`R15`レジスタのバイト部分を指すため、32ビット環境ではこのレジスタは存在しないか、あるいは異なる意味を持つことになります。この不整合が、コンパイラのビルドプロセス中に問題を引き起こしていた可能性が高いです。例えば、存在しないレジスタタイプを参照しようとしたり、誤ったレジスタタイプをバイトレジスタとして認識してしまったりするなどの問題が考えられます。

修正後のコードでは、バイトレジスタの範囲を`D_AL`から`D_BL`までに限定しています。
`if(D_AL <= a->type && a->type <= D_BL)`

これにより、チェックの対象が32ビットx86アーキテクチャで一般的に使用されるバイトレジスタ（AL, CL, DL, BLなど）の範囲に適切に絞り込まれました。この修正によって、コンパイラは正しいレジスタタイプのみを検証するようになり、ビルドエラーが解消され、より正確なアセンブリコードの生成が可能になったと考えられます。

`fatal("use of byte register");`というエラーメッセージは、このチェックが、特定の文脈でバイトレジスタが不適切に使用された場合に、コンパイラが処理を中断するためのガードとして機能していることを示唆しています。

## コアとなるコードの解説

変更は、`src/cmd/8g/peep.c`ファイル内の`copyas`関数にあります。この関数は、`Adr`型のポインタ`a`と`v`を引数として受け取ります。`Adr`は、Goコンパイラ内部でアセンブリ命令のオペランド（レジスタ、メモリ位置、定数など）を表現するために使用される構造体です。

`copyas`関数内では、`a`と`v`の`type`フィールド（オペランドの型を示す）がバイトレジスタの範囲内にあるかどうかをチェックしています。

**変更前:**

```c
if(D_AL <= a->type && a->type <= D_R15B)
 fatal("use of byte register");
if(D_AL <= v->type && v->type <= D_R15B)
 fatal("use of byte register");
```

この条件式は、`a->type`または`v->type`が`D_AL`（ALレジスタ）から`D_R15B`（R15レジスタの下位8ビット）までの範囲にある場合に、`fatal("use of byte register");`というエラーを発生させます。前述の通り、`D_R15B`は64ビットx86アーキテクチャのレジスタであり、32ビットx86アーキテクチャ向けの`cmd/8g`コンパイラでは不適切な参照でした。この誤った範囲指定が、コンパイラのビルドエラーの原因となっていました。

**変更後:**

```c
if(D_AL <= a->type && a->type <= D_BL)
 fatal("use of byte register");
if(D_AL <= v->type && v->type <= D_BL)
 fatal("use of byte register");
```

修正後の条件式では、バイトレジスタの範囲を`D_AL`から`D_BL`までに限定しています。`D_AL`と`D_BL`はどちらも32ビットx86アーキテクチャで一般的な8ビットレジスタ（AL, CL, DL, BLなど）の範囲に含まれます。この変更により、`cmd/8g`コンパイラは、32ビット環境で実際に存在するバイトレジスタのみを対象に型チェックを行うようになり、ビルドの問題が解決されました。

この修正は、コンパイラが生成するアセンブリコードの正確性を保証し、特定のアーキテクチャにおけるレジスタの特性に関する誤った仮定を排除するために不可欠です。
