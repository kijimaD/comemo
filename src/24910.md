# [インデックス 24910] ファイルの概要

このコミットは、Goコンパイラのディストリビューションツール (`cmd/dist`) とリンカー (`cmd/link`) における変更を導入しています。具体的には、ARMアーキテクチャ上で共有ライブラリ（`c-shared`）をビルドする際に、外部リンキングを強制するように修正し、`cmd/dist`のテストスイートに`linux-arm`プラットフォームでの`c-shared`ビルドモードのサポートを追加しています。これにより、ARM環境でのGoの共有ライブラリの生成と利用が改善されます。

## 変更の背景

この変更の背景には、GoプログラムをC言語のライブラリとしてビルドする際のリンキングの問題、特にARMアーキテクチャにおける共有ライブラリのサポートの不完全さがありました。Goは、`c-archive`（静的ライブラリ）や`c-shared`（共有ライブラリ）といったビルドモードを提供しており、これによりGoのコードを他の言語（C/C++など）から呼び出すことが可能になります。

しかし、Goのリンカーは内部リンキング（Go独自のリンカーが全てを処理する）と外部リンキング（システムのリンカーを使用する）の2つのモードを持っています。特定のプラットフォームやビルドモード、特に共有ライブラリを生成する際には、システムのリンカーが提供する機能（例えば、ダイナミックリンキングの解決）が必要となる場合があります。

Go issue #12425（"cmd/link: c-shared on linux/arm fails"）によると、`linux-arm`環境で`c-shared`ビルドモードを使用するとリンキングエラーが発生していました。これは、Goの内部リンカーがARM上で共有ライブラリを正しく処理できないことが原因でした。このコミットは、この問題を解決するために、ARMアーキテクチャで`c-archive`または`c-shared`ビルドモードを使用する場合、あるいはGoコードが動的にリンクされる場合に、明示的に外部リンキングを強制するように変更を加えています。これにより、システムのリンカーがこれらの複雑なリンキングタスクを処理できるようになり、ARM上での共有ライブラリの生成が成功するようになります。

また、`cmd/dist`の変更は、この新しい機能が`linux-arm`プラットフォームで正しくテストされることを保証するためのものです。

## 前提知識の解説

1.  **Goのビルドモード (`-buildmode`)**:
    *   Goコンパイラは、`go build -buildmode=<mode>`オプションを通じて様々なビルドモードをサポートしています。
    *   **`c-archive`**: GoパッケージをCアーカイブ（静的ライブラリ、例: `.a`ファイル）としてビルドします。他のC/C++プログラムにリンクしてGoの関数を呼び出すことができます。
    *   **`c-shared`**: GoパッケージをC共有ライブラリ（動的ライブラリ、例: `.so`ファイルや`.dylib`ファイル）としてビルドします。これは、実行時に他のプログラムからロードされ、Goの関数を呼び出すことができます。
    *   **`exe`**: 実行可能ファイルをビルドします（デフォルト）。
    *   **`pie`**: Position-Independent Executable (PIE) をビルドします。
    *   **`shared`**: 複数のGoプログラムで共有されるGo共有ライブラリをビルドします。

2.  **リンキング (Linking)**:
    *   コンパイルされたオブジェクトファイル（`.o`）を結合して、実行可能ファイルやライブラリを作成するプロセスです。
    *   **静的リンキング**: 必要なライブラリコードが実行可能ファイルに直接コピーされます。
    *   **動的リンキング**: ライブラリコードは実行可能ファイルには含まれず、実行時にロードされます。これにより、ディスクスペースの節約やライブラリの更新が容易になります。

3.  **Goのリンカー (`cmd/link`)**:
    *   Goツールチェーンの一部であり、Goのオブジェクトファイルをリンクして実行可能ファイルやライブラリを生成します。
    *   **内部リンキング (`ld.LinkInternal`)**: Go独自のリンカーが全てのリンキング処理を行います。これはクロスコンパイルのシナリオで特に有用です。
    *   **外部リンキング (`ld.LinkExternal`)**: Goのリンカーはオブジェクトファイルを生成するだけで、最終的なリンキングはシステムのリンカー（例: `gcc`や`clang`）に委ねられます。これは、CGOを使用する場合や、特定のプラットフォーム固有のリンキング要件がある場合に必要となります。

4.  **ARMアーキテクチャ**:
    *   Advanced RISC Machineの略で、モバイルデバイスや組み込みシステムで広く使用されているCPUアーキテクチャです。Goは様々なARMベースのシステムをサポートしています。

5.  **`cmd/dist`**:
    *   Goのディストリビューションツールであり、Goのビルドシステムの一部です。GoのソースコードからGoツールチェーン自体をビルドしたり、テストを実行したりする際に使用されます。`test.go`ファイルは、Goの様々なビルドモードやプラットフォームの組み合わせに対するテストのサポート状況を定義しています。

## 技術的詳細

このコミットは、Goのリンキングプロセスにおける特定の課題、特にARMアーキテクチャでの共有ライブラリの生成に関する問題を解決します。

Goのリンカーは、デフォルトでは内部リンキングを試みます。これは、Goが自己完結型のツールチェーンを目指しているためです。しかし、`c-archive`や`c-shared`のようなビルドモードでは、GoのコードがCのABI（Application Binary Interface）に準拠し、Cのツールチェーンと連携する必要があります。特に共有ライブラリの場合、動的なシンボル解決や位置独立コード（PIC）の生成など、システムのリンカーが持つ高度な機能が必要となることがあります。

ARMアーキテクチャでは、これらの要件がGoの内部リンカーにとって特に複雑であったと考えられます。Go issue #12425で報告されたエラーは、内部リンカーがARM上で共有ライブラリを生成する際に必要な特定のリンキングディレクティブやシンボル解決メカニズムを適切に処理できなかったことを示唆しています。

このコミットでは、`src/cmd/link/internal/arm/obj.go`内の`archinit`関数にロジックを追加することで、この問題を解決しています。`archinit`は、リンカーが特定のアーキテクチャ（この場合はARM）の初期化を行う際に呼び出される関数です。ここで、ビルドモードが`c-archive`または`c-shared`である場合、あるいは`ld.DynlinkingGo()`が真（Goコードが動的にリンクされる必要がある場合）である場合に、`ld.Linkmode`を`ld.LinkExternal`に明示的に設定しています。これにより、Goのリンカーはオブジェクトファイルを生成する役割に徹し、最終的な共有ライブラリの生成はシステムのリンカー（通常は`gcc`）に委ねられることになります。システムのリンカーは、ARMアーキテクチャにおける共有ライブラリの生成に関する全ての複雑な要件を処理する能力を持っています。

また、`src/cmd/dist/test.go`の変更は、`c-shared`ビルドモードが`linux-arm`プラットフォームでサポートされるようになったことを反映しています。これにより、Goのテストスイートが`linux-arm`環境での`c-shared`ライブラリのビルドと実行を検証するようになり、回帰テストが強化されます。

## コアとなるコードの解説

1.  **`src/cmd/dist/test.go` の変更**:
    `supportedBuildmode`関数は、Goのテストスイートが特定のビルドモードを特定のプラットフォームで実行すべきかどうかを判断するために使用されます。以前は、`c-shared`ビルドモードは`linux-amd64`, `darwin-amd64`, `android-arm`でのみサポートされていると認識されていました。このコミットにより、`"linux-arm"`がこのリストに追加され、`linux-arm`環境でも`c-shared`ライブラリのビルドとテストが実行されるようになります。これは、Goの共有ライブラリ機能がARM Linuxプラットフォームで正式にサポートされ、テストカバレッジが拡大されたことを意味します。

2.  **`src/cmd/link/internal/arm/obj.go` の変更**:
    `archinit`関数は、リンカーがターゲットアーキテクチャ（この場合はARM）に特化した初期設定を行う場所です。
    追加された以下のコードブロックがこのコミットの核心です。
    ```go
    if ld.Buildmode == ld.BuildmodeCArchive || ld.Buildmode == ld.BuildmodeCShared || ld.DynlinkingGo() {
    	ld.Linkmode = ld.LinkExternal
    }
    ```
    *   `ld.Buildmode == ld.BuildmodeCArchive`: GoコードをC静的ライブラリとしてビルドする場合。
    *   `ld.Buildmode == ld.BuildmodeCShared`: GoコードをC共有ライブラリとしてビルドする場合。
    *   `ld.DynlinkingGo()`: Goのランタイムや他のGoパッケージが動的にリンクされる必要がある場合。

    これらの条件のいずれかが真である場合、`ld.Linkmode`が`ld.LinkExternal`に設定されます。これは、Goのリンカーがオブジェクトファイルを生成した後、最終的なリンキングステップをシステムの外部リンカー（例: `ld`や`gcc`）に委ねることを意味します。ARMアーキテクチャでは、特に共有ライブラリの生成において、位置独立コード（PIC）の生成や、特定のセクション配置、動的シンボル解決など、システムのリンカーが持つ専門的な知識と機能が必要不可欠です。この変更により、Goのリンカーはこれらの複雑なタスクをシステムのリンカーにオフロードし、ARM上での`c-archive`および`c-shared`ビルドモードの信頼性と互換性を大幅に向上させます。
