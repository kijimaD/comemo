# [インデックス 23528] ファイルの概要

このコミットは、Go言語のビルドシステムにおいて、アーキテクチャ固有のコンパイラ（例: `5g`, `6g`, `8g`）およびリンカ（例: `5l`, `6l`, `8l`）の使用を廃止し、新たに導入された汎用的な `go tool compile` および `go tool link` コマンドに切り替える変更を導入しています。これにより、ビルドプロセスの統一化と効率化が図られています。

## 元コミット内容

このコミットは、Go言語のビルドシステム全体で、従来のアーキテクチャ固有のコンパイラ（`5g`, `6g`, `7g`, `8g`, `9g`）およびリンカ（`5l`, `6l`, `7l`, `8l`, `9l`）の使用を、新しく導入された汎用的な `go tool compile` および `go tool link` コマンドに置き換えるものです。この変更は、Go 1.5リリースにおけるツールチェインのGo言語自身による再実装の一環として行われました。主要な動機ではありませんでしたが、この変換により `make.bash` の実行時間が約10%短縮されるという副次的な効果ももたらされました。

## 変更の背景

Go言語の初期のバージョンでは、異なるCPUアーキテクチャ（例: x86-32, x86-64, ARM）ごとに個別のコンパイラとリンカが提供されていました。これらはそれぞれ `5g`/`5l` (ARM), `6g`/`6l` (x86-64), `8g`/`8l` (x86-32) といった命名規則を持っていました。このアプローチは、異なるアーキテクチャへの対応を明確にする一方で、ツールチェインの管理と拡張を複雑にする側面がありました。

Go 1.5の開発において、Goチームはツールチェイン全体をGo言語自身で書き直すという大きな目標を掲げました。この「セルフホスト」化は、ツールチェインの保守性、移植性、そして将来的な機能拡張の容易さを向上させることを目的としていました。この再実装の一環として、アーキテクチャ固有のツールを廃止し、単一の汎用的な `go tool compile` と `go tool link` コマンドに統合する決定がなされました。これにより、`GOOS` (オペレーティングシステム) と `GOARCH` (アーキテクチャ) 環境変数に基づいて、適切なバックエンドが自動的に選択されるようになり、ユーザーやビルドスクリプトからはアーキテクチャの違いが抽象化されます。

このコミットは、その移行プロセスの最終段階の一つであり、Goのビルドシステム自体が新しい汎用ツールを使用するように更新するものです。

## 前提知識の解説

*   **Goツールチェイン**: Go言語のプログラムを開発、ビルド、実行するために必要な一連のツール群（コンパイラ、リンカ、アセンブラ、デバッガなど）を指します。
*   **`go tool` コマンド**: `go` コマンドの一部で、Goツールチェインに含まれる低レベルなツール（コンパイラ、リンカ、アセンブラなど）を直接呼び出すためのインターフェースです。例えば、`go tool compile` はコンパイラを、`go tool link` はリンカを呼び出します。
*   **`5g`, `6g`, `8g` (旧コンパイラ)**: Go 1.4以前のバージョンで使われていた、アーキテクチャ固有のコンパイラです。
    *   `5g`: ARMアーキテクチャ用
    *   `6g`: x86-64 (amd64) アーキテクチャ用
    *   `8g`: x86-32 (386) アーキテクチャ用
    *   同様に、`5l`, `6l`, `8l` はそれぞれのアーキテクチャに対応するリンカでした。
*   **`GOOS` と `GOARCH`**: Goのクロスコンパイルを制御するための環境変数です。
    *   `GOOS`: ターゲットのオペレーティングシステム (例: `linux`, `windows`, `darwin`)
    *   `GOARCH`: ターゲットのCPUアーキテクチャ (例: `amd64`, `arm`, `arm64`)
    これらの変数を設定することで、異なるOSやアーキテクチャ向けのバイナリを生成できます。
*   **`make.bash`**: Goプロジェクトのルートディレクトリにあるシェルスクリプトで、Goツールチェイン全体をソースからビルドするために使用されます。

## 技術的詳細

このコミットの核心は、Goのビルドスクリプトやテストスクリプト内で、ハードコードされていたアーキテクチャ固有のコンパイラ/リンカの呼び出しを、汎用的な `go tool compile` および `go tool link` に置き換えることです。

具体的には、以下の変更が行われています。

1.  **`src/cmd/dist/build.go`**:
    *   `install` 関数内で、リンカの呼び出しが `fmt.Sprintf("%s/%sl", tooldir, gochar)` から `pathf("%s/link", tooldir)` へ変更されています。`gochar` はアーキテクチャを示す文字（例: `6` for amd64）でした。
    *   コンパイラの呼び出しも同様に `pathf("%s/%sg", tooldir, gochar)` から `pathf("%s/compile", tooldir)` へ変更されています。
    *   `cleantab` 変数から、旧来のアーキテクチャ固有のコンパイラ/リンカ (`cmd/5g`, `cmd/5l` など) が削除され、代わりに `cmd/compile` と `cmd/link` が追加されています。これは、ビルドクリーンアップの対象が変更されたことを意味します。

2.  **`src/cmd/dist/buildtool.go`**:
    *   `bootstrapDirs` 変数から、旧来のアーキテクチャ固有のコンパイラ/リンカのディレクトリ（`5g`, `5l` など）が削除されています。
    *   代わりに、`compile` および `link` の新しい内部パッケージ構造（例: `compile/internal/amd64`, `link/internal/amd64`）が追加されています。これは、新しい汎用コンパイラ/リンカが内部的にアーキテクチャ固有のバックエンドを持つ構造になったことを示しています。

3.  **`src/cmd/go/build.go`**:
    *   `gcToolchain` 構造体の `compiler()` メソッドが `tool(archChar() + "g")` から `tool("compile")` に、`linker()` メソッドが `tool(archChar() + "l")` から `tool("link")` に変更されています。これは、`go` コマンド自身が内部でコンパイラやリンカを呼び出す際に、新しい汎用インターフェースを使用するように更新されたことを意味します。
    *   `linkShared`, `gc`, `ld` といったビルド関連の関数内で、具体的なツール呼び出しが `tool(archChar() + "l")` や `tool(archChar() + "g")` から `tool("link")` や `tool("compile")` に変更されています。

4.  **テストファイル (`src/cmd/pack/pack_test.go`, `src/debug/gosym/pclntab_test.go`, `test/bench/shootout/timing.sh`, `test/fixedbugs/*.go`, `test/nosplit.go`, `test/run.go`, `test/sinit_run.go`)**:
    *   これらのファイルでは、シェルコマンドやGoのテストコード内で、`go tool <arch>g` や `go tool <arch>l` といった形式でコンパイラやリンカを直接呼び出していた箇所が、`go tool compile` や `go tool link` に変更されています。これにより、テスト環境も新しいツールチェインの利用に適合しています。特に `test/run.go` では、`gc` と `ld` というグローバル変数が削除されており、アーキテクチャ固有のコンパイラ/リンカ名を動的に構築する必要がなくなったことが示されています。

これらの変更は、Goのビルドシステム全体にわたる広範なものであり、Goツールチェインの内部構造が大きく刷新されたことを反映しています。

## コアとなるコードの解説

これらの変更は、Goのビルドプロセスにおけるコンパイラとリンカの呼び出しを、アーキテクチャに依存しない統一されたインターフェースに移行させるものです。

*   **`src/cmd/dist/build.go` の変更**: このファイルはGoのブートストラップビルド（Go自身をビルドするプロセス）を担当しています。ここでの変更は、Goツールチェインのビルド時に、新しい `compile` と `link` コマンドが生成され、それらが使用されるように指示しています。`cleantab` の変更は、ビルド後にクリーンアップされるべき古いツールが新しいツールに置き換わったことを示します。
*   **`src/cmd/dist/buildtool.go` の変更**: このファイルは、Goツールチェインのブートストラップビルドに必要なパッケージのリストを定義しています。旧来のアーキテクチャ固有のツールディレクトリが削除され、`compile` と `link` の下に新しい内部パッケージ構造が追加されたことは、これらの新しい汎用ツールが、内部でアーキテクチャ固有のロジックをカプセル化していることを明確に示しています。これにより、外部からは単一のインターフェースとして扱えるようになります。
*   **`src/cmd/go/build.go` の変更**: このファイルは、`go build` や `go install` といったユーザーが日常的に使うコマンドのビルドロジックを定義しています。`gcToolchain` の `compiler()` と `linker()` メソッドが `tool("compile")` と `tool("link")` を返すように変更されたことで、`go` コマンドはもはやターゲットアーキテクチャに基づいてコンパイラ/リンカの名前を動的に構築する必要がなくなりました。代わりに、`go tool compile` と `go tool link` を呼び出すだけで、`GOOS` と `GOARCH` 環境変数に基づいて適切なコンパイル/リンク処理が内部的に行われるようになります。
*   **テストファイルの変更**: 多数のテストファイルにおける変更は、Goのテストスイート全体が新しいツールチェインの呼び出し規約に準拠するように更新されたことを示しています。これにより、新しいツールチェインが正しく機能していることを検証できます。

全体として、このコミットはGoツールチェインのモジュール化と抽象化を推進し、将来的なメンテナンスとクロスプラットフォーム開発をより容易にするための重要なステップです。また、ビルド時間の短縮という副次的なメリットも得られました。
