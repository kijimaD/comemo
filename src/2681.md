## 変更の背景

`sync.Once` はGo言語における重要な並行処理プリミティブであり、プログラムの実行中に特定の処理が一度だけ実行されることを保証するために使用されます。例えば、データベース接続の初期化や設定ファイルのロードなど、リソースの初期化処理によく用いられます。

しかし、`sync.Once` の `Do` メソッドに匿名関数（クロージャ）を直接渡す際に、開発者がその動作を誤解するケースが頻繁に発生していました。`once.Do` は内部的に渡された関数を識別するためにその関数値を使用しますが、Goにおいてクロージャは評価されるたびに新しい関数値を生成します。このため、異なるコンテキストで同じように見えるクロージャが `once.Do` に渡されると、`sync.Once` はそれらを異なる関数として認識し、結果として複数回実行してしまうという、意図しない動作を引き起こす可能性がありました。

このコミットは、このような一般的な誤用パターンによる潜在的なバグを防ぐため、`sync.Once` のドキュメンテーションに明確な警告と説明を追加することを目的としています。コードの動作自体を変更するものではなく、開発者へのガイダンスを強化するものです。

## 前提知識の解説

### Goの並行処理と `sync` パッケージ

Go言語は、ゴルーチン（goroutine）とチャネル（channel）を核とした並行処理モデルを特徴としています。`sync` パッケージは、これらのプリミティブを補完し、より高度な並行処理パターンを安全に実装するためのツールを提供します。`sync.Mutex`（ミューテックス）、`sync.WaitGroup`（ウェイトグループ）、そして `sync.Once` などが含まれます。

### `sync.Once` の役割

`sync.Once` は、プログラムのライフサイクルにおいて、ある関数が「一度だけ」実行されることを保証するための構造体です。これは、特に初期化処理において非常に有用です。例えば、アプリケーション起動時に一度だけ実行すべき設定ロードや、シングルトンインスタンスの生成などに利用されます。

`sync.Once` の `Do(f func())` メソッドは、引数 `f` で渡された関数を一度だけ実行します。複数のゴルーチンが同時に `Do(f)` を呼び出した場合でも、`f` は一度だけ実行され、他のゴルーチンは `f` の完了を待ってから処理を続行します。内部的には、ミューテックスとブールフラグを組み合わせてこの「一度だけ実行」を保証しています。

### Goにおけるクロージャ（匿名関数）

Go言語のクロージャは、関数リテラル（匿名関数）の一種で、それが定義されたスコープ（外部スコープ）の変数を参照・変更できる特性を持ちます。クロージャは非常に強力で柔軟な機能であり、コールバック、イベントハンドラ、イテレータなど、さまざまな場面で利用されます。

重要なのは、Goにおいて関数は第一級オブジェクト（first-class citizen）であるという点です。つまり、関数は変数に代入したり、関数の引数として渡したり、関数の戻り値として返したりすることができます。

### 関数値の評価とクロージャ

Goにおいて、関数リテラル（匿名関数）が評価されるたびに、その関数を表す「関数値」が生成されます。この関数値は、その関数のコードと、それがキャプチャした外部変数の環境（コンテキスト）を組み合わせたものです。

例えば、以下のコードを考えてみましょう。

```go
func createClosure(x int) func() {
    return func() {
        fmt.Println(x)
    }
}

c1 := createClosure(1) // c1 は x=1 をキャプチャしたクロージャ
c2 := createClosure(2) // c2 は x=2 をキャプチャしたクロージャ
```

`c1` と `c2` は異なる関数値です。たとえ同じ関数リテラルから生成されたとしても、異なる外部環境（この場合は `x` の値）をキャプチャしているため、これらはGoランタイムによって異なる関数として扱われます。

さらに、同じ関数リテラルが複数回評価される場合も、それぞれ異なる関数値が生成されます。

```go
func main() {
    x := 10
    f1 := func() { fmt.Println(x) }
    f2 := func() { fmt.Println(x) }
    // f1 と f2 は異なる関数値である
}
```

この「評価されるたびに異なる関数値が生成される」という特性が、`sync.Once` とクロージャを組み合わせる際の誤解の根源となります。

## 技術的詳細

`sync.Once` の `Do` メソッドは、内部的に `sync.Mutex` と `done` というブールフラグを使用して、渡された関数 `f` が一度だけ実行されることを保証します。しかし、このコミットが指摘している問題は、`Do` メソッドが引数として受け取る `f func()` の「関数値」の同一性に基づいている点にあります。

元の `sync/once` パッケージには、`Do` メソッドが内部で `jobs` というマップ（`map[func()] *job` のようなもの）を使用して、どの関数が既に実行されたかを追跡する実装がありました（コミット時点のコードベースに基づく）。このマップのキーとして `func()` 型の関数値が使用されます。

問題は、`func() { ... }` のような匿名関数（クロージャ）が `Do` メソッドに渡されるたびに、Goランタイムは新しい関数値を生成するということです。たとえそのクロージャが同じコードを含み、同じ外部変数をキャプチャしていたとしても、`Do` が呼び出されるたびに新しい関数値が生成されれば、`sync.Once` の内部マップではこれらが異なるキーとして扱われます。

結果として、`Do` メソッドは、異なる関数値が渡されるたびに、その関数を「まだ実行されていない新しい関数」と認識し、実行してしまいます。これは、開発者が「このロジックは一度だけ実行されるべきだ」と期待して `sync.Do` を使用したにもかかわらず、実際には複数回実行されてしまうという、意図しない動作につながります。

このコミットは、この動作を変更するものではなく、この挙動に関するドキュメンテーションを追加することで、開発者がこの落とし穴を回避できるようにするためのものです。つまり、`sync.Once` の設計上の特性とGoの関数値のセマンティクスを明確に説明し、誤用を防ぐための注意喚起を行っています。

## コアとなるコードの解説

追加されたコメントは、`sync.Once` の `Do` メソッドにクロージャを渡す際の注意点を明確に説明しています。

```go
// Since a func() expression typically evaluates to a differerent
// function value each time it is evaluated, it is incorrect to
// pass such values to Do.  For example,
// 	func f(x int) {
//		Do(func() { fmt.Println(x) })
//	}
// behaves the same as
//	func f(x int) {
//		fmt.Println(x)
//	}
// because the func() expression in the first creates a new
// func each time f runs, and each of those funcs is run once.
```

このコメントは以下の点を強調しています。

1.  **`func()` 式の評価:** `func()` 式（匿名関数）は、評価されるたびに異なる関数値を生成する傾向があること。
2.  **`Do` への不適切な渡し方:** そのため、このような関数値を `Do` メソッドに直接渡すのは誤りであること。
3.  **具体的な例:** `func f(x int) { Do(func() { fmt.Println(x) }) }` のようなコードは、`func f(x int) { fmt.Println(x) }` と同じように動作することを例示しています。これは、`f(x)` が呼び出されるたびに `Do` に渡されるクロージャが新しい関数値として認識され、結果として `fmt.Println(x)` が毎回実行されてしまうためです。
4.  **理由の明確化:** `func()` 式が `f` が実行されるたびに新しい関数を生成し、それらの関数がそれぞれ一度ずつ実行されるためであると説明しています。

このコメントにより、開発者は `sync.Once` を使用する際に、クロージャの特性と `sync.Once` の内部動作を考慮し、意図した通りに一度だけ実行されるようにコードを記述するための正しい理解を得ることができます。例えば、クロージャではなく、グローバル変数や構造体のフィールドとして定義された関数を `Do` に渡す、あるいは `Do` の呼び出し自体を一度だけ実行されるように設計するなどの対策が考えられます。
