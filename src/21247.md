## 変更の背景

Go言語は、バージョン1.0以降、厳格な[Go互換性保証 (Go Compatibility Promise)](https://go.dev/doc/go1compat) を掲げています。これは、Go 1で書かれたプログラムは、Go 1の将来のリリースでもコンパイルされ、実行され続けることを保証するものです。この互換性を維持するために、Goの公開API（エクスポートされた型、関数、メソッド、定数など）の変更は厳しく管理されています。

`go tool api` コマンドは、この互換性保証を強制するための主要なツールです。このツールは、Goの各メジャーリリース（Go 1.x）ごとに作成される `api/go1.x.txt` ファイルを参照し、現在のGoソースコードの公開APIが、過去のバージョンのAPIと互換性があるかどうかを検証します。

このコミットは、Go 1.4のリリースブランチ (`release-branch.go1.4`) において、Go 1.4の公開APIの「スナップショット」として `api/go1.4.txt` を作成するものです。これにより、将来のGoバージョンがGo 1.4との互換性を維持しているかを `go tool api` がチェックできるようになります。

## 前提知識の解説

### Goの互換性保証 (Go Compatibility Promise)

Go言語のバージョン1.0がリリースされて以来、Goチームは「Go 1のプログラムはGo 1の将来のリリースでも動作し続ける」という強力な互換性保証を提供しています。これは、既存のGoコードベースが新しいGoバージョンにアップグレードしても、コンパイルエラーやランタイムエラーなしに動作し続けることを意味します。この保証は、Goがエンタープライズ環境や長期プロジェクトで広く採用される上で非常に重要な要素となっています。

この互換性保証は主に公開APIに適用されます。つまり、エクスポートされた関数、メソッド、型、定数などのシグネチャやセマンティクスが、既存のコードを壊す形で変更されることはありません。ただし、内部実装の変更や、エクスポートされていない要素の変更は、この保証の対象外です。

### `go tool api` コマンド

`go tool api` は、Goのツールチェインに含まれるコマンドで、Goの公開APIの互換性を検証するために使用されます。このコマンドは、Goの標準ライブラリの公開APIを抽出し、それを特定のバージョンのAPI定義ファイル（例: `api/go1.txt`, `api/go1.1.txt` など）と比較します。

比較の結果、もし現在のAPIが過去のバージョンから非互換な変更（例: 関数の削除、引数の変更、型の削除など）を含んでいる場合、`go tool api` はエラーを報告します。これにより、Goチームは新しいAPIの変更が互換性保証に違反していないかをリリース前に確認することができます。

### `api/go1.x.txt` ファイルの役割

`api/go1.x.txt` ファイルは、Goの各メジャーリリース（Go 1.x）時点での標準ライブラリの公開APIの定義をテキスト形式で記述したものです。これらのファイルは、`go tool api` コマンドが互換性チェックを行う際の「基準」として機能します。

ファイルの内容は、各パッケージの公開された要素（型、関数、メソッド、定数、変数）のシグネチャを一行ずつ記述したものです。例えば、`pkg archive/zip, method (*Writer) Flush() error` のような形式で、`archive/zip` パッケージの `Writer` 型に `Flush` メソッドが追加されたことを示しています。

これらのファイルは、Goのリリースプロセスの一部として生成され、Goのソースリポジトリにコミットされます。これにより、Goの各バージョンのAPIの歴史が明確に記録され、互換性保証の透明性が確保されます。

## 技術的詳細

### `api/go1.4.txt` の内容

`api/go1.4.txt` ファイルは、Go 1.4で導入された多数の新しいAPI要素を列挙しています。コミットの差分を見ると、このファイルには以下のような様々なパッケージのAPI変更が記録されています。

*   **`archive/zip`**: `Writer.Flush` メソッドの追加。
*   **`compress/flate`, `compress/zlib`**: `Resetter` インターフェースの追加。これにより、圧縮器のバッファを再利用して複数のデータを圧縮できるようになります。
*   **`compress/gzip`**: `Reader.Multistream` メソッドの追加。
*   **`crypto`**: SHA3ハッシュ関数の定数 (`SHA3_224` など) や、`Signer` インターフェースの追加。
*   **`crypto/tls`**: `TLS_FALLBACK_SCSV` 定数、SNIのための動的な証明書取得 (`Config.GetCertificate`)、`ConnectionState.TLSUnique` の追加。
*   **`crypto/x509`**: `Certificate.MaxPathLenZero` フィールドの追加。
*   **`database/sql`**: `Drivers()` 関数の追加。
*   **`debug/dwarf`**: `UnspecifiedType` の関連メソッドと型の追加。
*   **`debug/elf`**: ARM64アーキテクチャのELF再配置タイプ (`R_AARCH64_*`) の多数の追加。これは、GoがARM64プラットフォームをより完全にサポートするための重要な変更です。
*   **`debug/plan9obj`**: `FileHeader` 構造体に `HdrSize` と `LoadAddress` フィールドの追加。
*   **`encoding/xml`**: `Decoder.InputOffset` メソッドの追加。
*   **`go/build`**: `ImportComment` 定数と `Package.ImportComment` フィールド、`MultiplePackageError` 型の追加。
*   **`go/token`**: `PositionFor` アクセサメソッドの追加。
*   **`image`**: `RGBAAt`, `Gray16At` などの `At` メソッド群の追加。
*   **`image/png`**: エンコーダの設定 (`CompressionLevel`, `Encoder` 構造体) の追加。
*   **`math`**: `Nextafter32` 関数の追加。
*   **`math/big`**: `Rat.Float32` メソッドの追加。
*   **`net/http`**: `Request.BasicAuth` メソッド、`Transport.DialTLS` フックの追加。
*   **`net/http/httputil`**: `ReverseProxy.ErrorLog` フィールドの追加。
*   **`os`, `syscall`**: `Unsetenv` 関数の追加。
*   **`reflect`**: `Type.Comparable` メソッドの追加。
*   **`runtime`**: `MemStats.PauseEnd` 配列の追加。
*   **`runtime/debug`**: `GCStats.PauseEnd` フィールドの追加。
*   **`sync/atomic`**: `Value` 型とその `Load`, `Store` メソッドの追加。これは、任意の型の値をアトミックに読み書きするための汎用的なメカニズムを提供します。
*   **`syscall` (Linux)**: Linuxユーザー名前空間のためのUID/GIDマッピング (`SysProcAttr.GidMappings`, `UidMappings`, `SysProcIDMap`) のサポート。
*   **`syscall` (Windows)**: WindowsにおけるCNAME解決の修正、シンボリックリンクのサポート (`CreateHardLink`, `CreateSymbolicLink` など)、UDPコネクションリセット動作の無効化、`Getppid()` の実装 (`CreateToolhelp32Snapshot`, `Process32First` など)、パス処理の改善 (`FullPath`)。
*   **`testing`**: `Coverage()` 関数、`TestMain` サポート (`MainStart`, `M.Run`, `M` 型) の追加。
*   **`text/scanner`**: `Scanner.IsIdentRune` フィールドの追加。
*   **`text/template`**: `Node` へのバックポインタの追加。
*   **`unicode`**: Unicode 7.0.0へのアップグレードに伴う新しいスクリプトの `RangeTable` の追加。

これらの変更は、Go 1.4が様々な分野で機能強化と改善をもたらしたことを示しています。

### `src/cmd/api/run.go` の変更

`src/cmd/api/run.go` は、`go tool api` コマンドの実行ロジックを定義するファイルです。このコミットでは、このファイルに2つの重要な変更が加えられています。

1.  **`go1.4.txt` の参照追加**:
    `exec.Command("go", "tool", "api", "-c", file("go1", "go1.1", "go1.2", "go1.3"), "-next", file("next"), "-except", file("except"))`
    という行が、
    `exec.Command("go", "tool", "api", "-c", file("go1", "go1.1", "go1.2", "go1.3", "go1.4"), "-next", file("next"), "-except", file("except"))`
    に変更されました。
    これは、`go tool api` コマンドが、Go 1.4のAPI定義ファイル (`go1.4.txt`) を互換性チェックの基準として使用するように指示するものです。これにより、Go 1.4以降のGoバージョンが、Go 1.4の公開APIとの互換性を維持しているかを検証できるようになります。

2.  **`gopath` 生成ロジックの変更**:
    `gopath := filepath.Join(os.TempDir(), "gopath-api-"+cleanUsername(username), goToolsVersion)`
    という行が、
    `gopath := filepath.Join(os.TempDir(), "gopath-api-"+cleanUsername(username)+"-"+cleanUsername(strings.Fields(runtime.Version())[0]), goToolsVersion)`
    に変更されました。
    この変更は、`go tool api` が一時的に使用するGOPATHのパスに、現在のGoのバージョン情報 (`runtime.Version()`) を含めるようにするものです。これにより、異なるGoバージョン（例えば、Go 1.3とGo 1.4）で `go tool api` を実行した場合でも、それぞれが独立したGOPATHを使用するようになり、互いに干渉することなく、より安定したテスト環境が提供されます。`strings.Fields(runtime.Version())[0]` は、`go1.4` のようなバージョン文字列の最初の部分（例: "go1.4" から "go1.4"）を取得します。
