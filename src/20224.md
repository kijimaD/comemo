# [インデックス 20224] ファイルの概要

このコミットは、Go言語のコードフォーマッタである `gofmt` コマンドの挙動に関する改善と修正を含んでいます。具体的には、標準入力から `gofmt` を実行する際に `-w` (in-place write) オプションの使用を禁止し、ファイル書き込み時のパーミッション設定を修正しています。

## 変更の背景

このコミットには二つの主要な変更点があり、それぞれ異なる背景を持っています。

1.  **`gofmt -w` と標準入力の組み合わせの禁止**:
    `gofmt` は通常、ファイルパスを引数として受け取り、そのファイルをフォーマットします。`-w` オプションが指定された場合、`gofmt` はフォーマット結果を元のファイルに上書きします。しかし、`gofmt` はファイルパスの代わりに標準入力からコードを受け取ることも可能です。この場合、`-w` オプションは意味をなしません。なぜなら、標準入力は一時的なデータストリームであり、「元のファイル」という概念が存在しないため、どこに上書き保存するべきか `gofmt` が判断できないからです。この組み合わせを許可すると、ユーザーが意図しない挙動や混乱を招く可能性がありました。そのため、この無効な組み合わせを明示的にエラーとして扱うように変更されました。

2.  **ファイルパーミッションの修正 (0x644)**:
    `ioutil.WriteFile` は、指定されたパスにファイルを書き込む際に使用されるGo標準ライブラリの関数です。この関数は、書き込むデータとファイルパーミッションを引数として受け取ります。以前のコードでは、パーミッションが `0` と指定されていました。これは、ファイルが作成される際にデフォルトのパーミッション（通常は `umask` の影響を受ける）が適用されることを意味します。しかし、明示的に `0644` (所有者には読み書き、グループとその他には読み取りのみ) を指定することで、ファイルの作成パーミッションがより予測可能で安全なものになります。コミットメッセージにある「should not happen anymore, though」という記述は、`gofmt` が通常は既存のファイルを上書きするため、新しいファイルが作成されるケースは稀である、という認識を示唆しています。しかし、万が一新しいファイルが作成されるような状況が発生した場合でも、適切なパーミッションが設定されるようにするための堅牢性向上策です。

## 前提知識の解説

*   **`gofmt`**: Go言語の公式なコードフォーマッタです。Goのコードを標準的なスタイルに自動的に整形し、コードの一貫性を保ち、可読性を向上させる役割を担っています。開発者がスタイルガイドラインについて議論する時間を減らし、より本質的な開発に集中できるようにします。
*   **標準入力 (stdin)**: プログラムが外部からデータを受け取るための標準的な入力ストリームです。パイプ (`|`) やリダイレクト (`<`) を通じて、他のプログラムの出力やファイルの内容を `gofmt` に渡すことができます。
*   **`-w` オプション**: `gofmt` のコマンドラインオプションの一つで、フォーマット結果を元のファイルに直接書き戻す（上書きする）ことを指示します。このオプションがない場合、`gofmt` はフォーマット結果を標準出力に出力します。
*   **ファイルパーミッション (Unix/Linux)**: Unix系OSにおけるファイルやディレクトリへのアクセス権限を制御する仕組みです。通常、3桁の8進数で表現され、それぞれ所有者 (owner)、グループ (group)、その他 (others) に対する読み取り (read: 4)、書き込み (write: 2)、実行 (execute: 1) の権限を示します。
    *   `0644`:
        *   最初の `0` は特殊パーミッション（setuid, setgid, sticky bit）がないことを示します。
        *   `6` (rw-): 所有者は読み取りと書き込みが可能。
        *   `4` (r--): グループは読み取りのみ可能。
        *   `4` (r--): その他は読み取りのみ可能。
    *   **`umask`**: 新しくファイルやディレクトリが作成される際に、デフォルトで適用されるパーミッションマスクです。`umask` の値は、デフォルトのパーミッションから「差し引かれる」ビットを示します。例えば、`umask` が `0022` の場合、ファイル作成時のデフォルトパーミッションは `0666` から `0022` を引いた `0644` になります。

## 技術的詳細

このコミットは、`gofmt` コマンドの `gofmt.go` ファイル内の `processFile` 関数と `gofmtMain` 関数に影響を与えています。

1.  **`gofmt -w` と標準入力の組み合わせの禁止**:
    `gofmtMain` 関数は `gofmt` コマンドのエントリポイントであり、コマンドライン引数を解析し、適切な処理をディスパッチします。この変更では、`flag.NArg() == 0` (つまり、ファイルパスが指定されず、標準入力が使用される場合) かつ `*write` (つまり、`-w` オプションが指定されている場合) の条件が追加されました。この条件が真の場合、`fmt.Fprintln(os.Stderr, "error: cannot use -w with standard input")` というエラーメッセージを標準エラー出力に表示し、`exitCode` を `2` に設定してプログラムを終了します。これにより、ユーザーは無効な操作を試みた際に明確なフィードバックを受け取ることができます。

2.  **ファイルパーミッションの修正**:
    `processFile` 関数は、個々のファイルをフォーマットし、その結果を処理する役割を担っています。この関数内で、フォーマットされた結果をファイルに書き戻すために `ioutil.WriteFile` が使用されています。以前は `ioutil.WriteFile(filename, res, 0)` となっていましたが、これが `ioutil.WriteFile(filename, res, 0644)` に変更されました。これにより、`ioutil.WriteFile` が新しいファイルを作成する際に、明示的に `0644` のパーミッションが設定されるようになります。これは、`umask` の設定に依存せず、一貫したファイルパーミッションを保証するための変更です。

## コアとなるコードの解説

### `processFile` 関数内の変更

```go
-			err = ioutil.WriteFile(filename, res, 0)
+			err = ioutil.WriteFile(filename, res, 0644)
```
この変更は、`gofmt` がフォーマットされた内容をファイルに書き込む際のパーミッション設定を修正しています。
*   `ioutil.WriteFile` は、Go言語の `io/ioutil` パッケージ（Go 1.16以降は `os` パッケージに移行）にある関数で、指定されたパスにデータを書き込むために使用されます。
*   第三引数は `os.FileMode` 型で、作成されるファイルのパーミッションを指定します。
*   以前の `0` は、システムが提供するデフォルトのパーミッション（`umask` の影響を受ける）を使用することを意味していました。
*   新しい `0644` は、ファイル所有者には読み書き (`rw-`)、グループとその他のユーザーには読み取り (`r--`) の権限を明示的に設定します。これにより、`gofmt` がファイルを書き込む際のパーミッションがより予測可能で安全になります。

### `gofmtMain` 関数内の変更

```go
 	if flag.NArg() == 0 {
+		if *write {
+			fmt.Fprintln(os.Stderr, "error: cannot use -w with standard input")
+			exitCode = 2
+			return
+		}
 		if err := processFile("<standard input>", os.Stdin, os.Stdout, true); err != nil {
 			report(err)
 		}
```
このコードブロックは、`gofmt` がコマンドライン引数なしで実行された場合（つまり、標準入力からデータを読み込む場合）の挙動を制御します。
*   `flag.NArg() == 0` は、`gofmt` がファイルパスの引数なしで呼び出されたことを確認します。この場合、`gofmt` は標準入力からコードを読み取ります。
*   追加された `if *write` ブロックは、ユーザーが `-w` オプションも同時に指定しているかどうかをチェックします。
*   もし `-w` オプションが指定されていた場合、`fmt.Fprintln(os.Stderr, "error: cannot use -w with standard input")` によってエラーメッセージが標準エラー出力に表示されます。
*   `exitCode = 2` は、プログラムがエラー終了したことを示す終了コードを設定します。
*   `return` は、それ以上の処理を行わずに `gofmtMain` 関数を終了させます。
この変更により、`gofmt -w` と標準入力の組み合わせという無意味で潜在的に混乱を招く操作が、明確なエラーとして扱われるようになりました。
