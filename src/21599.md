# [インデックス 21599] ファイルの概要

このコミットは、Go言語の標準ライブラリである `crypto/x509` パッケージにおける、CRL (Certificate Revocation List) 発行時の Authority Key Identifier (AKI) 拡張の取り扱いに関する修正です。具体的には、RFC5280 の要件に従い、発行される全ての CRL に Authority Key Identifier を含めるように変更されています。

    crypto/x509: Authority Key Identifier must be included in all CRLs issued
    
    According to RFC5280 the authority key identifier extension MUST included in all
    CRLs issued. This patch includes the authority key identifier extension when the
    Subject Key Identifier is present in the signing certificate.
    
    RFC5280 states:
    
    "The authority key identifier extension provides a means of identifying the
    public key corresponding to the private key used to sign a CRL.  The
    identification can be based on either the key identifier (the subject key
    identifier in the CRL signer's certificate) or the issuer name and serial
    number.  This extension is especially useful where an issuer has more than one
    signing key, either due to multiple concurrent key pairs or due to changeover."

    extension in all CRLs issued."

## 元コミット内容

`crypto/x509`: 発行される全ての CRL に Authority Key Identifier を含める必要がある

RFC5280 によると、発行される全ての CRL に Authority Key Identifier 拡張を含める必要があります。このパッチは、署名証明書に Subject Key Identifier が存在する場合に、Authority Key Identifier 拡張を含めるようにします。

RFC5280 は次のように述べています:

「Authority Key Identifier 拡張は、CRL の署名に使用された秘密鍵に対応する公開鍵を識別する手段を提供します。識別は、鍵識別子（CRL 署名者の証明書における Subject Key Identifier）または発行者名とシリアル番号に基づいて行うことができます。この拡張は、発行者が複数の署名鍵を持っている場合（複数の同時鍵ペアによるもの、または変更によるもの）に特に有用です。」

「準拠する CRL 発行者は、鍵識別子方式を使用し、発行される全ての CRL にこの拡張を含める必要があります。」

この変更は、http://golang.org/cl/177760043 で議論されました。

## 変更の背景

このコミットの背景には、X.509 証明書および CRL の標準を定義する RFC5280 の厳格な要件があります。RFC5280 は、公開鍵基盤 (PKI) における証明書と CRL の構造と処理方法を規定しており、その中で Authority Key Identifier (AKI) 拡張の重要性を強調しています。

RFC5280 のセクション 5.2.1 では、CRL に AKI 拡張を含めることが「MUST」（必須）であると明確に述べられています。この拡張は、CRL を発行した認証局 (CA) の公開鍵を識別するために使用されます。特に、CA が複数の署名鍵を運用している場合（例えば、鍵の更新や異なる目的のための鍵など）、どの鍵で特定の CRL が署名されたかを正確に特定するために不可欠です。これにより、証明書パスの検証プロセスにおいて、正しい CRL が適用されていることを保証し、失効情報の信頼性を高めます。

Go の `crypto/x509` パッケージは、X.509 証明書と CRL の生成、解析、検証を扱うための Go 標準ライブラリの一部です。このコミット以前は、`crypto/x509` パッケージが CRL を生成する際に、常に AKI 拡張を含めていなかった可能性があります。これは RFC5280 の「MUST」要件に準拠していない状態であり、相互運用性やセキュリティ上の問題を引き起こす可能性がありました。

このコミットは、この不適合を修正し、Go が生成する CRL が RFC5280 の仕様に完全に準拠するようにすることを目的としています。具体的には、CRL の署名に使用される証明書に Subject Key Identifier (SKI) が存在する場合、その SKI を基にした Authority Key Identifier を CRL に含めるように変更されました。これにより、Go で生成された CRL がより堅牢になり、他の PKI システムとの互換性が向上します。

## 前提知識の解説

このコミットを理解するためには、以下の概念を把握しておく必要があります。

1.  **X.509 証明書**:
    *   公開鍵暗号基盤 (PKI) において、公開鍵の所有者を検証するために使用されるデジタル証明書の標準フォーマットです。
    *   証明書には、所有者の公開鍵、所有者の識別情報（Subject）、発行者の識別情報（Issuer）、有効期間、発行者のデジタル署名などが含まれます。
    *   X.509 v3 証明書では、様々な「拡張 (Extensions)」を含めることができ、これにより証明書の機能や用途を拡張できます。

2.  **CRL (Certificate Revocation List)**:
    *   証明書失効リストの略で、認証局 (CA) によって発行され、失効した（もはや信頼できない）証明書のシリアル番号のリストを含みます。
    *   証明書が有効期限内であっても、秘密鍵の漏洩、所有者の情報変更、証明書の誤発行などの理由で失効することがあります。
    *   クライアントは、証明書を検証する際に、その証明書が CRL に含まれていないかを確認し、失効している場合は信頼しません。

3.  **Authority Key Identifier (AKI)**:
    *   X.509 v3 証明書および CRL の拡張の一つです。
    *   **CRL における AKI**: CRL を署名した認証局 (CA) の公開鍵を識別するために使用されます。これにより、CRL がどの CA のどの鍵によって署名されたかを明確に特定できます。CA が複数の署名鍵を持つ場合に特に重要です。
    *   **証明書における AKI**: 証明書を発行した CA の公開鍵を識別するために使用されます。これにより、証明書チェーンを構築する際に、親証明書（CA 証明書）を効率的に見つけることができます。

4.  **Subject Key Identifier (SKI)**:
    *   X.509 v3 証明書の拡張の一つです。
    *   証明書に含まれる公開鍵を一意に識別するためのハッシュ値です。
    *   AKI が親証明書の SKI を参照することで、証明書チェーンのリンクが確立されます。

5.  **RFC5280**:
    *   "Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile" の略で、X.509 証明書と CRL のインターネットでの利用方法を定義する標準仕様です。
    *   この RFC は、証明書と CRL の構造、必須フィールド、拡張の利用方法、パス検証アルゴリズムなど、PKI の運用に必要な詳細なルールを定めています。
    *   特に、CRL における AKI の包含は、この RFC で「MUST」（必須）とされています。

6.  **ASN.1 (Abstract Syntax Notation One)**:
    *   データ構造を記述するための標準的な記法です。X.509 証明書や CRL は、ASN.1 を用いて定義された構造に従ってエンコードされます。
    *   Go の `encoding/asn1` パッケージは、Go のデータ構造と ASN.1 形式の間でマーシャリング（エンコード）およびアンマーシャリング（デコード）を行う機能を提供します。

7.  **OID (Object Identifier)**:
    *   ASN.1 で定義されたオブジェクト（例えば、特定の拡張やアルゴリズム）を一意に識別するための数値列です。
    *   `oidExtensionAuthorityKeyId` は、Authority Key Identifier 拡張の OID を表します。

## 技術的詳細

このコミットの技術的詳細は、RFC5280 の CRL プロファイルにおける Authority Key Identifier (AKI) 拡張の要件に焦点を当てています。

RFC5280 のセクション 5.2.1 "Authority Key Identifier" は、CRL におけるこの拡張の役割と必須性について以下のように規定しています。

*   **目的**: AKI 拡張は、CRL を署名した秘密鍵に対応する公開鍵を識別する手段を提供します。これは、特に CA が複数の署名鍵（例えば、鍵の更新や異なる目的のための鍵）を運用している場合に、どの鍵で特定の CRL が署名されたかを明確に特定するために不可欠です。
*   **識別方法**: 識別は、以下のいずれかに基づいて行うことができます。
    *   **鍵識別子 (Key Identifier)**: CRL 署名者の証明書に含まれる Subject Key Identifier (SKI) を使用する方法。RFC5280 は、準拠する CRL 発行者がこの方法を使用することを「MUST」（必須）としています。
    *   **発行者名とシリアル番号 (Issuer Name and Serial Number)**: CRL 署名者の証明書の発行者名とシリアル番号を使用する方法。
*   **必須性**: RFC5280 は、「準拠する CRL 発行者は、鍵識別子方式を使用し、発行される全ての CRL にこの拡張を含める必要があります。」と明確に述べています。これは、CRL の信頼性と検証可能性を確保するための重要な要件です。

Go の `crypto/x509` パッケージは、CRL を生成する `CreateCRL` 関数を提供しています。このコミット以前は、`CreateCRL` 関数が常に AKI 拡張を CRL に含めていなかったため、RFC5280 のこの必須要件に準拠していませんでした。

このコミットでは、この問題を解決するために、`CreateCRL` 関数内で以下のロジックが追加されました。

1.  **条件付き追加**: CRL の署名に使用される証明書 (`c`、`*Certificate` 型) の `SubjectKeyId` フィールドが空でない場合（つまり、署名証明書に SKI が存在する場合）にのみ、AKI 拡張を追加します。これは、RFC5280 が鍵識別子方式を推奨していることに対応しています。
2.  **AKI 構造の生成**: `pkix.Extension` 型の新しい拡張オブジェクト `aki` を作成します。
    *   `aki.Id` には、Authority Key Identifier 拡張の OID である `oidExtensionAuthorityKeyId` を設定します。
    *   `aki.Value` には、`authKeyId` 構造体（`Id` フィールドに署名証明書の `SubjectKeyId` を持つ）を ASN.1 でマーシャルした結果を設定します。`authKeyId` は、AKI 拡張の内部構造を定義する Go の構造体です。
3.  **CRL への追加**: 生成された `aki` 拡張を、CRL の `tbsCertList.Extensions` スライスに追加します。`tbsCertList` は、CRL の署名対象となる部分（"To Be Signed Certificate List"）を表す構造体です。

この変更により、Go で生成される CRL は、署名証明書に SKI が含まれている限り、RFC5280 の必須要件である AKI 拡張を確実に含むようになります。これにより、Go の PKI 実装の標準準拠性が向上し、他のシステムとの相互運用性が強化されます。

## コアとなるコードの解説

追加されたコードブロックは、`CreateCRL` 関数内で CRL の `tbsCertList` (To Be Signed Certificate List) を構築する部分に挿入されています。

1.  **`// Authority Key Id`**: コメントで、これから Authority Key Identifier 拡張を追加する意図が示されています。

2.  **`if len(c.SubjectKeyId) > 0 { ... }`**:
    *   この条件文は、CRL を署名する証明書 (`c`、`*Certificate` 型) に `SubjectKeyId` が設定されているかどうかを確認しています。
    *   `SubjectKeyId` は、証明書に含まれる公開鍵を一意に識別するバイトスライスです。
    *   RFC5280 は、CRL の AKI を署名証明書の SKI に基づいて生成することを推奨しているため、この条件は適切です。SKI が存在しない場合は、AKI を生成するための情報がないため、このブロックはスキップされます。

3.  **`var aki pkix.Extension`**:
    *   `pkix.Extension` 型の変数 `aki` を宣言しています。
    *   `pkix.Extension` は、X.509 証明書および CRL の拡張を表す Go の構造体で、`Id` (OID) と `Value` (拡張データ) を持ちます。

4.  **`aki.Id = oidExtensionAuthorityKeyId`**:
    *   `aki` の `Id` フィールドに `oidExtensionAuthorityKeyId` を設定しています。
    *   `oidExtensionAuthorityKeyId` は、Go の `crypto/x509/pkix` パッケージで定義されている定数で、Authority Key Identifier 拡張の ASN.1 OID (Object Identifier) を表します。これにより、この拡張が AKI であることが識別されます。

5.  **`aki.Value, err = asn1.Marshal(authKeyId{Id: c.SubjectKeyId})`**:
    *   `aki` の `Value` フィールドに、AKI 拡張の実際のデータ（バイトスライス）を設定しています。
    *   `asn1.Marshal` は、Go のデータ構造を ASN.1 DER (Distinguished Encoding Rules) 形式のバイトスライスにエンコードする関数です。
    *   `authKeyId{Id: c.SubjectKeyId}` は、`authKeyId` という内部構造体のインスタンスを作成し、その `Id` フィールドに署名証明書 (`c`) の `SubjectKeyId` を渡しています。`authKeyId` 構造体は、AKI 拡張の内部構造（通常は `KeyIdentifier` フィールドのみを持つ）を Go で表現したものです。
    *   この行により、署名証明書の Subject Key Identifier が ASN.1 形式でエンコードされ、AKI 拡張の値として設定されます。

6.  **`if err != nil { return }`**:
    *   `asn1.Marshal` の実行中にエラーが発生した場合（例えば、エンコードに失敗した場合）に、関数から早期にリターンします。

7.  **`tbsCertList.Extensions = append(tbsCertList.Extensions, aki)`**:
    *   生成された `aki` 拡張を、`tbsCertList` 構造体の `Extensions` スライスに追加しています。
    *   `tbsCertList` は、CRL の署名対象となる部分（失効リスト、発行者情報など）を保持する構造体であり、その `Extensions` フィールドは CRL に含まれる拡張のリストです。
    *   この行により、Authority Key Identifier 拡張が CRL の一部として組み込まれます。

このコードブロック全体として、CRL を発行する際に、署名証明書に Subject Key Identifier が存在すれば、RFC5280 の要件に従って Authority Key Identifier 拡張を CRL に自動的に追加するロジックが実装されています。
