# [インデックス 27230] ファイルの概要

このコミットは、Goの標準ライブラリ `net/http` パッケージにおける `ServeMux` の初期化方法を変更し、`cmd/go` バイナリのサイズを約30KB削減することを目的としています。具体的には、`DefaultServeMux` の初期化を遅延させることで、不要なコードがバイナリにリンクされるのを防いでいます。

## 元コミット内容

このコミットは、`net/http` パッケージ内の `ServeMux` の初期化ロジックを変更し、`DefaultServeMux` の初期化を遅延させることで、`cmd/go` バイナリのサイズを30KB削減することを目的としています。具体的には、`DefaultServeMux` がパッケージ初期化時に `NewServeMux()` を呼び出して内部マップを即座に作成するのではなく、必要になったときに初めてマップを作成するように変更されています。

## 変更の背景

Goのバイナリサイズは、特に組み込みシステムやコンテナ環境など、リソースが限られた環境では重要な考慮事項となります。このコミットの主な動機は、`cmd/go` バイナリのサイズを削減することです。

以前の実装では、`net/http` パッケージが初期化される際に、グローバル変数である `DefaultServeMux` が `NewServeMux()` 関数を呼び出して初期化されていました。`NewServeMux()` は `ServeMux` 構造体の内部マップ (`m`) を即座に `make` で作成していました。

問題は、`cmd/go` のような一部のアプリケーションでは `net/http` パッケージをインポートするものの、`DefaultServeMux` を実際に使用しない場合があることです。しかし、`DefaultServeMux` がパッケージ初期化時にマップを「積極的に」初期化していたため、マップの作成に関連するコードや、そのマップが使用する可能性のある他のコードが、たとえ実際に使われなくてもバイナリにリンクされてしまっていました。

このコミットは、`DefaultServeMux` の初期化を「遅延」させることで、この問題を解決しようとしています。つまり、`DefaultServeMux` の内部マップは、実際にハンドラが登録される (`Handle` メソッドが呼び出される) まで作成されないように変更されました。これにより、`DefaultServeMux` が使われないバイナリでは、マップ作成に関連するコードがリンクされなくなり、結果としてバイナリサイズが削減されます。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と `net/http` パッケージの構造に関する知識が必要です。

1.  **Goのパッケージ初期化と `init` 関数**:
    *   Goプログラムが起動すると、インポートされたパッケージは依存関係の順序で初期化されます。
    *   各パッケージは、`init` という特別な関数を持つことができます。`init` 関数は、パッケージ内のすべてのグローバル変数が初期化された後に自動的に実行されます。
    *   以前の `DefaultServeMux` の初期化は、実質的にパッケージ初期化の一部として行われていました。グローバル変数の初期化は `init` 関数よりも前に行われますが、複雑な初期化ロジック（例えば `make` を含む関数呼び出し）は、バイナリにそのコードを含めることになります。

2.  **`net/http` パッケージの `ServeMux` と `DefaultServeMux`**:
    *   `net/http.ServeMux` は、HTTPリクエストのパスに基づいてハンドラをルーティングするためのマルチプレクサ（ルーター）です。
    *   `ServeMux` 構造体は、内部に `map[string]muxEntry` 型の `m` フィールドを持っており、これがパスとハンドラの対応を保持します。
    *   `net/http.DefaultServeMux` は、`net/http` パッケージが提供するグローバルな `ServeMux` インスタンスです。`http.Handle` や `http.HandleFunc` のような関数は、この `DefaultServeMux` に対してハンドラを登録します。また、`http.ListenAndServe` は、ハンドラが指定されない場合に `DefaultServeMux` を使用します。

3.  **Goのリンカとデッドコードエリミネーション (Dead Code Elimination)**:
    *   Goコンパイラとリンカは、最終的なバイナリサイズを最適化するために、使用されていないコードを削除する（デッドコードエリミネーション）機能を持っています。
    *   しかし、グローバル変数が初期化時に特定の関数を呼び出す場合、その関数は「使用されている」と見なされ、たとえそのグローバル変数が後で使われなくても、関連するコードがバイナリにリンクされてしまうことがあります。
    *   このコミットは、このリンカの挙動を考慮し、初期化ロジックを変更することで、より効果的なデッドコードエリミネーションを可能にしています。

4.  **積極的 (Eager) 初期化 vs. 遅延 (Lazy) 初期化**:
    *   **積極的初期化**: オブジェクトやリソースが宣言されたり、プログラムの起動時にすぐに初期化されること。リソースが常に必要とされる場合には効率的ですが、不要なリソースを消費したり、バイナリサイズを増大させたりする可能性があります。
    *   **遅延初期化**: オブジェクトやリソースが実際に必要とされるまで初期化を遅らせること。リソースが常に必要とされるわけではない場合に、起動時間の短縮やリソース消費の削減に役立ちます。このコミットは、`DefaultServeMux` の内部マップに対して遅延初期化を適用しています。

## 技術的詳細

このコミットの技術的な核心は、`net/http.DefaultServeMux` の内部マップ (`m`) の初期化を、パッケージ初期化時ではなく、`ServeMux` インスタンスに初めてハンドラが登録される時点まで遅延させる点にあります。

**変更前:**

```go
// src/net/http/server.go (変更前)

// NewServeMux allocates and returns a new ServeMux.
func NewServeMux() *ServeMux { return &ServeMux{m: make(map[string]muxEntry)} }

// DefaultServeMux is the default ServeMux used by Serve.
var DefaultServeMux = NewServeMux() // ここでNewServeMux()が呼ばれ、マップが即座に作成される
```

変更前は、`DefaultServeMux` がグローバル変数として宣言される際に、`NewServeMux()` が呼び出されていました。`NewServeMux()` は `ServeMux` 構造体を初期化し、その内部マップ `m` を `make(map[string]muxEntry)` によって即座に作成していました。これは「積極的初期化」の典型的な例です。

この積極的初期化の欠点は、`net/http` パッケージをインポートするすべてのプログラムにおいて、たとえ `DefaultServeMux` が全く使われなくても、マップを作成するためのコード（`make` 関数とその関連ランタイムコード）が最終的なバイナリにリンクされてしまうことでした。Goのリンカは、グローバル変数の初期化に使われるコードをデッドコードとは見なしません。

**変更後:**

```go
// src/net/http/server.go (変更後)

// NewServeMux allocates and returns a new ServeMux.
func NewServeMux() *ServeMux { return new(ServeMux) } // マップの初期化は行わない

// DefaultServeMux is the default ServeMux used by Serve.
var DefaultServeMux = &defaultServeMux // ゼロ値のServeMuxを指すポインタ
var defaultServeMux ServeMux           // ゼロ値のServeMux構造体

// (ServeMux).Handle メソッド内に追加されたロジック
func (mux *ServeMux) Handle(pattern string, handler Handler) {
    // ... (既存のロジック) ...

    if mux.m == nil { // マップがまだnilの場合、ここで初めて作成する
        mux.m = make(map[string]muxEntry)
    }
    mux.m[pattern] = muxEntry{explicit: true, h: handler, pattern: pattern}

    // ... (既存のロジック) ...
}
```

変更後では、以下の点が異なります。

1.  **`NewServeMux()` の変更**: `NewServeMux()` は `new(ServeMux)` を返すようになりました。`new(ServeMux)` は `ServeMux` 構造体のゼロ値を割り当て、そのポインタを返します。`ServeMux` 構造体のゼロ値では、マップフィールド `m` は `nil` となります。これにより、`NewServeMux()` が呼び出されても、マップは即座には作成されません。
2.  **`DefaultServeMux` の初期化**: `DefaultServeMux` は `&defaultServeMux` を指すように変更されました。`defaultServeMux` は `ServeMux` 型のグローバル変数であり、Goの仕様によりゼロ値で初期化されます。したがって、`DefaultServeMux` は `m` フィールドが `nil` の `ServeMux` インスタンスを指すことになります。この初期化は、`make` 関数を呼び出さないため、関連するコードがバイナリにリンクされる可能性が低くなります。
3.  **`(*ServeMux).Handle` メソッドでの遅延初期化**: `ServeMux` の `Handle` メソッドに `if mux.m == nil { mux.m = make(map[string]muxEntry) }` というチェックが追加されました。これにより、`ServeMux` インスタンス（`DefaultServeMux` も含む）に初めてハンドラが登録される際に、その内部マップ `m` が `nil` であれば、その時点で初めて `make` を使ってマップが作成されます。

この変更により、`DefaultServeMux` が全く使われないプログラムでは、`make(map[string]muxEntry)` を実行するためのコードがバイナリにリンクされなくなります。これは、Goのリンカが、実際に実行される可能性のあるコードパスのみをバイナリに含めるという最適化をより効果的に行えるようになるためです。結果として、`cmd/go` のような `DefaultServeMux` を使わないバイナリのサイズが削減されます。

`http_test.go` の変更は、この最適化が意図通りに機能していることを検証するためのものです。`cmd/go` バイナリに `net/http.(*ServeMux).ServeHTTP` や `net/http.DefaultServeMux` といったシンボルが含まれていないことを確認することで、`DefaultServeMux` が使われない場合にその関連コードがリンクされていないことをテストしています。

## コアとなるコードの解説

### `src/net/http/server.go` の変更点

1.  **`NewServeMux()` 関数の変更**:
    *   **変更前**: `func NewServeMux() *ServeMux { return &ServeMux{m: make(map[string]muxEntry)} }`
        *   この行は、`ServeMux` 構造体を初期化する際に、その内部マップ `m` を `make` を使って即座に作成していました。
    *   **変更後**: `func NewServeMux() *ServeMux { return new(ServeMux) }`
        *   `new(ServeMux)` は `ServeMux` 型のゼロ値を割り当て、そのポインタを返します。`ServeMux` 構造体のゼロ値では、マップフィールド `m` は `nil` となります。これにより、`NewServeMux()` が呼び出されても、マップの作成は行われなくなりました。

2.  **`DefaultServeMux` グローバル変数の初期化の変更**:
    *   **変更前**: `var DefaultServeMux = NewServeMux()`
        *   `DefaultServeMux` は、パッケージ初期化時に `NewServeMux()` を呼び出すことで初期化されていました。これにより、マップ作成のコードが常にバイナリにリンクされていました。
    *   **変更後**:
        ```go
        var DefaultServeMux = &defaultServeMux
        var defaultServeMux ServeMux
        ```
        *   `defaultServeMux` という `ServeMux` 型の新しいグローバル変数が導入されました。Goの仕様により、グローバル変数はゼロ値で初期化されます。`ServeMux` 構造体のゼロ値では、マップフィールド `m` は `nil` です。
        *   `DefaultServeMux` は、このゼロ値で初期化された `defaultServeMux` のアドレスを指すように変更されました。これにより、`DefaultServeMux` の初期化時に `make` を含む関数呼び出しが行われなくなり、リンカが不要なコードを削除しやすくなりました。

3.  **`(*ServeMux).Handle` メソッドへの遅延初期化ロジックの追加**:
    *   **追加されたコード**:
        ```go
        if mux.m == nil {
            mux.m = make(map[string]muxEntry)
        }
        ```
    *   このコードは、`ServeMux` インスタンス（`DefaultServeMux` も含む）の `Handle` メソッドが呼び出された際に、その内部マップ `m` がまだ `nil` であれば、その時点で初めてマップを作成するようにします。
    *   これにより、`ServeMux` が実際にハンドラを登録するために使われるまで、マップの作成が遅延されます。もし `ServeMux` が全く使われなければ、マップ作成のコードは実行されず、リンカによってバイナリから除外される可能性が高まります。

### `src/net/http/http_test.go` の変更点

*   **追加されたテストシンボル**:
    *   `"net/http.(*ServeMux).ServeHTTP": false,`
    *   `"net/http.DefaultServeMux":       false,`
    *   これらの行は、`cmd/go` バイナリに `net/http.(*ServeMux).ServeHTTP` メソッドや `net/http.DefaultServeMux` グローバル変数が含まれていないことを検証するためのテストケースを追加しています。
    *   このテストは、`DefaultServeMux` が使われない場合に、その関連コードがバイナリから適切に削除されていることを確認する「健全性チェック」として機能します。これにより、バイナリサイズ削減の目的が達成されていることを保証します。

これらの変更は、`DefaultServeMux` の内部マップの初期化を「積極的」から「遅延的」に移行させることで、Goリンカのデッドコードエリミネーションをより効果的に機能させ、結果として `cmd/go` のような特定のバイナリのサイズを削減するという、Goランタイムの最適化戦略の一環です。
