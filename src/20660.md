## 変更の背景

Go 1.4 リリースでは、`go test` コマンドの内部的な挙動が変更されました。以前のバージョンでは、`go test` は `_test.go` ファイル内に `Test` 関数（`TestXxx` の形式の関数）が定義されていない場合、そのファイルをコンパイルおよびリンクの対象から除外することがありました。しかし、この挙動は、テスト関連のユーティリティ関数やヘルパー関数のみを含む `_test.go` ファイルが正しく処理されないという問題を引き起こす可能性がありました。

このコミットは、その内部的な変更を反映し、`go test` がパッケージ内のすべての `_test.go` ファイルを、たとえ `Test` 関数が含まれていなくても、常にコンパイルおよびリンクするようになったことを公式ドキュメント (`doc/go1.4.txt`) に明記するために行われました。これにより、開発者は `_test.go` ファイルにテストロジック以外のコード（例えば、テスト用のデータ構造やヘルパー関数）を安心して配置できるようになり、テストのビルドプロセスの一貫性と予測可能性が向上しました。

## 前提知識の解説

*   **`go test` コマンド**: Go言語の標準テストツールです。`go test` を実行すると、現在のディレクトリまたは指定されたパッケージ内の `_test.go` で終わるファイルを探し、その中の `TestXxx`、`BenchmarkXxx`、`ExampleXxx` などの関数を実行します。
*   **`_test.go` ファイル**: Go言語の慣習として、テストコードはテスト対象のソースファイルと同じパッケージに属し、ファイル名の末尾が `_test.go` となるように配置されます。これにより、通常のビルドからは除外され、`go test` コマンドによってのみコンパイル・実行されます。
*   **コンパイルとリンク**:
    *   **コンパイル**: ソースコード（`.go` ファイル）を機械が理解できるオブジェクトコードに変換するプロセスです。
    *   **リンク**: コンパイルされた複数のオブジェクトファイルやライブラリを結合し、実行可能なプログラムを生成するプロセスです。`go test` の場合、テストコードとテスト対象のコード、および必要なGoランタイムライブラリがリンクされてテスト実行ファイルが作成されます。
*   **CL (Change List)**: Goプロジェクトにおける変更の単位です。GoのコードレビューシステムであるGerritで管理されます。各CLには一意の番号が割り当てられます。このコミットで言及されている `CL 150980043` は、このドキュメント変更の元となった `go test` の挙動変更に関する実際のコード変更を指します。

## 技術的詳細

このコミット自体は、Goコンパイラや `go test` コマンドのソースコードを変更するものではなく、Go 1.4 リリースノートの一部である `doc/go1.4.txt` ファイルに1行追加するものです。

追加された行は以下の通りです。

```diff
+cmd/go: compile and link all _test.go files during 'go test', even in packages where there are no Test functions (CL 150980043)
```

この変更は、`go test` のビルドプロセスにおける重要な挙動変更を明文化しています。以前は、`go test` は `_test.go` ファイルを解析し、`Test` 関数が見つからない場合は、そのファイルをテスト実行ファイルのビルドから除外する最適化を行っていました。しかし、この最適化は、テストヘルパー関数やテストデータ定義など、直接 `Test` 関数を含まないが、他の `_test.go` ファイルから参照される可能性のあるコードを含む `_test.go` ファイルの扱いを複雑にしていました。

Go 1.4 では、この挙動が変更され、`go test` はパッケージ内のすべての `_test.go` ファイルを無条件にコンパイルおよびリンクするようになりました。これにより、テストコードの依存関係がより明確になり、予期せぬビルドエラーや実行時エラーを防ぐことができます。例えば、`test_helper.go` というファイルにテストユーティリティ関数を定義し、`my_test.go` からそれを呼び出す場合、`test_helper.go` に `Test` 関数がなくても、`go test` は両方のファイルを正しくビルドしてリンクするようになります。

この変更は、`go test` の内部実装におけるビルドロジックの簡素化と堅牢化を目的としています。
