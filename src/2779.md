## 変更の背景

Go言語の`container/list`パッケージは、汎用的な双方向連結リストを提供します。このコミットが導入される前は、`List`内の要素数を取得する直接的な方法がありませんでした。リストの長さを知るためには、リストの先頭から末尾まで全ての要素を辿る必要があり、これはリストの要素数に比例する時間（O(N)）を要する操作でした。

多くのデータ構造において、要素数を取得する操作は頻繁に行われます。特に、リストの長さに基づいて条件分岐を行ったり、ループ回数を決定したりする場合、O(N)の操作はパフォーマンスのボトルネックとなる可能性があります。このコミットは、`List`構造体に内部的なカウンタ（`len`フィールド）を追加し、要素の追加・削除時にこのカウンタを更新することで、`Len()`メソッドが定数時間（O(1)）でリストの長さを返せるようにすることを目的としています。これにより、`container/list`パッケージの利便性とパフォーマンスが向上しました。

## 前提知識の解説

### Go言語の`container/list`パッケージ

`container/list`パッケージは、Go言語の標準ライブラリの一部であり、ジェネリックな双方向連結リスト（doubly linked list）の実装を提供します。このリストは、任意の型の値を格納でき、要素の追加、削除、移動などの操作を効率的に行えます。

*   **`List`型**: リスト全体を表す構造体。リストの先頭（`front`）と末尾（`back`）の要素へのポインタを持ちます。
*   **`Element`型**: リスト内の個々の要素を表す構造体。値（`Value`）と、前後の要素へのポインタ（`prev`, `next`）を持ちます。

### 双方向連結リスト (Doubly Linked List)

連結リストは、データ要素（ノード）が順序付けられたシーケンスで構成されるデータ構造です。双方向連結リストは、各ノードが以下の情報を持つ点で単方向連結リストと異なります。

1.  **データ**: ノードが保持する実際の値。
2.  **次へのポインタ (Next Pointer)**: シーケンス内の次のノードを指すポインタ。
3.  **前へのポインタ (Previous Pointer)**: シーケンス内の前のノードを指すポインタ。

この「前へのポインタ」があることで、リストを両方向に辿ることができ、特定のノードが与えられた場合にそのノードをO(1)で削除できるなどの利点があります。

### 計算量 (Time Complexity)

アルゴリズムの効率性を評価する際に用いられる指標です。

*   **O(1) (定数時間)**: 操作にかかる時間が入力サイズに関わらず一定であることを意味します。例えば、配列の特定インデックスへのアクセスや、このコミットで追加される`Len()`メソッドのように、内部カウンタを返す操作などが該当します。
*   **O(N) (線形時間)**: 操作にかかる時間が入力サイズ（N）に比例して増加することを意味します。例えば、連結リストの要素を全て走査して長さを数える操作などが該当します。Nが大きくなると、O(N)の操作はO(1)の操作よりもはるかに時間がかかります。

このコミットの目的は、リストの長さ取得操作をO(N)からO(1)に改善することにあります。

## 技術的詳細

このコミットの主要な変更点は、`container/list`パッケージの`List`構造体に`len`という名前の整数型フィールドを追加し、リストの要素が追加または削除されるたびにこのフィールドを適切に更新することです。そして、この`len`フィールドの値を返す`Len()`メソッドを新しく導入します。

具体的には以下の変更が行われています。

1.  **`List`構造体への`len`フィールドの追加**:
    `List`構造体に`len int;`が追加され、リストの現在の要素数を保持するようになりました。

    ```go
    type List struct {
    	front, back *Element;
    	len int; // 新しく追加されたフィールド
    }
    ```

2.  **`Init()`メソッドでの`len`の初期化**:
    リストを初期化またはクリアする`Init()`メソッド内で、`len`フィールドが`0`に設定されます。これにより、新しいリストやクリアされたリストの長さが正しく`0`から始まることが保証されます。

    ```go
    func (l *List) Init() *List {
    	l.front = nil;
    	l.back = nil;
    	l.len = 0; // lenフィールドの初期化
    	return l
    }
    ```

3.  **要素操作メソッドでの`len`の更新**:
    リストの要素数を変更する以下のメソッドで、`len`フィールドが適切にインクリメントまたはデクリメントされます。
    *   `Remove(e *Element)`: 要素が削除される際に`l.len--`でデクリメントされます。
    *   `insertFront(e *Element)`: リストの先頭に要素が追加される際に`l.len++`でインクリメントされます。
    *   `insertBack(e *Element)`: リストの末尾に要素が追加される際に`l.len++`でインクリメントされます。
    これらの内部ヘルパー関数が`PushFront`や`PushBack`などの公開メソッドから呼び出されるため、間接的に`len`が更新されます。

4.  **`Len()`メソッドの追加**:
    新しく`Len()`メソッドが追加され、`List`構造体の`len`フィールドの値をそのまま返します。これにより、リストの長さをO(1)で取得できるようになります。

    ```go
    func (l *List) Len() int {
    	return l.len
    }
    ```

5.  **テストコードの追加と更新**:
    `src/pkg/container/list/list_test.go`には、`Len()`メソッドの正確性を検証するためのテストコードが追加されています。
    *   `checkListLen`というヘルパー関数が追加され、リストの実際の長さと期待される長さを比較します。
    *   既存のテストケース（`TestList`）内で、リストの操作（`PushFront`, `Remove`など）の後に`checkListLen`が呼び出され、`len`フィールドが正しく更新されていることを確認しています。

これらの変更により、`List`の長さは常に`len`フィールドに保持され、`Len()`メソッドを呼び出すだけで即座に取得できるようになりました。

## コアとなるコードの解説

### `src/pkg/container/list/list.go`

1.  **`List`構造体への`len int;`の追加**:
    これは、リストの現在の要素数を追跡するための新しいフィールドです。このフィールドが存在することで、リストの長さを取得する際に、リスト全体を走査する必要がなくなります。

2.  **`l.len = 0;`の`Init()`メソッドへの追加**:
    `Init()`メソッドはリストを初期状態に戻す役割を担います。この変更により、リストが初期化される際に`len`フィールドも確実に`0`にリセットされ、リストの長さのカウントが正確に開始されるようになります。

3.  **`l.len--;`の`Remove()`メソッドへの追加**:
    `Remove()`メソッドはリストから要素を削除します。要素が一つ削除されるたびに、`len`フィールドをデクリメントすることで、リストの実際の要素数と`len`フィールドの値が一致するように保たれます。

4.  **`l.len++;`の`insertFront()`および`insertBack()`メソッドへの追加**:
    `insertFront()`と`insertBack()`は、それぞれリストの先頭と末尾に新しい要素を追加する内部ヘルパー関数です。新しい要素が追加されるたびに`len`フィールドをインクリメントすることで、リストの実際の要素数と`len`フィールドの値が一致するように保たれます。

5.  **`func (l *List) Len() int { return l.len }`の追加**:
    これがこのコミットの主要な機能追加です。このメソッドは、`List`構造体の内部カウンタである`len`フィールドの値を直接返します。これにより、リストの長さを取得する操作がO(1)の定数時間で実行できるようになり、非常に効率的になります。

### `src/pkg/container/list/list_test.go`

1.  **`func checkListLen(t *testing.T, l *List, n int)`の追加**:
    このヘルパー関数は、テストの可読性と再利用性を高めるために導入されました。`l.Len()`の戻り値と期待される長さ`n`を比較し、一致しない場合はテストエラーを報告します。これにより、`Len()`メソッドの動作検証が簡潔に行えるようになります。

2.  **`checkListLen(t, l, 0);`などの`TestList`内での呼び出し**:
    既存の`TestList`関数内で、リストの初期化、要素の追加、削除などの各操作の後に`checkListLen`が呼び出されています。これにより、`len`フィールドがリストのライフサイクル全体を通じて正確に維持されていることが保証されます。例えば、リストが空のときは`0`、要素が1つ追加されたら`1`、削除されたらその分減少するといった挙動が検証されます。

これらの変更は、`container/list`パッケージの`List`型が、その長さを効率的に報告できる、より堅牢で実用的なデータ構造となることを保証します。
