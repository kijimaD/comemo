## 変更の背景

`go doc` コマンドは、Go言語のパッケージ、シンボル、メソッドのドキュメントを表示するための非常に便利なツールです。しかし、その引数の解釈ルール、特にパッケージが明示されていない場合のシンボル解決や、メソッドの指定方法について、既存のドキュメントでは不明瞭な点がありました。

具体的には、`json.Decode` のように、パッケージ名とシンボル名が結合された形式でメソッドを指す場合に、`go doc` がどのように適切なドキュメント（この場合は `encoding/json.Decoder.Decode`）を見つけるのかがユーザーにとって分かりにくいという問題がありました。Issue #12377 はこのドキュメントの曖昧さを指摘しており、このコミットはその問題を解決するために、`go doc` のヘルプテキストと内部ドキュメントをより詳細かつ正確に記述することを目的としています。

この変更により、ユーザーは `go doc` コマンドの挙動をより深く理解し、意図したドキュメントを効率的に検索できるようになります。

## 前提知識の解説

### `go doc` コマンド

`go doc` は、Go言語の標準ライブラリやユーザーが作成したパッケージのドキュメントをコマンドラインで表示するためのツールです。Goのソースコード内のコメント（特にエクスポートされた識別子に付随するコメント）を解析し、整形された形で出力します。これにより、IDEやWebブラウザを開かずに、必要な情報を素早く参照できます。

### Go言語のパッケージ、シンボル、メソッド

*   **パッケージ (Package)**: Go言語のコードを整理する基本的な単位です。関連する機能や型、関数などをまとめます。例: `fmt`, `net/http`, `encoding/json`。
*   **シンボル (Symbol)**: パッケージ内で定義される名前付きのエンティティです。変数、定数、関数、型などが含まれます。例: `fmt.Println`, `http.Server`, `json.Decoder`。
*   **メソッド (Method)**: 特定の型に関連付けられた関数です。レシーバー引数（`func (r ReceiverType) MethodName(...)` の `r ReceiverType` 部分）を持ちます。例: `json.Decoder` 型の `Decode` メソッド。

### `encoding/json` パッケージと `json.Decoder.Decode` メソッド

`encoding/json` パッケージは、Go言語でJSONデータをエンコード（Goのデータ構造からJSONへ）およびデコード（JSONからGoのデータ構造へ）するための機能を提供します。

*   `json.Decoder`: JSONストリームを読み込み、Goのデータ構造にデコードするための型です。
*   `(*json.Decoder).Decode(v interface{}) error`: `json.Decoder` 型のポインタレシーバーを持つ `Decode` メソッドです。JSONストリームから次のJSONエンコードされた値を読み込み、それを `v` が指す値に格納します。

### `GOROOT` と `GOPATH`

これらはGoの環境変数で、Goのソースコードやパッケージの場所を定義します。

*   **`GOROOT`**: Goのインストールディレクトリを指します。標準ライブラリのソースコードなどがここにあります。
*   **`GOPATH`**: ユーザーが開発するGoプロジェクトのワークスペースを指します。サードパーティのライブラリやユーザー自身のプロジェクトのソースコードがここに配置されます。`go doc` はこれらのパスを検索してドキュメントを見つけます。

## 技術的詳細

このコミットの技術的詳細は、`go doc` コマンドの引数解析とドキュメント検索ロジックの明確化にあります。

1.  **引数形式の拡張**:
    以前は `go doc [<pkg>].<sym>[.<method>]` の形式が示されていましたが、このコミットでは `go doc [<pkg>.][<sym>.]<method>` という形式が追加されました。これは、パッケージ名やシンボル名を省略して直接メソッド名を指定できるケースがあることを示唆しています。特に、`json.decode` のように、パッケージ名とシンボル名が結合された形でメソッドを指す場合にも対応できることを示しています。

2.  **大文字で始まるシンボルの特別な扱い**:
    「However, if the argument begins with a capital letter it is always assumed to be a symbol in the current directory.」という記述が追加されました。これは、`go doc Foo` のように引数が大文字で始まる場合、`go doc` はまずカレントディレクトリ内の `Foo` というシンボルを探すという優先順位を明確にしています。これにより、ユーザーはカレントパッケージのシンボルをより直感的に参照できるようになります。

3.  **`json.Decoder.Decode` の具体的な例**:
    `go doc json.Decoder.Decode`、`go doc json.decoder.decode`、`go doc json.decode`、`cd go/src/encoding/json; go doc decode` の全てが `json.Decoder` の `Decode` メソッドのドキュメントを表示するという具体的な例が追加されました。これは、`go doc` が引数をどのように正規化し、曖昧な指定でも適切なドキュメントにたどり着けるかを示す重要な例です。特に、大文字・小文字を区別しない検索（デフォルト）や、パッケージ名の一部省略、カレントディレクトリからの相対的な指定など、`go doc` の柔軟な挙動を具体的に示しています。

これらの変更は、`go doc` の内部的な挙動そのものを変更するものではなく、その挙動をユーザーに伝えるためのドキュメントを改善するものです。しかし、ドキュメントの改善はツールの使いやすさに直結するため、非常に重要な変更と言えます。
