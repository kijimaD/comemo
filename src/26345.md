# [インデックス 26345] ファイルの概要

このコミットは、Go言語の`net`パッケージにおけるDNS逆引き処理のバグ修正に関するものです。具体的には、Plan 9およびWindows環境において、`net.LookupAddr("127.0.0.1")`が「localhost.」（末尾にドットが付く）ではなく「localhost」を返すように修正されました。この変更は、DNS名における末尾のドットの扱いをより正確にし、特定のOS環境での一貫性を保つことを目的としています。また、この修正に伴い、関連するLookup APIのテストケースがビルド環境で有効化されました。

## 変更の背景

この変更の背景には、Go言語の`net`パッケージが提供するDNS逆引き関数`LookupAddr`の挙動に関する不整合がありました。具体的には、ループバックアドレスである`127.0.0.1`を逆引きした場合、一部のOS（Plan 9とWindows）で「localhost.」という末尾にドットが付いた形式のホスト名が返されることがありました。

DNSの仕様において、ドメイン名の末尾のドットは、そのドメイン名がルートゾーンからの完全修飾ドメイン名（FQDN: Fully Qualified Domain Name）であることを示します。例えば、「www.example.com.」はFQDNですが、「www.example.com」は相対名またはFQDNの省略形として扱われることがあります。しかし、「localhost」のような特殊なホスト名の場合、通常は末尾のドットなしで扱われることが期待されます。

この不整合は、Goの`net`パッケージが内部的に使用していた`ensureEndDot`関数に起因していました。この関数は、与えられたドメイン名に末尾のドットがない場合に強制的に追加する役割を持っていましたが、「localhost」のようなケースではこの挙動が不適切でした。結果として、アプリケーションが「localhost」を期待しているにもかかわらず「localhost.」を受け取ってしまうことで、互換性の問題や予期せぬエラーが発生する可能性がありました。

この問題は、GoのIssue #13564として報告され、このコミットはその修正をPlan 9とWindows環境に適用し、同時にテストカバレッジを向上させることを目的としています。

## 前提知識の解説

### DNS (Domain Name System)
DNSは、インターネット上のコンピュータやサービスを識別するための階層的な分散型命名システムです。人間が覚えやすいドメイン名（例: example.com）と、コンピュータが通信に使うIPアドレス（例: 192.0.2.1）を相互に変換する役割を担っています。

### FQDN (Fully Qualified Domain Name)
FQDNは、ドメイン名の階層構造において、ルートゾーンから始まる完全なパスを示すドメイン名です。FQDNは通常、末尾にドット（`.`）が付くことで、それが絶対的なドメイン名であることを明示します。例えば、「www.example.com.」はFQDNですが、「www.example.com」は文脈によっては相対名として扱われることがあります。

### `net.LookupAddr`
Go言語の標準ライブラリ`net`パッケージが提供する関数の一つで、IPアドレスを受け取り、それに対応するホスト名（ドメイン名）のリストを逆引きで解決します。これはPTRレコード（ポインタレコード）と呼ばれるDNSレコードを利用して行われます。

### `localhost`
`localhost`は、現在のコンピュータ自身を指すために予約されたホスト名です。IPv4アドレスでは`127.0.0.1`、IPv6アドレスでは`::1`に解決されます。通常、ネットワーク設定やアプリケーションのテストなどで、ローカルマシン上のサービスにアクセスするために使用されます。`localhost`は特殊な名前であり、一般的にはFQDNのように末尾にドットが付くことは期待されません。

### Goの`net`パッケージ
Goの`net`パッケージは、TCP/IPネットワークプログラミングのための基本的なインターフェースを提供します。IPアドレスの解決、ポートのリスニング、接続の確立など、様々なネットワーク関連機能が含まれています。DNS解決もこのパッケージの重要な機能の一つです。

### Plan 9 / WindowsにおけるDNS解決
Goの`net`パッケージは、OSのネイティブなDNSリゾルバを利用する場合と、Go自身が実装する純粋なGoリゾルバ（`netgo`モード）を利用する場合があります。OSによってDNS解決の挙動や結果のフォーマットが異なることがあり、特にドメイン名の末尾のドットの扱いはOSやリゾルバの実装に依存することがあります。このコミットは、Plan 9とWindowsのネイティブリゾルバの挙動、またはGoリゾルバがこれらのOSでどのように動作するかに関連する問題を修正しています。

### `internal/testenv`
Goの標準ライブラリには、テスト環境に関するユーティリティを提供する`internal/testenv`パッケージが含まれています。これは、特定の環境（例: CI/CDビルド環境）でのみテストをスキップしたり、特定の条件でテストを有効にしたりするために使用されます。

## 技術的詳細

このコミットの技術的な核心は、ドメイン名の末尾のドットの扱いを修正することにあります。

1.  **`ensureEndDot`関数の削除**:
    以前のコードでは、`ensureEndDot`というヘルパー関数が存在し、これは与えられた文字列（ドメイン名）の末尾にドットがない場合に強制的にドットを追加していました。
    ```go
    // ensureEndDot adds '.' at the end of name unless it is already there.
    func ensureEndDot(name string) string {
    	if name == "" {
    		return "."
    	}
    	if name[len(name)-1] == '.' {
    		return name
    	}
    	return name + "."
    }
    ```
    この関数は、FQDNを扱う際には適切かもしれませんが、「localhost」のように末尾のドットが不要なケースや、DNSリゾルバがすでに適切な形式で名前を返している場合に、誤ってドットを追加してしまう原因となっていました。特に`LookupAddr("127.0.0.1")`が「localhost.」を返す問題は、この関数が「localhost」にドットを追加していたためと考えられます。

2.  **`absDomainName`関数の利用**:
    `ensureEndDot`関数が削除され、代わりに`absDomainName`関数が使用されるようになりました。`absDomainName`関数は`src/net/dnsclient.go`に定義されており、バイトスライスを受け取ります。この関数は、ドメイン名がすでに絶対形式（末尾にドットがある）であるか、または特殊なケース（例: `.`や`localhost`）であるかを適切に判断し、必要に応じて末尾のドットを処理します。
    `absDomainName`の内部ロジックは、DNSのラベルの長さ制限（255オクテット）や、ルートラベル（単一のドット）の扱いなどを考慮し、より厳密にドメイン名の絶対形式を決定します。これにより、「localhost」のような名前に対しては末尾のドットを追加せず、FQDNとして扱われるべき名前に対しては適切にドットを付与する、という正しい挙動が実現されます。

3.  **テストケースの有効化**:
    コミットメッセージにある「Also enables Lookup API test cases on builders.」の通り、`src/net/lookup_test.go`、`src/net/lookup_windows_test.go`、`src/net/non_unix_test.go`のテストコードが変更されています。
    多くのテスト関数で、スキップ条件が`testing.Short() || !*testExternal`から`testing.Short() && testenv.Builder() == "" || !*testExternal`に変更されました。
    *   `testing.Short()`: `-short`フラグが指定された場合にtrueを返します。通常、短時間で実行できるテストのみを実行するために使用されます。
    *   `testenv.Builder() == ""`: これは、現在の環境がGoの公式ビルド環境（CI/CDシステムなど）ではない場合にtrueを返します。
    この変更により、`testing.Short()`がtrueであっても、公式ビルド環境上ではこれらのテストがスキップされなくなります。つまり、ビルド環境では外部ネットワークに依存する可能性のあるLookup API関連のテストが実行されるようになり、テストカバレッジと信頼性が向上しました。

4.  **`forceGoDNS`関数の変更**:
    `src/net/non_unix_test.go`では、`forceGoDNS`関数の実装が変更されました。以前は常に`nil`を返していましたが、このコミットではPlan 9とWindowsの場合に空の関数を返すようになりました。これは、これらのOSでGoのネイティブDNSリゾルバを強制的に使用するためのメカニズムであり、テストがGoリゾルバの挙動を正確に検証できるようにするためのものです。

これらの変更により、Goの`net`パッケージは、DNS名の末尾のドットの扱いに関して、より正確で一貫性のある挙動を提供するようになりました。

## コアとなるコードの解説

このコミットの主要な変更は、`ensureEndDot`関数の削除と、その代わりに`absDomainName`関数を使用することです。

**`ensureEndDot`の削除と`absDomainName`への置き換え:**
`lookup_plan9.go`と`lookup_windows.go`の両方で、`ensureEndDot`関数が削除されました。この関数は、ドメイン名が末尾にドットを持たない場合に強制的にドットを追加する単純なロジックを持っていました。しかし、これは「localhost」のような特殊なケースや、DNSリゾルバがすでに適切な形式で名前を返している場合に、不正確な結果（例: "localhost."）を生み出す原因となっていました。

代わりに、これらのファイル内のDNS関連のルックアップ関数（`lookupSRV`, `lookupMX`, `lookupNS`, `lookupTXT`, `lookupAddr`, `lookupCNAME`など）では、結果のドメイン名を処理する際に`absDomainName([]byte(...))`が呼び出されるようになりました。
`absDomainName`関数は`src/net/dnsclient.go`に定義されており、より洗練されたロジックでドメイン名の絶対形式を処理します。この関数は、バイトスライスとして与えられたドメイン名が、DNSの仕様に則って絶対名であるべきか、そうでないかを判断します。例えば、`localhost`のような名前は末尾にドットが付かないのが一般的であるため、`absDomainName`はこれにドットを追加しません。一方で、FQDNとして扱われるべき名前には適切にドットを付与します。この変更により、DNS解決の結果がより正確で、OSやリゾルバの実装に依存しない一貫した形式で提供されるようになりました。

**テスト条件の変更:**
`lookup_test.go`、`lookup_windows_test.go`、`non_unix_test.go`では、多くのテスト関数でスキップ条件が変更されました。
`if testing.Short() || !*testExternal`
が
`if testing.Short() && testenv.Builder() == "" || !*testExternal`
に変更されました。
これは、Goの公式ビルド環境（`testenv.Builder()`が空でない場合）では、`-short`フラグが指定されていても、外部ネットワークに依存する可能性のあるDNSルックアップテストをスキップしないようにするためのものです。これにより、CI/CD環境でのテストカバレッジが向上し、この種のバグが将来的に再発するのを防ぐための安全網が強化されました。

**`forceGoDNS`の変更:**
`src/net/non_unix_test.go`の`forceGoDNS`関数は、Plan 9とWindows環境でGoのネイティブDNSリゾルバを強制的に使用するための変更が加えられました。これにより、これらのOS上でのテストが、Goリゾルバの挙動を正確に検証できるようになります。

これらのコード変更は、GoのネットワークスタックがDNS名をより正確に処理し、異なるOS環境間での一貫性を高めるための重要な改善です。
