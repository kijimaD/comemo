# [インデックス 23420] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net` パッケージの内部テストユーティリティである `net/internal/socktest` におけるデータ競合（data race）を修正するものです。`socktest` パッケージは、ソケット関連のシステムコールをフックし、テスト中にその挙動を制御・監視するために使用されます。このパッケージは、`net` パッケージの堅牢なテストスイートを構築する上で重要な役割を担っています。

## コミット

`net/internal/socktest` パッケージ内の初期化処理におけるデータ競合を修正し、並行実行環境下での安定性を向上させました。具体的には、`sync.Once` の使用方法を見直し、`Switch` 構造体の初期化がスレッドセーフかつ一度だけ実行されることを保証しています。

## 変更の背景

このコミットは、Go issue #10796 で報告された `net/internal/socktest` パッケージにおけるデータ競合の問題を解決するために行われました。

`socktest.Switch` 構造体は、ソケットのテスト状態を管理するための中心的なコンポーネントです。この構造体には、フィルターテーブル (`fltab`)、ソケットテーブル (`sotab`)、統計情報 (`stats`) など、複数のマップが含まれており、これらは使用前に適切に初期化される必要があります。

元の実装では、`Switch` 構造体の初期化ロジック (`switchInit` 関数) が `sync.Once` を介して呼び出されていましたが、この `sync.Once` の呼び出しが `Switch` のメソッド内で行われる際に、複数のゴルーチンから同時にアクセスされる可能性がありました。特に、`Switch` のフィールド（`fltab`, `sotab`, `stats`）が初期化される前に読み取られる可能性がある状況で、データ競合が発生していました。

データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みである場合に発生します。このような状況は予測不能な動作、プログラムのクラッシュ、または誤った結果を引き起こす可能性があり、並行プログラミングにおいて避けるべき重要な問題です。この特定のケースでは、`Switch` 構造体のマップフィールドが `nil` の状態でアクセスされる可能性があり、パニックを引き起こす原因となっていました。

## 前提知識の解説

### Goにおけるデータ競合 (Data Race)

データ競合は、並行プログラムにおける最も一般的なバグの一つです。Go言語では、以下の3つの条件がすべて満たされたときにデータ競合が発生します。

1.  複数のゴルーチンが同時に同じメモリ位置にアクセスする。
2.  少なくとも1つのアクセスが書き込み操作である。
3.  アクセスが同期メカニズムによって保護されていない。

データ競合が発生すると、プログラムの動作は未定義（undefined behavior）となり、結果としてクラッシュ、不正なデータ、セキュリティ脆弱性など、予測不能な問題を引き起こす可能性があります。Goにはデータ競合を検出するためのツール `go run -race` が用意されており、開発中にこれらの問題を特定するのに役立ちます。

### `sync.Once`

`sync.Once` はGo言語の `sync` パッケージで提供される型で、特定の関数が一度だけ実行されることを保証するために使用されます。これは、リソースの初期化、設定のロード、シングルトンインスタンスの作成など、アプリケーションのライフサイクルで一度だけ実行する必要がある処理に非常に役立ちます。

`sync.Once` の主なメソッドは `Do(f func())` です。複数のゴルーチンが同時に `once.Do(f)` を呼び出した場合でも、`f` は一度だけ実行され、他のゴルーチンは `f` の完了を待ってから処理を続行します。これにより、初期化処理におけるデータ競合を防ぎ、リソースの重複作成を回避できます。

### `net/internal/socktest` パッケージ

`net/internal/socktest` は、Go標準ライブラリの `net` パッケージの内部で使用されるテストユーティリティです。このパッケージは、実際のソケットシステムコールを直接呼び出す代わりに、テスト用のフック（`Switch`）を介してソケット操作をシミュレートまたは制御することを可能にします。これにより、ネットワーク操作を伴うテストをより安定して、予測可能に、そして分離して実行できます。例えば、特定のソケットエラーを注入したり、ソケットのライフサイクルを追跡したりするために使用されます。

## 技術的詳細

このコミットの技術的な核心は、`socktest.Switch` 構造体の初期化ロジックをより堅牢にし、データ競合を排除することにあります。

1.  **`switchInit` 関数のメソッド化**:
    *   元のコードでは、`switchInit(sw *Switch)` という独立した関数が `Switch` 構造体の初期化を行っていました。
    *   変更後、この初期化ロジックは `(sw *Switch) init()` という `Switch` 型のメソッドになりました。
    *   これにより、初期化処理が `Switch` 構造体自体にカプセル化され、コードの可読性と保守性が向上します。

2.  **`sync.Once` の適用箇所の見直し**:
    *   以前は `sw.once.Do(func() { switchInit(sw) })` のように、匿名関数内で `switchInit` を呼び出していました。
    *   このコミットでは、`sw.once.Do(sw.init)` と直接 `Switch` の `init` メソッドを `sync.Once` に渡す形に変更されました。これは機能的には同等ですが、より簡潔な記述です。
    *   **重要な変更点**は、`sw.once.Do(sw.init)` の呼び出しが、`Switch` 構造体のフィールドにアクセスする可能性のある複数のエントリーポイントに追加されたことです。
        *   `Switch.Set` メソッド: フィルターを設定する際に初期化を保証。
        *   `Switch.addLocked` メソッド (Unix/Windows): 新しいソケットステータスを追加する際に初期化を保証。
        *   `Switch.Socket` 関数 (Unix/Windows): ソケットを作成する際に初期化を保証。

3.  **`Switch.Socket` 関数への `sync.Once` 呼び出しの追加**:
    *   特に注目すべきは、`src/net/internal/socktest/sys_unix.go` と `src/net/internal/socktest/sys_windows.go` の `Socket` 関数に `sw.once.Do(sw.init)` が追加された点です。
    *   `Socket` 関数は、ソケットシステムコールをラップしており、`socktest` パッケージが提供する最も基本的なフックの一つです。この関数が呼び出される前に `Switch` が確実に初期化されることで、`fltab` などのマップが `nil` の状態でアクセスされる可能性がなくなります。

4.  **`TestSwitch` の追加**:
    *   `src/net/internal/socktest/main_test.go` に `TestSwitch` という新しいテスト関数が追加されました。
    *   このテストは、複数のゴルーチン (`N = 10`) を並行して起動し、それぞれが `socketFunc` を呼び出すことで、`Switch` 構造体への同時アクセスをシミュレートします。
    *   `socketFunc` は内部で `Switch.Socket` を呼び出すため、このテストは初期化処理におけるデータ競合の発生を検出し、修正が正しく機能していることを検証するためのものです。`sync.WaitGroup` を使用して、すべてのゴルーチンが完了するのを待っています。

これらの変更により、`Switch` 構造体の初期化が、どのゴルーチンから最初にアクセスされたとしても、一度だけ、かつスレッドセーフに実行されることが保証されます。これにより、初期化されていないマップへのアクセスによるデータ競合やパニックが防止されます。

## コアとなるコードの解説

このコミットの主要な変更は、`socktest.Switch` 構造体の初期化が、その構造体のメソッド `init()` を通じて、`sync.Once` によって確実に一度だけ実行されるようにした点です。

1.  **`switchInit` から `init` メソッドへの移行**:
    *   以前はグローバル関数 `switchInit` が初期化を担当していましたが、これを `(sw *Switch) init()` というメソッドにすることで、初期化ロジックが `Switch` インスタンスに直接関連付けられました。これはGoの慣用的なスタイルに沿った変更です。

2.  **`sw.once.Do(sw.init)` の戦略的な配置**:
    *   `sync.Once` の `Do` メソッドは、引数として渡された関数を一度だけ実行することを保証します。複数のゴルーチンが同時に `Do` を呼び出しても、最初の呼び出しだけが関数を実行し、他の呼び出しは最初の呼び出しが完了するまでブロックされます。
    *   このコミットでは、`Switch` 構造体の内部マップ (`fltab`, `sotab`, `stats`) が使用される可能性のある主要なエントリーポイント（`Set`, `addLocked`, `Socket`）の直前に `sw.once.Do(sw.init)` を配置しました。
    *   これにより、`Switch` インスタンスのどのフィールドが最初にアクセスされようとも、そのアクセスが行われる前に `init()` メソッドが確実に呼び出され、すべてのマップが適切に `make` されることが保証されます。
    *   例えば、`Switch.Socket` 関数が複数のゴルーチンから同時に呼び出された場合でも、`sw.once.Do(sw.init)` が `init` メソッドを一度だけ実行し、`fltab` が初期化される前に `sw.fmu.RLock()` や `sw.fltab[FilterSocket]` が実行されることを防ぎます。

3.  **`TestSwitch` による検証**:
    *   追加された `TestSwitch` は、複数のゴルーチンから `socketFunc` (内部で `Switch.Socket` を呼び出す) を並行して実行することで、このデータ競合修正の有効性を検証します。
    *   このテストがデータ競合を報告せずに正常に完了することは、`sync.Once` の適切な使用により、`Switch` の初期化がスレッドセーフに行われていることを示します。

これらの変更は、`socktest` パッケージが並行環境下で安全に動作し、テストの信頼性を高める上で不可欠です。
