## 元コミット内容

`encoding/asn1: Reject invalid INTEGERs.`

`The empty string is not a valid DER integer. DER also requires that values be minimally-encoded, so excess padding with leading 0s (0xff for negative numbers) is forbidden. (These rules also apply to BER, incidentally.)`

`Fixes #12622.`

## 変更の背景

このコミットの背景には、ASN.1 (Abstract Syntax Notation One) のDER (Distinguished Encoding Rules) におけるINTEGER型の厳格なエンコーディング規則への準拠があります。以前の実装では、DERの仕様に反する形式のINTEGER値（例えば、空のバイト列や、冗長なパディングを持つ数値）が誤ってデコードされる可能性がありました。

特に、以下の2つの問題が指摘されていました。

1.  **空のINTEGER**: DERでは、INTEGER値は常に少なくとも1オクテットで表現されなければなりません。空のバイト列は有効なINTEGERではありません。
2.  **最小エンコーディングの違反**: DERは、INTEGER値を表現する際に「最小エンコーディング」を要求します。これは、数値の符号を維持しつつ、可能な限り少ないオクテット数で表現することを意味します。例えば、正の数 `128` は `00 80` とエンコードされますが、もし `80` だけでエンコードすると、2の補数表現では負の数 `-128` と解釈されてしまいます。また、`0` のパディング（正の数で `00` が続く場合）や `FF` のパディング（負の数で `FF` が続く場合）は冗長であり、DERでは許容されません。

これらの問題は、セキュリティプロトコルや証明書などで広く利用されるASN.1データのパースにおいて、潜在的な脆弱性や互換性の問題を引き起こす可能性があります。このコミットは、これらの不正な形式を早期に検出し、エラーを返すことで、`encoding/asn1` パッケージの堅牢性と標準への準拠を強化することを目的としています。

## 前提知識の解説

### ASN.1 (Abstract Syntax Notation One)

ASN.1は、データ構造を記述するための標準的な記法であり、異なるシステム間でデータを交換する際に使用されます。プロトコル定義、特に通信、セキュリティ、ディレクトリサービスなどの分野で広く利用されています。ASN.1自体はデータの抽象的な構造を定義するものであり、具体的なバイト列への変換方法（エンコーディングルール）は別途定義されます。

### DER (Distinguished Encoding Rules)

DERは、ASN.1で定義されたデータ構造をバイト列にエンコードするためのエンコーディングルールの一つです。DERの最大の特徴は、**一意性 (uniqueness)** です。つまり、特定のASN.1値は、DERによって常にただ一つのバイト列にエンコードされ、逆に特定のバイト列はただ一つのASN.1値にデコードされます。この一意性は、デジタル署名やハッシュ計算など、データの同一性が厳密に要求されるセキュリティ関連のアプリケーションで非常に重要です。

DERは、より一般的なBER (Basic Encoding Rules) のサブセットであり、BERが許容する複数のエンコーディング形式の中から、最も厳格で一意な形式を選択するように制約を加えています。

### BER (Basic Encoding Rules)

BERは、ASN.1値をバイト列にエンコードするための最も基本的なルールセットです。BERは柔軟性が高く、同じASN.1値を複数の異なるバイト列で表現することを許容します。例えば、長さのエンコーディング方法や、コンストラクテッドエンコーディングとプリミティブエンコーディングの選択などにおいて、いくつかの選択肢があります。

### INTEGER型のエンコーディング規則 (DER/BER共通の主要なルール)

DERにおけるINTEGER型のエンコーディングには、以下の重要な規則があります。

1.  **2の補数表現**: INTEGER値は、符号付きの2の補数表現でバイト列に変換されます。
2.  **最小オクテット数**: 値を表現するために必要なオクテット数は最小でなければなりません。これは、冗長な先行ゼロ（正の数の場合）や先行FF（負の数の場合）を禁止します。
    *   具体的には、エンコードされたバイト列が複数オクテットで構成される場合、最初のオクテットのすべてのビットが0であるか、または最初のオクテットのすべてのビットが1であることは許されません。
    *   また、最初のオクテットと2番目のオクテットの8ビット目（最上位ビット）が両方とも0であるか、両方とも1であることも許されません。
    *   例: `0` は `00`。`127` は `7F`。`128` は `00 80`（`80` だけだと `-128` と解釈されるため、符号を正に保つために `00` を追加）。`-1` は `FF`。`-128` は `80`。`-129` は `FF 7F`（`7F` だけだと `127` と解釈されるため、符号を負に保つために `FF` を追加）。
3.  **空のバイト列の禁止**: INTEGER値のエンコーディングは、常に少なくとも1オクテットで構成されなければなりません。空のバイト列は有効なINTEGERではありません。

これらの規則は、データの正確な解釈と、一意なエンコーディングを保証するために不可欠です。

## 技術的詳細

このコミットは、`encoding/asn1` パッケージ内のINTEGER型をパースする関数 (`parseInt64`, `parseInt32`, `parseBigInt`) に、DERのエンコーディング規則に準拠しているかをチェックする新しい関数 `checkInteger` を導入することで、不正なINTEGER値を拒否するように変更しています。

`checkInteger` 関数は、以下のロジックでINTEGERバイト列の妥当性を検証します。

1.  **空のバイト列のチェック**:
    *   `len(bytes) == 0` の場合、`StructuralError{"empty integer"}` を返します。これは、DERの規則でINTEGERが少なくとも1オクテットでなければならないという要件に対応します。
2.  **最小エンコーディングのチェック**:
    *   `len(bytes) == 1` の場合は、常に有効とみなされます（1オクテットの数値は常に最小エンコーディングであるため）。
    *   `len(bytes) > 1` の場合、以下の2つの条件をチェックします。
        *   `(bytes[0] == 0 && bytes[1]&0x80 == 0)`: これは、最初のオクテットが `0x00` であり、かつ2番目のオクテットの最上位ビットが `0` である場合を検出します。これは正の数における冗長な先行ゼロのパディングを意味します（例: `00 01` は `01` で表現できる）。
        *   `(bytes[0] == 0xff && bytes[1]&0x80 == 0x80)`: これは、最初のオクテットが `0xff` であり、かつ2番目のオクテットの最上位ビットが `1` である場合を検出します。これは負の数における冗長な先行 `0xff` のパディングを意味します（例: `ff fe` は `fe` で表現できる）。
    *   これらの条件のいずれかに合致する場合、`StructuralError{"integer not minimally-encoded"}` を返します。

`parseInt64`, `parseInt32`, `parseBigInt` の各関数は、実際の数値変換処理の前に `checkInteger` を呼び出し、エラーが返された場合はそのエラーを呼び出し元に伝播させます。これにより、不正な形式のINTEGER値がデコード処理に進むことを防ぎ、早期にエラーを検出できるようになります。

テストコード (`asn1_test.go`) も更新され、空のバイト列や冗長なパディングを持つINTEGER値が正しくエラーとして扱われることを検証するテストケースが追加されています。

## コアとなるコードの解説

### `checkInteger` 関数

この関数は、与えられたバイト列がDERエンコードされたINTEGERとして有効であるかをチェックします。

*   **`if len(bytes) == 0`**:
    *   入力バイト列が空の場合、DERの規則に違反するため、`StructuralError{"empty integer"}` を返します。
*   **`if len(bytes) == 1`**:
    *   入力バイト列が1オクテットの場合、常に最小エンコーディングであるため、有効とみなし `nil` を返します。
*   **`if (bytes[0] == 0 && bytes[1]&0x80 == 0) || (bytes[0] == 0xff && bytes[1]&0x80 == 0x80)`**:
    *   この条件は、冗長なパディングを検出します。
        *   `bytes[0] == 0 && bytes[1]&0x80 == 0`: 最初のオクテットが `0x00` で、かつ2番目のオクテットの最上位ビットが `0` の場合。これは正の数で、`0x00` が冗長であることを示します（例: `00 7F` は `7F` で十分）。
        *   `bytes[0] == 0xff && bytes[1]&0x80 == 0x80`: 最初のオクテットが `0xff` で、かつ2番目のオクテットの最上位ビットが `1` の場合。これは負の数で、`0xff` が冗長であることを示します（例: `FF 80` は `80` で十分）。
    *   これらのいずれかの条件に合致する場合、`StructuralError{"integer not minimally-encoded"}` を返します。

### `parseInt64`, `parseInt32`, `parseBigInt` の変更

これらの関数は、数値のパース処理の前に `checkInteger(bytes)` を呼び出すように変更されました。

*   `err = checkInteger(bytes)` または `if err := checkInteger(bytes); err != nil` の形式で `checkInteger` の結果をチェックします。
*   `checkInteger` がエラーを返した場合、これらのパース関数もそのエラーをそのまま返します。これにより、不正な形式のINTEGERが後続の数値変換ロジックに渡されることを防ぎます。
*   `parseBigInt` は元々 `*big.Int` を返す関数でしたが、エラーを返すようにシグネチャが `(*big.Int, error)` に変更されました。これにより、`checkInteger` からのエラーを適切に伝播できるようになります。

### `parseField` の変更

`parseField` 関数は、`bigIntType` のケースで `parseBigInt` の戻り値が変更されたことに対応して、エラーハンドリングが追加されました。

*   `parsedInt, err1 := parseBigInt(innerBytes)`: `parseBigInt` がエラーを返すようになったため、エラーも受け取るように変更。
*   `if err1 == nil { v.Set(reflect.ValueOf(parsedInt)) }`: エラーがない場合にのみ、パースされた値を `reflect.Value` にセットします。
*   `err = err1`: `parseBigInt` からのエラーを `parseField` の戻り値のエラーに設定します。

### テストコード (`asn1_test.go`) の変更

*   `int64TestData`, `int32TestData`, `bigIntTests` の各テストデータ構造に、期待される結果がエラーであるか (`ok` フィールド) を示すブール値が追加されました。
*   冗長なパディングを持つ `-1` のテストケース (`{[]byte{0xff, 0xff, ...}, true, -1}`) がコメントアウトまたは削除され、代わりに `checkInteger` がエラーを検出するような不正な形式のテストケースが追加されました。
    *   `{[]byte{}, false, 0}`: 空のバイト列がエラーになることを確認。
    *   `{[]byte{0x00, 0x7f}, false, 0}`: 正の数における冗長な先行ゼロがエラーになることを確認。
    *   `{[]byte{0xff, 0xf0}, false, 0}`: 負の数における冗長な先行 `0xff` がエラーになることを確認。
*   テストロジックも、`parseBigInt` がエラーを返すようになったことに対応し、エラーの有無と、エラーがない場合の数値の正確性を検証するように更新されました。

これらの変更により、`encoding/asn1` パッケージはDERのINTEGERエンコーディング規則に厳密に準拠し、不正な形式の入力をより堅牢に処理できるようになりました。
