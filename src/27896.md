# [インデックス 27896] ファイルの概要

このコミットは、Go言語のネットワークパッケージ（`net`）におけるWindows環境でのホスト名およびサービス名の解決方法を近代化するものです。具体的には、古く非推奨となっているWindows API関数である`GetHostByName`と`GetServByName`の使用を廃止し、より新しい`GetAddrInfo`ベースの実装に完全に移行します。これにより、IPv6サポートの強化、スレッドセーフティの向上、および全体的な堅牢性の向上が図られます。

## 変更の背景

この変更の主な背景は、Go 1.6がWindows XP以降のOSを必須要件としたことにあります。これにより、Goランタイムは、それ以前のWindowsバージョンとの互換性を維持するために使用されていた、古く非推奨のネットワークAPIを安全に廃止できるようになりました。

具体的には、`GetHostByName`と`GetServByName`は、以下の点で現代のネットワークプログラミングにおいて問題がありました。

1.  **IPv4のみのサポート**: これらの関数はIPv4アドレスのみを解決し、IPv6をサポートしていませんでした。現代のインターネット環境ではIPv6の利用が拡大しており、IPv6に対応できないAPIは不十分です。
2.  **スレッドセーフティの問題**: これらの関数は、結果をスレッドローカルストレージに格納するため、マルチスレッド環境での同時呼び出しに対してスレッドセーフではありませんでした。Goの並行処理モデルとは相性が悪く、安全に利用するためには`runtime.LockOSThread()`のようなコストのかかる回避策が必要でした。
3.  **機能の制限**: ホスト名からIPアドレスへの解決、サービス名からポート番号への解決といった基本的な機能に限定され、より柔軟な解決オプション（例：特定のアドレスファミリーやソケットタイプを指定する）を提供していませんでした。
4.  **Microsoftによる非推奨化**: Microsoft自身がWindows 2000/XP以降、これらのAPIを`GetAddrInfo`に置き換えることを推奨しており、古いAPIはメンテナンスの対象外となっていました。

Go 1.6でWindows XPが最低要件となったことで、`GetAddrInfo`が利用可能であることが保証され、これらの古いAPIを完全に排除し、より堅牢で現代的なネットワーク解決メカニズムに移行する道が開かれました。

## 前提知識の解説

このコミットを理解するためには、以下のWindowsネットワークAPIに関する知識が不可欠です。

1.  **`GetHostByName`**:
    *   Windows Sockets (Winsock) 1.1 APIの一部として提供されていた関数。
    *   ホスト名（例: "www.example.com"）をIPv4アドレスに解決するために使用されました。
    *   戻り値は`hostent`構造体へのポインタで、この構造体はスレッドローカルストレージに格納されるため、スレッドセーフではありませんでした。
    *   IPv6をサポートしていません。

2.  **`GetServByName`**:
    *   Winsock 1.1 APIの一部。
    *   サービス名（例: "http"）とプロトコル（例: "tcp"）からポート番号を解決するために使用されました。
    *   `GetHostByName`と同様に、戻り値はスレッドローカルストレージに格納される`servent`構造体へのポインタであり、スレッドセーフではありませんでした。

3.  **`GetAddrInfo`**:
    *   Winsock 2 APIの一部として導入された、現代的で推奨されるネットワークアドレス解決関数。
    *   ホスト名とサービス名の両方を解決できます。
    *   IPv4とIPv6の両方をサポートし、プロトコルに依存しないアプリケーション開発を可能にします。
    *   `hints`構造体を使用して、解決の条件（例: IPv4のみ、TCPストリームソケット用など）を細かく指定できます。
    *   結果は`addrinfo`構造体のリンクリストとして返され、スレッドセーフです。
    *   `GetHostByName`や`GetServByName`が抱えていたスレッドセーフティの問題やIPv6非対応の問題を解決します。

4.  **`syscall.LoadGetAddrInfo()`**:
    *   Go言語の`syscall`パッケージで提供される関数で、`GetAddrInfo`関数がOS上で利用可能かどうかを動的にチェックします。
    *   このチェックが成功するということは、OSが`GetAddrInfo`をサポートしていることを意味します。Windows XP以降では常に利用可能です。

5.  **`runtime.LockOSThread()`**:
    *   Goランタイムの関数で、現在のGoルーチンを特定のOSスレッドにロックします。
    *   `GetHostByName`や`GetServByName`のようなスレッドローカルストレージを使用するCライブラリ関数をGoから呼び出す際に、結果の破損を防ぐための回避策として使用されることがあります。しかし、これはGoの並行処理モデルとは異なり、パフォーマンスオーバーヘッドを伴います。

## 技術的詳細

このコミットの技術的詳細は、Goの`net`パッケージがWindows上での名前解決において、古いWinsock 1.1 APIからWinsock 2 APIへの完全な移行を完了した点に集約されます。

以前のGoバージョンでは、`GetAddrInfo`が利用できない可能性のある古いWindowsバージョン（Go 1.6の最低要件より前のバージョン）との互換性を維持するため、`GetAddrInfo`が利用可能な場合は新しい実装（`newLookupIP`, `newLookupPort`）を、そうでない場合は古い実装（`oldLookupIP`, `oldLookupPort`）をフォールバックとして使用するロジックが存在しました。この古い実装は、`GetHostByName`と`GetServByName`を内部的に使用し、スレッドセーフティの問題を回避するために`runtime.LockOSThread()`を使ってGoルーチンをOSスレッドに固定するという複雑な処理を行っていました。

このコミットでは、Go 1.6がWindows XP以降を必須としたことで、`GetAddrInfo`が常に利用可能であることが保証されるようになりました。これにより、条件分岐や古いAPIに基づく複雑なフォールバックロジックが不要となり、コードが大幅に簡素化されました。

具体的には、以下の変更が行われました。

*   `src/net/fd_windows.go`から、`syscall.LoadGetAddrInfo()`の成功に基づいて`lookupPort`と`lookupIP`に`newLookupPort`と`newLookupIP`を割り当てる条件付きロジックが削除されました。これは、`GetAddrInfo`が常に利用可能であるため、この条件分岐が不要になったことを意味します。
*   `src/net/lookup_windows.go`では、`oldLookupPort`と`oldLookupIP`、そしてそれらが内部で使用していた`gethostbyname`と`getservbyname`関数が完全に削除されました。
*   以前は`newLookupIP`と`newLookupPort`として定義されていた関数が、それぞれ`lookupIP`と`lookupPort`に名称変更され、これらがWindows上でのIPアドレスおよびポート番号解決の標準的な実装となりました。これにより、コードベース全体で一貫した、`GetAddrInfo`ベースの解決メカニズムが使用されることになります。

この変更は、Goのネットワークスタックの堅牢性と将来性を向上させ、Windows環境でのIPv6のサポートをよりシームレスにし、スレッドセーフティに関する潜在的なバグのリスクを低減します。

## コアとなるコードの解説

### `src/net/fd_windows.go` の変更

このファイルでは、`sysInit()` 関数内の以下のコードブロックが削除されました。

```go
-	if syscall.LoadGetAddrInfo() == nil {
-		lookupPort = newLookupPort
-		lookupIP = newLookupIP
-	}
```

このコードは、`syscall.LoadGetAddrInfo()` が `nil` でない（つまり、`GetAddrInfo`関数がOSに存在しないか、ロードに失敗した）場合に、`lookupPort`と`lookupIP`というグローバル変数に、それぞれ`newLookupPort`と`newLookupIP`という新しいルックアップ関数を割り当てるという条件付きロジックでした。

このブロックが削除されたということは、Go 1.6の最低要件がWindows XP以降になったことで、`GetAddrInfo`が常に利用可能であることが保証されるようになったため、この条件分岐が不要になったことを意味します。これにより、`lookupPort`と`lookupIP`は常に`GetAddrInfo`ベースの新しい実装を参照するようになります。

### `src/net/lookup_windows.go` の変更

このファイルでは、大幅なコードの削除と関数のリネームが行われました。

1.  **グローバル変数の削除**:
    ```diff
    -var (
    -	lookupPort = oldLookupPort
    -	lookupIP   = oldLookupIP
    -)
    ```
    この変数は、デフォルトで古いルックアップ関数（`oldLookupPort`, `oldLookupIP`）を使用するように設定されていました。上記の`fd_windows.go`の変更と合わせて、この古い実装への参照が完全に削除されました。

2.  **`gethostbyname` 関数の削除**:
    この関数は、Winsock 1.1の`syscall.GetHostByName`をラップし、ホスト名をIPv4アドレスに解決する役割を担っていました。スレッドセーフティの問題を抱えていたため、完全に削除されました。

3.  **`oldLookupIP` 関数の削除**:
    この関数は、`gethostbyname`を使用してIPアドレスを解決する古い実装でした。`GetHostByName`がスレッドセーフではないため、`runtime.LockOSThread()`を使って新しいOSスレッドで実行するという複雑な回避策を講じていました。この関数も、`GetAddrInfo`への移行に伴い削除されました。

4.  **`newLookupIP` から `lookupIP` へのリネーム**:
    ```diff
    -func newLookupIP(ctx context.Context, name string) ([]IPAddr, error) {
    +func lookupIP(ctx context.Context, name string) ([]IPAddr, error) {
    ```
    以前は`newLookupIP`として定義されていた関数が、`lookupIP`にリネームされました。これは、この`GetAddrInfo`ベースの実装が、Windows環境におけるIPアドレス解決の標準的な方法になったことを示しています。

5.  **`getservbyname` 関数の削除**:
    この関数は、Winsock 1.1の`syscall.GetServByName`をラップし、サービス名からポート番号を解決する役割を担っていました。`gethostbyname`と同様に、スレッドセーフティの問題を抱えていたため、完全に削除されました。

6.  **`oldLookupPort` 関数の削除**:
    この関数は、`getservbyname`を使用してポート番号を解決する古い実装でした。`oldLookupIP`と同様に、スレッドセーフティの問題を回避するための複雑なロジックを含んでいました。この関数も削除されました。

7.  **`newLookupPort` から `lookupPort` へのリネーム**:
    ```diff
    -func newLookupPort(ctx context.Context, network, service string) (int, error) {
    +func lookupPort(ctx context.Context, network, service string) (int, error) {
    ```
    以前は`newLookupPort`として定義されていた関数が、`lookupPort`にリネームされました。これも、この`GetAddrInfo`ベースの実装が、Windows環境におけるポート番号解決の標準的な方法になったことを示しています。

これらの変更により、GoのWindowsネットワークスタックは、古いAPIの複雑さと制限から解放され、よりシンプルで効率的、かつ現代的な`GetAddrInfo`ベースの解決メカニズムに完全に移行しました。
