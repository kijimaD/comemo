# [インデックス 22318] ファイルの概要

`src/cmd/internal/ld/pcln.go` はGoコンパイラのリンカの一部であり、Goバイナリに埋め込まれるPC-lineテーブル（`pclntab`）の生成を担当しています。`pclntab`は、プログラムカウンタ（PC）とソースコードの行番号、ファイル名、関数名などの情報をマッピングするために使用され、主にデバッグやプロファイリング、スタックトレースの生成に不可欠なデータ構造です。

## 変更の背景

このコミットの背景には、GoランタイムのPC-lineテーブル（`pclntab`）内に存在する`pcln.frame`というフィールドの扱いにまつわる歴史的な経緯と、将来的な誤用を防ぐという明確な意図があります。

元々、`pcln.frame`はスタックフレームのサイズに関する情報を持つことを意図していた可能性がありますが、コミットメッセージにあるように「値は決して完全に正しくなかった」とされており、実際にはGoランタイムのどの部分もこのフィールドを積極的に利用していませんでした。

しかし、過去のメーリングリストのスレッドで、この`pcln.frame`フィールドをスタックトレースの高速化のために利用しようという提案があったようです。Goのスタックトレースは、デバッグやプロファイリングにおいて非常に重要な機能ですが、その生成には一定のコストがかかります。もし`pcln.frame`がスタックトレースの最適化に利用されることになれば、その不正確な値が問題を引き起こす可能性がありました。

このコミットの目的は、`pcln.frame`が将来的に誤って利用されることを防ぐことにあります。フィールドを完全に削除することが理想的ではありますが、Goのオブジェクトファイルフォーマットのバージョンアップが必要となり、`debug/gosym`のような外部ツールとの互換性が失われるリスクがありました。フォーマットのバージョンアップは、既存のツールやデバッガが新しいバイナリを解析できなくなるという大きな影響を伴います。そのため、完全に削除する代わりに、このフィールドに意図的に「毒となる値」（`0x1234567`）を書き込むことで、その値が有効な情報として扱われないように「ポイズニング（Poisoning）」するという手法が取られました。これにより、このフィールドが利用された場合にすぐに異常を検知できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムおよびコンパイラに関する前提知識が必要です。

### 1. Goのスタックフレームとスタックトレース

Goプログラムが実行される際、各関数呼び出しはスタック上に「スタックフレーム」を生成します。スタックフレームには、関数の引数、ローカル変数、戻りアドレスなどの情報が含まれます。スタックトレースは、現在実行中のゴルーチン（goroutine）の呼び出しスタックを遡り、どの関数がどの関数を呼び出したかを示す一連のスタックフレームのリストです。これはデバッグ時にプログラムの実行パスを理解するために不可欠です。

### 2. PC-lineテーブル (`pclntab`)

Goのバイナリには、`pclntab`（Program Counter-line table）と呼ばれる特殊なデータ構造が埋め込まれています。これは、プログラムカウンタ（PC、実行中の命令のアドレス）と、対応するソースコードのファイル名、行番号、関数名などのシンボリック情報をマッピングするために使用されます。コンパイラは、関数インライン化などの最適化を行うため、PCから直接ソースコード情報を得ることは困難です。`pclntab`は、このマッピングを効率的に行うためのルックアップテーブルとして機能します。`runtime.Frame`のような構造体は、この`pclntab`から情報を抽出し、人間が読める形式でスタックフレーム情報を提供します。

`pclntab`は、GoバイナリのELFファイルでは`.gopclntab`セクションに、Mach-Oファイルでは`__gopclntab`セクションに格納されます。このテーブルは、`pcsp`（PCからスタックポインタの差分）、`pcfile`（PCからファイルインデックス）、`pcln`（PCから行番号）など、複数のサブテーブルで構成されています。

### 3. `debug/gosym`パッケージ

`debug/gosym`パッケージは、Goのバイナリからシンボル情報を読み取るためのGo標準ライブラリの一部です。これには、`pclntab`やその他のデバッグ情報が含まれます。このパッケージは、デバッガやプロファイラ、あるいはカスタムの分析ツールがGoバイナリの内部構造を理解し、シンボリックな情報を抽出するために利用されます。コミットメッセージで言及されているように、`pcln.frame`フィールドを完全に削除すると、この`debug/gosym`のような外部ツールが古いオブジェクトファイルフォーマットを期待している場合に互換性の問題を引き起こす可能性がありました。

### 4. 「ポイズニング（Poisoning）」とは

ソフトウェア開発において「ポイズニング」とは、特定のメモリ領域やデータ構造のフィールドに、意図的に無効な値や、通常ではありえないような特徴的な値を書き込むことを指します。これは、その値が誤って使用された場合に、すぐにクラッシュや明確なエラーを発生させることを目的としています。これにより、潜在的なバグや誤用を早期に発見し、デバッグを容易にすることができます。このコミットでは、`0x1234567`という、アドレスやサイズとしては非常に不自然な値が選ばれています。

## 技術的詳細

このコミットは、Goのリンカ（`src/cmd/internal/ld/pcln.go`）が`pclntab`を構築する際の挙動を変更しています。具体的には、各関数のPC-lineエントリに格納される`frame`フィールドの値を操作しています。

Goのオブジェクトファイルフォーマットには、各関数に関するメタデータが含まれており、その一部として`frame`フィールドが存在していました。このフィールドは、理論的には関数のスタックフレームサイズに関する情報を持つことを意図していたと考えられます。しかし、実際にはこの値は正確に設定されておらず、Goランタイムのどの部分もこの値を信頼して使用していませんでした。

コミットメッセージが示唆するように、このフィールドを完全に削除することが最もクリーンな解決策でした。しかし、Goのバイナリフォーマットは後方互換性を維持する必要があり、特に`debug/gosym`のような既存のツールがこのフィールドの存在を前提としている場合、フォーマットのバージョンアップなしに削除することはできませんでした。フォーマットのバージョンアップは、既存のツールやデバッガが新しいバイナリを解析できなくなるという大きな影響を伴います。

そこで、開発チームは「ポイズニング」という手法を選択しました。これは、`frame`フィールドに`0x1234567`という、明らかに無効で、かつ特定のアドレスやサイズとしてはありえない値を書き込むことを意味します。この値は、もし何らかのコードが誤ってこの`frame`フィールドの値を読み取り、それを有効な情報として利用しようとした場合に、即座にクラッシュや予期せぬ動作を引き起こすように設計されています。これにより、このフィールドの誤用を早期に検出し、開発者に警告を与えることができます。

この変更は、Goランタイムの安定性と保守性を向上させるための予防措置であり、将来的に不正確なデータが原因で発生する可能性のあるバグを防ぐことを目的としています。

## コアとなるコードの解説

このコミットにおける主要な変更は、`src/cmd/internal/ld/pcln.go`ファイル内の`pclntab()`関数に集中しています。この関数は、Goバイナリに埋め込まれるPC-lineテーブル（`pclntab`）を構築する役割を担っています。

変更前は、`pclntab()`関数内で`frameptrsize`という変数が宣言され、関数のスタックフレームサイズに関連する値を計算しようとしていました。具体的には、`Ctxt.Cursym.Locals`（ローカル変数のサイズ）と`frameptrsize`（ポインタのサイズ、リーフ関数では0）を合計して、`pcln.frame`フィールドに書き込んでいました。コミット前のコメントにもあるように、この値は「スタックウォーク中のフォールバックケースでのみ使用される」とされており、その正確性には疑問符が付けられていました。また、「`pcsp`テーブルの方がより正確である」とも述べられており、この`frame`フィールドの役割が既に時代遅れであることが示唆されています。

今回のコミットでは、以下の変更が行われました。

1.  **`frameptrsize`変数の削除**:
    `var frameptrsize int32` の行が削除されました。これは、もはやこの変数が不要になったことを意味します。

2.  **`pcln.frame`フィールドへの値の書き込みロジックの変更**:
    変更の核心は、`off = int32(setuint32(Ctxt, ftab, int64(off), uint32(Ctxt.Cursym.Locals)+uint32(frameptrsize)))` の行が削除され、代わりに `off = int32(setuint32(Ctxt, ftab, int64(off), 0x1234567))` が追加された点です。
    *   `setuint32`関数は、指定されたオフセットに32ビットの符号なし整数を書き込むためのヘルパー関数です。
    *   変更前は、`Ctxt.Cursym.Locals`と`frameptrsize`の合計が`pcln.frame`に書き込まれていました。
    *   変更後は、`0x1234567`という固定値が`pcln.frame`フィールドに書き込まれるようになりました。この値は、前述の「ポイズニング」の概念に基づいています。これは、有効なスタックフレームサイズやアドレスとしてはありえない値であり、もしこのフィールドが誤って読み取られた場合に、すぐに異常を検知できるようにするためのマーカーとして機能します。

新しいコメント `// This has been removed (it was never set quite correctly anyway). // Nothing should use it. // Leave an obviously incorrect value. // TODO: Remove entirely.` は、このフィールドがもはや使用されず、将来的には完全に削除されるべきであるという開発チームの意図を明確に示しています。しかし、既存のツールとの互換性を維持するために、現時点ではフィールドを削除せず、無効な値を書き込むことで対応していることがわかります。
