# [インデックス 21105] ファイルの概要

このコミットは、Goコンパイラのリンカ部分（`liblink`）において、`D_*`定数に対応する文字列配列（`dnames`）を自動生成する機能を追加するものです。特に、`D_*`定数が持つ明示的な初期化子や重複する値といった複雑な特性に対応するためのロジックが導入されています。

## コミット

Goコンパイラのビルドツールである`dist`の一部である`buildgc.c`が更新され、`D_*`定数に対応する`dnames`文字列配列を生成するようになりました。これは、他の列挙型とは異なり、`D_*`定数が明示的な初期化子や重複する値を持つため、より複雑な処理を必要とします。この変更は、これらの定数をより適切に分離することで、将来的にさらにクリーンになることを目指しています。

## 変更の背景

Goコンパイラおよびリンカの内部では、様々な種類の定数が定義されており、これらはコード内で数値として扱われます。しかし、デバッグや可読性のために、これらの数値定数に対応する人間が読める文字列名が必要となる場合があります。例えば、アセンブリ命令（`A_*`）、コンパイラ定数（`C_*`）などには、それぞれ`anames`や`cnames`といった文字列配列が用意され、数値から文字列へのマッピングを提供していました。

`D_*`定数も同様にリンカ内部で使用される重要な定数ですが、他の定数とは異なり、その定義方法に特殊性がありました。具体的には、`D_*`定数には以下のような特徴がありました。

1.  **明示的な初期化子**: `D_FOO = 10`のように、定数に特定の数値が明示的に割り当てられる場合がある。
2.  **重複する値**: 複数の定数が同じ数値を指す場合がある（例: `D_BAR = 20`, `D_BAZ = 20`）。

これらの特性により、単純な連番で文字列配列を生成することが困難でした。このコミット以前は、`D_*`定数に対応する文字列配列が自動生成されていなかったか、手動で管理されており、保守が困難であったと考えられます。この変更の目的は、`D_*`定数についても自動生成メカニズムを導入し、コードの保守性とデバッグのしやすさを向上させることにありました。将来的には、これらの定数の定義方法自体を改善することで、さらにクリーンな解決策を目指すという意図も示されています。

## 前提知識の解説

### Goコンパイラ/リンカのビルドプロセスと`dist`ツール

Goのツールチェインは、Go言語で書かれたプログラムをビルドするために、コンパイラ、アセンブラ、リンカなどの様々なツールを含んでいます。これらのツール自体もGo言語で書かれていますが、そのビルドプロセスの一部にはC言語で書かれた補助ツールが使用されます。

`src/cmd/dist/`ディレクトリには、Goツールチェインのビルドを管理するためのユーティリティが含まれています。`buildgc.c`はその一つで、Goコンパイラやリンカが使用するC言語のソースファイルを生成する役割を担っています。具体的には、Goのソースコードや定義ファイルから、C言語のヘッダファイルや、定数に対応する文字列配列（例: `anames`, `cnames`）を含むCソースファイルを生成します。これにより、Goの内部定数をC言語のコードから参照し、その文字列表現を利用できるようになります。

### `D_*`定数

`D_*`定数は、Goのリンカ（`liblink`）内部で使用される「データ型」や「宣言」に関連する定数です。例えば、シンボルの種類、セクションの種類、アライメントなど、リンカがオブジェクトファイルを処理する際に必要となる様々なメタデータを表現するために使われます。これらの定数は、通常、`src/cmd/5l/5.out.h`（アーキテクチャ依存のリンカヘッダファイル）のようなファイルで定義されています。

### `anames`, `cnames`, `dnames`配列

Goのツールチェインでは、内部で使用される数値定数（例: アセンブリ命令コード、コンパイラ定数）を、人間が読める文字列にマッピングするためのC言語の文字列配列が生成されます。

*   **`anames`**: アセンブリ命令（`A_*`定数）の文字列名を含む配列。
*   **`cnames`**: コンパイラ定数（`C_*`定数）の文字列名を含む配列。
*   **`dnames`**: このコミットで追加された、`D_*`定数の文字列名を含む配列。

これらの配列は、デバッグ時に数値コードから対応する文字列名を表示したり、内部ツールのログ出力などで利用されます。

### `include/link.h`

`include/link.h`は、Goのリンカが使用する共通のヘッダファイルです。リンカのデータ構造、関数プロトタイプ、そして`anames`や`cnames`のような文字列配列の`extern`宣言などが含まれています。このファイルは、リンカの様々な部分で共有される定義を提供します。

## 技術的詳細

このコミットの主要な変更は、`src/cmd/dist/buildgc.c`内の`mkanames`関数に`D_*`定数に対応する`dnames`配列を生成するロジックを追加したことです。

### `buildgc.c`の役割と`mkanames`関数

`buildgc.c`は、Goのビルドプロセスにおいて、特定のヘッダファイル（例: `5.out.h`）を読み込み、そこから定数定義を解析して、対応するC言語のソースファイル（例: `anames5.c`）を生成します。`mkanames`関数は、この処理の中心的な役割を担っています。これまでは`A_*`定数と`C_*`定数に対応する`anames`と`cnames`配列を生成していましたが、このコミットにより`D_*`定数も対象となりました。

### `D_*`定数処理の複雑性への対応

コミットメッセージが指摘するように、`D_*`定数は明示的な初期化子（例: `D_CONST = 10`）や重複する値を持つため、単純なインデックス付けでは文字列配列を生成できません。このコミットでは、以下の方法でこれに対応しています。

1.  **`xatoi`関数の追加**:
    このヘルパー関数は、文字列から整数値を解析するために追加されました。これは、`D_CONST = 10`のような明示的な初期化子から数値`10`を抽出するために使用されます。

    ```c
    static int
    xatoi(char *s, char **end)
    {
        int val = 0;
        for(; *s && *s >= '0' && *s <= '9'; ++s)
            val = val * 10 + (*s - '0');
        *end = s;
        return val;
    }
    ```

2.  **`mkanames`関数の変更**:
    `mkanames`関数内に、`D_*`定数を処理するための新しいループが追加されました。

    *   **`Vec dnames[128];`**: `dnames`という`Vec`（動的配列のようなもの）の配列が宣言されています。これは、`D_*`定数の数値に対応する文字列を一時的に格納するために使用されます。配列のインデックスが`D_*`定数の値に対応し、その要素（`Vec`）には同じ値を持つ複数の定数名が格納される可能性があります（重複する値に対応するため）。
    *   **行の解析**: 入力ファイル（例: `5.out.h`）の各行を走査し、`\tD_`で始まる行（`D_*`定数の定義行）を特定します。
    *   **値の抽出**:
        *   行に`=`が含まれる場合、`xatoi`関数を使用して明示的な初期化子から数値（`n`）を抽出します。
        *   `=`が含まれない場合、`n`は前の定数の値に1を加算したものとして扱われます（連番の場合）。
        *   数値以外の値や、`dnames`配列の範囲を超える値は`unknown`としてスキップされます。
    *   **文字列の格納**: 抽出した数値`n`をインデックスとして、`dnames[n]`の`Vec`に定数名（例: `D_FOO`から`FOO`の部分）を追加します。これにより、同じ数値を持つ複数の定数名が1つの`Vec`に格納されます。
    *   **`dnames`配列の生成**: 全ての`D_*`定数を処理した後、`dnames`配列の各`Vec`を走査し、対応するC言語の文字列配列を生成します。同じ数値を持つ複数の定数名がある場合（例: `[D_BAR] = "BAR/BAZ"`）、それらは`/`で区切られて1つの文字列として結合されます。

### `include/link.h`の変更

`include/link.h`には、新しく生成される`dnames`配列の`extern`宣言が追加されました。これにより、リンカの他のCソースファイルから`dnames`配列を参照できるようになります。

```c
extern  char*   dnames5[];
extern  char*   dnames6[];
extern  char*   dnames8[];
extern  char*   dnames9[];
```
これらの宣言は、Goがサポートする各アーキテクチャ（例: `5`はARM、`6`はAMD64、`8`は386、`9`はPPC64）に対応する`dnames`配列が存在することを示しています。

## コアとなるコードの解説

### `xatoi`関数

この関数は、文字列`s`の先頭から数字を読み取り、整数値に変換します。`end`ポインタは、数字の読み取りが終了した位置を指すように更新されます。これは、`D_CONST = 10`のような形式で定義された定数から、数値`10`を安全に抽出するために使用されます。

### `mkanames`関数内の`D_*`定数処理ロジック

1.  **`Vec dnames[128];`の初期化**:
    `dnames`は`Vec`（動的配列）の配列であり、各`Vec`は特定の数値に対応する`D_*`定数の名前を格納します。`nelem(dnames)`は配列の要素数（この場合は128）を返します。ループで各`Vec`が初期化され、空の状態になります。

2.  **`D_*`定数行の解析ループ**:
    `for(i=0; i<lines.len; i++)`のループは、入力ファイルから読み込まれた各行を処理します。
    *   `if(hasprefix(lines.p[i], "\tD_"))`: 行がタブと`D_`で始まる場合、それは`D_*`定数の定義行であると判断されます。
    *   **行の整形**: 行末のカンマや改行文字をヌル終端に置き換えることで、定数名と値の抽出を容易にします。
    *   **明示的な値の解析**:
        *   `p = xstrstr(lines.p[i], "=");`: 行に`=`が含まれるかを確認します。
        *   `if(p)`ブロック: `=`が存在する場合、その後の文字列から`xatoi`を使って数値を解析し、`n`に格納します。このとき、数値以外の文字が続く場合や、解析に失敗した場合は`unknown`フラグを立ててその定数をスキップします。また、`=`の前の空白文字を削除し、定数名部分をヌル終端します。
        *   `else`ブロック: `=`が存在しない場合、`n`は前の定数の値に1を加算したものとして扱われます。これは、連番で定義されている定数に対応するためです。
    *   **エラーチェックと格納**:
        *   `if(unknown || n >= nelem(dnames)) continue;`: `unknown`フラグが立っている場合や、解析された数値`n`が`dnames`配列の範囲外である場合は、その定数をスキップします。
        *   `p = lines.p[i] + 3;`: 定数名（例: `D_FOO`の`FOO`部分）の開始位置を特定します（`\tD_`の3文字分をスキップ）。
        *   `vadd(&dnames[n], p);`: 抽出した定数名を、対応する数値`n`の`dnames`配列の`Vec`に追加します。これにより、同じ数値を持つ複数の定数名が1つの`Vec`に格納されます。

3.  **`dnames`配列のCソースコード生成ループ**:
    `if(j>0)`ブロックは、`D_*`定数が1つ以上見つかった場合に実行されます。
    *   `char*\tdnames%c[] = {\\n"`: 生成されるC言語の文字列配列の開始部分を出力します。`%c`はアーキテクチャを示す文字（例: `5`, `6`など）に置き換えられます。
    *   `for(i=0; i<nelem(dnames); i++)`: `dnames`配列の各要素を走査します。
    *   `if(dnames[i].len == 0) continue;`: その数値に対応する定数名がない場合はスキップします。
    *   `[D_%s] = \""`: C言語の配列の初期化子として、`[D_定数名] = "文字列"`の形式で出力します。`D_%s`の部分には、その数値に対応する最初の定数名が使用されます。
    *   `for(j=0; j<dnames[i].len; j++)`: 同じ数値を持つ複数の定数名がある場合、それらを`/`で区切って結合します。
    *   `\\",\\n"`: 文字列の終端と改行を出力します。
    *   `};\\n"`: C言語の文字列配列の終端を出力します。

4.  **`dnames`配列の解放**:
    処理の最後に、`for(i=0; i<nelem(dnames); i++) vfree(&dnames[i]);`によって、一時的に使用した`dnames`配列内の各`Vec`が解放されます。

この一連のロジックにより、`D_*`定数の複雑な定義形式（明示的な値、重複する値）に対応しつつ、リンカが利用できるC言語の文字列配列が自動生成されるようになりました。

## 変更の背景

Goコンパイラおよびリンカの内部では、様々な種類の定数が定義されており、これらはコード内で数値として扱われます。しかし、デバッグや可読性のために、これらの数値定数に対応する人間が読める文字列名が必要となる場合があります。例えば、アセンブリ命令（`A_*`）、コンパイラ定数（`C_*`）などには、それぞれ`anames`や`cnames`といった文字列配列が用意され、数値から文字列へのマッピングを提供していました。

`D_*`定数も同様にリンカ内部で使用される重要な定数ですが、他の定数とは異なり、その定義方法に特殊性がありました。具体的には、`D_*`定数には以下のような特徴がありました。

1.  **明示的な初期化子**: `D_FOO = 10`のように、定数に特定の数値が明示的に割り当てられる場合がある。
2.  **重複する値**: 複数の定数が同じ数値を指す場合がある（例: `D_BAR = 20`, `D_BAZ = 20`）。

これらの特性により、単純な連番で文字列配列を生成することが困難でした。このコミット以前は、`D_*`定数に対応する文字列配列が自動生成されていなかったか、手動で管理されており、保守が困難であったと考えられます。この変更の目的は、`D_*`定数についても自動生成メカニズムを導入し、コードの保守性とデバッグのしやすさを向上させることにありました。将来的には、これらの定数の定義方法自体を改善することで、さらにクリーンな解決策を目指すという意図も示されています。

## 前提知識の解説

### Goコンパイラ/リンカのビルドプロセスと`dist`ツール

Goのツールチェインは、Go言語で書かれたプログラムをビルドするために、コンパイラ、アセンブラ、リンカなどの様々なツールを含んでいます。これらのツール自体もGo言語で書かれていますが、そのビルドプロセスの一部にはC言語で書かれた補助ツールが使用されます。

`src/cmd/dist/`ディレクトリには、Goツールチェインのビルドを管理するためのユーティリティが含まれています。`buildgc.c`はその一つで、Goコンパイラやリンカが使用するC言語のソースファイルを生成する役割を担っています。具体的には、Goのソースコードや定義ファイルから、C言語のヘッダファイルや、定数に対応する文字列配列（例: `anames`, `cnames`）を含むCソースファイルを生成します。これにより、Goの内部定数をC言語のコードから参照し、その文字列表現を利用できるようになります。

### `D_*`定数

`D_*`定数は、Goのリンカ（`liblink`）内部で使用される「データ型」や「宣言」に関連する定数です。例えば、シンボルの種類、セクションの種類、アライメントなど、リンカがオブジェクトファイルを処理する際に必要となる様々なメタデータを表現するために使われます。これらの定数は、通常、`src/cmd/5l/5.out.h`（アーキテクチャ依存のリンカヘッダファイル）のようなファイルで定義されています。

### `anames`, `cnames`, `dnames`配列

Goのツールチェインでは、内部で使用される数値定数（例: アセンブリ命令コード、コンパイラ定数）を、人間が読める文字列にマッピングするためのC言語の文字列配列が生成されます。

*   **`anames`**: アセンブリ命令（`A_*`定数）の文字列名を含む配列。
*   **`cnames`**: コンパイラ定数（`C_*`定数）の文字列名を含む配列。
*   **`dnames`**: このコミットで追加された、`D_*`定数の文字列名を含む配列。

これらの配列は、デバッグ時に数値コードから対応する文字列名を表示したり、内部ツールのログ出力などで利用されます。

### `include/link.h`

`include/link.h`は、Goのリンカが使用する共通のヘッダファイルです。リンカのデータ構造、関数プロトタイプ、そして`anames`や`cnames`のような文字列配列の`extern`宣言などが含まれています。このファイルは、リンカの様々な部分で共有される定義を提供します。

## 技術的詳細

このコミットの主要な変更は、`src/cmd/dist/buildgc.c`内の`mkanames`関数に`D_*`定数に対応する`dnames`配列を生成するロジックを追加したことです。

### `buildgc.c`の役割と`mkanames`関数

`buildgc.c`は、Goのビルドプロセスにおいて、特定のヘッダファイル（例: `5.out.h`）を読み込み、そこから定数定義を解析して、対応するC言語のソースファイル（例: `anames5.c`）を生成します。`mkanames`関数は、この処理の中心的な役割を担っています。これまでは`A_*`定数と`C_*`定数に対応する`anames`と`cnames`配列を生成していましたが、このコミットにより`D_*`定数も対象となりました。

### `D_*`定数処理の複雑性への対応

コミットメッセージが指摘するように、`D_*`定数は明示的な初期化子（例: `D_CONST = 10`）や重複する値を持つため、単純なインデックス付けでは文字列配列を生成できません。このコミットでは、以下の方法でこれに対応しています。

1.  **`xatoi`関数の追加**:
    このヘルパー関数は、文字列から整数値を解析するために追加されました。これは、`D_CONST = 10`のような明示的な初期化子から数値`10`を抽出するために使用されます。

    ```c
    static int
    xatoi(char *s, char **end)
    {
        int val = 0;
        for(; *s && *s >= '0' && *s <= '9'; ++s)
            val = val * 10 + (*s - '0');
        *end = s;
        return val;
    }
    ```

2.  **`mkanames`関数の変更**:
    `mkanames`関数内に、`D_*`定数を処理するための新しいループが追加されました。

    *   **`Vec dnames[128];`**: `dnames`という`Vec`（動的配列のようなもの）の配列が宣言されています。これは、`D_*`定数の数値に対応する文字列を一時的に格納するために使用されます。配列のインデックスが`D_*`定数の値に対応し、その要素（`Vec`）には同じ値を持つ複数の定数名が格納される可能性があります（重複する値に対応するため）。
    *   **行の解析**: 入力ファイル（例: `5.out.h`）の各行を走査し、`\tD_`で始まる行（`D_*`定数の定義行）を特定します。
    *   **値の抽出**:
        *   行に`=`が含まれる場合、`xatoi`関数を使用して明示的な初期化子から数値（`n`）を抽出します。
        *   `=`が含まれない場合、`n`は前の定数の値に1を加算したものとして扱われます（連番の場合）。
        *   数値以外の値や、`dnames`配列の範囲を超える値は`unknown`としてスキップされます。
    *   **文字列の格納**: 抽出した数値`n`をインデックスとして、`dnames[n]`の`Vec`に定数名（例: `D_FOO`から`FOO`の部分）を追加します。これにより、同じ数値を持つ複数の定数名が1つの`Vec`に格納されます。
    *   **`dnames`配列の生成**: 全ての`D_*`定数を処理した後、`dnames`配列の各`Vec`を走査し、対応するC言語の文字列配列を生成します。同じ数値を持つ複数の定数名がある場合（例: `[D_BAR] = "BAR/BAZ"`）、それらは`/`で区切られて1つの文字列として結合されます。

### `include/link.h`の変更

`include/link.h`には、新しく生成される`dnames`配列の`extern`宣言が追加されました。これにより、リンカの他のCソースファイルから`dnames`配列を参照できるようになります。

```c
extern  char*   dnames5[];
extern  char*   dnames6[];
extern  char*   dnames8[];
extern  char*   dnames9[];
```
これらの宣言は、Goがサポートする各アーキテクチャ（例: `5`はARM、`6`はAMD64、`8`は386、`9`はPPC64）に対応する`dnames`配列が存在することを示しています。

## コアとなるコードの解説

### `xatoi`関数

この関数は、文字列`s`の先頭から数字を読み取り、整数値に変換します。`end`ポインタは、数字の読み取りが終了した位置を指すように更新されます。これは、`D_CONST = 10`のような形式で定義された定数から、数値`10`を安全に抽出するために使用されます。

### `mkanames`関数内の`D_*`定数処理ロジック

1.  **`Vec dnames[128];`の初期化**:
    `dnames`は`Vec`（動的配列）の配列であり、各`Vec`は特定の数値に対応する`D_*`定数の名前を格納します。`nelem(dnames)`は配列の要素数（この場合は128）を返します。ループで各`Vec`が初期化され、空の状態になります。

2.  **`D_*`定数行の解析ループ**:
    `for(i=0; i<lines.len; i++)`のループは、入力ファイルから読み込まれた各行を処理します。
    *   `if(hasprefix(lines.p[i], "\tD_"))`: 行がタブと`D_`で始まる場合、それは`D_*`定数の定義行であると判断されます。
    *   **行の整形**: 行末のカンマや改行文字をヌル終端に置き換えることで、定数名と値の抽出を容易にします。
    *   **明示的な値の解析**:
        *   `p = xstrstr(lines.p[i], "=");`: 行に`=`が含まれるかを確認します。
        *   `if(p)`ブロック: `=`が存在する場合、その後の文字列から`xatoi`を使って数値を解析し、`n`に格納します。このとき、数値以外の文字が続く場合や、解析に失敗した場合は`unknown`フラグを立ててその定数をスキップします。また、`=`の前の空白文字を削除し、定数名部分をヌル終端します。
        *   `else`ブロック: `=`が存在しない場合、`n`は前の定数の値に1を加算したものとして扱われます。これは、連番で定義されている定数に対応するためです。
    *   **エラーチェックと格納**:
        *   `if(unknown || n >= nelem(dnames)) continue;`: `unknown`フラグが立っている場合や、解析された数値`n`が`dnames`配列の範囲外である場合は、その定数をスキップします。
        *   `p = lines.p[i] + 3;`: 定数名（例: `D_FOO`の`FOO`部分）の開始位置を特定します（`\tD_`の3文字分をスキップ）。
        *   `vadd(&dnames[n], p);`: 抽出した定数名を、対応する数値`n`の`dnames`配列の`Vec`に追加します。これにより、同じ数値を持つ複数の定数名が1つの`Vec`に格納されます。

3.  **`dnames`配列のCソースコード生成ループ**:
    `if(j>0)`ブロックは、`D_*`定数が1つ以上見つかった場合に実行されます。
    *   `char*\tdnames%c[] = {\\n"`: 生成されるC言語の文字列配列の開始部分を出力します。`%c`はアーキテクチャを示す文字（例: `5`, `6`など）に置き換えられます。
    *   `for(i=0; i<nelem(dnames); i++)`: `dnames`配列の各要素を走査します。
    *   `if(dnames[i].len == 0) continue;`: その数値に対応する定数名がない場合はスキップします。
    *   `[D_%s] = \""`: C言語の配列の初期化子として、`[D_定数名] = "文字列"`の形式で出力します。`D_%s`の部分には、その数値に対応する最初の定数名が使用されます。
    *   `for(j=0; j<dnames[i].len; j++)`: 同じ数値を持つ複数の定数名がある場合、それらを`/`で区切って結合します。
    *   `\\",\\n"`: 文字列の終端と改行を出力します。
    *   `};\\n"`: C言語の文字列配列の終端を出力します。

4.  **`dnames`配列の解放**:
    処理の最後に、`for(i=0; i<nelem(dnames); i++) vfree(&dnames[i]);`によって、一時的に使用した`dnames`配列内の各`Vec`が解放されます。

この一連のロジックにより、`D_*`定数の複雑な定義形式（明示的な値、重複する値）に対応しつつ、リンカが利用できるC言語の文字列配列が自動生成されるようになりました。
