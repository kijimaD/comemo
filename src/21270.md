# [インデックス 21270] ファイルの概要

このコミットは、Go言語の`net/http`パッケージにおいて、`Transport`構造体の`DisableKeepAlives`オプションが有効になっている場合に、HTTPリクエストに`Connection: close`ヘッダーを自動的に追加するように変更するものです。これにより、キープアライブが無効な接続において、サーバー側が接続を適切に閉じることを保証し、リソースの無駄な消費や予期せぬ動作を防ぎます。

## 元コミット内容

このコミットは、`net/http`パッケージの`Transport`が`DisableKeepAlives`設定時に`Connection: close`ヘッダーを送信するように変更します。この変更は、既存のバグ報告に基づいて行われたものではなく、コミッター自身が以前から疑っていた動作を調査した結果として実装されました。

## 変更の背景

HTTP/1.1では、デフォルトで接続の再利用（キープアライブ）が有効になっています。これにより、複数のリクエストとレスポンスを同じTCP接続上で送受信でき、接続確立のオーバーヘッドを削減し、パフォーマンスを向上させます。しかし、特定のシナリオでは、キープアライブを無効にしたい場合があります。例えば、サーバーが接続をすぐに閉じることが期待される場合や、クライアントが多数の異なるサーバーに短期間で接続する場合などです。

Goの`net/http.Transport`には、`DisableKeepAlives`というフィールドがあり、これを`true`に設定すると、クライアントはサーバーとのキープアライブ接続を試みなくなります。しかし、この設定だけでは、クライアントが接続を再利用しないことをサーバーに明示的に伝えるための`Connection: close`ヘッダーが自動的に送信されませんでした。

この状況では、クライアントが接続を再利用しない意図であっても、サーバーはデフォルトのキープアライブ動作に従い、接続をオープンに保とうとする可能性があります。これにより、サーバー側で不要なリソース（ファイルディスクリプタ、メモリなど）が消費され続けたり、タイムアウトするまで接続が維持されたりする問題が発生する可能性がありました。特に、大量の短命な接続を生成するクライアントの場合、サーバー側のリソース枯渇につながる恐れがありました。

このコミットは、`DisableKeepAlives`が`true`の場合に`Connection: close`ヘッダーを送信することで、クライアントの意図をサーバーに明確に伝え、サーバーがリクエスト処理後に速やかに接続を閉じることができるようにし、上記の問題を解決することを目的としています。

## 前提知識の解説

### HTTP/1.1の持続的接続 (Persistent Connections / Keep-Alive)

HTTP/1.1では、TCP接続を再利用する「持続的接続」がデフォルトで有効です。これは「HTTP Keep-Alive」とも呼ばれます。
- **目的**: 各HTTPリクエスト/レスポンスごとに新しいTCP接続を確立・切断するオーバーヘッド（TCPスリーウェイハンドシェイク、TLSハンドシェイクなど）を削減し、Webページのロード時間を短縮し、サーバーの負荷を軽減します。
- **動作**: クライアントがサーバーにリクエストを送信し、レスポンスを受け取った後も、TCP接続はすぐに閉じられず、次のリクエストのために開いたままになります。クライアントは同じ接続を使って後続のリクエストを送信できます。
- **ヘッダー**: HTTP/1.1では、明示的に`Connection: close`ヘッダーが指定されない限り、持続的接続がデフォルトで期待されます。HTTP/1.0では、`Connection: Keep-Alive`ヘッダーを送信することで持続的接続を要求していました。

### `Connection: close` ヘッダー

`Connection: close`ヘッダーは、HTTPメッセージの送信者が、現在の接続がこのトランザクションの完了後に閉じられるべきであることを受信者に通知するために使用されます。
- **クライアントからサーバーへ**: クライアントが`Connection: close`を送信すると、そのリクエストのレスポンスを受け取った後、クライアントは接続を閉じます。サーバーもこのヘッダーを受け取ると、レスポンスを送信した後に接続を閉じるべきだと理解します。
- **サーバーからクライアントへ**: サーバーが`Connection: close`を送信すると、そのレスポンスを送信した後、サーバーは接続を閉じます。クライアントもこのヘッダーを受け取ると、レスポンスを受け取った後に接続を閉じるべきだと理解します。
- **重要性**: このヘッダーは、持続的接続のデフォルト動作を上書きし、接続の明示的な終了を指示するために不可欠です。

### Goの `net/http.Transport`

`net/http.Transport`は、GoのHTTPクライアント（`http.Client`）が実際にHTTPリクエストを送信し、レスポンスを受信する際の低レベルな詳細を処理する構造体です。これには、TCP接続の確立、TLSハンドシェイク、プロキシの処理、接続の再利用（キープアライブ）、リクエストの多重化などの機能が含まれます。
- **`DisableKeepAlives`フィールド**: `Transport`構造体のブール型フィールドです。これを`true`に設定すると、`Transport`はHTTPキープアライブを無効にし、各リクエスト後に接続を再利用しようとしなくなります。これは、クライアントが各リクエスト後に新しい接続を確立することを意味します。

## 技術的詳細

このコミットの技術的な核心は、`net/http.Transport`の`DisableKeepAlives`が`true`に設定されている場合に、クライアントが送信するHTTPリクエストヘッダーに`Connection: close`を明示的に追加することです。

従来の`DisableKeepAlives = true`の動作では、Goクライアントは接続を再利用しないように内部的に動作していましたが、その意図をHTTPヘッダーを通じてサーバーに伝えていませんでした。HTTP/1.1の仕様では、`Connection: close`ヘッダーがない場合、サーバーはデフォルトで接続をキープアライブ状態に保とうとします。

この不整合により、以下のような問題が発生する可能性がありました。
1.  **サーバー側のリソース消費**: クライアントが接続を閉じても、サーバーはクライアントが接続を再利用するかもしれないと期待して、一定期間（通常はタイムアウトするまで）接続をオープンに保ち続けます。これにより、サーバーのファイルディスクリプタやメモリなどのリソースが不必要に消費されます。特に、短命な接続が大量に発生するシナリオでは、サーバーのリソース枯渇やパフォーマンス低下につながる可能性があります。
2.  **予期せぬ動作**: サーバーが接続を閉じないことで、クライアントが新しい接続を確立した後に、古い接続がまだ開いているために予期せぬネットワーク動作やエラーが発生する可能性もゼロではありませんでした。

このコミットによって、`DisableKeepAlives = true`の場合に`Connection: close`ヘッダーが追加されることで、以下のようになります。
-   **クライアントの意図の明確化**: クライアントは「このリクエストの処理後、接続を閉じてください」という明確なシグナルをサーバーに送ります。
-   **サーバーの適切な応答**: サーバーはこのヘッダーを受け取ると、レスポンスを送信した後に速やかに接続を閉じることができます。これにより、サーバー側のリソースが効率的に解放され、不要な接続の維持が回避されます。
-   **リソース効率の向上**: 特に、短期間で多数のHTTPリクエストを異なるエンドポイントに送信するようなアプリケーションにおいて、サーバーとクライアント双方のリソース効率が向上します。

この変更は、HTTPプロトコルのセマンティクスに沿ったものであり、`DisableKeepAlives`オプションの意図を完全に実現するために必要な修正と言えます。

## コアとなるコードの解説

### `src/net/http/transport.go` の変更

-   **追加されたコード**:
    ```go
    +	if pc.t.DisableKeepAlives {
    +		req.extraHeaders().Set("Connection", "close")
    +	}
    ```
-   **解説**:
    この変更は、`persistConn`構造体の`roundTrip`メソッド内で行われています。`persistConn`は、単一のHTTP接続を管理し、その接続上でリクエストを送信する役割を担います。
    `pc.t`は、この`persistConn`が属する`Transport`インスタンスを指します。
    `pc.t.DisableKeepAlives`が`true`である場合、つまり、この`Transport`がキープアライブを無効にするように設定されている場合に、`req.extraHeaders().Set("Connection", "close")`が実行されます。
    これは、送信されるHTTPリクエストのヘッダーに`Connection: close`を追加することを意味します。これにより、クライアントはサーバーに対して、このリクエストの処理が完了した後に接続を閉じるべきであることを明示的に伝えます。
