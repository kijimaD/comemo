## 変更の背景

このコミットの背景には、Goコンパイラの呼び出し方法の変更があります。以前のGoツールチェーンでは、コンパイラは `go tool 6g` (amd64の場合)、`8g` (386の場合) のように、ターゲットアーキテクチャを示す文字（`GOCHAR`）をツール名に含んでいました。しかし、Go 1.5のリリースに向けて、`go tool compile` という統一されたコマンドに移行されました。この移行により、コンパイラを呼び出す際にアーキテクチャ固有の文字を指定する必要がなくなり、ツールチェーンの使い方が簡素化されました。

`test/nosplit.go` は、特定の関数がスタック分割（stack split）を行わないことを検証するためのテストファイルです。このテスト内で、コンパイラのバージョン情報を取得するために `go tool compile -V` のようなコマンドが実行されていました。移行前のコードでは、このコマンドを構築する際に `GOCHAR` 環境変数の値を取得し、`go tool <GOCHAR>g -V` の形式で使用していました。しかし、`go tool compile` への移行後、この `GOCHAR` を取得して使用するロジックは不要となり、デッドコード（到達不能コード）となっていました。このコミットは、そのデッドコードを削除し、テストコードを新しい `go tool compile` の呼び出し方法に合わせることを目的としています。

## 前提知識の解説

*   **Goツールチェーンとコンパイラ**: Go言語のプログラムをビルドするために使用される一連のツール群です。主要なツールの一つがコンパイラで、Goのソースコードを機械語に変換します。

*   **`go tool compile`**: Go 1.5以降で推奨されるコンパイラの呼び出し方法です。以前は `go tool 6g` (amd64), `go tool 8g` (386), `go tool 5g` (arm) のように、ターゲットアーキテクチャを示す文字（`GOCHAR`）がツール名に含まれていました。
*   **`GOCHAR` 環境変数**: 以前のGoツールチェーンで、ターゲットアーキテクチャに対応する文字（例: `6` for amd64, `8` for 386, `5` for arm）を示すために使用されていた環境変数です。`go tool compile` への移行後は、その直接的な利用はほとんどなくなりました。
*   **スタック分割 (Stack Split)**: Goランタイムの重要な機能の一つで、Goルーチンが実行中にスタック領域を使い果たしそうになったときに、自動的にスタックを拡張するメカニズムです。これにより、Goルーチンは非常に小さなスタックで開始でき、必要に応じて動的に成長させることができます。
*   **`nosplit`**: Goの関数に適用されるディレクティブ（またはコンパイラによって自動的に付与される属性）で、その関数がスタック分割を行わないことを示します。これは、非常に短い関数や、スタック分割のオーバーヘッドが許容できない低レベルのランタイムコードでよく使用されます。`nosplit` 関数は、呼び出し元が十分なスタック空間を持っていることを前提とします。
*   **`test/nosplit.go`**: Goのテストスイート内のファイルで、`nosplit` とマークされた関数が実際にスタック分割を行わないことを検証するためのテストが含まれています。これは、Goランタイムの安定性と正確性を保証するために重要です。

## 技術的詳細

変更前の `test/nosplit.go` の `main` 関数内では、`go tool compile -V` コマンドを実行する前に、`go env GOCHAR` を実行して `GOCHAR` の値を取得していました。

```go

	if gochar, err := exec.Command("go", "env", "GOCHAR").Output(); err != nil {
		bug()
		fmt.Printf("running go env GOCHAR: %v\\n", err)
		return
	} else {
		thechar = strings.TrimSpace(string(gochar))
	}

	version, err := exec.Command("go", "tool", "compile", "-V").Output()
	if err != nil {
		bug()
		fmt.Printf("running go tool %sg -V: %v\\n", thechar, err) // ここで thechar を使用
		return
	}
```

このコードは、`GOCHAR` の値（例えば `6`）を取得し、エラーメッセージのフォーマット文字列 `running go tool %sg -V: %v\\n` に挿入して `running go tool 6g -V: ...` のようなメッセージを生成していました。

しかし、Go 1.5で `go tool compile` が導入されたことにより、コンパイラを呼び出す際のコマンドは `go tool compile` となり、アーキテクチャ固有の文字は不要になりました。したがって、`thechar` 変数を取得するロジック全体が不要となり、エラーメッセージのフォーマットも `running go tool compile -V: %v\\n` に変更されるべきでした。

このコミットは、このデッドコードを特定し、削除することで、テストコードの簡潔性と正確性を向上させています。`exec.Command("go", "env", "GOCHAR").Output()` の呼び出しは、もはや意味をなさず、実行されるべきではありません。また、エラーメッセージも新しいコンパイラ呼び出しに合わせることで、将来的なデバッグの際に誤解を招く可能性を排除しています。
