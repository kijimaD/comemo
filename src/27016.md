## 変更の背景

Goコンパイラの進化に伴い、内部データ構造の設計も改善されてきました。`nodesOrNodeListPtr` は、おそらく過去のGoコンパイラでASTノードのリストを柔軟に扱うために導入された型であると推測されます。しかし、このような柔軟な型は、コンパイラの複雑な処理において型安全性の問題を引き起こしたり、コードの意図を不明瞭にしたりする可能性があります。

`syntax.go` はGoコンパイラのASTノード定義や基本的な操作を扱うファイルであり、`nodesOrNodeListPtr` のような低レベルな抽象化が許容される場合があります。しかし、それ以外のコンパイラパス（例: `walk`、`sinit`、`racewalk` など）では、より明確で型安全なインターフェースが求められます。

このコミットは、`nodesOrNodeListPtr` の使用を `syntax.go` に限定することで、コンパイラの他の部分での型安全性を高め、コードの理解を容易にすることを目的としています。関連するIssue `#14473` は、このリファクタリングの必要性を示唆している可能性があります。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

`cmd/compile` はGo言語の公式コンパイラであり、Goのソースコードを機械語に変換する役割を担っています。コンパイラは複数のフェーズ（字句解析、構文解析、型チェック、中間表現生成、最適化、コード生成など）を経て処理を進めます。

### 抽象構文木 (AST: Abstract Syntax Tree)

ASTは、ソースコードの構文構造を木構造で表現したものです。コンパイラはソースコードをASTに変換し、このASTを操作しながら様々な解析や変換を行います。Goコンパイラでは、ASTの各ノードは `Node` 構造体で表現されます。

### `Node` 構造体

Goコンパイラ内部の `Node` 構造体は、ASTの各要素（変数、関数呼び出し、演算子、リテラルなど）を表します。各 `Node` は、その種類（`Op`）、型情報（`Type`）、子ノードへの参照（`Left`, `Right`, `List`, `Ninit`, `Nbody` など）といった情報を持っています。

### `NodeList` と `Nodes`

Goコンパイラでは、複数の `Node` をリストとして扱うためのデータ構造が存在します。
- `NodeList`: 以前のGoコンパイラで使われていた、連結リスト形式のノードリスト。
- `Nodes`: 現在のGoコンパイラで推奨されている、スライス（`[]*Node`）をラップしたノードリスト。`Nodes` 型は、ノードの追加や操作のためのメソッドを提供し、より効率的で型安全なリスト操作を可能にします。

### `nodesOrNodeListPtr` (旧型)

このコミットで削除対象となっている `nodesOrNodeListPtr` は、`NodeList` または `Nodes` のいずれかを指すことができるような、より抽象的なポインタ型であったと推測されます。これは、異なるリスト実装を透過的に扱えるようにするためのものでしたが、その柔軟性が逆に型チェックを複雑にし、コンパイラの他の部分での誤用を招く可能性がありました。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの内部でASTノードのリストを表現する方法を、より厳密で効率的なものに統一することにあります。

1.  **型安全性の向上**: `nodesOrNodeListPtr` のような抽象的なポインタ型は、コンパイラのコードベース全体でその実体が `NodeList` なのか `Nodes` なのかを常に意識する必要がありました。これは、コンパイラの開発者にとって負担となり、誤った型アサーションやキャストによるランタイムエラーのリスクを高めます。`*Nodes` に統一することで、コンパイラの各パスは常に `Nodes` 型のセマンティクスに基づいてコードを記述できるようになり、コンパイル時の型チェックによって多くのエラーを早期に検出できるようになります。

2.  **コードの明確化と保守性**: `*Nodes` 型は、Goのスライスをラップした構造体であり、`Append` や `AppendNodes` といった明確なメソッドを提供します。これにより、ノードリストの操作がより直感的になり、コードの意図が明確になります。また、`NodeList` のような連結リスト構造は、スライスに比べてメモリの局所性が低く、パフォーマンス上のオーバーヘッドが発生する可能性があります。`Nodes` を使用することで、Goのスライスの効率的なメモリ管理と操作の恩恵を受けることができます。

3.  **`syntax.go` への責任の集中**: `syntax.go` はGoコンパイラのASTの基本的な定義と操作をカプセル化する役割を担っています。`nodesOrNodeListPtr` のような低レベルな抽象化をこのファイルに限定することで、コンパイラの他の部分がこれらの実装詳細に依存するのを防ぎ、モジュール性を高めます。

4.  **`toolstash -cmp` の通過**: コミットメッセージにある `Passes toolstash -cmp` は、この変更がコンパイラの出力（生成されるバイナリコード）に影響を与えないことを意味します。これは、リファクタリングが機能的な変更ではなく、内部実装の改善であることを保証する重要なテストです。

具体的には、多くの関数シグネチャが `init nodesOrNodeListPtr` から `init *Nodes` に変更されています。これに伴い、ノードリストへの追加操作も `appendNodeSeqNode(init, a)` や `appendNodeSeq(init, n.Ninit)` のようなヘルパー関数から、`init.Append(a)` や `init.AppendNodes(&n.Ninit)` のような `Nodes` 型のメソッド呼び出しに置き換えられています。

	case n2.slice == nil:
	case n.slice == nil:
		n.slice = n2.slice
	default:
		*n.slice = append(*n.slice, *n2.slice...)
	}

}

具体的には、多くの関数シグネチャが `init nodesOrNodeListPtr` から `init *Nodes` に変更されています。これに伴い、ノードリストへの追加操作も `appendNodeSeqNode(init, a)` や `appendNodeSeq(init, n.Ninit)` のようなヘルパー関数から、`init.Append(a)` や `init.AppendNodes(&n.Ninit)` のような `Nodes` 型のメソッド呼び出しに置き換えられています。

func (n *Nodes) AppendNodes(n2 *Nodes) {
	switch {
	case n2.slice == nil:
	case n.slice == nil:
		n.slice = n2.slice

	}

}

## コアとなるコードの解説

このコミットの主要な変更は、Goコンパイラの内部でASTノードのリストを扱うためのデータ構造とAPIの統一です。

1.  **`nodesOrNodeListPtr` から `*Nodes` への移行**:
    - 以前は、`nodesOrNodeListPtr` という型が、`NodeList` (連結リスト) または `Nodes` (スライスをラップした構造体) のいずれかを指すポインタとして使用されていました。これは柔軟性を提供しましたが、型安全性が低く、コードの理解を難しくしていました。
    - このコミットでは、`syntax.go` 以外のすべてのファイルで `nodesOrNodeListPtr` の使用を廃止し、より明確で型安全な `*Nodes` 型に統一しました。`*Nodes` は、Goのスライス `[]*Node` を内部に持ち、ノードリストの操作をカプセル化します。

2.  **`Nodes.AppendNodes` メソッドの導入**:
    - `syntax.go` に `func (n *Nodes) AppendNodes(n2 *Nodes)` という新しいメソッドが追加されました。
    - このメソッドは、`n2` の持つノードスライスを `n` のノードスライスに効率的に追加し、その後 `n2` をクリアします。これにより、複数の `Nodes` オブジェクトを結合する際のコードが簡潔になり、メモリ効率も向上します。

3.  **ノードリスト操作の変更**:
    - `appendNodeSeqNode` や `appendNodeSeq` のような、以前の `NodeList` や `nodesOrNodeListPtr` に対応するヘルパー関数は、`Nodes` 型のメソッド (`init.Append(a)`, `init.AppendNodes(&n.Ninit)`) に置き換えられました。
    - `walkstmtlist` や `walkexprlist` のような、ノードリストを走査する関数も、引数を `nodesOrNodeList` から `[]*Node` または `*Nodes` に変更し、内部のイテレーションロジックもそれに合わせて修正されました。これにより、スライスベースの操作が直接行われるようになり、オーバーヘッドが削減されます。

これらの変更により、Goコンパイラの内部コードはより一貫性があり、型安全で、保守しやすくなりました。特に、コンパイラの各パスがASTノードリストを扱う際に、`Nodes` 型の明確なインターフェースを通じて操作できるようになり、開発者がコードの意図をより容易に理解できるようになります。
