## 変更の背景

この変更は、GoのIssue #12907 に対応するものです。このIssueでは、`GOBIN`環境変数に相対パスが設定されている場合に、`go install`コマンドの動作がユーザーにとって混乱を招く可能性があるという問題が提起されていました。

具体的には、`GOBIN`が相対パスである場合、`go install`が実行されるカレントディレクトリによって、バイナリのインストール先が変動してしまいます。これは、ビルドシステムやスクリプト内で`go install`を使用する際に、予期せぬ場所に実行ファイルが生成されたり、パス解決の問題を引き起こしたりする原因となります。

Goの設計思想として、ビルドやインストールに関する挙動は予測可能で一貫しているべきであるという考えがあります。`GOBIN`に相対パスを許可することは、この一貫性を損なう可能性があったため、明確に絶対パスのみを受け入れるようにすることで、ユーザーの混乱を防ぎ、より堅牢なビルドプロセスを保証することが目的とされました。

## 前提知識の解説

### Goの環境変数 `GOBIN`

`GOBIN`はGo言語の環境変数の一つで、`go install`コマンドによってビルドされた実行可能バイナリがインストールされるディレクトリを指定します。

*   **`GOBIN`が設定されていない場合**: `go install`は、`GOPATH`環境変数で指定されたワークスペースの`bin`ディレクトリ（例: `$GOPATH/bin`）にバイナリをインストールします。
*   **`GOBIN`が設定されている場合**: `go install`は、`GOBIN`で指定されたディレクトリにバイナリをインストールします。このディレクトリは、通常、ユーザーの`PATH`環境変数に追加され、どこからでもコマンドを実行できるようにします。

### 絶対パスと相対パス

*   **絶対パス (Absolute Path)**: ファイルシステム上のルートディレクトリから始まる完全なパスです。例えば、Linux/macOSでは`/home/user/bin`、Windowsでは`C:\Users\user\bin`のような形式です。どのディレクトリから参照しても、常に同じ場所を指します。
*   **相対パス (Relative Path)**: 現在の作業ディレクトリ（カレントディレクトリ）を基準としたパスです。例えば、`./bin`や`../local/bin`のような形式です。カレントディレクトリが変わると、指し示す場所も変わります。

### `go install`コマンド

`go install`コマンドは、Goのソースコードをコンパイルし、その結果生成された実行可能バイナリを`GOBIN`（または`GOPATH/bin`）にインストールするコマンドです。通常、プロジェクトのルートディレクトリで実行され、依存関係の解決やビルド、そして最終的なバイナリの配置までを一貫して行います。

## 技術的詳細

このコミットの技術的な変更は、主に以下の3つの側面から構成されています。

1.  **`go install`コマンドの実行時チェックの追加**: `src/cmd/go/build.go`内の`runInstall`関数に、`GOBIN`が設定されている場合にそれが絶対パスであるかどうかを検証するロジックが追加されました。`filepath.IsAbs()`関数を使用してパスが絶対パスであるかを確認し、相対パスである場合はエラーメッセージと共にプログラムを終了（`fatalf`）させます。これにより、不正な`GOBIN`設定でのインストールを未然に防ぎます。

2.  **ドキュメントの更新**: `src/cmd/go/alldocs.go`と`src/cmd/go/help.go`内の`GOBIN`に関する説明文に、「GOBIN must be an absolute path.」（GOBINは絶対パスでなければなりません。）という明確な制約が追記されました。これにより、ユーザーは`go help install`や関連ドキュメントを参照した際に、この新しい制約を認識できるようになります。

3.  **テストケースの追加**: `src/cmd/go/go_test.go`に`TestRelativeGOBINFail`という新しいテスト関数が追加されました。このテストは、`GOBIN`に相対パス（例: `.`）を設定した状態で`go install`を実行し、期待通りにエラーメッセージ「cannot install, GOBIN must be an absolute path」が出力されることを検証します。これにより、将来の変更でこの制約が誤って削除されたり、動作が変更されたりすることを防ぐためのリグレッションテストが確立されました。

これらの変更により、`GOBIN`の利用に関するGoコマンドの挙動がより明確かつ堅牢になり、ユーザーが意図しない場所にバイナリをインストールしてしまうリスクが低減されました。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更

`runInstall`関数は、`go install`コマンドの主要なロジックを実行する部分です。この関数に追加された以下のコードブロックが、今回の変更の核心です。

```go
	if gobin != "" && !filepath.IsAbs(gobin) {
		fatalf("cannot install, GOBIN must be an absolute path")
	}
```

*   `gobin != ""`: `GOBIN`環境変数が設定されているかどうかを確認します。設定されていない場合は、デフォルトの`GOPATH/bin`が使用されるため、このチェックはスキップされます。
*   `!filepath.IsAbs(gobin)`: `filepath.IsAbs()`関数は、与えられたパスが絶対パスである場合に`true`を返します。この条件は、`gobin`が絶対パスでない（つまり相対パスである）場合に`true`となります。
*   `fatalf("cannot install, GOBIN must be an absolute path")`: 上記の2つの条件が両方とも真（`GOBIN`が設定されており、かつそれが相対パスである）の場合、`fatalf`関数が呼び出され、指定されたエラーメッセージを出力してプログラムが異常終了します。これにより、相対パスの`GOBIN`でのインストールが強制的に阻止されます。

### `src/cmd/go/go_test.go` の変更

`TestRelativeGOBINFail`テスト関数は、この新しい制約が正しく機能することを保証します。

```go
func TestRelativeGOBINFail(t *testing.T) {
	tg := testgo(t) // テストヘルパーの初期化
	defer tg.cleanup() // テスト終了後に一時ファイルをクリーンアップ
	tg.tempFile("triv.go", `package main; func main() {}`) // ダミーのGoソースファイルを作成
	tg.setenv("GOBIN", ".") // GOBINに相対パス "." を設定
	tg.runFail("install") // go install コマンドを実行し、失敗することを期待
	tg.grepStderr("cannot install, GOBIN must be an absolute path", "go install must fail if $GOBIN is a relative path") // 標準エラー出力に特定のエラーメッセージが含まれることを検証
}
```

このテストは、`GOBIN`に意図的に相対パスを設定し、`go install`が期待通りにエラーを発生させ、適切なエラーメッセージを出力することを確認します。これにより、この重要な制約が将来にわたって維持されることが保証されます。

### ドキュメントの変更 (`alldocs.go`, `help.go`)

これらのファイルでは、`GOBIN`に関する既存のドキュメントに「`GOBIN must be an absolute path.`」という一文が追加されました。これは、ユーザーが`go help install`やGoの公式ドキュメントを参照した際に、この新しい要件を明確に理解できるようにするためのものです。ドキュメントの更新は、コードの変更と合わせて、ユーザーエクスペリエンスを向上させる上で不可欠な要素です。
