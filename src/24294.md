# [インデックス 24294] ファイルの概要

このコミットは、Go言語の `encoding/json` パッケージにおけるJSON `null` 値のデコードに関するバグ修正を扱っています。具体的には、`json.Unmarshaler` インターフェースや `encoding.TextUnmarshaler` インターフェースを実装する型に対して `null` 値が誤って渡され、デコードエラーが発生する問題を解決します。期待される動作は、`null` 値がデコードエンジンによって処理され、値が変更されずに保持されることです。

## コミット

Author: Didier Spezia <didier.06@gmail.com>
Date:   Tue Apr 28 11:20:19 2015 +0000

    encoding/json: fix decoding of JSON null values
    
    JSON decoding currently fails for null values bound to any type
    which does implement the JSON Unmarshaler interface without checking
    for null values (such as time.Time).
    
    It also fails for types implementing the TextUnmarshaler interface.
    
    The expected behavior of the JSON decoding engine in such case is
    to process null by keeping the value unchanged without producing
    any error.
    
    Make sure null values are handled by the decoding engine itself,
    and never passed to the UnmarshalText or UnmarshalJSON methods.
    
    Fixes #9037

## 元コミット内容

JSONデコードは現在、`json.Unmarshaler` インターフェースを実装しているが `null` 値のチェックを行わない型（`time.Time` など）にバインドされた `null` 値に対して失敗します。
また、`TextUnmarshaler` インターフェースを実装する型に対しても失敗します。

このような場合のJSONデコードエンジンの期待される動作は、`null` を処理する際に値を変更せずにエラーを生成しないことです。

`null` 値がデコードエンジン自体によって処理され、`UnmarshalText` または `UnmarshalJSON` メソッドに渡されないようにします。

Fixes #9037

## 変更の背景

Goの `encoding/json` パッケージは、JSONデータをGoの構造体にマッピングするための強力なツールです。このパッケージは、カスタムのデコードロジックを可能にするために `json.Unmarshaler` および `encoding.TextUnmarshaler` インターフェースを提供しています。しかし、このコミット以前は、JSONの `null` 値がこれらのカスタムアンマーシャラーに渡される際に問題がありました。

具体的には、JSONの `null` はGoのゼロ値（ポインタ型の場合は `nil`）に対応するのが一般的です。しかし、`time.Time` のような一部の型や、カスタムの `Unmarshaler` を実装した型では、`null` が入力として与えられた場合に、その `Unmarshaler` メソッド内で `null` を適切に処理するロジックが欠けていることがありました。その結果、`null` が渡されると、`Unmarshaler` メソッドが予期しないエラーを返したり、パニックを起こしたりする可能性がありました。

この問題は、GoのIssue #9037として報告されました。ユーザーは、`time.Time` 型のフィールドにJSON `null` をデコードしようとした際にエラーが発生することを指摘しました。`time.Time` は `json.Unmarshaler` を実装していますが、`null` 値の特別なハンドリングは行っていませんでした。このコミットは、この問題を解決し、`encoding/json` パッケージがJSONの `null` 値をより堅牢に処理できるようにすることを目的としています。

## 前提知識の解説

### JSON `null` の意味
JSON (JavaScript Object Notation) における `null` は、値が存在しないこと、または意図的に空であることを示します。Go言語では、`null` は通常、ポインタ型の場合は `nil`、その他の型の場合はその型のゼロ値にデコードされます。

### `encoding/json` パッケージ
Goの標準ライブラリの一部であり、JSONデータのエンコード（Goのデータ構造からJSONへ）とデコード（JSONからGoのデータ構造へ）を提供します。

### `json.Unmarshaler` インターフェース
このインターフェースは、Goの型がJSONデータをカスタムでデコードする方法を定義するために使用されます。
```go
type Unmarshaler interface {
    UnmarshalJSON([]byte) error
}
```
`UnmarshalJSON` メソッドは、JSONデータの生バイトスライスを受け取り、それをGoの型の値に変換する責任があります。

### `encoding.TextUnmarshaler` インターフェース
このインターフェースは、Goの型がテキスト形式のデータをカスタムでデコードする方法を定義するために使用されます。`encoding/json` パッケージは、JSON文字列をこのインターフェースを実装する型にデコードする際に、このインターフェースを利用することがあります。
```go
type TextUnmarshaler interface {
    UnmarshalText(text []byte) error
}
```
`UnmarshalText` メソッドは、テキストデータの生バイトスライスを受け取り、それをGoの型の値に変換する責任があります。

### `reflect` パッケージ
Goの `reflect` パッケージは、実行時にGoの型、値、構造体を検査および操作するための機能を提供します。`encoding/json` パッケージは、この `reflect` パッケージを広範に利用して、任意のGoの型へのデコードを処理します。特に、`reflect.Value` はGoの値を抽象化し、その型や値を動的に操作することを可能にします。`v.IsNil()` はポインタ、インターフェース、マップ、スライス、チャネル、関数などの値が `nil` かどうかをチェックするために使用されます。`v.Type().NumMethod()` は、その型が持つメソッドの数を返します。

## 技術的詳細

このコミットの核心は、`encoding/json` パッケージのデコードロジックが、JSON `null` 値をカスタムアンマーシャラーに渡す前に適切に処理するように変更された点にあります。

以前の動作では、デコードエンジンは、ターゲットのGoの型が `json.Unmarshaler` または `encoding.TextUnmarshaler` を実装している場合、JSONの `null` 値であってもそのメソッドを呼び出そうとしました。しかし、これらのカスタムアンマーシャラーの多くは、`null` 値を予期しておらず、文字列や数値などの具体的な値が来ることを前提として設計されていることがありました。その結果、`null` が渡されると、アンマーシャラー内でエラーが発生したり、パニックを引き起こしたりしていました。

この修正では、`decodeState` 構造体の `indirect` メソッドが変更されました。`indirect` メソッドは、ポインタのデリファレンスや、カスタムアンマーシャラーの検出と呼び出しを担当する重要な部分です。

変更のポイントは、`decodingNull` という新しいブール引数を導入し、このフラグが `true` の場合（つまり、現在デコードしているJSONトークンが `null` である場合）には、`Unmarshaler` インターフェースのメソッドを呼び出さないようにすることです。

JSONの仕様では、`null` は「値がない」ことを意味し、Goのデータ構造にデコードされる際には、そのフィールドのゼロ値（ポインタの場合は `nil`）に設定されるべきです。カスタムアンマーシャラーがこの `null` を処理するのではなく、`encoding/json` パッケージ自体がこのセマンティクスを強制するべきであるという設計思想に基づいています。

これにより、カスタムアンマーシャラーは `null` 値の特別なハンドリングについて心配する必要がなくなり、`encoding/json` パッケージが `null` を適切にGoのゼロ値にマッピングする責任を負うことになります。これは、`time.Time` のような標準ライブラリの型だけでなく、ユーザーが定義したカスタム型にも一貫した動作を提供します。

## コアとなるコードの変更箇所

変更は主に `src/encoding/json/decode.go` の `indirect` 関数にあります。

```diff
--- a/src/encoding/json/decode.go
+++ b/src/encoding/json/decode.go
@@ -358,7 +358,7 @@ func (d *decodeState) indirect(v reflect.Value, decodingNull bool) (Unmarshaler,\n 		if v.IsNil() {\n 			v.Set(reflect.New(v.Type().Elem()))\n 		}\n-		if v.Type().NumMethod() > 0 {\n+		if v.Type().NumMethod() > 0 && !decodingNull {\n 			if u, ok := v.Interface().(Unmarshaler); ok {\n 				return u, nil, reflect.Value{}\n 			}\
```

テストファイル `src/encoding/json/decode_test.go` にも、この修正を検証するための新しいテストケースが追加されています。

## コアとなるコードの解説

`src/encoding/json/decode.go` の `indirect` 関数は、Goの `reflect.Value` を受け取り、それがポインタである場合にデリファレンスを行い、必要に応じて新しい値を割り当て、そして `json.Unmarshaler` インターフェースを実装しているかどうかをチェックします。

変更前のコード:
```go
		if v.IsNil() {
			v.Set(reflect.New(v.Type().Elem()))
		}
		if v.Type().NumMethod() > 0 { // ここでメソッドの存在をチェック
			if u, ok := v.Interface().(Unmarshaler); ok {
				return u, nil, reflect.Value{}
			}
```
この部分では、`v` が `nil` ポインタの場合、新しい要素を割り当ててから、その型がメソッドを持っているかどうかをチェックし、もし `Unmarshaler` インターフェースを実装していれば、そのアンマーシャラーを返していました。問題は、`null` をデコードしている最中であっても、このロジックが実行され、`UnmarshalJSON` メソッドが呼び出されてしまうことでした。

変更後のコード:
```go
		if v.IsNil() {
			v.Set(reflect.New(v.Type().Elem()))
		}
		if v.Type().NumMethod() > 0 && !decodingNull { // decodingNull が false の場合のみメソッドをチェック
			if u, ok := v.Interface().(Unmarshaler); ok {
				return u, nil, reflect.Value{}
			}
```
追加された `&& !decodingNull` という条件が重要です。
`decodingNull` は、現在デコード中のJSONトークンが `null` であるかどうかを示すブール値です。
この条件が追加されたことで、もし現在デコードしている値がJSON `null` である場合 (`decodingNull` が `true`)、`v.Type().NumMethod() > 0` が `true` であっても、`Unmarshaler` インターフェースのチェックと呼び出しはスキップされます。

これにより、JSON `null` がカスタムアンマーシャラーに渡されることなく、`encoding/json` パッケージの内部ロジックによって適切に処理され、ターゲットのGoのフィールドがその型のゼロ値（ポインタの場合は `nil`）に設定されるようになります。

`src/encoding/json/decode_test.go` に追加されたテストケースは、この新しい動作を検証します。
`TestUnmarshalJSONLiteralError1` では、`time.Time` 型に `null` をデコードする際にエラーが発生しないことを確認しています。
`TestUnmarshalJSONLiteralError2` では、`json.Unmarshaler` と `encoding.TextUnmarshaler` の両方を実装するカスタム型を含む構造体 `STime` を定義し、JSON `null` がこれらのカスタムアンマーシャラーに渡されずに、フィールドが適切にゼロ値（ポインタの場合は `nil`）に設定されることを検証しています。
