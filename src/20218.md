## 変更の背景

このコミットの背景には、Goの`net/http`パッケージがHTTPリクエストを処理する際に、クライアントからの`Connection: close`ヘッダの意図を正確に反映できていなかったという問題があります。HTTP/1.1では、デフォルトでコネクションは持続的（persistent）ですが、`Connection: close`ヘッダが存在する場合、そのリクエスト/レスポンスの送受信後にコネクションを閉じるべきであることを示します。

以前の実装では、`http.Request`構造体の`Close`フィールドが、`ReadRequest`関数によってリクエストが読み込まれる際に、この`Connection: close`ヘッダに基づいて適切に設定されていませんでした。その結果、サーバーアプリケーションは、クライアントがコネクションを閉じたいと意図しているにもかかわらず、コネクションを持続させようとしてしまう可能性がありました。これは、リソースの無駄遣いや、クライアントとサーバー間のプロトコルハンドシェイクの不一致を引き起こす可能性がありました。

この問題はGoのIssue #8261として報告されており、このコミットはその問題を解決するために導入されました。`Request.Close`フィールドが正しく設定されることで、サーバーはクライアントの意図を正確に把握し、適切なコネクション管理（例えば、リクエスト処理後にコネクションを閉じる）を行うことができるようになります。

## 前提知識の解説

### HTTP/1.1におけるコネクション管理

HTTP/1.1では、TCPコネクションの再利用（持続的コネクション、Persistent Connections）がデフォルトの動作です。これにより、複数のリクエスト/レスポンスを同じTCPコネクション上で送受信でき、コネクション確立のオーバーヘッドを削減し、パフォーマンスを向上させます。

しかし、特定の状況下ではコネクションを閉じる必要がある場合があります。これを制御するために`Connection`ヘッダが使用されます。

*   **`Connection: keep-alive`**: これはHTTP/1.1のデフォルト動作であるため、通常は明示的に指定する必要はありませんが、HTTP/1.0クライアントが持続的コネクションを要求する際に使用されることがあります。
*   **`Connection: close`**: このヘッダが存在する場合、送信側は現在のリクエスト/レスポンスの送受信が完了した後にTCPコネクションを閉じることを意図していることを示します。受信側もこれに従い、処理後にコネクションを閉じることが期待されます。

### Goの`net/http`パッケージ

Goの`net/http`パッケージは、HTTPクライアントとサーバーを実装するための強力な機能を提供します。

*   **`http.Request`構造体**: HTTPリクエストを表す構造体です。この構造体には、リクエストメソッド（GET, POSTなど）、URL、ヘッダ、ボディなどの情報が含まれます。
    *   **`Close`フィールド**: `bool`型で、このリクエストの処理後にコネクションを閉じるべきかどうかを示します。このフィールドは、主に`Connection: close`ヘッダの有無や、HTTPプロトコルのバージョンに基づいて設定されます。
*   **`http.ReadRequest`関数**: `bufio.Reader`からHTTPリクエストの生データを読み込み、それをパースして`http.Request`構造体を生成する関数です。この関数は、HTTPサーバーがクライアントからのリクエストを受け取った際に内部的に使用されます。
*   **`shouldClose`関数**: `net/http`パッケージ内部で使用されるヘルパー関数で、与えられたHTTPプロトコルバージョンとヘッダに基づいて、コネクションを閉じるべきかどうかを判断します。

## 技術的詳細

このコミットの主要な変更点は、`http.ReadRequest`関数がリクエストヘッダをパースした直後に、`http.Request`構造体の`Close`フィールドを適切に設定するようになったことです。

具体的には、以下の変更が行われました。

1.  **`http.Request`構造体の`Close`フィールドの初期化**:
    `src/pkg/net/http/request.go`の`ReadRequest`関数内で、リクエストのプロトコルバージョンとヘッダ情報に基づいて`shouldClose`関数が呼び出され、その結果が`req.Close`に代入されるようになりました。
    ```go
    // src/pkg/net/http/request.go
    func ReadRequest(b *bufio.Reader) (req *Request, err error) {
        // ... (既存のコード) ...
        req.Close = shouldClose(req.ProtoMajor, req.ProtoMinor, req.Header, false)
        return req, nil
    }
    ```
    ここで、`shouldClose`に渡される最後の引数`false`は、リクエストのコンテキストでは`Connection`ヘッダを削除しないことを意味します。

2.  **`shouldClose`関数のシグネチャ変更とロジックの調整**:
    `src/pkg/net/http/transfer.go`にある`shouldClose`関数のシグネチャに、`removeCloseHeader bool`という新しい引数が追加されました。
    ```go
    // src/pkg/net/http/transfer.go
    func shouldClose(major, minor int, header Header, removeCloseHeader bool) bool {
        // ... (既存のロジック) ...
        if strings.ToLower(header.get("Connection")) == "close" {
            if removeCloseHeader {
                header.Del("Connection")
            }
            return true
        }
        // ... (既存のロジック) ...
    }
    ```
    この`removeCloseHeader`引数は、`Connection: close`ヘッダが検出された場合に、そのヘッダをリクエスト/レスポンスのヘッダマップから削除するかどうかを制御します。HTTPの仕様では、`Connection`ヘッダはホップバイホップヘッダ（Hop-by-hop header）であり、プロキシなどを通過する際に削除されるべきとされています。この変更により、`ReadRequest`が呼び出す際には`false`が渡されヘッダは削除されず、`readTransfer`（レスポンス処理に関連）が呼び出す際には`true`が渡されヘッダが削除されるという、異なるコンテキストでの適切な挙動が実現されます。

3.  **テストケースの追加と改善**:
    `src/pkg/net/http/readrequest_test.go`に、`Connection: close`ヘッダを含むHTTPリクエストの新しいテストケースが追加されました。このテストケースでは、`ReadRequest`によってパースされた`http.Request`オブジェクトの`Close`フィールドが期待通り`true`に設定されていることを検証します。
    ```go
    // src/pkg/net/http/readrequest_test.go
    // Connection: close. golang.org/issue/8261
    {
        "GET / HTTP/1.1\r\nHost: issue8261.com\r\nConnection: close\r\n\r\n",
        &Request{
            // ... (期待されるRequestフィールド) ...
            Close:      true, // ここが重要
            RequestURI: "/",
        },
        noBody,
        noTrailer,
        noError,
    },
    ```
    また、テストユーティリティも改善され、エラーメッセージやテスト名の表示がより詳細になりました。

これらの変更により、`net/http`パッケージはHTTP/1.1のコネクション管理のセマンティクスをより正確に遵守し、`Request.Close`フィールドが信頼できる情報源として機能するようになりました。

## コアとなるコードの解説

このコミットの核心は、`http.Request`構造体の`Close`フィールドが、HTTPリクエストのパース時に正確に設定されるようになった点です。

1.  **`ReadRequest`における`Request.Close`の設定**:
    `src/pkg/net/http/request.go`の`ReadRequest`関数は、クライアントから受信したHTTPリクエストの生データを読み込み、それをGoの`http.Request`構造体に変換します。このコミット以前は、`Request.Close`フィールドは、リクエストの読み込み段階では適切に設定されていませんでした。この修正により、リクエストのヘッダが完全にパースされた直後に、`shouldClose`関数が呼び出され、その戻り値が`req.Close`に代入されます。これにより、`Connection: close`ヘッダの有無やHTTPプロトコルバージョンに基づいて、コネクションを閉じるべきかどうかの情報が、リクエストオブジェクトが生成された時点で利用可能になります。`ReadRequest`からの呼び出しでは、`shouldClose`の`removeCloseHeader`引数に`false`が渡されるため、リクエストヘッダから`Connection`ヘッダが削除されることはありません。これは、リクエストヘッダはそのまま保持されるべきであるという意図を反映しています。

2.  **`shouldClose`関数の柔軟性向上**:
    `src/pkg/net/http/transfer.go`にある`shouldClose`関数は、コネクションを閉じるべきかを判断するロジックをカプセル化しています。このコミットでは、この関数に`removeCloseHeader`という新しい引数が追加されました。この引数は、`Connection: close`ヘッダが検出された場合に、そのヘッダをヘッダマップから削除するかどうかを制御します。
    *   `ReadRequest`から呼び出される場合（リクエストのパース時）は`removeCloseHeader`が`false`となり、ヘッダは削除されません。これは、受信したリクエストのヘッダはそのまま保持されるべきであるためです。
    *   `readTransfer`から呼び出される場合（レスポンスの処理時など）は`removeCloseHeader`が`true`となり、`Connection`ヘッダが削除されます。これは、`Connection`ヘッダがホップバイホップヘッダであり、プロキシなどを介して転送されるべきではないというHTTPの仕様に準拠するためです。

3.  **堅牢なテストの追加**:
    `src/pkg/net/http/readrequest_test.go`に追加されたテストケースは、この修正の正確性を保証する上で非常に重要です。`Connection: close`ヘッダを持つリクエストが正しくパースされ、`Request.Close`が`true`になることを明示的に検証することで、将来のリグレッションを防ぎ、この機能が期待通りに動作することを保証します。また、テストユーティリティの改善は、テストの可読性とデバッグのしやすさを向上させます。

これらの変更により、Goの`net/http`パッケージは、HTTPコネクションのライフサイクル管理において、より正確で堅牢な振る舞いを提供するようになりました。これは、特にHTTPプロキシやロードバランサーを介した通信において、コネクションの意図しない再利用や早期クローズを防ぐ上で重要です。
