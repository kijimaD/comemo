## 元コミット内容

`cmd/pprof: run $BROWSER and system browser before Chrome`

このコミットは、`cmd/pprof` ツールがプロファイル結果をWebブラウザで表示する際に、ブラウザの起動順序を変更するものです。具体的には、環境変数 `$BROWSER` で指定されたブラウザ、およびオペレーティングシステムが提供するデフォルトのブラウザ起動コマンドを、ハードコードされた特定のブラウザ（ChromeやFirefox）よりも優先して試行するように修正しています。

## 変更の背景

この変更は、Issue #10259 を解決するために行われました。元の `pprof` ツールは、Webインターフェースを起動する際に、特定のブラウザ（`chrome`, `google-chrome`, `firefox`）を決められた順序で試行していました。しかし、多くのユーザーは環境変数 `$BROWSER` を設定して好みのブラウザを指定したり、システムデフォルトのブラウザ起動コマンド（macOSの `open` やLinuxの `xdg-open` など）を使用することを期待していました。

従来の挙動では、たとえユーザーが `$BROWSER` に別のブラウザを設定していても、`pprof` はまず `chrome` を探し、見つかればそれを起動してしまっていました。これはユーザーの意図に反するものであり、特にChromeを使用していないユーザーにとっては不便でした。このコミットは、このようなユーザーエクスペリエンスの課題を解決し、より柔軟でユーザーフレンドリーなブラウザ起動メカニズムを提供することを目的としています。

## 前提知識の解説

### Go言語の `pprof` ツール

`pprof` はGo言語に標準で付属するプロファイリングツールです。CPU使用率、メモリ割り当て、ゴルーチンブロック、ミューテックス競合などのパフォーマンスデータを収集し、解析・可視化することができます。特にWebインターフェース機能は、プロファイル結果をグラフやコールスタックツリーとしてブラウザ上で視覚的に表示するため、パフォーマンスボトルネックの特定に非常に役立ちます。

### 環境変数 `$BROWSER`

Unix系システムでは、`$BROWSER` 環境変数は、コマンドラインツールがWebページを開く際に使用するデフォルトのWebブラウザを指定するための一般的な慣習です。例えば、`export BROWSER=firefox` と設定すると、多くのツールはFirefoxを起動しようとします。

### システムデフォルトのブラウザ起動コマンド

*   **macOS**: `/usr/bin/open` コマンドは、ファイルやURLを関連付けられたアプリケーションで開くために使用されます。Webブラウザの場合、システムデフォルトのブラウザでURLを開きます。
*   **Linux**: `xdg-open` コマンドは、XDG (X Desktop Group) の仕様に基づいて、ファイルやURLを適切なアプリケーションで開くためのユーティリティです。これもシステムデフォルトのブラウザを起動するために広く使用されます。
*   **Windows**: Windowsでは `start` コマンド（`cmd.exe`）や `explorer` コマンドが同様の機能を提供しますが、このコミットの文脈ではUnix系システムが主な対象です。

### `os.Getenv` 関数

Go言語の標準ライブラリ `os` パッケージに含まれる `Getenv(key string) string` 関数は、指定された環境変数の値を取得します。環境変数が設定されていない場合、空文字列を返します。

### `runtime.GOOS` 変数

Go言語の `runtime` パッケージに含まれる `GOOS` 変数は、プログラムが実行されているオペレーティングシステムの名前（例: "darwin", "linux", "windows"）を文字列で提供します。これにより、OS固有の処理を条件分岐で実装できます。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/pprof/internal/commands/commands.go` ファイル内の `browsers()` 関数にあります。この関数は、`pprof` がWebインターフェースを起動する際に試行するブラウザ起動コマンドのリストを生成します。

変更前は、`browsers()` 関数は以下のようなロジックでブラウザリストを構築していました。

1.  `cmds := []string{"chrome", "google-chrome", "firefox"}` で初期化。
2.  `runtime.GOOS` に応じて、macOSなら `/usr/bin/open`、それ以外なら `xdg-open` を `cmds` に追加。

この順序では、`chrome` が常に最初に試行されるため、ユーザーの意図が無視される可能性がありました。

変更後は、このロジックが以下のように修正されました。

1.  `var cmds []string` で空のスライスを初期化。
2.  `os.Getenv("BROWSER")` を呼び出し、`$BROWSER` 環境変数の値を取得。
3.  もし `$BROWSER` が設定されていれば（空文字列でなければ）、その値を `cmds` スライスの先頭に追加。これにより、ユーザーが明示的に指定したブラウザが最優先されます。
4.  `runtime.GOOS` に応じて、macOSなら `/usr/bin/open`、それ以外なら `xdg-open` を `cmds` に追加。これにより、システムデフォルトのブラウザ起動コマンドが次に優先されます。
5.  最後に、`cmds = append(cmds, "chrome", "google-chrome", "firefox")` を実行し、ハードコードされた特定のブラウザコマンドをリストの末尾に追加します。これらは、上記の方法でブラウザが見つからなかった場合のフォールバックとして機能します。

この変更により、ブラウザの試行順序は以下のようになります。

1.  `$BROWSER` 環境変数で指定されたブラウザ
2.  システムデフォルトのブラウザ起動コマンド（macOSの `open` またはLinuxの `xdg-open`）
3.  `chrome`
4.  `google-chrome`
5.  `firefox`

この優先順位付けは、ユーザーのカスタマイズ性（`$BROWSER`）とOSの標準的な挙動（システムデフォルト）を尊重しつつ、最終的なフォールバックとして一般的なブラウザを試行するという、堅牢かつ柔軟なアプローチを提供します。

## コアとなるコードの解説

変更された `browsers()` 関数は、`pprof` がWebインターフェースを開く際に使用するブラウザコマンドの優先順位を定義しています。

1.  `var cmds []string`
    *   ブラウザコマンドを格納するための空の文字列スライス `cmds` を宣言します。これにより、以前のように特定のブラウザで初期化するのではなく、動的にリストを構築できるようになります。

2.  `if exe := os.Getenv("BROWSER"); exe != "" { cmds = append(cmds, exe) }`
    *   `os.Getenv("BROWSER")` を呼び出して、`BROWSER` 環境変数の値を取得します。
    *   もし `BROWSER` 環境変数が設定されており、その値が空文字列でなければ（つまり、ユーザーが特定のブラウザを指定している場合）、その値を `cmds` スライスの最初の要素として追加します。これにより、ユーザーの好みが最優先されます。

3.  `switch runtime.GOOS { ... }`
    *   現在のオペレーティングシステム (`runtime.GOOS`) に応じて、システムデフォルトのブラウザ起動コマンドを追加します。
    *   `case "darwin"` (macOSの場合): `cmds = append(cmds, "/usr/bin/open")`
        *   macOSでは `/usr/bin/open` コマンドがデフォルトのブラウザを起動するために使用されます。
    *   `default` (その他のOS、主にLinuxの場合): `cmds = append(cmds, "xdg-open")`
        *   LinuxなどのUnix系システムでは `xdg-open` が広く使用されます。

4.  `cmds = append(cmds, "chrome", "google-chrome", "firefox")`
    *   最後に、一般的なブラウザの実行ファイル名である `"chrome"`, `"google-chrome"`, `"firefox"` を `cmds` スライスの末尾に追加します。これらは、環境変数やシステムデフォルトのコマンドでブラウザが見つからなかった場合のフォールバックとして機能します。

この一連の処理により、`pprof` はブラウザを起動する際に、ユーザーの意図を最大限に尊重し、かつ幅広い環境で動作する堅牢なメカニズムを提供します。
