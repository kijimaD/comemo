## 変更の背景

Go言語のランタイムは、初期の段階ではパフォーマンスや既存のシステムとの連携のためにC言語で多くの部分が実装されていました。しかし、Go言語自体の成熟と、Go言語でランタイムを記述することの利点（例えば、Goのツールチェインによるデバッグの容易さ、ガベージコレクションとの統合、より安全なメモリ管理、そしてGo開発者にとっての可読性の向上など）から、徐々にC言語で書かれた部分をGo言語に移植する作業が進められていました。

このコミットもその一環であり、特にパニック処理のようなGo言語のコアな機能の一部をGo言語自身で記述することで、ランタイム全体のGo化を推進し、保守性や開発効率の向上を目指しています。`panicindex` や `panicslice` といった関数は、Goプログラムの実行中に頻繁に発生しうるエラー条件（配列の範囲外アクセスやスライスの不正な使用）を検出した際に呼び出される重要な関数です。これらをGo言語で実装することで、Goランタイムの内部構造がより一貫性のあるものになり、将来的な機能拡張や最適化が容易になります。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション、スケジューリング、メモリ管理、パニック処理など、Go言語の多くの重要な機能を提供します。初期のGoランタイムはC言語とGo言語の混在で書かれていましたが、徐々にGo言語への移行が進められています。
*   **パニック (Panic)**: Go言語におけるエラー処理メカニズムの一つで、回復不可能なエラーが発生した場合にプログラムの実行を停止させるために使用されます。パニックが発生すると、通常の実行フローは中断され、`defer` 関数が実行された後、スタックがアンワインドされます。
*   **`panicindex`**: Go言語のコンパイラやランタイムが、配列や文字列のインデックスアクセスが範囲外であると判断した場合に呼び出される内部関数です。これにより「index out of range」というパニックが発生します。
*   **`panicslice`**: Go言語のコンパイラやランタイムが、スライスの作成や操作において境界が不正であると判断した場合に呼び出される内部関数です。これにより「slice bounds out of range」というパニックが発生します。
*   **`panicstring` (C言語の関数)**: C言語で実装されたランタイム関数で、指定された文字列を引数としてパニックを発生させます。
*   **`panic` (Go言語の組み込み関数)**: Go言語の組み込み関数で、任意の値を引数としてパニックを発生させます。
*   **`errorString` (Go言語の関数)**: Goランタイム内部で使用される関数で、文字列を`runtime.errorString`型に変換し、`panic`関数に渡すためのものです。これにより、パニックメッセージが適切にフォーマットされます。
*   **Cgo**: Go言語とC言語のコードを相互に呼び出すためのメカニズムです。GoランタイムがC言語で書かれた部分と連携するために使用されます。

## 技術的詳細

このコミットの主要な目的は、GoランタイムのC言語依存性を減らし、Go言語で書かれたコードの割合を増やすことです。`panicindex` と `panicslice` は、Goプログラムの実行中に発生する可能性のある一般的なランタイムエラー（インデックス範囲外アクセスやスライス境界エラー）を処理するために、コンパイラによって生成されたコードから呼び出される内部関数です。

変更前は、これらの関数は `src/pkg/runtime/panic.c` にC言語で実装されており、`runtime·panicstring` という別のC言語関数を呼び出してパニックを発生させていました。C言語の関数名にはGoランタイムの慣例として `runtime·` というプレフィックスが付与されています。

変更後は、これらの関数が `src/pkg/runtime/panic.go` にGo言語で実装されました。Go言語版の `panicindex` と `panicslice` は、Go言語の組み込み関数である `panic` を直接呼び出します。パニックメッセージは `errorString` 関数によって生成され、`panic` に渡されます。

この移行により、以下の利点が考えられます。

1.  **コードの一貫性**: ランタイムのパニック処理がGo言語で統一されることで、コードベース全体の一貫性が向上します。
2.  **保守性の向上**: Go言語のツールチェイン（デバッガ、プロファイラなど）がより効果的に利用できるようになり、Go開発者にとってランタイムのデバッグや保守が容易になります。
3.  **安全性と堅牢性**: Go言語の型安全性やメモリ管理の恩恵をランタイムコード自体が享受できるようになり、潜在的なバグや脆弱性が減少する可能性があります。
4.  **将来的な最適化**: Go言語のコンパイラやランタイムの最適化が、Go言語で書かれたランタイムコードにも適用されるため、将来的なパフォーマンス向上の余地が生まれます。

この変更は、GoランタイムがC言語からGo言語へと段階的に移行していくという、より大きな戦略の一部です。

## コアとなるコードの解説

削除されたC言語の関数 `runtime·panicindex` と `runtime·panicslice` は、それぞれ `runtime·panicstring` を呼び出してパニックメッセージを生成していました。

```c
// src/pkg/runtime/panic.c (削除前)
void
runtime·panicindex(void)
{
	runtime·panicstring("index out of range");
}

void
runtime·panicslice(void)
{
	runtime·panicstring("slice bounds out of range");
}
```

これに対し、新しく追加されたGo言語の関数 `panicindex` と `panicslice` は、Go言語の組み込み関数 `panic` を直接呼び出しています。パニックに渡される引数は `errorString` 関数によって生成された文字列です。

```go
// src/pkg/runtime/panic.go (追加後)
func panicindex() {
	panic(errorString("index out of range"))
}

func panicslice() {
	panic(errorString("slice bounds out of range"))
}
```

この変更は、パニック処理のロジック自体を大きく変えるものではなく、その実装言語をC言語からGo言語へと移行したものです。これにより、Goランタイムの内部がよりGo言語フレンドリーになり、Go言語の機能やツールとの統合が深まります。
