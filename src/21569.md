# [インデックス 21569] ファイルの概要

このコミットは、Go言語のAndroid向けツール群（`misc/android`）における重要な改善を含んでいます。具体的には、`go_android_exec.go`スクリプトが、Goのパッケージが`GOPATH`配下にある場合でも正しく動作するように修正され、さらに一時ファイルのクリーンアップ処理が強化されました。`README`ファイルも、`go.mobile`リポジトリの新しいGitHubの場所を反映するように更新されています。

## 元コミット内容

misc/android: GOPATH配下のbinに対して正しいサブディレクトリを選択する。

この変更には、バイナリ実行中に作成された一時ファイルのクリーンアップも含まれる。

## 変更の背景

このコミットは、主に`misc/android/go_android_exec.go`スクリプトが抱えていた2つの課題を解決するために導入されました。

1.  **GOPATHのサポート不足**: 以前の`go_android_exec.go`は、テスト対象のGoパッケージが`$GOROOT/src`配下にあることを前提としていました。しかし、Goの標準的な開発ワークフローでは、ユーザーのプロジェクトは通常`$GOPATH/src`配下に配置されます。このため、`GOPATH`で管理されているパッケージをAndroidデバイス上でテストしようとすると、スクリプトが正しいパスを特定できず、実行に失敗するという問題がありました。コミットメッセージ内の`TODO(crawshaw): Pick useful subdir when we are not inside a GOROOT, e.g. we are in a GOPATH.`というコメントが、この問題の存在と解決の必要性を示唆しています。

2.  **一時ファイルのクリーンアップの不備**: `go_android_exec.go`は、Androidデバイス上でGoのバイナリを実行するために、一時的なバイナリファイルをデバイスにプッシュしていました。しかし、これらのファイルが実行後に適切にクリーンアップされない場合があり、デバイスのストレージを不必要に消費する可能性がありました。

これらの課題に対処するため、このコミットでは`GOPATH`のサポートを追加し、一時ファイルの管理とクリーンアップを改善しています。また、`misc/android/README`のリンクが、`go.mobile`プロジェクトの移行に伴い、古いGoogle CodeのURLから新しいGitHubのURLに更新されています。

## 前提知識の解説

### Goの環境変数 (`GOROOT`, `GOPATH`)

*   **`GOROOT`**: Goのインストールディレクトリを指します。Goの標準ライブラリのソースコードやツール群がここに格納されています。
*   **`GOPATH`**: Goのワークスペースディレクトリを指します。ユーザーが開発するGoのプロジェクトや、`go get`コマンドで取得したサードパーティのライブラリのソースコードがここに格納されます。Goのビルドシステムは、ソースコードの解決に`GOROOT`と`GOPATH`の両方を参照します。

### Android開発におけるGo (`golang.org/x/mobile`)

Go言語は、`golang.org/x/mobile`プロジェクトを通じて、AndroidおよびiOSアプリケーションの開発をサポートしています。このプロジェクトは、Goのコードをモバイルプラットフォーム向けにクロスコンパイルし、Java/Kotlin（Android）やObjective-C/Swift（iOS）のコードからGoの機能を呼び出せるようにするためのツールやライブラリを提供します。`misc/android`ディレクトリ内のスクリプトは、このモバイル開発環境の一部として、Androidデバイス上でのGoバイナリの実行やテストを支援するために使用されます。

### `adb shell`コマンド

`adb` (Android Debug Bridge) は、AndroidデバイスとPC間で通信するためのコマンドラインツールです。`adb shell`コマンドは、PCから接続されたAndroidデバイス上でシェルコマンドを実行するために使用されます。このコミットの文脈では、GoのテストバイナリをAndroidデバイス上で実行するために利用されています。

重要な注意点として、Androidの`adb shell`は、実行されたコマンドの終了ステータスに関わらず、常に`0`を返すという既知の挙動があります（[https://code.google.com/p/android/issues/detail?id=3254](https://code.google.com/p/android/issues/detail?id=3254)）。このため、`go_android_exec.go`スクリプトは、実行されたGoバイナリの実際の終了コードを解析するために、特別な文字列（`exitstr`）を付加して出力させ、それをパースするという工夫をしています。

### `go/build`パッケージ

Goの標準ライブラリの一部である`go/build`パッケージは、Goのビルドシステムがどのようにソースコードを検索し、パッケージを解決するかに関する情報を提供します。このコミットでは、`build.Default.GOPATH`を使用して、システムに設定されている`GOPATH`のパスを取得し、現在の作業ディレクトリがどの`GOPATH`エントリに属しているかを判断するために利用されています。

## 技術的詳細

このコミットの主要な技術的変更点は、`go_android_exec.go`がGoのパッケージの場所を特定する方法と、一時ファイルの管理方法の改善にあります。

1.  **パッケージパスの動的な決定 (`subdir()`関数)**:
    *   以前は、現在の作業ディレクトリ（`cwd`）が常に`GOROOT`配下にあると仮定し、`filepath.Rel(runtime.GOROOT(), cwd)`を使って相対パスを計算していました。
    *   新しい`subdir()`関数は、まず`cwd`が`runtime.GOROOT()`配下にあるかどうかをチェックします。
    *   もし`GOROOT`配下になければ、`build.Default.GOPATH`で取得したすべての`GOPATH`エントリをループし、`cwd`がそのいずれかの`GOPATH`配下にあるかどうかをチェックします。
    *   これにより、`go_android_exec.go`は、`GOROOT`または`GOPATH`のどちらにパッケージが存在しても、そのパッケージへの正しい相対パス（`pkgpath`）を特定できるようになりました。
    *   `subdir()`関数は、`pkgpath`と、それが`GOROOT`配下にあるかどうかのブール値（`underGoRoot`）を返します。

2.  **一時ディレクトリの導入とクリーンアップ**:
    *   以前は、Androidデバイス上の一時バイナリは`/data/local/tmp/goroot`に直接配置され、実行後に個別に削除されていました。
    *   このコミットでは、`deviceGotmp`という新しい一時ディレクトリが導入されました。これは、`fmt.Sprintf("/data/local/tmp/%s-%d", filepath.Base(os.Args[1]), os.Getpid())`のように、実行されるバイナリ名とプロセスIDに基づいてユニークな名前で作成されます。
    *   `main`関数内で、まず`mkdir -p deviceGotmp`コマンドでこのディレクトリが作成されます。
    *   Goバイナリは、この`deviceGotmp`ディレクトリにプッシュされ、実行されます。
    *   `adb shell`コマンドの`TMPDIR`環境変数も、この`deviceGotmp`を指すように設定されます。これにより、実行されるGoバイナリが作成する可能性のある一時ファイルも、このディレクトリ内に収まるようになります。
    *   実行後、`run("shell", "rm", "-rf", deviceGotmp)`コマンドが追加され、`deviceGotmp`ディレクトリとその内容全体が再帰的に削除されるようになりました。これにより、以前の個別のファイル削除よりも堅牢で確実なクリーンアップが保証されます。

3.  **`adb shell`コマンドの変更**:
    *   `cd`コマンドのターゲットパスが、`deviceGoroot`固定から、`subdir()`関数によって決定された`deviceCwd`（`deviceGoroot`または`deviceGopath`のいずれか）に動的に変更されました。
    *   `GOPATH`環境変数が`adb shell`コマンド内で設定されるようになりました。これにより、Androidデバイス上でのGoバイナリの実行環境が、ホスト側の`GOPATH`設定をより正確に反映するようになります。

これらの変更により、`go_android_exec.go`はより柔軟になり、Goの標準的な開発ワークフローに沿った`GOPATH`ベースのプロジェクトでも、Androidデバイス上でのテストが容易になりました。

## コアとなるコードの解説

### `subdir()` 関数

この関数は、現在の作業ディレクトリ（`cwd`）が`GOROOT`と`GOPATH`のどちらに属しているかを判断し、そのルートからの相対パスを返します。

1.  `cwd, err := os.Getwd()`: 現在の作業ディレクトリのパスを取得します。
2.  `if root := runtime.GOROOT(); strings.HasPrefix(cwd, root)`: まず、`cwd`が`GOROOT`のパスで始まっているかを確認します。
    *   もしそうであれば、`filepath.Rel(root, cwd)`を使って`GOROOT`からの相対パスを計算し、`true`（`underGoRoot`）と共に返します。
3.  `for _, p := range filepath.SplitList(build.Default.GOPATH)`: `cwd`が`GOROOT`配下になかった場合、システムに設定されているすべての`GOPATH`エントリをループします。`filepath.SplitList`は、複数のパスがコロン（Linux/macOS）やセミコロン（Windows）で区切られている`GOPATH`文字列を個々のパスに分割します。
    *   `if !strings.HasPrefix(cwd, p)`: 現在の`GOPATH`エントリ`p`が`cwd`のプレフィックスでない場合、次の`GOPATH`エントリに進みます。
    *   `subdir, err := filepath.Rel(p, cwd)`: `cwd`が現在の`GOPATH`エントリ`p`の配下にある場合、`p`からの相対パスを計算します。
    *   `if err == nil`: エラーがなければ、その相対パスと`false`（`underGoRoot`ではない）を返します。
4.  `log.Fatalf(...)`: どの`GOROOT`または`GOPATH`にも属さない場合、致命的なエラーとしてプログラムを終了します。

### `main()` 関数における変更

*   **一時ディレクトリの準備**:
    *   `deviceGotmp := fmt.Sprintf("/data/local/tmp/%s-%d", filepath.Base(os.Args[1]), os.Getpid())`: 実行されるバイナリ名とプロセスIDを基に、ユニークな一時ディレクトリ名を作成します。
    *   `run("shell", "mkdir", "-p", deviceGotmp)`: Androidデバイス上にこの一時ディレクトリを作成します。
*   **パッケージパスの決定**:
    *   `subdir, inGoRoot := subdir()`: 上記の`subdir()`関数を呼び出し、パッケージの相対パスと、それが`GOROOT`配下にあるかどうかの情報を取得します。
    *   `deviceCwd := filepath.Join(deviceGoroot, subdir)`: デバイス上での作業ディレクトリの初期パスを`deviceGoroot`と`subdir`を結合して設定します。
    *   `if !inGoRoot { deviceCwd = filepath.Join(deviceGopath, subdir) }`: もしパッケージが`GOROOT`配下になければ（つまり`GOPATH`配下であれば）、`deviceCwd`を`deviceGopath`と`subdir`を結合したものに上書きします。これにより、`cd`コマンドが正しいディレクトリに移動できるようになります。
*   **バイナリの配置**:
    *   `deviceBin := fmt.Sprintf("%s/%s-%d", deviceGotmp, binName, os.Getpid())`: 実行されるバイナリが、新しく作成された一時ディレクトリ`deviceGotmp`に配置されるようにパスを変更します。
*   **`adb shell`コマンドの構築**:
    *   `cmd := `export TMPDIR=\"` + deviceGotmp + `\"` + ...`: `TMPDIR`環境変数を`deviceGotmp`に設定します。これにより、Goバイナリが一時ファイルを生成する際に、このディレクトリを使用するよう促します。
    *   ``; export GOPATH=\"` + deviceGopath + `\"` + ...`: `GOPATH`環境変数を設定します。
    *   ``; cd \"` + deviceCwd + `\"` + ...`: `cd`コマンドのターゲットを、動的に決定された`deviceCwd`に設定します。
*   **クリーンアップ**:
    *   `run("shell", "rm", "-rf", deviceGotmp)`: バイナリ実行後、`deviceGotmp`ディレクトリ全体を再帰的に削除します。これにより、バイナリ自体と、その実行中に生成されたすべての一時ファイルが確実にクリーンアップされます。

これらの変更により、`go_android_exec.go`は、Goの標準的な開発環境（`GOPATH`の使用）により適応し、Androidデバイス上でのテスト実行の信頼性とクリーンアップの効率が向上しました。
