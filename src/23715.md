## 元コミット内容

`cmd/go: update documentation: use 'go doc' rather than 'godoc'`

このコミットは、`go` コマンドのドキュメントを更新し、`godoc` コマンドではなく `go doc` コマンドを使用するように変更します。

## 変更の背景

Go言語の初期のバージョンでは、`godoc` はGoのソースコードからドキュメントを生成し、表示するためのスタンドアロンツールでした。これは、ローカルのGoインストールに含まれるパッケージや、Goの標準ライブラリのドキュメントを参照するのに非常に便利でした。また、`godoc -http=:6060` のように実行することで、Webサーバーとしてドキュメントを提供することもできました。

しかし、Goツールチェインの進化に伴い、`go` コマンド自体がより多くの機能を取り込むようになりました。その一環として、`go doc` サブコマンドが導入され、`godoc` と同様のドキュメント表示機能が `go` コマンドに統合されました。これにより、ユーザーは `go` コマンド一つでビルド、テスト、フォーマット、そしてドキュメント参照まで行えるようになり、ツールの統一性が向上しました。

このコミットは、この統合された `go doc` の利用を促進し、`go` コマンドの内部ドキュメントが最新の推奨プラクティスを反映するようにするためのものです。具体的には、`go fix`、`go fmt`、`go vet`、`go test` などのサブコマンドのヘルプメッセージや、`cgo`、`runtime` パッケージのドキュメント参照箇所において、`godoc` への言及を `go doc` に置き換えています。

## 前提知識の解説

*   **Goコマンド (`go`):** Go言語の公式ツールチェインの中心となるコマンドラインツールです。コードのビルド、テスト、依存関係の管理、フォーマット、ドキュメントの表示など、Go開発における多岐にわたるタスクを実行します。
*   **`godoc` コマンド (旧):** Go言語の初期に存在した、Goのソースコードからドキュメントを生成・表示するためのスタンドアロンツールです。パッケージ、関数、型などのドキュメントをコマンドラインで表示したり、Webサーバーとして提供したりする機能がありました。
*   **`go doc` サブコマンド (現行):** `go` コマンドの一部として統合されたドキュメント表示機能です。`godoc` と同様に、Goのソースコードからドキュメントを抽出し、コマンドラインに表示します。例えば、`go doc fmt` で `fmt` パッケージのドキュメントを、`go doc fmt.Println` で `fmt` パッケージの `Println` 関数のドキュメントを表示できます。
*   **Goのドキュメンテーション規約:** Go言語では、エクスポートされた（大文字で始まる）パッケージ、関数、型、変数、定数には、その直前にコメントを記述することでドキュメントとして扱われます。このコメントは `godoc` や `go doc` によって抽出され、表示されます。

## 技術的詳細

このコミットは、Goツールチェインのユーザーインターフェースにおける一貫性を高めるための、純粋なドキュメントの更新です。コードの振る舞いを変更するものではなく、ユーザーがドキュメントを参照する際に推奨されるコマンドを明確にするものです。

具体的には、`src/cmd/go` ディレクトリ内の複数のファイル（`alldocs.go`, `fix.go`, `fmt.go`, `help.go`, `test.go`）において、文字列リテラル内の `godoc` への参照が `go doc` に変更されています。

変更のパターンは以下の通りです。

*   `'godoc fix'` -> `'go doc cmd/fix'`
*   `'godoc gofmt'` -> `'go doc cmd/gofmt'`
*   `'godoc golang.org/x/tools/cmd/vet'` -> `'go doc cmd/vet'`
*   `'godoc cmd/cgo'` -> `'go doc cmd/cgo'`
*   `'godoc runtime SetBlockProfileRate'` -> `'go doc runtime.SetBlockProfileRate'`
*   `'godoc runtime MemProfileRate'` -> `'go doc runtime.MemProfileRate'`

注目すべきは、`godoc <package>` の形式が `go doc cmd/<command>` や `go doc <package>.<symbol>` の形式に変わっている点です。これは、`go doc` がコマンドラインツール自体 (`cmd/fix` など) や、特定のパッケージ内のシンボル (`runtime.SetBlockProfileRate`) をより直接的に参照できるようになったことを示しています。

この変更は、Goのドキュメントシステムがより洗練され、`go` コマンドに統合された結果であり、ユーザー体験の向上を目的としています。

## コアとなるコードの解説

このコミットにおける「コアとなるコード」は、Goコマンドのヘルプメッセージやドキュメント文字列を定義している部分です。これらの文字列は、ユーザーが `go help <command>` や `go doc <package>` などを実行した際に表示される情報源となります。

例えば、`src/cmd/go/alldocs.go` の以下の変更を見てみましょう。

```diff
--- a/src/cmd/go/alldocs.go
+++ b/src/cmd/go/alldocs.go
@@ -287,7 +287,7 @@ Usage:
 
 Fix runs the Go fix command on the packages named by the import paths.
 
-For more about fix, see 'godoc fix'.
+For more about fix, see 'go doc cmd/fix'.
 For more about specifying packages, see 'go help packages'.
 
 To run fix with specific options, run 'go tool fix'.
```

ここでは、`go fix` コマンドに関する説明文の中で、「`fix` についてさらに詳しく知るには、`'godoc fix'` を参照してください」という指示が、「`fix` についてさらに詳しく知るには、`'go doc cmd/fix'` を参照してください」という指示に変わっています。

この変更は、Goのドキュメントシステムが `go` コマンドに統合されたことをユーザーに伝えるためのものです。`godoc` はスタンドアロンツールでしたが、`go doc` は `go` コマンドのサブコマンドとして機能します。また、`godoc fix` のようにコマンド名を直接指定する代わりに、`go doc cmd/fix` のように `cmd/` プレフィックスを付けてツールチェイン内のコマンドを明示的に参照する形式が推奨されるようになりました。これは、パッケージとコマンドの区別を明確にし、より正確なドキュメント参照を可能にします。

同様に、`runtime.SetBlockProfileRate` のような特定の関数や変数のドキュメントを参照する場合も、`godoc runtime SetBlockProfileRate` のようにスペース区切りで指定する形式から、`go doc runtime.SetBlockProfileRate` のようにドット表記でシンボルを指定する形式に統一されています。これは、Goの言語仕様におけるパッケージとシンボルの階層構造を反映した、より自然な参照方法です。

これらの変更は、Goツールチェインのドキュメント参照方法の進化と、それによるユーザー体験の改善を示しています。
