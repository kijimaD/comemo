# [インデックス 20718] ファイルの概要

このコミットは、Go言語の `math/big` パッケージにおける `Exp` (べき乗剰余) 関数の振る舞いを修正するものです。具体的には、`Exp(x, y, m)` が `x` の `y` 乗を `m` で割った剰余を計算する際に、結果が常に非負 (0以上) となるように変更されています。これは、`math/big` パッケージの `Mod` (剰余) 演算がユークリッド剰余 (常に非負) を返すという仕様に合わせるための修正です。

## 元コミット内容

`math/big: math.Exp should return result >= 0 for |m| > 0`

このコミットは、`math/big` パッケージの `Exp` 関数が、`m` が `nil` でなく `m > 0` の場合に `x**y mod |m|` を計算する際に、結果が常に0以上になるように修正することを目的としています。`math/big` パッケージの `Mod` 関数はユークリッド剰余を計算し、これは常に0以上を返します。この修正は、Issue #8822 を解決します。

## 変更の背景

この変更の背景には、`math/big` パッケージにおける剰余演算の定義と、`Exp` 関数の期待される振る舞いの間の不整合がありました。

Go言語の `math/big` パッケージは、任意精度の整数演算を提供します。その中で `Exp(x, y, m)` 関数は、`x` の `y` 乗を `m` で割った剰余を計算する、いわゆる「べき乗剰余」を実装しています。この関数は、暗号学的な計算（例: RSA暗号）や、大きな数値を用いた数学的アルゴリズムで頻繁に利用されます。

問題は、剰余演算の定義にありました。数学にはいくつかの剰余の定義が存在します。
1.  **切り捨て剰余 (Truncated Modulo)**: 商を0方向に切り捨てる。結果の符号は被除数と同じになる。多くのプログラミング言語（C, Java, Goの組み込み `%` 演算子など）で採用されている。
2.  **床関数剰余 (Floored Modulo)**: 商を負の無限大方向に切り捨てる。結果の符号は除数と同じになる。
3.  **ユークリッド剰余 (Euclidean Modulo)**: 結果が常に非負となるように定義される。数学的な性質が良く、特に数論で好まれる。

`math/big` パッケージの `Mod` 関数は、ユークリッド剰余の定義を採用しており、常に0以上の結果を返します。しかし、`Exp` 関数が内部的に計算する `x**y mod |m|` の結果が、`x**y` が負の値になる場合に、負の剰余を返す可能性がありました。これは、`Exp` 関数のドキュメントが「`x**y mod |m|` を計算する」と明記しているにもかかわらず、`Mod` 関数の振る舞いと一致しないという矛盾を生んでいました。

具体的には、`x` が負で `y` が奇数の場合、`x**y` は負になります。この負の値を `m` で割った剰余が、`math/big` の `Mod` 関数の定義に従って常に非負であるべきなのに、そうならないケースがあったのです。

この不整合は、Issue #8822 として報告されました。このコミットは、この不整合を解消し、`Exp` 関数の結果が `math/big` パッケージ全体の剰余演算のセマンティクス（ユークリッド剰余、すなわち常に非負）に準拠するように修正することを目的としています。これにより、`math/big` パッケージの一貫性と予測可能性が向上し、利用者が期待する数学的な振る舞いが保証されます。

## 前提知識の解説

このコミットを理解するためには、以下の概念を理解しておく必要があります。

1.  **任意精度整数 (Arbitrary-Precision Integers)**:
    通常のプログラミング言語の組み込み整数型（例: Goの `int64`）は、表現できる数値の範囲が固定されています。これに対し、任意精度整数は、メモリが許す限り任意の大きさの整数を表現できるデータ型です。`math/big` パッケージは、Go言語でこの機能を提供します。内部的には、整数の各桁をスライス（配列）の要素として保持し、必要に応じてスライスを拡張することで大きな数を扱います。

2.  **べき乗剰余 (Modular Exponentiation)**:
    `x^y mod m` の形式で表される計算です。これは「`x` を `y` 乗し、その結果を `m` で割った余り」を意味します。特に、`x`, `y`, `m` が非常に大きな数になる場合でも効率的に計算できるアルゴリズム（例: バイナリ法、繰り返し二乗法）が用いられます。暗号学（RSA、Diffie-Hellman鍵交換など）やハッシュ関数、擬似乱数生成など、多くの分野で利用されます。

3.  **剰余演算の定義 (Definitions of Modulo Operation)**:
    前述の通り、剰余演算には複数の定義があります。
    *   **数学的な剰余**: 通常、結果は `0 <= r < |m|` の範囲に収まります。負の数に対する剰余の定義は文脈によって異なります。
    *   **プログラミング言語における剰余演算子 (`%`)**: 多くの言語では、商を0方向に切り捨てるため、結果の符号は被除数と同じになります。例えば、`-5 % 3` は `-2` となります。
    *   **ユークリッド剰余**: `a = qm + r` かつ `0 <= r < |m|` を満たす `r` を返します。この定義では、結果は常に非負です。例えば、`-5 mod 3` は `1` となります（`-5 = (-2) * 3 + 1`）。`math/big` パッケージの `Mod` 関数はこの定義に従います。

4.  **Go言語の `math/big` パッケージ**:
    Go標準ライブラリの一部で、任意精度の整数 (`Int`)、有理数 (`Rat`)、浮動小数点数 (`Float`) を扱うための型とメソッドを提供します。
    *   `Int.Exp(x, y, m *Int) *Int`: `z = x^y mod m` を計算し、`z` を返します。`m` が `nil` の場合、または `m` が `0` の場合、剰余は計算されず、`x^y` がそのまま返されます。
    *   `Int.Mod(x, m *Int) *Int`: `z = x mod m` を計算し、`z` を返します。`m` が `0` の場合、パニックが発生します。`m` が負の場合、`|m|` を法とします。結果は常に `0 <= z < |m|` の範囲に収まります。

このコミットは、`Exp` 関数が `math/big` パッケージの `Mod` 関数のユークリッド剰余のセマンティクスに準拠するように、負の剰余結果を非負に調整するものです。

## 技術的詳細

このコミットの技術的な核心は、`math/big.Int.Exp` 関数が計算した中間結果が負になる場合に、それをユークリッド剰余の定義に従って非負の値に変換するロジックを追加した点にあります。

`Exp(x, y, m)` 関数は、まず `x` の `y` 乗を計算し、その結果に対して `m` を法とする剰余を求めます。内部的には、`z.abs = z.abs.expNN(x.abs, yWords, mWords)` の行で、符号を考慮しない絶対値ベースのべき乗剰余計算が行われます。この `expNN` 関数は、非負の数に対する計算を行います。

問題は、`x` が負の数であり、かつ `y` が奇数の場合です。このとき、`x` の `y` 乗の結果は負の数になります。例えば、`(-5)^1 mod 7` を考えます。
*   `(-5)^1 = -5`
*   `math/big` の `Mod` 関数の定義では、`-5 mod 7` は `2` となります（`-5 = (-1) * 7 + 2`）。
*   しかし、修正前の `Exp` 関数は、内部計算の結果が `-5` のままで、`z.neg` フラグが `true` に設定される可能性がありました。

このコミットで追加されたコードは、この状況を検出し、結果を修正します。

```go
	if z.neg && len(mWords) > 0 {
		// make modulus result positive
		z.abs = z.abs.sub(mWords, z.abs) // z == x**y mod |m| && 0 <= z < |m|
		z.neg = false
	}
```

このコードブロックの動作は以下の通りです。

1.  `if z.neg && len(mWords) > 0`:
    *   `z.neg`: `Exp` 関数の計算結果 `z` が負の数である場合に `true` となります。これは、`x` が負で `y` が奇数の場合に発生します。
    *   `len(mWords) > 0`: 法 `m` が0でないことを確認します。`m` が0の場合、剰余演算は行われず、`x^y` がそのまま返されるため、この修正は不要です。

2.  `z.abs = z.abs.sub(mWords, z.abs)`:
    *   `z.abs` は現在の `z` の絶対値を表します。
    *   `mWords` は法 `m` の絶対値を表します。
    *   この行は、`z.abs` を `m.abs - z.abs` に更新します。
    *   例: `z` が `-5` で `m` が `7` の場合、`z.abs` は `5`、`mWords` は `7` です。計算は `7 - 5 = 2` となり、`z.abs` は `2` に更新されます。
    *   これは、負の剰余 `r` をユークリッド剰余 `r'` に変換する標準的な方法です。`r' = r + |m|` (もし `r < 0` なら) または `r' = r - |m|` (もし `r >= |m|` なら) のいずれかですが、ここでは `r` が負であるため、`r + |m|` に相当する操作を行っています。`z` が負であるため、`z = -z.abs` です。したがって、`z + |m| = -z.abs + |m| = |m| - z.abs` となり、この計算が正しいことがわかります。

3.  `z.neg = false`:
    *   結果が非負になったため、`z` の符号フラグを `false` に設定します。

この修正により、`Exp` 関数は `math/big` パッケージの `Mod` 関数と同じユークリッド剰余のセマンティクスに従い、常に非負の剰余結果を返すようになります。これにより、パッケージ全体の一貫性が保たれ、利用者は `Exp` の結果が常に `0 <= result < |m|` の範囲にあることを信頼できるようになります。

## コアとなるコードの解説

`src/math/big/int.go` の `Exp` 関数に追加された以下のコードブロックが、このコミットの核心です。

```go
		if z.neg && len(mWords) > 0 {
			// make modulus result positive
			z.abs = z.abs.sub(mWords, z.abs) // z == x**y mod |m| && 0 <= z < |m|
			z.neg = false
		}
```

このコードは、`Exp` 関数の計算結果 `z` が負であり（`z.neg` が `true`）、かつ法 `m` が0でない（`len(mWords) > 0`）場合に実行されます。

1.  `z.neg`: `z` が負の数であることを示します。これは、基数 `x` が負で、指数 `y` が奇数の場合に発生する可能性があります。例えば、`(-5)^1 = -5` のようなケースです。
2.  `len(mWords) > 0`: 法 `m` が有効な（0でない）モジュラスであることを確認します。`m` が0の場合、剰余演算は行われず、`x^y` がそのまま返されるため、この修正は適用されません。
3.  `z.abs = z.abs.sub(mWords, z.abs)`:
    *   `z.abs` は `z` の絶対値を表す `nat` 型（自然数、つまり非負の整数）のスライスです。
    *   `mWords` は法 `m` の絶対値を表す `nat` 型のスライスです。
    *   この行は、`z` が負の場合に、その絶対値 `z.abs` を `|m| - z.abs` に変換します。
    *   例: `z = -5`, `m = 7` の場合、`z.abs = 5`, `mWords = 7`。計算は `7 - 5 = 2` となり、`z.abs` は `2` に更新されます。
    *   これにより、負の剰余 `-5` が、ユークリッド剰余の定義に従った非負の剰余 `2` に変換されます。これは、`-5 mod 7 = 2` という数学的な関係に基づいています。
4.  `z.neg = false`:
    *   `z.abs` が更新され、結果が非負になったため、`z` の符号フラグ `z.neg` を `false` に設定します。

この修正により、`Exp` 関数は `math/big` パッケージの `Mod` 関数と同様に、常に `0 <= result < |m|` の範囲の非負の剰余を返すようになります。これにより、`math/big` パッケージ全体での剰余演算のセマンティクスが一貫し、利用者が期待する数学的な振る舞いが保証されます。

`src/math/big/int_test.go` に追加されたテストケース `{"-5", "1", "7", "2"}` は、この修正の意図を明確に示しています。これは `(-5)^1 mod 7` が `2` になることを検証するもので、修正前は期待通りの結果が得られなかった可能性があります。また、Issue #8822 に関連する非常に大きな数値のテストケースも追加されており、この問題が単なる小さな数値のケースだけでなく、任意精度の計算全体に影響を与える可能性があったことを示唆しています。
