このコミットは、GoコンパイラのSSAジェネレータにおいて、等価（Eq）および非等価（Neq）比較演算の全てのビットサイズ（8ビット、16ビット、32ビット、64ビット）を実装することを目的としています。

## 変更の背景

Goコンパイラは、プログラムの最適化と機械語への変換のためにSSA（Static Single Assignment）形式の中間表現を使用します。以前のGoコンパイラのSSAバックエンド（特にAMD64アーキテクチャ向け）では、等価・非等価比較演算（`Eq`や`Neq`）が主に64ビット幅（`Eq64`, `Neq64`）に特化して実装されており、`CMPQ`（Compare Quadword）命令を使用していました。

しかし、プログラム中では64ビット以外のデータ型（例: `int8`, `int16`, `int32`）も頻繁に使用されます。これらの小さなサイズの比較を行う際、常に64ビットの比較命令を使用することは、不必要なレジスタの拡張や、場合によっては非効率なコード生成につながる可能性がありました。例えば、32ビットの整数を比較する際に64ビットの比較命令を使うと、上位32ビットがゼロクリアされていることを保証するための追加の命令が必要になるか、あるいは比較結果が意図しないものになるリスクがありました。

このコミットの背景には、Goコンパイラのコード生成の精度と効率を向上させるという目的があります。具体的には、各ビットサイズに対応する適切な比較命令（`CMPB`, `CMPW`, `CMPL`, `CMPQ`）を使用することで、生成されるアセンブリコードをより最適化し、実行時のパフォーマンスを向上させることが期待されます。これにより、SSA形式からAMD64アセンブリへの変換がより直接的かつ効率的になります。

## 前提知識の解説

### 1. GoコンパイラとSSA (Static Single Assignment) 形式

*   **Goコンパイラ**: Go言語のソースコードを機械語に変換するツールです。複数のステージを経てコードを処理し、最終的に実行可能なバイナリを生成します。
*   **SSA形式**: コンパイラの中間表現（IR: Intermediate Representation）の一種で、「静的単一代入」を意味します。SSA形式では、各変数が一度だけ代入されるように変換されます。これにより、データフロー解析や最適化が非常に容易になります。Goコンパイラは、AST（Abstract Syntax Tree）からSSA形式に変換し、様々な最適化パスを適用した後、最終的に機械語に変換します。

### 2. AMD64アーキテクチャとアセンブリ命令

*   **AMD64 (x86-64)**: 現代のほとんどのデスクトップおよびサーバーCPUで使用されている64ビット命令セットアーキテクチャです。
*   **レジスタ**: CPU内部にある高速な記憶領域です。AMD64には汎用レジスタ（RAX, RBX, RCX, RDXなど）や、特定の目的を持つレジスタ（RSP: スタックポインタ、RBP: ベースポインタ、RFLAGS: フラグレジスタなど）があります。
*   **RFLAGSレジスタ**: CPUのステータスフラグを格納するレジスタです。比較演算や算術演算の結果に応じて、特定のビット（フラグ）がセットまたはクリアされます。例えば、ゼロフラグ（ZF）、キャリーフラグ（CF）、サインフラグ（SF）、オーバーフローフラグ（OF）などがあります。
*   **比較命令 (CMP)**: `CMP`命令は、2つのオペランドを減算し、その結果に基づいてRFLAGSレジスタのフラグを更新しますが、結果は保存しません。
    *   `CMPB`: 8ビット（バイト）の比較
    *   `CMPW`: 16ビット（ワード）の比較
    *   `CMPL`: 32ビット（ロングワード）の比較
    *   `CMPQ`: 64ビット（クアッドワード）の比較
*   **条件付きセット命令 (SETcc)**: `SETcc`命令は、`CMP`命令によって設定されたRFLAGSレジスタのフラグの状態に基づいて、指定されたバイトレジスタに0または1を書き込みます。
    *   `SETEQ` (Set if Equal): ゼロフラグ（ZF）がセットされている場合（つまり、比較結果が等しい場合）に1をセットします。
    *   `SETNE` (Set if Not Equal): ゼロフラグ（ZF）がクリアされている場合（つまり、比較結果が等しくない場合）に1をセットします。

### 3. Goコンパイラのコード生成におけるSSAルール

GoコンパイラのSSAバックエンドでは、SSA形式の抽象的な操作を特定のアーキテクチャの具体的なアセンブリ命令に変換するために「ルール」が使用されます。これらのルールは、`*.rules`ファイルに記述されており、パターンマッチングと書き換えによって機能します。例えば、`Eq64`というSSA操作が`CMPQ`と`SETEQ`の組み合わせに変換される、といった具合です。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおけるAMD64アーキテクチャ向けのコード生成ロジックを拡張し、`Eq`（等価）および`Neq`（非等価）比較演算が、データ型のビットサイズに応じて適切なAMD64の比較命令（`CMPB`, `CMPW`, `CMPL`, `CMPQ`）を使用するように変更します。

具体的な変更点は以下の通りです。

1.  **新しいSSA操作の定義**:
    *   `src/cmd/compile/internal/ssa/opGen.go` に、新しいAMD64固有の比較操作 `OpAMD64CMPL`, `OpAMD64CMPW`, `OpAMD64CMPB` が追加されます。これらはそれぞれ32ビット、16ビット、8ビットの比較に対応します。
    *   これらの操作には、対応するx86アセンブリ命令（`x86.ACMPL`, `x86.ACMPW`, `x86.ACMPB`）と、入力レジスタマスク、出力レジスタマスク（RFLAGSレジスタが影響を受けることを示す）が定義されます。

2.  **AMD64オペレーションの登録**:
    *   `src/cmd/compile/internal/ssa/gen/AMD64Ops.go` に、`CMPL`, `CMPW`, `CMPB` の名前と対応するアセンブリ命令が登録されます。これにより、SSAジェネレータがこれらの操作を認識し、コード生成時に利用できるようになります。

3.  **SSA書き換えルールの追加**:
    *   `src/cmd/compile/internal/ssa/gen/AMD64.rules` に、`Eq32`, `Eq16`, `Eq8`, `Neq32`, `Neq16`, `Neq8` の新しい書き換えルールが追加されます。
        *   例えば、`(Eq32 x y)` というSSA操作は、`(SETEQ (CMPL <TypeFlags> x y))` というAMD64固有の操作シーケンスに変換されます。これは、32ビットの比較（`CMPL`）を行い、その結果に基づいて等しい場合に1をセットする（`SETEQ`）というアセンブリ命令の組み合わせを意味します。
        *   同様に、`(Neq32 x y)` は `(SETNE (CMPL <TypeFlags> x y))` に変換されます。
    *   `src/cmd/compile/internal/ssa/rewriteAMD64.go` には、これらの新しいSSA操作（`OpEq16`, `OpEq32`, `OpEq8`, `OpNeq16`, `OpNeq32`, `OpNeq8`）を、対応するAMD64アセンブリ命令（`OpAMD64CMPW`, `OpAMD64CMPL`, `OpAMD64CMPB` と `OpAMD64SETEQ`, `OpAMD64SETNE`）に変換するための具体的なGoコードが追加されます。このコードは、SSA値のオペレーションを書き換え、新しいSSA値を生成して引数を設定する役割を担います。

4.  **`genValue`関数の更新**:
    *   `src/cmd/compile/internal/gc/ssa.go` の `genValue` 関数が更新され、`OpAMD64CMPL`, `OpAMD64CMPW`, `OpAMD64CMPB` が、SSA値からアセンブリ命令を生成する際の対象として追加されます。これにより、これらの新しい比較命令が実際にアセンブリコードに変換されるようになります。

これらの変更により、Goコンパイラは、プログラム中の異なるビットサイズの整数比較に対して、より適切なAMD64アセンブリ命令を選択できるようになり、結果として生成されるコードの効率と正確性が向上します。特に、小さなサイズの比較で不必要な64ビット操作を避けることで、命令数やレジスタ使用の最適化が図られます。

## コアとなるコードの解説

このコミットの核心は、GoコンパイラのSSAバックエンドが、異なるビットサイズの整数比較をより効率的にAMD64アセンブリ命令に変換できるようにすることです。

具体的には、以下のメカニズムが働いています。

1.  **SSA操作の拡張**: Goコンパイラは、プログラムをSSA形式に変換する際に、`Eq8`, `Eq16`, `Eq32`, `Eq64` (等価比較) や `Neq8`, `Neq16`, `Neq32`, `Neq64` (非等価比較) といった抽象的な操作を生成します。これらは、それぞれ8ビット、16ビット、32ビット、64ビットの整数に対する比較を表します。

2.  **AMD64固有の比較命令の導入**:
    *   `src/cmd/compile/internal/ssa/opGen.go` と `src/cmd/compile/internal/ssa/gen/AMD64Ops.go` では、AMD64アーキテクチャが提供する具体的な比較命令である `CMPB` (8ビット比較), `CMPW` (16ビット比較), `CMPL` (32ビット比較) をSSA操作として定義し、Goコンパイラがこれらを認識できるようにします。
    *   これらの命令は、2つのオペランドを比較し、その結果をCPUのRFLAGSレジスタに反映させます。例えば、オペランドが等しければゼロフラグ (ZF) がセットされます。

3.  **SSA書き換えルールによる変換**:
    *   `src/cmd/compile/internal/ssa/gen/AMD64.rules` は、SSA形式の抽象的な操作をAMD64固有の命令シーケンスに変換するためのルールを記述しています。
    *   例えば、`Eq32 x y` (32ビットのxとyが等しいか) というSSA操作は、`SETEQ (CMPL <TypeFlags> x y)` というルールによって変換されます。
        *   `CMPL <TypeFlags> x y`: これは、32ビットの`x`と`y`を比較し、RFLAGSレジスタを更新するAMD64の`CMPL`命令に対応します。`<TypeFlags>`は、この操作がRFLAGSレジスタに影響を与えることを示します。
        *   `SETEQ (...)`: これは、`CMPL`命令によって設定されたRFLAGSレジスタのゼロフラグ (ZF) をチェックし、ZFがセットされていれば（つまり比較結果が等しければ）1を、そうでなければ0を結果として生成するAMD64の`SETEQ`命令に対応します。
    *   `src/cmd/compile/internal/ssa/rewriteAMD64.go` には、これらのルールを実際に適用するGoコードが記述されています。`rewriteValueAMD64`関数内で、`OpEq16`, `OpEq32`, `OpEq8`, `OpNeq16`, `OpNeq32`, `OpNeq8` の各ケースが処理され、対応する`OpAMD64CMP*`と`OpAMD64SET*`の組み合わせにSSA値が書き換えられます。これにより、コンパイラはより低レベルでアーキテクチャに特化した表現に変換されます。

4.  **アセンブリコード生成**:
    *   `src/cmd/compile/internal/gc/ssa.go` の `genValue` 関数は、SSA形式の操作を最終的なAMD64アセンブリ命令に変換する役割を担います。このコミットにより、`OpAMD64CMPL`, `OpAMD64CMPW`, `OpAMD64CMPB` がこの関数で認識され、それぞれ対応する`CMPL`, `CMPW`, `CMPB`アセンブリ命令が生成されるようになります。

この一連の変更により、Goコンパイラは、Go言語のソースコードで記述された様々なビットサイズの整数比較を、AMD64プロセッサが最も効率的に実行できるネイティブな比較命令に直接マッピングできるようになります。これにより、生成されるバイナリのパフォーマンスが向上し、不必要な命令のオーバーヘッドが削減されます。
