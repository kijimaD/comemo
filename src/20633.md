# [インデックス 20633] ファイルの概要

このコミットは、Goコンパイラ（`cmd/gc`）における型チェックの改善に関するものです。具体的には、コンパイル時に定数文字列に対して範囲外のスライス操作が行われた場合に、適切なエラーを報告するように修正されています。これにより、開発者はコンパイル時に不正なスライス操作を検知できるようになり、実行時エラーや予期せぬ挙動を防ぐことができます。

## 変更の背景

Go言語では、文字列はバイトの不変なシーケンスとして扱われます。文字列のスライス操作は非常に一般的ですが、コンパイル時に値が確定している定数文字列に対して、その長さを超える範囲でスライスを試みた場合、Goコンパイラが適切なエラーを報告しないという問題（Issue 7200）が存在していました。

この問題は、開発者が意図しない範囲外のスライス操作を行っても、コンパイル時には警告されず、実行時にパニック（panic）を引き起こす可能性がありました。これは、プログラムの堅牢性を損ない、デバッグを困難にする要因となります。

このコミットは、このような潜在的な実行時エラーをコンパイル時に捕捉し、開発者に早期にフィードバックを提供することを目的としています。これにより、Goプログラムの安全性と信頼性が向上します。

## 前提知識の解説

このコミットの理解には、以下のGo言語およびコンパイラの概念に関する知識が役立ちます。

*   **Go言語の文字列**: Goの文字列は、読み取り専用のバイトスライスとして内部的に表現されます。文字列は不変であり、スライス操作を行っても元の文字列のデータは変更されず、新しい文字列ヘッダが作成されるだけです。
*   **定数 (Constants)**: Goにおける定数は、コンパイル時にその値が確定するリテラルです。定数文字列もこれに含まれ、その長さもコンパイル時に既知です。
*   **スライス操作**: Goでは、配列、スライス、文字列に対して `[low:high]` または `[low:high:capacity]` の形式でスライス操作を行うことができます。`low` は開始インデックス（含む）、`high` は終了インデックス（含まない）を示します。
*   **Goコンパイラ (`cmd/gc`)**: Go言語の公式コンパイラであり、ソースコードを機械語に変換する役割を担います。コンパイルプロセスには、字句解析、構文解析、型チェック、最適化、コード生成などのフェーズが含まれます。
*   **型チェック (Type Checking)**: コンパイラの重要なフェーズの一つで、プログラム内のすべての式や変数がGo言語の型システム規則に準拠しているかを確認します。例えば、整数型と文字列型を直接加算するような不正な操作を検出します。
*   **抽象構文木 (AST - Abstract Syntax Tree)**: ソースコードの構文構造を木構造で表現したものです。コンパイラはソースコードをASTに変換し、このASTを操作しながら型チェックやコード生成を行います。
*   **`Node`**: Goコンパイラの内部でASTの各要素を表すデータ構造です。例えば、変数、リテラル、演算子などが`Node`として表現されます。
*   **`yyerror`**: Goコンパイラのフロントエンドでエラーを報告するために使用される関数です。通常、`yacc`や`bison`のようなパーサジェネレータによって生成されたコードで使用されます。

## 技術的詳細

このコミットの主要な変更は、Goコンパイラの型チェックフェーズ、特に`src/cmd/gc/typecheck.c`ファイル内の`checksliceindex`関数に集中しています。

以前の`checksliceindex`関数は、スライス操作のインデックスが有効であるかをチェックしていましたが、定数文字列に対する範囲外のスライス操作を明示的に検出するロジックが不足していました。

このコミットでは、以下の点が変更されています。

1.  **`checksliceindex`関数のシグネチャ変更**:
    `static int checksliceindex(Node *r, Type *tp)` から `static int checksliceindex(Node *l, Node *r, Type *tp)` へと変更されました。
    新しい引数 `Node *l` は、スライス操作の対象となる左辺の式（この場合は定数文字列）を表します。これにより、`checksliceindex`関数内でスライス対象の型や値（特に文字列の長さ）にアクセスできるようになりました。

2.  **定数文字列の範囲外スライスチェックの追加**:
    `checksliceindex`関数内に、以下の新しい条件が追加されました。
    ```c
    else if(isconst(l, CTSTR) && mpgetfix(r->val.u.xval) > l->val.u.sval->len) {
        yyerror("invalid slice index %N (out of bounds for %d-byte string)", r, l->val.u.sval->len);
        return -1;
    }
    ```
    *   `isconst(l, CTSTR)`: スライス対象の左辺 `l` が定数文字列であるかを確認します。
    *   `mpgetfix(r->val.u.xval)`: スライスインデックス `r` の定数値を取得します。`mpgetfix`は多倍長整数（multi-precision integer）から固定長の整数値を取得する関数です。
    *   `l->val.u.sval->len`: 定数文字列 `l` のバイト長を取得します。
    *   この条件は、インデックスが文字列の長さを超えている場合に真となり、`yyerror`関数を呼び出してコンパイルエラーを報告します。エラーメッセージには、不正なインデックスと文字列の長さが含まれ、開発者にとって分かりやすい情報が提供されます。

3.  **`typecheck1`関数内の`checksliceindex`呼び出しの更新**:
    `typecheck1`関数内で`checksliceindex`が呼び出されている箇所が、新しいシグネチャに合わせて`l`（スライス対象のノード）を渡すように修正されました。これにより、定数文字列のスライスチェックが正しく機能するようになります。

4.  **テストケースの追加**:
    `test/fixedbugs/issue4232.go`ファイルが更新され、定数文字列に対する様々な範囲外スライス操作のテストケースが追加されました。これらのテストケースは、コンパイラが期待通りにエラーを報告するかどうかを検証します。特に、`c[10]`（長さ10の文字列に対してインデックス10）、`c[9:12]`（範囲外の終了インデックス）、`c[1<<100 : 1<<110]`（非常に大きなインデックス）などが追加されています。

これらの変更により、Goコンパイラは定数文字列の範囲外スライスをコンパイル時に検出し、開発者に明確なエラーメッセージを提示できるようになりました。

## コアとなるコードの解説

このコミットの核心は、`src/cmd/gc/typecheck.c` ファイル内の `checksliceindex` 関数にあります。

1.  **`checksliceindex` 関数の拡張**:
    この関数は、スライス操作のインデックスが有効な範囲内にあるかをチェックする役割を担っています。変更前は、スライス対象の型情報 (`Type *tp`) とインデックスのノード (`Node *r`) のみを受け取っていました。
    変更後は、スライス対象の式全体を表す `Node *l` が追加されました。これにより、`checksliceindex` はスライスされる元のデータ（配列、スライス、または文字列）に関するより詳細な情報にアクセスできるようになりました。

2.  **定数文字列の範囲チェックロジックの追加**:
    `checksliceindex` 関数内に、以下の新しい条件分岐が追加されました。
    ```c
    } else if(isconst(l, CTSTR) && mpgetfix(r->val.u.xval) > l->val.u.sval->len) {
        yyerror("invalid slice index %N (out of bounds for %d-byte string)", r, l->val.u.sval->len);
        return -1;
    }
    ```
    *   `isconst(l, CTSTR)`: これは、スライス操作の左辺 `l` がコンパイル時に値が確定している「定数文字列」であるかどうかを判定します。`CTSTR` は、Goコンパイラ内部で定数文字列を表す型定数です。
    *   `mpgetfix(r->val.u.xval)`: スライスインデックス `r` が定数である場合、その定数値を抽出します。`r->val.u.xval` は、`r` が表す定数値（多倍長整数形式）を指し、`mpgetfix` はそれを通常の整数値に変換します。
    *   `l->val.u.sval->len`: 定数文字列 `l` の実際のバイト長を取得します。Goの文字列はバイトのシーケンスであるため、`len` はバイト数を返します。
    *   この `if` 文は、「もしスライス対象が定数文字列であり、かつ指定されたインデックスがその文字列の長さを超えている場合」に真となります。
    *   条件が真の場合、`yyerror` 関数が呼び出され、コンパイルエラーが報告されます。エラーメッセージには、不正なインデックスの値 (`%N`) と、その文字列の実際の長さ (`%d-byte string`) が含まれるため、開発者は問題の原因をすぐに特定できます。`return -1;` は、エラーが発生したことを呼び出し元に通知します。

3.  **`typecheck1` からの呼び出し箇所の修正**:
    `typecheck1` 関数は、Goコンパイラの型チェックの主要なエントリポイントの一つです。この関数内で、スライス操作に関連するノードが処理される際に `checksliceindex` が呼び出されます。今回の変更により、`checksliceindex` のシグネチャが変わったため、`typecheck1` 内のすべての `checksliceindex` 呼び出しが、スライス対象のノード `l` を最初の引数として渡すように更新されました。

これらの変更により、Goコンパイラは定数文字列に対する不正なスライス操作をコンパイル時に検出し、実行時パニックを未然に防ぐことができるようになりました。これは、Goプログラムの堅牢性と開発者の生産性向上に貢献する重要な改善です。

*   **Goコンパイラ (`cmd/gc`)**: Go言語の公式コンパイラであり、ソースコードを機械語に変換する役割を担います。コンパイルプロセスには、字句解析、構文解析、型チェック、最適化、コード生成などのフェーズが含まれます。
*   **型チェック (Type Checking)**: コンパイラの重要なフェーズの一つで、プログラム内のすべての式や変数がGo言語の型システム規則に準拠しているかを確認します。例えば、整数型と文字列型を直接加算するような不正な操作を検出します。
*   **抽象構文木 (AST - Abstract Syntax Tree)**: ソースコードの構文構造を木構造で表現したものです。コンパイラはソースコードをASTに変換し、このASTを操作しながら型チェックやコード生成を行います。
*   **`Node`**: Goコンパイラの内部でASTの各要素を表すデータ構造です。例えば、変数、リテラル、演算子などが`Node`として表現されます。
*   **`yyerror`**: Goコンパイラのフロントエンドでエラーを報告するために使用される関数です。通常、`yacc`や`bison`のようなパーサジェネレータによって生成されたコードで使用されます。

## 技術的詳細

このコミットの主要な変更は、Goコンパイラの型チェックフェーズ、特に`src/cmd/gc/typecheck.c`ファイル内の`checksliceindex`関数に集中しています。

以前の`checksliceindex`関数は、スライス操作のインデックスが有効であるかをチェックしていましたが、定数文字列に対する範囲外のスライス操作を明示的に検出するロジックが不足していました。

このコミットでは、以下の点が変更されています。

1.  **`checksliceindex`関数のシグネチャ変更**:
    `static int checksliceindex(Node *r, Type *tp)` から `static int checksliceindex(Node *l, Node *r, Type *tp)` へと変更されました。
    新しい引数 `Node *l` は、スライス操作の対象となる左辺の式（この場合は定数文字列）を表します。これにより、`checksliceindex`関数内でスライス対象の型や値（特に文字列の長さ）にアクセスできるようになりました。

2.  **定数文字列の範囲外スライスチェックの追加**:
    `checksliceindex`関数内に、以下の新しい条件が追加されました。
    ```c
    else if(isconst(l, CTSTR) && mpgetfix(r->val.u.xval) > l->val.u.sval->len) {
        yyerror("invalid slice index %N (out of bounds for %d-byte string)", r, l->val.u.sval->len);
        return -1;
    }
    ```
    *   `isconst(l, CTSTR)`: スライス対象の左辺 `l` が定数文字列であるかを確認します。
    *   `mpgetfix(r->val.u.xval)`: スライスインデックス `r` の定数値を取得します。`mpgetfix`は多倍長整数（multi-precision integer）から固定長の整数値を取得する関数です。
    *   `l->val.u.sval->len`: 定数文字列 `l` のバイト長を取得します。
    *   この条件は、インデックスが文字列の長さを超えている場合に真となり、`yyerror`関数を呼び出してコンパイルエラーを報告します。エラーメッセージには、不正なインデックスと文字列の長さが含まれ、開発者にとって分かりやすい情報が提供されます。

3.  **`typecheck1`関数内の`checksliceindex`呼び出しの更新**:
    `typecheck1`関数内で`checksliceindex`が呼び出されている箇所が、新しいシグネチャに合わせて`l`（スライス対象のノード）を渡すように修正されました。これにより、定数文字列のスライスチェックが正しく機能するようになります。

4.  **テストケースの追加**:
    `test/fixedbugs/issue4232.go`ファイルが更新され、定数文字列に対する様々な範囲外スライス操作のテストケースが追加されました。これらのテストケースは、コンパイラが期待通りにエラーを報告するかどうかを検証します。特に、`c[10]`（長さ10の文字列に対してインデックス10）、`c[9:12]`（範囲外の終了インデックス）、`c[1<<100 : 1<<110]`（非常に大きなインデックス）などが追加されています。

これらの変更により、Goコンパイラは定数文字列の範囲外スライスをコンパイル時に検出し、開発者に明確なエラーメッセージを提示できるようになりました。

## コアとなるコードの解説

このコミットの核心は、`src/cmd/gc/typecheck.c` ファイル内の `checksliceindex` 関数にあります。

1.  **`checksliceindex` 関数の拡張**:
    この関数は、スライス操作のインデックスが有効な範囲内にあるかをチェックする役割を担っています。変更前は、スライス対象の型情報 (`Type *tp`) とインデックスのノード (`Node *r`) のみを受け取っていました。
    変更後は、スライス対象の式全体を表す `Node *l` が追加されました。これにより、`checksliceindex` はスライスされる元のデータ（配列、スライス、または文字列）に関するより詳細な情報にアクセスできるようになりました。

2.  **定数文字列の範囲チェックロジックの追加**:
    `checksliceindex` 関数内に、以下の新しい条件分岐が追加されました。
    ```c
    } else if(isconst(l, CTSTR) && mpgetfix(r->val.u.xval) > l->val.u.sval->len) {
        yyerror("invalid slice index %N (out of bounds for %d-byte string)", r, l->val.u.sval->len);
        return -1;
    }
    ```
    *   `isconst(l, CTSTR)`: これは、スライス操作の左辺 `l` がコンパイル時に値が確定している「定数文字列」であるかどうかを判定します。`CTSTR` は、Goコンパイラ内部で定数文字列を表す型定数です。
    *   `mpgetfix(r->val.u.xval)`: スライスインデックス `r` が定数である場合、その定数値を抽出します。`r->val.u.xval` は、`r` が表す定数値（多倍長整数形式）を指し、`mpgetfix` はそれを通常の整数値に変換します。
    *   `l->val.u.sval->len`: 定数文字列 `l` の実際のバイト長を取得します。Goの文字列はバイトのシーケンスであるため、`len` はバイト数を返します。
    *   この `if` 文は、「もしスライス対象が定数文字列であり、かつ指定されたインデックスがその文字列の長さを超えている場合」に真となります。
    *   条件が真の場合、`yyerror` 関数が呼び出され、コンパイルエラーが報告されます。エラーメッセージには、不正なインデックスの値 (`%N`) と、その文字列の実際の長さ (`%d-byte string`) が含まれるため、開発者は問題の原因をすぐに特定できます。`return -1;` は、エラーが発生したことを呼び出し元に通知します。

3.  **`typecheck1` からの呼び出し箇所の修正**:
    `typecheck1` 関数は、Goコンパイラの型チェックの主要なエントリポイントの一つです。この関数内で、スライス操作に関連するノードが処理される際に `checksliceindex` が呼び出されます。今回の変更により、`checksliceindex` のシグネチャが変わったため、`typecheck1` 内のすべての `checksliceindex` 呼び出しが、スライス対象のノード `l` を最初の引数として渡すように更新されました。

これらの変更により、Goコンパイラは定数文字列に対する不正なスライス操作をコンパイル時に検出し、実行時パニックを未然に防ぐことができるようになりました。これは、Goプログラムの堅牢性と開発者の生産性向上に貢献する重要な改善です。
