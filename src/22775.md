## 変更の背景

この変更は、GitHubのIssue #9744で報告された問題に対応するものです。`io.Copy`関数の既存のドキュメントには、「コピー中に最初に遭遇したエラーを返す」という記述がありました。しかし、実際の動作では、`Read`操作がエラーを返しながらも一部のバイトを読み込み、その後の`Write`操作もエラーを返した場合、`Copy`関数は`Write`操作のエラーを返していました。これは、時間的に`Read`エラーが先に発生しているにもかかわらず、`Write`エラーが返されるという点で、ドキュメントの記述と実際の動作が食い違っていました。

ユーザーは、ドキュメントの記述に基づいて`Read`エラーが返されることを期待していましたが、実際には`Write`エラーが返されるため、混乱が生じていました。このコミットは、この誤解を解消し、`Copy`関数が「それ以上の進行を妨げたエラー」を返すという実際の動作を正確に反映するようにドキュメントを修正することを目的としています。

## 前提知識の解説

*   **`io.Reader`と`io.Writer`インターフェース**: Go言語における基本的なI/O操作を定義するインターフェースです。`io.Reader`はデータを読み込むための`Read`メソッドを、`io.Writer`はデータを書き込むための`Write`メソッドを持ちます。
*   **`io.Copy`関数**: `io.Copy(dst Writer, src Reader)`は、`src`から`dst`へデータをコピーする関数です。`src`のEOFに達するか、エラーが発生するまでコピーを続けます。
*   **エラーハンドリング**: Go言語では、関数は通常、結果とエラーの2つの値を返します。エラーが発生しなかった場合はエラー値は`nil`になります。
*   **`Read`メソッドの特性**: `Read`メソッドは、エラーを返しながらも、一部のバイトを読み込むことがあります。これは、例えばネットワーク接続が切断された場合など、部分的なデータ転送が行われた後にエラーが発生するシナリオで起こり得ます。
*   **`Write`メソッドの特性**: `Write`メソッドも同様に、エラーを返すことがあります。

## 技術的詳細

`io.Copy`関数の内部動作は、`src`からデータを読み込み（`Read`）、そのデータを`dst`に書き込む（`Write`）というループで構成されています。このコミットの核心は、このループ内でエラーが発生した場合の`Copy`関数のエラー報告ロジックではなく、そのロジックを説明するドキュメントの記述の正確性にあります。

以前のドキュメントでは、「最初に遭遇したエラー」という表現が使われていました。これは、多くの開発者にとって、時間的に最初に発生したエラーが返されると解釈される可能性がありました。しかし、`io.Copy`の実際の動作では、`Read`がエラーを伴って非ゼロのバイト数を返し、その後の`Write`もエラーを返した場合、`Copy`は`Write`のエラーを返します。これは、`Write`エラーが、それ以上のデータコピーの進行を「妨げた」最終的なエラーであるためです。

このコミットでは、この挙動をより正確に表現するために、ドキュメントの記述を「それ以上の進行を妨げたエラー」に変更しました。これにより、`io.Copy`のユーザーは、特定のシナリオでどのエラーが返されるかをより正確に理解できるようになります。

また、この変更の正当性を確認するために、`io/io_test.go`に`TestCopyReadErrWriteErr`という新しいテストケースが追加されました。このテストケースは、`Read`がエラーと非ゼロバイトを返し、`Write`もエラーを返すという具体的なシナリオをシミュレートし、`Copy`が`Write`エラーを返すことを検証しています。

## コアとなるコードの解説

*   **`src/io/io.go`**:
    *   `Copy`関数のドキュメントコメントが変更されました。
    *   変更前: `It returns the number of bytes copied and the first error encountered while copying, if any.`
    *   変更後: `It returns the number of bytes copied and the error that prevented it from progressing further, if any.`
    *   この変更により、`Copy`関数がエラーを返す際の挙動がより正確に表現され、特に`Read`と`Write`の両方でエラーが発生するようなエッジケースでの誤解が解消されます。

*   **`src/io/io_test.go`**:
    *   `zeroErrReader`構造体: `Read`メソッドが常に1バイト（`{0}`）をコピーし、指定されたエラーを返すカスタム`Reader`です。これにより、エラーを伴いながらも非ゼロバイトを読み込むシナリオをシミュレートできます。
    *   `errWriter`構造体: `Write`メソッドが常に0バイトを書き込み、指定されたエラーを返すカスタム`Writer`です。
    *   `TestCopyReadErrWriteErr`関数:
        *   `readError`と`writeError`という2つの異なるエラーを定義します。
        *   `zeroErrReader`と`errWriter`のインスタンスを作成し、それぞれに定義したエラーを設定します。
        *   `io.Copy`を呼び出し、`zeroErrReader`から`errWriter`へコピーを試みます。
        *   結果として返されるバイト数`n`が0であること、および返されるエラー`err`が`writeError`と等しいことを検証します。
        *   このテストは、`Read`エラーが先に発生しても、`Write`エラーがコピーの進行を最終的に妨げた場合に、`Write`エラーが返されるという`io.Copy`の実際の挙動を明確に示しています。
