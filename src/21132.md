## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語およびそのランタイムに関する基本的な知識が役立ちます。

*   **Go 1.4**: Go 1.4は、2014年12月10日にリリースされたGoプログラミング言語の主要な安定版リリースです。このリリースは主に実装作業に焦点を当てており、ガベージコレクタの改善や、将来のリリースで完全に並行なガベージコレクタを導入するための準備が行われました。また、`go generate`コマンドの追加、AndroidおよびNative Client (NaCl) 上のARMプロセッサの公式サポート、Plan 9上のAMD64のサポートなども含まれています。
*   **`doc/go1.4.html`**: これはGo 1.4リリースの公式ドキュメントであり、新機能、変更点、改善点などが詳細に記述されています。Goの各リリースには、そのバージョンで導入された変更点をまとめた専用のHTMLドキュメントが提供されます。
*   **`for-range`ループ**: Go言語における`for-range`ループは、スライス、配列、文字列、マップ、チャネルなどのコレクションを反復処理するための構文です。Go 1.4では、値、ループインデックス、またはマップキーを割り当てずに反復処理を許可する、より簡潔な`for range s { ... }`形式が追加されました。
*   **ポインタのポインタに対するメソッド呼び出し (`**T`)**: Go 1.4では、ポインタのポインタ (`**T`) に対するメソッド呼び出しに関するコンパイラの動作に、破壊的な変更が導入されました。Goの仕様では、メソッド呼び出しのために単一のデリファレンス（例: `v.M()`が`(&v).M()`と解釈される）は自動的に挿入されることが許可されていますが、二重のデリファレンスは許可されていませんでした。Go 1.4以前のコンパイラは、`**T`に対するメソッド呼び出しを誤って許可していましたが、Go 1.4でこの動作が禁止されました。これにより、以前の非準拠の動作に依存していたコードはコンパイルされなくなりました。
*   **"Hot stack split"問題**: これはGoランタイムの古いバージョン（Go 1.4以前）に存在したパフォーマンスの問題です。Goのゴルーチンは、小さく動的に成長するスタックを持つように設計されています。以前のバージョンでは、ゴルーチンのスタックが不足すると、「スタック分割」と呼ばれる処理が行われ、新しいスタックセグメントが割り当てられ、以前のセグメントにリンクされていました。特に、頻繁に実行される（"hot"な）コードパスでこのスタック分割が繰り返し発生すると、新しいスタックセグメントの割り当て、リンク、および解放に伴うオーバーヘッドがパフォーマンスのボトルネックとなっていました。Go 1.4では、この問題に対処するため、セグメントスタックからスタックコピー方式に切り替えることで、この問題が解消されました。
*   **ガベージコレクタ**: Go言語のガベージコレクタは、プログラムが使用しなくなったメモリを自動的に解放するシステムです。Go 1.4では、ガベージコレクタの改善が行われ、将来の完全に並行なコレクタの導入に向けた基盤が築かれました。

## 技術的詳細

このコミットは、`doc/go1.4.html`の導入部分の文章を、より自然で理解しやすいように修正しています。

元の文章は以下の通りでした。

```html
The latest Go release, version 1.4, arrives as scheduled six months after 1.3
and contains only one tiny language change,
a possibly breaking change to the compiler,
a backwards-compatible simple form of <code>for</code>-<code>range</code> loop.
```

この文章は、「and contains only one tiny language change, a possibly breaking change to the compiler, a backwards-compatible simple form of `for`-`range` loop.」の部分が、複数の異なる種類の変更点を羅列しており、文法的にやや不自然で読みにくい構造になっていました。特に、「tiny language change」と「possibly breaking change to the compiler」が並列に記述され、その後に「backwards-compatible simple form of `for`-`range` loop」が続くことで、読者が各変更点の関係性を把握しにくくなっていました。

修正後の文章は以下の通りです。

```html
The latest Go release, version 1.4, arrives as scheduled six months after 1.3.
It contains only one tiny language change,
in the form of a backwards-compatible simple variant of <code>for</code>-<code>range</code> loop,
and a possibly breaking change to the compiler involving methods on pointers-to-pointers.
```

この修正では、まず「The latest Go release, version 1.4, arrives as scheduled six months after 1.3.」で文を一度区切ることで、Go 1.4のリリース時期に関する情報を独立させ、明確にしています。

次に、「It contains only one tiny language change, in the form of a backwards-compatible simple variant of `for`-`range` loop, and a possibly breaking change to the compiler involving methods on pointers-to-pointers.」と続くことで、Go 1.4に含まれる変更点をより論理的に記述しています。

*   「only one tiny language change」の後に「in the form of a backwards-compatible simple variant of `for`-`range` loop」と続くことで、その「小さな言語変更」が具体的に何であるかを明確にしています。これにより、読者は「小さな言語変更」と「`for`-`range`ループの変更」が同じ事柄を指していることを容易に理解できます。
*   そして、「and a possibly breaking change to the compiler involving methods on pointers-to-pointers.」と続くことで、もう一つの重要な変更点である「コンパイラへの破壊的な変更」を明確に区別して提示しています。

また、文章の後半部分でも微細な修正が行われています。

元の文章:
`and AMD64 on Plan 9.`

修正後の文章:
`and for AMD64 on Plan 9.`

「for」を追加することで、「ARM processors on Android and Native Client (NaCl) and for AMD64 on Plan 9」という並列構造がより自然になり、読みやすさが向上しています。

これらの変更は、技術的な内容そのものを変えるものではなく、その説明の質を向上させるためのものです。特に、公式ドキュメントにおいては、正確性だけでなく、明瞭性も非常に重要であり、このコミットはその点を改善しています。

変更は主に2つの箇所で行われています。

1.  **導入文の修正**:
    *   `- The latest Go release, version 1.4, arrives as scheduled six months after 1.3`
        *   元の文章では、Go 1.4のリリース時期と内容が「and」で接続されていましたが、ここで一度文を区切ることで、情報の区切りを明確にしています。
    *   `- and contains only one tiny language change,`
    *   `- a possibly breaking change to the compiler,`
    *   `- a backwards-compatible simple form of <code>for</code>-<code>range</code> loop.`
        *   これら3行は、元の文章で羅列されていたGo 1.4の変更点です。文法的に不明瞭な接続詞と句読点により、読みにくくなっていました。
    *   `+ The latest Go release, version 1.4, arrives as scheduled six months after 1.3.`
        *   修正後の文章では、ここでピリオドを打ち、Go 1.4のリリース時期に関する記述を独立させています。
    *   `+ It contains only one tiny language change,`
    *   `+ in the form of a backwards-compatible simple variant of <code>for</code>-<code>range</code> loop,`
        *   「小さな言語変更」が具体的に「`for`-`range`ループの互換性のあるシンプルなバリアント」であることを「in the form of」という句で明確に示しています。これにより、読者はこの2つの情報が関連していることを容易に理解できます。
    *   `+ and a possibly breaking change to the compiler involving methods on pointers-to-pointers.`
        *   そして、「ポインタのポインタに対するメソッドに関するコンパイラへの破壊的な変更」という別の重要な変更点を「and」で接続し、明確に区別して提示しています。これにより、文章全体の構造が改善され、各変更点がより分かりやすくなっています。

2.  **プラットフォームサポートに関する記述の修正**:
    *   `- and AMD64 on Plan 9.`
        *   元の文章では、「ARM processors on Android and Native Client (NaCl) and AMD64 on Plan 9.」となっており、「and」の使い方がやや不自然でした。
