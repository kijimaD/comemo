## 変更の背景

このコミットは、Go 1.6のリリースノート `doc/go1.6.txt` を更新し、`cmd/go` ツールがGitリポジトリをクローンする際の挙動変更を反映させるものです。具体的には、新しいGitチェックアウトで「シャロークローン」を使用するようになったという重要な変更をドキュメントに追加しています。

この変更の背景には、Goモジュールや依存関係管理の進化があります。`go get` コマンドなどで外部のGitリポジトリを取得する際、完全な履歴をクローンすることは、特に大規模なリポジトリの場合、時間とディスクスペースの無駄になることがありました。開発者は通常、最新のバージョンや特定のタグ/ブランチのコードのみを必要とし、完全な履歴は不要な場合が多いです。

シャロークローンを導入することで、`go get` などによるリポジトリの取得が高速化され、必要なディスクスペースも削減されます。これは、特にCI/CD環境や、多数の依存関係を持つプロジェクトにおいて、ビルド時間の短縮やリソース効率の向上に貢献します。

この変更は、Issue #13204 に関連しており、そのIssueで議論された内容がこのドキュメント更新に繋がっています。

## 前提知識の解説

### Gitのクローンとシャロークローン

*   **Gitクローン (Git Clone)**: Gitリポジトリをローカルにコピーする操作です。通常、`git clone` コマンドを実行すると、リポジトリの完全な履歴（すべてのコミット、ブランチ、タグ）がローカルにダウンロードされます。これにより、オフラインでの作業や過去の任意の時点への切り替えが可能になります。
*   **シャロークローン (Shallow Clone)**: Gitのクローンの一種で、リポジトリの完全な履歴ではなく、指定された深さ（通常は最新のコミットのみ）の履歴のみをダウンロードします。`git clone --depth 1` のように `--depth` オプションを使用して実行されます。これにより、ダウンロードサイズが大幅に削減され、クローンにかかる時間が短縮されます。開発者が最新のコードのみを必要とする場合や、CI/CDパイプラインで一時的なビルド環境を構築する際などに非常に有用です。

### `cmd/go` コマンド

`cmd/go` はGo言語の公式ツールチェーンに含まれるコマンドラインツールです。Goプロジェクトのビルド、テスト、依存関係の管理（`go get`、`go mod` など）、コードのフォーマットなど、多岐にわたる機能を提供します。Go開発者にとって最も基本的なツールの一つです。

### Go 1.6

Go 1.6は、2016年2月にリリースされたGo言語のバージョンです。このバージョンでは、HTTP/2のサポート、テンプレートパッケージの改善、`go tool trace` の強化、そしてこのコミットで言及されている `cmd/go` の改善など、多くの新機能とパフォーマンス向上が含まれていました。特に、ベンダーリング（vendoring）がデフォルトで有効になったことが大きな変更点の一つです。

## 技術的詳細

このコミット自体はコードの機能変更ではなく、Go 1.6のリリースノート `doc/go1.6.txt` に一行追加するドキュメントの変更です。しかし、このドキュメント変更が指し示している技術的な内容は、`cmd/go` コマンドがGitリポジトリをクローンする際の内部挙動の変更です。

具体的には、`cmd/go` が `go get` などの操作でリモートのGitリポジトリからコードを取得する際、完全な履歴をダウンロードする代わりに、デフォルトでシャロークローンを使用するようになったことを示唆しています。これは、内部的に `git clone --depth 1` のようなコマンドを実行するか、それに相当するGitライブラリの機能を使用するように `cmd/go` が変更されたことを意味します。

この変更は、特に以下のようなメリットをもたらします。

1.  **ダウンロード時間の短縮**: 大規模なリポジトリの場合、完全な履歴をダウンロードするのに数分かかることがありますが、シャロークローンであれば数秒で完了することがあります。
2.  **ディスクスペースの節約**: 履歴データが少ないため、ローカルに保存されるリポジトリのサイズが小さくなります。これは、ディスク容量が限られている環境や、多数の依存関係を扱う場合に特に重要です。
3.  **CI/CDパイプラインの高速化**: ビルドサーバーが依存関係を取得する時間を短縮できるため、全体のビルド時間が短縮され、開発サイクルが加速します。

ただし、シャロークローンにはいくつかの制約もあります。例えば、完全な履歴がないため、過去のコミットへの切り替えや、履歴に基づいた高度なGit操作（例: `git blame` の完全な実行、特定のコミットからのブランチ作成など）が制限される場合があります。しかし、`go get` のような依存関係取得の文脈では、通常は最新のコードのみが必要とされるため、これらの制約は問題になりにくいと判断されたと考えられます。

この変更は、Go言語の依存関係管理戦略の一部として、より効率的な開発ワークフローをサポートするために導入されました。
