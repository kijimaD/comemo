# [インデックス 2021] ファイルの概要

このコミットは、Go言語の `reflect` パッケージにおける `DeepEqual` 関数が、比較対象の2つの値の型が異なる場合に正しく `false` を返すように修正するものです。以前の `DeepEqual` は、値の型が異なる場合でも、その内部構造がたまたま同じであれば `true` を返してしまう可能性がありましたが、この変更により、厳密な型の一致が比較の前提条件として追加されました。

## 変更の背景

Go言語の `reflect` パッケージが提供する `DeepEqual` 関数は、2つの値が「深く」等しいかどうかを判定するために使用されます。ここでいう「深く」とは、単に値が同じであるだけでなく、ポインタが指す先の値や、構造体のフィールド、配列やスライスの要素など、再帰的にその内容を比較することを意味します。

このコミットが導入される以前の `DeepEqual` の実装では、比較対象の2つの値の「型」が異なる場合でも、その内部表現や構造が偶然一致していれば `true` を返してしまうという問題がありました。例えば、`type MyInt int` と定義された `MyInt` 型の変数と、組み込みの `int` 型の変数が同じ値を持っていた場合、これらは概念的には異なる型であるにもかかわらず、`DeepEqual` が `true` を返してしまう可能性がありました。これは、Goの型システムにおける厳密な型付けの原則に反し、予期せぬバグを引き起こす原因となり得ました。

この問題を解決し、`DeepEqual` のセマンティクスをより直感的で安全なものにするために、比較の初期段階でまず両者の型が一致するかどうかを確認する変更が導入されました。型が異なる場合は、値が何であれ `false` を返すようにすることで、`DeepEqual` の振る舞いがより予測可能になりました。

## 前提知識の解説

### Go言語の型システム

Go言語は静的型付け言語であり、変数は宣言時に型を持ち、その型はコンパイル時に決定されます。Goの型システムは厳格で、異なる型同士の直接的な代入や比較は、明示的な型変換がない限り許可されません。例えば、`int` 型と `float64` 型は異なる型であり、たとえ同じ数値 `5` を表していても、直接比較することはできません。

また、Goでは既存の型を基に新しい型を定義することができます（型定義）。
```go
type MyInt int
```
この `MyInt` は `int` を基にしていますが、`int` とは異なる新しい型として扱われます。したがって、`MyInt(5)` と `int(5)` は異なる型を持つ値と見なされます。

### `reflect` パッケージ

`reflect` パッケージは、Goプログラムが実行時に自身の構造を検査（リフレクション）するための機能を提供します。これにより、プログラムは変数や関数の型、値、構造体のフィールドなどを動的に調べたり、操作したりすることができます。

`reflect` パッケージの主要な概念には以下があります。

*   **`reflect.Type`**: Goの型の情報を表します。例えば、`int`、`string`、`struct{}` などの型そのものの情報（名前、カテゴリ、メソッドなど）を保持します。
*   **`reflect.Value`**: Goの値の情報を表します。任意のGoの変数の値を `reflect.Value` 型のインスタンスとしてラップすることで、その値を動的に操作したり、型情報を取得したりできます。
*   **`reflect.DeepEqual`**: `reflect` パッケージが提供する関数の一つで、2つのGoの値が「深く」等しいかどうかを判定します。これは、テストコードやデータ構造の比較などで頻繁に利用されます。

### `DeepEqual` の動作原理（変更前）

変更前の `DeepEqual` は、内部的に `deepValueEqual` という関数を呼び出し、2つの `reflect.Value` を再帰的に比較していました。この `deepValueEqual` は、値の種類（プリミティブ型、構造体、配列、マップなど）に応じて異なる比較ロジックを持っていましたが、比較を開始する前に「型が同じであること」を必須条件としていませんでした。そのため、例えば `type Basic struct { x int; y float32 }` と `type NotBasic Basic` のように、基底となる構造は同じだが型名が異なる2つの構造体インスタンスを比較した場合、そのフィールドの値が全て一致していれば `true` を返してしまう可能性がありました。

## 技術的詳細

このコミットの核心は、`DeepEqual` 関数の冒頭に型の一致チェックを追加した点にあります。

変更後の `DeepEqual` 関数のロジックは以下のようになります。

1.  比較対象の2つのインターフェース値 `a1` と `a2` を、それぞれ `reflect.Value` 型の `v1` と `v2` に変換します。
2.  `v1` の型 (`v1.Type()`) と `v2` の型 (`v2.Type()`) が `equalType` 関数によって比較されます。
3.  もし型が等しくない場合 (`!equalType(v1.Type(), v2.Type())` が `true` の場合)、`DeepEqual` は直ちに `false` を返します。これは、異なる型の値は、たとえその内部表現が同じに見えても、Goのセマンティクス上は等しくないと判断されるためです。
4.  型が等しい場合にのみ、従来の `deepValueEqual` 関数が呼び出され、値の深い比較が実行されます。

ここで使用されている `equalType` 関数は、おそらく `reflect.Type` オブジェクト同士を比較し、それらが同じ型を表しているかどうかを判定する内部関数です。これは通常、`Type` インターフェースの `Comparable` メソッドや、内部的なポインタ比較などによって実現されます。

この変更により、`DeepEqual` はGoの型システムの厳密さを尊重するようになり、異なる型の値が「深く等しい」と誤って判定されることがなくなりました。これは、特にカスタム型を定義して使用するGoプログラムにおいて、比較の正確性と堅牢性を向上させる上で非常に重要です。

テストケース `DeepEqualTest{ Basic{ 1, 0.5 }, NotBasic{ 1, 0.5 }, false }` が追加されたことも重要です。これは、`Basic` 型と `NotBasic` 型（`Basic` を基にした新しい型）のインスタンスが、たとえ同じフィールド値を持っていても、型が異なるため `DeepEqual` が `false` を返すことを検証しています。このテストケースの追加は、変更が意図通りに機能していることを保証します。

## コアとなるコードの解説

### `src/lib/reflect/deepequal.go` の変更

`DeepEqual` 関数は、2つの任意のインターフェース値 `a1` と `a2` を受け取ります。
変更前は、これらの値を `NewValue` で `reflect.Value` に変換した後、直接 `deepValueEqual` に渡していました。

変更後は、以下の3行が追加されました。

```go
	v1 := NewValue(a1);
	v2 := NewValue(a2);
	if !equalType(v1.Type(), v2.Type()) {
		return false;
	}
```

1.  `v1 := NewValue(a1);` と `v2 := NewValue(a2);` で、入力されたインターフェース値 `a1`, `a2` をそれぞれ `reflect.Value` 型の `v1`, `v2` に変換しています。これは、リフレクション操作を行うための標準的な手順です。
2.  `if !equalType(v1.Type(), v2.Type()) { return false; }` が追加された最も重要な部分です。
    *   `v1.Type()` と `v2.Type()` は、それぞれの `reflect.Value` が持つ `reflect.Type` オブジェクトを取得します。この `reflect.Type` オブジェクトが、値の具体的な型情報（例: `int`, `string`, `struct Basic` など）を保持しています。
    *   `equalType(Type1, Type2)` は、2つの `reflect.Type` オブジェクトが等しいかどうかを判定する関数です。この関数が `false` を返した場合（つまり、型が異なる場合）、`DeepEqual` は直ちに `false` を返して処理を終了します。これにより、異なる型の値は「深く等しい」とは見なされないというセマンティクスが強制されます。
    *   `equalType` の具体的な実装はこのdiffには含まれていませんが、Goの内部では `reflect.Type` オブジェクトの同一性を比較することで実現されます。

この変更により、`DeepEqual` はまず型の一致を厳密にチェックし、その後に値の深い比較を行うという、より堅牢で直感的な振る舞いをするようになりました。

### `src/lib/reflect/all_test.go` の変更

テストファイル `all_test.go` には、`DeepEqual` の動作を検証するための `deepEqualTests` というスライスがあります。このコミットでは、このスライスに新しいテストケースが追加されました。

```go
type NotBasic Basic
```
まず、`Basic` 構造体を基にした新しい型 `NotBasic` が定義されました。これは、`Basic` と同じフィールドを持つが、型名が異なることを示しています。

```go
DeepEqualTest{ Basic{ 1, 0.5 }, NotBasic{ 1, 0.5 }, false },
```
この新しいテストケースは、以下のことを検証しています。
*   `Basic{ 1, 0.5 }`: `Basic` 型の構造体インスタンスで、`x` が `1`、`y` が `0.5`。
*   `NotBasic{ 1, 0.5 }`: `NotBasic` 型の構造体インスタンスで、`x` が `1`、`y` が `0.5`。
*   `false`: 期待される `DeepEqual` の結果。

このテストケースは、`Basic` と `NotBasic` は内部のフィールド値が同じであっても、型が異なるため `DeepEqual` が `false` を返すことを期待しています。このテストケースの追加は、`deepequal.go` で行われた型チェックの変更が正しく機能していることを確認するためのものです。
