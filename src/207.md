# [インデックス 207] ファイルの概要

このコミットは、Goランタイムにおけるシグナルハンドリングとトレースバック機能の初期実装を追加し、同時にランタイムコードをアーキテクチャ依存およびOS依存の部分と、それらに依存しない部分に分離（ファクタリング）する重要な変更を行っています。これにより、Goプログラムがクラッシュした際に、より詳細なデバッグ情報（スタックトレース）を提供できるようになり、ランタイムの構造が将来の拡張に向けて整理されました。

## 変更の背景

Go言語の初期段階において、プログラムの予期せぬ終了（クラッシュ）時に、開発者が問題の原因を特定するための情報が不足していました。特に、セグメンテーション違反（SIGSEGV）や不正な命令（SIGILL）などのシグナルが発生した場合、どのコードパスで問題が起きたのかを把握するためのスタックトレースが提供されていませんでした。

このコミットの主な目的は以下の通りです。

1.  **デバッグ能力の向上**: プログラムがクラッシュした際に、自動的にスタックトレースを生成し、エラー発生時のプログラムの状態を詳細に報告することで、デバッグプロセスを大幅に改善する。
2.  **堅牢性の向上**: シグナルを適切に捕捉し、予期せぬ終了をより gracefully に処理する基盤を構築する。
3.  **ランタイムのモジュール化**: ランタイムコードが特定のCPUアーキテクチャ（例: AMD64）やオペレーティングシステム（例: Linux, Darwin）に強く依存する部分と、そうでない部分が混在していました。これを明確に分離することで、コードの保守性、可読性、そして将来的な異なるプラットフォームへの移植性を向上させることを目指しました。

この変更は、Goランタイムがより成熟したエラーハンドリングとデバッグ機能を持つための重要な一歩でした。

## 前提知識の解説

### 1. オペレーティングシステムにおけるシグナル

シグナル（Signal）は、Unix系オペレーティングシステムにおいて、プロセスに対して非同期的にイベントを通知するメカニズムです。これは、ソフトウェア割り込みのようなもので、特定のイベント（例: ユーザーがCtrl+Cを押す、不正なメモリアクセスが発生する、子プロセスが終了する）が発生した際に、OSがプロセスにシグナルを送信します。

主要なシグナルには以下のようなものがあります。
*   **SIGINT**: 割り込み（Ctrl+Cなど）
*   **SIGSEGV**: セグメンテーション違反（不正なメモリアクセス）
*   **SIGILL**: 不正な命令
*   **SIGFPE**: 浮動小数点例外
*   **SIGTERM**: 終了要求
*   **SIGHUP**: 端末の切断

プロセスは、これらのシグナルに対して以下のいずれかの処理を行うことができます。
*   **デフォルトの動作**: OSが定義した標準的な動作（例: プロセス終了、コアダンプ生成）。
*   **シグナルハンドラ**: プログラマが定義した関数を実行し、シグナルを捕捉して特定の処理を行う。
*   **シグナルの無視**: 特定のシグナルを無視する（ただし、SIGKILLやSIGSTOPなど一部のシグナルは無視できない）。

シグナルハンドラを設定するには、`signal()`やより高機能な`sigaction()`システムコールが使用されます。`sigaction()`は、シグナルハンドラの設定に加えて、シグナル発生時の追加情報（`siginfo`構造体）の取得や、シグナルマスク（ハンドラ実行中にブロックするシグナル）の制御など、より詳細な制御が可能です。

### 2. スタックトレース（トレースバック）

スタックトレース（またはトレースバック）は、プログラムの実行中に特定の時点（通常はエラー発生時や例外発生時）において、現在実行中の関数から、その関数を呼び出した関数、さらにその関数を呼び出した関数へと遡って、呼び出し履歴（コールスタック）を表示するものです。

スタックトレースには通常、以下の情報が含まれます。
*   関数名
*   ファイル名と行番号
*   引数の値（デバッグ情報が利用可能な場合）

これにより、開発者はエラーがどの関数の呼び出しパスで発生したのかを視覚的に把握し、問題の根本原因を特定するのに役立ちます。Goランタイムのような低レベルの環境では、スタックトレースの生成は、プログラムカウンタ（PC）とスタックポインタ（SP）を操作し、スタックフレームを逆順に辿ることで実現されます。これは、アセンブリレベルの知識と、コンパイラが生成するスタックフレームの構造に関する理解を必要とします。

### 3. Goランタイムの初期構造

Go言語は、その設計当初から独自のランタイム（runtime）を持っていました。このランタイムは、ガベージコレクション、スケジューラ、チャネル、ゴルーチンなどのGo言語の並行処理モデルを支える低レベルの機能を提供します。初期のGoランタイムは、C言語とアセンブリ言語で書かれており、OSやアーキテクチャに依存する部分と、Go言語のセマンティクスを実装する共通部分が混在していました。

このコミットが行われた2008年時点では、Goはまだ開発の初期段階にあり、ランタイムの構造も進化の途上にありました。`src/runtime/runtime.c`のようなファイルは、多くの異なる機能（メモリ管理、スケジューリング、エラーハンドリングなど）を一つのファイルに集約している傾向がありました。このコミットは、そのモノリシックな構造から、よりモジュール化された設計への移行の始まりを示しています。

## 技術的詳細

このコミットは、Goランタイムに以下の主要な技術的変更を導入しています。

### 1. シグナルハンドリングの実装

*   **`rt0_amd64_linux.s`におけるシステムコールラッパー**:
    *   `sys_rt_sigaction`というアセンブリ関数が追加されました。これは、Linuxの`rt_sigaction`システムコールを呼び出すためのラッパーです。`rt_sigaction`は、シグナルハンドラを設定するためのシステムコールであり、`sigaction`構造体を使用して詳細なシグナル処理の挙動を定義できます。
    *   `sigtramp`というアセンブリ関数も追加されました。これは「シグナルトランポリン」として機能します。OSがシグナルハンドラを呼び出す際に、直接C言語のハンドラ関数を呼び出すのではなく、このアセンブリコードを経由します。これにより、スタックフレームの調整やレジスタの保存など、低レベルの準備作業を行うことができます。
*   **`rt1_amd64_linux.c`におけるシグナルハンドラ**:
    *   `siginfo`と`sigaction`というC言語の構造体が定義されています。これらは、Linuxカーネルがシグナルハンドラに渡す情報（シグナル番号、エラーアドレスなど）や、シグナルハンドラの設定に使用される構造体を模倣したものです。
    *   `sighandler`関数が実装されました。これが実際にシグナルが発生した際に呼び出されるC言語のハンドラです。この関数は、発生したシグナルの種類を識別し、エラーメッセージを出力し、特に重要なのは`traceback`関数を呼び出してスタックトレースを生成する点です。
    *   `initsig`関数が追加されました。この関数は、Goランタイムの初期化時に呼び出され、`sys_rt_sigaction`システムコールを使用して、捕捉すべきシグナル（SIGQUIT, SIGILL, SIGABRT, SIGFPE, SIGBUS, SIGSEGV, SIGSYSなど）に対して`sigtramp`をシグナルハンドラとして登録します。`sa_flags`には`SA_SIGINFO`（シグナルハンドラに`siginfo`とコンテキスト情報を渡す）などのフラグが設定されています。
*   **`signals.h`の導入**:
    *   `SigTab`構造体と`sigtab`配列が定義されました。これは、各シグナル番号に対応する名前と、そのシグナルを捕捉すべきかどうか（`catch`フラグ）を管理するためのテーブルです。これにより、シグナルに関する情報を一元的に管理できるようになりました。

### 2. トレースバック機能の分離と実装

*   **`rt2_amd64.c`における`traceback`関数**:
    *   以前は`runtime.c`の`sys_panicl`内に埋め込まれていたスタックトレース生成ロジックが、`rt2_amd64.c`の独立した`traceback`関数として抽出されました。
    *   この`traceback`関数は、プログラムカウンタ（`pc`）とスタックポインタ（`sp`）を受け取り、スタックフレームを逆順に辿ることで、呼び出し履歴を再構築します。
    *   初期のGoランタイムでは、関数プロローグに特定のバイトシーケンス（`spmark`）を埋め込むことで、スタックフレームのサイズや次のPC/SPを特定する原始的なメカニズムが使用されていました。このコミットでもその手法が踏襲されています。
    *   トレースバックは、各フレームのPC、関数名、そして引数（最初の3つ）を出力します。

### 3. ランタイムのファクタリング

*   **OS依存とアーキテクチャ依存の分離**:
    *   `rt1_amd64_linux.c`と`rt1_amd64_darwin.c`が新設されました。これらはそれぞれLinuxとDarwin（macOS）というOSに特化したシグナル初期化コード（`initsig`）を含むことを意図しています。これにより、OSごとの差異をこれらのファイルに閉じ込めることができます。
    *   `rt2_amd64.c`が新設されました。これはAMD64アーキテクチャに特化したトレースバックロジックを含みますが、OSには依存しません。
*   **`runtime.c`のクリーンアップ**:
    *   `runtime.c`から、以前含まれていた`sys_panicl`内のトレースバックロジックが削除され、新しく分離された`traceback`関数と`initsig`関数を呼び出すように変更されました。これにより、`runtime.c`はより汎用的なランタイム機能に集中できるようになりました。

### 4. ビルドシステムの更新

*   `src/cmd/6l/obj.c`（Goリンカの一部）が変更され、新しく追加された`rt1_amd64_linux.6`、`rt1_amd64_darwin.6`、`rt2_amd64.6`といったオブジェクトファイルをリンクするように更新されました。
*   `src/runtime/make.bash`スクリプトが更新され、これらの新しいCファイル（`rt1_amd64_linux.c`, `rt1_amd64_darwin.c`, `rt2_amd64.c`）をコンパイルし、生成されたオブジェクトファイルを適切なライブラリディレクトリに配置するようになりました。

これらの変更により、Goランタイムはよりモジュール化され、シグナルハンドリングとトレースバックという重要なデバッグ機能が組み込まれました。

### 1. シグナルハンドラの設定 (`src/runtime/rt1_amd64_linux.c`)

```c
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

#include "runtime.h"
#include "signals.h"

/*
 * This assembler routine takes the args from registers, puts them on the stack,
 * and calls sighandler().
 */
extern void sigtramp();

// ... (siginfo, sigaction typedefs) ...

void
sighandler(int32 sig, siginfo* info, void** context) {
    int32 i;

    if(sig < 0 || sig >= NSIG){
        prints("Signal ");
        sys_printint(sig);
    }else{
        prints(sigtab[sig].name);
    }
    prints("\nFaulting address: 0x");
    sys_printpointer(info->si_addr);
    prints("\nPC: 0x");
    sys_printpointer(context[21]); // Empirically discovered PC location in context
    prints("\nSP: 0x");
    sys_printpointer(context[20]); // Empirically discovered SP location in context
    prints("\n");
    traceback(context[21], context[20]);    /* empirically discovered locations */
    sys_breakpoint();
    sys_exit(2);
}

sigaction a;

void
initsig(void)
{
    int32 i;
    a.u.sa_sigaction = (void*)sigtramp; // Set sigtramp as the handler entry point
    a.sa_flags = 1|2|4|0x10000000|0x20000000|0x40000000|0x80000000; // Various flags including SA_SIGINFO
    //a.sa_flags |= SA_SIGINFO;
    a.sa_flags = ~0;    /* BUG: why is this needed? */ // Overwrites flags, likely a temporary hack
    for(i=0; i<sizeof(a.sa_mask); i++)
        a.sa_mask[i] = 0xFF; // Block all signals during handler execution
    //a.sa_mask[1] = (1 << (11-1));
    for(i = 0; i <NSIG; i++)
        if(sigtab[i].catch){ // For signals marked as 'catch' in sigtab
            sys_rt_sigaction(i, &a, (void*)0, 8); // Register the signal handler
        }
}
```

### 2. トレースバックの実装 (`src/runtime/rt2_amd64.c`)

```c
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

#include "runtime.h"

extern int32    debug;

static int8 spmark[] = "\xa7\xf1\xd9\x2a\x82\xc8\xd8\xfe"; // Stack frame marker

void
traceback(uint8 *pc, uint8 *sp)
{
    int32 spoff;
    int8* spp;
    int32 counter;
    int32 i;
    int8* name;


    counter = 0;
    name = "panic"; // Default name
    for(;;){
        prints("0x");
        sys_printpointer(pc);
        prints("?zi\n"); // Placeholder for symbol information

        /* find SP offset by stepping back through instructions to SP offset marker */
        while(pc > (uint8*)0x1000+sizeof spmark-1) {
            for(spp = spmark; *spp != '\0' && *pc++ == (uint8)*spp++; );
            if(*spp == '\0'){ // Marker found
                spoff = *pc++;
                spoff += *pc++ << 8;
                spoff += *pc++ << 16; // Read 3-byte stack offset
                name = (int8*)pc; // Function name follows the marker
                sp += spoff + 8; // Adjust SP for the next frame
                break;
            }
        }
        if(counter++ > 100){ // Prevent infinite loops
            prints("stack trace terminated\n");
            break;
        }
        if((pc = ((uint8**)sp)[-1]) <= (uint8*)0x1000) // Get return PC from stack
            break;
        /* print args for this frame */
        prints("\t");
        prints(name);
        prints("(");
        for(i = 0; i < 3; i++){ // Print first 3 arguments
            if(i != 0)
                prints(", ");
            sys_printint(((uint32*)sp)[i]);
        }
        prints(", ...)\n");
        prints("\t");
        prints(name);
        prints("(");
        for(i = 0; i < 3; i++){ // Print first 3 arguments (as pointers)
            if(i != 0)
                prints(", ");
            prints("0x");
            sys_printpointer(((void**)sp)[i]);
        }
        prints(", ...)\n");
        /* print pc for next frame */
    }
}
```

### 3. シグナルトランポリン (`src/runtime/rt0_amd64_linux.s`)

```assembly
TEXT    sys_rt_sigaction(SB),1,$-8
    MOVL    8(SP), DI
    MOVQ    16(SP), SI
    MOVQ    24(SP), DX
    MOVQ    32(SP), CX
    MOVL    CX, R10
    MOVL    $13, AX         // syscall entry for rt_sigaction (syscall number 13 on x86-64 Linux)
    SYSCALL
    JCC 2(PC)
    CALL    notok(SB)
    RET

TEXT sigtramp(SB),1,$24 // Signal trampoline
    MOVQ    DI,0(SP)    // Save arg1 (signal number)
    MOVQ    SI,8(SP)    // Save arg2 (siginfo pointer)
    MOVQ    DX,16(SP)   // Save arg3 (ucontext pointer)
    CALL    sighandler(SB) // Call the C signal handler
    RET
```

## コアとなるコードの解説

### 1. シグナルハンドラの設定 (`src/runtime/rt1_amd64_linux.c`)

このファイルは、Linux AMD64環境におけるシグナルハンドリングの核心部分を担っています。

*   **`sigtramp`の利用**: `initsig`関数内で、`a.u.sa_sigaction = (void*)sigtramp;`という行があります。これは、OSがシグナルを配送する際に、直接C言語の`sighandler`を呼び出すのではなく、アセンブリ言語で書かれた`sigtramp`関数を最初に実行するように設定しています。`sigtramp`は、OSがレジスタに配置したシグナル関連の引数（シグナル番号、`siginfo`構造体へのポインタ、コンテキスト情報へのポインタ）を、C言語の呼び出し規約に従ってスタックにプッシュし、その後`sighandler`を呼び出します。これにより、C言語側でこれらの引数を簡単に受け取れるようになります。
*   **`sighandler`の役割**: `sighandler`関数は、実際にシグナルが捕捉されたときに実行されるGoランタイムのC関数です。
    *   引数として、シグナル番号（`sig`）、シグナルに関する詳細情報を含む`siginfo`構造体へのポインタ（`info`）、およびシグナル発生時のCPUコンテキスト（レジスタの状態など）を含む`ucontext`構造体へのポインタ（`context`）を受け取ります。
    *   `info->si_addr`からフォルト発生アドレスを、`context[21]`からプログラムカウンタ（PC）、`context[20]`からスタックポインタ（SP）を「経験的に発見された場所」として取得しています。これは、当時のGoランタイムがOSのコンテキスト構造を直接解析していたことを示唆しており、OSのバージョンやアーキテクチャによってこれらのオフセットが変わる可能性があるため、注意が必要な実装です。
    *   取得したPCとSPを引数として`traceback`関数を呼び出し、スタックトレースを生成します。
    *   最後に`sys_breakpoint()`（デバッガがアタッチされていればブレークポイントで停止）と`sys_exit(2)`（エラーコード2でプロセス終了）を呼び出します。
*   **`initsig`の初期化**: `initsig`関数は、Goプログラムの起動時に一度だけ呼び出され、`sigtab`配列で`catch`フラグが設定されているシグナル（例: SIGSEGV, SIGILL）に対して、`sys_rt_sigaction`システムコールを使って`sigtramp`をシグナルハンドラとして登録します。`a.sa_flags = ~0;`という行は、すべてのフラグを立てるという意図のようですが、「BUG: why is this needed?」というコメントがあり、当時の試行錯誤が垣間見えます。`sa_mask`を`0xFF`で埋めることで、シグナルハンドラ実行中は他のすべてのシグナルをブロックするように設定しています。

### 2. トレースバックの実装 (`src/runtime/rt2_amd64.c`)

このファイルは、AMD64アーキテクチャに特化したスタックトレース生成ロジックを含んでいます。

*   **`traceback`関数**: `sighandler`から呼び出されるこの関数は、与えられたPCとSPからスタックを逆順に辿り、呼び出し履歴を再構築します。
*   **`spmark`によるスタックフレームの特定**: `static int8 spmark[] = "\xa7\xf1\xd9\x2a\x82\xc8\xd8\xfe";`というバイトシーケンスが定義されています。これは、Goコンパイラが生成する各関数のプロローグ（関数の開始部分）に埋め込まれる特殊なマーカーです。`traceback`関数は、このマーカーを逆方向に検索することで、現在のスタックフレームの終わりと、次のスタックフレームの開始位置（およびスタックオフセット、関数名）を特定します。これは、Goの初期のランタイムが、デバッグ情報（DWARFなど）に頼らずに、独自のメカニズムでスタックフレームを解析していたことを示しています。
*   **スタックポインタの調整**: マーカが見つかると、その後に続くバイトからスタックオフセット（`spoff`）を読み取り、`sp += spoff + 8;`によってスタックポインタを次のフレームの適切な位置に調整します。
*   **リターンPCの取得**: `if((pc = ((uint8**)sp)[-1]) <= (uint8*)0x1000)`の行は、現在のスタックフレームから呼び出し元のリターンアドレス（PC）を取得しています。これは、スタックの特定のオフセットにリターンアドレスが保存されているという仮定に基づいています。
*   **引数の出力**: 各スタックフレームについて、関数名と、スタック上の最初の3つの引数を整数値とポインタ値の両方で出力しています。これは、デバッグ時に役立つ情報を提供するためです。
*   **ループの終了条件**: `counter++ > 100`という条件で、無限ループを防ぐための安全装置が設けられています。また、PCが特定の低いアドレス（`0x1000`）以下になった場合もトレースバックを終了します。

### 3. シグナルトランポリン (`src/runtime/rt0_amd64_linux.s`)

このアセンブリファイルは、Linux AMD64環境における低レベルのシグナル処理とシステムコールラッパーを提供します。

*   **`sys_rt_sigaction`**: これは、Linuxカーネルの`rt_sigaction`システムコールを呼び出すためのGoランタイムのアセンブリラッパーです。Goランタイムは、C言語の関数から直接システムコールを呼び出すのではなく、このようなアセンブリラッパーを介して行います。これは、Goの呼び出し規約とOSのシステムコール規約の間の橋渡しをする役割を果たします。`$13, AX`は、x86-64 Linuxにおける`rt_sigaction`システムコールの番号が13であることを示しています。
*   **`sigtramp`**: この関数は、OSがシグナルハンドラを呼び出す際に最初に実行されるアセンブリコードです。OSはシグナルハンドラに引数をレジスタ（DI, SI, DXなど）で渡すことがありますが、C言語の関数は通常、引数をスタックから読み取ります。`sigtramp`は、これらのレジスタの値をスタックに保存し、C言語の`sighandler`関数が期待する形式に変換してから`sighandler`を呼び出します。これにより、C言語側で複雑なレジスタ操作を意識することなく、シグナルハンドラを記述できるようになります。

これらのコード変更は、Goランタイムがクラッシュ時に有用なデバッグ情報を提供し、異なるプラットフォームへの適応性を高めるための基盤を築いたことを示しています。

Go言語の初期段階において、プログラムの予期せぬ終了（クラッシュ）時に、開発者が問題の原因を特定するための情報が不足していました。特に、セグメンテーション違反（SIGSEGV）や不正な命令（SIGILL）などのシグナルが発生した場合、どのコードパスで問題が起きたのかを把握するためのスタックトレースが提供されていませんでした。

このコミットの主な目的は以下の通りです。

1.  **デバッグ能力の向上**: プログラムがクラッシュした際に、自動的にスタックトレースを生成し、エラー発生時のプログラムの状態を詳細に報告することで、デバッグプロセスを大幅に改善する。
2.  **堅牢性の向上**: シグナルを適切に捕捉し、予期せぬ終了をより gracefully に処理する基盤を構築する。
3.  **ランタイムのモジュール化**: ランタイムコードが特定のCPUアーキテクチャ（例: AMD64）やオペレーティングシステム（例: Linux, Darwin）に強く依存する部分と、そうでない部分が混在していました。これを明確に分離することで、コードの保守性、可読性、そして将来的な異なるプラットフォームへの移植性を向上させることを目指しました。

この変更は、Goランタイムがより成熟したエラーハンドリングとデバッグ機能を持つための重要な一歩でした。

## 前提知識の解説

### 1. オペレーティングシステムにおけるシグナル

シグナル（Signal）は、Unix系オペレーティングシステムにおいて、プロセスに対して非同期的にイベントを通知するメカニズムです。これは、ソフトウェア割り込みのようなもので、特定のイベント（例: ユーザーがCtrl+Cを押す、不正なメモリアクセスが発生する、子プロセスが終了する）が発生した際に、OSがプロセスにシグナルを送信します。

主要なシグナルには以下のようなものがあります。
*   **SIGINT**: 割り込み（Ctrl+Cなど）
*   **SIGSEGV**: セグメンテーション違反（不正なメモリアクセス）
*   **SIGILL**: 不正な命令
*   **SIGFPE**: 浮動小数点例外
*   **SIGTERM**: 終了要求
*   **SIGHUP**: 端末の切断

プロセスは、これらのシグナルに対して以下のいずれかの処理を行うことができます。
*   **デフォルトの動作**: OSが定義した標準的な動作（例: プロセス終了、コアダンプ生成）。
*   **シグナルハンドラ**: プログラマが定義した関数を実行し、シグナルを捕捉して特定の処理を行う。
*   **シグナルの無視**: 特定のシグナルを無視する（ただし、SIGKILLやSIGSTOPなど一部のシグナルは無視できない）。

シグナルハンドラを設定するには、`signal()`やより高機能な`sigaction()`システムコールが使用されます。`sigaction()`は、シグナルハンドラの設定に加えて、シグナル発生時の追加情報（`siginfo`構造体）の取得や、シグナルマスク（ハンドラ実行中にブロックするシグナル）の制御など、より詳細な制御が可能です。

### 2. スタックトレース（トレースバック）

スタックトレース（またはトレースバック）は、プログラムの実行中に特定の時点（通常はエラー発生時や例外発生時）において、現在実行中の関数から、その関数を呼び出した関数、さらにその関数を呼び出した関数へと遡って、呼び出し履歴（コールスタック）を表示するものです。

スタックトレースには通常、以下の情報が含まれます。
*   関数名
*   ファイル名と行番号
*   引数の値（デバッグ情報が利用可能な場合）

これにより、開発者はエラーがどの関数の呼び出しパスで発生したのかを視覚的に把握し、問題の根本原因を特定するのに役立ちます。Goランタイムのような低レベルの環境では、スタックトレースの生成は、プログラムカウンタ（PC）とスタックポインタ（SP）を操作し、スタックフレームを逆順に辿ることで実現されます。これは、アセンブリレベルの知識と、コンパイラが生成するスタックフレームの構造に関する理解を必要とします。

### 3. Goランタイムの初期構造

Go言語は、その設計当初から独自のランタイム（runtime）を持っていました。このランタイムは、ガベージコレクション、スケジューラ、チャネル、ゴルーチンなどのGo言語の並行処理モデルを支える低レベルの機能を提供します。初期のGoランタイムは、C言語とアセンブリ言語で書かれており、OSやアーキテクチャに依存する部分と、Go言語のセマンティクスを実装する共通部分が混在していました。

このコミットが行われた2008年時点では、Goはまだ開発の初期段階にあり、ランタイムの構造も進化の途上にありました。`src/runtime/runtime.c`のようなファイルは、多くの異なる機能（メモリ管理、スケジューリング、エラーハンドリングなど）を一つのファイルに集約している傾向がありました。このコミットは、そのモノリシックな構造から、よりモジュール化された設計への移行の始まりを示しています。

## 技術的詳細

このコミットは、Goランタイムに以下の主要な技術的変更を導入しています。

### 1. シグナルハンドリングの実装

*   **`rt0_amd64_linux.s`におけるシステムコールラッパー**:
    *   `sys_rt_sigaction`というアセンブリ関数が追加されました。これは、Linuxの`rt_sigaction`システムコールを呼び出すためのラッパーです。`rt_sigaction`は、シグナルハンドラを設定するためのシステムコールであり、`sigaction`構造体を使用して詳細なシグナル処理の挙動を定義できます。
    *   `sigtramp`というアセンブリ関数も追加されました。これは「シグナルトランポリン」として機能します。OSがシグナルハンドラを呼び出す際に、直接C言語のハンドラ関数を呼び出すのではなく、このアセンブリコードを経由します。これにより、スタックフレームの調整やレジスタの保存など、低レベルの準備作業を行うことができます。
*   **`rt1_amd64_linux.c`におけるシグナルハンドラ**:
    *   `siginfo`と`sigaction`というC言語の構造体が定義されています。これらは、Linuxカーネルがシグナルハンドラに渡す情報（シグナル番号、エラーアドレスなど）や、シグナルハンドラの設定に使用される構造体を模倣したものです。
    *   `sighandler`関数が実装されました。これが実際にシグナルが発生した際に呼び出されるC言語のハンドラです。この関数は、発生したシグナルの種類を識別し、エラーメッセージを出力し、特に重要なのは`traceback`関数を呼び出してスタックトレースを生成する点です。
    *   `initsig`関数が追加されました。この関数は、Goランタイムの初期化時に呼び出され、`sys_rt_sigaction`システムコールを使用して、捕捉すべきシグナル（SIGQUIT, SIGILL, SIGABRT, SIGFPE, SIGBUS, SIGSEGV, SIGSYSなど）に対して`sigtramp`をシグナルハンドラとして登録します。`sa_flags`には`SA_SIGINFO`（シグナルハンドラに`siginfo`とコンテキスト情報を渡す）などのフラグが設定されています。
*   **`signals.h`の導入**:
    *   `SigTab`構造体と`sigtab`配列が定義されました。これは、各シグナル番号に対応する名前と、そのシグナルを捕捉すべきかどうか（`catch`フラグ）を管理するためのテーブルです。これにより、シグナルに関する情報を一元的に管理できるようになりました。

### 2. トレースバック機能の分離と実装

*   **`rt2_amd64.c`における`traceback`関数**:
    *   以前は`runtime.c`の`sys_panicl`内に埋め込まれていたスタックトレース生成ロジックが、`rt2_amd64.c`の独立した`traceback`関数として抽出されました。
    *   この`traceback`関数は、プログラムカウンタ（`pc`）とスタックポインタ（`sp`）を受け取り、スタックフレームを逆順に辿ることで、呼び出し履歴を再構築します。
    *   初期のGoランタイムでは、関数プロローグに特定のバイトシーケンス（`spmark`）を埋め込むことで、スタックフレームのサイズや次のPC/SPを特定する原始的なメカニズムが使用されていました。このコミットでもその手法が踏襲されています。
    *   トレースバックは、各フレームのPC、関数名、そして引数（最初の3つ）を出力します。

### 3. ランタイムのファクタリング

*   **OS依存とアーキテクチャ依存の分離**:
    *   `rt1_amd64_linux.c`と`rt1_amd64_darwin.c`が新設されました。これらはそれぞれLinuxとDarwin（macOS）というOSに特化したシグナル初期化コード（`initsig`）を含むことを意図しています。これにより、OSごとの差異をこれらのファイルに閉じ込めることができます。
    *   `rt2_amd64.c`が新設されました。これはAMD64アーキテクチャに特化したトレースバックロジックを含みますが、OSには依存しません。
*   **`runtime.c`のクリーンアップ**:
    *   `runtime.c`から、以前含まれていた`sys_panicl`内のトレースバックロジックが削除され、新しく分離された`traceback`関数と`initsig`関数を呼び出すように変更されました。これにより、`runtime.c`はより汎用的なランタイム機能に集中できるようになりました。

### 4. ビルドシステムの更新

*   `src/cmd/6l/obj.c`（Goリンカの一部）が変更され、新しく追加された`rt1_amd64_linux.6`、`rt1_amd64_darwin.6`、`rt2_amd64.6`といったオブジェクトファイルをリンクするように更新されました。
*   `src/runtime/make.bash`スクリプトが更新され、これらの新しいCファイル（`rt1_amd64_linux.c`, `rt1_amd64_darwin.c`, `rt2_amd64.c`）をコンパイルし、生成されたオブジェクトファイルを適切なライブラリディレクトリに配置するようになりました。

これらの変更により、Goランタイムはよりモジュール化され、シグナルハンドリングとトレースバックという重要なデバッグ機能が組み込まれました。

// Use of this source code is governed by a BSD-style

#include "runtime.h"

extern int32    debug;

static int8 spmark[] = "\xa7\xf1\xd9\x2a\x82\xc8\xd8\xfe"; // Stack frame marker

void
traceback(uint8 *pc, uint8 *sp)
{
    int32 spoff;
    int8* spp;
    int32 counter;
    int32 i;
    int8* name;


    counter = 0;
    name = "panic"; // Default name
    for(;;){
        prints("0x");
        sys_printpointer(pc);
        prints("?zi\n"); // Placeholder for symbol information

        /* find SP offset by stepping back through instructions to SP offset marker */
        while(pc > (uint8*)0x1000+sizeof spmark-1) {
            for(spp = spmark; *spp != '\0' && *pc++ == (uint8)*spp++; );
            if(*spp == '\0'){ // Marker found
                spoff = *pc++;
                spoff += *pc++ << 8;
                spoff += *pc++ << 16; // Read 3-byte stack offset
                name = (int8*)pc; // Function name follows the marker
                sp += spoff + 8; // Adjust SP for the next frame
                break;
            }
        }
        if(counter++ > 100){ // Prevent infinite loops
            prints("stack trace terminated\n");
            break;
        }
        if((pc = ((uint8**)sp)[-1]) <= (uint8*)0x1000) // Get return PC from stack
            break;
        /* print args for this frame */
        prints("\t");
        prints(name);
        prints("(");
        for(i = 0; i < 3; i++){ // Print first 3 arguments
            if(i != 0)
                prints(", ");
            sys_printint(((uint32*)sp)[i]);
        }
        prints(", ...)\n");
        prints("\t");
        prints(name);
        prints("(");
        for(i = 0; i < 3; i++){ // Print first 3 arguments (as pointers)
            if(i != 0)
                prints(", ");
            prints("0x");
            sys_printpointer(((void**)sp)[i]);
        }
        prints(", ...)\n");
        /* print pc for next frame */
    }
}

## コアとなるコードの解説

### 1. シグナルハンドラの設定 (`src/runtime/rt1_amd64_linux.c`)

このファイルは、Linux AMD64環境におけるシグナルハンドリングの核心部分を担っています。

*   **`sigtramp`の利用**: `initsig`関数内で、`a.u.sa_sigaction = (void*)sigtramp;`という行があります。これは、OSがシグナルを配送する際に、直接C言語の`sighandler`を呼び出すのではなく、アセンブリ言語で書かれた`sigtramp`関数を最初に実行するように設定しています。`sigtramp`は、OSがレジスタに配置したシグナル関連の引数（シグナル番号、`siginfo`構造体へのポインタ、コンテキスト情報へのポインタ）を、C言語の呼び出し規約に従ってスタックにプッシュし、その後`sighandler`を呼び出します。これにより、C言語側でこれらの引数を簡単に受け取れるようになります。
*   **`sighandler`の役割**: `sighandler`関数は、実際にシグナルが捕捉されたときに実行されるGoランタイムのC関数です。
    *   引数として、シグナル番号（`sig`）、シグナルに関する詳細情報を含む`siginfo`構造体へのポインタ（`info`）、およびシグナル発生時のCPUコンテキスト（レジスタの状態など）を含む`ucontext`構造体へのポインタ（`context`）を受け取ります。
    *   `info->si_addr`からフォルト発生アドレスを、`context[21]`からプログラムカウンタ（PC）、`context[20]`からスタックポインタ（SP）を「経験的に発見された場所」として取得しています。これは、当時のGoランタイムがOSのコンテキスト構造を直接解析していたことを示唆しており、OSのバージョンやアーキテクチャによってこれらのオフセットが変わる可能性があるため、注意が必要な実装です。
    *   取得したPCとSPを引数として`traceback`関数を呼び出し、スタックトレースを生成します。
    *   最後に`sys_breakpoint()`（デバッガがアタッチされていればブレークポイントで停止）と`sys_exit(2)`（エラーコード2でプロセス終了）を呼び出します。
*   **`initsig`の初期化**: `initsig`関数は、Goプログラムの起動時に一度だけ呼び出され、`sigtab`配列で`catch`フラグが設定されているシグナル（例: SIGSEGV, SIGILL）に対して、`sys_rt_sigaction`システムコールを使って`sigtramp`をシグナルハンドラとして登録します。`a.sa_flags = ~0;`という行は、すべてのフラグを立てるという意図のようですが、「BUG: why is this needed?」というコメントがあり、当時の試行錯誤が垣間見えます。`sa_mask`を`0xFF`で埋めることで、シグナルハンドラ実行中は他のすべてのシグナルをブロックするように設定しています。

### 2. トレースバックの実装 (`src/runtime/rt2_amd64.c`)

このファイルは、AMD64アーキテクチャに特化したスタックトレース生成ロジックを含んでいます。

*   **`traceback`関数**: `sighandler`から呼び出されるこの関数は、与えられたPCとSPからスタックを逆順に辿り、呼び出し履歴を再構築します。
*   **`spmark`によるスタックフレームの特定**: `static int8 spmark[] = "\xa7\xf1\xd9\x2a\x82\xc8\xd8\xfe";`というバイトシーケンスが定義されています。これは、Goコンパイラが生成する各関数のプロローグ（関数の開始部分）に埋め込まれる特殊なマーカーです。`traceback`関数は、このマーカーを逆方向に検索することで、現在のスタックフレームの終わりと、次のスタックフレームの開始位置（およびスタックオフセット、関数名）を特定します。これは、Goの初期のランタイムが、デバッグ情報（DWARFなど）に頼らずに、独自のメカニズムでスタックフレームを解析していたことを示しています。
*   **スタックポインタの調整**: マーカが見つかると、その後に続くバイトからスタックオフセット（`spoff`）を読み取り、`sp += spoff + 8;`によってスタックポインタを次のフレームの適切な位置に調整します。
*   **リターンPCの取得**: `if((pc = ((uint8**)sp)[-1]) <= (uint8*)0x1000)`の行は、現在のスタックフレームから呼び出し元のリターンアドレス（PC）を取得しています。これは、スタックの特定のオフセットにリターンアドレスが保存されているという仮定に基づいています。
*   **引数の出力**: 各スタックフレームについて、関数名と、スタック上の最初の3つの引数を整数値とポインタ値の両方で出力しています。これは、デバッグ時に役立つ情報を提供するためです。
*   **ループの終了条件**: `counter++ > 100`という条件で、無限ループを防ぐための安全装置が設けられています。また、PCが特定の低いアドレス（`0x1000`）以下になった場合もトレースバックを終了します。

### 3. シグナルトランポリン (`src/runtime/rt0_amd64_linux.s`)

このアセンブリファイルは、Linux AMD64環境における低レベルのシグナル処理とシステムコールラッパーを提供します。

*   **`sys_rt_sigaction`**: これは、Linuxカーネルの`rt_sigaction`システムコールを呼び出すためのGoランタイムのアセンブリラッパーです。Goランタイムは、C言語の関数から直接システムコールを呼び出すのではなく、このようなアセンブリラッパーを介して行います。これは、Goの呼び出し規約とOSのシステムコール規約の間の橋渡しをする役割を果たします。`$13, AX`は、x86-64 Linuxにおける`rt_sigaction`システムコールの番号が13であることを示しています。
*   **`sigtramp`**: この関数は、OSがシグナルハンドラを呼び出す際に最初に実行されるアセンブリコードです。OSはシグナルハンドラに引数をレジスタ（DI, SI, DXなど）で渡すことがありますが、C言語の関数は通常、引数をスタックから読み取ります。`sigtramp`は、これらのレジスタの値をスタックに保存し、C言語の`sighandler`関数が期待する形式に変換してから`sighandler`を呼び出します。これにより、C言語側で複雑なレジスタ操作を意識することなく、シグナルハンドラを記述できるようになります。

これらのコード変更は、Goランタイムがクラッシュ時に有用なデバッグ情報を提供し、異なるプラットフォームへの適応性を高めるための基盤を築いたことを示しています。
