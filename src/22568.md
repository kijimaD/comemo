## 元コミット内容

このコミットは、Goランタイムに`TestCgoDLLImports`というテストを追加します。このテストは、issue 9356の単純な再現であり、この問題の解決を目的としています。また、issue 8948も関連する問題として更新されています。

## 変更の背景

このコミットは、GoのCgo機能がWindows上でDLL（Dynamic Link Library）をインポートする際に発生する可能性のある問題を解決するために導入されました。具体的には、コミットメッセージで言及されている「issue 9356」と「issue 8948」に関連しています。これらの問題の詳細は公開されていませんが、Cgoを介してWindows API関数（この場合は`GetCurrentThreadId`）を呼び出す際に、特定のシナリオで予期せぬ動作やクラッシュが発生する可能性があったと推測されます。

GoプログラムがCコードと連携するCgoを使用する場合、特にWindows環境では、DLLのロードと関数の呼び出しに関する複雑さが伴います。DLLからの関数インポートが正しく処理されないと、プログラムの不安定性や誤動作につながる可能性があります。このコミットは、そのような問題を特定し、将来の回帰を防ぐためのテストカバレッジを追加することで、Goランタイムの堅牢性を向上させることを目的としています。

## 前提知識の解説

### Cgo

Cgoは、GoプログラムがCコードを呼び出すことを可能にするGoの機能です。これにより、既存のCライブラリを利用したり、パフォーマンスが重要な部分をCで記述したりすることができます。Cgoを使用するには、Goのソースファイル内に特別な`import "C"`ディレクティブと、Cコードを記述するためのコメントブロックを含めます。GoとCの間でデータをやり取りする際には、型変換が必要になります。

### DLL (Dynamic Link Library)

DLLは、Windowsオペレーティングシステムで使用される共有ライブラリの形式です。複数のプログラムが同時に使用できるコードとデータを含んでいます。DLLは、プログラムの実行時にロードされ、必要な関数を提供します。これにより、メモリ使用量を削減し、プログラムのモジュール性を高めることができます。GoプログラムがWindows API関数を呼び出す場合、通常はこれらの関数がDLLとして提供されているため、Cgoを介してDLLをインポートする必要があります。

### `GetCurrentThreadId()`

`GetCurrentThreadId()`は、Windows APIが提供する関数で、現在のスレッドの一意の識別子（ID）を取得します。この関数は、スレッド固有の操作やデバッグ、ログ記録など、さまざまな目的で使用されます。このコミットのテストでは、GoとCgoを介してこの関数を呼び出すことで、異なるパッケージからDLLインポートが正しく機能するかどうかを検証しています。

### `#cgo CFLAGS: -mnop-fun-dllimport`

これはGCC（GNU Compiler Collection）のコンパイラフラグで、特にWindowsターゲット向けに使用されます。
通常、Windowsでは、DLLから関数をインポートする際に、コンパイラは`__declspec(dllimport)`属性を使用して、関数がDLLからインポートされることを示します。これにより、コンパイラはDLLを介した関数呼び出しを最適化できます。
しかし、`-mnop-fun-dllimport`フラグは、この`dllimport`属性の自動的な適用を無効にします。これは、特定のリンケージの問題を回避したり、コンパイラのデフォルトの動作を上書きしたりするために使用されることがあります。このテストでは、サブパッケージのCgoコードにこのフラグが適用されており、DLLインポートの挙動が特定の条件下でどのように変化するかを検証する意図があると考えられます。

## 技術的詳細

このコミットは、`src/runtime/crash_cgo_test.go`に`TestCgoDLLImports`という新しいテスト関数を追加します。このテストはWindows固有のものであり、Windows以外のOSではスキップされます。

テストの核心は、`executeTest`ヘルパー関数を使用して、2つのGoソースコードスニペット（`cgoDLLImportsMainSource`と`cgoDLLImportsPkgSource`）を実行することです。

1.  **`cgoDLLImportsMainSource`**: これはメインのGoパッケージのソースコードを表します。このパッケージは、Cgoを使用してC関数`getthread()`を定義し、`GetCurrentThreadId()`を呼び出します。さらに、`./a`というローカルパッケージをインポートし、そのパッケージの`GetThread()`関数も呼び出します。
2.  **`cgoDLLImportsPkgSource`**: これは`a`というサブパッケージのソースコードを表します。このパッケージもCgoを使用し、C関数`agetthread()`を定義して`GetCurrentThreadId()`を呼び出します。ここで注目すべきは、`#cgo CFLAGS: -mnop-fun-dllimport`というコンパイラフラグが指定されている点です。

テストの目的は、メインパッケージとサブパッケージの両方からCgoを介して`GetCurrentThreadId()`を呼び出すことが、Windows上で問題なく動作することを確認することです。特に、サブパッケージに`-mnop-fun-dllimport`フラグが適用されている状況下でのDLLインポートの挙動が検証されます。テストは、両方の呼び出しが成功し、最終的に"OK"が出力されることを期待します。

また、`src/runtime/crash_test.go`の`executeTest`関数にも変更が加えられています。以前は、テスト用の追加ファイルを作成する際に、ファイルパスにディレクトリが含まれていてもディレクトリの作成は行われませんでした。今回の変更では、`filepath.Split`を使用してファイル名からディレクトリ部分を抽出し、必要であれば`os.Mkdir`でディレクトリを作成するように修正されています。これにより、`a/a.go`のようにサブディレクトリに配置されるテストファイルを正しく処理できるようになり、`TestCgoDLLImports`のような複雑なテストケースをサポートします。

## コアとなるコードの変更箇所

-   `src/runtime/crash_cgo_test.go`に`TestCgoDLLImports`関数が追加されました。
-   `src/runtime/crash_cgo_test.go`に`cgoDLLImportsMainSource`と`cgoDLLImportsPkgSource`という2つの定数が追加され、テスト用のGoとCのソースコードが定義されています。
-   `src/runtime/crash_test.go`の`executeTest`関数が修正され、テストファイルを作成する際に必要に応じてディレクトリを自動的に作成するようになりました。

## コアとなるコードの解説

### `TestCgoDLLImports` (src/runtime/crash_cgo_test.go)

```go
func TestCgoDLLImports(t *testing.T) {
	// test issue 9356
	if runtime.GOOS != "windows" {
		t.Skip("skipping windows specific test")
	}
	got := executeTest(t, cgoDLLImportsMainSource, nil, "a/a.go", cgoDLLImportsPkgSource)
	want := "OK\n"
	if got != want {
		t.Fatalf("expected %q, but got %v", want, got)
	}
}
```
このテスト関数は、`runtime.GOOS`が`"windows"`でない場合はスキップされます。これは、テストがWindows固有のDLLインポートの挙動を検証するためです。`executeTest`を呼び出し、`cgoDLLImportsMainSource`をメインのテストコードとして、`cgoDLLImportsPkgSource`を`a/a.go`というパスでサブパッケージのコードとして渡します。期待される出力は"OK"であり、それ以外の場合はテストが失敗します。

### `cgoDLLImportsMainSource` (src/runtime/crash_cgo_test.go)

```go
const cgoDLLImportsMainSource = `
package main

/*
#include <windows.h>

DWORD getthread() {
	return GetCurrentThreadId();
}
*/
import "C"

import "./a"

func main() {
	C.getthread()
	a.GetThread()
	println("OK")
}
`
```
これはテストされるメインのGoプログラムです。
-   `import "C"`: Cgoを使用するための必須ディレクティブです。
-   Cコメントブロック内: `windows.h`をインクルードし、`GetCurrentThreadId()`を呼び出す`getthread()`というC関数を定義しています。
-   `import "./a"`: ローカルのサブパッケージ`a`をインポートしています。
-   `main`関数内:
    -   `C.getthread()`: メインパッケージから直接Cgoを介して`GetCurrentThreadId()`を呼び出します。
    -   `a.GetThread()`: サブパッケージ`a`の`GetThread()`関数を呼び出します。この関数も内部で`GetCurrentThreadId()`を呼び出します。
-   `println("OK")`: 両方のCgo呼び出しが成功した場合に"OK"を出力します。

### `cgoDLLImportsPkgSource` (src/runtime/crash_cgo_test.go)

```go
const cgoDLLImportsPkgSource = `
package a

/*
#cgo CFLAGS: -mnop-fun-dllimport

#include <windows.h>

DWORD agetthread() {
	return GetCurrentThreadId();
}
*/
import "C"

func GetThread() uint32 {
	return uint32(C.agetthread())
}
`
```
これはテストされるサブパッケージ`a`のGoプログラムです。
-   `package a`: パッケージ名を`a`としています。
-   `#cgo CFLAGS: -mnop-fun-dllimport`: ここが重要なポイントで、このCgoディレクティブは、このパッケージのCコードをコンパイルする際に`-mnop-fun-dllimport`フラグをGCCに渡します。これにより、DLLからの関数インポートの挙動が変更される可能性があります。
-   Cコメントブロック内: `windows.h`をインクルードし、`GetCurrentThreadId()`を呼び出す`agetthread()`というC関数を定義しています。
-   `GetThread()`関数: Cgoを介して`C.agetthread()`を呼び出し、その結果を`uint32`型で返します。

このテストは、異なるGoパッケージ（メインとサブパッケージ）から、それぞれ異なるCgoコンパイルフラグ（特に`-mnop-fun-dllimport`）を適用したCコードを介して、同じWindows API関数（`GetCurrentThreadId`）を呼び出すシナリオを網羅しています。これにより、Windows上でのCgoとDLLインポートの複雑な相互作用における潜在的な問題を効果的に検出できます。
