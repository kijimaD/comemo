# [インデックス 25225] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）メカニズムにおける`gcController.scanWork`の更新方法を変更するものです。以前はGCサイクルの終わりにまとめて更新されていた`scanWork`が、GCサイクル中に定期的に更新されるように修正されました。これにより、ミューテータアシストの比率計算の精度が向上し、GCの効率化に寄与します。

## コミット

```
commit 8e8219deb5166ee67c8ba4409692de6fd7b67303
Author: Austin Clements <austin@google.com>
Date:   Sun Oct 4 23:00:01 2015 -0400

    runtime: update gcController.scanWork regularly

    Currently, gcController.scanWork is updated as lazily as possible
    since it is only read at the end of the GC cycle. We're about to read
    it during the GC cycle to improve the assist ratio revisions, so
    modify gcDrain* to regularly flush to gcController.scanWork in much
    the same way as we regularly flush to gcController.bgScanCredit.

    One consequence of this is that it's difficult to keep gcw.scanWork
    monotonic, so we give up on that and simply return the amount of scan
    work done by gcDrainN rather than calculating it in the caller.
```

## 元コミット内容

このコミットの元の内容は、`gcController.scanWork`の更新頻度を改善することにあります。以前はGCサイクルの最後に一度だけ読み取られるため、可能な限り遅延して更新されていました。しかし、GCサイクル中に`scanWork`を読み取ることでアシスト比率の改訂を改善する計画があったため、`gcDrain*`関数群を修正し、`gcController.bgScanCredit`が定期的にフラッシュされるのと同様に、`gcController.scanWork`も定期的にフラッシュするように変更されました。

この変更の結果、`gcw.scanWork`を単調増加に保つことが困難になったため、`gcDrainN`が実行したスキャン作業量を呼び出し元で計算するのではなく、`gcDrainN`が直接その作業量を返すように設計が変更されました。

## 変更の背景

Goのガベージコレクタは、プログラムの実行（ミューテータ）と並行して動作する並行マーク＆スイープコレクタです。GCの効率とアプリケーションのレイテンシは、GCがどれだけ効率的にバックグラウンドで動作し、ミューテータの実行を妨げないかにかかっています。

`gcController.scanWork`は、GCサイクル中に実行されたスキャン作業の総量を追跡する重要なメトリックです。この値は、GCの進行状況を把握し、特にミューテータアシストの量を決定するために使用されます。ミューテータアシストとは、アプリケーション（ミューテータ）がメモリを割り当てようとした際に、GCが十分な速度で進行していない場合に、ミューテータ自身がGC作業の一部を手伝うメカニズムです。

以前の実装では、`gcController.scanWork`はGCサイクルの最後にまとめて更新されていました。これは、その値がGCサイクルの終わりにしか読み取られないという前提に基づいています。しかし、GCの「アシスト比率」を改善するためには、GCサイクル中にも`scanWork`の値をより頻繁に、かつ正確に把握する必要が生じました。アシスト比率とは、ミューテータがGC作業に費やす時間の割合を指し、この比率を適切に制御することで、アプリケーションのパフォーマンスとGCの効率のバランスを取ります。

このコミットは、アシスト比率の計算精度を高め、より動的なGC制御を可能にするための基盤となる変更です。`scanWork`を定期的に更新することで、GCはよりリアルタイムに自身の進行状況を評価し、ミューテータアシストの必要性をより正確に判断できるようになります。

## 前提知識の解説

このコミットを理解するためには、Goのガベージコレクタの以下の概念を理解しておく必要があります。

1.  **並行マーク＆スイープGC**: GoのGCは、アプリケーションの実行と並行してマークフェーズとスイープフェーズを実行します。これにより、アプリケーションの一時停止（Stop-The-World: STW）時間を最小限に抑えます。
2.  **ミューテータ (Mutator)**: アプリケーションのコード自体を指します。ヒープメモリを割り当てたり、既存のオブジェクトを変更したりします。
3.  **GCワーカー (GC Worker)**: GC作業を実行するゴルーチンです。バックグラウンドでマーク作業などを担当します。
4.  **スキャン作業 (Scan Work)**: GCがヒープ上のオブジェクトを走査し、到達可能なオブジェクトをマークする作業の量です。これは、GCの進行状況を測る主要な指標の一つとなります。
5.  **`gcController.scanWork`**: GCサイクル全体で実行されたスキャン作業の総量を追跡するグローバルカウンタです。
6.  **`gcController.bgScanCredit`**: バックグラウンドGCワーカーが実行したスキャン作業のうち、ミューテータアシストが利用できるクレジット（貸し）の量を追跡するカウンタです。ミューテータがGC作業を手伝う必要がある場合、このクレジットを消費します。
7.  **ミューテータアシスト (Mutator Assist)**: ミューテータが新しいメモリを割り当てようとした際に、GCが十分な速度で進行していない場合に、ミューテータ自身がGC作業の一部（スキャン作業など）を実行することです。これにより、GCの進行を加速し、メモリ不足を防ぎます。アシストの量は、GCの進行状況やヒープの割り当て速度に基づいて動的に調整されます。
8.  **アシスト比率 (Assist Ratio)**: ミューテータがGC作業に費やす時間の割合。この比率を適切に管理することで、GCのオーバーヘッドとアプリケーションの応答性のバランスを取ります。
9.  **`gcw.scanWork`**: 各GCワーカー（またはPに紐づく`gcWork`構造体）がローカルに保持するスキャン作業量です。これは、グローバルな`gcController.scanWork`にフラッシュされるまでの一時的なバッファとして機能します。
10. **`gcCreditSlack`**: ローカルに蓄積できるスキャン作業量の閾値。この閾値を超えると、ローカルの作業量がグローバルカウンタにフラッシュされます。これにより、メモリ競合を減らしつつ、グローバルカウンタの鮮度を保ちます。

## 技術的詳細

このコミットの主要な変更点は、`gcController.scanWork`の更新戦略です。

1.  **`gcController.scanWork`の更新頻度向上**:
    *   以前はGCサイクルの終わりにまとめて更新されていましたが、この変更により、`gcDrain`および`gcDrainN`関数内で`gcCreditSlack`（以前の`gcBgCreditSlack`）で定義された閾値に達するたびに、ローカルの`gcw.scanWork`がグローバルな`gcController.scanWork`にアトミックに加算されるようになりました。
    *   これにより、`gcController.scanWork`の値がGCサイクル中により頻繁に、かつ正確に反映されるようになります。

2.  **`gcCreditSlack`の導入と役割の拡張**:
    *   定数`gcBgCreditSlack`が`gcCreditSlack`に名称変更され、その役割が拡張されました。
    *   `gcCreditSlack`は、ローカルに蓄積できるスキャン作業量のクレジットの閾値を定義します。この閾値を超えると、`gcController.scanWork`およびオプションで`gcController.bgScanCredit`が更新されます。
    *   この値が低いほど、アシスト比率の精度が向上し、ミューテータアシストがバックグラウンドクレジットをより成功裏に利用できるようになります。一方、値が高いほど、メモリ競合が減少します。

3.  **`gcDrainN`の戻り値の変更**:
    *   `gcDrainN`関数は、以前は`void`を返していましたが、この変更により`int64`型のスキャン作業量を返すようになりました。
    *   これは、`gcw.scanWork`を単調増加に保つことが困難になったためです。`gcDrainN`がローカルの`gcw.scanWork`をグローバルカウンタにフラッシュするようになったため、呼び出し元で`gcw.scanWork`の差分を取って作業量を計算するのではなく、`gcDrainN`自身が実行した作業量を正確に返す方が適切になりました。

4.  **`gcDrain`および`gcDrainN`内のフラッシュロジック**:
    *   `gcDrain`関数内では、`gcw.scanWork`が`gcCreditSlack`を超えた場合に、`gcController.scanWork`にフラッシュされます。`flushBgCredit`フラグが設定されている場合は、`gcController.bgScanCredit`にもフラッシュされます。
    *   `gcDrainN`関数内でも同様に、ループ内で`gcw.scanWork`が`gcCreditSlack`を超えた場合に`gcController.scanWork`にフラッシュされます。

これらの変更により、GoのGCは、GCサイクル中のスキャン作業の進行状況をより細かく、かつリアルタイムに把握できるようになり、ミューテータアシストの制御精度が向上し、結果としてGCの全体的なパフォーマンスとアプリケーションのレイテンシ特性が改善されることが期待されます。

## コアとなるコードの解説

このコミットの核心は、`gcDrain`と`gcDrainN`関数における`gcw.scanWork`の管理と、それがグローバルな`gcController.scanWork`にフラッシュされるタイミングの変更にあります。

1.  **`gcDrainN`の変更**:
    *   以前は`gcDrainN`は`void`を返し、呼び出し元が`gcw.scanWork`の開始値と終了値の差分を取ることで、実行された作業量を計算していました。
    *   変更後、`gcDrainN`は`int64`を返し、自身が実行したスキャン作業量を直接報告します。
    *   `workFlushed := -gcw.scanWork`という初期化は、`gcDrainN`が呼び出された時点で`gcw.scanWork`に既に蓄積されている作業量を考慮し、この呼び出しによって新たに実行された作業量のみを正確に計算するためのものです。
    *   ループ内で`gcw.scanWork >= gcCreditSlack`という条件が満たされると、`xaddint64(&gcController.scanWork, gcw.scanWork)`によってローカルの`gcw.scanWork`がグローバルな`gcController.scanWork`にアトミックに加算され、`gcw.scanWork`は0にリセットされます。これにより、グローバルカウンタが定期的に更新されます。

2.  **`gcDrain`の変更**:
    *   `gcDrain`関数も同様に、ループ内で`gcw.scanWork >= gcCreditSlack`という条件で`gcController.scanWork`へのフラッシュを行います。
    *   さらに、`flushBgCredit`フラグが設定されている場合は、`gcController.bgScanCredit`にもフラッシュが行われます。これは、バックグラウンドGCワーカーが実行した作業をミューテータアシストが利用できるようにするためです。
    *   ループ終了後、`if gcw.scanWork > 0`のブロックで、残りの`gcw.scanWork`もグローバルカウンタにフラッシュされます。これにより、GCワーカーが中断される場合でも、作業量が失われることなくグローバルカウンタに反映されます。

これらの変更により、`gcController.scanWork`はGCサイクル中に動的に更新されるようになり、GCの進行状況をより正確に反映するようになりました。これは、ミューテータアシストの決定ロジックにおいて、よりタイムリーで正確な情報を提供し、GCの応答性と効率を向上させるための重要なステップです。
