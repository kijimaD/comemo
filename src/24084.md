# [インデックス 24084] ファイルの概要

このコミットは、Goコマンドラインツール（`cmd/go`）において、不正なインポートパスが`/vendor/`を含んでいる場合に発生するパニック（プログラムの異常終了）を修正するものです。具体的には、`vendor`ディレクトリの可視性ルールをチェックする`disallowVendorVisibility`関数内で、パスの切り詰め処理におけるインデックス計算が不正な値になる可能性があり、それが原因でランタイムパニックが発生していました。このコミットは、インデックスの範囲チェックを追加することで、この脆弱性を解消しています。

## 変更の背景

Go 1.5では、依存関係管理の改善を目指し、`vendor`ディレクトリの実験的なサポートが導入されました。これは、`GO15VENDOREXPERIMENT`という環境変数を設定することで有効化される機能でした。`vendor`ディレクトリは、プロジェクトの依存パッケージをローカルにコピーして配置することで、ビルドの再現性を高めることを目的としていました。`go`コマンドは、パッケージのインポートパスを解決する際に、まず`vendor`ディレクトリ内を探索し、そこで見つかったパッケージを優先的に使用します。

このコミットが修正する問題は、`vendor`ディレクトリの可視性ルールを強制する`disallowVendorVisibility`関数にありました。この関数は、`vendor`ディレクトリ内のパッケージが、その`vendor`ディレクトリを含む親パッケージからのみインポートされるべきであるという制約をチェックします。しかし、特定の不正なインポートパス（特に`/vendor/`を含むが、その構造が期待される形式ではない場合）が与えられた際、パスを切り詰めるためのインデックス計算が負の値になったり、元のパスの長さを超えたりする可能性がありました。Go言語のスライス操作は、不正なインデックスが指定されるとランタイムパニックを引き起こすため、これがプログラムの異常終了の原因となっていました。

具体的には、`p.Dir[:i+len(p.Dir)-len(p.ImportPath)]`というスライス操作において、`i+len(p.Dir)-len(p.ImportPath)`の結果が負の値になるか、`p.Dir`の長さを超える場合にパニックが発生していました。この問題はGo issue #11414として報告され、このコミットによって修正されました。

## 前提知識の解説

### Goのパッケージ管理と`GOPATH`

Go 1.5がリリースされた2015年当時、Go言語のパッケージ管理は主に`GOPATH`環境変数に依存していました。`GOPATH`は、Goのソースコード、コンパイル済みパッケージ、実行可能バイナリが配置されるワークスペースのルートディレクトリを指定するものでした。プロジェクトの依存関係は、通常`go get`コマンドによって`GOPATH`内の共有リポジトリにダウンロードされ、すべてのプロジェクトで同じバージョンの依存関係が使用されることが一般的でした。しかし、これは異なるプロジェクトで異なるバージョンの依存関係が必要な場合に問題を引き起こすことがありました。

### `vendor`ディレクトリ

`vendor`ディレクトリは、Go 1.5で導入された実験的な機能であり、Go 1.6でデフォルトで有効化され、Go 1.7で完全に組み込まれました。この機能の目的は、プロジェクト固有の依存関係を管理し、ビルドの再現性を向上させることでした。プロジェクトのルートディレクトリ直下やサブディレクトリに`vendor`という名前のディレクトリを作成し、その中に依存パッケージのソースコードを配置します。`go`コマンドは、パッケージをインポートする際に、まず現在のパッケージの`vendor`ディレクトリ、次に親ディレクトリの`vendor`ディレクトリ、そして最終的に`GOPATH`を探索するという優先順位で解決を行います。これにより、プロジェクトは特定のバージョンの依存関係を「ベンダー化」（vendoring）し、外部の変更から隔離することが可能になりました。

### `GO15VENDOREXPERIMENT`

`GO15VENDOREXPERIMENT`は、Go 1.5で`vendor`ディレクトリ機能を有効にするために導入された環境変数です。Go 1.5では、この変数を`1`または`on`に設定することで、`go`コマンドが`vendor`ディレクトリを認識し、利用するようになりました。Go 1.6では、この機能がデフォルトで有効になったため、この環境変数を設定する必要はなくなりましたが、`0`に設定することで明示的に無効にすることも可能でした。Go 1.7では、`vendor`機能が完全に標準機能として組み込まれたため、`GO15VENDOREXPERIMENT`環境変数自体が削除されました。

### `panic`とは

Go言語における`panic`は、プログラムの実行中に回復不能なエラーが発生した際に、現在のゴルーチン（軽量スレッド）の実行を停止し、コールスタックを巻き戻しながらエラーを伝播させるメカニズムです。通常、`panic`は、プログラマーが予期しない、または処理できないような重大なエラー（例: `nil`ポインタのデリファレンス、配列のインデックス範囲外アクセス、無限再帰など）が発生した場合に引き起こされます。`panic`が発生すると、`defer`関数が実行された後、プログラム全体がクラッシュすることが一般的です。このコミットで修正された問題は、まさにこのようなインデックス範囲外アクセスによる`panic`でした。

### `import path`の解決

Goの`import path`は、パッケージを一意に識別するための文字列です。`go`コマンドは、ソースコード内で`import "path/to/package"`のような記述を見つけると、そのパッケージのソースコードを探しに行きます。この探索順序は、`vendor`ディレクトリの導入により複雑化しました。

1.  **現在のパッケージの`vendor`ディレクトリ**: まず、インポート元のパッケージのディレクトリから見て、`vendor`ディレクトリ内に目的のパッケージがあるかを探します。
2.  **親ディレクトリの`vendor`ディレクトリ**: 見つからなければ、親ディレクトリを遡りながら`vendor`ディレクトリ内を探します。
3.  **`GOPATH`**: 最終的に、`GOPATH`で指定されたディレクトリ内のパッケージを探します。
4.  **`GOROOT`**: 標準ライブラリの場合は`GOROOT`内を探します。

このコミットで問題となったのは、この解決プロセスの一部である`vendor`ディレクトリの可視性チェックにおいて、不正なインポートパスが与えられた場合に、パスの操作が安全に行われない点でした。

## 技術的詳細

このコミットの核心は、`src/cmd/go/pkg.go`ファイル内の`disallowVendorVisibility`関数に対する変更です。この関数は、`vendor`ディレクトリの可視性ルール、すなわち「`vendor`ディレクトリ内のパッケージは、その`vendor`ディレクトリを含む親パッケージからのみインポート可能である」という制約を強制するために存在します。

元のコードでは、`parent`という変数を計算する際に、`p.Dir`（現在のパッケージのディレクトリパス）から`p.ImportPath`（現在のパッケージのインポートパス）の長さを引くことで、`vendor`ディレクトリの親ディレクトリのパスを特定しようとしていました。この計算は以下の行で行われていました。

```go
parent := p.Dir[:i+len(p.Dir)-len(p.ImportPath)]
```

ここで、`i`は`"/vendor/"`という文字列が見つかったインデックスです。問題は、`i+len(p.Dir)-len(p.ImportPath)`という計算結果が負の値になったり、`p.Dir`の有効なインデックス範囲を超えたりする可能性があったことです。Go言語では、スライス操作`s[low:high]`において、`low`が負の値であるか、`high`が`len(s)`を超える場合にランタイムパニックが発生します。

このコミットでは、この脆弱性に対処するために、`truncateTo`という中間変数を導入し、スライス操作を行う前にその値が有効な範囲内にあるかを明示的にチェックするガード句を追加しました。

```go
	truncateTo := i + len(p.Dir) - len(p.ImportPath)
	if truncateTo < 0 || len(p.Dir) < truncateTo {
		return p
	}
	parent := p.Dir[:truncateTo]
```

この変更により、`truncateTo`が負の値であるか、または`p.Dir`の長さを超える場合、関数は現在のパッケージ`p`をそのまま返し、不正なスライス操作によるパニックを回避します。これにより、`go`コマンドは不正なインポートパスに対しても堅牢になり、予期せぬクラッシュを防ぐことができます。

また、この修正を検証するために、`src/cmd/go/testdata/src/vend/x/invalid/invalid.go`という新しいテストファイルと、`src/cmd/go/vendor_test.go`に`TestVendorInvalid`という新しいテストケースが追加されました。`invalid.go`は、`vend/x/invalid/vendor/foo`という不正なインポートパスを含むパッケージを定義しており、`TestVendorInvalid`はこの不正なインポートパスがパニックを引き起こさずにエラーとして適切に処理されることを確認します。

## コアとなるコードの解説

変更された`src/cmd/go/pkg.go`内の`disallowVendorVisibility`関数は、`vendor`ディレクトリの可視性ルールをチェックする役割を担っています。

1.  **`truncateTo := i + len(p.Dir) - len(p.ImportPath)`**:
    *   この行は、`p.Dir`（現在のパッケージの物理パス）から、`p.ImportPath`（現在のパッケージのインポートパス）の長さを差し引いた位置を計算し、`vendor`ディレクトリを含む親ディレクトリのパスを特定するためのインデックス`truncateTo`を決定しようとします。
    *   `i`は、`p.Dir`内で`"/vendor/"`という文字列が見つかった開始インデックスです。`i--`は、`vendor`の前のスラッシュまで巻き戻すための処理です。
    *   この計算が、特定の不正なインポートパスの場合に負の値になったり、`p.Dir`の長さを超える可能性がありました。

2.  **`if truncateTo < 0 || len(p.Dir) < truncateTo { return p }`**:
    *   この新しいガード句は、計算された`truncateTo`の値が有効なインデックス範囲内にあるかをチェックします。
    *   `truncateTo < 0`: `truncateTo`が負の値である場合、スライス操作はパニックを引き起こします。
    *   `len(p.Dir) < truncateTo`: `truncateTo`が`p.Dir`の長さを超える場合、これもスライス操作でパニックを引き起こします。
    *   これらの条件のいずれかが真である場合、関数は現在のパッケージ`p`をそのまま返し、それ以上の処理を行いません。これにより、不正なインデックスによるパニックが未然に防がれます。

3.  **`parent := p.Dir[:truncateTo]`**:
    *   `truncateTo`が有効なインデックスであることが保証された後、この行で`p.Dir`を`truncateTo`の位置で切り詰め、`vendor`ディレクトリの親ディレクトリのパスを`parent`として取得します。

この変更により、`disallowVendorVisibility`関数は、不正なインポートパスが与えられた場合でも、安全に処理を続行できるようになり、`go`コマンドの安定性が向上しました。
