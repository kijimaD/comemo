## 変更の背景

Goコンパイラは、コードの最適化と効率的な機械語生成のためにSSA (Static Single Assignment) 形式の中間表現を使用しています。ビット演算、特にローテーション操作は、暗号化アルゴリズムやハッシュ関数、データパッキングなど、多くの低レベルプログラミングで頻繁に利用されます。

従来のGoコンパイラでは、左ローテーション操作は `(x << n) | (x >> (BIT_WIDTH - n))` のようなシフトとORの組み合わせとして表現され、コンパイルされていました。しかし、多くのCPUアーキテクチャ（特にAMD64）には、このローテーション操作を単一の命令（例: `ROL` 命令）で実行できる機能が備わっています。単一のCPU命令を使用することで、複数の命令を組み合わせるよりも高速かつ効率的なコードが生成されます。

このコミットの背景には、Goコンパイラがこのようなハードウェアの機能を活用し、より最適化された機械語を生成することで、Goプログラムのパフォーマンスを向上させるという目的があります。特に、定数によるローテーションはコンパイル時に最適化の機会が多いため、そのサポートが優先されたと考えられます。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSAは、コンパイラの中間表現（IR）の一種で、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、Go言語のソースコードを抽象構文木（AST）に変換した後、SSA形式に変換し、様々な最適化パスを適用してから最終的な機械語を生成します。

### 2. ビットローテーション (Circular Shift)

ビットローテーションは、ビット列を左右にシフトする際に、端からはみ出したビットが反対側の端に戻ってくるようにする操作です。通常のビットシフト（論理シフトや算術シフト）では、はみ出したビットは失われ、空いたビット位置には0が埋められます。

- **左ローテーション (LROT: Left Rotate)**: ビット列を左にシフトし、左端からはみ出したビットが右端に戻ってきます。
  例: 8ビット値 `10110010` を左に2ビットローテーションすると `11001010` になります。

ビットローテーションは、特に暗号化アルゴリズム（例: SHA-256、AES）やハッシュ関数で、データの拡散や混合を行うために不可欠な操作です。

### 3. AMD64アーキテクチャの `ROL` 命令

AMD64 (x86-64) アーキテクチャには、ビットローテーションを直接サポートする `ROL` (Rotate Left) 命令があります。この命令は、指定されたレジスタまたはメモリ位置のビットを左に指定された回数だけローテーションします。例えば、`ROL EAX, 5` は `EAX` レジスタの値を5ビット左にローテーションします。この命令は、シフトとORの組み合わせよりも効率的です。

### 4. コンパイラの最適化パス

コンパイラは、ソースコードをより効率的な機械語に変換するために、様々な最適化パスを実行します。
- **パターンマッチング**: 特定のコードパターン（例: `(x << n) | (x >> (BIT_WIDTH - n))`）を認識し、それに対応するより効率的な単一のCPU命令（例: `ROL`）に置き換える最適化です。
- **定数伝播**: コンパイル時に値が確定している定数を利用して、計算を簡略化したり、特定の命令を選択したりする最適化です。このコミットでは、ローテーション距離が定数である場合に特化した最適化が行われています。

## 技術的詳細

このコミットは、Goコンパイラの以下の部分に影響を与えます。

1.  **`src/cmd/compile/internal/gc/ssa.go`**:
    -   Go言語のASTノード (`OLROT`) をSSAのオペレーション (`ssa.OpLrot8`, `ssa.OpLrot16`, `ssa.OpLrot32`, `ssa.OpLrot64`) にマッピングする `opToSSA` マップにエントリが追加されました。
    -   `ssaRotateOp` という新しいヘルパー関数が追加され、Goの型に基づいて適切なSSAローテーションオペレーションを選択します。
    -   `expr` 関数内で、`OLROT` ノードが検出された際に、左オペランドと定数である右オペランド（ローテーション距離）を抽出し、`newValue1I` を使用してSSAローテーション命令を生成するロジックが追加されました。ローテーション距離が型のビット幅の範囲内であるかどうかの検証も行われます。
    -   `genValue` 関数内で、AMD64の `ROLQconst` などの定数ローテーション命令が、レジスタアロケータの制約を考慮して処理されるように変更されました。

2.  **`src/cmd/compile/internal/gc/testdata/arith_ssa.go`**:
    -   `lrot1_ssa`, `lrot2_ssa`, `lrot3_ssa` といった新しいテスト関数が追加されました。これらは、異なるビット幅（`uint8`, `uint16`, `uint32`, `uint64`）と異なるローテーション距離（定数、変数、ビット幅と同じ距離）での左ローテーションの挙動を検証します。
    -   特に `lrot2_ssa` と `lrot3_ssa` は、「32ビットローテーション」が実際には元の値に戻る（`w << 32` が0になり、`w >> 0` が `w` になる）というエッジケースをテストしています。
    -   `main` 関数に `testLrot()` の呼び出しが追加され、新しいローテーションテストが実行されるようになりました。

3.  **`src/cmd/compile/internal/ssa/gen/AMD64.rules`**:
    -   SSAの汎用ローテーションオペレーション (`Lrot64`, `Lrot32`, `Lrot16`, `Lrot8`) を、AMD64アーキテクチャ固有の定数ローテーション命令 (`ROLQconst`, `ROLLconst`, `ROLWconst`, `ROLBconst`) に書き換えるルールが追加されました。
    -   ローテーション距離 `c` は、各型のビット幅に応じてマスク (`&63`, `&31`, `&15`, `&7`) され、有効な範囲に制限されます。これは、AMD64の `ROL` 命令がローテーションカウントをレジスタのビット幅でマスクする挙動に合わせたものです。

4.  **`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`**:
    -   AMD64アーキテクチャのSSAオペレーションとして、`ROLQconst`, `ROLLconst`, `ROLWconst`, `ROLBconst` が定義されました。これらはそれぞれ `ROLQ`, `ROLL`, `ROLW`, `ROLB` というアセンブリ命令に対応し、定数によるローテーションを表現します。

5.  **`src/cmd/compile/internal/ssa/gen/genericOps.go`**:
    -   SSAの汎用オペレーションとして `Lrot8`, `Lrot16`, `Lrot32`, `Lrot64` が追加されました。
    -   コメントで、これらの左ローテーションオペレーションが `(arg0 << arg1) ^ (arg0 >> (A-arg1))` というパターンからフロントエンドでパターンマッチングされることが説明されています。
    -   ローテーション距離 `arg1` が定数で、かつ `1` から `A-1` の範囲内である場合にのみ、ローテーション命令に置換されるという重要な制約が記述されています。これは、`arg1 = 0` や `arg1 = A` のケースがシフトのイディオムとは異なる結果を生む可能性があるため、安全のために設けられたものです。

6.  **`src/cmd/compile/internal/ssa/opGen.go`**:
    -   SSAオペレーションの列挙型に、汎用ローテーションオペレーション (`OpLrot8` など) とAMD64固有の定数ローテーションオペレーション (`OpAMD64ROLQconst` など) が追加されました。
    -   `opcodeTable` に、これらの新しいオペレーションに関する情報（名前、アセンブリ命令、レジスタ情報など）が定義されました。特に、`ROLQconst` などのレジスタ情報では、出力レジスタマスクが `65519` となっており、これは `SP` レジスタが破壊される可能性があることを示唆しています（ただし、`ROL` 命令自体は通常、フラグレジスタのみを変更し、オペランドレジスタは変更しないため、これは一般的なレジスタ使用規則の一部である可能性があります）。

7.  **`src/cmd/compile/internal/ssa/rewriteAMD64.go`**:
    -   `rewriteValueAMD64` 関数に、`OpLrot16`, `OpLrot32`, `OpLrot64`, `OpLrot8` の各SSAオペレーションを、対応するAMD64の定数ローテーション命令 (`OpAMD64ROLWconst` など) に書き換えるロジックが追加されました。
    -   この書き換えルールは、SSAの汎用ローテーションオペレーションを、ターゲットアーキテクチャ（AMD64）の具体的な命令に変換する役割を担います。ローテーション距離は、`AuxInt` フィールドから取得され、適切なビット幅でマスクされます。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、GoコンパイラのSSAバックエンドが、Go言語のソースコードで表現されたビットローテーションパターンを認識し、それをAMD64アーキテクチャのネイティブな `ROL` 命令に変換する能力を獲得した点にあります。

具体的には、以下のファイルにおける変更が重要です。

-   **`src/cmd/compile/internal/gc/ssa.go`**: GoのASTノード `OLROT` をSSAの汎用ローテーションオペレーション (`ssa.OpLrotX`) にマッピングし、ローテーション距離が定数である場合の処理を追加。
-   **`src/cmd/compile/internal/ssa/gen/AMD64.rules`**: SSAの汎用ローテーションオペレーションをAMD64の定数ローテーション命令 (`ROLXconst`) に変換する書き換えルールを定義。
-   **`src/cmd/compile/internal/ssa/rewriteAMD64.go`**: 上記のルールに基づいて、実際にSSA値をAMD64固有の命令に書き換えるロジックを実装。

これらの変更により、Goコンパイラは、`x << n | x >> (BIT_WIDTH - n)` のようなGoコードを、より効率的な単一の `ROL` 機械語命令に変換できるようになります。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更

```go
// opToSSA マップへの追加
opAndType{OLROT, TUINT8}:  ssa.OpLrot8,
opAndType{OLROT, TUINT16}: ssa.OpLrot16,
opAndType{OLROT, TUINT32}: ssa.OpLrot32,
opAndType{OLROT, TUINT64}: ssa.OpLrot64,

// ssaRotateOp 関数の追加
func (s *state) ssaRotateOp(op uint8, t *Type) ssa.Op {
	etype1 := s.concreteEtype(t)
	x, ok := opToSSA[opAndType{op, etype1}]
	if !ok {
		s.Unimplementedf("unhandled rotate op %s etype=%s", opnames[op], Econv(int(etype1), 0))
	}
	return x
}

// expr 関数内の OLROT 処理
case OLROT:
	a := s.expr(n.Left) // ローテーション対象の値
	i := n.Right.Int()  // ローテーション距離 (定数)
	if i <= 0 || i >= n.Type.Size()*8 {
		s.Fatalf("Wrong rotate distance for LROT, expected 1 through %d, saw %d", n.Type.Size()*8-1, i)
	}
	return s.newValue1I(s.ssaRotateOp(n.Op, n.Type), a.Type, i, a)
```
`opToSSA` マップは、Goの演算子と型をSSAのオペレーションにマッピングします。`OLROT` が追加されたことで、コンパイラはGoコード中のローテーション操作をSSAレベルで認識できるようになります。`ssaRotateOp` は、具体的な型（`uint8`, `uint16` など）に基づいて適切なSSAローテーションオペレーションを選択します。`expr` 関数は、ASTノードをSSA値に変換する主要な場所です。ここで `OLROT` ノードが処理され、ローテーション距離が定数であること、およびその値が有効な範囲内であること（1からビット幅-1）が検証されます。その後、`newValue1I` を使って、ローテーション距離をAuxIntとして持つSSA値が生成されます。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更

```
(Lrot64 <t> x [c]) -> (ROLQconst <t> [c&63] x)
(Lrot32 <t> x [c]) -> (ROLLconst <t> [c&31] x)
(Lrot16 <t> x [c]) -> (ROLWconst <t> [c&15] x)
(Lrot8 <t> x [c])  -> (ROLBconst <t> [c&7] x)
```
これらのルールは、SSAの汎用ローテーションオペレーション (`LrotX`) を、AMD64アーキテクチャの具体的な定数ローテーション命令 (`ROLXconst`) に変換するためのパターンマッチング規則です。`[c]` は定数オペランドを示し、`c&63` のようにビット幅でマスクすることで、AMD64の `ROL` 命令がローテーションカウントをレジスタのビット幅で自動的にマスクする挙動をエミュレートしています。これにより、例えば64ビット値の64ビットローテーションが0ビットローテーションとして扱われるなど、ハードウェアの特性に合わせた正しいコードが生成されます。

### `src/cmd/compile/internal/ssa/rewriteAMD64.go` の変更

```go
case OpLrot16:
	// match: (Lrot16 <t> x [c])
	// cond:
	// result: (ROLWconst <t> [c&15] x)
	{
		t := v.Type
		x := v.Args[0]
		c := v.AuxInt
		v.Op = OpAMD64ROLWconst // オペレーションをAMD64固有の定数ローテーションに設定
		v.AuxInt = c & 15      // ローテーション距離をマスクして設定
		v.AddArg(x)            // オペランドを追加
		return true
	}
// OpLrot32, OpLrot64, OpLrot8 も同様
```
`rewriteValueAMD64` 関数は、SSAの値をAMD64アーキテクチャの命令に変換するリライトパスの一部です。ここで、`OpLrotX` オペレーションが検出されると、そのSSA値のオペレーションが対応する `OpAMD64ROLXconst` に変更され、ローテーション距離が `AuxInt` として設定されます。これにより、コンパイラのバックエンドは最終的に `ROL` アセンブリ命令を生成できるようになります。
