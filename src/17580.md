## 変更の背景

Go言語は継続的に進化しており、新しいバージョンがリリースされるたびに、言語、ツール、標準ライブラリに多くの変更が加えられます。これらの変更をユーザーに正確に伝えるために、公式のリリースノートが作成されます。このコミットは、Go 1.2のリリースノートである `doc/go1.2.html` を、以下の主要な変更点を反映するように更新することを目的としています。

1.  **`godoc` と `vet` ツールの `go.tools` サブリポジトリへの移動**: これらのツールはGoの配布物に含まれていますが、そのソースコードは独立した `go.tools` サブリポジトリに移行されました。これにより、Goのコアリポジトリの肥大化を防ぎ、ツールの開発と管理をより柔軟に行えるようになります。
2.  **テストカバレッジ機能の導入**: `go test` コマンドにテストカバレッジを測定する機能が追加され、`go tool cover` という新しいツールが導入されました。これは、Goアプリケーションのテスト品質を向上させる上で非常に重要な機能です。
3.  **`go doc` コマンドの削除**: `go` コマンドのサブコマンドとして提供されていた `go doc` が削除されました。これは、`godoc` ツール自体が同様の機能を提供しており、重複を避けるための合理化です。
4.  **`go get -t` フラグの追加**: `go get` コマンドに `-t` フラグが追加され、テストに必要な依存関係もダウンロードできるようになりました。これにより、テスト環境のセットアップが容易になります。
5.  **Goテンプレートの変更**: Goの `html/template` および `text/template` パッケージにおいて、閉じられていないデリミタ（`{{` と `}}`）の診断がより厳密になりました。これにより、不正なテンプレート構文が早期に検出されるようになります。
6.  **圧縮ライブラリの `Reset` メソッド追加**: `compress/flate`, `compress/gzip`, `compress/zlib` パッケージの `Writer` 型に `Reset` メソッドが追加され、リソースの再利用とアロケーションの削減が可能になりました。
7.  **`netgo` ビルドタグの導入**: `net` パッケージにおいて、cgoに依存しない純粋なGo実装をビルドするための `netgo` ビルドタグが導入されました。これは、特定の環境でのデプロイメントや静的リンクのニーズに対応するためのものです。

これらの変更は、Go言語の使いやすさ、開発効率、およびパフォーマンスを向上させるための重要なステップであり、リリースノートの更新は、これらの改善をユーザーに明確に伝えるために不可欠でした。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語に関する基本的な知識が必要です。

*   **Go言語のツールチェイン**: Go言語は、コンパイラ、リンカ、フォーマッタ、テストツールなど、開発に必要な多くのツールを内蔵しています。これらは通常、`go` コマンドを通じて利用されます。
*   **`go get`**: 外部のGoパッケージやコマンドをダウンロードし、インストールするためのコマンドです。
*   **`go test`**: Goパッケージのテストを実行するためのコマンドです。
*   **`godoc`**: Goのソースコードからドキュメントを生成し、表示するためのツールです。Webサーバーとしても機能し、Goの標準ライブラリやプロジェクトのドキュメントをブラウザで閲覧できます。
*   **`go vet`**: Goのソースコードを静的に解析し、潜在的なバグや疑わしい構造を報告するツールです。
*   **`go.tools` サブリポジトリ**: Goプロジェクトの一部ですが、Goのコアリポジトリとは別に管理されているツールやライブラリのコレクションです。これには、`godoc` や `vet` のようなツールが含まれます。
*   **Goテンプレート (`html/template`, `text/template`)**: Go言語に組み込まれているテンプレートエンジンで、動的にHTMLやテキストを生成するために使用されます。`{{.FieldName}}` のようなデリミタを使用して、データとテンプレートを結合します。
*   **ビルドタグ (Build Tags)**: Goのソースファイルに特定のコメント行を追加することで、特定の条件（OS、アーキテクチャ、カスタムタグなど）に基づいてファイルのコンパイルを制御するメカニズムです。例えば、`// +build linux` はLinuxシステムでのみコンパイルされることを示します。
*   **cgo**: GoプログラムからC言語のコードを呼び出すためのメカニズムです。`net` パッケージのように、OSのネイティブなネットワーク機能を利用する場合にはcgoが使われることがあります。
*   **圧縮ライブラリ (`compress/flate`, `compress/gzip`, `compress/zlib`)**: Goの標準ライブラリに含まれる、データ圧縮・解凍のためのパッケージ群です。

## 技術的詳細

このコミットは、Go 1.2リリースノートのHTMLドキュメント (`doc/go1.2.html`) を更新することで、Go言語のいくつかの重要な変更点を詳細に説明しています。

1.  **`godoc` と `vet` の `go.tools` への移動**:
    *   以前はGoのメインリポジトリの一部だった `godoc` と `vet` のソースコードが、`code.google.com/p/go.tools` サブリポジトリに移動しました。
    *   バイナリは引き続きGoの配布物に含まれるため、既存のユーザーへの影響は最小限です。
    *   ソースからビルドするユーザーは、`go get code.google.com/p/go.tools/cmd/godoc` および `go get code.google.com/p/go.tools/cmd/vet` を実行してこれらのツールをインストールする必要があります。
    *   `godoc` のコア部分はライブラリとして分割され、コマンド自体は別のディレクトリに配置されました。これにより、カスタムバイナリの構築が容易になります。

2.  **テストカバレッジ (`go tool cover`)**:
    *   `go test` コマンドに `-cover` フラグが追加され、テスト実行時にコードカバレッジを測定できるようになりました。
    *   `go test -cover fmt` のように実行すると、パッケージのステートメントカバレッジのパーセンテージが表示されます。
    *   より詳細なレポートのために、`go test` はカバレッジプロファイルファイルを生成でき、これを `go tool cover` コマンドで解析できます。
    *   `go tool cover` は `go.tools` サブリポジトリの一部であり、`go get code.google.com/p/go.tools/cmd/cover` でインストールできます。
    *   この機能は、テストの網羅性を評価し、テストが不足している領域を特定するのに役立ちます。

3.  **`go doc` コマンドの削除**:
    *   `go` コマンドのサブコマンドであった `go doc` が削除されました。
    *   これは、`godoc` ツール自体が同様の機能（パッケージパスによるドキュメント表示）をより柔軟に提供しているためです。
    *   `go doc` の代わりに、`godoc .` を実行することで、現在のディレクトリのパッケージドキュメントを表示できます。この変更は、ドキュメンテーションツールの数を減らし、将来的に良い選択肢を奨励するためのものです。

4.  **`go get -t` フラグ**:
    *   `go get` コマンドに `-t` フラグが追加されました。
    *   このフラグを使用すると、パッケージ自体の依存関係だけでなく、そのパッケージのテストに必要な依存関係もダウンロードされるようになります。
    *   デフォルトでは、テストの依存関係はダウンロードされません。これにより、開発者はテスト環境のセットアップをより細かく制御できるようになります。

5.  **Goテンプレートの変更**:
    *   `text/template` および `html/template` パッケージにおいて、閉じられていない右デリミタ（`}}`）が正しく診断されるようになりました。
    *   以前は、これらの不正なデリミタは警告なしに受け入れられていましたが、Go 1.2以降はパースエラーとなります。
    *   これにより、テンプレートの構文エラーが早期に発見され、より堅牢なテンプレートコードの作成が促されます。既存のテンプレートでこの問題がある場合は、手動で修正する必要があります。

6.  **圧縮ライブラリの `Reset` メソッド**:
    *   `compress/flate`, `compress/gzip`, `compress/zlib` パッケージの `Writer` 型に `Reset` メソッドが追加されました。
    *   このメソッドを使用すると、既存の `Writer` インスタンスを再利用して、新しい圧縮ストリームを開始できます。
    *   これにより、特に複数のファイルを圧縮するようなシナリオで、オブジェクトのアロケーションを削減し、ガベージコレクションの負荷を軽減できます。

7.  **`netgo` ビルドタグ**:
    *   `net` パッケージは通常、cgoを使用してホストOSのネットワーク機能と連携します。
    *   新しいビルドタグ `netgo` を使用すると、cgoに依存しない純粋なGo実装の `net` パッケージをビルドできます（可能なシステムに限る）。
    *   これは、動的リンクを避けたい場合や、特定のクロスコンパイル環境で役立ちます。デフォルトでは無効です。

これらの変更は、Go言語の機能性、開発者の利便性、およびパフォーマンスの向上に貢献しています。
