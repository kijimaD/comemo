## 変更の背景

この変更の背景には、Android NDK（Native Development Kit）の進化と、それに伴う `PTHREAD_KEYS_MAX` の定義に関する問題がありました。

GoのCgo機能は、GoプログラムがC言語のコードを呼び出すことを可能にします。Androidプラットフォームでは、Goプログラムがネイティブコードと連携するために、Android NDKが提供するCライブラリ（bionic libc）を利用します。

以前のAndroid NDKのバージョンでは、`PTHREAD_KEYS_MAX` というマクロが `sys/limits.h` に定義されていませんでした。そのため、GoランタイムのCgo関連コード（特に `src/runtime/cgo/gcc_android_arm.c` のようなファイル）では、このマクロを独自に定義する必要がありました。コミットメッセージにある `TODO(crawshaw): remove this definition when a new NDK is released.` というコメントは、この暫定的な対応を示しています。

しかし、新しいAndroid NDK（具体的には、コミットメッセージで言及されている `NDK r10d` のリリースが示唆されています）では、`PTHREAD_KEYS_MAX` がbionicの `sys/limits.h` に追加されました。この変更により、Goランタイムが独自に `PTHREAD_KEYS_MAX` を定義していると、コンパイル時に「マクロの再定義」エラーが発生する可能性が出てきました。

このコミットは、この再定義の問題を回避し、Goランタイムが新しいNDKバージョンと互換性を持つようにするために行われました。`Fixes #9374` は、この問題がGoのイシュートラッカーで報告されていたことを示しています。

## 前提知識の解説

*   **Cgo**: Go言語の機能の一つで、GoプログラムからC言語の関数を呼び出したり、C言語のコードからGoの関数を呼び出したりすることを可能にします。これにより、既存のCライブラリをGoから利用したり、パフォーマンスが重要な部分をCで記述したりすることができます。
*   **Android NDK (Native Development Kit)**: AndroidアプリケーションでC/C++コードを使用するためのツールセットです。これには、コンパイラ、ヘッダーファイル、ライブラリなどが含まれており、Androidデバイス上で動作するネイティブコードをビルドするために使用されます。
*   **bionic libc**: Androidオペレーティングシステムで使用されているC標準ライブラリです。一般的なLinuxシステムで使われるglibcとは異なり、Androidの特定の要件に合わせて最適化されています。
*   **`PTHREAD_KEYS_MAX`**: POSIXスレッド（pthreads）APIにおいて、スレッド固有データ（Thread-Local Storage, TLS）のキーの最大数を定義するマクロです。スレッド固有データは、各スレッドが独自のデータを持つことを可能にするメカニズムで、グローバル変数とは異なり、スレッド間で共有されません。`pthread_key_create` 関数を使ってキーを作成し、`pthread_getspecific` や `pthread_setspecific` を使ってデータを操作します。
*   **マクロの再定義**: C/C++プログラミングにおいて、同じ名前のマクロが複数回、異なる定義で現れることを指します。これは通常、コンパイルエラーや予期せぬ動作の原因となります。`#ifndef` や `#define` などのプリプロセッサディレクティブを使って、このような問題を回避します。

## 技術的詳細

このコミットの技術的な核心は、Cプリプロセッサの `#ifndef` ディレクティブを使用して、`PTHREAD_KEYS_MAX` マクロの条件付き定義を行うことです。

Goランタイムの `src/runtime/cgo/gcc_android_arm.c` ファイルでは、以前から `PTHREAD_KEYS_MAX` が `128` としてハードコードされていました。これは、当時のAndroid NDKのヘッダーファイルにこの定義が存在しなかったためです。

```c
#define PTHREAD_KEYS_MAX 128
```

しかし、Android NDKの更新により、bionic libcの `sys/limits.h` に `PTHREAD_KEYS_MAX` が公式に定義されるようになりました。この状況で、Goランタイムが引き続き独自の定義を行っていると、コンパイラは同じマクロが二重に定義されていると判断し、エラーを報告します。

この問題を解決するために、Goランタイムのコードに `#ifndef PTHREAD_KEYS_MAX` と `#endif` が追加されました。

```c
#ifndef PTHREAD_KEYS_MAX
#define PTHREAD_KEYS_MAX 128
#endif
```

この変更により、コンパイラが `src/runtime/cgo/gcc_android_arm.c` を処理する際に、以下のロジックが適用されます。

1.  **`PTHREAD_KEYS_MAX` がまだ定義されていない場合**: `#ifndef PTHREAD_KEYS_MAX` の条件が真となり、`#define PTHREAD_KEYS_MAX 128` が実行され、マクロが定義されます。これは、古いNDKバージョンを使用している場合に該当します。
2.  **`PTHREAD_KEYS_MAX` が既に定義されている場合**: `#ifndef PTHREAD_KEYS_MAX` の条件が偽となり、`#define PTHREAD_KEYS_MAX 128` の行はスキップされます。これは、新しいNDKバージョンを使用しており、bionicのヘッダーファイルによって既にマクロが定義されている場合に該当します。

このようにして、Goランタイムは、使用されているAndroid NDKのバージョンに関わらず、`PTHREAD_KEYS_MAX` の定義に関するコンパイルエラーを回避できるようになりました。これは、異なる環境やライブラリバージョンへの互換性を確保するための一般的なC/C++プログラミングのプラクティスです。

また、コミットメッセージの `TODO(crawshaw): remove this definition when NDK r10d is required.` というコメントは、将来的にGoがNDK r10d以降のバージョンのみをサポートするようになった場合、この条件付き定義自体が不要になる可能性を示唆しています。その時点で、Goランタイムはbionicの定義に完全に依存できるようになるため、このコードは削除されるべきであるという意図が込められています。

## コアとなるコードの解説

変更の中心は、`PTHREAD_KEYS_MAX` の定義に `#ifndef` と `#endif` のプリプロセッサディレクティブを追加した点です。

*   **`- #define PTHREAD_KEYS_MAX 128`**: 変更前のコードでは、`PTHREAD_KEYS_MAX` が無条件に `128` と定義されていました。
*   **`+ #ifndef PTHREAD_KEYS_MAX`**: この行は、プリプロセッサに対して「もし `PTHREAD_KEYS_MAX` がまだ定義されていなければ」という条件を指示します。
*   **`+ #define PTHREAD_KEYS_MAX 128`**: この行は、上記の `#ifndef` の条件が真（つまり、`PTHREAD_KEYS_MAX` が未定義）の場合にのみ実行され、マクロを `128` と定義します。
*   **`+ #endif`**: これは `#ifndef` ブロックの終わりを示します。

この変更により、`PTHREAD_KEYS_MAX` が既にシステムヘッダー（例: Android NDKのbionic libcの `sys/limits.h`）によって定義されている場合、Goランタイムのコードは独自の定義を行わなくなります。これにより、マクロの再定義によるコンパイルエラーが回避され、Goランタイムが新しいNDKバージョンと互換性を持つようになります。

コメントも更新され、`TODO(crawshaw): remove this definition when a new NDK is released.` から `TODO(crawshaw): remove this definition when NDK r10d is required.` に変更されています。これは、この暫定的な定義が将来的にどのNDKバージョンで不要になるかについて、より具体的な目標を示しています。
