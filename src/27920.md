## 変更の背景

Go言語の `container/heap` パッケージは、ヒープデータ構造を実装するための汎用的なインターフェースと関数を提供します。このパッケージの性能を評価するために、ベンチマークテストが用意されています。

`BenchmarkDup` は、重複する要素をヒープに追加する際の性能を測定するためのベンチマーク関数です。このベンチマークの実装において、ヒープの初期化方法に誤りがありました。

元のコードでは、`h := make(myHeap, n)` という形でヒープが初期化されていました。Goのスライス（ヒープの実装に用いられる）において、`make([]T, length)` は `length` の長さを持つスライスを作成し、その要素はゼロ値で初期化されます。つまり、この時点ですでに `n` 個のゼロ値要素がヒープ（スライス）内に存在していました。

その後、ベンチマークのループ内で `n` 個の要素が `Push(&h, 0)` を使って追加されていました。`heap.Push` 関数は、ヒープの末尾に要素を追加し、ヒープのプロパティを維持するように要素を並べ替えます。結果として、ベンチマークの各イテレーションの開始時には、意図せず `n` 個のゼロ値と `n` 個の追加された要素、合計 `2*n` 個の要素がヒープ内に存在することになっていました。

この状態では、ベンチマークは `n` 個の要素を扱う性能を正確に測定しているとは言えません。ヒープのサイズが意図よりも大きくなることで、ベンチマーク結果が実際の使用シナリオと乖離し、誤った性能評価につながる可能性がありました。このコミットは、この初期化の誤りを修正し、ベンチマークが `n` 個の要素のみを扱うようにすることで、より正確な性能測定を可能にすることを目的としています。

## 前提知識の解説

### Go言語のスライスと `make` 関数

Go言語のスライスは、可変長シーケンスを扱うための強力なデータ型です。スライスは内部的に配列を参照しており、長さ（`len`）と容量（`cap`）という2つのプロパティを持ちます。

-   **長さ (length)**: スライスに含まれる要素の数。
-   **容量 (capacity)**: スライスが参照している基底配列の、スライス開始位置から末尾までの要素の数。

`make` 関数は、スライス、マップ、チャネルを初期化するために使用されます。スライスの場合、`make` には以下の2つの形式があります。

1.  `make([]T, length)`: 型 `T` の要素を持つスライスを作成し、長さと容量を `length` に設定します。このとき、`length` 個の要素がゼロ値で初期化されます。
2.  `make([]T, length, capacity)`: 型 `T` の要素を持つスライスを作成し、長さを `length` に、容量を `capacity` に設定します。このとき、`length` 個の要素がゼロ値で初期化されます。`capacity` は `length` 以上である必要があります。

このコミットの文脈では、`h := make(myHeap, n)` は `n` 個のゼロ値要素を持つスライスを作成し、その長さと容量を `n` に設定していました。

### `container/heap` パッケージ

`container/heap` パッケージは、ヒープデータ構造（最小ヒープまたは最大ヒープ）を実装するための汎用的なインターフェースを提供します。このパッケージ自体は具体的なヒープの実装を持たず、`heap.Interface` インターフェースを満たす任意の型をヒープとして扱うことができます。

`heap.Interface` は以下のメソッドを定義します。

-   `Len() int`: ヒープの要素数を返します。
-   `Less(i, j int) bool`: `i` 番目の要素が `j` 番目の要素よりも小さい（または大きい）場合に `true` を返します。これにより、最小ヒープか最大ヒープかが決定されます。
-   `Swap(i, j int)`: `i` 番目と `j` 番目の要素を交換します。
-   `Push(x any)`: 要素 `x` をヒープに追加します。
-   `Pop() any`: ヒープから最小（または最大）要素を削除して返します。

`heap.Push` 関数は、`heap.Interface` を満たすスライスに対して要素を追加し、ヒープのプロパティを維持します。この関数は内部的に `append` を使用してスライスの長さを増やし、その後要素を適切な位置に移動させます。

### Go言語のベンチマーク

Go言語には、コードの性能を測定するための組み込みのベンチマーク機能があります。ベンチマーク関数は `BenchmarkXxx(*testing.B)` というシグネチャを持ち、`go test -bench=.` コマンドで実行されます。

`*testing.B` 型は、ベンチマークの実行を制御するためのメソッドを提供します。

-   `b.N`: ベンチマーク関数が実行されるイテレーション回数。この値はベンチマークシステムによって動的に調整され、統計的に有意な結果が得られるようにします。
-   `b.ResetTimer()`: タイマーをリセットします。通常、セットアップコードの後に呼び出され、測定対象のコードのみが計測されるようにします。
-   `b.StopTimer()`: タイマーを停止します。
-   `b.StartTimer()`: タイマーを開始します。

ベンチマークの目的は、特定の操作がどれくらいの時間で完了するか、またはどれくらいのメモリを消費するかを正確に測定することです。そのため、ベンチマークのセットアップは、測定対象のコードが意図した通りの条件で実行されるように慎重に行う必要があります。

## 技術的詳細

このコミットの技術的な核心は、Goのスライスにおける `make` 関数の挙動と、`container/heap` パッケージの `Push` 操作の組み合わせによって生じる、ベンチマークの初期状態の誤解釈にあります。

元のコード `h := make(myHeap, n)` は、`myHeap` 型（`[]int` のようなスライス型）の基底配列を `n` の長さで確保し、その `n` 個の要素をゼロ値（この場合は `0`）で初期化していました。この時点で、ヒープはすでに `n` 個の要素を含んでいる状態でした。

その後、ベンチマークの各イテレーション内で `for j := 0; j < n; j++ { Push(&h, 0) }` というループが実行されていました。`heap.Push` 関数は、ヒープの `Push` メソッドを呼び出しますが、これは通常、基底スライスに要素を `append` することで行われます。したがって、このループはさらに `n` 個の要素をヒープに追加していました。

結果として、`b.N` 回の各イテレーションの開始時には、ヒープ `h` は合計 `2*n` 個の要素（初期の `n` 個のゼロ値と、`Push` で追加された `n` 個のゼロ値）を含んでいました。ベンチマークの意図は `n` 個の要素を持つヒープに対する操作の性能を測定することであったため、この `2*n` 個の要素という状態は誤りでした。

修正は、`h := make(myHeap, 0, n)` とすることで、この問題を解決しています。
-   `length` を `0` に設定することで、初期状態ではヒープに要素が全く含まれないようにします。
-   `capacity` を `n` に設定することで、`n` 個の要素を追加する際に、基底配列の再割り当て（reallocation）が不要になり、ベンチマークのノイズを減らすことができます。これにより、`Push` 操作の純粋な性能がより正確に測定されるようになります。

この変更により、`BenchmarkDup` は、`n` 個の要素が追加される前の空のヒープから開始し、正確に `n` 個の要素が追加された状態での性能を測定するようになります。これは、ベンチマークの信頼性と正確性を向上させる上で重要な修正です。

-   `length` を `0` に設定することで、初期状態ではヒープに要素が全く含まれないようにします。
-   `capacity` を `n` に設定することで、`n` 個の要素を追加する際に、基底配列の再割り当て（reallocation）が不要になり、ベンチマークのノイズを減らすことができます。これにより、`Push` 操作の純粋な性能がより正確に測定されるようになります。

この変更により、`BenchmarkDup` は、`n` 個の要素が追加される前の空のヒープから開始し、正確に `n` 個の要素が追加された状態での性能を測定するようになります。これは、ベンチマークの信頼性と正確性を向上させる上で重要な修正です。

## コアとなるコードの解説

変更された行は以下の通りです。

-   **変更前**: `h := make(myHeap, n)`
    -   これは、`myHeap` 型（`[]int` のようなスライス）のヒープ `h` を作成し、その長さと容量を `n` に設定します。この時点で、`n` 個のゼロ値（`0`）がヒープ内に存在します。
    -   `n` は `10000` と定義されているため、初期状態で `10000` 個の `0` がヒープに含まれていました。

-   **変更後**: `h := make(myHeap, 0, n)`
    -   これは、`myHeap` 型のヒープ `h` を作成し、長さを `0` に、容量を `n` に設定します。
    -   長さが `0` であるため、初期状態ではヒープに要素は含まれていません。
    -   容量が `n` であるため、後続の `n` 回の `Push` 操作で要素が追加される際に、基底配列の再割り当てが発生せず、ベンチマークの測定がより安定します。
