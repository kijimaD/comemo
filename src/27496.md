## 変更の背景

Goコンパイラの内部では、型の特性を判定するためのメソッドが多数存在します。このコミット以前の`Type.IsPtr()`メソッドは、「その型がメモリ上でポインタとして表現されているか」という広範な意味で使用されていました。しかし、このメソッドを呼び出す一部のコード箇所では、「その型がGo言語の仕様上の純粋なポインタ型（例: `*int`）であるか」という、より厳密な意味でのポインタ判定を期待していました。

この意味の曖昧さが、コンパイラのロジック内で混乱や潜在的なバグの原因となる可能性がありました。例えば、型変換の処理や、メモリ管理（ガベージコレクション）に関連するポインタの追跡などにおいて、Goのポインタ型と、内部的にポインタとして扱われるがGoのポインタ型ではない型（マップ、チャネル、関数、`unsafe.Pointer`）とを区別する必要がある場面が存在します。

この問題を解決するため、既存の`Type.IsPtr()`を`Type.IsPtrShaped()`にリネームし、その広範な意味（内部表現がポインタ形状であること）を継承させました。そして、新たに`Type.IsPtr()`メソッドを導入し、こちらはGo言語の仕様上の厳密なポインタ型のみを判定するように定義し直されました。これにより、コンパイラのコードベース全体で型のポインタ性をより正確に、意図通りに判定できるようになりました。

この変更は、Go issue #15028 に関連しています。このissueでは、`Type.IsPtr`の定義が曖昧であること、特に`unsafe.Pointer`を含むかどうかが明確でない点が指摘されており、このコミットはその解決策として提案されました。

## 前提知識の解説

### Goの型システムにおけるポインタと関連型

Go言語には、以下のようなポインタに関連する型が存在します。

1.  **Goのポインタ型 (`*T`)**: 特定の型の値へのメモリアドレスを指す型です。例: `*int`, `*string`。これらはGoの型システムにおいて明確なポインタとして扱われます。
2.  **`unsafe.Pointer`**: 任意の型へのポインタを保持できる特殊なポインタ型です。型安全性をバイパスするために使用され、C言語の`void*`に似ています。Goの型システムからは「ポインタ」として扱われますが、通常のGoポインタ型とは異なる特性を持ちます。
3.  **マップ (`map[K]V`)**: キーと値のペアを格納するハッシュテーブルです。内部的にはポインタによって実装されており、マップ変数はマップヘッダへのポインタを保持します。
4.  **チャネル (`chan T`)**: ゴルーチン間の通信に使用されるデータ構造です。内部的にはポインタによって実装されており、チャネル変数はチャネルヘッダへのポインタを保持します。
5.  **関数型 (`func(...) (...)`)**: 関数のシグネチャを表す型です。関数値は、その関数のコードエントリポイントへのポインタと、クロージャの場合は環境ポインタを保持します。

これらの型は、Goのソースコード上では異なるキーワードで宣言されますが、コンパイラの内部、特にメモリ上での表現においては、単一の機械語ポインタとして扱われることが多いという共通点があります。

### Goコンパイラの内部表現とSSA

Goコンパイラは、ソースコードを機械語に変換する過程で、様々な中間表現（IR）を使用します。その一つが**SSA (Static Single Assignment)** 形式です。SSAは、各変数が一度だけ代入されるようにプログラムを変換する形式で、最適化の効率を高めます。

コンパイラのバックエンド、特にSSA生成フェーズでは、Goの型をコンパイラ内部の`Type`構造体で表現し、その特性（ポインタであるか、整数であるかなど）を判定するメソッドを頻繁に利用します。`Type.IsPtr()`のようなメソッドは、SSAのオペレーション（例: 型変換、ゼロ値の生成、ストア操作）を決定する上で重要な役割を果たします。

このコミットは、`src/cmd/compile/internal/gc/type.go`で定義される`Type`構造体とそのメソッド、そして`src/cmd/compile/internal/gc/ssa.go`や`src/cmd/compile/internal/ssa/`配下のSSA関連コードに影響を与えています。

## 技術的詳細

このコミットの核心は、`Type`構造体におけるポインタ性の判定ロジックの厳密化です。

### 既存の`Type.IsPtr()`の問題点

コミット前の`Type.IsPtr()`は、以下のいずれかの条件を満たす場合に`true`を返していました。

*   `TPTR32` または `TPTR64` (通常のGoポインタ型)
*   `TUNSAFEPTR` (`unsafe.Pointer`)
*   `TMAP` (マップ型)
*   `TCHAN` (チャネル型)
*   `TFUNC` (関数型)

つまり、このメソッドは「Goのポインタ型であるか」ではなく、「コンパイラの内部で単一の機械語ポインタとして表現される型であるか」を判定していました。この広範な定義が、Goのポインタ型のみを期待するコンパイラ内部のロジックと衝突し、混乱を招いていました。

### `Type.IsPtrShaped()`の導入と`Type.IsPtr()`の再定義

このコミットでは、この問題を解決するために以下の変更が行われました。

1.  **`Type.IsPtr()`のリネームと再定義**:
    *   既存の`Type.IsPtr()`メソッドは`Type.IsPtrShaped()`にリネームされました。この新しいメソッドは、以前の`IsPtr()`と同じロジック（`TPTR32`, `TPTR64`, `TUNSAFEPTR`, `TMAP`, `TCHAN`, `TFUNC`のいずれか）で、内部的にポインタ形状である型を判定します。
    *   新たに`Type.IsPtr()`メソッドが定義されました。この新しい`IsPtr()`は、Goのポインタ型 (`TPTR32` または `TPTR64`) のみを厳密に判定するように変更されました。`unsafe.Pointer`、マップ、チャネル、関数型は含まれません。

2.  **呼び出し元の更新**:
    *   `src/cmd/compile/internal/gc/ssa.go`内のSSA生成ロジックにおいて、型のポインタ性を判定している箇所が多数存在しました。これらの箇所では、Goのポインタ型であるかどうかが重要ではなく、内部表現がポインタ形状であるかどうかが重要であったため、`t.IsPtr()`の呼び出しが`t.IsPtrShaped()`に更新されました。
    *   同様に、`src/cmd/compile/internal/ssa/rewrite.go`、`src/cmd/compile/internal/ssa/type.go`、`src/cmd/compile/internal/ssa/type_test.go`内の関連するメソッドやテストも、新しい`IsPtrShaped()`を使用するように変更されました。

この変更により、コンパイラの開発者は、Goのポインタ型を厳密に扱いたい場合は`IsPtr()`を、内部的にポインタ形状の型を扱いたい場合は`IsPtrShaped()`を使用することで、意図を明確にしたコードを書けるようになりました。これは、コンパイラの正確性と保守性を向上させる上で重要な改善です。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/type.go` の変更

```go
// IsPtr reports whether t is a regular Go pointer type.
// This does not include unsafe.Pointer.
func (t *Type) IsPtr() bool {
	return t.Etype == TPTR32 || t.Etype == TPTR64
}

// IsPtrShaped reports whether t is represented by a single machine pointer.
// In addition to regular Go pointer types, this includes map, channel, and
// function types and unsafe.Pointer. It does not include array or struct types
// that consist of a single pointer shaped type.
// TODO(mdempsky): Should it? See golang.org/issue/15028.
func (t *Type) IsPtrShaped() bool {
	return t.Etype == TPTR32 || t.Etype == TPTR64 || t.Etype == TUNSAFEPTR ||
		t.Etype == TMAP || t.Etype == TCHAN || t.Etype == TFUNC
}
```

このスニペットは、型判定ロジックの明確化を最もよく示しています。

*   **`IsPtr()`**: 新しい`IsPtr()`は、`t.Etype`（型の基本要素型）が`TPTR32`（32ビットポインタ）または`TPTR64`（64ビットポインタ）である場合にのみ`true`を返します。これは、Go言語の仕様で定義される純粋なポインタ型（例: `*int`）を正確に識別します。`unsafe.Pointer`は含まれません。
*   **`IsPtrShaped()`**: このメソッドは、`t.Etype`が`TPTR32`, `TPTR64`, `TUNSAFEPTR`, `TMAP`, `TCHAN`, `TFUNC`のいずれかである場合に`true`を返します。これは、Goのポインタ型に加えて、`unsafe.Pointer`、マップ、チャネル、関数といった、コンパイラの内部で単一の機械語ポインタとして扱われる型を識別します。コメントにある`TODO`は、配列や構造体の中にポインタ形状の型が含まれる場合を`IsPtrShaped`に含めるべきかという将来的な検討事項を示唆しており、issue #15028で議論された内容の一部です。

### `src/cmd/compile/internal/gc/ssa.go` の変更例

```diff
--- a/src/cmd/compile/internal/gc/ssa.go
+++ b/src/cmd/compile/internal/gc/ssa.go
@@ -1512,14 +1512,14 @@ func (s *state) expr(n *Node) *ssa.Value {
 		// We don't want pointers accidentally classified
 		// as not-pointers or vice-versa because of copy
 		// elision.
-		if to.IsPtr() != from.IsPtr() {
+		if to.IsPtrShaped() != from.IsPtrShaped() {
 			return s.newValue2(ssa.OpConvert, to, x, s.mem())
 		}

 		v := s.newValue1(ssa.OpCopy, to, x) // ensure that v has the right type

 		// CONVNOP closure
-		if to.Etype == TFUNC && from.IsPtr() {
+		if to.Etype == TFUNC && from.IsPtrShaped() {

```

この差分は、`ssa.go`内の型変換ロジックの一部を示しています。`to.IsPtr() != from.IsPtr()`という条件が`to.IsPtrShaped() != from.IsPtrShaped()`に変更されています。これは、型変換の際に、Goのポインタ型であるかどうかではなく、コンパイラ内部でのメモリ表現がポインタ形状であるかどうかが重要であることを示しています。例えば、`map`型から`interface{}`型への変換など、Goのポインタ型ではないが内部的にポインタとして扱われる型間の変換を正しく処理するために、より広範な`IsPtrShaped()`のセマンティクスが必要とされたと考えられます。

同様に、`zeroVal`関数（型のゼロ値を生成する）や`storeTypeScalars`、`storeTypePtrs`、`storeTypePtrsWB`関数（メモリへのストア操作を行う）などでも、`IsPtr()`の呼び出しが`IsPtrShaped()`に置き換えられています。これらの操作では、Goのポインタ型であるか否かよりも、その型がメモリ上でポインタとして扱われるかどうかが、処理の分岐や最適化の判断においてより適切であるためです。
