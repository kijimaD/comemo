## 変更の背景

このコミットは、Go言語の初期段階で発見されたコンパイラのバグを修正するものです。具体的には、Go言語の重要な特徴である「多値返却（multiple return values）」を持つ関数を呼び出した結果を、単一の変数に「短い変数宣言（short variable declaration）`:=`」を使って代入しようとした際に、コンパイラが適切なエラーを報告せず、不正なコードを許してしまうという問題がありました。

Go言語では、`x, y := f()`のように、多値返却関数の結果を複数の変数に同時に代入するのが一般的です。しかし、このバグが存在するバージョンでは、`x := f()`のように、多値返却関数の結果を単一の変数に代入しようとすると、コンパイラがこれを誤って処理し、予期せぬ動作や後続のコンパイルエラーを引き起こす可能性がありました。このコミットは、このような不正な代入パターンをコンパイル時に検出し、明確なエラーメッセージを出すようにコンパイラの挙動を修正することを目的としています。

## 前提知識の解説

### Go言語の多値返却 (Multiple Return Values in Go)

Go言語の関数は、複数の値を返すことができます。これはエラーハンドリングや、関連する複数の結果を一度に返す際に非常に便利です。例えば、`func f() (int, bool)` のように定義された関数は、整数とブール値の2つの値を返します。これらの値は通常、`a, b := f()` のように複数の変数で受け取られます。

### `:=` 演算子 (Short Variable Declaration Operator `:=`)

`:=` はGo言語における短い変数宣言演算子です。これは、変数の宣言と初期化を同時に行うための簡潔な方法であり、型推論を利用します。例えば、`x := 10` は `var x int = 10` と同等です。この演算子は、新しい変数を宣言する際にのみ使用でき、既に宣言されている変数には使用できません（その場合は `=` を使用します）。

### Goコンパイラの構造 (Go Compiler Structure - `gc`, `subr.c`, `walk.c`)

Go言語の公式コンパイラは、歴史的に`gc`（Go Compiler）と呼ばれています。`gc`は、Goのソースコードを機械語に変換するプロセスを担います。このプロセスは複数のフェーズに分かれており、字句解析、構文解析、型チェック、中間コード生成、最適化、コード生成などが含まれます。

*   **`src/cmd/gc/subr.c`**: このファイルは、コンパイラのサブルーチンやユーティリティ関数を多く含んでいます。特に、型の文字列表現（`Tpretty`関数など）や、コンパイラ内部で使用される補助的な処理が定義されています。
*   **`src/cmd/gc/walk.c`**: このファイルは、抽象構文木（AST）を走査（walk）し、型チェックや中間コードへの変換などのセマンティックな処理を行う主要な部分です。`:=`演算子のような言語構造の処理もここで行われます。

### `funarg` フラグ (The `funarg` flag in Go's type system)

Goコンパイラの内部では、型システムが様々な情報を管理しています。`funarg`は、関数の引数または戻り値の型を表す際に使用される可能性のある内部的なフラグまたは属性です。多値返却の文脈では、複数の戻り値をまとめて一つの「型」として扱う際に、その型が関数の引数/戻り値の集合であることを示すためにこのフラグが使われることがあります。このコミットでは、`TSTRUCT`型（構造体型）が`funarg`フラグを持つ場合に、それが関数の戻り値のタプルであることを示唆していると解釈できます。

## 技術的詳細

このバグは、Goコンパイラの型チェックロジックの不備に起因していました。`:=`演算子による短い変数宣言は、右辺の式の型に基づいて左辺の変数の型を推論し、宣言と初期化を行います。多値返却関数が右辺にある場合、通常は複数の変数が左辺に必要です。

バグの発生状況は以下の通りです。

1.  `f()`という多値返却関数（例: `func f() (int, bool)`）が存在する。
2.  `x := f()`のように、単一の変数`x`に対して`f()`の呼び出し結果を`:=`で代入しようとする。
3.  コンパイラは、`f()`が多値を返すことを認識しているにもかかわらず、`:=`の処理において、その多値が単一の変数に代入されるという不正な状況を適切に検出できていなかった。
4.  結果として、コンパイラは`x`の型を`f()`の最初の戻り値の型（この例では`int`）と誤って推論したり、あるいは内部的に不正な型情報で処理を進めたりしてしまい、後続のコンパイルフェーズでエラーが発生するか、あるいはさらに悪いことに、不正なコードが生成される可能性がありました。

このコミットでは、`walk.c`内の`old2new`関数が`:=`演算子の処理を担当しており、ここで右辺の式の型が多値返却（`funarg`フラグを持つ`TSTRUCT`型）であるにもかかわらず、左辺が単一の変数である場合にエラーを発生させるように修正されました。また、`subr.c`の`Tpretty`関数は、コンパイラのデバッグ出力などで型を整形する際に、`funarg`フラグを持つ`TSTRUCT`型を`(type1, type2)`のような形式で表示するように改善され、コンパイラ内部での型の表現がより正確になりました。

### `src/cmd/gc/subr.c` の変更

`Tpretty`関数は、Goコンパイラが内部的な型情報を人間が読める形式の文字列に変換する際に使用されます。この変更は、`TSTRUCT`（構造体）型が`funarg`フラグを持っている場合に、その表示方法を特別に扱うようにしています。

*   `if(t->funarg)`: 型`t`が`funarg`フラグを持っているかどうかをチェックします。`funarg`フラグは、この`TSTRUCT`型が関数の引数または戻り値のタプルを表すことを示唆しています。
*   `fmtprint(fp, "("); ... fmtprint(fp, ")");`: `funarg`フラグがセットされている場合、型を`(type1, type2, ...)`のような形式で括弧で囲んで表示するようにします。これは、多値返却のシグネチャをより明確に表現するためです。
*   `for(t1=t->type; t1!=T; t1=t1->down)`: タプル内の個々の型をループで処理し、それぞれを`%T`フォーマット指定子を使って再帰的に`Tpretty`で表示します。
*   `if(t1->down) fmtprint(fp, ", ");`: 複数の型がある場合に、カンマとスペースで区切ります。

この変更自体はバグ修正の直接的なロジックではありませんが、コンパイラ内部での型の表現を改善し、デバッグやエラーメッセージの生成において多値返却の型がより正確に表示されるようにすることで、間接的にバグの理解や診断に役立ちます。

### `src/cmd/gc/walk.c` の変更

`old2new`関数は、`:=`演算子を含む短い変数宣言を処理するGoコンパイラの重要な部分です。この関数は、新しい変数を宣言し、右辺の式からその型を推論します。

*   `if(t != T && t->funarg)`: ここがバグ修正の核心です。
    *   `t != T`: 右辺の式に型`t`が存在することを確認します（`T`はGoコンパイラ内部で「型なし」または「無効な型」を示す定数）。
    *   `t->funarg`: 右辺の式の型`t`が`funarg`フラグを持っているかどうかをチェックします。前述の通り、これは多値返却関数の結果のタプル型であることを示します。
*   `yyerror("use of multi func value as single value in :=");`: もし右辺が多値返却の型であるにもかかわらず、`old2new`が単一の変数への代入として処理しようとしている場合（つまり、左辺が単一の変数である場合）、このエラーメッセージを出力します。これは、多値返却を単一の変数に代入しようとする不正なコードをコンパイル時に検出するためのものです。
*   `return n;`: エラーが検出された場合、それ以上の処理を行わずに`n`（元のノード）を返し、コンパイルエラーとして処理を中断します。

この変更により、コンパイラは`x := f()`のような不正なコードを早期に検出し、開発者に明確なエラーメッセージを提示できるようになりました。

## 変更の背景

このコミットは、Go言語の初期段階で発見されたコンパイラのバグを修正するものです。具体的には、Go言語の重要な特徴である「多値返却（multiple return values）」を持つ関数を呼び出した結果を、単一の変数に「短い変数宣言（short variable declaration）`:=`」を使って代入しようとした際に、コンパイラが適切なエラーを報告せず、不正なコードを許してしまうという問題がありました。

Go言語では、`x, y := f()`のように、多値返却関数の結果を複数の変数に同時に代入するのが一般的です。しかし、このバグが存在するバージョンでは、`x := f()`のように、多値返却関数の結果を単一の変数に代入しようとすると、コンパイラがこれを誤って処理し、予期せぬ動作や後続のコンパイルエラーを引き起こす可能性がありました。このコミットは、このような不正な代入パターンをコンパイル時に検出し、明確なエラーメッセージを出すようにコンパイラの挙動を修正することを目的としています。

## 前提知識の解説

### Go言語の多値返却 (Multiple Return Values in Go)

Go言語の関数は、複数の値を返すことができます。これはエラーハンドリングや、関連する複数の結果を一度に返す際に非常に便利です。例えば、`func f() (int, bool)` のように定義された関数は、整数とブール値の2つの値を返します。これらの値は通常、`a, b := f()` のように複数の変数で受け取られます。

### `:=` 演算子 (Short Variable Declaration Operator `:=`)

`:=` はGo言語における短い変数宣言演算子です。これは、変数の宣言と初期化を同時に行うための簡潔な方法であり、型推論を利用します。例えば、`x := 10` は `var x int = 10` と同等です。この演算子は、新しい変数を宣言する際にのみ使用でき、既に宣言されている変数には使用できません（その場合は `=` を使用します）。

### Goコンパイラの構造 (Go Compiler Structure - `gc`, `subr.c`, `walk.c`)

Go言語の公式コンパイラは、歴史的に`gc`（Go Compiler）と呼ばれています。`gc`は、Goのソースコードを機械語に変換するプロセスを担います。このプロセスは複数のフェーズに分かれており、字句解析、構文解析、型チェック、中間コード生成、最適化、コード生成などが含まれます。

*   **`src/cmd/gc/subr.c`**: このファイルは、コンパイラのサブルーチンやユーティリティ関数を多く含んでいます。特に、型の文字列表現（`Tpretty`関数など）や、コンパイラ内部で使用される補助的な処理が定義されています。
*   **`src/cmd/gc/walk.c`**: このファイルは、抽象構文木（AST）を走査（walk）し、型チェックや中間コードへの変換などのセマンティックな処理を行う主要な部分です。`:=`演算子のような言語構造の処理もここで行われます。

### `funarg` フラグ (The `funarg` flag in Go's type system)

Goコンパイラの内部では、型システムが様々な情報を管理しています。`funarg`は、関数の引数または戻り値の型を表す際に使用される可能性のある内部的なフラグまたは属性です。多値返却の文脈では、複数の戻り値をまとめて一つの「型」として扱う際に、その型が関数の引数/戻り値の集合であることを示すためにこのフラグが使われることがあります。このコミットでは、`TSTRUCT`型（構造体型）が`funarg`フラグを持つ場合に、それが関数の戻り値のタプルであることを示唆していると解釈できます。

## 技術的詳細

このバグは、Goコンパイラの型チェックロジックの不備に起因していました。`:=`演算子による短い変数宣言は、右辺の式の型に基づいて左辺の変数の型を推論し、宣言と初期化を行います。多値返却関数が右辺にある場合、通常は複数の変数が左辺に必要です。

バグの発生状況は以下の通りです。

1.  `f()`という多値返却関数（例: `func f() (int, bool)`）が存在する。
2.  `x := f()`のように、単一の変数`x`に対して`f()`の呼び出し結果を`:=`で代入しようとする。
3.  コンパイラは、`f()`が多値を返すことを認識しているにもかかわらず、`:=`の処理において、その多値が単一の変数に代入されるという不正な状況を適切に検出できていなかった。
4.  結果として、コンパイラは`x`の型を`f()`の最初の戻り値の型（この例では`int`）と誤って推論したり、あるいは内部的に不正な型情報で処理を進めたりしてしまい、後続のコンパイルフェーズでエラーが発生するか、あるいはさらに悪いことに、不正なコードが生成される可能性がありました。

このコミットでは、`walk.c`内の`old2new`関数が`:=`演算子の処理を担当しており、ここで右辺の式の型が多値返却（`funarg`フラグを持つ`TSTRUCT`型）であるにもかかわらず、左辺が単一の変数である場合にエラーを発生させるように修正されました。また、`subr.c`の`Tpretty`関数は、コンパイラのデバッグ出力などで型を整形する際に、`funarg`フラグを持つ`TSTRUCT`型を`(type1, type2)`のような形式で表示するように改善され、コンパイラ内部での型の表現がより正確になりました。

## コアとなるコードの解説

### `src/cmd/gc/subr.c` の変更

`Tpretty`関数は、Goコンパイラが内部的な型情報を人間が読める形式の文字列に変換する際に使用されます。この変更は、`TSTRUCT`（構造体）型が`funarg`フラグを持っている場合に、その表示方法を特別に扱うようにしています。

*   `if(t->funarg)`: 型`t`が`funarg`フラグを持っているかどうかをチェックします。`funarg`フラグは、この`TSTRUCT`型が関数の引数または戻り値のタプルを表すことを示唆しています。
*   `fmtprint(fp, "("); ... fmtprint(fp, ")");`: `funarg`フラグがセットされている場合、型を`(type1, type2, ...)`のような形式で括弧で囲んで表示するようにします。これは、多値返却のシグネチャをより明確に表現するためです。
*   `for(t1=t->type; t1!=T; t1=t1->down)`: タプル内の個々の型をループで処理し、それぞれを`%T`フォーマット指定子を使って再帰的に`Tpretty`で表示します。
*   `if(t1->down) fmtprint(fp, ", ");`: 複数の型がある場合に、カンマとスペースで区切ります。

この変更自体はバグ修正の直接的なロジックではありませんが、コンパイラ内部での型の表現を改善し、デバッグやエラーメッセージの生成において多値返却の型がより正確に表示されるようにすることで、間接的にバグの理解や診断に役立ちます。

### `src/cmd/gc/walk.c` の変更

`old2new`関数は、`:=`演算子を含む短い変数宣言を処理するGoコンパイラの重要な部分です。この関数は、新しい変数を宣言し、右辺の式からその型を推論します。

*   `if(t != T && t->funarg)`: ここがバグ修正の核心です。
    *   `t != T`: 右辺の式に型`t`が存在することを確認します（`T`はGoコンパイラ内部で「型なし」または「無効な型」を示す定数）。
    *   `t->funarg`: 右辺の式の型`t`が`funarg`フラグを持っているかどうかをチェックします。前述の通り、これは多値返却関数の結果のタプル型であることを示します。
*   `yyerror("use of multi func value as single value in :=");`: もし右辺が多値返却の型であるにもかかわらず、`old2new`が単一の変数への代入として処理しようとしている場合（つまり、左辺が単一の変数である場合）、このエラーメッセージを出力します。これは、多値返却を単一の変数に代入しようとする不正なコードをコンパイル時に検出するためのものです。
*   `return n;`: エラーが検出された場合、それ以上の処理を行わずに`n`（元のノード）を返し、コンパイルエラーとして処理を中断します。

この変更により、コンパイラは`x := f()`のような不正なコードを早期に検出し、開発者に明確なエラーメッセージを提示できるようになりました。

### `test/fixedbugs/bug175.go` の追加

このファイルは、上記のバグを再現し、修正が正しく機能することを確認するためのテストケースです。

*   `// errchk $G $D/$F.go`: この行は、Goのテストフレームワークに対して、このファイルがコンパイルエラーを発生させることを期待していることを示します。`$G`はGoコンパイラ、`$D/$F.go`は現在のテストファイルのパスを指します。
*   `func f() (int, bool) { return 0, true }`: `int`と`bool`の2つの値を返す多値返却関数`f`を定義します。
*   `x, y := f(), 2; // ERROR "multi"`: `main`関数内で、`f()`の呼び出し結果とリテラル`2`を、`x`と`y`という2つの変数に代入しようとしています。しかし、`f()`は2つの値を返すため、`f()`の結果を単一の変数`x`に代入しようとすることはGoの文法上不正です。この行のコメント`// ERROR "multi"`は、コンパイラが「multi」という文字列を含むエラーメッセージを出すことを期待していることを示しています。

このテストケースは、修正が適用されたコンパイラが、多値返却関数を単一の変数に代入しようとした際に、期待通りにエラーを報告することを確認します。
