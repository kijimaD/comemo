# [インデックス 20751] ファイルの概要

このコミットは、Go言語の標準ライブラリである`strings`パッケージ内の`IndexRune`関数のパフォーマンス改善を目的としています。具体的には、検索対象のルーン（Unicodeコードポイント）がASCII文字である場合に、より高速な`IndexByte`関数を利用する「高速パス」を導入することで、文字列検索の効率を向上させています。

## 元コミット内容

このコミットの元の内容は、`strings.IndexRune`関数が、他の`strings`/`bytes`パッケージ内の高速パス（特にアセンブリ最適化された`IndexByte`）を利用していないという問題提起と、その改善提案です。コミットメッセージは、`IndexRune`がこれまであまり使われていなかったため、その最適化が見過ごされていた可能性を示唆しています。

## 変更の背景

この変更の背景には、Go言語の標準ライブラリにおけるパフォーマンス最適化の継続的な取り組みがあります。`strings.IndexRune`関数は、文字列`s`内で特定のルーン`r`が最初に出現するインデックスを返しますが、以前の実装では、ルーンがASCII文字（1バイトで表現できる文字）であっても、汎用的なルーン検索ロジックを使用していました。

一方、`strings.IndexByte`関数は、文字列内で特定のバイトが最初に出現するインデックスを検索するもので、Goのランタイムにおいてアセンブリ言語レベルで高度に最適化されています。これには、SIMD（Single Instruction, Multiple Data）命令（例: AVX2, SSE）が利用され、特に長い文字列に対して非常に高速な検索が可能です。

コミットの作者は、コードレビュー中に`IndexRune`がこの既存の高速な`IndexByte`の恩恵を受けていないことに気づきました。ASCII文字の検索は非常に頻繁に行われる操作であるため、このケースで`IndexByte`の高速パスを利用しないことは、不必要なパフォーマンスオーバーヘッドを生み出していました。この変更は、一般的なASCII文字の検索において`IndexRune`のパフォーマンスを向上させ、同時にコード量を削減することを目的としています。

## 前提知識の解説

*   **Go言語の文字列 (string)**: Go言語の文字列は、読み取り専用のバイトスライスであり、UTF-8エンコードされたUnicodeテキストを保持することを意図しています。文字列内の個々の文字は「ルーン (rune)」と呼ばれ、これはUnicodeコードポイントに対応します。UTF-8エンコーディングでは、ASCII文字は1バイトで表現されますが、非ASCII文字は2バイト以上で表現されます。
*   **ルーン (rune)**: Go言語における`rune`型は、`int32`のエイリアスであり、Unicodeコードポイントを表します。
*   **`strings.IndexRune`**: `func IndexRune(s string, r rune) int` は、文字列`s`内でルーン`r`が最初に出現するインデックス（バイトオフセット）を返します。見つからない場合は-1を返します。
*   **`strings.IndexByte`**: `func IndexByte(s string, c byte) int` は、文字列`s`内でバイト`c`が最初に出現するインデックスを返します。見つからない場合は-1を返します。この関数は、Goのランタイムでアセンブリ言語を用いて高度に最適化されています。
*   **`utf8.RuneSelf`**: `unicode/utf8`パッケージで定義されている定数で、値は`0x80`（128）です。UTF-8エンコーディングにおいて、`utf8.RuneSelf`未満のルーン値はすべて1バイトのASCII文字として表現されます。これ以上のルーン値は、複数バイトで表現される非ASCII文字です。この定数は、ルーンがASCII文字であるか否かを効率的に判別するために使用されます。
*   **アセンブリ最適化**: 特定のCPU命令（例: SIMD命令）を直接利用することで、高レベル言語では実現が難しいレベルのパフォーマンスを引き出す最適化手法です。Goの標準ライブラリでは、I/O処理や文字列操作など、パフォーマンスがクリティカルな部分でアセンブリ最適化が適用されることがあります。

## 技術的詳細

このコミットの技術的な核心は、`strings.IndexRune`関数における条件分岐の変更です。

変更前は、`IndexRune`は検索対象のルーン`r`が`0x80`未満（つまりASCII文字）である場合に、手動でバイト単位のループを実行していました。

```go
// 変更前
func IndexRune(s string, r rune) int {
	switch {
	case r < 0x80: // ASCII文字の場合
		b := byte(r)
		for i := 0; i < len(s); i++ {
			if s[i] == b {
				return i
			}
		}
	default: // 非ASCII文字の場合
		for i, c := range s {
			if c == r {
				return i
			}
		}
	}
	return -1
}
```

この手動ループは、`strings.IndexByte`が提供するアセンブリレベルの最適化を利用していませんでした。

変更後は、`r < utf8.RuneSelf`という条件（`utf8.RuneSelf`は`0x80`と同じ値）で、直接`strings.IndexByte(s, byte(r))`を呼び出すように修正されました。

```go
// 変更後
func IndexRune(s string, r rune) int {
	switch {
	case r < utf8.RuneSelf: // ASCII文字の場合
		return IndexByte(s, byte(r)) // IndexByteの高速パスを利用
	default: // 非ASCII文字の場合
		for i, c := range s {
			if c == r {
				return i
			}
		}
	}
	return -1
}
```

この変更により、`IndexRune`がASCII文字を検索する際には、Goランタイムが提供する最も効率的なバイト検索ルーチン（アセンブリ最適化された`IndexByte`）が利用されるようになります。これにより、特に大量のASCII文字列処理において、`IndexRune`のパフォーマンスが大幅に向上します。

非ASCII文字（`r >= utf8.RuneSelf`）の場合のロジックは変更されていません。これは、複数バイトで構成されるルーンの検索には、UTF-8デコードを伴うより複雑な処理が必要であり、単純なバイト検索では対応できないためです。

## コアとなるコードの解説

変更された`IndexRune`関数のコア部分は以下の通りです。

```go
func IndexRune(s string, r rune) int {
	switch {
	case r < utf8.RuneSelf: // 検索対象のルーンがASCII文字の場合
		// utf8.RuneSelf (0x80) 未満のルーンは、UTF-8において1バイトのASCII文字として表現される。
		// この場合、ルーンはそのままバイト値として扱えるため、
		// 高度に最適化されたstrings.IndexByte関数に処理を委譲する。
		// IndexByteはアセンブリ言語で実装されており、非常に高速なバイト検索を提供する。
		return IndexByte(s, byte(r))
	default: // 検索対象のルーンが非ASCII文字（複数バイト文字）の場合
		// このケースでは、ルーンは複数バイトで構成されるため、
		// 文字列sをルーン単位でイテレートし、各ルーンをデコードしながら比較する必要がある。
		// range s は文字列をUTF-8デコードしながらルーンとインデックスを返すため、
		// このループが適切である。
		for i, c := range s {
			if c == r {
				return i
			}
		}
	}
	return -1 // ルーンが見つからなかった場合
}
```

この変更により、`IndexRune`は、検索対象がASCII文字であるという一般的なケースにおいて、Goランタイムの最も効率的なバイト検索メカニズムを透過的に利用できるようになりました。これにより、コードの簡潔性が向上し、同時にパフォーマンスも改善されています。
