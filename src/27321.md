## 変更の背景

このコミットの背景には、Go言語がより多様なハードウェアアーキテクチャをサポートするという継続的な取り組みがあります。IBM System z (s390x) は、メインフレームコンピューティングで使用される64ビットの命令セットアーキテクチャであり、エンタープライズレベルのワークロードに特化しています。Go言語がこのアーキテクチャ上で効率的に動作するためには、ランタイムがs390x固有の特性（エンディアン、キャッシュラインサイズ、ページサイズなど）を認識し、それに応じて動作を調整する必要があります。

このコミットは、Goランタイムの`runtime/internal/sys`パッケージにs390xアーキテクチャのサポートを追加することで、Goプログラムがs390xシステム上でネイティブにコンパイルおよび実行できるようにするための基盤を構築します。これにより、Goはメインフレーム環境での利用範囲を拡大し、より多くの開発者や企業がGoの恩恵を受けられるようになります。

## 前提知識の解説

### 1. s390xアーキテクチャ

s390xは、IBMが開発したメインフレームコンピュータ向けの64ビット命令セットアーキテクチャです。これは、System/360、System/370、ESA/390といったIBMのメインフレームの歴史的進化の最新版にあたります。s390xは、高い信頼性、可用性、保守性（RAS特性）を特徴とし、大規模なトランザクション処理、データベース、仮想化環境などで広く利用されています。

主な特徴としては、以下の点が挙げられます。
*   **ビッグエンディアン**: データをメモリに格納する際のバイト順序がビッグエンディアンです。これは、最上位バイトが最も低いメモリアドレスに格納される方式です。
*   **固定長命令**: 多くの命令が固定長であり、命令デコードを簡素化します。
*   **豊富なレジスタセット**: 汎用レジスタ、浮動小数点レジスタ、制御レジスタなど、多様なレジスタを備えています。
*   **ハードウェアによる仮想化支援**: 複数のオペレーティングシステムを効率的に実行するための強力な仮想化機能がハードウェアレベルで提供されます。

### 2. Goランタイムとアーキテクチャサポート

Go言語は、クロスプラットフォーム開発を強力にサポートしており、異なるCPUアーキテクチャやオペレーティングシステム向けにプログラムをコンパイルできます。Goのランタイムは、ガベージコレクション、スケジューラ、メモリ管理など、Goプログラムの実行に必要な低レベルの機能を提供します。

Goランタイムが特定のアーキテクチャをサポートするためには、そのアーキテクチャ固有の特性を理解し、それに対応するコードを提供する必要があります。これには、以下のような情報が含まれます。
*   **エンディアン**: バイト順序（ビッグエンディアンかリトルエンディアンか）。
*   **ポインタサイズ**: アドレス空間のサイズ（32ビットか64ビットか）。
*   **ページサイズ**: オペレーティングシステムがメモリを管理する最小単位。
*   **キャッシュラインサイズ**: CPUキャッシュの最小転送単位。
*   **レジスタの幅**: CPUレジスタのビット幅。
*   **システムコール規約**: OSとのやり取りの方法。

### 3. `runtime/internal/sys`パッケージ

`runtime/internal/sys`パッケージは、Goランタイムの内部で使用される、システムおよびアーキテクチャ固有の定数や型を定義する役割を担っています。このパッケージは、Goの標準ライブラリの一部ではなく、Goランタイム自体が異なるアーキテクチャやOS上で正しく動作するために必要な低レベルの詳細を抽象化するために存在します。

このパッケージ内のファイルは、通常、`arch_GOARCH.go`（アーキテクチャ固有の定数や型）と`zgoarch_GOARCH.go`（`go generate`によって生成されるアーキテクチャ識別子）のような命名規則に従います。

### 4. `GOARCH`と`GOOS`

Goのビルドシステムでは、環境変数`GOARCH`と`GOOS`を使用して、ターゲットとするアーキテクチャとオペレーティングシステムを指定します。
*   `GOARCH`: ターゲットCPUアーキテクチャ（例: `amd64`, `arm`, `s390x`）。
*   `GOOS`: ターゲットオペレーティングシステム（例: `linux`, `windows`, `darwin`）。

これらの変数を設定することで、Goコンパイラは指定されたターゲット環境に最適化されたバイナリを生成します。

## 技術的詳細

このコミットでは、s390xアーキテクチャをGoランタイムに統合するために、以下の2つのファイルが追加されています。

### 1. `src/runtime/internal/sys/arch_s390x.go`

このファイルは、s390xアーキテクチャに固有の低レベルの定数を定義しています。これらの定数は、Goランタイムがメモリ管理、スタックフレームのレイアウト、ガベージコレクション、スケジューリングなどの内部動作をs390x上で正しく実行するために不可欠です。

*   **`TheChar = 'z'`**:
    この定数は、Goの内部でアーキテクチャを識別するための単一文字のコードです。s390xの場合、慣例的に'z'が割り当てられています。これは、Goのツールチェーンがファイル名や内部構造でアーキテクチャを区別するために使用されることがあります。
*   **`BigEndian = 1`**:
    s390xアーキテクチャがビッグエンディアンであることを示します。Goランタイムは、この情報を使用して、マルチバイトデータの読み書きやネットワークバイトオーダーの処理を適切に行います。`1`はビッグエンディアン、`0`はリトルエンディアンを意味します。
*   **`CacheLineSize = 256`**:
    CPUのキャッシュラインのサイズをバイト単位で定義します。s390xプロセッサのキャッシュラインサイズは256バイトであることが一般的です。この情報は、メモリのアライメントやデータ構造のパディングを最適化し、キャッシュミスを減らすことでパフォーマンスを向上させるためにGoランタイムによって利用されます。
*   **`PhysPageSize = 4096`**:
    物理メモリのページサイズをバイト単位で定義します。これは、オペレーティングシステムがメモリを管理する最小単位であり、通常は4KB（4096バイト）です。Goランタイムは、この情報に基づいてメモリのアロケーションや仮想メモリのマッピングを行います。
*   **`PCQuantum = 2`**:
    プログラムカウンタ（PC）の量子サイズをバイト単位で定義します。これは、命令のアドレスが常にこの値の倍数であることを示します。s390xでは、命令は2バイト境界にアラインされることが多いため、`2`が設定されています。Goのスタックトレースやプロファイリングにおいて、PCの値を解釈する際にこの情報が使用されます。
*   **`Int64Align = 8`**:
    64ビット整数型（`int64`）がメモリ上でアラインされるべきバイト数を定義します。s390xでは、64ビットデータは8バイト境界にアラインされるのが一般的です。適切なアライメントは、CPUがデータを効率的にアクセスするために重要です。
*   **`HugePageSize = 0`**:
    ヒュージページ（大容量ページ）のサイズをバイト単位で定義します。`0`は、このアーキテクチャではヒュージページがサポートされていないか、Goランタイムがヒュージページを使用しないことを示唆しています。ヒュージページは、TLB（Translation Lookaside Buffer）のミスを減らし、大規模なメモリを扱うアプリケーションのパフォーマンスを向上させるために使用されることがあります。
*   **`MinFrameSize = 8`**:
    関数呼び出しのスタックフレームの最小サイズをバイト単位で定義します。これは、スタックフレームが確保すべき最小限の領域を示し、レジスタの保存や戻りアドレスの格納などに使用されます。s390xのABI（Application Binary Interface）に基づいて設定されます。
*   **`type Uintreg uint64`**:
    `Uintreg`型は、符号なし整数レジスタの幅を表現するために使用されます。s390xは64ビットアーキテクチャであるため、レジスタは64ビット幅であり、`uint64`として定義されています。これは、Goランタイムがレジスタの値を操作する際に、適切なサイズと型を使用することを保証します。

### 2. `src/runtime/internal/sys/zgoarch_s390x.go`

このファイルは、`go generate`コマンドによって自動生成されるファイルであり、Goのビルドシステムが現在のターゲットアーキテクチャを識別するために使用されます。

*   **`// generated by gengoos.go using 'go generate'`**:
    このコメントは、このファイルが手動で編集されるものではなく、`gengoos.go`スクリプトによって自動生成されたものであることを示しています。Goのビルドプロセスでは、`go generate`コマンドが実行され、各アーキテクチャとOSの組み合わせに対応するこのようなファイルが生成されます。
*   **`package sys`**:
    `arch_s390x.go`と同様に、`runtime/internal/sys`パッケージに属します。
*   **`const TheGoarch = `s390x``**:
    現在のターゲットアーキテクチャが`s390x`であることを文字列定数として定義します。これは、Goのビルドツールやランタイムが、コンパイル時または実行時に現在のアーキテクチャをプログラム的に識別するために使用できます。
*   **`const Goarch386 = 0`, `const GoarchAmd64 = 0`, ..., `const GoarchS390x = 1`**:
    これらの定数は、Goがサポートする各アーキテクチャに対して定義されており、現在のビルドターゲットがそのアーキテクチャである場合に`1`、そうでない場合に`0`が設定されます。`GoarchS390x = 1`は、このファイルがs390xアーキテクチャ向けに生成されたものであることを明確に示しています。これにより、条件付きコンパイルやアーキテクチャ固有のコードパスの選択が容易になります。

## コアとなるコードの解説

### `arch_s390x.go`

このファイルは、s390xアーキテクチャの基本的な特性をGoランタイムに伝えるための「設定ファイル」のようなものです。

*   **`TheChar = 'z'`**: Goの内部でs390xを識別するための短いコードです。例えば、アセンブリファイル名が`file_z.s`のようになることがあります。
*   **`BigEndian = 1`**: s390xがビッグエンディアンであることを明示します。これは、メモリ上のバイト順序が最上位バイトから始まることを意味し、Goランタイムがポインタ演算やデータ構造の解釈を行う際にこの情報を使用します。
*   **`CacheLineSize = 256`**: s390xプロセッサのキャッシュラインサイズが256バイトであることを示します。Goランタイムは、この値を利用して、データ構造をキャッシュラインにアラインしたり、偽共有（false sharing）を避けるためのパディングを挿入したりすることで、メモリアクセス性能を最適化します。
*   **`PhysPageSize = 4096`**: s390xシステムにおける物理メモリのページサイズが4KBであることを示します。Goのメモリマネージャは、このページサイズに基づいてヒープ領域を管理し、OSからのメモリ割り当て要求を行います。
*   **`PCQuantum = 2`**: プログラムカウンタ（PC）の最小増分単位が2バイトであることを示します。これは、s390xの命令が通常2バイト境界にアラインされるためです。Goのプロファイラやデバッガは、この情報を使って正確な命令アドレスを特定します。
*   **`Int64Align = 8`**: 64ビット整数が8バイト境界にアラインされるべきであることを示します。これにより、CPUが64ビットデータを効率的に読み書きできるようになります。
*   **`HugePageSize = 0`**: s390xではGoランタイムがヒュージページを使用しないことを示します。ヒュージページは、TLBミスを減らすことで大規模なメモリを扱うアプリケーションのパフォーマンスを向上させることがありますが、この設定では利用されません。
*   **`MinFrameSize = 8`**: 関数呼び出しのスタックフレームの最小サイズが8バイトであることを示します。これは、関数が呼び出されたときにスタック上に確保されるべき最小限の領域であり、戻りアドレスや一部のレジスタを保存するために使用されます。
*   **`type Uintreg uint64`**: `Uintreg`型は、s390xの汎用レジスタが64ビット幅であることを表現するために`uint64`として定義されています。Goランタイムは、レジスタの値を扱う際にこの型を使用し、アーキテクチャ固有のレジスタ操作を抽象化します。

### `zgoarch_s390x.go`

このファイルは、Goのビルドシステムが特定のアーキテクチャ向けにコンパイルしていることを識別するためのマーカーとして機能します。

*   **`// generated by gengoos.go using 'go generate'`**: このコメントは、このファイルが自動生成されたものであり、手動で変更すべきではないことを開発者に伝えます。`gengoos.go`スクリプトは、Goのソースツリー内の様々なアーキテクチャとOSの組み合わせに対して、このような識別子ファイルを生成します。
*   **`const TheGoarch = `s390x``**: 現在のビルドターゲットの`GOARCH`環境変数の値（`s390x`）を文字列定数として提供します。これにより、Goのツールやランタイムは、実行時に現在のアーキテクチャをプログラム的に確認できます。
*   **`const Goarch386 = 0`, ..., `const GoarchS390x = 1`**: これらの定数は、Goがサポートするすべてのアーキテクチャに対して定義されています。現在のビルドターゲットが`s390x`であるため、`GoarchS390x`のみが`1`に設定され、他のアーキテクチャの定数は`0`になります。これは、Goのソースコード内で`// +build s390x`のようなビルドタグを使用する代わりに、Goコード内で直接`if sys.GoarchS390x == 1`のような条件分岐を使ってアーキテクチャ固有のロジックを実装することを可能にします。これにより、コンパイル時に不要なコードが除外され、バイナリサイズが最適化されます。

これらのファイルが追加されることで、Goランタイムはs390xアーキテクチャの特性を正確に理解し、その上で効率的かつ安定して動作するための基盤が確立されます。
