# [インデックス 25643] ファイルの概要

このコミットは、Goコンパイラ、リンカ、およびランタイムがPowerPC 64-bit (ppc64x) アーキテクチャ上で位置独立コード (PIC) を生成する際の、TOC (Table Of Contents) ポインタ (R2レジスタ) の維持に関する変更を導入します。PowerPCアーキテクチャの特性上、PC相対ロード命令が存在しないため、PICの生成にはTOCポインタの管理が不可欠です。このコミットは、そのための基盤となるメカニズムを実装しており、Goコードの動的リンクをサポートするための重要なステップです。

## コミット

```
cmd/compile, cmd/link, runtime: on ppc64x, maintain the TOC pointer in R2 when compiling PIC

The PowerPC ISA does not have a PC-relative load instruction, which poses
obvious challenges when generating position-independent code. The way the ELFv2
ABI addresses this is to specify that r2 points to a per "module" (shared
library or executable) TOC pointer. Maintaining this pointer requires
cooperation between codegen and the system linker:

 * Non-leaf functions leave space on the stack at r1+24 to save the TOC pointer.
 * A call to a function that *might* have to go via a PLT stub must be followed
   by a nop instruction that the system linker can replace with "ld r1, 24(r1)"
   to restore the TOC pointer (only when dynamically linking Go code).
 * When calling a function via a function pointer, the address of the function
   must be in r12, and the first couple of instructions (the "global entry
   point") of the called function use this to derive the address of the TOC
   for the module it is in.
 * When calling a function that is implemented in the same module, the system
   linker adjusts the call to skip over the instructions mentioned above (the
   "local entry point"), assuming that r2 is already correctly set.

So this changeset adds the global entry point instructions, sets the metadata so
the system linker knows where the local entry point is, inserts code to save the
TOC pointer at 24(r1), adds a nop after any call not known to be local and copes
with the odd non-local code transfer in the runtime (e.g. the stuff around
jmpdefer). It does not actually compile PIC yet.
```

## 元コミット内容

このコミットは、PowerPC 64-bit (ppc64x) アーキテクチャにおいて、位置独立コード (PIC) をコンパイルする際にTOC (Table Of Contents) ポインタをR2レジスタで維持するための変更を、Goコンパイラ、リンカ、およびランタイムに導入します。

PowerPC ISA (命令セットアーキテクチャ) にはPC相対ロード命令がないため、位置独立コードの生成には課題があります。ELFv2 ABI (Application Binary Interface) は、この問題を解決するために、R2レジスタがモジュール（共有ライブラリまたは実行可能ファイル）ごとのTOCポインタを指すように規定しています。このポインタを維持するには、コード生成器 (codegen) とシステムリンカの連携が必要です。

具体的には、以下のメカニズムが導入されます。

*   **TOCポインタの保存**: 非リーフ関数は、スタック上の `r1+24` の位置にTOCポインタを保存するためのスペースを確保します。
*   **PLTスタブを介した呼び出し後のNOP**: PLT (Procedure Linkage Table) スタブを介して呼び出される可能性のある関数呼び出しの後には、`nop` 命令が挿入されます。システムリンカは、Goコードを動的にリンクする場合にのみ、この `nop` を `ld r1, 24(r1)` 命令に置き換えてTOCポインタを復元します。
*   **関数ポインタを介した呼び出し**: 関数ポインタを介して関数を呼び出す場合、関数のアドレスは `r12` に格納され、呼び出された関数の最初の数命令（「グローバルエントリーポイント」）が、そのモジュールのTOCアドレスを導出するために使用されます。
*   **同一モジュール内の関数呼び出し**: 同一モジュール内で実装されている関数を呼び出す場合、システムリンカは、R2がすでに正しく設定されていると仮定して、上記の命令（「ローカルエントリーポイント」）をスキップするように呼び出しを調整します。

この変更セットは、グローバルエントリーポイント命令の追加、システムリンカがローカルエントリーポイントを認識するためのメタデータの設定、`24(r1)` へのTOCポインタ保存コードの挿入、ローカルではないと判断された呼び出し後の `nop` の追加、およびランタイム内の特殊な非ローカルコード転送（`jmpdefer` 周りの処理など）への対応を含みます。ただし、このコミット自体はまだPICを実際にコンパイルするものではありません。

## 変更の背景

このコミットの背景には、PowerPC 64-bit (ppc64x) アーキテクチャにおけるGo言語の動的リンクサポートの実現があります。Go言語は通常、静的リンクされたバイナリを生成しますが、共有ライブラリとしてGoコードをビルドしたり、C/C++などの他の言語で書かれた共有ライブラリと連携したりする場合には、動的リンクのメカニズムが必要になります。

PowerPCアーキテクチャの命令セットは、x86-64などの他のアーキテクチャとは異なり、PC (プログラムカウンタ) 相対アドレス指定を直接サポートするロード命令を持っていません。これは、実行時にロードされるアドレスが固定されていない位置独立コード (PIC) を生成する上で大きな課題となります。PICは、共有ライブラリがメモリ上の任意のアドレスにロードされても正しく動作するために不可欠です。

この課題を解決するために、PowerPCのELFv2 ABIでは、TOC (Table Of Contents) と呼ばれる特別なデータ構造と、それを指すR2レジスタの使用を規定しています。TOCは、モジュール内のグローバル変数や関数へのアドレスを格納するテーブルであり、R2レジスタは常に現在のモジュールのTOCのベースアドレスを保持するように運用されます。これにより、PC相対ロード命令がなくても、R2レジスタを基準としたオフセットでデータや関数にアクセスできるようになります。

このコミットは、GoコンパイラとリンカがこのPowerPC ELFv2 ABIのTOC管理規則に準拠するための初期段階の変更を導入するものです。具体的には、Goの生成コードがR2レジスタをTOCポインタとして適切に扱い、関数呼び出しやスタック操作の際にその値を維持・復元するメカニズムを構築しています。これにより、将来的にGoがPowerPC上で真の動的リンクとPICをサポートするための土台が築かれます。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

### 1. PowerPC 64-bit (ppc64x) アーキテクチャ

*   **レジスタ**: PowerPCは汎用レジスタ (GPR) を32本 (R0-R31) 持ちます。このコミットでは特に `R1` (スタックポインタ `SP`)、`R2` (TOCポインタ)、`R12` (関数ポインタ呼び出し時のアドレス) が重要です。
*   **命令セット**: x86-64のようなPC相対ロード命令を持たないことが特徴です。このため、位置独立コードの生成に特別なアプローチが必要です。
*   **ELFv2 ABI**: PowerPC 64-bit Linux環境で標準的に使用されるABIです。関数呼び出し規約、レジスタの使用方法、スタックフレームの構造、そして特にTOCの管理方法を規定しています。

### 2. 位置独立コード (PIC: Position-Independent Code)

*   **定義**: メモリ上のどこにロードされても正しく実行できるコードのことです。共有ライブラリ (Shared Libraries) の実装に不可欠です。
*   **必要性**: 共有ライブラリは複数のプロセスで共有され、各プロセスのアドレス空間の異なる位置にロードされる可能性があります。PICでないと、ロード時にコードを修正 (再配置) する必要があり、メモリ効率が悪くなります。
*   **課題**: コード内の絶対アドレス参照 (例: グローバル変数や他の関数へのジャンプ) は、ロードアドレスに依存するため、PICでは直接使用できません。

### 3. Table Of Contents (TOC) と R2レジスタ

*   **TOC**: PowerPC ELFv2 ABIにおけるPICの実現に不可欠なデータ構造です。各モジュール (実行可能ファイルまたは共有ライブラリ) は、自身のTOCを持ちます。TOCには、そのモジュール内のグローバル変数や関数、および外部シンボルへの参照を解決するための情報が格納されています。
*   **R2レジスタ**: PowerPC ELFv2 ABIでは、R2レジスタが常に現在のモジュールのTOCのベースアドレスを指すように規定されています。これにより、コードはR2からのオフセットを使って、グローバルデータや関数にアクセスできます。
*   **TOCの維持**: 関数呼び出しを跨いでR2レジスタの値を正しく維持することが重要です。特に、異なるモジュール間の呼び出しでは、呼び出し先のモジュールのTOCポインタにR2を更新する必要があります。

### 4. 動的リンク (Dynamic Linking) と PLT/GOT

*   **動的リンク**: プログラムの実行時にライブラリをロードし、リンクする方式です。これにより、ディスクスペースの節約、メモリの共有、プログラムの更新容易性などの利点があります。
*   **PLT (Procedure Linkage Table)**: 外部関数への呼び出しを解決するためのテーブルです。初めて外部関数が呼び出される際に、リンカが実際の関数のアドレスを解決し、PLTエントリを更新します。
*   **GOT (Global Offset Table)**: グローバル変数や外部データへの参照を解決するためのテーブルです。PICでは、データへのアクセスもGOTを介して行われます。

### 5. Goコンパイラとリンカの内部構造

*   **`cmd/compile`**: Goソースコードをアセンブリコードに変換するコンパイラです。アーキテクチャ固有のコード生成ロジック (`internal/ppc64`) を含みます。
*   **`cmd/link`**: コンパイルされたオブジェクトファイルをリンクして実行可能ファイルや共有ライブラリを生成するリンカです。再配置処理 (`internal/ld`) やアーキテクチャ固有のリンク処理 (`internal/ppc64`) を担当します。
*   **`runtime`**: Goプログラムの実行をサポートするランタイムシステムです。ガベージコレクション、スケジューラ、スタック管理、システムコールなどを担当します。アセンブリコード (`asm_ppc64x.s`) で書かれた低レベルな処理も含まれます。

### 6. スタックフレームと `jmpdefer`

*   **スタックフレーム**: 関数が呼び出されるたびに、ローカル変数、引数、戻りアドレスなどを格納するためにスタック上に確保される領域です。
*   **`jmpdefer`**: Goの `defer` ステートメントの実装に関連するランタイム関数です。`defer` された関数が実行される際に、元の呼び出し元に戻るための特殊なジャンプ処理を行います。この処理もTOCポインタの維持に影響を与える可能性があります。

## 技術的詳細

このコミットは、PowerPC 64-bit (ppc64x) 環境におけるGoの動的リンクと位置独立コード (PIC) のサポートに向けた、TOC (Table Of Contents) ポインタ (R2レジスタ) の管理メカニズムを実装しています。PowerPC ISAの特性上、PC相対ロード命令が存在しないため、TOCポインタの正確な維持がPIC生成の鍵となります。

### 1. TOCポインタ (R2) の役割と課題

PowerPC ELFv2 ABIでは、R2レジスタが常に現在のモジュールのTOCのベースアドレスを指すことが義務付けられています。これにより、グローバルデータや関数へのアクセスは、R2を基準としたオフセットで行われます。しかし、関数呼び出し、特に異なるモジュール間の呼び出しでは、R2の値が変更される可能性があるため、その値を適切に保存・復元する必要があります。

### 2. コンパイラ (`cmd/compile`) の変更

*   **`src/cmd/compile/internal/gc/cgen.go`**:
    *   `deferreturn` 呼び出しの前後でTOCポインタの保存・復元ロジックが追加されます。`deferreturn` はGoの `defer` 機構の内部的な呼び出しであり、スタックの巻き戻しなど特殊なコンテキストで実行されるため、R2の整合性維持が特に重要です。
    *   `Ctxt.Flag_shared != 0` (共有ライブラリとしてコンパイルされる場合) の条件で、`ppc64.AMOVD` 命令を使って `24(R1)` (スタック上の `R1+24` オフセット) から `R2` へTOCポインタをロードするコードが挿入されます。これは、`deferreturn` から戻る際にTOCポインタを確実に復元するための措置です。
    *   `nop` 命令の挿入も行われます。これは、システムリンカが後でTOCポインタ復元命令に置き換えるためのプレースホルダとして機能します。
*   **`src/cmd/compile/internal/gc/plive.go`**:
    *   ライブネス解析 (liveness analysis) のエピローグ処理において、`deferreturn` 呼び出し前の命令を特定するロジックが修正されます。ppc64では、TOCリロード命令が追加される可能性があるため、`PCDATA` (PC-relative data) の開始位置を正しく調整するために、追加の命令を考慮に入れる必要があります。
*   **`src/cmd/compile/internal/ppc64/gsubr.go`**:
    *   関数ポインタを介した呼び出し (`obj.ACALL` で `obj.TYPE_REG` を使用する場合) の処理が変更されます。`Ctxt.Flag_shared != 0` の場合、呼び出し後に `24(R1)` から `R2` へTOCポインタをリロードする `MOVD` 命令が追加されます。これは、呼び出された関数が別のモジュールに実装されており、R2を上書きした可能性があるためです。
    *   関数ポインタ呼び出しのターゲットレジスタとして `R12` を使用するよう、コンパイラが `R12` に値を移動させる処理が追加されます。
*   **`src/cmd/compile/internal/ppc64/reg.go`**:
    *   レジスタ割り当てにおいて、`Ctxt.Flag_shared != 0` の場合、`R2` と `R12` が予約済みレジスタとして除外されるようになります。`R2` はTOCポインタ、`R12` は関数ポインタ呼び出し時に使用されるため、コンパイラがこれらのレジスタを他の用途に割り当てないようにします。

### 3. リンカ (`cmd/link`) の変更

*   **`src/cmd/internal/obj/link.go`**:
    *   新しい再配置タイプ `R_ADDRPOWER_PCREL` が追加されます。これは、PowerPCの `addis`/`addi` 命令ペアを使ってPC相対アドレスを計算するための再配置です。TOCポインタのロードに使用されます。
*   **`src/cmd/internal/obj/ppc64/a.out.go`**:
    *   新しいシンボルクラス `C_LBRAPIC` が追加されます。これは、PICコンパイル時の分岐命令の処理に関連します。
*   **`src/cmd/internal/obj/ppc64/asm9.go`**:
    *   `aclass` 関数が `obj.TYPE_BRANCH` タイプのアドレスに対して `C_LBRAPIC` を返すロジックが追加されます。
    *   `asmout` 関数において、`nop` 命令 (`0x60000000`) が挿入されるようになります。これは、システムリンカがTOCポインタ復元命令に置き換える可能性のある場所です。
*   **`src/cmd/internal/obj/ppc64/obj9.go`**:
    *   関数のプロローグに、TOCポインタを `R12` から `R2` へロードする命令 (`addis r2, r12, .TOC.-func@ha` および `addi r2, r2, .TOC.-func@l+4`) が追加されます。これは、`ctxt.Flag_shared != 0` (PICコンパイル時) かつ特定のランタイム関数 (`runtime.duffzero`, `runtime.duffcopy`) でない場合に適用されます。これらの命令は `AWORD` として直接挿入され、`R_ADDRPOWER_PCREL` 再配置タイプが使用されます。
    *   関数のプロローグで、`R2` の値をスタック上の `24(R1)` に保存する `MOVD` 命令が追加されます。
*   **`src/cmd/link/internal/ld/data.go`**:
    *   `.TOC.` シンボルに対する未処理の再配置エラーを抑制するロジックが追加されます。これは、外部リンカが `.TOC.` シンボルを処理するためです。
*   **`src/cmd/link/internal/ld/lib.go`**:
    *   `.TOC.` シンボルが `genasmsym` 関数によって非表示にされないようにする変更が加えられます。
*   **`src/cmd/link/internal/ld/symtab.go`**:
    *   `Buildmode == BuildmodePIE` (PIE: Position Independent Executable) かつ ppc64x の場合、関数の `st_other` フィールドに、グローバルエントリーポイントとローカルエントリーポイントの間の命令数を示すメタデータ (`3 << 5`) が設定されます。これは、システムリンカがローカルエントリーポイントをスキップするために使用します。
*   **`src/cmd/link/internal/ppc64/asm.go`**:
    *   `R_ADDRPOWER_PCREL` 再配置タイプを処理するための `elfreloc1` および `archreloc` 関数が実装されます。これにより、`addis`/`addi` 命令ペアの再配置が正しく行われます。
*   **`src/cmd/link/internal/ppc64/obj.go`**:
    *   外部リンクモード (`ld.LinkExternal`) の場合、`.TOC.` シンボルが `obj.SDYNIMPORT` タイプとしてマークされます。

### 4. ランタイム (`runtime`) の変更

*   **`src/runtime/asm_ppc64x.s`**:
    *   `runtime·rt0_go` (Goプログラムのエントリポイント) で、スタックフレーム作成後に `R2` の値を `24(R1)` に保存し、スタック復元後に `24(R1)` から `R2` に復元する処理が追加されます。
    *   `runtime·mcall`、`runtime·systemstack_switch`、`runtime·goexit`、`runtime·sigfwd`、`runtime·_sigtramp` などの重要なランタイム関数において、関数呼び出し後やスタック切り替え後に `24(R1)` から `R2` へTOCポインタをリロードする命令が追加されます。これは、これらの関数が特殊なコンテキストで実行され、R2が上書きされる可能性があるためです。
    *   `runtime·jmpdefer` の処理が変更され、`deferreturn` 呼び出し前の命令に戻る際に、`8` バイト (TOCリロード命令と `nop` を含む) 巻き戻すように修正されます。
    *   `runtime·prepGoExitFrame` という新しいアセンブリ関数が追加されます。これは、`goexit` が実行されるスタックフレームに現在のTOCポインタを保存するためのものです。
*   **`src/runtime/cgo/gcc_ppc64x.S`**:
    *   `_cgo_reginit` 呼び出し後に `nop` 命令が追加されます。これは、システムリンカがTOCポインタ復元命令に置き換えるためのプレースホルダです。
*   **`src/runtime/proc.go`**:
    *   `newproc1` 関数 (新しいゴルーチンを作成する関数) で、`prepGoExitFrame` が呼び出されるようになります。これにより、ゴルーチン終了時に `goexit` がTOCポインタを正しく復元できるようになります。
*   **`src/runtime/sys_linux_ppc64x.s`**:
    *   シグナルハンドラ関連の関数 (`runtime·sigfwd`, `runtime·_sigtramp`) で、関数呼び出し後に `24(R1)` から `R2` へTOCポインタをリロードする命令が追加されます。
*   **`src/runtime/sys_nonppc64x.go` および `src/runtime/sys_ppc64x.go`**:
    *   `prepGoExitFrame` 関数のGo側の宣言が追加され、ppc64x以外のアーキテクチャでは空の実装が提供されます。

### 5. 全体的な影響

このコミットは、PowerPC 64-bitアーキテクチャにおけるGoの動的リンクサポートの実現に向けた、低レベルなコード生成とランタイムの変更の集合体です。TOCポインタの維持は、PICの正確な動作に不可欠であり、この変更によりGoバイナリが共有ライブラリとして機能したり、他の共有ライブラリと連携したりするための基盤が強化されます。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更箇所は、PowerPC 64-bit (ppc64x) アーキテクチャ固有のコード生成、リンキング、およびランタイムのアセンブリコードに集中しています。

1.  **`src/cmd/compile/internal/gc/cgen.go`**:
    *   `Ginscall` 関数内で、`deferreturn` 呼び出しの前後でTOCポインタの保存・復元ロジックが追加されています。特に、`Ctxt.Flag_shared != 0` の場合に `MOVD 24(R1), R2` 命令を挿入する部分。
    ```go
    				if Thearch.Thechar == '9' {
    					// On ppc64, when compiling Go into position
    					// independent code on ppc64le we insert an
    					// instruction to reload the TOC pointer from the
    					// stack as well. See the long comment near
    					// jmpdefer in runtime/asm_ppc64.s for why.
    					// If the MOVD is not needed, insert a hardware NOP
    					// so that the same number of instructions are used
    					// on ppc64 in both shared and non-shared modes.
    					if Ctxt.Flag_shared != 0 {
    						p := Thearch.Gins(ppc64.AMOVD, nil, nil)
    						p.From.Type = obj.TYPE_MEM
    						p.From.Offset = 24
    						p.From.Reg = ppc64.REGSP
    						p.To.Type = obj.TYPE_REG
    						p.To.Reg = ppc64.REG_R2
    					} else {
    						Thearch.Ginsnop()

    ```

## コアとなるコードの解説

このコミットの核心は、PowerPC 64-bit (ppc64x) アーキテクチャにおける位置独立コード (PIC) の生成と動的リンクを可能にするために、TOC (Table Of Contents) ポインタ (R2レジスタ) の厳密な管理をGoコンパイラ、リンカ、ランタイムに組み込むことです。

### 1. TOCポインタの保存と復元 (`cmd/compile`, `runtime`)

PowerPCではPC相対ロード命令がないため、グローバルデータや関数へのアクセスはR2レジスタが指すTOCを介して行われます。しかし、関数呼び出し、特に異なるモジュール間の呼び出しではR2の値が上書きされる可能性があります。

*   **`deferreturn` 処理の強化**: `src/cmd/compile/internal/gc/cgen.go` では、`deferreturn` (Goの `defer` 処理の内部的な呼び出し) の前後でTOCポインタの保存・復元ロジックが追加されます。`defer` はスタックを巻き戻すなど特殊なコンテキストで実行されるため、R2の整合性維持が極めて重要です。`Ctxt.Flag_shared != 0` (共有ライブラリとしてコンパイルされる場合) の条件で、スタック上の `R1+24` の位置にTOCポインタを保存し、そこから `R2` へロードする命令が挿入されます。これにより、`deferreturn` から戻る際にTOCポインタが確実に復元されます。
*   **関数ポインタ呼び出し後のリロード**: `src/cmd/compile/internal/ppc64/gsubr.go` では、関数ポインタを介した呼び出し後に `24(R1)` から `R2` へTOCポインタをリロードする `MOVD` 命令が追加されます。これは、呼び出された関数が別のモジュールに存在し、R2を上書きした可能性を考慮したものです。
*   **ランタイムでの明示的な管理**: `src/runtime/asm_ppc64x.s` では、`runtime·rt0_go` (プログラムエントリポイント) や `runtime·mcall`、`runtime·systemstack_switch`、`runtime·goexit` などの重要なランタイム関数で、スタックフレームの操作と連動してR2の保存・復元が明示的に行われます。これにより、Goランタイムの低レベルな処理においてもTOCポインタの整合性が保証されます。

### 2. グローバルエントリーポイントとローカルエントリーポイント (`cmd/link`, `cmd/compile`)

PowerPC ELFv2 ABIでは、関数には「グローバルエントリーポイント」と「ローカルエントリーポイント」の概念があります。

*   **グローバルエントリーポイント**: 異なるモジュールから関数が呼び出される際に使用されます。このエントリーポイントでは、呼び出された関数のモジュールのTOCポインタを `R12` から `R2` にロードする命令が含まれます。
*   **ローカルエントリーポイント**: 同一モジュール内から関数が呼び出される際に使用されます。この場合、R2は既に正しく設定されていると仮定されるため、TOCポインタをロードする命令をスキップして、関数の本体に直接ジャンプします。

このコミットでは、`src/cmd/internal/obj/ppc64/obj9.go` において、`ctxt.Flag_shared != 0` の場合に、関数のプロローグにグローバルエントリーポイントの命令 (`addis r2, r12, .TOC.-func@ha` および `addi r2, r2, .TOC.-func@l+4`) が挿入されます。また、`src/cmd/link/internal/ld/symtab.go` では、リンカがELFシンボルの `st_other` フィールドに、グローバルエントリーポイントとローカルエントリーポイントの間の命令数を示すメタデータ (`3 << 5`) を設定するようになります。これにより、システムリンカは適切なエントリーポイントにジャンプできるようになります。

### 3. 再配置タイプ `R_ADDRPOWER_PCREL` の導入 (`cmd/link`)

`src/cmd/internal/obj/link.go` で導入された `R_ADDRPOWER_PCREL` は、PowerPCの `addis`/`addi` 命令ペアを使ってPC相対アドレスを計算するための新しい再配置タイプです。これは、TOCポインタをロードする命令 (`addis r2, r12, .TOC.-func@ha` および `addi r2, r2, .TOC.-func@l+4`) の `.TOC.-func@ha` および `.TOC.-func@l+4` の部分をリンカが正しく解決するために使用されます。`src/cmd/link/internal/ppc64/asm.go` でこの再配置タイプを処理するロジックが実装されています。

### 4. `nop` 命令の戦略的配置 (`cmd/compile`, `cmd/link`, `runtime`)

*   **リンカによる置き換え**: `src/cmd/internal/obj/ppc64/asm9.go` では、`nop` 命令 (`0x60000000`) が戦略的に挿入されます。これは、PLTスタブを介した呼び出しの後など、システムリンカがTOCポインタ復元命令 (`ld r1, 24(r1)`) に置き換える可能性のある場所です。
*   **`jmpdefer` の巻き戻し**: `src/runtime/asm_ppc64x.s` の `jmpdefer` 関数では、`deferreturn` 呼び出し前の命令に戻る際に、巻き戻すバイト数が `4` から `8` に変更されています。これは、TOCリロード命令と `nop` が追加されたことを考慮したものです。

これらの変更は、PowerPC 64-bit環境でGoが動的リンクされたコードを生成し、他の共有ライブラリとシームレスに連携するための低レベルな基盤を構築するものです。このコミット自体はまだPICの完全なコンパイルを有効にするものではありませんが、そのための重要なステップとなります。
