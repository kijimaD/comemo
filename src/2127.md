## 変更の背景

Go言語は、その設計思想の一つとして「統一されたコードスタイル」を重視しています。この思想を実現するために、Go言語の開発初期から、ソースコードを自動的に整形するツールの開発が進められていました。このコミットは、その自動整形ツール、特に後の`gofmt`へと繋がるAST（抽象構文木）からのコード生成・整形機能の初期開発段階に位置づけられます。

当時のGo言語はまだ開発途上にあり、ASTの構造やそれをテキストとして出力するロジックは試行錯誤の段階でした。このコミットの目的は、ASTを基にGoプログラムを正確に再構築できる「テンプレート駆動型」のアプローチを確立し、その再現性を高めることにありました。これにより、Go言語のコードベース全体で一貫したフォーマットを強制し、可読性と保守性を向上させるための基盤を築こうとしていたと考えられます。特に、コメントの扱いが課題として挙げられている点も、後の`gofmt`開発における重要な論点であったことが示唆されます。

## 前提知識の解説

### Go言語のAST (抽象構文木)

AST（Abstract Syntax Tree）は、プログラミング言語のソースコードを抽象的な構文構造で表現したツリー構造のデータ形式です。コンパイラやリンタ、コードフォーマッタなどのツールがソースコードを解析する際に内部的に利用します。Go言語では、標準ライブラリの`go/ast`パッケージがASTの定義と操作を提供しています。

-   **ノード**: ASTの各要素はノードと呼ばれ、変数宣言、関数定義、式、文など、コードの様々な構成要素に対応します。
-   **ツリー構造**: ノードは親子関係を持ち、コードの階層的な構造を表現します。例えば、関数ノードの下にはその関数内の文を表すノードがぶら下がります。
-   **用途**: ASTは、コードの静的解析、リファクタリング、コード生成、そして`gofmt`のようなコードフォーマットツールにおいて不可欠な役割を果たします。

### コードフォーマッタ/プリティプリンタの役割

コードフォーマッタ（またはプリティプリンタ）は、ソースコードのレイアウト（インデント、スペース、改行など）を自動的に整形するツールです。

-   **一貫性の確保**: チーム開発において、個々の開発者のコーディングスタイルに依存せず、プロジェクト全体で統一されたコードスタイルを維持します。
-   **可読性の向上**: 整形されたコードは、インデントや改行が適切に配置され、視覚的に理解しやすくなります。
-   **レビューの効率化**: スタイルに関する議論を減らし、コードのロジックや設計に集中できるようになります。
-   **Go言語における重要性**: `gofmt`はGo言語の公式ツールとして広く利用されており、Goコミュニティにおけるコードスタイルの一貫性に大きく貢献しています。

### テンプレート駆動型コード生成/フォーマットの概念

テンプレート駆動型のアプローチは、データ（この場合はAST）を特定の形式のテキスト（この場合はGoのソースコード）に変換するための「テンプレート」を定義する手法です。

-   **テンプレート**: 出力されるテキストの構造と、データから埋め込まれるプレースホルダーを定義します。
-   **データバインディング**: テンプレートエンジンが、テンプレート内のプレースホルダーに実際のデータを埋め込み、最終的なテキストを生成します。
-   **柔軟性**: テンプレートを変更するだけで出力形式を変更できるため、コード生成やフォーマットのルールを柔軟に調整できます。

このコミットでは、`ast.txt`がASTノードの出力形式を定義するテンプレートとして機能し、`format.go`がそのテンプレートを解析し、ASTを整形して出力するエンジンとして動作しています。

## 技術的詳細

このコミットは、Go言語のASTを整形して出力する「テンプレート駆動型」のメカニズムに大幅な変更を加えています。主要な変更点は、`ast.txt`におけるテンプレート定義の拡張と、それを解釈・実行する`format.go`のロジックの強化にあります。

### `ast.txt`の変更点

`ast.txt`は、GoのASTノードをどのようにテキストとして表現するかを定義するテンプレートファイルです。このコミットでは、より柔軟で表現力豊かなフォーマットを可能にするために、その構文と定義が大幅に拡張されています。

-   **`ast.`プレフィックスの導入**: 多くのASTノード定義に`ast.`プレフィックスが追加されました（例: `Comment`が`ast.Comment`に）。これは、`go/ast`パッケージの実際の型名との対応をより明確にし、システムがASTノードを正確にマッピングできるようにするための変更と考えられます。
-   **新しい構文要素の追加/変更**:
    -   `string`, `char`, `bytes`, `nil`, `not_empty`などの基本的な型や概念が導入され、より詳細な値の出力制御が可能になりました。
    -   `array`, `pointer`などの型も定義され、Goの型システムを反映した出力が可能になっています。
    -   `signature`や`blockStmt`のような、より複雑なコードブロックの構造を表現するための補助的な定義が追加されました。これにより、関数シグネチャやブロック文の整形ルールを再利用可能にしています。
    -   `StructType`や`InterfaceType`の定義が大幅に改善され、構造体フィールドやインターフェースメソッドのインデントや区切り文字の制御がより細かく行えるようになりました。特に、`>>`と`<<`を用いたインデントの制御が導入されています。
    -   `AssignStmt`, `ReturnStmt`, `IfStmt`, `SwitchStmt`, `ForStmt`, `RangeStmt`など、主要な文のフォーマット定義がよりGoらしい構文を再現するように修正されました。例えば、`AssignStmt`では複数の左辺値と右辺値の出力が改善され、`IfStmt`では`Init`と`Cond`のオプション指定が可能になっています。
    -   `ImportSpec`, `ValueSpec`, `TypeSpec`, `GenDecl`, `FuncDecl`といった宣言のフォーマットも強化され、コメントや複数の宣言のグループ化、インデントなどが考慮されています。
-   **繰り返しと区切り文字の改善**: `{Elements / "Separator"}`のような構文が導入され、繰り返し要素の間に特定の区切り文字（例: `, `や`;\n`）を挿入する機能が強化されました。これは、リストや引数、宣言などを整形する際に非常に重要です。

### `format.go`の変更点

`format.go`は、`ast.txt`で定義されたテンプレートを解析し、実際のASTノードを整形して出力するエンジンです。`ast.txt`の変更に合わせて、このファイルも大幅に改修されています。

-   **パーサーの強化**:
    -   `parseFactor`, `parseTerm`, `parseExpr`などの構文解析関数が、`ast.txt`で導入された新しい構文要素（`>>`, `<<`, `!`, `/`など）を正しく解釈できるように更新されました。
    -   `indentation`（インデント制御）、`negation`（否定）、`repetition`（繰り返し）などの新しい内部表現が導入され、テンプレートの複雑なルールを表現できるようになりました。
    -   `parseProd`関数が導入され、プロダクション（ASTノードのフォーマット定義）の解析がより構造化されました。
-   **インデント管理の導入**:
    -   `state`構造体が導入され、インデントのテキストと幅を管理するようになりました。これにより、ネストされたコードブロックのインデントを正確に制御できるようになりました。
    -   `indent`と`outdent`メソッドが追加され、テンプレート内の`>>`と`<<`に対応してインデントレベルを増減させます。
    -   `printIndented`関数が、改行文字の後に現在のインデントテキストを挿入することで、整形された出力に適切なインデントを適用します。
-   **`printf`関数の改善**:
    -   `rawPrintf`関数が導入され、Goの`fmt.Fprintf`と同様に、フォーマット文字列中の`%`の数に応じて引数を渡すロジックが改善されました。これにより、テンプレート内でより柔軟な文字列フォーマットが可能になります。
    -   `state.printf`が、インデントが有効な場合に一時バッファを使用してインデントを適用するようになりました。
-   **カスタムフォーマッタのサポート**:
    -   `Formatter`と`FormatterMap`型が導入され、外部からカスタムのフォーマット関数を登録できるようになりました。これにより、特定のASTノードに対して、テンプレートでは表現しにくい複雑な整形ロジックを適用する柔軟性が提供されます。
    -   `Parse`関数が`FormatterMap`を受け取るようになり、解析時にカスタムフォーマッタを組み込むことが可能になりました。
-   **`print0`と`print`メソッドのロジック変更**:
    -   これらのメソッドは、ASTノードを再帰的にトラバースし、対応するテンプレートルールに基づいて出力を行うコアロジックです。
    -   新しい`indentation`, `negation`, `repetition`などの内部表現に対応するように、各ケースの処理が追加・修正されました。
    -   特に、`field`の処理が強化され、フィールド名だけでなく型名に基づくフォーマット選択も可能になっています。
    -   繰り返し要素の処理において、区切り文字（`t.div`）の概念が導入され、より正確なリストの整形が可能になりました。

### `format_test.go`と`pretty.go`の変更点

-   **`format_test.go`**: 新しいテンプレート構文と整形ロジックを検証するためのテストケースが追加・修正されました。特に、繰り返し要素の区切り文字や、構造体、配列、マップなどの複雑な型の整形に関するテストが強化されています。
-   **`pretty.go`**: `format.Parse`の呼び出しが、カスタムフォーマッタを渡せるように変更されましたが、このコミットでは`nil`が渡されています。また、`tabwriter.NewWriter`のフラグが変更され、HTMLフィルタリングが無効化されています。

これらの変更により、GoのASTをより正確かつ柔軟に、そしてGoのコーディングスタイルに沿って整形して出力する能力が大幅に向上しました。これは、後の`gofmt`の堅牢な基盤を築く上で不可欠なステップでした。

## コアとなるコードの解説

### `ast.txt`における`StructType`の定義変更

この変更は、Goの構造体型（`struct`）の出力フォーマットを大幅に改善しています。

-   **旧定義**: `StructType = "struct {\n"` のように、構造体の開始ブレースの後に単純な改行を挿入するだけでした。これにより、構造体フィールドのインデントや整形が不十分でした。
-   **新定義**:
    -   `ast.StructType = "struct {"`: 構造体の開始ブレースは改行なしで出力されます。
    -   `[Fields:not_empty ... ]`: これはオプションのブロックであり、`Fields`が空でない場合にのみ内部のルールが適用されます。`not_empty`という新しい概念が導入され、フィールドが存在しない場合は何も出力しないように制御しています。
    -   `>> "\t" "\n"`: ここが最も重要な変更点です。`>>`は「インデントを開始する」ことを意味し、続く`"\t"`と`"\n"`は、インデントとしてタブ文字と改行文字を挿入することを指示します。これにより、構造体フィールドが適切にインデントされた状態で出力されるようになります。
    -   `{Fields / ";\n"}`: `Fields`は構造体のフィールドのリストを表します。`{... / "Separator"}`構文は、リストの各要素を整形し、その間に指定された`Separator`（この場合は`;\n`、つまりセミコロンと改行）を挿入します。これにより、各フィールド宣言が新しい行に適切に配置され、セミコロンで区切られるようになります。
    -   `<< "\n"`: `<<`は「インデントを終了する」ことを意味し、続く`"\n"`は、構造体の終了ブレースの前に改行を挿入することを指示します。

この変更により、構造体の定義がGoの標準的なフォーマット（各フィールドがインデントされ、セミコロンで区切られ、閉じブレースが新しい行に配置される）に近づきました。これは、Goプログラム全体の再現性を高める上で不可欠な改善です。

### `usr/gri/pretty/format.go`における`state`構造体とインデント関連関数の追加

このセクションの変更は、テンプレート駆動型AST出力エンジンにおけるインデント管理の基盤を構築しています。

-   **`state`構造体**:
    -   `f Format`: 現在のフォーマットルール（`ast.txt`から解析されたもの）を保持します。
    -   `indent_text []byte`: 現在のインデント文字列（例: `\t`、`\t\t`など）をバイトスライスとして保持します。
    -   `indent_widths []int`: 各インデントレベルにおける`indent_text`の長さを記録します。これにより、`outdent`時に正しいインデントレベルに戻ることができます。
    -   この構造体は、ASTのトラバース中に現在のインデント状態を追跡するために使用されます。

-   **`init(f Format)`メソッド**:
    -   `state`構造体を初期化し、フォーマットルールを設定します。
    -   `indent_text`と`indent_widths`を空のスライスとして初期化します。

-   **`indent(text []byte)`メソッド**:
    -   新しいインデントレベルを開始する際に呼び出されます。
    -   現在の`indent_text`の長さを`indent_widths`に`push`（追加）します。
    -   `indent_text`に、引数で渡された`text`（例: `\t`や`\n`）を追加します。これにより、インデント文字列が長くなります。

-   **`outdent()`メソッド**:
    -   現在のインデントレベルを終了する際に呼び出されます。
    -   `indent_widths`から最後の要素を`pop`（削除）し、その値（前のインデントレベルの`indent_text`の長さ）を使って`indent_text`を切り詰めます。これにより、インデントが解除されます。

-   **`printIndented(w io.Write, s []byte)`関数**:
    -   整形されたバイトスライス`s`を`io.Writer` `w`に書き込む際に使用されます。
    -   `s`内の各改行文字（`\n`）を検出し、その直後に現在の`indent_text`を挿入します。これにより、出力されるコードの各行が適切にインデントされます。

これらのインデント管理機能は、`ast.txt`で定義された`>>`と`<<`構文と密接に連携しています。パーサーは`>>`を検出すると`state.indent`を呼び出し、`<<`を検出すると`state.outdent`を呼び出すことで、出力されるコードのインデントレベルを動的に調整します。これにより、Goのソースコードが持つ構造的なインデントを正確に再現することが可能になりました。
