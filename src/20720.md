# [インデックス 20720] ファイルの概要

このコミットは、Go言語の標準ライブラリ `fmt` パッケージにおける `%#v` フォーマット動詞の挙動を改善し、特に `fmt.Formatter` インターフェースを実装する型でのフラグの取り扱いを修正します。`%#v` はGoの構文で値を表示する特殊な動詞ですが、`#` フラグが他の文脈で持つ意味と衝突することがありました。この変更は、`%#v` の特殊な性質を `fmt` 構造体内の専用フラグ (`sharpV`) として分離することで、コードの明確性を高め、`Formatter` の正しい動作を保証します。

## 変更の背景

Goの `fmt` パッケージは、C言語の `printf` に似た書式設定されたI/Oを提供します。その中で、`%v` は値のデフォルト表現を出力し、`%#v` はGoの構文に沿った表現（例えば、構造体はフィールド名と値を含む `{Field: Value}` 形式）を出力します。

問題は、`#` フラグが `fmt` パッケージ内で二重の意味を持っていたことにあります。
1.  **一般的なフラグ**: `fmt.Formatter` インターフェースを実装する型に対して、`#` フラグは `Format` メソッドに渡される `fmt.State` インターフェースを通じて利用可能であり、型固有の代替フォーマットを指示するために使用できます。
2.  **`%#v` の特殊な意味**: `%#v` は、`#` フラグが単なるオプションのフォーマット指示ではなく、Goの構文表現を強制するという、より強力な意味を持ちます。

この二重の意味が衝突し、特にカスタムフォーマットを提供する `Formatter` を実装した型が `%#v` でフォーマットされる際に、予期せぬ挙動やバグを引き起こす可能性がありました。具体的には、`%#v` が指定された場合でも、内部の `sharp` フラグが `Formatter` に渡される際に、その特殊な意味が正しく伝わらない、あるいは他の `#` フラグの解釈と混同されることがありました。

このコミットは、`%#v` の特殊な「Go構文」モードを、一般的な `#` フラグとは独立した内部状態として管理することで、この問題を解決しようとしています。これにより、`Formatter` は `sharp` フラグをその本来の「代替フォーマット」の意味で受け取ることができ、同時に `fmt` パッケージ全体が `%#v` の「Go構文」要件を正しく適用できるようになります。

## 前提知識の解説

### Goの `fmt` パッケージとフォーマット動詞

Goの `fmt` パッケージは、C言語の `printf` ファミリ関数にインスパイアされた書式設定されたI/O機能を提供します。`fmt.Printf` や `fmt.Sprintf` などの関数は、フォーマット文字列と引数を受け取り、指定された形式で文字列を生成または出力します。

*   **フォーマット動詞 (Verbs)**: `%d` (整数), `%s` (文字列), `%f` (浮動小数点数) など、引数の型に応じた出力形式を指定します。
*   **フラグ (Flags)**: 動詞の前に置かれる修飾子で、出力の挙動を変更します。
    *   `+`: 数値の符号を常に表示、構造体や配列でフィールド名/要素番号を表示。
    *   `-`: 左寄せ。
    *   ` `: 数値が負でない場合にスペースを前置。
    *   `0`: 数値のゼロパディング。
    *   `#`: **代替フォーマット**。数値では基数プレフィックス (`0x` など)、文字列ではクォート、そして `%v` と組み合わせるとGo構文での出力。

### `%v` と `%#v`

*   **`%v`**: 値のデフォルト表現を出力します。これは、型に応じて適切なフォーマットが自動的に選択されます。
*   **`%#v`**: 値のGo構文表現を出力します。これは、デバッグや構造体の内容を正確に表示する際に特に有用です。例えば、`struct{A int}{A: 1}` は `%v` で ` {1}` となるかもしれませんが、`%#v` では `main.struct { A int }{A:1}` のように型情報を含んだ形で出力されます。

### `fmt.Formatter` インターフェース

Goでは、任意の型が `fmt.Formatter` インターフェースを実装することで、`fmt` パッケージによる自身のフォーマット方法をカスタマイズできます。

```go
type Formatter interface {
    Format(f State, c rune)
}
```

*   `Format` メソッドは、`fmt.State` インターフェースとフォーマット動詞 (`c`) を引数に取ります。
*   `fmt.State` インターフェースは、`Flag(int) bool` メソッドを提供し、`#`, `+`, ` ` などのフラグが設定されているかどうかをチェックできます。また、`Width()` や `Precision()` などのメソッドも提供します。
*   `Format` メソッド内で `f.Write()` を呼び出すことで、フォーマットされた文字列を `fmt` パッケージの出力バッファに書き込みます。

### `fmt.GoStringer` インターフェース

`fmt.GoStringer` インターフェースは、`GoString() string` メソッドを持つ型が実装します。`%#v` 動詞が使用された場合、`fmt` パッケージはまず `GoStringer` インターフェースの存在をチェックし、もし実装されていればその `GoString()` メソッドの戻り値を出力します。これは、カスタムのGo構文表現を提供するためのメカニズムです。

```go
type GoStringer interface {
    GoString() string
}
```

## 技術的詳細

このコミットの核心は、`fmt` パッケージの内部状態管理、特にフォーマットフラグの処理方法の変更にあります。

1.  **`sharpV` フラグの導入**:
    `src/fmt/format.go` の `fmt` 構造体に `sharpV bool` という新しいフィールドが追加されました。このフラグは、現在のフォーマット操作が `%#v` 動詞によってトリガーされた「Go構文」モードであるかどうかを明示的に示します。これにより、従来の `sharp` フラグ（`#` フラグが設定されているかどうかを示す）と `%#v` の特殊な意味を分離します。

    ```go
    type fmt struct {
        // ...
        sharp       bool
        // ...
        // For the format %#v, we set this flag and
        // clear the plus flag, since it is in effect
        // a different, flagless format set at the top level.
        // TODO: plusV could use this too.
        sharpV   bool
        // ...
    }
    ```

2.  **`%#v` の処理ロジックの変更**:
    `src/fmt/print.go` の `doPrintf` 関数内で、フォーマット動詞が `v` であり、かつ `sharp` フラグが設定されている場合（つまり `%#v` の場合）、`p.fmt.sharpV` を `true` に設定し、同時に `p.fmt.sharp` を `false` にクリアします。これにより、`%#v` の特殊な意味が `sharpV` にカプセル化され、一般的な `sharp` フラグは他の用途のために解放されます。

    ```go
    // src/fmt/print.go (doPrintf)
    if c == 'v' && p.fmt.sharp {
        // Go syntax. Set the flag in the fmt and clear the sharp flag.
        p.fmt.sharp = false
        p.fmt.sharpV = true
    }
    ```

3.  **`Formatter` および `GoStringer` 処理の改善**:
    `pp.handleMethods` 関数は、`Formatter` や `GoStringer` インターフェースを実装する型を処理します。この関数内で、`sharpV` フラグの状態を一時的に保存し、`Formatter` の `Format` メソッドを呼び出す前に `sharp` フラグを復元するロジックが追加されました。これにより、`Formatter` は `Format` メソッド内で `f.Flag('#')` を呼び出した際に、`%#v` の特殊なGo構文モードではなく、純粋な `#` フラグの状態を正しく取得できるようになります。

    新しいヘルパー関数 `clearSpecialFlags` と `restoreSpecialFlags` が導入され、`sharpV` の状態を安全に保存・復元するメカニズムを提供します。

    ```go
    // src/fmt/print.go
    // clearSpecialFlags pushes %#v back into the regular flags and returns their old state.
    func (p *pp) clearSpecialFlags() bool {
        ret := p.fmt.sharpV
        if ret {
            p.fmt.sharp = true
            p.fmt.sharpV = false
        }
        return ret
    }

    // restoreSpecialFlags, whose argument should be a call to clearSpecialFlags,
    // restores the setting of the sharpV flag.
    func (p *pp) restoreSpecialFlags(sharpV bool) {
        if sharpV {
            p.fmt.sharp = false
            p.fmt.sharpV = true
        }
    }

    // src/fmt/print.go (handleMethods)
    if formatter, ok := p.arg.(Formatter); ok {
        handled = true
        defer p.restoreSpecialFlags(p.clearSpecialFlags()) // ここでフラグの状態を保存・復元
        defer p.catchPanic(p.arg, verb)
        formatter.Format(p, verb)
        return
    }
    // ...
    if p.fmt.sharpV { // GoStringer の処理も sharpV に基づく
        if stringer, ok := p.arg.(GoStringer); ok {
            handled = true
            defer p.restoreSpecialFlags(p.clearSpecialFlags())
            defer p.catchPanic(p.arg, verb)
            p.fmtString(stringer.GoString(), 's')
            return
        }
    }
    ```

4.  **`goSyntax` パラメータの削除と `sharpV` への置き換え**:
    `print.go` 内の多くの関数 (`fmtUint64`, `fmtString`, `fmtBytes`, `fmtPointer`, `printArg`, `printValue`, `printReflectValue`) から `goSyntax bool` パラメータが削除され、その代わりに `p.fmt.sharpV` が直接参照されるようになりました。これにより、Go構文モードの伝播がより一貫性のある内部状態 (`sharpV`) に基づくようになり、関数のシグネチャが簡素化されます。

5.  **`wasString` 戻り値の削除**:
    `pp.handleMethods` および `pp.printArg` 関数から `wasString` 戻り値が削除されました。コミットメッセージによると、この値は常に `false` であったため、冗長と判断されました。

これらの変更により、`fmt` パッケージは `%#v` の特殊なセマンティクスをより正確に処理できるようになり、特に `Formatter` インターフェースを実装するカスタム型が、`#` フラグをその本来の意図（代替フォーマット）で利用できるようになります。

## コアとなるコードの解説

### `src/fmt/format.go` の変更

```go
type fmt struct {
    // ...
    plus        bool
    sharp       bool
    space       bool
    // For the format %#v, we set this flag and
    // clear the plus flag, since it is in effect
    // a different, flagless format set at the top level.
    // TODO: plusV could use this too.
    sharpV   bool // <-- New field
    unicode     bool
    uniQuote    bool // Use 'x'= prefix for %U if printable.
    zero        bool
}

func (f *fmt) clearflags() {
    // ...
    f.plus = false
    f.sharp = false
    f.space = false
    f.sharpV = false // <-- Initialize new field
    f.unicode = false
    f.uniQuote = false
    f.zero = false
}
```
`fmt` 構造体は、現在のフォーマット操作の状態（幅、精度、フラグなど）を保持します。`sharpV` フィールドの追加は、`%#v` が指定された場合にのみ `true` になる専用のフラグを導入することで、`#` フラグの一般的な意味と `%#v` の特殊なGo構文モードを明確に区別します。これにより、`#` フラグが `Formatter` に渡される際に、その本来の「代替フォーマット」の意味を保持できるようになります。

### `src/fmt/print.go` の変更

#### `doPrintf` 関数

```go
func (p *pp) doPrintf(format string, a []interface{}) {
    // ...
    for i := 0; i < len(format); i++ {
        // ...
        if c == 'v' && p.fmt.sharp {
            // Go syntax. Set the flag in the fmt and clear the sharp flag.
            p.fmt.sharp = false
            p.fmt.sharpV = true // <-- Set sharpV and clear sharp
        }
        plus := c == 'v' && p.fmt.plus
        p.printArg(arg, c, plus, 0) // <-- goSyntax parameter removed
    }
    // ...
}
```
`doPrintf` は、フォーマット文字列を解析し、各引数を処理する主要な関数です。ここで、`%#v` が検出された場合（`c == 'v'` かつ `p.fmt.sharp` が `true`）、`p.fmt.sharp` を `false` にクリアし、代わりに `p.fmt.sharpV` を `true` に設定します。これにより、`#` フラグの一般的な状態と `%#v` の特殊なGo構文モードが内部的に分離されます。以降の処理では、Go構文モードが必要な場合は `p.fmt.sharpV` を参照するようになります。

#### `clearSpecialFlags` と `restoreSpecialFlags` 関数

```go
func (p *pp) clearSpecialFlags() bool {
    ret := p.fmt.sharpV
    if ret {
        p.fmt.sharp = true
        p.fmt.sharpV = false
    }
    return ret
}

func (p *pp) restoreSpecialFlags(sharpV bool) {
    if sharpV {
        p.fmt.sharp = false
        p.fmt.sharpV = true
    }
}
```
これらの関数は、`Formatter` や `GoStringer` のメソッドが呼び出される際に、`sharpV` フラグの状態を一時的に変更し、メソッドの実行後に元の状態に戻すためのユーティリティです。
*   `clearSpecialFlags()`: `sharpV` が `true` の場合、`sharp` を `true` に設定し、`sharpV` を `false` にクリアします。これは、`Formatter` が `Format` メソッド内で `f.Flag('#')` を呼び出した際に、`#` フラグが正しく設定されているように見せるためです。元の `sharpV` の状態を返します。
*   `restoreSpecialFlags()`: `clearSpecialFlags()` が返した値を受け取り、`sharpV` を元の状態に戻します。これは `defer` ステートメントと組み合わせて使用され、メソッドの実行が完了した後に必ず元の状態に戻るようにします。

#### `handleMethods` 関数

```go
func (p *pp) handleMethods(verb rune, plus bool, depth int) (handled bool) { // <-- wasString removed
    // ...
    if formatter, ok := p.arg.(Formatter); ok {
        handled = true
        defer p.restoreSpecialFlags(p.clearSpecialFlags()) // <-- Use new helper functions
        defer p.catchPanic(p.arg, verb)
        formatter.Format(p, verb)
        return
    }
    // ...
    if p.fmt.sharpV { // <-- Use sharpV instead of goSyntax parameter
        if stringer, ok := p.arg.(GoStringer); ok {
            // ...
            defer p.restoreSpecialFlags(p.clearSpecialFlags())
            // ...
            p.fmtString(stringer.GoString(), 's') // <-- goSyntax parameter removed
            return
        }
    }
    // ...
    return false // <-- wasString always false, so removed
}
```
`handleMethods` は、引数が `Formatter` や `GoStringer` インターフェースを実装している場合に、それらのカスタムフォーマットメソッドを呼び出します。
重要な変更は、`Formatter` の `Format` メソッドを呼び出す直前に `defer p.restoreSpecialFlags(p.clearSpecialFlags())` が追加されたことです。これにより、`Format` メソッドが実行されている間は、`#` フラグが `Formatter` に正しく伝達され、`%#v` の特殊なGo構文モードが `Formatter` の内部ロジックに影響を与えないようにします。
また、`GoStringer` の処理も `p.fmt.sharpV` に基づくようになり、`wasString` 戻り値が削除されました。

#### その他の関数 (`fmtUint64`, `fmtString`, `fmtBytes`, `fmtPointer`, `printArg`, `printValue`, `printReflectValue`)

これらの関数は、様々な型の値を実際にフォーマットする役割を担っています。変更のパターンは共通しており、以前は `goSyntax bool` というパラメータを受け取っていましたが、これが削除され、代わりに `p.fmt.sharpV` を直接参照するようになりました。

例:
```go
// Before:
// func (p *pp) fmtUint64(v uint64, verb rune, goSyntax bool) {
//     if goSyntax { ... } else { ... }
// }

// After:
func (p *pp) fmtUint64(v uint64, verb rune) { // <-- goSyntax removed
    if p.fmt.sharpV { // <-- Use p.fmt.sharpV
        p.fmt0x64(v, true)
    } else {
        p.fmt.integer(int64(v), 10, unsigned, ldigits)
    }
}
```
この変更は、Go構文モードの伝播を、関数のパラメータではなく、`pp` 構造体の内部状態 (`sharpV`) を介して行うことで、コードの整合性と保守性を向上させます。

## 変更の背景

Goの `fmt` パッケージは、C言語の `printf` に似た書式設定されたI/Oを提供します。その中で、`%v` は値のデフォルト表現を出力し、`%#v` はGoの構文に沿った表現（例えば、構造体はフィールド名と値を含む `{Field: Value}` 形式）を出力します。

問題は、`#` フラグが `fmt` パッケージ内で二重の意味を持っていたことにあります。
1.  **一般的なフラグ**: `fmt.Formatter` インターフェースを実装する型に対して、`#` フラグは `Format` メソッドに渡される `fmt.State` インターフェースを通じて利用可能であり、型固有の代替フォーマットを指示するために使用できます。
2.  **`%#v` の特殊な意味**: `%#v` は、`#` フラグが単なるオプションのフォーマット指示ではなく、Goの構文表現を強制するという、より強力な意味を持ちます。

この二重の意味が衝突し、特にカスタムフォーマットを提供する `Formatter` を実装した型が `%#v` でフォーマットされる際に、予期せぬ挙動やバグを引き起こす可能性がありました。具体的には、`%#v` が指定された場合でも、内部の `sharp` フラグが `Formatter` に渡される際に、その特殊な意味が正しく伝わらない、あるいは他の `#` フラグの解釈と混同されることがありました。

このコミットは、`%#v` の特殊な「Go構文」モードを、一般的な `#` フラグとは独立した内部状態として管理することで、この問題を解決しようとしています。これにより、`Formatter` は `sharp` フラグをその本来の「代替フォーマット」の意味で受け取ることができ、同時に `fmt` パッケージ全体が `%#v` の「Go構文」要件を正しく適用できるようになります。

## 前提知識の解説

### Goの `fmt` パッケージとフォーマット動詞

Goの `fmt` パッケージは、C言語の `printf` ファミリ関数にインスパイアされた書式設定されたI/O機能を提供します。`fmt.Printf` や `fmt.Sprintf` などの関数は、フォーマット文字列と引数を受け取り、指定された形式で文字列を生成または出力します。

*   **フォーマット動詞 (Verbs)**: `%d` (整数), `%s` (文字列), `%f` (浮動小数点数) など、引数の型に応じた出力形式を指定します。
*   **フラグ (Flags)**: 動詞の前に置かれる修飾子で、出力の挙動を変更します。
    *   `+`: 数値の符号を常に表示、構造体や配列でフィールド名/要素番号を表示。
    *   `-`: 左寄せ。
    *   ` `: 数値が負でない場合にスペースを前置。
    *   `0`: 数値のゼロパディング。
    *   `#`: **代替フォーマット**。数値では基数プレフィックス (`0x` など)、文字列ではクォート、そして `%v` と組み合わせるとGo構文での出力。

### `%v` と `%#v`

*   **`%v`**: 値のデフォルト表現を出力します。これは、型に応じて適切なフォーマットが自動的に選択されます。
*   **`%#v`**: 値のGo構文表現を出力します。これは、デバッグや構造体の内容を正確に表示する際に特に有用です。例えば、`struct{A int}{A: 1}` は `%v` で ` {1}` となるかもしれませんが、`%#v` では `main.struct { A int }{A:1}` のように型情報を含んだ形で出力されます。

### `fmt.Formatter` インターフェース

Goでは、任意の型が `fmt.Formatter` インターフェースを実装することで、`fmt` パッケージによる自身のフォーマット方法をカスタマイズできます。

```go
type Formatter interface {
    Format(f State, c rune)
}
```

*   `Format` メソッドは、`fmt.State` インターフェースとフォーマット動詞 (`c`) を引数に取ります。
*   `fmt.State` インターフェースは、`Flag(int) bool` メソッドを提供し、`#`, `+`, ` ` などのフラグが設定されているかどうかをチェックできます。また、`Width()` や `Precision()` などのメソッドも提供します。
*   `Format` メソッド内で `f.Write()` を呼び出すことで、フォーマットされた文字列を `fmt` パッケージの出力バッファに書き込みます。

### `fmt.GoStringer` インターフェース

`fmt.GoStringer` インターフェースは、`GoString() string` メソッドを持つ型が実装します。`%#v` 動詞が使用された場合、`fmt` パッケージはまず `GoStringer` インターフェースの存在をチェックし、もし実装されていればその `GoString()` メソッドの戻り値を出力します。これは、カスタムのGo構文表現を提供するためのメカニズムです。

```go
type GoStringer interface {
    GoString() string
}
```

また、`GoStringer` の処理も `p.fmt.sharpV` に基づくようになり、`wasString` 戻り値が削除されました。

#### その他の関数 (`fmtUint64`, `fmtString`, `fmtBytes`, `fmtPointer`, `printArg`, `printValue`, `printReflectValue`)

これらの関数は、様々な型の値を実際にフォーマットする役割を担っています。変更のパターンは共通しており、以前は `goSyntax bool` というパラメータを受け取っていましたが、これが削除され、代わりに `p.fmt.sharpV` を直接参照するようになりました。

例:
```go
// Before:
// func (p *pp) fmtUint64(v uint64, verb rune, goSyntax bool) {
//     if goSyntax { ... } else { ... }
// }

// After:
func (p *pp) fmtUint64(v uint64, verb rune) { // <-- goSyntax removed
    if p.fmt.sharpV { // <-- Use p.fmt.sharpV
        p.fmt0x64(v, true)
    } else {
        p.fmt.integer(int64(v), 10, unsigned, ldigits)
    }
}
```
この変更は、Go構文モードの伝播を、関数のパラメータではなく、`pp` 構造体の内部状態 (`sharpV`) を介して行うことで、コードの整合性と保守性を向上させます。

### `src/fmt/fmt_test.go` の変更

```go
type fp struct{}

func (fp) Format(f State, c rune) {
    s := "%"
    for i := 0; i < 128; i++ {
        if f.Flag(i) { // <-- Check flags passed to Formatter
            s += string(i)
        }
    }
    // ...
    io.WriteString(f, "["+s+"]")
}

var formatterFlagTests = []struct {
    in  string
    val interface{}
    out string
}{
    // ... various tests with #, +, width, precision, and different verbs
    // scalar values with the (unused by fmt) 'a' verb.
    {"%#a", fp{}, "[%#a]"}, // Test # flag with custom verb
    // ...
    // simple values with the 'v' verb
    {"%#v", fp{}, "[%#v]"}, // Test %#v with Formatter
    // ...
    // composite values with the 'v' verb. Some are still broken.
    {"%#v", [1]fp{}, "[1]fmt_test.fp{[%#v]}"}, // Test %#v with composite type containing Formatter
    // ...
}

func TestFormatterFlags(t *testing.T) {
    for _, tt := range formatterFlagTests {
        s := Sprintf(tt.in, tt.val)
        if s != tt.out {
            t.Errorf("Sprintf(%q, %T) = %q, want %q", tt.in, tt.val, s, tt.out)
        }
    }
}
```
`TestFormatterFlags` は、このコミットの変更が意図通りに機能することを検証するための重要なテストです。`fp` 型は `Formatter` インターフェースを実装しており、`Format` メソッド内で `f.Flag(i)` を呼び出すことで、`fmt` パッケージから渡されたフラグをチェックし、そのフラグを文字列として出力します。
このテストは、`%#a` のように `#` フラグが `Formatter` に正しく渡されること、そして `%#v` のように `sharpV` が内部的に処理される場合でも、`Formatter` が `Format` メソッド内で `f.Flag('#')` を呼び出した際に正しい結果（この場合は `#` フラグが設定されていること）を受け取ることを確認します。特に、`%#v` で複合型をフォーマットする際の挙動もテストされており、`[1]fmt_test.fp{[%#v]}` のようなGo構文表現が期待されます。
