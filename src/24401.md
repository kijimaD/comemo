## 元コミット内容

このコミットは、Goコンパイラの`cmd/compile`パッケージにおいて、SSA（Static Single Assignment）バックエンドが`OCALLMETH`（メソッド呼び出し）を処理する方法を実装します。これは、従来のコンパイラバックエンドが`OCALLMETH`をコンパイルする方法を模倣しています。

## 変更の背景

Goコンパイラは、パフォーマンスと最適化の向上を目的として、従来のAST（Abstract Syntax Tree）ベースのコード生成からSSA（Static Single Assignment）形式の中間表現への移行を進めていました。この移行プロセスでは、Go言語のあらゆる構文要素がSSA形式に正しく変換されるように、各ASTノードタイプに対応するSSA生成ロジックを実装する必要がありました。

`OCALLMETH`は、Go言語におけるメソッド呼び出しを表すASTノードです。例えば、`myObject.myMethod(arg1, arg2)`のようなコードは、コンパイラのフロントエンドでパースされた後、`OCALLMETH`ノードとして表現されます。このコミット以前は、SSAバックエンドが`OCALLMETH`を直接処理するロジックを持っていなかったため、SSA形式への変換が不完全でした。

この変更の背景には、SSAバックエンドの機能網羅性を高め、最終的に従来のバックエンドを完全に置き換えるという目標があります。従来のバックエンドの挙動を模倣することで、既存のGoプログラムのセマンティクスを維持しつつ、SSAの最適化パスの恩恵を受けられるようにすることが意図されています。

## 前提知識の解説

### Goコンパイラの構造

Goコンパイラ（`cmd/compile`）は、主に以下のフェーズで構成されます。

1.  **フロントエンド**: ソースコードをパースし、AST（Abstract Syntax Tree）を構築します。型チェックや定数畳み込みなどの初期処理も行われます。
2.  **ミドルエンド**: ASTを最適化し、中間表現に変換します。この中間表現がSSA形式です。
3.  **バックエンド**: SSA形式からターゲットアーキテクチャの機械語コードを生成します。レジスタ割り当てや命令スケジューリングなどが行われます。

### ASTノード (OCALLFUNC, OCALLMETH, ODOTMETH)

GoコンパイラのASTでは、様々な操作が特定のノードタイプで表現されます。

*   **OCALLFUNC**: 通常の関数呼び出しを表すノードです。例: `fmt.Println("hello")`
*   **OCALLMETH**: メソッド呼び出しを表すノードです。例: `myObject.myMethod()`
*   **ODOTMETH**: メソッドセレクタを表すノードです。`myObject.myMethod`のように、メソッドが呼び出される前の「メソッド値」自体を指します。`OCALLMETH`ノードの左の子（`n.Left`）は通常`ODOTMETH`ノードになります。

### SSA (Static Single Assignment) 形式

SSA形式は、コンパイラ最適化で広く用いられる中間表現です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。GoコンパイラのSSAバックエンドは、ASTからSSA形式のグラフを構築し、そのグラフに対して様々な最適化（デッドコード削除、共通部分式除去など）を適用した後、最終的な機械語コードを生成します。

### Go言語におけるメソッドの内部表現

Go言語のメソッドは、糖衣構文（syntactic sugar）であり、内部的にはレシーバを最初の引数として取る通常の関数として扱われます。例えば、`type T struct {}; func (t T) M() {}`というメソッド`M`は、コンパイラ内部では`func M(t T) {}`のような関数として扱われます。`myVar.M()`という呼び出しは、`M(myVar)`という関数呼び出しに変換されます。この変換は「メソッドの脱糖（desugaring）」と呼ばれます。

## 技術的詳細

このコミットの核心は、SSAバックエンドが`OCALLMETH`ノードを`OCALLFUNC`ノードに「書き換える」ことで、メソッド呼び出しを通常の関数呼び出しとして処理する点にあります。これは、Go言語のメソッドが内部的にレシーバを引数とする関数として扱われるという設計思想をSSAバックエンドに適用するものです。

具体的な変換ロジックは以下の通りです。

1.  **`OCALLMETH`ノードの検出**: コンパイラがASTを走査し、`OCALLMETH`ノードに遭遇します。
2.  **`ODOTMETH`ノードの検証**: `OCALLMETH`ノードの左の子（`n.Left`）が`ODOTMETH`ノードであることを確認します。`ODOTMETH`は`myObject.myMethod`のようなメソッドセレクタを表します。
3.  **ASTの書き換え**:
    *   `ODOTMETH`ノードの右の子（`left.Right`）は、実際の関数（メソッドの実体）を表すノードです。これを新しい`left`ノード（`newLeft`）としてコピーします。
    *   `newLeft`の型を元の`left`（`ODOTMETH`）の型に設定します。
    *   `newLeft`が`ONAME`（名前）ノードである場合、そのクラスを`PFUNC`（関数ポインタ）に設定し、これが関数であることを明示します。
    *   これにより、元の`OCALLMETH`ノードは、レシーバを最初の引数として持つ`OCALLFUNC`ノードとして扱われる準備が整います。例えば、`myObject.myMethod(arg1)`は、概念的に`(myMethod)(myObject, arg1)`のような形に変換されます。
4.  **`static`フラグの設定**: 書き換えられた`OCALLMETH`は、もはや動的なメソッドディスパッチではなく、特定の関数への静的な呼び出しとして扱われるため、`static`フラグが`true`に設定されます。
5.  **SSA値の生成**:
    *   `static`な呼び出しの場合、`ssa.OpStaticCall`オペレーションを使用してSSA値が生成されます。この際、書き換えられた`left.Sym`（シンボル）が使用されます。
    *   `closure`（クロージャ呼び出し）の場合、`ssa.OpLoad`と`ssa.OpClosureCall`オペレーションが使用されます。
6.  **引数サイズの伝達**: 呼び出しオペレーションには、呼び出される関数の引数サイズ（`left.Type.Argwid`）が`AuxInt`として付加されます。これは、スタックフレームの管理やガベージコレクションの正確な動作に必要です。
7.  **戻り値の処理**: `Getoutarg(left.Type)`を使用して、呼び出しの戻り値の型情報を取得し、その後のSSAグラフ構築に利用します。

この一連の処理により、`OCALLMETH`はSSAバックエンドで直接処理されるのではなく、`OCALLFUNC`として統一的に扱われるようになります。これにより、SSAバックエンドの複雑さを軽減し、既存の関数呼び出し最適化パスをメソッド呼び出しにも適用できるようになります。

## コアとなるコードの解説

この変更は、`func (s *state) expr(n *Node) *ssa.Value` メソッド内の`switch n.Op`ステートメントの一部を修正しています。この`expr`メソッドは、ASTノード`n`をSSA値に変換する役割を担っています。

1.  **`case OCALLFUNC:` から `case OCALLFUNC, OCALLMETH:` への変更**:
    *   これにより、`OCALLFUNC`と`OCALLMETH`の両方のASTノードがこの共通の処理ブロックで扱われるようになります。
2.  **`left := n.Left` の導入**:
    *   元のコードでは`n.Left`が直接使われていましたが、`OCALLMETH`の書き換え処理のために、`left`という新しい変数が導入され、これが呼び出し対象の式を指すようになります。
3.  **`if n.Op == OCALLMETH` ブロックの追加**:
    *   このブロックが、メソッド呼び出し（`OCALLMETH`）を関数呼び出し（`OCALLFUNC`）に変換する主要なロジックを含んでいます。
    *   `Fatal("OCALLMETH: n.Left not an ODOTMETH: %v", left)`: `OCALLMETH`ノードの左の子が`ODOTMETH`ノードでない場合、コンパイラエラーとして処理します。これは、`myObject.myMethod()`のようなメソッド呼び出しのAST構造が期待通りであることを保証するためのチェックです。
    *   `newLeft := *left.Right`: `ODOTMETH`ノードの右の子（`left.Right`）は、メソッドの実体である関数を表します。このノードをコピーして`newLeft`を作成します。これにより、元のASTを直接変更することなく、新しいASTノードを構築します。
    *   `newLeft.Type = left.Type`: 新しい`newLeft`ノードに、元の`ODOTMETH`ノードの型情報を引き継ぎます。
    *   `if newLeft.Op == ONAME { newLeft.Class = PFUNC }`: `newLeft`が名前ノード（`ONAME`）である場合、そのクラスを`PFUNC`（関数）に設定します。これは、メソッドが通常の関数として扱われることをコンパイラに伝えます。
    *   `left = &newLeft`: 以降の処理で、`left`変数がこの書き換えられた`newLeft`ノードを指すように更新されます。
    *   `static = true`: メソッド呼び出しが特定の関数への静的な呼び出しに変換されたため、`static`フラグを`true`に設定します。これにより、動的なクロージャ呼び出しのパスではなく、静的な関数呼び出しのパスが選択されるようになります。
4.  **`closure = s.expr(left)`**:
    *   `static`でない（クロージャ呼び出しなどの）場合に、`closure`のSSA値を評価する際に、更新された`left`変数を使用するように変更されています。
5.  **`call = s.newValue1A(ssa.OpStaticCall, ssa.TypeMem, left.Sym, s.mem())`**:
    *   静的な呼び出しの場合、`ssa.OpStaticCall`を生成する際に、更新された`left.Sym`（シンボル）を使用します。
6.  **`call.AuxInt = left.Type.Argwid`**:
    *   呼び出しオペレーションに付加される引数サイズも、更新された`left.Type`から取得するように変更されています。
7.  **`fp := Structfirst(&titer, Getoutarg(left.Type))`**:
    *   戻り値の型情報を取得する際も、更新された`left.Type`を使用します。

これらの変更により、`OCALLMETH`はSSAバックエンドの初期段階で`OCALLFUNC`と同様の形式に「脱糖」され、その後のSSA最適化パスで一貫して処理されるようになります。
