# [インデックス 2098] ファイルの概要

このコミットは、Go言語の初期のビルドシステムにおける依存関係の定義を修正するものです。具体的には、`src/lib/Makefile` ファイルにおいて、`go.dirinstall` ターゲットが依存するパッケージに不足があったため、これらを追加することで、`make nuke install` コマンドが正しく動作するようにしています。これにより、Go標準ライブラリのビルドとインストールプロセスが改善されました。

## 変更の背景

このコミットが行われた2009年4月は、Go言語がまだ一般に公開される前の非常に初期の段階でした。当時のGoプロジェクトは、現在のGo Modulesのような洗練された依存関係管理システムを持っておらず、ビルドプロセスは主に`Makefile`によって制御されていました。

`make nuke install` コマンドは、通常、プロジェクトのクリーンビルド（既存のビルド成果物をすべて削除してから再ビルド）を行い、その後、コンパイルされたバイナリやライブラリをシステムにインストールする目的で使用されます。このコマンドが「動作しない」という問題は、`lib/go`（おそらくGo標準ライブラリのコア部分を指す）のビルドまたはインストールに必要な依存関係が`Makefile`に適切に定義されていなかったことを示唆しています。

具体的には、`go.dirinstall` ターゲットが、そのビルドに必要な他のパッケージ（`regexp`、`sort`、`strings`）のインストールが完了していることを前提としていましたが、`Makefile`上ではそれらの依存関係が明示されていませんでした。このため、`make nuke install` のようなクリーンな環境でのビルド時に、これらの依存パッケージがまだインストールされていない状態で`go.dirinstall`が実行され、ビルドエラーが発生していたと考えられます。このコミットは、この依存関係の欠落を修正し、ビルドプロセスを安定させることを目的としています。

## 前提知識の解説

### Makefileと`make`コマンド

`Makefile`は、プログラムのコンパイルやインストールなどのタスクを自動化するためのルールを記述するファイルです。`make`コマンドは、この`Makefile`を読み込み、記述されたルールに従ってタスクを実行します。

*   **ターゲット (Target)**: `Makefile`における特定のタスクや生成されるファイルを指します。例えば、`all`、`clean`、`install`などが一般的なターゲットです。このコミットでは、`go.dirinstall`のようなカスタムターゲットが登場します。
*   **依存関係 (Dependencies)**: ターゲットをビルドするために事前に完了している必要がある他のターゲットやファイルを指します。`ターゲット: 依存関係` の形式で記述されます。`make`は、ターゲットをビルドする前に、その依存関係がすべて最新であることを確認し、必要であればそれらをビルドします。
*   **レシピ (Recipe)**: ターゲットをビルドするために実行されるコマンドのリストです。

### `make nuke install` コマンド

このコマンドは、Goプロジェクトの初期のビルドスクリプトにおける慣用的な表現です。

*   `nuke`: 一般的に、ビルドディレクトリや生成されたファイルを完全に削除する「クリーン」操作を指します。これにより、以前のビルドの残骸が原因で発生する可能性のある問題を排除し、完全にゼロからビルドを開始できます。
*   `install`: コンパイルされたプログラムやライブラリを、システム上の適切な場所に配置する操作を指します。

したがって、`make nuke install` は「完全にクリーンな状態からプロジェクトをビルドし、インストールする」という一連の操作を意味します。

### Go言語のパッケージと依存関係（初期のGo）

Go言語は、コードをパッケージに分割して管理します。各パッケージは、他のパッケージの機能を利用することができます。現代のGoでは`go.mod`ファイルとGo Modulesが依存関係を管理しますが、2009年当時はこのような仕組みは存在せず、`Makefile`のようなビルドシステムが手動でパッケージ間の依存関係を追跡し、ビルド順序を決定する必要がありました。

このコミットにおける`*.install`や`*.dirinstall`といったターゲットは、特定のGoパッケージをビルドし、インストールするための`Makefile`のルールであると推測されます。例えば、`fmt.dirinstall`は`fmt`パッケージをインストールするターゲット、`strconv.install`は`strconv`パッケージをインストールするターゲットを意味していると考えられます。

## 技術的詳細

このコミットの核心は、`src/lib/Makefile` ファイル内の `go.dirinstall` ターゲットの依存関係の定義にあります。

元の `Makefile` の該当行は以下の通りでした。

```makefile
go.dirinstall: strconv.dirinstall utf8.install unicode.dirinstall fmt.dirinstall
```

これは、「`go.dirinstall` ターゲットをビルドする前に、`strconv`、`utf8`、`unicode`、`fmt` の各パッケージがインストールされている必要がある」と定義していました。

しかし、Go言語の進化に伴い、`lib/go` パッケージ（またはそれが依存する他のパッケージ）が、新たに `regexp`、`sort`、`strings` パッケージの機能を利用するようになったと考えられます。これらの新しい依存関係が `go.dirinstall` の定義に追加されていなかったため、`make nuke install` のようなクリーンビルド時に、これらのパッケージが未インストールの状態で `go.dirinstall` が実行され、ビルドが失敗していました。

このコミットでは、以下の3つの依存関係が `go.dirinstall` ターゲットに追加されました。

1.  `regexp.dirinstall`: 正規表現パッケージのインストール
2.  `sort.install`: ソートパッケージのインストール
3.  `strings.install`: 文字列操作パッケージのインストール

これらの追加により、`go.dirinstall` ターゲットが実行される前に、必要なすべての依存パッケージが確実にインストールされるようになり、`make nuke install` コマンドが正常に動作するようになりました。これは、Go言語の標準ライブラリが成長し、内部的な依存関係が複雑化していく過程で発生した、典型的なビルドシステムの調整です。
