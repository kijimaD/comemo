## 変更の背景

このコミットは、Goプロジェクトがバージョン管理システムをMercurial (Hg) からGitへ移行したことに関連するものです。Goプロジェクトは2014年11月にこの移行を発表し、Go 1.4リリース直後の2014年12月上旬に実施されました。Go 1.5以降のすべての開発はGitHubに移行しました。

この移行の主な理由は以下の通りです。

*   **コミュニティとの連携**: Goコミュニティの大部分がすでにGitを使用し、プロジェクトをGitHubでホストしていました。Goチームは、これらのコミュニティの慣行に合わせ、広く採用されているプラットフォームに参加することを目指しました。
*   **高度なGitベースのコードレビューシステム**: Mercurialはプロジェクトに貢献してきましたが、バージョン管理システムの状況は変化していました。Androidのようなプロジェクトの影響を受けたGitベースのコードレビューシステムの開発は、Goチームのワークフローにより適した機能を提供しました。彼らは、GoogleがホストするGerritのインスタンスをコードレビューに採用し、線形なコミット履歴の維持や、複数のパッチセットの改善された処理など、GitHubのネイティブなプルリクエストシステムよりも優れていると見なされる利点を提供しました。
*   **GitHubへの集中ホスティング**: この移行には、プロジェクトのメインリポジトリ、サブリポジトリ、課題トラッカー、WikiをGitHubに統合し、その人気をホスティングプラットフォームとして活用することも含まれていました。

このコミットは、GoのビルドツールがMercurialコマンドではなくGitコマンドを使用してバージョン情報を取得するように適応させるための、この大規模な移行の一部です。

## 前提知識の解説

### バージョン管理システム (VCS): Mercurial (Hg) と Git

*   **Mercurial (Hg)**: 分散型バージョン管理システムの一つで、Gitと同様にリポジトリ全体をローカルにクローンして作業します。シンプルなコマンド体系と、変更セットの概念が特徴です。Goプロジェクトは長らくMercurialを使用していました。
*   **Git**: 現在最も広く使用されている分散型バージョン管理システムです。強力なブランチ・マージ機能、ステージングエリアの概念、そして大規模プロジェクトでのパフォーマンスに優れています。GitHubなどのホスティングサービスと密接に連携しています。

GoプロジェクトがMercurialからGitへ移行した背景には、Gitのコミュニティでの普及、より高度なコードレビューワークフローのサポート、そしてGitHubという統合された開発プラットフォームの利用が挙げられます。

### `cmd/dist`

`cmd/dist` はGoのソースツリー内にあるツールで、Goのディストリビューション（コンパイラ、標準ライブラリ、ツールなど）をビルドするために使用されます。これはGoのビルドプロセスの中核をなす部分であり、Goのバージョン文字列を決定し、ビルドされたバイナリに埋め込む責任も持っています。

### Goのバージョン文字列

Goのバイナリ（例えば `go` コマンド自体や、Goで書かれたアプリケーション）は、通常、ビルドされたGoのバージョン情報を含む文字列を持っています。例えば、`go version` コマンドを実行すると `go version go1.21.0 linux/amd64` のような出力が得られます。このバージョン文字列は、Goのソースコードがどのリビジョンでビルドされたかを示す重要な情報であり、デバッグや互換性の確認に役立ちます。このコミットが変更しているのは、このバージョン文字列を生成する際に、Mercurialのリビジョン情報ではなくGitのリビジョン情報を利用するようにすることです。

## 技術的詳細

このコミットの主要な目的は、Goのビルドプロセスがバージョン情報を取得するために使用するバージョン管理システムをMercurialからGitに切り替えることです。具体的には、`src/cmd/dist/build.c` 内の `findgoversion` 関数が変更されています。

以前の `findgoversion` 関数は、Mercurialコマンド（`hg identify -b` で現在のブランチを特定し、`hg log` でタグやリビジョン情報を取得）を使用していました。このコミットでは、これらのMercurialコマンドが対応するGitコマンドに置き換えられています。

### `findgoversion` 関数の変更点

1.  **バージョン管理システムの切り替え**:
    *   Mercurialリポジトリがない場合のコメントが「without the Mercurial repo.」から「without the source repo.」に変更され、より一般的な表現になりました。
    *   `VERSION.cache` ファイルに関するコメントも「avoid invoking hg every time」から「avoid invoking git every time」に変更されました。
    *   バージョン情報を取得する際のコメントが「Otherwise, use Mercurial.」から「Otherwise, use Git.」に変更されました。

2.  **ブランチの特定**:
    *   以前は `hg identify -b` を使用して現在のブランチを特定していましたが、これが `git rev-parse --abbrev-ref HEAD` に置き換えられました。このGitコマンドは、現在のHEADが指すブランチの簡潔な名前を出力します。

3.  **タグとリビジョン情報の取得ロジックの変更**:
    *   Mercurialの `hg log` コマンドと、その出力からタグやリビジョン数を解析する複雑なロジック（`splitfields`, `nrev` カウンタなど）が削除されました。
    *   代わりに、Gitのタグ情報を処理するための新しいヘルパー関数 `branchtag` が導入されました。

### 新しい `branchtag` 関数の導入

このコミットの最も重要な技術的変更は、`branchtag` という新しい静的ヘルパー関数の追加です。この関数は、特にリリースブランチにおいて、現在のコミットに最も近い関連するGitタグを特定するために設計されています。

*   `branchtag` は、`git log --decorate=full --format=format:%d master..%s` (ここで `%s` は現在のブランチ名) を実行します。このコマンドは、指定されたブランチ上のコミットに関連付けられたすべての参照（タグ、リモートブランチ、ローカルブランチなど）を出力します。
*   出力された各行を解析し、「`refs/tags/`」で始まる要素を探します。これはGitのタグを示します。
*   見つかったタグ名（例: `go1.4rc2`）を抽出し、それを返します。
*   `precise` というブール型ポインタを引数に取り、見つかったタグがHEADを正確に指しているかどうか（つまり、タグが現在のコミットと完全に一致するかどうか）を示すフラグを設定します。これは、バージョン文字列にコミットハッシュや日付を追加するかどうかを決定するために使用されます。

### バージョン文字列の生成ロジック

*   `findgoversion` は、現在のブランチが「`release-branch.`」で始まる場合、`branchtag` 関数を呼び出して適切なタグを取得します。
*   `precise` フラグが `false` の場合（つまり、タグがHEADを正確に指していない場合）、`git log -n 1 --format=format: +%h %cd HEAD` を実行して、現在のコミットの短いハッシュとコミット日付を取得し、これをバージョン文字列に追加します。これにより、「`go1.4rc2 +f33fc0e 2014-12-08`」のような形式のバージョン文字列が生成され、タグと現在のコミットの差分が示されます。

これらの変更により、GoのビルドシステムはMercurialからGitへの移行後も、正確なバージョン情報を生成し続けることができます。

## コアとなるコードの解説

### `branchtag` 関数

`branchtag` 関数は、Gitリポジトリから関連するタグ情報を抽出するために導入されました。

*   **目的**: この関数は、特にリリースブランチにおいて、現在のコミットに最も近い、かつそのブランチ上にあるタグを見つけることを目的としています。
*   **Gitコマンドの利用**:
    *   `git log --decorate=full --format=format:%d master..%s` を実行します。
        *   `--decorate=full`: コミットに付随するすべての参照（ブランチ、タグなど）を完全な形式で表示します。
        *   `--format=format:%d`: 参照情報のみを出力するようにフォーマットを指定します。
        *   `master..%s`: `master` ブランチから現在のブランチ (`%s` で指定) までの範囲のコミットを対象とします。これにより、リリースブランチに特有のタグを効率的に検索できます。
*   **出力の解析**: `git log` の出力は、例えば `(tag: refs/tags/go1.4rc2, refs/remotes/origin/release-branch.go1.4, refs/heads/release-branch.go1.4)` のような形式の行を含みます。
    *   関数は `refs/tags/` という文字列を探し、その後に続くタグ名（例: `go1.4rc2`）を抽出します。
    *   タグ名はカンマ (`,`) または括弧 (`)`) で終わると判断されます。
*   **`precise` フラグ**: `precise` ポインタは、見つかったタグが現在のHEADコミットを正確に指しているかどうかを示します。`i == 0` の場合（つまり、`git log` の出力の最初の行でタグが見つかった場合）、それはHEADがそのタグを指していることを意味し、`*precise` は `1` に設定されます。これは、後でバージョン文字列にコミットハッシュや日付を追加するかどうかを決定するために使用されます。

### `findgoversion` 関数の変更

`findgoversion` 関数は、Goのバージョン文字列を決定する主要なロジックを含んでいます。

*   **Mercurial関連コードの削除**: 以前のMercurialコマンド（`hg identify`, `hg log`）の呼び出しと、それに関連する複雑なタグ解析ロジック（`splitfields`, `nrev` カウンタ、`tags` ベクタの利用）がすべて削除されました。これにより、コードが大幅に簡素化されました。
*   **Gitコマンドへの切り替え**:
    *   現在のブランチの取得に `git rev-parse --abbrev-ref HEAD` が使用されるようになりました。
*   **`branchtag` の利用**:
    *   `if(hasprefix(bstr(&branch), "release-branch."))` の条件が追加されました。これは、現在のブランチがリリースブランチ（例: `release-branch.go1.4`）である場合にのみ、`branchtag` 関数を呼び出すことを意味します。これにより、リリースブランチに特有のバージョン管理のニーズに対応します。
*   **バージョン文字列の生成**:
    *   `precise` フラグが `false` の場合（つまり、現在のコミットが正確にタグ付けされていない場合）、`git log -n 1 --format=format: +%h %cd HEAD` を実行して、現在のコミットの短いハッシュとコミット日付を取得します。
    *   この情報（例: ` +f33fc0e 2014-12-08`）は、基本となるタグ名（例: `go1.4rc2`）に追加され、より詳細なバージョン文字列（例: `go1.4rc2 +f33fc0e 2014-12-08`）が生成されます。これにより、開発中のバージョンや、タグ付けされていないコミットのバージョンを正確に識別できます。

これらの変更により、GoのビルドシステムはMercurialからGitへの移行後も、Goのバージョン情報を正確かつ効率的に取得し、ビルドされたバイナリに埋め込むことができるようになりました。
