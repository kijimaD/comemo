# [インデックス 27805] ファイルの概要

このコミットは、Goリンカ (`cmd/link`) が非常に長いシンボル名を適切に処理できるようにするための修正です。特に、`bufio.Reader` の内部バッファサイズを超える長さのシンボル名が出現した場合に発生する問題を解決します。この変更により、リンカの堅牢性が向上し、特定のGoプログラム（特に、型情報や構造体タグに非常に長い文字列を含むもの）のリンクが安定して行えるようになります。

## 変更の背景

この変更は、Goリンカが非常に長いシンボル名を処理する際に発生するバグ（Issue #15104）を修正するために導入されました。Goのコンパイラは、型情報、特に構造体のタグ（`struct`フィールドのバッククォートで囲まれた文字列）をシンボル名に含めることがあります。これらのタグが非常に長い文字列を含む場合、生成されるシンボル名も非常に長くなります。

リンカは、オブジェクトファイルからシンボル名を読み取る際に `bufio.Reader.Peek` メソッドを使用していました。`Peek` メソッドは、指定されたバイト数だけデータをバッファリングして返す機能ですが、要求されたバイト数が内部バッファのサイズを超える場合、`bufio.ErrBufferFull` エラーを返します。このエラーが発生した際、リンカはこれを致命的なエラーとして扱い、プログラムを異常終了させていました。

この問題は、特に大規模な構造体定義や、ドキュメント、ライセンス情報など非常に長い文字列を構造体タグに埋め込むような特殊なケースで顕在化しました。リンカがこれらの長いシンボル名を正しく読み取れないため、リンク処理が失敗し、結果として実行可能ファイルが生成できないという問題がありました。

## 前提知識の解説

*   **Goリンカ (`cmd/link`)**: Goツールチェーンの一部であり、コンパイラによって生成されたオブジェクトファイル（`.o`ファイル）を結合し、実行可能なバイナリファイルを生成するプログラムです。シンボル解決、メモリレイアウトの決定、デバッグ情報の埋め込みなどを行います。
*   **シンボル名**: プログラム内の関数、変数、型などの識別子を指します。リンカはこれらのシンボル名を使って、異なるオブジェクトファイル間で参照を解決します。Goでは、特に型情報がシンボル名にエンコードされることがあり、これが長くなる原因となることがあります。
*   **`bufio.Reader`**: Go標準ライブラリの `bufio` パッケージにある型で、I/O操作をバッファリングすることで効率を向上させます。
    *   **`Peek(n int) ([]byte, error)`**: `Peek` メソッドは、次の `n` バイトを読み込まずに返します。これは、ストリームの先頭を「覗き見」して、次に何を読み込むべきかを判断するのに便利です。しかし、`n` バイトが内部バッファに収まらない場合、`bufio.ErrBufferFull` エラーを返します。
    *   **`readFull(buf []byte)`**: `io.ReadFull` のラッパーで、指定されたバイトスライスが完全に満たされるまでデータを読み込みます。これは、`Peek` がバッファオーバーフローを起こした場合でも、確実に全データを読み込むために使用されます。
*   **構造体タグ**: Goの構造体フィールドに付加される文字列リテラルです。リフレクションAPIを通じて実行時にアクセスでき、JSONエンコーディングのフィールド名指定 (`json:"field_name"`) やORMのマッピング情報など、様々なメタデータとして利用されます。このタグに非常に長い文字列を含めることが可能です。
*   **Issue #15104**: このコミットが修正したGoのバグトラッカーの課題番号です。通常、課題の詳細には問題の再現方法や議論が含まれています。

## 技術的詳細

このコミットの核心は、`src/cmd/link/internal/ld/objfile.go` 内の `objReader.readSymName()` 関数における `bufio.Reader.Peek` のエラーハンドリングの改善です。

元のコードでは、`r.rd.Peek(n)` がエラーを返した場合、それがどのようなエラーであるかに関わらず、一律に `log.Fatalf` を呼び出してプログラムを終了させていました。これは、シンボル名が予期せず長い場合に発生する問題として扱われていました。

修正後のコードでは、`Peek` が返したエラーが `bufio.ErrBufferFull` であるかどうかを明示的にチェックします。
1.  **`bufio.ErrBufferFull` の検出**: `Peek` が `bufio.ErrBufferFull` を返した場合、これはシンボル名が `bufio.Reader` の内部バッファよりも長いため、`Peek` が要求された全バイトを返せなかったことを意味します。
2.  **専用バッファの割り当てと読み込み**: この場合、リンカは `n` バイト（シンボル名の実際の長さ）分の新しいバイトスライス `origName` を作成し、`r.readFull(origName)` を呼び出して、シンボル名全体を確実に読み込みます。これにより、長いシンボル名でも途中で切り捨てられることなく、完全に取得できるようになります。
3.  **その他のエラーハンドリング**: `bufio.ErrBufferFull` 以外のエラーが発生した場合は、引き続き `log.Fatalf` を呼び出して、他の予期せぬI/Oエラーに対処します。
4.  **`r.readFull` の条件付き呼び出し**: シンボル名を読み取った後、`r.readFull(r.rdBuf[:n])` を呼び出して、`Peek` で既に「覗き見」したデータをバッファから破棄する処理があります。この呼び出しが、`Peek` がエラーを返さなかった（つまり `err == nil`）場合にのみ実行されるように変更されました。これは、`Peek` が `bufio.ErrBufferFull` を返した場合、`origName` が `Peek` の結果ではなく `readFull` で読み込まれた新しいバッファであるため、`Peek` の結果を破棄する必要がない、あるいは既に `readFull` がバッファを進めているため不要になる、といった状況に対応するためのものです。

この修正により、リンカは `bufio.Reader` のバッファサイズに依存することなく、任意の長さのシンボル名を処理できるようになり、堅牢性が大幅に向上しました。

新しいテストファイル `src/cmd/link/link_test.go` は、この修正が正しく機能することを検証するために追加されました。このテストは、非常に長い文字列リテラルを構造体タグに埋め込むことで、意図的に長いシンボル名を生成し、リンカがそれをエラーなく処理できることを確認します。

## コアとなるコードの解説

`objReader.readSymName()` 関数は、オブジェクトファイルからシンボル名を読み取る役割を担っています。

変更前は、シンボル名の長さを `n` として取得した後、`r.rd.Peek(n)` を呼び出して `n` バイトを「覗き見」していました。この `Peek` がエラーを返すと、それが `bufio.ErrBufferFull` であっても、一律に `log.Fatalf` でプログラムを終了させていました。これは、`Peek` が内部バッファに収まらないデータを読み込もうとした場合に発生する正常な挙動であるにも関わらず、致命的なエラーとして扱われていたため、リンカがクラッシュする原因となっていました。

変更後では、以下の点が改善されています。

1.  **`bufio.ErrBufferFull` の明示的なハンドリング**: `origName, err := r.rd.Peek(n)` の結果を評価する際に、`err == bufio.ErrBufferFull` という条件が追加されました。
2.  **長いシンボル名の完全な読み込み**: `bufio.ErrBufferFull` が検出された場合、`origName = make([]byte, n)` でシンボル名全体を格納できる新しいバッファを確保し、`r.readFull(origName)` を呼び出して、`bufio.Reader` からシンボル名全体を確実に読み込みます。これにより、`Peek` のバッファサイズ制限を回避し、長いシンボル名も正しく処理できるようになります。
3.  **汎用エラーハンドリングの維持**: `bufio.ErrBufferFull` 以外のエラー（例えば、実際のI/Oエラー）が発生した場合は、引き続き `log.Fatalf` を呼び出して、それらのエラーに対処します。
4.  **`r.readFull` の条件付き実行**: シンボル名を読み取った後、`Peek` で「覗き見」したデータをバッファから破棄するために `r.readFull(r.rdBuf[:n])` が呼び出されますが、この呼び出しが `if err == nil` の条件の下に置かれました。これは、`Peek` が `bufio.ErrBufferFull` を返した場合、`origName` は `Peek` の結果ではなく `readFull` で読み込まれた新しいバッファであるため、`Peek` の結果を破棄する必要がない、あるいは既に `readFull` がバッファを進めているため不要になる、といった状況に対応するためのものです。これにより、不要なバッファ操作が避けられ、コードの正確性が向上しています。

追加された `link_test.go` は、この修正の有効性を検証するための重要なテストです。`AuthorPaidByTheColumnInch` 構造体は、Goのコンパイラが生成するシンボル名が非常に長くなるように、意図的に長い文字列を構造体タグに含んでいます。`TestLargeSymName` 関数でこの構造体を参照することで、リンカがこのような長いシンボル名を問題なく処理できることを確認します。
