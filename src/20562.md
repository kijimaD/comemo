# [インデックス 20562] ファイルの概要

このコミットは、Go言語の標準ライブラリ `os` パッケージにおける `RemoveAll` 関数の挙動を改善するものです。具体的には、`RemoveAll` がディレクトリを削除しようとした際に、そのディレクトリが既に存在しない場合（例えば、別のゴルーチンやプロセスによって削除された場合）に、エラーを返さないように修正しています。これにより、並行処理環境下での `RemoveAll` の堅牢性が向上します。

## コミット

`os`: `RemoveAll` の実行中にディレクトリが削除された場合にエラーを回避

## 変更の背景

この変更の背景には、Go言語の `os` パッケージにある `RemoveAll` 関数が抱えていた特定のエラーハンドリングの問題があります。`RemoveAll` は指定されたパスとその配下の全てを再帰的に削除する関数ですが、複数のゴルーチンやプロセスが同時に同じディレクトリを削除しようとした場合、あるいはディレクトリが `RemoveAll` の実行中に外部から削除された場合に、予期せぬエラーを返す可能性がありました。

具体的には、`RemoveAll` がディレクトリの削除を試みた際に、そのディレクトリが既に存在しない（`os.ErrNotExist` に相当するエラー）場合でも、`RemoveAll` はエラーを返していました。しかし、最終的な目的が「そのパスに何も存在しない状態にする」ことであれば、既に存在しないことは成功とみなすべきです。この挙動は、特に並行処理において、複数の `RemoveAll` 呼び出しが競合する「レースコンディション」のシナリオで問題となります。例えば、あるゴルーチンがディレクトリを削除し終えた直後に別のゴルーチンが同じディレクトリに対して `RemoveAll` を呼び出すと、後者の呼び出しは「ファイルまたはディレクトリが存在しない」というエラーを受け取ってしまい、これは開発者にとっては不必要なエラーと認識される可能性がありました。

この問題は、GoのIssueトラッカーで #7776 として報告されており、このコミットはその問題を解決するために導入されました。

## 前提知識の解説

*   **`os` パッケージ**: Go言語の標準ライブラリの一部で、オペレーティングシステム（OS）の機能へのポータブルなインターフェースを提供します。ファイルシステム操作（ファイルの読み書き、ディレクトリの作成・削除など）、プロセス管理、環境変数へのアクセスなどが含まれます。
*   **`os.RemoveAll` 関数**: 指定されたパス（ファイルまたはディレクトリ）とその配下の全てを再帰的に削除する関数です。ディレクトリの場合、その中のファイルやサブディレクトリも全て削除されます。
*   **`os.Remove` 関数**: 指定されたパス（ファイルまたは空のディレクトリ）を削除する関数です。`RemoveAll` と異なり、非空のディレクトリは削除できません。
*   **`os.IsNotExist(err)`**: `os` パッケージで提供されるヘルパー関数で、与えられたエラー `err` が「ファイルまたはディレクトリが存在しない」ことを示すエラーであるかどうかを判定します。これは、異なるOS間でエラーコードが異なる場合でも、ポータブルに存在しないエラーを検出するために重要です。
*   **レースコンディション (Race Condition)**: 複数の並行プロセスやスレッドが共有リソースにアクセスしようとした際に、そのアクセス順序によって結果が非決定的に変わってしまう状態を指します。このコミットの文脈では、複数のゴルーチンが同時に同じディレクトリを削除しようとすることがレースコンディションを引き起こす可能性があります。
*   **ゴルーチン (Goroutine)**: Go言語における軽量な並行実行単位です。OSのスレッドよりもはるかに軽量で、数千、数万のゴルーチンを同時に実行することが可能です。

## 技術的詳細

このコミットの技術的な核心は、`os.RemoveAll` 関数がエラーを処理する方法の変更にあります。従来の `RemoveAll` は、`os.Remove` やその他の内部的なファイルシステム操作がエラーを返した場合、そのエラーをそのまま呼び出し元に伝播させていました。しかし、この変更では、`os.Remove` が `os.ErrNotExist` に相当するエラーを返した場合、それをエラーとはみなさず、`nil`（エラーなし）を返すように修正されています。

具体的には、`src/os/path.go` 内の `RemoveAll` 関数において、以下の変更が加えられました。

1.  **最初の `Remove(path)` 呼び出しの変更**:
    `RemoveAll` はまず、対象のパスを直接 `Remove` しようとします。この最初の試行で `Remove` が成功した場合、または `IsNotExist(err)` が真であった場合、`RemoveAll` は直ちに `nil` を返して終了します。これは、対象が既に存在しない場合でも、目的の状態（パスが存在しないこと）が達成されているため、成功とみなすというロジックです。

    ```go
    // 変更前
    // err := Remove(path)
    // if err == nil {
    //     return nil
    // }

    // 変更後
    err := Remove(path)
    if err == nil || IsNotExist(err) { // ここが変更点
        return nil
    }
    ```

2.  **再帰的な削除後の `Remove(path)` 呼び出しの変更**:
    `RemoveAll` は、ディレクトリの場合、その内容を再帰的に削除した後、最後にそのディレクトリ自体を再度 `Remove` しようとします。この最終的な `Remove` 呼び出しでも、同様に `IsNotExist(err)` のチェックが追加されました。これにより、再帰的な削除中にディレクトリが外部から削除された場合でも、不必要なエラーが返されるのを防ぎます。

    ```go
    // 変更前
    // err1 := Remove(path)
    // if err == nil {
    //     err = err1
    // }

    // 変更後
    err1 := Remove(path)
    if err1 == nil || IsNotExist(err1) { // ここが変更点
        return nil
    }
    if err == nil {
        err = err1
    }
    ```

この変更により、複数の `RemoveAll` 呼び出しが同時に実行され、一方が先にディレクトリを削除し終えたとしても、他方が `os.ErrNotExist` を受け取ってエラーを報告することがなくなります。これは、冪等性（何度実行しても同じ結果になること）の観点からも望ましい挙動であり、並行処理におけるエラーハンドリングを簡素化します。

また、この変更を検証するために、`src/os/os_test.go` に `TestRemoveAllRace` という新しいテストケースが追加されました。このテストは、複数のゴルーチンが同時に同じディレクトリに対して `RemoveAll` を呼び出すというレースコンディションを意図的に発生させ、その際にエラーが報告されないことを確認します。このテストは、`runtime.GOMAXPROCS` を設定して並行性を制御し、`sync.WaitGroup` と `chan struct{}` を使用してゴルーチン間の同期を取りながら、複数の `RemoveAll` 呼び出しが競合するように設計されています。

## コアとなるコードの変更箇所

### `src/os/os_test.go`

*   `mkdirTree` 関数が追加され、テスト用の深いディレクトリ構造を生成するために使用されます。
*   `TestRemoveAllRace` 関数が追加されました。このテストは、複数のゴルーチンが同時に `RemoveAll` を呼び出すレースコンディションをシミュレートし、エラーが返されないことを検証します。
    *   `runtime.GOMAXPROCS` を一時的に増やし、並行実行を促進します。
    *   `ioutil.TempDir` で一時ディレクトリを作成し、`mkdirTree` で深い階層のディレクトリ構造を構築します。
    *   `sync.WaitGroup` と `hold` チャネルを使用して、複数のゴルーチンが同時に `RemoveAll` を開始するように同期します。
    *   各ゴルーチンは `RemoveAll(root)` を呼び出し、エラーが返されないことをアサートします。
    *   `sync` パッケージの `WaitGroup` がインポートされています。

### `src/os/path.go`

*   `RemoveAll` 関数内のエラーチェックロジックが変更されました。
    *   最初の `Remove(path)` 呼び出しの後、`err == nil` に加えて `IsNotExist(err)` のチェックが追加されました。
    *   再帰的な削除後の最終的な `Remove(path)` 呼び出しの後も、同様に `err1 == nil` に加えて `IsNotExist(err1)` のチェックが追加されました。

## コアとなるコードの解説

### `src/os/os_test.go` の `TestRemoveAllRace`

```go
func TestRemoveAllRace(t *testing.T) {
	n := runtime.GOMAXPROCS(16) // 並行性を高めるためにGOMAXPROCSを設定
	defer runtime.GOMAXPROCS(n) // テスト終了後に元に戻す

	root, err := ioutil.TempDir("", "issue") // 一時ディレクトリを作成
	if err != nil {
		t.Fatal(err)
	}
	mkdirTree(t, root, 1, 6) // 深いディレクトリツリーを作成

	hold := make(chan struct{}) // ゴルーチンを同時に開始するためのチャネル
	var wg sync.WaitGroup      // 全てのゴルーチンの完了を待つためのWaitGroup

	for i := 0; i < 4; i++ { // 4つのゴルーチンを起動
		wg.Add(1)
		go func() {
			defer wg.Done()
			<-hold // holdチャネルが閉じられるまで待機
			err := RemoveAll(root) // RemoveAllを呼び出す
			if err != nil {
				t.Errorf("unexpected error: %T, %q", err, err) // エラーが発生したらテスト失敗
			}
		}()
	}
	close(hold) // 全てのゴルーチンにRemoveAllの実行を許可
	wg.Wait()   // 全てのゴルーチンの完了を待つ
}
```
このテストは、`RemoveAll` が並行環境下で正しく動作し、不必要なエラーを返さないことを保証します。複数のゴルーチンが同時に同じディレクトリを削除しようとすると、そのうちの1つが成功し、他のゴルーチンは既にディレクトリが存在しない状態に遭遇します。このテストは、その「存在しない」状態がエラーとして報告されないことを確認します。

### `src/os/path.go` の `RemoveAll`

```go
func RemoveAll(path string) error {
	// Simple case: if Remove works, we're done.
	err := Remove(path)
	if err == nil || IsNotExist(err) { // 変更点: IsNotExist(err) を追加
		return nil
	}

	// ... (ディレクトリの内容を再帰的に削除するロジック) ...

	// Remove directory.
	err1 := Remove(path)
	if err1 == nil || IsNotExist(err1) { // 変更点: IsNotExist(err1) を追加
		return nil
	}
	if err == nil {
		err = err1
	}
	return err
}
```
この変更により、`RemoveAll` は、対象のパスが既に存在しない場合でも、その操作を成功とみなすようになりました。これは、`RemoveAll` の最終的な目的が「指定されたパスに何も存在しない状態にする」ことであるため、その目的が達成されていれば、たとえそのパスが既に存在しなかったとしても、エラーを返す必要はないという設計思想に基づいています。これにより、並行処理における競合状態でのエラーハンドリングがより堅牢かつ直感的になります。
