# [インデックス 22533] ファイルの概要

このコミットは、Go言語の標準ライブラリである`html/template`パッケージにおいて、不完全なテンプレート（名前は定義されているが、内容がパースされていないテンプレート）をエスケープしようとした際に発生していたクラッシュを修正するものです。`text/template`パッケージでは同様の状況で適切にエラーを返していたのに対し、`html/template`ではクラッシュするという挙動の不一致とバグが解消されました。

具体的には、`text/template`パッケージの内部ロジックがリファクタリングされ、定義済みのテンプレートのリストを取得するための新しい関数`text/template.DefinedTemplates`がエクスポートされました。`html/template`はこの新しい関数を利用することで、不完全なテンプレートが実行された際に、より詳細で役立つエラーメッセージを生成し、クラッシュではなくエラーとして処理できるようになりました。

## 元コミット内容

`html/template`パッケージにおいて、不完全なテンプレートをエスケープしようとした際に発生するクラッシュを修正します。

`text/template`パッケージではこの状況をエラーとして処理していましたが、`html/template`ではクラッシュしていました。この修正では、`text/template.Execute`をリファクタリングし、新しい関数`text/template.DefinedTemplates`をエクスポートします。これにより、`html/template`は同様のケースで同じ役立つエラーメッセージを取得できるようになり、エスケープされるテンプレートに定義がない場合にこの関数を呼び出すようにします。

Issue #10204を修正します。

## 変更の背景

この変更の背景には、Go言語のテンプレートエンジンにおける`text/template`と`html/template`という二つのパッケージ間の挙動の不一致がありました。

-   **`text/template`**: 汎用的なテキスト生成のためのテンプレートエンジンです。テンプレートが名前だけ定義され、実際の内容（ツリー構造）がパースされていない「不完全なテンプレート」に対して`Execute`メソッドが呼び出された場合、このパッケージは「`[テンプレート名]`は不完全または空のテンプレートです」という形式の適切なエラーメッセージを返していました。

-   **`html/template`**: `text/template`をラップし、HTML出力に特化したテンプレートエンジンです。特に、クロスサイトスクリプティング（XSS）攻撃を防ぐための自動エスケープ機能が組み込まれています。しかし、`text/template`と同様の「不完全なテンプレート」に対して`Execute`メソッドが呼び出された場合、`html/template`はエラーを返す代わりにクラッシュ（パニック）するという問題がありました。これは、エスケープ処理の内部でテンプレートのツリー構造が`nil`であることに起因するnilポインタ参照などが発生していたためと考えられます。

この挙動の不一致は、開発者にとって混乱を招くものであり、特に`html/template`のクラッシュはアプリケーションの安定性を損なう重大なバグでした。この問題はGitHub Issue #10204として報告されており、このコミットはその修正を目的としています。修正の目標は、`html/template`が`text/template`と同様に、不完全なテンプレートに対してクラッシュすることなく、明確なエラーメッセージを返すようにすることでした。

## 前提知識の解説

このコミットを理解するためには、Go言語のテンプレートパッケージ、特に`text/template`と`html/template`の基本的な概念と違いを理解しておく必要があります。

1.  **`text/template`パッケージ**:
    *   **目的**: 任意のテキスト形式の出力を生成するための汎用的なテンプレートエンジンです。設定ファイル、コード生成、プレーンテキストのレポートなど、HTML以外の様々なテキストベースのコンテンツ生成に使用されます。
    *   **エスケープ**: セキュリティのための自動エスケープ機能は持っていません。テンプレートに渡されたデータはそのまま出力されます。したがって、HTMLやJavaScriptなどの特殊なコンテキストで`text/template`を使用する場合、開発者が手動でエスケープ処理を行う必要があります。
    *   **テンプレートの構造**: テンプレートは内部的にツリー構造（`parse.Tree`）として表現されます。このツリーは、テンプレート文字列が`Parse`メソッドによって解析（パース）されたときに構築されます。

2.  **`html/template`パッケージ**:
    *   **目的**: HTML出力を安全に生成するために特化したテンプレートエンジンです。`text/template`の機能を拡張し、HTMLコンテキストに応じた自動エスケープ機能を提供します。これにより、悪意のあるスクリプトの挿入（XSS攻撃）を防ぐことができます。
    *   **自動エスケープ**: テンプレート内のデータがHTML属性、JavaScriptコード、CSSスタイル、URLなど、どのコンテキストで使用されるかに応じて、自動的に適切なエスケープ処理を適用します。例えば、`<`は`&lt;`に、`"`は`&quot;`に変換されます。
    *   **安全性**: `html/template`は、生成されるHTMLが安全であることを保証しようとします。信頼できないソースからの生のHTMLを直接埋め込むことは、通常、エスケープされるか、エラーを引き起こします。開発者が意図的に安全なHTMLを埋め込みたい場合は、`template.HTML`型を使用しますが、これは慎重に行う必要があります。
    *   **内部構造**: `html/template`は内部で`text/template`のインスタンスを保持し、その上にエスケープロジックを追加しています。

3.  **「不完全なテンプレート」**:
    *   Goのテンプレートパッケージでは、`template.New("name")`のようにテンプレートに名前を付けてインスタンスを作成できます。しかし、この時点ではテンプレートは「空」であり、まだ`Parse`メソッドなどで実際のテンプレート文字列が解析されていません。
    *   テンプレートの内容がパースされていない状態では、その内部的なツリー構造（`t.Tree`フィールド）は`nil`となります。
    *   このような、名前は存在するが内容が定義されていないテンプレートを「不完全なテンプレート」と呼びます。この状態のテンプレートに対して`Execute`などの操作を行うと、通常はエラーとなるか、今回のバグのようにクラッシュする可能性がありました。

このコミットは、`html/template`が不完全なテンプレートを処理する際に、`text/template`と同様に、クラッシュせずに適切なエラーメッセージを返すようにするためのものです。

## 技術的詳細

このコミットの技術的な解決策は、主に以下の2つの側面から構成されています。

1.  **`text/template`パッケージのリファクタリングと新関数のエクスポート**:
    *   これまで`text/template`の`Execute`メソッド内で、不完全なテンプレートに対するエラーメッセージを生成する際に、定義済みのテンプレートのリストを文字列として構築するロジックがインラインで存在していました。
    *   このロジックが`text/template.DefinedTemplates()`という新しい公開関数として切り出されました。この関数は、テンプレートセット内で定義されている（つまり、`Tree`フィールドが`nil`ではない）すべてのテンプレートの名前を引用符で囲み、カンマで区切ってリストアップした文字列（例: `; defined templates are: "tmpl1", "tmpl2"`)を返します。定義されているテンプレートがない場合は空文字列を返します。
    *   この変更により、`text/template`の`Execute`メソッドは、エラーメッセージ生成時に`t.DefinedTemplates()`を呼び出すだけでよくなり、コードの重複が避けられ、よりモジュール化されました。

2.  **`html/template`パッケージでの新関数の利用とエラー処理の改善**:
    *   `html/template`の`Template`構造体には、内部的に`text/template.Template`のインスタンスが埋め込まれています（`t.text`）。
    *   `html/template`の`escape()`メソッド（テンプレートのエスケープ処理を行う内部メソッド）内で、テンプレートのツリー構造が`nil`であるかどうかを明示的にチェックするようになりました。
    *   具体的には、`if t.Tree == nil`という条件が追加されました。
    *   もし`t.Tree`が`nil`であれば、それは不完全なテンプレートであることを意味します。この場合、`fmt.Errorf`を使用してエラーメッセージを構築し、その際に`t.text.DefinedTemplates()`を呼び出して、`text/template`から提供される定義済みテンプレートのリストをエラーメッセージに含めるようにしました。
    *   これにより、`html/template`は不完全なテンプレートに対してクラッシュする代わりに、`text/template`と同様の形式で「`[テンプレート名]`は不完全または空のテンプレートです; defined templates are: ...」という、より詳細で役立つエラーメッセージを返すようになりました。

この修正により、`html/template`と`text/template`の間で不完全なテンプレートに対する挙動が統一され、`html/template`の堅牢性が向上しました。また、エラーメッセージに定義済みテンプレートのリストが含まれることで、デバッグの際に問題の特定が容易になります。

## コアとなるコードの変更箇所

このコミットによる主要なコード変更は以下の3つのファイルにわたります。

1.  **`src/html/template/escape_test.go`**:
    *   新しいテストケース `TestErrorOnUndefined` が追加されました。
    *   このテストは、名前だけ定義され内容がパースされていない`html/template`インスタンスに対して`Execute`を呼び出し、エラーが返されること、そしてそのエラーメッセージが「incomplete」という文字列を含むことを検証します。これにより、クラッシュが修正され、適切なエラーメッセージが返されるようになったことを確認します。

2.  **`src/html/template/template.go`**:
    *   `(*Template).escape()` メソッド内に変更が加えられました。
    *   具体的には、`if t.escapeErr == nil` ブロックの直後に以下の行が追加されました。
        ```go
        if t.Tree == nil {
            return fmt.Errorf("template: %q is an incomplete or empty template%s", t.Name(), t.text.DefinedTemplates())
        }
        ```
    *   このコードは、`html/template`の内部ツリー（`t.Tree`）が`nil`である（つまり、テンプレートが不完全である）場合に、`fmt.Errorf`を使ってエラーを生成し、`t.text.DefinedTemplates()`を呼び出して定義済みテンプレートのリストをエラーメッセージに含めるようにします。

3.  **`src/text/template/exec.go`**:
    *   `(*Template).Execute()` メソッド内の、不完全なテンプレートに対するエラー処理ロジックが変更されました。
    *   以前は`Execute`メソッド内に直接記述されていた、定義済みテンプレートのリストを文字列として構築する部分が削除されました。
    *   代わりに、このロジックが`(*Template).DefinedTemplates()`という新しい公開関数として切り出されました。
        ```go
        // DefinedTemplates returns a string listing the defined templates,
        // prefixed by the string "defined templates are: ". If there are none,
        // it returns the empty string. For generating an error message here
        // and in html/template.
        func (t *Template) DefinedTemplates() string {
            // ... (定義済みテンプレートをリストアップするロジック) ...
        }
        ```
    *   `Execute`メソッド内では、エラーメッセージ生成時にこの新しい`t.DefinedTemplates()`関数が呼び出されるようになりました。
        ```go
        state.errorf("%q is an incomplete or empty template%s", t.Name(), t.DefinedTemplates())
        ```

これらの変更により、`text/template`はエラーメッセージ生成ロジックをモジュール化し、`html/template`はその新しい関数を利用して、不完全なテンプレートに対するクラッシュを修正し、より適切なエラーメッセージを返すようになりました。

## コアとなるコードの解説

このコミットの核心は、`text/template`パッケージから`DefinedTemplates()`関数をエクスポートし、`html/template`がそれを利用して不完全なテンプレートに対するエラー処理を改善した点にあります。

### `src/text/template/exec.go` における変更

1.  **`DefinedTemplates()` 関数の導入**:
    *   以前は`Execute`メソッド内に散在していた、定義済みテンプレートの名前を列挙するロジックが、`DefinedTemplates()`という独立したメソッドとして抽出されました。
    *   この関数は、`t.tmpl`マップ（テンプレートセット内のすべてのテンプレートを保持するマップ）をイテレートし、`tmpl.Tree == nil || tmpl.Root == nil`ではない（つまり、内容がパースされている）テンプレートの名前を収集します。
    *   収集した名前は、`bytes.Buffer`を使って効率的に「`"name1", "name2"`」のようなカンマ区切りの文字列に整形されます。
    *   最終的に、この文字列の前に「`; defined templates are: `」というプレフィックスを付けて返します。これにより、エラーメッセージの一部として非常に読みやすい形式で提供されます。
    *   この関数が`html/template`からも呼び出せるように、公開（エクスポート）されました。

2.  **`Execute()` メソッドの簡素化**:
    *   `Execute()` メソッド内のエラーパスで、不完全なテンプレートを検出した場合の処理が簡素化されました。
    *   以前はここで定義済みテンプレートのリストを構築していましたが、今後は単に`t.DefinedTemplates()`を呼び出すだけで、必要な情報を含む文字列を取得できるようになりました。
    *   これにより、`Execute()`のコードがよりクリーンになり、ロジックの重複が排除されました。

### `src/html/template/template.go` における変更

1.  **`escape()` メソッドでの不完全テンプレートチェック**:
    *   `html/template`の`escape()`メソッドは、テンプレートが実行される前に、その内容をHTMLエスケープするための重要なステップです。
    *   このメソッドの冒頭に、`if t.Tree == nil`というチェックが追加されました。
    *   `t.Tree`は、テンプレートのパースされた構造を表すフィールドです。もしこれが`nil`であれば、そのテンプレートは名前だけが定義されており、実際の内容がパースされていない「不完全なテンプレート」であることを意味します。
    *   **クラッシュの防止**: 以前は、この`t.Tree`が`nil`であるにもかかわらず、エスケープ処理が続行され、`nil`ポインタ参照などが発生してクラッシュしていました。この明示的なチェックにより、クラッシュが未然に防がれます。
    *   **適切なエラーメッセージの生成**: `t.Tree`が`nil`の場合、`fmt.Errorf`を使用してエラーを生成します。この際、`t.Name()`で現在のテンプレート名を取得し、さらに`t.text.DefinedTemplates()`を呼び出します。
        *   `t.text`は、`html/template.Template`が内部に持つ`text/template.Template`のインスタンスです。
        *   `t.text.DefinedTemplates()`を呼び出すことで、`text/template`側で定義されているテンプレートのリストを文字列として取得し、それをエラーメッセージに含めることができます。
        *   これにより、エラーメッセージは「`template: "undefined" is an incomplete or empty template; defined templates are: "main"`」のように、どのテンプレートが不完全であるか、そして他にどのテンプレートが定義されているかという、非常に役立つ情報を提供するようになります。

### `src/html/template/escape_test.go` における変更

1.  **`TestErrorOnUndefined` テストの追加**:
    *   このテストは、修正が正しく機能していることを検証するためのものです。
    *   `tmpl := New("undefined")`で、内容がパースされていない不完全なテンプレートを作成します。
    *   `err := tmpl.Execute(nil, nil)`を呼び出し、この不完全なテンプレートを実行しようとします。
    *   テストは、`err`が`nil`ではないこと（つまり、エラーが返されたこと）と、エラーメッセージが「incomplete」という文字列を含むことをアサートします。これにより、クラッシュが修正され、期待されるエラーメッセージが返されるようになったことが確認されます。

これらの変更は、Goのテンプレートパッケージの堅牢性を高め、開発者体験を向上させる上で重要な役割を果たしています。特に、セキュリティが重視される`html/template`において、予期せぬクラッシュを防ぎ、より明確なエラーハンドリングを可能にした点は大きな改善です。
