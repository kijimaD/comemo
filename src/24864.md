## 変更の背景

GoコンパイラのSSAバックエンドは、コードの最適化において重要な役割を担っています。コンパイラの性能をプロファイリングし、ボトルネックを特定するためには、各最適化パスがどれくらいの時間とリソースを消費しているかを詳細に把握することが不可欠です。

このコミット以前は、SSAパスの統計情報には主に実行時間と総メモリ割り当てバイト数が含まれていました。しかし、メモリ割り当ての「回数」もまた、パフォーマンス分析において重要な指標となります。例えば、多数の小さなオブジェクトを頻繁に割り当てることは、ガベージコレクションの負荷を増大させ、全体的な実行速度に悪影響を与える可能性があります。総バイト数が少なくても、割り当て回数が多い場合は最適化の余地があることを示唆します。

この変更は、コンパイラ開発者がSSAパスのメモリ使用パターンをより深く理解し、メモリ割り当ての最適化を通じてコンパイラ自体の性能を向上させるための、より詳細な情報を提供することを目的としています。また、HTMLレポートでの表示改善は、この追加された情報が開発者にとって読みやすく、分析しやすいようにするためのユーザビリティ向上の一環です。

## 前提知識の解説

### GoコンパイラのSSAバックエンド

Goコンパイラは、ソースコードを中間表現に変換し、様々な最適化を適用してから最終的な機械語コードを生成します。その中間表現の一つに「SSA (Static Single Assignment)」形式があります。SSA形式は、各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。GoコンパイラのSSAバックエンドは、このSSA形式を用いて、レジスタ割り当て、不要なコードの削除、共通部分式の除去など、多くの高度な最適化を実行します。

### `runtime.MemStats`

Go言語の`runtime`パッケージには、プログラムのメモリ使用状況に関する統計情報を提供する`MemStats`構造体が含まれています。この構造体は、`runtime.ReadMemStats`関数を呼び出すことで現在のメモリ統計情報を取得するために使用されます。
`MemStats`には以下のようなフィールドがあります。

*   `TotalAlloc`: ヒープに割り当てられたオブジェクトの総バイト数（解放されたものも含む）。
*   `Mallocs`: ヒープ割り当ての総回数。
*   `Frees`: ヒープ解放の総回数。
*   `HeapAlloc`: 現在ヒープに割り当てられているオブジェクトのバイト数。
*   `HeapSys`: ヒープのためにOSから取得したメモリのバイト数。

このコミットでは、`TotalAlloc`と`Mallocs`が特に重要です。`TotalAlloc`の差分は「割り当てられた総バイト数」を示し、`Mallocs`の差分は「割り当て操作の総回数」を示します。

### コンパイラパスとプロファイリング

コンパイラは通常、複数の「パス」と呼ばれる段階を経てコードを処理します。各パスは特定の最適化や変換を担当します。コンパイラの性能を分析する際には、どのパスが最も時間を消費しているか、どのパスが多くのメモリを割り当てているかを特定することが重要です。これにより、最適化の努力を集中すべき箇所を判断できます。

### HTMLレポート

Goコンパイラには、デバッグやプロファイリングのために、SSA形式のグラフや統計情報をHTML形式で出力する機能があります。これは、コンパイラの内部動作を視覚的に理解するのに役立ちます。

## 技術的詳細

このコミットの技術的な核心は、`runtime.MemStats`から取得できる2つの異なるメモリ指標（総割り当てバイト数と割り当て回数）を区別し、それらをSSAパスの統計情報に含める点にあります。

1.  **メモリ統計の取得**:
    `src/cmd/compile/internal/ssa/compile.go`内の`Compile`関数において、各SSAパスの開始時と終了時に`runtime.ReadMemStats`を呼び出し、`mStart`と`mEnd`という`runtime.MemStats`構造体にスナップショットを保存します。

2.  **指標の計算**:
    *   `nBytes := mEnd.TotalAlloc - mStart.TotalAlloc`: これは、パスの実行中にヒープに割り当てられたメモリの総バイト数を示します。
    *   `nAllocs := mEnd.Mallocs - mStart.Mallocs`: これは、パスの実行中に発生したメモリ割り当て操作の総回数を示します。

    以前は`mEnd.TotalAlloc - mStart.TotalAlloc`の結果を`nAllocs`という変数名で扱っていましたが、これは実質的に「バイト数」を意味していました。今回の変更で、変数名を`nBytes`に修正し、新たに`Mallocs`の差分を`nAllocs`として導入することで、より正確な意味付けを行っています。

3.  **統計情報のフォーマット**:
    統計情報の文字列は、`fmt.Sprintf`を用いて以下のように変更されました。
    変更前: `[%d ns %d bytes]` (時間と総バイト数)
    変更後: `[%d ns %d allocs %d bytes]` (時間、割り当て回数、総バイト数)
    これにより、各パスの実行時間、割り当て回数、割り当てバイト数が一目でわかるようになります。

4.  **HTML表示の改善**:
    `src/cmd/compile/internal/ssa/compile.go`では、HTMLレポートに統計情報を書き出す際に、新しく追加された統計文字列を`<span class="stats">...</span>`で囲むように変更されました。
    これに対応して、`src/cmd/compile/internal/ssa/html.go`には、`.stats`クラスに対するCSSルールが追加されました。
    ```css
    .stats {
        font-size: 60%;
    }
    ```
    このCSSルールにより、統計情報が他のテキストよりも小さく表示され、レポート全体の可読性が向上します。特に、詳細な統計情報が追加されたことで文字列が長くなるため、視覚的な整理が重要になります。

これらの変更により、コンパイラ開発者はSSAパスのパフォーマンス特性をより多角的に分析できるようになり、メモリ効率の改善に向けた具体的な手がかりを得ることができます。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/compile.go` の変更

1.  **メモリ統計の計算ロジックの変更**:
    *   `nAllocs := mEnd.TotalAlloc - mStart.TotalAlloc` が `nBytes := mEnd.TotalAlloc - mStart.TotalAlloc` に変更されました。これは、変数名がその内容（割り当てられたバイト数）をより正確に反映するように修正されたものです。
    *   `nAllocs := mEnd.Mallocs - mStart.Mallocs` が新しく追加されました。これにより、`runtime.MemStats.Mallocs`フィールドの差分から、各SSAパスで発生したメモリ割り当て操作の回数が正確に取得されるようになりました。

2.  **統計情報文字列のフォーマット変更**:
    *   `stats = fmt.Sprintf("[%d ns %d bytes]", time, nAllocs)` が `stats = fmt.Sprintf("[%d ns %d allocs %d bytes]", time, nAllocs, nBytes)` に変更されました。これにより、統計情報には実行時間（ナノ秒）、割り当て回数（`allocs`）、および割り当てバイト数（`bytes`）の3つの主要な指標が含まれるようになりました。

3.  **HTML出力の変更**:
    *   `f.Config.HTML.WriteFunc(fmt.Sprintf("after %s %s", phaseName, stats), f)` が `f.Config.HTML.WriteFunc(fmt.Sprintf("after %s <span class=\"stats\">%s</span>", phaseName, stats), f)` に変更されました。これは、生成されるHTML内で統計情報文字列が`<span class="stats">`タグで囲まれるようにするための変更です。このタグは、後述のCSSルールと連携して、統計情報の表示スタイルを制御します。

### `src/cmd/compile/internal/ssa/html.go` の変更

1.  **CSSルールの追加**:
    *   `.stats`クラスに対する新しいCSSルールが追加されました。
    ```css
    .stats {
    	font-size: 60%;
    }
    ```
    このルールは、`class="stats"`を持つHTML要素（`compile.go`で追加された`<span>`タグ）のフォントサイズを、親要素の60%に縮小することを指示します。これにより、詳細な統計情報が追加されても、HTMLレポートが過度に冗長にならず、主要な情報（例えば、パス名）が際立つように視覚的に調整されます。

これらの変更は、GoコンパイラのSSAバックエンドのプロファイリングとデバッグ能力を向上させ、開発者がコンパイラのパフォーマンスボトルネックをより効果的に特定し、最適化を進めるための重要なツールを提供します。
