## 元コミット内容

このコミットは、`cmd/compile`と`cmd/link`のドキュメントを追加し、Go 1.5向けにGo 1.4のドキュメントを更新したものです。特に、Plan 9ツールチェインへのすべての参照が削除され、GoツールがもはやPlan 9ツールチェインと意味のある類似性を持たないことが強調されています。

## 変更の背景

Go言語の初期のツールチェインは、ベル研究所で開発されたオペレーティングシステムであるPlan 9のツールチェインに強く影響を受けていました。特に、Goのコンパイラ（`8g`, `6g`, `5g`など、ターゲットアーキテクチャごとに異なる名前を持っていた）やリンカ（`8l`, `6l`, `5l`など）は、Plan 9のCコンパイラやリンカの設計思想やコマンドラインオプションを継承していました。

しかし、Go言語が進化し、より多くのプラットフォームをサポートし、独自の最適化や機能が追加されるにつれて、Plan 9ツールチェインとの直接的な関連性は薄れていきました。Go 1.5は、Go言語の歴史において重要なマイルストーンとなるリリースであり、セルフホスト化（GoコンパイラがGo自身で書かれるようになった）や、ガベージコレクタの改善など、多くの大きな変更が導入されました。

このコミットは、Go 1.5のリリースに向けて、ドキュメントを最新の状態に保ち、もはや関連性のないPlan 9ツールチェインへの言及を削除することで、Goツールチェインの独立性と成熟を反映することを目的としています。これにより、ユーザーはGoツールチェインを理解する上で、過去の歴史的な背景に惑わされることなく、現在のGoツールチェインの機能と動作に集中できるようになります。

## 前提知識の解説

*   **Goツールチェイン**: Go言語のプログラムを開発、ビルド、実行するために必要な一連のツール群（コンパイラ、リンカ、アセンブラ、デバッガなど）を指します。
*   **`go tool compile`**: Goソースコードをオブジェクトファイルにコンパイルするコマンドです。Go 1.5以前は、ターゲットアーキテクチャに応じて`go tool 8g`（amd64用）、`go tool 6g`（386用）などのように呼ばれていました。
*   **`go tool link`**: コンパイルされたオブジェクトファイルやアーカイブファイルを結合し、実行可能なバイナリを生成するコマンドです。Go 1.5以前は、ターゲットアーキテクチャに応じて`go tool 8l`、`go tool 6l`などのように呼ばれていました。
*   **Plan 9**: ベル研究所で開発された分散オペレーティングシステムです。Go言語の設計者の一部（Ken Thompson, Rob Pikeなど）はPlan 9の開発にも携わっており、Go言語の設計思想や初期のツールチェインに大きな影響を与えました。
*   **`doc.go`ファイル**: Goのパッケージやコマンドのドキュメントを記述するための慣習的なファイルです。このファイルに記述されたコメントは、`go doc`コマンドやGoの公式ドキュメントサイトで表示されます。
*   **セルフホスト化 (Self-hosting)**: コンパイラが自身の言語で書かれている状態を指します。Go 1.5でGoコンパイラがGo言語自身で書かれるようになり、Goツールチェインの独立性がさらに高まりました。

## 技術的詳細

このコミットの主要な技術的変更は、`src/cmd/compile/doc.go`と`src/cmd/link/doc.go`という2つの新しいファイルが追加されたことです。これらのファイルは、それぞれ`go tool compile`と`go tool link`コマンドの公式ドキュメントとして機能します。

`doc.go`ファイルには、以下の情報が含まれています。

*   **`go tool compile`**:
    *   コンパイラの基本的な機能（単一のGoパッケージをコンパイルし、オブジェクトファイルを生成する）。
    *   `-pack`オプションを使用すると、中間オブジェクトファイルを介さずに直接アーカイブファイルを生成できること。
    *   生成されるファイルには、エクスポートされたシンボルやインポートされた型に関する型情報が含まれること。
    *   コマンドラインの使用法（`go tool compile [flags] file...`）。
    *   主要なフラグとその説明（例: `-D`, `-I`, `-L`, `-N`, `-S`, `-V`, `-o`, `-race`など）。
    *   コンパイラディレクティブ（`//line`, `//go:noescape`, `//go:nosplit`, `//go:linkname`）とその機能。これらのディレクティブは、コンパイラに特定の動作を指示するために使用され、特に低レベルのランタイムコードや最適化において重要です。
*   **`go tool link`**:
    *   リンカの基本的な機能（パッケージのGoアーカイブまたはオブジェクトファイルとその依存関係を読み込み、実行可能なバイナリに結合する）。
    *   コマンドラインの使用法（`go tool link [flags] main.a`）。
    *   主要なフラグとその説明（例: `-B`, `-D`, `-E`, `-H`, `-I`, `-L`, `-T`, `-V`, `-X`, `-buildmode`, `-cpuprofile`, `-d`, `-extld`, `-extldflags`, `-installsuffix`, `-linkmode`, `-linkshared`, `-memprofile`, `-o`, `-r`, `-race`, `-s`, `-shared`, `-tmpdir`, `-v`, `-w`など）。

また、`src/cmd/compile/internal/gc/lex.go`には、出力ファイル名のサフィックスを決定するロジックに小さな変更が加えられています。具体的には、`-pack`オプションが指定された場合に、出力ファイルのサフィックスが`.o`（オブジェクトファイル）ではなく`.a`（アーカイブファイル）になるように修正されています。これは、`doc.go`で説明されている`-pack`オプションの動作と一致させるための変更です。

Plan 9ツールチェインへの参照の削除は、Goツールチェインが独自の進化を遂げ、もはやPlan 9の設計に直接依存していないことを明確にするための重要なステップです。これにより、Goのコンパイラやリンカは、より現代的なシステムやアーキテクチャの要件に合わせて最適化され、独立したツールとして機能するようになりました。

## コアとなるコードの解説

### `src/cmd/compile/doc.go` および `src/cmd/link/doc.go`

これらのファイルは、Goツールチェインのコンパイラとリンカの公式ドキュメントとして機能します。Go言語では、`doc.go`ファイルにパッケージレベルのドキュメンテーションコメントを記述する慣習があり、これは`go doc`コマンドやGoの公式ドキュメントサイトで自動的に抽出・表示されます。

これらのドキュメントは、Go 1.5のユーザーが`go tool compile`と`go tool link`の機能、コマンドラインオプション、および特別なディレクティブを理解するための包括的なリファレンスを提供します。特に、`//go:noescape`, `//go:nosplit`, `//go:linkname`といったコンパイラディレクティブの解説は、Goのランタイムや低レベルのコードを理解する上で非常に重要です。

*   **`//go:noescape`**: このディレクティブは、続く関数宣言が、引数として渡されたポインタをヒープにエスケープさせたり、関数から返される値に含めたりしないことをコンパイラに伝えます。これは、コンパイラの「エスケープ解析」を支援し、不要なヒープアロケーションを削減してパフォーマンスを向上させるために使用されます。
*   **`//go:nosplit`**: このディレクティブは、続く関数がスタックオーバーフローチェックを含まないことを指定します。これは、Goランタイムの低レベル部分でよく使用され、特にゴルーチンがプリエンプトされるのが安全でない状況で呼び出される関数に適用されます。スタックチェックを省略することで、オーバーヘッドを削減し、クリティカルなセクションでの実行を高速化します。
*   **`//go:linkname`**: このディレクティブは、ソースコード内の`localname`として宣言された変数または関数に対して、オブジェクトファイルシンボル名として`importpath.name`を使用するようにコンパイラに指示します。このディレクティブは、型システムやパッケージのモジュール性を迂回する可能性があるため、`"unsafe"`パッケージをインポートしているファイルでのみ有効です。主に、GoのランタイムとGo以外のコード（アセンブリなど）との間のリンケージを確立するために使用されます。

### `src/cmd/compile/internal/gc/lex.go` の変更

この変更は、`go tool compile`コマンドの`-pack`オプションの動作を正確に反映させるためのものです。

`mkpackage`関数は、コンパイルされたパッケージの出力ファイル名を決定する役割を担っています。変更前は、常に`.o`サフィックス（オブジェクトファイル）を使用していましたが、`-pack`オプションが指定された場合（`writearchive > 0`）、コンパイラはオブジェクトファイルではなくパッケージアーカイブファイルを生成します。このアーカイブファイルは、通常`.a`サフィックスを持ちます。

このコミットでは、`writearchive`変数の値に基づいて、出力ファイルのサフィックスを動的に`.o`または`.a`に設定するようにロジックが修正されました。これにより、コンパイラの実際の動作と、新しく追加された`doc.go`ファイルでの`-pack`オプションの説明との間に一貫性が保たれます。
