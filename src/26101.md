# [インデックス 26101] ファイルの概要

このコミットは、Go言語の標準ライブラリ `archive/tar` パッケージにおける `Reader.Read` メソッドの振る舞いに関するドキュメントの追加です。特に、`TypeLink`、`TypeSymLink`、`TypeChar`、`TypeBlock`、`TypeDir`、`TypeFifo` といった特殊なファイルタイプ（ヘッダーのみでデータを持たないファイル）に対して `Reader.Read` が常に `0, io.EOF` を返すという重要な挙動を明示的に記述することで、APIの明確性を向上させています。これは、以前のコミットで導入された動作変更をユーザーに正しく伝えるためのものです。

## 変更の背景

このコミットの背景には、`archive/tar` パッケージにおける `Reader.Read` メソッドの以前の挙動変更があります。具体的には、コミット `dd5e14a7511465d20c6e95bf54c9b8f999abbbf6` (タイトル: "archive/tar: properly handle header-only \"files\" in Reader") によって、tarアーカイブ内の特定の特殊なエントリタイプ（例: シンボリックリンク、ディレクトリなど）がヘッダーのみであり、データセクションを持たない場合でも、`Header.Size` フィールドがゼロ以外の値を指していると、`Reader` が誤ってデータ読み込みを試みる可能性があった問題が修正されました。

この修正により、`TypeLink`, `TypeSymLink`, `TypeChar`, `TypeBlock`, `TypeDir`, `TypeFifo` といったヘッダーのみのファイルタイプに対しては、`Header.Size` の値に関わらず `Reader.Read` が常に `0, io.EOF` を返すようになりました。このコミットは、この重要な動作変更を公式ドキュメントに明記し、ユーザーがAPIの挙動を正しく理解できるようにすることを目的としています。これにより、予期せぬデータ読み込みの試みや、それによるエラーを防ぎ、APIの堅牢性と予測可能性を高めています。

## 前提知識の解説

*   **`archive/tar` パッケージ**: Go言語の標準ライブラリの一部で、tarアーカイブ（テープアーカイブ）の読み書きをサポートします。tarファイルは、複数のファイルを一つのアーカイブにまとめるための一般的な形式です。
*   **`tar` アーカイブ形式**: ファイルのメタデータ（ファイル名、パーミッション、サイズ、タイプなど）とファイルデータが連続して格納される形式です。ファイルタイプには、通常のファイル (`TypeReg`) の他に、ディレクトリ (`TypeDir`)、ハードリンク (`TypeLink`)、シンボリックリンク (`TypeSymLink`)、デバイスファイル (`TypeChar`, `TypeBlock`)、FIFO (`TypeFifo`) など、様々な特殊なタイプが存在します。
*   **`Reader.Read` メソッド**: `archive/tar` パッケージの `Reader` 型が提供するメソッドで、現在のtarエントリのデータ部分を読み込むために使用されます。Go言語の `io.Reader` インターフェースを実装しており、バイトスライス `b` にデータを読み込み、読み込んだバイト数 `n` とエラー `err` を返します。エントリの終わりに達すると `0, io.EOF` を返します。
*   **`io.EOF`**: `io` パッケージで定義されているエラー定数で、入力の終わりに達したことを示します。`Read` メソッドが `io.EOF` を返した場合、それ以上読み込むデータがないことを意味します。
*   **`Header.Size`**: `archive/tar` パッケージの `Header` 構造体に含まれるフィールドで、現在のtarエントリのデータ部分のサイズ（バイト単位）を示します。通常のファイルでは実際のファイルサイズが格納されますが、特殊なファイルタイプ（例: ディレクトリやシンボリックリンク）では、仕様上はゼロであるべきですが、非準拠のアーカイブではゼロ以外の値が設定されている場合があります。
*   **特殊なファイルタイプ**:
    *   `TypeLink` (ハードリンク): 既存のファイルへの別の名前。データは持たない。
    *   `TypeSymLink` (シンボリックリンク): 別のファイルへの参照。データは持たない。
    *   `TypeChar` (キャラクタースペシャルファイル): キャラクターデバイス（例: ターミナル）を表す。データは持たない。
    *   `TypeBlock` (ブロックスペシャルファイル): ブロックデバイス（例: ディスクドライブ）を表す。データは持たない。
    *   `TypeDir` (ディレクトリ): ディレクトリ。データは持たない。
    *   `TypeFifo` (FIFO): 名前付きパイプ。データは持たない。
    これらのタイプは、ファイルシステム上の実体を参照したり、特別な機能を提供したりするものであり、tarアーカイブ内に直接データコンテンツを持つことはありません。

## 技術的詳細

このコミットは、`archive/tar` パッケージの `Reader.Read` メソッドのドキュメンテーションを更新するものです。以前のコミット `dd5e14a7511465d20c6e95bf54c9b8f999abbbf6` によって、`Reader` が特殊なファイルタイプ（`TypeLink`, `TypeSymLink`, `TypeChar`, `TypeBlock`, `TypeDir`, `TypeFifo`）を処理する際に、`Header.Size` フィールドの値に関わらず、データ読み込みを試みないように変更されました。これは、これらのファイルタイプがデータコンテンツを持たないというtarアーカイブの仕様に準拠するための修正でした。

本コミットでは、この修正によって確立された挙動をAPIドキュメントに明記しています。具体的には、`Reader.Read` のコメントブロックに以下の記述が追加されました。

```go
// Calling Read on special types like TypeLink, TypeSymLink, TypeChar,
// TypeBlock, TypeDir, and TypeFifo returns 0, io.EOF regardless of what
// the Header.Size claims.
```

この変更は、コードの動作自体を変更するものではなく、その動作を明確に文書化することで、ライブラリの利用者に対して、これらの特殊なファイルタイプからデータを読み込もうとしても常に `0, io.EOF` が返されることを保証し、誤解やバグの発生を防ぐことを目的としています。これにより、`archive/tar` パッケージのAPI契約がより明確になり、開発者は安心してこれらのファイルタイプを扱うことができるようになります。

## コアとなるコードの解説

追加された4行のコメントは、`Reader.Read` メソッドの既存のドキュメンテーションに追記されています。

```go
// Calling Read on special types like TypeLink, TypeSymLink, TypeChar,
// TypeBlock, TypeDir, and TypeFifo returns 0, io.EOF regardless of what
// the Header.Size claims.
```

このコメントは、`Reader.Read` が特定の特殊なtarエントリタイプ（`TypeLink`, `TypeSymLink`, `TypeChar`, `TypeBlock`, `TypeDir`, `TypeFifo`）に対してどのように振る舞うかを明確に説明しています。これらのタイプは、tarアーカイブの仕様上、データコンテンツを持たないため、`Read` メソッドが呼び出されても常に `0` バイトを読み込み、`io.EOF` エラーを返すことが保証されます。この挙動は、たとえ `Header.Size` フィールドがゼロ以外の値を報告していたとしても変わらない、という点が強調されています。

このドキュメントの追加は、APIの利用者にとって非常に重要です。これにより、開発者はこれらの特殊なファイルタイプを処理する際に、データ読み込みの試みが無意味であり、常に `io.EOF` が返されることを事前に知ることができます。これは、コードの予測可能性を高め、不必要なエラーハンドリングや誤ったロジックの実装を防ぐのに役立ちます。
