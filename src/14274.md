## 元コミット内容

`runtime: add memorydump() debugging function`

このコミットは、Goランタイムに`memorydump()`というデバッグ関数を追加します。

## 変更の背景

Go言語のランタイムは、メモリ管理（特にガベージコレクション）を自動的に行いますが、複雑なアプリケーションではメモリリークや予期せぬメモリ使用量の増加が発生することがあります。このような問題を診断するためには、ランタイムがどのようにメモリを管理しているかを詳細に可視化するツールが必要になります。

この`memorydump()`関数は、Goランタイムの内部的なメモリ構造、特にヒープの割り当て状況をダンプすることで、開発者がメモリ関連の問題をデバッグする手助けをすることを目的としています。これにより、どのオブジェクトがどこに割り当てられているか、ガベージコレクタがどのようにメモリを認識しているかなどを、より低レベルで確認できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムのメモリ管理に関する基本的な概念を理解しておく必要があります。

*   **ヒープ (Heap)**: Goプログラムが動的にメモリを割り当てる領域です。`make`や`new`で作成されるオブジェクトはヒープに割り当てられます。
*   **ガベージコレクション (Garbage Collection, GC)**: Goランタイムが自動的に不要になったヒープメモリを解放するプロセスです。開発者は手動でメモリを解放する必要がありません。
*   **MSpan**: Goランタイムのメモリ管理において、ヒープはページ (通常8KB) の集まりとして管理されます。`MSpan`は、連続したページ群を表す構造体で、特定のサイズのオブジェクトを割り当てるために使用されます。`MSpan`は、そのページが現在使用中であるか、空いているか、または特定のサイズのオブジェクトのために予約されているかなどの状態を持ちます。
*   **アリーナ (Arena)**: GoランタイムがOSから取得する大きな連続したメモリ領域です。このアリーナがさらにページに分割され、`MSpan`によって管理されます。
*   **ビットマップ (Bitmap)**: Goランタイムは、ヒープ内の各オブジェクトの割り当て状態や、ポインタの有無などを追跡するためにビットマップを使用します。これにより、ガベージコレクタはヒープを効率的にスキャンし、到達可能なオブジェクトを特定できます。`bitAllocated`や`bitSpecial`といったフラグは、このビットマップの一部であり、それぞれメモリが割り当てられているか、特別な意味を持つか（例えば、ファイナライザを持つオブジェクトなど）を示します。
*   **PageShift**: ページサイズをビットシフトで表現するための定数です。例えば、ページサイズが8KB (2^13バイト) ならば、`PageShift`は13になります。
*   **sizeclass**: Goランタイムは、異なるサイズのオブジェクトに対して、効率的なメモリ割り当てを行うために、いくつかの「サイズクラス」を定義しています。これにより、小さなオブジェクトの割り当てが高速化され、メモリの断片化が抑制されます。

## 技術的詳細

`memorydump()`関数は、Goランタイムの内部構造を直接読み取り、ヒープの割り当て状況を詳細に出力します。その主要な処理は以下の通りです。

1.  **`runtime·mheap.allspans`の走査**: Goランタイムのグローバルなヒープ構造体`runtime·mheap`には、すべての`MSpan`を管理する`allspans`という配列があります。`memorydump()`は、この配列を`spanidx`でループし、各`MSpan`を検査します。
2.  **`MSpanInUse`の確認**: 各`MSpan`について、その`state`が`MSpanInUse`であるかどうかを確認します。`MSpanInUse`は、その`MSpan`が現在オブジェクトの割り当てに使用されていることを意味します。使用中でない`MSpan`はスキップされます。
3.  **`dumpspan()`の呼び出し**: 使用中の各`MSpan`に対して、ヘルパー関数である`dumpspan()`が呼び出されます。
4.  **`dumpspan()`の処理**:
    *   `MSpan`の開始アドレス(`s->start << PageShift`)と終了アドレスを計算し、その範囲を出力します。
    *   `sizeclass`と`elemsize`（その`MSpan`が割り当てる要素のサイズ）に基づいて、その`MSpan`内の要素数`n`を計算します。
    *   `MSpan`内の各要素（オブジェクト）をループで処理します。
    *   **ビットマップの読み取り**: 各要素のアドレス`p`から、`arena_start`（アリーナの開始アドレス）とのオフセットを計算し、対応するビットマップのエントリを特定します。`bitp`と`shift`を使って、その要素の`bitAllocated`と`bitSpecial`フラグを読み取ります。
    *   **割り当て状態と特殊フラグの表示**: `allocated`（割り当て済み）と`special`（特殊なオブジェクト）のフラグに基づいて、出力に`(`または`[`、そして`@`を追加します。
    *   **ポインタ値の表示**: 各要素の内部を`sizeof(void*)`（ポインタのサイズ）単位で走査し、その位置にあるポインタの値を`%p`フォーマットで出力します。これにより、オブジェクトが他のオブジェクトを指している場合、その参照関係を視覚的に確認できます。
    *   整形された出力: `column`変数を使って、1行に8つのポインタ値が表示されるように整形し、可読性を高めています。

この関数は、Goランタイムの非常に低レベルな部分にアクセスし、メモリの物理的な配置と論理的な割り当て状態を詳細に表示することで、メモリリークの原因特定や、ガベージコレクタの動作理解に役立ちます。

### `src/pkg/runtime/mgc0.c`

#### `dumpspan` 関数

```c
static void
dumpspan(uint32 idx)
{
    // ... (変数の宣言と初期化) ...

    s = runtime·mheap.allspans[idx];
    if(s->state != MSpanInUse)
        return; // 使用中のMSpanのみを処理

    // MSpanの開始アドレスと終了アドレスを計算し、出力
    p = (byte*)(s->start << PageShift);
    sizeclass = s->sizeclass;
    size = s->elemsize;
    if(sizeclass == 0) { // sizeclassが0の場合は特別な扱い（大きなオブジェクトなど）
        n = 1;
    } else {
        npages = runtime·class_to_allocnpages[sizeclass];
        n = (npages << PageShift) / size; // MSpan内の要素数を計算
    }
    
    runtime·printf("%p .. %p:\n", p, p+n*size); // MSpanのメモリ範囲を出力

    column = 0;
    for(; n>0; n--, p+=size) { // MSpan内の各要素をループ
        uintptr off, *bitp, shift, bits;

        // ビットマップから割り当て状態と特殊フラグを読み取る
        off = (uintptr*)p - (uintptr*)arena_start;
        bitp = (uintptr*)arena_start - off/wordsPerBitmapWord - 1;
        shift = off % wordsPerBitmapWord;
        bits = *bitp>>shift;

        allocated = ((bits & bitAllocated) != 0); // 割り当て済みか
        special = ((bits & bitSpecial) != 0);     // 特殊なオブジェクトか

        for(i=0; i<size; i+=sizeof(void*)) { // 要素内のポインタを走査
            if(column == 0) {
                runtime·printf("\t");
            }
            if(i == 0) { // 要素の開始時
                runtime·printf(allocated ? "(" : "["); // 割り当て状態を示す括弧
                runtime·printf(special ? "@" : "");    // 特殊フラグを示す@
                runtime·printf("%p: ", p+i);           // 要素の開始アドレス
            } else {
                runtime·printf(" ");
            }

            runtime·printf("%p", *(void**)(p+i)); // ポインタの値を表示

            if(i+sizeof(void*) >= size) { // 要素の終了時
                runtime·printf(allocated ? ") " : "] "); // 括弧を閉じる
            }

            column++;
            if(column == 8) { // 8列ごとに改行
                runtime·printf("\n");
                column = 0;
            }
        }
    }
    runtime·printf("\n");
}
```
`dumpspan`関数は、特定の`MSpan`のメモリ内容を詳細にダンプする役割を担います。
*   `s->state != MSpanInUse`のチェックにより、現在使用中の`MSpan`のみが処理の対象となります。
*   `sizeclass`と`elemsize`を用いて、その`MSpan`が管理するオブジェクトのサイズと数を計算します。
*   ループ内で、各オブジェクトの開始アドレスから、対応するメモリビットマップを読み取り、そのオブジェクトが割り当て済みであるか（`allocated`）、または特別な意味を持つか（`special`）を判断します。
*   オブジェクトの内部をポインタサイズ(`sizeof(void*)`)ごとに走査し、その位置にあるポインタの値を16進数で出力します。これにより、オブジェクトが指し示す他のメモリ領域（他のオブジェクトなど）を視覚的に確認できます。
*   出力は整形され、割り当て状態を示す括弧`()`または`[]`、特殊フラグを示す`@`、そしてアドレスとポインタ値が分かりやすく表示されます。

#### `runtime·memorydump` 関数

```c
// A debugging function to dump the contents of memory
void
runtime·memorydump(void)
{
	uint32 spanidx;

	for(spanidx=0; spanidx<runtime·mheap.nspan; spanidx++) {
		dumpspan(spanidx);
	}
}
```
`runtime·memorydump`関数は、Goランタイムのヒープ全体をダンプするためのエントリポイントです。
*   `runtime·mheap.nspan`は、Goランタイムが管理する`MSpan`の総数を表します。
*   この関数は、`spanidx`を0から`runtime·mheap.nspan - 1`までループさせ、各`MSpan`のインデックスを`dumpspan`関数に渡します。
*   これにより、ヒープ内のすべての使用中の`MSpan`が順にダンプされ、Goプログラムのメモリ使用状況の全体像が提供されます。
