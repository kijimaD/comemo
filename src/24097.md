# [インデックス 24097] ファイルの概要

このコミットは、Go 1.5のリリースノートドキュメント `doc/go1.5.html` における誤植を修正するものです。具体的には、スタックポインタとして `R13` レジスタを使用するアーキテクチャに関する記述で、「x86」と誤って記載されていた箇所を「ARM」に訂正しています。これは、Goコンパイラが特定のレジスタをスタックポインタとして扱う際の規則に関する重要な技術的詳細の正確性を確保するための修正です。

## 変更の背景

この変更は、Go 1.5のリリースノートドキュメント `doc/go1.5.html` 内の技術的な記述の正確性を向上させるために行われました。Go 1.5では、コンパイラとアセンブラの内部的な変更が多数導入されており、特にレジスタの扱いに関する規則が厳格化されました。このドキュメントは、これらの変更が開発者に与える影響を説明するものであり、その内容が正確であることは非常に重要です。

元の記述では、`R13` レジスタがスタックポインタとして機能するアーキテクチャとして「x86」が挙げられていましたが、これは誤りでした。実際には、ARMアーキテクチャにおいて `R13` はスタックポインタ (SP) として慣習的に使用されるレジスタです。x86アーキテクチャでは、スタックポインタは通常 `ESP` (32ビット) または `RSP` (64ビット) と呼ばれる専用のレジスタが使用されます。この誤植は、読者がGoのアセンブラや低レベルのコードを理解する上で混乱を招く可能性があったため、修正が必要とされました。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

1.  **Go 1.5の変更点**: Go 1.5は、Go言語の歴史において非常に重要なリリースでした。このバージョンで、Goコンパイラは完全にGo言語自身で記述されるようになり（ブートストラップ）、また、ガベージコレクタのレイテンシが大幅に改善されました。さらに、アセンブラの内部的な変更も行われ、特にレジスタの参照方法に関する規則が厳格化されました。
2.  **アセンブラとレジスタ**: アセンブラは、CPUが直接実行できる機械語に近い低レベルのプログラミング言語です。CPUには、データを一時的に保持するための「レジスタ」と呼ばれる高速な記憶領域があります。これらのレジスタは、特定の目的（例: 汎用レジスタ、スタックポインタ、プログラムカウンタなど）に割り当てられることがあります。
3.  **スタックポインタ (SP)**: スタックポインタは、プログラムの実行中に使用される「スタック」と呼ばれるメモリ領域の現在の最上位（または最下位、アーキテクチャによる）を指し示すレジスタです。関数呼び出し時の引数やローカル変数、戻りアドレスなどがスタックにプッシュ（追加）されたり、ポップ（削除）されたりする際に、スタックポインタが更新されます。
4.  **プログラムカウンタ (PC)**: プログラムカウンタは、次に実行される命令のアドレスを保持するレジスタです。
5.  **x86アーキテクチャ**: IntelやAMDのCPUに代表される、広く普及しているコンピュータアーキテクチャです。スタックポインタには `ESP` (Extended Stack Pointer) や `RSP` (Register Stack Pointer) が使用されます。
6.  **ARMアーキテクチャ**: スマートフォンや組み込みシステムで広く使用されているCPUアーキテクチャです。ARMでは、`R0` から `R12` までの汎用レジスタに加え、`R13` がスタックポインタ (SP)、`R14` がリンクレジスタ (LR)、`R15` がプログラムカウンタ (PC) として慣習的に使用されます。
7.  **Goのアセンブラ**: Go言語は、特定のパフォーマンスが要求される箇所でGoアセンブラ（Plan 9アセンブラの派生）を使用することができます。Goのアセンブラは、一般的なアセンブラとは異なる独自の構文と規則を持っています。特に、Go 1.5以降では、レジスタを直接参照する際に、シンボル（例: `SP`）を伴わない数値レジスタ名（例: `R13`）の使用が制限されるようになりました。

## 技術的詳細

Go 1.5のリリースでは、Goコンパイラとアセンブラの内部構造に大きな変更が加えられました。その一環として、アセンブラコード内でレジスタを参照する方法に関する規則が厳格化されました。

変更前のGoアセンブラでは、特定のアーキテクチャにおいて、スタックポインタやプログラムカウンタのような特殊な意味を持つレジスタを、その数値レジスタ名（例: `R13`）で直接参照することが許容されていました。しかし、Go 1.5以降では、このようなレジスタを数値レジスタ名で参照する際には、必ずシンボル（例: `SP` や `PC`）を伴う形式（例: `SP` や `4(SP)`）で記述することが義務付けられました。シンボルを伴わない数値レジスタ名での参照は、コンパイルエラーとなるようになりました。

この変更の目的は、アセンブラコードの可読性と移植性を向上させることにありました。シンボルを使用することで、レジスタの役割が明確になり、異なるアーキテクチャ間でのコードの理解が容易になります。

コミットが修正している箇所は、この新しい規則を説明するドキュメントの一部です。ドキュメントでは、この変更の例として「`R13` がスタックポインタ、`R15` がハードウェアプログラムカウンタであるようなマシン」について言及しています。ここで、`R13` がスタックポインタ、`R15` がプログラムカウンタとして機能するのはARMアーキテクチャの慣習であり、x86アーキテクチャではありません。x86では、スタックポインタは `ESP` や `RSP`、プログラムカウンタは `EIP` や `RIP` といった専用のレジスタ名を持ちます。

したがって、ドキュメントの「on x86」という記述は誤りであり、これを「on ARM」に修正することで、Go 1.5におけるアセンブラのレジスタ参照規則に関する説明が、対象アーキテクチャと正しく結びつけられるようになりました。これにより、Goのアセンブラコードを記述または理解しようとする開発者が、正確な情報を得られるようになります。

## コアとなるコードの解説

この変更は、HTMLドキュメント内の単一の単語の修正です。

-   `-on x86,` の行が削除され、
-   `+on ARM,` の行が追加されています。

これにより、Go 1.5のリリースノートにおいて、`R13` がスタックポインタ、`R15` がハードウェアプログラムカウンタとして機能するアーキテクチャが、誤って「x86」と記載されていた箇所が、正しい「ARM」に修正されました。この修正は、Goのアセンブラにおけるレジスタの参照規則に関する説明の正確性を保証するものです。
