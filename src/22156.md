# [インデックス 22156] ファイルの概要

このコミットは、Go言語の標準ライブラリ `image` パッケージにおいて、YCbCr色空間における新たなクロマサブサンプリング比率である `4:1:1` と `4:1:0` のサポートを追加するものです。これにより、これらの形式でエンコードされたJPEG画像などの実世界の画像データを正しく処理できるようになります。

## 変更の背景

JPEGなどの画像圧縮フォーマットでは、人間の視覚が輝度（明るさ）の変化には敏感である一方で、色相や彩度（色情報）の変化には比較的鈍感であるという特性を利用して、色情報を間引くことでデータ量を削減する「クロマサブサンプリング」という技術が広く用いられています。

Go言語の `image` パッケージは、画像データの読み込みや操作を行うための基本的な機能を提供しています。このパッケージ内の `YCbCr` 型は、YCbCr色空間の画像データを表現するために使用されます。既存の実装では、`4:4:4` (サブサンプリングなし)、`4:2:2`、`4:2:0`、`4:4:0` といった一般的なクロマサブサンプリング比率をサポートしていました。

しかし、実際のJPEG画像の中には、`4:1:1` や `4:1:0` といった、より積極的なクロマサブサンプリングが適用された形式も存在します。これらの形式の画像をGoの `image` パッケージで正しくデコードし、処理するためには、これらの新しい比率を認識し、それに応じた色成分の配置と計算ロジックを実装する必要がありました。このコミットは、そのような実世界の画像フォーマットへの対応を強化するために行われました。

## 前提知識の解説

### YCbCr色空間

YCbCrは、輝度（Y）と2つの色差成分（CbとCr）に画像を分解する色空間です。
*   **Y (Luminance)**: 画像の明るさ（輝度）を表します。人間の視覚が最も敏感な部分です。
*   **Cb (Chroma Blue)**: 青色と輝度の差を表す色差成分です。
*   **Cr (Chroma Red)**: 赤色と輝度の差を表す色差成分です。

この分離により、輝度情報を保持しつつ、色差情報を間引く（サブサンプリングする）ことが可能になり、視覚的な品質を大きく損なうことなくデータ量を削減できます。

### クロマサブサンプリング

クロマサブサンプリングは、色差成分（CbとCr）の解像度を輝度成分（Y）よりも低くすることで、画像データのサイズを削減する技術です。これは、人間の目が輝度の変化に比べて色の変化に鈍感であるという特性に基づいています。

クロマサブサンプリングの比率は、通常「J:a:b」または「J:a:b:alpha」の形式で表現されます。ここで、Jは輝度成分の水平サンプリング参照（通常4）、aは最初の行における水平方向のCb/Crサンプルの数、bは2番目の行における水平方向のCb/Crサンプルの数を表します。

*   **4:4:4**: サブサンプリングなし。輝度と色差成分が同じ解像度を持ちます。各ピクセルにY, Cb, Crの全情報があります。
*   **4:2:2**: 水平方向に色差成分を半分に間引きます。2つの輝度サンプルに対して1つのCbと1つのCrサンプルがあります。
*   **4:2:0**: 水平方向と垂直方向の両方で色差成分を半分に間引きます。4つの輝度サンプル（2x2のブロック）に対して1つのCbと1つのCrサンプルがあります。JPEGで最も一般的に使用される形式です。
*   **4:1:1**: 水平方向に色差成分を1/4に間引きます。4つの輝度サンプルに対して1つのCbと1つのCrサンプルがあります。これは、4:2:0とは異なり、垂直方向には間引きを行いません。
*   **4:1:0**: 水平方向に色差成分を1/4に、垂直方向に色差成分を半分に間引きます。8つの輝度サンプル（4x2のブロック）に対して1つのCbと1つのCrサンプルがあります。

これらの比率は、色差成分のデータが輝度成分のデータに対してどのように配置され、どの程度の頻度でサンプリングされるかを示します。

## 技術的詳細

このコミットは、Goの `image` パッケージ内の `YCbCr` 型と関連する関数に、`4:1:1` と `4:1:0` のクロマサブサンプリング比率を認識させ、それらを適切に処理するためのロジックを追加しています。

具体的には、以下の変更が行われました。

1.  **新しいサブサンプリング比率の定数定義**: `YCbCrSubsampleRatio` 列挙型に `YCbCrSubsampleRatio411` と `YCbCrSubsampleRatio410` の2つの新しい定数が追加されました。
2.  **`String()` メソッドの更新**: `YCbCrSubsampleRatio` 型の `String()` メソッドが更新され、新しい定数に対応する文字列表現（例: "YCbCrSubsampleRatio411"）を返すようになりました。これにより、デバッグやログ出力時にこれらの比率が人間が読める形式で表示されます。
3.  **`YCbCr` 構造体のコメント更新**: `YCbCr` 構造体の定義に、新しい `4:1:1` と `4:1:0` の比率における `CStride` (色差成分のストライド) と `len(Cb)/len(Cr)` (色差成分のデータ長) の関係がコメントとして追加されました。これは、これらの比率で画像データを扱う際のメモリレイアウトとアクセス方法を理解するために重要です。
    *   `4:1:1`: `CStride == YStride/4 && len(Cb) == len(Cr) == len(Y)/4`
    *   `4:1:0`: `CStride == YStride/4 && len(Cb) == len(Cr) == len(Y)/8`
4.  **`COffset()` メソッドの更新**: `YCbCr` 型の `COffset()` メソッドは、与えられたピクセル座標 `(x, y)` に対応する色差成分（CbまたはCr）のオフセットを計算します。このメソッドに、`4:1:1` と `4:1:0` の比率に応じたオフセット計算ロジックが追加されました。
    *   `4:1:1` の場合、水平方向のサブサンプリングが4分の1であるため、`x` 座標は `x/4` として計算されます。垂直方向は輝度と同じ解像度なので `y` はそのままです。
    *   `4:1:0` の場合、水平方向のサブサンプリングが4分の1、垂直方向のサブサンプリングが半分であるため、`x` 座標は `x/4`、`y` 座標は `y/2` として計算されます。
5.  **`NewYCbCr()` 関数の更新**: `NewYCbCr()` 関数は、指定された矩形領域とサブサンプリング比率に基づいて新しい `YCbCr` 画像を初期化します。この関数に、`4:1:1` と `4:1:0` の比率に応じた色差成分の幅 (`cw`) と高さ (`ch`) の計算ロジックが追加されました。これらの計算は、色差成分のデータ配列に必要なメモリを正確に割り当てるために不可欠です。
    *   `4:1:1`: `cw = (r.Max.X+3)/4 - r.Min.X/4` (水平方向の幅を4で割る)、`ch = h` (垂直方向の高さは輝度と同じ)
    *   `4:1:0`: `cw = (r.Max.X+3)/4 - r.Min.X/4` (水平方向の幅を4で割る)、`ch = (r.Max.Y+1)/2 - r.Min.Y/2` (垂直方向の高さを2で割る)
6.  **テストケースの追加**: `src/image/ycbcr_test.go` に、新しいサブサンプリング比率がテストスイートに含まれるように更新されました。これにより、追加された機能が正しく動作することが保証されます。

これらの変更により、Goの `image` パッケージは、より多様なJPEG画像フォーマットに対応できるようになり、実世界の画像処理アプリケーションにおける互換性と堅牢性が向上しました。

## コアとなるコードの解説

### `src/image/ycbcr.go`

1.  **`const` ブロックへの追加**:
    `YCbCrSubsampleRatio` 型の定数リストに `YCbCrSubsampleRatio411` と `YCbCrSubsampleRatio410` が追加されました。これにより、これらの新しいサブサンプリング比率をコード内で識別できるようになります。

2.  **`String()` メソッドの `switch` 文への追加**:
    `YCbCrSubsampleRatio` 型の `String()` メソッドは、各サブサンプリング比率に対応する人間が読める文字列を返します。新しい `case` 文が追加され、`YCbCrSubsampleRatio411` と `YCbCrSubsampleRatio410` がそれぞれ "YCbCrSubsampleRatio411" と "YCbCrSubsampleRatio410" を返すようになりました。

3.  **`YCbCr` 構造体のコメント更新**:
    `YCbCr` 構造体の定義の上にあるコメントは、各サブサンプリング比率における `CStride` (色差成分の行ごとのバイト数) と `Cb`/`Cr` スライスの長さ (`len(Cb) == len(Cr)`) と `Y` スライスの長さ (`len(Y)`) の関係を説明しています。新しい `4:1:1` と `4:1:0` の比率に関する説明が追加され、これらの比率でのデータレイアウトが明確になりました。
    *   `4:1:1`: 輝度Yの水平方向の4ピクセルに対して、色差Cb/Crが1ピクセル存在し、垂直方向はYと同じ。そのため、`CStride` は `YStride/4`、`Cb`/`Cr` のデータ長は `Y` の `1/4` となります。
    *   `4:1:0`: 輝度Yの水平方向の4ピクセル、垂直方向の2ピクセル（計8ピクセル）に対して、色差Cb/Crが1ピクセル存在。そのため、`CStride` は `YStride/4`、`Cb`/`Cr` のデータ長は `Y` の `1/8` となります。

4.  **`COffset()` メソッドの `switch` 文への追加**:
    `COffset(x, y int)` メソッドは、指定された `(x, y)` 座標に対応する色差成分（CbまたはCr）のオフセットを計算します。これは、`YCbCr` 構造体の `Cb` または `Cr` スライス内の正しいバイト位置を見つけるために使用されます。
    *   `YCbCrSubsampleRatio411` の場合: `(y-p.Rect.Min.Y)*p.CStride + (x/4 - p.Rect.Min.X/4)`。水平方向のサブサンプリングが4分の1であるため、`x` 座標は `x/4` で計算されます。垂直方向はサブサンプリングされないため、`y` はそのままです。
    *   `YCbCrSubsampleRatio410` の場合: `(y/2-p.Rect.Min.Y/2)*p.CStride + (x/4 - p.Rect.Min.X/4)`。水平方向のサブサンプリングが4分の1、垂直方向のサブサンプリングが半分であるため、`x` 座標は `x/4`、`y` 座標は `y/2` で計算されます。

5.  **`NewYCbCr()` 関数の `switch` 文への追加**:
    `NewYCbCr(r Rectangle, subsampleRatio YCbCrSubsampleRatio)` 関数は、新しい `YCbCr` 画像を初期化し、その `Y`, `Cb`, `Cr` スライスに適切なメモリを割り当てます。この関数は、指定された `subsampleRatio` に基づいて色差成分の幅 (`cw`) と高さ (`ch`) を計算します。
    *   `YCbCrSubsampleRatio411` の場合: `cw = (r.Max.X+3)/4 - r.Min.X/4` (水平方向の幅を4で割る際の切り上げ処理を含む)、`ch = h` (垂直方向の高さは輝度と同じ)。
    *   `YCbCrSubsampleRatio410` の場合: `cw = (r.Max.X+3)/4 - r.Min.X/4` (水平方向の幅を4で割る際の切り上げ処理を含む)、`ch = (r.Max.Y+1)/2 - r.Min.Y/2` (垂直方向の高さを2で割る際の切り上げ処理を含む)。
    これらの計算は、色差成分のデータ配列に必要なメモリを正確に割り当てるために重要です。

### `src/image/ycbcr_test.go`

1.  **`TestYCbCr` 関数内の `subsampleRatios` スライスへの追加**:
    `TestYCbCr` 関数は、様々なサブサンプリング比率で `YCbCr` 型の動作をテストします。このテストで使用される `subsampleRatios` スライスに `YCbCrSubsampleRatio411` と `YCbCrSubsampleRatio410` が追加されました。これにより、新しい比率が既存のテストフレームワークで検証されるようになります。

これらの変更は、Goの `image` パッケージが `4:1:1` および `4:1:0` のクロマサブサンプリング形式の画像を正しく解釈し、操作するための基盤を提供します。
