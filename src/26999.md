## 元コミット内容

## 変更の背景

Goコンパイラは、Go言語のソースコードを最終的な機械語に変換する過程で、各アーキテクチャ（x86, ARM, MIPSなど）向けのアセンブラを使用します。このコミットはMIPSアーキテクチャに特化したもので、特に定数（リテラル値）をレジスタにロードする際の命令生成ロジックに関わります。

MIPSアーキテクチャでは、32ビットの定数を直接一つの命令でレジスタにロードすることはできません。これは、MIPS命令が32ビット幅であり、その中にオペコード、レジスタ指定、即値などを収める必要があるため、即値フィールドが限られているためです。通常、16ビットの即値しか扱えません。

大きな32ビット定数をレジスタにロードする場合、MIPSでは一般的に2つの命令を組み合わせて使用します。
1.  **`LUI` (Load Upper Immediate)**: 定数の上位16ビットをレジスタの上位16ビットにロードし、下位16ビットをゼロクリアします。
2.  **`ORI` (OR Immediate)**: `LUI` でロードされたレジスタに対し、定数の下位16ビットを論理和（OR）で結合します。

これにより、32ビット定数全体がレジスタにロードされます。

Goのアセンブラ内部では、これらのMIPS命令に対応する内部的な定数（擬似命令）が定義されています。以前は、`LUI` 命令に直接対応する定数がなく、汎用的な「最後の命令」を意味する `ALAST` という定数を `LUI` の代わりとして「濫用」していました。これはコードの意図を不明瞭にし、将来的なメンテナンスや拡張の際に混乱を招く可能性がありました。

このコミットの目的は、`LUI` 命令専用の `ALUI` 定数を導入することで、コードの可読性と正確性を向上させ、アセンブラが生成するMIPS命令がより意図に沿ったものになるようにすることです。Issue #14692 は、この `ALAST` の不適切な使用に関する問題を追跡していたものと考えられます。

## 前提知識の解説

### Goのツールチェーンとアセンブラ (`cmd/internal/obj`)

Go言語のコンパイラは、`go tool compile` コマンドによって呼び出されます。このコンパイラは、Goのソースコードを中間表現に変換し、最終的に各ターゲットアーキテクチャ（GOARCH）の機械語に変換します。この機械語生成の過程で、`cmd/internal/obj` パッケージ群が重要な役割を果たします。

*   **`cmd/internal/obj`**: Goのコンパイラとリンカが使用する共通のオブジェクトファイルフォーマットとアセンブラのバックエンドを提供します。
*   **`cmd/internal/obj/mips`**: MIPSアーキテクチャに特化したアセンブラのバックエンドです。MIPS命令セットに対応する定数、命令のエンコーディングロジック、および擬似命令の展開ロジックが含まれます。

Goのアセンブラは、Goのソースコードから生成されるアセンブリ命令（擬似命令を含む）を、ターゲットアーキテクチャの実際の機械語命令に変換する役割を担います。

### MIPSアーキテクチャと `LUI` 命令

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。特徴として、固定長の命令形式、ロード/ストアアーキテクチャ、多数の汎用レジスタなどが挙げられます。

*   **`LUI` (Load Upper Immediate)**: MIPSの命令の一つで、即値（Immediate）の上位16ビットをレジスタの上位16ビットにロードし、レジスタの下位16ビットをゼロクリアします。
    *   フォーマット: `LUI Rt, immediate`
    *   動作: `Rt = immediate << 16`
    *   用途: 32ビット定数の上位部分をロードするために使用されます。

*   **`ORI` (OR Immediate)**: レジスタの値と即値の論理和を計算し、結果を別のレジスタに格納します。
    *   フォーマット: `ORI Rt, Rs, immediate`
    *   動作: `Rt = Rs | immediate`
    *   用途: `LUI` と組み合わせて、32ビット定数の下位部分を結合するために使用されます。

### Goアセンブラにおける定数と擬似命令

Goのアセンブラ内部では、各アーキテクチャの機械語命令に対応する独自の定数（例: `AADD`, `AMOV` など）が定義されています。これらは、アセンブラが命令を識別し、適切な機械語にエンコードするために使用されます。

また、Goのアセンブラは、特定の操作を簡略化するための「擬似命令」をサポートしています。例えば、`mov $lcon,r` のような命令は、実際にはMIPSの `LUI` と `ORI` の組み合わせに展開されることがあります。

*   **`ALAST`**: Goのアセンブラ内部で、特定の命令セットの「最後の命令」を示すために使われる汎用的な定数です。本来は、命令セットの範囲を示すマーカーとして使われることが多いですが、このコミット以前はMIPSの `LUI` 命令を表現するために一時的に流用されていました。
*   **`ALUI`**: このコミットで新しく導入された定数で、MIPSの `LUI` 命令に直接対応します。これにより、コードの意図が明確になり、`ALAST` のような汎用的な定数を特定の命令に割り当てるという「濫用」が解消されます。

## 技術的詳細

このコミットは、主に以下の3つのファイルに影響を与えています。

1.  **`src/cmd/internal/obj/mips/a.out.go`**:
    *   このファイルは、MIPSアーキテクチャ向けのアセンブラが認識する命令コードの定数を定義しています。
    *   `const` ブロック内に `ALUI` という新しい定数が追加されました。これにより、GoのアセンブラがMIPSの `LUI` 命令を明示的に識別できるようになります。

2.  **`src/cmd/internal/obj/mips/anames.go`**:
    *   このファイルは、`a.out.go` で定義された命令コードの定数と、それに対応する文字列名をマッピングしています。これはデバッグ出力やアセンブリリストの生成などで使用されます。
    *   `Anames` 配列に `"LUI"` という文字列が追加され、`ALUI` 定数と関連付けられました。

3.  **`src/cmd/internal/obj/mips/asm0.go`**:
    *   このファイルは、MIPSアセンブリコードの生成ロジック、特に擬似命令の展開や定数ロードの処理を実装しています。
    *   `asmout` 関数内の複数の `case` 文（`case 19`, `case 23`, `case 24`, `case 25`, `case 26`, `case 50`, `case 51`）で、`ALAST` を使用していた箇所が `ALUI` に置き換えられました。これらの `case` は、主に大きな定数をレジスタにロードする処理（`mov $lcon,r` など）や、アドレス計算に関連する処理を扱っています。
    *   `opirr` 関数内でも、`ALAST` が `LUI` 命令に対応付けられていた箇所が `ALUI` に変更されました。`opirr` 関数は、Goのアセンブラ内部の命令定数（`AADD`, `ALUI` など）を、MIPSの実際の命令エンコーディングの一部（オペコードやファンクションコード）に変換する役割を担っています。具体的には、`ALAST` が `SP(1, 7)` (MIPSの `LUI` 命令のエンコーディングの一部) を返していましたが、これが `ALUI` に変更されました。

この変更により、GoのアセンブラはMIPSの `LUI` 命令をより正確かつ意図的に扱うことができるようになります。以前は `ALAST` という汎用的な定数で `LUI` を表現していたため、コードの意図が不明瞭でしたが、`ALUI` の導入により、その役割が明確になりました。これは、MIPSアーキテクチャにおける定数ロードの最適化や、将来的なアセンブラの機能拡張において、より堅牢な基盤を提供します。

### `src/cmd/internal/obj/mips/anames.go` の変更

*   `Anames` 配列への `"LUI"` の追加:
    *   `ALUI` 定数に対応する文字列 `"LUI"` を追加しています。これにより、デバッグ出力やアセンブリリストなどで `LUI` 命令が正しく表示されるようになります。

### `src/cmd/internal/obj/mips/asm0.go` の変更

*   `asmout` 関数内の `ALAST` から `ALUI` への置き換え:
    *   `asmout` 関数は、Goの擬似命令をMIPSの実際の機械語命令に変換する主要なロジックを含んでいます。
    *   `case 19: /* mov $lcon,r ==> lu+or */` など、複数の `case` で `OP_IRR(opirr(ctxt, ALAST), ...)` が `OP_IRR(opirr(ctxt, ALUI), ...)` に変更されています。
    *   これらの `case` は、Goのアセンブラが `mov $lcon,r` (大きな定数をレジスタにロードする) や `add $lcon,r1,r2` (大きな定数を加算する) といった擬似命令を処理する際に、MIPSの `LUI` と `ORI` 命令の組み合わせに展開する部分です。
    *   以前は `ALAST` を使用して `LUI` 命令を表現していましたが、`ALUI` を直接使用することで、コードの意図がより明確になり、`ALAST` の汎用的な意味合いとの混同がなくなります。

*   `opirr` 関数内の `ALAST` から `ALUI` への変更:
    *   `opirr` 関数は、Goのアセンブラ内部の命令定数（`ALUI` など）を、MIPSの命令エンコーディングの一部（この場合は `SP(1, 7)` という値）にマッピングする役割を担っています。
    *   `case ALAST: return SP(1, 7) /* lui */` という行が `case ALUI: return SP(1, 7)` に変更されています。
    *   これは、`SP(1, 7)` がMIPSの `LUI` 命令のエンコーディングの一部を表すことを示しており、このマッピングが `ALAST` ではなく、新しく導入された `ALUI` に関連付けられるようになったことを意味します。

これらの変更により、MIPSアーキテクチャ向けGoアセンブラは、`LUI` 命令をより正確かつ意図的に扱うことができるようになり、コードの可読性と保守性が向上しました。
