## 元コミット内容

`encoding/xml: Add CDATA-wrapper output support to xml.Marshal.`

このコミットは、`encoding/xml` パッケージの `xml.Marshal` 関数に、CDATAセクションでラップされた出力のサポートを追加します。

## 変更の背景

XMLドキュメントでは、`<` や `&` といった特殊文字は、それぞれ `&lt;` や `&amp;` のようにXMLエンティティとしてエスケープする必要があります。しかし、スクリプトコードやマークアップ言語の断片など、大量の特殊文字を含むテキストをXML内に含めたい場合、全てをエスケープするのは非効率的であり、可読性を著しく損なう可能性があります。

CDATAセクション（`<![CDATA[...]]>`）は、このようなテキストをXMLパーサーが解析する際に、内部のコンテンツを文字データとして扱い、特殊文字のエスケープを不要にするメカニズムを提供します。

このコミットは、Goの `encoding/xml` パッケージが、構造体のフィールドタグに `cdata` オプションを指定することで、そのフィールドの値を自動的にCDATAセクションとしてマーシャリングできるようにすることで、この問題を解決します。これにより、ユーザーは手動でエスケープ処理を行うことなく、特殊文字を含むデータをXMLに出力できるようになります。

関連するIssue #12963は、この機能の必要性を示唆しています。

## 前提知識の解説

### XML (Extensible Markup Language)

XMLは、情報を構造化するためのマークアップ言語です。データ交換や設定ファイルの記述など、幅広い用途で利用されます。XMLドキュメントは、要素、属性、テキストコンテンツなどで構成されます。

### XMLの特殊文字とエスケープ

XMLでは、以下の5つの文字が特殊文字として扱われます。
- `<` (小なり記号): 要素の開始タグや終了タグの区切り文字
- `>` (大なり記号): 要素の開始タグや終了タグの区切り文字
- `&` (アンパサンド): エンティティ参照の開始文字
- `'` (シングルクォート): 属性値の区切り文字
- `"` (ダブルクォート): 属性値の区切り文字

これらの文字をテキストコンテンツとしてXMLドキュメント内に含める場合、それぞれ `&lt;`, `&gt;`, `&amp;`, `&apos;`, `&quot;` のようにXMLエンティティにエスケープする必要があります。

### CDATAセクション

CDATA (Character Data) セクションは、XMLドキュメント内で特殊文字をエスケープせずに文字データを記述するための特別なブロックです。CDATAセクションは `<![CDATA[` で始まり、`]]>` で終わります。このブロック内のコンテンツは、XMLパーサーによって文字データとして扱われ、内部の `<` や `&` などの特殊文字はエスケープされません。

ただし、CDATAセクションの終了デリミタである `]]>` 自体は、CDATAセクション内に直接含めることはできません。このコミットでは、この `]]>` が含まれる場合の適切なエスケープ（分割）処理も実装されています。

### Go言語の `encoding/xml` パッケージ

`encoding/xml` パッケージは、Go言語でXMLドキュメントとGoの構造体との間でデータをマーシャリング（Goの構造体からXMLへ変換）およびアンマーシャリング（XMLからGoの構造体へ変換）するための機能を提供します。構造体のフィールドタグに `xml:"element_name,attr"` のような形式でオプションを指定することで、XML要素名や属性へのマッピングを制御できます。

### `src/encoding/xml/xml.go` (抜粋)

```go
var (
	cdataStart  = []byte("<![CDATA[")
	cdataEnd    = []byte("]]>")
	cdataEscape = []byte("]]]]><![CDATA[>")
)

// emitCDATA writes to w the CDATA-wrapped plain text data s.
// It escapes CDATA directives nested in s.
func emitCDATA(w io.Writer, s []byte) error {
	if len(s) == 0 {
		return nil
	}
	if _, err := w.Write(cdataStart); err != nil {
		return err
	}
	for {
		i := bytes.Index(s, cdataEnd)
		if i >= 0 && i+len(cdataEnd) <= len(s) {
			// Found a nested CDATA directive end.
			if _, err := w.Write(s[:i]); err != nil {
				return err
			}
			if _, err := w.Write(cdataEscape); err != nil {
				return err
			}
			i += len(cdataEnd)
		} else {
			if _, err := w.Write(s); err != nil {
				return err
			}
			break
		}
		s = s[i:]
	}
	if _, err := w.Write(cdataEnd); err != nil {
		return err
	}
	return nil
}
```

## コアとなるコードの解説

`marshal.go` の変更は、構造体のフィールドをマーシャリングする際に、そのフィールドが `cdata` タグを持つかどうかを `finfo.flags` から判断し、適切な出力関数 (`emitCDATA` または `EscapeText`) を選択するようにしています。これにより、ユーザーは構造体タグを通じてCDATA出力を宣言的に制御できるようになります。

`xml.go` に追加された `emitCDATA` 関数は、CDATAセクションの生成ロジックをカプセル化しています。この関数は、まず `<![CDATA[` を出力し、次に与えられたバイトスライス `s` の内容を処理します。ここで重要なのは、`s` の中に `]]>` というシーケンスが含まれていないかを繰り返しチェックするループです。もし `]]>` が見つかった場合、それは `]]]]><![CDATA[>` という形式に変換されて出力されます。これにより、XMLパーサーがCDATAセクションの途中で終了デリミタを誤認識することを防ぎ、CDATAセクションの整合性を保ちます。最後に `]]>` を出力してCDATAセクションを閉じます。

この `emitCDATA` 関数の実装は、XMLの仕様に準拠し、CDATAセクション内に `]]>` が出現した場合の正しい処理方法を提供しています。
