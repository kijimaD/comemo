## 変更の背景

このコミットが作成された2009年6月時点では、Go言語はまだ初期段階にあり、標準ライブラリも発展途上でした。HTTPサーバー機能は既に存在していましたが、HTTPクライアント機能はまだ提供されていませんでした。Webアプリケーションやネットワークサービスを構築する上で、外部のHTTPリソースにアクセスするクライアント機能は不可欠です。このコミットは、Go言語でHTTPリクエストを送信し、レスポンスを処理するための基本的なメカニズムを提供することで、Go言語のネットワークプログラミング能力を拡張することを目的としています。

特に、`net/http`パッケージはHTTPプロトコルを扱うための中心的な場所であり、サーバー機能に加えてクライアント機能も統合することで、一貫性のあるAPIと開発体験を提供しようとしていました。

## 前提知識の解説

このコミットを理解するためには、以下の概念に関する基本的な知識が必要です。

*   **HTTPプロトコル**: Web上でデータを交換するためのプロトコル。リクエストとレスポンスの構造、ヘッダー、ステータスコードなど。RFC 2616はHTTP/1.1の主要な仕様です。
*   **TCP/IPソケットプログラミング**: HTTPクライアントは、基盤となるTCPソケットを介してサーバーと通信します。`net.Dial`関数はTCP接続を確立するために使用されます。
*   **Go言語のI/Oインターフェース**: `io.Reader`、`io.Writer`、`io.ReadCloser`などのインターフェースは、データの読み書きやリソースのクローズを抽象化するためにGoで広く使用されます。
*   **Go言語のパッケージ構造**: `src/pkg`ディレクトリは標準ライブラリのパッケージが配置される場所です。`http`パッケージはHTTPプロトコルを、`strings`パッケージは文字列操作を提供します。
*   **Makefile**: Goのビルドシステムが成熟する前は、`Makefile`がパッケージのビルドとリンクを管理するために使用されていました。
*   **URLのパース**: HTTPリクエストを送信するには、ターゲットURLをスキーム、ホスト、パス、クエリなどのコンポーネントに分解（パース）する必要があります。

## 技術的詳細

このコミットの主要な技術的詳細は以下の通りです。

1.  **`http.Response`構造体**: HTTPレスポンスを表す新しい構造体が定義されました。これには、ステータスライン（例: "200 OK"）、ステータスコード（例: 200）、ヘッダーのマップ、そしてレスポンスボディを読み取るための`io.ReadCloser`インターフェースが含まれます。
2.  **`Response`のヘッダー操作**: `GetHeader`と`AddHeader`メソッドが`Response`構造体に追加され、HTTPヘッダーの取得と追加を容易にします。ヘッダーキーの大文字・小文字を区別しない処理のために`CanonicalHeaderKey`が使用されます。
3.  **`send`関数**: HTTPリクエストを実際に送信し、レスポンスを受信する非公開関数`send`が実装されました。
    *   URLのスキームが`http`であることを確認します。
    *   `net.Dial("tcp", "", addr)`を使用してTCP接続を確立します。
    *   `req.write(conn)`を呼び出してリクエストヘッダーとボディを接続に書き込みます。
    *   `bufio.NewReader`を使用してレスポンスをバッファリングしながら読み取ります。
    *   レスポンスのステータスラインとヘッダーをパースします。
    *   レスポンスボディを`io.ReadCloser`として提供するために、`readClose`という内部構造体を使用します。これは`io.Reader`と`io.Closer`をバンドルしたものです。
4.  **`Get`関数**: 指定されたURLに対してHTTP GETリクエストを発行する公開関数`Get`が追加されました。
    *   リダイレクト（301, 302, 303, 307）を最大10回まで自動的に追跡するロジックが含まれています。
    *   リダイレクト時には`Location`ヘッダーから新しいURLを取得します。
5.  **`Post`関数**: 指定されたURLに対してHTTP POSTリクエストを発行する公開関数`Post`が追加されました。リクエストボディを`io.Reader`として受け取ります。
6.  **`Request.write`メソッド**: `http.Request`構造体に、リクエストをワイヤーフォーマット（HTTPプロトコル形式）で`io.Writer`に書き込む`write`メソッドが追加されました。これにより、クライアントがリクエストを送信する際に使用されます。
    *   メソッド、URI、プロトコルバージョンを含むリクエストラインをフォーマットします。
    *   `Host`, `User-Agent`, `Referer`などの標準ヘッダーを書き込みます。
    *   `req.Header`マップ内のカスタムヘッダーを書き込みます。
    *   `req.Body`があれば、その内容を`io.Copy`で書き込みます。
7.  **`strings.LastIndex`関数**: `strings`パッケージに、文字列内で指定されたサブストリングが最後に出現するインデックスを返す`LastIndex`関数が追加されました。これは、`http`パッケージの`hasPort`関数（ホスト名からポートを分離するために使用）で利用されます。

## コアとなるコードの解説

### `src/pkg/http/client.go`

このファイルは、HTTPクライアント機能の心臓部です。

*   **`type Response struct { ... }`**: HTTPレスポンスの構造を定義します。`Status`、`StatusCode`、`Header`、`Body`といった基本的な要素が含まれます。`Header`は`map[string]string`で、キーは正規化されます。
*   **`func (r *Response) GetHeader(key string) (value string)`**: `Response`オブジェクトから指定されたヘッダーの値を取得します。`CanonicalHeaderKey`を使用してキーを正規化し、大文字・小文字を区別せずにヘッダーを検索します。
*   **`func (r *Response) AddHeader(key, value string)`**: `Response`オブジェクトにヘッダーを追加します。既存のヘッダーがある場合は、RFC 2616に従ってカンマ区切りで値を連結します。
*   **`func hasPort(s string) bool`**: ホスト文字列にポートが含まれているかを判定するヘルパー関数です。`strings.LastIndex`を使用して、最後のコロンが角括弧（IPv6アドレス用）の後に来るかどうかで判断します。
*   **`type readClose struct { ... }`**: `io.Reader`と`io.Closer`を組み合わせた内部構造体で、レスポンスボディの読み取りと基盤となる接続のクローズを同時に管理できるようにします。
*   **`func send(req *Request) (resp *Response, err os.Error)`**: HTTPリクエストを送信し、レスポンスを処理する主要なロジックを含みます。
    *   `net.Dial`でTCP接続を確立。
    *   `req.write(conn)`でリクエストを送信。
    *   `bufio.NewReader`でレスポンスを読み込み、ステータスラインとヘッダーをパース。
    *   `resp.Body`に`readClose`インスタンスを割り当て、呼び出し元がボディを読み終えたら接続をクローズできるようにします。
*   **`func Get(url string) (r *Response, finalUrl string, err os.Error)`**: GETリクエストを送信し、リダイレクトを自動的に処理します。最大10回のリダイレクトを追跡し、`Location`ヘッダーを使用します。
*   **`func Post(url string, requestBody io.Reader) (r *Response, err os.Error)`**: POSTリクエストを送信します。リクエストボディは`io.Reader`として渡されます。

### `src/pkg/http/request.go`

*   **`func (req *Request) write(w io.Writer) os.Error`**: `Request`構造体の内容をHTTPプロトコル形式で`io.Writer`に書き出します。これは`send`関数によって呼び出され、実際のネットワーク送信の前にリクエストをフォーマットする役割を担います。`fmt.Fprintf`や`io.WriteString`を使って、リクエストライン、ヘッダー、そしてボディを順に書き込みます。

### `src/pkg/strings/strings.go`

*   **`func LastIndex(s, sep string) int`**: 文字列`s`内でサブストリング`sep`が最後に出現する位置のインデックスを返します。これは、`http`パッケージの`hasPort`関数で、ホスト文字列内のポート番号を特定するために利用されます。この関数は、`sep`の最初の文字`c`を効率的に検索し、その後`s[i:i+n] == sep`で完全なマッチを確認することで実装されています。
