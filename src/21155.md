# [インデックス 21155] ファイルの概要

このコミットは、Go言語のパーサーパッケージである `go/parser` のテストコードにおける競合状態（race condition）を解消することを目的としています。具体的には、テスト間で共有されていた `token.FileSet` の使用を止め、各テストが独立した `token.FileSet` を使用するように変更することで、テストの信頼性と並列実行時の安定性を向上させています。この変更は、プロダクションコードではなく、テストコードのみに影響します。

## 変更の背景

Go言語のテストフレームワークは、テストの並列実行をサポートしています。しかし、`go/parser` パッケージのテストコードでは、`token.FileSet` というファイル位置情報を管理するオブジェクトがグローバル変数として定義され、複数のテスト関数間で共有されていました。

`token.FileSet` は、ソースコードのファイル名、オフセット、行番号、列番号といった位置情報を一元的に管理するための構造体です。パーサーがソースコードを解析する際、この `FileSet` にファイル情報を登録し、解析中に遭遇するトークンの位置を記録します。

複数のテストが並列で実行される場合、共有された `token.FileSet` に対して同時にファイルの追加や位置情報の参照が行われると、競合状態が発生する可能性がありました。これにより、テスト結果が不安定になったり、誤った位置情報が報告されたりする問題が生じていました。コミットメッセージに記載されている `#9025` および `#9130` は、これらの競合状態に起因するテストの不具合を指していると考えられます（これらのIssueの具体的な内容は公開されていませんが、文脈からテストの不安定性に関連すると推測されます）。

このコミットは、このようなテストの不安定性を解消し、テストの信頼性を向上させることを目的としています。

## 前提知識の解説

### Go言語の `go/parser` パッケージ

`go/parser` パッケージは、Go言語のソースコードを解析し、抽象構文木（AST: Abstract Syntax Tree）を生成するためのパッケージです。Goコンパイラや各種ツール（`go fmt`、`go vet`など）の基盤として利用されています。ソースコードを解析する際、`parser.ParseFile` のような関数が `token.FileSet` オブジェクトを受け取り、解析対象のファイル情報をその `FileSet` に登録します。

### `token.FileSet` と `token.Pos`

`go/token` パッケージは、Goソースコード内の位置情報を表現するための型を提供します。
- **`token.FileSet`**: 複数のソースファイルにわたる位置情報を管理するコレクションです。各ソースファイルは `token.File` オブジェクトとして `FileSet` に登録されます。`FileSet` は、ソースコード内の任意の `token.Pos`（位置）から、その位置がどのファイル、どの行、どの列に当たるかを効率的に特定するためのマッピングを提供します。
- **`token.Pos`**: ソースコード内の特定のバイトオフセットを表す整数型です。このオフセットは、`FileSet` 内の特定のファイルに関連付けられています。

### 競合状態（Race Condition）

競合状態とは、複数のゴルーチン（またはスレッド）が共有リソース（この場合はグローバルな `token.FileSet`）に同時にアクセスし、そのアクセス順序によってプログラムの最終結果が変わってしまう状態を指します。Go言語では、`go test -race` コマンドを使用することで、テスト中の競合状態を検出できます。

テストコードにおいて競合状態が発生すると、テストが非決定的な振る舞いを示し、ある実行では成功し、別の実行では失敗するといった不安定な状況を引き起こします。これは、テストの信頼性を著しく損ない、開発者がバグを特定・修正するのを困難にします。

## 技術的詳細

このコミットの技術的な核心は、`go/parser` のテストコードが抱えていた `token.FileSet` の共有問題とその解決策にあります。

従来のテストコードでは、`src/go/parser/error_test.go` と `src/go/parser/parser_test.go` の両方で、以下のようなグローバル変数として `token.FileSet` が定義されていました。

```go
var fsetErrs = token.NewFileSet() // error_test.go
var fset = token.NewFileSet()     // parser_test.go
```

これらのグローバルな `FileSet` インスタンスは、それぞれのテストファイル内の複数のテスト関数から参照され、ファイルの追加や位置情報の取得に使用されていました。Goのテストはデフォルトで並列実行される可能性があるため、複数のテスト関数が同時にこれらの共有 `FileSet` を操作しようとすると、内部の状態が破壊されたり、不正確な位置情報が返されたりする可能性がありました。

このコミットでは、この問題を解決するために以下の戦略を採用しました。

1.  **グローバル `FileSet` の削除**: `fsetErrs` と `fset` というグローバル変数を削除しました。
2.  **テストごとの `FileSet` の生成**: 各テスト関数、または `token.FileSet` を必要とするテストヘルパー関数内で、`token.NewFileSet()` を呼び出して新しい `FileSet` インスタンスを生成するように変更しました。これにより、各テストの実行は完全に独立した `FileSet` を持つことになり、他のテストの実行とは干渉しなくなります。
3.  **`FileSet` の引数渡し**: `getFile`, `getPos`, `expectedErrors`, `compareErrors` といったヘルパー関数が `token.FileSet` を引数として受け取るようにシグネチャを変更しました。これにより、これらの関数は特定のテスト実行に関連付けられた `FileSet` を使用できるようになります。

この変更により、テストの並列実行時における `FileSet` への同時アクセスが原因で発生していた競合状態が解消され、テストの実行が安定し、信頼性が向上しました。これは、テストコードの品質を保つ上で非常に重要な改善です。

## コアとなるコードの変更箇所

変更は主に以下の2つのテストファイルで行われています。

1.  `src/go/parser/error_test.go`
2.  `src/go/parser/parser_test.go`

具体的な変更内容は、グローバルな `token.FileSet` 変数の削除と、`token.FileSet` を必要とする関数への引数追加、そして各テスト関数内での `token.NewFileSet()` の呼び出しです。

### `src/go/parser/error_test.go` の変更

-   `var fsetErrs = token.NewFileSet()` の削除。
-   `getFile`, `getPos`, `expectedErrors`, `compareErrors` 関数が `*token.FileSet` を第一引数として受け取るように変更。
-   `checkErrors` 関数内で `fset := token.NewFileSet()` を呼び出し、その `fset` を後続の関数呼び出しに渡すように変更。

### `src/go/parser/parser_test.go` の変更

-   `var fset = token.NewFileSet()` の削除。
-   `TestParse`, `TestParseDir`, `TestColonEqualsScope`, `TestVarScope`, `TestUnresolved`, `TestImports`, `TestCommentGroups`, `TestLeadAndLineComments` といったテスト関数内で、`parser.ParseFile` や `parser.ParseDir` を呼び出す際に、`token.NewFileSet()` を直接渡すように変更。

## コアとなるコードの解説

### `src/go/parser/error_test.go`

変更前:
```go
var fsetErrs = token.NewFileSet()

func getFile(filename string) (file *token.File) {
    fsetErrs.Iterate(func(f *token.File) bool { ... })
    return file
}

func checkErrors(t *testing.T, filename string, input interface{}) {
    _, err = ParseFile(fsetErrs, filename, src, DeclarationErrors|AllErrors)
    // ...
    expected := expectedErrors(t, filename, src)
    // ...
    compareErrors(t, expected, found)
}
```

変更後:
```go
// var fsetErrs = token.NewFileSet() // 削除

func getFile(fset *token.FileSet, filename string) (file *token.File) {
    fset.Iterate(func(f *token.File) bool { ... }) // fset を引数で受け取る
    return file
}

func checkErrors(t *testing.T, filename string, input interface{}) {
    fset := token.NewFileSet() // 新しい FileSet を生成
    _, err = ParseFile(fset, filename, src, DeclarationErrors|AllErrors)
    // ...
    expected := expectedErrors(t, fset, filename, src) // fset を渡す
    // ...
    compareErrors(t, fset, expected, found) // fset を渡す
}
```
この変更により、`checkErrors` が呼び出されるたびに新しい `token.FileSet` が作成され、その `FileSet` が関連するヘルパー関数に渡されるようになりました。これにより、各 `checkErrors` の実行が独立した `FileSet` を使用し、並列実行時の競合が解消されます。

### `src/go/parser/parser_test.go`

変更前:
```go
var fset = token.NewFileSet()

func TestParse(t *testing.T) {
    for _, filename := range validFiles {
        _, err := ParseFile(fset, filename, nil, DeclarationErrors)
        // ...
    }
}

func TestParseDir(t *testing.T) {
    path := "."
    pkgs, err := ParseDir(fset, path, dirFilter, 0)
    // ...
}
```

変更後:
```go
// var fset = token.NewFileSet() // 削除

func TestParse(t *testing.T) {
    for _, filename := range validFiles {
        _, err := ParseFile(token.NewFileSet(), filename, nil, DeclarationErrors) // 新しい FileSet を直接渡す
        // ...
    }
}

func TestParseDir(t *H) {
    path := "."
    pkgs, err := ParseDir(token.NewFileSet(), path, dirFilter, 0) // 新しい FileSet を直接渡す
    // ...
}
```
`parser_test.go` では、各テスト関数内で `parser.ParseFile` や `parser.ParseDir` を呼び出す際に、その場で `token.NewFileSet()` を生成して渡すように変更されています。これにより、各テストの実行が完全に独立した `FileSet` を使用することが保証されます。

これらの変更は、Goのテストにおけるベストプラクティス、すなわちテストの独立性と再現性を確保するための典型的なアプローチを示しています。共有状態を排除することで、テストの信頼性が向上し、並列実行時のデバッグが容易になります。
