## 元コミット内容

このコミットは、FreeBSDのルーティングソケットAPIの変更に対応するため、Goの`syscall`パッケージを更新します。具体的には、`IfMsghdr`と`IfaMsghdr`を新しい「l」バリアント（`if_msghdrl`と`ifa_msghdrl`）に切り替え、`IfData`構造体のレイアウトをFreeBSD 11.0の定義に合わせます。`freebsdVersion`変数を用いて実行時にFreeBSDのバージョンを検出し、適切なデータレイアウトでルーティングソケットメッセージをデコードするように変更されます。これにより、FreeBSDの異なるバージョン間での互換性が維持されます。

## 変更の背景

FreeBSDのカーネルAPI、特にネットワーク関連のデータ構造は、OSのバージョンアップに伴い変更されることがあります。このコミットの背景には、FreeBSD 11.0でルーティングソケットメッセージの構造が変更されたことがあります。具体的には、ネットワークインターフェースの統計情報や設定をやり取りするための`if_msghdr`および`ifa_msghdr`構造体、そしてそれらに含まれる`if_data`構造体のレイアウトが更新されました。

以前のGoの`syscall`パッケージは、古いFreeBSDバージョンのデータ構造を前提としていました。このため、FreeBSD 11.0以降のシステムでGoプログラムがネットワークインターフェース情報を正しく取得・解析できない問題（Issue #11641）が発生していました。この変更は、この互換性の問題を解決し、Goが新しいFreeBSD環境でも正しく動作するようにするために必要でした。

新しい構造体は、より多くの情報を含んだり、フィールドの配置が変更されたりすることが一般的です。特に、`NET_RT_IFLIST`から`NET_RT_IFLISTL`への切り替えは、より詳細な情報（"L"は"long"または"large"を意味することが多い）を提供する新しい`sysctl`インターフェースが導入されたことを示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **ルーティングソケット (Routing Socket)**:
    *   Unix系OS（FreeBSDを含む）において、カーネルのルーティングテーブルやネットワークインターフェースの状態に関する情報を取得したり、設定を変更したりするための特殊なソケットです。
    *   アプリケーションはルーティングソケットを通じて、インターフェースの追加/削除、IPアドレスの割り当て、ルーティングエントリの操作などを行います。
    *   カーネルは、ネットワークイベント（例: インターフェースのアップ/ダウン、IPアドレスの変更）が発生した際に、ルーティングソケットにメッセージを送信してアプリケーションに通知します。

2.  **`sysctl`**:
    *   Unix系OSにおけるシステムパラメータの取得・設定を行うためのメカニズムです。
    *   `sysctl`は、カーネルの内部状態や設定をユーザー空間からアクセスするためのインターフェースを提供します。
    *   `NET_RT_IFLIST`や`NET_RT_IFLISTL`は、`sysctl`コマンドの一種で、ネットワークインターフェースのリストとその詳細情報を取得するために使用されます。`NET_RT_IFLISTL`は、`NET_RT_IFLIST`の拡張版であり、より新しいFreeBSDバージョンで導入された可能性が高いです。

3.  **`if_msghdr` (`IfMsghdr`) と `ifa_msghdr` (`IfaMsghdr`)**:
    *   ルーティングソケットを通じてやり取りされるメッセージのヘッダ構造体です。
    *   `if_msghdr`はネットワークインターフェース自体の情報（例: インターフェース名、フラグ、インデックス）を含みます。
    *   `ifa_msghdr`はネットワークインターフェースに割り当てられたアドレス情報（例: IPアドレス、ネットマスク）を含みます。
    *   これらの構造体には、メッセージの長さ、バージョン、タイプ、関連するアドレスの数などのメタデータが含まれます。

4.  **`if_data` (`IfData`)**:
    *   `if_msghdr`構造体の一部として含まれる、ネットワークインターフェースの統計情報や状態を格納する構造体です。
    *   送受信パケット数、エラー数、衝突数、帯域幅、MTU（Maximum Transmission Unit）などの詳細なデータが含まれます。
    *   OSのバージョンアップに伴い、この構造体のフィールドが追加、削除、または再配置されることがあります。

5.  **`freebsdVersion`**:
    *   Goの`syscall`パッケージ内でFreeBSDのバージョンを識別するために使用される変数です。
    *   これにより、Goプログラムは実行中のFreeBSDのバージョンに応じて、異なるシステムコールやデータ構造のレイアウトを動的に選択できます。これは、OSのバージョン間の互換性を維持するために非常に重要です。

6.  **`unsafe.Pointer`**:
    *   Go言語の`unsafe`パッケージに含まれる型で、任意の型のポインタを保持できます。
    *   C言語の構造体とGo言語の構造体の間でデータを変換する際など、型安全性をバイパスしてメモリを直接操作する必要がある場合に使用されます。このコミットでは、ルーティングソケットから受信したバイト列をGoの構造体にキャストするために多用されています。

## 技術的詳細

このコミットの核となる技術的変更は、FreeBSDのルーティングソケットメッセージのパースロジックを、OSのバージョンに応じて動的に適応させる点にあります。

1.  **`NET_RT_IFLISTL`の導入**:
    *   `src/net/interface_freebsd.go`において、ネットワークインターフェース情報を取得するための`sysctl`定数が`syscall.NET_RT_IFLIST`から`syscall.NET_RT_IFLISTL`に変更されました。これは、FreeBSD 11.0以降で導入された新しい、より詳細なインターフェース情報を提供するAPIを利用するためです。
    *   他のBSD系OS（Darwin, DragonFly, NetBSD, OpenBSD）では引き続き`syscall.NET_RT_IFLIST`が使用されるよう、`rtSockIfListSyscall`という定数が導入され、各OS固有のファイルで定義されています。

2.  **`IfMsghdr`と`IfaMsghdr`の「l」バリアントへの切り替え**:
    *   `src/syscall/types_freebsd.go`では、C言語のヘッダファイルに定義されている`if_msghdrl11`と`ifa_msghdrl11`という新しい構造体が導入されました。これらは、FreeBSD 11.0で変更された`if_msghdr`と`ifa_msghdr`の「long」バージョンに相当します。
    *   Goの`syscall`パッケージ内の`IfMsghdr`と`IfaMsghdr`型は、これらの新しいC構造体に対応するように再定義されました。
    *   また、`if_msghdrl_fixed`と`ifa_msghdrl_fixed`という、`if_data`部分を含まないヘッダ部分のみの構造体も定義され、メッセージのヘッダ部分を先にパースするために使用されます。

3.  **`IfData`構造体のFreeBSDバージョンごとの適応**:
    *   最も重要な変更は、`if_data`構造体のレイアウトがFreeBSDのバージョンによって異なるため、これを動的に処理するロジックが`src/syscall/route_freebsd.go`に導入されたことです。
    *   `if_data11_raw`と`if_data10`という、FreeBSD 11.0とFreeBSD 10.xの`if_data`構造体に対応するC構造体が`src/syscall/types_freebsd.go`に定義されました。
    *   Goの`IfData`構造体は、FreeBSD 11.0の`if_data11`に対応するように更新されました。
    *   `anyMessage`型に`parseInterfaceMessage`と`parseInterfaceAddrMessage`という新しいメソッドが追加されました。これらのメソッドは、受信したルーティングソケットメッセージのバイト列をパースする際に、`freebsdVersion`の値に基づいて適切な`IfData`レイアウトを選択します。
    *   具体的には、`freebsdVersion >= 1100011`（FreeBSD 11.0以降）の場合は`ifData11Raw`を使用し、`freebsdVersion >= 1001000`（FreeBSD 10.1以降）の場合は`ifData10`を使用します。
    *   `IfData`構造体には、`copyFromV11Raw`と`copyFromV10`というヘルパーメソッドが追加され、それぞれのバージョンの生データからGoの`IfData`構造体にデータをコピーする役割を担います。これにより、異なるバージョンの`if_data`構造体からでも統一された`IfData`型としてアクセスできるようになります。

4.  **`Epoch`と`Lastchange`フィールドの処理**:
    *   FreeBSD 11.0の`if_data11_raw`構造体では、`ifi_epoch`と`ifi_lastchange`フィールドが`union`として定義されており、直接アクセスすることができません。
    *   このため、`src/syscall/syscall_freebsd_386.go`、`src/syscall/syscall_freebsd_amd64.go`、`src/syscall/syscall_freebsd_arm.go`に、`fillEpochLastChange`という関数が追加されました。この関数は、`ifData11Raw`のバイト列から`Epoch`と`Lastchange`の値を`unsafe.Pointer`と型キャストを駆使して抽出し、Goの`IfData`構造体に設定します。これは、アーキテクチャ（386, amd64, arm）によってポインタのサイズやアライメントが異なるため、それぞれのファイルで実装されています。

5.  **生成された型定義の更新**:
    *   `src/syscall/ztypes_freebsd_386.go`と`src/syscall/ztypes_freebsd_amd64.go`は、`mksyscall.sh`スクリプトによって自動生成されるファイルです。このコミットでは、`types_freebsd.go`の変更に伴い、これらのファイル内のGo構造体定義（`IfData`, `IfMsghdr`, `IfaMsghdr`など）も更新され、新しいフィールドやサイズが反映されています。

これらの変更により、GoはFreeBSDのルーティングソケットAPIの進化に対応し、異なるFreeBSDバージョン間でのネットワークインターフェース情報の取得と解析の互換性を確保しています。

`src/syscall/route_freebsd.go`の`parseInterfaceMessage`メソッドを例に、コアとなる変更を解説します。

```go
func (any *anyMessage) parseInterfaceMessage(b []byte) *InterfaceMessage {
	p := (*ifMsghdrFixed)(unsafe.Pointer(any)) // まず固定長のヘッダ部分をパース
	h := IfMsghdr{ // GoのIfMsghdr構造体にデータをコピー
		Msglen:   p.Msglen,
		Version:  p.Version,
		Type:     p.Type,
		Addrs:    p.Addrs,
		Flags:    p.Flags,
		Index:    p.Index,
		Len:      p.Len,
		Data_off: p.Data_off,
	}

	switch {
	case freebsdVersion >= 1100011: // FreeBSD 11.0以降の場合
		// FreeBSD 11 uses a new struct if_data layout
		// See https://svnweb.freebsd.org/base?view=revision&revision=263102
		data11 := *(*ifData11Raw)(unsafe.Pointer(&b[p.Data_off:p.Len][0])) // FreeBSD 11の生データ構造体としてキャスト
		h.Data.copyFromV11Raw(&data11) // GoのIfDataにコピー
	case freebsdVersion >= 1001000: // FreeBSD 10.1以降の場合
		// FreeBSD 10.1 and newer
		data10 := *(*ifData10)(unsafe.Pointer(&b[p.Data_off:p.Len][0])) // FreeBSD 10の生データ構造体としてキャスト
		h.Data.copyFromV10(&data10) // GoのIfDataにコピー
	case freebsdVersion >= 903000:
		// TODO (FreeBSD 9.3の対応はまだ)
	}

	return &InterfaceMessage{Header: h, Data: b[p.Len:any.Msglen]}
}
```

このコードスニペットは、ルーティングソケットから受信したバイト列`b`をGoの`InterfaceMessage`構造体に変換するプロセスを示しています。

1.  **`p := (*ifMsghdrFixed)(unsafe.Pointer(any))`**:
    *   `any`は受信したメッセージの生バイト列の先頭を指す`unsafe.Pointer`です。
    *   まず、メッセージの先頭部分を`ifMsghdrFixed`という固定長のヘッダ構造体として解釈します。これは、`if_msghdrl`構造体から`if_data`部分を除いたもので、メッセージの基本的なメタデータ（長さ、バージョン、タイプなど）と、`if_data`部分のオフセットと長さ（`Len`と`Data_off`）を取得するために使用されます。

2.  **`h := IfMsghdr{...}`**:
    *   `ifMsghdrFixed`から取得した情報を基に、Goの`IfMsghdr`構造体のヘッダ部分を初期化します。

3.  **`switch { ... }`**:
    *   ここで`freebsdVersion`変数を用いて、実行中のFreeBSDのバージョンを判定します。
    *   **`case freebsdVersion >= 1100011:`**: FreeBSD 11.0以降の場合の処理です。
        *   `data11 := *(*ifData11Raw)(unsafe.Pointer(&b[p.Data_off:p.Len][0]))`: `p.Data_off`から`p.Len`までのバイト列を、FreeBSD 11.0の`if_data`構造体に対応する`ifData11Raw`型として解釈します。`ifData11Raw`は、C言語の`union`を含む生データ構造体です。
        *   `h.Data.copyFromV11Raw(&data11)`: `ifData11Raw`からGoの`IfData`構造体（`h.Data`）に必要なフィールドをコピーします。このメソッド内で、`union`として定義されている`Epoch`や`Lastchange`フィールドは、`syscall_freebsd_*.go`で定義された`fillEpochLastChange`関数を通じて適切に抽出されます。
    *   **`case freebsdVersion >= 1001000:`**: FreeBSD 10.1以降の場合の処理です。
        *   `data10 := *(*ifData10)(unsafe.Pointer(&b[p.Data_off:p.Len][0]))`: 同様に、FreeBSD 10.xの`if_data`構造体に対応する`ifData10`型としてバイト列を解釈します。
        *   `h.Data.copyFromV10(&data10)`: `ifData10`からGoの`IfData`構造体に必要なフィールドをコピーします。

4.  **`return &InterfaceMessage{Header: h, Data: b[p.Len:any.Msglen]}`**:
    *   最終的に、パースされたヘッダ`h`と、`if_data`部分に続く残りのメッセージデータ（もしあれば）を結合して、完全な`InterfaceMessage`を返します。

この動的なバージョン判定とデータ構造の適応により、GoはFreeBSDの異なるバージョンでルーティングソケットメッセージを正しく処理できるようになります。

このコミットは、FreeBSDのルーティングソケットAPIの変更に対応するため、Goの`syscall`パッケージを更新します。具体的には、`IfMsghdr`と`IfaMsghdr`を新しい「l」バリアント（`if_msghdrl`と`ifa_msghdrl`）に切り替え、`IfData`構造体のレイアウトをFreeBSD 11.0の定義に合わせます。`freebsdVersion`変数を用いて実行時にFreeBSDのバージョンを検出し、適切なデータレイアウトでルーティングソケットメッセージをデコードするように変更されます。これにより、FreeBSDの異なるバージョン間での互換性が維持されます。

## 変更の背景

FreeBSDのカーネルAPI、特にネットワーク関連のデータ構造は、OSのバージョンアップに伴い変更されることがあります。このコミットの背景には、FreeBSD 11.0でルーティングソケットメッセージの構造が変更されたことがあります。具体的には、ネットワークインターフェースの統計情報や設定をやり取りするための`if_msghdr`および`ifa_msghdr`構造体、そしてそれらに含まれる`if_data`構造体のレイアウトが更新されました。

以前のGoの`syscall`パッケージは、古いFreeBSDバージョンのデータ構造を前提としていました。このため、FreeBSD 11.0以降のシステムでGoプログラムがネットワークインターフェース情報を正しく取得・解析できない問題（Issue #11641）が発生していました。この変更は、この互換性の問題を解決し、Goが新しいFreeBSD環境でも正しく動作するようにするために必要でした。

新しい構造体は、より多くの情報を含んだり、フィールドの配置が変更されたりすることが一般的です。特に、`NET_RT_IFLIST`から`NET_RT_IFLISTL`への切り替えは、より詳細な情報（"L"は"long"または"large"を意味することが多い）を提供する新しい`sysctl`インターフェースが導入されたことを示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **ルーティングソケット (Routing Socket)**:
    *   Unix系OS（FreeBSDを含む）において、カーネルのルーティングテーブルやネットワークインターフェースの状態に関する情報を取得したり、設定を変更したりするための特殊なソケットです。
    *   アプリケーションはルーティングソケットを通じて、インターフェースの追加/削除、IPアドレスの割り当て、ルーティングエントリの操作などを行います。
    *   カーネルは、ネットワークイベント（例: インターフェースのアップ/ダウン、IPアドレスの変更）が発生した際に、ルーティングソケットにメッセージを送信してアプリケーションに通知します。

2.  **`sysctl`**:
    *   Unix系OSにおけるシステムパラメータの取得・設定を行うためのメカニズムです。
    *   `sysctl`は、カーネルの内部状態や設定をユーザー空間からアクセスするためのインターフェースを提供します。
    *   `NET_RT_IFLIST`や`NET_RT_IFLISTL`は、`sysctl`コマンドの一種で、ネットワークインターフェースのリストとその詳細情報を取得するために使用されます。`NET_RT_IFLISTL`は、`NET_RT_IFLIST`の拡張版であり、より新しいFreeBSDバージョンで導入された可能性が高いです。

3.  **`if_msghdr` (`IfMsghdr`) と `ifa_msghdr` (`IfaMsghdr`)**:
    *   ルーティングソケットを通じてやり取りされるメッセージのヘッダ構造体です。
    *   `if_msghdr`はネットワークインターフェース自体の情報（例: インターフェース名、フラグ、インデックス）を含みます。
    *   `ifa_msghdr`はネットワークインターフェースに割り当てられたアドレス情報（例: IPアドレス、ネットマスク）を含みます。
    *   これらの構造体には、メッセージの長さ、バージョン、タイプ、関連するアドレスの数などのメタデータが含まれます。

4.  **`if_data` (`IfData`)**:
    *   `if_msghdr`構造体の一部として含まれる、ネットワークインターフェースの統計情報や状態を格納する構造体です。
    *   送受信パケット数、エラー数、衝突数、帯域幅、MTU（Maximum Transmission Unit）などの詳細なデータが含まれます。
    *   OSのバージョンアップに伴い、この構造体のフィールドが追加、削除、または再配置されることがあります。

5.  **`freebsdVersion`**:
    *   Goの`syscall`パッケージ内でFreeBSDのバージョンを識別するために使用される変数です。
    *   これにより、Goプログラムは実行中のFreeBSDのバージョンに応じて、異なるシステムコールやデータ構造のレイアウトを動的に選択できます。これは、OSのバージョン間の互換性を維持するために非常に重要です。

6.  **`unsafe.Pointer`**:
    *   Go言語の`unsafe`パッケージに含まれる型で、任意の型のポインタを保持できます。
    *   C言語の構造体とGo言語の構造体の間でデータを変換する際など、型安全性をバイパスしてメモリを直接操作する必要がある場合に使用されます。このコミットでは、ルーティングソケットから受信したバイト列をGoの構造体にキャストするために多用されています。

## 技術的詳細

このコミットの核となる技術的変更は、FreeBSDのルーティングソケットメッセージのパースロジックを、OSのバージョンに応じて動的に適応させる点にあります。

1.  **`NET_RT_IFLISTL`の導入**:
    *   `src/net/interface_freebsd.go`において、ネットワークインターフェース情報を取得するための`sysctl`定数が`syscall.NET_RT_IFLIST`から`syscall.NET_RT_IFLISTL`に変更されました。これは、FreeBSD 11.0以降で導入された新しい、より詳細なインターフェース情報を提供するAPIを利用するためです。
    *   他のBSD系OS（Darwin, DragonFly, NetBSD, OpenBSD）では引き続き`syscall.NET_RT_IFLIST`が使用されるよう、`rtSockIfListSyscall`という定数が導入され、各OS固有のファイルで定義されています。

2.  **`IfMsghdr`と`IfaMsghdr`の「l」バリアントへの切り替え**:
    *   `src/syscall/types_freebsd.go`では、C言語のヘッダファイルに定義されている`if_msghdrl11`と`ifa_msghdrl11`という新しい構造体が導入されました。これらは、FreeBSD 11.0で変更された`if_msghdr`と`ifa_msghdr`の「long」バージョンに相当します。
    *   Goの`syscall`パッケージ内の`IfMsghdr`と`IfaMsghdr`型は、これらの新しいC構造体に対応するように再定義されました。
    *   また、`if_msghdrl_fixed`と`ifa_msghdrl_fixed`という、`if_data`部分を含まないヘッダ部分のみの構造体も定義され、メッセージのヘッダ部分を先にパースするために使用されます。

3.  **`IfData`構造体のFreeBSDバージョンごとの適応**:
    *   最も重要な変更は、`if_data`構造体のレイアウトがFreeBSDのバージョンによって異なるため、これを動的に処理するロジックが`src/syscall/route_freebsd.go`に導入されたことです。
    *   `if_data11_raw`と`if_data10`という、FreeBSD 11.0とFreeBSD 10.xの`if_data`構造体に対応するC構造体が`src/syscall/types_freebsd.go`に定義されました。
    *   Goの`IfData`構造体は、FreeBSD 11.0の`if_data11`に対応するように更新されました。
    *   `anyMessage`型に`parseInterfaceMessage`と`parseInterfaceAddrMessage`という新しいメソッドが追加されました。これらのメソッドは、受信したルーティングソケットメッセージのバイト列をパースする際に、`freebsdVersion`の値に基づいて適切な`IfData`レイアウトを選択します。
    *   具体的には、`freebsdVersion >= 1100011`（FreeBSD 11.0以降）の場合は`ifData11Raw`を使用し、`freebsdVersion >= 1001000`（FreeBSD 10.1以降）の場合は`ifData10`を使用します。
    *   `IfData`構造体には、`copyFromV11Raw`と`copyFromV10`というヘルパーメソッドが追加され、それぞれのバージョンの生データからGoの`IfData`構造体にデータをコピーする役割を担います。これにより、異なるバージョンの`if_data`構造体からでも統一された`IfData`型としてアクセスできるようになります。

4.  **`Epoch`と`Lastchange`フィールドの処理**:
    *   FreeBSD 11.0の`if_data11_raw`構造体では、`ifi_epoch`と`ifi_lastchange`フィールドが`union`として定義されており、直接アクセスすることができません。
    *   このため、`src/syscall/syscall_freebsd_386.go`、`src/syscall/syscall_freebsd_amd64.go`、`src/syscall/syscall_freebsd_arm.go`に、`fillEpochLastChange`という関数が追加されました。この関数は、`ifData11Raw`のバイト列から`Epoch`と`Lastchange`の値を`unsafe.Pointer`と型キャストを駆使して抽出し、Goの`IfData`構造体に設定します。これは、アーキテクチャ（386, amd64, arm）によってポインタのサイズやアライメントが異なるため、それぞれのファイルで実装されています。

5.  **生成された型定義の更新**:
    *   `src/syscall/ztypes_freebsd_386.go`と`src/syscall/ztypes_freebsd_amd64.go`は、`mksyscall.sh`スクリプトによって自動生成されるファイルです。このコミットでは、`types_freebsd.go`の変更に伴い、これらのファイル内のGo構造体定義（`IfData`, `IfMsghdr`, `IfaMsghdr`など）も更新され、新しいフィールドやサイズが反映されています。

これらの変更により、GoはFreeBSDのルーティングソケットAPIの進化に対応し、異なるFreeBSDバージョン間でのネットワークインターフェース情報の取得と解析の互換性を確保しています。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に以下のファイルに集中しています。

1.  **`src/syscall/route_freebsd.go`**:
    *   `anyMessage.toRoutingMessage`メソッド内で、`RTM_IFINFO`、`RTM_NEWADDR`、`RTM_DELADDR`メッセージの処理が変更され、新しい`parseInterfaceMessage`および`parseInterfaceAddrMessage`メソッドが呼び出されるようになりました。
    *   `parseInterfaceMessage`メソッドが追加され、`ifMsghdrFixed`を使用してヘッダをパースした後、`freebsdVersion`に基づいて`ifData11Raw`または`ifData10`から`IfData`を構築するロジックが実装されました。
    *   `parseInterfaceAddrMessage`メソッドが追加され、`ifaMsghdrFixed`を使用してヘッダをパースした後、同様に`freebsdVersion`に基づいて`IfData`を構築するロジックが実装されました。
    *   `IfData`型に`copyFromV11Raw`と`copyFromV10`メソッドが追加され、それぞれのバージョンの生データからフィールドをコピーする処理が定義されました。

2.  **`src/syscall/types_freebsd.go`**:
    *   FreeBSD 11.0の`if_data11_raw`、`if_data11`、`if_msghdrl11`、`ifa_msghdrl11`構造体がC言語の定義として追加されました。
    *   FreeBSD 10.xの`if_data10`構造体がC言語の定義として追加されました。
    *   Goの`IfData`、`IfMsghdr`、`IfaMsghdr`型が、これらの新しいC構造体に対応するように更新されました。
    *   `if_msghdrl_fixed`と`ifa_msghdrl_fixed`という、ヘッダ部分のみのC構造体が追加されました。

3.  **`src/syscall/syscall_freebsd_*.go` (386, amd64, arm)**:
    *   `fillEpochLastChange`関数が追加され、`ifData11Raw`構造体内の`union`として定義されている`Epoch`と`Lastchange`フィールドを、`unsafe.Pointer`とバイトスライス操作を用いて抽出するロジックが実装されました。これはアーキテクチャ固有の処理です。

4.  **`src/net/interface_freebsd.go`**:
    *   `rtSockIfListSyscall`定数が`syscall.NET_RT_IFLISTL`として定義されました。

## コアとなるコードの解説

`src/syscall/route_freebsd.go`の`parseInterfaceMessage`メソッドを例に、コアとなる変更を解説します。

```go
func (any *anyMessage) parseInterfaceMessage(b []byte) *InterfaceMessage {
	p := (*ifMsghdrFixed)(unsafe.Pointer(any)) // まず固定長のヘッダ部分をパース
	h := IfMsghdr{ // GoのIfMsghdr構造体にデータをコピー
		Msglen:   p.Msglen,
		Version:  p.Version,
		Type:     p.Type,
		Addrs:    p.Addrs,
		Flags:    p.Flags,
		Index:    p.Index,
		Len:      p.Len,
		Data_off: p.Data_off,
	}

	switch {
	case freebsdVersion >= 1100011: // FreeBSD 11.0以降の場合
		// FreeBSD 11 uses a new struct if_data layout
		// See https://svnweb.freebsd.org/base?view=revision&revision=263102
		data11 := *(*ifData11Raw)(unsafe.Pointer(&b[p.Data_off:p.Len][0])) // FreeBSD 11の生データ構造体としてキャスト
		h.Data.copyFromV11Raw(&data11) // GoのIfDataにコピー
	case freebsdVersion >= 1001000: // FreeBSD 10.1以降の場合
		// FreeBSD 10.1 and newer
		data10 := *(*ifData10)(unsafe.Pointer(&b[p.Data_off:p.Len][0])) // FreeBSD 10の生データ構造体としてキャスト
		h.Data.copyFromV10(&data10) // GoのIfDataにコピー
	case freebsdVersion >= 903000:
		// TODO (FreeBSD 9.3の対応はまだ)
	}

	return &InterfaceMessage{Header: h, Data: b[p.Len:any.Msglen]}
}
```

このコードスニペットは、ルーティングソケットから受信したバイト列`b`をGoの`InterfaceMessage`構造体に変換するプロセスを示しています。

1.  **`p := (*ifMsghdrFixed)(unsafe.Pointer(any))`**:
    *   `any`は受信したメッセージの生バイト列の先頭を指す`unsafe.Pointer`です。
    *   まず、メッセージの先頭部分を`ifMsghdrFixed`という固定長のヘッダ構造体として解釈します。これは、`if_msghdrl`構造体から`if_data`部分を除いたもので、メッセージの基本的なメタデータ（長さ、バージョン、タイプなど）と、`if_data`部分のオフセットと長さ（`Len`と`Data_off`）を取得するために使用されます。

2.  **`h := IfMsghdr{...}`**:
    *   `ifMsghdrFixed`から取得した情報を基に、Goの`IfMsghdr`構造体のヘッダ部分を初期化します。

3.  **`switch { ... }`**:
    *   ここで`freebsdVersion`変数を用いて、実行中のFreeBSDのバージョンを判定します。
    *   **`case freebsdVersion >= 1100011:`**: FreeBSD 11.0以降の場合の処理です。
        *   `data11 := *(*ifData11Raw)(unsafe.Pointer(&b[p.Data_off:p.Len][0]))`: `p.Data_off`から`p.Len`までのバイト列を、FreeBSD 11.0の`if_data`構造体に対応する`ifData11Raw`型として解釈します。`ifData11Raw`は、C言語の`union`を含む生データ構造体です。
        *   `h.Data.copyFromV11Raw(&data11)`: `ifData11Raw`からGoの`IfData`構造体（`h.Data`）に必要なフィールドをコピーします。このメソッド内で、`union`として定義されている`Epoch`や`Lastchange`フィールドは、`syscall_freebsd_*.go`で定義された`fillEpochLastChange`関数を通じて適切に抽出されます。
    *   **`case freebsdVersion >= 1001000:`**: FreeBSD 10.1以降の場合の処理です。
        *   `data10 := *(*ifData10)(unsafe.Pointer(&b[p.Data_off:p.Len][0]))`: 同様に、FreeBSD 10.xの`if_data`構造体に対応する`ifData10`型としてバイト列を解釈します。
        *   `h.Data.copyFromV10(&data10)`: `ifData10`からGoの`IfData`構造体に必要なフィールドをコピーします。

4.  **`return &InterfaceMessage{Header: h, Data: b[p.Len:any.Msglen]}`**:
    *   最終的に、パースされたヘッダ`h`と、`if_data`部分に続く残りのメッセージデータ（もしあれば）を結合して、完全な`InterfaceMessage`を返します。

この動的なバージョン判定とデータ構造の適応により、GoはFreeBSDの異なるバージョンでルーティングソケットメッセージを正しく処理できるようになります。
