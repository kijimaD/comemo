# [インデックス 25311] ファイルの概要

このコミットは、Go言語の`fmt`パッケージにおけるスキャン機能の改善に関するものです。具体的には、`fmt.Scanf`関数が大文字の`%X`フォーマット動詞を使用して文字列やバイトスライスをスキャンする際の挙動を修正し、小文字の`%x`と同様に正しく処理できるようにします。

## 元コミット内容

`fmt`: スキャン用に大文字の`%X`フォーマット動詞のサポートを追加

出力時には、`%X`フォーマット動詞はフォーマットされた値の大文字の16進数表現を生成します。逆に、`Scanf`関数で`%X`を使用する場合、16進数表現を所与の`interface{}`にスキャンするべきです。しかし、既存の実装では、`%X`は整数への16進数値のスキャンのみをサポートしており、文字列やバイトスライスは空のままでした。一方、小文字の`%x`は文字列とバイトスライスを問題なくサポートしていました。これは単なる見落としであり、このコミットで修正されます。（追加のテストも含まれています。）

`Fixes #12940`

## 変更の背景

このコミットの背景には、Go言語の標準ライブラリである`fmt`パッケージにおける一貫性の欠如がありました。`fmt`パッケージは、GoプログラムにおけるフォーマットされたI/O（入出力）を扱うための機能を提供します。具体的には、`fmt.Printf`のような関数で値を出力する際に、`%x`と`%X`というフォーマット動詞を使って数値を16進数形式で表現できます。ここで、`%x`は小文字の16進数（例: `a`, `b`, `c`）を、`%X`は大文字の16進数（例: `A`, `B`, `C`）を使用します。

この一貫性は、入力（スキャン）側である`fmt.Scanf`関数にも期待されるべきでした。しかし、コミットメッセージが指摘するように、`fmt.Scanf`の既存の実装では、`%X`を使って16進数文字列をスキャンする際に、それが整数型にスキャンされる場合は正しく機能しましたが、文字列型（`string`）やバイトスライス型（`[]byte`）にスキャンしようとすると、結果が空になってしまうという問題がありました。これに対し、小文字の`%x`はこれらの型に対しても正しく機能していました。

この挙動の不一致は、ユーザーが`%X`を期待通りに使用できないというバグ（Issue #12940）として報告されました。このコミットは、この「単なる見落とし」を修正し、`fmt.Scanf`が`%X`を使って文字列やバイトスライスをスキャンする際にも、小文字の`%x`と同様に正しく機能するようにすることで、`fmt`パッケージのフォーマット動詞の挙動に一貫性をもたらすことを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と`fmt`パッケージの機能に関する知識が必要です。

1.  **`fmt`パッケージ**: Go言語の標準ライブラリの一部で、フォーマットされたI/O（入出力）を実装するための関数を提供します。`Printf`系の関数は値をフォーマットして出力し、`Scanf`系の関数はフォーマットされた入力から値を読み取ります。

2.  **フォーマット動詞 (Format Verbs)**: `fmt`パッケージの関数で使用される特殊な記号で、値の表示形式や解釈形式を指定します。例えば、`%d`は10進整数、`%s`は文字列、`%v`はデフォルト形式などを意味します。

3.  **`%x`と`%X`**:
    *   **出力時 (`Printf`系)**:
        *   `%x`: 数値を小文字の16進数形式で出力します（例: `10` -> `a`）。
        *   `%X`: 数値を大文字の16進数形式で出力します（例: `10` -> `A`）。
    *   **入力時 (`Scanf`系)**:
        *   `%x`: 入力文字列を小文字または大文字の16進数として解釈し、対応する値に変換します。
        *   `%X`: 本来は`%x`と同様に16進数として解釈するべきですが、このコミット以前は文字列やバイトスライスに対しては機能していませんでした。

4.  **`fmt.Scanf`関数**: フォーマット文字列に基づいて入力ストリーム（通常は標準入力）から値を読み取り、指定された変数に格納します。フォーマット文字列は、読み取るデータの形式と、それを格納する変数の型を指示します。

5.  **`interface{}`**: Go言語における空のインターフェース型です。任意の型の値を保持できるため、`fmt.Scanf`のような汎用的な関数で、スキャンされた値を任意の型の変数に格納するために使用されます。

6.  **16進数表現 (Hexadecimal Representation)**: 基数が16の数値表現システムです。0-9とA-F（またはa-f）の文字を使用して値を表します。コンピュータサイエンスでは、バイトデータやメモリアドレスなどを簡潔に表現するためによく用いられます。

7.  **文字列 (string) とバイトスライス (`[]byte`)**:
    *   `string`: Go言語における不変のバイト列で、通常はUTF-8エンコードされたテキストを表します。
    *   `[]byte`: 可変長のバイト列で、バイナリデータやテキストのバイト表現を扱うのに使われます。
    `fmt.Scanf`は、これらの型に対しても16進数表現をスキャンできる必要があります。

このコミットは、`fmt.Scanf`が`%X`フォーマット動詞を文字列やバイトスライスに対して正しく適用できるように、内部的な処理ロジックを調整するものです。

## 技術的詳細

このコミットの技術的な詳細は、`src/fmt/scan.go`ファイル内の`convertString`関数と、それに関連する`okVerb`関数の呼び出しに焦点を当てています。

`fmt`パッケージの`Scanf`系の関数は、入力文字列を解析し、指定されたフォーマット動詞に基づいて値をGoのデータ型に変換します。この変換処理の大部分は、`ss`（scanState）構造体のメソッドによって行われます。

`convertString`関数は、特定のフォーマット動詞（`verb`）に基づいて入力から文字列を抽出する役割を担っています。この関数は、まず`s.okVerb`を呼び出して、与えられた`verb`が文字列型への変換に適しているかどうかを検証します。

コミット前の`s.okVerb`の呼び出しは以下のようになっていました。
`if !s.okVerb(verb, "svqx", "string") { ... }`
ここで、`"svqx"`は、`s` (string), `v` (value), `q` (quoted string), `x` (hexadecimal) の各フォーマット動詞が文字列スキャンで許可されていることを示しています。しかし、大文字の`X`は含まれていませんでした。これが、`%X`が文字列やバイトスライスに対して機能しなかった根本原因です。`okVerb`が`%X`を許可しないため、`convertString`関数は早期にリターンし、空の文字列を返していました。

このコミットでは、`s.okVerb`の呼び出しに`X`を追加することで、大文字の`%X`も文字列スキャンで許可されるように変更されました。
`if !s.okVerb(verb, "svqxX", "string") { ... }`

さらに、`convertString`関数内の`switch verb`ステートメントも修正されています。この`switch`は、具体的なフォーマット動詞に基づいて異なるスキャンロジックを適用します。
コミット前は、16進数スキャンは`case 'x':`のみで処理されていました。
`case 'x': str = s.hexString()`
この変更により、`case 'x', 'X':`とすることで、小文字の`%x`と大文字の`%X`の両方が`s.hexString()`メソッドを呼び出すようになります。`s.hexString()`は、入力ストリームから16進数文字列を読み取り、それを通常の文字列に変換する内部ヘルパー関数です。この関数自体は、入力が大文字か小文字かに関わらず16進数を正しく解釈できるため、この変更だけで`%X`が文字列やバイトスライスに対して機能するようになります。

`scan_test.go`の変更は、これらの修正が正しく機能することを確認するためのテストケースの追加です。`%X`を使って文字列とバイトスライスをスキャンする新しいテストが追加され、期待される大文字の16進数表現が正しくスキャンされることを検証しています。

`src/fmt/scan_test.go`における変更は、これらの修正が意図通りに機能することを検証するためのテストケースの追加です。

*   `{\"%X\", \"7573696E672D2558\\n\", &stringVal, \"using-%X\"},`
*   `{\"%X\", \"62797465732D2558\\n\", &bytesVal, []byte(\"bytes-%X\")},`

このコミットは、`fmt.Scanf`が`%X`フォーマット動詞を文字列やバイトスライスに対して正しく適用できるように、内部的な処理ロジックを調整するものです。

## 技術的詳細

このコミットの技術的な詳細は、`src/fmt/scan.go`ファイル内の`convertString`関数と、それに関連する`okVerb`関数の呼び出しに焦点を当てています。

`fmt`パッケージの`Scanf`系の関数は、入力文字列を解析し、指定されたフォーマット動詞に基づいて値をGoのデータ型に変換します。この変換処理の大部分は、`ss`（scanState）構造体のメソッドによって行われます。

`convertString`関数は、特定のフォーマット動詞（`verb`）に基づいて入力から文字列を抽出する役割を担っています。この関数は、まず`s.okVerb`を呼び出して、与えられた`verb`が文字列型への変換に適しているかどうかを検証します。

コミット前の`s.okVerb`の呼び出しは以下のようになっていました。
`if !s.okVerb(verb, "svqx", "string") { ... }`
ここで、`"svqx"`は、`s` (string), `v` (value), `q` (quoted string), `x` (hexadecimal) の各フォーマット動詞が文字列スキャンで許可されていることを示しています。しかし、大文字の`X`は含まれていませんでした。これが、`%X`が文字列やバイトスライスに対して機能しなかった根本原因です。`okVerb`が`%X`を許可しないため、`convertString`関数は早期にリターンし、空の文字列を返していました。

このコミットでは、`s.okVerb`の呼び出しに`X`を追加することで、大文字の`%X`も文字列スキャンで許可されるように変更されました。
`if !s.okVerb(verb, "svqxX", "string") { ... }`

さらに、`convertString`関数内の`switch verb`ステートメントも修正されています。この`switch`は、具体的なフォーマット動詞に基づいて異なるスキャンロジックを適用します。
コミット前は、16進数スキャンは`case 'x':`のみで処理されていました。
`case 'x': str = s.hexString()`
この変更により、`case 'x', 'X':`とすることで、小文字の`%x`と大文字の`%X`の両方が`s.hexString()`メソッドを呼び出すようになります。`s.hexString()`は、入力ストリームから16進数文字列を読み取り、それを通常の文字列に変換する内部ヘルパー関数です。この関数自体は、入力が大文字か小文字かに関わらず16進数を正しく解釈できるため、この変更だけで`%X`が文字列やバイトスライスに対して機能するようになります。

`scan_test.go`の変更は、これらの修正が正しく機能することを確認するためのテストケースの追加です。`%X`を使って文字列とバイトスライスをスキャンする新しいテストが追加され、期待される大文字の16進数表現が正しくスキャンされることを検証しています。

## コアとなるコードの解説

`src/fmt/scan.go`における変更は、`convertString`関数が`%X`フォーマット動詞を正しく処理できるようにするためのものです。

1.  **`s.okVerb(verb, "svqx", "string")` から `s.okVerb(verb, "svqxX", "string")` への変更**:
    *   `s.okVerb`は、与えられた`verb`（フォーマット動詞）が、特定の型（この場合は`"string"`）のスキャン操作で許可されているかどうかをチェックする内部ヘルパー関数です。
    *   変更前は、許可される動詞のリストに大文字の`'X'`が含まれていませんでした。このため、`fmt.Scanf`が`%X`を使って文字列をスキャンしようとすると、`okVerb`チェックで失敗し、`convertString`関数はすぐに空の文字列を返していました。
    *   変更後、許可される動詞のリストに`'X'`が追加されたことで、`%X`が文字列スキャン操作で有効なフォーマット動詞として認識されるようになりました。これにより、`convertString`関数は`%X`が指定された場合でも処理を続行できるようになります。

2.  **`case 'x':` から `case 'x', 'X':` への変更**:
    *   `convertString`関数内の`switch`ステートメントは、具体的なフォーマット動詞に基づいて異なるスキャンロジックを選択します。
    *   変更前は、16進数スキャンを担当する`s.hexString()`メソッドは、`'x'`（小文字の16進数）の場合にのみ呼び出されていました。
    *   変更後、`'x'`と`'X'`の両方のケースで`s.hexString()`が呼び出されるようになりました。`s.hexString()`メソッド自体は、入力された16進数文字列が大文字か小文字かに関わらず、正しく解析して通常の文字列に変換する能力を持っています。したがって、この変更により、`%X`が指定された場合でも、入力された大文字の16進数文字列が正しくスキャンされ、対応する文字列やバイトスライスに変換されるようになります。

`src/fmt/scan_test.go`における変更は、これらの修正が意図通りに機能することを検証するためのテストケースの追加です。

*   `{\"%X\", \"7573696E672D2558\\n\", &stringVal, \"using-%X\"},`
*   `{\"%X\", \"62797465732D2558\\n\", &bytesVal, []byte(\"bytes-%X\")},`

これらのテストケースは、`%X`フォーマット動詞を使用して、大文字の16進数表現（例: `7573696E672D2558`）がそれぞれ`string`型と`[]byte`型に正しくスキャンされることを確認します。これにより、修正が正しく適用され、`fmt.Scanf`が`%X`を期待通りに扱えるようになったことが保証されます。
