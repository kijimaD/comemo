## 変更の背景

Go言語の `html/template` パッケージは、WebアプリケーションにおいてHTMLコンテンツを安全に生成するための強力なツールです。このパッケージは、クロスサイトスクリプティング（XSS）などのセキュリティ脆弱性を防ぐために、自動エスケープ機能を提供しています。この自動エスケープは、内部的に定義された一連の関数（エスケーパー関数）を `FuncMap` に登録し、テンプレートの解析時に適切なエスケープ処理を適用することで実現されます。

しかし、これらの内部関数がユーザーが定義する可能性のある関数名と同じ名前であった場合、意図しない関数が呼び出されたり、セキュリティ上の問題が発生したりする可能性がありました。特に、`html_template_attrescaper` のような、パッケージ名と機能名を組み合わせた形式の関数名は、ユーザーが誤って同じ名前の関数を定義してしまうリスクを完全に排除できるものではありませんでした。

このコミットは、このような名前の衝突リスクをさらに低減することを目的としています。`Fixes #13852` と記載されていますが、この特定のIssueの詳細は現在のWeb検索では確認できませんでした。しかし、コミットメッセージから、ユーザー定義関数との名前衝突が問題となり、その解決策として内部関数の命名規則を変更する必要があったことが推測されます。

## 前提知識の解説

### Go言語の `html/template` パッケージ

`html/template` パッケージは、Go言語でHTML出力を生成する際に、セキュリティを考慮したテンプレート処理を提供するパッケージです。通常の `text/template` パッケージとは異なり、HTMLのコンテキストに応じて自動的にエスケープ処理を行うことで、XSS攻撃などの脆弱性からアプリケーションを保護します。

### `template.FuncMap`

`template.FuncMap` は、テンプレート内で呼び出すことができるカスタム関数を登録するためのマップです。キーはテンプレート内で関数を呼び出す際に使用する名前（文字列）で、値は対応するGoの関数です。
例:
```go
funcMap := template.FuncMap{
    "upper": strings.ToUpper,
    "add": func(a, b int) int { return a + b },
}
```
この `FuncMap` をテンプレートに登録することで、テンプレート内で `{{ upper "hello" }}` や `{{ add 1 2 }}` のようにカスタム関数を呼び出すことができます。

### 自動エスケープとコンテキストアウェアネス

`html/template` の最も重要な機能の一つは、コンテキストアウェアな自動エスケープです。これは、テンプレート内のデータが出力されるHTMLのどの部分（例: HTML要素のテキストコンテンツ、属性値、JavaScriptコード、CSSコード、URLなど）に挿入されるかに応じて、適切なエスケープ処理を自動的に適用する機能です。この処理は、内部的に多数のエスケーパー関数やフィルター関数を組み合わせて行われます。

### 名前空間の衝突

プログラミングにおいて、異なるモジュールやライブラリが同じ名前の識別子（変数、関数など）を使用することで発生する問題を「名前空間の衝突」と呼びます。Go言語では、パッケージ名によって名前空間が区切られますが、`template.FuncMap` のように文字列で関数名を指定する仕組みでは、ユーザーが意図せず内部関数と同じ名前の関数を定義してしまう可能性があります。

## 技術的詳細

このコミットの技術的な核心は、`html/template` パッケージが内部的に使用するエスケープ関連の関数群の命名規則を変更することにあります。具体的には、`src/html/template/escape.go` ファイル内で定義されている `funcMap` および `equivEscapers` という2つのマップにおいて、キーとなる関数名の先頭にアンダースコア (`_`) を追加しています。

変更前:
- `"html_template_attrescaper"`
- `"html_template_commentescaper"`
- ...

変更後:
- `"_html_template_attrescaper"`
- `"_html_template_commentescaper"`
- ...

Go言語の慣習として、アンダースコアで始まる識別子（変数、関数、構造体フィールドなど）は、通常、内部的な利用やプライベートな性質を持つことを示唆します。ただし、`template.FuncMap` のキーとして使用される文字列においては、Go言語の言語仕様として「アンダースコアで始まるからプライベートになる」という直接的なルールはありません。テンプレートエンジンは、登録された文字列キーに基づいて関数を呼び出すため、`_` が付いていてもテンプレートから呼び出すことは可能です。

しかし、この変更の意図は、開発者やユーザーに対して「これらの関数は `html/template` パッケージの内部実装の詳細であり、直接利用したり、同じ名前の関数をユーザーが定義したりすることは推奨されない」という強いシグナルを送ることにあります。これにより、ユーザーが誤って同じ名前の関数を `FuncMap` に登録してしまい、内部のエスケープ処理が上書きされたり、予期せぬ動作やセキュリティ上の問題が発生したりするリスクを大幅に低減できます。

この変更は、`funcMap` の定義だけでなく、`escapeAction` メソッド内でこれらの内部関数を呼び出す箇所や、`redundantFuncs` マップの定義箇所など、`escape.go` ファイル全体にわたって一貫して適用されています。これにより、内部的な参照も新しい命名規則に統一され、コードの一貫性と保守性が向上しています。

## コアとなるコードの変更箇所

変更は `src/html/template/escape.go` ファイルに集中しています。

1.  **`funcMap` のキー名の変更**:
    `var funcMap = template.FuncMap{...}` の定義内で、すべてのキー文字列の先頭に `_` が追加されています。
    例: `"html_template_attrescaper"` -> `"_html_template_attrescaper"`

2.  **`equivEscapers` のキー名の変更**:
    `var equivEscapers = map[string]string{...}` の定義内で、すべてのキー文字列の先頭に `_` が追加されています。
    例: `"html_template_attrescaper"` -> `"_html_template_attrescaper"`

3.  **`escapeAction` メソッド内の関数名参照の変更**:
    `func (e *escaper) escapeAction(c context, n *parse.ActionNode) context {...}` メソッド内で、内部関数を `append(s, ...)` でパイプラインに追加する際に使用される文字列リテラルが、新しい `_` プレフィックス付きの名前に変更されています。
    例: `s = append(s, "html_template_urlfilter")` -> `s = append(s, "_html_template_urlfilter")`

4.  **`redundantFuncs` のキー名の変更**:
    `var redundantFuncs = map[string]map[string]bool{...}` の定義内で、キーおよびネストされたマップのキー文字列の先頭に `_` が追加されています。
    例: `"html_template_commentescaper"` -> `"_html_template_commentescaper"`

これらの変更により、合計で46行が削除され、46行が追加されています。これは、既存の関数名を新しい名前に一括置換した結果です。

## コアとなるコードの解説

`src/html/template/escape.go` は、`html/template` パッケージにおける自動エスケープ処理の核心を担うファイルです。このファイルには、テンプレートの構文木を走査し、各ノードのコンテキスト（HTML、CSS、JavaScript、URLなど）を判断して、適切なエスケープ関数を適用するロジックが含まれています。

-   **`funcMap`**: このマップは、`html/template` が内部的に使用するエスケープ処理関数（例: `attrEscaper`, `cssEscaper`, `jsStrEscaper` など）を、文字列キーに関連付けて保持しています。これらの関数は、テンプレート内でデータが出力されるコンテキストに応じて、自動的に呼び出されます。今回の変更で、これらのキーに `_` プレフィックスが付与されました。

-   **`equivEscapers`**: このマップは、特定の内部エスケーパー関数が、Goの組み込みテンプレート関数（例: `html`, `urlquery`）と等価であることを示しています。これにより、冗長なエスケープ処理を避けるための最適化が行われることがあります。ここでもキー名が変更されました。

-   **`escapeAction`**: このメソッドは、テンプレートの構文木を走査する `escaper` 型の主要なロジックの一部です。`ActionNode`（`{{.Var}}` のようなデータ出力箇所）に遭遇すると、現在のHTMLコンテキスト（`c.state`）に基づいて、どのエスケープ関数を適用すべきかを決定し、その関数名をパイプラインに追加します。このパイプラインは、最終的にテンプレートが実行される際に、データに適用されるエスケープ処理の順序を定義します。このメソッド内の `append(s, ...)` の呼び出しで、新しい `_` プレフィックス付きの関数名が使用されるようになりました。

-   **`redundantFuncs`**: このマップは、特定のエスケープ関数が適用された後に、さらに別のあるエスケープ関数を適用しても結果が変わらない（冗長である）関係を示しています。これにより、不必要なエスケープ処理の連鎖を最適化し、パフォーマンスを向上させることができます。ここでもキー名が変更されました。

これらの変更は、`html/template` パッケージの外部インターフェースには影響を与えませんが、内部実装の堅牢性とセキュリティを向上させるための重要な改善です。ユーザーが誤って内部関数を上書きするリスクを減らすことで、テンプレートの自動エスケープ機能が常に意図した通りに動作することを保証します。
