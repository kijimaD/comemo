# [インデックス 19932] ファイルの概要

このコミットは、Goランタイムにおける`mcall`または`onM`によって呼び出し可能な関数の命名規則を整理し、これらの特殊な関数を表す`mFunction`型を導入することを目的としています。これにより、ランタイムのコードベースの可読性と保守性が向上します。

## 変更の背景

Goランタイムは、ゴルーチン（G）とOSスレッド（M）という2つの主要な抽象化を用いて並行性を管理しています。特定のランタイム内部関数は、通常のゴルーチンのスタックではなく、OSスレッド（M）に紐付けられた特別なシステムスタック（`g0`スタック）上で実行される必要があります。これらの関数は、スケジューリング、メモリ管理、プロファイリングなど、ランタイムのコアな操作を担っており、ユーザーゴルーチンのプリエンプションの影響を受けないように設計されています。

このコミット以前は、これらの「mcallable」な関数（`mcall`や`onM`を通じて呼び出される関数）の命名規則が統一されておらず、その特殊な性質がコードから明確ではありませんでした。この曖昧さは、コードの理解を妨げ、将来的な保守やデバッグを困難にする可能性がありました。

この変更の背景には、Goランタイムのコードベースの可読性と保守性を向上させるという明確な意図があります。`mFunction`型の導入と`_m`サフィックスによる命名規則の統一は、これらの特殊な関数を明確に識別し、その実行コンテキスト（Mのスタック上）を開発者に示唆することを目的としています。

## 前提知識の解説

このコミットを理解するためには、Goランタイムのスケジューラにおける以下の概念を理解しておく必要があります。

*   **Goroutine (G)**: Goにおける軽量な実行単位です。Goプログラムのほとんどのコードはゴルーチン上で実行されます。各ゴルーチンは独自のスタックを持ちます。
*   **Machine (M)**: OSスレッドを表します。Goランタイムは、OSスレッドを抽象化してMとして扱います。Mは、P（Processor）にアタッチされ、Pがゴルーチンを実行します。
*   **Processor (P)**: 論理プロセッサを表し、MとGを仲介します。Pは実行可能なゴルーチンのキューを保持し、MがPからゴルーチンを取得して実行します。
*   **`g0`スタック**: 各M（OSスレッド）には、特別なゴルーチンである`g0`が関連付けられています。`g0`は、Mのシステムスタックとして機能し、Goスケジューラやその他のランタイムの低レベルなコードが実行される場所です。ユーザーゴルーチンのスタックとは異なり、`g0`スタックはプリエンプションの対象外となる重要な操作のために使用されます。
*   **`mcall`**: Goランタイムの内部で用いられるアセンブリ関数です。これは、現在のユーザーゴルーチンのスタックから、現在のOSスレッド（M）の`g0`スタックへと実行コンテキストを切り替えるために使用されます。`mcall`に渡された関数は`g0`スタック上で実行され、通常、`mcall`の呼び出し元には戻りません。代わりに、別のゴルーチンへのコンテキストスイッチやスケジューラの呼び出しによって実行が継続されます。
*   **`onM`**: `mcall`と同様に、指定された関数をMの`g0`スタック上で実行するためのメカニズムです。`mcall`がより低レベルなコンテキストスイッチを伴うのに対し、`onM`はGoコードから`mcall`を安全に呼び出すためのラッパーとして機能することが多いです。

これらの`mcall`や`onM`を通じて実行される関数は、Goランタイムの安定性と効率性を保つ上で極めて重要であり、ユーザーコードとは異なる特別な扱いを受けます。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの内部で`mcall`や`onM`によって呼び出される関数群の型と命名を標準化することにあります。

1.  **`mFunction`型の導入**:
    `src/pkg/runtime/stubs.go`に`type mFunction byte`という新しい型が導入されました。この型は、`mcall`や`onM`に渡される関数のシグネチャを明確に定義するためのマーカーとして機能します。コメントには「`mFunction`はMスタック上で実行されるC関数を表す。`mcall`または`onM`を使ってGoから呼び出すことができる。リンキングの魔法により、`mFunction`変数と対応するCコードのエントリポイントは同じアドレスに存在する。」と説明されています。これは、Goの`byte`型を基盤としつつ、そのセマンティクスをランタイムの特殊な関数に限定するものです。

2.  **`_m`サフィックスによる命名規則の統一**:
    `mcall`や`onM`によって呼び出されるすべての関数（C言語で実装されたランタイム関数）に対して、関数名の末尾に`_m`サフィックスが追加されました。例えば、`runtime·setFinalizer`は`runtime·setFinalizer_m`に、`runtime·mcacheRefill`は`runtime·mcacheRefill_m`に、`runtime·mgc2`は`runtime·gc_m`（これは名前自体も変更されていますが、`_m`サフィックスが追加されています）に変更されました。この命名規則により、コードを読む開発者は、その関数がMのスタック上で実行される特別な関数であることを一目で認識できるようになります。

3.  **`mcall`および`onM`のシグネチャ変更**:
    `src/pkg/runtime/stubs.go`において、`mcall`と`onM`関数の引数型が`*byte`から`*mFunction`に変更されました。これにより、これらの関数が期待する引数の型がより厳密になり、コンパイル時に型チェックが可能になります。

4.  **変数の型変更**:
    `src/pkg/runtime/print.go`や`src/pkg/runtime/stubs.go`で宣言されている、`mcall`や`onM`を通じて参照される関数ポインタ変数（例: `mcacheRefill`, `largeAlloc`など）の型が`byte`から`mFunction`に変更され、グループ化して宣言されるようになりました。

これらの変更は、機能的な振る舞いを変更するものではなく、主にコードの構造と可読性を改善するためのリファクタリングです。しかし、ランタイムのような低レベルで複雑なシステムにおいては、このような明確な命名規則と型定義は、バグの発生を防ぎ、将来の変更を容易にする上で非常に重要です。

## コアとなるコードの変更箇所

このコミットによって変更された主要なファイルとコードの変更箇所は以下の通りです。

*   **`src/pkg/runtime/malloc.c`**:

*   **`src/pkg/runtime/malloc.go`**:

    *   `runtime·mgc2` -> `runtime·gc_m`

## コアとなるコードの解説

このコミットの主要な変更は、Goランタイムの内部で`mcall`や`onM`を通じて呼び出されるC言語で実装された関数群の命名規則と型定義の統一です。

例えば、`src/pkg/runtime/malloc.c`では、メモリ割り当てに関連するランタイム関数が変更されています。
変更前:
```c
void
runtime·setFinalizer(void)
```
変更後:
```c
void
runtime·setFinalizer_m(void)
```
このように、関数名の末尾に`_m`が追加されています。これは、この関数がMのスタック上で実行されることを明示的に示しています。

また、`src/pkg/runtime/malloc.go`では、GoコードからこれらのC関数を呼び出す際の`onM`の引数が変更されています。
変更前:
```go
onM(&mcacheRefill)
```
変更後:
```go
onM(&mcacheRefill_m)
```
`mcacheRefill`が`mcacheRefill_m`に変わったことで、Goコード側でも新しい命名規則が反映されています。

最も重要な変更は`src/pkg/runtime/stubs.go`にあります。
```go
// An mFunction represents a C function that runs on the M stack.  It
// can be called from Go using mcall or onM.  Through the magic of
// linking, an mFunction variable and the corresponding C code entry
// point live at the same address.
type mFunction byte

// in asm_*.s
func mcall(fn *mFunction)
func onM(fn *mFunction)

// C functions that run on the M stack.  Call these like
//   mcall(&mcacheRefill_m)
// Arguments should be passed in m->scalararg[x] and
// m->ptrarg[x].  Return values can be passed in those
// same slots.
var (
	mcacheRefill_m,
	largeAlloc_m,
	mprofMalloc_m,
	gc_m,
	setFinalizer_m,
	markallocated_m mFunction
)
```
ここで、`mFunction`型が定義され、`mcall`と`onM`の引数型が`*mFunction`に変更されています。これにより、これらの関数が期待する引数の型がより明確になり、コンパイル時の型安全性が向上します。また、`mcall`や`onM`を通じて参照されるランタイム関数の変数も`mFunction`型として一箇所にまとめられ、その特殊な性質が強調されています。

これらの変更は、Goランタイムの内部構造をより明確にし、開発者がどの関数がMのスタック上で実行されるべきかを容易に識別できるようにすることで、コードの理解と保守を大幅に簡素化します。これは、機能的な変更ではなく、コード品質と設計の一貫性を高めるための重要なリファクタリングです。
