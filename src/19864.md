# [インデックス 19864] ファイルの概要

このコミットは、GoランタイムがWindows上でモノトニッククロックを実装する方法を変更します。具体的には、`GetSystemTimeAsFileTime` APIの使用を廃止し、代わりにWindowsの内部データ構造である`KUSER_SHARED_DATA`を直接読み取ることで、より正確で信頼性の高いモノトニックな時間測定を実現しています。これにより、`time.Sleep`などの時間関連の操作の精度が向上し、Windows環境でのGoプログラムの動作が改善されます。

## 変更の背景

この変更の主な背景には、Windows環境におけるGoランタイムの時刻管理の精度と信頼性の問題がありました。

従来のGoランタイムは、Windows上で`GetSystemTimeAsFileTime`というAPIを使用して時間を取得していました。しかし、このAPIが返す時間は「システム時刻」であり、ユーザーやネットワークタイムプロトコルによって調整される可能性があるため、必ずしも単調増加（モノトニック）ではありませんでした。つまり、システム時刻がNTP同期などによって巻き戻されると、時間の測定が不正確になり、特に`time.Sleep`のような時間ベースの操作で予期せぬ動作を引き起こす可能性がありました。

Goの`time`パッケージ、特に`time.Sleep`や`time.Now`は、正確な時間測定と単調増加するクロックに依存しています。システム時刻の非単調性は、スリープ時間の計算のずれや、イベント間の正確な時間差の測定を困難にしていました。

このコミットは、GoランタイムがWindows上でより信頼性の高い「モノトニッククロック」を利用できるようにすることで、この問題に対処しています。コミットメッセージに`Update #6007`とありますが、公開されているGoのIssueトラッカーではこの番号の具体的なIssueは見つかりませんでした。これは内部的な追跡番号であるか、あるいは後に別のIssueに統合された可能性があります。しかし、この変更がWindowsにおける時間測定の精度向上を目的としていることは明らかです。

## 前提知識の解説

### モノトニッククロック (Monotonic Clock)

モノトニッククロックとは、時間の経過とともに常に単調に増加することが保証されているクロックのことです。システム時刻（ウォールクロック）とは異なり、NTP同期や手動での時刻調整によって時間が進んだり戻ったりすることはありません。そのため、イベント間の正確な時間間隔（期間）を測定するのに非常に適しています。例えば、プログラムの実行時間を測定したり、タイムアウトを実装したりする際に、モノトニッククロックが使用されます。

### Windowsの時刻管理

Windowsには複数の時刻取得APIが存在します。

*   **`GetSystemTimeAsFileTime`**: これはシステム時刻（ウォールクロック）を返すAPIです。協定世界時 (UTC) の1601年1月1日からの100ナノ秒間隔の数を返します。この時刻はNTP同期などによって調整されるため、単調増加が保証されません。
*   **`QueryPerformanceCounter` (QPC)**: これはWindowsで高精度なモノトニッククロックとして広く利用されているAPIです。プロセッサのタイムスタンプカウンタ (TSC) や高精度イベントタイマー (HPET) などのハードウェアタイマーに基づいており、非常に高い分解能で単調増加する時間を提供します。

### `KUSER_SHARED_DATA`と`KSYSTEM_TIME`

`KUSER_SHARED_DATA`は、Windowsカーネルが管理する重要なデータ構造で、すべてのユーザーモードプロセスのアドレス空間に固定された仮想アドレス（通常`0x7FFE0000`）にマッピングされています。これにより、ユーザーモードアプリケーションは、カーネルモードへの遷移（システムコール）のオーバーヘッドなしに、現在のシステム時刻、割り込み時刻、タイムゾーン情報などの頻繁にアクセスされるグローバルなシステムデータに高速にアクセスできます。この構造はユーザーモードからは読み取り専用です。

`KSYSTEM_TIME`は、`KUSER_SHARED_DATA`内で時間値を表現するために使用される構造体です。通常、`LowPart`、`High1Time`、`High2Time`の3つのメンバーで構成されます。この設計、特に`High1Time`と`High2Time`の重複フィールドは、カーネルがロックなしで64ビットの時間値を更新できるようにする同期メカニズムです。これにより、ユーザーモードアプリケーションは常に一貫した時間値を読み取ることができます。

*   **`0x7ffe0008`**: このアドレスは、`KUSER_SHARED_DATA`構造体内の`InterruptTime`フィールドを指します。`InterruptTime`は、システム起動時からの100ナノ秒単位の時間を表すモノトニックなクロックです。
*   **`0x7ffe0014`**: このアドレスは、`KUSER_SHARED_DATA`構造体内の`SystemTime`フィールドを指します。`SystemTime`は、`GetSystemTimeAsFileTime`と同様に、1601年1月1日からの100ナノ秒単位の時間を表すウォールクロックです。

このコミットでは、Goランタイムがこれらの`KUSER_SHARED_DATA`内のアドレスを直接参照することで、Windowsの内部的なモノトニッククロックとウォールクロックにアクセスしています。

## 技術的詳細

このコミットの核心は、GoランタイムがWindowsの時刻情報を取得する方法を根本的に変更した点にあります。

1.  **`GetSystemTimeAsFileTime`の廃止**: 従来の`runtime·nanotime`関数は`GetSystemTimeAsFileTime`を使用していましたが、これが非モノトニックであるため、このAPIへの依存が完全に削除されました。
2.  **`KUSER_SHARED_DATA`の直接利用**: 新しい実装では、Windowsの内部データ構造である`KUSER_SHARED_DATA`を直接参照します。この構造体は、ユーザーモードプロセスから高速にアクセスできる共有メモリ領域に存在し、システム時刻や割り込み時刻などの重要な情報を含んでいます。
3.  **`KSYSTEM_TIME`構造体の導入**: `os_windows.c`に`KSYSTEM_TIME`構造体が定義され、`KUSER_SHARED_DATA`内の`InterruptTime` (`0x7ffe0008`) と`SystemTime` (`0x7ffe0014`) を指すポインタ`INTERRUPT_TIME`と`SYSTEM_TIME`が導入されました。
4.  **`runtime·systime`関数の実装**: 新たに`runtime·systime`関数が追加されました。この関数は`KSYSTEM_TIME`構造体のアドレスを受け取り、その内容を安全に読み取ります。`KSYSTEM_TIME`の`High1Time`、`LowPart`、`High2Time`を特定の順序で読み取り、`High1Time`と`High2Time`が一致するまでループすることで、64ビットの時間値の一貫した読み取りを保証します。これは、カーネルが時間値を更新している最中に読み取りが行われた場合でも、破損した値を取得しないための重要な同期メカニズムです。
5.  **`runtime·nanotime`の変更**: `runtime·nanotime`関数は、モノトニックな時間を提供するように変更されました。これは`runtime·systime(INTERRUPT_TIME)`を呼び出すことで、`KUSER_SHARED_DATA`内の`InterruptTime`（システム起動時からのモノトニックな時間）を取得します。
6.  **`time·now`の変更**: `time·now`関数は、ウォールクロック時間を提供するように変更されました。これは`runtime·systime(SYSTEM_TIME)`を呼び出すことで、`KUSER_SHARED_DATA`内の`SystemTime`（1601年1月1日からの時間）を取得し、それを1970年1月1日からのナノ秒に変換します。
7.  **`sleep_test.go`の調整**: `sleep_test.go`では、Windows環境での`time.Sleep`の精度に関する既知の問題に対処するため、`windowsInaccuracy`という定数が導入されました。これは、Goランタイムが`time.Now`とスリープのために異なるWindowsタイマーを使用しており、これらのタイマーが異なる周波数で動作し、同期がずれる可能性があるためです。特にWindows XP SP3 (windows/386) で観測された、`time.Sleep(100ms)`が`time.Now`で測定すると実際には100msより短くなるという現象に対応するため、テストの許容誤差が調整されました。

これらの変更により、GoランタイムはWindows上でより正確で信頼性の高い時間測定が可能になり、特に時間間隔の測定やスリープの精度が向上しました。

## コアとなるコードの変更箇所

### `src/pkg/runtime/os_windows.c`

- `runtime·GetSystemTimeAsFileTime`の`#pragma dynimport`および`extern void *`宣言が削除されました。
- `KSYSTEM_TIME`構造体が定義されました。
    ```c
    typedef struct KSYSTEM_TIME {
    	uint32	LowPart;
    	int32	High1Time;
    	int32	High2Time;
    } KSYSTEM_TIME;
    ```
- `INTERRUPT_TIME`と`SYSTEM_TIME`の定数ポインタが定義され、`KUSER_SHARED_DATA`内の特定のアドレスを指すようになりました。
    ```c
    const KSYSTEM_TIME* INTERRUPT_TIME	= (KSYSTEM_TIME*)0x7ffe0008;
    const KSYSTEM_TIME* SYSTEM_TIME		= (KSYSTEM_TIME*)0x7ffe0014;
    ```
- 新しい関数`runtime·systime`が追加されました。これは`KSYSTEM_TIME`ポインタを受け取り、安全に時間値を読み取ります。
    ```c
    #pragma textflag NOSPLIT
    int64
    runtime·systime(KSYSTEM_TIME *timeaddr)
    {
    	KSYSTEM_TIME t;
    	int32 i;

    	for(i = 0; i < 10000; i++) {
    		// these fields must be read in that order (see URL above)
    		t.High1Time = timeaddr->High1Time;
    		t.LowPart = timeaddr->LowPart;
    		t.High2Time = timeaddr->High2Time;
    		if(t.High1Time == t.High2Time)
    			return (int64)t.High1Time<<32 | t.LowPart;
    		if((i%100) == 0)
    			runtime·osyield();
    	}
    	runtime·throw("interrupt/system time is changing too fast");
    	return 0;
    }
    ```
- `runtime·nanotime`関数が`runtime·systime(INTERRUPT_TIME)`を使用するように変更されました。
    ```c
    #pragma textflag NOSPLIT
    int64
    runtime·nanotime(void)
    {
    	return runtime·systime(INTERRUPT_TIME) * 100LL;
    }
    ```
- `time·now`関数が`runtime·systime(SYSTEM_TIME)`を使用するように変更され、1970年からのナノ秒に変換するロジックが適用されました。
    ```c
    void
    time·now(int64 sec, int32 usec)
    {
    	int64 ns;

    	// SystemTime is 100s of nanoseconds since January 1, 1601.
    	// Convert to nanoseconds since January 1, 1970.
    	ns = (runtime·systime(SYSTEM_TIME) - 116444736000000000LL) * 100LL;

    	sec = ns / 1000000000LL;
    	usec = ns - sec * 1000000000LL;
    	FLUSH(&sec);
    }
    ```

### `src/pkg/time/sleep_test.go`

- `windowsInaccuracy`定数が追加されました。
    ```go
    const windowsInaccuracy = 17 * Millisecond
    ```
- `TestSleep`と`TestAfter`関数で、Windowsの場合に`delayadj`を`windowsInaccuracy`分減算するロジックが追加され、テストの許容範囲が調整されました。
    ```go
    // TestSleep
    	delayadj := delay
    	if runtime.GOOS == "windows" {
    		delayadj -= windowsInaccuracy
    	}
    	duration := Now().Sub(start)
    	if duration < delayadj {
    		t.Fatalf("Sleep(%s) slept for only %s", delay, duration)
    	}

    // TestAfter
    	delayadj := delay
    	if runtime.GOOS == "windows" {
    		delayadj -= windowsInaccuracy
    	}
    	if duration := Now().Sub(start); duration < delayadj {
    		t.Fatalf("After(%s) slept for only %d ns", delay, duration)
    	}
    	if min := start.Add(delayadj); end.Before(min) {
    		t.Fatalf("After(%s) expect >= %s, got %s", delay, min, end)
    	}
    ```

## コアとなるコードの解説

### `src/pkg/runtime/os_windows.c`の変更

このファイルはGoランタイムのWindows固有の実装を含んでいます。
- `GetSystemTimeAsFileTime`の削除は、このAPIがシステム時刻を返し、単調増加が保証されないためです。Goの内部時間管理では、時間間隔の正確な測定のためにモノトニックなクロックが必要です。
- `KSYSTEM_TIME`構造体と`INTERRUPT_TIME`、`SYSTEM_TIME`ポインタの導入は、Windowsの`KUSER_SHARED_DATA`という共有メモリ領域を直接利用するためのものです。この領域は、カーネルが頻繁に更新するシステム情報をユーザーモードから高速に読み取ることを可能にします。`0x7ffe0008`は`InterruptTime`（モノトニック）、`0x7ffe0014`は`SystemTime`（ウォールクロック）のアドレスです。
- `runtime·systime`関数は、`KSYSTEM_TIME`構造体の特殊な読み取りメカニズムを実装しています。`High1Time`、`LowPart`、`High2Time`の順序で読み取り、`High1Time`と`High2Time`が一致することを確認するループは、カーネルが64ビットの時間値を更新している最中に、部分的に更新された値（ティアリング）を読み取ってしまうことを防ぐためのものです。これにより、ロックなしで一貫性のある64ビット時間値を取得できます。
- `runtime·nanotime`が`INTERRUPT_TIME`を使用するように変更されたことで、GoランタイムはWindows上で真のモノトニッククロックを利用できるようになりました。これは、Goのスケジューラやタイマーなど、正確な時間間隔測定を必要とする内部処理にとって非常に重要です。
- `time·now`が`SYSTEM_TIME`を使用するように変更されたことで、Goの`time.Now()`は引き続きウォールクロック時間を提供しますが、その取得方法がより効率的かつ内部的な`KUSER_SHARED_DATA`の利用に切り替わりました。また、1601年からの時間を1970年からの時間に変換するオフセット計算も行われています。

### `src/pkg/time/sleep_test.go`の変更

このファイルはGoの`time`パッケージのテストを含んでいます。
- `windowsInaccuracy`定数の導入とテストロジックの調整は、Windowsにおける時間測定の現実的な制約を考慮したものです。Windowsでは、`time.Now`が使用するタイマーと`time.Sleep`が使用するタイマーが異なる場合があり、その結果、スリープの実際の長さと`time.Now`で測定した長さの間にわずかな不一致が生じることがあります。この不一致は、特に古いWindowsバージョンや特定のハードウェア構成で顕著になることがあります。テストの許容誤差を調整することで、このようなプラットフォーム固有の挙動を考慮しつつ、テストが安定してパスするようにしています。これは、Goが異なるOS環境での動作の差異を吸収し、堅牢な標準ライブラリを提供しようとする姿勢を示しています。

これらの変更は、GoランタイムがWindows環境でより正確かつ効率的に時間管理を行うための重要な改善であり、Goプログラムの信頼性とパフォーマンス向上に貢献しています。
