# [インデックス 28161] ファイルの概要

このコミットは、Goの`cgo`ツールが生成するCコードにおける2つの問題を解決します。一つは、一部のCコンパイラで`-Wdeclaration-after-statement`フラグが有効な場合に発生する警告を解消することです。もう一つは、ThreadSanitizer (tsan)などのツールが`errno`グローバル変数を予期せず変更する可能性から、`cgo`の`errno`ハンドリングを保護することです。

## 変更の背景

このコミットには主に2つの背景があります。

1.  **`-Wdeclaration-after-statement`警告の解消**:
    C言語の標準では、C99以降、文の後に宣言を記述することが許可されています。しかし、一部のCコンパイラ（特にGCC）では、`-Wdeclaration-after-statement`というコンパイルフラグを有効にすると、このC99の機能を使用しているコードに対して警告を発します。`cgo`が生成するCコードがこの警告をトリガーしており、厳格なコンパイル設定を持つプロジェクトでは、この警告がビルドプロセスを妨げたり、ノイズになったりする可能性がありました。コミットメッセージでは、C99で許可されているためテストする価値はないとしつつも、修正が容易であるため対応されたことが示されています。

2.  **`errno`ハンドリングの改善とThreadSanitizer (tsan)との競合回避**:
    C言語の標準ライブラリ関数がエラーを報告する際に設定するグローバル変数`errno`は、マルチスレッド環境や、コードの実行をフックするようなツール（例: ThreadSanitizer）が存在する場合に、予期せぬ挙動を示すことがあります。`cgo`がC関数を呼び出す際、そのC関数が`errno`を設定する可能性があります。しかし、`cgo`が生成するコード内で、C関数呼び出しと`errno`の読み取りの間にThreadSanitizer (tsan)のフック関数（`_cgo_tsan_acquire()`や`_cgo_tsan_release()`など）が実行されると、これらのフック関数が誤って`errno`の値を変更してしまう可能性がありました。これにより、Go側で取得される`errno`の値が、実際にC関数で発生したエラーとは異なるものになってしまうという問題が発生していました。

## 前提知識の解説

*   **Cgo**: GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoのツールです。`cgo`は、GoとCの間のインターフェースとなるCコードを自動生成します。
*   **`-Wdeclaration-after-statement`**: GCCなどのCコンパイラにおける警告フラグの一つです。C89標準ではブロックの先頭で全ての変数を宣言する必要がありましたが、C99標準では文の後に宣言を記述することが許可されました。このフラグは、C99以降のスタイルで書かれた「文の後の宣言」に対して警告を発します。これは、古いC標準への互換性を保つためや、コードスタイルを統一するために使用されることがあります。
*   **`errno`**: C言語の標準ライブラリで定義されているグローバル変数（またはスレッドローカル変数）で、システムコールやライブラリ関数がエラーを報告する際にエラーコードを格納するために使用されます。関数がエラーを返した場合、通常、`errno`をチェックしてエラーの種類を特定します。`errno`は、関数呼び出しが成功した場合には変更されないことが保証されていますが、失敗した場合には変更されます。
*   **ThreadSanitizer (tsan)**: データ競合（data race）を検出するための動的解析ツールです。Goランタイムに統合されており、並行処理のバグを見つけるのに役立ちます。`tsan`は、メモリアクセスを監視するために、コンパイル時にコードにインストゥルメンテーション（計測コードの挿入）を行います。このインストゥルメンテーションが、`errno`のようなグローバルな状態に影響を与える可能性がありました。

## 技術的詳細

このコミットは、上記の2つの問題を解決するために、`cgo`が生成するCコードの構造と`errno`の扱い方を変更しています。

1.  **`-Wdeclaration-after-statement`警告の解消**:
    `cgo`が生成するCコードにおいて、変数の宣言が文の後に来るパターンを修正しました。具体的には、`misc/cgo/test/issue3250.go`と`misc/cgo/test/issue5986.go`のテストファイル内のCコードブロックで、変数の宣言をブロックの先頭に移動させています。これは、`cgo`のコードジェネレータである`src/cmd/cgo/out.go`が、よりC89互換の宣言スタイルでコードを生成するように変更されたことを示唆しています。これにより、`-Wdeclaration-after-statement`フラグが有効なコンパイラでも警告なしにコンパイルできるようになります。

2.  **`errno`ハンドリングの改善**:
    `cgo`が生成するCコード内で、C関数呼び出しによって設定される`errno`の値を、`tsan`のフック関数による影響から隔離するために、ローカル変数`_cgo_errno`を導入しました。
    *   C関数呼び出しの前に`errno = 0;`で`errno`を初期化する処理は、`_cgo_tsan_acquire()`の後に移動されました。これは、`tsan`の取得フックが`errno`をリセットする可能性を考慮したものです。
    *   C関数が実行された直後、かつ`_cgo_tsan_release()`が呼び出される前に、グローバルな`errno`の値をローカル変数`_cgo_errno`にコピーします。
    *   最終的に、`cgo`のラッパー関数がGo側に返すエラーコードとして、グローバルな`errno`ではなく、このローカル変数`_cgo_errno`の値を使用するように変更されました。
    この変更により、`tsan`のインストゥルメンテーションが`errno`を一時的に変更したとしても、Go側にはC関数呼び出しによって設定された正しい`errno`の値が伝達されるようになります。

## コアとなるコードの解説

*   **`misc/cgo/test/issue3250.go` および `misc/cgo/test/issue5986.go` の変更**:
    これらの変更は、`cgo`が生成するCコードのテストケースにおける、`-Wdeclaration-after-statement`警告の具体的な修正例を示しています。変数の宣言（例: `(void)p;` や `double d;`）が、そのブロック内の他の文よりも前に移動されています。これにより、C89の規則に準拠し、警告を回避します。

*   **`src/cmd/cgo/out.go` の変更**:
    これは`cgo`のコードジェネレータの核心部分であり、Goの関数からCの関数を呼び出すためのラッパーC関数を生成するロジックが含まれています。
    *   `if n.AddError { fmt.Fprintf(fgcc, "\\tint _cgo_errno;\\n") }`
        `errno`を扱う必要がある場合（`n.AddError`が真の場合）、グローバルな`errno`と競合しないように、ローカル変数`_cgo_errno`が宣言されます。
    *   `if tr != nil { fmt.Fprintf(fgcc, "\\t__typeof__(a->r) r;\\n") }`
        関数の戻り値がある場合、その戻り値を格納するためのローカル変数`r`が、他の処理の前に宣言されるようになりました。これも`-Wdeclaration-after-statement`警告を回避するためです。
    *   `fmt.Fprintf(fgcc, "\\t_cgo_tsan_acquire();\\n")` の後に `if n.AddError { fmt.Fprintf(fgcc, "\\terrno = 0;\\n") }`
        `errno`の初期化が`_cgo_tsan_acquire()`の後に移動されました。これにより、`tsan`のフックが`errno`をリセットする可能性を考慮し、C関数呼び出し直前の`errno`の状態をより正確に制御します。
    *   `if n.AddError { fmt.Fprintf(fgcc, "\\t_cgo_errno = errno;\\n") }`
        C関数呼び出しが完了し、`_cgo_tsan_release()`が呼び出される直前に、グローバルな`errno`の値をローカル変数`_cgo_errno`にコピーします。これにより、`tsan`のフックが`errno`を上書きする前に、C関数によって設定された正しいエラーコードを捕捉します。
    *   `if n.AddError { fmt.Fprintf(fgcc, "\\treturn _cgo_errno;\\n") }`
        ラッパー関数の戻り値として、グローバルな`errno`ではなく、捕捉したローカル変数`_cgo_errno`が使用されます。これにより、`tsan`の影響を受けない、正確なエラー情報がGo側に返されます。

これらの変更は、`cgo`が生成するコードの堅牢性と互換性を向上させ、開発者がよりスムーズにGoとCの連携コードを扱えるようにするための重要な改善です。
