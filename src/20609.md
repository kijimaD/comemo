# [インデックス 20609] ファイルの概要

このコミットは、Go 1.4 リリースノートのドキュメントファイル `doc/go1.4.txt` に変更を加えています。具体的には、Cgo を使用しない Go パッケージにおける C ソースファイルの利用が許可されなくなったという変更を追記しています。

## 変更の背景

このコミットは、Go 1.4 のリリースに向けたドキュメント更新の一環です。Go 1.4 では、Go のビルドシステムにおける C ソースファイルの扱いに関して重要な変更が導入されました。以前のバージョンでは、Cgo を明示的に使用しない Go パッケージ内でも `.c` や `.s` (アセンブリ) ファイルを配置することが可能でした。しかし、これは Go のビルドプロセスを複雑にし、予期せぬ挙動や依存関係の問題を引き起こす可能性がありました。

この変更の主な目的は、Go のビルドシステムをより明確で予測可能なものにすることです。Cgo を使用しないパッケージでは、Go のコードのみを扱うべきであるという原則を徹底することで、ビルドの整合性を高め、開発者が混乱する可能性を減らします。このコミットで参照されている `CL 149720043` が、この機能的な変更を実装したコミットであり、このドキュメントコミットはその変更をユーザーに伝えるためのものです。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とビルドシステムに関する知識が必要です。

*   **Go言語のビルドシステム**: Go言語は、`go build` コマンドによってソースコードをコンパイルし、実行可能なバイナリを生成します。このビルドシステムは、依存関係の解決、パッケージの管理、クロスコンパイルなどを自動的に行います。
*   **Cgo**: Cgo は、Go プログラムから C 言語のコードを呼び出したり、C 言語のコードから Go の関数を呼び出したりするための Go の機能です。Cgo を使用する Go パッケージには、`import "C"` という特別な宣言が含まれ、C 言語のソースファイル (`.c`, `.h` など) を含めることができます。Cgo は、Go と C の間のインターフェースを生成し、それぞれの言語のコンパイラとリンカを連携させて最終的なバイナリを生成します。
*   **Goパッケージ**: Go のコードはパッケージに分割され、関連する機能がまとめられています。各パッケージは通常、独自のディレクトリに配置されます。
*   **Go 1.4**: Go 1.4 は、2014年12月にリリースされた Go 言語のメジャーバージョンです。このバージョンでは、パフォーマンスの向上、ツールチェインの改善、新しい言語機能の追加など、多くの変更が加えられました。このコミットは、そのリリースノートの一部を構成しています。

## 技術的詳細

Go 1.4 より前は、`go build` コマンドは、Cgo を使用しない Go パッケージであっても、そのディレクトリ内に存在する `.c` や `.s` ファイルを自動的にコンパイルしようと試みることがありました。これは、Go のビルドシステムが Cgo の有無にかかわらず、特定の拡張子を持つファイルを「ビルド対象」と見なす可能性があったためです。

しかし、この挙動はいくつかの問題を引き起こしました。

1.  **意図しないコンパイル**: 開発者が Go のコードのみを意図しているにもかかわらず、誤って配置された C ソースファイルがコンパイルされ、予期せぬエラーや警告が発生する可能性がありました。
2.  **ビルドの複雑性**: Cgo を使用しないパッケージで C ソースファイルを扱うことは、ビルドプロセスに不必要な複雑性をもたらし、デバッグを困難にしました。
3.  **依存関係の不明瞭さ**: Cgo を使用しないパッケージで C ソースファイルが存在すると、そのパッケージが外部の C ライブラリに依存しているのか、それとも単に古いコードが残っているだけなのかが不明瞭になることがありました。

Go 1.4 で導入された変更は、この曖昧さを解消し、Go のビルドシステムをより厳格にしました。具体的には、Go のツールチェインは、`import "C"` 宣言がない Go パッケージにおいては、`.c` や `.s` といった C/アセンブリ言語のソースファイルをビルド対象から除外するようになりました。これにより、Cgo を使用しないパッケージは純粋な Go コードのみで構成されることが保証され、ビルドの予測可能性と堅牢性が向上しました。

このコミットは、この重要な変更を `doc/go1.4.txt` に追記することで、Go 1.4 にアップグレードする開発者に対して、この新しい制約を明確に伝えています。

## コアとなるコードの解説

このコミットは、Go のビルドシステム自体のコードを変更するものではなく、Go 1.4 のリリースノートに新しい制約を追記するものです。したがって、直接的な「コアとなるコードの解説」は存在しません。

しかし、この行が指し示している `CL 149720043` は、Go のビルドツール (`cmd/go`) が Cgo を使用しないパッケージ内の C ソースファイルを無視するように変更された実際のコード変更を指します。この変更は、`go/build` パッケージや `cmd/go` の内部ロジックに影響を与え、ファイルの検出とコンパイルのルールを調整したと考えられます。具体的には、Go のビルドプロセスがソースファイルをスキャンする際に、`import "C"` がない Go パッケージでは `.c` や `.s` ファイルをスキップするようなロジックが追加されたと推測されます。

このドキュメントの追加は、Go 1.4 のユーザーがこの変更を認識し、既存のプロジェクトで Cgo を使用せずに C ソースファイルを含んでいる場合に、ビルドエラーを回避するための情報を提供することを目的としています。
