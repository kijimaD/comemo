## 変更の背景

このコミットの主な目的は、Goプログラムがコマンドラインフラグの不正な使用を検出した際に表示する「Usage」メッセージの動作を、開発者がより柔軟に制御できるようにすることです。

変更前は、`flag` パッケージの `Usage` 関数は固定されており、不正なフラグが検出されると、デフォルトのヘルプメッセージを標準エラーに出力した後、`os.Exit(1)` を呼び出してプログラムを終了していました。この挙動は、多くのシンプルなコマンドラインツールでは問題ありませんが、より複雑なアプリケーションや、テストフレームワーク、あるいは特定の終了コードを必要とする環境では、以下の点で不都合が生じる可能性がありました。

1.  **終了コードの制御**: `os.Exit(1)` がハードコードされているため、プログラムがエラー終了する際の終了コードをカスタマイズできませんでした。例えば、特定の種類のフラグエラーに対して異なる終了コードを返したい場合などです。
2.  **プログラムの継続**: `os.Exit()` が呼び出されると、プログラムは即座に終了し、それ以降のクリーンアップ処理やエラーハンドリングロジックが実行されません。これにより、リソースの解放やログの記録など、終了前に実行すべき重要な処理がスキップされる可能性がありました。
3.  **カスタムヘルプメッセージ**: デフォルトの `Usage` メッセージは、すべての定義済みフラグを列挙するシンプルなものでした。しかし、アプリケーションによっては、より詳細な説明、使用例、あるいは特定の書式を持つカスタムヘルプメッセージを表示したい場合があります。以前の設計では、これを実現するためには `flag` パッケージの内部をハックするか、独自のフラグ解析ロジックを実装する必要がありました。

このコミットは、`Usage` 関数をユーザーが上書き可能な変数にすることで、これらの課題を解決し、`flag` パッケージの柔軟性を向上させています。

## 前提知識の解説

### Go言語の `flag` パッケージ

Go言語の `flag` パッケージは、コマンドライン引数を解析するための標準ライブラリです。これにより、開発者は `-name=value` や `-name value` の形式でコマンドライン引数を定義し、プログラム内でその値にアクセスできます。

主要な機能:
*   `flag.StringVar`, `flag.IntVar`, `flag.BoolVar` などを用いて、特定の型のフラグを定義します。
*   `flag.Parse()` を呼び出すことで、コマンドライン引数を解析し、定義されたフラグ変数に値を設定します。
*   デフォルトでは、不正なフラグが渡された場合や `-h`, `--help` フラグが指定された場合に、`flag.Usage` 関数が呼び出され、定義されているすべてのフラグとその説明が出力されます。

### `os.Exit()` 関数

`os.Exit(code int)` は、Goプログラムを即座に終了させるための関数です。引数 `code` は終了ステータスを表し、慣習的に `0` は成功、`0` 以外の値はエラーを示します。`os.Exit()` が呼び出されると、`defer` ステートメントで登録された関数は実行されず、プログラムは強制的に終了します。

### 関数型変数 (Function Variables)

Go言語では、関数も第一級オブジェクトであり、変数に代入したり、関数の引数として渡したり、関数の戻り値として返すことができます。このコミットでは、`Usage` 関数を通常の関数定義から関数型変数 `var Usage = func() { ... }` に変更しています。これにより、ユーザーは `flag.Usage = myCustomUsageFunction` のように、独自の関数を `flag.Usage` 変数に代入することで、デフォルトの挙動を簡単に上書きできるようになります。

## 技術的詳細

このコミットにおける技術的な変更点は主に以下の3つです。

1.  **`Usage` 関数の定義変更**:
    *   以前は `func Usage() { ... }` という通常の関数として定義されていました。
    *   変更後は `var Usage = func() { ... }` という関数型変数として定義されています。これにより、外部からこの変数に別の関数を代入することで、デフォルトの `Usage` の実装を上書きすることが可能になります。

2.  **デフォルト `Usage` からの `os.Exit(1)` の削除**:
    *   変更前の `Usage` 関数は、ヘルプメッセージを出力した後、`os.Exit(1)` を呼び出してプログラムを終了させていました。
    *   変更後のデフォルト `Usage` 関数からは `os.Exit(1)` が削除されました。これにより、ユーザーが `flag.Usage` を上書きした場合、そのカスタム `Usage` 関数が `os.Exit()` を呼び出すかどうかを自由に決定できるようになります。デフォルトの `Usage` が呼び出された場合でも、プログラムは即座に終了せず、呼び出し元に戻ります。

3.  **フラグ解析エラー時の `os.Exit(2)` の追加**:
    *   `flag` パッケージの内部関数 `parseOne` 内で、不正なフラグ構文、フラグの二重指定、未定義のフラグ、不正なブール値、引数不足などのエラーが発生した場合に、以前は `Usage()` を呼び出すだけでした。
    *   変更後は、`Usage()` を呼び出した直後に `os.Exit(2)` が追加されました。これは、デフォルトの `Usage` 関数が `os.Exit()` を呼び出さなくなったため、フラグ解析エラーが発生した際には、明示的にプログラムを終了させる必要があるためです。終了コード `2` は、コマンドライン構文エラーを示す一般的な慣習です。

これらの変更により、`flag` パッケージは、デフォルトの挙動を維持しつつ、より高度なカスタマイズとエラーハンドリングの柔軟性を開発者に提供するようになりました。

*   **変更点**: `func Usage()` という通常の関数定義が `var Usage = func() { ... }` という関数型変数定義に変わりました。
*   **影響**: この変更により、`flag.Usage` はパッケージ外部からアクセス可能な変数となり、開発者は `flag.Usage = myCustomFunction` のように独自の関数を代入して、デフォルトのヘルプメッセージ表示ロジックを完全に置き換えることができるようになりました。
*   **`os.Exit(1)` の削除**: 以前は `Usage` 関数が呼び出されると、メッセージ表示後に `os.Exit(1)` でプログラムが終了していました。この行が削除されたことで、デフォルトの `Usage` が呼び出されても、プログラムは即座に終了せず、呼び出し元に制御が戻るようになりました。これにより、開発者は `flag.Parse()` の後に独自の終了処理やエラーハンドリングを記述できるようになります。

### `parseOne` 関数内の `os.Exit(2)` の追加

`parseOne` 関数は、個々のコマンドラインフラグを解析する内部関数です。この関数内で様々なフラグ解析エラーが検出された際に、`Usage()` を呼び出した後に `os.Exit(2)` が追加されました。
