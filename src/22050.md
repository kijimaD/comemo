# [インデックス 22050] ファイルの概要

このコミットは、Go言語のアセンブラ（`cmd/asm`）において、PPC64アーキテクチャ向けの浮動小数点演算命令である`FMADD`（Fused Multiply-Add）とその関連命令のサポートを追加するものです。具体的には、これらの命令が既存の`RLD`（Rotate Left Doubleword）命令群と同様の特殊な処理を必要とすることから、`IsPPC64RLD`関数に`FMADD`系の命令を追加し、アセンブラが正しくこれらの命令を処理できるように変更しています。

## 変更の背景

このコミットの背景には、Go言語のPPC64アーキテクチャ向けアセンブラ（`cmd/asm`）が、特定の浮動小数点演算命令である`FMADD`（Fused Multiply-Add）のサポートを欠いていたという問題があります。`FMADD`は、浮動小数点数の乗算と加算を単一の命令で実行するもので、特に科学技術計算やグラフィックス処理において高い精度と性能を提供する重要な命令です。

Goのアセンブラは、各アーキテクチャ固有の命令セットを抽象化して扱いますが、一部の命令は特殊なオペランドの処理や構文規則を持つため、アセンブラ側で特別なハンドリングが必要です。PPC64アーキテクチャの`RLD`（Rotate Left Doubleword）命令群は、その複雑なオペランド構造から既に`IsPPC64RLD`関数で特殊な処理が施されていました。

以前のパスで`FMADD`命令のサポートが見落とされていたため、このコミットでは`FMADD`とその関連命令（`FMSUB`, `FNMADD`, `FNMSUB`など）も`RLD`命令と同様の特殊な処理が必要であると判断され、`IsPPC64RLD`関数にこれらを追加することで、アセンブラが`FMADD`系の命令を正しく解析・処理できるように修正されました。これにより、PPC64上でGoプログラムが`FMADD`命令を効率的に利用できるようになり、浮動小数点演算の精度とパフォーマンスが向上することが期待されます。

## 前提知識の解説

### 1. Go言語のアセンブラ (`cmd/asm`)

Go言語は、そのコンパイラツールチェーンの一部として独自のアセンブラ（`go tool asm`、または内部的には`cmd/asm`）を持っています。これは、Goのソースコードから生成されるアセンブリコード（`.s`ファイル）をオブジェクトファイル（`.o`ファイル）に変換する役割を担います。Goのアセンブラは、一般的なアセンブラとは異なり、特定のCPUアーキテクチャに直接対応するのではなく、Go独自の抽象化された命令セットを使用します。これにより、Goは異なるアーキテクチャ間で一貫したアセンブリ言語の記述を可能にしています。この抽象化された命令は、最終的にリンカによって各ターゲットアーキテクチャのネイティブ命令に変換されます。

### 2. PPC64アーキテクチャ

PPC64（PowerPC 64-bit）は、IBMによって開発されたPowerPC命令セットアーキテクチャの64ビット版です。サーバー、スーパーコンピュータ、組み込みシステムなど、幅広い分野で使用されています。PPC64は、その強力な浮動小数点演算能力と並列処理能力で知られています。

### 3. FMADD (Fused Multiply-Add) 命令

`FMADD`は「Fused Multiply-Add」の略で、浮動小数点数の乗算と加算を単一のCPU命令で実行するものです。具体的には、`(A * B) + C`のような計算を、中間結果の丸めなしに行います。通常、乗算と加算はそれぞれ独立した命令であり、乗算結果が一度丸められてから加算されます。しかし、`FMADD`ではこの中間丸めが行われないため、計算の精度が向上し、また命令の実行サイクルも短縮されるため、パフォーマンスも向上します。PPC64アーキテクチャには、`FMADD`の他にも、`FMSUB`（Fused Multiply-Subtract）、`FNMADD`（Fused Negative Multiply-Add）、`FNMSUB`（Fused Negative Multiply-Subtract）といった関連命令が存在します。

### 4. RLD (Rotate Left Doubleword) 命令

`RLD`命令は、PPC64アーキテクチャにおけるビット操作命令の一種です。64ビットのダブルワード（doubleword）内のビットを左に回転させたり、特定のビット範囲を抽出・挿入したりするために使用されます。これらの命令は、その複雑なオペランドの指定方法から、Goのアセンブラ内で特殊な処理を必要とすることがあります。例えば、Goのアセンブリ構文とネイティブPPC64のアセンブリ構文では、オペランドの順序が異なる場合があり、アセンブラがこれを適切に変換する必要があります。

### 5. `obj.Prog` と `obj.Addr`

Goのコンパイラとリンカの内部では、`cmd/internal/obj`パッケージが低レベルのアセンブリ命令とそのオペランドを表現するために`obj.Prog`と`obj.Addr`というデータ構造を使用します。
*   `obj.Prog`: 単一のアセンブリ命令（プログラム）を表します。オペコードや、その命令が参照するオペランドなどの情報を含みます。
*   `obj.Addr`: `obj.Prog`内のオペランドやアドレスを表します。定数、レジスタ、メモリ位置、あるいは他の命令への参照など、様々な種類のアドレスを表現できます。

これらの構造は、Goのコンパイルプロセスにおいて、Goのソースコードが中間的なアセンブリ形式に変換され、最終的な実行可能ファイルが生成されるまでの低レベルな処理を担っています。

## 技術的詳細

このコミットの技術的詳細な変更点は、主に`src/cmd/asm/internal/arch/ppc64.go`ファイル内の`IsPPC64RLD`関数の拡張と、`src/cmd/asm/internal/asm/asm.go`ファイル内のコメント修正にあります。

### `IsPPC64RLD`関数の拡張

`IsPPC64RLD`関数は、PPC64アーキテクチャにおいて、Goのアセンブラが特殊な処理を必要とする命令（主に`RLD`系のビット操作命令）を識別するために使用されます。これらの命令は、そのオペランドの解釈や処理が他の一般的な命令とは異なるため、アセンブラが特別にハンドリングする必要があります。

このコミットでは、`FMADD`系の命令（`AFMADD`, `AFMADDCC`, `AFMADDS`, `AFMADDSCC`, `AFMSUB`, `AFMSUBCC`, `AFMSUBS`, `AFMSUBSCC`, `AFNMADD`, `AFNMADDCC`, `AFNMADDS`, `AFNMADDSCC`, `AFNMSUB`, `AFNMSUBCC`, `AFNMSUBS`, `AFNMSUBSCC`）が、`RLD`命令と同様に特殊なオペランド処理を必要とすることが判明したため、この関数に追加されました。

`FMADD`系の命令は、複数の浮動小数点レジスタをオペランドとして取り、そのうちのいくつかは乗算の入力、残りは加算の入力となります。Goのアセンブラがこれらの命令を正しく解析し、`obj.Prog`構造の`From`, `Reg`, `From3`などのフィールドに適切にマッピングするためには、これらの命令が特殊なカテゴリに属することを`IsPPC64RLD`関数で識別する必要があります。これにより、アセンブラはこれらの命令に対して、例えば2番目のオペランドが常にレジスタであるといった特定の規則を適用できるようになります。

### `src/cmd/asm/internal/asm/asm.go`の変更

`src/cmd/asm/internal/asm/asm.go`ファイルでは、`asmInstruction`メソッド内のコメントが修正されました。このメソッドは、アセンブリ命令を解析し、`obj.Prog`構造に変換する主要なロジックを含んでいます。

変更前:
```go
// 2nd operand is always a register.
```
変更後:
```go
// 2nd operand must always be a register.

// That is, are there 4-operand instructions without this property?
```
この変更は、`IsPPC64RLD`によって識別される命令（`RLD`系および今回追加された`FMADD`系）の2番目のオペランドが常にレジスタであるという前提をより明確にしています。また、`TODO`コメントが追加され、将来的にこの規則がすべての4オペランド命令に適用されるべきか、あるいは命令タイプによって条件付けされるべきかについての検討が促されています。これは、アセンブラの堅牢性を高め、将来的な拡張性に対応するための配慮です。

これらの変更により、GoのPPC64アセンブラは`FMADD`系の命令を正しく処理できるようになり、PPC64アーキテクチャ上でのGoプログラムの浮動小数点演算の正確性と効率性が向上します。

## コアとなるコードの解説

### `src/cmd/asm/internal/arch/ppc64.go` の変更点

このファイルでは、`IsPPC64RLD`関数が拡張されています。この関数は、GoのアセンブラがPPC64アーキテクチャの命令を解析する際に、特定の命令が特殊な処理を必要とするかどうかを判断するために使用されます。

*   **変更前**: `IsPPC64RLD`関数は、`ppc64.ARLDC`、`ppc64.ARLDCCC`などの`RLD`（Rotate Left Doubleword）系の命令のみを特殊な命令として認識していました。これらの命令は、ビット操作に関連し、そのオペランドの解釈に特殊なルールがあるため、アセンブラが特別に処理する必要がありました。
*   **変更後**: `FMADD`（Fused Multiply-Add）系の命令（`ppc64.AFMADD`, `ppc64.AFMADDCC`, `ppc64.AFMADDS`, `ppc64.AFMADDSCC`, `ppc64.AFMSUB`, `ppc64.AFMSUBCC`, `ppc64.AFMSUBS`, `ppc64.AFMSUBSCC`, `ppc64.AFNMADD`, `ppc64.AFNMADDCC`, `ppc64.AFNMADDS`, `ppc64.AFNMADDSCC`, `ppc64.AFNMSUB`, `ppc64.AFNMSUBCC`, `ppc64.AFNMSUBS`, `ppc64.AFNMSUBSCC`）が、`RLD`命令と同様に特殊な処理を必要とする命令として追加されました。
    *   これらの`FMADD`系の命令は、複数の浮動小数点レジスタをオペランドとして取り、そのうちのいくつかは乗算の入力、残りは加算の入力となります。Goのアセンブラがこれらの命令を正しく解析し、`obj.Prog`構造の`From`, `Reg`, `From3`などのフィールドに適切にマッピングするためには、これらの命令が特殊なカテゴリに属することを`IsPPC64RLD`関数で識別する必要があります。
    *   この追加により、アセンブラは`FMADD`系の命令に対しても、例えば2番目のオペランドが常にレジスタであるといった特定の規則を適用できるようになります。

### `src/cmd/asm/internal/asm/asm.go` の変更点

このファイルでは、`Parser`構造体の`asmInstruction`メソッド内のコメントが修正されています。このメソッドは、アセンブリ命令を解析し、`obj.Prog`構造に変換する主要なロジックを含んでいます。

*   **変更前**: `if p.arch.Thechar == '9' && arch.IsPPC64RLD(op)`という条件分岐の内部で、「2番目のオペランドは常にレジスタである」というコメントがありました。
*   **変更後**: コメントが「2番目のオペランドは常にレジスタでなければならない」とより強調された表現に変更されました。さらに、`TODO`コメントが追加され、「この規則を命令タイプでガードする必要があるか？つまり、このプロパティを持たない4オペランド命令は存在するか？」という疑問が提示されています。
    *   この`TODO`は、`IsPPC64RLD`関数によって識別される命令（`RLD`系および`FMADD`系）の2番目のオペランドが常にレジスタであるという前提が、PPC64アーキテクチャのすべての4オペランド命令に当てはまるわけではない可能性を考慮し、アセンブラの堅牢性と正確性をさらに高めるための将来的な改善点を示唆しています。

これらの変更は、GoのPPC64アセンブラが`FMADD`系の命令を正しく解析し、内部表現に変換できるようにするために不可欠です。これにより、PPC64アーキテクチャ上でGoプログラムが`FMADD`命令を効率的に利用できるようになり、浮動小数点演算の精度とパフォーマンスが向上します。
