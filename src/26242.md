この変更は Issue #13685 を修正します。

## 変更の背景

このコミットの背景には、Goの `net/http` パッケージにおける `User-Agent` ヘッダーの処理に関する一貫性の欠如がありました。特に、HTTP/1.1とHTTP/2の間で `User-Agent` ヘッダーのデフォルト値の送信や、ユーザーが明示的にヘッダーを抑制しようとした際の挙動に差異が存在していました。

具体的には、以下のような問題が考えられます。

1.  **HTTP/1.1とHTTP/2間の挙動の不一致**: ユーザーが `http.Request.Header["User-Agent"]` を `nil` や空のスライス (`[]string{}`) に設定した場合、HTTP/1.1とHTTP/2でデフォルトの `User-Agent` が送信されるかどうかの挙動が異なっていた可能性があります。開発者は、両方のプロトコルで同じコードパスを使用しても、異なる結果に直面する可能性がありました。
2.  **ヘッダー抑制の意図の不明確さ**: ユーザーが `User-Agent` ヘッダーを送信したくない場合、どのように設定すればよいかが明確ではありませんでした。例えば、`req.Header.Set("User-Agent", "")` と `req.Header["User-Agent"] = nil` のどちらが意図した挙動（ヘッダーを送信しない）をもたらすのか、あるいはデフォルトの `User-Agent` を抑制するのかが曖昧でした。
3.  **他のオプションヘッダーとの非一貫性**: `net/http` パッケージでは、`Date` や `Content-Type` のような他のオプションヘッダーについては、ユーザーがヘッダーを明示的に設定した場合（たとえ値が空であっても）、デフォルト値の自動生成や送信は行われないという一貫したポリシーがありました。しかし、`User-Agent` ヘッダーはこのポリシーから逸脱している部分があったため、全体的なAPI設計の一貫性を損なっていました。

これらの問題を解決し、開発者がより予測可能で一貫性のある方法で `User-Agent` ヘッダーを制御できるようにするために、このコミットが導入されました。特に、HTTP/1.1の挙動をHTTP/2の挙動に合わせることで、将来的なメンテナンス性やコードの理解度も向上させることが意図されています。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

### 1. HTTP `User-Agent` ヘッダー

`User-Agent` ヘッダーは、HTTPリクエストを送信するクライアント（ウェブブラウザ、アプリケーションなど）が、自身の識別情報（アプリケーション名、バージョン、オペレーティングシステムなど）をサーバーに伝えるために使用するリクエストヘッダーです。サーバーはこの情報を使って、クライアントの種類に応じたコンテンツを提供したり、統計情報を収集したりします。

例: `User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/100.0.4896.88 Safari/537.36`

Goの `net/http` パッケージでは、デフォルトで `Go-http-client/1.1` (HTTP/1.1の場合) や `Go-http-client/2.0` (HTTP/2の場合) のような `User-Agent` が自動的に設定されます。ユーザーは `http.Request.Header` を介してこのヘッダーをカスタマイズしたり、抑制したりすることができます。

### 2. Goの `net/http` パッケージ

`net/http` はGo言語の標準ライブラリで、HTTPクライアントとサーバーの実装を提供します。クライアント側では、`http.Client` と `http.Transport` がHTTPリクエストの送信を担当します。

*   `http.Client`: HTTPリクエストを送信するための高レベルなインターフェースを提供します。
*   `http.Transport`: 実際のネットワーク接続、プロトコルハンドリング（HTTP/1.1、HTTP/2）、接続の再利用などを担当する低レベルなインターフェースです。`http.Client` はデフォルトで `http.DefaultTransport` を使用します。

### 3. HTTP/1.1 と HTTP/2

*   **HTTP/1.1**: 広く普及しているHTTPのバージョンで、テキストベースのヘッダーを使用し、リクエストごとに新しいTCP接続を確立するか、Keep-Aliveで再利用します。
*   **HTTP/2**: HTTP/1.1のパフォーマンス上の課題を解決するために設計された新しいバージョンです。バイナリフレーミング、多重化、ヘッダー圧縮（HPACK）などの機能により、より効率的な通信を可能にします。Goの `net/http` パッケージは、`golang.org/x/net/http2` パッケージをバンドルすることでHTTP/2をサポートしています。

HTTP/1.1とHTTP/2では、ヘッダーの処理方法に内部的な違いがあります。特に、HTTP/2ではヘッダーがバイナリ形式でエンコードされ、HPACKというアルゴリズムで圧縮されます。このため、ヘッダーの存在チェックや値の処理ロジックが、両プロトコルで完全に同一ではない場合があります。

### 4. `golang.org/x/net/http2` のバンドル

Goの標準ライブラリは、安定性と互換性を重視しています。しかし、HTTP/2のような比較的新しいプロトコルや、急速に進化するネットワーク関連の機能については、標準ライブラリのリリースサイクルとは独立して開発が進められることがあります。`golang.org/x/net` リポジトリは、Goのネットワーク関連の実験的な機能や、標準ライブラリに統合される前のプロトコル実装（例: HTTP/2）をホストしています。

`net/http` パッケージが `golang.org/x/net/http2` を「バンドル」しているとは、`net/http` のソースコード内に `golang.org/x/net/http2` の特定のリビジョン（スナップショット）のコードが含まれていることを意味します。これにより、標準ライブラリのユーザーは、外部モジュールをインポートすることなくHTTP/2機能を利用できますが、`net/http` が更新されるたびに、バンドルされている `http2` のバージョンも更新される可能性があります。

## 技術的詳細

このコミットの技術的詳細は、主に `User-Agent` ヘッダーの処理ロジックの一貫性向上と、HTTP/2実装の更新にあります。

### 1. `User-Agent` ヘッダー処理の一貫性向上

以前のGoの `net/http` パッケージでは、`User-Agent` ヘッダーの処理において、HTTP/1.1とHTTP/2の間で微妙な差異がありました。このコミットは、この差異を解消し、ユーザーが `User-Agent` ヘッダーを明示的に設定した場合（たとえそれが空の値であっても）には、デフォルトの `User-Agent` を送信しないという一貫した挙動を確立します。

**変更前（推測される挙動）:**

*   **HTTP/1.1 (`src/net/http/request.go`)**:
    *   `req.Header["User-Agent"]` が `nil` または空のスライスの場合、デフォルトの `User-Agent` (`Go-http-client/1.1`) が送信される。
    *   `req.Header["User-Agent"] = []string{""}` のように明示的に空の文字列が設定された場合、空の `User-Agent` ヘッダーが送信される（またはヘッダーが抑制される）。
    *   `req.Header.Set("User-Agent", "custom")` のようにカスタム値が設定された場合、そのカスタム値が送信される。
*   **HTTP/2 (`src/net/http/h2_bundle.go`)**:
    *   HTTP/2の実装は、`User-Agent` ヘッダーの存在をより厳密にチェックし、ユーザーが明示的にヘッダーを設定した場合は、その値が空であってもデフォルトを抑制する傾向があった可能性があります。

**変更後（このコミットによる挙動）:**

このコミットにより、HTTP/1.1とHTTP/2の両方で以下の挙動が統一されます。

*   `req.Header["User-Agent"]` が**存在する場合**（`nil` であっても、空のスライスであっても、または空の文字列を含むスライスであっても）、`net/http` はデフォルトの `User-Agent` を**送信しません**。
    *   もし `req.Header["User-Agent"]` が `nil` または `[]string{}` の場合、`User-Agent` ヘッダー自体がリクエストから完全に省略されます。
    *   もし `req.Header.Set("User-Agent", "")` のように空の文字列が設定された場合も、`User-Agent` ヘッダーは省略されます。
    *   もし `req.Header.Set("User-Agent", "custom")` のようにカスタム値が設定された場合、そのカスタム値が送信されます。
*   `req.Header["User-Agent"]` が**存在しない場合**、`net/http` はデフォルトの `User-Agent` (`Go-http-client/1.1` または `Go-http-client/2.0`) を自動的に追加して送信します。

この変更の意図は、`Date` や `Content-Type` といった他のオプションヘッダーと同様に、ユーザーがヘッダーを「定義した」時点で、そのヘッダーの管理はユーザーに委ねられるという一貫したポリシーを `User-Agent` にも適用することです。

### 2. HTTP/2実装の更新

このコミットでは、`net/http` にバンドルされている `golang.org/x/net/http2` のコードが、特定のリビジョン `1ade16a545` に更新されています。この更新は、`https://go-review.googlesource.com/18285` で行われた変更を取り込むためのものです。具体的な変更内容は、このコミットの差分からは詳細には読み取れませんが、一般的に `x/net/http2` の更新は、パフォーマンスの改善、バグ修正、またはHTTP/2プロトコル仕様の変更への対応などを含みます。

このコミットの差分では、`src/net/http/h2_bundle.go` 内で `http2defaultUserAgent = "Go-http-client/2.0"` という定数が追加され、`encodeHeaders` 関数内で `User-Agent` の処理ロジックが変更されていることが確認できます。これは、HTTP/2側でもHTTP/1.1と同様の `User-Agent` 処理ロジックを実装し、一貫性を保つためのものです。

### 3. テストの追加

このコミットの重要な側面は、`User-Agent` の挙動を検証するための包括的なテスト (`TestTransportUserAgent_h1`, `TestTransportUserAgent_h2`) が追加されたことです。これらのテストは、以下のシナリオをカバーしています。

*   `User-Agent` が設定されていない場合（デフォルトが送信されることを期待）。
*   カスタムの `User-Agent` が設定されている場合。
*   `User-Agent` が複数の値を持つスライスとして設定されている場合（最初の値のみが使用されることを期待）。
*   `User-Agent` が空の文字列 (`""`) に設定されている場合（ヘッダーが省略されることを期待）。
*   `User-Agent` が `nil` に設定されている場合（ヘッダーが省略されることを期待）。

これらのテストにより、`User-Agent` の挙動がHTTP/1.1とHTTP/2の両方で意図通りに機能し、将来の変更によって意図しないリグレッションが発生しないことが保証されます。

## コアとなるコードの解説

### `src/net/http/clientserver_test.go` の変更

このファイルに追加されたテストコードは、`User-Agent` ヘッダーの新しい挙動を検証するためのものです。`testTransportUserAgent` 関数は、HTTP/1.1 (`h1Mode`) と HTTP/2 (`h2Mode`) の両方で実行され、様々な `User-Agent` の設定パターン（未設定、カスタム値、空文字列、nil）に対して、サーバーが受け取る `User-Agent` ヘッダーが期待通りであるかをチェックします。

特に重要なのは、`req.Header.Set("User-Agent", "")` や `req.Header["User-Agent"] = nil` の場合に、サーバー側で `User-Agent` ヘッダーが全く受信されない（`[]` となる）ことを期待している点です。これは、ユーザーが明示的に `User-Agent` を設定しようとした場合、たとえその値が空であっても、デフォルトの `User-Agent` が抑制されるという新しいポリシーを反映しています。

### `src/net/http/h2_bundle.go` の変更

このファイルは、`net/http` パッケージにバンドルされているHTTP/2の実装です。

1.  **`http2defaultUserAgent` 定数の追加**:
    `http2defaultUserAgent = "Go-http-client/2.0"` が追加されました。これは、HTTP/2リクエストで `User-Agent` が明示的に設定されていない場合に送信されるデフォルト値です。HTTP/1.1の `defaultUserAgent` (`Go-http-client/1.1`) と対をなします。

2.  **`encodeHeaders` 関数の変更**:
    `encodeHeaders` 関数は、HTTP/2リクエストのヘッダーをエンコードする役割を担います。この関数内で `User-Agent` ヘッダーの処理ロジックが大幅に変更されました。
    *   `var didUA bool` が導入され、ループ内で `lowKey == "user-agent"` が検出された場合に `didUA = true` と設定されます。これにより、ユーザーが `User-Agent` ヘッダーをリクエストに含めたかどうかを追跡します。
    *   `User-Agent` ヘッダーが検出された場合、`len(vv) < 1` (値が空のスライス) または `vv[0] == ""` (最初の値が空文字列) であれば、`continue` してこのヘッダーをエンコードしないようにします。これは、ユーザーが `User-Agent` を空に設定することで、ヘッダーを抑制する意図を示していると解釈するためです。
    *   ループの最後に `if !didUA` のチェックが追加され、もしユーザーが `User-Agent` ヘッダーを全く設定していなかった場合（`didUA` が `false` のままの場合）にのみ、`cc.writeHeader("user-agent", http2defaultUserAgent)` を呼び出してデフォルトの `User-Agent` を追加します。

この変更により、HTTP/2においても、ユーザーが `User-Agent` ヘッダーを明示的に設定した場合は、その値が空であってもデフォルトの `User-Agent` は送信されなくなります。

### `src/net/http/request.go` の変更

このファイルは、HTTP/1.1リクエストの書き込みロジックを扱います。

*   **`User-Agent` 決定ロジックの変更**:
    以前のコードでは、`req.Header["User-Agent"]` が存在し、かつ `len(ua) > 0` (値が空でない) の場合にのみ、その値が `userAgent` として使用されていました。
    新しいコードでは、`if _, ok := req.Header["User-Agent"]; ok` というパターンが使用されています。これは、`req.Header` マップに `"User-Agent"` というキーが**存在するかどうか**のみをチェックします。
    *   もしキーが存在すれば（`ok` が `true`）、`userAgent = req.Header.Get("User-Agent")` を使用します。`Header.Get` メソッドは、指定されたヘッダーの最初の値を返します。もしヘッダーが存在しないか、値が空の場合は空文字列を返します。
    *   もしキーが存在しなければ（`ok` が `false`）、`userAgent` は `defaultUserAgent` のままになります。

この変更により、HTTP/1.1においても、ユーザーが `req.Header["User-Agent"]` を `nil` や空のスライス、あるいは空文字列に設定した場合でも、`"User-Agent"` キーが `req.Header` マップに存在することになるため、デフォルトの `User-Agent` は抑制され、`req.Header.Get("User-Agent")` が返す空文字列が `userAgent` として使用されます。最終的に `if userAgent != ""` のチェックで空文字列は送信されないため、ヘッダーは省略されます。

これらの変更は、HTTP/1.1とHTTP/2の両方で `User-Agent` ヘッダーの挙動を一貫させ、ユーザーがヘッダーを明示的に制御する際の予測可能性を高めることを目的としています。
