## 元コミット内容

`net.Listener`インターフェースに`Addr() string`メソッドを追加し、テストで固定ポートを使用しないように変更しました。また、`google/net/rpc`を`gotest`形式に変換しました。

## 変更の背景

この変更の主な背景には、ネットワークプログラミングにおけるテストの信頼性と柔軟性の向上が挙げられます。

1.  **固定ポートの競合問題の解消**: 従来のテストでは、特定のポート番号（例: `9997`）をハードコードして使用していました。しかし、複数のテストが同時に実行されたり、同じマシン上で他のプロセスがそのポートを使用していたりする場合、ポートの競合が発生し、テストが不安定になったり失敗したりする原因となります。これを解決するためには、システムが利用可能なポートを動的に割り当て、そのポート番号をテストコードが取得できる仕組みが必要です。
2.  **`net.Listener`インターフェースの機能強化**: `net.Listener`は、ネットワーク接続をリッスンするための汎用インターフェースですが、リッスンしているアドレス（特に動的に割り当てられたポートを含む）を取得する標準的な方法がありませんでした。`Addr()`メソッドを追加することで、この情報にアクセスできるようになり、インターフェースの完全性が向上します。
3.  **テストフレームワークの統一**: `google/net/rpc`のテストをGo標準の`testing`パッケージ（`gotest`）に移行することで、テストの実行方法やレポートの一貫性を保ち、Goエコシステム全体での開発体験を向上させます。

## 前提知識の解説

*   **`net.Listener`インターフェース**: Go言語の`net`パッケージで定義されているインターフェースで、着信ネットワーク接続をリッスンするための一般的な抽象化を提供します。`Accept()`メソッドで新しい接続を受け入れ、`Close()`メソッドでリスナーを閉じます。
*   **動的ポート割り当て**: サーバーアプリケーションが特定のポート番号を指定せずにリッスンを開始すると、オペレーティングシステムは利用可能なポートを自動的に割り当てます。これは通常、ポート番号`0`を指定することで実現されます。割り当てられたポートは、`getsockname`システムコールなどを使用して取得できます。
*   **`syscall.Getsockname`**: ソケットディスクリプタ（ファイルディスクリプタ）に関連付けられたローカルアドレスを取得するためのシステムコールです。これにより、ソケットがリッスンしているIPアドレスとポート番号を知ることができます。
*   **`testing`パッケージ (gotest)**: Go言語に組み込まれているテストフレームワークです。テスト関数は`TestXxx(*testing.T)`というシグネチャを持ち、`go test`コマンドで実行されます。
*   **`Makefile`**: ビルドプロセスを自動化するためのツールです。`src/pkg/Makefile`はGoの標準ライブラリパッケージのビルドとテストの実行方法を定義しています。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`net.Listener`インターフェースへの`Addr()`メソッドの追加**:
    `net.Listener`インターフェースに`Addr() string`メソッドが追加されました。これにより、リスナーが現在リッスンしているネットワークアドレス（IPアドレスとポート番号）を文字列形式で取得できるようになります。
    ```go
    type Listener interface {
        Accept() (c Conn, raddr string, err os.Error);
        Close() os.Error;
        Addr() string; // Listener's network address
    }
    ```

2.  **`netFD.addr()`メソッドの実装**:
    `net`パッケージ内部で使用される`netFD`構造体に`addr()`メソッドが追加されました。このメソッドは、`syscall.Getsockname`システムコールを呼び出してソケットのローカルアドレスを取得し、それを文字列形式に変換して返します。
    ```go
    func (fd *netFD) addr() string {
        sa, err := syscall.Getsockname(fd.fd);
        if err != 0 {
            return "";
        }
        addr, err1 := sockaddrToString(sa);
        return addr;
    }
    ```
    ここで`syscall.Getsockname`は、ソケットのファイルディスクリプタ`fd.fd`からソケットアドレス情報を取得します。取得した`syscall.Sockaddr`型の情報を`sockaddrToString`ヘルパー関数で人間が読める文字列形式に変換しています。

3.  **`ListenerUnix`と`ListenerTCP`への`Addr()`メソッドの実装**:
    `net.Listener`インターフェースを実装する具体的な型である`ListenerUnix`と`ListenerTCP`に、新しく追加された`Addr()`メソッドが実装されました。これらの実装は、内部の`netFD`の`addr()`メソッドを呼び出すことで、実際のアドレス情報を取得します。
    ```go
    // ListenerUnix
    func (l *ListenerUnix) Addr() string {
        return l.fd.addr();
    }

    // ListenerTCP
    func (l *ListenerTCP) Addr() string {
        return l.fd.addr();
    }
    ```

4.  **`syscall`パッケージへの`Getsockname`と`Getpeername`の追加**:
    `syscall`パッケージに、`getsockname`と`getpeername`システムコールをラップするGo関数が追加されました。これらは、ソケットのローカルアドレス（`Getsockname`）およびピアアドレス（`Getpeername`）を取得するために使用されます。これらの関数は、OS固有の実装（Darwin, Linuxの386およびamd64アーキテクチャ）で提供されます。
    例 (`syscall_darwin.go`):
    ```go
    func Getsockname(fd int) (sa Sockaddr, errno int) {
        var rsa RawSockaddrAny;
        var len _Socklen = SizeofSockaddrAny;
        if errno = getsockname(fd, &rsa, &len); errno != 0 {
            return;
        }
        return anyToSockaddr(&rsa);
    }
    ```
    これらの関数は、`RawSockaddrAny`という汎用的なソケットアドレス構造体と、その長さを表す`_Socklen`ポインタを引数に取り、システムコールを呼び出した後、結果を`Sockaddr`インターフェース型に変換して返します。

5.  **`net/server_test.go`でのテストコードの変更**:
    テストコード`doTest`関数が変更され、`net.Listen`でポート`0`を指定して動的にポートを割り当て、`l.Addr()`で割り当てられたポート番号を取得するように修正されました。これにより、テストが固定ポートに依存しなくなり、並行実行時の競合が回避されます。
    ```go
    func doTest(t *testing.T, network, listenaddr, dialaddr string) {
        // ...
        listening := make(chan string); // チャンネルの型がintからstringに変更
        // ...
        if network == "tcp" {
            listenaddr += ":0"; // 任意の利用可能なポートをリッスン
        }
        go runServe(t, network, listenaddr, listening, done);
        addr := <-listening; // サーバーが開始するのを待つ。割り当てられたアドレスを取得
        if network == "tcp" {
            dialaddr += addr[strings.LastIndex(addr, ":"):len(addr)]; // 割り当てられたポートをダイヤルアドレスに追加
        }
        connect(t, network, dialaddr);
        // ...
    }
    ```
    `runServe`関数も`listening`チャネルの型が`chan<- int`から`chan<- string`に変更され、`l.Addr()`の戻り値を送信するように修正されています。

6.  **`src/pkg/Makefile`の更新**:
    `Makefile`の`TEST`変数に`bytes`と`crypto/hmac`が追加されました。これは、これらのパッケージのテストがGoの標準テストスイートに含まれるようになったことを示しています。

## コアとなるコードの解説

このコミットの核心は、`net.Listener`インターフェースの拡張と、それを利用したテストの改善です。

`net.Listener`インターフェースに`Addr() string`メソッドが追加されたことで、ネットワークリスナーがリッスンしている具体的なアドレス情報を取得する標準的な方法が提供されました。これは、特にポート`0`を指定してOSにポートを動的に割り当てさせた場合に非常に重要です。

`netFD.addr()`メソッドは、この`Addr()`インターフェースメソッドの基盤となる実装です。これは、ソケットのファイルディスクリプタ（`fd.fd`）を使って`syscall.Getsockname`を呼び出し、ソケットのローカルアドレス情報を取得します。`syscall.Getsockname`は、OSレベルでソケットの状態を問い合わせるためのプリミティブな操作であり、これによりGoのランタイムは、ソケットが実際にどのIPアドレスとポート番号にバインドされているかを知ることができます。

テストコード`net/server_test.go`では、この新機能が早速活用されています。`doTest`関数内で`listenaddr += ":0"`とすることで、テストサーバーは利用可能な任意のポートでリッスンを開始します。その後、`addr := <-listening`で`runServe`ゴルーチンから`l.Addr()`で取得した実際のアドレス文字列を受け取ります。このアドレス文字列には、OSが割り当てたポート番号が含まれているため、クライアント側の接続（`dialaddr`）もその動的に割り当てられたポートを使用するように調整されます。

これにより、テストは特定のポート番号に依存することなく、より堅牢で並行実行に適したものになりました。テストの実行環境に左右されにくくなり、開発の効率と信頼性が向上します。

`syscall`パッケージへの`Getsockname`と`Getpeername`の追加は、Goの標準ライブラリがOSの低レベルなネットワーク機能にアクセスするための基盤を強化するものです。これにより、Goプログラムはより詳細なソケット情報を取得できるようになり、ネットワーク関連の機能開発においてより柔軟な制御が可能になります。
