## 変更の背景

このコミットの主な背景は、Goコンパイラの字句解析器における数値リテラルの処理ロジックの複雑さと、それに伴う可読性および保守性の問題の解消です。元のコードでは、数値の様々な形式（整数、浮動小数点数、16進数、8進数、虚数など）を解析するために、複数の `goto` ステートメントとラベルが多用されていました。これは、コードのフローを追跡することを困難にし、将来的な変更やデバッグの際にエラーを引き起こす可能性がありました。

特に、浮動小数点数の指数表記において、`e` や `E` だけでなく、`p` や `P` を使用するケース（基数2の指数表記）の扱いが問題となっていました。Goのソースコードでは `p` や `P` を用いた指数表記は許可されていませんが、コンパイラが生成する内部データ（エクスポートデータ）では使用される可能性があり、この区別を明確にする必要がありました（`#9036`で言及されている問題）。

このコミットは、`goto` を排除し、より構造化された `if/else` ロジックに置き換えることで、コードの意図を明確にし、将来的な拡張やバグ修正を容易にすることを目指しています。

## 前提知識の解説

### Goコンパイラの字句解析（Lexing）
字句解析（Lexical Analysis、またはスキャニング）は、コンパイラの最初のフェーズです。ソースコードの文字列を読み込み、意味のある最小単位である「トークン」（字句）のストリームに変換します。例えば、`123 + 4.5` というコードは、`123`（整数リテラル）、`+`（演算子）、`4.5`（浮動小数点リテラル）といったトークンに分解されます。

### `cmd/compile/internal/gc` パッケージ
`cmd/compile` はGoコンパイラの主要な部分であり、`internal/gc` はその中でも特にGo言語の構文解析、型チェック、中間コード生成など、コンパイラのコアロジックを担うパッケージです。`lex.go` はこのパッケージ内にあり、字句解析器の実装を含んでいます。

### `lexer` 構造体と `number` メソッド
`lexer` 構造体は、ソースコードを読み込み、トークンを生成するための状態を保持します。`number` メソッドは、字句解析器が数値の開始文字（数字または小数点）を検出した際に呼び出され、その後の文字を読み進めて完全な数値リテラルを形成し、対応するトークンを生成する役割を担います。

### `goto` ステートメントの問題点
`goto` ステートメントは、プログラムの実行フローをコード内の任意のラベルに直接ジャンプさせる命令です。C言語などではよく使われますが、多用すると「スパゲッティコード」と呼ばれる、理解や保守が極めて困難なコードを生み出す原因となります。現代のプログラミングでは、構造化プログラミングの原則に基づき、`if/else`、`for`、`switch` などの制御構造を使用して、より明確で予測可能なコードフローを構築することが推奨されています。

### 数値リテラルの種類とGoの構文規則
Go言語では、様々な形式の数値リテラルがサポートされています。
*   **10進整数**: `123`, `0`
*   **8進整数**: `0755` (Go 1.13以降は `0o755`)
*   **16進整数**: `0xAF`, `0X10`
*   **浮動小数点数**: `3.14`, `1e-9`, `2.`, `.5`
*   **虚数**: `3i`, `1.2e-5i`

特に浮動小数点数の指数表記には、以下の2種類があります。
*   **10進指数**: `e` または `E` を使用し、基数10の指数を表します（例: `1.23e+5` は `1.23 * 10^5`）。
*   **2進指数**: `p` または `P` を使用し、基数2の指数を表します（例: `0x1.fp+3` は `(1 + 15/16) * 2^3`）。Goのソースコードでは、`p` または `P` を用いた2進指数表記は許可されていません。これは、主に機械生成されたデータや、コンパイラ内部での浮動小数点数の表現に使用されます。

### `Yyerror`
`Yyerror` は、字句解析または構文解析中にエラーが検出された際に、エラーメッセージを出力するための関数です。コンパイラが不正な構文を検出した場合に、ユーザーに適切なフィードバックを提供するために使用されます。

## 技術的詳細

このコミットにおける `number` 関数の変更は、主に以下の技術的詳細を含みます。

1.  **`goto` ステートメントの排除**:
    元のコードでは、数値の異なる部分（整数部、小数点以下、指数部、虚数単位）を解析するために `casedot`, `caseep`, `casei`, `ncu`, `caseout` といった複数のラベルと `goto` が使われていました。新しいコードでは、これらの `goto` が完全に削除され、代わりに `if/else` とループ構造を用いて、より線形な制御フローが実現されています。これにより、コードの可読性が大幅に向上し、どのパスがどの条件で実行されるかが一目でわかるようになりました。

2.  **状態変数の導入**:
    *   `isInt` (bool): 現在解析中の数値が整数である可能性が高いかどうかを示すフラグです。初期値は `false` ですが、小数点や指数部が検出されない限り `true` に保たれます。これにより、最終的に整数リテラルとして処理すべきか、浮動小数点リテラルとして処理すべきかを判断します。
    *   `malformedOctal` (bool): 8進数リテラルとして解析中に、`8` や `9` の数字が検出された場合に `true` に設定されます。Goでは `0` で始まる数値は8進数として扱われますが、`8` や `9` は8進数には含まれないため、これは不正な8進数リテラルとなります。このフラグにより、適切なエラーメッセージを生成できます。

3.  **解析ロジックの構造化**:
    新しい `number` 関数は、以下の論理的なステップで数値リテラルを解析します。
    *   **符号なし整数部（または小数点前の部分）の解析**:
        *   `0` 以外の数字で始まる場合: 10進数または浮動小数点数の整数部として数字を読み込みます。
        *   `0` で始まる場合:
            *   `0x` または `0X` が続く場合: 16進数として解析します。この場合、`isInt` は `true` に設定され、浮動小数点数にはなりません。
            *   それ以外の場合: 8進数または10進数の `0` として解析します。この際、`8` や `9` が検出された場合は `malformedOctal` フラグを立てます。
    *   **小数点以下（分数部）および指数部の解析**:
        *   `isInt` が `false` でない場合（つまり、まだ整数として扱われる可能性がある場合）にのみ、このセクションに進みます。
        *   **分数部**: `.` が検出された場合、`isInt` を `false` に設定し、小数点以下の数字を読み込みます。
        *   **指数部**: `e` または `E` が検出された場合、`isInt` を `false` に設定し、指数部の数字を読み込みます。
        *   **基数2の指数部（`p` または `P`）**: `importpkg != nil` の条件付きで `p` または `P` が許可されます。これは、Goのソースコードではなく、コンパイラが生成する内部データ（エクスポートデータ）でのみ有効な形式であることを示しています。Goのソースコードで `p` または `P` が検出された場合は、`Yyerror` でエラーが報告されます。
    *   **虚数単位の解析**: `i` が検出された場合、虚数リテラルとして処理します。
    *   **最終的な数値の変換**:
        *   `isInt` が `true` の場合: 整数リテラルとして `Mpint` 型に変換します。`malformedOctal` が `true` の場合はエラーを報告します。
        *   `isInt` が `false` の場合: 浮動小数点リテラルとして `Mpflt` 型に変換します。

4.  **エラーハンドリングの改善**:
    `malformed hex constant` (不正な16進数定数)、`malformed floating point constant exponent` (不正な浮動小数点定数指数)、`malformed octal constant` (不正な8進数定数)、`overflow in imaginary constant` (虚数定数のオーバーフロー)、`overflow in float constant` (浮動小数点定数のオーバーフロー)、`overflow in constant` (定数のオーバーフロー) など、様々なエラーケースに対して、より正確なタイミングで `Yyerror` を呼び出すようになっています。

5.  **`issue9036.go` の更新**:
    テストファイル `test/fixedbugs/issue9036.go` は、`p` または `P` を用いた指数表記がGoのソースコードでは不正であることを検証するためのものです。コミット前は `ERROR "malformed floating point constant"` というエラーメッセージを期待していましたが、コミット後は `ERROR "unexpected p10"` や `ERROR "unexpected p0"` のように、より具体的なエラーメッセージを期待するように更新されています。これは、コンパイラが `p` を浮動小数点数の一部としてではなく、予期しない識別子として解釈するようになったことを示唆しています。

## コアとなるコードの解説

変更後の `number` 関数は、数値リテラルの字句解析をより構造化された方法で実行します。

1.  **初期化**:
    `str` は最終的な数値文字列を保持し、`lexbuf` は文字を一時的にバッファリングするために使用されます。
    `isInt` は、現在解析中の数値が整数であると仮定できるかどうかを示すフラグです。
    `malformedOctal` は、8進数として解析中に不正な数字（8または9）が検出された場合に設定されるフラグです。

2.  **整数部（または小数点前の部分）の解析**:
    *   `c != '.'` の条件で、まず数値の整数部（または小数点前の部分）を解析します。
    *   `c != '0'` の場合、通常の10進数を読み込みます。
    *   `c == '0'` の場合、`0x` または `0X` が続くかをチェックし、16進数であれば `isInt = true` と設定し、16進数の数字を読み込みます。`lexbuf.Len() == 2` (つまり `0x` のみで数字が続かない) の場合は `malformed hex constant` エラーを報告します。
    *   `0` の後に `x` や `X` が続かない場合、8進数または単なる `0` として扱います。この際、`8` や `9` が検出された場合は `malformedOctal = true` と設定します。

3.  **分数部と指数部の解析**:
    *   `if !isInt` ブロックに入ります。これは、16進数として確定していない場合にのみ実行されます。
    *   **分数部**: `c == '.'` であれば、`isInt = false` と設定し、小数点以下の数字を読み込みます。
    *   **指数部**: `c == 'e' || c == 'E'` または `importpkg != nil && (c == 'p' || c == 'P')` の条件で指数部を解析します。
        *   `e` または `E` は通常の10進指数です。
        *   `p` または `P` は基数2の指数ですが、`importpkg != nil` (コンパイラ内部のエクスポートデータの場合) のみ許可されます。Goのソースコードで `p` または `P` が検出された場合、`isInt = false` と設定し、指数部の数字を読み込みます。
        *   指数記号の後に数字が続かない場合は `malformed floating point constant exponent` エラーを報告します。

4.  **虚数単位の解析**:
    `c == 'i'` であれば、虚数リテラルとして処理し、`Mpcplx` 型に変換します。オーバーフローチェックも行われます。処理が完了したら `goto done` で終了します。

5.  **最終的な数値の変換**:
    `l.ungetr(c)` で最後に読み込んだ文字を戻した後、`isInt` の値に基づいて数値の型を決定します。
    *   `isInt` が `true` の場合: 整数リテラルとして `Mpint` 型に変換します。`malformedOctal` が `true` であれば `malformed octal constant` エラーを報告し、オーバーフローチェックも行います。
    *   `isInt` が `false` の場合: 浮動小数点リテラルとして `Mpflt` 型に変換します。オーバーフローチェックも行います。

この新しい構造により、数値リテラルの解析パスが明確になり、各ステップでの条件分岐が `goto` に依存しないため、コードの理解と保守が容易になりました。
