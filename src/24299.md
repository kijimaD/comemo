## 変更の背景

この変更は、Goの `crypto/x509` パッケージが提供する証明書検証機能が、基盤となるオペレーティングシステム（特にWindows）の証明書ストアや検証API（CryptoAPI）を利用する際に発生する特定のテスト失敗を解決するために行われました。

Goの `crypto/x509` パッケージは、X.509証明書のパース、検証、および管理を行うための機能を提供します。通常、Goは独自の証明書ストアと検証ロジックを使用しますが、一部のプラットフォームでは、システムの証明書ストアや検証メカニズムと統合することで、より信頼性の高い（またはユーザーが期待する）動作を提供します。

問題の核心は、Goのテストスイートに含まれる特定のSHA2証明書検証テストが、WindowsのCryptoAPIを使用した場合に失敗するという点にありました。Goの内部検証ロジックとシステムAPIの検証ロジックの間には、証明書チェーンの構築や信頼パスの探索方法に微妙な違いが存在することがあります。特に、CryptoAPIのようなシステムAPIは、Goが想定しない「代替の検証パス」を見つけることがあり、これがテストの期待値と異なる結果を生み出していました。

この問題は、Go issue #11730 で報告されており、このコミットはその問題を修正するために導入されました。テストがシステムAPIの動作と矛盾する場合、そのテストをシステムAPI使用時にはスキップすることで、テストスイート全体の安定性を保ちつつ、Goの証明書検証機能がシステムと適切に連携できるようにすることが目的です。

## 前提知識の解説

### X.509証明書と証明書チェーン

X.509証明書は、公開鍵暗号システムにおいて、公開鍵の所有者をデジタル的に証明するための標準フォーマットです。ウェブサイトのHTTPS通信などで広く利用されています。
証明書は通常、階層的な「証明書チェーン」を形成します。これは、エンドエンティティ証明書（例：ウェブサイトの証明書）が中間認証局（Intermediate CA）によって署名され、その中間認証局の証明書がさらに上位の認証局によって署名され、最終的に信頼されたルート認証局（Root CA）によって署名されるという構造です。検証プロセスでは、このチェーンをルートまで辿り、各証明書の署名が有効であること、有効期限内であること、失効していないことなどを確認します。

### SHA2ハッシュ関数

SHA2（Secure Hash Algorithm 2）は、NIST（アメリカ国立標準技術研究所）によって開発された暗号学的ハッシュ関数のファミリーです。SHA-256、SHA-384、SHA-512などが含まれます。これらのハッシュ関数は、データの整合性を保証したり、デジタル署名の一部として使用されたりします。X.509証明書では、証明書の署名アルゴリズムや公開鍵のフィンガープリントなどにSHA2が利用されます。

### システムAPIとCryptoAPI

Go言語はクロスプラットフォームですが、TLS/SSL通信や証明書検証のようなセキュリティ関連の機能では、基盤となるオペレーティングシステムの機能を利用することがあります。
- **システムAPI**: オペレーティングシステムが提供するプログラミングインターフェースの総称です。証明書管理や暗号化処理に関するAPIも含まれます。
- **Windows CryptoAPI (Cryptographic API)**: Microsoft Windowsが提供する暗号化サービスプロバイダ（CSP）を介して、暗号化、復号化、デジタル署名、ハッシュ計算、証明書管理などの機能を提供するAPIセットです。Windows環境では、アプリケーションが証明書を検証する際に、このCryptoAPIを利用してシステムの証明書ストア（信頼されたルート証明機関など）にアクセスし、検証パスを構築することが一般的です。

### 証明書検証パスと代替パス

証明書検証の目的は、与えられた証明書が信頼できるかどうかを判断することです。これには、証明書チェーンを構築し、そのチェーン内のすべての証明書が有効であり、最終的に信頼されたルート証明書に繋がることを確認するプロセスが含まれます。
「代替の検証パス」とは、Goの内部ロジックが想定する標準的な証明書チェーンの構築方法とは異なる、しかしシステムAPIにとっては有効な別のチェーン構築方法が存在する可能性を指します。例えば、システムはGoが認識しない中間証明書をローカルストアから見つけ出し、それを使って有効なチェーンを完成させることがあります。このような違いが、Goの特定のテストケースで問題を引き起こす原因となります。

### Goのテストにおける `systemSkip`

Goのテストフレームワークでは、特定の環境や条件でのみテストをスキップするメカニズムが提供されています。このコミットで追加された `systemSkip: true` は、Goの `crypto/x509` パッケージのテスト構造体 `verifyTest` のフィールドとして導入されたもので、システムAPI（特にWindowsのCryptoAPI）が使用される環境では、そのテストケースを実行しないように指示します。これにより、Goの内部ロジックとシステムAPIの動作の差異によって発生するテストの失敗を回避し、テストスイートの信頼性を維持します。

## 技術的詳細

このコミットは、`src/crypto/x509/verify_test.go` ファイル内の `verifyTests` スライスに定義されている特定のテストケースに `systemSkip: true` フィールドを追加することで、そのテストを条件付きで無効化しています。

`verifyTests` は、様々な証明書検証シナリオを網羅するために設計されたテストケースのコレクションです。各 `verifyTest` エントリは、検証対象の証明書、期待される検証結果、および検証プロセスに影響を与える可能性のある追加のパラメータ（例：現在の時刻、DNS名、SHA2証明書であるか否かなど）を定義します。

追加された `systemSkip: true` は、Goの `crypto/x509` パッケージがシステムAPI（特にWindowsのCryptoAPI）を使用して証明書検証を行う場合に、この特定のテストケースをスキップするように指示するフラグです。コメントにもあるように、CryptoAPIはGoのテストが想定する検証パスとは異なる「代替の検証パス」を見つける能力があるため、このテストケースがGoの内部検証ロジックとシステムAPIの検証ロジックの間で異なる結果を生み出す可能性がありました。

具体的には、このテストケースは `api.moip.com.br` というDNS名を持つ証明書に関するもので、`sha2: true` が設定されていることから、SHA2ハッシュアルゴリズムを使用する証明書の検証に関連しています。Goの内部検証ロジックでは特定のチェーンを期待する一方で、WindowsのCryptoAPIはシステムの証明書ストアやポリシーに基づいて異なる有効なチェーンを構築する可能性があり、これがテストの失敗につながっていました。

`systemSkip: true` を設定することで、Goのテストランナーは、システムAPIが有効な環境（例：Windowsビルド）ではこのテストを無視し、Go独自の検証ロジックが使用される環境（例：Linuxビルド）でのみ実行するように動作します。これにより、プラットフォーム固有の動作の違いによるテストの不安定性を解消し、テストスイートの信頼性を向上させています。

## コアとなるコードの解説

この変更は、`verifyTests` というグローバル変数（`verifyTest` 型のスライス）内の特定の要素に対して行われています。`verifyTest` 構造体は、証明書検証テストの個々のケースを定義するために使用されます。

追加されたのは、以下の4行です。

```go
		// CryptoAPI can find alternative validation paths so we don't
		// perform this test with system validation.
		systemSkip: true,
```

- `systemSkip: true,`: これは `verifyTest` 構造体の新しいフィールド `systemSkip` に `true` を設定しています。このフィールドは、Goのテストランナーが、システムAPI（特にWindowsのCryptoAPI）を使用して証明書検証を行う場合に、このテストケースをスキップすべきかどうかを判断するために使用されます。`true` に設定することで、システムAPIが使用される環境ではこのテストが実行されなくなります。
- コメント: `// CryptoAPI can find alternative validation paths so we don't // perform this test with system validation.` は、この `systemSkip` フラグが追加された理由を明確に説明しています。WindowsのCryptoAPIは、Goのテストが期待する検証パスとは異なる、しかし有効な代替パスを見つける可能性があるため、このテストケースがシステム検証と互換性がないことを示しています。

この変更により、`api.moip.com.br` の証明書に関するSHA2検証テストは、Windows環境でGoがシステムの証明書ストアとCryptoAPIを利用して検証を行う際には実行されなくなります。これにより、Goのテストスイートは、プラットフォーム固有の証明書検証動作の違いによる誤った失敗を回避し、より堅牢になります。
