## 元コミット内容

`[dev.cc] cmd/asm: fix macro definition bug in the lexer`

このコミットは、`cmd/asm` の字句解析器におけるマクロ定義のバグを修正し、さらにARMアーキテクチャ特有のシフトレジスタ演算子を認識するためのヘルパーを追加します。

具体的には、`text/scanner` パッケージがスペースを隠蔽するため、字句解析器が `#define A(x)` と `#define A (x)` を同じものとして扱ってしまう問題がありました。これらはCプリプロセッサにおいては異なる意味を持ちます。前者は引数を取るマクロであり、後者は定義内容に括弧を含む単純な単語マクロです。この問題を修正するために、`A` から `(` に移動する際の相対的なカラム番号をチェックする「ハック的だがシンプルな」方法が導入されました。

また、ARMの特殊なシフトレジスタ演算子を認識するためのヘルパー関数も追加されています。

## 変更の背景

このコミットは、Go言語のアセンブラ `cmd/asm` の正確性と堅牢性を向上させるために行われました。

1.  **マクロ定義の曖昧さの解消**: `cmd/asm` は、アセンブリコード内でC言語のようなプリプロセッサディレクティブ（`#define` など）をサポートしています。しかし、Go標準ライブラリの `text/scanner` パッケージの挙動により、マクロ定義の際に意図しない解釈が生じていました。特に、`#define A(x)`（引数付きマクロ）と `#define A (x)`（引数なしで定義内容が括弧で始まるマクロ）の区別ができないという問題がありました。これは、`text/scanner` がトークン間の空白をスキップするため、字句解析器が `A` の直後に `(` が来るのか、それとも間に空白を挟んで `(` が来るのかを区別できなかったためです。この曖昧さは、アセンブリコードの意図しない挙動やコンパイルエラーを引き起こす可能性がありました。この修正は、アセンブラがより正確にマクロを解釈し、開発者が期待する通りのコード生成を保証するために不可欠でした。

2.  **ARMシフトレジスタ演算子のサポート**: ARMアーキテクチャは、レジスタの値をシフトする際に、そのシフト操作自体を命令の一部としてエンコードできる「シフトレジスタ演算子」という特徴的な機能を持っています。これは、他のアーキテクチャでは通常、シフト操作と算術演算を別々の命令として記述する必要があるのとは対照的です。`cmd/asm` がARMアセンブリを正確に解析し、GoプログラムからARMネイティブコードを生成するためには、これらの特殊な演算子を正しく認識し、処理できる必要があります。このヘルパー関数の追加は、ARMアーキテクチャのサポートを強化し、より効率的で正確なARMアセンブリコードの生成を可能にするためのものです。

これらの変更は、`cmd/asm` が多様なアセンブリ構文を正確に処理し、Go言語のクロスプラットフォーム対応をより堅牢にするための継続的な改善の一環として行われました。

## 前提知識の解説

このコミットの理解には、以下の概念に関する知識が役立ちます。

### 1. 字句解析器（Lexer/Scanner）

字句解析器は、コンパイラやインタプリタの最初の段階で、ソースコードを意味のある最小単位である「トークン」の並びに変換するプログラムです。例えば、`int x = 10;` というコードは、`int`（キーワード）、`x`（識別子）、`=`（演算子）、`10`（リテラル）、`;`（区切り文字）といったトークンに分割されます。

Go言語の標準ライブラリには `text/scanner` パッケージがあり、これはテキストをスキャンしてトークンを生成するための汎用的なツールを提供します。しかし、このスキャナはデフォルトでトークン間の空白文字をスキップする特性を持っています。これが今回のマクロ定義のバグの根本原因となりました。

### 2. Cプリプロセッサのマクロ（`#define`）

C言語のプリプロセッサは、コンパイルの前にソースコードを変換するツールです。`#define` ディレクティブは、テキスト置換のためのマクロを定義するために使用されます。マクロには大きく分けて2種類あります。

*   **オブジェクト形式マクロ（Object-like macro）**: 単純なテキスト置換を行います。
    例: `#define PI 3.14159`
*   **関数形式マクロ（Function-like macro）**: 引数を取り、関数呼び出しのように使用できます。
    例: `#define MAX(a, b) ((a) > (b) ? (a) : (b))`

今回の問題は、関数形式マクロの定義と、オブジェクト形式マクロの定義で括弧が使われる場合の構文上の曖昧さに関するものです。

*   `#define A(x)`: これは `A` が引数 `x` を取る関数形式マクロとして定義されます。`A` の直後に `(` が続きます。
*   `#define A (x)`: これは `A` が `(x)` というテキストに置換されるオブジェクト形式マクロとして定義されます。`A` と `(` の間に空白があります。

Cプリプロセッサはこれらを明確に区別しますが、`text/scanner` の空白スキップ特性により、`cmd/asm` の字句解析器はこれらを区別できませんでした。

### 3. ARMアーキテクチャとシフトレジスタ演算子

ARM（Advanced RISC Machine）は、モバイルデバイスや組み込みシステムで広く使用されているRISC（Reduced Instruction Set Computer）アーキテクチャです。ARMプロセッサは、その命令セットに特徴的な機能を持っています。

*   **シフトレジスタ演算子（Shifted Register Operators）**: ARMの多くのデータ処理命令（例: `ADD`, `SUB`, `AND`）は、2番目のオペランドに対して、命令実行前にシフト操作（論理左シフト `LSL`、論理右シフト `LSR`、算術右シフト `ASR`、ローテート右 `ROR` など）を適用する機能を持っています。これにより、例えば `ADD R0, R1, R2, LSL #2` のように、`R2` を2ビット左シフトした結果を `R1` に加算するといった操作を単一の命令で実行できます。これは、コードの密度を高め、パフォーマンスを向上させるのに役立ちます。

    例:
    *   `ADD R0, R1, R2, LSL #2` (R0 = R1 + (R2 << 2))
    *   `MOV R0, R1, ASR #3` (R0 = R1 >> 3, 符号拡張)

`cmd/asm` がARMアセンブリを正しく解析するためには、これらの特殊なシフト演算子をトークンとして認識し、その意味を理解する必要があります。

## 技術的詳細

### 1. マクロ定義のバグとその修正

**問題の根源**:
`cmd/asm` の字句解析器は、Goの `text/scanner` パッケージを利用してソースコードをトークン化しています。`text/scanner` は、デフォルトでトークン間の空白文字（スペース、タブなど）をスキップします。この挙動は通常は便利ですが、Cプリプロセッサのマクロ定義においては問題を引き起こしました。

Cプリプロセッサでは、`#define A(x)` と `#define A (x)` は明確に区別されます。
*   `#define A(x)`: `A` の直後に `(` が続くため、`A` は引数を取る関数形式マクロと解釈されます。
*   `#define A (x)`: `A` と `(` の間に空白があるため、`A` は `(x)` という文字列に置換されるオブジェクト形式マクロと解釈されます。

`text/scanner` が空白をスキップすると、字句解析器は `A` のトークンを読み取った後、次に `(` のトークンを読み取りますが、その間に空白があったかどうかを区別できませんでした。結果として、両方のケースで `A` の後に `(` が続くと判断し、常に引数付きマクロとして扱ってしまうバグがありました。

**修正方法**:
このコミットでは、この問題を解決するために、`text/scanner` が提供するトークンの「カラム番号（column number）」情報を利用しています。

修正は `src/cmd/asm/internal/lex/input.go` の `macroDefinition` 関数で行われました。
1.  `prevCol := in.Stack.Col()`: `A` のトークンを読み取る直前のカラム番号を `prevCol` に保存します。
2.  `tok := in.Stack.Next()`: 次のトークン（この場合は `(`）を読み取ります。
3.  `if tok == '(' && in.Stack.Col() == prevCol+1`: ここが修正の核心です。
    *   `tok == '('`: 読み取ったトークンが `(` であることを確認します。
    *   `in.Stack.Col() == prevCol+1`: 現在のカラム番号が、直前のトークン（`A`）の開始カラム番号の直後（つまり、`A` の文字数分進んだ位置）であるかをチェックします。`text/scanner` はトークンの「終わり」の位置を報告するため、`prevCol+1` は `A` の直後に `(` が続いていることを意味します（`A` が1文字の場合）。もし間に空白があれば、`in.Stack.Col()` は `prevCol+1` よりも大きな値になります。

このチェックにより、`#define A(x)` のように `A` の直後に `(` が続く場合と、`#define A (x)` のように間に空白を挟んで `(` が続く場合を正確に区別できるようになりました。コミットメッセージではこれを「Hacky but simple」と表現していますが、`text/scanner` の制約の中で効果的に問題を解決するアプローチです。

この修正に伴い、`src/cmd/asm/internal/lex/lex.go` の `TokenReader` インターフェース、`src/cmd/asm/internal/lex/stack.go` の `Stack` 構造体、および `src/cmd/asm/internal/lex/tokenizer.go` の `Tokenizer` 構造体に `Col()` メソッドが追加され、カラム番号を取得できるようになっています。

### 2. ARMシフトレジスタ演算子の認識ヘルパー

**目的**:
ARMアセンブリの特殊なシフトレジスタ演算子（`LSL`, `LSR`, `ASR`, `ROR` など）を字句解析器が正しく識別できるようにするためのヘルパー関数が追加されました。これにより、`cmd/asm` はARMアセンブリコードをより正確に解析し、Goコンパイラが生成するARMネイティブコードの品質を向上させることができます。

**実装**:
`src/cmd/asm/internal/lex/lex.go` に `IsRegisterShift` 関数が追加されました。

```go
// IsRegisterShift reports whether the token is one of the ARM register shift operators.
func IsRegisterShift(r ScanToken) bool {
	return ROT <= r && r <= LSH // Order looks backwards because these are negative.
}
```

この関数は、`ScanToken` 型のトークンを受け取り、それが定義済みのシフト演算子（`ROT` から `LSH` までの範囲）のいずれかであるかをチェックします。`ScanToken` は、字句解析器が生成するトークンの種類を表す列挙型です。コメントにある「Order looks backwards because these are negative.」は、これらのトークン定数が負の値で定義されており、その順序が通常の数値順とは逆になっていることを示唆しています。

このヘルパー関数は、字句解析器がアセンブリコードを解析する際に、特定のトークンがARMのシフト演算子であるかどうかを効率的に判断するために使用されます。これにより、アセンブラはこれらの演算子を含む命令を正しくパースし、後続の段階で適切な機械語に変換できるようになります。

## コアとなるコードの解説

### マクロ定義の修正 (`input.go`)

```go
func (in *Input) macroDefinition(name string) ([]string, []Token) {
	prevCol := in.Stack.Col() // (1) 直前のトークン（マクロ名）のカラム番号を記録
	tok := in.Stack.Next()    // (2) 次のトークン（通常は'('）を読み込む
	if tok == '\n' || tok == scanner.EOF {
		in.Error("no definition for macro:", name)
	}
	var args []string
	// The C preprocessor treats
	//	#define A(x)
	// and
	//	#define A (x)
	// distinctly: the first is a macro with arguments, the second without.
	// Distinguish these cases using the column number, since we don't
	// see the space itself. Note that text/scanner reports the position at the
	// end of the token. It's where you are now, and you just read this token.
	if tok == '(' && in.Stack.Col() == prevCol+1 { // (3) カラム番号をチェックして区別
		// Macro has arguments. Scan list of formals.
		acceptArg := true
		args = []string{} // Zero length but not nil.
		// ... (引数解析ロジック)
	}
	// ... (引数なしマクロのロジック)
}
```

1.  `prevCol := in.Stack.Col()`: マクロ名（例: `A`）のトークンを処理した直後の、現在の字句解析器のスタックにおけるカラム番号を取得し、`prevCol` に保存します。`text/scanner` はトークンの「終わり」の位置を報告するため、これはマクロ名の最後の文字の直後のカラム位置を示します。
2.  `tok := in.Stack.Next()`: 次のトークンを読み込みます。`#define A(x)` の場合は `(`, `#define A (x)` の場合も `(` が読み込まれます（間に空白があっても `text/scanner` がスキップするため）。
3.  `if tok == '(' && in.Stack.Col() == prevCol+1`: ここが肝心な部分です。
    *   `tok == '('`: 読み込んだトークンが確かに左括弧であることを確認します。
    *   `in.Stack.Col() == prevCol+1`: 現在の字句解析器のカラム番号が、`prevCol` の直後であるかをチェックします。
        *   もし `A` の直後に `(` が続いていた場合（`#define A(x)`）、`text/scanner` は `A` のトークンを処理した後、すぐに `(` のトークンを処理するため、`(` の開始位置は `A` の終了位置の直後になります。したがって、`in.Stack.Col()` は `prevCol+1` となります（`A` が1文字の場合）。
        *   もし `A` と `(` の間に空白があった場合（`#define A (x)`）、`text/scanner` は空白をスキップしますが、`(` のトークンが始まる位置は `A` の終了位置から数文字離れた場所になります。したがって、`in.Stack.Col()` は `prevCol+1` よりも大きな値になります。

この `prevCol+1` のチェックにより、字句解析器は `A(x)` と `A (x)` を正確に区別し、それぞれを引数付きマクロと引数なしマクロとして適切に処理できるようになりました。

### ARMシフトレジスタ演算子のヘルパー (`lex.go`)

```go
// IsRegisterShift reports whether the token is one of the ARM register shift operators.
func IsRegisterShift(r ScanToken) bool {
	return ROT <= r && r <= LSH // Order looks backwards because these are negative.
}
```

この関数は、`cmd/asm` の字句解析器がARMアセンブリコードを処理する際に、特定のトークンがARMのシフト演算子であるかどうかを判定するために使用されます。

*   `ScanToken`: `cmd/asm` の字句解析器が認識するトークンの種類を表す型です。
*   `ROT`, `LSH`: これらは `ScanToken` 型の定数で、それぞれ `ROR`（Rotate Right）と `LSL`（Logical Shift Left）に対応するトークン値を表しています。
*   `ROT <= r && r <= LSH`: この条件は、`r` が `ROT` から `LSH` までの範囲内の値であるかをチェックしています。コメントにあるように、これらの定数は負の値で定義されており、その順序が逆になっているため、このような範囲チェックになっています。この範囲内にあるトークンは、ARMのシフトレジスタ演算子として認識されます。

このヘルパー関数は、アセンブリ命令のパース中に呼び出され、オペランドがシフト演算子である場合に特別な処理を行うための分岐ロジックで使用されます。これにより、`cmd/asm` はARMの複雑な命令形式を正確に解釈し、適切な機械語を生成できるようになります。
