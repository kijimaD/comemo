# [インデックス 22885] ファイルの概要

このコミットは、GoランタイムのARMアーキテクチャにおける共有ライブラリとしての初期化フローを改善するものです。具体的には、`src/runtime/rt0_linux_arm.s`と`src/runtime/sys_linux_arm.s`の2つのアセンブリファイルが変更されています。

-   `src/runtime/rt0_linux_arm.s`: GoプログラムがARM Linux上で起動する際の初期エントリポイントを定義するファイルです。このコミットでは、共有ライブラリとしてロードされた場合の新しい初期化エントリポイントと、それに関連するスレッド作成ロジックが追加されています。
-   `src/runtime/sys_linux_arm.s`: LinuxシステムコールへのGoランタイムのラッパーを含むファイルです。このコミットでは、`clone`システムコールをGoランタイムから呼び出すための`runtime·clone0`関数の実装が追加されています。

## コミット

このコミットは、Goプログラムが共有ライブラリとしてビルドされ、ARMアーキテクチャ上で動作する際に、ランタイムの初期化を適切に行うための変更を導入します。AMD64アーキテクチャと同様に、共有ライブラリの初期化エントリポイントを利用して新しいOSスレッドを作成し、そのスレッド上で通常のGoランタイム初期化を実行します。これにより、メイン（ローダー）スレッドは即座に制御を返し、最初のCGO呼び出し時にランタイムの初期化が完了するのを待つようになります。この変更は、Raspberry PiおよびAndroidフォンで動作することが検証されています。

## 変更の背景

Goプログラムを共有ライブラリ（`.so`ファイルなど）としてビルドし、C言語などの他の言語で書かれたアプリケーションからロードして利用する場合、Goランタイムの初期化が課題となります。通常のGo実行可能ファイルの場合、OSがプログラムをロードすると、Goランタイムの初期化コード（`rt0`）が直接実行され、Goの実行環境がセットアップされます。しかし、共有ライブラリとしてロードされる場合、ライブラリの初期化は通常、メインアプリケーションのスレッドで行われます。

Goランタイムは、プロセス内に単一のインスタンスしか存在できないという制約があります。もし共有ライブラリがロードされた際にメインスレッドでGoランタイムの初期化を始めてしまうと、メインアプリケーションのGoランタイム（もし存在すれば）と衝突したり、初期化が完了するまでメインスレッドをブロックしてしまったりする可能性があります。特に、Goランタイムの初期化は、ガベージコレクション、スケジューラ、メモリ管理など、Goプログラムの動作に不可欠な多くのコンポーネントをセットアップするため、時間がかかる場合があります。

このコミットは、この問題を解決するために、AMD64アーキテクチャで既に採用されているアプローチをARMアーキテクチャにも適用します。具体的には、共有ライブラリがロードされた際に、ライブラリの初期化エントリポイントから新しいOSスレッドを生成し、その新しいスレッド上でGoランタイムの初期化を非同期的に実行します。これにより、メイン（ローダー）スレッドはすぐに制御を返し、アプリケーションの起動をブロックすることなく、Goランタイムの初期化がバックグラウンドで進められます。Goの機能が実際に必要となる最初のCGO呼び出し時に、ランタイムの初期化が完了していることを確認するメカニズムも導入されています。これにより、Goの共有ライブラリがよりスムーズに既存のC/C++アプリケーションに統合できるようになります。

## 前提知識の解説

### Goランタイムの初期化 (Go Runtime Initialization)

Goプログラムが実行される際、`main`関数が呼び出される前に、Goランタイムが自身を初期化するプロセスがあります。この初期化は、メモリ管理（ヒープの初期化）、ガベージコレクタのセットアップ、ゴルーチン（goroutine）スケジューラの起動、そしてGoの標準ライブラリの初期化など、Goプログラムが動作するために必要な基盤を構築します。このプロセスの最初の部分は、通常、`rt0`（runtime 0）と呼ばれるアセンブリコードで実装されており、OSからのエントリポイントとして機能します。`rt0`は、`argc`（引数の数）や`argv`（引数配列）などのコマンドライン引数を受け取り、Goランタイムのより高レベルな初期化関数（例: `runtime.rt0_go`）に制御を渡します。

### 共有ライブラリ (Shared Libraries / Dynamic Link Libraries)

共有ライブラリ（Linuxでは`.so`、Windowsでは`.dll`）は、複数のプログラムによって共有されるコードとデータを含むファイルです。これにより、ディスクスペースとメモリを節約し、プログラムのモジュール性を高めることができます。プログラムは実行時に`dlopen`（Linux）などのシステムコールを使用して共有ライブラリをロードし、その中の関数を呼び出すことができます。共有ライブラリには、ロード時に実行される初期化ルーチン（コンストラクタ）を持つことができ、このルーチンはライブラリがメモリにロードされた直後に自動的に呼び出されます。

### CGO

CGOは、GoプログラムがC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。GoとCの間の橋渡し役となり、既存のCライブラリをGoから利用したり、Goで書かれた機能をC/C++アプリケーションにエクスポートしたりすることを可能にします。CGOを使用すると、Goのビルドプロセス中にCコンパイラが呼び出され、GoとCのコードがリンクされます。

### ARMアーキテクチャ (ARM Architecture)

ARM（Advanced RISC Machine）は、モバイルデバイス、組み込みシステム、IoTデバイスなどで広く使用されているRISC（Reduced Instruction Set Computer）ベースのプロセッサアーキテクチャです。低消費電力と高性能を両立させる設計が特徴です。Goは、ARMを含む多くのアーキテクチャをサポートしており、クロスコンパイルによって様々なARMベースのデバイスでGoプログラムを実行できます。

### Goアセンブリ (Go Assembly)

Goは、独自の抽象化されたアセンブリ言語を使用しています。これは、特定のCPU命令セットに直接マッピングされるのではなく、Goコンパイラによって最終的にターゲットアーキテクチャのネイティブ命令に変換されます。Goアセンブリは、レジスタの命名規則や命令の構文が一般的なアセンブリ言語（例: AT&T構文やIntel構文）とは異なる場合があります。Goランタイムの低レベルな部分は、パフォーマンスやOSとの直接的なインタラクションのために、このGoアセンブリで書かれています。

### `clone`システムコール (Linux `clone` System Call)

Linuxの`clone`システムコールは、新しいプロセスまたはスレッドを作成するための強力なメカニズムです。従来の`fork`システムコールが親プロセスのほぼ完全なコピーを作成するのに対し、`clone`はよりきめ細かな制御を提供し、新しい実行コンテキストが親と何を共有するか（メモリ空間、ファイルディスクリプタ、シグナルハンドラなど）を指定できます。Goランタイムは、ゴルーチンを実装するための軽量なスレッド（M: マシン）を作成するために、この`clone`システムコールを内部的に利用しています。`CLONE_THREAD`などのフラグを使用することで、GoランタイムはOSレベルのスレッドを作成し、Goのスケジューラがその上でゴルーチンを実行します。

## 技術的詳細

このコミットの核心は、Goが共有ライブラリとしてロードされた際のGoランタイムの初期化フローを、ARMアーキテクチャ向けに再設計することにあります。

1.  **共有ライブラリのエントリポイント**:
    通常のGo実行可能ファイルは`_rt0_arm_linux`から起動しますが、共有ライブラリとしてロードされるGoコードは、`_rt0_arm_linux_lib`という新しいエントリポイントから初期化が開始されます。このエントリポイントは、共有ライブラリが`dlopen`などによってロードされた際に、OSによって呼び出されるライブラリの初期化ルーチンとして機能します。

2.  **レジスタの保存と引数の取得**:
    `_rt0_arm_linux_lib`の冒頭では、呼び出し元（メインアプリケーション）のコンテキストを保護するために、カリキュラセーブレジスタ（R4, R5, R6, R7, R8, R11）がスタックに保存されます。これは、ライブラリの初期化が完了した後に、メインアプリケーションが期待するレジスタの状態を維持するためです。また、`argc`と`argv`（コマンドライン引数）が、それぞれ`_rt0_arm_linux_lib_argc`と`_rt0_arm_linux_lib_argv`というグローバル変数に保存されます。これらは、後でGoランタイムの初期化ルーチンに渡されます。

3.  **新しいOSスレッドの作成**:
    Goランタイムの初期化は、メイン（ローダー）スレッドをブロックしないように、新しいOSスレッドで実行されます。
    -   **CGOが利用可能な場合**: `_cgo_sys_thread_create`関数が利用されます。これはCGOランタイムが提供するスレッド作成関数で、Goランタイムの初期化関数`_rt0_arm_linux_lib_go`を新しいスレッドで実行するように指示します。
    -   **CGOが利用できない場合**: `runtime·newosproc0`が直接呼び出されます。これはGoランタイム内部のスレッド作成関数で、指定されたスタックサイズ（8MB）と関数ポインタ（`_rt0_arm_linux_lib_go`）で新しいOSスレッドを生成します。

4.  **メインスレッドの即時リターン**:
    新しいOSスレッドが正常に作成された後、`_rt0_arm_linux_lib`は保存しておいたレジスタを復元し、即座に呼び出し元（メインアプリケーション）に制御を返します。これにより、Goランタイムの初期化がバックグラウンドで進行している間も、メインアプリケーションはブロックされずに実行を継続できます。

5.  **CGO呼び出し時の初期化完了待ち**:
    コミットメッセージには「at the first CGO invocation, we wait for the runtime initialization to complete」とあります。これは、Goの共有ライブラリ内の関数がCGOを介して初めて呼び出される際に、Goランタイムの初期化がまだ完了していない場合は、その完了を待機するメカニズムがGoランタイム内部に存在することを示唆しています。これにより、Goの機能が実際に利用される時点では、ランタイムが完全にセットアップされていることが保証されます。

6.  **`runtime·clone0`の実装**:
    `src/runtime/sys_linux_arm.s`では、これまで未実装だった`runtime·clone0`関数が実装されています。この関数は、Goランタイムが新しいOSスレッドを作成する際に内部的に呼び出す、Linuxの`clone`システムコールへのラッパーです。
    -   `flags`と`stack`、`fn`（新しいスレッドで実行する関数）、`fnarg`（その関数への引数）を引数として受け取ります。
    -   新しいスレッドのスタックポインタを調整し、そのスタック上に`fn`と`fnarg`を保存します。
    -   `SYS_clone`システムコールを呼び出します。`clone`システムコールは、親プロセスでは新しい子プロセスのPIDを返し、子プロセスでは0を返します。
    -   親プロセスでは、`clone`の戻り値（子スレッドのPID）を返します。
    -   子プロセスでは、スタックから`fn`と`fnarg`を読み出し、`fn`を実行します。`fn`の実行が完了すると、`runtime·exit1`を呼び出してスレッドを終了します。

この一連の変更により、Goの共有ライブラリがARM環境でより堅牢かつ効率的に動作し、既存のC/C++アプリケーションとの統合が容易になります。

## コアとなるコードの解説

### `src/runtime/rt0_linux_arm.s` の変更点

```assembly
+TEXT _rt0_arm_linux_lib(SB),NOSPLIT,$40
+	// Preserve callee-save registers.  Raspberry Pi's dlopen(), for example,
+	// actually cares that R11 is preserved.
+	MOVW	R4, 16(R13)
+	MOVW	R5, 20(R13)
+	MOVW	R6, 24(R13)
+	MOVW	R7, 28(R13)
+	MOVW	R8, 32(R13)
+	MOVW	R11, 36(R13)
+
+	// Save argc/argv.
+	MOVW	R0, _rt0_arm_linux_lib_argc<>(SB)
+	MOVW	R1, _rt0_arm_linux_lib_argv<>(SB)
+
+	// Create a new thread to do the runtime initialization.
+	MOVW	_cgo_sys_thread_create(SB), R2
+	CMP	$0, R2
+	BEQ	nocgo
+	MOVW	$_rt0_arm_linux_lib_go<>(SB), R0
+	MOVW	$0, R1
+	BL	(R2)
+	B	rr
+nocgo:
+	MOVW	$0x800000, R0                     // stacksize = 8192KB
+	MOVW	$_rt0_arm_linux_lib_go<>(SB), R1  // fn
+	MOVW	$0, R2                            // fnarg
+	MOVW	R0, 4(R13)
+	MOVW	R1, 8(R13)
+	MOVW	R2, 12(R13)
+	BL	runtime·newosproc0(SB)
+rr:
+	// Restore callee-save registers and return.
+	MOVW	16(R13), R4
+	MOVW	20(R13), R5
+	MOVW	24(R13), R6
+	MOVW	28(R13), R7
+	MOVW	32(R13), R8
+	MOVW	36(R13), R11
+	RET
+
+TEXT _rt0_arm_linux_lib_go<>(SB),NOSPLIT,$8
+	MOVW	_rt0_arm_linux_lib_argc<>(SB), R0
+	MOVW	_rt0_arm_linux_lib_argv<>(SB), R1
+	MOVW	R0, 0(R13)
+	MOVW	R1, 4(R13)
+	B	runtime·rt0_go(SB)
+
+DATA _rt0_arm_linux_lib_argc<>(SB)/4,$0
+GLOBL _rt0_arm_linux_lib_argc<>(SB),NOPTR,$4
+DATA _rt0_arm_linux_lib_argv<>(SB)/4,$0
+GLOBL _rt0_arm_linux_lib_argv<>(SB),NOPTR,$4
```

-   `_rt0_arm_linux_lib`: 共有ライブラリがロードされた際のエントリポイントです。
    -   `MOVW R4, 16(R13)` など: 呼び出し元（メインアプリケーション）のカリキュラセーブレジスタ（R4, R5, R6, R7, R8, R11）をスタックポインタR13からのオフセット位置に保存しています。これは、Goランタイムの初期化が完了した後に、これらのレジスタが元の値を保持していることを保証するためです。
    -   `MOVW R0, _rt0_arm_linux_lib_argc<>(SB)`: `R0`レジスタに格納されている`argc`（引数の数）を、グローバル変数`_rt0_arm_linux_lib_argc`に保存します。
    -   `MOVW R1, _rt0_arm_linux_lib_argv<>(SB)`: `R1`レジスタに格納されている`argv`（引数配列のポインタ）を、グローバル変数`_rt0_arm_linux_lib_argv`に保存します。
    -   `MOVW _cgo_sys_thread_create(SB), R2`: `_cgo_sys_thread_create`関数のアドレスを`R2`レジスタにロードします。この関数はCGOランタイムが提供するスレッド作成関数です。
    -   `CMP $0, R2` / `BEQ nocgo`: `_cgo_sys_thread_create`が利用可能かどうか（アドレスが0でないか）をチェックします。もし利用できない場合（`R2`が0の場合）、`nocgo`ラベルに分岐します。
    -   `MOVW $_rt0_arm_linux_lib_go<>(SB), R0` / `MOVW $0, R1` / `BL (R2)`: `_cgo_sys_thread_create`が利用可能な場合、新しいスレッドで実行する関数として`_rt0_arm_linux_lib_go`のアドレスを`R0`に、引数として`0`を`R1`に設定し、`_cgo_sys_thread_create`を呼び出します。`BL`は関数呼び出し（Branch with Link）です。
    -   `nocgo:`: `_cgo_sys_thread_create`が利用できない場合の処理です。
        -   `MOVW $0x800000, R0`: スタックサイズとして8MB（8192KB）を`R0`に設定します。
        -   `MOVW $_rt0_arm_linux_lib_go<>(SB), R1`: 新しいスレッドで実行する関数として`_rt0_arm_linux_lib_go`のアドレスを`R1`に設定します。
        -   `MOVW $0, R2`: 関数への引数として`0`を`R2`に設定します。
        -   `MOVW R0, 4(R13)` / `MOVW R1, 8(R13)` / `MOVW R2, 12(R13)`: これらの値をスタックにプッシュします。これらは`runtime·newosproc0`への引数となります。
        -   `BL runtime·newosproc0(SB)`: Goランタイム内部のスレッド作成関数`runtime·newosproc0`を呼び出します。
    -   `rr:`: スレッド作成後の共通の処理です。
        -   `MOVW 16(R13), R4` など: 冒頭で保存したカリキュラセーブレジスタをスタックから復元します。
        -   `RET`: 呼び出し元（メインアプリケーション）に制御を返します。
-   `_rt0_arm_linux_lib_go`: 新しいOSスレッドで実行される関数です。
    -   `MOVW _rt0_arm_linux_lib_argc<>(SB), R0`: 保存しておいた`argc`を`R0`にロードします。
    -   `MOVW _rt0_arm_linux_lib_argv<>(SB), R1`: 保存しておいた`argv`を`R1`にロードします。
    -   `MOVW R0, 0(R13)` / `MOVW R1, 4(R13)`: `argc`と`argv`をスタックにプッシュします。これらは`runtime·rt0_go`への引数となります。
    -   `B runtime·rt0_go(SB)`: Goランタイムの主要な初期化関数である`runtime·rt0_go`に分岐します。これにより、Goランタイムの残りの初期化プロセスが新しいスレッドで実行されます。
-   `_rt0_arm_linux_lib_argc<>(SB)` / `_rt0_arm_linux_lib_argv<>(SB)`: `argc`と`argv`を一時的に保存するためのグローバル変数です。

### `src/runtime/sys_linux_arm.s` の変更点

```assembly
+	MOVW	flags+0(FP), R0
+	MOVW	stack+4(FP), R1
+	// Update child's future stack and save fn and fnarg on it.
+	MOVW	$-8(R1), R1
+	MOVW	fn+8(FP), R6
+	MOVW	R6, 0(R1)

```

-   `runtime·clone0`: Linuxの`clone`システムコールを呼び出すためのGoアセンブリラッパーです。
    -   `MOVW flags+0(FP), R0` / `MOVW stack+4(FP), R1`: フレームポインタ`FP`からのオフセットで、引数`flags`を`R0`に、`stack`を`R1`にロードします。
    -   `MOVW $-8(R1), R1`: 子スレッドのスタックポインタを調整します。これは、`fn`と`fnarg`をスタックに保存するためのスペースを確保するためです。
    -   `MOVW fn+8(FP), R6` / `MOVW R6, 0(R1)`: 引数`fn`（新しいスレッドで実行する関数）を`R6`にロードし、それを子スレッドの新しいスタックの先頭に保存します。
    -   `MOVW fnarg+12(FP), R6` / `MOVW R6, 4(R1)`: 引数`fnarg`（関数への引数）を`R6`にロードし、それを子スレッドの新しいスタックの`fn`の直後に保存します。
    -   `MOVW $0, R2` / `MOVW $0, R3` / `MOVW $0, R4` / `MOVW $0, R5`: `clone`システムコールに渡す追加の引数（`parent_tidptr`, `tls`, `child_tidptr`など）を0に設定します。
    -   `MOVW $SYS_clone, R7`: `clone`システムコールの番号を`R7`に設定します。
    -   `SWI $0`: ソフトウェア割り込み（Software Interrupt）命令を実行し、`clone`システムコールを呼び出します。
    -   `CMP $0, R0` / `BEQ 3(PC)`: `clone`システムコールの戻り値（`R0`）をチェックします。親プロセスでは子スレッドのPIDが返され、子プロセスでは0が返されます。`R0`が0の場合（子プロセスの場合）、`3(PC)`（現在のプログラムカウンタから3バイト先）に分岐します。
    -   `MOVW R0, ret+16(FP)` / `RET`: 親プロセスの場合、`R0`（子スレッドのPID）を戻り値としてスタックに保存し、関数からリターンします。
    -   `// In child.`: 子プロセス側のコードです。
        -   `MOVW 0(R13), R6`: 子スレッドのスタックから`fn`（実行する関数）を`R6`にロードします。
        -   `MOVW 4(R13), R0`: 子スレッドのスタックから`fnarg`（関数への引数）を`R0`にロードします。
        -   `MOVW $8(R13), R13`: スタックポインタ`R13`を調整し、`fn`と`fnarg`が占めていたスペースを解放します。
        -   `BL (R6)`: `R6`に格納されている関数（`fn`）を呼び出します。
        -   `MOVW $0, R0` / `MOVW R0, 4(R13)` / `BL runtime·exit1(SB)`: `fn`の実行が完了した後、`runtime·exit1`を呼び出してスレッドを終了します。
    -   `// It shouldn't return`: この部分は、`runtime·exit1`がリターンしないことを示すデバッグ用のコードです。
