## 元コミット内容

このコミットは、GoランタイムがARM64アーキテクチャ上でページアライメントのために64KBのページサイズを使用するように変更します。これにより、GoランタイムがOSからメモリを要求する際や、内部でメモリを管理する際の粒度が調整されます。

主な変更点は以下の通りです。

1.  `src/runtime/arch1_arm64.go` において、`_PhysPageSize` 定数をARM64アーキテクチャ向けに`65536` (64KB) に設定。
2.  `src/runtime/debug/garbage_test.go` において、`TestFreeOSMemory` テストのスキップ条件を更新。ARM64アーキテクチャ全体で、物理ページサイズが論理ページサイズよりも大きいシステムでのscavenger（メモリ解放機構）の動作に関する既知の問題（issue 9993）のため、このテストを一時的にスキップするように変更。

## 変更の背景

この変更の背景には、ARM64アーキテクチャにおけるメモリページサイズの特性があります。多くのシステムでは4KBのページサイズが一般的ですが、ARM64アーキテクチャでは64KBのページサイズが採用されることがあります。Goランタイムは、OSからメモリを確保し、それを管理する際に、物理ページサイズを考慮する必要があります。

以前のGoランタイムでは、ARM64環境での`_PhysPageSize`が、Darwin（macOS）の場合のみ16KB、それ以外では4KBと定義されていました。しかし、ARM64環境、特にLinuxなどでは64KBの物理ページサイズが一般的であり、Goランタイムがこれを正しく認識し、適切にメモリをアラインメントする必要がありました。

この不一致は、Goのガベージコレクタ（GC）のscavenger（未使用メモリをOSに返却するメカニズム）が、物理ページサイズと論理ページサイズの違いに起因する問題（issue 9993）を抱えていることと関連しています。特に、物理ページサイズが論理ページサイズよりも大きいシステムでは、scavengerが正しく機能しない可能性がありました。

このコミットは、ARM64環境でのメモリ管理の正確性を向上させ、将来的なscavengerの改善に向けた基盤を築くことを目的としています。

## 前提知識の解説

### 1. メモリページとページサイズ

コンピュータのメモリは、OSによって「ページ」と呼ばれる固定サイズのブロックに分割されて管理されます。CPUはメモリにアクセスする際に、このページ単位でアドレス変換を行います。ページサイズは、OSやハードウェアアーキテクチャによって異なり、一般的には4KB、8KB、16KB、64KBなどが使われます。

*   **論理ページサイズ (Logical Page Size)**: OSがアプリケーションに提供する仮想メモリのページサイズ。
*   **物理ページサイズ (Physical Page Size)**: 物理メモリのページサイズ。ハードウェアによって決定されます。

これらが異なる場合、特に物理ページサイズが論理ページサイズより大きい場合、メモリ管理に複雑さをもたらすことがあります。

### 2. Goランタイムとメモリ管理

Goランタイムは、独自のメモリマネージャとガベージコレクタ（GC）を持っています。Goプログラムがメモリを要求すると、ランタイムはOSから大きなメモリブロック（ヒープ）を確保し、それを細かく分割してGoオブジェクトに割り当てます。

*   **ガベージコレクタ (GC)**: 不要になったメモリを自動的に解放し、再利用可能にする仕組み。
*   **Scavenger**: GoのGCの一部で、ヒープ上の未使用のメモリページをOSに返却する役割を担います。これにより、OSはこれらのページを他のプロセスに割り当てたり、物理メモリを解放したりできます。

### 3. ARM64アーキテクチャ

ARM64（またはAArch64）は、ARMv8-A命令セットアーキテクチャに基づく64ビットのプロセッサアーキテクチャです。スマートフォン、タブレット、サーバー、組み込みシステムなど、幅広いデバイスで利用されています。ARM64プロセッサは、特定のOS構成において64KBの物理ページサイズを使用することがあります。

### 4. `goos_darwin` と `goos_linux`

Goのビルドシステムでは、`goos`という環境変数でターゲットOSを指定します。`goos_darwin`や`goos_linux`は、それぞれmacOSとLinuxを指すビルドタグのようなもので、コンパイル時に特定のOS向けのコードを条件付きで含めるために使用されます。

## 技術的詳細

このコミットの核心は、GoランタイムがARM64アーキテクチャ上でメモリを管理する際の物理ページサイズの認識を修正することです。

以前の`src/runtime/arch1_arm64.go`では、`_PhysPageSize`の定義が以下のようになっていました。

```go
_PhysPageSize  = 4096*(1-goos_darwin) + 16384*goos_darwin
```

これは、`goos_darwin`（macOS）の場合には`16384` (16KB) を、それ以外の場合（主にLinuxなど）には`4096` (4KB) を物理ページサイズとして設定していました。しかし、実際のARM64環境、特にLinuxでは64KBの物理ページサイズが一般的であるため、この定義は不正確でした。

このコミットでは、`_PhysPageSize`を単純に`65536` (64KB) に変更することで、ARM64アーキテクチャ全体で64KBのページサイズを使用するように統一しました。

```go
_PhysPageSize  = 65536
```

この変更は、GoランタイムがOSからメモリを要求する際や、内部でメモリをアラインメントする際に、より正確なページサイズ情報を使用することを意味します。これにより、メモリの断片化の軽減や、OSとのより効率的なメモリ連携が期待されます。

また、`src/runtime/debug/garbage_test.go`の変更は、この物理ページサイズの変更が既存のscavengerの既知の問題（issue 9993）に影響を与えることを示しています。`TestFreeOSMemory`は、GoランタイムがOSにメモリを返却するscavengerの機能をテストするものです。物理ページサイズが論理ページサイズよりも大きいシステムでは、scavengerが正しく動作しないという問題が以前から存在していました。

以前のスキップ条件は以下の通りでした。

```go

```

この条件では、macOS上のARM64でのみscavengerテストがスキップされていました。しかし、`_PhysPageSize`がARM64全体で64KBに設定されたことで、他のARM64環境でも同様の問題が発生する可能性が高まりました。そのため、スキップ条件は以下のように変更されました。

```go
if runtime.GOARCH == "arm64" || runtime.GOARCH == "ppc64" || runtime.GOARCH == "ppc64le" || runtime.GOOS == "nacl" {
```

これにより、すべてのARM64アーキテクチャで`TestFreeOSMemory`がスキップされるようになりました。これは、scavengerの問題がARM64アーキテクチャの一般的な特性に関連していることを示唆しており、この問題が解決されるまでテストを無効化することで、CI/CDパイプラインの安定性を保つための措置です。

### `src/runtime/arch1_arm64.go` の変更

このファイルは、ARM64アーキテクチャに特化したランタイム定数を定義しています。
`_PhysPageSize`は、Goランタイムが認識する物理メモリページのサイズをバイト単位で表す定数です。
変更前は、`goos_darwin`（macOS）の場合に16KB、それ以外の場合に4KBという条件付きの定義でした。これは、macOS上のARM64が16KBのページサイズを使用する一方で、他のARM64システム（例えばLinux）が4KBのページサイズを使用するという仮定に基づいていた可能性があります。

### `src/runtime/debug/garbage_test.go` の変更

このファイルには、Goランタイムのデバッグ機能、特にガベージコレクションに関連するテストが含まれています。

変更前のスキップ条件は、`ppc64`、`ppc64le`、`nacl`、そして`darwin`上の`arm64`アーキテクチャでこのテストをスキップしていました。これは、これらの環境でscavengerが正しく動作しない既知の問題（issue 9993）があったためです。

この変更は、scavengerの問題がARM64アーキテクチャの特定のメモリページサイズ設定と密接に関連していることを示しており、問題が解決されるまでの間、テストの失敗を防ぐための実用的な措置です。

## コアとなるコードの解説

### `src/runtime/arch1_arm64.go` の変更

このファイルは、ARM64アーキテクチャに特化したランタイム定数を定義しています。
`_PhysPageSize`は、Goランタイムが認識する物理メモリページのサイズをバイト単位で表す定数です。
変更前は、`goos_darwin`（macOS）の場合に16KB、それ以外の場合に4KBという条件付きの定義でした。これは、macOS上のARM64が16KBのページサイズを使用する一方で、他のARM64システム（例えばLinux）が4KBのページサイズを使用するという仮定に基づいていた可能性があります。
しかし、このコミットでは、`_PhysPageSize`を`65536`（64KB）に固定しています。これは、多くのARM64システム、特にサーバー環境などで64KBの物理ページサイズが採用されていることを反映したものです。Goランタイムがこの正確な物理ページサイズを認識することで、メモリのアラインメントやOSとのメモリ連携がより最適化されます。

### `src/runtime/debug/garbage_test.go` の変更

このファイルには、Goランタイムのデバッグ機能、特にガベージコレクションに関連するテストが含まれています。
`TestFreeOSMemory`関数は、GoランタイムのscavengerがOSに未使用メモリを正しく返却できるかを検証するテストです。
変更前のスキップ条件は、`ppc64`、`ppc64le`、`nacl`、そして`darwin`上の`arm64`アーキテクチャでこのテストをスキップしていました。これは、これらの環境でscavengerが正しく動作しない既知の問題（issue 9993）があったためです。
今回のコミットで`_PhysPageSize`がARM64全体で64KBに統一されたことにより、`darwin`上の`arm64`だけでなく、他の`arm64`環境でも同様の問題が発生する可能性が高まりました。そのため、スキップ条件から`(runtime.GOOS == "darwin" && runtime.GOARCH == "arm64")`を削除し、代わりに`runtime.GOARCH == "arm64"`を直接追加することで、すべてのARM64アーキテクチャでこのテストをスキップするように変更されました。
この変更は、scavengerの問題がARM64アーキテクチャの特定のメモリページサイズ設定と密接に関連していることを示しており、問題が解決されるまでの間、テストの失敗を防ぐための実用的な措置です。
