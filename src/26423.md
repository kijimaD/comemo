## 変更の背景

このコミットの背景には、Go言語の標準ライブラリである `math/big` パッケージの進化と、それをコンパイラ (`cmd/compile`) が内部的に利用しているという事実があります。

1.  **`math/big` パッケージの更新**: `math/big` パッケージは、任意精度の整数および浮動小数点数演算を提供する重要なライブラリです。時間とともに、このパッケージには機能追加、パフォーマンス改善、そしてバグ修正が行われます。特に、暗号化や大規模な数値計算で用いられるモンゴメリ乗算のような複雑なアルゴリズムには、細心の注意と継続的な改善が必要です。
2.  **Vendoringの利用**: Go言語のプロジェクトでは、外部依存関係をプロジェクトの `vendor/` ディレクトリにコピーして管理する「vendoring」という手法が用いられることがあります。これにより、ビルドの再現性が向上し、外部ライブラリの予期せぬ変更による影響を防ぐことができます。`cmd/compile` も `math/big` の特定のバージョンをベンダーコピーとして保持しており、このコミットはそのベンダーコピーを最新の状態に同期させるものです。
3.  **モンゴメリ乗算のバグ修正とテストの強化**: コミットメッセージに明記されているように、この更新にはモンゴメリ乗算に関するバグ修正とテストの強化が含まれています。モンゴメリ乗算は、モジュラー冪乗（`x^y mod m`）などの計算を効率的に行うための手法であり、その正確性は非常に重要です。
    *   特に、`issue 13907` (`math/big: ExpNNMontgomery can return result >= m`) は、モンゴメリ冪乗の計算結果がモジュラス `m` 以上になる可能性があるというバグを指摘しており、このコミットでその修正が取り込まれています。

4.  **一貫性の維持**: コンパイラが使用する `math/big` のバージョンと、標準ライブラリとして提供される `math/big` のバージョンとの間に一貫性を持たせることも、この更新の重要な動機の一つです。これにより、将来的な互換性の問題や予期せぬ動作を防ぐことができます。

## 前提知識の解説

### Go言語の `math/big` パッケージ

`math/big` パッケージは、Go言語で任意精度の数値演算を行うための標準ライブラリです。通常の `int` や `float64` 型では扱えない非常に大きな整数や、高い精度が要求される浮動小数点数、有理数を扱うことができます。

*   **`Int`**: 任意精度の整数型。
*   **`Float`**: 任意精度の浮動小数点数型。
*   **`Rat`**: 任意精度の有理数型。
*   **`nat`**: `math/big` パッケージの内部で使われる型で、非負の整数（自然数）の配列として大きな数を表現します。ワード（`Word`型、通常は `uint` または `uint64`）の配列として数値を格納し、各ワードが数値の一部を構成します。

### Vendoring

Vendoringは、プロジェクトの依存関係をプロジェクト自身のソースコードリポジトリ内にコピーして管理する手法です。

*   **利点**:
    *   **再現性**: 特定のバージョンの依存関係がプロジェクト内に固定されるため、異なる環境や将来のビルドでも同じ依存関係が使用されることが保証されます。
    *   **オフラインビルド**: 外部ネットワークにアクセスできない環境でもビルドが可能です。
    *   **依存関係の安定性**: 外部ライブラリの予期せぬ変更や削除による影響を受けません。
*   **欠点**:
    *   リポジトリサイズが増加する。
    *   セキュリティアップデートなどの追跡が手動になる場合がある。

このコミットでは、`cmd/compile` が `math/big` のベンダーコピーを使用しており、それを `sh vendor.bash` スクリプトで更新しています。

### モンゴメリ乗算 (Montgomery Multiplication)

モンゴメリ乗算は、大きな数の剰余演算（モジュラー演算）を効率的に行うためのアルゴリズムです。特に、モジュラー冪乗（`a^b mod m`）のような計算で頻繁に利用されます。

*   **目的**: 剰余演算は除算を伴うため計算コストが高いですが、モンゴメリ乗算は除算をビットシフトと加算・乗算に置き換えることで高速化を図ります。
*   **モンゴメリ表現**: 数値を直接扱うのではなく、「モンゴメリ表現」と呼ばれる特殊な形式に変換してから計算を行います。計算後、結果を元の表現に戻します。
*   **`montgomery` 関数**: `math/big` パッケージの `nat` 型には、モンゴメリ乗算を実行する `montgomery` 関数があります。これは、モンゴメリ表現された2つの数 `x` と `y` を乗算し、その結果をモンゴメリ表現で返します。
*   **`expNNMontgomery` 関数**: `nat` 型の冪剰余 `x^y mod m` をモンゴメリ乗算を用いて計算する関数です。

### ユークリッド除算と剰余 (Euclidean Division and Modulus)

数学における除算と剰余の定義にはいくつかありますが、ユークリッド除算は特に重要です。

*   **定義**: 整数 `x` と非ゼロ整数 `y` が与えられたとき、`x = qy + m` となるような一意の整数 `q` (商) と `m` (剰余) が存在し、`0 <= m < |y|` を満たします。
*   **Go言語の `Mod` 関数**: Go言語の `math/big.Int.Mod` 関数は、このユークリッド除算の定義に従って剰余を計算します。コミットでは、この関数のコメントが `0 <= m < |q|` から `0 <= m < |y|` に修正されており、これはユークリッド除算の標準的な定義に合致させるためのものです。

## コアとなるコードの解説

### `montgomery` 関数の変更

`montgomery` 関数は、モンゴメリ乗算の核となる部分であり、2つのモンゴメリ表現された数 `x` と `y` を乗算し、結果をモンゴメリ表現で返します。

*   **キャリー変数のリネームとスコープの明確化**: 以前は `c1, c2, c3` というキャリー変数が関数スコープで宣言されていましたが、`c1` が `c` にリネームされ、`c2` と `c3` はループ内で `:=` を使って宣言されるようになりました。これにより、各ループイテレーションで `c2` と `c3` が新しい値で初期化されることが保証され、以前のイテレーションからの値が誤って持ち越される可能性が排除されます。これは、特に複雑な多倍長演算において、キャリーの正確な伝播を保証するために重要です。
*   **キャリー計算の修正**: `cx := c1 + c2` が `cx := c + c2` に変更されたのは、変数名のリネームに伴う直接的な修正です。この変更は、モンゴメリ乗算のアルゴリズムにおけるキャリーの加算ロジックの正確性を維持するためのものです。

### `expNNMontgomery` 関数の変更

`expNNMontgomery` 関数は、モンゴメリ乗算を利用して `x^y mod m` を計算します。

*   **入力 `x` の正規化ロジックの改善**:
    *   モンゴメリ乗算を行う前に、基数 `x` がモジュラス `m` と同じワード長になるように調整する必要があります。
    *   以前のコードは、`x` の長さが `m` のワード長 (`numWords`) より大きい場合や小さい場合に、それぞれ異なる方法で `x` を調整していました。
    *   新しいコードでは、まず `x` が `m` より大きい場合は `x = x mod m` を計算し、その結果の `x` が `numWords` より短い場合はゼロパディングして `numWords` の長さに揃える、というより統一されたロジックになりました。
    *   この変更により、`x` が常に `m` のワード長と同じか、それ以下の長さで、かつ `m` 未満の値としてモンゴメリ乗算の処理に渡されることが保証され、計算の正確性と安定性が向上します。

*   **最終的な剰余の追加削減 (One last reduction)**:
    *   これは `golang.org/issue/13907` で報告されたバグへの直接的な修正です。モンゴメリ乗算の性質上、計算結果がモジュラス `m` 以上になることが稀に発生する可能性があります。
    *   このバグは、結果が `m` 以上であるにもかかわらず、それが最終的な結果として返されてしまうというものでした。
    *   追加されたコードブロックは、モンゴメリ乗算の最終結果 `zz` が `m` 以上であるかどうかを `zz.cmp(m) >= 0` でチェックします。
    *   もし `zz >= m` であれば、`zz = zz - m` を実行して `m` を減算します。
    *   さらに、念のため（`m` が非常に特殊な値である場合など）、減算後も `zz >= m` である可能性を考慮して、再度 `zz.cmp(m) >= 0` をチェックし、その場合は `_, zz = nat(nil).div(nil, zz, m)` を実行して最終的な剰余を計算します。ただし、コメントにもあるように、通常は最初の減算で十分であり、`div` が実行されることは稀であると想定されています。
    *   この「One last reduction」により、`expNNMontgomery` 関数が常に `0 <= result < m` の範囲の正しい剰余を返すことが保証され、モンゴメリ乗算の正確性が向上します。

これらの変更は、Go言語の `math/big` パッケージが提供する任意精度演算、特に暗号化などで重要なモンゴメリ乗算の信頼性と正確性を高める上で不可欠なものです。
