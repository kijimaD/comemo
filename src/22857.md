# [インデックス 22857] ファイルの概要

このコミットは、GoランタイムがDarwin (macOS/iOS) のARMアーキテクチャ上で、C言語アーカイブ（`-buildmode=c-archive`）またはC言語共有ライブラリ（`-buildmode=c-shared`）としてビルドされた際に、外部からGoランタイムの初期化を行うための新しいエントリポイントを追加するものです。これにより、Goのコードを既存のC/Objective-Cプロジェクト（特にiOSアプリケーション）に組み込むことが可能になります。

## 変更の背景

Go言語は、その強力な並行処理モデルと効率性から、様々なアプリケーション開発に利用されています。しかし、既存のC/Objective-Cベースのプロジェクト、特にiOSアプリケーションにGoの機能を組み込む場合、Goランタイムの初期化とC言語との連携が課題となります。

従来のGoプログラムは、`main`関数から実行が開始され、Goランタイムが自動的に初期化されます。しかし、GoコードをライブラリとしてC/Objective-Cアプリケーションに組み込む場合、Goの`main`関数は呼び出されず、Goランタイムの初期化が適切に行われません。

このコミットは、Goのビルドモードである`-buildmode=c-archive`（静的ライブラリ）や`-buildmode=c-shared`（共有ライブラリ）を使用してGoコードをビルドした際に、外部のC/Objective-CコードからGoランタイムを安全に初期化するための特定のエントリポイントを提供することを目的としています。これにより、Goで書かれたロジックをiOSアプリなどの既存のネイティブアプリケーションにシームレスに統合できるようになります。コミットメッセージにあるように、Xcodeプロジェクトに組み込んでiOSアプリからGo関数を呼び出すテストが行われたことが、この変更の具体的なユースケースを示しています。

## 前提知識の解説

このコミットの理解には、以下の概念が不可欠です。

1.  **Goのビルドモード (`-buildmode`)**:
    *   **`-buildmode=c-archive`**: GoのパッケージをC言語の静的ライブラリ（`.a`ファイル）としてビルドします。このライブラリは、C/C++/Objective-Cのプロジェクトにリンクされ、Goの関数をCの関数として呼び出すことができます。Goランタイムもこのアーカイブに含まれます。
    *   **`-buildmode=c-shared`**: GoのパッケージをC言語の共有ライブラリ（`.so`やmacOS/iOSでは`.dylib`）としてビルドします。これは動的にロードされ、Goの関数をCの関数として呼び出すことができます。
    *   これらのビルドモードは、Goのコードを既存の非Goアプリケーションに組み込むための主要な手段です。

2.  **Goランタイムの初期化 (`rt0`)**:
    *   Goプログラムが実行される際、OSから最初に制御を受け取るのは、Goランタイムの初期化コードです。これは通常、アセンブリ言語で書かれた`rt0`（runtime zero）ファイルに定義されています。
    *   `rt0`の役割は、スタックの設定、レジスタの初期化、Goスケジューラの起動、そして最終的にGoの`main`関数（またはライブラリモードの場合はGoランタイムの初期化ルーチン）へのジャンプを行うことです。
    *   通常の実行可能ファイルの場合、`_rt0_arm_darwin`のようなエントリポイントが使用されますが、ライブラリとして組み込まれる場合は、異なる初期化パスが必要になります。

3.  **ARMアーキテクチャとレジスタ**:
    *   このコミットは`darwin/arm`、つまりiOSデバイスなどで使用されるARMプロセッサを対象としています。
    *   **レジスタ**: ARMプロセッサには汎用レジスタ（R0-R15）があります。
        *   `R0`, `R1`: 関数呼び出しの際に引数を渡すためによく使われます。
        *   `R4`: このコードでは、ジャンプ先のアドレスを保持するために使用されています。
        *   `R13` (SP: Stack Pointer): スタックの現在位置を指すレジスタです。スタックにデータをプッシュしたり、スタックからデータをポップしたりする際に使用されます。
    *   **`MOVW`**: ARMアセンブリ命令で、ワード（4バイト）をレジスタまたはメモリに移動します。
    *   **`B`**: 無条件分岐（ジャンプ）命令。
    *   **`BL`**: 分岐とリンク（Branch with Link）命令。関数呼び出しに使用され、戻りアドレスをリンクレジスタ（LR, R14）に保存します。
    *   **`CMP`**: 比較命令。
    *   **`B.EQ`**: 等しい場合に分岐する条件分岐命令。

4.  **Cgo**:
    *   GoとC言語の相互運用を可能にするGoの機能です。GoコードからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。
    *   `_cgo_sys_thread_create`: Cgoが提供する関数で、新しいOSスレッドを作成し、そのスレッドで指定されたGo関数を実行するために使用されます。これは、GoランタイムがOSスレッドを管理するために重要です。

5.  **`NOSPLIT`**:
    *   Goのアセンブリ関数におけるディレクティブで、その関数がスタックを分割しないことを示します。これは、非常に短い関数や、スタックの管理をGoランタイムに任せない低レベルの関数でよく使用されます。

6.  **`SB` (Static Base)**:
    *   Goのアセンブリにおける擬似レジスタで、静的データやグローバルシンボルへのオフセットを計算するためのベースアドレスとして機能します。`main(SB)`のように使われ、`main`関数のアドレスを示します。

## 技術的詳細

このコミットは、`src/runtime/rt0_darwin_arm.s`ファイルに新しいアセンブリコードを追加し、Goランタイムがライブラリとして組み込まれる際の初期化パスを定義しています。

追加された主要なエントリポイントは`_rt0_arm_darwin_lib`です。これは、C/Objective-Cの初期化ルーチンから呼び出されることを想定しています。

1.  **`_rt0_arm_darwin_lib` エントリポイント**:
    *   この関数は、Cの規約に従って`argc`と`argv`（コマンドライン引数の数と配列）を`R0`と`R1`レジスタで受け取ります。
    *   これらの引数は、Goランタイムが後で利用できるように、グローバル変数`_rt0_arm_darwin_lib_argc`と`_rt0_arm_darwin_lib_argv`に保存されます。
    *   **スレッド作成**: Goランタイムの初期化は、新しいOSスレッドで行う必要があります。これは、GoのスケジューラがOSスレッド上で動作し、Goの実行モデルがOSスレッドの管理に依存しているためです。
        *   まず、`_cgo_sys_thread_create`関数のアドレスを`R4`にロードし、そのアドレスが`0`でないか（つまり、cgoが利用可能か）をチェックします。
        *   **cgoが利用可能な場合**: `_cgo_sys_thread_create`を呼び出して新しいスレッドを作成し、そのスレッドで`_rt0_arm_darwin_lib_go`関数を実行させます。`_rt0_arm_darwin_lib_go`はGoランタイムの実際の初期化を開始する関数です。
        *   **cgoが利用できない場合 (`nocgo`ラベルへ分岐)**: `_cgo_sys_thread_create`が利用できない場合（例えば、cgoがリンクされていない場合）、Goランタイムは`runtime·newosproc0`を直接呼び出して新しいOSスレッドを作成します。この場合、スタックサイズ、実行する関数（`_rt0_arm_darwin_lib_go`）、および引数をスタックにプッシュしてから`runtime·newosproc0`を呼び出します。

2.  **`_rt0_arm_darwin_lib_go` 関数**:
    *   この関数は、`_rt0_arm_darwin_lib`で保存された`argc`と`argv`の値をロードし、それらをスタックにプッシュします。
    *   最終的に、Goランタイムのメイン初期化ルーチンである`runtime·rt0_go`へ分岐します。`runtime·rt0_go`は、Goのスケジューラやガベージコレクタなど、ランタイムの主要コンポーネントを初期化する役割を担います。

3.  **グローバル変数**:
    *   `_rt0_arm_darwin_lib_argc`と`_rt0_arm_darwin_lib_argv`という2つのグローバルデータセクションが定義されています。これらは、`_rt0_arm_darwin_lib`で受け取った`argc`と`argv`の値を一時的に保存するために使用されます。`GLOBL`ディレクティブは、これらのシンボルが外部から参照可能であることを示し、`NOPTR`はポインタを含まないことを示します。

この変更により、GoのコードがC/Objective-Cアプリケーションに組み込まれた際に、Goランタイムが適切に初期化され、Goの機能が利用できるようになります。特にiOSのような組み込み環境では、Goの並行処理能力やメモリ効率がアプリケーションのパフォーマンス向上に貢献する可能性があります。

## コアとなるコードの解説

追加されたアセンブリコードは、GoランタイムがCライブラリとして利用される際の初期化フローを定義しています。

1.  **`TEXT _rt0_arm_darwin_lib(SB),NOSPLIT,$12`**:
    *   `_rt0_arm_darwin_lib`という新しいテキストセクション（関数）を定義します。
    *   `NOSPLIT`は、この関数がスタックを分割しないことを示します。
    *   `$12`は、この関数のスタックフレームサイズが12バイトであることを示します。

2.  **`MOVW R0, _rt0_arm_darwin_lib_argc<>(SB)`**:
    *   レジスタ`R0`の内容（Cの呼び出し規約における第一引数、通常は`argc`）を、グローバル変数`_rt0_arm_darwin_lib_argc`に保存します。

3.  **`MOVW R1, _rt0_arm_darwin_lib_argv<>(SB)`**:
    *   レジスタ`R1`の内容（Cの呼び出し規約における第二引数、通常は`argv`）を、グローバル変数`_rt0_arm_darwin_lib_argv`に保存します。

4.  **`MOVW _cgo_sys_thread_create(SB), R4`**:
    *   `_cgo_sys_thread_create`関数のアドレスを`R4`レジスタにロードします。この関数はcgoが提供するスレッド作成関数です。

5.  **`CMP $0, R4` / `B.EQ nocgo`**:
    *   `R4`（`_cgo_sys_thread_create`のアドレス）が`0`と比較されます。もし`0`であれば、cgoが利用できないため、`nocgo`ラベルに分岐します。

6.  **`MOVW $_rt0_arm_darwin_lib_go(SB), R0` / `MOVW $0, R1` / `BL (R4)`**:
    *   cgoが利用可能な場合、`_rt0_arm_darwin_lib_go`関数のアドレスを`R0`に、`0`を`R1`にロードします。これらは`_cgo_sys_thread_create`への引数となります。
    *   `BL (R4)`は、`R4`に格納されているアドレス（`_cgo_sys_thread_create`）を呼び出し、戻りアドレスをリンクレジスタ（LR）に保存します。これにより、新しいOSスレッドでGoランタイムの初期化が開始されます。

7.  **`RET`**:
    *   関数から戻ります。

8.  **`nocgo:` ラベル以下のコード**:
    *   cgoが利用できない場合のフォールバックパスです。
    *   `MOVW $0x400000, R0` / `MOVW $_rt0_arm_darwin_lib_go(SB), R1` / `MOVW $0, R2`:
        *   新しいスレッドのスタックサイズ（`0x400000`バイト）、実行する関数（`_rt0_arm_darwin_lib_go`）、およびその関数の引数（`0`）をそれぞれ`R0`, `R1`, `R2`にロードします。
    *   `MOVW R0, (R13)` / `MOVW R1, 4(R13)` / `MOVW R2, 8(R13)`:
        *   これらの値をスタックポインタ`R13`を基準としたオフセットにプッシュします。これらは`runtime·newosproc0`への引数となります。
    *   `MOVW $runtime·newosproc0(SB), R4` / `BL (R4)`:
        *   `runtime·newosproc0`関数のアドレスを`R4`にロードし、それを呼び出します。`runtime·newosproc0`は、Goランタイムが直接OSスレッドを作成するための低レベル関数です。

9.  **`TEXT _rt0_arm_darwin_lib_go(SB),NOSPLIT,$0`**:
    *   新しいスレッドで実行されるGoランタイム初期化のラッパー関数です。スタックフレームサイズは`$0`です。

10. **`MOVW _rt0_arm_darwin_lib_argc<>(SB), R0` / `MOVW _rt0_arm_darwin_lib_argv<>(SB), R1`**:
    *   先に保存しておいた`argc`と`argv`の値を`R0`と`R1`にロードします。

11. **`MOVW R0, (R13)` / `MOVW R1, 4(R13)`**:
    *   `argc`と`argv`の値をスタックにプッシュします。これらは`runtime·rt0_go`への引数となります。

12. **`MOVW $runtime·rt0_go(SB), R4` / `B (R4)`**:
    *   Goランタイムのメイン初期化関数である`runtime·rt0_go`のアドレスを`R4`にロードし、そこに無条件分岐します。これにより、Goランタイムの本格的な初期化が開始されます。

13. **`DATA _rt0_arm_darwin_lib_argc<>(SB)/4, $0` / `GLOBL _rt0_arm_darwin_lib_argc<>(SB),NOPTR, $4`**:
    *   `_rt0_arm_darwin_lib_argc`というグローバル変数を定義します。サイズは4バイトで、初期値は`0`です。`GLOBL`は外部リンケージ可能であることを、`NOPTR`はポインタを含まないことを示します。

14. **`DATA _rt0_arm_darwin_lib_argv<>(SB)/4, $0` / `GLOBL _rt0_arm_darwin_lib_argv<>(SB),NOPTR, $4`**:
    *   `_rt0_arm_darwin_lib_argv`についても同様に定義します。

これらの変更により、GoのコードがC/Objective-Cアプリケーションに組み込まれた際に、Goランタイムが適切に初期化され、Goの機能が利用できるようになります。
