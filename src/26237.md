# [インデックス 26237] ファイルの概要

このコミットは、Go言語のビルドツールである `cmd/dist` において、macOS (OS X) 環境でのホストアーキテクチャ判定ロジックを簡素化する変更を導入しています。具体的には、macOS上での `amd64` アーキテクチャの判定に `sysctl` コマンドを使用するのをやめ、常に `amd64` であると仮定するように修正されました。これは、32ビットのみのハードウェアをサポートするOS XバージョンがGoのサポート対象外となったためです。

## 元コミット内容

このコミットは、`cmd/dist` ツールがmacOS (OS X) 上でホストのアーキテクチャを判定する際に、`sysctl machdep.cpu.extfeatures` コマンドの実行を停止し、代わりに `amd64` であると直接仮定するように変更します。これにより、ビルドプロセスの効率が向上し、不要な外部コマンドの実行が回避されます。この変更は、Issue #13425 を解決します。

## 変更の背景

この変更の背景には、Go言語がサポートするmacOSのバージョンとハードウェアの進化があります。

1.  **32ビットOS Xのサポート終了**: 以前のGoバージョンでは、32ビットのOS X環境（例えば、初期のIntel Macや古いOS Xバージョン）も考慮する必要がありました。そのため、`cmd/dist` は `sysctl` コマンドを使用してCPUの拡張機能（`EM64T` など）をチェックし、システムが64ビット（`amd64`）をサポートしているかどうかを動的に判定していました。
2.  **`uname -m` の限界**: macOSの `uname -m` コマンドは、64ビットシステムであっても `i386` を返すことがあり、これが正確なアーキテクチャ判定を困難にしていました。そのため、より詳細なCPU情報を得るために `sysctl` が使われていました。
3.  **Goのサポートポリシーの変更**: Goプロジェクトは、時間の経過とともに古いOSバージョンやハードウェアのサポートを段階的に終了しています。このコミットが作成された2016年頃には、GoがサポートするmacOSの最小バージョンが引き上げられ、32ビットのみのハードウェアで動作するOS Xバージョンはもはやサポート対象外となっていました。
4.  **ビルドプロセスの簡素化と高速化**: 32ビットOS Xのサポートが不要になったことで、`sysctl` コマンドを実行してアーキテクチャを動的に判定する必要がなくなりました。これにより、ビルドスクリプトが簡素化され、外部コマンドの実行オーバーヘッドが削減されるため、ビルド時間のわずかな短縮にも繋がります。

これらの理由から、macOS上では常に `amd64` であると仮定することが適切かつ効率的であると判断され、この変更が導入されました。

## 前提知識の解説

このコミットを理解するためには、以下の知識が役立ちます。

*   **Go言語のビルドシステム (`cmd/dist`)**:
    *   `cmd/dist` はGo言語のソースコードからGoツールチェイン自体をビルドするためのツールです。Goのコンパイラ、リンカ、標準ライブラリなどを構築する際に使用されます。
    *   クロスコンパイルのサポートが強力であり、異なるOSやアーキテクチャ向けのバイナリを生成できます。このプロセスにおいて、ホスト環境のOS (`gohostos`) やアーキテクチャ (`gohostarch`) を正確に判定することが重要です。
*   **`sysctl` コマンド**:
    *   `sysctl` はUnix系オペレーティングシステム（macOSを含む）で、カーネルの状態を検査および設定するためのコマンドラインユーティリティです。
    *   `machdep.cpu.extfeatures` は、macOSにおいてCPUの拡張機能に関する情報を提供する `sysctl` キーの一つです。これには、`EM64T` (Intel 64) のような64ビット拡張機能の有無が含まれることがあります。
*   **`uname -m` コマンド**:
    *   `uname` はシステム情報を表示するコマンドで、`-m` オプションはマシンのハードウェア名（アーキテクチャ）を表示します。
    *   macOSでは、64ビットIntelプロセッサを搭載したシステムでも、歴史的な理由から `i386` を返すことがありました。これは、macOSが長らく32ビットと64ビットのユニバーサルバイナリをサポートしていたため、カーネルが32ビットモードで動作している場合などに `i386` を返すことがあったためです。
*   **`amd64` アーキテクチャ**:
    *   Intel 64 (x86-64) または AMD64 とも呼ばれる64ビット命令セットアーキテクチャです。現代のほとんどのデスクトップおよびサーバーCPUで採用されています。
    *   Go言語では、このアーキテクチャを `amd64` と表記します。
*   **Goの環境変数 `GOOS` と `GOARCH`**:
    *   Goのビルドプロセスでは、ターゲットのオペレーティングシステムを `GOOS` (例: `darwin`, `linux`, `windows`)、ターゲットのアーキテクチャを `GOARCH` (例: `amd64`, `arm64`, `386`) という環境変数で指定します。
    *   `cmd/dist` は、これらの値を適切に設定するためにホスト環境の情報を利用します。

## 技術的詳細

このコミットの技術的詳細は、`cmd/dist` の `util.go` ファイル内の `main` 関数（またはそれに相当する初期化ロジック）における `gohostos` が `"darwin"` の場合の処理にあります。

変更前は、macOS環境 (`gohostos == "darwin"`) で `gohostarch` を決定するために以下のロジックが使用されていました。

```go
		// Even on 64-bit platform, darwin uname -m prints i386.
		if strings.Contains(run("", CheckExit, "sysctl", "machdep.cpu.extfeatures"), "EM64T") {
			gohostarch = "amd64"
		}
```

このコードは、以下の手順でアーキテクチャを判定していました。

1.  `run("", CheckExit, "sysctl", "machdep.cpu.extfeatures")` を実行し、`sysctl machdep.cpu.extfeatures` コマンドの出力を取得します。
2.  取得した出力文字列に `"EM64T"` が含まれているかを確認します。`EM64T` はIntel 64 (x86-64) の拡張機能を示すもので、これが存在すればCPUが64ビット対応であることを意味します。
3.  `"EM64T"` が含まれていれば、`gohostarch` を `"amd64"` に設定します。

このロジックは、`uname -m` が常に `i386` を返す可能性があるというmacOSの特性に対応するためのものでした。しかし、このコミットにより、この動的な判定ロジックは削除され、代わりに以下のコードに置き換えられました。

```go
		// We don't support any of the OS X versions that run on 32-bit-only hardware anymore.
		gohostarch = "amd64"
```

この変更により、`gohostos` が `"darwin"` の場合、`gohostarch` は無条件に `"amd64"` に設定されます。これは、GoがサポートするmacOSのバージョンが、すべて64ビットIntelプロセッサ上で動作することを前提としているためです。32ビットのみのmacOS環境はGoのサポート対象外となったため、この簡素化が可能になりました。

この変更の利点は以下の通りです。

*   **パフォーマンスの向上**: `sysctl` コマンドを外部プロセスとして実行するオーバーヘッドがなくなります。ビルドプロセス全体から見れば微々たるものかもしれませんが、不要な外部依存を減らすことは常に良いプラクティスです。
*   **コードの簡素化**: アーキテクチャ判定ロジックがより直接的になり、コードの可読性と保守性が向上します。
*   **信頼性の向上**: 外部コマンドの出力解析に依存するロジックは、コマンドの出力形式が将来変更された場合に壊れる可能性があります。直接的な代入は、このような潜在的な問題を回避します。

## コアとなるコードの解説

変更されたコードブロックは、Goのビルドツール `cmd/dist` がホストのオペレーティングシステムがmacOS (`darwin`) であると判断した場合に実行される部分です。

**変更前**:
コメント `// Even on 64-bit platform, darwin uname -m prints i386.` が示すように、`uname -m` の出力が信頼できないため、`sysctl machdep.cpu.extfeatures` を実行し、その出力に `EM64T` という文字列が含まれているかどうかで64ビットCPU (`amd64`) であるかを判定していました。`EM64T` はIntelの64ビット拡張技術の名称です。この動的なチェックは、32ビットと64ビットの両方のmacOS環境をサポートする必要があった時代の名残です。

**変更後**:
既存の判定ロジックが完全に削除され、新しいコメント `// We don't support any of the OS X versions that run on 32-bit-only hardware anymore.` が追加されました。このコメントは、Goがもはや32ビットのみのハードウェアで動作する古いOS Xバージョンをサポートしていないことを明確に示しています。
そのため、`gohostarch = "amd64"` という行が追加され、macOS環境ではホストアーキテクチャが常に `amd64` であると直接的に仮定されるようになりました。

この変更は、Goのサポートポリシーの進化と、それに伴うビルドプロセスの合理化を反映しています。これにより、ビルド時の外部コマンド実行が不要になり、わずかながらも効率が向上し、コードベースが簡素化されました。
