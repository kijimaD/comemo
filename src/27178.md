## 元コミット内容

このコミットは、`darwin/arm`および`darwin/arm64`プラットフォームにおけるGoランタイムの初期化ルーチンが、呼び出し先保存レジスタ（callee-save registers）を適切に保存・復元するように修正するものです。以前の変更（CL 14603）では不十分であり、Issue #14778で報告されたクラッシュを引き起こしていました。このコミットでは、`linux/arm`と同様にレジスタをスタックに保存・復元することで問題を解決します。また、`darwin/arm64`および同じ呼び出し規約に従う`linux/arm64`にも同様の変更が適用されています。この変更は、特にiOSプラットフォームと`gomobile`にとって重要であり、Go 1.6のマイナーリリース候補とされています。Issue #14778とIssue #12590（再発）を修正します。

## 変更の背景

Goランタイムの初期化処理において、特定のプラットフォーム（`darwin/arm`、`darwin/arm64`、`linux/arm64`）で呼び出し規約が正しく守られていないことが原因でクラッシュが発生していました。特に`darwin/arm`環境では、以前の修正（CL 14603）が不十分であり、`liblink`が予約する一時レジスタ（`REGTMP`、ARMでは`R11`、ARM64では`R27`）が、同時に呼び出し先保存レジスタでもあるために、関数呼び出しを跨いで値が破壊される可能性がありました。

この問題はIssue #14778として報告され、`gomobile`を利用したiOSアプリケーションが実用不可能になるほどの深刻なものでした。このコミットは、`linux/arm`が既に採用している、呼び出し先保存レジスタをスタックに明示的に保存・復元するという堅牢なアプローチを導入することで、このクラッシュを根本的に解決しようとしています。`darwin/arm64`では直接的な再現はなかったものの、同じ呼び出し規約を持つため、将来的な問題を未然に防ぐために同様の変更が適用されました。

## 前提知識の解説

### 呼び出し規約 (Calling Convention)

関数が呼び出される際に、引数の渡し方、戻り値の受け取り方、レジスタの使用方法、スタックの管理方法などを定めた取り決めです。CPUアーキテクチャやOSによって異なる場合があります。

### 呼び出し先保存レジスタ (Callee-save Registers) と 呼び出し元保存レジスタ (Caller-save Registers)

*   **呼び出し元保存レジスタ (Caller-save Registers)**: 関数を呼び出す側（caller）が、そのレジスタの値を保持したい場合に、関数呼び出し前に自分でスタックに保存し、関数から戻った後に復元する責任を持つレジスタです。呼び出された関数（callee）は、これらのレジスタを自由に変更できます。
*   **呼び出し先保存レジスタ (Callee-save Registers)**: 関数を呼び出された側（callee）が、そのレジスタの値を変更する前にスタックに保存し、関数から戻る前に復元する責任を持つレジスタです。これにより、呼び出し元はこれらのレジスタの値を関数呼び出しを跨いで信頼できます。

このコミットの文脈では、`R11` (ARM) や `R19-R27` (ARM64) などが呼び出し先保存レジスタに該当します。

### Goランタイムの初期化 (`_rt0_..._lib`)

Goプログラムが起動する際、OSから最初に制御を受け取るのがランタイムの初期化ルーチンです。アセンブリ言語で書かれたこれらのルーチン（例: `_rt0_arm_darwin_lib`）は、Goランタイムの環境設定、スタックのセットアップ、スケジューラの起動など、Goプログラムが実行されるための基盤を構築します。特に`-buildmode=c-shared`でビルドされた共有ライブラリの場合、ライブラリがロードされた際にこれらのルーチンが呼び出されます。

### ARM/ARM64 アセンブリ言語の基本

*   **`MOVW` (Move Word)**: ARM32アーキテクチャで32ビットの値をレジスタ間で移動したり、レジスタとメモリ間で移動したりする命令です。
*   **`MOVD` (Move Doubleword)**: ARM64アーキテクチャで64ビットの値をレジスタ間で移動したり、レジスタとメモリ間で移動したりする命令です。
*   **`BL` (Branch with Link)**: 関数呼び出しを行う命令です。現在のプログラムカウンタ（PC）の次のアドレスをリンクレジスタ（LR）に保存し、指定されたアドレスにジャンプします。
*   **`RET` (Return)**: 関数から戻る命令です。通常、リンクレジスタ（LR）に保存されたアドレスにジャンプします。
*   **`R0`, `R1`, ..., `R11` (ARM32)**: 汎用レジスタ。`R0-R3`は通常、引数や戻り値に使用されます。`R11`は`REGTMP`として`liblink`に予約されていますが、同時に呼び出し先保存レジスタでもあります。
*   **`RSP` (Stack Pointer)**: スタックの最上位を指すレジスタ。
*   **`R19`, `R20`, ..., `R27` (ARM64)**: 汎用レジスタ。ARM64の呼び出し規約では、これらは呼び出し先保存レジスタです。`R27`は`REGTMP`として`liblink`に予約されています。
*   **`12(R13)` など**: メモリへのアクセスを示します。`R13`（ARM32ではスタックポインタ`SP`として使われることが多い）が指すアドレスから12バイトオフセットした位置を意味します。これはスタック上の特定の場所を指します。
*   **`NOSPLIT`**: Goのアセンブリ関数で、スタックの拡張チェックを行わないことを示すディレクティブです。初期化ルーチンなど、スタックがまだ完全にセットアップされていない状況で使われます。
*   **`$`**: アセンブリコードにおけるスタックフレームサイズを指定します。例えば`$32`は、この関数が32バイトのスタックフレームを使用することを示します。

### `liblink`と`REGTMP`

`liblink`はGoのリンカであり、アセンブリコードを処理する際に特定の一時レジスタを内部的に使用します。この一時レジスタは`REGTMP`と呼ばれ、ARM32では`R11`、ARM64では`R27`に割り当てられています。問題は、これらのレジスタがOSの呼び出し規約では「呼び出し先保存レジスタ」として扱われる点にありました。つまり、`liblink`が一時的に使用するレジスタが、関数呼び出しを跨いでその値が保持されるべきレジスタと衝突し、予期せぬ値の破壊を引き起こしていたのです。

### Go Issue #14778 と #12590

*   **Issue #14778**: `darwin/arm`環境でのGoランタイム初期化時のクラッシュに関する問題。`gomobile`でビルドされたiOSアプリが起動時にクラッシュする原因となっていました。
*   **Issue #12590**: 以前にも同様のレジスタ保存に関する問題で、`darwin/arm`環境でのクラッシュを引き起こしていました。このコミットは、その問題の「再発」を修正するものです。

## 技術的詳細

このコミットの核心は、Goランタイムの初期化ルーチン（`_rt0_arm_darwin_lib`, `_rt0_arm64_darwin_lib`, `_rt0_arm64_linux_lib`）において、呼び出し先保存レジスタを関数エントリ時にスタックに保存し、関数リターン時にスタックから復元する処理を追加した点にあります。

具体的には、以下の変更が行われました。

1.  **スタックフレームサイズの増加**: 呼び出し先保存レジスタを保存するために必要な領域を確保するため、各関数のスタックフレームサイズが拡張されました。
    *   `_rt0_arm_darwin_lib`: `$0` から `$32` へ (32バイト増加)
    *   `_rt0_arm64_darwin_lib`: `$0` から `$88` へ (88バイト増加)
    *   `_rt0_arm64_linux_lib`: `$40` から `$88` へ (48バイト増加)
    このスタックフレームサイズは、保存するレジスタの数とレジスタのサイズ（ARM32は4バイト、ARM64は8バイト）に基づいて計算されます。例えば、`darwin/arm`では`R4-R8`と`R11`の計6つのレジスタを保存するため、6 * 4バイト = 24バイトが必要ですが、スタックアライメントやその他の理由で32バイトが確保されています。ARM64では`R19-R27`の9つのレジスタを保存するため、9 * 8バイト = 72バイトが必要ですが、88バイトが確保されています。

2.  **レジスタの保存**: 関数エントリ直後、`MOVW` (ARM32) または `MOVD` (ARM64) 命令を使用して、対象となる呼び出し先保存レジスタの値をスタック上のオフセットされた位置に書き込みます。
    *   `darwin/arm`: `R4`, `R5`, `R6`, `R7`, `R8`, `R11` をスタックに保存。
    *   `darwin/arm64` および `linux/arm64`: `R19`, `R20`, `R21`, `R22`, `R23`, `R24`, `R25`, `R26`, `R27` をスタックに保存。

3.  **レジスタの復元**: 関数がリターンする直前、または`runtime·newosproc0`などの重要な関数呼び出しから戻った後、スタックに保存しておいた値を対応するレジスタに復元します。これにより、呼び出し元が期待するレジスタの状態が維持されます。

このアプローチは、`linux/arm`が既に採用しているものと同様であり、呼び出し規約の厳密な遵守を保証します。特に`liblink`が`REGTMP`として使用するレジスタが、OSの呼び出し規約で呼び出し先保存レジスタである場合に発生する衝突を回避します。

## コアとなるコードの解説

### `src/runtime/rt0_darwin_arm.s` の変更点

*   `TEXT _rt0_arm_darwin_lib(SB),NOSPLIT,$0` が `TEXT _rt0_arm_darwin_lib(SB),NOSPLIT,$32` に変更され、スタックフレームサイズが32バイトに拡張されました。
*   以前は `R11` を一時的に `R2` に保存していましたが、この一時的な保存では関数呼び出しを跨いだレジスタの保護が不十分でした。
*   新たに以下の命令が追加され、`R4`から`R8`、そして`R11`（`REGTMP`）といった呼び出し先保存レジスタがスタックに保存されます。`R13`はスタックポインタとして機能し、オフセット値（`12(R13)`など）でスタック上の位置を指定しています。
    ```assembly
    MOVW    R4, 12(R13)
    MOVW    R5, 16(R13)
    MOVW    R6, 20(R13)
    MOVW    R7, 24(R13)
    MOVW    R8, 28(R13)
    MOVW    R11, 32(R13)
    ```
*   関数呼び出し（`BL (R3)`）の後、以前は直接 `RET` していましたが、`B rr` で `rr` ラベルにジャンプするように変更されました。
*   `rr:` ラベル以下で、スタックに保存しておいたレジスタの値を元のレジスタに復元しています。
    ```assembly
    rr:
    	// Restore callee-save registers and return.
    	MOVW    12(R13), R4
    	MOVW    16(R13), R5
    	MOVW    20(R13), R6
    	MOVW    24(R13), R7
    	MOVW    28(R13), R8
    	MOVW    32(R13), R11
    	RET
    ```
    これにより、`_rt0_arm_darwin_lib`関数が終了する際に、呼び出し元が期待するレジスタの状態が保証されます。

### `src/runtime/rt0_darwin_arm64.s` の変更点

*   `TEXT _rt0_arm64_darwin_lib(SB),NOSPLIT,$0` が `TEXT _rt0_arm64_darwin_lib(SB),NOSPLIT,$88` に変更され、スタックフレームサイズが88バイトに拡張されました。
*   以前は `R27` を一時的に `R7` に保存していましたが、これも不十分でした。
*   新たに以下の命令が追加され、`R19`から`R27`（`REGTMP`）といった呼び出し先保存レジスタがスタックに保存されます。`RSP`はスタックポインタです。
    ```assembly
    MOVD R19, 24(RSP)
    MOVD R20, 32(RSP)
    MOVD R21, 40(RSP)
    MOVD R22, 48(RSP)
    MOVD R23, 56(RSP)
    MOVD R24, 64(RSP)
    MOVD R25, 72(RSP)
    MOVD R26, 80(RSP)
    MOVD R27, 88(RSP)
    ```
*   関数呼び出し（`BL (R4)`）の後、スタックに保存しておいたレジスタの値を元のレジスタに復元しています。
    ```assembly
    // Restore callee-save registers.
    MOVD 24(RSP), R19
    MOVD 32(RSP), R20
    MOVD 40(RSP), R21
    MOVD 48(RSP), R22
    MOVD 56(RSP), R23
    MOVD 64(RSP), R24
    MOVD 72(RSP), R25
    MOVD 80(RSP), R26
    MOVD 88(RSP), R27
    RET
    ```

*   `TEXT _rt0_arm64_linux_lib(SB),NOSPLIT,$40` が `TEXT _rt0_arm64_linux_lib(SB),NOSPLIT,$88` に変更され、スタックフレームサイズが88バイトに拡張されました。
*   以前は `R27` のみをスタックに保存していましたが、ARM64の呼び出し規約に従い、他の呼び出し先保存レジスタも保存するように変更されました。
*   `darwin/arm64` と同様に、`R19`から`R27`までの呼び出し先保存レジスタがスタックに保存・復元されます。

    ```assembly
    	MOVD 32(RSP), R20
    	MOVD 40(RSP), R21
    	MOVD 48(RSP), R22
    	MOVD 56(RSP), R23
    	MOVD 64(RSP), R24
    	MOVD 72(RSP), R25
    	MOVD 80(RSP), R26
    	MOVD 88(RSP), R27
    	RET
    ```

これらの変更により、Goランタイムの初期化ルーチンが、各プラットフォームの呼び出し規約を厳密に遵守し、関数呼び出しを跨いで呼び出し先保存レジスタの値を破壊しないように保証されます。これにより、特に`gomobile`を利用したiOSアプリケーションでの安定性が大幅に向上しました。
