## 元コミット内容

このコミットは、`go/build` パッケージの変更に対応するために、`api/go1.6.txt` ファイルを更新するものです。コミットメッセージは「api: fix build for go/build change」とあり、`go/build` パッケージの変更によって発生したビルド問題を修正することが目的であることを示しています。具体的には、`go/build` パッケージ内の `AllowVendor` という定数が `IgnoreVendor` にリネームされたことに伴い、そのAPI定義を更新しています。

## 変更の背景

Go 1.5では、依存関係管理の実験的な機能として「Vendor Experiment」が導入されました。これは、プロジェクトのルートディレクトリに `vendor/` ディレクトリを配置することで、そのプロジェクト固有の依存関係を管理できるようにするものでした。Go 1.6では、このベンダー機能がデフォルトで有効になる方向で進められていました。

`go/build` パッケージは、Goのソースコードをビルドする際に、パッケージの解決（どのパッケージをインポートするか）を行うための重要な機能を提供します。ベンダー機能の導入に伴い、`go/build` パッケージには、ベンダーディレクトリの扱いを制御するための `ImportMode` 定数が必要となりました。

当初、この定数は `AllowVendor` と命名されていた可能性があります。しかし、Go 1.6でベンダー機能がデフォルトで有効になるという設計変更があったため、「ベンダーを許可する」というよりも「ベンダーを無視する」という逆の概念で制御する方が、APIの意図をより明確に表現できると判断されたと考えられます。つまり、デフォルトでベンダーが使用されるため、明示的にベンダーを「無視」したい場合にこのフラグを使用するというセマンティクスに変更されたのです。

この名称変更（`AllowVendor` から `IgnoreVendor` へ）が `go/build` パッケージ本体で行われた後、その変更がGo 1.6のAPI定義ファイルである `api/go1.6.txt` に反映されていなかったため、API定義のビルドが失敗する状態になっていました。本コミットは、このAPI定義の不整合を解消し、ビルドを正常化するための修正です。

## 前提知識の解説

### Go言語のビルドシステムと `go/build` パッケージ

Go言語には、`go build` や `go get` といったコマンドを通じて、ソースコードのコンパイルや依存関係の取得を行うための強力なビルドシステムが組み込まれています。このビルドシステムの核となるのが、標準ライブラリの `go/build` パッケージです。

`go/build` パッケージは、以下の主要な機能を提供します。
*   **パッケージの検索**: 指定されたパスやインポートパスに基づいて、Goパッケージのソースディレクトリを特定します。
*   **パッケージ情報の解析**: 特定されたディレクトリ内のGoソースファイルから、パッケージ名、インポートパス、エクスポートされたシンボルなどの情報を抽出します。
*   **ビルドタグの処理**: `// +build` ディレクティブを解釈し、現在のビルド環境に適したファイルを選択します。
*   **`ImportMode`**: パッケージのインポート動作を制御するためのフラグの集合体です。例えば、テストファイルをインポートに含めるか、Cgoを有効にするか、そして本コミットの主題であるベンダーディレクトリをどのように扱うか、などを指定できます。

### Go ModulesとVendor Experiment

Go言語の依存関係管理は、歴史的にいくつかの変遷をたどってきました。
*   **GOPATH時代**: 初期Goでは、すべてのプロジェクトが単一の `GOPATH` ワークスペース内で依存関係を共有していました。これはプロジェクトごとに異なるバージョンの依存関係を持つことを困難にしていました。
*   **Vendor Experiment (Go 1.5/1.6)**: `GOPATH` の問題を解決するための一歩として、Go 1.5で「Vendor Experiment」が導入されました。これは、プロジェクトのルートに `vendor/` ディレクトリを作成し、その中に依存パッケージのコピーを配置することで、プロジェクト固有の依存関係を管理できるようにするものでした。`go build` コマンドは、まず `vendor/` ディレクトリ内を検索し、見つからなければ `GOPATH` を検索するようになりました。Go 1.6では、このベンダー機能がデフォルトで有効になりました。
*   **Go Modules**: その後、Go 1.11でGo Modulesが導入され、Go 1.13でデフォルトとなり、Go言語の公式な依存関係管理メカニズムとなりました。Go Modulesは、`go.mod` ファイルと `go.sum` ファイルを使用して、より堅牢で再現性のある依存関係管理を提供します。

本コミットは、Go Modulesが導入される前のVendor Experimentの時代、特にGo 1.6のリリースに向けた開発段階での変更に当たります。

### GoのAPI定義ファイル (`api/go1.6.txt`)

Go言語のリリースプロセスでは、各バージョンのAPI互換性を厳密に管理しています。`api/goX.Y.txt` のようなファイルは、そのGoバージョンで利用可能な公開API（関数、型、定数など）のリストを定義しています。これらのファイルは、Goのツールチェーンによって生成・検証され、APIの意図しない変更や非互換性の導入を防ぐ役割を果たします。

このファイルが更新されるのは、新しいAPIが追加されたり、既存のAPIが変更（例えば、定数のリネーム）されたりした場合です。本コミットでは、`go/build` パッケージの定数名が変更されたため、このAPI定義ファイルもそれに合わせて更新する必要がありました。

## 技術的詳細

このコミットの技術的詳細は、`go/build` パッケージの `ImportMode` 型に定義されている定数のセマンティクス変更と、それに伴うAPI定義の同期にあります。

`go/build` パッケージの `ImportMode` は、`go/build` パッケージの `Context` 構造体で使用され、パッケージのインポート動作をカスタマイズするためのビットフラグの集合です。

変更前:
```go
// go/build/build.go (hypothetical, based on diff)
const (
    // ... other ImportMode flags
    AllowVendor ImportMode = 1 << iota // 8 (example value)
    // ...
)
```
`AllowVendor` は、ベンダーディレクトリからのインポートを許可するかどうかを制御するフラグとして設計されていたと考えられます。

変更後:
```go
// go/build/build.go (hypothetical, based on diff)
const (
    // ... other ImportMode flags
    IgnoreVendor ImportMode = 1 << iota // 8 (example value)
    // ...
)
```
`IgnoreVendor` は、ベンダーディレクトリからのインポートを「無視」するかどうかを制御するフラグとして再設計されました。Go 1.6でベンダー機能がデフォルトで有効になったため、このフラグがセットされている場合は、`vendor/` ディレクトリ内のパッケージよりも `GOPATH` や標準ライブラリのパッケージが優先される、あるいは `vendor/` ディレクトリが全く検索されない、といった動作になることが期待されます。

この変更は、単なる名称変更以上の意味を持ちます。それは、ベンダー機能のデフォルトの振る舞いと、それをオーバーライドするためのメカニズムに関する設計思想の変更を反映しています。`AllowVendor` は「許可制」のニュアンスが強いのに対し、`IgnoreVendor` は「デフォルト有効だが、必要に応じて無効化できる」というニュアンスが強いです。

本コミットは、この `go/build` パッケージ内部の変更（`AllowVendor` から `IgnoreVendor` へのリネーム）が、Go 1.6の公開APIリスト (`api/go1.6.txt`) に正しく反映されるようにするためのものです。API定義ファイルが実際のコードと同期していないと、GoのビルドシステムがAPIの不整合を検出し、ビルドエラーを発生させます。このコミットは、そのビルドエラーを解消するための修正です。

## コアとなるコードの解説

この差分は、`api/go1.6.txt` ファイル内の2行を削除し、2行を追加していることを示しています。

*   `-pkg go/build, const AllowVendor = 8`
*   `-pkg go/build, const AllowVendor ImportMode`

これらの行は、`go/build` パッケージに `AllowVendor` という名前の定数が存在し、その値が `8` であり、型が `ImportMode` であることを定義していました。

*   `+pkg go/build, const IgnoreVendor = 8`
*   `+pkg go/build, const IgnoreVendor ImportMode`

これらの行は、`go/build` パッケージに `IgnoreVendor` という名前の定数が存在し、その値が `8` であり、型が `ImportMode` であることを新たに定義しています。

この変更は、`AllowVendor` 定数が `IgnoreVendor` 定数にリネームされたことを、Go 1.6の公開APIリストに正確に反映させるためのものです。定数の値 (`8`) と型 (`ImportMode`) は変更されていないため、これは純粋な名称変更であり、そのセマンティクスが変更されたことを示唆しています。
