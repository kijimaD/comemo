# [インデックス 2354] ファイルの概要

このコミットは、Go言語の初期段階におけるスキャナー（字句解析器）とパーサー（構文解析器）の挙動変更に関するものです。具体的には、スキャナーが不正な文字（Go言語の構文規則に合致しない文字）を検出した際に、即座にエラーを報告するのではなく、その処理を継続できるようにする機能が追加されました。これにより、Go言語のコードではない部分（例えば、他の言語の埋め込みや、Go言語のツールが構文解析以外の目的でスキャナーを使用する場合）に対しても、スキャナーをより柔軟に利用できるようになりました。パーサー側も、このスキャナーの新しいモードに対応するように調整されています。

## 元コミット内容

このコミットの目的は以下の2点です。

1.  スキャナーが不正な文字を検出してもエラーを返さずに処理を継続できるようにする。これにより、Go言語以外の文字を含む入力に対してもスキャナーを利用可能にする。
2.  上記変更に合わせて、パーサーを調整する。

## 変更の背景

Go言語のコンパイラやツールチェーンにおいて、ソースコードを処理する最初の段階は字句解析（スキャン）と構文解析（パース）です。通常、字句解析器（スキャナー）は、入力ストリームを読み込み、Go言語の文法規則に従ってトークン（識別子、キーワード、演算子、リテラルなど）に分割します。この過程で、Go言語の規則に合致しない文字（不正な文字）が検出された場合、スキャナーはエラーを報告し、多くの場合、処理を停止します。

しかし、Go言語のツール（例えば、IDEの構文ハイライト機能、コードフォーマッター、あるいはGo言語のコードを他の言語のコンテキストに埋め込むような特殊なケース）では、入力全体が厳密なGo言語の構文に従っているとは限りません。このようなシナリオでは、不正な文字が検出されたとしても、スキャナーがエラーで停止するのではなく、可能な限り処理を継続し、不正な文字を特定のトークンとして報告する方が望ましい場合があります。

このコミットは、このような柔軟な利用ケースに対応するために、スキャナーの挙動を制御する「モード」を導入し、不正な文字に対するエラー報告をオプション化することを目的としています。これにより、スキャナーはGo言語のコンパイラだけでなく、より広範なツールやアプリケーションで利用できる汎用的なコンポーネントとしての価値を高めます。

## 前提知識の解説

### 字句解析（Lexical Analysis / Scanning）
字句解析は、コンパイラのフロントエンドにおける最初の段階です。ソースコードの文字列を読み込み、意味のある最小単位である「トークン」の並びに変換します。例えば、`if x > 0 {` というコードは、`if` (キーワード)、`x` (識別子)、`>` (演算子)、`0` (整数リテラル)、`{` (区切り文字) といったトークンに分割されます。この処理を行うプログラムを「字句解析器」または「スキャナー（Scanner）」と呼びます。

### 構文解析（Syntactic Analysis / Parsing）
構文解析は、字句解析によって生成されたトークンの並びが、プログラミング言語の文法規則に合致しているかを検証し、通常は抽象構文木（AST: Abstract Syntax Tree）と呼ばれるツリー構造を構築します。この処理を行うプログラムを「構文解析器」または「パーサー（Parser）」と呼びます。パーサーは、トークンの並びが文法的に正しいかを判断し、エラーがあれば報告します。

### 不正な文字（Illegal Characters）
プログラミング言語の仕様では、ソースコードに使用できる文字が厳密に定義されています。例えば、Go言語の識別子には英数字とアンダースコアが使用できますが、`$`や`@`のような記号は通常、不正な文字と見なされます。スキャナーがこれらの不正な文字を検出した場合、それは字句エラーとなります。

### ビットマスク（Bitmask）
ビットマスクは、整数の個々のビットをフラグとして使用するプログラミング手法です。各ビットが特定のオプションや状態を表し、ビットごとのAND (`&`) やOR (`|`) 演算を使って、複数のオプションを効率的に設定したり、特定のオプションが設定されているかを確認したりできます。このコミットでは、スキャナーの挙動を制御するために、`mode`という`uint`型の変数にビットマスクとしてフラグを設定しています。

## 技術的詳細

このコミットの主要な変更点は、Go言語のスキャナー（`src/lib/go/scanner/scanner.go`）が、不正な文字を検出した際のエラー処理を制御するための新しいメカニズムを導入したことです。

1.  **スキャナーのモード導入**:
    *   以前は、コメントをトークンとして報告するかどうかを制御する`scan_comments bool`というブーリアン型のフィールドが`scanner.Scanner`構造体に存在しました。
    *   このコミットでは、`scan_comments bool`が`mode uint`という`uint`型（符号なし整数）のフィールドに置き換えられました。これにより、スキャナーの挙動を制御するための複数のフラグをビットマスクとして`mode`フィールドに格納できるようになります。
    *   新しい定数`ScanComments`と`AllowIllegalChars`が導入されました。これらは`iota`を使って定義されており、それぞれ異なるビット位置に対応するフラグとなります。
        ```go
        const (
            ScanComments = 1 << iota;  // return comments as COMMENT tokens
            AllowIllegalChars;  // do not report an error for illegal chars
        )
        ```
        `ScanComments`はコメントをトークンとして扱うかどうかを、`AllowIllegalChars`は不正な文字をエラーとして報告しないかどうかを制御します。

2.  **`Init`関数の変更**:
    *   `scanner.Init`関数のシグネチャが変更され、`scan_comments bool`引数が`mode uint`引数に置き換えられました。
    *   `S.scan_comments = scan_comments;`という行は`S.mode = mode;`に変わり、新しいモードがスキャナーの状態として設定されます。

3.  **コメント処理の変更**:
    *   スキャナーの`Scan`メソッド内でコメントをスキップするかどうかの判定ロジックが、`if !S.scan_comments {`から`if S.mode & ScanComments == 0 {`に変更されました。これは、`mode`フィールドの`ScanComments`ビットが立っていない（つまり、コメントをトークンとして扱わない）場合にコメントをスキップするという意味です。

4.  **不正な文字処理の変更**:
    *   最も重要な変更は、`scanner.Scan`メソッド内の`default`ケース（Go言語の有効なトークンにマッチしない文字が検出された場合）です。
    *   以前は、`S.error(pos, "illegal character " + charString(ch));`と直接エラーを報告していました。
    *   変更後、このエラー報告の前に`if S.mode & AllowIllegalChars == 0 {`という条件が追加されました。これは、`mode`フィールドの`AllowIllegalChars`ビットが立っていない（つまり、不正な文字を許可しない）場合にのみエラーを報告するという意味です。`AllowIllegalChars`ビットが立っている場合、スキャナーは不正な文字を検出してもエラーを報告せず、処理を継続します。

5.  **パーサーの調整**:
    *   `src/lib/go/parser/parser.go`では、`Parse`関数がスキャナーを初期化する際に、新しい`scannerMode`ヘルパー関数を導入しました。
    *   `scannerMode`関数は、パーサーのモードビット（`ParseComments`など）を受け取り、それをスキャナーの新しい`uint`型モードに変換します。これにより、パーサーはスキャナーの新しいモードインターフェースに適合し、以前と同様にコメントの扱いを制御できるようになります。
    *   `p.scanner.Init(data, &p, mode & ParseComments != 0);`という行は、`p.scanner.Init(data, &p, scannerMode(mode));`に変更されました。

6.  **テストの追加と更新**:
    *   `src/lib/go/scanner/scanner_test.go`では、既存のテストが新しい`scanner.ScanComments`フラグを使用するように更新されました。
    *   `TestIllegalChars`という新しいテスト関数が追加されました。このテストでは、`*?*$*@*`のような不正な文字を含む文字列を`scanner.AllowIllegalChars`モードでスキャンし、エラーが報告されないことを検証しています。これは、このコミットの意図を直接的に確認する重要なテストです。

これらの変更により、Go言語のスキャナーは、Go言語の厳密な構文解析だけでなく、より柔軟な字句解析のニーズにも対応できる、汎用性の高いコンポーネントへと進化しました。

## コアとなるコードの解説

### `scanner.go` の変更

*   **`Scanner`構造体の変更**: `scan_comments bool`フィールドが`mode uint`に置き換えられたことで、スキャナーの挙動を制御するフラグが単一の整数値で管理されるようになりました。これは、将来的にさらに多くのオプションを追加する際の拡張性を高めます。
*   **`const`定義**: `ScanComments`と`AllowIllegalChars`というビットフラグが導入されました。`ScanComments`は以前の`scan_comments`の役割を引き継ぎ、コメントをトークンとして扱うかどうかを制御します。`AllowIllegalChars`は、このコミットの主要な目的である「不正な文字をエラーとして報告しない」という新しい挙動を制御します。
*   **`Init`関数の変更**: `Init`関数のシグネチャが`scan_comments bool`から`mode uint`に変更されたことで、スキャナーの初期化時に複数の挙動オプションを一度に設定できるようになりました。
*   **コメント処理ロジックの変更**: `if !S.scan_comments`が`if S.mode & ScanComments == 0`に変更されたのは、ブーリアンフラグからビットマスクフラグへの移行に伴う自然な変更です。`&`演算子を使って、`mode`に`ScanComments`ビットが設定されているか（つまり、コメントをトークンとして扱うか）をチェックしています。`== 0`はビットが立っていない状態、つまりコメントをスキップする状態を意味します。
*   **不正な文字処理ロジックの変更**: `default: S.error(...)`の前に`if S.mode & AllowIllegalChars == 0`という条件が追加されたのが、このコミットの最も重要な機能変更点です。
    *   `S.mode & AllowIllegalChars`が`0`でない場合（つまり、`AllowIllegalChars`フラグが設定されている場合）、`if`ブロックは実行されず、`S.error`は呼び出されません。これにより、スキャナーは不正な文字を検出してもエラーを報告せず、処理を継続します。
    *   `S.mode & AllowIllegalChars`が`0`の場合（つまり、`AllowIllegalChars`フラグが設定されていない場合）、`if`ブロックが実行され、`S.error`が呼び出されて不正な文字がエラーとして報告されます。これは、従来の厳密なGo言語の構文解析の挙動を維持します。

### `parser.go` の変更

*   **`scannerMode`関数の追加**: パーサーは、スキャナーの新しい`uint`型モードに直接対応するために、`scannerMode`というヘルパー関数を導入しました。この関数は、パーサー自身のモード（例えば`ParseComments`）をスキャナーの対応するモードビットに変換します。これにより、パーサーはスキャナーの内部実装の詳細に依存することなく、スキャナーの挙動を制御できます。
*   **`p.scanner.Init`の呼び出し変更**: `p.scanner.Init`の呼び出しが`mode & ParseComments != 0`というブーリアン値から`scannerMode(mode)`という`uint`値に変更されました。これは、スキャナーの`Init`関数のシグネチャ変更に合わせた調整です。

### `scanner_test.go` の変更

*   **既存テストの更新**: 既存のテストは、スキャナーの`Init`関数と`Tokenize`関数のシグネチャ変更に合わせて、`true`や`false`の代わりに`scanner.ScanComments`フラグを使用するように更新されました。
*   **`TestIllegalChars`の追加**: この新しいテストは、`scanner.AllowIllegalChars`モードが正しく機能することを確認します。`*?*$*@*`のようなGo言語では不正な文字を含む文字列をスキャンし、`s.ErrorCount`が`0`であることをアサートすることで、エラーが報告されないことを検証しています。これは、このコミットが意図した新しい柔軟な挙動を直接的にテストするものです。

これらの変更は、Go言語のスキャナーが、単なるコンパイラのフロントエンドとしてだけでなく、より多様なツールやアプリケーションのニーズに応えるための基盤を築いたことを示しています。特に、不正な文字をエラーとして扱わないオプションは、構文ハイライトやコード補完など、部分的なコードや不完全なコードを扱うツールにとって非常に有用です。
