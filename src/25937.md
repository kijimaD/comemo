## 元コミット内容

このコミットの元の内容は、`archive/tar` パッケージにおけるGNU base-256エンコーディングの適切なフォーマットに関するものです。主な動機は以下の2点でした。

1.  **整数オーバーフロー時のサイレントな失敗の修正**: 以前の実装では、数値がオーバーフローした場合にエラーを報告せず、サイレントに失敗していました。このコミットにより、`ErrFieldTooLong` エラーが報告されるようになりました。
2.  **負の数のエンコードのサポート**: 以前の実装では、GNU tarの仕様である2の補数形式でのエンコードに対応しておらず、負の数を正しくエンコードできませんでした。このコミットにより、2の補数形式での負の数のエンコードが可能になりました。

GNU tarの仕様では、「GNU形式は、標準のustar範囲に収まらない値を格納するために、2の補数base-256表記を使用する」と明記されており、このコミットはこの仕様に準拠するための変更です。

## 変更の背景

tarアーカイブ形式には、ustar、pax、GNU tarなどいくつかのバリエーションがあります。ustar形式では、ファイルサイズやUID/GIDなどの数値フィールドは通常、8進数で表現されます。しかし、8進数表現には格納できる数値の範囲に限界があります。特に大きなファイルサイズやUID/GIDを扱う場合、ustarの8進数フィールドでは表現しきれないことがあります。

GNU tar形式は、この制限を克服するために、より大きな数値を格納するための拡張として「base-256エンコーディング」を導入しました。このエンコーディングは、数値を256進数（つまりバイト列）として直接表現するもので、特に負の数を扱う際には2の補数表現を使用するという特徴があります。

このコミット以前のGoの `archive/tar` パッケージの実装では、GNU tarのbase-256エンコーディングに関して以下の問題がありました。

*   **オーバーフロー時の不適切な挙動**: 数値が指定されたフィールド幅に収まらない場合、実装はサイレントに切り捨てを行うか、予期しない値を書き込んでいました。これは、アーカイブの破損やデータの不整合につながる可能性がありました。
*   **負の数の未サポート**: GNU tarのbase-256エンコーディングは2の補数表現を要求しますが、Goの実装はこの要件を満たしておらず、負の数値を正しくエンコードできませんでした。これにより、負のUID/GIDなどを持つファイルをGNU tar形式でアーカイブする際に問題が生じていました。

これらの問題は、Goの `archive/tar` パッケージがGNU tar形式のアーカイブを生成する際の互換性と堅牢性を低下させていました。このコミットは、これらの問題を解決し、GNU tarの仕様に完全に準拠したbase-256エンコーディングを実装することを目的としています。

## 前提知識の解説

### tarアーカイブ形式

`tar` (tape archive) は、複数のファイルを1つのアーカイブファイルにまとめるためのファイル形式およびユーティリティです。Unix系システムで広く使われています。tarファイルは、ファイルデータと、ファイル名、パーミッション、タイムスタンプ、所有者情報などのメタデータ（ヘッダ）の連続で構成されます。

### ustar, pax, GNU tar

tar形式にはいくつかの標準と拡張があります。

*   **ustar (POSIX.1-1988)**: 最も基本的なtar形式の一つで、ファイル名、サイズ、UID/GIDなどのフィールドに固定長の8進数表現を使用します。フィールド長に制限があるため、大きなファイルや長いパス名には対応できません。
*   **GNU tar**: GNUプロジェクトによって開発されたtarの拡張で、ustarの制限を克服するためにいくつかの新しいフィールドやエンコーディングを導入しました。特に、大きなファイルサイズやUID/GIDを扱うためにbase-256エンコーディングを使用します。
*   **pax (POSIX.1-2001)**: POSIXによって標準化されたtarの拡張で、ustarの制限を克服するために拡張ヘッダレコードを使用します。これは、任意の長さのメタデータをキーと値のペアで格納できる柔軟な形式です。

### base-256エンコーディング

GNU tar形式におけるbase-256エンコーディングは、ustarの8進数フィールドでは表現できない大きな数値を格納するための方法です。これは、数値をバイト列として直接表現するもので、各バイトが256進数の桁に対応します。

重要な特徴は以下の通りです。

*   **2の補数表現**: 負の数をエンコードする際に、2の補数表現を使用します。これは、コンピュータが負の整数を表現する標準的な方法であり、最上位ビットが符号ビットとして機能します。
*   **最上位ビット (MSB) の利用**: GNU tarのbase-256エンコーディングでは、数値フィールドの最初のバイトの最上位ビット (0x80) がセットされている場合、そのフィールドがbase-256形式でエンコードされていることを示します。これにより、8進数フィールドとbase-256フィールドを区別できます。

### 2の補数 (Two's Complement)

2の補数表現は、コンピュータで負の整数を表現するために広く用いられる方法です。Nビットの2の補数表現では、正の数は通常の2進数と同じですが、負の数は以下のように計算されます。

1.  対応する正の数の2進数表現を反転（ビットを0と1を入れ替える）。
2.  結果に1を加える。

例えば、8ビットで-1を表現する場合：
1.  +1 は `00000001`
2.  反転すると `11111110`
3.  1を加えると `11111111` となります。

この表現の利点は、加算と減算が同じハードウェアで処理できる点です。最上位ビットが1であれば負の数、0であれば正の数（またはゼロ）を示します。

## 技術的詳細

このコミットの核となる変更は、`src/archive/tar/writer.go` 内の `formatNumeric` 関数と、新しく導入された `fitsInBase256` 関数にあります。

### `fitsInBase256` 関数

```go
// fitsInBase256 reports whether x can be encoded into n bytes using base-256
// encoding. Unlike octal encoding, base-256 encoding does not require that the
// string ends with a NUL character. Thus, all n bytes are available for output.
//
// If operating in binary mode, this assumes strict GNU binary mode; which means
// that the first byte can only be either 0x80 or 0xff. Thus, the first byte is
// equivalent to the sign bit in two's complement form.
func fitsInBase256(n int, x int64) bool {
	var binBits = uint(n-1) * 8
	return n >= 9 || (x >= -1<<binBits && x < 1<<binBits)
}
```

この関数は、与えられた `int64` 型の数値 `x` が、`n` バイト幅のbase-256フィールドに収まるかどうかを判定します。

*   `n >= 9` の条件: tarヘッダの数値フィールドは通常8バイトです。しかし、GNU tarの拡張では、より大きな数値を格納するために、フィールド幅が9バイト以上になることがあります。この条件は、フィールド幅が十分に大きい場合（9バイト以上）は、`int64` の範囲内のすべての値が収まることを意味します。`int64` は8バイト（64ビット）なので、9バイトあれば符号ビットを含めて表現可能です。
*   `binBits` の計算: `uint(n-1) * 8` は、符号ビットを除く残りの `n-1` バイトが表現できるビット数を計算します。例えば、`n=8` の場合、`binBits` は `(8-1)*8 = 56` となります。これは、8バイトフィールドのうち1バイトが符号とbase-256フラグに使われ、残りの7バイト（56ビット）が数値の絶対値を表現するために使われることを示唆しています。
*   `x >= -1<<binBits && x < 1<<binBits` の条件: これは、`x` が `binBits` で表現できる2の補数範囲内に収まっているかをチェックします。
    *   `1<<binBits` は `2^binBits` を意味し、`binBits` で表現できる正の数の最大値（+1）の1つ上です。
    *   `-1<<binBits` は `-(2^binBits)` を意味し、`binBits` で表現できる負の数の最小値です。
    *   この範囲チェックにより、`x` が指定されたバイト幅でオーバーフローせずに表現できるかを確認します。

2.  **2の補数エンコーディング**:

3.  **GNU base-256フラグ**: `b[0] |= 0x80` は、最初のバイトの最上位ビットをセットします。これは、このフィールドがGNU base-256形式でエンコードされていることを示すフラグです。
4.  **エラーハンドリング**: `fitsInBase256` が `false` を返した場合（つまり、数値がフィールドに収まらない場合）、`f.formatOctal(b, 0)` を呼び出してフィールドをゼロで埋め、`f.err = ErrFieldTooLong` を設定してエラーを報告します。これにより、サイレントな失敗が防止されます。

## コアとなるコードの解説

### `fitsInBase256` 関数

この関数は、与えられた数値 `x` が `n` バイトのフィールドに2の補数base-256形式で収まるかを効率的に判定します。

*   `var binBits = uint(n-1) * 8`: ここで `n-1` としているのは、GNU base-256エンコーディングでは、フィールドの最初のバイトが符号とbase-256フラグ（0x80）を兼ねるため、実質的に数値を表現するために使えるバイト数が1つ減ることを考慮しているためです。例えば、8バイトフィールドの場合、7バイト（56ビット）が数値の絶対値を表現するために使われます。
*   `return n >= 9 || (x >= -1<<binBits && x < 1<<binBits)`:
    *   `n >= 9` の部分は、フィールド幅が9バイト以上であれば、`int64` の全ての値（64ビット）が収まるため、常に `true` を返します。`int64` は符号付き64ビット整数であり、9バイト（72ビット）あれば確実に表現できます。
    *   `(x >= -1<<binBits && x < 1<<binBits)` の部分は、`x` が `binBits` で表現できる2の補数範囲内に収まっているかをチェックします。
        *   `1<<binBits` は `2^binBits` を計算し、これは `binBits` で表現できる正の数の最大値に1を加えたものです。
        *   `-1<<binBits` は `-(2^binBits)` を計算し、これは `binBits` で表現できる負の数の最小値です。
        *   この範囲チェックにより、`x` が指定されたバイト幅でオーバーフローせずに表現できるかを確認します。

### `formatNumeric` 関数

この関数は、`int64` 型の数値 `x` をGNU base-256形式のバイト列 `b` に書き込みます。

1.  **`if fitsInBase256(len(b), x)`**: まず、`fitsInBase256` を呼び出して、`x` が `b` の長さに収まるかを確認します。
2.  **エンコーディングループ**:
    *   `for i := len(b) - 1; i >= 0; i--`: ループはバイト配列 `b` の末尾から先頭に向かって実行されます。これは、数値の最下位バイトから順に書き込むためです。
    *   `b[i] = byte(x)`: `x` の現在の最下位バイトを `b[i]` に書き込みます。Goでは、`int64` を `byte` にキャストすると、その値の最下位8ビットが取得されます。
    *   `x >>= 8`: `x` を右に8ビットシフトします。これにより、次のループイテレーションでは、`x` の次の8ビットが最下位バイトとして扱われます。
    *   このループは、`x` が正か負かに関わらず、2の補数表現のバイト列を正しく生成します。例えば、-1 (0xFFFFFFFFFFFFFFFF) をエンコードする場合、最初のバイトは0xFF、次のバイトも0xFF...となります。
3.  **GNU base-256フラグの設定**: `b[0] |= 0x80`: エンコードが完了した後、最初のバイトの最上位ビットをセットします。これは、このフィールドがGNU base-256形式であることを示すマーカーです。
4.  **エラー処理**: `fitsInBase256` が `false` を返した場合、つまり数値がフィールドに収まらない場合は、`f.formatOctal(b, 0)` を呼び出してフィールドをゼロで埋め、`f.err = ErrFieldTooLong` を設定します。これにより、呼び出し元はエンコードが失敗したことを検知できます。

これらの変更により、`archive/tar` パッケージはGNU tar形式のbase-256エンコーディングを正確かつ堅牢に処理できるようになり、特に負の数値や大きな数値のアーカイブにおける互換性が向上しました。
