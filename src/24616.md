# [インデックス 24616] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおいて、分岐予測の概念を導入する初期実装です。具体的には、コンパイラが生成するコードの性能を向上させるため、条件分岐がどちらのパスに進む可能性が高いかという「尤度 (likeliness)」の情報をSSAブロックに付与し、それに基づいてコードのレイアウトや命令生成を最適化する基盤を構築しています。これにより、CPUの分岐予測ミスによるパイプラインストールを減らし、実行速度の向上が期待されます。

## 変更の背景

このコミットの主な背景は、Goコンパイラが生成するバイナリの実行性能を向上させることにあります。現代のCPUは、パイプライン処理と投機的実行によって高い性能を実現していますが、条件分岐の予測ミス（分岐予測ミス）が発生すると、パイプラインがフラッシュされ、大きな性能ペナルティが発生します。

コンパイラは、プログラムの構造やヒューリスティックに基づいて、特定の分岐がどちらのパスに進む可能性が高いかを予測できます。この「分岐の尤度 (likely direction)」の情報をコンパイラの中間表現（この場合はSSA）に組み込むことで、以下の最適化が可能になります。

1.  **コードレイアウトの最適化**: 可能性の高いパスのコードを物理的に近くに配置することで、CPUの命令キャッシュヒット率を高め、プリフェッチを効率化できます。
2.  **アセンブリ命令の選択**: 一部のアーキテクチャでは、分岐予測のヒントをOSやハードウェアに伝えるための特別な命令や命令プレフィックスが存在します。コンパイラがこの情報を利用することで、より効率的なアセンブリコードを生成できます。

このコミットは、GoコンパイラがSSAバックエンドに移行する過程で、このような重要な最適化の基盤を築くための初期ステップとして導入されました。`src/cmd/compile/internal/ssa/TODO` ファイルの変更からも、「Branch prediction: Respect hints from the frontend, add our own」という項目が「Add branch predictions」に更新されており、この機能がSSA最適化の重要な目標の一つであったことが伺えます。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSA形式は、コンパイラの中間表現（IR）の一種で、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が大幅に簡素化されます。

*   **特徴**:
    *   すべての変数定義がユニークである。
    *   複数の制御フローパスが合流する点（Φ関数と呼ばれる特別な命令）で、異なるパスからの値を結合する。
*   **利点**:
    *   データフロー解析が容易になる（例: どの定義がどの使用に到達するかを簡単に追跡できる）。
    *   多くの最適化（共通部分式除去、定数伝播、デッドコード除去など）がより効果的に適用できる。
    *   レジスタ割り当ての効率が向上する。

Goコンパイラは、従来のAST (Abstract Syntax Tree) ベースのコンパイルから、より高度な最適化を可能にするSSA形式への移行を進めていました。このコミットは、そのSSAバックエンドにおける重要な機能追加です。

### 2. 分岐予測 (Branch Prediction)

分岐予測は、現代のマイクロプロセッサがプログラムの条件分岐（`if`文、`for`ループなど）が次にどちらのパスに進むかを推測する技術です。

*   **必要性**: CPUは命令パイプラインを使って複数の命令を同時に処理しますが、条件分岐に遭遇すると、次にどの命令を実行すべきか確定できません。もしCPUが分岐の結果を待ってから次の命令をフェッチすると、パイプラインが停止し、性能が大幅に低下します。
*   **動作**: CPUは過去の実行履歴やヒューリスティックに基づいて、分岐が「取られる (taken)」か「取られない (not taken)」かを予測し、予測したパスの命令を投機的に実行します。
*   **予測ミス (Misprediction)**: 予測が外れた場合、投機的に実行された命令は破棄され、正しいパスの命令を最初からフェッチし直す必要があります。このペナルティは非常に大きく、数十サイクルから数百サイクルに及ぶことがあります。
*   **コンパイラの役割**: コンパイラは、プログラムの静的な情報（ループの構造、特定のAPI呼び出しなど）から分岐の尤度を推測し、そのヒントを生成される機械語コードに埋め込むことができます。これにより、ハードウェアの分岐予測器を補助し、全体的な予測精度を向上させることが期待されます。

### 3. Goコンパイラの構造 (`cmd/compile`)

Goコンパイラは `cmd/compile` ディレクトリにあります。その内部は大きく分けて以下のフェーズで構成されます。

*   **フロントエンド (`internal/gc`)**: ソースコードのパース、ASTの構築、型チェック、一部の初期最適化などを行います。このフェーズで、元のGoコードの構造から分岐の尤度に関する初期ヒントが生成されることがあります。
*   **ミドルエンド/バックエンド (`internal/ssa`)**: ASTをSSA形式に変換し、SSAベースの最適化（このコミットで導入される分岐予測に基づく最適化も含む）を実行します。最終的に、SSA形式から特定アーキテクチャの機械語コードを生成します。

### 4. 基本ブロック (Basic Block)

基本ブロックは、制御フローグラフ (CFG) の基本的な構成要素です。

*   **定義**:
    *   単一のエントリポイント（最初の命令）を持つ。
    *   単一のイグジットポイント（最後の命令）を持つ。
    *   エントリポイントとイグジットポイントの間には、分岐命令を含まない。
*   **役割**: プログラムの実行パスを線形なシーケンスに分割することで、コンパイラがコードの解析や最適化を構造的に行えるようにします。条件分岐は、複数の基本ブロックへのエッジ（遷移）として表現されます。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドに分岐予測の概念を導入し、その情報をコンパイルパイプライン全体で利用可能にするための基盤を構築しています。

1.  **`ssa.Block` 構造体への `Likely` フィールドの追加**:
    *   `src/cmd/compile/internal/ssa/block.go` に `Block` 構造体が定義されており、これに `Likely BranchPrediction` というフィールドが追加されました。
    *   `Likely` フィールドは、そのブロックの制御フロー操作（条件分岐など）がどちらのサクセッサ（後続ブロック）に進む可能性が高いかを示します。
    *   `BranchPrediction` 型は `int8` のエイリアスで、以下の定数が定義されています。
        *   `BranchUnlikely = -1`: `Succs[1]` がより可能性が高い。
        *   `BranchUnknown = 0`: 予測不能、または予測情報がない。
        *   `BranchLikely = +1`: `Succs[0]` がより可能性が高い。
    *   このフィールドは、`len(Succs) < 2` の場合は無視され、`len(Succs) > 2` の場合は `BranchUnknown` でなければならないという制約が `check.go` で追加されています。これは、通常、条件分岐は2つのパスしか持たないためです。

2.  **`gc` フロントエンドからの `Likely` ヒントの伝播**:
    *   `src/cmd/compile/internal/gc/ssa.go` は、ASTからSSA形式への変換を担当します。
    *   `stmt` 関数内で `ssa.BlockIf` を生成する際に、ASTノード `n` の `n.Likely` フィールド（Go言語のフロントエンドが持つ分岐の尤度情報）を `b.Likely` にコピーするようになりました。これにより、フロントエンドで得られたヒントがSSAバックエンドに引き継がれます。
    *   `nilCheck` や `boundsCheck` のようなランタイムチェックのブロックでは、デフォルトで `ssa.BranchLikely` が設定されています。これは、これらのチェックが失敗する（パニックする）ことは稀であり、通常はチェックを通過するパスが実行されると予測されるためです。

3.  **`rulegen.go` における分岐予測の更新**:
    *   `src/cmd/compile/internal/ssa/gen/rulegen.go` は、SSAの最適化ルールを生成するツールです。
    *   ブロックのサクセッサが変更された場合（例: `Succs[0]` と `Succs[1]` が入れ替わった場合）、`b.Likely` の値も適切に更新されるロジックが追加されました。具体的には、サクセッサが入れ替わった場合は `b.Likely *= -1` となり、予測方向が反転します。サクセッサの数が2以外になった場合は `BranchUnknown` にリセットされます。

4.  **`layout.go` におけるブロックスケジューリングへの利用**:
    *   `src/cmd/compile/internal/ssa/layout.go` は、SSAブロックを物理メモリ上でどのように配置するか（コードレイアウト）を決定します。これは、命令キャッシュの効率や分岐予測の精度に直接影響します。
    *   このコミットでは、`b.Likely` の情報を使って、次にスケジュールすべきブロックを決定するロジックが追加されました。`BranchLikely` であれば `Succs[0]` を、`BranchUnlikely` であれば `Succs[1]` を優先的にスケジュールしようとします。これにより、可能性の高い実行パスのコードが連続して配置され、CPUのプリフェッチやキャッシュの効率が向上します。

5.  **`rewritegeneric.go` における分岐予測の調整**:
    *   `src/cmd/compile/internal/ssa/rewritegeneric.go` は、SSAブロックの書き換え（最適化）ルールを定義しています。
    *   ブロックのサクセッサが変更されるような書き換えが行われた場合、`b.Likely` の値も適切に調整されるようになりました。例えば、`if cond then no else yes` のようなブロックが `if !cond then yes else no` のように反転された場合、`b.Likely *= -1` となり、予測方向が反転します。

6.  **`gc/ssa.go` におけるアセンブリ生成時のヒント伝達 (AMD64)**:
    *   `genBlock` 関数（AMD64アーキテクチャ向け）では、条件分岐命令を生成する際に、`b.Likely` の情報が `liblink` (Goリンカ) に渡されるようになりました。
    *   具体的には、生成される `obj.Prog` (プログラム命令) の `p.From.Type` を `obj.TYPE_CONST` に、`p.From.Offset` を `0` (Unlikely) または `1` (Likely) に設定しています。これは、リンカが最終的なバイナリを生成する際に、この分岐予測ヒントを利用してコードレイアウトをさらに最適化したり、特定のCPUアーキテクチャの分岐予測機構に情報を伝えたりするためです。
    *   コメントには「liblink reorders the instruction stream as it sees fit. Pass along what we know so liblink can make use of it.」とあり、リンカが命令ストリームを再配置する際にこの情報が役立つことが示唆されています。

このコミットは、Goコンパイラがより高度なプロファイルに基づく最適化（PGO: Profile-Guided Optimization）や、より洗練された静的解析に基づく最適化を将来的に導入するための重要な一歩となります。

## コアとなるコードの解説

このコミットの最も核となる変更は、`src/cmd/compile/internal/ssa/block.go` における `ssa.Block` 構造体への `Likely` フィールドの追加と、それに伴う `BranchPrediction` 型の導入です。

```go
// src/cmd/compile/internal/ssa/block.go
type Block struct {
	// ... 既存のフィールド ...

	// Likely direction for branches.
	// If BranchLikely, Succs[0] is the most likely branch taken.
	// If BranchUnlikely, Succs[1] is the most likely branch taken.
	// Ignored if len(Succs) < 2.
	// Fatal if not BranchUnknown and len(Succs) > 2.
	Likely BranchPrediction
}

type BranchPrediction int8

const (
	BranchUnlikely = BranchPrediction(-1)
	BranchUnknown  = BranchPrediction(0)
	BranchLikely   = BranchPrediction(+1)
)
```

この `Likely` フィールドは、GoコンパイラのSSA中間表現において、各条件分岐ブロックがどのパスに進む可能性が高いかという情報を保持するためのものです。

1.  **情報の源**: `src/cmd/compile/internal/gc/ssa.go` では、Go言語のASTからSSA形式への変換時に、フロントエンドが持つ `n.Likely` というヒントを `b.Likely` にコピーしています。これは、Go言語の特定の構文（例: `if` 文の条件式）から静的に推測される尤度情報です。また、`nil` チェックや境界チェックのようなランタイムチェックでは、通常は成功する（パニックしない）パスが実行されると予測されるため、明示的に `ssa.BranchLikely` が設定されます。

2.  **最適化への利用**:
    *   **コードレイアウト (`src/cmd/compile/internal/ssa/layout.go`)**: `layout.go` は、SSAブロックを最終的な機械語コードのメモリ上でどのように配置するかを決定します。`Likely` フィールドが `BranchLikely` であれば `Succs[0]` を、`BranchUnlikely` であれば `Succs[1]` を優先的に現在のブロックの直後に配置しようとします。これにより、可能性の高い実行パスの命令が連続して配置され、CPUの命令キャッシュの効率が向上し、分岐予測ミスによるペナルティが軽減されます。
    *   **アセンブリ生成時のヒント (`src/cmd/compile/internal/gc/ssa.go` の `genBlock` 関数)**: AMD64アーキテクチャ向けのアセンブリコード生成において、`genBlock` 関数は `b.Likely` の値を利用して、生成される分岐命令 (`obj.Prog`) の `p.From.Offset` に `0` (Unlikely) または `1` (Likely) を設定します。この情報は `liblink` (Goリンカ) に渡され、リンカが最終的なバイナリを生成する際に、このヒントを基にさらにコードレイアウトを最適化したり、特定のCPUアーキテクチャの分岐予測機構に情報を伝えたりする可能性があります。

3.  **一貫性の維持**:
    *   `src/cmd/compile/internal/ssa/gen/rulegen.go` や `src/cmd/compile/internal/ssa/rewritegeneric.go` では、SSAの最適化ルールが適用され、ブロックの構造（特にサクセッサの順序）が変更されることがあります。これらの変更箇所では、`b.Likely` の値が常に現在のブロック構造と一貫するように、適切に更新されるロジックが追加されています。例えば、サクセッサの順序が反転した場合は `b.Likely *= -1` とすることで、予測方向も反転させます。
    *   `src/cmd/compile/internal/ssa/check.go` では、`Likely` フィールドの不正な使用を防ぐためのバリデーションが追加されており、`len(b.Succs) > 2` のブロックでは `Likely` が `BranchUnknown` でなければならないという制約が課されています。

これらの変更により、Goコンパイラはプログラムの実行フローに関するより深い理解を持ち、その情報を利用してより高性能な機械語コードを生成するための重要な基盤が確立されました。
