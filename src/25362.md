# [インデックス 25362] ファイルの概要

このコミットは、Goランタイムのメモリ管理において、`mspan`のリスト表現方法を改善し、メモリ使用量を削減することを目的としています。具体的には、リストのヘッドとして`mspan`構造体自体を使用する代わりに、専用の`mSpanList`型を導入しています。これにより、`mheap`構造体のサイズが大幅に縮小されました。

## 変更の背景

Goランタイムのメモリ管理システムでは、`mspan`という構造体がメモリのチャンク（ページ群）を表現し、これらの`mspan`は様々なリスト（例えば、空きオブジェクトを持つスパンのリスト、空きオブジェクトがないスパンのリストなど）に組織化されています。以前の実装では、これらのリストのヘッド（先頭）として、実体のない（空の）`mspan`構造体自体が使用されていました。

しかし、`mspan`構造体はamd64アーキテクチャで112バイトと比較的大きなサイズを持っていました。リストのヘッドとしてこの大きな構造体を使用することは、特に`mheap`のような多数のリストを管理する構造体において、不要なメモリ消費を引き起こしていました。`mheap`は、様々なサイズの空き`mspan`リストや使用中`mspan`リストを保持するため、多数の`mspan`をリストヘッドとして持つことになり、その結果`mheap`構造体全体のサイズが肥大化していました。

このコミットの主な目的は、このメモリオーバーヘッドを削減することです。専用の`mSpanList`型を導入することで、リストヘッドに必要な情報（先頭と末尾へのポインタ）のみを保持し、`mspan`構造体全体のサイズをリストヘッドのために確保する必要がなくなりました。これにより、`mheap`のサイズを大幅に削減し、ランタイム全体のメモリ効率を向上させることが背景にあります。

また、以前の循環双方向連結リストからテールキュー（tail queue）への変更は、型安全性の向上と、リスト操作のロジックをより明確にする意図も含まれています。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムのメモリ管理に関する概念とデータ構造の知識が必要です。

1.  **Goのメモリ管理（GC）**: Goは自動ガベージコレクション（GC）を採用しており、開発者が手動でメモリを解放する必要はありません。ランタイムはヒープメモリを管理し、オブジェクトの割り当てと解放を行います。
2.  **`mspan`**: `mspan`はGoランタイムのメモリ管理における基本的な単位です。これは、連続した物理メモリページ（通常は8KBの倍数）のチャンクを表します。`mspan`は、特定のサイズのオブジェクトを格納するために使用されたり、スタックとして使用されたり、空きメモリとして管理されたりします。各`mspan`は、その状態（使用中、スタック、空きなど）、ページ数、フリーリスト（内部の空きオブジェクトのリスト）などの情報を持っています。
3.  **`mheap`**: `mheap`はGoランタイム全体のヒープメモリを管理するグローバルな構造体です。様々なサイズの`mspan`を管理するためのフリーリスト（`free`、`freelarge`）と、使用中の`mspan`を管理するためのビジーリスト（`busy`、`busylarge`）を保持しています。
4.  **`mcentral`**: `mcentral`は、特定のサイズクラス（例えば、8バイトオブジェクト用、16バイトオブジェクト用など）の`mspan`を管理する構造体です。`mheap`から`mspan`を取得し、それを`mcache`（各P（プロセッサ）にローカルなキャッシュ）に提供します。`mcentral`は、空きオブジェクトを持つ`mspan`のリスト（`nonempty`）と、空きオブジェクトがない`mspan`のリスト（`empty`）を保持しています。
5.  **連結リスト（Linked List）**: データを線形に並べたデータ構造で、各要素が次の要素（双方向連結リストの場合は前の要素も）へのポインタを持っています。
    *   **循環双方向連結リスト（Circular Doubly Linked List）**: リストの最後の要素が最初の要素を指し、最初の要素が最後の要素を指す形式の双方向連結リストです。リストのヘッドも通常の要素と同様に扱われ、`head.next`が最初の要素、`head.prev`が最後の要素を指します。このコミット以前は、`mspan`のリストはこの形式で実装されており、リストヘッドとして空の`mspan`が使われていました。
    *   **テールキュー（Tail Queue）**: BSDでよく使われる連結リストの一種で、リストの先頭と末尾へのポインタを明示的に持つことで、両端からの高速な挿入・削除を可能にします。このコミットでは、型安全性を高めるためにこの形式に移行しています。テールキューは通常、リストのヘッド構造体が`first`（先頭要素へのポインタ）と`last`（末尾要素の`next`フィールドへのポインタ）を持ちます。

## 技術的詳細

このコミットの核心は、`mspan`のリスト管理方法を根本的に変更した点にあります。

1.  **`mSpanList`型の導入**:
    *   以前は、`mcentral`や`mheap`内の`mspan`リストのヘッドとして、`mspan`構造体自体が使用されていました。これは、`mspan`が`next`と`prev`ポインタを持つ双方向連結リストの要素として機能していたためです。リストが空の場合でも、`head.next = head`、`head.prev = head`のように自身を指すことで循環リストを表現していました。
    *   新しく導入された`mSpanList`型は、リストのヘッド専用の構造体です。
        ```go
        type mSpanList struct {
            first *mspan  // first span in list, or nil if none
            last  **mspan // last span's next field, or first if none
        }
        ```
        `first`はリストの最初の`mspan`へのポインタ、`last`はリストの最後の`mspan`の`next`フィールドへのポインタ（またはリストが空の場合は`first`フィールドへのポインタ）を保持します。これにより、リストの先頭と末尾へのアクセスが効率的になります。

2.  **循環連結リストからテールキューへの移行**:
    *   以前の循環双方向連結リストでは、リストのヘッドも`mspan`型であり、`mspan`の`next`と`prev`フィールドがリストの構造を形成していました。
    *   `mSpanList`の導入により、リストの構造はテールキューに変わりました。テールキューは、リストの先頭と末尾を直接指すポインタを持つことで、リストの操作をより効率的かつ型安全に行うことができます。
    *   この変更により、`mSpanList_Remove`関数は、どの`mSpanList`から`mspan`を削除するのかを知る必要が生じました。これは、`mspan`が複数のリストに属する可能性がないため、常に計算可能であると判断されています。

3.  **メモリ使用量の削減**:
    *   `mspan`構造体はamd64で112バイトです。以前は、`mheap`や`mcentral`内の各リストヘッドがこの112バイトを消費していました。
    *   `mSpanList`は`*mspan`と`**mspan`の2つのポインタのみを持つため、amd64で16バイト（ポインタサイズが8バイトの場合）です。
    *   コミットメッセージによると、この変更により`mheap`のサイズが50216バイトから12584バイトへと大幅に削減されました。これは、`mheap`が多数の`mspan`リスト（`free`、`freelarge`、`busy`、`busylarge`など）を保持しているため、リストヘッドのサイズ削減が全体に大きな影響を与えたことを示しています。

4.  **型安全性とデバッグ**:
    *   `mSpanList`を導入することで、リストヘッドとリスト要素（`mspan`）の役割が明確に分離され、型安全性が向上します。
    *   一時的な健全性チェックとして、`mSpanList_Insert`と`mSpanList_InsertBack`は、`mspan`が挿入されたリストを`span.list`フィールドに記録するようになりました。これにより、`mSpanList_Remove`が正しいリストから削除しようとしているかを検証できます。これはデバッグ目的であり、最終的には削除される予定です（`TODO: Remove.`のコメントがあるため）。

3.  **`src/runtime/stack.go`**:
    *   `stackpool`と`stackFreeQueue`の型が`mspan`から`mSpanList`に変更されました。
    *   リスト操作関数（`mSpanList_Remove`）の呼び出し箇所で、引数として`mSpanList`のポインタが渡されるように変更されました。
    *   リストの走査ロジックが、循環リストの`s == list`から、テールキューの`s == nil`に変更されました。

## コアとなるコードの解説

このコミットで導入された主要なデータ構造と関数について詳しく見ていきます。

### `mSpanList`構造体

```go
type mSpanList struct {
	first *mspan  // first span in list, or nil if none
	last  **mspan // last span's next field, or first if none
}
```
この構造体は、`mspan`の連結リストのヘッドを表します。
*   `first`: リストの最初の`mspan`へのポインタです。リストが空の場合は`nil`になります。
*   `last`: リストの最後の`mspan`の`next`フィールドへのポインタです。これにより、リストの末尾への要素の追加がO(1)で可能になります。リストが空の場合は、`&list.first`を指します。

### `mspan`構造体の変更

```go
type mspan struct {
	next *mspan     // next span in list, or nil if none
	prev **mspan    // previous span's next field, or list head's first field if none
	list *mSpanList // For debugging. TODO: Remove.
	// ... (既存のフィールド)
}
```
*   `next`: リスト内の次の`mspan`へのポインタ。リストの末尾の場合は`nil`。
*   `prev`: リスト内の前の`mspan`の`next`フィールドへのポインタ。これにより、双方向連結リストの削除操作が効率的に行えます。リストの先頭の場合は、その`mSpanList`の`first`フィールドへのポインタを指します。
*   `list`: デバッグ目的で追加されたフィールドで、この`mspan`が現在属している`mSpanList`へのポインタです。`mSpanList_Remove`での検証に使用されます。

### `mSpan_InList`関数

```go
func mSpan_InList(span *mspan) bool {
	return span.prev != nil
}
```
`mspan`が何らかのリストに属しているかどうかをチェックするヘルパー関数です。`span.prev`が`nil`でなければリストに属していると判断します。これは、`mspan`がリストから削除される際に`span.prev`が`nil`に設定されるためです。

### `mSpanList_Init`関数

```go
func mSpanList_Init(list *mSpanList) {
	list.first = nil
	list.last = &list.first
}
```
`mSpanList`を初期化します。`first`を`nil`に設定し、`last`を`&list.first`に設定することで、空のリストを表現します。

### `mSpanList_Remove`関数

```go
func mSpanList_Remove(list *mSpanList, span *mspan) {
	if span.prev == nil || span.list != list {
		println("failed MSpanList_Remove", span, span.prev, span.list, list)
		throw("MSpanList_Remove")
	}
	if span.next != nil {
		span.next.prev = span.prev
	} else {
		list.last = span.prev
	}
	*span.prev = span.next
	span.next = nil
	span.prev = nil
	span.list = nil
}
```
指定された`mSpanList`から`mspan`を削除します。
*   `span.prev == nil || span.list != list`のチェックは、`mspan`が実際にリストに属しているか、そして正しいリストから削除しようとしているかを検証するためのデバッグチェックです。
*   `span.next != nil`の場合、次の`mspan`の`prev`ポインタを、削除される`mspan`の`prev`ポインタ（つまり、削除される`mspan`の前の`mspan`の`next`フィールド）に更新します。
*   `span.next == nil`（つまり、`span`がリストの最後の要素）の場合、`list.last`を削除される`mspan`の`prev`ポインタに更新します。
*   `*span.prev = span.next`は、削除される`mspan`の前の要素の`next`ポインタを、削除される`mspan`の次の要素に直接繋ぎ変える操作です。
*   最後に、削除された`mspan`の`next`, `prev`, `list`フィールドを`nil`に設定し、リストから完全に切り離します。

### `mSpanList_Insert`関数

```go
func mSpanList_Insert(list *mSpanList, span *mspan) {
	if span.next != nil || span.prev != nil || span.list != nil {
		println("failed MSpanList_Insert", span, span.next, span.prev, span.list)
		throw("MSpanList_Insert")
	}
	span.next = list.first
	if list.first != nil {
		list.first.prev = &span.next
	} else {
		list.last = &span.next
	}
	list.first = span
	span.prev = &list.first
	span.list = list
}
```
指定された`mSpanList`の先頭に`mspan`を挿入します。
*   挿入前の`mspan`がどのリストにも属していないことを確認するデバッグチェックがあります。
*   `span.next`を現在の`list.first`に設定します。
*   もしリストが空でなければ、元の`list.first`（新しい`span.next`）の`prev`ポインタを`&span.next`に更新します。
*   リストが空の場合、`list.last`を`&span.next`に設定します。
*   `list.first`を新しい`span`に設定します。
*   `span.prev`を`&list.first`に設定します。
*   `span.list`に現在の`list`を設定します（デバッグ用）。

### `mSpanList_InsertBack`関数

```go
func mSpanList_InsertBack(list *mSpanList, span *mspan) {
	if span.next != nil || span.prev != nil || span.list != nil {
		println("failed MSpanList_InsertBack", span, span.next, span.prev, span.list)
		throw("MSpanList_InsertBack")
	}
	span.next = nil
	span.prev = list.last
	*list.last = span
	list.last = &span.next
	span.list = list
}
```
指定された`mSpanList`の末尾に`mspan`を挿入します。
*   挿入前の`mspan`がどのリストにも属していないことを確認するデバッグチェックがあります。
*   `span.next`を`nil`に設定します（末尾なので次はない）。
*   `span.prev`を現在の`list.last`に設定します。
*   `*list.last = span`は、現在のリストの最後の要素の`next`ポインタ（またはリストが空の場合は`list.first`）を新しい`span`に設定します。
*   `list.last`を新しい`span`の`next`フィールドへのポインタ`&span.next`に更新します。
*   `span.list`に現在の`list`を設定します（デバッグ用）。

これらの変更により、Goランタイムのメモリ管理はより効率的になり、特に`mheap`のような重要なデータ構造のメモリフットプリントが大幅に削減されました。

now a tail queue instead.  One complication of this is
mSpanList_Remove needs to know the list a span is being removed from,
but this appears to be computable in all circumstances.

As a temporary sanity check, mSpanList_Insert and mSpanList_InsertBack
record the list that an mspan has been inserted into so that
mSpanList_Remove can verify that the correct list was specified.

Whereas mspan is 112 bytes on amd64, mSpanList is only 16 bytes.  This
shrinks the size of mheap from 50216 bytes to 12584 bytes.

## 変更の背景

Goランタイムのメモリ管理システムでは、`mspan`という構造体がメモリのチャンク（ページ群）を表現し、これらの`mspan`は様々なリスト（例えば、空きオブジェクトを持つスパンのリスト、空きオブジェクトがないスパンのリストなど）に組織化されています。以前の実装では、これらのリストのヘッド（先頭）として、実体のない（空の）`mspan`構造体自体が使用されていました。

しかし、`mspan`構造体はamd64アーキテクチャで112バイトと比較的大きなサイズを持っていました。リストのヘッドとしてこの大きな構造体を使用することは、特に`mheap`のような多数のリストを管理する構造体において、不要なメモリ消費を引き起こしていました。`mheap`は、様々なサイズの空き`mspan`リストや使用中`mspan`リストを保持するため、多数の`mspan`をリストヘッドとして持つことになり、その結果`mheap`構造体全体のサイズが肥大化していました。

このコミットの主な目的は、このメモリオーバーヘッドを削減することです。専用の`mSpanList`型を導入することで、リストヘッドに必要な情報（先頭と末尾へのポインタ）のみを保持し、`mspan`構造体全体のサイズをリストヘッドのために確保する必要がなくなりました。これにより、`mheap`のサイズを大幅に削減し、ランタイム全体のメモリ効率を向上させることが背景にあります。

また、以前の循環双方向連結リストからテールキュー（tail queue）への変更は、型安全性の向上と、リスト操作のロジックをより明確にする意図も含まれています。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムのメモリ管理に関する概念とデータ構造の知識が必要です。

1.  **Goのメモリ管理（GC）**: Goは自動ガベージコレクション（GC）を採用しており、開発者が手動でメモリを解放する必要はありません。ランタイムはヒープメモリを管理し、オブジェクトの割り当てと解放を行います。
2.  **`mspan`**: `mspan`はGoランタイムのメモリ管理における基本的な単位です。これは、連続した物理メモリページ（通常は8KBの倍数）のチャンクを表します。`mspan`は、特定のサイズのオブジェクトを格納するために使用されたり、スタックとして使用されたり、空きメモリとして管理されたりします。各`mspan`は、その状態（使用中、スタック、空きなど）、ページ数、フリーリスト（内部の空きオブジェクトのリスト）などの情報を持っています。
3.  **`mheap`**: `mheap`はGoランタイム全体のヒープメモリを管理するグローバルな構造体です。様々なサイズの`mspan`を管理するためのフリーリスト（`free`、`freelarge`）と、使用中の`mspan`を管理するためのビジーリスト（`busy`、`busylarge`）を保持しています。
4.  **`mcentral`**: `mcentral`は、特定のサイズクラス（例えば、8バイトオブジェクト用、16バイトオブジェクト用など）の`mspan`を管理する構造体です。`mheap`から`mspan`を取得し、それを`mcache`（各P（プロセッサ）にローカルなキャッシュ）に提供します。`mcentral`は、空きオブジェクトを持つ`mspan`のリスト（`nonempty`）と、空きオブジェクトがない`mspan`のリスト（`empty`）を保持しています。
5.  **連結リスト（Linked List）**: データを線形に並べたデータ構造で、各要素が次の要素（双方向連結リストの場合は前の要素も）へのポインタを持っています。
    *   **循環双方向連結リスト（Circular Doubly Linked List）**: リストの最後の要素が最初の要素を指し、最初の要素が最後の要素を指す形式の双方向連結リストです。リストのヘッドも通常の要素と同様に扱われ、`head.next`が最初の要素、`head.prev`が最後の要素を指します。このコミット以前は、`mspan`のリストはこの形式で実装されており、リストヘッドとして空の`mspan`が使われていました。
    *   **テールキュー（Tail Queue）**: BSDでよく使われる連結リストの一種で、リストの先頭と末尾へのポインタを明示的に持つことで、両端からの高速な挿入・削除を可能にします。このコミットでは、型安全性を高めるためにこの形式に移行しています。テールキューは通常、リストのヘッド構造体が`first`（先頭要素へのポインタ）と`last`（末尾要素の`next`フィールドへのポインタ）を持ちます。

## 技術的詳細

このコミットの核心は、`mspan`のリスト管理方法を根本的に変更した点にあります。

1.  **`mSpanList`型の導入**:
    *   以前は、`mcentral`や`mheap`内の`mspan`リストのヘッドとして、`mspan`構造体自体が使用されていました。これは、`mspan`が`next`と`prev`ポインタを持つ双方向連結リストの要素として機能していたためです。リストが空の場合でも、`head.next = head`、`head.prev = head`のように自身を指すことで循環リストを表現していました。
    *   新しく導入された`mSpanList`型は、リストのヘッド専用の構造体です。
        ```go
        type mSpanList struct {
            first *mspan  // first span in list, or nil if none
            last  **mspan // last span's next field, or first if none
        }
        ```
        `first`はリストの最初の`mspan`へのポインタ、`last`はリストの最後の`mspan`の`next`フィールドへのポインタ（またはリストが空の場合は`first`フィールドへのポインタ）を保持します。これにより、リストの先頭と末尾へのアクセスが効率的になります。

2.  **循環連結リストからテールキューへの移行**:
    *   以前の循環双方向連結リストでは、リストのヘッドも`mspan`型であり、`mspan`の`next`と`prev`フィールドがリストの構造を形成していました。
    *   `mSpanList`の導入により、リストの構造はテールキューに変わりました。テールキューは、リストの先頭と末尾を直接指すポインタを持つことで、リストの操作をより効率的かつ型安全に行うことができます。
    *   この変更により、`mSpanList_Remove`関数は、どの`mSpanList`から`mspan`を削除するのかを知る必要が生じました。これは、`mspan`が複数のリストに属する可能性がないため、常に計算可能であると判断されています。

3.  **メモリ使用量の削減**:
    *   `mspan`構造体はamd64で112バイトです。以前は、`mheap`や`mcentral`内の各リストヘッドがこの112バイトを消費していました。
    *   `mSpanList`は`*mspan`と`**mspan`の2つのポインタのみを持つため、amd64で16バイト（ポインタサイズが8バイトの場合）です。
    *   コミットメッセージによると、この変更により`mheap`のサイズが50216バイトから12584バイトへと大幅に削減されました。これは、`mheap`が多数の`mspan`リスト（`free`、`freelarge`、`busy`、`busylarge`など）を保持しているため、リストヘッドのサイズ削減が全体に大きな影響を与えたことを示しています。

4.  **型安全性とデバッグ**:
    *   `mSpanList`を導入することで、リストヘッドとリスト要素（`mspan`）の役割が明確に分離され、型安全性が向上します。
    *   一時的な健全性チェックとして、`mSpanList_Insert`と`mSpanList_InsertBack`は、`mspan`が挿入されたリストを`span.list`フィールドに記録するようになりました。これにより、`mSpanList_Remove`が正しいリストから削除しようとしているかを検証できます。これはデバッグ目的であり、最終的には削除される予定です（`TODO: Remove.`のコメントがあるため）。

## コアとなるコードの解説

このコミットで導入された主要なデータ構造と関数について詳しく見ていきます。

### `mSpanList`構造体

```go
type mSpanList struct {
	first *mspan  // first span in list, or nil if none
	last  **mspan // last span's next field, or first if none
}
```
この構造体は、`mspan`の連結リストのヘッドを表します。
*   `first`: リストの最初の`mspan`へのポインタです。リストが空の場合は`nil`になります。
*   `last`: リストの最後の`mspan`の`next`フィールドへのポインタです。これにより、リストの末尾への要素の追加がO(1)で可能になります。リストが空の場合は、`&list.first`を指します。

### `mspan`構造体の変更

```go
type mspan struct {
	next *mspan     // next span in list, or nil if none
	prev **mspan    // previous span's next field, or list head's first field if none
	list *mSpanList // For debugging. TODO: Remove.
	// ... (既存のフィールド)
}
```
*   `next`: リスト内の次の`mspan`へのポインタ。リストの末尾の場合は`nil`。
*   `prev`: リスト内の前の`mspan`の`next`フィールドへのポインタ。これにより、双方向連結リストの削除操作が効率的に行えます。リストの先頭の場合は、その`mSpanList`の`first`フィールドへのポインタを指します。
*   `list`: デバッグ目的で追加されたフィールドで、この`mspan`が現在属している`mSpanList`へのポインタです。`mSpanList_Remove`での検証に使用されます。

### `mSpan_InList`関数

```go
func mSpan_InList(span *mspan) bool {
	return span.prev != nil
}
```
`mspan`が何らかのリストに属しているかどうかをチェックするヘルパー関数です。`span.prev`が`nil`でなければリストに属していると判断します。これは、`mspan`がリストから削除される際に`span.prev`が`nil`に設定されるためです。

### `mSpanList_Init`関数

```go
func mSpanList_Init(list *mSpanList) {
	list.first = nil
	list.last = &list.first
}
```
`mSpanList`を初期化します。`first`を`nil`に設定し、`last`を`&list.first`に設定することで、空のリストを表現します。

### `mSpanList_Remove`関数

```go
func mSpanList_Remove(list *mSpanList, span *mspan) {
	if span.prev == nil || span.list != list {
		println("failed MSpanList_Remove", span, span.prev, span.list, list)
		throw("MSpanList_Remove")
	}
	if span.next != nil {
		span.next.prev = span.prev
	} else {
		list.last = span.prev
	}
	*span.prev = span.next
	span.next = nil
	span.prev = nil
	span.list = nil
}
```
指定された`mSpanList`から`mspan`を削除します。
*   `span.prev == nil || span.list != list`のチェックは、`mspan`が実際にリストに属しているか、そして正しいリストから削除しようとしているかを検証するためのデバッグチェックです。
*   `span.next != nil`の場合、次の`mspan`の`prev`ポインタを、削除される`mspan`の`prev`ポインタ（つまり、削除される`mspan`の前の`mspan`の`next`フィールド）に更新します。
*   `span.next == nil`（つまり、`span`がリストの最後の要素）の場合、`list.last`を削除される`mspan`の`prev`ポインタに更新します。
*   `*span.prev = span.next`は、削除される`mspan`の前の要素の`next`ポインタを、削除される`mspan`の次の要素に直接繋ぎ変える操作です。
*   最後に、削除された`mspan`の`next`, `prev`, `list`フィールドを`nil`に設定し、リストから完全に切り離します。

### `mSpanList_Insert`関数

```go
func mSpanList_Insert(list *mSpanList, span *mspan) {
	if span.next != nil || span.prev != nil || span.list != nil {
		println("failed MSpanList_Insert", span, span.next, span.prev, span.list)
		throw("MSpanList_Insert")
	}
	span.next = list.first
	if list.first != nil {
		list.first.prev = &span.next
	} else {
		list.last = &span.next
	}
	list.first = span
	span.prev = &list.first
	span.list = list
}
```
指定された`mSpanList`の先頭に`mspan`を挿入します。
*   挿入前の`mspan`がどのリストにも属していないことを確認するデバッグチェックがあります。
*   `span.next`を現在の`list.first`に設定します。
*   もしリストが空でなければ、元の`list.first`（新しい`span.next`）の`prev`ポインタを`&span.next`に更新します。
*   リストが空の場合、`list.last`を`&span.next`に設定します。
*   `list.first`を新しい`span`に設定します。
*   `span.prev`を`&list.first`に設定します。
*   `span.list`に現在の`list`を設定します（デバッグ用）。

### `mSpanList_InsertBack`関数

```go
func mSpanList_InsertBack(list *mSpanList, span *mspan) {
	if span.next != nil || span.prev != nil || span.list != nil {
		println("failed MSpanList_InsertBack", span, span.next, span.prev, span.list)
		throw("MSpanList_InsertBack")
	}
	span.next = nil
	span.prev = list.last
	*list.last = span
	list.last = &span.next
	span.list = list
}
```
指定された`mSpanList`の末尾に`mspan`を挿入します。
*   挿入前の`mspan`がどのリストにも属していないことを確認するデバッグチェックがあります。
*   `span.next`を`nil`に設定します（末尾なので次はない）。
*   `span.prev`を現在の`list.last`に設定します。
*   `*list.last = span`は、現在のリストの最後の要素の`next`ポインタ（またはリストが空の場合は`list.first`）を新しい`span`に設定します。
*   `list.last`を新しい`span`の`next`フィールドへのポインタ`&span.next`に更新します。
*   `span.list`に現在の`list`を設定します（デバッグ用）。

これらの変更により、Goランタイムのメモリ管理はより効率的になり、特に`mheap`のような重要なデータ構造のメモリフットプリントが大幅に削減されました。
