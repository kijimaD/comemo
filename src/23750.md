## 元コミット内容

このコミットの目的は、GoコンパイラのSSAバックエンドにおいて、`Value` オブジェクトにソースコードの行番号情報を付与することです。これにより、SSAの各操作が元のソースコードのどの行から生成されたのかを正確に把握できるようになります。

主な変更点は以下の通りです。

*   `ssa.Value` 構造体に `Line int32` フィールドを追加。
*   `ssa.Block` 構造体に `Line int32` フィールドを追加。
*   SSA生成フェーズ (`src/cmd/compile/internal/gc/ssa.go`) で、`state` 構造体にラインナンバースタック (`line []int32`) を導入し、`pushLine`、`popLine`、`peekLine` メソッドで管理。
*   `state` 構造体の `newValue`, `newValue1`, `newValue2`, `newValue3`, `entryNewValue`, `entryNewValue1`, `entryNewValue2`, `constInt` といったヘルパー関数を導入し、`Value` 生成時に現在の行番号を自動的に付与するように変更。
*   `ssa.Block` の生成時にも行番号を付与。
*   `src/cmd/compile/internal/ssa/func.go` 内の `NewValue` 系の関数シグネチャに行番号引数 `line int32` を追加。
*   `src/cmd/compile/internal/ssa/TODO` から、行番号に関する項目を削除。これは、このコミットによって解決されたことを意味します。
*   `src/cmd/compile/internal/ssa/regalloc.go`, `src/cmd/compile/internal/ssa/rewriteAMD64.go`, `src/cmd/compile/internal/ssa/rewritegeneric.go` など、SSAの最適化やコード生成に関わるファイルで、`Value` 生成時に行番号を渡すように修正。
*   `src/cmd/compile/internal/gc/ssa.go` の `genValue` および `genBlock` 関数で、`v.Line` および `b.Line` を `lineno` グローバル変数に設定するように変更。これは、生成されるアセンブリコードに正しい行番号情報が埋め込まれるようにするためです。

## 変更の背景

Goコンパイラは、ソースコードを中間表現に変換し、様々な最適化を適用してから最終的な機械語コードを生成します。この過程で、プログラムの構造は大きく変化し、特にSSA (Static Single Assignment) 形式は、最適化を容易にするために設計された低レベルの中間表現です。

しかし、SSA形式のコードは元のソースコードとは大きく異なるため、デバッグやコンパイラの動作解析が困難になるという課題がありました。特に、特定のSSA `Value` がどのソースコードの行に対応しているのかが不明な場合、コンパイラのバグを特定したり、最適化が意図通りに機能しているかを確認したりすることが非常に難しくなります。

このコミットの背景には、以下のニーズがあったと考えられます。

1.  **デバッグの改善**: コンパイラの開発者がSSAレベルでデバッグを行う際に、各 `Value` が元のソースコードのどの部分に由来するかを迅速に特定できるようにするため。
2.  **診断情報の強化**: コンパイラがエラーや警告を報告する際に、より正確なソースコードの行番号を提供するため。
3.  **最適化の可視化**: `GOSSAFUNC` のようなツールを通じて、SSAの最適化パスがどのようにコードを変換し、それが元のソースコードのどの部分に影響を与えているかを開発者が視覚的に理解できるようにするため。これにより、最適化の挙動を分析し、さらなる改善点を見つけることが可能になります。
4.  **プロファイリングとトレース**: 将来的に、SSAレベルでのプロファイリングや実行トレースにおいて、より詳細なソースコード位置情報を提供するための基盤を構築するため。

この変更は、Goコンパイラの開発効率と診断能力を向上させるための重要なステップと言えます。

## 前提知識の解説

### 1. GoコンパイラとSSA (Static Single Assignment)

Goコンパイラは、Go言語のソースコードを機械語に変換するツールチェーンの一部です。コンパイルの過程で、コードは複数の段階を経て変換されます。SSAは、その中間表現の一つであり、特に最適化フェーズで広く利用されます。

*   **SSA形式**: Static Single Assignment (静的単一代入) 形式は、プログラム中の各変数が一度だけ代入されるようにする中間表現です。これにより、データフロー解析が単純化され、コンパイラがより効果的な最適化（例: 共通部分式除去、デッドコード削除、レジスタ割り当てなど）を実行できるようになります。SSAでは、変数の各定義に新しいバージョン番号が割り当てられます（例: `x1 = ...`, `x2 = ...`）。

### 2. `Value` と `Block` (SSAにおける基本要素)

GoコンパイラのSSAバックエンドにおいて、主要なデータ構造は `Value` と `Block` です。

*   **`ssa.Value`**: SSA形式における基本的な操作単位です。これは、定数、変数への参照、算術演算の結果、メモリ操作など、プログラム内のあらゆる「値」を表します。各 `Value` は、その操作の種類 (`Op`)、型 (`Type`)、補助情報 (`Aux`)、そして引数 (`Args`) を持ちます。このコミット以前は、`Value` に直接的な行番号情報はありませんでした。
*   **`ssa.Block`**: 基本ブロック (Basic Block) を表します。基本ブロックは、一つの入り口と一つの出口を持つ、分岐やジャンプを含まない命令のシーケンスです。SSA形式では、プログラムの制御フローはこれらの `Block` 間を移動することで表現されます。各 `Block` は、その `Block` 内で生成される `Value` を含みます。

### 3. `cmd/compile/internal/gc` と `cmd/compile/internal/ssa`

*   **`cmd/compile/internal/gc`**: Goコンパイラのフロントエンドおよび中間コード生成を担当する部分です。ここでは、Goのソースコードが抽象構文木 (AST) にパースされ、型チェックが行われ、その後、SSA形式への変換が開始されます。
*   **`cmd/compile/internal/ssa`**: SSA形式のコードに対する最適化と、最終的な機械語コード生成を担当するバックエンドです。

### 4. `GOSSAFUNC` 環境変数

Goコンパイラには、`GOSSAFUNC` という環境変数があります。これを特定の関数名に設定してコンパイルを実行すると、コンパイラはその関数のSSA中間表現の各段階をHTMLファイルとして出力します。このHTMLファイルは、SSAの各 `Value` や `Block` が元のソースコードのどの行に対応しているかを示すデバッグ情報を含んでおり、コンパイラの動作を視覚的に理解するのに非常に役立ちます。このコミットは、`GOSSAFUNC` が提供するようなデバッグ情報をより正確かつ効率的に生成するための基盤となります。

## 技術的詳細

このコミットの技術的な核心は、SSA形式の `Value` と `Block` にソースコードの行番号を伝播させるメカニズムを導入した点にあります。

1.  **`ssa.Value` および `ssa.Block` への `Line` フィールド追加**:
    *   `src/cmd/compile/internal/ssa/value.go` の `Value` 構造体に `Line int32` が追加されました。
    *   `src/cmd/compile/internal/ssa/block.go` の `Block` 構造体にも `Line int32` が追加されました。
    *   これにより、SSAの各要素が自身のソースコード上の位置情報を保持できるようになります。

2.  **ラインナンバースタックの導入 (`state` 構造体)**:
    *   `src/cmd/compile/internal/gc/ssa.go` 内の `state` 構造体は、SSA生成のコンテキストを保持します。ここに `line []int32` というスライスが追加され、行番号のスタックとして機能します。
    *   `pushLine(line int32)`: 現在処理しているソースコードの行番号をスタックにプッシュします。
    *   `popLine()`: スタックのトップから行番号をポップします。
    *   `peekLine() int32`: スタックのトップにある現在の行番号を返します。
    *   このスタックは、関数やステートメントのスコープに入る際に行番号をプッシュし、スコープを抜ける際にポップすることで、常に現在の正確な行番号を追跡するために使用されます。

3.  **`Value` 生成ヘルパー関数の導入と行番号の自動付与**:
    *   `state` 構造体に `newValue`, `newValue1`, `newValue2`, `newValue3`, `entryNewValue`, `entryNewValue1`, `entryNewValue2`, `constInt` といった新しいヘルパーメソッドが追加されました。
    *   これらのメソッドは、`ssa.Block` の `NewValue` 系の関数をラップし、`s.peekLine()` を呼び出して現在の行番号を取得し、それを `Value` の生成時に自動的に渡すように変更されています。これにより、SSA生成ロジックの各所で手動で行番号を渡す手間が省け、一貫性が保たれます。

4.  **`ssa.Block` への行番号付与**:
    *   `state.endBlock()` メソッド内で、`b.Line = s.peekLine()` が追加され、ブロックが終了する際にも現在の行番号が `Block` に付与されるようになりました。これは、ブロックの制御フロー操作（例: 条件分岐）がどのソースコードの行に対応するかを示すために重要です。

5.  **SSAバックエンドへの行番号伝播**:
    *   `src/cmd/compile/internal/ssa/func.go` 内の `Block.NewValue` 系の関数シグネチャが変更され、`line int32` 引数を受け取るようになりました。これにより、`Value` が生成される際に常にその行番号が設定されることが保証されます。
    *   `rulegen.go` (ルール生成)、`generic.go` (汎用ルール)、`regalloc.go` (レジスタ割り当て)、`rewriteAMD64.go` (AMD64リライト)、`rewritegeneric.go` (汎用リライト) など、SSAの様々な最適化パスやコード生成パスで `Value` が生成または変換される際に、この行番号情報が適切に伝播されるように修正されています。これにより、最適化によって新しい `Value` が生成された場合でも、その `Value` が元のソースコードのどの行に由来するかが追跡可能になります。

6.  **アセンブリコードへの行番号埋め込み**:
    *   `src/cmd/compile/internal/gc/ssa.go` の `genValue` および `genBlock` 関数で、`lineno = v.Line` や `lineno = b.Line` が設定されるようになりました。これは、最終的に生成されるアセンブリコードのデバッグ情報 (DWARF情報など) に、SSAの `Value` や `Block` に対応する正確なソースコードの行番号が埋め込まれるようにするための重要なステップです。これにより、デバッガで機械語レベルのコードをステップ実行する際に、元のGoソースコードの行と対応付けられるようになります。

この一連の変更により、GoコンパイラのSSA中間表現は、ソースコードの行番号という重要なメタデータを保持するようになり、コンパイラの内部動作の理解、デバッグ、および診断能力が飛躍的に向上しました。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更点

```go
// state 構造体に行番号スタックを追加
type state struct {
	// ... 既存のフィールド ...
	// line number stack.  The current line number is top of stack
	line []int32
}

// pushLine pushes a line number on the line number stack.
func (s *state) pushLine(line int32) {
	s.line = append(s.line, line)
}

// popLine pops the top of the line number stack.
func (s *state) popLine() {
	s.line = s.line[:len(s.line)-1]
}

// peekLine peek the top of the line number stack.
func (s *state) peekLine() int32 {
	return s.line[len(s.line)-1]
}

// newValue adds a new value with no arguments to the current block.
// 現在の行番号を自動的に付与するヘルパー関数
func (s *state) newValue(op ssa.Op, t ssa.Type, aux interface{}) *ssa.Value {
	return s.curBlock.NewValue(s.peekLine(), op, t, aux)
}

// ... 他の newValue1, newValue2, newValue3, entryNewValue 系のヘルパー関数も同様 ...

// buildssa 関数内で、関数の処理開始時に行番号をプッシュし、終了時にポップ
func buildssa(fn *Node) *ssa.Func {
	// ...
	s.pushLine(fn.Lineno)
	defer s.popLine()
	// ...
}

// stmt 関数内で、各ステートメントの処理開始時に行番号をプッシュし、終了時にポップ
func (s *state) stmt(n *Node) {
	s.pushLine(n.Lineno)
	defer s.popLine()
	// ...
}

// expr 関数内で、各式の処理開始時に行番号をプッシュし、終了時にポップ
func (s *state) expr(n *Node) *ssa.Value {
	s.pushLine(n.Lineno)
	defer s.popLine()
	// ...
}

// endBlock 関数内で、ブロックに行番号を付与
func (s *state) endBlock() *ssa.Block {
	// ...
	s.curBlock = nil
	s.vars = nil
	b.Line = s.peekLine() // ここでブロックに行番号を設定
	return b
}

// genValue および genBlock 関数内で、最終的なコード生成時に行番号をグローバル変数に設定
func genValue(v *ssa.Value) {
	lineno = v.Line // Value の行番号を lineno グローバル変数に設定
	switch v.Op {
	// ...
	}
}

func genBlock(b, next *ssa.Block, branches []branch) []branch {
	lineno = b.Line // Block の行番号を lineno グローバル変数に設定
	switch b.Kind {
	// ...
	}
}
```

この `state` 構造体とヘルパー関数の導入により、SSA生成ロジック全体で一貫して行番号が `Value` と `Block` に付与されるようになります。`lineno` グローバル変数への設定は、最終的なアセンブリコードのデバッグ情報にこの行番号が反映されるようにするために重要です。

### `src/cmd/compile/internal/ssa/func.go` の変更点

```go
// NewValue メソッドのシグネチャに行番号引数を追加
func (b *Block) NewValue(line int32, op Op, t Type, aux interface{}) *Value {
	v := &Value{
		ID:    b.Func.vid.get(),
		Op:    op,
		Type:  t,
		Aux:   aux,
		Block: b,
		Line:  line, // ここで Value に行番号を設定
	}
	b.Values = append(b.Values, v)
	return v
}

// ... NewValue1, NewValue2, NewValue3, ConstInt も同様に行番号引数を追加 ...
```

`Block.NewValue` 系の関数が `line int32` 引数を受け取るように変更されたことで、`Value` オブジェクトが生成される際に、そのソースコード上の位置情報が確実に埋め込まれるようになりました。これは、SSAの各操作がどのソースコードの行に対応するかを追跡するための基盤となります。
