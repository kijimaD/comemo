## 元コミット内容

このコミットは、定数宣言における小さくも強力な変更を導入します。これは、列挙型に関する議論の後、Ken氏によって提案されたものです。実装は些細なものであるはずです。ドキュメントの文言は、おそらく改善されるべきでしょう。

## 変更の背景

Go言語の初期段階において、定数宣言の構文は現在よりも厳格でした。特に、複数の関連する定数を宣言する際に、それぞれの定数に明示的に値を割り当てる必要がありました。しかし、プログラミング言語において、関連する一連の定数（例えば、エラーコード、状態、ビットフラグなど）を簡潔に定義する「列挙型（enum）」の概念は非常に一般的であり、Go言語でも同様のニーズがありました。

このコミットは、Go言語の設計者の一人であるKen Thompson氏からの提案を受け、列挙型のような定数グループをより「軽量」に宣言できるようにするためのものです。既存の`iota`定数ジェネレータと組み合わせることで、このニーズに応えることが意図されました。これにより、冗長な記述を減らし、コードの可読性と保守性を向上させることが目的とされています。

## 前提知識の解説

### Go言語の定数 (Constants)

Go言語における定数は、プログラムの実行中に値が変更されない不変の値を指します。定数は数値、ブール値、文字列のみを保持でき、コンパイル時にその値が決定されます。定数宣言は`const`キーワードを用いて行われます。

```go
const pi = 3.14159
const greeting = "Hello, Go!"
```

### `iota`定数ジェネレータ

`iota`はGo言語の特別な予約済み識別子で、`const`ブロック内で使用されると、連続する定数に自動的にインクリメントされる整数値を割り当てます。`const`ブロックの最初の`iota`は`0`に評価され、それ以降の`const`指定ごとに`1`ずつ増加します。これにより、連番の定数を簡潔に定義できます。

```go
const (
    zero = iota // zero = 0
    one         // one = 1
    two         // two = 2
)
```

### 列挙型 (Enums) の概念

多くのプログラミング言語には「列挙型」というデータ型があり、これは関連する名前付き定数のセットを定義するために使用されます。例えば、曜日や月の名前、状態コードなどがこれに該当します。Go言語にはC++やJavaのような明示的な`enum`キーワードはありませんが、`const`と`iota`を組み合わせることで、同様の機能を実現するのが一般的です。

## 技術的詳細

このコミットの核心的な変更は、Go言語の定数宣言の構文規則（BNF記法）にあります。

変更前:
`ConstSpec = identifier [ Type ] "=" Expression .`
（定数名 [型] "=" 式）

変更後:
`ConstSpec = identifier [ Type ] [ "=" Expression ] .`
（定数名 [型] [ "=" 式 ]）

この変更により、`ConstSpec`（個々の定数指定）において、`"=" Expression`の部分がオプションになりました。つまり、定数に値を割り当てる式を省略できるようになったのです。

この省略された場合のセマンティクスは以下の通りです。
1.  `const`キーワードの後に続く定数ブロック内で、式が省略された場合、その定数には直前の定数宣言で使用された式が再利用されます。
2.  もし直前の定数宣言が存在しない（つまり、`const`ブロックの最初の定数である）場合、式を省略することはできません。

この新しいセマンティクスと`iota`を組み合わせることで、以下のような「軽量な列挙型」の宣言が可能になります。

```go
const (
    illegal = iota // illegal = 0 (iotaの初期値)
    eof            // eof = 1 (直前の式 illegal = iota が再利用され、iotaがインクリメントされる)
    ident          // ident = 2 (同様に再利用とインクリメント)
    string         // string = 3
    number         // number = 4
)
```

このメカニズムにより、各定数に`= iota`と記述する冗長さを排除し、より簡潔で読みやすい定数グループの定義が実現されました。これは、Go言語が持つ「簡潔さ」と「実用性」という設計哲学に合致する変更と言えます。
