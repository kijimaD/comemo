## 変更の背景
Goランタイムは、異なるオペレーティングシステム（OS）上で一貫した動作を提供することを目指しています。シグナル処理はOS固有の動作が多いため、各OSの特性に合わせて調整が必要です。このコミットの背景には、Solaris環境における`SIGTSTP`（端末からの停止要求）と`SIGCANCEL`（スレッドキャンセル）のデフォルトのシグナルハンドリングが、Goランタイムの期待する動作やGNU/Linuxでの処理方法と異なっていたという問題があります。

具体的には、以前のSolarisでの`SIGTSTP`と`SIGCANCEL`は、Goランタイム内で特別な処理が割り当てられていませんでした（`0`として定義）。これにより、これらのシグナルがGoプログラムに送信された際に、予期せぬ動作や、他のOS（特にGNU/Linux）との挙動の不一致が生じる可能性がありました。この変更は、これらのシグナルに対するGoランタイムの応答を標準化し、クロスプラットフォームでの信頼性と予測可能性を高めることを目的としています。

## 前提知識の解説

### シグナル (Signals)
UNIX系OSにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。例えば、ユーザーがCtrl+Cを押すと`SIGINT`が、プログラムが不正なメモリアクセスをすると`SIGSEGV`が送信されます。プロセスはこれらのシグナルを捕捉（catch）して特定の処理を実行したり、無視（ignore）したり、デフォルトの動作（プロセス終了など）を受け入れたりすることができます。

### SIGTSTP
`SIGTSTP` (Terminal Stop) は、ユーザーが端末からプロセスを一時停止させたいときに送信されるシグナルです。通常、Ctrl+Zを押すことで生成されます。このシグナルを受け取ったプロセスは、一時的に実行を停止し、フォアグラウンドからバックグラウンドに移動します。その後、`SIGCONT`シグナルを受け取ることで実行を再開できます。

### SIGCANCEL
`SIGCANCEL`は、主にSolarisや一部のUNIX系システムで使用されるシグナルで、スレッドのキャンセル処理に関連しています。Pthreads（POSIX Threads）ライブラリにおけるスレッドキャンセル機能は、あるスレッドが別のスレッドの実行を終了させるメカニズムを提供します。`SIGCANCEL`はこのキャンセル処理を内部的に実装するために使用されることがあります。

### Goランタイムのシグナル処理
Goランタイムは、OSからのシグナルを捕捉し、Goプログラム内のgoroutineに適切にディスパッチする役割を担っています。`src/runtime/signal_solaris.go`のようなファイルは、特定のOSにおけるシグナル番号と、それに対応するGoランタイム内部の処理フラグ（例: `_SigNotify`, `_SigDefault`, `_SigSetStack`, `_SigUnblock`）をマッピングする`sigtable`を定義しています。

*   `_SigNotify`: このフラグが設定されているシグナルは、Goプログラム内の`os/signal`パッケージを通じてユーザーコードに通知されます。
*   `_SigDefault`: このフラグが設定されているシグナルは、Goランタイムが特別な処理を行わず、OSのデフォルトの動作に任せることを意味します。多くの場合、プロセスが終了します。
*   `_SigSetStack`: シグナルハンドラが代替シグナルスタック（`sigaltstack`）上で実行されるべきであることを示します。これは、シグナルハンドラが通常のスタックオーバーフローを引き起こすのを防ぐために重要です。
*   `_SigUnblock`: シグナルハンドラが実行される際に、そのシグナル自体がブロック解除されるべきであることを示します。これにより、シグナルハンドラ内で同じシグナルが再度発生した場合に処理できるようになります。

## 技術的詳細
このコミットの技術的詳細なポイントは、Solarisにおける`sigtable`の定義を更新し、`SIGTSTP`と`SIGCANCEL`の挙動を調整した点にあります。

1.  **`SIGTSTP`の変更**:
    *   変更前: `/* 24 */ {0, "SIGTSTP: user stop requested from tty"}`
        *   `0`は、Goランタイムがこのシグナルに対して特別な内部処理を行わないことを意味していました。これは、Goランタイムが`SIGTSTP`を捕捉せず、OSのデフォルト動作に任せるか、あるいはGoランタイムがこのシグナルを適切に処理できない状態を示唆していました。
    *   変更後: `/* 24 */ {_SigNotify + _SigDefault, "SIGTSTP: user stop requested from tty"}`
        *   `_SigNotify`が追加されたことで、`SIGTSTP`がGoプログラムに通知されるようになります。これにより、`os/signal`パッケージを使用してユーザーコードが`SIGTSTP`を捕捉し、カスタムの停止処理を実装できるようになります。
        *   `_SigDefault`も引き続き含まれているため、Goランタイムがこのシグナルを捕捉しつつも、最終的にはOSのデフォルトの停止動作（プロセスの一時停止）も尊重されることを示唆しています。これは、Goプログラムが`SIGTSTP`を捕捉しない場合に、通常のシェルジョブコントロールの挙動を維持するために重要です。

2.  **`SIGCANCEL`の変更**:
    *   変更前: `/* 36 */ {0, "SIGCANCEL: reserved signal for thread cancellation"}`
        *   `SIGCANCEL`も`0`として定義されており、Goランタイムによる特別な処理はありませんでした。
    *   変更後: `/* 36 */ {_SigSetStack + _SigUnblock, "SIGCANCEL: reserved signal for thread cancellation"}`
        *   `_SigSetStack`が追加されたことで、`SIGCANCEL`のハンドラが代替シグナルスタック上で実行されるようになります。これは、スレッドキャンセル処理のような複雑なシグナルハンドラが、スタックオーバーフローなどの問題を引き起こすリスクを軽減するために重要です。
        *   `_SigUnblock`が追加されたことで、`SIGCANCEL`ハンドラが実行中に同じ`SIGCANCEL`シグナルがブロック解除されます。これにより、シグナルハンドラが再入可能であるか、あるいは特定の状況下で同じシグナルを複数回処理する必要がある場合に、デッドロックやシグナルロストを防ぐのに役立ちます。

これらの変更により、Solaris上でのGoランタイムは、`SIGTSTP`に対してはユーザーコードによる捕捉を可能にしつつ、デフォルトのジョブコントロール動作も維持するようになります。また、`SIGCANCEL`に対しては、より堅牢で安全なシグナルハンドリングメカニズムを提供するようになります。これは、GNU/Linux環境でのGoランタイムのシグナル処理との一貫性を高めるための重要なステップです。

## コアとなるコードの解説

このコードスニペットは、GoランタイムがSolaris上でシグナルをどのように扱うかを定義する`sigtable`配列の一部です。各エントリは、シグナル番号に対応するGoランタイム内部のフラグと、シグナルの説明文字列を含んでいます。

1.  **`SIGTSTP` (シグナル番号 24)**:
    *   変更前は`{0, ...}`となっており、Goランタイムはこのシグナルに対して特別な処理を行いませんでした。
    *   変更後は`{_SigNotify + _SigDefault, ...}`となりました。
        *   `_SigNotify`の追加により、Goプログラムは`os/signal`パッケージを通じて`SIGTSTP`を捕捉し、カスタムのハンドリングロジックを実行できるようになります。
        *   `_SigDefault`は、Goランタイムがシグナルを捕捉しつつも、OSのデフォルトの動作（プロセスの一時停止）も尊重することを示します。これにより、Goプログラムが`SIGTSTP`を明示的に処理しない場合でも、通常のジョブコントロールの挙動が維持されます。

2.  **`SIGCANCEL` (シグナル番号 36)**:
    *   変更前は`{0, ...}`となっており、Goランタイムはこのシグナルに対して特別な処理を行いませんでした。
    *   変更後は`{_SigSetStack + _SigUnblock, ...}`となりました。
        *   `_SigSetStack`の追加により、`SIGCANCEL`のシグナルハンドラは代替シグナルスタック上で実行されるようになります。これは、シグナルハンドラがスタックオーバーフローを引き起こす可能性を減らし、より安全な実行を保証するために重要です。
        *   `_SigUnblock`の追加により、`SIGCANCEL`ハンドラが実行されている間、`SIGCANCEL`シグナル自体がブロック解除されます。これは、シグナルハンドラが再入可能であるか、または特定のシナリオで同じシグナルを複数回処理する必要がある場合に、デッドロックやシグナルロストを防ぐのに役立ちます。

これらの変更は、Solaris環境におけるGoランタイムのシグナル処理を、より堅牢で、他の主要なOS（特にGNU/Linux）との一貫性を持たせるためのものです。これにより、GoプログラムがSolaris上でより予測可能で信頼性の高い動作をするようになります。
