## 変更の背景

Go言語は静的型付け言語であり、型安全性は非常に重要です。しかし、異なる型間での変換や代入は、言語の柔軟性を保つ上で不可欠な機能でもあります。特に、チャネル（`chan`）やスライス（`[]`）のような組み込み型、そしてユーザー定義の名前付き型（`type MyType UnderlyingType`）が絡む場合、コンパイラがこれらの操作をGo言語の仕様に厳密に従って処理することが求められます。

このコミットの背景には、Goコンパイラが型変換と代入のルールを正確に実装していることを検証する目的があります。具体的には、以下のシナリオがテストされています。

1.  **チャネルの方向性変換**: 双方向チャネル（`chan T`）から送信専用チャネル（`chan<- T`）への変換。
2.  **配列ポインタとスライスの変換**: 配列へのポインタ（`*[N]T`）からスライス（`[]T`）への変換。
3.  **名前付き型と基底型の互換性**: ユーザー定義の名前付き型と、その基底型（underlying type）との間での代入および変換のルール。

これらのケースは、一見すると単純に見えますが、Goの型システムにおける重要な側面をカバーしており、コンパイラの堅牢性を保証するために不可欠なテストです。

## 前提知識の解説

### Go言語の型システム

Go言語の型システムは、静的で厳格ですが、特定のルールに基づいて型変換と代入を許可します。

*   **基底型 (Underlying Type)**: ユーザー定義の名前付き型 `type MyType UnderlyingType` において、`UnderlyingType` が `MyType` の基底型です。例えば、`type MyInt int` の場合、`int` が `MyInt` の基底型です。
*   **型互換性**: Goでは、異なる型間での代入や比較は、型が同一であるか、特定の互換性ルールを満たす場合にのみ可能です。
*   **型変換 (Type Conversion)**: `T(x)` の形式で明示的に型を変換できます。これは、`x` の値が型 `T` の値として表現可能である場合にのみ成功します。Goの型変換ルールは厳密であり、C++のような暗黙的な型変換はほとんどありません。
*   **代入 (Assignment)**: `x = y` の形式で値を代入します。代入は、`y` の型が `x` の型に代入可能である場合にのみ可能です。

### チャネル (Channels)

Goのチャネルは、ゴルーチン間で値を送受信するためのパイプです。チャネルには方向性があり、以下の3種類があります。

*   `chan T`: 双方向チャネル（送受信可能）
*   `chan<- T`: 送信専用チャネル
*   `<-chan T`: 受信専用チャネル

双方向チャネルは、送信専用チャネルや受信専用チャネルに暗黙的に変換して代入することができます。これは、より制限されたインターフェースを公開することで、コードの安全性を高めるためによく使われます。

### スライス (Slices)

スライスは、Goにおける可変長シーケンスのデータ型です。スライスは基底となる配列への参照であり、長さと容量を持ちます。スライスは配列とは異なる型ですが、配列へのポインタからスライスへの変換は特定の条件下で可能です。

### `errchk` ディレクティブ

Goのテストコードでは、`// errchk $G $D/$F.go` のようなコメントが使われることがあります。これは、コンパイラが特定の行でエラーを報告することを期待するテストケースで利用されます。`$G` はGoコンパイラ、`$D/$F.go` は現在のファイルパスを指します。このディレクティブがある行でコンパイルエラーが発生しない場合、または異なるエラーが発生した場合、テストは失敗します。

## 技術的詳細

このコミットで追加された `test/convert3.go` ファイルは、Go言語の型変換と代入の以下の具体的なルールを検証しています。

1.  **チャネルの方向性変換**:
    *   `var c chan int`: 双方向チャネル `c` を宣言。
    *   `var d1 chan<- int = c`: 双方向チャネル `c` を送信専用チャネル `chan<- int` に暗黙的に代入。これはGoの仕様で許可されています。
    *   `var d2 = (chan<- int)(c)`: 双方向チャネル `c` を送信専用チャネル `chan<- int` に明示的に型変換して代入。これも許可されています。
    これらのテストは、チャネルの方向性を制限する操作が正しく行われることを確認します。

2.  **配列ポインタからスライスへの変換**:
    *   `var e *[4]int`: 4つの整数を格納する配列へのポインタ `e` を宣言。
    *   `var f1 []int = e`: 配列ポインタ `e` をスライス `[]int` に暗黙的に代入。Goの仕様では、配列ポインタからスライスへの暗黙的な代入は許可されていません。これはコンパイルエラーになるはずです。
    *   `var f2 = []int(e)`: 配列ポインタ `e` をスライス `[]int` に明示的に型変換して代入。Goの仕様では、`*[N]T` 型の値を `[]T` 型に変換することは許可されています。この変換は、配列全体を参照するスライスを生成します。
    これらのテストは、配列ポインタとスライスの間の変換ルール、特に明示的な変換が必要であることを確認します。

3.  **名前付き型と基底型の互換性**:
    *   `type H *[4]int`: 基底型が `*[4]int` である名前付き型 `H` を定義。
    *   `type J []int`: 基底型が `[]int` である名前付き型 `J` を定義。
    *   `var h H`: 型 `H` の変数 `h` を宣言。
    *   `var j1 J = h`: 型 `H` の変数 `h` を型 `J` の変数 `j1` に暗黙的に代入。`H` の基底型は `*[4]int`、`J` の基底型は `[]int` です。Goの仕様では、名前付き型とその基底型が異なる場合、明示的な型変換なしには代入できません。したがって、これはコンパイルエラーになるはずです。
    *   `var j2 = J(h)`: 型 `H` の変数 `h` を型 `J` に明示的に型変換して代入。これは、`H` の基底型 `*[4]int` から `J` の基底型 `[]int` への変換が許可されているため、成功します。
    これらのテストは、名前付き型間の代入には基底型の互換性だけでなく、型自体の同一性または明示的な変換が必要であることを検証します。

特に `var j1 J = h` の行には `// ERROR "compat|illegal"` というコメントが付されており、この行がコンパイルエラーを引き起こすことを期待していることが示されています。これは、Goの型システムが名前付き型に対して厳格なルールを適用していることを確認するための重要なテストポイントです。

## コアとなるコードの解説

追加された `test/convert3.go` ファイルは、Goコンパイラの型変換と代入の挙動を検証するためのテストケースを含んでいます。

*   `// errchk $G $D/$F.go`: この行は、このファイルがコンパイルエラーを期待するテストであることを示しています。具体的には、ファイル内のどこかでコンパイラがエラーを報告することを期待しています。
*   `package main`: 実行可能なプログラムであることを示します。
*   `// everything here is legal except the ERROR line`: このコメントは、`ERROR` コメントが付いている行以外はすべて合法的なGoコードであることを示唆しています。
*   `var c chan int`: `int` 型の値を送受信できる双方向チャネル `c` を宣言します。
*   `var d1 chan<- int = c`: 双方向チャネル `c` を送信専用チャネル `chan<- int` に代入します。これはGoの仕様で許可されている暗黙的な変換です。
*   `var d2 = (chan<- int)(c)`: 双方向チャネル `c` を送信専用チャネル `chan<- int` に明示的に型変換して代入します。これも合法です。
*   `var e *[4]int`: 4つの `int` 型要素を持つ配列へのポインタ `e` を宣言します。
*   `var f1 []int = e`: 配列ポインタ `e` をスライス `[]int` に代入しようとします。これはGoの仕様では許可されておらず、コンパイルエラーとなるべきです。配列ポインタからスライスへの暗黙的な代入はできません。
*   `var f2 = []int(e)`: 配列ポインタ `e` をスライス `[]int` に明示的に型変換して代入します。これは合法です。`*[N]T` から `[]T` への変換は、配列全体を参照するスライスを生成します。
*   `var g = []int(nil)`: `nil` を `[]int` 型のスライスに代入します。これは合法であり、長さと容量が0のスライスを生成します。
*   `type H *[4]int`: 基底型が `*[4]int` である名前付き型 `H` を定義します。
*   `type J []int`: 基底型が `[]int` である名前付き型 `J` を定義します。
*   `var h H`: 型 `H` の変数 `h` を宣言します。
*   `var j1 J = h	// ERROR "compat|illegal"`: 型 `H` の変数 `h` を型 `J` の変数 `j1` に代入しようとします。`H` と `J` は異なる名前付き型であり、たとえそれらの基底型が互換性のある変換をサポートしていても、明示的な型変換なしには直接代入できません。したがって、この行はコンパイルエラーとなることが期待されます。`"compat|illegal"` は、コンパイラが「互換性がない」または「不正な」代入であると報告することを期待する正規表現パターンです。
*   `var j2 = J(h)`: 型 `H` の変数 `h` を型 `J` に明示的に型変換して代入します。`H` の基底型 `*[4]int` から `J` の基底型 `[]int` への変換は合法であるため、この明示的な変換は成功します。

このテストファイルは、Goコンパイラがこれらの複雑な型変換と代入のルールを正確に適用し、期待されるエラーを報告し、合法的な操作を許可することを確認するためのものです。
