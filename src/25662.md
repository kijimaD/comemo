## 変更の背景

この変更は、GitHub Issue #12078 に対応するものです。それ以前のGoの `net/http` パッケージでは、HTTPメソッド（例: "GET", "POST"）は文字列リテラルとして直接コード中に記述されることが一般的でした。しかし、これは以下のような問題を引き起こす可能性がありました。

1.  **タイポ（入力ミス）**: メソッド名が文字列であるため、開発者が誤って "GET" を "GEt" のように入力してしまうと、コンパイルエラーにはならず、実行時に予期せぬ動作やバグにつながる可能性がありました。
2.  **可読性の低下**: コード中にマジックストリング（意味が明確でない文字列リテラル）が散在すると、コードの意図が分かりにくくなることがあります。
3.  **保守性の問題**: もし将来的にHTTPメソッドの表現方法に変更があった場合、コードベース全体を検索して文字列リテラルを修正する必要があり、手間がかかりエラーのリスクも高まります。
4.  **IDEのサポートの欠如**: 文字列リテラルでは、IDEのオートコンプリートやリファクタリング機能の恩恵を受けにくいという側面もありました。

これらの問題を解決するため、HTTPメソッドを定数として定義し、それらを使用するように促すことで、コードの品質と開発効率を向上させることを目的としています。

## 前提知識の解説

### HTTPメソッド

HTTP (Hypertext Transfer Protocol) は、Web上でデータをやり取りするためのプロトコルです。HTTPメソッドは、クライアントがサーバーに対してどのような操作を要求しているかを示すものです。主なHTTPメソッドには以下のようなものがあります。

*   **GET**: サーバーからリソースを取得します。データの取得のみで、サーバーの状態を変更しません（冪等かつ安全）。
*   **HEAD**: GETと同様にリソースのヘッダー情報のみを取得します。ボディは返されません。
*   **POST**: サーバーにデータを送信し、新しいリソースを作成したり、既存のリソースを更新したりします。
*   **PUT**: 指定されたURIにリソースをアップロードし、既存のリソースを完全に置き換えるか、新しいリソースを作成します。
*   **PATCH**: リソースの部分的な変更を適用します。PUTがリソース全体を置き換えるのに対し、PATCHは差分更新を行います。
*   **DELETE**: 指定されたリソースをサーバーから削除します。
*   **CONNECT**: プロキシサーバーを介したトンネル接続を確立します。
*   **OPTIONS**: サーバーがサポートしているHTTPメソッドやその他の通信オプションを問い合わせます。
*   **TRACE**: クライアントからサーバーへのリクエストパスを診断します。

### RFC (Request for Comments)

RFCは、インターネット技術に関する公式な文書シリーズです。インターネットのプロトコル、手順、プログラムなどを定義する標準や情報を提供します。HTTPメソッドの定義もRFCによって標準化されており、このコミットで参照されている `RFC 7231` はHTTP/1.1のセマンティクスとコンテンツを定義する主要な文書の一つです。`RFC 5741` はPATCHメソッドに関するものです。

### Go言語の `net/http` パッケージ

`net/http` パッケージは、Go言語でHTTPクライアントおよびサーバーを実装するための標準ライブラリです。このパッケージは、HTTPリクエストの送信、レスポンスの処理、HTTPサーバーの構築など、HTTP通信に関する基本的な機能を提供します。GoのWebアプリケーション開発において中心的な役割を果たすパッケージです。

## 技術的詳細

このコミットの技術的な詳細としては、`net/http` パッケージ内に新しいファイル `src/net/http/method.go` を作成し、その中にHTTPメソッドを表す `string` 型の定数を定義した点にあります。

以前は、HTTPメソッドを扱う際には以下のように文字列リテラルが直接使用されていました。

```go
req, _ := http.NewRequest("GET", "http://example.com", nil)
// または
if r.Method == "POST" {
    // ...
}
```

このコミットにより、上記のようなコードは以下のように書き換えられるようになります。

```go
req, _ := http.NewRequest(http.MethodGet, "http://example.com", nil)
// または
if r.Method == http.MethodPost {
    // ...
}
```

この変更のメリットは以下の通りです。

1.  **コンパイル時チェックの強化**: 定数を使用することで、存在しないメソッド名を指定した場合にコンパイルエラーとなるため、実行時エラーを未然に防ぐことができます。
2.  **コードの自己文書化**: `http.MethodGet` のようにパッケージ名と定数名を組み合わせることで、その値が何を表しているのかがより明確になります。
3.  **リファクタリングの容易さ**: もし将来的にHTTPメソッドの文字列表現に変更があった場合でも、定数の定義箇所を一度変更するだけで、その定数を使用している全ての箇所に修正が反映されます。
4.  **IDEのサポート**: 多くのIDEでは、定数に対してオートコンプリート機能が働き、開発者はタイポを減らし、より迅速にコードを記述できます。

定数の定義には、それぞれのメソッドがどのRFCで定義されているかというコメントが付記されており、これはコードの背景にある標準を明確にする上で非常に有用です。特に `MethodPatch` については `RFC 5741` と明記されており、他のメソッドが `RFC 7231` で定義されていることと区別されています。

## コアとなるコードの解説

追加された `src/net/http/method.go` ファイルは、`http` パッケージの一部として、以下のHTTPメソッド定数を定義しています。

```go
package http

// Common HTTP methods.
//
// Unless otherwise noted, these are defined in RFC 7231 section 4.3.
const (
	MethodGet     = "GET"
	MethodHead    = "HEAD"
	MethodPost    = "POST"
	MethodPut     = "PUT"
	MethodPatch   = "PATCH" // RFC 5741
	MethodDelete  = "DELETE"
	MethodConnect = "CONNECT"
	MethodOptions = "OPTIONS"
	MethodTrace   = "TRACE"
)
```

*   `package http`: このファイルが `net/http` パッケージに属することを示します。
*   `// Common HTTP methods.`: 定数群の目的を説明するコメントです。
*   `// Unless otherwise noted, these are defined in RFC 7231 section 4.3.`: ほとんどのメソッドがHTTP/1.1の主要な仕様である `RFC 7231` のセクション4.3で定義されていることを示しています。これは、これらの定数が標準に基づいていることを明確にします。
*   `const (...)`: 複数の定数をまとめて定義するGoの構文です。
    *   `MethodGet = "GET"`: リソースの取得。
    *   `MethodHead = "HEAD"`: リソースのヘッダーのみの取得。
    *   `MethodPost = "POST"`: データの送信、リソースの作成/更新。
    *   `MethodPut = "PUT"`: リソースの完全な置き換え。
    *   `MethodPatch = "PATCH" // RFC 5741`: リソースの部分的な更新。このメソッドのみ `RFC 5741` で定義されていることが明記されています。
    *   `MethodDelete = "DELETE"`: リソースの削除。
    *   `MethodConnect = "CONNECT"`: プロキシトンネルの確立。
    *   `MethodOptions = "OPTIONS"`: サーバーがサポートするメソッドの問い合わせ。
    *   `MethodTrace = "TRACE"`: リクエストパスの診断。

これらの定数は、`net/http` パッケージを使用するGoプログラムにおいて、HTTPメソッドを安全かつ明確に指定するための標準的な方法を提供します。
