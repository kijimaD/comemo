# [インデックス 25489] ファイルの概要

このコミットは、`cmd/go` パッケージ内のファイルコピー処理における堅牢性を向上させるものです。具体的には、`builder.copyFile` 関数がファイルをコピーする際に、宛先が通常のファイルであるかどうかを確認し、通常のファイルでない場合には削除処理を行わないように変更されています。これにより、デバイスファイルなどの特殊なファイルを誤って削除してしまうリスクを防ぎ、ビルドプロセスの安全性を高めています。また、この変更に関連して、新しいテストケースが追加されています。

## 変更の背景

このコミットは、`go build` コマンドがビルド出力ファイルをコピーする際の潜在的な問題を解決するために導入されました。`builder.copyFile` 関数は、ビルドの出力先がオブジェクトファイルであることを前提としていますが、もし出力先が通常のファイルではない場合（例えば、`/dev/null`のようなデバイスファイルや名前付きパイプなど）、この前提が崩れます。

具体的には、以下のようなシナリオで問題が発生する可能性がありました。

1.  **非正規ファイルへの書き込み**: ユーザーが `go build -o /dev/null` のように、ビルド出力をデバイスファイルにリダイレクトした場合。
2.  **コピー失敗時の削除処理**: `copyFile` 関数内でファイルコピーが失敗した場合、エラー処理の一環として `os.Remove(dst)` が呼び出されます。
3.  **特権昇格時の危険性**: もし `go build` が十分な権限を持つユーザー（例: root）で実行されていた場合、`os.Remove(dst)` は `/dev/null` のような重要なシステムファイルを実際に削除してしまう可能性がありました。これはシステムに深刻な影響を与える可能性があります。

このコミットは、このような意図しないファイル削除を防ぎ、ビルドプロセスの堅牢性と安全性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

*   **`os.FileMode` と `IsRegular()`**: Go言語の `os` パッケージには、ファイルやディレクトリのパーミッションとタイプを表す `FileMode` 型があります。`FileMode` のメソッドである `IsRegular()` は、そのファイルが通常のファイル（ディレクトリ、シンボリックリンク、デバイスファイルなどではない）である場合に `true` を返します。これは、特殊なファイルタイプを識別するために重要です。
*   **`os.Remove()`**: 指定されたパスのファイルまたは空のディレクトリを削除するGoの関数です。この関数は、削除対象がどのような種類のファイルであるか（通常のファイル、デバイスファイルなど）を区別せず、指定されたパスを削除しようとします。
*   **`os.Lstat()`**: 指定されたパスのファイル情報を取得するGoの関数です。`os.Stat()` と似ていますが、シンボリックリンクの場合、`os.Lstat()` はシンボリックリンク自体の情報を返し、`os.Stat()` はリンク先のファイルの情報を返します。このコミットでは、シンボリックリンクのリンク先ではなく、リンク自体が通常のファイルでないことを確認するために `os.Lstat()` が使用されています。
*   **`/dev/null`**: Unix系システムにおける特殊なデバイスファイルです。このファイルに書き込まれたデータはすべて破棄され、このファイルから読み取ろうとするとEOF（ファイルの終端）が返されます。プログラムの出力を無視したい場合によく使われます。
*   **オブジェクトファイル (Object file)**: コンパイラによって生成される中間ファイルで、機械語コードやデータ、シンボル情報などが含まれます。リンカによって最終的な実行可能ファイルやライブラリに結合されます。`go build` の文脈では、最終的な実行可能ファイルやライブラリを指すこともあります。
*   **`builder.copyFile`**: `cmd/go` パッケージ内のビルドプロセスで使用される内部関数で、ビルドされた成果物（オブジェクトファイルなど）を最終的な出力先にコピーする役割を担っています。

## 技術的詳細

このコミットの技術的な核心は、ファイル操作の安全性を高めるための条件付き削除ロジックの導入と、既存のチェックの改善にあります。

1.  **`mayberemovefile` 関数の導入**:
    *   新しいヘルパー関数 `mayberemovefile(s string)` が追加されました。
    *   この関数は、引数 `s` で指定されたパスのファイルを削除する前に、そのファイルが通常のファイルであるかどうかを `os.Lstat(s)` と `!fi.Mode().IsRegular()` を使って確認します。
    *   もしファイルが存在し、かつそれが通常のファイルではない場合（例: ディレクトリ、シンボリックリンク、デバイスファイルなど）、関数は何もせずに `return` します。
    *   これにより、`os.Remove(s)` が呼び出されるのは、`s` が通常のファイルである場合に限定され、意図しないシステムファイルの削除を防ぎます。

2.  **`builder.copyFile` 関数の変更**:
    *   **既存ファイルチェックの改善**:
        変更前: `if !force && !isObject(dst)`
        変更後: `if !force && fi.Mode().IsRegular() && !isObject(dst)`
        この変更により、コピー先の `dst` が既に存在し、かつそれが通常のファイルである場合にのみ、`isObject(dst)`（オブジェクトファイルであるかどうかのチェック）が実行されるようになりました。これにより、非正規ファイルに対してオブジェクトファイルであるかどうかの無意味なチェックを避けることができます。
    *   **ファイル削除処理の置き換え**:
        変更前: `os.Remove(dst)`
        変更後: `mayberemovefile(dst)`
        `copyFile` 関数内で、ファイルを削除する可能性のある2箇所（コピー開始前と、コピー失敗時のエラーハンドリング）で、直接 `os.Remove(dst)` を呼び出す代わりに、新しく導入された `mayberemovefile(dst)` を呼び出すように変更されました。これにより、前述の通り、通常のファイルのみが削除対象となることが保証されます。

3.  **新しいテストケースの追加**:
    *   `TestBuildOutputToDevNull` という新しいテスト関数が `go_test.go` に追加されました。
    *   このテストは、`go build -o /dev/null go-cmd-test` のように、ビルド出力を `/dev/null` にリダイレクトした場合の挙動を検証します。
    *   このテストの目的は、ビルドが成功し、かつ `/dev/null` のような特殊なファイルが誤って削除されないことを確認することです。

これらの変更により、`go build` コマンドは、出力先が特殊なファイルである場合でも安全に動作するようになり、システムへの潜在的なリスクが軽減されました。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更点

1.  **`builder.copyFile` 関数内の条件分岐の変更**:
    ```diff
    -		if !force && !isObject(dst) {
    +		if !force && fi.Mode().IsRegular() && !isObject(dst) {
    ```
    この変更は、コピー先のファイル `dst` が既に存在する場合のチェックロジックを改善しています。以前は、`force` フラグが `false` で、かつ `dst` がオブジェクトファイルでない場合にエラーを返していました。しかし、`dst` が通常のファイルではない（例: `/dev/null`）場合、`isObject(dst)` のチェックは意味をなしません。
    新しいコードでは、`fi.Mode().IsRegular()` という条件が追加され、`dst` が通常のファイルである場合にのみ `isObject(dst)` のチェックが行われるようになりました。これにより、非正規ファイルに対する不必要なチェックが回避され、ロジックがより正確になります。

2.  **`os.Remove(dst)` の `mayberemovefile(dst)` への置き換え**:
    ```diff
    -	os.Remove(dst)
    +	mayberemovefile(dst)
    ```
    ```diff
    -	\t\tos.Remove(dst)
    +	\t\tmayberemovefile(dst)
    ```
    `builder.copyFile` 関数内で、ファイルコピーを開始する前と、コピー中にエラーが発生した場合のクリーンアップ処理として、`os.Remove(dst)` が直接呼び出されていました。この直接的な削除は、`dst` がデバイスファイルのような特殊なファイルである場合に危険でした。
    この変更により、`os.Remove(dst)` の呼び出しが、新しく定義された `mayberemovefile(dst)` 関数に置き換えられました。`mayberemovefile` 関数は、削除対象が通常のファイルであるかどうかを事前に確認するため、特殊なファイルの誤削除を防ぐことができます。

3.  **`mayberemovefile` 関数の新規追加**:
    ```go
    // mayberemovefile removes a file only if it is a regular file
    // When running as a user with sufficient privileges, we may delete
    // even device files, for example, which is not intended.
    func mayberemovefile(s string) {
    	if fi, err := os.Lstat(s); err == nil && !fi.Mode().IsRegular() {
    		return
    	}
    	os.Remove(s)
    }
    ```
    この関数は、ファイル `s` を削除する前に、そのファイルが通常のファイルであるかを厳密にチェックします。
    *   `os.Lstat(s)`: ファイル `s` のファイル情報を取得します。シンボリックリンクの場合、リンク自体の情報を取得します。
    *   `err == nil`: ファイル情報が正常に取得できたことを確認します。
    *   `!fi.Mode().IsRegular()`: 取得したファイル情報 `fi` のモードが通常のファイルではないことを確認します。
    *   これらの条件がすべて真である場合（つまり、ファイルが存在し、かつそれが通常のファイルではない場合）、関数は `os.Remove(s)` を呼び出さずに即座に `return` します。
    *   それ以外の場合（ファイルが存在しない、エラーが発生した、または通常のファイルである場合）、`os.Remove(s)` が呼び出され、ファイルが削除されます。
    このロジックにより、特権ユーザーで実行された場合でも、`/dev/null` のような重要なシステムファイルを誤って削除するリスクが排除されます。

### `src/cmd/go/go_test.go` の変更点

1.  **`TestBuildOutputToDevNull` テスト関数の追加**:
    ```go
    // Issue 12407
    ```

    この新しいテストは、`go build -o /dev/null` のシナリオをシミュレートします。
    *   `tg := testgo(t)`: テスト環境をセットアップします。
    *   `defer tg.cleanup()`: テスト終了後にクリーンアップ処理が実行されるようにします。
    *   `tg.setenv("GOPATH", ...)`: `GOPATH` 環境変数をテスト用のディレクトリに設定します。
    *   `tg.run("build", "-o", os.DevNull, "go-cmd-test")`: `go build` コマンドを実行し、`-o` フラグで出力先を `os.DevNull`（`/dev/null` に相当）に指定します。`go-cmd-test` はテスト用のサンプルプログラムです。
    このテストは、`go build` が `/dev/null` のような特殊なファイルに出力しようとした際に、エラーなく正常に完了し、かつシステムに悪影響を与えないことを検証します。
