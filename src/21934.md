# [インデックス 21934] ファイルの概要

このコミットは、Go言語の標準ライブラリ `encoding/xml` パッケージにおけるXML名前空間（namespace）のエンコーディングに関する重要な修正です。これまでの実装では、XML名前空間が正しく解釈されず、不適切なプレフィックスの使用や、場合によっては無効なXML出力が生成される問題がありました。この変更により、`xmlns` 属性が適切に処理され、要素や属性に正しい名前空間プレフィックスが適用されるようになります。

## 変更の背景

このコミットの背景には、Go言語の `encoding/xml` パッケージがXML名前空間を適切に処理できないという長年の問題がありました。具体的には、XMLをGoのデータ構造からエンコード（マーシャリング）する際に、名前空間の宣言（`xmlns` 属性）が正しく解釈されず、結果として以下のような問題が発生していました。

1.  **`xmlns` 属性の誤った扱い**: 既存のXMLプリンターは `xmlns` 属性を単なる通常の属性として扱っており、それが名前空間の宣言であるという特別な意味を理解していませんでした。このため、名前空間が定義されていても、その名前空間に属する要素や属性に適切なプレフィックスが付与されない、あるいは不必要な名前空間宣言が重複して出力されるなどの問題が生じていました。
2.  **無効なXMLの生成**: 名前空間の処理が不適切なため、生成されるXMLがXML仕様に準拠しない、あるいは意図しない構造になることがありました。特に、名前空間のスコープやプレフィックスの解決が正しく行われないと、XMLパーサーがエラーを報告したり、期待通りのパース結果が得られなかったりする可能性がありました。
3.  **Issue #7535の修正**: この問題はGoのIssueトラッカーで「Issue 7535: encoding/xml: round trip of xml with namespaces fails」として報告されていました。このIssueは、名前空間を含むXMLをデコード（アンマーシャリング）してから再度エンコード（マーシャリング）すると、元のXMLと異なる、あるいは無効なXMLが生成されるという、いわゆる「ラウンドトリップ問題」を指摘していました。これは、`encoding/xml` パッケージが名前空間の情報を内部で正しく保持・利用できていなかったことに起因します。

このコミットは、これらの問題を解決し、`encoding/xml` パッケージがXML名前空間をより堅牢かつ正確に処理できるようにすることを目的としています。

## 前提知識の解説

### XML名前空間 (XML Namespaces)

XML名前空間は、XMLドキュメント内で要素名や属性名の衝突を避けるためのメカニズムです。異なるXML語彙（スキーマ）から要素や属性を組み合わせる際に特に重要になります。

*   **衝突の回避**: 例えば、異なるXMLスキーマが両方とも `<title>` という要素を定義している場合、名前空間を使用することで、どちらの `<title>` を指しているのかを明確に区別できます。
*   **宣言**: 名前空間は `xmlns` 属性を使って宣言されます。
    *   **デフォルト名前空間**: `xmlns="http://example.com/ns"` のようにプレフィックスなしで宣言された場合、その要素とその子孫要素（プレフィックスが明示的に指定されていないもの）はすべてこの名前空間に属します。
    *   **プレフィックス付き名前空間**: `xmlns:prefix="http://example.com/ns"` のようにプレフィックスを付けて宣言された場合、そのプレフィックスを持つ要素や属性がその名前空間に属します。例: `<prefix:element>`
*   **スコープ**: 名前空間の宣言は、それが宣言された要素からその子孫要素にわたって有効です。子孫要素で同じプレフィックスやデフォルト名前空間が再宣言された場合、新しい宣言がそのスコープ内で有効になります。
*   **`xml` および `xmlns` プレフィックス**: `xml` プレフィックス（`http://www.w3.org/XML/1998/namespace`）と `xmlns` プレフィックス（`http://www.w3.org/2000/xmlns/`）はXML仕様で予約されており、特別な意味を持ちます。

### Goの `encoding/xml` パッケージ

`encoding/xml` パッケージは、Goのデータ構造とXMLドキュメントの間でデータを変換するための機能を提供します。

*   **`xml.Encoder`**: Goのデータ構造をXMLにエンコードするために使用されます。`Encode` メソッドや `EncodeToken` メソッドを通じてXMLトークン（`StartElement`, `EndElement`, `CharData` など）を書き出します。
*   **`xml.Decoder`**: XMLドキュメントをGoのデータ構造にデコードするために使用されます。`Token` メソッドを通じてXMLトークンを読み取ります。
*   **`xml.Name`**: XMLの要素名や属性名を表す構造体で、`Space`（名前空間URI）と `Local`（ローカル名）のフィールドを持ちます。
*   **`xml.StartElement`**: XMLの開始タグを表す構造体で、`Name` と `Attr`（属性のリスト）を持ちます。
*   **`xml.Attr`**: XMLの属性を表す構造体で、`Name` と `Value` を持ちます。

これまでの `encoding/xml` パッケージは、`xml.Name` の `Space` フィールドに名前空間URIを格納していましたが、エンコード時にこの情報から適切な `xmlns` 属性を生成したり、プレフィックスを解決したりするロジックが不十分でした。

## 技術的詳細

このコミットの技術的詳細は、`encoding/xml` パッケージの内部構造、特にXMLのエンコードを担当する `printer` 型の大幅な変更に集約されます。

### 1. `printer` 型の拡張

XMLの出力状態を管理する `printer` 型に、名前空間管理のための新しいフィールドが追加されました。

*   `defaultNS string`: 現在のスコープにおけるデフォルト名前空間のURIを保持します。
*   `attrNS map[string]string`: プレフィックスから名前空間URIへのマッピングを保持します（例: `{"ex": "http://example.com/schema"}`）。
*   `attrPrefix map[string]string`: 名前空間URIからプレフィックスへのマッピングを保持します（例: `{"http://example.com/schema": "ex"}`）。
*   `prefixes []printerPrefix`: 名前空間の宣言履歴をスタック形式で管理します。これにより、要素の開始・終了に伴う名前空間スコープの変更を正確に追跡できます。

### 2. `printerPrefix` 構造体の導入

名前空間の宣言を記録するための新しい内部構造体 `printerPrefix` が導入されました。

```go
type printerPrefix struct {
	prefix string
	url    string
	mark   bool
}
```

*   `prefix`: 宣言されたプレフィックス（デフォルト名前空間の場合は空文字列）。
*   `url`: そのプレフィックスが指す名前空間URI。
*   `mark`: このエントリが新しい要素の開始（名前空間スコープの開始）を示すマーカーであるかどうか。これにより、要素が終了した際に、その要素内で宣言された名前空間のみをスタックからポップできるようになります。

### 3. 名前空間管理ロジックの刷新

`printer` 型に、名前空間の定義、解決、および出力を行うための多数の新しいメソッドが追加・修正されました。

*   **`defineNS(attr Attr, ignoreNonEmptyDefault bool) error`**: `xmlns` 属性を解析し、新しい名前空間宣言として `printer` の内部状態に登録します。既存のプレフィックスとの衝突や、`xmlns` 属性の再定義に関するXML仕様のルールを考慮します。
*   **`createNSPrefix(url string, isAttr bool)`**: 指定された名前空間URIに対して、まだプレフィックスが定義されていない場合に新しいプレフィックスを生成し、登録します。属性の名前空間の場合（`isAttr=true`）はデフォルト名前空間を使用しないなど、XMLのルールに従います。
*   **`pushPrefix(prefix, url string)`**: 新しい名前空間宣言を `prefixes` スタックにプッシュし、`attrNS` と `attrPrefix` マップを更新します。
*   **`popPrefix()`**: 要素の終了時に、その要素内で宣言された名前空間を `prefixes` スタックからポップし、対応するマッピングを元に戻します。これにより、名前空間のスコープが正しく管理されます。
*   **`nsForPrefix(prefix string) string`**: 指定されたプレフィックスに対応する名前空間URIを返します。
*   **`setAttrPrefix(prefix, url string)`**: `attrNS` と `attrPrefix` マップを直接更新するヘルパー関数です。
*   **`writeNamespaces()`**: 現在の要素で新しく定義された名前空間宣言（`xmlns` 属性）をXML出力ストリームに書き出します。
*   **`writeName(name Name, isAttr bool)`**: `xml.Name` を受け取り、その名前空間に基づいて適切なプレフィックスを解決し、`prefix:local` 形式でXML出力ストリームに書き出します。

### 4. エンコードフローの変更

`Encoder.EncodeToken` および `printer.writeStart` メソッドが、上記の新しく導入された名前空間管理ロジックを利用するように変更されました。

*   `writeStart` メソッド内で、要素の開始時に `markPrefix()` を呼び出して新しいスコープをマークし、要素の属性から明示的な名前空間宣言を `defineNS` で処理します。
*   その後、要素名や属性の名前空間URIに基づいて `createNSPrefix` を呼び出し、必要に応じて新しいプレフィックスを生成します。
*   `writeNamespaces()` を呼び出して、その要素で宣言されたすべての `xmlns` 属性をまとめて出力します。
*   要素名や属性名の出力には `writeName` を使用し、正しいプレフィックスが適用されるようにします。
*   `writeEnd` メソッドでは、要素の終了時に `popPrefix()` を呼び出して名前空間スコープを元に戻します。

### 5. `xml.Name` と `xml.StartElement` の拡張

*   **`Name.isNamespace() bool`**: `xml.Name` が `xmlns` 属性（名前空間宣言）であるかどうかを判定するヘルパーメソッドが追加されました。
*   **`StartElement.setDefaultNamespace()`**: 要素の名前空間をその要素のデフォルト名前空間として宣言するためのヘルパーメソッドが追加されました。これにより、Goの構造体からXMLをマーシャリングする際に、要素の名前空間が自動的にデフォルト名前空間として設定される「歴史的振る舞い」が維持されます。

これらの変更により、`encoding/xml` パッケージはXML名前空間の複雑なルールをより正確に理解し、適用できるようになり、結果としてより仕様に準拠したXML出力を生成できるようになりました。特に、名前空間のスコープ管理が改善されたことで、ラウンドトリップ問題が解決され、より信頼性の高いXML処理が可能になりました。

## コアとなるコードの解説

### `printer` 構造体と `printerPrefix`

`printer` 構造体は、XMLエンコーディングの内部状態を管理する中心的な役割を担います。このコミットでは、名前空間の管理に特化したフィールドが追加されました。

```go
type printer struct {
	// ... 既存のフィールド ...
	defaultNS  string              // 現在のデフォルト名前空間URI
	attrNS     map[string]string   // プレフィックス -> 名前空間URI のマッピング
	attrPrefix map[string]string   // 名前空間URI -> プレフィックス のマッピング
	prefixes   []printerPrefix     // 名前空間宣言のスタック
	tags       []Name              // 要素名のスタック
}

type printerPrefix struct {
	prefix string // プレフィックス (デフォルト名前空間の場合は "")
	url    string // 名前空間URI
	mark   bool   // 新しい要素の開始を示すマーカー
}
```

`prefixes` スライスは、XMLの要素のネスト構造に対応して名前空間のスコープを管理するためのスタックとして機能します。`printerPrefix` の `mark` フィールドは、新しい要素が開始された位置を示し、その要素内で宣言された名前空間のみを、要素が終了したときに元に戻せるようにします。

### 名前空間の定義と解決 (`defineNS`, `createNSPrefix`, `writeName`)

*   **`defineNS`**: XMLの開始タグ内で `xmlns` 属性が見つかった場合、このメソッドが呼び出されます。例えば `<foo xmlns:ex="http://example.com/schema">` のような属性を解析し、`printer` の `attrNS` と `attrPrefix` マップに `ex` と `http://example.com/schema` のマッピングを登録します。また、`prefixes` スタックにもこの宣言をプッシュします。これにより、エンコーダーはどのプレフィックスがどの名前空間URIに対応するかを常に把握できます。

*   **`createNSPrefix`**: 要素や属性が特定の名前空間に属しているが、その名前空間に対応するプレフィックスがまだ定義されていない場合に呼び出されます。このメソッドは、名前空間URIから適切なプレフィックス（例: `ex` や `_`）を生成し、それを `printer` の内部状態に登録します。これにより、XML出力時にその名前空間に属する要素や属性に正しいプレフィックスが付与されるようになります。

*   **`writeName`**: 要素名や属性名をXMLに出力する際に使用されます。このメソッドは、与えられた `xml.Name` の `Space` フィールド（名前空間URI）を見て、`printer` の内部状態から対応するプレフィックスを検索します。プレフィックスが見つかれば `prefix:local` 形式で、見つからなければ `local` 形式で出力します。これにより、名前空間が正しく解決されたXMLが生成されます。

### 名前空間の出力 (`writeNamespaces`)

`(*printer).writeNamespaces()` メソッドは、現在の要素で新しく定義されたすべての `xmlns` 属性をXML出力ストリームに書き出す役割を担います。

```go
func (p *printer) writeNamespaces() {
	for i := len(p.prefixes) - 1; i >= 0; i-- {
		prefix := p.prefixes[i]
		if prefix.mark { // 要素の開始マーカーに到達したら終了
			return
		}
		p.WriteString(" ")
		if prefix.prefix == "" {
			// デフォルト名前空間
			p.WriteString(`xmlns="`)
		} else {
			// プレフィックス付き名前空間
			p.WriteString("xmlns:")
			p.WriteString(prefix.prefix)
			p.WriteString(`="`)
		}
		EscapeText(p, []byte(p.nsForPrefix(prefix.prefix))) // 名前空間URIをエスケープして出力
		p.WriteString(`"`)
	}
}
```

このループは `prefixes` スタックを逆順に辿り、現在の要素内で新しく宣言された名前空間（`mark` が `true` のエントリに到達するまで）をすべて `xmlns` 属性として出力します。これにより、XMLの開始タグに必要な名前空間宣言がまとめて、かつ正しい順序で出力されます。

### スコープ管理 (`markPrefix`, `popPrefix`)

*   **`markPrefix()`**: `writeStart` メソッド内で、新しい要素の処理を開始する直前に呼び出されます。これは `prefixes` スタックに `mark: true` の `printerPrefix` エントリをプッシュすることで、新しい名前空間スコープの開始を示します。
*   **`popPrefix()`**: `writeEnd` メソッド内で、要素の処理が終了したときに呼び出されます。このメソッドは `prefixes` スタックを逆順に辿り、`mark: true` のエントリに到達するまで、その要素内で宣言されたすべての名前空間をスタックからポップし、`attrNS` と `attrPrefix` マップの状態を元に戻します。これにより、名前空間のスコープが正しく管理され、親要素の名前空間宣言が復元されます。

これらの変更により、`encoding/xml` パッケージはXML名前空間の複雑なセマンティクスを正確にモデル化し、Goのデータ構造からXMLを生成する際に、より堅牢で仕様に準拠した出力を提供できるようになりました。
