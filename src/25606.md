# [インデックス 25606] ファイルの概要

このコミットは、Go言語の`math`および`math/big`パッケージにMIPS64およびMIPS64LE（Little-Endian）アーキテクチャのサポートを追加するものです。具体的には、これらのアーキテクチャ向けに、`math/big`パッケージの多倍長整数演算と`math`パッケージの標準数学関数に対するアセンブリスタブファイルが導入されました。これらのスタブは、現時点では純粋なGo実装に処理を委譲する形になっていますが、将来的なパフォーマンス最適化のための基盤を築いています。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。MIPS64は、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで広く利用されている64ビットRISCアーキテクチャです。Go言語がこれらのプラットフォームで効率的に動作するためには、基本的な数学演算や多倍長整数演算といったコアライブラリがMIPS64アーキテクチャに対応している必要があります。

このコミットは、MIPS64およびMIPS64LEアーキテクチャ向けに`math`および`math/big`パッケージのサポートを導入する初期段階です。通常、新しいアーキテクチャのサポートを追加する際には、まず純粋なGoコードで機能が動作することを確認し、その後、パフォーマンスが重要な部分についてはアセンブリ言語による最適化された実装を追加します。このコミットでは、アセンブリスタブを導入することで、Goコンパイラがこれらの関数をMIPS64向けにビルドできるようにし、将来的なアセンブリ最適化のためのプレースホルダーを提供しています。

## 前提知識の解説

### MIPS64アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64は、その64ビット版であり、64ビットのレジスタとアドレス空間を持ちます。MIPS64LEは、MIPS64のLittle-Endian版を指します（LEはLittle-Endian、通常版はBig-Endian）。エンディアンネスは、マルチバイトデータをメモリに格納する際のバイト順序を定義します。

### `math`パッケージ

Go言語の標準ライブラリの一部であり、浮動小数点数演算（三角関数、指数関数、対数関数など）やその他の基本的な数学関数を提供します。これらの関数は、多くの場合、パフォーマンスが重要であるため、特定アーキテクチャ向けにアセンブリ言語で最適化されることがあります。

### `math/big`パッケージ

Go言語の標準ライブラリの一部であり、任意精度の整数（`big.Int`）、有理数（`big.Rat`）、浮動小数点数（`big.Float`）を扱うための機能を提供します。これらの演算は、通常のCPUレジスタのサイズを超える数値を扱うため、複数のワード（Goでは`Word`型）に分割して処理されます。そのため、`mulWW`（Word同士の乗算）や`addVV`（Wordベクトルの加算）のような低レベルな演算が頻繁に利用され、これらはパフォーマンスのボトルネックになりやすいため、アセンブリ言語による最適化が特に有効です。

### アセンブリスタブと`JMP`命令

Go言語のランタイムや標準ライブラリでは、特定のパフォーマンスクリティカルな関数について、Goで書かれた汎用実装（通常は関数名の末尾に`_g`が付く）と、特定アーキテクチャ向けにアセンブリ言語で書かれた最適化実装の両方を提供することがあります。
このコミットで追加されたアセンブリファイル（`.s`拡張子）は「スタブ」として機能します。スタブとは、実際の処理を行わず、別の関数に処理を転送する（ジャンプする）小さなコードのことです。
Goのアセンブリでは、`TEXT`ディレクティブで関数を定義し、`JMP`命令を使って別の関数に制御を移します。例えば、`JMP ·mulWW_g(SB)`は、`mulWW`という関数が呼び出された際に、純粋なGoで実装された`mulWW_g`関数にジャンプして実行を委譲することを意味します。`SB`はStatic Baseレジスタを指し、シンボルがグローバルであることを示します。

### ビルドタグ（`+build`ディレクティブ）

Goのソースファイルには、`+build`ディレクティブを使ってビルドタグを指定できます。これにより、特定の環境（OS、アーキテクチャなど）でのみそのファイルをコンパイルするように制御できます。
例: `// +build !math_big_pure_go,mips64 !math_big_pure_go,mips64le`
これは、「`math_big_pure_go`タグが設定されておらず、かつMIPS64またはMIPS64LEアーキテクチャの場合にこのファイルをビルドする」という意味になります。`!math_big_pure_go`は、純粋なGo実装のみを使用するモードではないことを示唆しており、アセンブリ実装が存在する場合に有効になります。

## 技術的詳細

このコミットでは、以下の2つの新しいアセンブリファイルが追加されました。

1.  `src/math/big/arith_mips64x.s`: `math/big`パッケージの多倍長整数演算の低レベルな算術操作（例: `mulWW`, `addVV`など）に対するMIPS64/MIPS64LE向けスタブ。
2.  `src/math/stubs_mips64x.s`: `math`パッケージの標準数学関数（例: `Sin`, `Cos`, `Sqrt`など）に対するMIPS64/MIPS64LE向けスタブ。

これらのファイルの内容は非常に似ており、各関数に対して以下のようなパターンで記述されています。

```assembly
TEXT ·FunctionName(SB),NOSPLIT,$0
	JMP ·functionName_g(SB)
```

*   `TEXT ·FunctionName(SB),NOSPLIT,$0`: `FunctionName`という名前の関数を定義します。
    *   `TEXT`: 関数定義の開始。
    *   `·FunctionName`: Goのリンカが認識するシンボル名。パッケージ名と関数名がドットで区切られます。
    *   `(SB)`: シンボルが静的ベース（グローバル）であることを示します。
    *   `NOSPLIT`: この関数がスタックを分割しないことを示します。これは、非常に短い関数や、スタックフレームを必要としないジャンプ命令のみで構成される関数によく使われます。
    *   `$0`: この関数のスタックフレームサイズが0バイトであることを示します。
*   `JMP ·functionName_g(SB)`: `FunctionName`が呼び出された際に、`functionName_g`という別の関数に無条件にジャンプします。`_g`サフィックスは、通常、純粋なGoで書かれた汎用実装を指します。

このアプローチの利点は以下の通りです。

*   **初期サポートの迅速な導入**: まずは既存のGo実装に委譲することで、新しいアーキテクチャでの基本的な機能動作を迅速に確立できます。
*   **将来的な最適化のパス**: アセンブリファイルが存在することで、後からパフォーマンスが重要な関数について、MIPS64/MIPS64LEの命令セットを活用した最適化されたアセンブリ実装に置き換えることが容易になります。その際、`JMP`命令を実際の最適化コードに置き換えるだけで済みます。
*   **コンパイルエラーの回避**: Goコンパイラは、特定のアーキテクチャ向けにビルドする際に、そのアーキテクチャ固有のファイルを探します。これらのスタブファイルが存在することで、MIPS64/MIPS64LE向けビルド時に必要なシンボルが見つからないというコンパイルエラーを防ぎます。

## コアとなるコードの解説

両ファイルともに、`TEXT`ディレクティブでGoの関数シンボルを定義し、その直後に`JMP`命令で対応する純粋なGo実装（`_g`サフィックスが付く関数）にジャンプしています。

例えば、`src/math/big/arith_mips64x.s`の`mulWW`関数は、MIPS64/MIPS64LEアーキテクチャで`math/big.mulWW`が呼び出された際に、`math/big.mulWW_g`というGoで書かれた汎用実装に処理を転送します。同様に、`src/math/stubs_mips64x.s`の`Sin`関数は、`math.Sin`が呼び出された際に、`math.sin`（Goの内部実装）に処理を転送します。

この実装は、MIPS64/MIPS64LEアーキテクチャでこれらの関数が呼び出されたときに、Goランタイムが適切な実装を見つけられるようにするためのものです。現時点では、これらの関数はアセンブリレベルでの最適化は行っておらず、既存のGoコードのパフォーマンスに依存します。しかし、このスタブの存在により、将来的にMIPS64の特定の命令セット（例: 乗算、除算、浮動小数点演算命令など）を活用した、より高速なアセンブリ実装を導入する道が開かれました。
