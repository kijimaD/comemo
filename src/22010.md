## 元コミット内容

```
cmd/gc: generate simpler names for closures

Fixes #8291

There were several complaints about closure names in the issue tracker.
The first problem is that you see names like net/http.func·001
in profiles, traces, etc. And there is no way to figure out what
is that function.
Another issue is non-US-ascii symbols. All programs out there
should accept UTF-8. But unfortunately it is not true in reality.
For example, less does not render middle dot properly.

This change prepends outer function name to closure name and
replaces middle dot with dot. Now names look like:

main.glob.func1
main.glob.func2
main.glob.func2.1
main.init.1
main.init.1.func1
main.init.1.func1.1
main.main.func1
main.main.func1.1

Change-Id: I725726af88f2ad3ced2e3450f0f06bf459fd91c0
Reviewed-on: https://go-review.googlesource.com/3964
Reviewed-by: Russ Cox <rsc@golang.org>
```

## 変更の背景

このコミットは、Goのクロージャおよび`init`関数の自動生成される名前に関する複数の問題に対処するために行われました。主な問題点は以下の通りです。

1.  **可読性の低さ**: 以前の命名規則では、プロファイリングツールやトレースツールで`net/http.func·001`のような名前が表示されていました。これらの名前は、それがどの関数に属するクロージャなのかを特定するのが困難であり、デバッグやパフォーマンス分析の妨げとなっていました。
2.  **非ASCII文字による表示問題**: クロージャ名に使用されていた中点（`·`、U+00B7）は非ASCII文字であり、`less`などの一部のターミナルツールやプログラムで正しくレンダリングされないことがありました。これは、UTF-8を完全にサポートしていない環境での互換性問題を引き起こしていました。

これらの問題は、開発者がGoプログラムの挙動を理解し、デバッグする上で大きな障壁となっていたため、命名規則の改善が求められていました。

## 前提知識の解説

### Goのクロージャ（無名関数）

Go言語におけるクロージャは、関数リテラル（無名関数）の一種で、それが定義された環境（レキシカルスコープ）の変数を参照できる特性を持ちます。これにより、外部の変数を「キャプチャ」して、その変数の状態を保持したまま関数を実行できます。クロージャは、コールバック、イベントハンドラ、並行処理におけるタスクの定義など、様々な場面で利用されます。

Goコンパイラは、これらの無名関数を内部的に処理するために、一意の名前を生成します。この生成される名前が、プロファイリングやデバッグの際に表示されることになります。

### `cmd/gc`コンパイラ

`cmd/gc`は、Go言語の公式かつ主要なコンパイラです。Goのソースコードを機械語に変換する役割を担っています。コンパイルプロセスは、字句解析、構文解析、型チェック、中間表現（IR）の構築、そして最終的な機械語の生成といった複数のフェーズに分かれています。クロージャの命名は、この`cmd/gc`コンパイラの内部処理の一部として行われます。

### `init`関数

Go言語の`init`関数は、パッケージが初期化される際に自動的に実行される特殊な関数です。各パッケージは複数の`init`関数を持つことができ、これらはパッケージ内の変数の初期化や、プログラムの実行開始前に必要なセットアップを行うために使用されます。`init`関数もまた、コンパイラによって内部的に一意の名前が与えられます。

### 中点（`·`）と文字エンコーディング

中点（`·`）は、一部の言語で句読点や区切り記号として使用される文字です。しかし、ASCII文字セットには含まれておらず、UTF-8などのより広範な文字エンコーディングでのみ表現されます。古いシステムや、UTF-8のサポートが不完全なツールでは、このような非ASCII文字が正しく表示されず、文字化けや表示崩れの原因となることがあります。Goのコンパイラが生成する内部名にこの文字が使われていたことが、互換性の問題を引き起こしていました。

## 技術的詳細

このコミットの主要な変更点は、クロージャと`init`関数の命名規則を、より人間が理解しやすく、かつ互換性の高い形式に変更したことです。

1.  **クロージャ名の改善**:
    *   以前は`func·001`のような形式でしたが、変更後は`main.main.func1`や`main.init.1.func1`のように、**外側の関数名がクロージャ名のプレフィックスとして付加される**ようになりました。これにより、プロファイリングツールなどで表示される名前を見ただけで、そのクロージャがどの関数内で定義されたものか、より容易に特定できるようになります。
    *   ネストされたクロージャの場合、`main.main.func1.1`のように、外側のクロージャ名がさらにプレフィックスとして付加され、階層的な関係が明確になります。
    *   グローバルスコープのクロージャには`glob`というプレフィックスが付き、`main.glob.func1`のようになります。
    *   中点（`·`）は、互換性の高い通常のドット（`.`）に置き換えられました。

2.  **`init`関数名の改善**:
    *   `init`関数も同様に、中点（`·`）がドット（`.`）に置き換えられ、`init·1`から`init.1`のような形式に変更されました。

これらの変更は、`src/cmd/gc/closure.c`、`src/cmd/gc/go.h`、`src/cmd/gc/init.c`、`src/cmd/gc/pgen.c`の4つのファイルにわたって実装されています。

*   `src/cmd/gc/closure.c`: クロージャの命名ロジックが主に変更されました。`closurename`という新しい静的関数が導入され、再帰的に外側の関数名を解決し、新しい命名規則に従ってクロージャ名を生成します。また、`Node`構造体に`outerfunc`フィールドが追加され、クロージャが定義された外側の関数への参照を保持できるようになりました。
*   `src/cmd/gc/go.h`: `Node`構造体に`closgen`（クロージャのジェネレーション番号）と`outerfunc`（外側の関数へのポインタ）のフィールドが追加されました。
*   `src/cmd/gc/init.c`: `init`関数の命名ロジックが変更され、中点（`·`）がドット（`.`）に置き換えられました。
*   `src/cmd/gc/pgen.c`: `init`関数の名前をチェックする箇所で、新しい命名規則に合わせて文字列比較のパターンが変更されました。

## コアとなるコードの解説

### `src/cmd/gc/closure.c`

*   **`closurehdr(Node *ntype)`**:
    *   `n->outerfunc = curfn;` の行が追加されました。これは、新しく作成されるクロージャノード（`n`）に、現在処理中の外側の関数（`curfn`）への参照を保存するものです。これにより、ネストされたクロージャの命名時に、その親となる関数を辿れるようになります。

*   **`closurename(Node *n)` 関数の追加**:
    *   この関数は、与えられたクロージャノード`n`に対して、新しい命名規則に基づいたシンボル名（`Sym*`）を生成します。
    *   **再帰的な命名**: ネストされたクロージャの場合、内側のクロージャから型チェックが始まるため、外側のクロージャの名前がまだ確定していないことがあります。この関数は、`n->outerfunc->op == OCLOSURE`の場合に自身を再帰的に呼び出すことで、外側のクロージャの名前を先に解決し、完全な階層的な名前を構築します。
    *   **命名ロジック**:
        *   `n->outerfunc == N` (グローバルクロージャの場合): `outer`は`"glob"`、`prefix`は`"func"`となり、`glob.funcN`のような名前が生成されます。
        *   `n->outerfunc->op == ODCLFUNC` (名前付き関数内のクロージャの場合): `outer`は外側の関数名（例: `main`）、`prefix`は`"func"`となり、`main.funcN`のような名前が生成されます。
        *   `n->outerfunc->op == OCLOSURE` (ネストされたクロージャの場合): `outer`は再帰的に解決された外側のクロージャ名、`prefix`は空文字列となり、`outerClosureName.N`のような名前が生成されます。
    *   `snprint(namebuf, sizeof namebuf, "%s.%s%d", outer, prefix, gen);` の行で、外側の関数名、プレフィックス、生成番号をドットで結合して新しい名前を構築しています。
    *   `n->sym = lookup(namebuf);` で、生成された名前のシンボルをルックアップし、クロージャノードに設定します。

*   **`makeclosure(Node *func)`**:
    *   `snprint(namebuf, sizeof namebuf, "func·%.3d", ++closgen);` の行が削除され、代わりに `xfunc->nname = newname(closurename(func));` が追加されました。これにより、従来の固定的な命名ではなく、新しく導入された`closurename`関数を使ってクロージャ名が生成されるようになりました。

*   **`walkclosure(Node *func, NodeList **init)`**:
    *   コメント内の例で、`func·001`が`func.1`に変更され、中点（`·`）がドット（`.`）に置き換えられたことが示されています。
    *   `typ->list = list1(nod(ODCLFIELD, newname(lookup("F")), typenod(types[TUINTPTR])));` の行が `typ->list = list1(nod(ODCLFIELD, newname(lookup(".F")), typenod(types[TUINTPTR])));` に変更されました。これは、クロージャの構造体フィールド名も中点からドットに変更されたことを示しています。

*   **`makepartialcall(Node *fn, Type *t0, Node *meth)`**:
    *   `smprint`関数で生成される名前のフォーマット文字列が変更され、中点（`·`）がハイフン（`-`）に置き換えられました。これは、メソッド値の生成される名前にも同様の変更が適用されたことを示しています。

### `src/cmd/gc/go.h`

*   `struct Node`に以下のフィールドが追加されました。
    *   `int closgen;`: その関数/クロージャ内で生成されたクロージャの数を追跡するためのカウンター。これにより、各関数スコープ内でクロージャに一意の番号を割り当てることができます。
    *   `Node* outerfunc;`: そのクロージャが定義された外側の関数（またはクロージャ）へのポインタ。これにより、ネストされたクロージャの階層を辿ることが可能になります。

### `src/cmd/gc/init.c`

*   **`renameinit(void)`**:
    *   `snprint(namebuf, sizeof(namebuf), "init·%d", ++initgen);` が `snprint(namebuf, sizeof(namebuf), "init.%d", ++initgen);` に変更されました。これにより、`init`関数の名前も中点からドットに置き換えられました。

*   **`anyinit(NodeList *n)`**:
    *   `snprint(namebuf, sizeof(namebuf), "init·1");` と `s = lookup(namebuf);` の組み合わせが `s = lookup("init.1");` に変更されました。これは、特定の`init`関数名をルックアップする際に、新しい命名規則が適用されることを示しています。

*   **`fninit(NodeList *n)`**:
    *   `snprint(namebuf, sizeof(namebuf), "init·%d", i);` が `snprint(namebuf, sizeof(namebuf), "init.%d", i);` に変更されました。これにより、`init`関数の名前を生成するループでも新しい命名規則が適用されます。

### `src/cmd/gc/pgen.c`

*   **`compile(Node *fn)`**:
    *   `strncmp(fn->nname->sym->name, "init·", 6) == 0` が `strncmp(fn->nname->sym->name, "init.", 5) == 0` に変更されました。これは、`init`関数の名前をチェックする際に、新しい命名規則に合わせて比較文字列が更新されたことを示しています。文字列の長さも`6`から`5`に変わっています。

これらの変更により、Goコンパイラはより情報量が多く、かつ互換性の高いクロージャおよび`init`関数名を生成するようになり、デバッグやプロファイリングの体験が大幅に改善されました。
