## 変更の背景

Go言語の型チェックシステムは、ソースコードを解析し、その型が正しいかどうかを検証する重要なコンポーネントです。このシステムは、他のパッケージが提供する型情報に依存するため、パッケージのインポート機能は型チェッカーの核となります。

このコミット以前は、`go/types`パッケージが直接インポートのロジックの一部を管理していました。しかし、異なるコンパイラ（例: `gc`や`gccgo`）がそれぞれ独自のパッケージエクスポート形式を持つため、型チェッカーがこれらの異なる形式を透過的に扱えるようにする必要がありました。また、型チェックのプロセスをより柔軟にし、特定のインポート戦略（例えば、テストにおけるパッケージの再利用）を容易に実現できるようにすることも求められていました。

この変更の主な背景は以下の点に集約されます。

1.  **インポートメカニズムの抽象化と分離**: 型チェッカーからインポートの具体的な実装を分離し、より汎用的なインターフェースを通じてインポートを行えるようにすること。これにより、将来的に新しいコンパイラやインポート形式が追加された場合でも、型チェッカー本体に大きな変更を加えることなく対応できるようになります。
2.  **`unsafe`パッケージの特殊な扱い**: `unsafe`パッケージはGo言語の組み込みパッケージであり、その型情報はコンパイラに依存せず、型チェッカーが直接知っているべきものです。以前はインポーターを通じて処理されていましたが、これを型チェッカー内部で直接扱うことで、インポート処理の効率化とロジックの単純化を図ります。
3.  **テスト効率の向上**: 標準ライブラリのテストなど、多数のパッケージを型チェックするシナリオでは、同じパッケージが何度もインポートされることがありました。インポーターの再利用を可能にすることで、このオーバーヘッドを削減し、テスト時間を短縮することを目指しました。
4.  **APIの整理**: `types.Check`のような高レベルのヘルパー関数を削除し、より低レベルで柔軟な`types.Config.Check`の使用を促すことで、APIの意図を明確にし、ユーザーが型チェックプロセスをより細かく制御できるようにします。

これらの背景から、`go/importer`パッケージが導入され、`go/types`と`go/internal/gcimporter`が再構築されることになりました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびコンパイラ関連の概念について理解している必要があります。

1.  **Go言語のパッケージシステム**: Go言語のコードはパッケージに分割され、他のパッケージの機能を利用するには`import`文を使用します。パッケージは、コンパイルされたバイナリ（通常は`.a`ファイルなど）として配布され、その中にはエクスポートされた型や関数の情報（エクスポートデータ）が含まれています。
2.  **型チェッカー (`go/types`)**: `go/types`パッケージは、Go言語のソースコードを解析し、その型がGo言語の仕様に準拠しているかを確認する役割を担います。これには、変数の型、関数のシグネチャ、式の型推論、インターフェースの実装チェックなどが含まれます。型チェッカーは、依存するパッケージの型情報を参照する必要があります。
3.  **インポーター**: インポーターは、コンパイル済みのパッケージファイルから型情報を読み込み、それを型チェッカーが利用できる形式（`go/types.Package`オブジェクトなど）に変換するコンポーネントです。Go言語には、公式コンパイラである`gc`（Go Compiler）と、GCCベースの`gccgo`という主要なコンパイラがあり、それぞれ異なるエクスポート形式を使用します。
4.  **`gcimporter` (`go/internal/gcimporter`)**: これは`gc`コンパイラが生成するパッケージのエクスポートデータを読み込むためのインポーターです。Goのツールチェイン内部で使用されるため、`internal`パッケージとして提供されています。
5.  **`go/ast`と`go/token`**: `go/ast`パッケージはGo言語の抽象構文木（AST）を定義し、`go/token`パッケージはソースコード内の位置情報（ファイル、行、列など）を扱います。型チェッカーはこれらのパッケージを利用してソースコードを解析します。
6.  **`types.Config`**: `go/types`パッケージの`Config`構造体は、型チェックの挙動をカスタマイズするための設定を提供します。これには、エラーハンドリング、インポーターの指定、型情報の収集方法などが含まれます。
7.  **`unsafe`パッケージ**: `unsafe`パッケージは、Go言語の型システムをバイパスして、低レベルのメモリ操作を可能にする特殊な組み込みパッケージです。ポインタ演算や、異なる型の間の変換など、通常では許可されない操作を提供します。このパッケージはコンパイラに深く関連しており、その型情報はGo言語の仕様の一部として扱われます。

これらの知識を前提として、今回の変更が型チェックのアーキテクチャにどのように影響を与えたかを詳細に見ていきます。

## 技術的詳細

このコミットの技術的な核心は、パッケージインポートの責任を`go/types`パッケージから`go/importer`パッケージへと移譲し、より抽象化されたインポーターインターフェースを導入した点にあります。

### 1. `go/importer`パッケージの導入

新しく追加された`src/go/importer/importer.go`ファイルは、コンパイラ固有のインポーターを提供する役割を担います。

-   **`importer.For(compiler string, lookup Lookup) types.Importer`**: この関数は、指定されたコンパイラ（例: "gc", "gccgo"）と、パッケージデータを読み込むための`Lookup`関数（`io.ReadCloser`を返す関数）を受け取り、対応する`types.Importer`インターフェースの実装を返します。これにより、型チェッカーは特定のコンパイラに依存することなく、汎用的な`types.Importer`インターフェースを通じてパッケージをインポートできるようになります。
-   **`importer.Default() types.Importer`**: 実行中のバイナリをビルドしたコンパイラ（`runtime.Compiler`で取得）に対応するデフォルトのインポーターを返します。これは、ほとんどのGoアプリケーションで利用される標準的なインポート方法を提供します。
-   **`types.Importer`インターフェースの定義**: `go/types`パッケージ内で、`Importer`が関数型からインターフェース型に変更されました。
    ```go
    type Importer interface {
        // Import returns the imported package for the given import
        // path, or an error if the package couldn't be imported.
        // Import is responsible for returning the same package for
        // matching import paths.
        Import(path string) (*Package, error)
    }
    ```
    この変更により、インポーターの実装はより柔軟になり、状態を持つことができるようになりました（例えば、既にインポートしたパッケージをキャッシュするなど）。

### 2. `go/types`パッケージの変更

`go/types`パッケージは、新しいインポートシステムに合わせて大幅に修正されました。

-   **`types.Check`関数の削除**: 以前は`types.Check(path string, fset *token.FileSet, files []*ast.File) (*Package, error)`というヘルパー関数が存在しましたが、これは削除されました。代わりに、`types.Config`構造体を使用して型チェックを行うことが推奨されます。これは、型チェックのプロセスをより細かく制御できるようにするための変更です。
-   **`Config.Importer`フィールドの導入**: `Config`構造体に`Importer Importer`フィールドが追加されました。これにより、型チェックを行う際に使用するインポーターを明示的に設定できるようになりました。以前の`Config.Import`関数型フィールドや、グローバルな`types.DefaultImport`変数は削除されました。
-   **`Config.Packages`フィールドの削除**: 以前`Config`にあった`Packages map[string]*Package`フィールドが削除されました。これは、インポートされたパッケージのキャッシュ管理が、インポーター自身の責任になったことを意味します。インポーターは、同じパスに対して常に同じ`*Package`インスタンスを返す責任を負います。
-   **`unsafe`パッケージの直接処理**: `src/go/types/resolver.go`内の`collectObjects`関数において、`unsafe`パッケージのインポートがインポーターを介さず、型チェッカー内部で直接`Unsafe`パッケージオブジェクトを返すように変更されました。これにより、`unsafe`パッケージの特殊性が明確になり、インポート処理から除外されることで効率化が図られます。
-   **テストコードの更新**: `go/types`のテストコード（例: `api_test.go`, `stdlib_test.go`など）は、新しい`importer.Default()`を使用して`Config.Importer`を設定するように変更されました。また、テスト用のカスタムインポーターも、新しい`types.Importer`インターフェースに準拠するように修正されています。

### 3. `go/internal/gcimporter`パッケージの変更

`gcimporter`は、`go/importer`パッケージから呼び出されるように変更されました。

-   **`init()`関数の削除**: 以前`src/go/internal/gcimporter/gcimporter.go`にあった`init()`関数で`types.DefaultImport = Import`としていた部分が削除されました。これは、グローバルな`types.DefaultImport`が廃止され、インポーターが`Config`を通じて明示的に設定されるようになったためです。
-   **`unsafe`パッケージの処理の変更**: `gcimporter.Import`関数内で`path == "unsafe"`の場合に`types.Unsafe`を直接返していたロジックが削除され、代わりに`panic`を発生させるようになりました。これは、`unsafe`パッケージの処理が型チェッカー本体に移管されたため、`gcimporter`が`unsafe`パッケージのインポートを試みるべきではないという意図を示しています。

### 全体的な影響

これらの変更により、Goの型チェックシステムは、パッケージインポートのメカニズムにおいてよりモジュール化され、柔軟性が高まりました。

-   **責務の分離**: 型チェッカーは型チェックに専念し、パッケージの読み込みと解決は`go/importer`とその具体的な実装（`gcimporter`など）に委ねられるようになりました。
-   **拡張性**: 将来的に新しいコンパイラやパッケージ形式が登場した場合でも、`go/importer`パッケージに新しいインポーター実装を追加するだけで対応できるようになります。
-   **パフォーマンス**: テストコードにおけるインポーターの再利用は、大規模なコードベースの型チェック時間を短縮する効果があります。
-   **APIの明確化**: `types.Config`を通じた明示的なインポーター設定は、型チェックの挙動をより分かりやすく、制御しやすくします。

## コアとなるコードの解説

### `src/go/importer/importer.go` (新規追加)

```go
// Package importer provides access to export data importers.
package importer

import (
	"go/internal/gcimporter"
	"go/types"
	"io"
	"runtime"
)

// A Lookup function returns a reader to access package data for
// a given import path, or an error if no matching package is found.
type Lookup func(path string) (io.ReadCloser, error)

// For returns an Importer for the given compiler and lookup interface,
// or nil. Supported compilers are "gc", and "gccgo". If lookup is nil,
// the default package lookup mechanism for the given compiler is used.
func For(compiler string, lookup Lookup) types.Importer {
	switch compiler {
	case "gc":
		if lookup == nil {
			return make(gcimports) // gcimports implements types.Importer
		}
		panic("gc importer for custom import path lookup not yet implemented")
	case "gccgo":
		// TODO(gri) We have the code. Plug it in.
		panic("gccgo importer unimplemented")
	}
	// compiler not supported
	return nil
}

// Default returns an Importer for the compiler that built the running binary.
func Default() types.Importer {
	return For(runtime.Compiler, nil)
}

type gcimports map[string]*types.Package

func (m gcimports) Import(path string) (*types.Package, error) {
	return gcimporter.Import(m, path) // Delegates to gcimporter.Import
}
```
このファイルは、Goの型チェッカーが使用するインポーターを抽象化するための新しいレイヤーを提供します。`For`関数は、指定されたコンパイラ（現時点では`gc`のみが完全にサポート）に対応する`types.Importer`インターフェースの実装を返します。`Default`関数は、現在実行中のGoバイナリをビルドしたコンパイラ（`runtime.Compiler`）に対応するデフォルトのインポーターを簡単に取得できるようにします。
`gcimports`型は、`types.Importer`インターフェースを満たすように定義されており、実際のインポート処理は`go/internal/gcimporter.Import`に委譲しています。この`gcimports`マップは、既にインポートされたパッケージをキャッシュするために使用されます。
