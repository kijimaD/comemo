# [インデックス 27867] ファイルの概要

このコミットは、Goランタイムが起動時にカーネルの物理ページサイズをチェックする機能を追加するものです。これにより、Goランタイムが想定する物理ページサイズとカーネルの実際のページサイズとの間に不整合がある場合に、メモリ管理の問題（特に`sysUnused`によるメモリ解放の誤り）が発生するのを防ぎます。

## 元コミット内容

```
runtime: check kernel physical page size during init

The runtime hard-codes an assumed physical page size. If this is
smaller than the kernel's page size or not a multiple of it, sysUnused
may incorrectly release more memory to the system than intended.

Add a runtime startup check that the runtime's assumed physical page
is compatible with the kernel's physical page size.

For #9993.

Change-Id: Ida9d07f93c00ca9a95dd55fc59bf0d8a607f6728
Reviewed-on: https://go-review.googlesource.com/22064
Reviewed-by: Rick Hudson <rlh@golang.org>
```

## 変更の背景

Goランタイムは、メモリ管理のために物理ページサイズを内部的にハードコードして使用しています。しかし、このGoランタイムが想定する物理ページサイズが、実際にOSカーネルが使用している物理ページサイズと異なる場合、特に`sysUnused`関数によるメモリ解放処理において問題が発生する可能性がありました。

具体的には、Goランタイムが想定するページサイズがカーネルのページサイズよりも小さい場合、またはカーネルのページサイズの倍数でない場合、`sysUnused`はシステムに対して意図したよりも多くのメモリを誤って解放してしまう可能性がありました。これは、GoランタイムがメモリをOSに返却する際に、ページ単位で処理を行うため、ページサイズの不一致が直接的な問題を引き起こすためです。

この問題は、Go issue #9993で報告されており、特にARM64、PPC64、MIPS64などの大規模な物理ページを使用するシステムで顕著でした。Goランタイムが内部的にメモリを「解放」しても、OSの観点からはプロセスの常駐メモリが減少しないという状況が発生し、メモリ制約のある環境（モバイルデバイスなど）での効率的なメモリ再利用が妨げられていました。

このコミットは、このようなメモリ管理の不整合による潜在的な問題を未然に防ぐために、Goランタイムの起動時にカーネルの物理ページサイズを検出し、Goランタイムが想定するページサイズとの互換性を検証するチェックを追加することを目的としています。

## 前提知識の解説

### 物理ページサイズ (Physical Page Size)

物理ページサイズとは、オペレーティングシステムが物理メモリを管理する最小単位のことです。メモリは連続したバイト列として扱われますが、OSはこれを固定長のブロック（ページ）に分割して管理します。このページのサイズが物理ページサイズです。一般的なシステムでは4KBが主流ですが、大規模なシステムや特定のアーキテクチャ（例: ARM64, PPC64）では、より大きなページサイズ（例: 16KB, 64KB）が使用されることがあります。ページサイズは、メモリのアクセス効率や管理のオーバーヘッドに影響を与えます。

### Goランタイムのメモリ管理

Goランタイムは独自のメモリマネージャ（mheap）を持ち、OSからメモリを確保し、それをGoのヒープとして管理します。Goのガベージコレクタは、不要になったオブジェクトが占めるメモリを解放しますが、そのメモリをすぐにOSに返却するとは限りません。Goランタイムは、将来の割り当てのために解放されたメモリを内部的に保持することがあります。OSにメモリを返却する際には、`sysUnused`のような関数を通じて、特定のメモリ領域が未使用であることをOSに通知します。このプロセスは、OSのページ単位で行われるため、GoランタイムとOSのページサイズの認識が一致していることが重要です。

### `sysUnused`

`sysUnused`はGoランタイムの内部関数で、特定のメモリ範囲がGoランタイムによって使用されなくなったことをOSに通知するために使用されます。これにより、OSはそのメモリを他のプロセスに割り当てたり、ページキャッシュとして再利用したりすることができます。この関数が正しく機能するためには、GoランタイムがOSのメモリ管理の単位（ページサイズ）を正確に理解している必要があります。

### Auxiliary Vector (`_AT_PAGESZ`)

Auxiliary Vector (補助ベクトル) は、LinuxなどのUnix系OSにおいて、プログラムが起動する際にカーネルから渡される情報の一つです。これは、プログラムの実行環境に関する様々な情報（例: プロセッサのアーキテクチャ、ページサイズ、乱数シードなど）をキーと値のペアのリストとして提供します。

`_AT_PAGESZ`は、この補助ベクトル内のエントリの一つで、システムの物理ページサイズ（バイト単位）を示します。プログラムは、この値を利用して、OSのメモリ管理の特性を動的に把握し、それに応じて自身のメモリ管理戦略を調整することができます。Goランタイムは、この`_AT_PAGESZ`の値を取得することで、カーネルが実際に使用している物理ページサイズを知ることができます。

## 技術的詳細

このコミットは、Goランタイムの起動プロセスに、カーネルの物理ページサイズを動的に取得し、Goランタイムが内部的に想定しているページサイズ（`sys.PhysPageSize`）との互換性を検証するロジックを追加します。

具体的には、以下のステップで処理が行われます。

1.  **`_AT_PAGESZ`の定義**: Auxiliary Vectorから物理ページサイズを取得するための定数`_AT_PAGESZ`が`src/runtime/os_linux.go`に追加されます。この値は、Linuxカーネルが物理ページサイズを示すために使用するマジックナンバーです。
2.  **`sysargs`関数での取得**: Goランタイムの初期化時に呼び出される`sysargs`関数内で、Auxiliary Vectorを走査し、`_AT_PAGESZ`に対応する値（カーネルの物理ページサイズ）を取得します。
3.  **互換性チェック**: 取得したカーネルの物理ページサイズ（`val`）と、Goランタイムが内部的に持つ物理ページサイズ（`sys.PhysPageSize`）との間で以下の2つの互換性チェックが行われます。
    *   **Goランタイムのページサイズがカーネルのページサイズより小さいか？**: `sys.PhysPageSize < val`
        *   もしGoランタイムのページサイズがカーネルのページサイズよりも小さい場合、これは深刻な問題です。Goランタイムがメモリを解放する際に、カーネルが認識する最小単位よりも細かい単位で解放しようとするため、不正確なメモリ解放が発生する可能性があります。
    *   **Goランタイムのページサイズがカーネルのページサイズの倍数でないか？**: `sys.PhysPageSize % val != 0`
        *   Goランタイムのページサイズがカーネルのページサイズの倍数でない場合も問題です。この場合、GoランタイムがメモリブロックをOSに返却する際に、カーネルのページ境界と一致しないため、部分的なページが解放されずに残ったり、誤った計算が行われたりする可能性があります。
4.  **エラー時の終了**: 上記のいずれかのチェックに失敗した場合、Goランタイムはエラーメッセージを出力し、プロセスを終了します。これにより、不正なメモリ管理が引き起こす可能性のあるクラッシュやデータ破損を未然に防ぎます。

この変更により、Goランタイムは様々なLinuxシステム環境において、より堅牢なメモリ管理を実現できるようになります。

## コアとなるコードの解説

1.  **`_AT_PAGESZ = 6` の追加**:
    *   これは、LinuxカーネルのAuxiliary Vectorにおいて、システムの物理ページサイズを示すための定数です。`sysargs`関数がAuxiliary Vectorを解析する際に、このタグを持つエントリを探し、その値を取得するために使用されます。

2.  **`case _AT_PAGESZ:` ブロックの追加**:
    *   `sysargs`関数は、プログラム起動時にカーネルから渡されるAuxiliary Vectorをループで処理します。`tag`が`_AT_PAGESZ`と一致した場合、このブロックが実行されます。
    *   `val`変数には、カーネルが報告する実際の物理ページサイズが格納されています。

3.  **`if sys.PhysPageSize < val { ... }`**:
    *   この条件は、Goランタイムが内部的に想定している物理ページサイズ（`sys.PhysPageSize`）が、カーネルが報告する実際の物理ページサイズ（`val`）よりも小さい場合に真となります。
    *   もしこの条件が真であれば、Goランタイムはカーネルのページサイズを過小評価していることになり、メモリ解放時に問題が発生する可能性があります。エラーメッセージを出力し、`exit(1)`でプロセスを異常終了させます。

4.  **`if sys.PhysPageSize%val != 0 { ... }`**:
    *   この条件は、Goランタイムの物理ページサイズがカーネルの物理ページサイズの倍数でない場合に真となります。
    *   GoランタイムがOSにメモリを返却する際、カーネルのページ境界に沿って処理を行う必要があります。もしGoランタイムのページサイズがカーネルのページサイズの倍数でなければ、メモリブロックを正確にOSのページにマッピングできず、メモリリークや不正確な解放を引き起こす可能性があります。この場合もエラーメッセージを出力し、`exit(1)`でプロセスを異常終了させます。

これらのチェックにより、Goランタイムは起動時に自身のメモリ管理設定がOSの実際の環境と互換性があることを確認し、潜在的なメモリ管理の不整合による問題を未然に防ぐことができます。
