## 変更の背景

Go言語がWindows上でシステムコールを扱う際、DLL（Dynamic Link Library）のロードは重要な要素です。以前は、`syscall`パッケージのコード生成ツールである`mksyscall_windows.go`が、WindowsのシステムDLLを遅延ロードするために`windows.LazyDLL`構造体を直接初期化していました。

この直接初期化のアプローチは機能的には問題ありませんでしたが、以下のような課題がありました。

1.  **冗長性**: `&LazyDLL{Name: "...", System: true}`という記述は、`System: true`という特定のフラグを常に設定する必要があり、冗長でした。
2.  **カプセル化の欠如**: `LazyDLL`構造体の内部実装が変更された場合、`mksyscall_windows.go`のようなコード生成ツールも更新する必要がありました。これは、構造体の内部詳細が外部に露出しているためです。
3.  **意図の不明瞭さ**: `System: true`というフラグが何を意味するのか、コードを読むだけでは直感的に理解しにくい場合がありました。

`windows.NewLazySystemDLL`というヘルパー関数を導入し、それを使用するように変更することで、これらの課題を解決し、よりクリーンで意図が明確なコードを生成することが目的とされました。この関数は、システムDLLの遅延ロードという特定のユースケースをカプセル化し、将来的な`LazyDLL`の実装変更に対する耐性も高めます。

## 前提知識の解説

### Windows DLL (Dynamic Link Library)

DLLは、Windowsオペレーティングシステムで使用される共有ライブラリの一種です。複数のプログラムが同じDLL内の関数やリソースを共有できるため、メモリ使用量の削減やモジュール性の向上が図られます。

### 遅延ロード (Lazy Loading)

遅延ロードとは、プログラムの起動時にすべてのリソース（この場合はDLL）をロードするのではなく、そのリソースが実際に必要になった時点で初めてロードする手法です。これにより、プログラムの起動時間を短縮し、メモリ使用量を最適化できます。Windows APIの呼び出しにおいて、Go言語の`syscall`パッケージは、この遅延ロードのメカニズムを利用してDLLを扱います。

### `syscall`パッケージと`mksyscall_windows.go`

Go言語の標準ライブラリには、低レベルなシステムコールを扱うための`syscall`パッケージがあります。Windows環境では、このパッケージを通じてWindows APIを呼び出すことができます。
`mksyscall_windows.go`は、Goの`syscall`パッケージの一部として存在するコード生成ツールです。このツールは、Windows APIの定義からGo言語のコード（特に`syscall`パッケージ内で使用される関数や構造体）を自動生成する役割を担っています。これにより、開発者が手動で膨大な数のWindows APIのバインディングを作成する手間を省き、正確性を保つことができます。

### `windows.LazyDLL`と`windows.NewLazySystemDLL`

-   **`windows.LazyDLL`**: `golang.org/x/sys/windows`パッケージ（または以前は`syscall`パッケージ内）に存在する構造体で、Windows DLLの遅延ロードを管理するために使用されます。この構造体は、DLLの名前や、それがシステムDLLであるかどうかなどの情報を含みます。
-   **`windows.NewLazySystemDLL`**: このコミットで利用されるようになったヘルパー関数です。DLL名を引数に取り、`System: true`が設定された`LazyDLL`インスタンスを返します。この関数を使用することで、呼び出し側は`LazyDLL`の内部構造を意識することなく、システムDLLの遅延ロードオブジェクトを生成できます。特に、`NewLazySystemDLL`はDLLの検索パスをWindowsのシステムディレクトリに限定するため、DLLハイジャックなどのセキュリティリスクを軽減する効果もあります。

## 技術的詳細

この変更の核心は、`mksyscall_windows.go`が生成するコードにおいて、`windows.LazyDLL`オブジェクトの生成方法を、直接的な構造体リテラルからファクトリ関数（コンストラクタ）呼び出しへと切り替えた点にあります。

変更前は、以下のようなコードが生成されていました。

```go
&LazyDLL{Name: "...", System: true}
```
または
```go
&windows.LazyDLL{Name: "...", System: true}
```

これは、`LazyDLL`構造体のフィールドを直接指定してインスタンスを作成する方法です。`System: true`というフィールドは、そのDLLがWindowsのシステムディレクトリに存在することを示し、セキュリティ上の理由からDLLの検索パスを制限するために使用されます。

変更後は、以下のようなコードが生成されるようになります。

```go
NewLazySystemDLL("...")
```
または
```go
windows.NewLazySystemDLL("...")
```

この`NewLazySystemDLL`関数は、内部で`LazyDLL`構造体を初期化し、`System: true`を設定して返します。このアプローチにはいくつかの技術的な利点があります。

1.  **抽象化とカプセル化**: `LazyDLL`構造体の内部実装が変更されても、`NewLazySystemDLL`関数のシグネチャが変わらなければ、この関数を呼び出しているコード（`mksyscall_windows.go`が生成するコード）を変更する必要がありません。これにより、システムコール生成ロジックと`LazyDLL`の実装が疎結合になります。
2.  **意図の明確化**: `NewLazySystemDLL`という関数名自体が、「システムDLLを遅延ロードするためのオブジェクトを新しく作成する」という意図を明確に伝えます。`System: true`というマジックワードを直接扱う必要がなくなります。
3.  **一貫性のある初期化**: `NewLazySystemDLL`関数は、常に正しい方法で`LazyDLL`を初期化することを保証します。例えば、将来的に`LazyDLL`に新しい必須フィールドが追加された場合でも、この関数を更新するだけで済み、すべての呼び出し元が自動的に恩恵を受けます。
4.  **セキュリティの強化**: `NewLazySystemDLL`は、DLLの検索パスをシステムディレクトリに限定する役割を担っており、DLLハイジャック攻撃のリスクを低減します。このセキュリティメカニズムが関数内にカプセル化されることで、誤って`System: true`を設定し忘れるといったヒューマンエラーを防ぐことができます。

この変更は、`mksyscall_windows.go`というコード生成ツール自体が生成するコードの品質と保守性を向上させるものであり、Go言語のWindowsサポートの堅牢性を高める一環と言えます。
