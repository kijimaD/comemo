# [インデックス 25582] ファイルの概要

このコミットは、Goランタイムの `src/runtime/sys_linux_386.s` ファイルに対する変更です。このファイルは、Linux/386 (x86) アーキテクチャ上でGoプログラムがシステムコールを呼び出すためのアセンブリコードを定義しています。具体的には、`access`、`connect`、`socket` といったシステムコールが追加されており、これらはAndroidプラットフォームにおけるGoアプリケーションのロギング機能に必要とされています。

## 変更の背景

この変更は、Go言語がAndroidプラットフォーム、特に `android/386` (x86) アーキテクチャ上でのクロスコンパイルと実行をより適切にサポートするために行われました。`golang/go#9327` のIssueで議論されていたように、Go 1.5以降、`android/armv7` 以外のAndroidアーキテクチャ（`android/x86`、`android/arm64`、`android/amd64`など）でCGOを有効にしたGoプログラムをクロスコンパイルする際に、特定のシステムコールや型定義が不足しているために問題が発生していました。

このコミットは、その問題の一部を解決するために、`android/386` 環境でGoアプリケーションがロギングを行う際に必要となる `access`、`connect`、`socket` といったシステムコールをGoランタイムに追加します。これらのシステムコールは、例えばAndroidのログシステム（logcatなど）への接続や、ネットワーク経由でのログ転送など、ロギングに関連する操作で利用される可能性があります。GoプログラムがAndroid上で動作する際に、これらの低レベルなOS機能にアクセスできるようにすることで、より堅牢で機能豊富なアプリケーションの構築が可能になります。

## 前提知識の解説

### システムコール (Syscall)
システムコールは、オペレーティングシステム (OS) のカーネルが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。ファイルI/O、プロセス管理、メモリ管理、ネットワーク通信など、OSの基本的な機能のほとんどはシステムコールを通じて提供されます。Go言語のような高水準言語であっても、最終的にはこれらの低レベルなシステムコールを呼び出すことでOSと対話します。

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する一連のライブラリとコードです。これには、ガベージコレクション、スケジューラ、メモリ管理、そしてシステムコールを呼び出すための低レベルなコードなどが含まれます。Goプログラムが異なるOSやアーキテクチャで動作できるように、ランタイムはそれぞれの環境に特化したシステムコールラッパーを提供します。

### Android/386
Android/386は、AndroidオペレーティングシステムがIntel x86 (32ビット) アーキテクチャのプロセッサ上で動作する環境を指します。Go言語はクロスコンパイルをサポートしており、開発者は異なるアーキテクチャ向けにGoプログラムをビルドできます。このコミットは、特にこの `android/386` 環境でのGoプログラムの動作を改善することを目的としています。

### `src/runtime/sys_linux_386.s`
このファイルは、Goランタイムの一部であり、Linux/386アーキテクチャ向けのシステムコールを呼び出すためのアセンブリコード (`.s` 拡張子) を含んでいます。Goプログラムが特定のシステムコールを呼び出す際、ランタイムはこのファイルに定義されたアセンブリルーチンを介してOSカーネルに要求を伝えます。

### `access()` システムコール
`access()` は、指定されたファイルパスに対して、呼び出し元のプロセスが特定のアクセス権限（読み取り、書き込み、実行）を持っているかどうかを確認するために使用されるシステムコールです。ファイルが存在するかどうかのチェックや、パーミッションの確認に利用されます。

### `connect()` システムコール
`connect()` は、ソケットをリモートホスト上の指定されたアドレスに接続するために使用されるシステムコールです。クライアントアプリケーションがサーバーに接続する際に不可欠な機能であり、TCP/IP通信の確立に用いられます。

### `socket()` システムコール
`socket()` は、ネットワーク通信のエンドポイントであるソケットを作成するために使用されるシステムコールです。ソケットは、プロセス間通信やネットワーク通信を行うための抽象的なインターフェースを提供します。`domain` (アドレスファミリー、例: AF_INET)、`type` (ソケットの種類、例: SOCK_STREAM)、`protocol` (プロトコル、例: IPPROTO_TCP) を指定して作成します。

### `socketcall()` システムコール (Linux/x86特有)
Linuxの32ビットx86アーキテクチャでは、ソケット関連のシステムコール（`socket`, `connect`, `bind`, `listen`, `accept`, `send`, `recv` など）は、直接個別のシステムコール番号を持つのではなく、`socketcall()` という単一のシステムコールを介して呼び出されます。`socketcall()` は、第一引数でどのソケット操作を行うかを指定し、第二引数でその操作に必要な引数をポインタとして渡します。これは、システムコール番号の数を節約するためのメカニズムです。

## 技術的詳細

このコミットでは、`src/runtime/sys_linux_386.s` ファイルに3つの新しいシステムコールラッパーが追加されています。Goランタイムのアセンブリコードは、Goの特殊なアセンブリ構文を使用しており、一般的なGAS (GNU Assembler) 構文とは異なります。

各システムコールラッパーは、以下の共通パターンに従っています。
1.  `TEXT runtime·<function_name>(SB),NOSPLIT,$0`：Goのアセンブリ関数定義。`runtime·` はGoランタイムのシンボルであることを示し、`(SB)` はスタティックベースレジスタからのオフセットであることを示します。`NOSPLIT` はスタックフレームを分割しないことを意味し、`$0` はローカル変数に0バイトを割り当てることを意味します。
2.  `MOVL $<syscall_number>, AX`：システムコール番号を `AX` レジスタにロードします。Linux/386では、システムコール番号は `AX` レジスタに格納されます。
3.  引数のロード：システムコールに渡す引数を `BX`, `CX`, `DX`, `SI`, `DI`, `BP` などのレジスタにロードします。引数はスタックフレームから取得されます。
4.  `INVOKE_SYSINFO`：これはGoランタイムのアセンブリマクロで、実際にシステムコールをトリガーする `int $0x80` 命令（または `sysenter` 命令）を実行します。
5.  戻り値の処理：システムコールの結果は通常 `AX` レジスタに格納されるため、それをGoの戻り値としてスタックフレームに格納します。
6.  `RET`：関数から戻ります。

### `access` システムコールの実装
`access` システムコールは、システムコール番号 `33` を使用します。
引数 `name` (ファイルパス) は `BX` レジスタに、`mode` (アクセスモード) は `CX` レジスタにロードされます。

### `connect` および `socket` システムコールの実装
`connect` と `socket` は、Linux/386では直接システムコールとして呼び出されるのではなく、`socketcall` システムコールを介して呼び出されます。`socketcall` のシステムコール番号は `102` です。

*   **`socketcall` の呼び出し規約**:
    *   `AX` レジスタに `102` (socketcallのシステムコール番号) をセット。
    *   `BX` レジスタに、実行したいソケット操作のサブコマンド番号をセット (`connect` なら `3`、`socket` なら `1`)。
    *   `CX` レジスタに、ソケット操作の引数を格納したスタック上の領域へのポインタをセット。

このコミットでは、`connect` と `socket` の両方で、それぞれの引数 (`fd`, `addr`, `addrlen` または `domain`, `type`, `protocol`) がスタック上に配置されていることを前提とし、そのスタック上の先頭アドレスを `LEAL fd+0(FP), CX` や `LEAL domain+0(FP), CX` のように `CX` レジスタにロードしています。`LEAL` (Load Effective Address) 命令は、オペランドのアドレスを計算してレジスタに格納します。

## コアとなるコードの解説

### `runtime·access` の実装

```assembly
// int access(const char *name, int mode)
TEXT runtime·access(SB),NOSPLIT,$0
	MOVL	$33, AX  // syscall - access
	MOVL	name+0(FP), BX
	MOVL	mode+4(FP), CX
	INVOKE_SYSINFO
	MOVL	AX, ret+8(FP)
	RET
```
*   `TEXT runtime·access(SB),NOSPLIT,$0`: `runtime` パッケージの `access` 関数を定義します。スタックフレームは分割されず、ローカル変数は使用しません。
*   `MOVL $33, AX`: `access` システムコールの番号 `33` を `AX` レジスタに移動します。
*   `MOVL name+0(FP), BX`: 関数引数 `name` (ファイルパスへのポインタ) をスタックフレームポインタ `FP` からのオフセット `0` で取得し、`BX` レジスタに移動します。
*   `MOVL mode+4(FP), CX`: 関数引数 `mode` (アクセスモード) をスタックフレームポインタ `FP` からのオフセット `4` で取得し、`CX` レジスタに移動します。
*   `INVOKE_SYSINFO`: システムコールを実行します。これにより、カーネルモードに移行し、`AX` レジスタのシステムコール番号と他のレジスタの引数に基づいて `access` システムコールが呼び出されます。
*   `MOVL AX, ret+8(FP)`: システムコールの戻り値（通常は `AX` レジスタに格納される）を、Go関数の戻り値 `ret` が格納されるスタックフレーム上のオフセット `8` に移動します。
*   `RET`: 関数から戻ります。

### `runtime·connect` の実装

```assembly
// int connect(int fd, const struct sockaddr *addr, socklen_t addrlen)
TEXT runtime·connect(SB),NOSPLIT,$0-16
	// connect is implemented as socketcall(NR_socket, 3, *(rest of args))
	// stack already should have fd, addr, addrlen.
	MOVL	$102, AX  // syscall - socketcall
	MOVL	$3, BX  // connect
	LEAL	fd+0(FP), CX
	INVOKE_SYSINFO
	MOVL	AX, ret+12(FP)
	RET
```
*   `TEXT runtime·connect(SB),NOSPLIT,$0-16`: `runtime` パッケージの `connect` 関数を定義します。`$0-16` は、この関数が16バイトの引数を受け取ることを示します。
*   `MOVL $102, AX`: `socketcall` システムコールの番号 `102` を `AX` レジスタに移動します。
*   `MOVL $3, BX`: `socketcall` のサブコマンドとして `connect` に対応する番号 `3` を `BX` レジスタに移動します。
*   `LEAL fd+0(FP), CX`: 関数引数 `fd` (ファイルディスクリプタ) がスタックフレームポインタ `FP` からのオフセット `0` にあることを利用し、`fd`、`addr`、`addrlen` の引数ブロックの先頭アドレスを計算して `CX` レジスタに移動します。`socketcall` は引数へのポインタを `CX` で受け取ります。
*   `INVOKE_SYSINFO`: `socketcall` システムコールを実行します。
*   `MOVL AX, ret+12(FP)`: システムコールの戻り値を、Go関数の戻り値 `ret` が格納されるスタックフレーム上のオフセット `12` に移動します。
*   `RET`: 関数から戻ります。

### `runtime·socket` の実装

```assembly
// int socket(int domain, int type, int protocol)
```

*   `MOVL $1, BX`: `socketcall` のサブコマンドとして `socket` に対応する番号 `1` を `BX` レジスタに移動します。
*   `LEAL domain+0(FP), CX`: 関数引数 `domain` (アドレスファミリー) がスタックフレームポインタ `FP` からのオフセット `0` にあることを利用し、`domain`、`type`、`protocol` の引数ブロックの先頭アドレスを計算して `CX` レジスタに移動します。
