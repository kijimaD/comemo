## 変更の背景

Go言語のコンパイラ`gc`において、構造体などの型が前方宣言されている場合、その型の完全な定義がまだ利用できない段階で、その型へのポインタが作成されることがあります。このコミット以前は、ポインタ型を構築する際に、ポインタが指す先の型（`$2`）に対して`checkwidth`という幅（サイズ）チェック関数が呼び出されていました。

しかし、もし`$2`がまだ完全には定義されていない前方宣言された構造体であった場合、その時点では正確な幅を決定することはできません。このような時期尚早な幅チェックは、コンパイルエラーを引き起こしたり、誤った型情報に基づいて不正確なコードが生成されたりする可能性がありました。このコミットは、この問題を修正し、前方宣言された型へのポインタが正しく扱われるようにすることを目的としています。

## 前提知識の解説

### `go.y`ファイル
`go.y`は、Goコンパイラ`gc`の構文解析器を生成するためのYacc/Bison形式の文法定義ファイルです。Go言語のソースコードがどのようにトークン化され、どのように構文木に変換されるかを定義しています。このファイルは、Go言語の文法規則と、それらの規則がマッチしたときに実行されるアクション（セマンティックアクション）を含んでいます。

### `gc` (Go Compiler)
`gc`は、Go言語の公式コンパイラです。Goのソースコードを機械語に変換する役割を担っています。型チェック、最適化、コード生成など、コンパイルの様々な段階を処理します。

### 前方宣言 (Forward Declaration)
前方宣言とは、プログラム中で識別子（変数、関数、型など）をその完全な定義の前に宣言することです。C言語などでは、相互参照する構造体（例: `struct A { struct B *b; }; struct B { struct A *a; };`）を定義する際に必要となります。Go言語では、型宣言の順序に依存しないため、C言語のような明示的な前方宣言は通常必要ありませんが、コンパイラの内部処理においては、型の解決順序が重要になる場合があります。特に、型がまだ完全に定義されていない段階でその型へのポインタが参照されるようなケースで、コンパイラは前方参照を適切に処理する必要があります。

### `checkwidth`関数
Goコンパイラの文脈における`checkwidth`関数は、型のサイズ（幅）とアライメント（配置）が適切であるかを確認するための内部関数であると推測されます。メモリレイアウトの決定や、効率的なコード生成のために、各型の正確なサイズを知ることはコンパイラにとって非常に重要です。この関数は、型の定義が完了し、そのサイズが確定した後に呼び出されるべきものです。

### `ptrto($2)`
`ptrto`は、Goコンパイラのセマンティックアクション内で使用される関数で、引数として与えられた型（`$2`）へのポインタ型を生成する役割を担っています。`$2`はYacc/Bisonの記法で、文法規則の2番目の要素に対応するセマンティック値（この場合は型情報）を指します。

## 技術的詳細

このコミットの核心は、ポインタ型を構築する際の型チェックのタイミングの修正にあります。`go.y`ファイル内のポインタ型定義のセクションでは、`'*' hidden_type`という規則があります。これは、`*`（ポインタ演算子）と`hidden_type`（ポインタが指す基底型）が組み合わさってポインタ型を形成することを示しています。

以前の実装では、この規則がマッチした際に、`ptrto($2)`（ポインタ型を生成）の直前に`checkwidth($2)`が呼び出されていました。ここで`$2`は`hidden_type`、つまりポインタが指す先の型です。

問題は、`hidden_type`が前方宣言された構造体である場合、その時点ではまだその構造体の完全な定義がコンパイラによって処理されていない可能性がある点です。構造体の完全な定義がなければ、その正確なサイズ（幅）は不明です。このような状況で`checkwidth($2)`を呼び出すと、不完全な情報に基づいて幅チェックが行われ、誤った結果やエラーが発生する可能性がありました。

ポインタ型自体のサイズは、それが指す先の型のサイズに関わらず、アーキテクチャに依存する固定値（例: 32ビットシステムでは4バイト、64ビットシステムでは8バイト）です。したがって、ポインタ型を生成する段階で、ポインタが指す先の型の幅をチェックすることは、この時点では不要であり、むしろ有害である可能性がありました。

このコミットでは、`checkwidth($2);`の行を削除することで、この時期尚早な幅チェックを回避しています。これにより、ポインタが指す先の型の幅チェックは、その型が完全に定義され、そのサイズが確定した後の適切なタイミングで行われるようになります。この修正により、前方宣言された構造体へのポインタがGoコンパイラによって正しく処理され、コンパイルの堅牢性が向上しました。

## コアとなるコードの解説

変更箇所は、`go.y`ファイル内の`hidden_type1`という文法規則の一部です。この規則は、Go言語の型定義、特にポインタ型に関連する部分を扱っています。

具体的には、`'*' hidden_type`という行は、`*`記号の後に`hidden_type`が続くパターン、すなわちポインタ型（例: `*int`, `*MyStruct`）を認識する文法規則です。この規則にマッチした場合、その直後の`{ ... }`ブロック内のセマンティックアクションが実行されます。

以前のコードでは、このブロック内に以下の2行がありました。

1.  `checkwidth($2);`
2.  `$$ = ptrto($2);`

`$2`は、`hidden_type`に対応する型情報を指します。
`ptrto($2)`は、`$2`で示される型へのポインタ型を生成し、その結果を`$$`（現在の文法規則の結果）に代入します。

このコミットでは、`checkwidth($2);`の行が削除されました。
この削除により、ポインタ型が構築される際に、ポインタが指す先の型（`$2`）の幅チェックがこの段階では行われなくなります。これにより、`$2`がまだ完全には定義されていない前方宣言された型であっても、コンパイラはエラーなくポインタ型を構築できるようになります。型の完全な幅チェックは、その型が完全に解決された後の適切なコンパイルフェーズで実行されることになります。
