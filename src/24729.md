# [インデックス 24729] ファイルの概要

このコミットは、Go言語の `time` パッケージがWindows環境でタイムゾーン名を扱う際の国際化対応（ローカライズされたタイムゾーン名のサポート）を改善するものです。具体的には、非英語環境でタイムゾーンの略称が正しく決定できない問題を解決するため、Windows APIの `RegLoadMUIString` 関数を利用して、レジストリからローカライズされたタイムゾーン名（標準名および夏時間名）を取得する機能を追加しています。

## 変更の背景

Go言語の `time` パッケージは、オペレーティングシステムからタイムゾーン情報を取得する際に、Windows環境ではレジストリを参照します。しかし、従来のGoのWindows向け実装では、レジストリに格納されているタイムゾーン名（例: "Central European Standard Time"）を英語の固定文字列として扱っていました。

このアプローチには問題がありました。Windowsは、ユーザーの表示言語設定に応じて、タイムゾーン名をローカライズして表示する機能を持っています。レジストリには、英語のタイムゾーン名だけでなく、多言語UI (MUI: Multilingual User Interface) に対応するためのローカライズされたタイムゾーン名も格納されています。従来のGoの実装では、これらのローカライズされた名前を適切に読み取ることができず、特に非英語環境でGoプログラムが実行された場合、タイムゾーンの略称（例: CET, CEST）が正しく解決できないというバグ（Issue #12015）が発生していました。

このコミットは、この問題を解決するために、Windowsのレジストリからローカライズされたタイムゾーン名を安全かつ正確に取得するメカニズムを導入することを目的としています。

## 前提知識の解説

### Windowsレジストリとタイムゾーン情報

Windowsは、システム設定やアプリケーション設定をレジストリに格納します。タイムゾーンに関する情報は、主に以下のパスに格納されています。

*   `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Time Zones\`
    このキーの下には、各タイムゾーン（例: "Central European Standard Time"）に対応するサブキーが存在します。各タイムゾーンのサブキーには、そのタイムゾーンに関する詳細情報が含まれています。

### タイムゾーン名のレジストリ値

各タイムゾーンのサブキーには、以下のような値が含まれています。

*   **`Std`**: 標準時の英語名（例: "Central European Standard Time"）
*   **`Dlt`**: 夏時間（Daylight Saving Time）の英語名（例: "Central European Daylight Time"）
*   **`MUI_Std`**: 標準時のローカライズされた名前を参照するためのMUI文字列。これは直接的な文字列ではなく、リソースファイル内の文字列IDやDLLパスを含む形式で格納されます。
*   **`MUI_Dlt`**: 夏時間のローカライズされた名前を参照するためのMUI文字列。

### 多言語UI (MUI) と `RegLoadMUIString`

Windowsの多言語UI (MUI) は、アプリケーションが複数の言語でユーザーインターフェースを提供するためのフレームワークです。レジストリ値の中には、直接文字列を格納するのではなく、MUIリソースを参照する形式でローカライズされた文字列を格納するものがあります。

`RegLoadMUIString` は、Windows APIの一つで、レジストリに格納されたMUI文字列を読み込み、現在のユーザーインターフェース言語に基づいてローカライズされた文字列に解決する機能を提供します。これにより、アプリケーションはユーザーの言語設定に応じた適切なタイムゾーン名を取得できます。

### `syscall` パッケージと `internal/syscall/windows/registry`

Go言語では、低レベルのシステムコールやOS固有の機能にアクセスするために `syscall` パッケージが提供されています。Windows固有のレジストリ操作は、`internal/syscall/windows/registry` パッケージ（Goの内部パッケージであり、外部からの直接利用は推奨されない）を通じて行われます。このパッケージは、Windows APIのレジストリ関連関数をGoから呼び出すためのラッパーを提供します。

## 技術的詳細

このコミットの主要な変更点は、Windowsレジストリからタイムゾーン名を取得するロジックに `RegLoadMUIString` APIのサポートを追加したことです。

1.  **`RegLoadMUIString` のGoへのバインディング**:
    *   `src/internal/syscall/windows/registry/syscall.go` に `regLoadMUIString` という新しいシステムコール関数が定義されました。これは `advapi32.RegLoadMUIStringW` を呼び出すためのGo側の宣言です。
    *   `src/internal/syscall/windows/registry/zsyscall_windows.go` には、`regLoadMUIString` の実際のGoからWindows APIへの呼び出しを生成するためのコードが追加されています。これは `mksyscall` ツールによって自動生成される部分です。
    *   `LoadRegLoadMUIString()` 関数が追加され、`procRegLoadMUIStringW` が利用可能かどうか（つまり、`RegLoadMUIString` APIがOSでサポートされているか）をチェックできるようになりました。

2.  **`GetMUIStringValue` メソッドの追加**:
    *   `src/internal/syscall/windows/registry/value.go` に `Key` 型の新しいメソッド `GetMUIStringValue(name string) (string, error)` が追加されました。
    *   このメソッドは、指定されたレジストリキーと値の名前に対して `regLoadMUIString` を呼び出し、ローカライズされた文字列を取得します。
    *   `RegLoadMUIString` は、MUI文字列がリソースファイルへのパスを含む場合があるため、`%SystemRoot%\system32\` をフォールバックパスとして試行するロジックも含まれています。
    *   バッファが不足した場合に自動的に拡張するロジックも実装されており、`syscall.ERROR_MORE_DATA` エラーを適切に処理します。

3.  **`time` パッケージでの利用**:
    *   `src/time/zoneinfo_windows.go` の `matchZoneKey` 関数が変更されました。この関数は、Goの内部的なタイムゾーン名とWindowsレジストリのタイムゾーン名を比較して一致を判定する役割を担います。
    *   変更後、`matchZoneKey` はまず `registry.LoadRegLoadMUIString()` を呼び出して `RegLoadMUIString` がサポートされているかを確認します。
    *   サポートされている場合、`k.GetMUIStringValue("MUI_Std")` と `k.GetMUIStringValue("MUI_Dlt")` を試行して、ローカライズされた標準時名と夏時間名を取得します。
    *   もし `RegLoadMUIString` がサポートされていない、または `GetMUIStringValue` の呼び出し中に何らかのエラーが発生した場合は、従来の `k.GetStringValue("Std")` と `k.GetStringValue("Dlt")` を使用して英語のタイムゾーン名にフォールバックします。
    *   この優先順位付けにより、新しいOSバージョンではローカライズされた名前を優先し、古いOSバージョンやMUI情報が利用できない環境では既存の英語名を使用するという互換性が保たれます。

4.  **テストの追加と修正**:
    *   `src/internal/syscall/windows/registry/registry_test.go` に `TestGetMUIStringValue` という新しいテストケースが追加されました。このテストは、`GetMUIStringValue` が正しくローカライズされたタイムゾーン名を取得できることを検証します。`GetDynamicTimeZoneInformation` を使用して現在のタイムゾーン情報を取得し、その情報とレジストリから取得したMUI文字列を比較しています。
    *   `src/time/zoneinfo_windows_test.go` の既存のテストも、新しいローカライズされたタイムゾーン名取得ロジックを反映するように更新されました。

この変更により、GoプログラムはWindowsの表示言語設定に依存せず、常に正しいタイムゾーン略称を決定できるようになります。

## コアとなるコードの変更箇所

### `src/internal/syscall/windows/registry/value.go` の `GetMUIStringValue` メソッド

```go
// GetMUIStringValue retrieves the localized string value for
// the specified value name associated with an open key k.
// If the value name doesn't exist or the localized string value
// can't be resolved, GetMUIStringValue returns ErrNotExist.
// GetMUIStringValue panics if the system doesn't support
// regLoadMUIString; use LoadRegLoadMUIString to check if
// regLoadMUIString is supported before calling this function.
func (k Key) GetMUIStringValue(name string) (string, error) {
	pname, err := syscall.UTF16PtrFromString(name)
	if err != nil {
		return "", err
	}

	buf := make([]uint16, 1024)
	var buflen uint32
	var pdir *uint16

	err = regLoadMUIString(syscall.Handle(k), pname, &buf[0], uint32(len(buf)), &buflen, 0, pdir)
	if err == syscall.ERROR_FILE_NOT_FOUND { // Try fallback path
		var s string
		s, err = ExpandString("%SystemRoot%\\\\system32\\\\")
		if err != nil {
			return "", err
		}
		pdir, err = syscall.UTF16PtrFromString(s)
		if err != nil {
			return "", err
		}

		err = regLoadMUIString(syscall.Handle(k), pname, &buf[0], uint32(len(buf)), &buflen, 0, pdir)
	}

	for err == syscall.ERROR_MORE_DATA { // Grow buffer if needed
		if buflen <= uint32(len(buf)) {
			break // Buffer not growing, assume race; break
		}
		buf = make([]uint16, buflen)
		err = regLoadMUIString(syscall.Handle(k), pname, &buf[0], uint32(len(buf)), &buflen, 0, pdir)
	}

	if err != nil {
		return "", err
	}

	return syscall.UTF16ToString(buf), nil
}
```

### `src/time/zoneinfo_windows.go` の `matchZoneKey` 関数

```go
func matchZoneKey(zones registry.Key, kname string, stdname, dstname string) (matched bool, err2 error) {
	k, err := registry.OpenKey(zones, kname, registry.READ)
	if err != nil {
		return false, err
	}
	defer k.Close()

	var std, dlt string
	if err = registry.LoadRegLoadMUIString(); err == nil {
		// Try MUI_Std and MUI_Dlt first, fallback to Std and Dlt if *any* error occurs
		std, err = k.GetMUIStringValue("MUI_Std")
		if err == nil {
			dlt, err = k.GetMUIStringValue("MUI_Dlt")
		}
	}
	if err != nil { // Fallback to Std and Dlt
		if std, _, err = k.GetStringValue("Std"); err != nil {
			return false, err
		}
		if dlt, _, err = k.GetStringValue("Dlt"); err != nil {
			return false, err
		}
	}

	if std != stdname {
		return false, nil
	}
	if dlt != dstname && dstname != stdname {
		return false, nil
	}
	return true, nil
}
```

## コアとなるコードの解説

### `GetMUIStringValue` メソッド

このメソッドは、WindowsレジストリからMUI文字列を読み取るための主要なロジックをカプセル化しています。

1.  **`syscall.UTF16PtrFromString(name)`**: Goの文字列 `name` をWindows APIが期待するUTF-16形式のポインタに変換します。
2.  **バッファの初期化**: `buf := make([]uint16, 1024)` で、MUI文字列を格納するためのUTF-16ワードのバッファを初期化します。最初は1024ワード（2KB）のサイズを確保しています。
3.  **`regLoadMUIString` の呼び出し**:
    *   `regLoadMUIString(syscall.Handle(k), pname, &buf[0], uint32(len(buf)), &buflen, 0, pdir)` を呼び出します。
    *   `syscall.Handle(k)` は開いているレジストリキーのハンドルです。
    *   `pname` は読み取る値の名前（例: "MUI_Std"）です。
    *   `&buf[0]` は文字列を格納するバッファの先頭アドレスです。
    *   `uint32(len(buf))` はバッファのサイズです。
    *   `&buflen` は実際に書き込まれた文字数（または必要なバッファサイズ）を受け取るポインタです。
    *   `pdir` はMUIリソースDLLのパスを指定するためのもので、最初は `nil` で試行されます。
4.  **フォールバックパスの試行**:
    *   もし最初の `regLoadMUIString` の呼び出しが `syscall.ERROR_FILE_NOT_FOUND` エラーを返した場合、これはMUIリソースDLLが見つからないことを示唆している可能性があります。
    *   この場合、`ExpandString("%SystemRoot%\\\\system32\\\\")` を使用して `%SystemRoot%\system32\` パスを解決し、`pdir` に設定して再度 `regLoadMUIString` を呼び出します。これは、多くのシステムDLLがこのディレクトリに存在するためです。
5.  **バッファの動的拡張**:
    *   `regLoadMUIString` が `syscall.ERROR_MORE_DATA` を返した場合、これは提供されたバッファが小さすぎたことを意味します。
    *   ループ内で `buflen`（必要なバッファサイズ）に基づいて新しいバッファを `make([]uint16, buflen)` で作成し、再度 `regLoadMUIString` を呼び出します。これにより、任意の長さのMUI文字列に対応できます。
6.  **エラー処理と文字列変換**:
    *   最終的にエラーがなければ、`syscall.UTF16ToString(buf)` を使用してUTF-16バッファの内容をGoの文字列に変換して返します。

### `matchZoneKey` 関数

この関数は、Goの `time` パッケージがWindowsのタイムゾーン情報を解決する際の中心的なロジックです。

1.  **キーのオープン**: `registry.OpenKey(zones, kname, registry.READ)` で、指定されたタイムゾーンのレジストリキーを開きます。
2.  **`RegLoadMUIString` のサポートチェック**: `if err = registry.LoadRegLoadMUIString(); err == nil` で、システムが `RegLoadMUIString` をサポートしているかを確認します。
3.  **MUI文字列の優先取得**:
    *   `RegLoadMUIString` がサポートされている場合、`k.GetMUIStringValue("MUI_Std")` と `k.GetMUIStringValue("MUI_Dlt")` を試行します。
    *   これらの呼び出しが成功すれば、ローカライズされたタイムゾーン名が `std` と `dlt` に格納されます。
    *   もし `GetMUIStringValue` のいずれかの呼び出しでエラーが発生した場合（例: 値が存在しない、解決できない）、`err` は `nil` 以外になり、次のフォールバックロジックに進みます。
4.  **英語文字列へのフォールバック**:
    *   `if err != nil` の条件が真の場合（MUI文字列の取得に失敗した場合）、従来の `k.GetStringValue("Std")` と `k.GetStringValue("Dlt")` を使用して英語のタイムゾーン名を取得します。
    *   ここでもエラーが発生した場合は、`false, err` を返して処理を中断します。
5.  **名前の一致判定**:
    *   取得した `std` と `dlt` の値が、引数で渡された `stdname` と `dstname`（Goの内部的なタイムゾーン名）と一致するかを比較します。
    *   一致しない場合は `false, nil` を返します。
    *   すべて一致すれば `true, nil` を返します。

このロジックにより、GoはWindowsのタイムゾーン名を、ユーザーの表示言語設定に合わせたローカライズされた形式で取得できるようになり、非英語環境でのタイムゾーン略称の誤認識が解消されます。
