# [インデックス 26198] ファイルの概要

このコミットは、Goランタイムにおけるシグナルハンドリングの挙動、特にCGO（C言語との相互運用）を使用する際の`os/signal.Notify`と`os/signal.Reset`の動作を修正し、改善するものです。GoプログラムがCライブラリとしてビルドされる（`c-archive`または`c-shared`モード）場合において、Goのシグナルハンドラを登録・解除した際に、元のC側のシグナルハンドラが正しく復元されるように変更が加えられています。

## 元コミット内容

このコミットの目的は、「元のディスポジションを復元することでシグナルを無効にする」ことです。これは、`os/signal.Reset`が呼び出されたときに、シグナルの処理方法をデフォルトに戻すのではなく、Goがシグナルハンドラを登録する前の元の状態（Cコードが設定したハンドラなど）に戻すことを意味します。

## 変更の背景

この変更は、以下のIssueを解決するために行われました。

*   **Fixes #13034: os/signal.Reset does not restore original signal handler when using c-archive**
    *   `c-archive`ビルドモードでGoコードをCライブラリとして使用する際、Goの`os/signal.Notify`でシグナルハンドラを設定し、その後`os/signal.Reset`で解除しても、Goが登録する前のC側のシグナルハンドラが正しく復元されない問題。
*   **Fixes #13042: os/signal.Reset does not restore original signal handler when using c-shared**
    *   `c-shared`ビルドモードでも同様に、Goのシグナルハンドラ解除後にC側の元のハンドラが復元されない問題。
*   **Update #9896: runtime: signal handling in c-archive mode**
    *   これはより広範なシグナルハンドリングに関するIssueで、このコミットはその解決に貢献するものです。

これらの問題は、GoとCが混在するアプリケーションにおいて、シグナル処理の予測不能な挙動を引き起こす可能性がありました。特に、Cコードが特定のシグナルに対して独自のハンドラを設定している場合、Goがそのシグナルを一時的に処理し、その後解除した際に、C側のハンドラが失われてしまうという深刻なバグにつながります。

## 前提知識の解説

### シグナル (Signals)

シグナルは、Unix系OSにおいてプロセスに対して非同期に通知されるイベントです。例えば、Ctrl+Cを押すと`SIGINT`シグナルが、不正なメモリアクセスが発生すると`SIGSEGV`シグナルがプロセスに送られます。プロセスはこれらのシグナルに対して、以下のいずれかの処理を行います。

*   **デフォルト動作 (Default Action):** OSが定義する標準的な動作（例: `SIGINT`はプロセスを終了させる、`SIGSEGV`はコアダンプを生成して終了させる）。
*   **シグナルを無視 (Ignore):** シグナルを完全に無視し、何も処理しない。
*   **シグナルハンドラの実行 (Catch):** プログラムが独自に定義した関数（シグナルハンドラ）を実行する。

### `sigaction`システムコール

Unix系OSでは、`sigaction`システムコールを使ってシグナルハンドラを設定します。このシステムコールは、特定のシグナルに対する新しいアクション（ハンドラ関数、フラグなど）を設定し、同時に以前のアクションを取得することができます。

### `os/signal`パッケージ (Go)

Go言語の`os/signal`パッケージは、Goプログラム内でOSシグナルを処理するための機能を提供します。

*   **`signal.Notify(c chan<- os.Signal, sig ...os.Signal)`**: 指定されたシグナルがプロセスに送信されたときに、それらのシグナルをチャネル`c`に転送するようにGoランタイムに指示します。これにより、Goコードはシグナルを非同期に受信し、処理できます。この関数が呼び出されると、Goランタイムは指定されたシグナルに対して独自のシグナルハンドラをインストールします。
*   **`signal.Reset(sig ...os.Signal)`**: `signal.Notify`によって設定されたシグナルハンドラを解除し、シグナルの処理をGoランタイムが介入する前の状態に戻します。この「前の状態」が、このコミットの主要な変更点です。

### CGO (C言語との相互運用)

CGOは、GoプログラムからC言語のコードを呼び出したり、C言語のプログラムからGoの関数を呼び出したりするためのメカニズムです。GoコードをCライブラリとしてビルドする`c-archive`（静的ライブラリ）や`c-shared`（動的ライブラリ）モードでは、GoランタイムがCプログラムの一部として動作するため、シグナルハンドリングの挙動が複雑になります。Cプログラムが既にシグナルハンドラを設定している場合、Goが独自のハンドラをインストールする際に、C側のハンドラを適切に保存・復元する必要があります。

### `_SIG_IGN`と`_SIG_DFL`

*   **`_SIG_IGN`**: シグナルを無視する設定。
*   **`_SIG_DFL`**: シグナルのデフォルト動作を実行する設定。

これらは、シグナルハンドラとして設定できる特殊な値です。

## 技術的詳細

このコミットの核心は、`os/signal.Reset`が呼び出された際に、Goランタイムがシグナルハンドラをインストールする前の「元のシグナルディスポジション（処理方法）」を正確に復元するように変更された点にあります。

以前のGoランタイムでは、`signal.Reset`が呼び出されると、シグナルハンドラをデフォルト動作（`_SIG_DFL`）に戻すか、Goがシグナルハンドラをインストールする前にシグナルが無視されていた場合は無視（`_SIG_IGN`）に戻す、という単純なロジックが使われていました。しかし、これはCGOのシナリオで問題を引き起こしました。Cコードが独自のカスタムシグナルハンドラを設定していた場合、Goが`signal.Notify`でそのシグナルを「乗っ取り」、その後`signal.Reset`で解除すると、C側のカスタムハンドラが失われ、代わりにデフォルト動作や無視が設定されてしまうことがありました。

このコミットでは、以下の変更によってこの問題が解決されています。

1.  **元のシグナルディスポジションの保存**:
    *   `src/runtime/signal1_unix.go`の`initsig()`関数において、Goランタイムが起動する際に、各シグナルに対する現在の（つまり、Goが介入する前の）シグナルディスポジションを`fwdSig`という配列に保存するようになりました。これは、`getsig(i)`（現在のシグナルハンドラを取得する内部関数）の結果を`fwdSig[i]`に格納することで実現されます。
    *   これにより、Goがシグナルハンドラをインストールする前にCコードが設定したカスタムハンドラも正確に記録されるようになります。

2.  **`_SigIgnored`フラグの廃止**:
    *   `src/runtime/runtime2.go`から`_SigIgnored`フラグが削除されました。
    *   `src/runtime/signal1_unix.go`の`initsig()`および`sigenable()`関数から、このフラグに関連するロジックが削除されています。
    *   以前は、シグナルがGoによって処理される前に`_SIG_IGN`であったかどうかをこのフラグで追跡していましたが、`fwdSig`に元のディスポジションを直接保存するようになったため、このフラグは不要になりました。

3.  **`signal.Reset`時の元のディスポジションの復元**:
    *   `src/runtime/signal1_unix.go`の`sigdisable(sig uint32)`関数（`signal.Reset`が内部的に呼び出す関数）において、シグナルハンドラを解除する際に、`setsig(int32(sig), fwdSig[sig], true)`が呼び出されるようになりました。
    *   これは、Goがシグナルハンドラをインストールする前に`fwdSig`に保存しておいた元のディスポジションを、`setsig`を使って復元することを意味します。これにより、C側のカスタムハンドラが設定されていた場合はそれが正確に復元され、デフォルト動作や無視が設定されていた場合はそれが復元されます。

これらの変更により、GoとCが混在する環境でのシグナルハンドリングの挙動がより堅牢になり、予測可能になりました。

## コアとなるコードの解説

このコミットの最も重要な変更は、`src/runtime/signal1_unix.go`の`sigdisable`関数にあります。

以前は、`sigdisable`が呼び出されたとき（つまり`os/signal.Reset`が実行されたとき）、Goランタイムはシグナルが以前に無視されていた場合は`_SIG_IGN`を設定し、それ以外の場合は`_SIG_DFL`（デフォルト動作）を設定していました。このロジックは、Goがシグナルハンドラをインストールする前にCコードがカスタムハンドラを設定していたシナリオを考慮していませんでした。

変更後、`sigdisable`は`setsig(int32(sig), fwdSig[sig], true)`を呼び出します。ここで`fwdSig[sig]`は、Goランタイムが起動した際に`initsig`関数で取得・保存された、そのシグナルに対する**元のディスポジション**です。これにより、Goがシグナルハンドラを一時的に「乗っ取った」後、`signal.Reset`でそれを解除すると、Cコードが設定していたカスタムハンドラを含む、Goが介入する前の正確なシグナル処理設定が復元されるようになります。

この変更は、GoとCのシグナルハンドリングの相互作用における重要なバグを修正し、より堅牢なCGOアプリケーションの開発を可能にします。
