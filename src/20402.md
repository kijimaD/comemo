## 変更の背景

このコミットは、Goランタイムのシグナル処理ロジックをより明確にするためのマイナーな変更です。コミットメッセージには「Observed while working on the conversion.」とあり、これはGoランタイムのより大規模なリファクタリングや変更作業中に、`sigqueue.go` 内の既存のロジックが改善の余地があることが発見されたことを示唆しています。特に、シグナルハンドラとGoルーチン間の同期メカニズムのステート管理が、より読みやすく、理解しやすいように改善されています。

## 前提知識の解説

このコミットの変更を理解するためには、以下の前提知識が役立ちます。

*   **Goランタイムのシグナル処理**: Goプログラムは、オペレーティングシステムからのシグナル（例: `SIGINT`、`SIGTERM`、`SIGSEGV`）を受け取ることができます。これらのシグナルは、通常、非同期的に発生し、プログラムの実行フローを中断します。Goランタイムは、これらのシグナルを捕捉し、Goルーチンが安全に処理できるようにするための内部メカニズムを持っています。`sigqueue.go` は、このシグナル処理の重要な部分であり、OSのシグナルハンドラ（通常はC言語で書かれ、Goランタイムとは異なるスレッドで実行される）と、Goプログラム内でシグナルを待機・処理するGoルーチンとの間の橋渡しをします。
*   **アトミック操作**: 複数のスレッド（この場合はシグナルハンドラとGoルーチン）が共有データに同時にアクセスする場合、データの整合性を保つためにアトミック操作が不可欠です。アトミック操作は、その操作が中断されることなく完全に実行されることを保証します。
    *   **CAS (Compare-And-Swap)**: 特定のメモリ位置の値が期待する値と一致する場合にのみ、その値を新しい値に更新する操作です。これは、ロックを使用せずにスレッドセーフな更新を行うための基本的なプリミティブです。Goランタイムでは `cas()` 関数として提供されます。
    *   **XCHG (Exchange)**: 特定のメモリ位置の値を新しい値に設定し、同時にそのメモリ位置の古い値を返す操作です。これもアトミックに行われます。Goランタイムでは `xchg()` 関数として提供されます。
    *   **atomicload**: 特定のメモリ位置の値をアトミックに読み込む操作です。
*   **Goランタイムの同期プリミティブ**: Goランタイムは、Go言語の `sync` パッケージで提供される高レベルな同期プリミティブ（ミューテックス、条件変数など）とは別に、より低レベルな内部同期プリミティブを持っています。
    *   **`Note`**: Goランタイム内部で使用される軽量な同期プリミティブで、条件変数に似ています。`notewakeup()` は `Note` を待機しているGoルーチンを起床させ、`notetsleepg()` はGoルーチンをスリープさせ、`Note` が起床されるのを待ちます。

## 技術的詳細

`sigqueue.go` の主要な役割は、OSのシグナルハンドラからGoルーチンへのシグナル配送を安全かつ効率的に行うことです。これは、シグナルハンドラがGoのスケジューラやガベージコレクタと直接やり取りできないという制約があるため重要です。

このファイルの中心にあるのは `sig` 構造体です。この構造体は、シグナルの状態、待機中のGoルーチン、および配送されるべきシグナルのビットマスクを管理します。

変更前の `sig.state` 変数は、`0`、`_HASWAITER`、`_HASSIGNAL` という数値定数を使用して状態を表していました。これは、コードを読む際にそれぞれの数値が何を意味するのかを常に参照する必要があり、可読性が低いという問題がありました。

このコミットでは、以下の点が改善されています。

1.  **状態定数の明確化**:
    *   `_HASWAITER` は `sigReceiving` に、`_HASSIGNAL` は `sigSending` に、そして暗黙の `0` は `sigIdle` にそれぞれ名前が変更されました。これらの新しい定数は `iota` を使用して定義され、より意味のある名前が付けられています。これにより、`sig.state` の値がコード内で使用される際に、その意図がはるかに明確になります。
    *   `sigIdle`: シグナルがキューになく、`signal_recv` がブロックされていない状態。
    *   `sigReceiving`: `signal_recv` が `sig.Note` でブロックされており、新しい保留中のシグナルがない状態。
    *   `sigSending`: `sig.mask` に新しい保留中のシグナルが含まれている可能性があり、`signal_recv` はこの状態ではブロックできない状態。

2.  **`sigsend` 関数のロジック改善**:
    *   `sigsend` は、シグナルハンドラからシグナルをキューに追加する関数です。
    *   変更前は、`sig.state` の更新ロジックが `if/else` と `for` ループの組み合わせで表現されており、やや複雑でした。
    *   変更後は、`atomicload(&sig.state)` の結果に基づいて `switch` ステートメントを使用するようになりました。これにより、`sigIdle`、`sigSending`、`sigReceiving` の各状態からの遷移ロジックが明確に分離され、可読性が大幅に向上しました。
    *   特に、`sigReceiving` 状態から `sigIdle` への遷移時に `notewakeup(&sig.note)` を呼び出すことで、待機中のGoルーチンを起床させるロジックがより明確になりました。

3.  **`signal_recv` 関数のロジック改善**:
    *   `signal_recv` は、Goプログラムがキューからシグナルを受け取る関数です。
    *   `sigsend` と同様に、`sig.state` の更新ロジックが `switch` ステートメントに置き換えられました。これにより、`sigIdle` と `sigSending` の各状態からの遷移がより明確になりました。
    *   `sigIdle` 状態から `sigReceiving` への遷移時に `notetsleepg(&sig.note, -1)` を呼び出すことで、シグナルが到着するまでGoルーチンをスリープさせるロジックが明確になりました。
    *   最も重要な変更点の一つは、`sig.mask` から `sig.recv` へのシグナルビットマスクの転送方法です。変更前は `for` ループ内で `cas` を使用してアトミックに `sig.mask[i]` を `0` に設定し、その古い値を `m` に取得していました。変更後は、`xchg(&sig.mask[i], 0)` という単一のアトミック操作に置き換えられました。`xchg` は、指定されたメモリ位置の値を新しい値に設定し、同時にその古い値を返すため、この操作をより簡潔かつ効率的に行えます。

これらの変更は、機能的な振る舞いを大きく変えるものではなく、主にコードの明確性、保守性、および理解しやすさを向上させることを目的としています。

## コアとなるコードの解説

このコミットの主要な目的は、`sigqueue.go` 内のシグナル処理ロジックの明確性を向上させることです。

1.  **状態定数の改善**:
    以前は `0`, `_HASWAITER`, `_HASSIGNAL` といった数値定数で表現されていた `sig.state` の状態が、`sigIdle`, `sigReceiving`, `sigSending` という自己記述的な名前を持つ定数に置き換えられました。これにより、コードを読んだ際に、現在のシグナル処理システムがどのような状態にあるのかを一目で理解できるようになりました。これは、特に複雑な並行処理ロジックにおいて、バグの発見やデバッグを容易にする上で非常に重要です。

2.  **`sigsend` および `signal_recv` のロジックの構造化**:
    `sigsend` と `signal_recv` の両関数において、`sig.state` の遷移ロジックが、以前の `if/else` と `for` ループの組み合わせから、より構造化された `switch` ステートメントに書き換えられました。
    *   `switch atomicload(&sig.state)` を使用することで、現在の状態に基づいて異なる処理パスを明確に定義できます。これにより、各状態での振る舞いが分離され、コードのフローが追いやすくなります。
    *   例えば、`sigsend` では、シグナルが既にキューにある場合の処理、通知が既に保留中の場合の処理、そして受信側が待機している場合に `notewakeup` を呼び出す処理が、それぞれの `case` ブロック内で明確に表現されています。
    *   `signal_recv` では、シグナルがない場合にGoルーチンをスリープさせる `notetsleepg` の呼び出しや、シグナルが到着した場合の処理が、同様に明確に記述されています。

3.  **`xchg` の導入による簡潔化**:
    `signal_recv` 関数内で、`sig.mask` から `sig.recv` へのシグナルビットマスクの転送ロジックが大幅に簡素化されました。以前は、`for` ループ内で `cas` を使用してアトミックな交換を実現していましたが、これはやや冗長でした。新しいコードでは、`sig.recv[i] = xchg(&sig.mask[i], 0)` という単一の `xchg` (atomic exchange) 操作に置き換えられました。`xchg` は、メモリ位置の値を新しい値に設定し、同時にその古い値をアトミックに返すため、この操作をより効率的かつ簡潔に表現できます。これにより、コードの行数が減り、意図がより明確になりました。

これらの変更は、Goランタイムのシグナル処理サブシステムが、より堅牢で、理解しやすく、保守しやすいものになることに貢献しています。

    *   `_HASWAITER` は `sigReceiving` に、`_HASSIGNAL` は `sigSending` に、そして暗黙の `0` は `sigIdle` にそれぞれ名前が変更されました。これらの新しい定数は `iota` を使用して定義され、より意味のある名前が付けられています。これにより、`sig.state` の値がコード内で使用される際に、その意図がはるかに明確になります。
    *   `sigIdle`: シグナルがキューになく、`signal_recv` がブロックされていない状態。
    *   `sigReceiving`: `signal_recv` が `sig.Note` でブロックされており、新しい保留中のシグナルがない状態。
    *   `sigSending`: `sig.mask` に新しい保留中のシグナルが含まれている可能性があり、`signal_recv` はこの状態ではブロックできない状態。

2.  **`sigsend` 関数のロジック改善**:
    *   `sigsend` は、シグナルハンドラからシグナルをキューに追加する関数です。
    *   変更前は、`sig.state` の更新ロジックが `if/else` と `for` ループの組み合わせで表現されており、やや複雑でした。
    *   変更後は、`atomicload(&sig.state)` の結果に基づいて `switch` ステートメントを使用するようになりました。これにより、`sigIdle`、`sigSending`、`sigReceiving` の各状態からの遷移ロジックが明確に分離され、可読性が大幅に向上しました。
    *   特に、`sigReceiving` 状態から `sigIdle` への遷移時に `notewakeup(&sig.note)` を呼び出すことで、待機中のGoルーチンを起床させるロジックがより明確になりました。

3.  **`signal_recv` 関数のロジック改善**:
    *   `signal_recv` は、Goプログラムがキューからシグナルを受け取る関数です。
    *   `sigsend` と同様に、`sig.state` の更新ロジックが `switch` ステートメントに置き換えられました。これにより、`sigIdle` と `sigSending` の各状態からの遷移がより明確になりました。
    *   `sigIdle` 状態から `sigReceiving` への遷移時に `notetsleepg(&sig.note, -1)` を呼び出すことで、シグナルが到着するまでGoルーチンをスリープさせるロジックが明確になりました。
    *   最も重要な変更点の一つは、`sig.mask` から `sig.recv` へのシグナルビットマスクの転送方法です。変更前は `for` ループ内で `cas` を使用してアトミックに `sig.mask[i]` を `0` に設定し、その古い値を `m` に取得していました。変更後は、`xchg(&sig.mask[i], 0)` という単一のアトミック操作に置き換えられました。`xchg` は、指定されたメモリ位置の値を新しい値に設定し、同時にその古い値を返すため、この操作をより簡潔かつ効率的に行えます。

これらの変更は、機能的な振る舞いを大きく変えるものではなく、主にコードの明確性、保守性、および理解しやすさを向上させることを目的としています。

## コアとなるコードの解説

このコミットの主要な目的は、`sigqueue.go` 内のシグナル処理ロジックの明確性を向上させることです。

1.  **状態定数の改善**:
    以前は `0`, `_HASWAITER`, `_HASSIGNAL` といった数値定数で表現されていた `sig.state` の状態が、`sigIdle`, `sigReceiving`, `sigSending` という自己記述的な名前を持つ定数に置き換えられました。これにより、コードを読んだ際に、現在のシグナル処理システムがどのような状態にあるのかを一目で理解できるようになりました。これは、特に複雑な並行処理ロジックにおいて、バグの発見やデバッグを容易にする上で非常に重要です。

2.  **`sigsend` および `signal_recv` のロジックの構造化**:
    `sigsend` と `signal_recv` の両関数において、`sig.state` の遷移ロジックが、以前の `if/else` と `for` ループの組み合わせから、より構造化された `switch` ステートメントに書き換えられました。
    *   `switch atomicload(&sig.state)` を使用することで、現在の状態に基づいて異なる処理パスを明確に定義できます。これにより、各状態での振る舞いが分離され、コードのフローが追いやすくなります。
    *   例えば、`sigsend` では、シグナルが既にキューにある場合の処理、通知が既に保留中の場合の処理、そして受信側が待機している場合に `notewakeup` を呼び出す処理が、それぞれの `case` ブロック内で明確に表現されています。
    *   `signal_recv` では、シグナルがない場合にGoルーチンをスリープさせる `notetsleepg` の呼び出しや、シグナルが到着した場合の処理が、同様に明確に記述されています。

3.  **`xchg` の導入による簡潔化**:
    `signal_recv` 関数内で、`sig.mask` から `sig.recv` へのシグナルビットマスクの転送ロジックが大幅に簡素化されました。以前は、`for` ループ内で `cas` を使用してアトミックな交換を実現していましたが、これはやや冗長でした。新しいコードでは、`sig.recv[i] = xchg(&sig.mask[i], 0)` という単一の `xchg` (atomic exchange) 操作に置き換えられました。`xchg` は、メモリ位置の値を新しい値に設定し、同時にその古い値をアトミックに返すため、この操作をより効率的かつ簡潔に表現できます。これにより、コードの行数が減り、意図がより明確になりました。

これらの変更は、Goランタイムのシグナル処理サブシステムが、より堅牢で、理解しやすく、保守しやすいものになることに貢献しています。
